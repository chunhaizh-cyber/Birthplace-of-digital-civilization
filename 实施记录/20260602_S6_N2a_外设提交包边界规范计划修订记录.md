```text
特征本身没有语言意义；
特征只有被组织到存在、区域、场景、任务输入、因果链之后，才成为自我可利用的信息。
```

同时要求：

```text
有不清楚的地方必须提出来；
绝对禁止使用文本来忽悠；
不得把外设给出的特征值直接解释成安全意义 / 服务意义。
```

## 新增硬边界

```text
外设提交包 = 供料；
自我外设本能方法 = 组织；
自我提交入口 = 入账；
因果链 = 解释。
```

不得等同：

```text
外设识别提交包 != 已确认观察存在
外设扫描提交包 != 当前场景风险明确
外设跟踪提交包 != 指定目标需求已满足
```

不得把外设特征值脱离下列结构直接送入安全值或服务值：

```text
区域
存在
场景
任务输入
因果模板
```

以下项目不得写成已实现，必须后续按真实源码逐项核对：

```text

3. 自我_扫描已识别区域 是否已存在；若不存在，只能列为待新增方法壳。
4. 自我_跟踪指定存在 是否已存在；若不存在，只能列为待新增方法壳。
5. 提交_观察存在特征值变化事实 是否已存在；若不存在，只能列为待新增提交入口。
6. 提交_指定存在跟踪事实 是否已存在；若不存在，只能列为待新增提交入口。
7. 安全评估是否只消费已提交入账的存在事实、扫描变化事实和跟踪事实。
```

## 对当前 S6-N2a 的修订

当前 S6-N2a 不再允许从自我线程过程代码硬编码识别 / 扫描 / 跟踪 / 确认子需求定义表。

当前下一步改为先代码对账：

```text
外设提交包结构
-> 自我外设本能方法组织结果场景
-> 正式提交入口入账
-> 当前场景特征值明确状态(范围) 子链
-> 安全 / 服务因果链解释
```

## 验收口径

文档修订验收只允许确认：

```text
规范和计划是否已经写清边界；
是否把待确认项写成待确认；
是否避免宣称代码已实现。
```

不得把本记录当作：

```text
三类提交包已实现；
三个自我外设本能方法已实现；
三个提交入口已实现；
当前场景特征值明确业务链已验收。
```
