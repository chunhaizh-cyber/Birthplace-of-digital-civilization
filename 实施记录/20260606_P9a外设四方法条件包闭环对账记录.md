## 2. 代码路径证据

### 2.1 等待项与报告匹配

`外设观察报告队列.ixx`

```text
结构_外设观察等待项：
    等待项ID
    来源需求ID
    目标外设
    观察运行模式
    期望报告类型
    最大允许报告年龄毫秒
    目标区域或目标簇
    幂等键
    质量要求摘要

外设观察_报告满足等待项：
    当前只按 目标外设 / 观察运行模式 / 期望报告类型 / 报告年龄 匹配。

按等待项匹配外设观察报告：
    从最新报告向前找匹配项，返回副本并写 匹配等待项ID。
```

结论：等待项具备来源需求和幂等信息，但报告匹配本身不会直接唤醒原任务，也不会把报告 ID 写回方法输入。

### 2.2 任务管理等待项构造

`任务模块.管理界面线程.impl.cpp`

```text
私有_外设观察需求口径_按方法供料要求：
    观察验证 -> 陌生环境逐簇识别 / 逐簇识别报告
    识别     -> 陌生环境逐簇识别 / 逐簇识别报告
    扫描     -> 已识别场景扫描变化 / 扫描变化报告
    跟踪     -> 目标跟踪观察 / 跟踪报告

私有_按方法供料要求构造外设观察等待项：
    观察验证 / 识别 不要求目标区域或目标簇。
    扫描 / 跟踪 要求目标区域或目标簇，来源为需求的 被需求存在。

私有_按当前方法供料要求提交外设等待项：
    当前方法执行失败、等待或条件缺口时，可提交外设观察等待项并启动 D455 线程。
```

结论：6127 / 6145 的等待项可自然生成；6146 / 6147 需要先形成合法目标存在或目标区域，不能从裸报告直接启动。

### 2.3 外设报告承接

`任务模块.管理工作线程.ixx`

```text
任务管理外设消息承接_处理一次：
    逐簇识别报告 / 扫描变化报告 -> 观察事实承接请求。
    跟踪报告 -> 稳定特征承接请求。
    上行消息携带 等待项ID / 报告ID / 来源需求ID / 外设 / 模式 / 报告类型 / 像素簇数量。
```

`任务模块.管理界面线程.impl.cpp`

```text
私有_巡检外设观察等待项并生成上行：
    读取等待项集合并按等待项匹配外设报告。
    生成任务管理上行消息。
    对相同 最新报告ID + 等待项数量 做去重。

巡检并派发就绪任务：
    先处理任务派发，再巡检外设观察等待项。
```

结论：报告承接入口存在，但承接产物是给自我线程的上行消息；它没有直接把原等待任务置为可重入。

### 2.4 自我线程材料落账

`自我线程模块.impl.cpp`

```text
私有_落任务管理观察事实承接请求到自我内部世界：
    读取报告。
    写 外设观察报告承接状态。
    写 外设观察像素簇数量。
    写 观察像素簇集合承接状态。
    写 存在候选集合状态 / 存在候选数量 / 存在识别摘要状态。
    写簇候选材料特征。
```

边界确认：该路径没有直接写需求满足、安全值、服务值或世界真值，符合“外设只供材料，自我方法产出正式事实”的边界。

当前缺口：承接完成后只触发安全根需求重筹办；没有按 `来源需求ID` 唤醒产生等待项的原任务。
