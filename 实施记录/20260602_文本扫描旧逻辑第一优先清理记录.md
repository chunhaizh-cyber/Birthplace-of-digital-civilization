# 文本扫描旧逻辑第一优先清理记录

日期：2026-06-02

## 触发原因

```text
用户指出：
    任务模块.管理界面线程.impl.cpp 中只有目标特征文本命中“逐簇识别 / 扫描变化 / 跟踪”才创建等待项，
    暴露出严重问题：正式业务分派不应成为文本扫描。

本次处理口径：
    彻底清理旧逻辑，哪怕项目不能正常运行；
    宁可让结构化上游缺口暴露，也不允许运行时词面扫描继续兜底。
```

## 已清理代码点

```text
任务模块.管理界面线程.impl.cpp：
    删除外设等待项生成中的目标特征 / 需求类型文本 contains 匹配；
    改为目标特征语素入口 / 需求类型语素入口精确命中规范特征集合；
    未登记外设观察运行模式的目标只记录结构化映射缺失，不再用疑似观察关键词兜底。

外设线程_D455深度相机.ixx：
    删除扫描变化等待项从质量要求摘要中扫描“基准 / 已确认 / 已识别”的兜底；
    扫描变化必须有结构化目标区域或目标簇。

需求类.cpp：
    枚举目标生产者分级不再把目标特征入口转成文本后匹配集合或后缀；
    改为规范特征语素入口主键比较；
    删除“观察事实可用状态 / 观察新鲜度状态”后缀兜底。

自我线程模块.impl.cpp：
    根必要条件到本能方法 ID 的映射改为语素入口主键命中；
    服务 / 安全固定字段过滤改为语素入口主键命中；
    根定义和必要条件子节点读取改为按规范语素入口定位；
    治理消息类型 / 特征类型不再从摘要文本推断，缺结构化枚举时保留默认值。

自我线程模块.消息协议.ixx：
    推断任务管理动作主体类型不再从类型摘要文本 contains 推断。

自检线程模块.impl.cpp：
    自检代码缺陷报告例外判断改为条件结果对统计特征语素入口比较；
    根定义状态节点读取改为按规范语素入口定位。
```

## 当前风险

```text
1. 如果上游需求没有结构化目标特征类型 / 需求类型，任务管理不会创建外设等待项。
2. 如果根特征定义子节点入口类型与当前规范入口不一致，根必要条件读取会暴露缺口。
3. 如果治理消息仍只给文本摘要而不带结构化枚举，主体类型 / 特征类型会保留默认值。
4. 这些风险是本次清理的预期结果：不再用旧文本扫描掩盖结构化缺口。
```
