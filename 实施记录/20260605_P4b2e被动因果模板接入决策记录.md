## TSV 接入清单

### 1. 安全需求树遗传被动链

保留 TSV / 初始因果模板接入。

代码证据：

```text
自我线程模块.impl.cpp
    私有_读取初始因果模板种子文件_线程侧
        读取 data/initial_causal_templates.tsv；
        字段为 名称 / 层级 / 主果宿主 / 主果特征 / 因宿主 / 因特征集；
        文件缺失时 C++固定清单回退=0。

    私有_应用安全因果风险树初始模板种子_线程侧
        把 TSV 行目标化为主果比较和因比较集合；
        通过 私有_确保初始因果模板_线程侧 入账。

    私有_确保安全因果风险树初始模板_线程侧
        主链仍补 自我安全值目标 <- 风险安全层明确状态；
        再应用 TSV 种子补 风险安全层 / 场景影响 / 当前场景可观测单位 / D455 路径。
```

接入理由：

```text
1. 它是跨宿主链：自我 / 风险安全层目标宿主 / 当前场景。
2. 它需要解释为什么要从安全值目标反推到场景可观测单位和 D455 路径。
3. 它不是本能方法，TSV 行只提供 条件集合 -> 必然结果。
4. 宿主解释由自我线程安全风险树写点提供。
```

### 2. 任务筹办因果路径只读查询

任务筹办不直接读取 TSV 文件，但应消费已经入账的初始因果模板。

代码证据：

```text
任务模块.筹办.ixx
    因果证据足够_筹办查询
        初始因果模板是冷启动路线图；
        筹办可用它反推必要状态。

    尝试准备因果路径筹办入口壳
        统计 初始因果模板 / 主果模板声明 / 主果命中；
        直接写需求树=0；
        实际发送派生需求消息=0。

    筹办_按因果反推必要状态
        直接写需求树=0；
        直接创建任务=0；
        直接结算价值=0。
```

接入决策：

```text
任务筹办只读消费因果模板，不拥有 TSV 加载权，也不直接写安全风险树。
```

## 内部等价规则清单

### 1. 方法状态最低可用

不接 TSV。

代码证据：

```text
方法虚拟存在服务类.cpp
    私有_同步方法状态特征
        无方法动作 -> 待方法动作；
        无有效动作句柄 -> 待可执行入口；
        无条件节点 -> 待条件节点；
        无结果节点且无条件结果对 -> 待结果节点；
        无条件结果对 -> 待条件结果对；
        条件结果对数量 > 0 -> 可用。

    私有_输出方法状态动作动态
        方法状态变化写成内部机制动作动态；
        只记录方法域记忆变化；
        不写任务状态、不修改需求树、不提交世界事实。
```

决策：

```text
方法状态最低可用只依赖目标方法结构底账；
目标宿主由方法虚拟存在服务类持有；
不需要 TSV。
```

### 2. 任务筹办方法结构缺口

不接 TSV。

代码证据：

```text
任务模块.筹办.ixx
    候选方法不可就绪状况
        缺方法动作；
        方法缺可执行入口；
        方法缺条件结果对。

    返回自我动作组合缺口
        因果反推是只读诊断；
        不提交方法动作、任务状态或需求节点；
        反推无法直接提交时，转为方法结构缺口等待统一任务执行链承接。

    返回方法结构缺口 / 返回方法状态可用性缺口
        缺口目标围绕已找到目标方法；
        筹办只形成回执和结构缺口。
```

决策：

```text
任务筹办用内部结构规则生成精确方法缺口；
不把这些缺口写入 TSV。
```

### 3. 练习达标与方法稳定

不接 TSV。

代码证据：

```text
自我动作实现模块.ixx
    自我_练习
        读取目标方法最近连续成功次数；
        读取同条件样本次数；
        读取同条件新结果分支数量；
        同条件样本次数 >= 4；
        同条件新结果分支数量 <= 0；
        方法最近连续成功次数 >= 4；
        练习后方法状态 >= 好用；
        写入 方法稳定状态。
```

决策：

```text
练习达标是目标方法虚拟存在和条件场景的数量底账组合；
当前由学习本能和方法虚拟存在服务类直接读写；
不需要 TSV。
```

### 4. 父任务重筹办与结算被动果

暂不接 TSV。

代码证据：

```text

    结构_被动触发初始因果规则_线程侧

    私有_增强被动触发初始因果_线程侧
    私有_确保任务结算被动初始因果_线程侧
```

决策：

```text

当前保持内部规则形式更准确；
后续只有在需要把生命周期被动果迁入外部种子表统一维护时，再单独拆 TSV 迁移切片。
```

## 等价布尔特征候选清单

本切片不新增等价布尔特征。

暂定候选如下：

```text
方法条件结果对数量已满足状态：
    条件：方法条件结果对数量 > 0。
    当前消费方：任务筹办和方法虚拟存在服务类直接读数量。
    决策：暂不新增。

同条件练习样本已达标状态：
    条件：同条件样本次数 >= 4。
    当前消费方：自我_练习直接读条件场景数量。
    决策：暂不新增。

同条件无新结果分支状态：
    条件：新结果分支数量 == 0。
    当前消费方：自我_练习直接读条件场景数量。
    决策：暂不新增。

方法好用 / 稳定维护材料已满足状态：
    条件：连续成功 >= 4、同条件样本 >= 4、新结果分支 == 0。
    当前已有特征：方法稳定状态。
    决策：优先复用 方法稳定状态，暂不新增。
```

新增等价布尔特征的触发条件：

```text
1. 出现跨轮任务筹办或因果账本消费方；
2. 消费方需要引用组合条件而不是数量底账；
3. 权威宿主和写点已明确；
4. 不会和现有 方法状态 / 方法稳定状态 重复。
```

## 主动反推排除

`因果类.cpp` 的主动反推有动作过滤：

```text
私有_因果模板可主动反推
    必须存在因方法模板 / 因动作语义键 / 因动作名称；
    且动作语义不能是被动整理或治理镜像。
```

因此 TSV 里的被动模板不会被误当作可执行本能动作来源。

## P5a 追加口径修正

用户补充后修正：

```text
内部治理因果不全部是被动因果；
内部治理也存在主动因果，例如学习方法。
```

因此，P4b2-e 的结论需要限定为：

```text
只需内部等价规则：
    仅指条件满足后必然发生的被动治理写值或状态派生；
    例如父任务重筹办、结算被动果、方法状态最终派生等。

主动治理因果：
    学习 / 练习 / 建立条件结果对 / 提交方法状态变化；
    条件具备后仍必须执行对应方法动作；
    必须走需求任务化、任务筹办统一找方法、任务执行调用方法。
```

修正后的 P5a 追因口径：

```text
当前学习堵点不是“方法状态被动派生没有自动发生”，
而是主动学习治理需求入树后没有进入任务创建和统一找方法。
```
