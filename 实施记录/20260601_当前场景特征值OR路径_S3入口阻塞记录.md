## 新问题

需求树新增子需求时会按目标重叠去重：

```text
目标主体主键
目标特征类型主键
方向掩码
```

见 `需求类.h:704` 附近的 `需求目标重叠_已加锁`，以及 `需求类.h:731` 附近的 `查找直接子需求_按目标重叠_已加锁`。

如果在同一个 OR 组下面直接创建三条路径：

```text
D455观察确认路径：方法路径完成状态 0 -> 1
读取已有场景缓存路径：方法路径完成状态 0 -> 1
交互者说明路径：方法路径完成状态 0 -> 1
```

且它们使用同一个目标宿主，那么三个路径节点会被判断为同一目标，最终合并成一个 `方法路径完成状态` 子需求。这会破坏 OR 路径的三路语义。

## 不能直接做的事

1. 不能新增需求主信息字段保存 `路径名称` 或 `路径类型`，因为规范要求逻辑组织语义不进入需求主信息。
2. 不能靠日志文本或派生原因区分三条路径，日志不是需求树目标键。
3. 不能把三条路径一起任务化为普通 AND 子任务，这会把 OR 路径误展开成并列必做。
4. 不能用同一个目标宿主创建三个 `方法路径完成状态` 节点，否则会被去重合并。

## 需要先确认的承载方案

S3/P1 继续实现前，需要明确每条方法路径的目标宿主或路径承载节点。可选方向：

```text
方案 A：为每条路径创建普通存在节点作为路径宿主
    特征：方法路径完成状态
    宿主：D455观察确认路径存在 / 已有场景缓存路径存在 / 交互者说明路径存在

方案 B：把路径承载为因果模板或获取途径视图中的普通存在
    仍由目标特征类型解释方法路径语义
    不新增需求主信息字段

方案 C：只先创建 OR 组节点和一个 D455 激活路径
    缓存 / 交互者说明先不入树，避免伪占位合并
    但这会偏离“先作为占位路径”的当前计划文字，需要确认。
```
