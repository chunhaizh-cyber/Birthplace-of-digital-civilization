# 需求树简化与内部治理闭环 P3c-P3f Codex断点清单

日期：2026-06-30

## 0. 恢复摘要

当前切片：R24 P3c-P3f，只读提取主动 / 被动动态信息，形成因果需求清单和方法映射。

本轮边界：

```text
不修改需求类 P4 草稿。
不新增结构体。
不新增本能方法。
不构建、不运行。
只把已核查代码事实写入实施记录，供后续 P4 / P5 恢复使用。
```

本轮结论：

```text
主动因果不能从任务执行桥、线程或普通治理函数直接生成。
主动因果只能由本能方法或方法动作入口产生的主动动态信息承接。
被动因果由任务状态提交、观察 / 扫描治理记录、结算后处理和被动触发模板承接。
被动动态可以作为来源证据和因果抽象材料，但不得进入方法候选、学习目标或普通需求入树来源。
现有代码已有主动 / 被动因果读取、验证和可任务化检查函数，但缺少一张面向治理闭环的统一动态信息盘点视图。
```

禁止宣称：

```text
不得宣称需求树简化生成已闭环。
不得宣称内部治理闭环已完成。
不得宣称服务业务 D0 生产闭环已完成。
不得宣称所有本能方法都能产生主动因果。
```

## 1. 上级口径与代码判据

本轮采用以下判据：

```text
方法动作动态必须绑定明确方法。
任务执行桥只调度方法并读取运行回执。
主动动态信息要有方法 / 动作入口、目标宿主、目标特征、动作前后状态和同源状态变化证据。
被动动态信息的动作语义为 `被动动作` 或 `被动触发.*` 时，只能作为证据、触发结构或上游追溯线索。
动作动态进入因果抽象后，因果分类仍要检查动作语义、来源方法、目标宿主、目标特征、初始状态和结果状态。
```

暂不新增本能方法的缺口：

```text
1. “动态信息盘点视图”是治理读取 / 复核需求，优先做普通只读函数或实施记录，不新增本能方法。
2. “主动 / 被动因果分类报告”是治理判断，优先复用因果类只读函数，不新增本能方法。
3. “服务 D0 缺口定位”先查现有服务动作和 D0 写入位置，不得直接新建服务本能方法。
4. “方法状态动态标准化”先复核 `方法虚拟存在服务类::私有_输出方法状态动作动态` 是否应迁到标准方法动作动态路径；未确认前不新增结构。
```

可能需要后续补充的本能方法候选，必须等更细审计后再定：

```text
1. 如果服务业务动作确实没有任何现有方法能生成合格 D0，才提出“服务业务动作登记 / 提交”类本能方法候选。
2. 如果安全处置动作确实只能生成评估或证据而不能产生对象作用动态，才提出具体安全处置本能方法候选。
3. 如果学习链不能通过现有 `自我_尝试学习` / `自我_定向学习` / `自我_练习` 改变方法状态，才提出方法状态改变类本能方法候选。
```

## 6. 对 P4 恢复的影响

P4 可恢复条件：

```text
1. P4 helper 只能处理需求入口准入，不得声称主动因果已闭合。
2. P4 helper 对内部治理缺陷必须返回禁止普通入树或开发诊断，不得生成普通需求。
3. P4 helper 允许把主动因果不足翻译为方法补齐类缺口，但必须依赖 P3e 的因果需求清单。
4. P4 helper 不能把任务状态提交、结算动态、G0、D2 或被动触发模板当成服务业务 D0。
5. P4 恢复前需要检查当前草稿与本文件 C-A / C-P 清单是否冲突。
```

下一最小切片建议：
