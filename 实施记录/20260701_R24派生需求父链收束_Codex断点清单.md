# 20260701 R24 派生需求父链收束 Codex断点清单

## 0. 恢复摘要

当前切片：删除派生需求消息中会绕过直接父需求的冗余父链来源，并停止自我根层直接生成服务根下扫描需求。

用户口径：

```text
不能靠拦截、审计、校验或追溯根字段修正父子关系。
派生需求必须从源头携带直接上级需求。
没有直接上级需求时不能生成派生需求消息。
```

## 1. 依据

- `规范/5140_子规范_需求临时因果视图展开_20260701.md`：派生需求消息必须有目标宿主、目标特征、当前状态、目标状态和目标比较符；临时因果视图只给缺口草案，正式承接仍走需求树、任务树、方法候选和动作动态链。
- `规范/6120_子规范_自我存在服务与生存基本因果闭环_20260701.md`：无直接服务触发事实时，只能生成间接服务维护需求，例如服务触发事实监听、服务机会检查、服务能力校准。
- `docs/工程图谱/01_任务需求方法闭环图谱.md`：派生需求必须经自我线程和需求类裁决；任务筹办不直接写需求树。

## 2. 当前判断

运行期 `父需求=2 -> 新需求=6 扫描` 的直接原因是 `自我线程模块.impl.cpp` 根层维护函数直接把 `服务根需求` 写入派生需求消息父需求字段。

更深层原因是派生需求消息存在多套父需求来源：父需求指针、父需求主键、工作线程按任务自动补父需求、自我线程按任务反查父需求。该机制允许生产方缺失或错填直接父需求后仍进入入树流程。

## 3. 预测

修改后：

```text
1. 派生需求消息只保留父需求主键作为直接父需求。
2. 工作线程不再自动从任务补齐父需求；筹办/执行消息生产方必须显式写父需求主键。
3. 自我线程不再用任务反查或父需求指针兜底解析父需求。
4. 根层当前场景维护函数不再直接生成服务根下扫描需求。
5. 真实运行中不应再出现 P7a|服务到扫描 或 父需求=2 的扫描派生消息。
6. 服务根仍可按定义生成 3/4/5 间接维护子需求。
```

## 4. 禁止宣称

不宣称 R24 完成、内部治理闭环完成、扫描需求已正确挂到服务机会检查、直接服务正向触发事实路径已接入、服务 G0 / D2 正向闭环完成、自我苏醒完成或初步成熟完成。

## 5. 本轮实际修改

- `任务模块.工作线程消息协议.ixx`：`结构_任务管理派生需求消息` 删除 `父需求指针`，只保留 `父需求主键` 作为直接上级需求字段。
- `任务模块.管理工作线程.ixx`：删除工作线程自动从任务补齐派生需求父需求的逻辑；执行缺失派生需求必须由当前任务显式对应需求给出父需求主键，缺直接父需求时不生成派生需求消息。
- `任务模块.筹办.ixx`：筹办生成正式派生需求消息时只写来源需求主键，不再写父需求指针。
- `自我线程模块.impl.cpp`：派生需求父需求解析只读 `父需求主键`；不再按父需求指针、关联任务、任务反查兜底；删除服务根直连当前场景扫描需求的 P7a 生成函数；任务来源需求读取也去掉按任务反查非根需求兜底。
- `说明书/函数功能说明文档.md`：已重新生成，删除函数说明中的旧 P7a 直连扫描函数条目。
- `计划/计划索引.md`、`计划/20260630_需求树简化生成与内部治理闭环计划_v0.1.md`：撤销旧 P7a 已满足结论，改判为旧证据父链错误，等待真实子需求、方法条件或观察/扫描比较边界产生扫描需求。
