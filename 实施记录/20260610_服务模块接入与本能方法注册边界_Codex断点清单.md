## 注册边界

### 允许继续作为服务本能方法的类型

只有满足以下条件的函数，才允许注册为普通服务本能方法：

```text
1. 是自我的最小可执行服务动作。
2. 有明确输入参数场景。
3. 有明确输出结果场景。
4. 有明确前置条件或字段绑定规则。
5. 能落到某个具体宿主存在的具体特征变化。
6. 能说明动作动态来源方法。
7. 输入缺失时只返回参数缺口，不伪造完成。
```

当前已注册的 8 个字段绑定方法属于这一类。

### 暂不注册为普通服务本能方法的 helper

以下服务模块 helper 暂不进入本能方法枚举、默认本能方法表、候选方法集或任务当前方法：

```text
装配方法声明特征到任务
检查服务方法输入字段
写入服务字段缺口回执
创建服务方法运行存在
读取并记录服务前状态
读取并记录服务后状态
比较服务前后状态
承接方法运行输出场景
读取服务D0动作动态
校验服务D0基础合法性
校验并回写任务服务D0
获取或创建G0治理视图
写入G0硬门槛状态
汇总G0硬门槛状态
计算服务三评分
回写G0层级与候选状态
组装G0成功服务候选
获取或创建任务成功服务候选池
登记成功服务候选记录
复核成功服务候选记录
计算成功服务lambda候选
计算成功服务值饱和入账
写入服务值结算候选结果
创建服务值结算D2动作动态
回写父任务组合汇总
记录OR胜出路径
```

理由：

```text
1. 多数是读取、校验、评分、组装、复核或账务计算。
2. G0 是内部治理判断，不是 D0 服务业务动作。
3. D2 是服务值结算动作动态，不能反向证明成功服务。
4. 候选池登记 / 复核属于治理账务动作，第一版没有独立输入输出场景和动作动态封装。
5. 父子组合汇总属于父任务治理摘要，不能复制子任务全部字段，也不能直接结算服务值。
```

这些 helper 可以被任务管理生命周期、服务治理流程或未来被动提交入口调用，但不得作为普通任务筹办可选方法。

## G0 / D2 接入边界

### G0

G0 成功服务治理视图只能由以下事实支撑：

```text
来源需求
来源任务
D0 服务业务动作动态
D1 任务状态动作动态
现实世界证据
输出结果场景事实
服务前后状态比较
验证与归因
权限与安全状态
```

G0 不是现实世界事实字段，也不是服务动作动态。G0 可以写治理判断特征，但不能替代 D0。

### D2

D2 服务值结算动作动态只能在 G0 已确认且非重复结算后出现。

第一版接入策略：

```text
保留现有 自我_结算叶子任务价值 / 结算叶子任务价值 链作为价值账务底层入口。
后续新增“服务_结算成功服务价值”时，只能作为语义包装或被动提交入口。
该入口必须以 G0已确认 + D0存在 + D1存在 + 候选记录可结算 + 未重复结算 为前置。
该入口不得进入普通候选方法集、当前方法、学习目标或练习目标。
```

因此，本切片不直接把 `创建服务值结算D2动作动态` 注册成本能方法。
