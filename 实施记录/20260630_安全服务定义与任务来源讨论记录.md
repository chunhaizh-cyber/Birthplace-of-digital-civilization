# 20260630 安全服务定义与任务来源讨论记录

## 0. 本轮讨论口径

本轮确认的核心口径：

```text
安全、服务是自我存在上的两个根特征类型。
安全 / 服务目标值与当前值的差异形成安全根需求 / 服务根需求。
满足根需求的任务来自定义，不来自结算临时发明。
推动这些任务完成的驱动力来自内部治理因果链。
任务完成后通过任务结算回写安全 / 服务值，形成下一轮内部治理判断。
```

三层必须分开：

```text
根需求形成：安全 / 服务根特征当前值 与 目标值比较。
任务存在来源：安全 / 服务定义、需求定义、任务定义和因果链缺口映射。
任务完成驱动力：内部治理因果链驱动任务筹办、执行、归并和结算。
```

## 1. 当前安全定义

当前规范定义中，安全不是场景事实，也不是场景或对象的常驻安全度。安全值是自我存在的根控制特征。

权威结构：

```text
根特征类型：自我_安全值
根特征宿主：自我存在
目标状态：安全抽象定义中的最大值目标
当前状态：自我存在上的自我_安全值实例当前值
根需求：当前值低于目标值时，安全根需求进入活动集
```

安全值第一版按四层解释：

```text
0：终止控制态。
1：休眠控制态。
1..90：物理 / 运行安全候选，经必要因素能力保留率叠乘得到。
90..99：风险安全余量解释层，不是根需求目标值。
```

安全任务的事实来源不是“安全值差距本身已经解决”，而是安全因果链中的可追溯缺口、风险树缺口、物理 / 运行事实恢复、负向影响处置或安全目标特征改善。

## 2. 当前服务定义

当前规范定义中，服务值也是自我存在的根特征，但服务值的事实来源不是自我服务值差距本身，而是自我通过自身动作改善人类服务对象的需求相关外在状态。

权威结构：

```text
根特征类型：自我_服务值
根特征宿主：自我存在
目标状态：服务抽象定义中的最大值目标
当前状态：自我存在上的自我_服务值实例当前值
根需求：当前值低于目标值时，服务根需求进入活动集
```

服务根需求的目标宿主仍是自我，因为 `自我_服务值` 是自我的账务 / 价值根特征；服务对象只在服务触发事实点亮后的服务因果链上下文子需求和服务事实子需求中作为目标宿主。

服务值增加必须能证明：

```text
存在服务对象；
存在服务目标或人类需求事实；
服务对象外在特征状态发生正向改善；
改善可验证；
改善可归因于自我动作。
```

任务运行成功、服务对象接受且无负反馈、服务值已经变化，都不能反向证明服务已成功。

## 3. 当前代码现状

当前代码已经具备以下结构：

```text
自我类::确保根需求_：
    为自我_安全值 / 自我_服务值创建或刷新根需求；
    写入需求主体、被需求存在、当前状态、目标状态和满足关系。

自我线程模块.impl.cpp 根需求刷新：
    读取当前安全值 / 当前服务值；
    读取抽象根特征定义目标区间；
    判断当前值是否低于目标值；
    根据缺口刷新根需求权重和根闭环信息位。

需求类::生成任务初始化上下文：
    从来源需求读取发起存在、场景、作用对象、当前状态、目标状态、满足关系、目标特征类型、安全权重和服务权重。

任务管理界面线程：
    对可任务化活动需求发起任务；
    创建任务头；
    绑定任务与需求；
    初始化任务运行壳和任务虚拟存在。
```

需要注意的实现差异：

```text
规范要求安全 / 服务目标状态按“最大值”读取。
当前代码局部仍从目标区间.低值读取安全 / 服务目标值。
```

这属于后续待校准点，不能把当前实现误记为最终口径。

另一个实现差异：

```text
代码中存在 安全根任务 / 服务根任务 的名称和读取入口；
也存在 自我类::确保根任务_ helper；
但本次搜索未发现 ensure helper 的调用点。
```

因此当前更可靠的任务生成事实是：

```text
活动需求 -> 任务化意图 -> 任务管理创建 / 复用同目标任务 -> 任务运行壳初始化
```

“根任务来自定义”是本轮应收口的设计口径，当前实现是否已经完整以安全根任务 / 服务根任务承接，需要后续代码切片复核。

## 4. 当前可以生成的任务类型

### 4.1 根承接任务

理论口径：

```text
安全根任务：
    承接安全根需求；
    不直接等同于安全值增加；
    负责沿安全因果链筹办安全缺口、派生子需求、归并子任务和触发结算。

服务根任务：
    承接服务根需求；
    不直接等同于服务值增加；
    负责沿服务因果链监听 / 检查 / 校准 / 承接服务触发事实，并在直接服务链点亮后派生具体服务子任务。
```

当前实现层面：

```text
安全根任务 / 服务根任务有名称和读取入口。
普通活动需求也可以经任务管理生成对应任务头和任务虚拟存在。
根任务是否稳定由初始化定义直接生成，需要后续复核。
```

### 4.2 安全链任务

安全根需求有缺口时，允许生成的任务必须来自安全因果链、风险树缺口或明确安全事实缺口，典型包括：

```text
安全根控制态检查任务；
服务能力保留率检查任务；
物理 / 运行安全因素候选检查任务；
资源状态、权限边界、运行依赖、方法可用性、外设状态等具体安全事实检查任务；
当前场景存在集合及其对自我关键特征影响的观察 / 确认任务；
安全影响因果明确任务；
负向影响处置任务；
风险安全余量判断任务；
风险树缺口补证任务。
```

禁止：

```text
仅因字段名存在就生成固定安全必要条件任务；
把场景安全度直接当作自我安全值事实；
把安全值已经变化当作结算前证据；
用旧固定清单重激活“自我运行状态正常 / 资源足够 / 权限明确”等直接子需求。
```

### 4.3 服务间接维护任务

服务根有缺口但没有直接服务触发事实时，可以生成间接服务维护任务：

```text
服务触发事实监听任务；
服务机会检查任务；
服务能力校准任务；
服务根缺口检查任务；
休眠 / 唤醒候选判断任务；
服务值动态衰减后的服务意识唤醒任务。
```

这些任务只能用于发现、承接或准备直接服务，不能证明：

```text
服务对象已经存在；
服务目标已经确定；
服务结果已经改善；
服务归因成立；
G0 成功服务成立；
D2 服务值结算成立。
```

### 4.4 服务直接链任务

只有直接服务触发事实、当前会话输入、人类表达、外部请求、已确认服务目标、服务动作结果或反馈事实点亮直接服务因果链后，才允许生成直接服务任务，典型包括：

```text
明确当前服务对象任务；
明确服务目标任务；
明确授权 / 权限 / 责任归因任务；
明确服务对象当前状态任务；
执行服务动作任务；
验证服务结果任务；
服务对象反馈承接任务；
服务对象外在特征状态改善任务；
服务结果归因任务；
来源需求满足回查任务；
叶子任务价值结算任务。
```

服务对象外在特征状态改善型子需求，才是服务值结算最核心的事实证据来源。

### 4.5 通用方法 / 条件补齐任务

安全链或服务链在筹办中发现明确方法缺口时，可以派生通用补齐任务：

```text
候选方法不可用 -> 方法状态达到可用；
缺执行入口 -> 方法动作状态达到已形成；
缺条件节点 -> 补条件节点；
缺结果节点 -> 补结果节点；
缺条件结果对 -> 建立条件结果对；
参数不可配 -> 补参数绑定条件；
证据不足 -> 补证据 / 观察 / 验证任务；
方法结果不稳定 -> 稳定度验证或练习任务。
```

这些任务不是安全 / 服务特征定义直接硬编码出来的固定任务，而是内部治理因果链在筹办时发现的可承接缺口任务。

## 5. 本轮待确认问题

需要后续继续确认：

```text
1. 安全 / 服务定义是否要显式给出“根任务模板”集合，而不是只靠活动需求任务化生成任务。
2. 根任务模板应落在抽象特征定义、需求定义、任务定义，还是方法定义中。
3. 当前代码中 自我类::确保根任务_ 未见调用，是否应恢复 / 重建为安全根任务和服务根任务的定义承接入口。
4. 安全 / 服务目标值读取应从当前代码的目标区间.低值校准为规范要求的最大值目标。
5. 服务根在无直接服务触发事实时，只能生成间接服务维护任务；直接服务任务的准入条件是否需要进一步结构化到服务因果链信息位。
```

## 6. 结论短句

```text
安全 / 服务是根特征类型。
根需求来自根特征当前值与目标值差异。
任务来自定义和需求任务化承接。
任务完成由内部治理因果链驱动。
任务结算只回写已完成叶子任务的安全 / 服务贡献，不生成任务本身。
```
