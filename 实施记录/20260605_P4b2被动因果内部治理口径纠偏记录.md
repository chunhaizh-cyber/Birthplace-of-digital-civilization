## 流程图复核结论

### 1. P4b2 主口径改为内部治理被动因果树

`自我内部治理被动因果树_任务方法虚拟存在_v0.2` 已明确：

```text
被动因：
    已正式入账的需求、任务状态、任务回执、方法状态、输出结果状态、动作动态、结算资格状态。

被动果：
    在被动因成立后，由生命周期提交链、后处理链或结算链必须自动出现的治理结果。
```

因此 P4b2 不再寻找“可被任务筹办选择的方法状态派生方法”，而是寻找：

```text
任务虚拟存在 / 方法虚拟存在特征自动改值写点；
写点读取哪些正式事实；
写点自动写出哪些治理结果；
写出结果是否生成权威动作动态或只作为被动镜像材料。
```

### 2. 任务完成流程与方法完善流程拆成两个分支

任务完成流程图给出的主链是：

```text
活动需求正式入树
-> 承接需求创建任务
-> 筹办回执镜像
-> 提交任务状态变化 D1
-> 执行回执镜像
-> 提交任务状态完成 / 等待 / 待重筹办 / 失败
-> 来源需求收束
-> 叶子任务价值结算 D2
-> 父任务重筹办
```

方法完善流程图给出的分流是：

```text
任务筹办命中方法缺口
-> 确保方法虚拟存在
-> 同步方法节点
-> 计算方法状态
-> 方法状态动作动态
-> 生成具体结构补齐需求
-> 补齐事实入账
-> 方法可用后唤醒任务重筹办
```

这意味着后续计划必须分别对账：

```text
任务虚拟存在写点；
方法虚拟存在写点；
父任务重筹办写点；
需求收束和结算写点；
统一因果吸收写点。
```

### 3. 安全需求树只用于消费边界

安全需求树两张图已经把主干节点限定为：

```text
直接需求节点；
AND / OR 逻辑组织需求节点。
```

自我线程维护、安全评估、扫描、跟踪、提交入口、D455识别等只能作为生产者或承接方式。

同时第一次扫描口径固定为：

```text
发现存在 / 发现特征事实。
```

有可比历史后才进入：

```text
特征值变化事实。
```

### 4. TSV 继续只是依据，不是动作表

此前把堵点描述为：

```text
TSV 应用入口只服务安全风险树；
没有把 target 解释为目标方法虚拟存在的方法状态派生入口。
```

现在修正为：

```text
TSV 只保存 条件集合 -> 必然结果；
具体目标宿主由内部治理写点提供；
是否读取 TSV 必须在写点对账后决定；
不得为了 P4b2 给 TSV 增加动作语义列或本能方法登记。
```
