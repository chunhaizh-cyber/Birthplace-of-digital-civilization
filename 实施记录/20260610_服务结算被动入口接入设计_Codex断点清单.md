## 现有任务价值结算链

当前自然链路是：

```text
任务管理工作线程
    -> 构造结果状态上行消息
    -> 写入 任务价值反馈.安全累计比例 / 服务累计比例
    -> 自我线程处理结果状态消息
    -> 私有_处理任务满足反馈_线程侧
    -> 私有_处理任务价值反馈_线程侧
    -> 私有_提交任务已结算状态_线程侧
    -> 私有_调用结算叶子任务价值本能方法_线程侧
    -> 自我_结算叶子任务价值
    -> 写自我安全值 / 自我服务值
    -> 输出叶子任务价值结算动作动态
```

其中：

```text
自我_结算叶子任务价值
    本能方法ID = 6080
    当前是已有价值账务底层入口。
```

当前服务值分支使用：

```text
计划服务增量
任务完成度百万分比
服务对象外在特征状态变化数
服务对象外在特征状态改善证据
服务结果可验证
服务结果可归因于自我动作
```

满足四项服务证据后，按：

```text
新服务值 = min(旧服务值 + 服务增量, 根目标服务值)
```

进行加法封顶。

## v1.1 成功服务结算链

新规范要求：

```text
D0 服务业务动作动态
+ D1 任务状态动作动态
+ 现实证据
+ G0 成功服务治理判断
+ 候选记录可结算
+ 非重复检查
    -> D2 服务值结算动作动态
        -> DeltaS = (Smax - S) * lambda(e)
```

其中：

```text
服务值只能由 G0 确认的成功服务事件增加。
证据不足只能进入候选池，不得直接入账。
D2 只能证明服务值如何入账，不能反向证明成功服务。
```

服务模块已经有辅助函数：

```text
计算成功服务值饱和入账
写入服务值结算候选结果
创建服务值结算D2动作动态
```

但这些 helper 当前没有接入自然任务价值反馈链。

## 冲突点

当前代码和 v1.1 之间存在实质口径差异：

```text
1. 现有服务值入口仍允许由任务价值反馈 + 四个服务证据字段产生服务值增加。
2. v1.1 要求服务值增加必须来自 G0 已确认成功服务。
3. 现有自我线程自然链路没有生成 G0，也没有传入成功服务候选记录。
4. 现有结算函数使用加法封顶；v1.1 要求事件级饱和入账。
5. 现有 D2 来源主要是任务已结算状态动态；v1.1 服务值 D2 还必须引用 G0。
```

因此，不能在本切片中直接把 `创建服务值结算D2动作动态` 注册或调用为新本能方法。

## 阻塞点

需要先做一个权威迁移决策：

```text
服务值权威入口是否立即切换为 G0-only？
```

如果立即切换：

```text
没有 G0 的现有任务价值反馈服务分支必须入账 0；
需要先在自我线程或动作实现模块中生成 G0 候选 / 已确认视图；
再由 G0 驱动饱和入账。
```

如果保留旧链兼容：

```text
短期仍会存在“任务价值反馈四证据字段 -> 服务值增加”的旧入口；
这与“服务值只能由 G0 确认成功服务增加”的规范不完全一致；
必须在计划索引中标为过渡债务，不能宣称 v1.1 已落地。
```

## 推荐迁移路线

推荐选择 G0-only 迁移，但按小切片执行：

### P8c：生成 G0 的自然链路接入

目标：

```text
在私有_处理任务价值反馈_线程侧调用结算前，
用当前任务、来源需求、D0、D1、actual状态、服务对象状态变化集生成 G0 候选。
```

边界：

```text
G0 是治理视图，不是动作动态。
证据不足写候选池，不写服务值。
不新增当前服务事件E虚拟存在。
```

### P8d：服务值入账切换到 G0 饱和路径

目标：

```text
只有 G0 已确认且候选记录可结算时，服务值分支才调用饱和入账 helper。
无 G0 或 G0 未确认时，服务增量为 0。
安全值分支暂不混入服务 G0 规则。
```

边界：

```text
不让 D2 反向证明成功服务。
不把任务完成直接证明成功服务。
不把输出存在直接证明成功服务。
```

### P8e：旧服务四证据字段降级

目标：

```text
服务对象外在特征状态变化数 / 改善证据 / 可验证 / 可归因
只作为 G0 证据材料或候选缺口材料，
不再直接作为服务值增加硬开关。
```

## 当前结论

本切片遇到需要决策的阻塞：

```text
不能在不决定 G0-only 迁移的情况下安全修改服务值结算入口。
```

当前推荐：

```text
下一切片先做 P8c：G0 自然链路接入。
暂不新增普通服务本能方法。
暂不改旧服务值入账行为。
暂不宣称 v1.1 服务值结算已实现。
```
