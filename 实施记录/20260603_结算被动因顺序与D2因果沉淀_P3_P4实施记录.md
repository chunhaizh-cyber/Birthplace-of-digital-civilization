## 1. 本次目标

```text
1. 让结算 D2 的前置因从“任务完成”推进为“任务虚拟存在.任务状态 = 已结算”。
2. 结算前自动提交任务已结算状态，并回读任务状态动作动态。
3. 以任务已结算状态动作动态作为 D2 来源动作动态。
4. D2 生成后自动调用 按动态创建因果信息。
```

## 2. 修改文件

```text
自我线程模块.impl.cpp
自我动作实现模块.ixx
```

## 3. 代码链路

新的结算后处理顺序：

```text
任务满足反馈
-> 回写需求满足 D1
-> 收集正式结算证据
-> 提交任务状态 = 已结算
-> 回读任务状态动作动态
-> 以任务已结算动作动态作为结算被动因
-> 调用 结算叶子任务价值
-> 生成 D2 安全 / 服务结算动态
-> D2 自动调用 按动态创建因果信息
```

关键变化：

```text
1. 私有_处理任务价值反馈_线程侧 不再因为任务已结算直接跳过；
   已结算状态只表示被动因已具备，仍继续检查结算被动果是否已生成。

2. 私有_处理任务价值反馈_线程侧 在调用结算方法前，
   必须先调用 私有_提交任务已结算状态_线程侧。

3. 若任务已结算状态动作动态缺失，则阻断 D2，
   记录 “任务已结算状态动作动态缺失”，不假装被动因成立。

4. 私有_调用结算叶子任务价值本能方法_线程侧
   现在要求任务状态为 已结算。

5. 结算叶子任务价值 本能动作内部也要求：
   输入任务状态 = 已结算，
   当前任务状态 = 已结算。

6. 输出叶子任务价值结算动作动态 在 D2 创建后调用：
   世界树.按动态创建因果信息(..., 枚举_因果来源类型::执行生成, ...)
```

## 4. 边界

本切片仍不做：

```text
1. 不把结算叶子任务价值放回普通任务筹办。
2. 不让 被动动作 进入候选方法集。
3. 不扫描同一任务同时满足的多个需求。
4. 不补需求满足动态和 OR 令牌动态的初始状态 / 结果状态。
```
