# P5b 零权重需求任务化闸门纠偏记录

日期：2026-06-05

## 背景

P5a 追因确认：

```text
自检学习 / 练习型候选已经正式入树；
方法维护父需求和自检正式需求均可能是 0 安全权重 / 0 服务权重；
当前活动需求任务化扫描把 0 安全权重 && 0 服务权重 当作 continue 条件；
因此主动学习治理需求没有进入任务创建和任务筹办。
```

用户修正口径：

```text
不能以安全 / 服务权重作为任务化限制条件。
权重只应影响排序、压力、调度优先级或价值预算，
不能决定一个有效需求是否允许创建承接任务。
```

## 修改

修改文件：

```text
自我线程模块.impl.cpp
```

修改内容：

```text
1. 新增 私有_需求可提交活动任务化意图_线程侧。

2. 活动需求任务化扫描不再用：
       安全权重 == 0 && 服务权重 == 0
   作为拒绝条件。

3. 新准入条件改为：
       需求节点存在；
       不是结构根；
       未截止；
       需求目标未满足；
       不存在未满足的活动直接子需求；
       目标语义允许进入普通候选方法筹办；
       目标宿主、目标特征、当前状态、目标状态、满足关系完整。

4. 若 0 安全权重 / 0 服务权重 的需求成功创建承接任务，
   记录：
       自我线程/活动需求任务化零权重需求承接
   用于后续真实日志验证。
```

## 边界

```text
本切片只修正“权重不得作为任务化准入闸门”。

仍未解决：
    自检学习维护目标目前仍可能使用 条件结果对命中次数；
    后续还需要把正式需求目标纠偏为 方法状态，
    条件结果对命中次数只保留为证据 / 缺口条件。
```

## 预测验证点

下一次真实运行中，如果自检学习 / 练习型方法维护需求仍入树，应观察：

```text
自我线程/自检正式需求入树；
自我线程/活动需求任务化零权重需求承接；
任务管理界面线程收到对应需求的任务创建请求；
随后任务筹办开始对该学习维护需求进行候选方法填充。
```

若仍未进入任务筹办，则下一堵点应继续追：

```text
任务创建承接；
同方法活跃学习任务去重；
目标特征与学习本能结果能力匹配。
```
