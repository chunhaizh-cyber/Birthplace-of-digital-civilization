# 20260627 P2a 扫描需求激活入口核查 Codex断点清单

## 0. 恢复摘要

当前切片：

```text
P1c 因果链驱动扫描需求自然生长计划 v0.1 / P2a
扫描可启动到扫描入账需求激活入口核查。
```

本切片只读结论：

```text
1. 现有目标观察约束桥具备扫描等待项所需结构：
   目标存在ID、目标特征类型ID、目标特征当前值、来源报告ID、来源帧ID、
   约束generation、目标特征generation、来源材料generation、定位材料和有效期。

2. 现有目标观察约束桥能从扫描可启动走到扫描等待项：
   稳定子集桥写入目标观察约束；
   任务管理按 `已识别区域扫描入账状态` 读取可用约束；
   然后提交已识别场景扫描变化等待项。

3. 现有目标观察约束桥不是正式需求来源：
   目标观察约束结构没有目标状态值；
   `自我_提交目标观察约束特征组` 的结果特征是 `目标观察约束写入状态`，
   不是扫描需求目标 `已识别区域扫描入账状态`；
   该方法日志明确标记 `不提交需求满足=1`、`不结算安全值=1`。

4. 扫描报告回来后，自我线程会围绕 `已识别区域扫描入账状态`
   确保 6146 扫描入账子需求 / 任务主体。
   但这是“扫描材料承接之后”的治理链，不是“扫描可启动当下”的需求自然生长。
```

当前判断：

```text
P2a 缺口归类为 B：需求派生入口补齐。

不是 A：因果初始模板补齐。
    因为当前缺的不是因果类生成能力，而是扫描可启动成立后，
    何处把 `已识别区域扫描入账状态` 正式提交为需求目标。

不是 D：只能等待真实扫描后天证据增强。
    因为目标观察约束桥已经具备前置结构材料，可以触发扫描等待项；
    缺的是把该桥纳入需求自然生长的入口，而不是缺真实扫描执行后的因果沉淀能力。

暂不直接实现。
原因是当前桥支持多个稳定子集目标，而现有输出场景 `派生需求` 标记更像单缺口承载；
若直接在稳定子集循环内多次写 `派生需求`，可能覆盖前一个目标或重新引入
`已识别区域扫描入账状态` 重复子需求增长风险。
```

下一步：

```text
登记 P2b：扫描入账需求派生入口最小实现方案。

P2b 必须先确定：
1. 多个稳定子集扫描目标如何提交为多个正式需求，而不是覆盖同一个输出场景派生需求标记。
2. 同一父需求下如何复用已有 `已识别区域扫描入账状态` 子需求，避免重复生长。
3. 入口放在外设对应事实提交链、任务管理等待项桥，还是自我线程承接入口。
4. 是否可复用现有 `构造新增原子需求指令(...)` / 派生需求消息草案，
   不新增主信息字段或新结构体。
```

禁止宣称：

```text
不宣称扫描需求自然生长闭合。
不宣称目标观察约束桥等于正式需求来源。
不宣称扫描执行后主动因果可以替代扫描需求冷启动因果。
不宣称自我苏醒完成或初步成熟完成。
```

## 3. P2a 结论

```text
P2a 已完成只读核查。

当前最小缺口不是因果模板，也不是动作动态；
而是扫描可启动成立后，如何把多个稳定子集目标以结构化方式正式提交为
`已识别区域扫描入账状态` 需求。

下一步应进入 P2b：
扫描入账需求派生入口最小实现方案。

P2b 先只定函数边界：
    优先复用已有需求派生消息 / 需求类去重 / 自我线程提交入口；
    不新增主信息字段；
    不新增目标观察约束结构；
    不把目标观察约束当事实主体；
    不恢复旧的重复扫描需求增长路径。
```
