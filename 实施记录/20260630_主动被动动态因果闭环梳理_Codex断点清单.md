## 2. 代码现状证据

### 2.1 结构承载

`基础信息主信息类.h:497-515` 的 `动态节点主信息类` 已有初始状态、结果状态、动态主体、动态特征、来源动作、来源动作名、输入 / 输出场景、执行结果、动态层级和来源低层动态，结构上能承载动态证据链。

`基础信息主信息类.h:903-923` 的 `因果主信息类` 已有条件模板、因方法模板、因动作名称、因动作语义键、果模板、主果迁移模板和证据动态样本，结构上能承载状态变化因果和动作致变因果的抽象信息。

### 2.2 动态类型推导

`动态类.cpp:184-194` 当前按字段推导动态类型：

```text
有 来源动作.指针 -> 主动动作动态
有 来源动作名，或无状态端点但有主体 / 特征 -> 被动动作动态
否则 -> 无动作状态变化动态
```

风险点：任务状态、方法状态等被动提交入口调用 `创建方法动作动态(...)` 时会携带提交来源方法，同时 `来源动作名` 写 `被动动作`。由于动态类型推导优先看 `来源动作.指针`，这类被动提交动态可能被推导为 `主动动作动态`，需要后续代码门禁用动作语义或提交来源语义再排除。

### 2.3 默认动态到因果回写链

`动态类.h:13-18` 默认 `动态创建后处理选项::生成动态二次特征 = true`。

`动态类.cpp:1209-1403` 的 `创建动态(...)` 在节点创建后默认调用 `世界树.获取动态二次特征(*节点)`。

`二次特征应用模块.ixx:1328-1333` 默认开启因果模板匹配和命中回写因果证据动态。

`二次特征应用模块.ixx:2094-2097` 在命中回写开启时调用 `私有_回写因果模板命中(...)`。

`二次特征应用模块.ixx:1305-1312` 的回写函数调用 `世界树->生成因果信息(...)`。

结论：当前代码已有“动态创建 -> 二次特征 -> 因果生成 / 证据回写”的默认骨架，不能说动态到因果完全断开。

### 2.4 动作致变门禁风险

`因果类.cpp:2448-2456` 当前以“动态类型不是 `无动作状态变化动态`”设置 `有动作`。

`因果类.cpp:2534-2570` 只要 `有动作` 就进入动作致变关系查找 / 创建，并把 `来源动作`、`动作语义键`、`来源动作名` 写入 `因果主信息类`。

`因果类.cpp:742-785` 的动作模板命中逻辑主要检查来源方法、动作语义键和动作名称；未在该处直接把 `被动动作动态`、`被动动作`、提交动作或结算动作排除出可执行动作致变关系。

结论：现有代码存在部分闭环骨架，但不满足本次新口径下的完整闭环。缺口不是缺少因果主信息结构，也不是没有动态到因果入口；缺口是主动 / 被动门禁不够锐利，尤其是被动提交动态可能因为携带提交来源方法而被纳入动作致变因果。

### 2.5 典型被动提交调用点

`自我动作实现模块.ixx:8551-8564` 方法域状态提交使用 `创建方法动作动态(...)`，来源方法为提交方法首节点，动作名为 `词_被动动作()`。

`自我动作实现模块.ixx:10378-10391` 任务状态被动提交同样使用 `创建方法动作动态(...)`，来源方法为提交方法首节点，动作名为 `词_被动动作()`。

`自我动作实现模块.ixx:12249-12279` 叶子任务价值结算会创建方法动作动态并显式调用 `世界树.生成因果信息(...)`。结算动态可以解释价值如何入账，但不能反向证明上游主动业务动作已经可执行。

```text

```
