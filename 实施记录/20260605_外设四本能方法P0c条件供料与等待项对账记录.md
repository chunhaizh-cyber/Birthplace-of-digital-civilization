## 总结论

```text
1. 方法规格已声明结构化形参、条件节点、结果表和结果能力；不再以旧外设提交包组织状态作为三方法执行闸门。
2. 任务筹办仍按“先填充候选集，再从候选集中选择当前方法”推进，未把任务筹办 / 任务执行恢复为本能方法。
3. 任务管理等待项在工作结果应用尾部按当前方法供料要求创建；等待项只入外设线程通信队列，并记录 直接写需求树=0、直接写世界树=0。
4. P0c 发现四个后续必须处理的残留：
   - 观察 / 验证入口没有接入任务管理等待项映射；
   - 等待项口径仍先检查旧的 外设识别 / 扫描 / 跟踪结果场景状态，实际三方法当前主要靠兼容本能ID兜底映射；
   - 识别规格声明 外设观察材料可回查状态，但执行路径未显式读取该条件；
   - 跟踪执行在缺 目标存在 时会退回 当前观察存在，和“跟踪是盯一个”的计划口径不完全一致。
```

```text
    当前观察候选存在验证状态
    已确认观察存在生成条件明确状态
    外设观察验证材料明确状态

    外设观察材料可回查状态 == 1
```

执行路径：

```text
读取最新 D455 逐簇识别报告；
逐项解析原始帧、深度帧、空间候选、像素归属材料和候选簇投影；
```

对账判断：

```text

但任务管理等待项映射只覆盖识别 / 扫描 / 跟踪，没有覆盖该观察 / 验证入口。
因此当该方法作为当前方法且缺 D455 报告时，任务管理当前不会按方法供料要求创建观察等待项。
```

### 识别

规格声明：

```text
形参：
    输入条件包
    目标宿主
    当前方法运行存在

条件：
    外设像素簇候选验证状态
    外设观察材料可回查状态

结果能力：
    外设观察存在候选确认方案取得状态 == 1
    当前观察范围可观测单位存在稳定对应事实取得状态 == 1
    扫描可启动状态 == 1
```

执行路径：

```text
读取最新 D455 逐簇识别报告；
从目标宿主或输出场景读取 外设像素簇候选验证状态 / 外设观察像素簇候选已验证状态；
构造外设观察存在确认方案；
缺报告或候选验证未通过时写 失败原因=当前方法条件不满足，并派生 外设像素簇候选验证状态 补齐需求；
成功时写候选确认数量、稳定对应数量、扫描可启动状态和动作动态。
```

对账判断：

```text
识别已撤出旧外设提交包组织函数壳，结果写入正式状态特征；
但执行路径没有显式读取规格中声明的 外设观察材料可回查状态，
仍是通过最新报告和候选验证状态间接判断材料可用。
该项需要后续切片把规格条件和执行条件统一。
```

### 扫描

规格声明：

```text
形参：
    输入条件包
    当前观察存在
    历史观察存在
    目标宿主
    当前方法运行存在

条件：
    当前观察存在

结果能力：
    观察存在发现状态 == 已发现
    观察存在变化结果 == 已生成
    已识别区域扫描入账状态 == 已生成
```

执行路径：

```text
解析 当前观察存在 和 历史观察存在；
没有 当前观察存在 时返回 当前方法条件不满足；
首次扫描有当前存在、无历史存在时，只写发现事实和扫描入账状态，不写变化动态；
有历史存在时，计算匹配关系、变化结果和变化事件，并写动作动态。
```

对账判断：

```text
扫描的结构化缺口路径存在；
任务管理等待项要求扫描目标带有 目标区域或目标簇，缺目标时拒绝创建扫描等待项；
但计划要求的扫描范围、归属绑定、上一轮基准、目标特征值域等条件尚未在规格条件节点中完整声明。
```

### 跟踪

规格声明：

```text
形参：
    输入条件包
    目标存在
    目标宿主
    当前方法运行存在

条件：
    目标存在

结果能力：
    目标存在跟踪状态 == 已更新
    目标观察窗口状态 == 已更新
```

执行路径：

```text
先从输入 / 输出 / 目标宿主读取 目标存在；
如果没有目标存在，则退回解析 当前观察存在；
有目标存在时写 目标存在跟踪状态、目标观察窗口状态、目标存在特征变化动态和动作动态；
没有任何目标时返回 当前方法条件不满足。
```

对账判断：

```text
任务管理等待项要求跟踪目标带有 目标区域或目标簇，缺目标时拒绝创建目标跟踪等待项；
但方法执行本身仍允许从 当前观察存在 兜底成跟踪目标。
这会弱化“跟踪是盯一个，不是看全场”的计划边界，后续应改为缺目标时只输出结构化缺口。
```

## 等待项生成路径

代码锚点：

```text
任务模块.管理界面线程.impl.cpp
    私有_外设观察需求口径_按方法供料要求
    私有_按方法供料要求构造外设观察等待项
    私有_工作结果需要方法供料等待项
    私有_按当前方法供料要求提交外设等待项
    工作结果应用尾部调用 私有_按当前方法供料要求提交外设等待项
```

生成条件：

```text
任务未完成；
且 工作结果.需要等待 == true，
或 方法已执行但推进失败 / 错误码非 0；
且 当前方法可映射为识别 / 扫描 / 跟踪口径；
且扫描 / 跟踪具备目标区域或目标簇。
```

等待项内容：

```text
识别：
    观察运行模式=陌生环境逐簇识别
    期望报告类型=逐簇识别报告
    最大允许报告年龄=120000ms
    可无目标区域或目标簇

扫描：
    观察运行模式=已识别场景扫描变化
    期望报告类型=扫描变化报告
    最大允许报告年龄=60000ms
    必须有目标区域或目标簇

跟踪：
    观察运行模式=目标跟踪观察
    期望报告类型=跟踪报告
    最大允许报告年龄=30000ms
    必须有目标区域或目标簇
```

边界：

```text
等待项是任务管理线程与外设线程之间的工程通信材料；
等待项不写需求树，不写世界树；
日志显式记录：
    按目标特征名映射=0
    直接写需求树=0
    直接写世界树=0
```

## 文本兜底残留

```text
1. 当前等待项映射先检查旧结果能力名：
       外设识别结果场景状态
       外设扫描结果场景状态
       外设跟踪结果场景状态
   P0a 直接重构后，三方法已不再声明这些旧结果能力。

2. 映射失败后退回 自我能力值 / 本能方法ID：
       自我_识别外设观察材料 -> 识别
       自我_扫描已识别区域 -> 扫描
       自我_跟踪指定存在 -> 跟踪
   日志中的 来源=兼容本能ID 会暴露该路径。

3. 等待项质量要求摘要仍是文本串，但当前可见决策分支使用的是枚举口径、报告类型、运行模式、目标区域或目标簇；
   该文本应保持诊断 / 显示用途，不应成为机器判定字段。
```
