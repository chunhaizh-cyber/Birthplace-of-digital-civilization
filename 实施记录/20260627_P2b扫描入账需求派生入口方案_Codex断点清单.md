# 20260627 P2b 扫描入账需求派生入口方案 Codex断点清单

## 0. 恢复摘要

当前切片：

```text
P1c 因果链驱动扫描需求自然生长计划 v0.1 / P2b
扫描入账需求派生入口最小实现方案。
```
本切片只读结论：

```text
1. 多个稳定子集扫描目标不能压成一个输出场景派生需求标记。
   应按“一个目标观察约束中的目标存在 + 已识别区域扫描入账状态”生成一条正式派生需求消息。

2. 现有目标观察约束集合读取已经按目标存在去重。
   任务管理等待项桥当前也是逐目标约束循环提交等待项，因此多目标提交不需要新增结构体。

3. 正式入树边界应放在自我线程 / 需求类裁决入口。
   目标观察约束桥只提供扫描目标材料，不直接成为事实主体，也不直接写需求树。

4. 最小方案应拆成两段：
      A. 外设对应事实提交链写入目标观察约束；
      B. 任务管理扫描约束消费处，为每个目标约束生成现有 `结构_任务管理派生需求消息`，
         经任务管理上行消息进入自我线程，再由 `私有_确保派生需求节点` / `需求类::执行更新指令` 裁决入树。

5. 同父需求去重已有两层可复用：
      A. 自我线程 `私有_确保派生需求节点` 会按同父需求、同目标主体、同目标特征、同目标状态和满足关系复用同目标子需求；
      B. 需求类 `执行更新指令` 的新增子需求路径还会按目标重叠合并直接子需求。

6. P2c 不能直接复用“外设等待项已提交”当需求已生成。
   需要新增或复用任务管理上行派生需求消息生成函数，且必须补齐消息幂等键和当前 / 目标状态节点。
```

当前判断：

```text
P2b 已闭合为方案切片。

下一步进入 P2c：扫描入账派生需求消息最小接入。

P2c 只允许复用现有消息结构和需求入树裁决链：
    结构_任务管理派生需求消息
    结构_任务管理上行消息
    自我线程派生需求落账入口
    需求类::构造新增原子需求指令
    需求类::执行更新指令

P2c 暂不新增结构体、主信息字段、并行需求账本或新因果结构。
```

禁止宣称：

```text
不宣称扫描需求自然生长闭合。
不宣称目标观察约束桥等于正式需求来源。
不宣称外设等待项提交等于需求已生成或已满足。
不宣称扫描执行后的主动因果可以替代扫描需求冷启动因果。
不宣称自我苏醒完成或初步成熟完成。
```

## 2. P2b 判定

### 2.1 多目标提交方式

结论：

```text
多个稳定子集扫描目标应生成多条正式派生需求消息。

基本单元：
    来源父需求
    + 目标存在ID
    + 目标特征类型ID = 已识别区域扫描入账状态
    + 当前状态值 = 目标观察约束.目标特征当前值
    + 目标状态值 = 1
    + 满足关系 = 等于
```

证据：

```text
外设观察报告队列.ixx:3089-3129
    读取可用目标观察约束集合_按目标特征(...)
    已按目标特征筛选，并按目标存在去重。

任务模块.管理界面线程.impl.cpp:4396-4433
    当前稳定子集等待项桥逐目标观察约束循环处理；
    每个等待项携带目标存在ID、目标特征类型ID、当前值、约束generation 和目标观察约束ID。
```

判断：

```text
现有约束集合已经是“多目标列表”，不用新增多目标结构。
P2c 只需要在每个约束循环项上构造一条派生需求消息。
```

### 2.2 同父需求去重

结论：

```text
同一父需求下，应复用已有 `已识别区域扫描入账状态` 子需求。
去重主键不靠日志文本，也不靠输出场景单标记，而靠正式需求目标结构：
    父需求
    目标宿主
    目标特征类型
    目标状态语义
    满足关系
```

证据：

```text
自我线程模块.impl.cpp:10281-10302
    `私有_确保派生需求节点` 先查找同目标子需求；
    命中后补齐主信息并返回已有需求。

需求类.h:1168-1170
    `添加子需求节点_已加锁` 再次按目标重叠查找直接子需求；
    命中后合并需求主信息并返回已有子需求。

自我线程模块.impl.cpp:13289-13305
    扫描报告承接后已有 `私有_确保扫描入账子需求_线程侧`，
    其底层复用 `私有_确保目标I64子需求_线程侧`。
```

判断：

```text
P2c 不应新增专用去重表。
优先复用自我线程派生需求入树去重和需求类目标重叠合并。
```

### 2.3 入口归属

结论：

```text
入口采用两段式：

第一段：外设对应事实提交链
    只写目标观察约束和稳定子集扫描可启动材料；
    不直接写需求树；
    不把目标观察约束当事实主体。

第二段：任务管理扫描约束消费处
    从可用目标观察约束集合生成一目标一条派生需求消息；
    派生需求消息通过任务管理上行消息进入自我线程；
    自我线程执行正式入树裁决。
```

不选方案：

```text
不选外设对应事实提交链直接写需求：
    该链缺正式需求裁决权，且目标观察约束没有目标状态值。

不选扫描报告回来后才作为主入口：
    那是扫描执行后的材料承接链，只能补后天证据，不能证明“扫描可启动当下自然生长扫描需求”。

不选任务管理等待项桥直接记需求满足：
    等待项只是外设执行通道，不是正式需求节点，也不是需求满足证据。
```

P2c 最小补齐点：

```text
1. 在任务管理稳定子集扫描约束消费处，增加一目标一条派生需求消息生成函数。

2. 派生需求消息必须补齐：
      父需求
      目标主体
      目标特征类型
      当前状态
      目标状态
      满足关系
      幂等键
      是否需要外部支撑 / 是否建议线程重判等治理标记。

3. 当前状态和目标状态必须是状态节点：
      当前状态 = 目标存在.已识别区域扫描入账状态 当前值
      目标状态 = 目标存在.已识别区域扫描入账状态 1
   不能用目标观察约束字段、日志文本或等待项摘要冒充状态。

4. `私有_任务管理上行消息幂等键` 当前只处理观察事实承接和执行前许可。
   P2c 需要补派生需求消息幂等键分支，否则同一约束可能重复上行。

5. 若 P2c 选择在任务管理侧物化状态，需要先核查该函数是否能合法取得自我内部世界 / 承载场景。
   若不能，P2c 必须改为自我线程侧物化状态，不能在任务管理侧裸造状态。
```
