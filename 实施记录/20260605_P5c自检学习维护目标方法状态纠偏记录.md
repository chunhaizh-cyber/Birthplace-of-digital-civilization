# P5c 自检学习维护目标方法状态纠偏记录

日期：2026-06-05

## 背景

P5 / P5a / P5b 已确认：

```text
自检线程已经能够产生练习型方法维护候选；
候选经自我线程可正式入树；
零安全权重 / 零服务权重不应再阻断任务化；
但当前自检学习维护需求的正式目标仍可能写成 条件结果对数量 或 条件结果对命中次数。
```

规范口径：

```text
方法类自检的正式需求目标特征应收束为 方法状态；
自检维护总目标应表达为 方法状态 达到 好用；
条件结果对数量、条件结果对命中次数、连续成功次数只作为证据、缺口条件或日志显示；
第一次承接好用目标时应由 自我_练习 处理；
练习发现缺条件结果对后，再派生 方法状态 达到 可用 的前置需求，由 自我_尝试学习 承接。
```

## 本切片修改边界

计划只修改：

```text
自检线程模块.impl.cpp
需求类.cpp
鱼巢.cpp
```

目标：

```text
1. 自检线程生成练习型正式需求时，原子目标特征改为 方法状态。
2. 缺条件结果对或缺命中次数时，正式目标统一为 方法状态 >= 好用。
3. 条件结果对数量 / 条件结果对命中次数继续保留在证据摘要和缺失结构类型中。
4. 不在任务筹办中直接调用 自我_练习 / 自我_尝试学习。
5. 不改写学习本能方法对目标方法虚拟存在的落账边界。
6. 需求类只允许 方法状态 这种有序枚举目标使用 >=；普通枚举目标仍保持等于比较闸门。
7. 命令行只扩展既有 `--self-check-log` 的等待毫秒参数，用于真实日志长跑验证；不新增模拟入口、夹具入口或回归检查入口。
8. 活动任务化只补 方法状态 目标需求的扫描诊断，不改变任务化准入和排序。
```

## 预测验证点

真实运行中如果再次出现自检学习维护正式需求，应观察：

```text
自检正式需求入树；
目标特征为 方法状态；
证据摘要中仍包含 条件结果对数量 / 条件结果对命中总数 / 条件结果对最大命中次数；
后续活动任务化不因零权重跳过；
任务筹办按 方法状态=好用 目标召回 自我_练习 的结果能力。
```

若真实运行没有自然产生新的自检学习维护正式需求，本切片只能验证：

```text
代码构建通过；
真实 --self-check-log 运行退出；
日志未出现目标特征仍为 条件结果对命中次数 的新正式入树样本。
```

## 二次预测验证点

首次真实运行若暴露 `方法状态 >= 好用` 被枚举目标等于闸门拒绝，则按规范中“方法状态达到或超过目标状态”的口径，只放行 `方法状态` 的大于等于比较。

二次真实运行应观察：

```text
不再出现 目标特征=方法状态 且 说明=枚举目标只能使用等于比较符 的拒绝日志；
若再次产生自检学习维护正式需求，应继续进入活动需求任务化或暴露下一个更靠后的具体堵点；
普通枚举目标仍不能因本切片获得 >= 入树能力。
```

## 三次预测验证点

若短跑 `--self-check-log` 在自检正式需求刚入树后立刻停止，则使用既有自检日志入口的等待参数延长真实运行时间。

三次真实运行应观察：

```text
自检正式需求入树后，线程仍继续运行至少一个活动需求任务化周期；
若学习维护需求可任务化，应出现 来源需求=新需求 的任务创建 / 活动需求任务化 / 任务筹办日志；
若没有出现，应以日志中的活动扫描条件、停止检查或目标过滤原因作为下一堵点。
```

## 四次预测验证点

若长跑仍未看到 `来源需求=6/7/8` 被任务化，则补充活动任务化扫描诊断。

四次真实运行应观察：

```text
出现 自我线程/活动需求任务化方法状态扫描诊断；
若扫描=0，说明方法维护分支需求未进入当前活动任务化扫描列表；
若扫描>0 且已提交=0，应由拒绝原因定位具体准入条件；
若已提交>0，应继续核对任务筹办是否按 方法状态>=好用 召回 自我_练习。
```

## 五次预测验证点

四次 8 秒真实运行已观察到方法状态正式需求入树，但未观察到方法状态任务化扫描诊断。

因此延长既有 `--self-check-log` 等待窗口到 20 秒，用于区分：

```text
1. 如果只是等待窗口不足：
   应在方法状态需求入树后，出现 自我线程/活动需求任务化方法状态扫描诊断；
   或出现 来源需求=6/7/8/C/D/E 的任务创建 / 活动需求任务化 / 任务筹办日志。

2. 如果仍未出现：
   说明当前真实流程中，自检方法维护需求入树后没有进入下一轮活动需求任务化通道；
   需要把堵点收束为 自检正式需求入树 -> 活动需求任务化调度之间的时序 / 冻结 / 停止检查问题。

3. 禁止把 20 秒未观察到任务化解释为学习闭环完成；
   只能记录为真实日志未通过，继续按日志锚点追任务化调度链。
```

## 六次预测验证点

五次 20 秒真实运行已观察到：

```text
方法动作数量缺口能够被任务化；
任务筹办能按统一候选逻辑命中学习本能 自我_定向学习；
但学习本能自身的真实单步入口仍被转成 方法可执行入口数量 缺口；
20 秒窗口结束时，该 16x 缺口的上行消息仍在排队 / 落账边界附近。
```

因此延长既有 `--self-check-log` 等待窗口到 30 秒，用于确认 16x 缺口是否自然进入下一轮任务化。

六次真实运行应观察：

```text
1. 如果 16x 可执行入口缺口能自然任务化：
   应出现以 方法可执行入口数量 为目标的新需求任务化；
   任务筹办候选应命中 自我_提交方法可执行入口；
   随后由任务执行调用 自我_提交方法可执行入口，而不是任务筹办直调。

2. 如果仍只反复生成 16x 缺口：
   堵点收束为 提交方法可执行入口 的结果能力 / 目标特征 与 方法可执行入口数量 缺口不匹配；
   或 16x 派生需求未进入普通任务化通道。

3. 禁止恢复任务筹办现场调用 提交方法可执行入口；
   只能通过任务化、统一找方法、任务执行验证入口提交链。
```

## 用户修正后的停点口径

当前不是自检目标口径问题，也不是任务筹办直调问题；也不应继续把 `16x` 解释为需要立即修复的任务化异常。

用户确认：

```text
定向学习的后续逻辑是：
    全局查找符合目标的动作动态；
    或从动作动态中提炼动作；
    或通过模仿形成候选动作 / 候选入口。

这部分以后再实现。
```

因此 P5c 的停点应收束为正常能力边界：

```text
学习本能缺真实单步入口
-> 任务筹办按规范转成 方法可执行入口数量 缺口
-> 任务管理工作线程生成 16x 派生需求消息
-> 自我线程收到 任务管理派生需求 上行消息
-> 需要定向学习从全局动作动态 / 动作提炼 / 模仿中形成候选动作入口
-> 当前定向学习尚未实现该能力
```

已确认的边界：

```text
方法可执行入口数量(16x) 派生消息已经产生；
自我_提交方法可执行入口(6081) 是最终提交已明确入口的本能方法；
但在入口候选尚未从动作动态 / 提炼 / 模仿中形成时，不应强行调用 6081；
当前不实现定向学习，因此本计划停在可解释的后续能力边界。
```

同时，方法状态维护正式需求虽然已经自然入树，但本轮没有出现 `自我线程/活动需求任务化方法状态扫描诊断`。这说明还不能宣称 `方法状态>=好用` 需求已经进入常规活动任务化扫描；当前只能证明自检入树和更靠后的 8b / 16x 缺口链路暴露出来。
