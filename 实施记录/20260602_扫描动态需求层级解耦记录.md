# 扫描动态需求层级解耦记录

日期：2026-06-02

## 用户修正

```text
只要发现一个存在就可以开始扫描获取动态。
```

因此需求层级必须避免：

```text
当前场景特征值明确状态
-> 全部可观测单位稳定对应闭合
-> 扫描
```

这种串行误读。

## 定案

`当前场景特征值明确状态` 只负责：

```text
当前观察范围全部有效可观测单位稳定对应存在。
```

`扫描可启动状态` 由同一个对应事实派生，但不是 `当前场景特征值明确状态` 的完成子需求：

```text
当前观察范围可观测单位存在对应事实
-> 稳定对应存在数量 >= 1
-> 扫描可启动状态
-> 当前观察范围稳定对应存在动态取得状态
-> 首次发现动态 / 后续变化动态
```

也就是说：

```text
全闭合用于写 当前场景特征值明确；
发现一个稳定对应存在用于启动扫描；
两者同源但不是父子完成关系。
```

## 禁止回退

```text
不得把扫描型 / 跟踪型子需求作为 当前场景特征值明确状态 的完成条件；
不得等待全观察范围闭合后才启动已稳定对应存在的扫描；
不得把扫描可启动等同于当前场景特征值明确；
不得把第一次扫描写成变化动态。
```
