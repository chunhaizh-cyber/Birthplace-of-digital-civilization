## 3. 架构缺陷清单

### D1 短命令必须完整冷启动运行环境

现象：

```text
--demand-tree-growth-summary 只是读取诊断摘要，但仍强制初始化自我环境。
本次耗时 9673ms，其中自我初始化 9565ms，默认本能方法规格确认 6533ms。
```

代码证据：

```text
鱼巢.cpp:956 私有_确保自我环境已初始化
鱼巢.cpp:970 成功后再次确认默认本能方法专属规格集
鱼巢.cpp:1493 需求树生长摘要入口仍调用初始化确保
自我线程模块.impl.cpp:13988 自我线程类::自我初始化
自我线程模块.impl.cpp:14005 初始化中确认默认本能方法专属规格集
自我动作实现模块.ixx:8081 确认默认本能方法专属规格集
```

影响：

```text
任何一次短命令、HTML 输出或摘要读取，只要新起进程，就要支付 9-10 秒冷启动成本。
进程内快路径只能减少同一进程内重复调用，不能解决“短命令每次新进程”的固定成本。
```

修复方向：

```text
1. 明确拆分命令模式：
   A. 纯读取最近持久快照 / 最近运行日志的离线诊断命令；
   B. 需要真实运行环境的 live 命令。
2. live 命令保留完整初始化；离线诊断命令不得调用 初始化自我环境。
3. 如果必须 live 读取，继续保留当前语义，但输出应明确“本次耗时主要为冷启动”。
```

优先级：P1。  
理由：影响所有短命令体验，但不直接解释常驻运行中 13 秒级任务巡检。

### D2 初始化结果读取不是纯只读

现象：

```text
读取初始化结果的函数会调用 世界树.初始化存在概念系统()。
这使错误报告、诊断读取和初始化状态判断带“确保 / 创建”副作用。
```

代码证据：

```text
自我类.初始化.cpp:998 私有_计算自我初始化结果
自我类.初始化.cpp:1011 结果.概念层已就绪 = 世界树.初始化存在概念系统()
自我类.初始化.cpp:1222 读取自我初始化结果

鱼巢.cpp:972 初始化失败分支读取初始化结果
自我线程模块.impl.cpp:16601 线程侧读取初始化结果
```

影响：

```text
诊断路径难以变轻；
只读检查可能拿写路径或初始化锁；
后续要做离线 / 轻量摘要时，无法清晰保证“读取不创建结构”。
```

修复方向：

```text
1. 拆出 只读检查存在概念系统已就绪()。
2. 私有_计算自我初始化结果 只读模式只检查，不确保。
3. 显式初始化路径继续调用 世界树.初始化存在概念系统()。
4. 日志中区分 只读检查 和 显式确保。
```

优先级：P1。

```text

2. 后台循环优先消费完成队列和脏任务，不每轮全树巡检；
3. 全量巡检降为低频兜底，且带冷却和预算；
4. 不可推进任务只有状态版本变化时才重复记录详细日志。
```

优先级：P0。  
理由：已有真实日志证明常驻路径单轮可超过 13 秒。

```text
4. 索引失败必须回退全量扫描并记录原因；
5. 与全量扫描基线比对候选结果一致后再启用。
```

优先级：P2。  
理由：目前已有增长风险，但任务巡检和冷启动更明确。

### D5 基础信息底层缺主键 / 类型 / 子节点业务索引

现象：

```text
基础信息主键查找和按类型枚举仍是链表扫描。
子特征 / 子存在按类型查找也先枚举子节点再筛选。
```

代码证据：

```text
双向链表模板核心.h:323 查找主键_已加锁
双向链表模板核心.h:326-329 遍历全链比较主键
基础信息类.h:66 枚举节点_按类型
基础信息类.h:71-75 遍历全链 dynamic_cast
特征类.cpp:1917 查找子特征_按类型
存在类.cpp:356 查找子存在_按类型
```

影响：

```text
大量 可解析引用.主键 -> 指针 的读取会叠加全链扫描；
控制面板、任务筹办、因果路径、状态解析、外设材料落账都会受影响；
规模增长后，P5 / P6 局部索引仍会被底层主键和类型扫描拖住。
```

修复方向：

```text
1. 基础信息树增加非权威、可重建的运行期索引：
   - 主键 -> 节点；
   - 主信息类型 -> 节点集合；
   - 父节点 + 主信息类型 -> 子节点集合；
   - 父节点 + 特征类型 / 存在类型 -> 子节点。
2. 添加、删除、更新主信息时同步索引版本。
3. 索引命中前后保留校验，失败回退链表扫描。
4. 不改变基础信息树的权威存储结构。
```

优先级：P2-P3。  
理由：影响面最大，但需要小心验证，不宜和 P0 任务巡检修复混做。

代码证据：

```text

```

影响：

```text

每条 flush 会放大磁盘 I/O；
在 D455 每帧多条长日志和任务巡检高频日志下，诊断证据本身会成为运行成本。
```

```text
4. 任务巡检不可推进重复日志按任务状态版本限流。
5. 日志模块增加丢弃计数 / 限流计数，避免静默吞证据。
```

优先级：P1-P2。  
理由：风险高且改动相对独立，但不能先于 P0 细分耗时，否则会遮蔽真实热点。
