# 20260602 需求 / 任务 / 方法结构化入口复查记录

## 复查目标

检查需求、任务、方法相关逻辑是否仍绕过现有数据结构，重点确认：

- 需求入树 / 更新是否走 `需求类::执行更新指令` 或正式需求提交方法。
- 任务状态是否走任务管理提交链或 `自我_提交任务状态变化`。
- 任务与需求关系是否有结构化绑定入口。
- 方法选择是否先填充候选方法集，再从候选集中选择当前方法。
- 动作动态是否绑定明确方法来源。

## 发现与处理

1. 任务侧缺少正式的“绑定对应需求”入口。
   - 已新增 `任务类::绑定对应需求`。
   - 任务创建与任务管理界面线程绑定关系时，改走该入口。

2. 自我线程主任务选择阶段存在隐式补写任务对应需求。
   - 已删除选择阶段的补写。
   - 任务来源需求与需求列表项不一致时，记录错误日志并跳过该任务。

3. 根需求权重刷新存在直接写主信息。
   - 已改为构造 `结构_需求树更新指令` 并通过 `需求类::执行更新指令` 提交。

4. 初始化链路保留了旧的“任务完成后直接同步需求当前状态 / 回退任务状态”函数。
   - 该函数未被当前链路调用，但与“回写需求满足 / 提交任务状态变化”边界冲突。
   - 已删除旧函数及其孤立 helper。

## 复查结论

当前命中的核心路径中：

- 需求满足的主信息写入集中在 `自我_回写需求满足` 正式提交方法内部，并输出需求满足动作动态。
- 任务状态写入集中在 `任务类` 内部初始化 / 辅助函数与 `自我_提交任务状态变化` 正式提交方法内部。
- 任务筹办 / 任务执行仍是任务管理生命周期普通函数，没有恢复为普通候选本能方法。
- 普通筹办路径保持“先填充候选方法集，再选择当前方法”。
