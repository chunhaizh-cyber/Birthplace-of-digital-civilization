# 20260606_P9外设四方法计划顺序与切片优化记录

## 本次目标

检查 `计划/20260606_外设四本能方法任务真实运行条件包闭环计划_v0.1.md`，优化执行顺序和切片颗粒度。

## 检查结论

原计划方向正确，但原顺序存在一个执行风险：

```text
P9b 先做“外设报告承接先行与任务重入”属于全局改造，
会同时触碰任务管理、自我线程、四方法输入和提交入口，
切片偏宽。
```

代码入口复核显示：

```text
1. D455 逐簇识别报告、扫描变化报告、跟踪报告生产入口已经存在。
2. 任务管理等待项巡检和外设消息承接入口已经存在。
3. 当前最小可闭合失败点是 6127 缺 D455 逐簇识别报告。
4. 扫描 / 跟踪必须排在识别写出已归属、扫描可启动、目标种子和基准之后。
```

## 调整内容

将 P9 顺序优化为：

```text
P9a 四方法条件包依赖矩阵对账
P9b 6127 观察验证最小闭环
P9c 6145 识别前置承接
P9d 识别结果到扫描 / 跟踪目标上下文桥
P9e 6146 扫描真实运行
P9f 6147 跟踪真实运行
P9g 提交入口和来源动作动态复验
P9h 端到端真实日志验证
```

关键调整：

```text
1. 不先做全局承接重入大改。
2. 先用 6127 闭合一条 报告 -> 条件包 -> 任务重入 链。
3. 只有 P9a 证明报告承接被任务派发暂停长期饿死时，才在 P9b 内补观察验证链专用承接先行安全步。
4. 将扫描 / 跟踪前的目标上下文桥单独切出，避免 6146 / 6147 裸运行。
5. 将提交入口复验从端到端验证中拆出，确保来源动作动态链单独验收。
```
