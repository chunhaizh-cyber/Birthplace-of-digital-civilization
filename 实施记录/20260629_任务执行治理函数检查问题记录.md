# 任务执行治理函数检查问题记录

记录时间：2026-06-29

## 0. 问题锚点

任务执行普通函数当前存在一个待统一整改点：

```text
任务执行阶段读取不到“可执行输入参数场景”时，会继续走兼容 fallback：
学习类方法使用当前场景引导执行；
普通方法尝试读取方法首个条件场景。
```

该逻辑容易把“执行阶段”扩展成“参数/条件兜底确定阶段”，与当前口径不完全一致。

## 1. 证据位置

```text
任务模块.执行.ixx:86-99
    私有_读取任务可执行输入参数场景_执行桥_最小_v0
    从任务虚拟存在读取“可执行输入参数场景”指针。

任务模块.执行.ixx:1414-1416
    执行任务读取任务场景与可执行输入参数场景。

任务模块.执行.ixx:1472-1484
    如果存在可执行输入参数场景，则作为本轮输入/条件场景；
    如果不存在，则走允许引导执行或方法首个条件场景 fallback。
```

## 2. 当前判断

```text
任务执行只应负责执行已经选定、已经就绪的当前方法。
方法需要的参数、参数来源、参数绑定、可执行输入参数场景构造，应在任务筹办/配对参数链中完成。
任务执行阶段缺少可执行输入参数场景时，更符合规范的处理应是形成执行缺口或等待重筹办，而不是在执行阶段继续补判条件场景。
```

## 3. 后续统一修改方向

```text
1. 先完成任务执行治理函数其余流程检查，不在当前点单独改代码。
2. 后续统一调整流程图与代码：
   - 将“存在可执行输入参数场景?”改为“读取筹办已形成的可执行输入参数场景”。
   - 缺失时返回执行缺口/等待重筹办。
   - 不在任务执行阶段补参数、配参数或重新决定普通方法条件场景。
3. 若保留学习类引导执行例外，必须单独按规范确认其边界，不能作为普通任务执行兜底。
```
