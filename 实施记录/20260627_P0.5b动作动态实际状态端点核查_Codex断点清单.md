本切片只读结论：

```text
1. 通用任务执行桥创建的是“方法调用过程证据”。
   它的动态主体是自我存在，动态特征是方法调用动作动态特征，

   因此它不能直接作为目标特征动作致变动态。

   它只能表达缺口或派生目标材料，不能冒充动作实际造成的结果端点。

3. 多条治理 / 扫描 / 服务结算路径已经具备完整状态端点：
   创建初始状态 + 创建结果状态 + 创建方法动作动态时传入两个状态。

4. 外设通用 helper `写入双目相机I64事实与动态(...)`
   已写入目标宿主 I64 事实，并创建一个结果状态，
   但创建方法动作动态时没有传入初始状态和结果状态。
   这是当前最明确的实际状态端点补齐点。
```

下一步建议：


## 4. P0.5b-2b 外设通用 I64 事实动作动态状态端点补齐

时间：2026-06-27

修改范围：

```text
自我动作实现.外设模块.ixx
    写入双目相机I64事实与动态(...)
```

实现策略：

```text
1. 写入新值前先读取目标宿主同特征旧 I64 值。
2. 只有旧值存在且旧值 != 新值时，才认为存在状态变化。
3. 状态发生变化时创建旧状态和结果状态。
4. 只有动作达成、状态发生变化、旧状态和结果状态都创建成功时，
   才把旧状态 / 结果状态传给 `世界树.创建方法动作动态(...)`。
5. 无旧值时，结果状态作为初始 / 基准状态，不生成完整动作致变端点。
6. 旧值等于新值时，只保留动作过程证据，不生成正向动作致变端点。
7. 动作未达成时，即使状态值变化，也不把端点挂到正向动作致变动态上；
   状态迁移底账仍由状态创建链自行处理。
```

验证前预测：

```text
1. Debug x64 构建应通过。
2. 代码不新增函数，不需要刷新函数说明文档。
3. 若真实运行自然命中外设通用 I64 写入，动作动态在旧值变化且动作达成时具备初始 / 结果状态端点。
4. 若真实运行未自然命中该路径，本切片只能标记为代码接入闭合 / 自然验证待条件。
```

### 4.1 新堵点：动作动态被状态迁移动态去重折叠

时间：2026-06-27

问题锚点：

```text
动态类.cpp
    动态类::创建动态(...)
    私有_查找已有状态动态(...)

自我动作实现.外设模块.ixx
    写入双目相机I64事实与动态(...)
```

证据：

```text
1. 状态类::创建状态(...) 写入状态后会自动调用 世界树.状态记录后刷新动态(...)。
2. 动态类::创建动态(...) 在存在初始状态 / 结果状态时，会按初始状态、结果状态、动态层级查找已有动态。
3. 方法动作动态若复用同一初始状态 / 结果状态，当前会命中已有状态迁移动态并直接返回，导致动作动态被状态迁移动态折叠。
```

当前判断：

```text
这与最新口径冲突：
    同一事实允许两种方式记录；
    状态迁移账用于确认变化；
    动作致变账用于方法选择和因果动作来源；
    二者只能通过同一存在、同一特征类型和双状态时间段包含关系做同源匹配，不能互相覆盖。
```

最小处理方案：

```text
1. 动态类.cpp：
    有来源动作 / 动作名的动作动态不得被无来源动作的状态迁移动态按同一双状态端点折叠。
    当动作动态携带初始 / 结果状态时，动态主信息时间应由两个状态时间派生。

2. 自我动作实现.外设模块.ixx：
    写入结果状态后复用状态记录链已经生成的状态迁移动态；
    从该状态迁移动态读取真实初始 / 结果状态端点；
    再创建动作致变动态，并通过来源低层动态引用该状态迁移动态。
```

验证前预测 R2：

```text
1. Debug x64 构建应通过。
2. 真实运行不应新增动态创建、空果模板或外设状态端点相关异常。
3. 若自然运行窗口未命中外设通用 I64 写入路径，只能记录代码接入闭合 / 自然验证待条件。
4. 若后续自然命中该路径，完整动作致变动态应满足：
    动态主体 = 被改变宿主；
    动态特征 = 被改变特征类型；
    初始 / 结果状态来自同源状态迁移动态；
    来源低层动态引用状态迁移动态；
    动态时间由初始 / 结果状态时间派生。
```
