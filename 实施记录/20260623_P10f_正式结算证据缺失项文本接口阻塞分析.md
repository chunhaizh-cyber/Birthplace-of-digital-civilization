# P10f 正式结算证据缺失项文本接口阻塞分析

## 0. 恢复摘要

当前切片：P10f-c 剩余 `摘要 / 原因 / 缺失证据` 字段复扫中的正式结算证据专项分析。

已复核锚点：

- `自我线程模块.impl.cpp::结构_线程结算因果投影预判::缺失证据 / 摘要`
- `自我线程模块.impl.cpp::结构_叶子任务正式结算证据::缺失证据 / 摘要`
- `世界树类::查询叶子任务目标投影层级`
- `因果类::查询叶子任务目标投影层级`

证据：

- `结构_叶子任务正式结算证据::缺失证据` 当前被 `私有_追加正式结算缺失证据_线程侧` 和 `私有_移除正式结算缺失证据_线程侧` 以文本项增删。
- `结构_线程结算因果投影预判::缺失证据` 来自 `世界树.查询叶子任务目标投影层级(...)`。
- `世界树类::查询叶子任务目标投影层级(...)` 继续转调 `因果类::查询叶子任务目标投影层级(...)`，该接口输出 `std::vector<std::string>& 缺失证据`。
- `因果类` 当前输出的缺失项不只是固定枚举项，还包含带节点键的文本，例如 `来源因果证据不足:<节点键>`、`条件模板引用无效:<节点键>`、`条件模板缺匹配初始状态证据:<条件引用键>`。

当前判断：

- 这里不是单个局部结构字段删除问题，而是因果类 / 世界树公开查询合同仍用文本缺失证据输出。
- 当前 P10f-c 小切片不能安全地把这些文本项临时映射成固定枚举，否则会丢失动态节点键证据或引入新的兼容解释层。

下一步条件：

- 需要单独建立或切入因果投影缺失证据结构化接口计划：至少定义缺失类型枚举、可选关联节点 / 条件引用句柄、缺失数量和值槽，并由 `因果类` 源头输出结构化证据。
- 在该接口替换前，`结构_线程结算因果投影预判 / 结构_叶子任务正式结算证据` 的 `缺失证据 / 摘要` 暂不在 P10f-c 局部硬删。
