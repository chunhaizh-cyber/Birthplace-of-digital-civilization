# 20260606 方法维护管理纯后台需求入树收口记录

## 问题

原始需求树显示：

```text
根需求 | 方法维护管理状态 | 子=14
子需求 | 方法状态 | 子=0
...
```

后续观察到：

```text
根需求 | 方法维护管理状态 | 子=21 | 主键=5
```

这说明运行中自检不是一次性写入后台清单，而是在持续把纯后台方法维护候选正式挂入普通需求树，造成无效增长。它们安全 / 服务权重为 0，但在 P5b 后零权重不再作为任务化准入闸门，因此这些后台维护需求仍会进入活动任务化扫描，污染当前主需求树。

## 判断

```text
方法维护管理分支可以作为报告 / 管理视图存在；
但方法维护管理根下必须严格检查被维护的方法；
同一个被维护方法已有未截止维护需求时，不得重复新增根下直接子需求。
没有局部来源需求、没有安全 / 服务投影的纯后台 方法状态>=好用 候选，
只能保留为自检报告，不进入当前普通需求树。
```

保留边界：

```text
1. 若方法缺口能反查局部来源需求，仍挂局部父链。
2. 若因果投影命中安全 / 服务，仍挂安全 / 服务链。
3. 任务执行自然暴露的 方法动作数量 / 方法可执行入口数量 等缺口不受本切片影响。
4. 不恢复任务筹办现场直调。
5. 不把值域裁决放到自我层。
6. 不把所有方法状态候选一律拦在普通需求树外；只拦无局部来源、无安全 / 服务投影的纯后台维护候选。
```

## 修改预测

```text
代码修改：
    自检候选父需求裁决中，纯后台 方法维护 + 方法状态 候选不再确保 方法维护管理状态 父需求；
    改为不进入当前普通需求树，并记录“方法维护入树必须严查被维护方法唯一性”裁决原因。

    自检正式需求入树前，若父域为 方法维护，
    先用 候选目标方法主键 检查 方法维护管理状态 父需求的直接子需求；
    若同一个被维护方法已有未截止直接子需求，则复用既有需求并记录严查日志，
    不再新增根下直接子需求。

验证预测：
    Debug x64 构建通过；
    30 秒 --self-check-log 退出码 0；
    最新运行区间不再出现纯后台 自检正式需求入树 | 父域=方法维护；
    应出现 自检需求入树裁决：候选不进入当前普通需求树 | 父域=方法维护；
    若后续出现非纯后台方法维护入树，同一被维护方法应复用既有需求；
    仍不宣称四方法自然链通过。
```
