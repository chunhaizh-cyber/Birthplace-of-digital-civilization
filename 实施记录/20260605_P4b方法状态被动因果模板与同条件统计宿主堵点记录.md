## 证据

1. `data/initial_causal_templates.tsv` 当前只有 6 列：

```text
名称 / 层级 / 主果宿主 / 主果特征 / 因宿主 / 因特征集
```

2. 用户已确认 `data/initial_causal_templates.tsv` 存储的是被动因果，只需要表达：

```text
具备什么条件后必然得到什么结果。
```

因此 TSV 不需要动作语义列，也不应把本能方法写成因动作。

3. `自我线程模块.impl.cpp` 的 TSV 读取器固定 `字段数量 == 6`，并在当前安全风险树应用路径中把每个特征创建为：

```text
安全因果风险树明确状态_未明确 -> 安全因果风险树明确状态_已明确
```

这说明现有 TSV 可以表达“条件特征集合 -> 结果特征”的被动因果；但当前应用入口只服务安全风险树明确状态，还没有把 `target` 绑定到目标方法虚拟存在的方法状态派生入口。

4. `私有_读取或确保被动触发初始因果_线程侧` 能将模板标记为：

```text
因动作语义键 = 被动动作
因动作名称 = 被动动作
```

但动作语义不是 TSV 必要字段；该接口更适合被动触发读取和证据增强。并且该接口在自我线程私有区，`自我线程模块.impl.cpp` 当前已有未提交改动，本切片不应混入跨线程模板接口改造。

5. P4b1 执行前，`结果符合次数 / 结果不符合次数` 写入方法虚拟存在整体，不是条件节点或条件结果对宿主：

```text
条件原已存在 && 结果原已存在 -> 方法虚拟存在.结果符合次数 += 1
条件原已存在 && 条件下原有结果 -> 方法虚拟存在.结果不符合次数 += 1
```

6. P4b1 已将同条件统计宿主改为 条件节点 -> 条件场景，并新增 `新结果分支数量`。

## 堵点

当前无法安全继续实现 P4b。

原因：

```text
1. TSV 口径已确认：只表达被动条件 -> 必然结果，不需要动作语义；
2. 当前 TSV 应用入口只服务安全风险树，不会把 target 解释为目标方法虚拟存在；
3. 方法状态条件需要先有“数量底账已满足”的条件特征或等价二次特征；
4. 当前 TSV 应用入口固定创建安全风险树明确状态的 未明确 -> 已明确 比较，不能表达数量阈值条件；
5. 自我线程私有模板接口所在文件存在既有脏改，不适合混入本切片跨模块改造。
```

## 建议确认

```text
2. 数量底账已满足特征生成路径：

3. 是否允许在 `自我线程模块.impl.cpp` 当前已有未提交改动时，进入方法状态被动模板应用入口改造。
```
