# S6-N2a 外设提交包代码对账记录

时间：2026-06-02

## 1. 对账范围

本记录只核对当前代码是否已经承载 050005 规范要求的链路：

```text
外设提交包
-> 自我外设本能方法组织
-> 正式提交入口入账
-> 因果链解释
```

本轮不把外设材料包、外设报告队列或任务管理承接请求直接当成提交入口，也不在自我线程硬编码识别 / 扫描 / 跟踪 / 确认子需求表。

### 2.3 任务管理承接已按枚举分支，不是文本扫描

```text

任务模块.工作线程消息协议.ixx
```

当前 `任务管理外设消息承接_处理一次` 按 `枚举_外设观察报告类型` 分支：


结论：

```text

但这里也还没有承接规范要求的三类结构化提交包。
```

### 2.4 自我线程只落材料摘要，不是三类组织方法

代码位置：

```text

```

当前 `私有_落任务管理观察事实承接请求到自我内部世界` 会：

```text

记录外设观察报告承接状态；
记录观察像素簇数量；

```

观察事实更新后触发函数：

```text

```

当前只发布事实变化事件、命中安全根需求、标记或提交重筹办：

```text

直接写风险状态=否
```

结论：

```text
当前自我线程承接路径没有再出现硬编码识别 / 扫描 / 跟踪 / 确认子需求表；
但它也不是 自我_识别外设观察材料 / 自我_扫描已识别区域 / 自我_跟踪指定存在 三个本能方法。
```

## 3. 对账结论

当前代码状态：

```text
外设材料 / 报告队列：已有，且 D455 材料页和可回查句柄已具备。
三类外设提交包：未实现统一结构。
三个自我外设组织方法：未实现。
三个正式提交入口：只实现 提交_确认观察存在事实。
任务管理承接：已按报告枚举分支，不是文本扫描；但仍是承接请求旗标，不是提交包。
自我线程承接：只落材料和候选摘要，不直接写世界真值；但不是三类组织方法。
安全评估：未直接消费外设报告；但缺少扫描 / 跟踪已提交事实的显式闸门。
```

因此，S6-N2a 的下一步不能是需求树继续生长，也不能是把总目标直接映射成 D455 等待项。

下一步应先补 P1：

```text
在外设报告队列现有材料基础上，定义三类外设提交包统一结构。
```

## 4. 不清楚 / 需确认点

这里有一个真实设计选择，不能用文字糊过去：

```text
方案 A：
    保留 结构_外设观察报告队列项 作为现有报告 / 材料队列；
    新增 结构_外设提交包头 / 结构_外设特征值条目 / 三类提交包；
    用规范化函数把报告队列项转换或包装成提交包。

方案 B：
    直接把 结构_外设观察报告队列项 改造成提交包主体；
    旧报告字段整体迁移到三类包结构。
```

当前建议选方案 A：

```text
保留已有 D455 报告队列和短期材料页，不破坏现在相机可正常工作的链路；
新增提交包结构作为自我侧消费的规范化供料层；
后续再把任务管理承接请求从布尔旗标逐步改为提交包 ID / 包类型 / 结构化缺口。
```

若采用方案 B，风险是会影响当前已能工作的 D455 采集、报告缓存、等待项匹配和任务管理承接链。
