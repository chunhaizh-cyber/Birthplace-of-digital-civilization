## 2. 当前审计发现

```text
疑点 A：
    `自我线程模块.impl.cpp::私有_动作验证摘要允许普通价值结算_线程侧`
    允许 `事实提交等级=待复核事实` 进入普通价值结算。
    规范口径要求结果事实可信后才能进入需求满足 / 价值结算；
    待复核事实应保留为复核或闭账状态，不能写成普通安全 / 服务价值结算。

疑点 B：
    `私有_处理任务满足反馈_线程侧` 和 `私有_处理非核心结算闭账_任务管理新链`
    允许基于 `需求状态已满足` / `已达未截止` 收束来源需求。
    这类路径可以作为自然闭合，但需要在日志和闸门中显式区分：
    本轮可信 actual 满足 != 自然闭合。

已确认父链方向：
    `私有_唤醒派生需求来源任务_任务管理新链`
    已先回查父需求目标，再以 `父需求仍需推进` 推动父任务等待条件变化；
    父目标未达成时可提交 `重筹办任务` 治理请求，方向符合 C7。
```

## 3. 本切片修改

```text
文件：
    自我线程模块.impl.cpp

修改：
    1. `私有_动作验证摘要允许普通价值结算_线程侧`
       从允许 `正常事实 / 待复核事实` 收紧为只允许 `正常事实`。

    2. `私有_判定任务结算域_线程侧`
       普通价值域增加 `actual满足目标` 闸门；未满足目标时保持非普通价值闭账路径。

    3. `私有_处理任务价值反馈_线程侧`
       在调用 `结算叶子任务价值` 前再次检查 `actual满足目标`；
       不满足时返回 `实际结果未满足目标`，不写核心安全值 / 服务值。

    4. `私有_处理任务满足反馈_线程侧`
       将 `结果事实可信`、`可信actual满足目标`、`输入允许自然收束` 分开；
       来源需求收束只允许可信 actual 满足或需求状态自然满足。

    5. `私有_处理非核心结算闭账_任务管理新链`
       新增 `结果事实可信` 入参；
       非核心闭账只在可信 actual 满足或来源需求自然满足时收束来源需求。
```
