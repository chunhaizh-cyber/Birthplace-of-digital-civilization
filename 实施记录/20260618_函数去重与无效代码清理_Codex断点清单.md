## 3. 基础数据类型全局迁移阻塞判定

时间：2026-06-18

复核对象：

```text
基础数据类型.ixx 全局共享候选 16 个：
三向关系 / 比较量 / ZigZag 编解码 / VecI64-VecIU64 编解码工具。
```

已复核证据：

```text
全局共享函数类.ixx 当前只有模块声明和边界注释，没有同功能函数。
基础数据类型.ixx 是 export module 基础数据类型模块。
基础数据类型.h 与 基础数据类型.ixx 均定义同一批候选函数。
鱼巢.vcxproj 同时编译 基础数据类型.ixx 和 全局共享函数类.ixx。
多个当前源码文件仍 include "基础数据类型.h"。
多个当前源码文件 import 基础数据类型模块。
```

当前判断：

```text
1. 这 16 个候选虽只依赖基础别名 / 基础容器，
   但这些别名 / 枚举 / 容器当前权威定义就在 基础数据类型.h/.ixx。
2. 若 全局共享函数类.ixx import 基础数据类型模块，
   而 基础数据类型模块 再 import / export 全局共享函数类 以维持现有调用入口，
   会形成 import 环。
3. 若把 I64 / 比较量 / VecI64 / VecIU64 等权威定义下沉到 全局共享函数类.ixx，
   属于基础类型权威归属重构，不是当前 1 到 3 个低风险函数迁移切片。
4. 若新增全局函数但在 基础数据类型.h/.ixx 保留转发函数，
   会保留双入口，不符合本计划“迁移后删除原重复定义并改变引用方式”的约束。
```

结论：

```text
当前不安全迁移这 16 个候选；也不能直接删除 基础数据类型.h 或 基础数据类型.ixx 的重复定义。
本切片遇到架构确认点：基础数据类型.h 与 基础数据类型.ixx 的双入口是否允许作为当前工程形态继续存在，
或是否需要先建立新的更底层基础共享模块 / 调整基础类型权威归属后再迁移。
```
