# 20260606_目标观察约束特征组实现方案_v0.1

## 1. 定义

`目标观察约束特征组` 是自我给外设的观察约束和比较基准。它不是包本身，不是世界真值，也不是让外设替自我理解世界。

正式语义：

```text
一个目标存在；
一个目标特征；
一个当前值；
一组观察约束；
一组质量 / 时效 / 性能阈值；
一个需求 / 任务 / 等待项路由。
```

用途：

```text
外设用它缩小观察范围；
外设用它选择本轮重点计算的特征；
外设用它和新观察值比较；
外设用它判断稳定、冲突、丢失、遮挡、重捕获或区间迁移；
任务管理用它把结果回到对应等待项；
自我用消费后的正式结果更新下一轮单特征当前值。
```

边界：

```text
自我给的是约束，不是世界真值；
外设输出的是观察材料，不是需求满足；
报告 / 包 / 队列项 / 材料页只是通信容器；
提交入口只接受存在、特征、二次特征、状态动态和来源动作动态引用。
```

## 6. 自我侧本能函数

建议新增或确认：

```text
自我_提交目标观察约束特征组
```

它是自我向外设缓冲区提交观察约束的边界动作，不是世界事实提交入口。

输入：

```text
目标存在ID
目标特征类型ID
目标特征当前值
来源需求ID
来源任务ID
来源等待项ID
来源报告ID
来源帧ID
ROI引用
像素集合掩码句柄
点集引用
彩色轮廓局部图句柄
深度轮廓局部图句柄
AABB / 中心
允许误差 / 稳定阈值 / 质量阈值
generation
TTL
```

输出：

```text
目标观察约束写入状态
目标观察约束ID
约束generation
缺口原因
```

触发点：

```text
1. 自我所在场景中的存在某一目标特征正式入账后，只针对变化的那个特征生成约束。
2. 扫描需求任务筹办时，把目标约束写入 / 新鲜度检查作为每轮检查项。
3. 跟踪需求任务筹办时，把目标种子和目标约束检查作为每轮检查项。
4. 约束过期、generation 失配或材料不可回查时，生成正式缺口，不伪造扫描或跟踪可用。
```

动作动态口径：

```text
动作动态只能表示：
    自我已把某目标存在的某目标特征当前值和观察约束提交给外设通信缓冲区。

动作动态不能表示：
    外设已确认目标存在；
    目标特征变化已经成立；
    需求已经满足；
    世界真值已经更新。
```

## 7. D455 外设侧使用规则

扫描：

```text
读取等待项；
读取目标观察约束；
检查 TTL / generation / 来源报告 / 材料句柄；
优先在 ROI / mask / 点集 / AABB 内比较；
只计算目标特征类型ID 对应的特征；
与目标特征当前值或基准值比较；
输出发现 / 无变化 / 变化 / 值域冲突 / 待复验。
```

跟踪：

```text
读取等待项；
读取目标观察约束；
用目标存在ID、目标种子、ROI / mask / 点集 / AABB 找目标；
持续读取目标特征当前观察值；
检查目标值域和预测区间；
检查非法区间跳变；
输出稳定 / 丢失 / 遮挡 / 重捕获 / 区间迁移。
```

识别：

```text
识别可以无目标约束；
如果有观察范围 / 期望特征集合 / 质量阈值，则作为识别观察范围和质量要求；
识别仍只输出外设观察存在材料，不确认自我世界存在。
```

## 8. 优质观察材料判断

建议函数：

```cpp
export 结构_观察材料质量判定 判断优质观察材料(
    const 结构_外设观察报告队列项& 队列项,
    const 结构_外设观察等待项* 等待项,
    const 结构_目标观察约束特征组* 目标约束);
```

返回：

```text
观察材料等级：不合格 / 可用 / 优质
依据字段
需补观察原因
建议外设动作
是否允许提交入口组织
```

判断顺序：

```text
1. 采集成功、报告类型、外设ID、时间戳。
2. 报告年龄 <= 等待项最大允许报告年龄。
3. d455:// 材料句柄可回查。
4. 扫描 / 跟踪目标上下文新鲜。
5. 全帧任务检查全局深度 / 空间质量。
6. 目标任务优先检查 ROI / mask 内深度 / 空间质量。
7. 颜色、轮廓、二维回查任务允许深度 / 空间不足时降级。
8. 识别 / 扫描 / 跟踪模式专属条件。
9. 跟踪额外检查当前值域区间ID、预测区间、预测误差、非法区间跳变和合法区间迁移。
```

输出使用：

```text
不合格：
    删除或标记失效，生成补观察 / 缺目标 / 缺基准 / 不可回查缺口。

可用：
    只进入待验证 / 待复验 / 缺口派生，不写最终事实。

优质：
    进入 6127 / 6145 / 6146 / 6147 方法重入和结果场景组织。
```

## 9. 三类队列视图

物理层：

```text
继续使用统一 报告队列。
```

逻辑层：

```text
识别观察材料队列视图：
    报告类型 = 逐簇识别报告；
    观察运行模式 = 陌生环境逐簇识别；
    用于 6127 / 6145。

扫描特征变化材料队列视图：
    报告类型 = 扫描变化报告；
    观察运行模式 = 已识别场景扫描变化；
    必须绑定目标约束或明确是首次基准；
    用于 6146。

跟踪连续观察材料队列视图：
    报告类型 = 跟踪报告；
    观察运行模式 = 目标跟踪观察；
    必须绑定目标种子 / 目标约束；
    用于 6147。
```

消费删除：

```text
1. 任务管理按等待项消费队列视图。
2. 消费前先做优质观察材料判断。
3. 生成上行消息、结果场景或缺口后，标记报告已消费。
4. 已消费报告不再匹配同一等待项。
5. 清理器删除已消费且超过保留窗口的报告。
6. D455 材料页继续按 TTL / 容量清理，保留必要回查时间。
```

## 10. 任务管理接线

`任务模块.管理界面线程.impl.cpp` 应调整：

```text
1. 按方法供料要求构造等待项时，同时查找或请求目标观察约束。
2. 扫描 / 跟踪等待项的幂等键加入目标约束ID、目标特征ID、generation。
3. 外设承接后台线程按三类队列视图消费报告。
4. 命中报告后先判断观察材料等级。
5. 上行消息携带报告ID、等待项ID、目标约束ID、观察材料等级和依据。
6. 上行被承接后完成等待项，并标记报告已消费。
```

扫描等待项最低要求：

```text
目标存在ID 或 目标区域；
目标特征类型ID；
目标特征当前值或首帧基准说明；
ROI / 掩码 / 点集 / AABB 至少一类；
TTL / generation。
```

跟踪等待项最低要求：

```text
目标存在ID；
目标种子；
目标特征类型ID；
目标特征当前值；
预测区间或最大预测误差；
最大允许观测年龄；
ROI / 掩码 / 点集 / AABB 至少一类。
```

| P3 本能函数 | 当前本能ID / 动作动态 / 缓冲区摘要 | 只写单特征约束，不写世界真值 |
| P4 D455 使用 | D455 日志 | 外设按约束读取 ROI / mask / 当前值；过期拒绝或降级 |
| P5 材料等级 | 质量判定日志 | 不合格 / 可用 / 优质分级可追溯 |
| P6 队列视图 | 队列状态日志 | 三类视图不污染；已消费项不重复命中 |
| P7 自我承接 | 方法动作动态 + 提交入口日志 | 正式入账对象不是报告 / 包 / 队列项 |
| P8 真实运行 | 构建 + 真实 D455 日志 | 形成目标约束 -> 外设约束观察 -> 队列视图 -> 自我方法 -> 提交入口 -> 单特征回写闭环，或停在明确真实堵点 |

## 14. 最终链路

```text
自我确认观察存在.目标特征当前值
    + ROI / 掩码 / 点集 / AABB / 基准
        -> 自我_提交目标观察约束特征组
        -> 自我存在信息缓冲区

任务管理扫描 / 跟踪等待项
    + 目标观察约束ID
        -> D455 读取目标约束
        -> 约束采集 / 比较 / 跟踪
        -> 识别 / 扫描 / 跟踪队列视图项

任务管理消费队列视图
    + 优质观察材料判断
        -> 6127 / 6145 / 6146 / 6147
        -> 自我方法组织结果场景
        -> 提交入口裁决
        -> 正式存在 / 特征 / 二次特征 / 状态动态入账

正式入账结果
    -> 更新该目标特征当前值
    -> 回写下一轮目标观察约束特征组
```

一句话：

```text
自我给外设的不是答案，而是“带着这个目标、这个特征、这个当前值、这些边界和这些质量要求去看”；外设看完交回观察材料，自我再决定它在世界中意味着什么。
```
