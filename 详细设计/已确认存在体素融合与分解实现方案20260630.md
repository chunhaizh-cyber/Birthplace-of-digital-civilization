## 1. 目标

本方案把已确认存在的第一版粗体素升级为可持续融合、可分解内部结构、可递归生成子存在体素的加工链。

目标不是新增一套外设识别系统，而是在已有观察入账和提交入口之后增加体素加工层：

```text
已确认存在新增观察体素特征值
-> 生成体素加工任务
-> 体素加工工作线程计算候选
-> 提交入口裁决
-> 更新父存在体素特征或创建内部世界子存在
-> 场景体素只读服务和控制面板读取结果
```

## 2. 设计边界

必须保留的边界：

```text
1. 外设原始帧新增不直接触发体素加工。
2. 已确认存在新增未消费观察体素特征值才触发体素加工。
3. 体素加工线程只返回候选，不写正式事实。
4. 父存在体素更新和子存在创建必须走提交入口。
5. 彩色轮廓只给分解候选，深度轮廓必须补空间占据。
6. 所有体素包围盒都是正立方体，外边界保留 1 格空白。
7. 控制面板和场景体素服务只读显示，不反向裁决事实。
```

不在第一版解决：

```text
SLAM。
复杂姿态估计。
多相机全局重建。
语义部件分类。
子存在长期身份合并。
跨对象物理关系推理。
```

## 3. 建议模块

第一版建议拆成四个相对独立的功能层。

### 3.1 体素观察任务生成层

职责：

```text
监听或扫描已确认存在新增的未消费观察体素特征值。
检查特征值是否已经消费。
读取父存在当前体素版本、尺寸、位置、AABB 和来源材料句柄。
生成体素加工任务。
```

建议函数：

```text
提交已确认存在体素加工任务
标记观察体素特征值已进入加工
读取存在当前体素加工输入快照
```

第一版可放在观察提交链或对应自我动作实现模块附近，避免工作线程直接扫描世界树。

### 3.2 体素加工工作线程

职责：

```text
从任务队列取体素加工任务。
读取任务内快照，不持有可写世界树引用。
做深度融合、彩色分解、深度补子轮廓、颜色统计、完整性检查。
输出候选结果包。
```

线程禁止：

```text
直接写存在特征。
直接创建子存在。
直接写方法动作动态。
直接更新需求满足。
```

### 3.3 体素候选提交层

职责：

```text
读取体素加工结果包。
检查父体素版本是否仍匹配。
检查融合点、边界完整性、来源可回查、质量状态。
决定写父体素候选、挂起待融合候选、或创建内部世界子存在候选。
```

正式写入仍由既有领域类承担：

```text
特征类：写入父存在三维体素模型、颜色、版本等特征。
存在类 / 场景类：确保内部世界和子存在归属。
提交入口：裁决候选是否入账。
```

### 3.4 只读展示和查询层

职责：

```text
场景体素服务读取父子体素特征。
控制面板显示父体素和子体素颜色覆盖。
显示层不写回父颜色、子颜色或体素事实。
```

## 4. 数据契约

### 4.1 输入任务

建议第一版结构：

```cpp
struct 结构_存在体素加工任务 {
    I64 任务ID;
    指针句柄 父存在;
    I64 观察体素特征值ID;
    I64 基准体素版本;
    VecU句柄 当前父体素模型;
    VecU句柄 深度轮廓材料;
    VecU句柄 彩色轮廓材料;
    VecU句柄 来源观察证据集合;
    VecI64 父存在尺寸;
    VecI64 父存在位置或AABB;
};
```

结构名和字段最终以代码现有类型为准；这里表达的是契约，不要求新增主信息字段。

### 4.2 候选结果包

建议第一版结构：

```cpp
struct 结构_存在体素加工结果包 {
    I64 任务ID;
    指针句柄 父存在;
    I64 输入观察体素特征值ID;
    I64 基准体素版本;
    I64 包围盒分辨率N;
    VecU句柄 父体素候选;
    I64 父基础颜色RGB;
    VecU句柄 子轮廓候选集合;
    VecU句柄 子存在局部体素候选集合;
    VecU句柄 父子坐标映射集合;
    I64 有融合点;
    I64 触碰外边界;
    I64 局部包围盒压紧状态;
    I64 可提交状态;
    VecU句柄 来源观察证据集合;
};
```

候选结果包可以先作为运行期结构，但凡需要长期回查、提交裁决或控制面板视图读取的判断，必须转为项目结构中的 I64、VecU 句柄、VecIU64 或指针句柄。

## 5. 加工算法口径

### 5.1 分辨率

```text
N = max(彩色轮廓图宽, 彩色轮廓图高)
有效区间 = 1 .. N-2
外边界层 0 和 N-1 必须为空
```

父存在实际最长尺寸对应 `N-2` 个有效体素；其他方向按尺寸比例计算。若缺尺寸信息，不能生成稳定等比例模型，只能输出缺尺寸候选或沿用当前 AABB 粗体素降级路径。

### 5.2 深度融合

流程：

```text
深度轮廓材料
-> 投影到父存在当前体素坐标
-> 检查与现有体素是否存在融合点
-> 生成父体素占据候选
-> 检查外边界是否被占据
-> 生成覆盖率和置信状态
```

没有融合点时，输出：

```text
可提交状态 = 不可提交
缺口类型 = 缺融合点 / 坐标映射不足 / 证据不连续
```

### 5.3 彩色分解

流程：

```text
彩色轮廓材料
-> 颜色分区
-> 子轮廓候选
-> 深度轮廓补空间占据
-> 子区域平均颜色
-> 子体素局部包围盒
-> 父子坐标映射
```

只凭颜色不能创建子存在。颜色块如果没有深度占据，只能作为父存在表面颜色区域或未解释区域候选。

### 5.4 子体素生成

子存在确认前：

```text
子体素只是候选。
```

子存在确认后：

```text
从父体素空间裁出子区域。
按子区域自身最长尺寸生成正立方体局部体素模型。
保存父子坐标映射。
子存在拥有自己的三维体素模型特征。
```

不得给每个子存在复制一份父存在完整 `N*N*N` 模型。

### 5.5 颜色合成

```text
父基础颜色 = 彩色轮廓扣除已确认子轮廓后的剩余区域平均色。
子颜色 = 子轮廓区域平均色。
渲染时子颜色覆盖父颜色显示。
```

父颜色和子颜色是不同事实；覆盖只发生在显示阶段。

## 6. 并发和版本

体素加工任务读取父体素快照时记录：

```text
父体素版本 = V1
```

候选提交时再读取当前版本：

```text
仍为 V1：允许按候选裁决。
已变为 V2：不得覆盖；重算、合并或挂起。
```

同一观察体素特征值必须具备消费状态，防止：

```text
观察特征值 -> 加工 -> 融合写回 -> 再触发加工
```

## 7. 项目结构映射

| 业务概念 | 项目承载结构 | 值类型 / 身份结构 | 写入方 | 读取方 | 验证方式 |
| --- | --- | --- | --- | --- | --- |
| 观察体素特征新增 | 已确认存在观察特征值 | I64 ID / VecU 句柄 / 指针句柄 | 观察提交链 | 体素任务生成层 | 同一特征值只生成一个任务 |

| 父体素候选 | 候选结果包 | VecU 句柄 / VecIU64 | 体素加工线程 | 提交入口 | 版本、融合点、边界状态通过 |

## 8. 实施顺序建议

最小可落地顺序：

```text
1. 补体素加工数据契约和消费状态。
2. 做正立方体包围盒与完整性检查 helper。
3. 做体素加工任务队列和单线程执行器。
4. 做深度融合候选，先不写正式事实。
5. 做提交入口版本闸门和父体素写入。
6. 做彩色分解候选和深度补空间。
7. 做内部世界子存在候选提交。
8. 做控制面板父子颜色覆盖只读显示。
```

每一步都必须能单独构建和回归；不能一次性把线程、融合、分解、子存在创建和显示全部混在一个切片里。

## 9. 验证建议

第一阶段验证应先证明守卫条件：

```text
旧当前特征值不重复触发。
无融合点不写父体素。
外边界触碰标记不完整。
线程不写世界树事实。
版本变化时不覆盖。
彩色无深度支撑不建子存在。
子存在局部体素不是父完整体素复制。
```

业务验证必须使用自然观察链或真实观察材料，不得用伪造入口宣称业务闭合。
