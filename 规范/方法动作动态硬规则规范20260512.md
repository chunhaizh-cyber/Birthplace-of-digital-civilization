# 方法动作动态硬规则规范 20260512

## 1. 权威结论

凡是能生成“方法动作动态”的变化，都必须对应一个明确动作。

```text
动作 = 方法。
动作函数 = 本能函数或方法动作入口。
```

本能方法是自我的最小可执行动作，不是线程流程、任务生命周期步骤、候选筛选逻辑或底层写入工具。

```text
本能方法 =
    明确输入参数规格
  + 明确前置条件 / 参数绑定规则
  + 明确动作入口
  + 明确输出结果规格
  + 明确动作动态落账规则
```

缺少明确输入参数或明确输出结果时，只能算未完成的方法结构、历史入口或普通逻辑函数，不能作为可执行本能方法进入普通候选集，也不能作为方法动作动态的动作来源。

方法动作动态不是普通日志。它表示系统承认：

```text
某个方法在某个场景下，
读取输入参数场景，
对某个主体的某个特征执行了动作，
并产生了可记录的运行事实。
```

因此：

```text
方法动作动态存在
    -> 系统承认某方法执行了某动作
    -> 该动态可作为状态变化证据
    -> 该方法必须有明确动作来源
```

但：

```text
可产生动作动态 != 可被任务主动选择
可作为因果证据 != 可作为学习目标
可被生命周期代码调用 != 可进入普通候选方法集
```

有些方法动作只负责提交已经成立的状态变化。它们可以产生因果证据，但不能被需求 / 任务主动当作解决手段来选择。

## 2. 成功 / 失败不是根概念

当前系统不以“成功 / 失败”作为动作动态的根概念。

动作动态记录的是：

```text
方法运行造成的事实动态。
```

不是：

```text
成功日志
失败日志
```

只要某个方法真实运行，并造成了某种可记录事实，就应该生成动作动态。除非逻辑崩溃、运行中断到连动态都无法生成，否则不应因为“没有达到最终目标”而放弃记录。

`成功 / 失败` 只能作为普通结果特征、兼容字段或派生判断使用，例如：

```text
目标达成情况
筹办结果类型
执行结果类型
需求满足情况
中断原因
```

不得把 `成功 / 失败` 当成动作动态本体的分类轴。

建议后续将动作动态核心结果改为：

```cpp
enum class 枚举_动作事实类型 : std::uint8_t {
    未定义 = 0,

    特征已改变,
    状态已推进,
    需求已派生,
    任务已创建,
    条件已观测,
    回执已生成,
    方法已运行,
    事实已提交,
    运行中断
};
```

如果底层签名暂时仍保留：

```cpp
bool 成功
```

则只能解释为：

```text
动作动态是否已生成 / 方法运行事实是否成立
```

不能解释为：

```text
父目标是否达成
```

## 3. 外部变化边界

只有“方法动作动态”表示自我能做。

外部发生的变化不能生成自我方法动作动态，只能落成：

```text
观察动态
外部事件动态
环境动态
未知来源动态
```

如果没有对应方法，不能叫方法动作动态。

## 4. 主动动作与被动动作

本规范把方法动作分为三类。

### 4.1 主动动作

主动动作是需求 / 任务可以主动选择的动作。

它表示自我线程或任务管理线程能够基于需求、目标、缺口、调度意图，构造输入参数场景，然后把某个方法作为候选方法、当前方法或学习目标来调用。

主动动作至少需要：

```text
1. 方法头。
2. 动作函数 / 本能函数入口。
3. 输入形参规格，且能说明必需参数、来源和类型。
4. 条件节点，且能用本轮输入参数场景完成参数绑定。
5. 结果规格 / 回执规格，且能说明输出会落到哪个特征或结果场景。
6. 可构造输入参数场景。
7. 调用后能返回运行存在 / 输出结果场景。
8. 输出结果能与目标需求的目标宿主、目标特征类型和目标状态进行比较。
9. 事实提交后能生成方法动作动态。
```

当前是否允许调用，还要受这些条件限制：

```text
条件节点是否满足。
参数是否可绑定。
权限是否允许。
所属线程是否有写入权。
目标对象是否存在。
状态迁移是否合法。
```

主动动作可以：

```text
进入候选方法集。
成为任务当前方法。
被学习 / 练习补强。
被因果反推视为可执行动作候选。
```

### 4.2 被动状态动作

被动状态动作不是需求 / 任务主动选择的解决手段。

它只在生命周期代码已经确认某个主链状态变化应当提交时调用，用于：

```text
写入正式状态。
生成动作动态证据。
把上游证据动态串到状态变化上。
```

被动状态动作可以产生方法动作动态，但只能由对应生命周期代码显式调用，不能进入普通候选方法集，不能作为练习目标，不能被因果反推当作下一步可行动作。

被动状态动作动态中的动作语义必须统一写成：

```text
被动动作
```

`被动动作` 是空的占位动作，含义是：

```text
这里发生了状态提交事实；
该动态只能作为证据；
不存在可被主动调用的动作语义。
```

真实提交来源，例如 `提交任务状态变化`、`提交方法状态变化`、`回写需求满足`，只能作为提交来源、审计来源或实现来源记录；不得作为动作语义暴露给候选方法查找、因果反推或学习链。

学习链读到 `被动动作` 时，必须判定为：

```text
空占位动作；
不可学习为主动方法；
不可进入自我动作组合；
不可进入普通候选方法集。
```

被动动作是自我可见的事实类型，不是自我可调用能力。自我不需要知道该动作如何使用、何时生成或如何生成；生命周期提交链、后处理链或结算链在条件成立时被动提交它。自我只需要知道：

```text
存在一条标准动作动态；
该动态可以解释上游事实为什么导致下游变化；
该动态可以作为后续需求投影、因果抽象和审计检查的材料。
```

这里的“被动”不是“可做可不做”，而是：

```text
只要被动因已经正式出现，且该被动因满足对应被动规则，
对应的被动果就必须由生命周期提交链、后处理链或结算链自动出现。
```

因此，被动动作不需要任务去选择，不需要自我发起普通调用，也不需要进入方法筹办；它是因具备后的自动提交义务。若被动因已经正式出现而被动果没有生成，应视为提交链、后处理链或结算链缺口，而不是等待任务筹办的普通缺口。

被动因不是任意上游线索，必须是已经正式入账、可回解、可去重的事实，例如任务状态、需求状态、方法状态、输出结果状态或结算资格状态。被动果自动出现时仍需遵守幂等和防重复规则：同一个被动因只能生成同一语义的一次被动果；重复触发只能引用已有动态或记录已处理结果。

被动动作动态仍必须使用统一动作动态结构，不能因为动作不可主动调用而降级成普通日志。至少应保留：

```text
动态主体；
动态特征；
初始状态；
结果状态；
来源低层动态；
来源输入场景 / 来源输出场景，或可回解的事实场景；
来源动作名 = 被动动作；
提交来源 / 审计来源 / 实现来源。
```

被动动作因果关系主要起承上启下作用：

```text
知道为什么：
    哪个已提交的上游事实、任务状态、需求状态或结果状态导致了本轮变化。

知道需要什么：
    若后续还要取得同类结果，需要哪些上游事实、条件状态、任务状态或证据材料。
```

因此，被动动作可以生成动作动态证据，也可以被动作动态到因果信息的统一流程被动吸收；但被动动作本身不得成为普通任务候选、学习目标、练习目标或自我动作组合中的可执行动作。

典型例子：

```text
提交任务状态变化
提交方法状态变化
回写需求满足
```

### 4.3 被动整理动作

被动整理动作只整理回执、候选镜像、运行上下文或诊断字段。

它不改变主链状态，通常不应生成方法动作动态，也不应作为本能方法参与普通方法选择。

典型例子：

```text
同步筹办回执到任务
同步执行回执到任务
同步可用方法数量镜像
候选集整理
回执整理
```

被动整理动作必须退回普通代码。它只能作为生命周期内部普通函数、字段同步函数或诊断整理函数存在，不得保留为新增本能方法边界；历史兼容入口应逐步移出默认本能方法表、运行时注册和方法候选链。

被动整理动作不得进入：

```text
普通候选方法集。
任务当前方法。
学习 / 练习目标。
自我动作组合反推候选。
```

## 5. 线程不是动作来源

线程只能作为调用者或编排者，不能作为方法动作动态的动作来源。

禁止表达：

```text
任务管理线程把任务改成完成。
自我线程把需求改成满足。
学习线程把方法改成可用。
```

正确表达：

```text
任务管理线程调用 本能方法_提交任务状态变化。
自我线程调用 本能方法_回写需求满足。
学习 / 方法管理流程调用 本能方法_提交方法状态变化。
```

方法才是动作来源，动作动态记录的是方法动作事实。

## 6. 提交类逻辑必须方法化

凡是会落成方法动作动态的提交类变化，都必须有对应本能方法或方法动作入口。

第一批动作边界按主动性分层：

```text
主动动作：
    尝试学习
    定向学习
    练习
    增加可用方法数量
    后续真实世界特征改变类方法

被动状态动作：
    提交任务状态变化
    提交方法状态变化
    回写需求满足
        动作动态中的动作语义统一写为 `被动动作`；
        具体提交口只作为审计来源。

被动方法结构 / 证据动作：
    建立条件结果对
        仅作为方法状态可用的证据提交口；
        不作为独立主链状态目标；
        不进入普通候选方法集或练习目标。

被动整理动作：
    同步筹办回执到任务
    同步执行回执到任务
        只同步任务回执字段；
        不改变任务状态；
        不生成主链动作动态；
        必须退回普通代码。
```

线程可以决定调用这些方法，但不能绕过方法直接生成方法动作动态。

`改变特征值` 不属于动作来源方法。它是所有语义方法共享的先天特征写入逻辑，只能接收外层动作来源方法并为该方法完成底层特征提交、状态节点和动态落账辅助。任务筹办不得选择它作为当前方法，方法动作动态也不得把它作为动作来源。

### 6.1 本能方法判定标准

不是所有操作都需要包装成本能方法或方法动作入口。

判定标准是：

```text
如果某段逻辑要作为自我的最小可执行动作，
    则必须具备明确输入参数规格、明确输出结果规格和动作入口；
    输入缺失时只能返回参数缺口；
    输出缺失时不能命中需求目标，也不能作为完成证据。

如果某段逻辑会持久改变方法、任务、需求或世界树中的特征状态，
    则该提交段必须有明确动作来源；
    若生成方法动作动态，则动作来源必须是对应语义方法 / 本能方法。

如果某段逻辑只是中间过程，
例如只读查询、因果反推、候选填充的本地列表、候选筛选、诊断、评分、排序、预测或回执整理，
    并且不直接持久写入方法、任务、需求或世界树特征状态，
    则可以由普通逻辑代码实现；
    不需要动作动态，也不需要本能方法。
```

同一流程中可以同时存在两类步骤：

```text
普通逻辑步骤：
    读取事实、计算候选、判断缺口、形成本轮临时结果。

提交动作步骤：
    把候选、状态、回执、结算或结构变化写入持久特征账。
```

例如：

```text
因果反推自我动作组合：
    只读因果模板和方法能力，返回由已实现本能方法组成的候选组合；
    不写方法动作句柄、不写任务状态、不写世界事实；
    因此第一版可以是普通逻辑接口。
    若组合链上存在未知动作、外部动作或缺输入输出规格的方法，
    该链段只能转成学习、观察或补动作入口需求，不能作为已实现复杂能力。

提交方法可执行入口：
    把明确的单步本能方法 ID 写入目标方法动作句柄；
    改变了方法域特征状态；
    因此必须由方法域提交动作承接。
```

最终判断不是“这个步骤是否重要”，而是：

```text
它是否把某个领域对象的特征状态正式改写进账。
该改写是否属于主链状态变化。
该方法是否允许被任务主动选择。
```

## 7. 任务完成动作动态

任务完成动作动态的动作来源是：

```text
本能方法_提交任务状态变化
```

标准链路：

```text
任务执行普通函数
    -> 运行回执：
        建议任务状态 = 完成
        目标是否达成 = true

任务管理线程
    -> 调用 本能方法_提交任务状态变化

本能方法_提交任务状态变化
    -> 写任务状态：
        执行中 -> 完成
    -> 生成任务状态方法动作动态
```

任务完成动作动态的动作来源不是任务管理线程，也不直接是被执行的业务方法。

业务方法负责世界事实动作动态；任务状态提交方法负责任务状态动作动态。

## 8. 需求满足动作动态

需求满足动作动态的动作来源是：

```text
本能方法_回写需求满足
```

标准链路：

```text
任务完成动作动态
    -> 自我线程收到任务完成回执
    -> 自我线程判断来源需求满足
    -> 调用 本能方法_回写需求满足
    -> 需求状态 / 被需求当前状态发生变化
    -> 生成需求状态方法动作动态
```

自我线程只是决定调用该方法，不是动作来源。

## 9. 动作动态链

不新增独立因果记录结构。方法动作动态之间通过来源特征串成因果链。

标准链：

```text
D0：世界事实动作动态
    方法 = 具体业务方法 / 提交类方法
    主体 = 世界存在
    特征 = 目标特征
    旧值 -> 新值

D1：任务状态动作动态
    方法 = 提交任务状态变化
    主体 = 任务
    特征 = 任务状态
    执行中 -> 完成
    来源动作动态 = D0

D2：需求状态动作动态
    方法 = 回写需求满足
    主体 = 需求
    特征 = 需求状态 / 被需求当前状态
    未满足 -> 已满足
    来源动作动态 = D1
    满足证据动态 = D0
```

## 10. 禁止项

```text
1. 没有方法来源时生成方法动作动态。
2. 线程直接作为方法动作动态来源。
3. 外部变化伪装成自我方法动作动态。
4. 任务状态、需求状态、方法状态变化绕过提交类本能方法。
5. 把观察动态 / 外部事件动态当成自我动作能力证据。
6. 把“主动动作”理解成无条件乱调。
7. 把“未达成父目标”直接记成动作动态失败。
8. 用成功 / 失败替代事实类型、相位、缺口、等待、派生、细化等真实事实。
9. 把先天特征写入逻辑当成任务可选择方法或动作动态来源。
10. 把被动状态动作当成普通候选方法、任务当前方法、学习目标或练习目标。
11. 把被动整理动作当成主链动作动态来源。
12. 用动作动态反向生成下一步动作；下一步动作必须由需求状态、任务状态、方法状态等正式状态驱动。
13. 把被动状态动作动态中的提交口名称当成可学习动作语义；被动状态动作动态的动作语义只能是 `被动动作`。
14. 把没有明确输入参数规格或输出结果规格的函数当成本能方法。
15. 用“函数运行成功”替代输出结果与需求目标之间的比较。
```

## 11. 最终定稿

```text
动作动态是明确方法动作造成事实变化的证据痕迹。
凡能落成方法动作动态的变化，都必须有一个对应的本能方法或方法动作入口作为动作来源。
动作动态不是胜负判定，而是方法运行造成的事实动态。
本能方法是自我的最小可执行动作；最小动作必须有明确输入、明确输出和明确动作动态落账规则。
主动动作可以被任务选择；被动状态动作只提交状态证据；被动整理动作必须退回生命周期普通代码。
```
