## 1. 总原则

2026-05-13 修订：

```text
任务筹办不再是本能方法，也不进入方法树候选集。
任务筹办改为任务管理生命周期普通函数，并保持单步循环执行。
每一轮任务筹办只根据当前任务状态、来源需求、候选方法和方法状态形成一个筹办过程回执。
```

核心原则：

```text
任务筹办是任务管理生命周期普通函数。
任务筹办的语义目标是让任务从初始状态逐步具备就绪条件。

任务筹办不独占所有中间动作。
凡是中间过程改变了任务、自我、方法、世界中的某个特征，
都必须由对应本能方法完成，并由该方法生成动作动态。
```

任务筹办本身只形成筹办过程回执、候选选择结果和缺口提示；任务状态变化仍由 `提交任务状态变化` 本能方法提交并生成任务状态动作动态。

任务筹办不能在自己内部递归执行子任务、学习链或执行链。它发现缺口后只返回等待 / 派生 / 重筹办提示；后续由 `提交_生成缺口子需求` 或统一需求树更新提交入口正式生长需求，任务管理线程创建或推进子任务，再在下一轮筹办中读取已经回流的事实。

任务筹办也不能把“某类需求应先补某类前置能力”写成自身逻辑。此类关系若成立，必须能被追溯为：

```text
需求目标自带的条件；
世界树因果条件或方法模板；
临时因果视图中的条件补齐 / 证据补齐 / 方法就绪路径；
候选方法的条件节点、结果节点或条件结果对；
已经由提交入口裁决入树的子需求。
```

如果上述来源均不存在，任务筹办应返回路径 / 条件来源不足或学习缺口，而不是新增领域硬编码分支。

## 1.1 父任务、汇总任务与叶子任务

当前口径固定为：

```text
每个任务都必须有方法头承接。
不是每个任务都需要绑定单步本能方法。
只有普通可任务化叶子任务必须最终具备可执行本能动作。
```

方法头承接不等于当前已经有可执行方法动作，也不表示任务筹办可以在无路径、无候选时自动创建占位方法头。对外需求任务允许暂时只有既有方法头、既有候选方法或外部支撑等待事实而没有可执行动作入口；若普通可任务化叶子任务完整查路径和查既有方法后仍无候选，本轮应返回无路径 / 无方法挂起回执，等待事实、外部输入或后续正式学习机制提供可定位缺口。

其中，父任务 / 汇总任务的方法可以是：

```text
复合方法 / 任务抽象方法：
    由复合需求、复合特征分解、子需求链、子任务链和结果归并规则抽象得到。
    它的核心不是单步执行，而是拆分、等待、归并、重筹办、回写和结算触发。
```

任务分层如下：

```text
父任务 / 汇总任务：
    承接父需求，负责组织子需求、子任务、等待、归并、重筹办和结算触发。
    必须有复合方法 / 任务抽象方法承接。
    不要求绑定单步业务本能方法。
    不以“当前方法为空”作为失败条件。

中间任务：
    仍可继续拆分或等待子结果。
    只要存在可生长子需求、可等待子任务、可归并子结果，就不强制进入方法候选选择。

叶子任务：
    不再继续向下拆分，必须直接产生可验收结果。
    必须最终绑定本能方法 / 可执行动作入口。
```

这里的叶子只是结构前提。若来源需求的目标特征定义视图表示 AND组、OR组、方法路径组、因果子链组织节点或结构性缺口，即使当前没有子节点，也不得直接进入普通方法候选选择；应先按该目标特征的展开、聚合、路径选择、结算令牌或治理缺口规则返回过程回执。

因此任务筹办必须先判断本轮任务形态：

```text
如果任务仍是父任务 / 中间任务：
    若来源需求是复合需求，优先按复合特征分解成子需求 / 子任务。
    返回等待、归并、派生或重筹办回执。
    可以不填充候选本能方法集。
    可以不写当前方法。

如果任务是普通可任务化叶子任务：
    必须完整遍历方法树填充候选集。
    候选集非空时，必须从候选集中选择当前方法。
    候选方法存在时，必须判断该方法是否具有真实可执行入口、条件结果对和可绑定参数。
    候选集为空时，不创建占位方法头，不写当前方法；返回挂起 / 等待回执并记录候选数量、路径查找结果和挂起原因。
```

父任务进入就绪，不表示父任务自身找到了业务本能方法；它表示其下游子任务 / 子需求 / 子结果已经使父任务具备继续推进或交付汇总结果的条件。

## 2. 任务筹办单步循环

### 2.1 任务管理生命周期普通函数_任务筹办

定位：

```text
单步筹办循环函数。
```

它统领：

```text
任务初始状态
-> 任务具备就绪条件
```

直接职责：

```text
1. 读取任务虚拟存在和任务状态。
2. 根据任务状态判断本轮是否需要筹办。
3. 读取任务来源需求。
4. 解析目标宿主、目标特征类型、当前状态、目标状态、满足关系。
5. 判断当前任务是父任务 / 中间任务、逻辑组织节点，还是普通可任务化叶子任务。
6. 如果是父任务 / 中间任务，检查子需求、子任务、子结果和等待条件，形成等待 / 归并 / 重筹办 / 可继续推进回执。
7. 如果来源需求目标特征是 AND组 / OR组 / 方法路径组 / 因果子链组织节点，按其目标特征定义视图形成展开、聚合、路径选择或结算闸门回执。
8. 如果是普通可任务化叶子任务，先填充任务方法候选集。
9. 如果是普通可任务化叶子任务，再从候选集中选择当前方法。
10. 如果是普通可任务化叶子任务，根据当前方法的方法状态、动作入口、条件结果对和参数绑定情况判断是否可就绪。
11. 如果普通可任务化叶子当前方法不可用，形成 `方法状态 = 可用` 等缺口回执。
12. 如果普通可任务化叶子当前方法可用且参数可绑定，形成可就绪回执。
13. 生成任务筹办运行存在或等价过程结果。
14. 在运行存在中写入筹办回执。
```

上述职责可归并为：

```text
找路径：解析目标并查询因果 / 子需求 / 子结果能否形成可达成路径。
找方法：按结果能力填充候选方法集并选择当前方法。
找条件：按需求条件、因果条件、方法条件和参数绑定规则识别未满足项。
```

不得扩展为：

```text
按安全 / 服务 / 观察等领域目标特征直接生成固定前置需求。
按方法状态值直接写死某个学习方法。
按外设、相机、控制面板等模块名直接分派筹办路径。
```

输出位置：

```text
运行存在：
    筹办回执
    筹办状态段轨迹
    当前方法候选
    筹办缺口类型
    派生需求提示
    已回流子任务结果引用
    已回流子方法结果引用
    建议任务状态

输出结果场景：
    一般不写任务状态。
    如果子方法产生世界事实，由子方法写入。

方法虚拟存在：
    不写。任务筹办不是方法，没有自己的方法虚拟存在。
```

其中 `当前方法候选` 和 `当前方法` 对父任务 / 中间任务 / 逻辑组织节点可以为空；对普通可任务化叶子任务必须由候选填充与选择流程产生。

任务筹办不生成方法动作动态。它可以形成这些过程回执事实：

```text
筹办运行事实已形成
筹办回执已生成
候选方法已确定
筹办缺口已形成
可就绪依据已形成
```

这些事实只是任务管理过程回执，不是方法动作动态。若要把候选方法集、当前方法、可执行输入参数场景等写入任务虚拟存在，必须由 `同步筹办回执到任务` 完成。

任务筹办不直接生成：

```text
任务状态：未启动 -> 就绪
```

该任务状态动作动态来源必须是：

```text
本能方法_提交任务状态变化
```


输入：

```text

```

写入任务特征：

```text

筹办状态段轨迹

```

```text

特征 = 最近筹办运行存在 / 当前方法 / 可执行输入参数场景 / 筹办缺口类型
事实 = 筹办回执已同步到任务
```

### 3.2 本能方法_提交任务状态变化

职责：

```text
统一提交任务状态变化。
```

可覆盖的筹办段状态变化：

```text
未启动 -> 筹办中
筹办中 -> 等待中
等待中 -> 待重筹办
待重筹办 -> 筹办中
筹办中 -> 就绪
筹办中 -> 无法执行
```

动作动态：

```text
方法 = 提交任务状态变化
主体 = 任务虚拟存在
特征 = 任务状态
事实 = 任务状态已推进
```

其中：

```text
任务进入就绪的动作动态来源 = 提交任务状态变化
```

不是 `任务筹办`。

```text
任务状态 -> 等待中
```

```text
提交任务状态变化
```

动作动态：

```text
方法 = 挂起任务等待子需求
主体 = 任务虚拟存在
特征 = 等待原因 / 阻塞子需求引用

```

### 3.4 本能方法_唤醒任务重筹办

职责：

```text
当子需求满足、方法可用、参数补齐后，让父任务重新进入筹办段。
```

输入：

```text
父任务
```



```text

```

## 4. 需求树协作方法

任务筹办无法一步就绪时，不是失败，而是需求树继续细化。
这里的“一步”指当前一轮任务筹办函数调用。
任务筹办本轮只返回缺口和派生提示，不在本函数内继续调用学习方法、创建子任务或执行子任务。

### 4.1 本能方法_派生需求入树

职责：

```text
把任务筹办缺口转成更细的原子需求。
```

输入：

```text
父需求
父任务
任务筹办运行存在
筹办缺口类型
目标宿主
目标特征类型
当前状态
目标状态
满足关系
派生归因
```

输出：

```text
新子需求
需求关系
阻塞父任务标记
派生来源动作动态
```

典型派生：

```text
无既有候选方法
    -> 完整候选填充后仍为空，任务筹办不创建占位方法头
    -> 当前方法为空，候选数量为 0
    -> 返回无路径 / 无方法挂起回执
    -> 调度继续推进其他可执行任务

候选方法不可用
    -> 子需求：候选方法.方法状态 = 可用

候选方法缺执行入口
    -> 子需求：候选方法.执行入口状态 = 已形成

参数配对失败
    -> 子需求：缺失参数已绑定 / 已获得

条件节点不满足
    -> 子需求：输入条件场景满足候选方法条件
```

动作动态：

```text
方法 = 派生需求入树
主体 = 自我需求治理账 / 自我需求树
特征 = 子需求集 / 需求关系图
事实 = 子需求已派生
```

## 6. 候选方法发现与参数协作方法

### 6.1 本能方法_查找候选方法

可以复用已有 `查找特征类型`，但任务筹办链中应有明确的候选方法查找动作来源。

职责：

```text
根据目标特征类型查找结果能力确定命中的方法。
```

输入：

```text
目标宿主
目标特征类型
目标状态
满足关系
方法仓库
```

输出：

```text
候选方法集
候选方法数量
候选结果项
```

动作动态：

```text
方法 = 查找候选方法
主体 = 任务筹办运行存在
特征 = 候选方法集
事实 = 候选方法集已形成
```

### 6.2 本能方法_选择当前方法

职责：

```text
从候选方法集中选择当前方法。
```

输入：

```text
候选方法集
任务上下文
来源需求目标
已有当前方法
```

输出：

```text
当前方法
选择理由
候选方法排序或优先级
```

动作动态：

```text
方法 = 选择当前方法
主体 = 任务筹办运行存在 / 任务虚拟存在
特征 = 当前方法
事实 = 当前方法已确定
```

如果当前方法最终写入任务虚拟存在，应由 `同步筹办回执到任务` 完成。

选择当前方法必须采用分层排序。候选集必须先由“方法结果能力是否命中任务目标”完整填充，当前方法只能从候选集中选择。

第一优先级是方法结果与任务目标的一致程度：

```text
目标宿主越一致越优先；
目标特征类型越一致越优先；
目标状态 / 目标值越一致越优先；
满足关系越一致越优先；
固定特征类型确定命中优先于参数化命中；
直接目标结果命中优先于间接或待补齐命中。
```

结果一致程度高的方法，即使当前还需要补条件、补参数或补状态，也优先于结果只粗略命中的方法。不能因为某方法当前更容易执行，就选择一个结果目标不一致的方法。

在结果一致程度相同的候选之间，直接满足全部执行条件的方法优先：

```text
方法状态可用；
有执行入口；
有条件结果对；
必需条件全部满足；
参数全部可绑定；
禁止项未命中。
```

如果存在多个结果一致程度相同且直接满足全部条件的方法，继续按以下顺序排序：

```text
1. 禁止项少者优先；
2. 风险约束少者优先；
3. 前置冲突少者优先；
4. 预计效率高者优先；
5. 预计耗时少者优先；
6. 能耗和资源占用少者优先；
7. 副作用少者优先；
8. 最近复现次数多、失败次数少、派生稳定分高者优先。
```

只有当不存在同等结果一致程度下直接满足全部条件的方法时，才进入过程型 / 可补齐候选：

```text
缺少条件但有明确补齐路径；
缺少参数但可由已知方法获得；
方法不可用但已有学习链可推进；
禁止项可通过子需求解除；
需要任务筹办继续拆解缺口。
```

再后才进入不确定候选：

```text
可能可学习；
可能可探索；
证据不足但有候选线索；
需要外界反馈或观察。
```

因此，`任务筹办` 不声明方法结果能力，也不作为候选方法参与选择。

```text
任务筹办是任务管理生命周期普通函数；
它负责组织候选填充、选择、缺口识别和回执形成；
它每轮只执行一次筹办判断；
真正能改变 方法状态 / 条件结果对 / 参数 / 世界特征 的，必须是对应方法。
```

对于 `方法状态 = 可用 / 好用` 这类目标，候选集不应写死为某一个学习方法，也不应按状态值特判学习方法。应先包含所有结果能力能够命中该任务目标的候选，再按“方法结果与任务目标的一致程度”选择；当前目标方法的缺口阶段只能通过候选方法自己的条件、结果能力和执行反馈体现。

候选方法必须显式声明自身结果能力的目标特征类型和目标值。第一版固定口径：

```text
自我_尝试学习：
    结果能力包括 方法条件结果配对状态 = 1；
    结果能力包括 方法状态 = 可用。

自我_练习：
    结果能力包括 方法状态 = 好用。
```

当任务目标是 `方法状态 = 好用` 时，`方法状态 = 好用` 的结果项优先于 `方法状态 = 可用` 的结果项；当任务目标是 `方法状态 = 可用` 时，`方法状态 = 可用` 的结果项优先。该选择来自结果能力与任务目标值的比较，不来自筹办函数对学习方法的硬编码。

`自我_练习` 与目标方法的账本边界必须保持清楚：

```text
自我_练习 = 练习方法 A；
被练习的方法 = 目标方法 B。

A 的职责：
    复用或构造练习输入场景；
    调用 B 的真实动作入口；
    读取 B 运行后由 B 自己写下的运行账；
    在 A 的运行存在 / 输出结果场景中写入目标方法运行观察、好用差距和失败原因。

A 不得写入 B 的方法运行次数、方法成功次数、方法最近连续成功次数、方法状态、方法稳定状态和最近运行虚拟存在。
B 的成功 / 失败只能由 B 自己的运行结果和运行账确认。
A 自身执行成功，不等于 B 成功。
```

```text
条件结果关系未知 / 未证实
    -> 通常由结果能力命中“方法状态=可用”的候选方法承接；

已有条件结果证据但未入账
    -> 通常由结果能力命中“条件结果对已建立”的候选方法承接；

条件结果对已入账且达到可用判据
    -> 通常由结果能力命中“方法状态=可用”的提交方法承接；

已可用但稳定性 / 好用度不足
    -> 通常由结果能力命中“方法状态=好用”的候选方法承接；

缺口尚未能直接提交
    -> 由任务筹办普通函数继续拆解子需求，不把任务筹办当候选方法。
```

## 11. 推荐执行链

```text
任务筹办
-> 查找候选方法
-> 选择当前方法
-> 检查方法条件是否满足
-> 配对参数
-> 同步筹办回执到任务
```

## 12. 最终定稿

任务筹办要完成“初始状态 -> 就绪状态”这一整段，需要一组协作方法。

```text
任务筹办负责单步读取任务状态、填充候选、选择当前方法、识别缺口并生成筹办回执；
同步筹办回执到任务负责写任务筹办事实；
提交任务状态变化负责真正推进任务状态；
派生需求入树负责让缺口变成更细目标；
学习类方法负责让方法从不会变会；
归并子结果负责把子任务、子方法结果纳入父筹办结果；
唤醒重筹办负责让父任务继续前进。
```

一句话：

```text
任务筹办是任务管理生命周期中的单步筹办循环；
其通用职责限于找路径、找方法、找条件；
每轮只产出本轮回执，缺口通过需求树和子任务在后续轮次回流；
每个中间特征变化都必须交给对应本能方法或方法动作入口落账。
```
