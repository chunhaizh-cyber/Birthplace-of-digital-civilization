```text
规范编号：011002
上级规范：011 特征类规范
相关上级：004 特征值符号三态比较底层逻辑规范
相关约束：005 主信息字段与结构新增准入约束规范
状态：二次特征专项收口规范
```

## 0. 与上级规范的关系

本规范用于收束二次特征的本体、边界和第一版可实现范围。

若本规范与 `004 特征值符号三态比较底层逻辑规范` 冲突，以 `004` 为准：

```text
所有方向必须来自有符号比较量：
    r < 0
    r = 0
    r > 0

生成、消除、增强、减弱、转换、促进、抑制等词，
不得作为底层逻辑字段。
```

若本规范与 `005 主信息字段与结构新增准入约束规范` 冲突，以 `005` 为准：

```text
能由特征、二次特征、方法动作、因果追踪表达的内容，
不得新增平行字段或平行结构。
```

## 1. 总目标

当前阶段只实现：

```text
两个不同特征类型之间的变化关系比较。
```

推荐命名：

```text
二元异类变化关系
双特征变化对应关系
```

它表达：

```text
一个特征类型发生某个变化量时，
另一个不同特征类型发生什么方向、什么范围的变化量。
```

例如：

```text
加热时间 +1 秒
    -> 温度 +[0.4, 0.7] 度

动作强度 +1 单位
    -> 位移 +[3, 5] 毫米

剩余保障时间 -1 分钟
    -> 风险值 +[2, 6]
```

这是一条变化映射经验，不是算术比例。

## 2. 第一版禁止范围

当前阶段不做：

```text
1. 多特征二次特征。
2. 自然语言关系理解。
3. 复杂高阶关系推导。
4. 除法比例。
5. 从大步长样本自动换算单位步样本。
6. 多基准项 / 多响应项。
7. 复杂函数拟合。
8. 任意不同特征类型自由比较。
```

多特征影响应进入：

```text
条件场景
方法分支条件
因果解释链
```

不得塞入单个二次特征。

## 3. 二次特征定位

二次特征不是判断器，也不是普通状态。

二次特征是：

```text
比较关系的特征化。
```

它可以表达：

```text
两个状态之间的比较关系；
两个特征值之间的差值 / 方向 / 区间；
一个动态的初始值与结果值之间的变化关系；
两个不同特征类型变化量之间的对应关系。
```

一旦比较关系沉淀为二次特征节点，它就进入特征体系，可以被：

```text
场景引用
方法条件引用
方法结果引用
因果条件引用
因果结果引用
查询筛选
概念树归并
更高阶二次特征生成
```

## 3.1 抽象归类关系的记录边界

当需要记录“具体存在属于某抽象存在”时，不得把来源、置信、证据或冲突情况写入抽象存在本体，也不得新增 `抽象存在主信息类`。

可追溯归类事实应由二次特征或等价关系事实承载：

```text
主体 = 具体存在 E
客体 = 抽象存在 A
概念模板 = 属于抽象存在
来源动态 = 观察 / 识别动作动态
来源场景 = 当前观察场景
来源因果 = 归类因果模板或因果实例，可选
标量值 = 置信度 / 命中度，可选
```

`概念集` 可以作为快速匹配缓存同步更新；需要解释“为什么属于、是否仍然属于、能否撤销或降低置信”时，以二次特征、状态、动态、场景和因果证据链为准。

本节不扩大第一版二元异类变化关系的学习范围；若当前实现尚未具备完整主体 / 客体归类二次特征节点，应先使用现有状态、动态、场景索引和因果实例保持证据链，不得因此把归类证据塞回存在主信息。

## 4. 二元异类变化关系不是状态特征

二元异类变化关系至少需要：

```text
源态
目标态
基准变化项
响应变化项
变化上下文
```

变化上下文可以是：

```text
动作前 -> 动作后
当前状态 -> 目标状态
源场景 -> 目标场景
输入变化 -> 输出变化
预测前 -> 修正后
```

因此它属于：

```text
变化信息
过程信息
动态信息
转换信息
结果动态模板
```

不得作为：

```text
普通状态信息
静态条件信息
静态虚拟存在当前特征
```

状态信息只回答：

```text
现在是什么。
```

二元异类变化关系回答：

```text
从一个态到另一个态，两个不同特征类型的变化如何对应。
```

## 5. 最小语义结构

规范层建议使用以下语义结构描述，具体代码实现可以由现有二次特征、动态、场景和方法结果模板承载，不要求必须新增同名结构体。

```cpp
结构_变化项
{
    特征类型ID 特征类型;
    变化量或变化量区间;
    比较方向符号或允许方向;
    单位ID 单位;
    状态角色 起始态;
    状态角色 结束态;
};

结构_二元异类变化关系
{
    关系ID;

    结构_变化项 基准变化项;
    结构_变化项 响应变化项;

    关系态域枚举 关系态域;

    动作ID 可选动作;
    方法ID 来源方法;
    分支ID 来源分支;

    场景ID 来源条件场景;
    场景ID 来源结果场景;
    动态ID 来源动态;

    证据样本集合;
    命中次数;
    失败次数;
};
```

最关键字段是：

```text
基准变化项
响应变化项
```

例如：

```text
基准变化项：
    特征类型 = 加热时间
    变化量 = +1
    单位 = 秒

响应变化项：
    特征类型 = 温度
    变化量 = [+0.4, +0.7]
    单位 = 度
```

## 6. 方向表达

方向必须来自比较关系，不得新增业务解释枚举作为底层事实。

底层方向应表达为：

```text
比较量符号
允许方向
方向区间
差值 / 变化量
```

其中：

```text
允许方向：
    表示比较量 r 的符号是否允许命中。

方向区间：
    表示已经确定方向后的量域细分。

差值 / 变化量：
    表示可用于距离、余量、多次特征生成的关系量。
```

不得把以下词写入二次特征本体作为权威字段：

```text
增加
减少
靠近
远离
改善
恶化
顺时针
逆时针
促进
抑制
```

这些词只能由：

```text
特征类型
比较对象
比较量符号
方向区间
显示解释器
```

临时解释出来，服务控制面板、日志或人类文档。

## 7. 比较规则

二元异类变化关系的比较不是跨特征数学运算，而是结构匹配。

一条观测样本是否命中已有关系模板，只检查：

```text
1. 基准特征类型是否相同。
2. 响应特征类型是否相同。
3. 基准变化量是否匹配。
4. 基准方向是否匹配。
5. 响应方向是否匹配。
6. 响应变化量是否落入区间。
7. 关系态域是否一致。
8. 动作 / 方法 / 分支是否一致或兼容。
```

伪逻辑：

```cpp
bool 匹配二元异类变化关系(模板, 样本)
{
    if (样本.基准变化项.特征类型 != 模板.基准变化项.特征类型) return false;
    if (样本.响应变化项.特征类型 != 模板.响应变化项.特征类型) return false;

    if (!方向命中(样本.基准变化项, 模板.基准变化项)) return false;
    if (!方向命中(样本.响应变化项, 模板.响应变化项)) return false;

    if (!基准变化量匹配(样本.基准变化项, 模板.基准变化项)) return false;
    if (!响应变化量落入区间(样本.响应变化项, 模板.响应变化项)) return false;

    if (样本.关系态域 != 模板.关系态域) return false;

    return true;
}
```

这里不做除法。

也不做：

```text
把 +5 自动折算成 +1。
```

## 8. 非单位变化样本处理

如果模板是：

```text
基准变化 +1
    -> 响应变化 [+3, +5]
```

但某次样本是：

```text
基准变化 +5
    -> 响应变化 +21
```

不得自动推成：

```text
基准变化 +1
    -> 响应变化 +4.2
```

正确处理只有三类。

### 8.1 作为独立步长关系

```text
基准变化 +5
    -> 响应变化 [+18, +24]
```

### 8.2 有过程轨迹时拆成真实单位样本

只有动态或场景真实记录了逐单位过程：

```text
第 1 单位变化 -> 响应 +4
第 2 单位变化 -> 响应 +5
第 3 单位变化 -> 响应 +3
```

才允许分别作为单位变化样本。

### 8.3 标记为大步长样本

```text
样本可记录；
但不用于更新 +1 单位对应模板。
```

这条规则用于防止系统把经验硬压成比例。

## 9. 关系类型注册

两个不同特征类型之间能不能形成二元异类变化关系，必须由关系类型注册或等价的模板声明决定。

不得自由比较任意特征类型。

允许示例：

```text
加热时间变化 -> 温度变化
动作强度变化 -> 位移变化
剩余时间变化 -> 风险值变化
资源投入变化 -> 完成度变化
```

禁止默认成立：

```text
颜色变化 -> 重量变化
名称变化 -> 温度变化
编号变化 -> 安全值变化
```

除非已经存在明确关系模板。

推荐注册语义：

```cpp
结构_异类变化关系类型注册
{
    关系类型ID;

    特征类型ID 基准特征类型;
    特征类型ID 响应特征类型;

    单位ID 基准单位;
    单位ID 响应单位;

    允许的基准方向集合;
    允许的响应方向集合;

    bool 是否允许单位步长关系;
    bool 是否允许多步长关系;
};
```

该注册可以由：

```text
抽象特征模板
方法结果动态模板
因果模板
专门注册表
```

承载。是否新增结构体应另按 `005` 准入约束审查。

## 10. 方法树中的位置

二元异类变化关系主要挂在：

```text
方法结果节点的结果动态模板
```

方法树推荐表达：

```text
方法头节点
    ├─ 动作
    ├─ 支持的基准特征类型集合
    ├─ 支持的响应特征类型集合
    ├─ 二元异类变化关系类型集合
    └─ 分支汇总

条件节点
    └─ 条件场景
        ├─ 一元特征区间
        └─ 静态二元关系约束，可选

结果节点
    ├─ 结果动态模板
    │    └─ 二元异类变化关系
    └─ 结果状态场景
         └─ 动作后状态区间
```

条件节点负责：

```text
动作前的状态条件。
```

结果节点负责：

```text
动作后的状态；
动作或转换造成的双特征变化关系。
```

## 11. 方法分支表达

一个方法分支可以表达为：

```text
条件场景
    + 动作
    + 二元异类变化关系模板
    + 结果状态场景
```

例如：

```text
方法：加热

条件场景：
    当前温度 ∈ [20, 40]
    材料类型 = 铁

动作：
    加热

二元异类变化关系：
    加热时间 +1 秒
        -> 温度 +[0.4, 0.7] 度

结果状态场景：
    动作后温度 ∈ [20.4, 40.7]
```

这里：

```text
材料类型
```

只是条件场景约束，不是二元异类变化关系的一部分。

如果同一条件区间下响应方向反复冲突，不得把矛盾吞进单个二元关系模板。应触发：

```text
条件节点拆分
条件场景补充约束
新增分支
```

## 12. 学习更新规则

执行后产生动态样本：

```text
动作 A
条件场景 C
基准变化项 X
响应变化项 Y
结果状态场景 R
```

更新流程：

```text
1. 找到方法头。
2. 找到条件分支。
3. 找到二元异类变化关系模板。
4. 判断样本是否命中。
5. 命中则更新基础统计。
6. 不命中则按差异处理。
```

差异处理规则：

```text
基准特征类型不同：
    不属于同一个关系模板。

响应特征类型不同：
    新建关系模板或忽略。

基准变化量不同：
    新建步长模板，不做除法换算。

响应方向不同：
    优先拆分条件区间，或新建结果节点。

响应变化量超出区间但方向相同：
    先记录边界样本；
    达到阈值后再扩张区间。

同一条件区间内响应方向反复冲突：
    说明条件维度不足；
    应补充条件特征或拆分条件节点；
    不得扩成多特征二次特征。
```

## 13. 与因果信息的关系

二元异类变化关系不是完整因果本体。

它可以作为：

```text
因果模板的条件比较模板
因果模板的因比较模板
因果模板的果比较模板
方法结果能力模板
执行后因果验收材料
```

完整因果仍需满足：

```text
条件比较集合 + 因比较集合 / 因方法 -> 果比较集合
```

如果只观察到：

```text
特征 A 的变化
特征 B 的变化
```

但不知道动作或条件，不得直接声称完整因果。只能形成：

```text
状态变化线索
二元异类变化关系候选
待补动作 / 待补条件材料
```

## 14. 最小可实现版本

第一版只需要支持：

```text
一个基准变化项
一个响应变化项
一个关系模板
一个比较函数
一个学习更新入口
```

最小语义：

```cpp
结构_变化项
{
    特征类型ID 特征类型;
    整数或定点数 变化量;
    区间 变化量区间;
    单位ID 单位;
    允许方向 方向;
};

结构_二元异类变化关系模板
{
    ID 关系模板ID;

    变化项 基准变化项;
    变化项 响应变化项;

    关系态域 态域;
    动作ID 动作;
    方法ID 方法;
    分支ID 分支;

    uint64_t 命中次数;
    uint64_t 失败次数;
};
```

不得在第一版加入：

```text
多基准项
多响应项
自然语言条件
复杂函数拟合
自动比例换算
多特征联合推理
```

## 15. 硬规则

```text
1. 二次特征只处理两个特征项之间的关系。
2. 二元异类变化关系只处理两个不同特征类型之间的变化对应。
3. 不做除法比例。
4. 不从大步长样本自动换算单位步样本。
5. 多特征影响进入条件场景，不进入二次特征。
6. 状态信息不存二元异类变化关系，只能引用相关动态或二次特征。
7. 方法结果节点通过结果动态模板承接二元异类变化关系。
8. 关系类型必须注册或由模板明确声明，不得任意跨特征比较。
9. 方向不得用解释性业务枚举作为底层事实，必须回到比较量符号、允许方向、方向区间和值域。
10. 二元异类变化关系候选不等于完整因果；缺动作或缺条件时只能作为因果补完材料。
```

一句话：

```text
当前只实现“基准特征变化项 -> 响应特征变化项”的二元异类变化关系比较；
多特征影响先留在条件场景里，不进入二次特征。
```
