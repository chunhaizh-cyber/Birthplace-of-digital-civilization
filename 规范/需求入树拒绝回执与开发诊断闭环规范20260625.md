## 0. 定位

本规范定义需求前材料、入树请求和派生需求消息在无法普通需求化时的闭环规则。

核心口径：

```text
拒绝普通需求化
    ≠ 不处理

拒绝入树
    = 进入拒绝回执闭环
```

需求入树拒绝回执是自我线程或需求提交入口生成的治理事件。它不是普通需求节点，也不是日志文本。它必须说明：

```text
1. 为什么不能普通需求化。
2. 后续进入哪一种闭环。
3. 由谁处理。
4. 是否可自动处理。
5. 是否允许重提入树。
6. 来源任务、来源需求、来源方法如何被影响。
7. 什么时候才算关闭。
```

## 1. 总规则

```text
1. 每类拒绝原因都必须有处理方案。
2. 没有处理方案的拒绝原因，不允许进入正式规范。
3. 入树拒绝不是终态。
4. 任意入树拒绝必须生成结构化拒绝回执。
5. 拒绝回执必须进入对应闭环处理器。
6. 禁止静默忽略。
7. 禁止仅记录日志但不改变任何治理状态。
8. 禁止把代码缺陷、外设内部材料字段、参数诊断强行普通需求化。
9. 来源任务必须接收入树成功或拒绝回执，并据此挂起、重筹办、降权、转学习、转观察验证、隔离路径或停止当前路径。
```

新增拒绝原因前，必须先补齐：

```text
拒绝原因
拒绝阶段
拒绝闭环类型
后续处理方案
可重试规则
来源任务影响
关闭标准
升级条件
```

否则该拒绝原因只能作为待确认材料，不得进入正式规范、正式枚举或机器判断。

## 2. 拒绝原因分类

拒绝原因先分为两类：

```text
可治理拒绝
不可运行期治理拒绝
```

### 2.1 可治理拒绝

可治理拒绝表示材料、证据、参数、观察或重复关系尚未满足普通入树要求，但系统可以通过运行期治理闭环处理。

包括：

```text
字段缺失
目标主体不可判定
目标特征缺失
当前状态缺失
目标状态缺失
来源因果不可解析
来源动态不可解析
参数诊断不需求化
外设内部材料字段
同批重复
近期重复
```

处理方向：

```text
自动补槽
退回来源模块补槽
挂起来源任务等待补齐
观察验证
学习缺口
参数重绑
来源任务重筹办
外设材料处理
合并 / 冷却
```

### 2.2 不可运行期治理拒绝

不可运行期治理拒绝表示系统实现、结构状态或状态机约束已经违反预期。它不得进入普通需求树，也不得由学习方法、观察方法或任务筹办路径吞掉。

包括：

```text
父需求非法
父为结构根且无合法映射
父子目标自复制
本应存在的来源动态为空
节点类型不符合预期
指针为空但逻辑上不允许为空
枚举值非法
需求树结构损坏
任务状态机非法跳转
代码缺陷型报告
```

处理方向固定为：

```text
开发诊断闭环
```

边界说明：

```text
来源动态不可解析：
    若是版本不同步、证据尚未送达、材料需补齐，属于可治理拒绝。
    若按当前流程该动态本应已经存在却为空或结构损坏，属于开发诊断闭环。

父为结构根：
    若能按目标特征映射到安全根、服务根、学习父域或内部治理父域，属于可治理重映射。
    若无法映射仍试图挂结构根，属于开发诊断闭环。
```

## 3. 拒绝闭环类型

拒绝回执必须绑定闭环类型：

```cpp
enum class 枚举_拒绝闭环类型 {
    内部治理闭环,
    来源任务内部闭环,
    外设材料闭环,
    学习闭环,
    观察验证闭环,
    开发诊断闭环,
    合并冷却闭环
};
```

每个闭环类型的最小语义：

| 闭环类型 | 适用对象 | 关闭标准 |
| --- | --- | --- |
| 内部治理闭环 | 可补槽、可重提、可重新判定父域的材料 | 补齐后重提成功，或转入其他明确闭环 |
| 来源任务内部闭环 | 参数绑定、方法内部材料、来源任务可自行重筹办的问题 | 来源任务拿到结构化处理结果并停止原路径重复派生 |
| 外设材料闭环 | 外设内部缓存、像素掩码、深度图、观察结果包等材料 | 材料进入外设材料仓库 / 观察结果包，或来源任务降级 |
| 学习闭环 | 缺方法、缺动作、缺条件结果对、缺参数映射、缺验证方法等 | 生成学习缺口材料或方法补全任务，且来源任务收到等待关系 |
| 观察验证闭环 | 当前状态、目标主体、证据可信性不可判定 | 生成观察验证材料，或确认不可观测并返回来源任务 |
| 开发诊断闭环 | 代码缺陷、结构损坏、状态机非法、逻辑上不允许的空值 | 开发诊断项建立，路径隔离；最终由代码修正、编译和回归测试关闭 |
| 合并冷却闭环 | 同批重复、近期重复 | 绑定既有需求 / 任务 / 回执，合并证据或进入冷却 |

## 4. 可治理拒绝处理表

| 拒绝原因 | 闭环类型 | 处理方案 | 关闭标准 |
| --- | --- | --- | --- |
| 字段缺失 | 内部治理闭环 / 来源任务内部闭环 | 可从来源任务、来源需求、动态补齐则自动补槽后重提；否则退回来源模块补槽并挂起来源任务 | 补齐后重提成功，或来源确认无法补齐并转诊断 |
| 目标主体不可判定 | 观察验证闭环 / 内部治理闭环 | 外部事实转观察识别缺口；内部事实读取虚拟存在或任务状态；仍不可判定则退回来源 | 主体明确，或来源路径被隔离 |
| 目标特征缺失 | 内部治理闭环 / 学习闭环 | 消息漏填则补槽；抽象特征不存在则转特征定义、方法补全或学习缺口 | 目标特征明确，或转开发诊断 |
| 当前状态缺失 | 观察验证闭环 / 来源任务内部闭环 | 外部现实状态缺失则观察验证；内部治理状态缺失则读取任务 / 方法虚拟存在；材料缺失则退回来源 | 当前状态获得，或确认不可观测 |
| 目标状态缺失 | 内部治理闭环 | 回到定义展开或临时因果视图，重新构造目标状态 | 目标状态明确，或转规则缺陷诊断 |
| 来源因果不可解析 | 学习闭环 / 内部治理闭环 | 重建临时因果视图；因果缺失则转学习；引用损坏则转开发诊断 | 因果可解析，或学习任务入树，或诊断项建立 |
| 来源动态不可解析 | 内部治理闭环 / 开发诊断闭环 | 可补证据则重读动作动态和结果场景；逻辑上应存在却缺失则转开发诊断 | 动态可解析，或任务结果作废并建立诊断项 |
| 参数诊断不需求化 | 来源任务内部闭环 / 学习闭环 | 参数绑定重试、参数映射学习、方法候选降权、任务重筹办 | 参数绑定成功，或候选方法判定不可用，或转学习 |
| 外设内部材料字段 | 外设材料闭环 / 来源任务内部闭环 | 转外设材料仓库、方法内部材料依赖或观察结果包 | 来源任务拿到材料句柄，或确认材料不可用 |
| 同批重复 | 合并冷却闭环 | 合并到同批既有候选、回执或需求，补证据计数 | 已合并，不再重复派生 |
| 近期重复 | 合并冷却闭环 | 进入冷却，绑定既有未闭合需求 / 任务，增加重复压力计数 | 冷却关闭或既有需求闭合 |

## 5. 代码缺陷型拒绝硬规则

代码缺陷型拒绝表示系统自身实现违反预期约束。它不是普通需求缺口。

典型表现：

```text
空指针
空数据
枚举值越界
节点类型不符合预期
引用不可解析且不应不可解析
字段本应存在但不存在
流程走到不该走的分支
任务状态与阶段不一致
需求节点结构损坏
动态记录缺关键字段
```

硬规则：

```text
1. 代码缺陷型拒绝不是普通需求缺口。
2. 代码缺陷型拒绝不得进入普通需求树。
3. 代码缺陷型拒绝不得由学习方法、观察方法或任务筹办路径自动吞掉。
4. 代码缺陷型拒绝必须生成开发诊断项。
5. 开发诊断项必须记录复现上下文、来源任务、来源需求、来源方法、失败阶段、失败原因和版本信息。
6. 来源任务必须收到实现缺陷阻断回执，并停止当前路径重复筹办。
7. 系统必须进行日志记录和弹窗 / 报错提示。
8. 该类问题只能通过修正代码、重新编译和回归测试关闭。
```

代码缺陷型报告的固定属性：

```text
拒绝闭环类型 = 开发诊断闭环
是否可自动处理 = false
是否可普通需求化 = false
是否可重试 = false
必须隔离来源路径 = true
必须通知开发者 = true
```

运行期可以完成：

```text
发现
隔离
保留证据
防止扩散
通知
等待修复
```

运行期不得宣称：

```text
代码缺陷已经由需求树解决
代码缺陷已经由学习链解决
代码缺陷已经由观察验证解决
代码缺陷已闭合
```

## 6. 开发诊断闭环

代码缺陷型拒绝进入以下闭环：

```text
检测
  -> 阻断 / 降级 / 隔离
  -> 记录完整诊断信息
  -> 弹窗 / 报错 / 通知开发者
  -> 禁止同路径重复污染治理流程
  -> 修正代码
  -> 编译
  -> 回归测试
  -> 关闭诊断项
```

开发诊断项的最低字段建议：

```cpp
struct 结构_开发诊断项 {
    I64 诊断项ID = 0;

    I64 来源回执ID = 0;
    I64 来源任务ID = 0;
    I64 来源需求ID = 0;
    I64 来源方法ID = 0;

    枚举_需求入树拒绝原因 原始拒绝原因{};

    std::string 文件名;
    std::string 函数名;
    int 行号 = 0;

    std::string 断言表达式;
    std::string 错误摘要;
    std::string 复现上下文;

    I64 需求树版本 = 0;
    I64 任务版本 = 0;
    I64 方法版本 = 0;
    I64 动态版本 = 0;

    bool 已弹窗 = false;
    bool 已写日志 = false;
    bool 已隔离来源路径 = false;

    enum class 状态 {
        新建,
        已报告,
        等待修复,
        已修复待验证,
        回归通过,
        已关闭
    } 当前状态 = 状态::新建;
};
```

文本字段只允许承载开发者可读的复现证据、错误提示和日志检索信息；机器状态推进必须读取枚举、I64 关联对象、版本号和隔离标志，不得用错误摘要、函数名或文本标签作为业务判断依据。

开发诊断项的运行期关闭状态只能表示：

```text
诊断项已建立
路径已隔离
来源任务已收到阻断回执
已等待开发修复
```

最终关闭必须同时满足：

```text
代码已修正
编译通过
对应回归通过
诊断项状态更新为已关闭
来源路径允许恢复或已替换
```

## 7. 冗余检查位置

代码缺陷型诊断应通过三层冗余检查发现：

```text
1. 编译期 / 预编译检查：
   类型、枚举、接口、静态断言、必需字段结构。

2. 运行期前置检查：
   空指针、空数据、节点类型、状态机合法性、引用可解析性。

3. 运行期一致性检查：
   任务状态与阶段一致性、需求父子关系一致性、动态记录完整性、来源任务与来源需求一致性。
```

运行期检查发现的问题，如果属于系统实现违反预期约束，必须生成代码缺陷型诊断项，而不是普通需求、学习需求或观察需求。

## 8. 来源任务影响

派生需求消息被拒绝后，来源任务必须接收回执。

对于可治理拒绝，来源任务可以进入：

```text
等待派生需求入树
派生需求被拒绝_等待补槽
派生需求被拒绝_已合并既有
派生需求被拒绝_转学习
派生需求被拒绝_转观察验证
派生需求被拒绝_需重筹办
```

对于开发诊断闭环，来源任务必须进入：

```text
实现缺陷阻断
来源路径隔离
等待开发修复
```

禁止：

```text
筹办失败
    -> 生成派生需求
    -> 入树拒绝
    -> 来源任务不知道
    -> 下一轮继续生成同一派生需求
```

| 入树拒绝回执 | 后续 `结构_需求入树拒绝回执` 或需求域回执节点 | I64、枚举、版本号、关联需求 / 任务 / 方法 ID | 自我线程 / 需求提交入口 | 任务管理、需求治理、诊断处理器 | 回执有闭环类型、处理状态和关联对象 |

| 拒绝闭环类型 | `枚举_拒绝闭环类型` | 枚举 | 拒绝策略映射 | 拒绝回执处理器 | 闭环类型不为空 |
| 开发诊断项 | 后续开发诊断账本 / 诊断节点 | I64、枚举、版本号、诊断证据文本 | 开发诊断闭环处理器 | 开发者、回归处理器、来源任务回执 | 已记录上下文、已隔离路径、关闭需编译回归 |

| 合并冷却 | 既有需求 / 任务 / 回执关联 | I64、冷却时刻、计数 | 拒绝处理器 | 需求治理 / 任务管理 | 重复材料绑定既有对象 |

本表是后续实现映射，不代表当前代码已经全部接入。未形成项目结构闭环前，不得宣称拒绝回执治理或开发诊断闭环已经实现。

## 10. 禁止项

```text
1. 禁止把代码缺陷转成普通需求节点。
2. 禁止把代码缺陷转成学习需求来绕过源码修复。
3. 禁止把代码缺陷转成观察验证缺口来掩盖实现错误。
4. 禁止只打印日志后让来源任务继续原路径重筹办。
5. 禁止没有处理方案的拒绝原因进入正式枚举或正式规范。
6. 禁止用字符串摘要、错误文本或日志文案作为拒绝处理状态。
7. 禁止把诊断项建立误写成代码缺陷已修复。
```

## 11. 最终口径

```text
普通缺口走治理闭环；
材料缺口走材料闭环；
学习缺口走学习闭环；
重复缺口走合并冷却闭环；
代码缺陷走开发诊断闭环。
```

拒绝入树可以，拒绝治理不可以。系统可以说“这不是一个普通需求”，但必须继续说清楚：它转给谁、怎么处理、什么时候关闭、失败后如何升级。
