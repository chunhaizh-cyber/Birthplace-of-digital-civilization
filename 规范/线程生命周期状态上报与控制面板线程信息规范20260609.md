# 线程生命周期状态上报与控制面板线程信息规范 20260609

规范编号：002002

父级规范：

```text
001 方法动作动态硬规则规范20260512.md
002 自我线程与任务管理线程权责边界规范20260512.md

```

若本文与父级规范冲突，以上级规范为准。

## 1. 目标

本规范收束线程创建、线程运行状态变化、线程堵塞 / 暂停 / 恢复、线程退出和线程异常的上报路径。

目标是让控制面板及时掌握：

```text
有哪些线程
线程用途是什么
线程名称是什么
线程逻辑 ID / 系统线程 ID 是什么
线程由谁创建或管理
线程当前生命周期 / 运行状态是什么
线程是否堵塞、暂停、退出或故障
```

该信息只服务线程可见性、健康监控、控制面板展示和诊断排错，不作为任务状态、需求树、世界事实、方法动作动态或安全 / 服务结算依据。

## 2. 核心边界

```text
纯线程状态消息 -> 消息中间件 -> 控制面板线程信息模块。
任务治理消息 -> 按任务管理上行协议进入自我线程。
```

纯线程状态消息包括：

```text
线程创建
线程启动中
线程运行中
线程堵塞 / 等待
线程暂停
线程恢复
线程停止请求中
线程收尾中
线程退出前
线程已退出
线程故障
线程异常退出
```

这些消息不得进入自我线程治理邮箱，不得落自我内部世界治理事实，不得生成主动动态、被动动态、方法动作动态或治理动作动态。

任务管理工作线程若产生以下内容，不属于纯线程状态消息：

```text
任务执行尝试状态
任务结果状态
任务缺口 / 派生需求
执行前许可请求
观察事实承接请求
任务回执同步材料
```

这些内容必须由任务管理界面线程按任务管理上行消息承接和上报，不得用通用线程状态变化消息替代。

## 3. 发送责任

### 3.1 创建消息

每个线程创建时，由创建者向控制面板线程信息模块发送线程创建消息。

创建者包括但不限于：

```text
自我线程启动者
任务管理界面线程启动者
任务管理工作线程池管理者
控制面板摘要线程启动者
外设控制线程 / 外设代理线程创建者
其他独立后台线程创建者
```

如果系统线程 ID 只能在线程入口内取得，创建者先发送带逻辑 ID 的创建消息；线程入口取得系统线程 ID 后，必须补发一次状态更新消息完成绑定。

### 3.2 状态变化消息

线程自身在生命周期或运行状态发生变化时，必须向控制面板线程信息模块发送状态变化消息。

状态变化至少包括：

```text
启动中 -> 运行中
运行中 -> 堵塞 / 等待
堵塞 / 等待 -> 运行中
运行中 -> 暂停
暂停 -> 运行中
运行中 -> 停止请求中
停止请求中 -> 收尾中
收尾中 -> 已退出
任意状态 -> 故障
```

线程状态消息发送不得长期阻塞业务线程。控制面板队列不可用时，发送方应记录独立错误日志或诊断日志，并继续按线程自身职责收口。

为避免线程创建早于控制面板线程启动导致创建消息丢失，线程状态消息必须先写入消息中间件缓存，再由控制面板线程信息模块消费。

### 3.3 退出消息

线程自身退出前必须发送退出前消息。

正常退出时应包含：

```text
退出原因键
退出阶段
是否正常退出
最后一次运行状态
最后一次处理对象摘要
退出时间
```

如果线程崩溃、被强制终止或未能执行退出前上报，创建者或所属管理者在检测到异常回收后，应发送异常退出消息。

## 4. 消息最小字段

线程信息消息必须结构化，不得只发送自然语言摘要。

最小字段：

```text
消息 ID
事件类型：创建 / 状态变化 / 退出前 / 已退出 / 故障 / 异常退出
发生时间
线程逻辑 ID
系统线程 ID
线程名称
线程用途
线程类别 / 角色
所属模块
创建者逻辑 ID
创建者名称
所属线程池 ID
所属线程池名称
旧生命周期状态
新生命周期状态
旧运行状态
新运行状态
是否堵塞
是否暂停
是否健康
是否正常退出
关联任务 ID
关联工作项 ID
原因键
显示摘要
```

字段口径：

```text
线程用途：
    用于控制面板解释该线程为什么存在，例如 自我主循环、任务管理工作线程、控制面板摘要刷新、D455观察采集。

线程名称：
    用于人类识别和日志查找，必须稳定。

线程逻辑 ID：
    进程内稳定 ID。系统线程 ID 变化或暂不可得时，逻辑 ID 仍作为主键。

关联任务 ID / 关联工作项 ID：
    只作为控制面板展示和排错索引。不得因为该字段存在就推导任务状态、需求满足或动作动态。

原因键：
    可用于枚举分类和筛选。

显示摘要：
    只用于控制面板和日志展示；不得作为路由、条件、结算或因果匹配依据。
```

## 5. 控制面板线程信息模块职责

### 5.1 消息中间件缓存

线程状态消息的中间件目录固定为：

```text
消息中间件
```

缓存规则：

```text
1. 每条线程状态消息先作为结构化消息文件写入 `消息中间件`。
2. 消息文件必须至少包含 4. 消息最小字段；不得只保存自然语言摘要。
3. 文件名必须包含消息类型、发生时间和消息 ID，保证同一时刻多线程写入时不覆盖。
4. 写入必须采用临时文件完成后原子改名的方式，避免控制面板读到半截消息。
5. 控制面板线程信息模块启动后先扫描 `消息中间件` 中未消费的线程状态消息，再消费运行期新增消息。
6. 消费顺序按发生时间、消息 ID 排序；同一线程的退出 / 故障消息优先级高于迟到的旧运行消息。
7. 已消费消息可以移动到已消费子目录或记录消费游标；不得删除尚未确认消费的消息。
8. 消息中间件只缓存项目自身线程生命周期消息，不缓存 OS / 系统线程枚举。
```

消息中间件不得：

```text
缓存任务治理材料来绕过任务管理上行协议
缓存世界树真值或需求树输入
把线程状态消息转换为动作动态
用系统线程枚举补造项目线程创建消息
```

### 5.2 线程信息表消费

控制面板线程信息模块负责维护进程内线程信息表。

收到消息后必须：

```text
1. 按线程逻辑 ID 查找或创建线程信息项。
2. 若系统线程 ID 可用，建立逻辑 ID -> 系统线程 ID 绑定。
3. 更新线程名称、用途、类别、所属模块、所属线程池、创建者信息。
4. 更新生命周期状态、运行状态、堵塞 / 暂停 / 健康 / 退出标记。
5. 更新时间戳、版本号和最近事件摘要。
6. 刷新线程状态页面或让下一次页面读取能看到最新数据。
```

处理规则：

```text
创建、退出、故障、异常退出消息不得被普通状态消息覆盖丢失。
同一线程连续重复状态变化可以合并，只保留最新状态和最后更新时间。
未知线程先到状态消息时，可以创建占位线程项，但必须标记 创建消息未到。
线程已退出后收到旧时间状态消息，不得覆盖已退出 / 故障状态，只能记录为迟到消息。
```

控制面板线程信息模块不得：

```text
写任务状态
写需求树
写世界树真值
生成动作动态
生成派生需求
回写安全值 / 服务值
向自我线程补造治理消息
```

线程状态页面显示规则：

```text
1. 页面上部显示统计信息：
   已知项目线程总数、当前运行数量、各状态数量、已结束数量和故障数量。
2. 页面中间栏显示完整线程列表：
   不分页、不缩略、不用 “等 N 项” 代替真实线程条目。
   只显示控制面板线程信息模块通过线程生命周期消息收到或登记的项目自身线程。
   不显示 OS / 系统线程枚举，不用当前进程系统线程列表补齐页面。
   当前尚未完成线程生命周期消息表接入时，只允许显示明确标记为 “待线程生命周期消息接入” 的项目线程占位或既有项目线程快照字段。
3. 页面右侧栏显示选中线程详细信息：
   线程用途、名称、逻辑 ID、系统线程 ID、创建者 / 所属模块、加载时间、运行时长、状态、最近事件、更新时间和故障 / 退出信息。
   系统线程 ID 只是项目线程消息携带的绑定字段，不代表页面可以显示系统线程列表。
4. 若某字段当前来源不足，必须显示 “未记录” 或 “待线程生命周期消息接入”，不得用控制面板快照时间伪装为线程创建时间。
```

## 6. 与自我线程的边界

自我线程不接收纯线程状态变化消息。

以下消息不得进入自我线程治理邮箱：

```text
线程创建消息
线程启动 / 运行 / 暂停 / 恢复消息
线程堵塞 / 等待消息
线程退出前 / 已退出消息
线程健康心跳消息
控制面板线程状态刷新消息
```

以下消息可以进入自我线程，但必须按任务管理上行协议或自检报告协议进入：

```text
任务管理派生需求消息
任务管理结果状态消息
任务执行前许可请求
观察事实承接请求
自检报告消息
```

任务管理工作线程的运行状态只有在绑定具体任务执行尝试并携带任务治理语义时，才可作为任务管理上行消息的一部分进入自我线程。

## 7. 与任务管理界面线程的边界

任务管理界面线程只收发任务管理工作线程相关消息。

允许：

```text
接收任务管理工作线程的任务工作结果
接收任务管理工作线程的任务缺口 / 结果 / 许可 / 观察承接材料
向自我线程上行任务治理消息
向控制面板线程信息模块上报任务管理工作线程创建、状态变化和退出
```

禁止：

```text
替其他无关线程做通用线程注册中心
把纯线程健康状态上行给自我线程
把任务工作线程堵塞状态直接写成任务状态
把任务工作线程状态变化当作方法动作动态来源
```

## 8. 验收口径

实现本规范后，至少需要用真实运行验证：

```text
1. 自我线程、任务管理界面线程、任务管理工作线程池、控制面板摘要线程创建时均能进入控制面板线程信息表。
2. 线程运行、堵塞 / 等待、暂停、恢复、停止请求、退出和故障状态变化能更新控制面板线程状态页面。
3. 纯线程状态变化不再投递到自我线程治理邮箱。
4. 任务管理工作线程的任务治理材料仍能通过任务管理上行消息进入自我线程。
5. 未新增主动动态、被动动态、方法动作动态或世界树真值写入。
6. 控制面板不可用时，业务线程不被长期阻塞，并产生可排查日志。
```

验证证据以 Debug x64 构建、真实运行日志、控制面板线程状态快照、任务管理上行日志和错误日志为准；不得新增 mock、伪入口或伪造线程事件。
