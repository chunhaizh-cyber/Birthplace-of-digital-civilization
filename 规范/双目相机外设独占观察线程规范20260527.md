## 1. 定案

可以让双目相机外设独占一个观察线程，作为：

```text
双目相机内部观察服务线程
```

该线程可以长期运行、持续观察视野、维护外设内部候选观察对象，并稳定输出可观察特征。

但该线程属于外设内部逻辑，不直接成为：

```text
自我世界树权威写入者
自我需求树权威写入者
自我存在树权威写入者
方法动作动态动作来源
安全 / 服务价值结算者
```

定案句：

```text
让双目相机像一只专职眼睛长期工作；
它不替自我理解世界；
它只负责把视野里能稳定复现的特征尽量交出来；
交不出来也要说清为什么。
```

补充定案：

```text
外设线程持续生产观察材料；
任务管理工作线程按当前正式需求创建观察等待项 / 订阅项；
外设线程根据等待项输出逐簇识别报告、扫描变化报告或跟踪报告；
任务管理工作线程消费报告并生成任务回执 / 派生需求消息；
提交入口裁决是否入需求树 / 世界树。
```

一句话：

```text
自我不直接吃相机流；
自我通过需求表达“我要逐簇识别”“我要扫描变化”或“我要跟踪目标”；
任务管理线程把它变成外设等待项 / 订阅项；
外设线程产出逐簇识别报告、扫描变化报告或跟踪报告。
```

实现口径：

```text
相机里面用工程代码干活；
相机外面用等待项、命令、三种观察运行模式和对应报告说话；
本能方法是自我理解和调度外设的契约，不是相机内部算法的实现方式。
```

### 1.1 同一外设线程支持三种外显运行模式

对自我和任务管理来说，双目相机外设线程对外只暴露三种高层观察运行模式：

```text
陌生环境逐簇识别模式
已识别场景扫描变化模式
目标跟踪观察模式
```

这三种模式不是相机内部算法分类，也不是整场景串行阶段，而是任务管理创建外设等待项 / 订阅项时可以使用的观察契约。同一帧可以按区域归属状态同时产生识别、扫描和跟踪输出。

三种模式定位：

```text
陌生环境逐簇识别模式：
    高成本，用于处理未识别区域、候选区域和冲突区域，建立当前有效观察材料的归属结果。
    归属目标包括已确认存在、新存在候选、未知区域、冲突区域、静止存在 / 环境存在和噪声 / 无效材料。
    闭合标准是有效观察材料没有无主漂浮项，不是所有像素都成为已确认存在。

已识别场景扫描变化模式：
    低成本，用于处理已识别区域中的已确认存在、已归属静止存在和环境存在，发现特征值变化、未解释变化或需重识别区域。
    不要求全场景已识别；只要求存在可扫描的已识别区域、已确认存在 / 已归属静止存在 / 环境存在、以及上一轮可比状态。

目标跟踪观察模式：
    高频局部，用于对指定已确认存在进行持续观察。
    只维护目标存在的特征值和变化，主动忽略非目标存在。
```

对应报告为：

```text
逐簇识别报告
扫描变化报告
跟踪报告
```

其中“识别”表示处理未识别区域、候选区域和冲突区域，建立观察材料到已确认存在、新存在候选、未知区域、冲突区域、静止存在 / 环境存在或噪声 / 无效材料的归属关系；它不表示语义识别、稳定世界存在确认、跨帧身份闭合或目标可见性闭合。旧像素级方案里的“100%”只表示帧内可寻址、可回查、无遗漏、无重复；新的识别闭合标准是有效观察材料没有无主漂浮项。自我认知中不得把“背景”作为归属目标；视觉工程背景必须转写为静止存在、环境存在或低动态存在。

质量诊断、ROI 观察、补观察、稳定特征取值、重捕获、局部细分、变化监测和配置学习，先不作为额外自我可见外设模式。它们分别归入：

```text
外设线程内部策略
逐簇识别 / 扫描变化 / 跟踪报告中的字段
自我后续方法对报告的使用方式
```

禁止把系统设计成：

```text
双目相机全局模式 = 补观察
或
双目相机全局模式 = 质量诊断
或
双目相机全局模式 = 重捕获
或
双目相机全局模式 = 局部细分
```

允许且推荐：

```text
双目相机线程有已识别场景低频扫描变化循环；
同帧未识别区域可提交逐簇识别等待项；
任务管理线程可以提交一个或多个观察订阅项；
订阅项只区分三种外显观察运行模式；
ROI、补观察、重捕获、配置调整等作为订阅参数、报告字段或外设内部策略处理；
外设线程按优先级、时效和质量缺口调度输出逐簇识别报告、扫描变化报告或跟踪报告。
```

`双目相机.主观察运行模式` 可以作为对外摘要，取值只限三种外显模式。实现上不得把它写死成相机唯一全局状态，也不得用它表示整场景阶段；内部仍应采用外设观察订阅 / 等待项，允许未识别区域识别、低频扫描变化与高频目标跟踪同时存在。

`双目相机.工作模式` 仍可表达物理采集配置，例如高深度质量、低延迟、指定 ROI、曝光或分辨率；但它不得被用作补观察、质量诊断、局部细分等内部策略的唯一全局状态。

### 1.2 其它能力的归属

其它能力不消失，只是不作为自我可见的外设模式暴露：

```text
质量诊断：三种报告里的质量字段、失败原因和降级可用说明。
ROI 观察：等待项的目标区域 / ROI 参数，通常服务逐簇识别或目标跟踪。
补观察：任务筹办根据质量缺口派生新的逐簇识别、扫描变化或目标跟踪等待项。
稳定特征取值：跟踪报告的核心输出字段。
重捕获：跟踪报告里的丢失处理、重捕获候选集合和失败原因。
局部细分：逐簇识别或跟踪模式内部策略，也可由自我方法使用局部图、掩码和点集继续处理。
变化监测：扫描变化模式的核心输出，也可由自我比较多次报告后生成变化候选。
配置学习：外设内部学习模块，只向报告暴露配置摘要、推荐配置和适用性。
```

对外等待项只应写成：

```text
外设观察订阅.观察运行模式 等于 陌生环境逐簇识别
外设观察订阅.观察运行模式 等于 已识别场景扫描变化
外设观察订阅.观察运行模式 等于 目标跟踪观察
```

不得写成：

```text
双目相机.全局模式 等于 某类型
```

## 2. 职责边界

### 2.1 外设独占线程负责

```text
1. 持续取得观察特征帧。
2. 维护三种观察运行模式对应的订阅项、跟踪目标列表和内部质量缺口状态。
3. 维护当前视野中的候选观察对象。
4. 对候选观察对象持续输出能稳定复现的特征。
5. 对每个特征给出有效性、稳定性、置信或失败原因。
6. 根据历史观察学习外设配置与稳定特征之间的关系。
7. 在任务管理提交逐簇识别、扫描变化或目标跟踪等待项时，优先使用已学到的稳定配置。
8. 对外只输出逐簇识别报告、扫描变化报告或跟踪报告；质量诊断、补观察、ROI、重捕获、局部细分、变化监测和配置学习只作为内部策略、报告字段或自我后续处理输入。
9. 把可被任务管理承接的观察材料 / 特征报告提交到外设观察结果队列。
```

### 2.2 外设独占线程不负责

```text
1. 直接写自我需求树。
2. 直接写世界树真值。
3. 直接宣称稳定外部对象。
4. 直接确认自我所在场景中的已确认观察存在。
5. 直接完成安全 / 服务价值结算。
6. 绕过本能方法生成方法动作动态。
7. 把外设内部候选观察对象直接等同于世界存在。
8. 把内部采集、校正、滤波、分割、跟踪、调参、缓存或学习步骤登记成自我层本能方法。
```

线程可以作为调用者、调度者或外设内部服务，但不能作为方法动作动态的动作来源。凡是需要落成自我侧动作动态或实例特征值的变化，必须由明确方法承接。

## 4. 输出核心

外设线程输出的核心不是：

```text
全都识别
```

而是：

```text
稳定给出。
```

原则：

```text
有什么稳定特征，就给什么稳定特征；
不稳定的特征，要明确标记不稳定；
无法取得的特征，要给出失败原因；
取得但只能降级使用的特征，要标记为降级可用。
```

外设线程可以说：

```text
我在视野中持续观测到若干候选观察对象；
这些候选的颜色、深度、轮廓、空间坐标、距离等特征在当前配置下稳定 / 降级可用 / 不稳定 / 不可得。
```

外设线程不能说：

```text
这是世界树中的杯子A；
这是稳定外部对象；
这个对象已被自我确认；
这个对象已经满足安全 / 服务结算。
```

同一个报告结构可以按三种外显运行模式裁剪输出。逐簇识别报告面向“未知视野如何组织成观察像素簇和存在候选输入”；扫描变化报告面向“已识别场景相比基准是否有新增、消失、移动、尺寸变化或高风险未知区域”；跟踪报告面向“这个已有目标簇 / 存在候选是否还能稳定复现特征”。补观察、质量诊断、局部细分、变化监测和配置学习不得成为额外可见外设模式；它们只能通过三种报告字段、外设内部策略或自我后续方法承接。

### 5.1 陌生环境逐簇识别报告

陌生环境逐簇识别的目标是：

```text
当前视野内哪些可分辨像素区域可以组织成观察像素簇？
每个簇能给出哪些可稳定复现的颜色 / 深度 / 空间 / 轮廓特征？
哪些区域未解释、低置信或不可观测？
是否已经为自我生成存在候选提供足够输入？
```

逐簇识别是高成本模式，适合自我刚进入陌生环境、当前场景没有可靠解释时运行。它不要求确认所有真实物体，只要求把当前外设帧材料内可分辨像素区域组织成观察像素簇，并给出可回查、可复现的观察特征。

逐簇识别报告应至少包含：

```text
当前观察帧
观察像素簇集合
每个簇的像素集合掩码
每个簇的彩色轮廓局部图
每个簇的深度轮廓局部图
每个簇的颜色 / 深度 / 空间 / 稳定性特征
簇ID掩码
未解释像素掩码
低置信像素掩码
不可观测区域掩码
可观测单位对应摘要
```

对应需求可以写成：

```text
双目相机.主观察运行模式 等于 陌生环境逐簇识别
当前观察帧.观察像素簇集合状态 等于 已生成
当前观察帧.存在候选集合状态 等于 已生成
当前观察帧.已解释像素比例 大于 最低解释比例
当前观察帧.未解释高价值区域数量 等于 0
当前观察材料集.可观测单位对应摘要状态 等于 已生成
```

其中 `当前观察帧.存在候选集合状态` 仍是接口层材料组织状态；`当前观察材料集.可观测单位对应摘要状态` 只能由任务管理承接报告后触发自我侧解释链生成。相机线程直接输出的是观察像素簇、掩码、局部图、稳定特征和质量 / 不可观测原因。

逐簇识别停止条件：

```text
当前观察帧.已解释像素比例 大于 最低解释比例
当前观察帧.未解释像素比例 小于 最大允许未解释比例
当前观察帧.冲突像素比例 小于 最大允许冲突比例
当前观察帧.高价值未解释区域数量 等于 0
```

如果已经没有可执行观察改善路径，且不可观测区域原因明确率达标，也可以停止，不能无限重试。

### 5.2 已识别场景扫描变化报告

扫描变化的目标是：

```text
当前视野和上一版场景解释 / 最近扫描缓存相比，有没有明显变化？
有没有新增、消失、移动、尺寸变化或质量异常区域？
有没有高风险未知簇需要任务管理继续承接？
```

扫描变化是低成本、低频、保最新报告的守望模式，不重新逐个识别所有簇，不默认做局部细分，也不默认承接所有原始帧。

扫描变化报告应至少包含：

```text
扫描变化报告ID
当前观察簇摘要
新增簇候选集合
消失簇候选集合
变化区域集合
高风险未知簇集合
低质量区域集合
与基准场景的差异摘要
```

对应需求可以写成：

```text
双目相机.主观察运行模式 等于 已识别场景扫描变化
当前观察帧.变化候选集合状态 等于 已生成
当前观察帧.扫描变化报告年龄 小于 最大允许扫描变化报告年龄
当前观察帧.新增观察簇候选数量 等于 0
当前观察帧.高风险未知簇数量 等于 0
```

如果变化候选数量大于 0，任务管理可以创建局部逐簇识别等待项或目标跟踪观察等待项。

### 5.3 目标跟踪观察报告

跟踪观察的目标是：

```text
我已经有一个目标簇 / 存在候选，
现在要持续获得它的稳定特征值。
```

跟踪要求跨帧连续性，但仍不能直接宣称稳定世界对象。它适合持续观察某个存在候选、稳定获取目标距离、稳定获取目标空间坐标、观察目标是否丢失、观察目标特征是否变化，并为后续内部世界细分积累稳定材料。

跟踪报告应至少包含：

```text
外设内部跟踪ID
来源观察帧
来源观察像素簇
目标ROI
目标掩码
彩色轮廓局部图
深度轮廓局部图
稳定特征集合
连续成功次数
复现离散度
丢失原因
重捕获候选集合
```

对应需求可以写成：

```text
双目相机.主观察运行模式 等于 目标跟踪观察
目标观察候选.跟踪状态 等于 稳定
目标观察候选.最近观测年龄 小于 最大允许观测年龄
目标观察候选.特征复现离散度 小于 最大允许离散度
目标观察候选.丢失状态 等于 未丢失
目标观察候选.稳定特征集合状态 等于 已生成
```

注意：

```text
外设内部跟踪ID != 自我世界存在ID
```

外设线程可以维护内部跟踪和重捕获线索，但不能把内部跟踪身份直接写成稳定世界存在。

### 5.4 其它策略的归属

以下能力可以存在，但不作为三种外显运行模式之外的模式暴露给自我：

```text
定向观察 / ROI 观察：
    作为逐簇识别或目标跟踪等待项的目标区域 / ROI 参数。

补观察 / 质量提升观察：
    由任务筹办根据质量缺口派生新的逐簇识别、扫描变化或目标跟踪等待项；旧帧质量不足仍是事实。

稳定特征取值：
    作为跟踪报告中的稳定特征集合、复现离散度、连续成功次数和失败原因。

重捕获：
    作为跟踪报告中的丢失状态、重捕获候选集合和丢失原因。

局部细分：
    作为逐簇识别或跟踪模式的内部策略，也可由自我方法使用报告里的彩色轮廓局部图、深度轮廓局部图和掩码继续处理。

变化监测：
    作为已识别场景扫描变化模式的核心输出，也可由自我比较多次报告生成变化候选。

质量诊断：
    作为三种报告里的低质量区域、不可观测区域、质量诊断摘要和失败原因。

配置学习：
    作为外设内部学习模块；对外只出现在外设配置摘要、推荐配置摘要和适用性字段里。
```

该报告应优先引用 `050004` 中定义的观察像素簇结构。若当前实现尚未完整支持观察像素簇，可在过渡期使用旧的空间候选 / 空间候选观察事实字段，但语义上必须按以下关系解释：

```text
外设候选观察对象
    -> 观察像素簇 / 观察特征报告
        -> 自我承接
            -> 存在候选
                -> 已确认观察存在
```

彩色轮廓截图和深度轮廓截图属于候选观察对象或观察像素簇的局部图像证据。它们用于控制面板显示、人工复核、递归细分、跨帧比较和外设配置学习，不是外设线程确认世界存在的依据。外设线程不得因为截图可用而直接宣称候选观察对象已经是自我世界树中的已确认观察存在。

掩码类特征不同于截图证据。掩码不是给人看的附件，而是后续候选生成、子轮廓提取、像素归属判断、三维建模和观察材料集可观测单位对应统计会直接使用的正式特征。外设线程可以提交掩码句柄和掩码状态，但可观测单位对应摘要、可观测单位存在对应闭合状态以及是否入树，仍由自我侧方法承接和裁决。

## 6. 特征稳定等级

外设线程输出的每类特征应分级：

```text
稳定特征:
    可直接作为自我后续判断材料。

降级可用特征:
    可以使用，但必须带低置信或用途限制。

不稳定特征:
    只能作为线索，不能作为确定结论。

不可得特征:
    不得伪造默认值，必须记录失败原因。
```

示例：

```text
候选观察对象#17:
    颜色特征状态 等于 稳定
    轮廓特征状态 等于 降级可用
    深度特征状态 等于 不稳定
    空间坐标特征状态 等于 不可得
    空间坐标不可得原因 等于 深度有效率不足
```

不得用一个整帧级的：

```text
质量不可用
```

粗暴覆盖所有局部候选观察对象和所有特征类型。整帧质量诊断只能作为上层摘要；候选对象和特征级稳定性必须保留用途相关的细分结果。

## 7. 外设内部循环

外设独占观察线程可以采用长期运行循环：

```text
while 外设线程运行:
    1. 检查相机运行状态。
    2. 读取任务管理提交的外设等待项 / 订阅项。
    3. 如果存在高优先级跟踪等待项:
           使用目标种子、ROI、掩码、推荐配置和内部重捕获策略采集材料。
           输出跟踪报告。
    4. 如果场景解释状态未建立或存在逐簇识别等待项:
           全局扫描当前视野，按优先级逐簇处理。
           输出逐簇识别报告。
    5. 如果场景解释已建立且扫描变化报告过期或存在扫描变化等待项:
           低频采集全局帧或指定 ROI，并与基准场景 / 最近缓存比较。
           输出扫描变化报告。
    6. 如果质量不足:
           在三种报告中写入质量诊断摘要、失败原因、降级可用状态和推荐配置摘要。
    7. 如果某跟踪目标丢失:
           在跟踪报告中写入丢失状态、丢失原因和重捕获候选集合。
    8. 更新最新观察报告缓存、稳定特征缓存和推荐配置缓存。
```

推荐调度规则：

```text
1. 如果有高优先级安全跟踪需求，跟踪优先。
2. 如果场景解释未建立，先进入陌生环境逐簇识别。
3. 如果只有低频安全守望，已识别场景扫描变化即可。
4. 如果服务任务锁定目标，目标跟踪优先，低频扫描变化可后台保留。
5. 如果观察材料质量不足，三种报告写明质量缺口；任务管理可派生新的逐簇识别、扫描变化或目标跟踪等待项。
6. 如果跟踪丢失，跟踪报告写明丢失状态和重捕获候选；任务管理可继续创建跟踪等待项或退回扫描变化 / 局部逐簇识别。
7. 如果扫描变化发现高风险未知簇，任务管理可派生目标跟踪或局部逐簇识别等待项。
8. 如果需要内部结构或三维建模，自我基于报告中的局部图和掩码启动后续方法。
```

对应三比较需求可以是：

```text
目标观察候选.丢失状态 等于 未丢失
当前观察帧.高风险未知簇数量 等于 0
当前观察帧.扫描变化报告年龄 小于 最大扫描变化报告年龄
目标观察候选.跟踪报告年龄 小于 最大跟踪报告年龄
```

外设内部可以有自己的小闭环：

```text
内部目标:
    某目标特征稳定复现状态 等于 稳定

内部任务:
    尝试配置 / 采样 / 比较 / 复现

内部方法:
    调分辨率
    调 ROI
    调工作模式
    调曝光
    多帧融合
    重新采样

内部学习:
    什么条件 + 什么配置 -> 什么特征稳定
```

这套内部闭环只属于双目相机外设内部服务，不进入自我需求树，不作为自我任务筹办的正式任务，不产生自我侧方法动作动态。

## 8. 对自我暴露的能力契约面

外设线程内部可以复杂，并且可以完全用普通工程代码实现。对自我暴露的不是内部算法步骤，而是控制、检查、使用三类外设契约；这些契约可以由本能方法、外设命令或任务管理等待项承载。

关键边界：

```text
相机线程内部不调用本能方法来完成采集 / 分割 / 跟踪；
任务管理或自我侧可以用本能方法 / 外设命令表达“需要相机可用、需要检查状态、需要逐簇识别报告 / 扫描变化报告 / 跟踪报告”；
动作动态只记录边界请求、回执、承接和裁决，不记录每个内部算法步骤。
```

### 8.1 控制类

示例目标：

```text
双目相机.可用状态 等于 可用
双目相机.工作模式 等于 指定模式
双目相机.占用状态 等于 已释放
```

控制类方法可以改变外设自身状态，但必须有明确输入、前置条件、输出和动作动态落账规则。

### 8.2 检查类

示例目标：

```text
双目相机.运行状态 等于 正常
双目相机.运行状态 等于 降级可用
双目相机.运行状态 等于 异常
双目相机.对当前观察需求的能力匹配状态 等于 满足
双目相机.对当前观察需求的能力匹配状态 等于 不满足
双目相机.工作质量状态 等于 可用
双目相机.工作质量状态 等于 降级可用
双目相机.工作质量状态 等于 不可用
```

检查类方法原则上不启动、重启、修复、切换模式或长期占用外设；如果检查必须改变主要工作状态，应返回控制类缺口。

### 8.3 使用类

示例目标：

```text
自我所在场景.当前观察特征帧取得状态 等于 已取得
外设观察报告.生成状态 等于 已生成
目标区域.目标特征稳定复现状态 等于 稳定
当前观察帧.观察像素簇集合状态 等于 已生成
```

使用类方法的目标宿主通常不是外设本体，而是自我、对象、场景、目标区域、当前观察帧或外设观察报告。

对双目相机第一版，使用类边界可以进一步收敛为：

```text
创建扫描等待项 / 订阅项
创建跟踪等待项 / 订阅项
取得或承接逐簇识别报告 / 扫描变化报告
取得或承接跟踪报告
```

这些边界动作不进入相机线程内部；相机线程只读取等待项或命令状态，并用内部代码生产相应报告。

### 8.4 不暴露的内部动作

不得把下列外设内部步骤暴露为自我层本能方法：

```text
内部采集
内部校正
内部匹配
内部滤波
内部分割
内部轮廓提取
内部掩码生成
内部局部图裁剪
内部扫描调度
内部跟踪调度
内部重捕获搜索
内部调参尝试
内部多帧缓存
内部候选跟踪细节
内部学习样本整理
内部配置评分
```

自我只读取：

```text
稳定特征报告
配置摘要
失败原因
能力匹配结果
外设观察报告
```

## 9. 数据交互

正式交互模型定为：

```text
外设主动生产；
需求驱动消费；
任务管理承接；
提交入口裁决入账。
```

最终交互口径定为：

```text
外设线程持续生产观察材料；
任务管理工作线程按当前正式需求创建观察等待项 / 订阅项；
外设线程根据等待项输出逐簇识别报告、扫描变化报告或跟踪报告；
任务管理工作线程消费报告并生成任务回执 / 派生需求消息；
提交入口裁决是否入需求树 / 世界树。
```

完整链路：

```text
双目相机外设线程
    -> 外设观察消息队列 / 最新观察缓存 / 稳定特征缓存
        -> 任务管理外设消息承接线程
            -> 匹配等待任务 / 活跃需求
            -> 生成任务回执 / 派生需求消息 / 动作动态输入
                -> 自我线程
                    -> 校验
                    -> 裁决
                    -> 通过统一更新指令入树 / 入世界
```

这里同时存在两个方向：

```text
外设线程是 push：
    持续观察，持续把观察报告、观察像素簇、质量缺口、稳定特征放入队列或缓存。

需求系统是 pull：
    安全 / 服务根需求派生出正式观察需求后，由任务管理外设消息承接线程去队列或缓存中匹配能满足需求的观察材料。
```

一句话：

```text
外设一直看，但只有被正式需求领走的信息，才有资格进入自我的正式认知链。
```

### 9.0 外设等待项 / 订阅项

任务管理工作线程维护外设等待项或订阅项：

```text
外设等待项 {
    来源需求
    目标外设
    观察运行模式 = 陌生环境逐簇识别 / 已识别场景扫描变化 / 目标跟踪观察
    目标区域 / 目标簇 / 目标候选，可空
    ROI / 掩码 / 跟踪种子，可空
    期望报告类型 = 逐簇识别报告 / 扫描变化报告 / 跟踪报告
    期望特征类型集合
    最小稳定性要求
    最大允许报告年龄
    是否允许缓存报告
    质量要求 / 内部策略提示，可空
}
```

逐簇识别等待项的目标区域可以为空，期望输出通常是观察像素簇集合、簇ID掩码、未解释像素掩码、低置信像素掩码、不可观测区域掩码和可观测单位对应摘要。扫描变化等待项基于已建立场景解释或最近缓存，期望输出新增、消失、变化、高风险未知和低质量区域集合。目标跟踪等待项通常携带观察像素簇ID、存在候选ID、ROI、掩码或目标特征摘要等种子，期望输出是跟踪状态、丢失状态、稳定特征集合和重捕获候选集合。

ROI、补观察、稳定特征取值、重捕获、质量诊断和配置学习不得作为新的观察运行模式写入等待项；如果确需表达，只能放在目标区域、期望特征类型集合、质量要求或内部策略提示里。

### 9.1 安全 / 服务根需求不得直接消费队列

不得采用：

```text
外设线程 -> 队列 -> 自我根需求直接消费
```

原因：

```text
1. 外设消息频率高，自我线程会被相机流淹没。
2. 安全 / 服务根需求是价值根，不直接处理外设原始消息。
3. 队列中大量信息与当前需求无关。
4. 原始观察报告不等于世界树真值。
5. 需要任务管理线程先匹配任务上下文、等待项、活跃需求和时效。
```

自我根需求真正接收的应是经过任务管理承接、匹配、转译后的：

```text
任务回执
派生需求消息
动作动态输入
观察事实承接请求
```

### 9.2 队列和缓存分层

不得把所有原始帧直接塞入自我可见的全局队列。队列和缓存分三层。

第一层：外设内部原始帧缓存。

```text
原始 RGB 帧
原始深度帧
内部滤波结果
内部临时分割结果
内部多帧缓存
```

该层由双目相机外设线程内部管理，自我和任务管理不直接消费。

第二层：外设观察报告队列。

```text
外设观察报告 {
    外设ID
    报告ID
    时间戳
    帧宽
    帧高
    彩色帧号
    深度帧号
    配置摘要

    观察像素簇集合
    簇ID掩码
    低质量区域集合
    未归簇区域集合
    错误摘要
}
```

该队列是任务管理外设消息承接线程消费的主队列。

第三层：最新稳定特征缓存。

```text
按 外设ID + 特征类型 + 目标区域 / 簇ID 建索引：
    最近稳定颜色特征
    最近稳定深度特征
    最近稳定空间坐标特征
    最近稳定轮廓特征
    最近推荐观察配置
```

如果正式需求需要：

```text
目标区域.深度有效率 大于 阈值
```

任务管理外设消息承接线程可以先查稳定特征缓存；满足时生成任务回执或承接请求，不必等待下一帧。

### 9.3 消费者

外设观察报告队列的正式消费者是：

```text
任务管理外设消息承接线程
```

不是：

```text
自我线程；
安全 / 服务根需求；
普通任务执行线程直接读取外设流。
```

任务管理外设消息承接线程负责：

```text
1. 从外设观察消息队列读取报告。
2. 校验报告完整性。
3. 去重和时效检查。
4. 更新最新观察缓存和稳定特征缓存。
5. 匹配等待中的任务。
6. 匹配活跃需求。
7. 判断是否需要上报自我线程。
8. 生成任务回执 / 派生需求消息 / 动作动态输入。
```

它是外设消息分拣层，不是世界树写入者。

### 9.4 根需求如何驱动消费

安全 / 服务根需求不直接读队列，而是通过需求树派生正式观察需求。

示例：

```text
自我.安全值 大于 安全值基线
```

经因果展开生成：

```text
当前观察材料集.可观测单位存在对应闭合状态 等于 闭合
当前观察帧.观察像素簇集合状态 等于 已生成
```

任务管理据此建立外设等待项或订阅项：

```text
外设等待项 {
    来源需求 = 当前观察帧.观察像素簇集合状态 等于 已生成
    目标外设 = 双目相机
    观察运行模式 = 陌生环境逐簇识别
    期望消息类型 = 外设观察报告
    期望内容 = 观察像素簇集合 / 簇ID掩码 / 可观测单位对应摘要
    最低稳定性要求
    最大允许报告年龄
    是否允许缓存 = 是
}
```

承接线程消费队列或缓存：

```text
如果队列或缓存中有匹配报告：
    生成任务回执 / 观察事实承接请求。

如果没有匹配报告：
    等待外设线程下一次报告。

如果报告质量不足：
    生成派生需求消息，例如推荐配置 / 重新观察 / 调整工作模式 / 观察质量改善路径学习需求。
```

### 9.5 三种消费方式

等待任务消费：

```text
有明确任务正在等待 双目相机_取得当前观察报告。
承接线程收到匹配报告后生成任务回执。
```

活跃需求消费：

```text
没有显式任务等待，但有活跃需求需要 目标区域.稳定特征状态 等于 稳定。
承接线程收到可满足材料后生成满足线索、派生回执或观察事实承接请求，上报提交入口裁决。
```

缓存不消费：

```text
没有等待任务，也没有活跃需求，只是普通观察流。
承接线程只更新最新观察报告缓存 / 稳定特征缓存，不打扰自我线程，不入树。
```

### 9.6 上报自我线程的条件

不是每条外设消息都上报。只有以下情况才上报自我线程：

```text
1. 命中等待任务。
2. 满足某个活跃需求。
3. 产生安全相关高优先级缺口。
4. 外设状态发生关键变化。
5. 稳定特征首次达标。
6. 活跃父需求的关键质量条件不满足。
7. 外设错误影响当前任务。
8. 需要正式派生需求入树。
```

其它消息只留在：

```text
外设观察缓存
稳定特征缓存
外设内部历史样本
```

### 9.7 队列消息不是事实权威

队列中的消息只是：

```text
外设观察材料
```

它还不是：

```text
自我所在场景的正式观察事实
世界树真值
已确认观察存在
安全 / 服务结算证据
```

只有经过：

```text
任务管理承接
    -> 提交入口裁决
        -> 自我承接方法 / 统一更新指令
```

之后，才可能形成：

```text
当前观察帧存在
观察像素簇集合
存在候选集合
动作动态
世界树因果样本
```

控制面板不得把相机原始画面、外设内部候选或未被需求领走的队列消息直接当作自我识别结果。控制面板复现场景信息应以自我所在场景中的观察帧、像素观察事实、观察像素簇、存在候选或已确认观察存在等已承接特征为数据源，不得反写世界树真值。

## 10. 外设内部学习模块

第一版最多引入一个外设内部学习模块：

```text
双目相机_稳定特征获取学习模块
```

该模块学习：

```text
观察条件 + 外设配置 + 目标特征类型
    -> 特征稳定性结果
```

建议记录：

```text
目标特征类型
观察距离范围
画面中心距离
ROI
分辨率
工作模式
光照摘要
纹理摘要
目标运动状态
相机运动状态
稳定成功次数
稳定失败次数
平均离散度
推荐配置
```

它对自我暴露的只能是学习摘要或检查 / 使用结果，例如：

```text
双目相机.推荐观察配置状态 等于 已生成
双目相机.目标特征稳定获取能力状态 等于 已知
双目相机.当前配置对目标特征适用状态 等于 适用
双目相机.当前配置对目标特征适用状态 等于 不适用
```

该学习模块不得直接改写自我需求树，不得直接把外设内部学习结论写成世界树真值。

## 11. 自我、任务管理、外设线程职责

### 11.1 外设线程

```text
持续观察
内部调参
内部学习
按观察等待项 / 订阅项调度扫描或跟踪
候选观察对象维护
外设内部跟踪目标维护
特征稳定性评估
报告观察像素簇、稳定特征、质量缺口、丢失状态、重捕获候选和配置摘要
报告失败原因
```

### 11.2 自我线程

```text
决定是否承接
决定是否入树
把观察报告转成观察事实
判断是否满足安全 / 服务需求
生成新的需求
更新世界树因果
```

自我线程可以裁决和调度，但不能绕过方法直接把外设报告写成世界树权威事实。

### 11.3 任务管理

```text
根据正式需求筹办任务
创建外设命令或观察等待项 / 订阅项
创建逐簇识别、扫描变化或目标跟踪外设等待项 / 订阅项
等待并匹配外设报告
处理缺口回执
生成任务回执 / 派生需求消息 / 观察事实承接请求
在子需求完成后触发父任务重筹办
```

任务筹办和任务执行仍是任务管理生命周期普通函数，不作为本能方法注册、选择或动作动态来源。任务管理可以调用自我侧边界本能方法或发送外设命令，但不得要求相机线程内部用本能方法实现观察算法。

## 12. 需求表达

对自我可见的需求表达仍使用三比较。

示例：

```text
目标区域.特征稳定复现状态 等于 稳定
目标区域.深度有效率 大于 最低深度有效率
目标区域.空间坐标有效率 大于 最低空间坐标有效率
目标存在.距离复现离散度 小于 最大允许离散度
目标存在.颜色特征稳定状态 等于 稳定
外设观察报告.生成状态 等于 已生成
当前观察帧.观察像素簇集合状态 等于 已生成
```

陌生环境逐簇识别需求示例：

```text
双目相机.主观察运行模式 等于 陌生环境逐簇识别
当前观察帧.观察像素簇集合状态 等于 已生成
当前观察帧.簇ID掩码状态 等于 已生成
当前观察帧.存在候选集合状态 等于 已生成
当前观察帧.已解释像素比例 大于 最低解释比例
当前观察帧.未解释高价值区域数量 等于 0
当前观察材料集.可观测单位对应摘要状态 等于 已生成
```

已识别场景扫描变化需求示例：

```text
双目相机.主观察运行模式 等于 已识别场景扫描变化
当前观察帧.变化候选集合状态 等于 已生成
当前观察帧.扫描变化报告年龄 小于 最大允许扫描变化报告年龄
当前观察帧.新增观察簇候选数量 等于 0
当前观察帧.高风险未知簇数量 等于 0
```

跟踪观察需求示例：

```text
双目相机.主观察运行模式 等于 目标跟踪观察
目标观察候选.跟踪状态 等于 稳定
目标观察候选.最近观测年龄 小于 最大允许观测年龄
目标观察候选.特征复现离散度 小于 最大允许离散度
目标观察候选.丢失状态 等于 未丢失
目标观察候选.稳定特征集合状态 等于 已生成
```

三种相机报告可以支持但不能直接满足的自我认知需求示例：

```text
当前观察帧.存在候选集合状态 等于 已生成
当前观察材料集.可观测单位对应摘要状态 等于 已生成
观察像素簇.子观察像素簇集合状态 等于 已生成
当前观察帧.变化候选集合状态 等于 已生成
存在候选.确认状态 等于 已确认
```

观察订阅自身应优先用三比较表达：

```text
外设观察订阅.观察运行模式 等于 陌生环境逐簇识别
外设观察订阅.观察运行模式 等于 已识别场景扫描变化
外设观察订阅.观察运行模式 等于 目标跟踪观察
```

不得写成：

```text
外设线程 方向=识别世界对象
相机 方向=发现存在
外设内部任务 方向=进入自我需求树
双目相机全局模式 等于 补观察
双目相机全局模式 等于 质量诊断
双目相机全局模式 等于 局部细分
```

## 13. 最小实施建议

第一版建议：

```text
1. 为双目相机建立一个独占观察线程。
2. 线程持续采集帧，但只保留最近 N 帧、最新观察报告缓存和稳定摘要。
3. 建立外设等待项 / 订阅项结构，观察运行模式只支持陌生环境逐簇识别、已识别场景扫描变化和目标跟踪观察。
4. 已识别场景扫描变化低频保留；高优先级目标跟踪订阅可抢占采样预算。
5. 建立外设内部候选观察对象列表、跟踪目标列表、质量缺口列表和配置推荐缓存。
6. 每个候选对象只输出稳定特征集合，有什么给什么。
7. 每个特征必须带：
       有效性
       稳定性
       离散度
       连续成功次数
       失败原因
8. 逐簇识别报告输出观察像素簇集合、帧级掩码、低质量区域、未解释区域、不可观测区域、局部图和可观测单位对应摘要。
9. 扫描变化报告输出变化候选、新增 / 消失 / 变化簇、低质量区域、高风险未知簇和差异摘要。
10. 跟踪报告输出跟踪状态、丢失状态、稳定特征集合、复现离散度、连续成功次数、重捕获候选和失败原因。
11. 质量诊断、补观察、ROI、稳定取值、重捕获、局部细分、变化监测和配置学习只进入内部策略、报告字段或自我后续方法。
12. 任务管理工作线程消费报告并生成任务回执 / 派生需求消息。
13. 自我只承接被任务管理领走并请求裁决的报告，不直接吃相机流。
```

缺真实 D455 连续样本时，只能记录等待真实样本或外设链路超时，不得用模拟样本、夹具入口或伪造动作动态证明稳定输出。

## 14. 禁止项

禁止：

```text
1. 外设线程直接写自我需求树。
2. 外设线程直接写世界树真值。
3. 外设线程直接宣称稳定外部对象。
4. 外设线程直接完成安全 / 服务价值结算。
5. 把外设内部候选观察对象当作已确认观察存在。
6. 把外设内部滤波、分割、调参、多帧缓存登记成自我层本能方法。
7. 把线程本身作为方法动作动态动作来源。
8. 把不稳定或不可得特征伪造成稳定特征。
9. 把控制面板显示层或外设原始画面反写成自我世界树真值。
10. 把像素 100% 回查解释成跨帧身份、语义识别或目标可见性闭合。
11. 为逐簇识别、扫描变化、跟踪、补观察、稳定取值、局部细分等各造一套并行外设系统。
12. 把观察意图写成双目相机唯一全局模式并硬切。
13. 让自我线程直接消费相机流或未匹配正式需求的外设报告。
14. 把补观察、稳定取值、局部细分、质量诊断或配置学习写成自我可见的外设模式。
```

一句话：

```text
双目相机外设独占线程是自我身体延伸中的长期观察服务；
它按任务管理提交的三种观察运行模式等待项稳定交付逐簇识别报告、扫描变化报告或跟踪报告；
补观察、稳定取值、局部细分、变化监测、质量诊断和配置学习只作为内部策略、报告字段或自我后续方法；
任务管理负责领取、转译和回执；
自我负责承接、验证、归并和结算。
```
