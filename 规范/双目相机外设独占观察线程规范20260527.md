## 1. 定案

可以让双目相机外设独占一个观察线程，作为：

```text
双目相机内部观察服务线程
```

该线程可以长期运行、持续观察视野、维护外设内部候选观察对象，并稳定输出可观察特征。

但该线程属于外设内部逻辑，不直接成为：

```text
自我世界树权威写入者
自我需求树权威写入者
自我存在树权威写入者
方法动作动态动作来源
安全 / 服务价值结算者
```

定案句：

```text
让双目相机像一只专职眼睛长期工作；
它不替自我理解世界；
它只负责把视野里能稳定复现的特征尽量交出来；
交不出来也要说清为什么。
```

## 2. 职责边界

### 2.1 外设独占线程负责

```text
1. 持续取得观察特征帧。
2. 维护当前视野中的候选观察对象。
3. 对候选观察对象持续输出能稳定复现的特征。
4. 对每个特征给出有效性、稳定性、置信或失败原因。
5. 根据历史观察学习外设配置与稳定特征之间的关系。
6. 在自我请求某类特征时，优先使用已学到的稳定配置。
7. 把可被自我承接的观察事实 / 特征报告提交到外设观察结果队列。
```

### 2.2 外设独占线程不负责

```text
1. 直接写自我需求树。
2. 直接写世界树真值。
3. 直接宣称稳定外部对象。
4. 直接确认自我所在场景中的已确认观察存在。
5. 直接完成安全 / 服务价值结算。
6. 绕过本能方法生成方法动作动态。
7. 把外设内部候选观察对象直接等同于世界存在。
```

线程可以作为调用者、调度者或外设内部服务，但不能作为方法动作动态的动作来源。凡是需要落成自我侧动作动态或实例特征值的变化，必须由明确方法承接。

## 3. 术语分层

### 3.1 外设内部术语

外设内部可以使用：

```text
候选观察对象
外设观察ID
外设候选跟踪ID
外设内部特征轨迹
外设内部稳定性窗口
外设配置学习记录
```

例如：

```text
候选观察对象#17:
    最近 10 帧都在；
    轮廓稳定；
    中心深度稳定；
    距离稳定；
    颜色稳定。
```

这些只是外设内部观察状态，不是自我世界树中的已确认存在。

### 3.2 自我侧术语

自我侧只承接：

```text
观察特征帧
外设观察特征报告
观察像素簇
候选观察对象特征报告
特征稳定性报告
外设质量诊断报告
配置学习摘要
错误 / 不可观测原因报告
```

自我根据这些报告生成或更新：

```text
观察帧存在
像素观察事实
观察像素簇
存在候选
已确认观察存在
世界树因果证据
后续需求
```

## 4. 输出核心

外设线程输出的核心不是：

```text
全都识别
```

而是：

```text
稳定给出。
```

原则：

```text
有什么稳定特征，就给什么稳定特征；
不稳定的特征，要明确标记不稳定；
无法取得的特征，要给出失败原因；
取得但只能降级使用的特征，要标记为降级可用。
```

外设线程可以说：

```text
我在视野中持续观测到若干候选观察对象；
这些候选的颜色、深度、轮廓、空间坐标、距离等特征在当前配置下稳定 / 降级可用 / 不稳定 / 不可得。
```

外设线程不能说：

```text
这是世界树中的杯子A；
这是稳定外部对象；
这个对象已被自我确认；
这个对象已经满足安全 / 服务结算。
```

## 5. 外设观察特征报告

建议将外设线程对自我的主要输出收敛为：

```text
外设观察特征报告 {
    来源外设
    来源线程
    来源观察帧 / 帧组
    观察时间
    外设配置摘要

    候选观察对象集合[]

    每个候选观察对象:
        外设内部观察ID
        外设内部跟踪状态
        观察像素簇引用 / 掩码引用 / 像素索引集合引用
        掩码类特征:
            像素集合掩码句柄
            轮廓掩码句柄
            彩色轮廓掩码句柄
            深度轮廓掩码句柄
            局部有效深度掩码句柄
            局部空间坐标有效掩码句柄
        局部图像证据:
            彩色轮廓截图句柄
            深度轮廓截图句柄
            截图边界框
            截图生成时间
            彩色轮廓掩码句柄，可选
            深度轮廓掩码句柄，可选
        特征集合:
            颜色特征
            深度特征
            空间坐标特征
            距离特征
            轮廓特征
            尺寸特征
            运动特征，可选

        每个特征:
            特征值
            有效性
            稳定性
            复现离散度
            连续成功次数
            失败次数
            来源配置
            失败原因
}
```

该报告应优先引用 `050004` 中定义的观察像素簇结构。若当前实现尚未完整支持观察像素簇，可在过渡期使用旧的空间候选 / 空间候选观察事实字段，但语义上必须按以下关系解释：

```text
外设候选观察对象
    -> 观察像素簇 / 观察特征报告
        -> 自我承接
            -> 存在候选
                -> 已确认观察存在
```

彩色轮廓截图和深度轮廓截图属于候选观察对象或观察像素簇的局部图像证据。它们用于控制面板显示、人工复核、递归细分、跨帧比较和外设配置学习，不是外设线程确认世界存在的依据。外设线程不得因为截图可用而直接宣称候选观察对象已经是自我世界树中的已确认观察存在。

掩码类特征不同于截图证据。掩码不是给人看的附件，而是后续候选生成、子轮廓提取、像素归属判断、三维建模和当前帧识别统计会直接使用的正式特征。外设线程可以提交掩码句柄和掩码状态，但当前帧存在识别摘要、存在识别达标状态以及是否入树，仍由自我侧方法承接和裁决。

## 6. 特征稳定等级

外设线程输出的每类特征应分级：

```text
稳定特征:
    可直接作为自我后续判断材料。

降级可用特征:
    可以使用，但必须带低置信或用途限制。

不稳定特征:
    只能作为线索，不能作为确定结论。

不可得特征:
    不得伪造默认值，必须记录失败原因。
```

示例：

```text
候选观察对象#17:
    颜色特征状态 等于 稳定
    轮廓特征状态 等于 降级可用
    深度特征状态 等于 不稳定
    空间坐标特征状态 等于 不可得
    空间坐标不可得原因 等于 深度有效率不足
```

不得用一个整帧级的：

```text
质量不可用
```

粗暴覆盖所有局部候选观察对象和所有特征类型。整帧质量诊断只能作为上层摘要；候选对象和特征级稳定性必须保留用途相关的细分结果。

## 7. 外设内部循环

外设独占观察线程可以采用长期运行循环：

```text
while 外设线程运行:
    1. 检查相机运行状态。
    2. 按当前观察配置采集帧。
    3. 生成观察特征帧。
    4. 更新内部候选观察对象。
    5. 计算候选对象特征。
    6. 更新特征稳定性。
    7. 记录当前配置和效果。
    8. 对自我请求的目标特征生成报告。
    9. 必要时切换配置继续尝试。
```

外设内部可以有自己的小闭环：

```text
内部目标:
    某目标特征稳定复现状态 等于 稳定

内部任务:
    尝试配置 / 采样 / 比较 / 复现

内部方法:
    调分辨率
    调 ROI
    调工作模式
    调曝光
    多帧融合
    重新采样

内部学习:
    什么条件 + 什么配置 -> 什么特征稳定
```

这套内部闭环只属于双目相机外设内部服务，不进入自我需求树，不作为自我任务筹办的正式任务，不产生自我侧方法动作动态。

## 8. 对自我暴露的本能方法面

外设线程内部可以复杂，但对自我暴露的外设本能方法必须收敛为控制、检查、使用三类。

### 8.1 控制类

示例目标：

```text
双目相机.可用状态 等于 可用
双目相机.工作模式 等于 指定模式
双目相机.占用状态 等于 已释放
```

控制类方法可以改变外设自身状态，但必须有明确输入、前置条件、输出和动作动态落账规则。

### 8.2 检查类

示例目标：

```text
双目相机.运行状态 等于 正常
双目相机.运行状态 等于 降级可用
双目相机.运行状态 等于 异常
双目相机.对当前观察需求的能力匹配状态 等于 满足
双目相机.对当前观察需求的能力匹配状态 等于 不满足
双目相机.工作质量状态 等于 可用
双目相机.工作质量状态 等于 降级可用
双目相机.工作质量状态 等于 不可用
```

检查类方法原则上不启动、重启、修复、切换模式或长期占用外设；如果检查必须改变主要工作状态，应返回控制类缺口。

### 8.3 使用类

示例目标：

```text
自我所在场景.当前观察特征帧取得状态 等于 已取得
外设观察报告.生成状态 等于 已生成
目标区域.目标特征稳定复现状态 等于 稳定
当前观察帧.观察像素簇集合状态 等于 已生成
```

使用类方法的目标宿主通常不是外设本体，而是自我、对象、场景、目标区域、当前观察帧或外设观察报告。

### 8.4 不暴露的内部动作

不得把下列外设内部步骤暴露为自我层本能方法：

```text
内部滤波
内部分割
内部轮廓提取
内部调参尝试
内部多帧缓存
内部候选跟踪细节
内部学习样本整理
内部配置评分
```

自我只读取：

```text
稳定特征报告
配置摘要
失败原因
能力匹配结果
外设观察报告
```

## 9. 数据交互

正式交互模型定为：

```text
外设主动生产；
需求驱动消费；
任务管理承接；
自我线程裁决入账。
```

完整链路：

```text
双目相机外设线程
    -> 外设观察消息队列 / 最新观察缓存 / 稳定特征缓存
        -> 任务管理外设消息承接线程
            -> 匹配等待任务 / 活跃需求
            -> 生成任务回执 / 派生需求消息 / 动作动态输入
                -> 自我线程
                    -> 校验
                    -> 裁决
                    -> 通过统一更新指令入树 / 入世界
```

这里同时存在两个方向：

```text
外设线程是 push：
    持续观察，持续把观察报告、观察像素簇、质量缺口、稳定特征放入队列或缓存。

需求系统是 pull：
    安全 / 服务根需求派生出正式观察需求后，由任务管理外设消息承接线程去队列或缓存中匹配能满足需求的观察材料。
```

一句话：

```text
外设一直看，但只有被正式需求领走的信息，才有资格进入自我的正式认知链。
```

### 9.1 安全 / 服务根需求不得直接消费队列

不得采用：

```text
外设线程 -> 队列 -> 自我根需求直接消费
```

原因：

```text
1. 外设消息频率高，自我线程会被相机流淹没。
2. 安全 / 服务根需求是价值根，不直接处理外设原始消息。
3. 队列中大量信息与当前需求无关。
4. 原始观察报告不等于世界树真值。
5. 需要任务管理线程先匹配任务上下文、等待项、活跃需求和时效。
```

自我根需求真正接收的应是经过任务管理承接、匹配、转译后的：

```text
任务回执
派生需求消息
动作动态输入
观察事实承接请求
```

### 9.2 队列和缓存分层

不得把所有原始帧直接塞入自我可见的全局队列。队列和缓存分三层。

第一层：外设内部原始帧缓存。

```text
原始 RGB 帧
原始深度帧
内部滤波结果
内部临时分割结果
内部多帧缓存
```

该层由双目相机外设线程内部管理，自我和任务管理不直接消费。

第二层：外设观察报告队列。

```text
外设观察报告 {
    外设ID
    报告ID
    时间戳
    帧宽
    帧高
    彩色帧号
    深度帧号
    配置摘要

    观察像素簇集合
    簇ID掩码
    低质量区域集合
    未归簇区域集合
    错误摘要
}
```

该队列是任务管理外设消息承接线程消费的主队列。

第三层：最新稳定特征缓存。

```text
按 外设ID + 特征类型 + 目标区域 / 簇ID 建索引：
    最近稳定颜色特征
    最近稳定深度特征
    最近稳定空间坐标特征
    最近稳定轮廓特征
    最近推荐观察配置
```

如果正式需求需要：

```text
目标区域.深度有效率 大于 阈值
```

任务管理外设消息承接线程可以先查稳定特征缓存；满足时生成任务回执或承接请求，不必等待下一帧。

### 9.3 消费者

外设观察报告队列的正式消费者是：

```text
任务管理外设消息承接线程
```

不是：

```text
自我线程；
安全 / 服务根需求；
普通任务执行线程直接读取外设流。
```

任务管理外设消息承接线程负责：

```text
1. 从外设观察消息队列读取报告。
2. 校验报告完整性。
3. 去重和时效检查。
4. 更新最新观察缓存和稳定特征缓存。
5. 匹配等待中的任务。
6. 匹配活跃需求。
7. 判断是否需要上报自我线程。
8. 生成任务回执 / 派生需求消息 / 动作动态输入。
```

它是外设消息分拣层，不是世界树写入者。

### 9.4 根需求如何驱动消费

安全 / 服务根需求不直接读队列，而是通过需求树派生正式观察需求。

示例：

```text
自我.安全值 大于 安全值基线
```

经因果展开生成：

```text
当前观察帧.存在识别达标状态 等于 达标
当前观察帧.观察像素簇集合状态 等于 已生成
```

任务管理据此建立外设等待项或订阅项：

```text
外设等待项 {
    来源需求 = 当前观察帧.观察像素簇集合状态 等于 已生成
    目标外设 = 双目相机
    期望消息类型 = 外设观察报告
    期望内容 = 观察像素簇集合
    最低稳定性要求
    最大等待时间
    是否允许缓存 = 是
}
```

承接线程消费队列或缓存：

```text
如果队列或缓存中有匹配报告：
    生成任务回执 / 观察事实承接请求。

如果没有匹配报告：
    等待外设线程下一次报告。

如果报告质量不足：
    生成派生需求消息，例如推荐配置 / 重新观察 / 调整工作模式 / 观察质量改善路径学习需求。
```

### 9.5 三种消费方式

等待任务消费：

```text
有明确任务正在等待 双目相机_取得当前观察报告。
承接线程收到匹配报告后生成任务回执。
```

活跃需求消费：

```text
没有显式任务等待，但有活跃需求需要 目标区域.稳定特征状态 等于 稳定。
承接线程收到可满足材料后生成满足线索、派生回执或观察事实承接请求，上报自我线程裁决。
```

缓存不消费：

```text
没有等待任务，也没有活跃需求，只是普通观察流。
承接线程只更新最新观察报告缓存 / 稳定特征缓存，不打扰自我线程，不入树。
```

### 9.6 上报自我线程的条件

不是每条外设消息都上报。只有以下情况才上报自我线程：

```text
1. 命中等待任务。
2. 满足某个活跃需求。
3. 产生安全相关高优先级缺口。
4. 外设状态发生关键变化。
5. 稳定特征首次达标。
6. 活跃父需求的关键质量条件不满足。
7. 外设错误影响当前任务。
8. 需要正式派生需求入树。
```

其它消息只留在：

```text
外设观察缓存
稳定特征缓存
外设内部历史样本
```

### 9.7 队列消息不是事实权威

队列中的消息只是：

```text
外设观察材料
```

它还不是：

```text
自我所在场景的正式观察事实
世界树真值
已确认观察存在
安全 / 服务结算证据
```

只有经过：

```text
任务管理承接
    -> 自我线程裁决
        -> 自我承接方法 / 统一更新指令
```

之后，才可能形成：

```text
当前观察帧存在
观察像素簇集合
存在候选集合
动作动态
世界树因果样本
```

控制面板不得把相机原始画面、外设内部候选或未被需求领走的队列消息直接当作自我识别结果。控制面板复现场景信息应以自我所在场景中的观察帧、像素观察事实、观察像素簇、存在候选或已确认观察存在等已承接特征为数据源，不得反写世界树真值。

## 10. 外设内部学习模块

第一版最多引入一个外设内部学习模块：

```text
双目相机_稳定特征获取学习模块
```

该模块学习：

```text
观察条件 + 外设配置 + 目标特征类型
    -> 特征稳定性结果
```

建议记录：

```text
目标特征类型
观察距离范围
画面中心距离
ROI
分辨率
工作模式
光照摘要
纹理摘要
目标运动状态
相机运动状态
稳定成功次数
稳定失败次数
平均离散度
推荐配置
```

它对自我暴露的只能是学习摘要或检查 / 使用结果，例如：

```text
双目相机.推荐观察配置状态 等于 已生成
双目相机.目标特征稳定获取能力状态 等于 已知
双目相机.当前配置对目标特征适用状态 等于 适用
双目相机.当前配置对目标特征适用状态 等于 不适用
```

该学习模块不得直接改写自我需求树，不得直接把外设内部学习结论写成世界树真值。

## 11. 自我、任务管理、外设线程职责

### 11.1 外设线程

```text
持续观察
内部调参
内部学习
候选观察对象维护
特征稳定性评估
报告可稳定给出的特征
报告失败原因
```

### 11.2 自我线程

```text
决定是否承接
决定是否入树
把观察报告转成观察事实
判断是否满足安全 / 服务需求
生成新的需求
更新世界树因果
```

自我线程可以裁决和调度，但不能绕过方法直接把外设报告写成世界树权威事实。

### 11.3 任务管理

```text
根据正式需求筹办任务
调用外设本能方法
等待外设报告
处理缺口回执
在子需求完成后触发父任务重筹办
```

任务筹办和任务执行仍是任务管理生命周期普通函数，不作为本能方法注册、选择或动作动态来源。

## 12. 需求表达

对自我可见的需求表达仍使用三比较。

示例：

```text
目标区域.特征稳定复现状态 等于 稳定
目标区域.深度有效率 大于 最低深度有效率
目标区域.空间坐标有效率 大于 最低空间坐标有效率
目标存在.距离复现离散度 小于 最大允许离散度
目标存在.颜色特征稳定状态 等于 稳定
外设观察报告.生成状态 等于 已生成
当前观察帧.观察像素簇集合状态 等于 已生成
```

不得写成：

```text
外设线程 方向=识别世界对象
相机 方向=发现存在
外设内部任务 方向=进入自我需求树
```

## 13. 最小实施建议

第一版建议：

```text
1. 为双目相机建立独占观察线程。
2. 线程持续采集帧，但只保留最近 N 帧和稳定摘要。
3. 建立外设内部候选观察对象列表。
4. 每个候选对象只输出稳定特征集合，有什么给什么。
5. 每个特征必须带：
       有效性
       稳定性
       离散度
       连续成功次数
       失败原因
6. 自我通过一个使用类本能方法读取最新稳定特征报告。
7. 自我只承接报告，不关心内部怎么得到。
```

缺真实 D455 连续样本时，只能记录等待真实样本或外设链路超时，不得用模拟样本、夹具入口或伪造动作动态证明稳定输出。

## 14. 禁止项

禁止：

```text
1. 外设线程直接写自我需求树。
2. 外设线程直接写世界树真值。
3. 外设线程直接宣称稳定外部对象。
4. 外设线程直接完成安全 / 服务价值结算。
5. 把外设内部候选观察对象当作已确认观察存在。
6. 把外设内部滤波、分割、调参、多帧缓存登记成自我层本能方法。
7. 把线程本身作为方法动作动态动作来源。
8. 把不稳定或不可得特征伪造成稳定特征。
9. 把控制面板显示层或外设原始画面反写成自我世界树真值。
10. 把像素 100% 回查解释成跨帧身份、语义识别或目标可见性闭合。
```

一句话：

```text
双目相机外设独占线程是自我身体延伸中的长期观察服务；
它负责稳定交付观察特征；
自我负责承接、验证、归并和结算。
```
