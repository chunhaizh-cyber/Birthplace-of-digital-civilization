## 2. 上级约束

1. 本规范服从 `规范/规范目录.md`、0050 总纲、0300 冲突清单和对应根规范。
2. 历史来源中与当前根规范冲突的表述不进入当前权威口径。
3. 旧名称、旧结构和旧阶段口径必须按 `规范/0300_规范冲突与前后矛盾清单_20260701.md` 的 C001-C008 收束，不得在本规范中恢复历史并列结构、旧字段身份或旧执行来源。
4. 任务筹办 / 任务执行只作为任务管理生命周期普通函数；动作来源、方法注册和方法选择必须服从 0050 总纲、3200 任务根规范、3300 方法根规范和 1170 动态根规范。
5. 文本、日志、注释、临时 JSON、自由字段和显示摘要不得承载正式机器逻辑或业务状态。

## 3. 当前有效规则

以下条款由历史来源按当前根规范修订抽取；若条款与第 2 章或上级规范冲突，以上级规范和第 2 章为准。

1. 线程不是动作来源。线程只能调度和调用方法。凡是生成方法动作动态的任务域、需求域、方法域提交，都必须通过对应本能方法或方法动作入口完成。
2. 被动整理动作必须退回普通代码。
3. 这类消息只用于线程可见性、健康监控和诊断展示，应由创建者或线程自身发送给控制面板线程信息模块。
4. 纯线程状态不得进入自我线程治理邮箱，不得落成自我内部世界治理事实，不得生成主动 / 被动 / 方法动作动态。
5. 应通过任务管理界面线程按任务管理上行消息发送给自我线程；不得用通用线程状态变化消息替代任务治理消息。
6. 任务筹办不得把安全、服务、观察、外设、学习等具体需求侧规则写成自身内部能力。
7. 某个需求目标需要哪些前置条件，必须来自需求目标、世界树因果信息、临时因果视图、方法条件节点、条件结果对或已入树子需求；不得由任务筹办按目标特征类型硬编码推导。
8. 自我线程决定“为什么要做、做哪个、优先做什么”。
9. 但任务状态动作动态的来源方法必须固定为 提交任务状态变化。
10. 自我线程只在任务管理准备派发真实执行动作前，审批该工作项是否允许执行。
11. 执行许可绑定工作项；工作线程未结束前，同一工作项不得重复向自我线程申请执行许可。

32. 任务管理线程不得把纯线程创建、退出、暂停、堵塞、恢复或健康状态作为自我治理消息上行。
33. 只有绑定具体任务、工作项、执行尝试、任务结果、任务缺口、执行前许可或观察事实承接的结构化任务治理消息，才允许进入自我线程。

39. 任务筹办只找路径、找方法、找条件；具体需求侧前置关系必须由需求 / 因果 / 方法条件数据表达。
40. 只能由任务管理线程编排，并由任务域被动状态提交动作入口提交；动作动态来源方法固定为 提交任务状态变化。
41. 自我线程只能提供任务生命周期事件和执行前许可，不得直接指定新任务状态。

## 4. 使用边界

1. 本规范用于计划、详细设计、代码修改和验收前的规则回读。
2. 本规范不能作为代码实现完成、业务闭环完成、自我苏醒完成或初步成熟完成的证据。
3. 需要展开历史论证时，只能把 `规范/旧规范/` 中的原文件作为追溯材料，不得让旧文件反向覆盖本规范。
