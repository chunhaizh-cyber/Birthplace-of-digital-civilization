# 0400 根规范缺失补齐建议

编号：0400
日期：20260701
状态：规范梳理结果候选建议

## 1. 结论

按当前代码扫描，现有正式 `规范/规范目录.md` 尚未为所有自定义主信息数据类型建立独立根规范入口。

本目录已为每个主信息数据类型生成候选独立根规范，但正式补齐仍需要后续修订 `规范/规范目录.md`，并逐条处理旧规范冲突。

## 2. 补齐路径建议

1. 第一阶段：保留本目录为候选结果，不改原规范目录。
2. 第二阶段：用户确认根规范口径后，建立正式编号映射表。
3. 第三阶段：修订 `规范/规范目录.md`，把候选根规范纳入正式目录或迁移到 `规范/` 根目录。
4. 第四阶段：逐条修订与根规范冲突的旧子规范。
5. 第五阶段：运行规范治理检查并更新工程图谱。

## 3. 优先级建议

| 优先级 | 类型 | 原因 |
| --- | --- | --- |
| P0 | 存在、特征、特征值、状态、动态、因果、二次特征 | 直接承载世界树事实和因果账本 |
| P1 | 需求、任务、方法 | 直接承载内部循环和执行链 |
| P2 | 语素入口、词、语言记录、文章、段落、自然句、子句、指代 | 主要承载入口、解析和引用，不应承载业务事实 |
| P3 | 因果模板别名型规范 | 需要与因果主信息根规范保持一致 |

## 4. 不建议做法

1. 不建议直接批量改旧规范正文而不先裁决根口径。
2. 不建议把本目录结果直接当成正式目录编号。
3. 不建议用“兼容旧称”的方式同时保留 `词性主信息类`、`实例特征主信息类` 或 `抽象存在主信息类` 作为当前规范口径。
