## 1. 设计目标

本设计用于统一回答以下问题：

```text
观察帧 F 的材料是否清晰；
观察候选 C 的边界、深度、空间和像素归属是否清晰；
局部体素候选 V_local 是否足以作为 C 的观察域证据；
跨帧材料是否稳定复现；
候选与 SceneVoxelPrior 是否一致；
当前材料是否足以进入识别、跟踪、扫描、观察或存在体素融合的后续治理链。
```

本设计不是事实裁决方法。它只产出评分、计数、状态值域、阻断原因、缺口材料和可回查证据句柄；不确认稳定存在、不确认 `C -> E` 归属、不更新稳定存在体素、不写需求满足、不生成动作动态。

一句话口径：

```text
清晰度与稳定复现评价是一把观察域证据尺，不是事实写入权。
```

## 3. 不解决范围

本设计不解决：

```text
1. 观察、扫描、识别、跟踪四方法的最终事实裁决。
2. `C -> E` 的最终唯一归属。
3. 稳定存在体素主模型更新。
4. 场景体素快照生成和先验图层生成。
5. 结构化缺口进入需求树后的父子角色最终裁决。
6. 新增长期 C++ 业务结构体。
7. 通过普通 bool 表达是否清晰、是否稳定、是否可融合、是否可提交。
```

## 4. 评价对象分层

评价对象：

```text
F：观察帧 / 外设报告材料页。
C：观察候选 / 像素簇 / 可观测单位。
V_local：局部体素候选 / 子体素候选。
O：观察域结果包 / 当前视觉融合结果。
S：SceneVoxelPrior / 当前场景体素只读快照。
```

禁止直接写入：

```text
E：世界树稳定存在。
E_voxel：稳定存在体素主模型。
```

基本流向：

```text
F 材料清晰度
    -> C 候选清晰度
    -> V_local 局部体素清晰度
    -> O 观察域结果评分 / 缺口
    -> 四方法或存在体素融合治理链只读消费
```

## 8. 复合特征收束口径

第一版建议收束以下复合特征或二次特征：

```text
CF-视觉观察帧清晰度成立
CF-观察候选清晰度成立
CF-局部体素清晰度成立
CF-跨帧稳定复现成立
CF-先验一致性可用
CF-体素融合前置可用
```

收束输入必须至少包含：

```text

版本 / generation；
来源报告 ID / 帧 ID / 材料页 ID；
```

禁止把以下判断直接写成普通一阶 bool：

```text

是否先验一致
是否遮挡成立
是否自由空间冲突成立

```

## 9. 与其它详细设计的关系

与 D2 `观察材料质量收束`：

```text
D2 收束材料是否可用、低质量、不可用、部分可用或需复验。
D9 在 D2 之后进一步把清晰度、稳定复现和先验一致性整理为观察域证据尺。
D9 不替代 D2，也不绕过 D2 质量准入。
```

与 D4 `像素归属候选分裂与局部体素证据`：

```text
D4 负责像素归属图、候选分裂和局部体素挂 C。
D9 读取 D4 形成的像素归属、候选和局部体素证据，计算清晰度和融合前置状态。
D9 不允许局部体素直接写稳定存在体素。
```

与 D5 `结构化信息缺口与需求派生承接`：

```text
D9 输出的清晰度缺口、稳定复现缺口、体素融合前置缺口、先验一致性缺口必须进入 D5 缺口链。
缺口不能自己变成需求，必须经过任务管理和父需求视角角色视图治理。
```

与 D6 / D7 场景体素和先验发布：

```text
D9 只读 SceneVoxelPrior 和外设处理先验材料。
先验一致性高只能提高评分或降低复验成本，不能确认 E 当前存在。
先验冲突只能输出冲突候选或复验缺口，不能确认 E 消失。
```

与 H1 / D8 `四方法共享底层关联判断能力`：

```text
D9 可作为共享底层能力中的评价子能力。
四方法读取 D9 结果时仍不得互相调用。
D9 不新增第五个本能方法。
```

## 10. 失败分流

```text
低清晰材料：
    生成清晰度缺口；不得进入体素融合；可建议补观察或降级观察。

稳定复现不足：
    只保留候选和复验材料；不得确认稳定存在或跟踪成功。

generation / 坐标版本不一致：
    阻断跨帧合并和体素融合；输出版本缺口。

局部体素清晰但归属不明：
    只挂 C 的局部体素证据链；不得写 E_voxel。

先验匹配高：
    输出先验一致性评分；不得写 E 当前存在。

自由空间冲突：
    输出冲突候选和复验缺口；不得写 E 消失。

遮挡解释候选：
    输出遮挡解释材料；不得写跟踪成功。
```

## 12. 反走样清单

禁止：

```text
1. 新增长期业务结构体承载清晰度评价包。
2. 用普通 bool 写“清晰 / 稳定 / 可融合 / 可提交 / 先验一致”。
3. 让外设线程直接写判断型状态作为一阶事实。
4. 把单帧高清等同于稳定复现。
5. 把先验匹配高等同于 E 当前存在。
6. 把自由空间冲突等同于 E 消失。
7. 把遮挡解释等同于跟踪成功。
8. 把局部体素清晰等同于稳定存在体素可更新。
9. 用日志、说明文本、控制面板或临时 JSON 参与机器判断。
10. 跳过 D5 缺口收束直接派生需求。
```

## 13. 验证剧本

```text
V1 单帧高清：
    清晰度评分高，但稳定复现未成立；不得确认稳定存在。

V2 多帧稳定：
    连续命中、离散度低，输出稳定复现评分；不得直接写 C -> E。

V3 局部体素清晰但归属不明：
    可挂 C 的局部体素证据链；不得更新 E 稳定体素。

V4 先验匹配高：
    输出先验一致性评分；不得写 E 当前存在。

V5 自由空间冲突：
    输出冲突候选和复验缺口；不得写 E 消失。

V6 遮挡解释：
    输出遮挡解释材料；不得写跟踪成功。

V7 低清晰材料：
    输出清晰度缺口；不得进入体素融合。

V8 generation 失配：
    阻断稳定复现和跨帧合并；不得合并多帧证据。

V9 普通 bool 负例：
    不得新增普通一阶 bool 特征表达判断。

V10 check_specs：
    `python .\tools\check_specs.py` 无 hard issues / warnings。
```
