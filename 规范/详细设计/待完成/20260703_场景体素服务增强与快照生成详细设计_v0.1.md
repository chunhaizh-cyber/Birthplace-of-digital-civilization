## 1. 设计对象

本设计只定义“当前场景体素服务增强与快照生成”这一桥接层，回答：

```text
1. 场景体素如何由当前场景中已确认存在的信息生成。
2. 场景体素快照包含哪些只读先验材料。
3. 场景体素维护线程如何触发、更新、发布快照。
4. 视觉中间层如何只读使用快照。
5. 场景体素缺口如何输出到结构化信息缺口链。
```

核心定义：

```text
场景体素 =
    根据自我当前所在场景中的已确认存在信息生成的当前场景运行期三维心像缓存。
```

工程角色：

```text
读：
    当前场景；
    已确认存在；
    稳定存在体素；
    存在坐标 / 位姿；
    颜色事实；
    局部子体素；
    坐标系版本。

写：
    运行期场景体素快照；
    快照统计；
    缺口集合；
    粗查询结果；
    视觉先验材料。

不写：
    世界树事实；
    稳定存在体素；
    观察事实入账；
    需求满足；
    动作动态；
    价值结算。
```

一句话：

```text
场景体素服务维护心像，不裁决事实。
```

## 3. 三层体素分工

### 3.1 局部观察体素

```text
宿主：
    观察候选 C 或观察材料集。

来源：
    当前 D455 观察帧、像素归属图、掩码、深度点、彩色轮廓、深度轮廓。

性质：
    短期、可回查、可丢弃、需复现的观察域证据。

禁止：
    直接写稳定存在体素、世界树稳定事实、场景体素缓存。
```

### 3.2 稳定存在体素

```text
宿主：
    已确认稳定存在 E。

来源：
    已归属、可回查、质量收束后的局部观察体素和轮廓证据。

性质：
    长期形状记忆。

写入：
    只能由存在体素融合内部治理链经正式提交入口更新。
```

### 3.3 当前场景体素

```text
宿主：
    当前场景运行期只读心像。

来源：
    当前场景中的已确认存在 E；
    E 的稳定体素；
    E 的场景坐标 / 位姿；
    场景边界；
    自我 / 外设姿态。

性质：
    运行期缓存和先验，不是事实源。

读取方：
    视觉中间层；
    观察 / 扫描 / 跟踪 / 识别的候选解释链；
    显示；
    路径或风险候选链。
```

## 7. 事件模型

当前实现锚点待核：

```text
同步当前场景快照
```

应扩展为：

```text
0 未定义
1 同步当前场景快照
2 当前场景切换
3 当前场景存在集合变化
4 稳定存在体素版本变化
5 存在场景坐标 / 位姿变化
6 自我位姿变化
7 外设位姿变化
8 场景边界变化
9 观察事实已入账
10 视觉中间层请求局部先验刷新
11 全量重建请求
12 局部刷新请求
13 保底刷新
14 停止请求
```

第一版实现可以先保持现有 `同步当前场景快照`，但详细设计必须预留事件值域，避免后续把所有变化都塞进同一个同步事件里。

## 8. 同步流程

```text
S0 接收维护事件
S1 校验基础信息、当前场景、坐标系版本
S2 读取当前场景子存在集合
S3 对每个存在读取稳定三维体素特征和值句柄
S4 读取存在场景绝对坐标或局部原点
S5 读取颜色事实和体素来源证据
S6 生成场景体素存在项
S7 可选读取内部世界子体素并映射到父存在场景坐标
S8 生成快照统计和缺口集合
S9 生成或更新空间索引 / 投影索引 / 先验图层
S10 发布只读快照版本
```

第一版可将 S9 标记为 `待增强`，但不能把场景体素先验引导前处理计划建立在不存在的 S9 输出上。

## 9. 快照查询能力

当前已有查询能力待 S0 核查：

```text
读取最新快照
查询AABB
查询点附近
射线粗查询
统计AABB
```

这些当前主要基于“存在原点”做粗过滤。

应增强：

```text
查询存在体素场景AABB
查询视锥内已知存在
查询预计遮挡项
查询已知空闲区
查询未知区
查询自由空间冲突候选区
查询相机投影ROI
查询预计深度范围
```

查询结果必须是运行期先验候选，不证明命中、遮挡、存在或消失事实。

## 10. 只读快照发布规则

```text
1. 场景体素服务内部可维护写缓存。
2. 对外只发布只读快照副本或只读句柄。
3. 视觉中间层不得持有可写缓存引用。
4. 快照必须带场景体素版本、坐标系版本、生成时间。
5. 视觉中间层提交候选时必须带使用的快照版本和坐标系版本。
6. 版本过旧、坐标失配或缺口严重时只能降权、复验或输出缺口。
```

## 11. 与视觉中间层的接口

视觉中间层读取 `SceneVoxelPrior` 后，可以生成：

```text
先验匹配评分；
遮挡候选；
深度缺失缺口；
自由空间冲突候选；
先验结构缺口；
观察候选解释类型。
```

视觉中间层不得生成：

```text
世界树存在确认；
稳定存在消失确认；
稳定体素更新；
需求满足结论；
动作动态。
```

## 12. 与像素归属 / 候选分裂的关系

场景体素先验可以参与：

```text
像素先验投影区；
预计遮挡区；
已知空闲区；
自由空间冲突区；
候选分裂边界；
观察候选先验匹配评分。
```

但仍必须遵守：

```text
像素 -> 观察候选 C
C -> 可能对应世界树 E 的候选评分
最终 C -> E 归属由观察 / 识别 / 跟踪 / 扫描裁决
```

## 13. 与存在体素融合的关系

```text
存在体素融合：
    更新 E 的稳定三维体素模型。

场景体素服务：
    读取 E 的稳定体素模型，生成当前场景体素只读快照。
```

场景体素服务不得直接修改稳定存在体素。

## 14. 与结构化缺口承接的关系

场景体素服务输出的缺口应标准化为结构化信息缺口：

```text
缺口大类 = 场景体素先验缺口
缺口来源模块 = 场景体素服务
来源场景 = 当前场景
来源快照版本 = 场景体素版本
来源坐标系版本 = 坐标系版本
目标宿主 = 场景 / 存在 / 快照图层
目标特征 = 三维体素 / 坐标 / 先验投影 / 可见性 / 空闲区等
缺口类型 = 场景体素缺口值域
阻断阶段 = 快照生成 / 快照查询 / 视觉先验发布
建议后续路径 = 补坐标 / 补体素 / 重建快照 / 降级观察 / 复验
```

不得自动变成需求，必须交由 D5 缺口收束和父需求角色视图处理。

## 16. 验证剧本

```text
V1 空场景：生成快照版本，存在项为 0，缺口为 0 或仅缺体素特征类型。
V2 缺坐标：存在有体素但无场景绝对坐标，进入缺存在场景绝对坐标缺口。
V3 缺体素：存在有坐标但无三维体素句柄，进入缺三维体素缺口。
V4 坐标系缺失：同步参数坐标系版本 <= 0，输出缺坐标系版本缺口。
V5 内部世界子体素：父存在带内部世界子存在和局部原点时，可映射为内部世界子存在体素项。
V6 AABB 查询：只返回原点或 AABB 落在范围内的存在项，不证明遮挡或命中事实。
V7 射线粗查询：只返回粗命中项，不生成观察事实。
V8 维护线程：事件只进入运行期队列，线程只生成快照，不写世界树事实。
V9 旧快照：视觉中间层读取旧版本快照后必须降权或输出缺口。
V10 视觉越权负例：视觉中间层不得通过 SceneVoxelPrior 直接写稳定存在或需求满足。
V11 场景体素越权负例：场景体素服务不得更新稳定存在体素。
```
