## 1. 核心结论

四个本能方法：

```text
观察
扫描
识别
跟踪
```

不得直接互相调用、互相完成或互相替代。

它们可以共享底层纯判定能力和材料处理能力，包括：

```text
像素归属
候选过滤
特征匹配
反证检查
范围内对应计算
材料质量读取 / 质量证据解释
先验匹配评分
遮挡 / 自由空间冲突候选解释
局部体素候选生成
目标观察约束解释
```

共享能力只允许输出：

```text
候选
评分
计数
状态码
缺口材料
建议后续方法类型
可回查证据句柄
```

共享能力不得输出：

```text
世界树稳定存在确认
C -> E 的最终唯一归属事实
稳定存在体素更新
扫描当前状态闭环
跟踪连续存在结论
需求满足状态
动作动态
```

一句话：

```text
共享的是“判定材料和候选关系”，不是共享本能方法的职责。
```

## 2. 设计必要性

共同边界已经允许四方法共享底层纯判定能力，但没有单独回答：

```text
什么能力可以共享；
共享能力的输入输出是什么；
谁可以调用；
输出只能是什么；
它不能写什么；
它如何输出缺口；
四方法如何读取共享结果但不互调。
```

如果缺少本设计，后续实现容易出现：

```text
观察方法直接调用识别方法；
扫描方法私自做识别或跟踪；
跟踪方法把候选匹配评分直接写成稳定归属；
共享函数绕过结构化缺口链直接派生需求；
视觉融合模块从候选 / 评分越权写事实。
```

因此本设计把共享能力收束为底层材料处理和候选关系判断，不授予事实提交权和方法调度权。

## 4. 能力边界

### 4.1 允许共享的能力

```text
A. 像素归属材料读取：
    读取像素归属账本、掩码、ROI、点集、空间候选句柄。

B. 候选过滤：
    基于材料质量、深度有效率、空间坐标有效率、ROI / mask、目标观察约束筛选合法候选。

C. 特征匹配：
    当前观察候选 C 与目标约束、SceneVoxelPrior、已有存在特征摘要之间做评分。

D. 反证检查：
    输出自由空间冲突、遮挡候选、深度缺失、先验过期、材料不可比较、证据不足等缺口。

E. 范围内对应计算：
    在限定范围内计算 C 与已有存在候选 E? 的空间重叠、距离、深度一致、局部体素相似和先验匹配评分。

F. 局部体素候选生成：
    根据深度轮廓、彩色轮廓、空间点、掩码生成局部体素候选材料。

G. 目标观察约束解释：
    读取目标观察约束并生成本轮共享判定所需阈值、ROI、空间范围和 generation 材料。

H. SceneVoxelPrior 匹配评分：
    读取场景体素先验并生成候选评分、冲突候选和缺口材料。
```

### 4.2 禁止共享的能力

共享底层能力不得执行：

```text
1. 调用观察 / 扫描 / 识别 / 跟踪任一本能方法。
2. 把观察候选 C 写成世界树稳定存在 E。
3. 写稳定存在体素。
4. 写场景体素缓存。
5. 写需求满足状态。
6. 生成动作动态。
7. 直接派生需求入树。
8. 把候选评分直接转成唯一归属事实。
9. 把遮挡候选直接转成“存在未消失”事实。
10. 把自由空间冲突直接转成“存在已消失”事实。
```

## 5. 项目承载原则

不得通过新增 C++ 长期业务结构体来解决本设计问题。

本设计中的“共享判定结果”“关联判断包”“候选匹配材料”等名称，只表示：

```text
运行期只读视图；
现有结果包；
现有外设报告项 / 目标观察约束 / 视觉观察域结果包；
观察域存在上的特征族；
结构化缺口材料。
```

普通一阶材料只能记录：

```text
句柄
版本
来源
计数
评分
坐标范围
时间戳
generation
目标约束 ID
报告 ID
帧 ID
候选 ID
```

判断型状态不得作为普通一阶事实：

```text
候选可用
材料可比较
唯一归属成立
遮挡解释成立
自由空间冲突成立
需复验
可提交
```

这些必须由复合特征、二次特征、内部治理节点、指定方法或运行期只读视图收束产生。

## 6. 共享能力输出值域

### 6.1 关联判断结果类型

建议值域：

```text
0 未评估
1 候选匹配
2 候选不唯一
3 证据不足
4 硬冲突
5 遮挡候选
6 视野外候选
7 深度缺失
8 自由空间冲突
9 材料不可比较
10 先验不可用
11 需复验
12 可交给目标方法承接
```

这是判断型枚举，不得由外设线程直接写入长期一阶事实。它只能作为运行期结果视图、方法阶段性结论或结构化缺口收束状态使用。

### 6.2 关联判断来源类型

```text
0 未定义
1 像素归属
2 候选过滤
3 特征匹配
4 反证检查
5 范围内对应计算
6 局部体素候选生成
7 SceneVoxelPrior 匹配
8 目标观察约束解释
```

### 6.3 建议后续方法类型

```text
0 无建议
1 补观察
2 识别
3 跟踪
4 扫描
5 体素融合
6 场景体素刷新
7 材料质量收束
8 目标观察约束重建
```

建议后续方法类型只是建议材料，不是直接调用。

## 8. 四方法如何使用共享能力

### 8.1 观察

观察可使用共享能力来：

```text
生成观察候选 C；
生成像素归属图；
生成局部体素证据；
生成材料质量 / 先验冲突 / 低质量缺口；
发现存在的特征值材料。
```

观察不得使用共享能力来：

```text
确认 C 是哪个稳定存在 E；
维护全范围当前状态；
声明目标连续存在。
```

### 8.2 识别

识别可使用共享能力来：

```text
计算 C 与已有存在 E 的候选关系；
计算唯一性、相似度、冲突和证据不足；
生成 C -> E 候选评分和缺口。
```

识别不得使用共享能力来：

```text
绕过识别提交入口写世界树事实；
把最高评分候选直接作为唯一归属事实；
把缺口直接派生需求。
```

### 8.3 跟踪

跟踪可使用共享能力来：

```text
计算目标集合内连续命中；
计算丢失、重捕获、遮挡候选；
读取范围内对应、距离和跨帧稳定材料。
```

跟踪不得使用共享能力来：

```text
把外设内部跟踪 ID 写成世界树存在 E；
把遮挡候选直接写成“存在仍存在”；
把未命中直接写成“存在消失”。
```

### 8.4 扫描

扫描可使用共享能力来：

```text
读取已归属范围内当前材料；
生成变化候选；
生成未覆盖解释；
生成自由空间冲突和遮挡候选。
```

扫描不得使用共享能力来：

```text
从原始材料直接创建新一阶观察特征；
私自调用识别或跟踪方法；
把扫描变化候选直接写成稳定事实。
```

## 9. 缺口承接

共享能力遇到以下情况必须输出结构化信息缺口材料：

```text
候选不唯一
材料不可比较
像素归属争议
SceneVoxelPrior 缺失
先验过期
坐标系版本不一致
自由空间冲突
遮挡解释不足
局部体素候选不可生成
目标观察约束缺失
```

缺口不得直接入树。必须由 D5 结构化信息缺口与需求派生承接链收束后，再由任务管理和父子需求角色视图决定：

```text
只记录过程证据；
派生非必须子需求；
派生可选路径子需求；
派生必须子需求；
转观察验证缺口；
转外设材料闭环；
转开发诊断。
```
