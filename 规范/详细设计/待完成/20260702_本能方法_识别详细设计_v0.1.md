## 1. 方法定位

识别是建立或判定当前材料与已有存在之间对应关联的过程。

更准确表述：

```text
在已确定观察范围内，使用已有存在特征和当前观察材料特征，进行一对多候选过滤、反证检查和唯一性收敛，输出“当前材料对应哪个已有存在”或“无法确定”的关联判断。
```

识别不是创建存在，不是补写一阶特征，也不是把关联直接写成世界树真值。

## 2. 两个方向

方向 A：

```text
已知存在 -> 在当前观察材料集合中找对应材料。
```

方向 B：

```text
已知图像特征 / 观察材料 -> 在场景已有存在集合中找对应存在。
```

两个方向共同都是：

```text
1 对多候选过滤
-> 候选收敛
-> 唯一 / 不唯一 / 冲突 / 证据不足
```

## 3. 输入

```text
已确定观察范围
当前观察材料或图像特征
已有存在集合
已有存在特征
可回查材料句柄
比较阈值或二次特征规则
最低反证检查规则
```

## 4. 输出

```text
已有存在指针
空指针
候选数量
同一性评分
硬冲突数量
证据不足原因
补观察建议
过程证据
```

其中语义输出只能是已有存在指针或空指针。候选数量、评分、冲突和证据不足原因只能作为过程证据。

## 5. 允许写入

```text
本轮运行存在中的过程证据
输出结果场景中的过程证据
已有存在指针或空指针结果
必要的结构化缺口
```

## 6. 禁止写入

```text
不得直接创建新存在。
不得补写颜色、空间坐标、轮廓、深度等一阶特征值。
不得把候选唯一但硬冲突的结果写成已归属。
不得把候选不唯一写成弱归属或默认归属。
不得把识别输出反推为观察完成、扫描完成、跟踪完成、全场景明确、需求满足或安全 / 服务值可结算。
不得把外设内部候选编号、帧内编号、任务编号或自我世界树内部 ID 当作语义识别依据。
```

## 7. 消费的数据层

识别不设独立数据队列。主要消费：

```text
已承接的存在特征
已确定观察范围
L1 逐簇识别报告或可回查观察材料
观察事实承接后形成的候选 / 特征结构
```

## 8. 关联分层

```text
临时关联：
    识别方法内部形成候选、评分、冲突和证据不足原因。

确认关联：
    识别结果唯一且无硬冲突，输出已有存在指针。

持久入账：
    不由识别裸写。必须走提交入口、观察事实承接、动态或状态写入规则。
```

## 9. 与其他方法边界

```text
与观察：
    观察生成材料、候选和特征补充材料；识别判断材料和已有存在的对应关联。

与扫描：
    扫描需要对应关系时可共享关联判断能力；缺对应时输出识别需求来源。

与跟踪：
    跟踪可以用识别后的已有存在作为目标来源；跟踪丢失或重捕获不等于识别完成。
```

## 10. 缺口分流

```text
范围未确定 -> 补观察或范围确定需求来源
候选不唯一 -> 补观察 / 增加比较特征的补完需求来源
硬冲突 -> 冲突复核或观察补证需求来源
缺特征 -> 若特征类型已确认属于目标存在，则生成特征值补完需求来源；若特征类型尚未确认，则生成观察发现或归属复核缺口
目标需连续复现 -> 跟踪需求来源
```

识别只能提出比较证据不足、候选不唯一、硬冲突或特征值补完需求来源。识别不得直接创建存在、不得补写一阶特征值，也不得把“识别需要某特征”反推为该存在一定具备该特征类型。
