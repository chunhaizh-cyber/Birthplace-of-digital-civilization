## 1. 记录目标

本文先固定外设感知四类本能方法的共同边界，避免后续生成 `观察 / 扫描 / 识别 / 跟踪` 详细设计时混用职责。

本设计只解决：

```text
四个方法如何共用外设材料和底层关联能力
四个方法如何区分输入、输出、禁止写入和缺口分流
外设数据队列按什么层次组织才便于后续调用
已确认存在的特征值缺口如何生成补完需求，并作为观察的一种触发来源
```

本设计不解决：

```text
具体算法实现
阈值最终取值
新代码修改
正式验收通过声明
```

## 2. 核心结论

外设数据不应按四个本能方法机械拆成四条队列，而应按材料成熟度和报告用途分层。

四个本能方法不得以本能方法身份直接互相嵌套调用、互相完成或互相替代。它们可以共享底层纯判定能力和材料处理能力，包括：

```text
像素归属
候选过滤
特征匹配
反证检查
范围内对应计算
```

凡是需要改变任务目标、补观察、补识别、补扫描或补跟踪的情况，必须输出结构化缺口，经需求树、任务筹办和方法选择重新承接。

特征值缺口补完可以成为观察任务执行中派生补完子需求的一种来源，不限制观察任务自身继续执行。观察仍可由原始场景进入、区域初始建账、外设材料承接、安全 / 服务复核、扫描或跟踪缺口等来源单独触发。

特征值缺口补完只允许从“已确认存在 E 已确认具备特征类型 FT，但 FT 当前值不完整、不可比较或当前无效”推出。不得因为新建存在时缺少任意特征，就批量生成所有可能特征的补完需求。

该缺口不写成存在的一阶特征；应由二次特征或状态比较承载“值不完整 / 不可比较 / 当前无效”的判断，再按需求主信息类表达为目标宿主、目标特征、目标状态齐全的补完需求。

## 3. 数据组织层次

| 层次 | 名称 | 作用 | 可被谁消费 | 禁止事项 |
| --- | --- | --- | --- | --- |
| L0 | 原始帧 / 原始簇 / 短期材料页 | 外设侧采集、稳定化、诊断和回查 | 外设线程、材料页读取、控制面板只读复现 | 不直接作为自我世界树事实 |
| L1 | 逐簇识别报告 | 组织观察像素簇、掩码、ROI、点集、质量和可观测单位对应摘要 | 观察、识别、观察事实承接链 | 不直接宣称稳定世界存在 |
| L2 | 扫描变化报告 | 面向已归属、可比较、有基准区域输出当前变化材料 | 扫描、扫描缺口分流链 | 不从原始材料直接生产新一阶观察特征 |
| L3 | 跟踪报告 | 面向确定目标集合输出连续复现、当前位置、丢失或重捕获材料 | 跟踪、观察补证、扫描复核 | 不把外设内部跟踪 ID 当自我世界存在 ID |

识别不单设独立数据队列。识别消费已承接的存在特征、已确定范围和可回查观察材料。

## 4. 共同术语

观察材料集：由外设报告、材料页、观察像素簇、ROI、掩码、点集、质量状态和可回查句柄组成的当前观察材料集合。

可观测单位：观察材料集中可被归属、比较、验证或分流的最小观察单位，可以对应像素簇、候选区域、ROI、掩码或点集。

已合法外设当前数据集：已经通过外设报告、任务管理承接、质量判定和材料可回查检查，可供自我方法读取的当前外设数据项集合。

关联判断能力：底层纯判定能力，用于判断材料、像素簇、观察特征和已有存在之间的候选关系、唯一性、冲突和证据不足原因。

识别本能方法：当任务目标就是建立或判定当前材料与已有存在的对应关联时，由任务筹办选择的本能方法。

跟踪目标集合：跟踪方法关注的确定对象集合，可以是一个目标，也可以是多个目标，但必须有明确目标来源、范围或约束。

特征值缺口：某个已确认存在已经确认具备某个特征类型，但该特征类型当前对应的特征值存在缺段、未知段、不可比较、过期或当前任务范围内无效。

补完需求：由特征值缺口、上级任务阻塞、扫描 / 识别 / 跟踪缺口、安全 / 服务需要或认知加深策略触发的需求。其目标不是把所有未知都补齐，而是让指定存在的指定特征值在当前任务范围、当前认知层或当前比较目标下达到可用状态。

## 6. 四个方法共同边界

```text
观察：
    目标是把材料组织成可承接的观察事实、可观测单位对应、存在信息新建或更新材料、特征补充材料和缺口。

扫描：
    目标是维护当前扫描范围内已归属、可比较、应覆盖存在的当前状态。

识别：
    目标是在限定范围内建立或判定当前材料与已有存在之间的对应关联。

跟踪：
    目标是对确定目标集合连续获取当前变化、位置、丢失状态或重捕获候选。
```

## 7. 特征值缺口到补完需求的共同闭环

```text
存在 E 已确认具备特征类型 FT
-> E.FT 的当前值不完整 / 不可比较 / 当前无效
-> 生成二次判断或状态比较结果：E.FT 存在补完缺口
-> 缺口被上级任务、扫描、识别、跟踪、安全 / 服务需要或认知加深策略选中
-> 生成补完需求：让 E.FT 在当前任务范围内达到可用状态
-> 任务筹办选择观察、跟踪观察、扫描复核或其他补完方法
-> 新事实或当前值回写项目结构
-> 二次判断更新
-> 需求结算
```

这个闭环只说明一种需求来源，不定义观察方法本身。观察可以在没有既有特征缺口时单独运行，例如初始观察、区域建账、外设材料承接和新存在发现。

## 8. 父任务收束时的子需求治理

观察、扫描、识别、跟踪在执行过程中都可能发现结构化缺口并派生子需求。该子需求不应反向绑死父任务，也不应在父任务完成后无来源悬挂。

完整的父子需求关系角色、三类子需求判定、父任务收束和活动承接规则，统一见：


## 9. 共同禁止项

```text
1. 不得把说明书当实现依据。
2. 不得把外设报告、ROI、掩码、点集或材料页直接当成自我世界存在真值。
3. 不得把识别结果反推为观察完成、扫描完成、跟踪完成、需求满足或安全 / 服务值可结算。
4. 不得把扫描或跟踪写成新一阶特征裸写入口。
5. 不得让自我线程直接消费高频相机原始流。
6. 不得把外设内部候选编号、帧内编号、任务编号或外设内部跟踪 ID 当成语义识别依据。
7. 不得用日志、显示文本、临时 JSON 或说明字段承载机器逻辑。
8. 不得把“新建存在时缺少某些可能特征”直接等同于补完需求。
9. 不得把认知完整度、体素完整度、可比较状态等二次判断写成存在的一阶特征值。
10. 不得让父任务完成后留下无父来源、无活动依据的子需求继续参与任务选择。
```
