## 1. 设计目标

当前系统中已经出现多类缺口来源：

```text
外设材料缺口；
视觉观察缺口；
观察候选缺口；
像素归属缺口；
局部体素缺口；
场景体素先验缺口；
方法筹办 / 执行缺口；
派生需求入树拒绝缺口。
```

本文要补齐中间承接层：

```text
各种缺口如何统一表达；
缺口什么时候只记录；
缺口什么时候进入需求派生候选；
缺口什么时候进入拒绝闭环；
缺口如何连接任务管理派生需求消息；
缺口如何交给父需求角色视图裁决为必须 / 可选路径 / 非必须。
```

一句话：

```text
缺口是阻断证据；
需求派生是治理结果；
二者中间必须经过结构化、收束和任务管理承接。
```

## 3. 核心口径

结构化信息缺口不是需求本身。

```text
结构化信息缺口 =
    某个目标、方法、观察材料或治理环节无法继续推进时的可回查阻断证据。
```

缺口可以：

```text
记录为过程证据；
转为派生需求候选；
触发父任务等待；
触发任务重筹办；
被合并到既有缺口；
被拒绝入树并进入拒绝闭环；
转入外设材料、观察验证、学习、规范补齐或开发诊断闭环。
```

缺口不可以：

```text
直接写成需求；
直接写需求满足失败事实；
直接写世界树事实；
直接调用观察 / 扫描 / 识别 / 跟踪；
直接创建稳定存在或稳定特征；
用普通 bool 表达是否阻塞、是否需要、是否可派生。
```

固定治理链：

```text
缺口来源材料
    -> 结构化信息缺口特征族
    -> 缺口收束
    -> 任务管理派生需求消息 / 入树拒绝闭环
    -> 父子关系角色视图
```

## 4. 工程承载原则

本文中的：

均表示项目中的存在、特征族、运行期只读视图、任务管理上行消息或现有协议槽位，不表示新增自由结构体。

```text

目标宿主；

缺口来源模块；
缺口材料句柄；
阻断阶段值；
严重度评分Q10000；
来源版本；
generation；
建议后续方法ID；
失败分流类型；
幂等键材料。
```

判断型状态必须由复合特征、二次特征、治理节点或指定方法收束：

```text

缺口是否应派生需求；

缺口是否影响安全；
缺口是否影响服务；
缺口是否可普通需求化；
缺口是否应转观察验证；
缺口是否应转外设材料闭环；
缺口是否应转开发诊断。
```

若当前代码内部已有 bool，只能视作协议兼容位或局部临时计算结果；进入项目事实层时必须转为状态值、评分、版本、来源和复合 / 治理收束结果。

### 7.3 需求化处理建议值域

```text

```

## 8. 缺口到派生需求的收束规则

缺口进入需求派生前，必须完成以下收束：

```text
1. 缺口来源可追溯。
2. 目标宿主明确。
3. 目标特征类型明确。
4. 当前状态和目标状态可表达。
5. 缺口不是单次低质量偶发材料，或已达到复验 / 频次阈值。
6. 缺口不是代码缺陷型报告、参数诊断、UI 文本或日志文本。
7. 父需求角色视图允许派生，或上级任务明确等待该缺口。
8. 缺口有可回查材料，或有明确无法回查的拒绝闭环。
```

### 8.1 只记录为过程证据

条件：

```text
缺口不阻断当前目标；
缺口只表示低价值信息不足；
缺口属于新候选的非必要特征缺失；
缺口无法指向明确目标宿主或目标特征；
缺口属于单次噪声。
```

处理：

```text
记录缺口候选；
不派生需求；
父任务继续推进。
```

### 8.2 派生非必须子需求候选

条件：

```text
缺口对认知加深、质量提升、未来复验有价值；
但不阻塞父需求当前目标达成；
父需求角色视图没有将该缺口标为必须或可选路径。
```

处理：

```text
生成派生需求消息；
角色建议为非必须子需求；
父任务可继续收束。
```

### 8.3 派生可选路径子需求候选

条件：

```text
父需求存在多条可满足路径；
该缺口对应其中一路的补齐需求；
至少一条路径满足即可推进父需求。
```

处理：

```text
生成派生需求消息；
角色建议为可选路径子需求；
父任务等待策略取决于路径集合收束。
```

### 8.4 派生必须子需求候选

条件：

```text
缺口直接阻断父需求目标判定；
没有该缺口的补齐，父需求不可满足；
目标特征、当前状态、目标状态和满足关系完整；
缺口不是外设内部临时字段或代码诊断。
```

处理：

```text
生成派生需求消息；
角色建议为必须子需求；
父任务进入等待或待重筹办。
```

### 8.5 拒绝普通需求化

条件：

```text
缺口来自外设内部材料字段；
缺口来自参数诊断；
缺口来自规范缺口；
缺口来自代码缺陷型报告；
缺口只有日志或说明文本来源；
缺口无法表达目标宿主、目标特征、当前状态或目标状态。
```

处理：

```text
不创建普通需求；
进入拒绝闭环；
按拒绝原因转外设材料、观察验证、学习、规范补齐、开发诊断或合并冷却。
```

## 9. 与任务管理派生需求消息的映射

现有 `结构_任务管理派生需求消息` 可承载第一版需求派生，不需要新增消息结构。

映射：

```text
缺口来源任务 -> 消息头.任务主键 / 步骤主键
来源方法 -> 来源方法指针 / 来源方法主键
来源动态 -> 来源动态指针 / 来源动态主键
来源因果 -> 来源因果指针 / 来源因果主键
父需求 -> 父需求主键
缺口大类 -> 派生需求类型
缺口生成原因 -> 因果路径生成类型
阻断严重度 -> 阻塞级别
目标特征类型 -> 需求特征类型指针 / 主键
目标宿主 -> 需求目标主体指针 / 主键
当前状态 -> 需求当前状态指针 / 主键
目标状态 -> 需求目标状态指针 / 主键
满足关系 -> 满足关系
贡献层级 -> 贡献层级
稳定度摘要 -> 稳定度摘要
幂等键材料 -> 消息头.幂等键 / 结构化稳定键材料
```

禁止：

```text
不得把外设材料缺口码直接塞成需求目标状态；
不得用日志文本或失败原因文本当机器判断依据；
不得绕过字段完整性检查直接写需求树；
不得从缺口生成点直接新增需求节点。
```

## 10. 与父子关系角色视图的关系

缺口生成点只允许输出角色建议，不允许直接写父子角色事实。

```text
缺口收束结果
    -> 角色建议：只记录 / 非必须 / 可选路径 / 必须 / 拒绝需求化
    -> 任务管理派生需求消息
    -> 入树 / 拒绝闭环
    -> 父需求视角角色视图最终裁决
```

固定边界：

```text
必须子需求 / 可选路径子需求 / 非必须子需求
    不是需求节点本体属性；
    不是外设报告字段；
    不是单个方法返回值；
    只能由父需求视角角色视图在运行期推导。
```

## 11. 与入树拒绝闭环的映射

派生需求入树拒绝不是失败丢弃，而是进入闭环。

建议映射：

```text
字段缺失 -> 自动补槽后重提 / 内部治理闭环
父需求缺失 -> 开发诊断闭环
外设内部材料字段 -> 外设材料闭环
参数诊断不需求化 -> 方法内部处理 / 开发诊断
规范缺口 -> 升级规范缺口
代码缺陷型报告 -> 转代码诊断
同批重复 / 近期重复 -> 合并冷却闭环
```

设计要求：

```text
1. 拒绝回执必须保留来源幂等键材料。
2. 拒绝回执必须记录拒绝阶段和拒绝原因。
3. 可重试项必须记录重试次数和最大重试次数。
4. 可合并项必须记录关联既有需求或任务。
5. 开发诊断项不能伪装成普通需求。
```

## 12. 与观察 / 扫描 / 识别 / 跟踪的边界

```text
观察：
    输出材料、候选、特征补充材料和缺口；
    不直接调用识别 / 扫描 / 跟踪。

识别：
    输出 C -> E 的候选关联、冲突、证据不足和识别缺口；
    不直接创建观察需求，只输出派生来源。

跟踪：
    输出连续复现、遮挡、丢失、重捕获候选和跟踪缺口；
    不直接确认消失。

扫描：
    输出已归属存在当前状态变化、未覆盖解释和扫描缺口；
    不从原始材料创建新存在。
```

四方法若需后续动作，只能输出结构化信息缺口或派生需求来源，经需求树、任务筹办和方法选择承接。

```text

若父需求等待唯一归属，则可生成识别补齐需求候选；
```

### V3 深度缺失但不阻塞父需求

输入：非目标区域深度缺失。

期望：

```text
只记录过程缺口或非必须子需求来源；
不阻塞父任务。
```

### V4 场景体素先验版本缺失

输入：视觉融合缺 SceneVoxelPrior 或坐标系版本缺失。

```text
生成场景体素先验缺口；
```
