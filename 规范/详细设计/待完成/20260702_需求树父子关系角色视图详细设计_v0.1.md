## 1. 记录目标

本文解决需求树中父子需求关系如何区分以下三种角色：

```text
必须子需求
可选路径子需求
非必须子需求
```

核心约束：

```text
不新增“子需求类型”字段。
不把三类角色写成需求节点本体属性。
不把控制面板显示、日志文本、临时 JSON 或说明字段作为机器判断依据。
```

三类角色不是需求本体类型，而是“父需求视角下的关系角色”。同一个需求节点本体仍然只表达：

```text
目标宿主
目标特征
目标状态
来源
任务承接
需求树治理信息
```

## 2. 核心结论

需求树至少要区分三套关系，不能只用“父子”一个关系覆盖全部语义：

```text
来源父子关系：
    子需求为什么从哪个父需求执行过程、筹办过程或缺口事实中产生。

满足依赖关系：
    子需求是否参与父需求当前满足判定。

活动承接关系：
    子需求当前是否还参与调度、等待、执行、截止、放弃或转挂。
```

三类角色由运行期只读视图推导：

```text
需求节点 + 父子关系 + 目标特征定义视图 + 方法条件 / 结果链 + 来源动态 / 回执 + 二次特征缺口 + 活动承接状态
-> 父子关系角色视图
```

该视图可以是函数返回值、临时只读投影或调度时计算结果，但不得成为 `需求主信息类` 新字段。

## 3. 三类关系角色

### 3.1 必须子需求

定义：

```text
子需求目标是父需求目标当前满足判定的必要组成、必要前置或当前绑定方法路径下的必要条件。
```

典型来源：

```text
父目标特征定义中的必要子特征
复合特征 AND 分解
当前绑定方法的必需条件节点
目标状态达到前必须满足的因果前置
父任务当前执行路径不可绕过的参数绑定 / 证据闭合缺口
```

结算规则：

```text
必须子需求未满足且活动承接未收束 -> 父需求不能判定满足。
必须子需求满足 / 截止 / 取消 / 明确收束 -> 父任务必须重筹办或重新结算父需求。
```

### 3.2 可选路径子需求

定义：

```text
子需求目标是父需求目标的可替代达成路径之一。任一合法路径满足后，父需求可进入重新结算；其他同组路径应截止、降权或取消活动承接。
```

典型来源：

```text
复合目标 OR 路径
多个可替代方法结果能力
多个可替代因果路径
多个可替代外部确认路径
```

结算规则：

```text
任一路径满足 -> 父任务重筹办 / 父需求重新结算。
同组其他路径 -> 不再继续消耗同一父需求预算，按截止、取消活动承接或历史保留处理。
没有路径满足 -> 父需求仍未满足，但可按优先级继续尝试其他路径。
```

### 3.3 非必须子需求

定义：

```text
子需求来自父需求执行过程中的发现、补完、认知加深、质量提升或机会型缺口。
它有来源父需求，但不参与父需求当前满足必要判定。
```

典型来源：

```text
观察中发现已确认特征值不完整
材料质量不足但不阻塞本轮观察目标
识别比较特征不足但已有其他路径可完成当前目标
扫描或跟踪发现可补充的当前值 / 证据
认知加深策略发现的低优先级补完需求
```

结算规则：

```text
父需求满足不依赖它。
无更高优先级任务时，父任务可以暂缓结束并优先执行它。
存在更高优先级任务时，放弃它的当前活动承接。
被安全 / 服务 / 扫描 / 识别 / 跟踪 / 认知加深策略接管时，转挂到新的有效父需求或维护类父需求。
```

非必须子需求不是“无价值需求”。它只是“不阻塞当前父需求满足”。它仍可在调度资源允许时执行，也可被更高来源接管。

## 4. 推导输入

| 输入材料 | 项目承载结构 | 作用 |
| --- | --- | --- |
| 父需求目标 | 需求主信息类 | 提供父目标宿主、目标特征、目标状态 |
| 子需求目标 | 需求主信息类 | 提供子目标宿主、目标特征、目标状态 |
| 父子来源 | 需求树关系、来源动态、任务回执 | 回答子需求为什么产生 |
| 目标特征定义 | 抽象特征树、复合特征规则、定义视图 | 判断 AND / OR / 路径 / 普通叶子语义 |
| 方法条件 / 结果链 | 方法主信息类、条件节点、结果节点、条件结果对 | 判断当前方法路径下的必要前置和可替代路径 |
| 状态 / 动态 / 因果证据 | 状态、动态、因果、临时因果视图 | 判断前置关系、路径来源和缺口来源 |
| 二次特征缺口 | 二次特征、状态比较结果 | 表达补完、质量、可比较性、关系性缺口 |
| 活动承接状态 | 需求活动集、任务运行账、截止 / 取消记录 | 判断是否继续调度或收束 |
| 当前优先级 | 需求权重、任务优先级、外部安全 / 服务压力 | 判断非必须子需求是否暂缓父任务或放弃当前承接 |

## 5. 推导顺序

父子关系角色视图建议按以下顺序推导：

```text
1. 读取父需求目标和子需求目标。
2. 读取子需求来源动态、任务回执或缺口事实。
3. 读取父目标特征定义视图。
4. 判断子需求是否是父目标必要组成或当前方法必要前置。
5. 若不是，判断子需求是否属于父目标的可替代路径组。
6. 若不是，判断是否为执行过程发现的补完 / 质量 / 认知加深 / 机会型缺口。
7. 读取活动承接状态和当前优先级。
8. 输出父子关系角色视图。
```

优先级规则：

```text
当前方法必要前置 > 父目标必要组成 > 可选路径 > 非必须补完
```

同一子需求在不同父需求或不同方法路径下，角色可以不同。角色变化不通过改字段完成，而是由当前视图重新推导。

## 6. 非必须到必须的临时升格

非必须子需求可以在当前方法路径下临时变成必须前置。

例：

```text
父需求：识别存在 E
非必须缺口：E.轮廓局部缺失
当前选定识别方法：必须使用完整轮廓反证
```

此时：

```text
在父需求本体视角：轮廓补完不是永久必要组成。
在当前方法路径视角：轮廓补完是当前方法的必要前置。
```

处理规则：

```text
不修改子需求本体。
不新增“已升格为必须”字段。
由方法条件 / 当前绑定方法 / 任务筹办结果在父子关系角色视图中临时推导。
当前方法被替换或取消后，重新推导角色。
```

## 7. 父需求收束规则

父需求准备判定完成或父任务准备结束时，必须先读取父子关系角色视图。

```text
存在未满足的必须子需求：
    父需求不能判定满足；父任务等待、执行子需求或重筹办。

存在可选路径子需求：
    若任一路径当前满足，父需求可重新结算，其他同组路径截止或取消活动承接。
    若无路径满足，父需求未满足，可继续调度下一路径。

仅存在未完成的非必须子需求：
    父需求可以判定满足，但活动承接要单独处理。
```

非必须子需求的活动承接规则：

```text
无更高优先级任务：
    父任务可以暂缓结束，先执行非必须子需求。

存在更高优先级任务：
    放弃该非必须子需求的当前活动承接，父任务结束并让出资源。

被更高来源接管：
    不随父任务结束放弃，转挂到新的有效父需求或维护类父需求。
```

已正式入树的需求不建议物理删除；应通过需求截止、取消活动承接、失去活动依据、转挂或同等项目结构状态表达。未入树的运行期候选或派生提示可以直接丢弃。

## 9. 禁止项

```text
1. 不新增“子需求类型”“父子关系类型”“是否必须”等需求主信息类字段。
2. 不用叶子 / 非叶子直接判断是否必须或是否可任务化。
3. 不用日志、控制面板显示、说明文本或临时 JSON 承载角色判断。
4. 不把非必须子需求误当作父需求满足前置。
5. 不把必须子需求未满足的父需求判定为满足。
6. 不把可选路径同组全部长期并行消耗父需求预算。
7. 不把已截止、已取消活动承接的子需求显示或判断成当前满足。
8. 不物理删除正式入树需求节点来掩盖来源关系；历史节点应保留为目标契约和过程证据。
9. 不让任务筹办按领域词硬编码父子角色；角色必须从目标特征定义、方法条件 / 结果、来源动态和缺口事实中推导。
```

## 10. 后续实现影响

当前详细设计会影响以下程序区域，后续实现前需要按代码事实确认具体入口：

```text
自我线程：
    需求活动集选择、父需求结算、非必须子需求放弃 / 转挂。

需求类：
    需求获取途径语义视图、父子关系读取、当前活动子需求读取、需求截止 / 取消活动承接。

任务管理：
    父任务收束、子任务完成后父任务重筹办、任务回执同步。

方法筹办：
    当前绑定方法条件导致非必须子需求临时变成必须前置的视图推导。

控制面板 / SQL 投影：
    只能显示只读推导结果，不得让显示字段成为机器判断依据。
```

后续代码实现建议优先做只读视图函数，而不是新增持久字段：

```text
读取父子关系角色视图(父需求, 子需求, 当前方法路径, 当前活动上下文)
读取父需求未满足必须子需求集合(父需求)
读取父需求可选路径满足状态(父需求)
读取父需求非必须活动子需求集合(父需求)
```

函数名为设计占位，最终以现有类边界和函数功能说明文档扫描结果为准。

## 11. 观察侧引用方式

观察方法执行中产生的特征值补完子需求，默认先视为来源于父观察任务的非必须子需求，除非：

```text
1. 它被父观察任务目标定义为完成前置；
2. 当前绑定观察方法的条件节点要求它先完成；
3. 安全 / 服务 / 扫描 / 识别 / 跟踪 / 认知加深策略把它接管为更高来源需求；
4. 后续父子关系角色视图重新推导为必须或可选路径。
```

观察详细设计只记录观察如何产生缺口和补完需求来源；父子需求如何暂缓、执行、放弃、截止或转挂，以本文为准。
