## 1. 审查结论

来源草稿的主方向可采纳：

```text
存在体素融合不是外设侧行为；
不是相机看到后直接更新世界；
它应作为自我内部治理承接链，在已确认存在 E 的观察材料归属、质量和稳定性满足后，生成子体素候选和稳定体素更新候选；
E 的稳定体素主模型写入必须回到 E 体素特征主模型写入治理入口或对应领域类执行最小一致性校验，不由外设、视觉融合层或体素加工线程裸写。
```

本优化版收紧以下风险：

```text
1. 将“内部治理线程”改写为“内部治理承接链 / 可由工作线程执行耗时计算”，避免线程被误解为动作来源。
2. 去掉“新增结构体”倾向，统一表达为存在、特征、特征值、复合特征、二次特征、运行期只读视图和候选结果包。
3. 强化“默认不合并、先建关系、先审计禁合并证据，再允许融合”的保守规则。
4. 把可融合、可提交、遮挡、归属可信、材料可回查等判断写成复合特征或治理收束状态，不写成普通 bool。
5. 明确局部观察体素、稳定存在体素和场景体素三层边界。
6. 补齐项目结构映射、反走样清单、验证剧本和代码落地前必须补的契约。
```

## 2. 核心口径

存在体素融合的最小链路：

```text
已确认存在 E 新增未消费的体素相关观察材料
    -> 提交体素融合待处理材料
    -> 内部治理承接链读取 E 的观察材料、归属材料、稳定体素基准和质量证据
    -> 提取输入证据子轮廓
    -> 生成子体素候选
    -> 子体素候选挂入 E 的稳定体素证据子链
    -> 合格子体素生成稳定体素主模型更新候选
    -> E 体素特征主模型写入治理入口执行最小材料一致性校验
    -> 写入 E 的稳定三维体素主模型
    -> 本轮到此闭合；派生轮廓重算、可见性索引和场景体素刷新请求后续由场景体素服务增强 / 先验发布相关计划承接
```

必须保留的核心边界：

```text
先提取输入证据子轮廓，再生成子体素，再生成稳定体素主模型更新候选。
不得把未经分解和审计的整组轮廓直接融合进稳定主模型。
不得由外设、视觉中间层、场景体素服务或控制面板直接写稳定存在体素。
不得让体素融合承接链直接写场景体素缓存。
不得把体素融合成功直接写成需求满足、安全满足或服务完成。
```

## 3. 三层体素分工

### 3.1 局部观察体素

局部观察体素是当前观察候选 C 或观察材料集中的局部空间证据。

允许：

```text
记录来源观察帧、观察候选、材料页、ROI、mask、点集、深度点、局部体素和质量评分；
作为观察、识别、跟踪、扫描或体素融合的证据材料；
作为短期可回查材料进入候选链。
```

禁止：

```text
直接写成稳定存在体素；
直接写成世界树稳定事实；
直接证明 C 已归属 E；
直接触发场景体素刷新。
```

### 3.2 稳定存在体素

稳定存在体素是已确认存在 E 的长期三维体素特征。

允许：

```text
作为 E 的稳定三维体素主模型；
维护版本、坐标系版本、分辨率、占据数量、颜色数量、清晰度、最近融合输入版本、来源观察证据集合、冲突累计数量和缺口累计数量；
维护子体素候选证据链；
为场景体素服务提供只读输入。
```

禁止：

```text
由外设直接写入；
由单帧局部观察材料直接覆盖；
由子体素候选入链直接等同为主模型更新；
由场景体素先验或主模型派生轮廓反向伪造为本次观察证据。
```

### 3.3 场景体素

场景体素是从当前场景中的已确认存在、稳定体素、位姿、自我 / 外设姿态和场景边界生成的只读快照。

允许：

```text
作为视觉先验、外设处理先验、扫描未覆盖解释、遮挡解释和自由空间冲突解释的只读材料；
在稳定存在体素版本更新后由场景体素服务刷新。
```

禁止：

```text
直接裁决存在 E 当前可见；
直接确认存在消失；
直接修改稳定存在体素；
直接写世界树事实、需求满足、安全 / 服务结算或方法动作动态。
```

## 4. 触发边界

### 4.1 合法触发来源

存在体素融合只能由已确认存在 E 上新增的未消费体素相关观察材料触发。

第一版合法来源：

```text
E 新增未消费观察体素特征值；
E 新增同 generation 的深度轮廓材料和彩色轮廓材料；
E 新增可回查的局部观察体素候选；
E 新增已归属、已通过质量收束和稳定性收束的局部体素证据；
上轮融合因缺口暂缓，本轮补足材料后恢复。
```

禁止触发来源：

```text
外设原始帧；
单帧分割结果；
场景体素快照；
视觉先验命中；
主模型派生轮廓；
控制面板刷新；
日志文本；
旧当前特征值；
融合写回本身。
```

### 4.2 触发动作

特征写入入口不得同步执行完整体素融合。它只能提交待处理材料：

```text
写入观察体素材料
    -> 记录来源版本和消费状态
    -> 生成或更新体素融合输入组材料
    -> 形成待处理项
    -> 由内部治理承接链异步或分步处理
```

触发动作本身不得生成方法动作动态。若后续需要动作动态，必须由合法方法执行或提交入口裁决链生成。

### 4.3 去重与幂等

同一 E、同一来源观察候选、同一轮廓组 generation、同一坐标系版本和同一材料页版本，应生成同一幂等键。

```text
已存在同幂等键待处理项 -> 合并材料或更新等待状态；
已存在同幂等键处理完成项 -> 复用处理记录，不重复挂子体素；
若存在既有稳定体素基准摘要且该摘要变化 -> 标记旧项失效，重新生成候选或挂起复算；
若 E 尚无稳定体素主模型 -> 允许以本轮融合模型作为第一版主模型候选。
```

## 5. 内部治理承接模型

本文中的“工作线程”只表示耗时计算的承接方式，不是动作来源。

正确表达：

```text
体素融合内部治理承接链
    消费待处理材料；
    读取项目结构中的存在、特征、特征值和来源证据；
    生成运行期候选结果包、子体素候选和结构化缺口；
    将 E 稳定体素主模型写入交给 E 体素特征主模型写入治理入口或对应领域类。
```

可由工作线程执行：

```text
子轮廓提取；
子体素候选生成；
候选与主模型比较；
冲突数量统计；
更新候选构造；
第一版主模型候选构造。
```

工作线程禁止：

```text
直接写正式世界树事实；
直接修改存在三维体素特征；
直接创建内部世界子存在；
直接生成方法动作动态；
直接更新需求满足、安全 / 服务结算；
直接修改场景体素缓存；
绕过 E 体素特征主模型写入治理入口。
```

## 10. 复合特征收束

以下判断只能作为复合特征、二次特征或治理收束结果，不得落成普通 bool：

```text
CF-体素融合输入闭合性
    依赖：深度轮廓句柄、彩色轮廓句柄、generation、来源观察候选、来源材料页、坐标版本。

CF-体素融合材料可回查性
    依赖：材料页生命周期、句柄有效状态、TTL、来源帧ID、来源候选ID。

CF-体素融合归属可信性
    依赖：观察候选归属状态、同一性评分、候选不唯一数量、冲突数量、跨帧复现次数。

CF-子轮廓分解可行性
    依赖：轮廓闭合评分、连续性评分、有效深度点数量、争议像素数量、质量收束证据。

CF-子体素生成可行性
    依赖：子轮廓有效深度点数量、空间点状态、坐标系版本、体素分辨率、质量评分。

CF-子体素入链可行性
    依赖：子体素来源、generation、坐标系版本、幂等键、低质量状态、阻断原因集合。

CF-主模型融合可行性
    依赖：融合点数量、命中体素数量、新增占据数量、自由空间冲突数量、越界数量、归属冲突数量。

CF-稳定体素写入可行性
    依赖：既有主模型摘要、候选状态、质量阈值、冲突数量、写入治理入口权限；无旧主模型时允许作为第一版主模型候选。
```

判断型枚举值必须声明依赖特征族和收束规则。枚举不能作为逃避复合特征规则的替代物。

## 11. 处理流程

### 11.1 输入组闭合

```text
未消费体素相关观察材料进入 E
    -> 按 E + 来源观察候选 + generation + 坐标系版本聚合输入组
    -> 检查深度 / 彩色 / ROI / mask / 点集材料
    -> 检查材料可回查和 TTL
    -> 检查归属可信性和候选唯一性
    -> 输入闭合则进入子轮廓提取
    -> 输入不闭合则输出结构化缺口
```

若只有深度无彩色、只有彩色无深度、generation 失配、坐标版本失配或来源材料不可回查，不得进入完整主模型融合。

### 11.2 输入证据子轮廓提取

新增轮廓组进入后，必须先提取输入证据子轮廓，再生成子体素候选。

处理顺序：

```text
轮廓输入组
    -> 输入闭合检查
    -> 子轮廓分解
    -> 子轮廓质量评价
    -> 子轮廓关系边记录
    -> 禁合并证据审计
    -> 子轮廓候选集合
```

不得把未经分解的整组轮廓直接写入稳定三维体素主模型。

### 11.3 默认不合并规则

同一轮廓组内部的多个簇、碎片、颜色块、深度块或局部体素，默认不合并。

合并前流程必须是：

```text
相邻
    -> 建关系边
    -> 分类
    -> 审计禁合并条件
    -> 多帧确认
    -> 才能进入同一存在体素模型
```

禁合并证据优先于同体证据。存在以下任一证据时，不得合并，只能建立关系或输出缺口：

```text
深度层明显分离；
自由空间隔断；
运动方向不一致；
稳定边界长期不相连；
坐标系或 generation 不一致；
归属候选不唯一；
材料质量不足；
一个区域仅有颜色纹理而缺深度占据；
疑似承载关系、接触关系、遮挡关系，而非同体关系。
```

过分裂可以在后续多帧证据足够时合并；过融合会污染稳定体素模型。因此第一版宁可过分裂，不得过融合。

### 11.4 子体素候选生成

子体素候选输入：

```text
输入证据子轮廓
来源深度点 / 空间点
来源颜色材料
存在 E 的局部坐标系
体素分辨率
稳定体素主模型基准版本
坐标变换材料
```

子体素候选输出：

```text
子体素候选ID
来源子轮廓ID
来源观察候选ID
子体素占据位块句柄
子体素颜色句柄
子体素边长_mm
子体素局部原点X/Y/Z
子体素AABB_存在局部坐标
子体素AABB_场景坐标
子体素占据数量
子体素颜色数量
子体素输入像素数量
子体素有效深度点数量
子体素质量评分Q10000
子体素坐标状态
子体素生成状态
子体素阻断原因集合
```

子体素候选只是候选，不是稳定体素更新。

### 11.5 子体素入链

稳定三维体素特征视为父特征。其下维护候选证据子链：

```text
存在 E
    稳定三维体素主模型特征
        主模型句柄
        主模型版本
        主模型派生轮廓
        子体素候选链
            子体素候选 #1
            子体素候选 #2
            子体素候选 #3
```

子体素入链表示该候选已成为 E 的体素融合证据之一，可以被主模型融合候选生成读取。它不表示稳定体素主模型已经更新。

入链条件：

```text
1. 子体素候选必须有来源子轮廓。
2. 子体素候选必须有来源观察帧或来源观察候选。
3. 子体素候选必须记录 generation 和坐标系版本。
4. 子体素候选不得覆盖主模型。
5. 同一幂等键的子体素不得重复入链。
6. 低质量子体素可进入证据链暂存，但不得进入主模型融合。
```

### 11.6 主模型融合候选

主模型融合候选输入：

```text
E.稳定三维体素主模型
E.稳定三维体素主模型版本
本次合格子体素候选集合
子体素坐标变换
主模型分辨率
冲突阈值
质量阈值
```

对每个合格子体素候选执行：

```text
1. 投影到 E 的稳定体素坐标系。
2. 计算命中体素数量。
3. 计算新增占据体素数量。
4. 计算颜色更新体素数量。
5. 计算自由空间冲突数量。
6. 计算越界体素数量。
7. 计算融合点数量。
8. 计算缺口数量。
9. 生成主模型融合候选状态。
```

保守融合规则：

```text
单次观察子体素可以增强已有占据或补充未知占据。
单次观察子体素不得直接删除主模型已有稳定占据。
不存在融合点时，不得进入主模型更新，只能挂起待融合候选或输出缺口。
高冲突子体素不得进入主模型，只能生成冲突缺口。
补全深度只能降低不完整程度，不能提高真实性。
```

### 11.7 E 体素特征主模型写入治理入口

主模型更新候选必须通过 E 体素特征主模型写入治理入口写回 E 的稳定三维体素特征。

该入口属于自我内部治理，不重新裁决 C -> E 同一性，也不把体素融合结果当成外部事实提交。它只负责把已归属到 E 的深度 / 彩色轮廓融合结果，经最小材料一致性校验后写入 E 的三维体素主模型。

写入前只做最小校验：

```text
目标 E 指针或句柄有效；
融合后体素模型非空；
正立方体包围盒合法；
融合后体素模型与深度轮廓 / 彩色轮廓有基本重合支撑；
明显越界、截断或自由空间冲突未超过第一版允许阈值；
候选不是由场景体素先验或派生轮廓伪造；
写入方是 E 体素特征主模型写入治理入口或对应领域类。
```

写入成功后允许更新：

```text
E.稳定三维体素主模型句柄
E.稳定三维体素清晰度Q10000
E.稳定三维体素最近融合时间
```

第一版不强制维护稳定体素版本、来源观察证据集合、消费状态或结构化拒绝回执。若最小校验失败，直接丢弃本次主模型融合候选；不派生需求，不写缺口，不影响 E 既有体素模型。

### 11.8 主模型派生轮廓重算后置

稳定体素主模型更新后，未来可以重算主模型派生轮廓或可见性索引，但这不是 P12 第一版 S5 的完成条件。

派生轮廓：

```text
来自融合后的稳定体素主模型；
用于下一轮预测、投影、识别、跟踪和显示；
不得替代本次输入证据子轮廓；
不得反向写成观察材料事实；
必须携带来源主模型版本。
```

第一版处理：

```text
P12 S5 不重算派生轮廓；
不生成可见性索引；
不把派生轮廓作为本次观察证据；
后续若需要该能力，转入场景体素服务增强、外设观察先验发布器或视觉前处理相关计划。
```

### 11.9 场景体素刷新后置

稳定体素主模型写入后，体素融合承接链不得直接修改场景体素缓存。

第一版处理：

```text
P12 S5 不提交场景体素刷新请求；
不新增存在体素变化事件类型；
不直接调用场景体素服务；
场景体素服务后续按 D6 / D7 设计从稳定体素事实只读生成或刷新快照。
```

## 12. 候选丢弃与缺口边界

体素融合内部治理第一版区分两类失败：

```text
1. S1-S4 的输入材料不闭合、候选不可生成、冲突过高：
   可以输出候选阻断原因掩码或结构化缺口材料，供后续 D5 缺口链承接。

2. S5 写入治理入口最小校验失败：
   直接丢弃本次主模型融合候选，不自动生成需求、不写入 D5 缺口、不影响 E。
```

可进入结构化缺口链的类型：

```text
轮廓输入组不闭合
深度材料缺失
彩色材料缺失
generation失配
坐标系版本失配
材料不可回查
归属不可信
候选不唯一
缺融合点
自由空间冲突过高
边界越界
子轮廓质量不足
子体素生成失败
```

缺口材料至少包含：

```text
目标存在ID
目标特征类型ID
来源输入组ID或幂等键
来源观察候选ID
来源材料句柄
阻断阶段
缺口类型
缺口严重度Q10000
建议后续方法ID或需求类型材料
可回查状态
```

建议后续方法只是缺口材料，不得由体素融合承接链直接调用观察、扫描、识别或跟踪本能方法。后续必须经需求树、任务筹办和方法选择承接。

S5 第一版候选丢弃不是需求缺口。后续若需要把反复丢弃、稳定不可融合或模型长期无法生成上升为需求治理，必须另经 D5 结构化信息缺口与需求派生承接设计补齐输入特征族和收束规则。

## 13. 与观察 / 扫描 / 识别 / 跟踪边界

```text
观察：
    产生观察材料、轮廓、局部体素、特征补充材料和缺口。
    不直接融合稳定存在体素。

识别：
    裁决观察候选 C 是否对应已有存在 E。
    归属不可信时不得触发稳定体素融合。

跟踪：
    提供连续命中、遮挡、丢失、复现离散度等持续性证据。
    体素融合可读取这些稳定性材料，但不替代跟踪。

扫描：
    判断已归属存在特征是否变化。
    自由空间冲突、主模型冲突过高时，可分流给扫描承接。

存在体素融合：
    在 E 的轮廓组证据已归属、闭合、可回查后，生成稳定体素更新候选。
    它不是观察、扫描、识别或跟踪本能方法的替代品。
```

四个本能方法和体素融合承接链不得直接互相调用。缺口必须经需求树、任务筹办和方法选择承接。

## 14. 反走样清单

禁止后续实现走偏：

```text
不得新增业务结构体来承载轮廓输入组、子轮廓、子体素或融合结果。
不得把普通一阶特征写成 bool。
不得用判断型枚举逃避复合特征收束规则。
不得在特征写入入口同步执行完整融合。
不得缺深度或缺彩色时进入完整主模型融合。
不得先融合主模型再从污染后的主模型反推输入证据子轮廓。
不得把主模型派生轮廓当作本次观察证据。
不得把子体素入链等同于稳定体素更新。
不得让场景体素服务或视觉中间层修改稳定存在体素。
不得因为场景体素先验命中就宣布存在 E 当前可见。
不得把“体素融合工作线程”写成动作来源。
不得把体素融合成功直接写成需求满足、安全满足或服务完成。
不得把同体融合默认打开；必须先关系建模、禁合并审计和多帧确认。
```

## 15. 验证剧本

### V1 正常融合链

```text
输入：E 新增同 generation 的深度轮廓图和彩色轮廓图，材料可回查，归属可信。
预期：生成输入组，提取子轮廓，生成子体素候选，子体素入链，生成主模型更新候选，经 E 体素特征主模型写入治理入口写入 E.稳定三维体素主模型；本轮不触发场景体素刷新请求。
```

### V2 只有深度无彩色

```text
输入：E 只新增深度轮廓图。
预期：进入等待配对或补观察缺口，不生成完整主模型融合候选。
```

### V3 深彩 generation 失配

```text
输入：深度轮廓和彩色轮廓来源不同 generation。
预期：输出轮廓组闭合缺口，不进入子体素生成。
```

### V4 子轮廓分解阻断污染

```text
输入：轮廓组中包含遮挡边界和低质量碎片。
预期：先生成多个输入证据子轮廓；低质量子轮廓只挂证据或输出缺口，不进入主模型融合。
```

### V5 高冲突不更新主模型

```text
输入：子体素与主模型自由空间冲突过高。
预期：S1-S4 阶段可输出候选阻断原因或冲突缺口；若进入 S5 最小校验才发现明显冲突，直接丢弃本次主模型融合候选，不更新稳定三维体素主模型。
```

### V6 第一版主模型写入

```text
输入：无旧稳定体素主模型，但主模型融合候选通过 S5 最小校验。
预期：允许写入第一版 E.稳定三维体素主模型，不因缺旧稳定版阻塞。
```

### V7 幂等去重

```text
输入：同一 E、同一轮廓组 generation 重复触发。
预期：只处理一次或复用已有处理记录，不重复挂接同一子体素。
```

### V8 场景体素刷新不纳入 P12 第一版

```text
输入：E.稳定三维体素主模型写入或更新。
预期：P12 不直接提交场景体素刷新请求，不写场景体素缓存；后续刷新由场景体素服务增强 / 先验发布计划另行承接。
```

### V9 默认不合并

```text
输入：两个相邻子轮廓只有空间相邻和颜色相近，但存在深度层分离或运动不一致。
预期：建立关系边和禁合并证据，不进入同一存在体素模型。
```

### N1 负例：直接融合整组轮廓

```text
禁止：深度 + 彩色轮廓组未经子轮廓提取直接写入主模型。
```

### N2 负例：普通 bool 字段

```text
禁止：新增 是否可融合、是否已提交、是否遮挡、是否可入链 等普通 bool 特征。
```

### N3 负例：视觉先验冒充证据

```text
禁止：用场景体素或主模型派生轮廓作为本次观察证据来源。
```

### N4 负例：线程成为动作来源

```text
禁止：把体素融合工作线程写成方法动作动态来源或需求满足来源。
```

## 16. 最小实施切片建议

```text
S0 代码事实扫描：
    查存在特征写入入口、深度 / 彩色轮廓特征现有落点、稳定三维体素特征子链、治理队列、E 体素特征主模型写入治理入口。

S1 体素融合输入组只读视图：
    读取 E、观察证据、基准体素、局部体素候选和质量材料，只输出只读摘要，不写稳定体素主模型。

S2 待处理材料和幂等闸：
    按目标 E、观察证据、基准体素版本和来源报告形成待处理材料；重复触发只累计重复命中。

S3 输入证据子轮廓和子体素候选：
    从候选结果包收束子轮廓、局部子体素、深度支撑、外边界和融合点材料，不创建子存在。

S4 主模型融合候选：
    从候选结果包和前置摘要生成稳定体素主模型更新候选摘要，不直接裸写主模型。

S5 写入治理切片：
    通过 E 体素特征主模型写入治理入口写入 E.稳定三维体素主模型；最小校验失败直接丢弃候选。

S6 验证与回归：
    完成 V1-V9 与 N1-N4。
```

## 18. 当前已知缺口

```text
1. 深度轮廓图和彩色轮廓图的现有特征类型 ID 待查。
2. 稳定三维体素主模型特征和子链的当前代码承载入口待查。
3. E 体素特征主模型写入治理入口是否已有稳定体素特征专用路径待查。
4. 体素融合内部治理承接链应复用哪个现有任务 / 队列 / worker 框架待查。
5. 轮廓输入组幂等键应采用哪些现有字段待查。
6. 子体素候选保留周期、清理策略和最大子链长度待定。
7. 主模型派生轮廓重算不纳入 P12 第一版，后续由场景体素服务增强、先验发布或视觉前处理相关计划承接。
8. 场景体素刷新事件不纳入 P12 第一版，后续由 D6 / D7 计划另行核查事件值域。
9. 代码落地契约已生成；代码实施仍必须按计划索引、实现映射计划和当前断点执行。
```
