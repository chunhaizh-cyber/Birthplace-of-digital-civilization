## 1. 核心定案

安全和服务不是两个独立对象，也不是两条硬编码任务链。

安全 / 服务是：

```text
自我这个存在上的两个根特征类型。
```

权威结构固定为：

```text
世界树.抽象特征树
    保存安全 / 服务的抽象特征定义、目标状态、阈值、成立条件和缺口映射规则。

自我存在
    保存自我_安全值 / 自我_服务值的具体特征实例和当前值。

自检
    读取抽象定义；
    读取自我实例；
    比较定义与实例；
    产出缺口报告。

缺口
    才允许生成或刷新需求。

需求未满足
    才允许任务化。
```

一句话：

```text
定义在抽象特征树，实例在自我存在，自检发现缺口，缺口生成需求，需求未满足再生成任务。
```

## 2. 世界树抽象定义

世界树抽象特征树中必须能表达根特征定义。

第一版至少包含：

```text
抽象特征：安全
    自我根特征类型 = 自我_安全值
    目标状态 / 安全区间
    最低阈值
    维持条件集
    缺口到需求的映射规则

抽象特征：服务
    自我根特征类型 = 自我_服务值
    目标状态 / 服务区间
    最低阈值
    增加条件集
    缺口到需求的映射规则
```

抽象特征定义不是需求、不是任务、不是方法。

它只回答：

```text
安全 / 服务应该是什么；
安全 / 服务需要满足哪些条件；
低于什么状态算缺口；
缺口应映射到哪类需求目标。
```

运行期不得用 C++ 固定函数表替代抽象定义，例如：

```text
取服务值增加必要条件()
取安全值维持必要条件()
```

这类固定函数不得作为安全 / 服务定义的权威来源。允许在初始化阶段显式创建默认抽象定义，但自检和需求刷新必须读取世界树中的定义节点。

## 3. 自我实例

自我存在上保存根特征实例：

```text
自我存在
├── 特征：自我_安全值
│   └── 当前值
└── 特征：自我_服务值
    └── 当前值
```

自我实例只回答：

```text
我当前是否有该特征实例；
该特征当前值是多少；
该当前值是否满足抽象定义目标状态；
定义要求的必要条件是否在当前上下文中满足。
```

安全 / 服务根特征的目标状态按“最大值”读取，不按比例高位区间读取：

```text
安全目标状态 = 自我_安全值 最大值
服务目标状态 = 自我_服务值 最大值

高位、基础稳定带、低位只用于状态分段和阈值判断，不作为根需求目标值。
```

根需求的目标宿主固定是自我存在：

```text
安全根需求：
    需求主体 = 自我
    被需求存在 = 自我
    目标特征类型 = 自我_安全值
    目标状态 = 安全抽象定义中的目标状态

服务根需求：
    需求主体 = 自我
    被需求存在 = 自我
    目标特征类型 = 自我_服务值
    目标状态 = 服务抽象定义中的目标状态
```

这不表示服务对象是自我。它只表示“服务值”是自我的账务 / 价值根特征。

## 4. 运行期读取结构

实现可以在运行期构造只读视图，例如：

```cpp
enum class 枚举_根特征类型 {
    安全,
    服务
};

enum class 枚举_根特征缺口类型 {
    无缺口,
    抽象定义缺失,
    自我特征实例缺失,
    当前值未知,
    当前值低于目标,
    必要条件未知,
    必要条件未满足,
    结果验证条件缺失,
    因果归因条件缺失
};

struct 结构_必要条件定义 {
    std::string 条件键;
    std::string 条件说明;
    std::string 检查宿主语义;
    const 词性节点类* 检查特征类型 = nullptr;
    const 状态节点类* 目标状态 = nullptr;
    std::string 缺口需求名称;
    const 词性节点类* 缺口目标特征类型 = nullptr;
    const 状态节点类* 缺口目标状态 = nullptr;
};

struct 结构_抽象根特征定义 {
    枚举_根特征类型 根特征类型{};
    基础信息节点类* 抽象定义节点 = nullptr;
    const 词性节点类* 自我特征类型 = nullptr;
    const 状态节点类* 目标状态 = nullptr;
    std::vector<结构_必要条件定义> 必要条件集;
};

struct 结构_自我根特征自检结果 {
    枚举_根特征类型 根特征类型{};
    结构_抽象根特征定义 定义{};
    特征节点类* 自我特征节点 = nullptr;
    const 特征值节点类* 当前值 = nullptr;
    bool 当前值满足目标 = false;
    std::vector<枚举_根特征缺口类型> 根缺口集;
    std::vector<结构_必要条件定义> 未满足必要条件集;
};
```

这些结构是运行期读取结果，不是必须新增的持久主信息字段。若现有抽象特征节点、子节点、状态节点、二次特征或因果链已经能表达同一语义，应优先复用已有结构。

## 5. 自检流程

根特征自检只读，不隐式创建定义或实例。

标准流程：

```text
1. 读取世界树.抽象特征树中的根特征定义。
2. 若定义缺失，产出 抽象定义缺失。
3. 从自我存在读取对应自我根特征实例。
4. 若实例缺失，产出 自我特征实例缺失。
5. 读取自我该特征当前值。
6. 若当前值缺失，产出 当前值未知。
7. 用抽象定义的目标状态 / 区间 / 比较策略检查当前值。
8. 若当前值未满足目标，产出 当前值低于目标。
9. 只有根特征有缺口时，继续检查抽象定义中的必要条件集。
10. 对每个未满足必要条件，产出必要条件缺口。
```

禁止：

```text
自检通过只读路径隐式创建抽象定义；
自检通过只读路径隐式创建自我特征实例；
自检直接创建任务；
自检缺少完整原子目标时兜底生成正式需求；
把根特征差距直接展开成同目标子需求；
用硬编码 C++ 条件表代替抽象特征树定义。
```

## 6. 缺口到需求

自检报告进入自我线程后，按缺口类型生成或刷新需求。

映射规则：

```text
抽象定义缺失：
    世界模型维护需求或报告。
    不是安全 / 服务业务根需求。

自我特征实例缺失：
    自我结构维护需求或报告。
    不是服务业务任务。

当前值未知：
    自我根特征观测需求。

当前值低于目标：
    生成或刷新对应根特征需求。

必要条件未知 / 必要条件未满足：
    按抽象定义中的缺口映射规则生成根需求下的子需求。
```

根需求活动性来自缺口，不来自初始化本身。

因此：

```text
根需求被初始化出来
    只表示需求系统骨架存在。

根特征自检发现缺口
    才表示根需求应进入活动集。
```

## 7. 第二层子需求

第二层子需求不得固定生成。

它只能来自：

```text
抽象特征定义.必要条件集
    与
当前自检事实
    的差异。
```

启动期服务定义包含：

```text
当前人类服务对象明确；
当前交互者明确；
当前权限者明确；
服务目标明确。
```

服务对象所需服务信息明确不在启动期预置为固定服务必要条件。它应由真实服务尝试中的结果、方向比较、信息缺口、沟通回执和执行阻塞汇总后生成；在汇总固化前，只能作为待归纳的候选抽象特征，不得直接当作自检已知条件。
服务对象反馈信息获取、服务结果可验证和服务结果可归因于自我动作也不在启动期预置为固定服务必要条件。它们只能在具体服务动作后，由服务对象表达、确认、生效回执、外在特征状态变化和来源动作动态汇总后生成。

自检只发现：

```text
当前人类服务对象未知；
服务目标未知。
```

则只生成：

```text
服务根需求
├── 明确当前人类服务对象
└── 明确当前服务目标
```

不得同时生成已满足条件对应的需求。

## 8. 子需求目标宿主

服务根需求的被需求存在是自我，但服务根需求下的子需求不一定作用于自我本体。

第一版分三类：

```text
事实补全型：
    例如明确当前服务对象、交互者、权限者、服务目标。
    被需求存在 = 自我当前交互上下文 / 自我世界模型。

服务对象外在特征状态改善型：
    例如让服务对象的问题状态从未解决变为已解决。
    被需求存在 = 人类服务对象 / 被授权服务对象。

安全维持型：
    例如确认运行状态、资源状态、权限边界、风险状态。
    被需求存在 = 自我 / 自我安全上下文 / 被检查资源。
```

服务对象外在特征状态改善型子需求，才是服务值结算最核心的事实证据来源。

## 9. 自检动作动态

自检线程不是动作来源。

若根特征自检需要进入因果账本，必须由明确方法表达：

```text
方法：自检自我根特征
输入：自我存在、抽象根特征定义
动作：读取自我特征实例和当前值，并比较定义
输出：自检报告 / 缺口事实
```

动作动态表达为：

```text
来源方法 = 自检自我根特征
动态主体 = 自我
动态对象 = 自我
动态特征 = 自我_安全值 / 自我_服务值
初始状态 = 待检查 / 未知
结果状态 = 当前特征状态已知 + 缺口集已知
```

该动态只说明：

```text
自检动作让缺口事实变得已知。
```

它不得直接结算为：

```text
安全值增加；
服务值增加。
```

若当前实现暂未把根特征自检注册为方法，则自检报告仍按需求信息来源处理，不得把线程本身当成动作来源。

## 10. 服务值定义边界

服务值是自我存在的根特征，但服务值来源于自我向服务对象提供服务后的价值。

因此，服务值增加的事实链应为：

```text
服务抽象定义
    -> 启动期只要求服务对象、交互者、权限者、服务目标等事实条件
        -> 自检发现必要条件缺口
            -> 生成对应服务子需求
                -> 子需求任务化
                    -> 服务对象外在特征状态改善 / 服务对象反馈信息
                        -> 来源需求满足
                            -> 叶子任务价值结算
                                -> 自我_服务值增加
```

禁止：

```text
把服务值差距本身当作服务已发生的证据；
把服务值账务变化反过来证明服务对象已改善；
缺少服务对象、服务目标或归因证据时正式结算服务值；
把服务对象建成服务根需求的目标宿主。
```

服务根需求目标宿主仍是自我；服务对象是服务必要条件和服务事实子需求中的目标宿主。

## 11. 当前实现映射

现有代码已经具备以下底座：

```text
世界树抽象特征根：
    世界树类::取或创建抽象特征根
    特征类::初始化常用抽象特征

自我根特征类型：
    自我特征定义类::类型_自我_安全值
    自我特征定义类::类型_自我_服务值

自我根特征实例读写：
    自我类::读取自我I64特征当前值
    自我类::写入自我I64特征当前值
    世界树类::读取特征快照
    世界树类::读取特征_I64

根需求目标关系：
    需求主信息类::被需求存在
    需求主信息类::被需求当前状态
    需求主信息类::需求状态
    需求主信息类::目标特征类型缓存
```

当前仍需迁移的旧口径：

```text
1. 自我类::根目标安全值 / 根目标服务值 仍是硬编码目标值来源。
2. 确保根需求_ 仍直接按硬编码目标值创建根需求目标状态。
3. 私有_刷新根需求状态镜像_线程侧 仍直接按当前值 / 根目标值刷新根需求。
4. 自检需求型候选第一版仍统一挂安全根。
5. 服务必要条件尚未从抽象特征树读取并派生服务子需求。
```

这些属于实现差距，不改变本文定案。

## 12. 最终口径

```text
安全 / 服务是自我存在的根特征类型。

抽象特征树保存安全 / 服务的定义、目标状态、成立条件和缺口映射。

自我节点保存安全 / 服务的当前特征实例和值。

自检读取两边：
    抽象定义；
    自我实例。

自检比较两边：
    定义需要什么；
    自我现在有什么。

比较结果生成缺口。

只有缺口才生成需求。

只有需求未满足才生成任务。
```
