```text
安全概念不由出生期定义为静态规则表。

    自我有安全值这个根特征；

```

一句话：

```text
遗传信息不是“安全知识”；
遗传信息是让自我能开始学习安全的初始因果信息。
```

安全信息按三层落地：

```text
安全抽象规则：
    保存为因果模板 / 抽象因果信息。

安全具体证据：
    保存为具体存在、场景、状态、动态、二次特征、因果实例和证据动态样本。

安全评估结果：
    由 安全_评估当前场景安全性 根据因果模板和具体证据临时生成；
    优先进入输出结果场景、执行回执视图或短期评估状态缓存。
```

抽象存在只作为类型模板和适用范围，不保存动态历史、安全评估结果或伤害记忆。

## 1. 核心定案

安全和服务不是两个独立对象，也不是两条硬编码任务链。

安全 / 服务是：

```text
自我这个存在上的两个根特征类型。
```

权威结构固定为：

```text
世界树.抽象特征树
    保存安全 / 服务的抽象特征定义、目标状态、阈值、成立条件和缺口映射规则。

自我存在
    保存自我_安全值 / 自我_服务值的具体特征实例和当前值。

自检
    读取抽象定义；
    读取自我实例；
    比较定义与实例；
    产出缺口报告。

缺口
    才允许生成或刷新需求。

需求未满足
    才允许任务化。
```

一句话：

```text
定义在抽象特征树，实例在自我存在，自检发现缺口，缺口生成需求，需求未满足再生成任务。
```

## 2. 世界树抽象定义

世界树抽象特征树中必须能表达根特征定义。

第一版至少包含：

```text
抽象特征：安全
    自我根特征类型 = 自我_安全值
    目标状态 / 安全区间
    最低阈值
    维持条件集
    缺口到需求的映射规则

抽象特征：服务
    自我根特征类型 = 自我_服务值
    目标状态 / 服务区间
    最低阈值
    增加条件集
    缺口到需求的映射规则
```

抽象特征定义不是需求、不是任务、不是方法。

它只回答：

```text
安全 / 服务根特征的目标状态或阈值如何表达；
安全 / 服务缺口需要哪些可验证条件或因果证据；
低于什么状态算缺口；
缺口应映射到哪类需求目标。
```

安全抽象定义不得回答：

```text
哪些人类天然安全 / 不安全；
哪些物体天然安全 / 不安全；
哪些场景天然安全 / 不安全；
哪些输入一定危险；
哪些资源状态一定导致风险。
```

这些属于后天形成的安全影响因果候选，不得写成出生期安全因素表。

运行期不得用 C++ 固定函数表替代抽象定义，例如类似以下旧式固定表入口：

```text
读取某根值的固定增加条件表()
读取某根值的固定维持条件表()
```

这类固定函数不得作为安全 / 服务定义的权威来源。允许在初始化阶段显式创建默认抽象定义，但自检和需求刷新必须读取世界树中的定义节点。

## 3. 自我实例

自我存在上保存根特征实例：

```text
自我存在
├── 特征：自我_安全值
│   └── 当前值
└── 特征：自我_服务值
    └── 当前值
```

自我实例只回答：

```text
我当前是否有该特征实例；
该特征当前值是多少；
该当前值是否满足抽象定义目标状态；
定义要求的必要条件是否在当前上下文中满足。
```

安全 / 服务根特征的目标状态按“最大值”读取，不按比例高位区间读取：

```text
安全目标状态 = 自我_安全值 最大值
服务目标状态 = 自我_服务值 最大值

高位、基础稳定带、低位只用于状态分段和阈值判断，不作为根需求目标值。
```

根需求的目标宿主固定是自我存在：

```text
安全根需求：
    需求主体 = 自我
    被需求存在 = 自我
    目标特征类型 = 自我_安全值
    目标状态 = 安全抽象定义中的目标状态

服务根需求：
    需求主体 = 自我
    被需求存在 = 自我
    目标特征类型 = 自我_服务值
    目标状态 = 服务抽象定义中的目标状态
```

这不表示服务对象是自我。它只表示“服务值”是自我的账务 / 价值根特征。

## 4. 运行期读取结构

实现可以在运行期构造只读视图，例如：

```cpp
enum class 枚举_根特征类型 {
    安全,
    服务
};

enum class 枚举_根特征缺口类型 {
    无缺口,
    抽象定义缺失,
    自我特征实例缺失,
    当前值未知,
    当前值低于目标,
    必要条件未知,
    必要条件未满足,
    结果验证条件缺失,
    因果归因条件缺失
};

struct 结构_必要条件定义 {
    std::string 条件键;
    std::string 条件说明;
    std::string 检查宿主语义;
    const 词性节点类* 检查特征类型 = nullptr;
    const 状态节点类* 目标状态 = nullptr;
    std::string 缺口需求名称;
    const 词性节点类* 缺口目标特征类型 = nullptr;
    const 状态节点类* 缺口目标状态 = nullptr;
};

struct 结构_抽象根特征定义 {
    枚举_根特征类型 根特征类型{};
    基础信息节点类* 抽象定义节点 = nullptr;
    const 词性节点类* 自我特征类型 = nullptr;
    const 状态节点类* 目标状态 = nullptr;
    std::vector<结构_必要条件定义> 必要条件集;
};

struct 结构_自我根特征自检结果 {
    枚举_根特征类型 根特征类型{};
    结构_抽象根特征定义 定义{};
    特征节点类* 自我特征节点 = nullptr;
    const 特征值节点类* 当前值 = nullptr;
    bool 当前值满足目标 = false;
    std::vector<枚举_根特征缺口类型> 根缺口集;
    std::vector<结构_必要条件定义> 未满足必要条件集;
};
```

这些结构是运行期读取结果，不是必须新增的持久主信息字段。若现有抽象特征节点、子节点、状态节点、二次特征或因果链已经能表达同一语义，应优先复用已有结构。

### 4.1 安全因果学习运行期视图与现有因果信息

安全因果学习不得新增“安全因素定义表”，也不得新增独立的 `结构_遗传因果模板` 主信息结构。所谓“遗传因果”，统一落在现有因果信息体系中：

```text
遗传因果 = 来源 / 归类口径为“遗传”的现有因果信息。

遗传信息的主体不是动作动态本身，而是带来源动态证据的因果信息组。该因果信息组只承载被动动作触发结构，表达“被动因正式出现 -> 被动果自动出现”的承上启下规则；主动动作能力从本能方法 / 方法系统取得，本能方法因果信息只能通过学习及实际使用生成。

承载结构：
    现有完整因果模板 / 抽象因果信息。

标准形态：
    条件比较集合
    + 因侧比较集合 / 因方法
    -> 果侧比较集合

来源与可追溯性：
    通过现有动态证据、来源链、二次特征或定义场景索引标记其初始来源为“遗传”。

后天更新：
    通过现有因果实例、动态证据、基础次数、归并 / 分化 / 覆盖流程完成。
```

因此旧口径中的字段按现有因果信息解释：

```text
模板ID / 名称：
    使用现有因果信息节点和名称。

来源 = 遗传：
    使用来源链 / 二次特征 / 定义场景索引表达，不新增字段。

原因特征 / 结果特征 / 因果方向：
    分别落入因侧比较集合、果侧比较集合和比较量方向。

初始置信度：
    不作为专用字段；第一版可由基础次数、动态证据数量、稳定度投影或评估方法临时计算。

可后天强化 / 削弱 / 覆盖：
    不作为专用字段；由现有因果学习、归并、分化、覆盖规则决定。

验证条件集：
    使用条件比较集合、动态证据要求、来源场景和方法条件 / 结果条件表达。
```

安全因果候选可以作为运行期结果视图保留，但它不是持久主信息结构，只保存证据指针和候选归因：

```cpp

struct 结构_安全因果候选
{
    存在节点类* 场景存在 = nullptr;
    特征类型* 被影响特征 = nullptr;

    状态节点类* 影响前状态 = nullptr;
    状态节点类* 影响后状态 = nullptr;

    时间点 出现时间;
    时间点 变化时间;

    I64 归因置信度 = 0;
    I64 风险贡献候选 = 0;

    bool 已验证 = false;
};
```

上述 `结构_安全因果候选` 只保存证据指针和候选归因，不表示存在本体自带“安全度”或“伤害可能性”。存在、场景、动态和因果实例保存原始事实；安全度、直接伤害可能性、伤害下界、当前场景安全度、当前场景最低安全度存在等，必须由 `安全_评估当前场景安全性` 读取原始事实后生成评估结果视图。

来源为“遗传”的安全因果信息第一版只能表达：

```text
当前场景可能影响自我安全值；
场景中的存在可能是影响源；
未收到负向因果证据时默认良好，但不关闭后续被动更新入口；
历史直接伤害如果发生，应沉淀为该影响源的负向因果证据；
真实负向影响需要通过观察场景存在、时间顺序、自我关键特征变化和归因证据验证；
持续存在且未造成关键特征负向变化，可降低该上下文下的风险置信；
出现后伴随可归因负向变化，可提高该上下文下的风险置信；
该因果信息可被后天证据强化、削弱、分化或覆盖。
```

## 5. 自检流程

根特征自检只读，不隐式创建定义或实例。

标准流程：

```text
1. 读取世界树.抽象特征树中的根特征定义。
2. 若定义缺失，产出 抽象定义缺失。
3. 从自我存在读取对应自我根特征实例。
4. 若实例缺失，产出 自我特征实例缺失。
5. 读取自我该特征当前值。
6. 若当前值缺失，产出 当前值未知。
7. 用抽象定义的目标状态 / 区间 / 比较策略检查当前值。
8. 若当前值未满足目标，产出 当前值低于目标。
9. 只有根特征有缺口时，继续检查抽象定义中的必要条件集。
10. 对每个未满足必要条件，产出必要条件缺口。
```

禁止：

```text
自检通过只读路径隐式创建抽象定义；
自检通过只读路径隐式创建自我特征实例；
自检直接创建任务；
自检缺少完整原子目标时兜底生成正式需求；
把根特征差距直接展开成同目标子需求；
用硬编码 C++ 条件表代替抽象特征树定义。
```

## 6. 缺口到需求

自检报告进入自我线程后，按缺口类型生成或刷新需求。

映射规则：

```text
抽象定义缺失：
    世界模型维护需求或报告。
    不是安全 / 服务业务根需求。

自我特征实例缺失：
    自我结构维护需求或报告。
    不是服务业务任务。

当前值未知：
    自我根特征观测需求。

当前值低于目标：
    生成或刷新对应根特征需求。

必要条件未知 / 必要条件未满足：
    按抽象定义中的缺口映射规则生成根需求下的子需求。
```

根需求活动性来自缺口，不来自初始化本身。

因此：

```text
根需求被初始化出来
    只表示需求系统骨架存在。

根特征自检发现缺口
    才表示根需求应进入活动集。
```

## 7. 第二层子需求

第二层子需求不得固定生成。

它只能来自：

```text
抽象特征定义.必要条件集
    与
当前自检事实
    的差异。
```

特征树可以保留以下服务上下文字段作为未来闭环信息位，但不得把它们写入服务值定义必要条件集：

```text
当前人类服务对象明确；
当前交互者明确；
当前权限者明确；
服务目标明确。
```

服务值抽象定义不得再把这些字段写入必要条件集；历史上已经生成的同类服务子需求只能由自我线程按根闭环准入结果收束或清理，不得因字段名仍存在而重激活为当前主动服务需求。无服务触发事实时，它们只能保持未触发 / 等待事实；有服务触发事实时，也必须先挂载到对应服务根闭环信息位，并确认缺失会阻断行动、验证、归因或回写，才允许通过闭环缺口准入生成服务子需求。

服务对象所需服务信息明确不得预置进服务值定义必要条件集。它应由真实服务尝试中的结果、方向比较、信息缺口、沟通回执和执行阻塞汇总后生成；在汇总固化前，只能作为待归纳的候选抽象特征，不得直接当作自检已知条件。
服务对象反馈信息获取、服务结果可验证和服务结果可归因于自我动作也不得预置进服务值定义必要条件集。它们只能在具体服务动作后，由服务对象表达、确认、生效回执、外在特征状态变化和来源动作动态汇总后生成。

有服务触发事实时，若闭环信息位判断只发现：

```text
当前人类服务对象未知；
服务目标未知。
```

则只能在闭环缺口准入通过后生成：

```text
服务根需求
├── 明确当前人类服务对象
└── 明确当前服务目标
```

不得同时生成已满足条件对应的需求。

启动期安全定义不得预置“安全因素表”，也不得把运行、资源、权限、观察或风险状态写成安全值定义的固定必要条件清单。以下字段可以作为安全事实字段、风险树节点状态、对象方法输出或提交入口结果存在，但不得因为字段名存在就直接生成当前主动安全需求：

```text
自我运行状态明确；
自我运行状态是否负向变化明确；

资源状态明确；
资源状态是否负向变化明确；

权限边界明确；
权限边界是否被影响明确；

当前场景存在集合明确；
当前场景存在对自我关键特征的影响关系未知 / 已知；
当前场景影响评估置信度达标；

安全影响因果明确；
负向影响处置需求明确。
```

当前安全需求的生成来源必须是：

```text
自我觉醒根闭环
-> 安全根目标或负向触发事实
-> 已存在或新展开的安全因果信息
-> 安全因果风险树运行期视图
-> 风险树缺口报告
-> 提交_生成缺口子需求
```

旧口径中的“自我运行状态明确 / 自我运行状态正常 / 资源状态明确 / 资源状态足够 / 权限边界明确 / 基础观察事实可用 / 风险状态明确 / 风险状态可控”等直接子需求，只能作为遗留固定安全需求被收束或清理；不得再由安全值抽象定义必要条件集重激活。若后续确有同名目标需要入树，也必须能追溯到安全因果风险树、具体负向触发事实、来源因果信息、可执行或可等待推进路径、验证方式、归因和下一轮自我状态回写。

安全到观察的需求链定案为：

```text
安全根需求未满足
-> 需要判断自我安全值为何不足或为何不能升高
-> 来源为遗传的现有因果信息：自我安全值可能受当前场景影响
-> 当前场景影响关系未知
-> 来源为遗传的现有因果信息：场景影响关系可由场景存在与自我状态变化验证
-> 当前场景存在集合未知
-> 生成需求：当前场景存在集合明确
-> 该需求未满足
-> 选择对象作用方法：安全_观察当前场景 / 安全_识别场景存在集合
-> 输出场景存在集合
-> 需要评估各存在安全度
-> 生成需求：当前场景各存在安全评估明确
-> 选择对象作用方法：安全_评估当前场景安全性
-> 输出当前场景安全度、最低安全度存在、直接伤害可能性候选和评估置信度
-> 持续跟踪自我关键特征变化
-> 形成或更新安全因果候选
-> 后天强化 / 削弱 / 覆盖对应因果信息
```

若评估结果显示场景安全度低，不得直接结算自我安全值；只能生成处置路径需求、持续观察需求或降级保护需求。场景评估安全值范围是 `0..I64_MAX`，其中 `I64_MAX` 表示当前评估下无已知负向因果压力 / 场景绝对安全，条件不足取 `I64_MAX / 4`，已证不安全取 `0`。存在风险安全值按具体存在分别评估；历史直接伤害先生成或更新负向安全因果信息，若没有可回查历史风险值，历史值必须为 `0`；因果信息是被动获取的，未收到负向因果证据时，不强求补因果链，风险压力候选为 `0`，默认按良好结果提交。场景中多个已确认存在属于同层因素，场景风险压力值取各存在风险压力候选的平均值，再转换为 `风险安全_场景影响部分 = I64_MAX - 场景风险压力值`；最低安全度存在只作为诊断 / 处置线索，不再单独决定场景安全值。风险安全层的直接因不得由 C++ 固定五因素表或固定权重表定义，必须来自来源类型为遗传或后天验证的因果信息组；场景影响、运行影响、资源影响、权限影响、未知影响只能作为可能的因果节点名称或历史兼容事实，不得因字段名存在就自动成为固定组成因。默认良好不是“已证永远安全”，只是当前没有被动获得的负向因果证据；安全影响因果不因缺省而被强行关闭或补齐。只有被动获得真实负向变化、时间顺序和归因证据后，安全评估才派生持续观察、负向影响处置或降级保护链。`安全_执行降级保护` 第一版只在负向影响处置需求已明确且安全影响因果已明确时允许执行；默认良好路径不触发该方法。场景自身安全评估结果产出后，仍必须经过持续共处时间、稳定性和归因证据，才会进一步影响自我风险安全值；是否提高或降低自我安全值，仍必须经过因果归因、价值投影和叶子任务价值结算入口。

## 8. 子需求目标宿主

服务根需求的被需求存在是自我，但服务根需求下的子需求不一定作用于自我本体。

第一版分三类：

```text
事实补全型：
    例如明确当前服务对象、交互者、权限者、服务目标。
    被需求存在 = 自我当前交互上下文 / 自我世界模型。
    该类字段只在 006 定义的服务触发事实已经挂载到服务根闭环信息位后，
    且缺失会阻断行动、验证、归因或回写时，才允许成为服务子需求；
    不得作为服务值定义必要条件自动入树。

服务对象外在特征状态改善型：
    例如让服务对象的问题状态从未解决变为已解决。
    被需求存在 = 人类服务对象 / 被授权服务对象。

安全维持型：
    例如确认运行状态、资源状态、权限边界、当前场景存在集合、安全影响因果、负向影响处置需求。
    被需求存在 = 自我 / 自我安全上下文 / 当前场景 / 场景存在 / 被检查资源。
```

服务对象外在特征状态改善型子需求，才是服务值结算最核心的事实证据来源。

## 9. 自检动作动态

自检线程不是动作来源。

若根特征自检需要进入因果账本，必须由明确方法表达：

```text
方法：自检自我根特征
输入：自我存在、抽象根特征定义
动作：读取自我特征实例和当前值，并比较定义
输出：自检报告 / 缺口事实
```

动作动态表达为：

```text
来源方法 = 自检自我根特征
动态主体 = 自我
动态对象 = 自我
动态特征 = 自我_安全值 / 自我_服务值
初始状态 = 待检查 / 未知
结果状态 = 当前特征状态已知 + 缺口集已知
```

该动态只说明：

```text
自检动作让缺口事实变得已知。
```

它不得直接结算为：

```text
安全值增加；
服务值增加。
```

若当前实现暂未把根特征自检注册为方法，则自检报告仍按需求信息来源处理，不得把线程本身当成动作来源。

## 10. 服务值定义边界

服务值是自我存在的根特征，但服务值来源于自我向服务对象提供服务后的价值。

因此，服务值增加的事实链应为：

```text
服务抽象定义
    -> 自我觉醒根闭环给出服务因果坐标
        -> 人类需求事实、服务目标事实或可验证服务触发事实被挂载
            -> 服务根闭环信息位被点亮
                -> 识别对象、目标、授权、行动、验证、归因或回写缺口
                    -> 通过闭环缺口准入后生成对应服务子需求
                        -> 子需求任务化
                            -> 服务对象外在特征状态改善 / 服务对象反馈信息
                                -> 来源需求满足
                                    -> 叶子任务价值结算
                                        -> 自我_服务值增加
```

禁止：

```text
把服务值差距本身当作服务已发生的证据；
把服务值账务变化反过来证明服务对象已改善；
缺少服务对象、服务目标或归因证据时正式结算服务值；
无服务触发事实时把当前交互者、权限者、服务对象或服务目标固定入树；
把服务对象建成服务根需求的目标宿主。
```

服务根需求目标宿主仍是自我；服务对象只在服务触发事实点亮后的服务因果链上下文子需求和服务事实子需求中作为目标宿主。

## 12. 最终口径

```text
安全 / 服务是自我存在的根特征类型。

抽象特征树保存安全 / 服务的定义、目标状态、成立条件和缺口映射。

自我节点保存安全 / 服务的当前特征实例和值。

自检读取两边：
    抽象定义；
    自我实例。

自检比较两边：
    定义需要什么；
    自我现在有什么。

比较结果生成缺口。

只有缺口才生成需求。

只有需求未满足才生成任务。

安全概念 = 自我基于因果证据逐步形成的预测模型。
安全因素 = 自我在运行中发现的、会影响自我安全值的存在 / 状态 / 动作 / 时间关系。
遗传信息 = 带来源动态证据或出生期初始假设标记的因果信息组；其中只承载被动动作触发结构。主动动作能力结构从本能方法 / 方法系统取得，本能方法因果信息只能通过学习及实际使用生成。后天证据可以强化、削弱、分化或覆盖遗传被动触发因果信息。
```
