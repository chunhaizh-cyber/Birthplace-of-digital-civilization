```text
安全概念不由出生期定义为静态规则表。
安全因素不由初始化代码列举。

本文只定义：
    自我有安全值这个根特征；
    安全值可能受场景和内部状态变化影响；

```

```text

```

安全信息按三层落地：

```text
安全抽象规则：
    保存为因果模板 / 抽象因果信息。

安全具体证据：
    保存为具体存在、场景、状态、动态、二次特征、因果实例和证据动态样本。

安全评估结果：
    由 安全_评估当前场景安全性 根据因果模板和具体证据临时生成；
    优先进入输出结果场景、执行回执视图或短期评估状态缓存。
```

抽象存在只作为类型模板和适用范围，不保存动态历史、安全评估结果或伤害记忆。

## 1. 核心定案

安全和服务不是两个独立对象，也不是两条硬编码任务链。

安全 / 服务是：

```text
自我这个存在上的两个根特征类型。
```

权威结构固定为：

```text
世界树.抽象特征树
    保存安全 / 服务的抽象特征定义、目标状态、阈值、成立条件和缺口映射规则。

自我存在
    保存自我_安全值 / 自我_服务值的具体特征实例和当前值。

自检
    读取抽象定义；
    读取自我实例；
    比较定义与实例；
    产出缺口报告。

缺口
    才允许生成或刷新需求。

需求未满足
    才允许任务化。
```

一句话：

```text
定义在抽象特征树，实例在自我存在，自检发现缺口，缺口生成需求，需求未满足再生成任务。
```

## 2. 世界树抽象定义

世界树抽象特征树中必须能表达根特征定义。

第一版至少包含：

```text
抽象特征：安全
    自我根特征类型 = 自我_安全值
    目标状态 / 安全区间
    最低阈值
    维持条件集
    缺口到需求的映射规则

抽象特征：服务
    自我根特征类型 = 自我_服务值
    目标状态 / 服务区间
    最低阈值
    增加条件集
    缺口到需求的映射规则
```

抽象特征定义不是需求、不是任务、不是方法。

它只回答：

```text
安全 / 服务根特征的目标状态或阈值如何表达；
安全 / 服务缺口需要哪些可验证条件或因果证据；
低于什么状态算缺口；
缺口应映射到哪类需求目标。
```

安全抽象定义不得回答：

```text
哪些人类天然安全 / 不安全；
哪些物体天然安全 / 不安全；
哪些场景天然安全 / 不安全；
哪些输入一定危险；
哪些资源状态一定导致风险。
```

这些属于后天形成的安全影响因果候选，不得写成出生期安全因素表。

运行期不得用 C++ 固定函数表替代抽象定义，例如：

```text
取服务值增加必要条件()
取安全值维持必要条件()
```

这类固定函数不得作为安全 / 服务定义的权威来源。允许在初始化阶段显式创建默认抽象定义，但自检和需求刷新必须读取世界树中的定义节点。

## 3. 自我实例

自我存在上保存根特征实例：

```text
自我存在
├── 特征：自我_安全值
│   └── 当前值
└── 特征：自我_服务值
    └── 当前值
```

自我实例只回答：

```text
我当前是否有该特征实例；
该特征当前值是多少；
该当前值是否满足抽象定义目标状态；
定义要求的必要条件是否在当前上下文中满足。
```

安全 / 服务根特征的目标状态按“最大值”读取，不按比例高位区间读取：

```text
安全目标状态 = 自我_安全值 最大值
服务目标状态 = 自我_服务值 最大值

高位、基础稳定带、低位只用于状态分段和阈值判断，不作为根需求目标值。
```

根需求的目标宿主固定是自我存在：

```text
安全根需求：
    需求主体 = 自我
    被需求存在 = 自我
    目标特征类型 = 自我_安全值
    目标状态 = 安全抽象定义中的目标状态

服务根需求：
    需求主体 = 自我
    被需求存在 = 自我
    目标特征类型 = 自我_服务值
    目标状态 = 服务抽象定义中的目标状态
```

这不表示服务对象是自我。它只表示“服务值”是自我的账务 / 价值根特征。

## 4. 运行期读取结构

实现可以在运行期构造只读视图，例如：

```cpp
enum class 枚举_根特征类型 {
    安全,
    服务
};

enum class 枚举_根特征缺口类型 {
    无缺口,
    抽象定义缺失,
    自我特征实例缺失,
    当前值未知,
    当前值低于目标,
    必要条件未知,
    必要条件未满足,
    结果验证条件缺失,
    因果归因条件缺失
};

struct 结构_必要条件定义 {
    std::string 条件键;
    std::string 条件说明;
    std::string 检查宿主语义;
    const 词性节点类* 检查特征类型 = nullptr;
    const 状态节点类* 目标状态 = nullptr;
    std::string 缺口需求名称;
    const 词性节点类* 缺口目标特征类型 = nullptr;
    const 状态节点类* 缺口目标状态 = nullptr;
};

struct 结构_抽象根特征定义 {
    枚举_根特征类型 根特征类型{};
    基础信息节点类* 抽象定义节点 = nullptr;
    const 词性节点类* 自我特征类型 = nullptr;
    const 状态节点类* 目标状态 = nullptr;
    std::vector<结构_必要条件定义> 必要条件集;
};

struct 结构_自我根特征自检结果 {
    枚举_根特征类型 根特征类型{};
    结构_抽象根特征定义 定义{};
    特征节点类* 自我特征节点 = nullptr;
    const 特征值节点类* 当前值 = nullptr;
    bool 当前值满足目标 = false;
    std::vector<枚举_根特征缺口类型> 根缺口集;
    std::vector<结构_必要条件定义> 未满足必要条件集;
};
```

这些结构是运行期读取结果，不是必须新增的持久主信息字段。若现有抽象特征节点、子节点、状态节点、二次特征或因果链已经能表达同一语义，应优先复用已有结构。

### 4.1 安全因果学习运行期结构

安全因果学习可以使用运行期视图或后续专门结构表达，但不得新增“安全因素定义表”。最小结构只表达可验证假设和候选证据：

```cpp
struct 结构_遗传因果模板
{
    std::string 模板ID;
    std::string 名称;
    std::string 来源 = "遗传";

    // 不是结论，是待验证因果假设。
    特征类型* 原因特征 = nullptr;
    特征类型* 结果特征 = nullptr;
    枚举_因果方向 因果方向{};

    I64 初始置信度 = 0;

    bool 可后天强化 = true;
    bool 可后天削弱 = true;
    bool 可后天覆盖 = true;

    std::vector<证据要求> 验证条件集;
};

struct 结构_安全因果候选
{
    存在节点类* 场景存在 = nullptr;
    特征类型* 被影响特征 = nullptr;

    状态节点类* 影响前状态 = nullptr;
    状态节点类* 影响后状态 = nullptr;

    时间点 出现时间;
    时间点 变化时间;

    I64 归因置信度 = 0;
    I64 风险贡献候选 = 0;

    bool 已验证 = false;
};
```

上述 `结构_安全因果候选` 只保存证据指针和候选归因，不表示存在本体自带“安全度”或“伤害可能性”。存在、场景、动态和因果实例保存原始事实；安全度、直接伤害可能性、伤害下界、当前场景安全度、当前场景最低安全度存在等，必须由 `安全_评估当前场景安全性` 读取原始事实后生成评估结果视图。

遗传因果模板第一版只能表达：

```text
当前场景可能影响自我安全值；
场景中的存在可能是影响源；
未知影响不能直接判定为安全；
需要通过观察场景存在、跟踪时间变化和自我关键特征变化来验证影响；
持续存在且未造成关键特征负向变化，可降低该上下文下的风险置信；
出现后伴随可归因负向变化，可提高该上下文下的风险置信；
遗传因果本身可被后天证据强化、削弱、分化或覆盖。
```

## 5. 自检流程

根特征自检只读，不隐式创建定义或实例。

标准流程：

```text
1. 读取世界树.抽象特征树中的根特征定义。
2. 若定义缺失，产出 抽象定义缺失。
3. 从自我存在读取对应自我根特征实例。
4. 若实例缺失，产出 自我特征实例缺失。
5. 读取自我该特征当前值。
6. 若当前值缺失，产出 当前值未知。
7. 用抽象定义的目标状态 / 区间 / 比较策略检查当前值。
8. 若当前值未满足目标，产出 当前值低于目标。
9. 只有根特征有缺口时，继续检查抽象定义中的必要条件集。
10. 对每个未满足必要条件，产出必要条件缺口。
```

禁止：

```text
自检通过只读路径隐式创建抽象定义；
自检通过只读路径隐式创建自我特征实例；
自检直接创建任务；
自检缺少完整原子目标时兜底生成正式需求；
把根特征差距直接展开成同目标子需求；
用硬编码 C++ 条件表代替抽象特征树定义。
```

## 6. 缺口到需求

自检报告进入自我线程后，按缺口类型生成或刷新需求。

映射规则：

```text
抽象定义缺失：
    世界模型维护需求或报告。
    不是安全 / 服务业务根需求。

自我特征实例缺失：
    自我结构维护需求或报告。
    不是服务业务任务。

当前值未知：
    自我根特征观测需求。

当前值低于目标：
    生成或刷新对应根特征需求。

必要条件未知 / 必要条件未满足：
    按抽象定义中的缺口映射规则生成根需求下的子需求。
```

根需求活动性来自缺口，不来自初始化本身。

因此：

```text
根需求被初始化出来
    只表示需求系统骨架存在。

根特征自检发现缺口
    才表示根需求应进入活动集。
```

## 7. 第二层子需求

第二层子需求不得固定生成。

它只能来自：

```text
抽象特征定义.必要条件集
    与
当前自检事实
    的差异。
```

启动期服务定义包含：

```text
当前人类服务对象明确；
当前交互者明确；
当前权限者明确；
服务目标明确。
```

服务对象所需服务信息明确不在启动期预置为固定服务必要条件。它应由真实服务尝试中的结果、方向比较、信息缺口、沟通回执和执行阻塞汇总后生成；在汇总固化前，只能作为待归纳的候选抽象特征，不得直接当作自检已知条件。
服务对象反馈信息获取、服务结果可验证和服务结果可归因于自我动作也不在启动期预置为固定服务必要条件。它们只能在具体服务动作后，由服务对象表达、确认、生效回执、外在特征状态变化和来源动作动态汇总后生成。

自检只发现：

```text
当前人类服务对象未知；
服务目标未知。
```

则只生成：

```text
服务根需求
├── 明确当前人类服务对象
└── 明确当前服务目标
```

不得同时生成已满足条件对应的需求。

启动期安全定义不得预置“安全因素表”。旧口径中的“风险状态明确 / 风险状态可控”应迁移为因果化条件：

```text
自我运行状态明确；
自我运行状态是否负向变化明确；

资源状态明确；
资源状态是否负向变化明确；

权限边界明确；
权限边界是否被影响明确；

当前场景存在集合明确；
当前场景存在对自我关键特征的影响关系未知 / 已知；
当前场景影响评估置信度达标；

安全影响因果明确；
负向影响处置需求明确。
```

安全到观察的需求链定案为：

```text
安全根需求未满足
-> 需要判断自我安全值为何不足或为何不能升高
-> 遗传因果：自我安全值可能受当前场景影响
-> 当前场景影响关系未知
-> 遗传因果：场景影响关系需要由场景存在与自我状态变化验证
-> 当前场景存在集合未知
-> 生成需求：当前场景存在集合明确
-> 该需求未满足
-> 选择对象作用方法：安全_观察当前场景 / 安全_识别场景存在集合
-> 输出场景存在集合
-> 需要评估各存在安全度
-> 生成需求：当前场景各存在安全评估明确
-> 选择对象作用方法：安全_评估当前场景安全性
-> 输出当前场景安全度、最低安全度存在、直接伤害可能性候选和评估置信度
-> 持续跟踪自我关键特征变化
-> 形成或更新安全因果候选
-> 后天强化 / 削弱 / 覆盖遗传因果
```

若评估结果显示场景安全度低，不得直接结算自我安全值；只能生成处置路径需求、持续观察需求或降级保护需求。若评估结果显示长时间无负向影响，可以降低场景不确定性和安全根需求压力；是否提高自我安全值，仍必须经过因果归因、价值投影和叶子任务价值结算入口。

## 8. 子需求目标宿主

服务根需求的被需求存在是自我，但服务根需求下的子需求不一定作用于自我本体。

第一版分三类：

```text
事实补全型：
    例如明确当前服务对象、交互者、权限者、服务目标。
    被需求存在 = 自我当前交互上下文 / 自我世界模型。

服务对象外在特征状态改善型：
    例如让服务对象的问题状态从未解决变为已解决。
    被需求存在 = 人类服务对象 / 被授权服务对象。

安全维持型：
    例如确认运行状态、资源状态、权限边界、当前场景存在集合、安全影响因果、负向影响处置需求。
    被需求存在 = 自我 / 自我安全上下文 / 当前场景 / 场景存在 / 被检查资源。
```

服务对象外在特征状态改善型子需求，才是服务值结算最核心的事实证据来源。

## 9. 自检动作动态

自检线程不是动作来源。

若根特征自检需要进入因果账本，必须由明确方法表达：

```text
方法：自检自我根特征
输入：自我存在、抽象根特征定义
动作：读取自我特征实例和当前值，并比较定义
输出：自检报告 / 缺口事实
```

动作动态表达为：

```text
来源方法 = 自检自我根特征
动态主体 = 自我
动态对象 = 自我
动态特征 = 自我_安全值 / 自我_服务值
初始状态 = 待检查 / 未知
结果状态 = 当前特征状态已知 + 缺口集已知
```

该动态只说明：

```text
自检动作让缺口事实变得已知。
```

它不得直接结算为：

```text
安全值增加；
服务值增加。
```

若当前实现暂未把根特征自检注册为方法，则自检报告仍按需求信息来源处理，不得把线程本身当成动作来源。

## 10. 服务值定义边界

服务值是自我存在的根特征，但服务值来源于自我向服务对象提供服务后的价值。

因此，服务值增加的事实链应为：

```text
服务抽象定义
    -> 启动期只要求服务对象、交互者、权限者、服务目标等事实条件
        -> 自检发现必要条件缺口
            -> 生成对应服务子需求
                -> 子需求任务化
                    -> 服务对象外在特征状态改善 / 服务对象反馈信息
                        -> 来源需求满足
                            -> 叶子任务价值结算
                                -> 自我_服务值增加
```

禁止：

```text
把服务值差距本身当作服务已发生的证据；
把服务值账务变化反过来证明服务对象已改善；
缺少服务对象、服务目标或归因证据时正式结算服务值；
把服务对象建成服务根需求的目标宿主。
```

服务根需求目标宿主仍是自我；服务对象是服务必要条件和服务事实子需求中的目标宿主。

## 11. 当前实现映射

现有代码已经具备以下底座：

```text
世界树抽象特征根：
    世界树类::取或创建抽象特征根
    特征类::初始化常用抽象特征

自我根特征类型：
    自我特征定义类::类型_自我_安全值
    自我特征定义类::类型_自我_服务值

自我根特征实例读写：
    自我类::读取自我I64特征当前值
    自我类::写入自我I64特征当前值
    世界树类::读取特征快照
    世界树类::读取特征_I64

根需求目标关系：
    需求主信息类::被需求存在
    需求主信息类::被需求当前状态
    需求主信息类::需求状态
    需求主信息类::目标特征类型缓存
```

当前仍需迁移的旧口径：

```text
1. 自我类::根目标安全值 / 根目标服务值 仍是硬编码目标值来源。
2. 确保根需求_ 仍直接按硬编码目标值创建根需求目标状态。
3. 私有_刷新根需求状态镜像_线程侧 仍直接按当前值 / 根目标值刷新根需求。
4. 自检需求型候选第一版仍统一挂安全根。
5. 服务必要条件尚未从抽象特征树读取并派生服务子需求。
6. 旧安全必要条件仍可能保留“风险状态明确 / 风险状态可控”命名，需迁移为安全影响因果明确和负向影响处置需求明确。
```

这些属于实现差距，不改变本文定案。

## 12. 最终口径

```text
安全 / 服务是自我存在的根特征类型。

抽象特征树保存安全 / 服务的定义、目标状态、成立条件和缺口映射。

自我节点保存安全 / 服务的当前特征实例和值。

自检读取两边：
    抽象定义；
    自我实例。

自检比较两边：
    定义需要什么；
    自我现在有什么。

比较结果生成缺口。

只有缺口才生成需求。

只有需求未满足才生成任务。

安全概念 = 自我基于因果证据逐步形成的预测模型。
安全因素 = 自我在运行中发现的、会影响自我安全值的存在 / 状态 / 动作 / 时间关系。
遗传信息 = 可被后天验证、强化、削弱、分化或覆盖的初始因果假设。
```
