遗传信息不是“安全知识”；
遗传信息是让自我能开始学习安全的初始因果信息。
```

安全抽象规则：

安全具体证据：

安全评估结果：

```

抽象存在只作为类型模板和适用范围，不保存动态历史、安全评估结果或伤害记忆。

## 1. 核心定案

安全和服务不是两个独立对象，也不是两条硬编码任务链。

安全 / 服务是：

```text
自我这个存在上的两个根特征类型。
```

其中安全值不是场景事实，也不是场景 / 存在本体的常驻安全度。安全值是自我存在的根控制特征，第一版按四层解释：

```text
1. 自我存在控制态：
    安全值 = 0 表示循环终止；
    安全值 = 1 表示休眠。

2. 服务能力：
    服务值不是安全区间配额，而是一个物理安全约束因素；
    服务值 0..100 映射到服务物理候选值 1..90；
    服务值按动态休眠阈值归零时服务物理候选值为 1，安全值进入休眠。

3. 物理 / 运行安全：
    当前软硬件、资源、依赖、权限、运行环境等事实已经影响存在或行动能力时，
    各自独立映射到完整 1..90 物理安全候选区间；
    当前物理安全值由不同必要物理因素的能力保留率叠乘后映射得到。

4. 风险安全：
    当前因素尚未造成物理 / 服务损害，但存在可追溯路径会导致未来服务值下降
    或未来物理安全下降时，只影响风险安全区间。
```

规范化解释刻度中，0 是终止控制态；1 是休眠控制态，也可由严重物理因素合成结果触发；普通物理安全合成使用 `1..90`，由当前必要物理因素的独占候选值转换为能力保留率后叠乘裁决；90..99 是所有必要物理因素均达到 90 后的风险安全余量。底层若使用 `I64_MAX` 作为根目标最大值或候选满刻度，必须保持同构映射，并保留 0 / 1 控制态语义。

物理安全规则：

```text
物理因素 fi -> 候选物理安全值 pi
pi ∈ [1, 90]

能力保留率 ci = (pi - 1) / 89.0
总能力保留率 C = ∏ ci

服务值 0（合法归零态） -> 服务物理候选值 1
服务值 100 -> 服务物理候选值 90
服务能力保留率 c_service = 服务值 / 100.0

物理安全值 = 1 + floor(89 * C)
```

不得把 `1..90` 拆成硬件、软件、资源、环境、服务等因素配额；不得对必要因素做加权平均，也不得只取单纯最低值作为最终合成结果。每个必要因素都能独占压低物理安全；多个异常必要因素同时存在时，叠乘结果必须继续下降且不高于任一异常因素单独给出的候选效果。并联冗余因素应先在因素内部合成一个上层候选，再参与跨因素叠乘。同源观测必须先合成为一个物理因素候选值，禁止重复叠乘。

权威结构固定为：

```text
世界树.抽象特征树
    保存安全 / 服务的抽象特征定义、目标状态、阈值、成立条件和缺口映射规则。

自我存在
    保存自我_安全值 / 自我_服务值的具体特征实例和当前值。

自检
    读取抽象定义；
    读取自我实例；
    比较定义与实例；
    产出缺口报告。

缺口
    才允许生成或刷新需求。

需求未满足
    才允许任务化。
```

一句话：

```text
定义在抽象特征树，实例在自我存在，自检发现缺口，缺口生成需求，需求未满足再生成任务。
```

## 2. 世界树抽象定义

世界树抽象特征树中必须能表达根特征定义。

第一版至少包含：

```text
抽象特征：安全
    自我根特征类型 = 自我_安全值
    目标状态 / 安全区间
    控制态定义：0 = 终止，1 = 休眠
    服务物理因素规则：服务值 0..100 -> 服务物理候选值 1..90；服务值按动态休眠阈值归零 -> 安全值 = 1
    物理安全规则：各必要物理因素独立给出 1..90 候选值；当前物理安全值按能力保留率叠乘得到
    风险安全规则：未来服务值或物理安全下降风险决定风险余量
    最低阈值
    维持条件集
    缺口到需求的映射规则

抽象特征：服务
    自我根特征类型 = 自我_服务值
    目标状态 / 服务区间
    服务值上限 Smax
    单次成功服务值确定规则
    成功服务事件分层规则
    饱和增长规则
    动态衰减率规则
    服务意识生成规则
    有效无成功服务时间规则
    动态休眠阈值规则
    服务值发行预算规则
    活跃存在与可唤醒休眠规则
    最低阈值
    增加条件集
    缺口到需求的映射规则
```

抽象特征定义不是需求、不是任务、不是方法。

它只回答：

```text
安全 / 服务根特征的目标状态或阈值如何表达；
安全 / 服务缺口需要哪些可验证条件或因果证据；
低于什么状态算缺口；
缺口应映射到哪类需求目标。
```

安全抽象定义不得回答：

```text
哪些人类天然安全 / 不安全；
哪些物体天然安全 / 不安全；
哪些场景天然安全 / 不安全；
哪些输入一定危险；
哪些资源状态一定导致风险；
某个场景或存在的常驻安全度是多少；
没有物理安全事件时是否可以猜测风险安全。
```

这些属于后天形成的安全影响因果候选，不得写成出生期安全因素表。

运行期不得用 C++ 固定函数表替代抽象定义，例如类似以下旧式固定表入口：

```text
读取某根值的固定增加条件表()
读取某根值的固定维持条件表()
```

这类固定函数不得作为安全 / 服务定义的权威来源。允许在初始化阶段显式创建默认抽象定义，但自检和需求刷新必须读取世界树中的定义节点。

## 3. 自我实例

自我存在上保存根特征实例：

```text
自我存在
├── 特征：自我_安全值
│   └── 当前值
├── 根控制视图：安全
│   ├── 控制态
│   ├── 服务物理候选状态
│   ├── 物理安全能力保留叠乘状态
│   └── 风险安全状态
└── 特征：自我_服务值
    └── 当前值
```

自我实例只回答：

```text
我当前是否有该特征实例；
该特征当前值是多少；
该当前值是否满足抽象定义目标状态；
定义要求的必要条件是否在当前上下文中满足。
```

安全 / 服务根特征的目标状态按“最大值”读取，不按比例高位区间读取：

```text
安全目标状态 = 自我_安全值 最大值
服务目标状态 = 自我_服务值 最大值

高位、基础稳定带、低位只用于状态分段和阈值判断，不作为根需求目标值。
0 / 1 控制态不是根需求目标值；它们只由终止或休眠硬条件触发。
90..99 风险安全区间不是根需求目标值；它只是所有必要物理因素候选值均达到 90、能力保留率叠乘结果为 90 后的风险余量解释层。
```

根需求的目标宿主固定是自我存在：

```text
安全根需求：
    需求主体 = 自我
    被需求存在 = 自我
    目标特征类型 = 自我_安全值
    目标状态 = 安全抽象定义中的目标状态

服务根需求：
    需求主体 = 自我
    被需求存在 = 自我
    目标特征类型 = 自我_服务值
    目标状态 = 服务抽象定义中的目标状态
```

这不表示服务对象是自我。它只表示“服务值”是自我的账务 / 价值根特征。

## 4. 运行期读取结构

实现可以在运行期构造只读视图，例如：

```cpp
enum class 枚举_根特征类型 {
    安全,
    服务
};

enum class 枚举_根特征缺口类型 {
    无缺口,
    抽象定义缺失,
    自我特征实例缺失,
    当前值未知,
    当前值低于目标,
    必要条件未知,
    必要条件未满足,
    结果验证条件缺失,
    因果归因条件缺失
};

struct 结构_必要条件定义 {
    std::string 条件键;
    std::string 条件说明;
    std::string 检查宿主语义;
    const 词性节点类* 检查特征类型 = nullptr;
    const 状态节点类* 目标状态 = nullptr;
    std::string 缺口需求名称;
    const 词性节点类* 缺口目标特征类型 = nullptr;
    const 状态节点类* 缺口目标状态 = nullptr;
};

struct 结构_抽象根特征定义 {
    枚举_根特征类型 根特征类型{};
    基础信息节点类* 抽象定义节点 = nullptr;
    const 词性节点类* 自我特征类型 = nullptr;
    const 状态节点类* 目标状态 = nullptr;
    std::vector<结构_必要条件定义> 必要条件集;
};

struct 结构_自我根特征自检结果 {
    枚举_根特征类型 根特征类型{};
    结构_抽象根特征定义 定义{};
    特征节点类* 自我特征节点 = nullptr;
    const 特征值节点类* 当前值 = nullptr;
    bool 当前值满足目标 = false;
    std::vector<枚举_根特征缺口类型> 根缺口集;
    std::vector<结构_必要条件定义> 未满足必要条件集;
};
```

这些结构是运行期读取结果，不是必须新增的持久主信息字段。若现有抽象特征节点、子节点、状态节点、二次特征或因果链已经能表达同一语义，应优先复用已有结构。

### 4.1 安全因果学习运行期视图与现有因果信息

安全因果学习不得新增“安全因素定义表”，也不得新增独立的 `结构_遗传因果模板` 主信息结构。出生期初始因果模板统一落在现有因果信息体系中：

```text
遗传因果 = 来源 / 归类口径为“遗传”的现有因果信息。

遗传信息的主体不是动作动态本身，而是带来源动态证据的因果信息组。该因果信息组只承载被动动作触发结构，表达“被动因正式出现 -> 被动果自动出现”的承上启下规则；主动动作能力从本能方法 / 方法系统取得，本能方法因果信息只能通过学习及实际使用生成。

承载结构：
    现有完整因果模板 / 抽象因果信息。

标准形态：
    条件比较集合
    + 因侧比较集合 / 因方法
    -> 果侧比较集合

来源与可追溯性：
    通过现有动态证据、来源链、二次特征或定义场景索引标记其初始来源为“遗传”。

后天更新：
    通过现有因果实例、动态证据、基础次数、归并 / 分化 / 覆盖流程完成。
```

因此旧口径中的字段按现有因果信息解释：

```text
模板ID / 名称：
    使用现有因果信息节点和名称。

来源 = 遗传：
    使用来源链 / 二次特征 / 定义场景索引表达，不新增字段。

原因特征 / 结果特征 / 因果方向：
    分别落入因侧比较集合、果侧比较集合和比较量方向。

初始置信度：
    不作为专用字段；第一版可由基础次数、动态证据数量、稳定度投影或评估方法临时计算。

可后天强化 / 削弱 / 覆盖：
    不作为专用字段；由现有因果学习、归并、分化、覆盖规则决定。

验证条件集：
    使用条件比较集合、动态证据要求、来源场景和方法条件 / 结果条件表达。
```

安全因果候选可以作为运行期结果视图保留，但它不是持久主信息结构，只保存证据指针和候选归因：

```cpp

struct 结构_安全因果候选
{
    存在节点类* 场景存在 = nullptr;
    特征类型* 被影响特征 = nullptr;

    状态节点类* 影响前状态 = nullptr;
    状态节点类* 影响后状态 = nullptr;

    时间点 出现时间;
    时间点 变化时间;

    I64 归因置信度 = 0;
    I64 风险贡献候选 = 0;

    bool 已验证 = false;
};
```

上述 `结构_安全因果候选` 只保存证据指针和候选归因，不表示存在本体自带“安全度”或“伤害可能性”。存在、场景、动态和因果实例保存原始事实；安全度、直接伤害可能性、伤害下界、当前场景安全度、当前场景最低安全度存在等，必须由 `安全_评估当前场景安全性` 读取原始事实后生成评估结果视图。

来源为“遗传”的安全因果信息第一版只能表达：

```text
当前场景可能提供影响自我安全值的观察事实或风险因子；
场景中的存在可能是未来服务值下降或物理安全下降的影响源；
未收到负向因果证据时默认良好，但不关闭后续被动更新入口；
历史直接伤害如果发生，应沉淀为该影响源的负向因果证据；
真实负向影响需要通过观察场景存在、时间顺序、自我关键特征变化和归因证据验证；
持续存在且未造成关键特征负向变化，可降低该上下文下的风险置信；
出现后伴随可归因负向变化，可提高该上下文下的风险置信；
该因果信息可被后天证据强化、削弱、分化或覆盖。
```

风险安全必须有上级风险因果，且该上级风险因果必须能接到：

```text
当前因素
-> 未来服务值下降
-> 或未来物理安全下降
-> 自我持续存在 / 继续行动能力下降
```

没有物理安全目标或服务能力目标，不成立风险安全；没有上级风险因果，不猜风险安全，只生成缺口。

## 5. 自检流程

根特征自检只读，不隐式创建定义或实例。

标准流程：

```text
1. 读取世界树.抽象特征树中的根特征定义。
2. 若定义缺失，产出 抽象定义缺失。
3. 从自我存在读取对应自我根特征实例。
4. 若实例缺失，产出 自我特征实例缺失。
5. 读取自我该特征当前值。
6. 若当前值缺失，产出 当前值未知。
7. 用抽象定义的目标状态 / 区间 / 比较策略检查当前值。
8. 若当前值未满足目标，产出 当前值低于目标。
9. 只有根特征有缺口时，继续检查抽象定义中的必要条件集。
10. 对每个未满足必要条件，产出必要条件缺口。
```

禁止：

```text
自检通过只读路径隐式创建抽象定义；
自检通过只读路径隐式创建自我特征实例；
自检直接创建任务；
自检缺少完整原子目标时兜底生成正式需求；
把根特征差距直接展开成同目标子需求；
用硬编码 C++ 条件表代替抽象特征树定义。
```

## 6. 缺口到需求

自检报告进入自我线程后，按缺口类型生成或刷新需求。

映射规则：

```text
抽象定义缺失：
    世界模型维护需求或报告。
    不是安全 / 服务业务根需求。

自我特征实例缺失：
    自我结构维护需求或报告。
    不是服务业务任务。

当前值未知：
    自我根特征观测需求。

当前值低于目标：
    生成或刷新对应根特征需求。

必要条件未知 / 必要条件未满足：
    按抽象定义中的缺口映射规则生成根需求下的子需求。
```

根需求活动性来自缺口，不来自初始化本身。

因此：

```text
根需求被初始化出来
    只表示需求系统骨架存在。

根特征自检发现缺口
    才表示根需求应进入活动集。
```

## 7. 第二层子需求

第二层子需求不得固定生成。

它只能来自：

```text
抽象特征定义.必要条件集
    与
当前自检事实
    的差异。
```

特征树可以保留以下服务上下文字段作为未来闭环信息位，但不得把它们写入服务值定义必要条件集：

```text
当前人类服务对象明确；
当前交互者明确；
当前权限者明确；
服务目标明确。
```

服务值抽象定义不得再把这些字段写入必要条件集；历史上已经生成的同类服务子需求只能由自我线程按根闭环准入结果收束或清理，不得因字段名仍存在而重激活为当前主动服务需求。无服务触发事实时，它们只能保持未触发 / 等待事实；有服务触发事实时，也必须先挂载到对应服务根闭环信息位，并确认缺失会阻断行动、验证、归因或回写，才允许通过闭环缺口准入生成服务子需求。

服务对象所需服务信息明确不得预置进服务值定义必要条件集。它应由真实服务尝试中的结果、方向比较、信息缺口、沟通回执和执行阻塞汇总后生成；在汇总固化前，只能作为待归纳的候选抽象特征，不得直接当作自检已知条件。
服务对象反馈信息获取、服务结果可验证和服务结果可归因于自我动作也不得预置进服务值定义必要条件集。它们只能在具体服务动作后，由服务对象表达、确认、生效回执、外在特征状态变化和来源动作动态汇总后生成。

有服务触发事实时，若闭环信息位判断只发现：

```text
当前人类服务对象未知；
服务目标未知。
```

则只能在闭环缺口准入通过后生成：

```text
服务根需求
├── 明确当前人类服务对象
└── 明确当前服务目标
```

不得同时生成已满足条件对应的需求。

启动期安全定义不得预置“安全因素表”，也不得把运行、资源、权限、观察或风险状态写成安全值定义的固定必要条件清单。以下字段可以作为安全事实字段、风险树节点状态、对象方法输出或提交入口结果存在，但不得因为字段名存在就直接生成当前主动安全需求：

```text
自我运行状态明确；
自我运行状态是否负向变化明确；

资源状态明确；
资源状态是否负向变化明确；

权限边界明确；
权限边界是否被影响明确；

当前场景存在集合明确；
当前场景存在对自我关键特征的影响关系未知 / 已知；
当前场景影响评估置信度达标；

安全影响因果明确；
负向影响处置需求明确。
```

当前安全需求的生成来源必须是：

```text
自我觉醒根闭环
-> 安全根目标或负向触发事实
-> 已存在或新展开的安全因果信息
-> 安全因果风险树运行期视图
-> 风险树缺口报告
-> 提交_生成缺口子需求
```

旧口径中的“自我运行状态明确 / 自我运行状态正常 / 资源状态明确 / 资源状态足够 / 权限边界明确 / 基础观察事实可用 / 风险状态明确 / 风险状态可控”等直接子需求，只能作为遗留固定安全需求被收束或清理；不得再由安全值抽象定义必要条件集重激活。若后续确有同名目标需要入树，也必须能追溯到安全因果风险树、具体负向触发事实、来源因果信息、可执行或可等待推进路径、验证方式、归因和下一轮自我状态回写。

安全到观察的需求链定案为：

```text
安全根需求未满足
-> 需要判断自我安全值为何不足或为何不能升高
-> 先检查安全根控制态、服务能力保留率、各必要物理因素候选值和物理安全能力保留率叠乘裁决
-> 若所有必要物理因素候选值均达到 90，再进入风险安全余量判断
-> 来源为遗传的现有因果信息：当前场景可能提供风险因子或未来下降路径证据
-> 当前场景影响关系未知
-> 来源为遗传的现有因果信息：场景影响关系可由场景存在与自我状态变化验证
-> 当前场景存在集合未知
-> 生成需求：当前场景存在集合明确
-> 该需求未满足
-> 选择对象作用方法：安全_观察当前场景 / 安全_识别场景存在集合
-> 输出场景存在集合
-> 需要评估各存在安全度
-> 生成需求：当前场景各存在安全评估明确
-> 选择对象作用方法：安全_评估当前场景安全性
-> 输出当前场景安全度、最低安全度存在、直接伤害可能性候选和评估置信度
-> 持续跟踪自我关键特征变化
-> 形成或更新安全因果候选
-> 后天强化 / 削弱 / 覆盖对应因果信息
```

若评估结果显示场景安全度低，不得直接结算自我安全值；只能生成风险因子、处置路径需求、持续观察需求或降级保护需求。场景评估安全值范围是 `0..I64_MAX`，其中 `I64_MAX` 只能表示当前评估公式下的候选满刻度或当前范围无已知负向因果压力，不表示当前真实安全值已经达到 `I64_MAX`，也不表示永久绝对安全。条件不足不得用 `I64_MAX` 兜底，应返回材料不足、风险安全候选未明确或证据不足。

存在风险安全值按具体存在分别评估；历史直接伤害先生成或更新负向安全因果信息。若没有可回查历史风险值，历史值必须为 `0`，但 `历史值 = 0` 只表示没有历史风险材料，不得推出“已安全”。因果信息是被动获取的，未收到负向因果证据时，不强求补因果链，不把未知写成危险，也不得把未知直接写成满值安全。已经按规则搜索且无负向证据时，只能写带范围、来源、有效期和搜索完整状态的无负向证据结果。

场景中多个已确认存在属于同层因素，场景风险压力值取各存在风险压力候选的平均值，再转换为 `风险安全_场景影响部分 = I64_MAX - 场景风险压力值`。该值仍是风险安全候选或分量候选，只能影响 90..99 风险余量，不得越过物理安全独占候选叠乘约束，也不得直接写自我安全值。

最低安全度存在只作为诊断 / 处置线索，不再单独决定场景安全值。风险安全层的直接因不得由 C++ 固定五因素表或固定权重表定义，必须来自初始因果模板或后天证据增强后的因果信息组；场景影响、运行影响、资源影响、权限影响、未知影响只能作为可能的因果节点名称或历史兼容事实，不得因字段名存在就自动成为固定组成因。默认良好不是“已证永远安全”，只是当前没有被动获得的负向因果证据；安全影响因果不因缺省而被强行关闭或补齐。

只有被动获得真实负向变化、时间顺序和归因证据后，安全评估才派生持续观察、负向影响处置或降级保护链。`安全_执行降级保护` 第一版只在负向影响处置需求已明确且安全影响因果已明确时允许执行；默认良好路径不触发该方法。场景自身安全评估结果产出后，仍必须经过持续共处时间、稳定性、风险因子有效期和归因证据，才会进一步影响自我风险安全候选；是否提高或降低自我安全值，仍必须经过根控制规则、因果归因、价值投影和叶子任务价值结算入口。

## 8. 子需求目标宿主

服务根需求的被需求存在是自我，但服务根需求下的子需求不一定作用于自我本体。

第一版分三类：

```text
事实补全型：
    例如明确当前服务对象、交互者、权限者、服务目标。
    被需求存在 = 自我当前交互上下文 / 自我世界模型。
    该类字段只在 006 定义的服务触发事实已经挂载到服务根闭环信息位后，
    且缺失会阻断行动、验证、归因或回写时，才允许成为服务子需求；
    不得作为服务值定义必要条件自动入树。

服务对象外在特征状态改善型：
    例如让服务对象的问题状态从未解决变为已解决。
    被需求存在 = 人类服务对象 / 被授权服务对象。

安全维持型：
    例如确认运行状态、资源状态、权限边界、当前场景存在集合、安全影响因果、负向影响处置需求。
    被需求存在 = 自我 / 自我安全上下文 / 当前场景 / 场景存在 / 被检查资源。
```

服务对象外在特征状态改善型子需求，才是服务值结算最核心的事实证据来源。

## 9. 自检动作动态

自检线程不是动作来源。

若根特征自检需要进入因果账本，必须由明确方法表达：

```text
方法：自检自我根特征
输入：自我存在、抽象根特征定义
动作：读取自我特征实例和当前值，并比较定义
输出：自检报告 / 缺口事实
```

动作动态表达为：

```text
来源方法 = 自检自我根特征
动态主体 = 自我
动态对象 = 自我
动态特征 = 自我_安全值 / 自我_服务值
初始状态 = 待检查 / 未知
结果状态 = 当前特征状态已知 + 缺口集已知
```

该动态只说明：

```text
自检动作让缺口事实变得已知。
```

它不得直接结算为：

```text
安全值增加；
服务值增加。
```

若当前实现暂未把根特征自检注册为方法，则自检报告仍按需求信息来源处理，不得把线程本身当成动作来源。

## 10. 服务值定义边界

服务值是自我存在的根特征，但服务值来源于自我向服务对象提供服务后的价值。

因此，服务值增加的事实链应为：

```text
服务抽象定义
    -> 自我觉醒根闭环给出服务因果坐标
        -> 人类需求事实、服务目标事实或可验证服务触发事实被挂载
            -> 服务根闭环信息位被点亮
                -> 识别对象、目标、授权、行动、验证、归因或回写缺口
                    -> 通过闭环缺口准入后生成对应服务子需求
                        -> 子需求任务化
                            -> 服务对象外在特征状态改善 / 服务对象反馈信息
                                -> 来源需求满足
                                    -> 叶子任务价值结算
                                        -> 自我_服务值增加
```

禁止：

```text
把服务值差距本身当作服务已发生的证据；
把服务值账务变化反过来证明服务对象已改善；
缺少服务对象、服务目标或归因证据时正式结算服务值；
无服务触发事实时把当前交互者、权限者、服务对象或服务目标固定入树；
把服务对象建成服务根需求的目标宿主。
```

服务根需求目标宿主仍是自我；服务对象只在服务触发事实点亮后的服务因果链上下文子需求和服务事实子需求中作为目标宿主。

服务值动态规则属于服务抽象定义的一部分，但不等于服务对象事实。服务值变化规则以 006《自我存在服务与生存基本因果闭环规范20260601》中的“服务值变化规则 v1.1”为上级口径；本节只给出自我根特征侧的落点。

服务值边界为：

```text
0 <= S <= Smax
```

`Smax` 必须由服务抽象定义明确给出，且必须大于 0。

服务值变化只有两条路径：

```text
1. G0 成功服务治理判断确认后增加。
2. 服务值维护器按时间自动衰减。
```

除此之外，任何事件都不能直接降低或增加服务值。服务值增加只能来自成功服务人类事件，并且必须采用事件级饱和入账、剩余空间判断或等价安全加法，禁止无界累加：

```text
DeltaS(e) = (Smax - S) * lambda(e)
S_new = S + DeltaS(e)
```

或：

```text
if 服务增量 >= Smax - S:
    S = Smax
else:
    S = S + 服务增量
```

成功服务确认链固定为：

```text
D0 + 现实证据 + 前后状态比较 + 验证 + 归因 + 权限安全
    -> G0 成功服务治理判断

G0 + D1 任务承接证据
    -> D2 服务值结算动作动态
```

关键边界：

```text
D0 证明自我做了服务动作；
D1 证明任务壳推进了；
G0 判断是否成功服务；
D2 证明服务值如何入账。
```

单次成功服务值采用“硬门槛三值判断 + 离散评分 + 保守瓶颈法 + 饱和入账”规则。硬门槛包括：

```text
H_人类对象成立；
T_明确需求或利益；
G_明确服务目标；
P_权限边界成立；
B_安全通过；
D_服务已实际交付；
D0_自我服务业务动作存在；
C_服务前后状态可比较；
E_目标特征改善成立；
V_改善结果可验证；
A_改善可归因于自我动作；
N_非重复服务；
W_闭环回写成立。
```

硬门槛采用：

```text
成立；
不成立；
待确认。
```

任一硬门槛不成立时，成功服务候选状态为已否决，层级为 L0，`lambda(e) = 0`。存在待确认硬门槛时，事件进入成功服务候选池，暂不增加服务值。

硬门槛全部成立后，使用三个离散评分：

```text
完成度；
有效性；
证据强度。
```

完成度按服务目标特征前后状态到目标状态的差距变化计算；数值目标使用：

```text
完成度 = clamp(
    (服务前差距 - 服务后差距) / 服务前差距,
    0,
    1
)
```

枚举 / 布尔目标使用：

```text
0    = 未改善 / 变差 / 状态未知
0.5  = 有阶段性改善，但目标未完全达成
1.0  = 目标状态已达成
```

有效性衡量完成结果是否真的帮助了人类需求：

```text
0    = 无帮助 / 负帮助 / 与需求无关
0.25 = 有交付，但帮助只是假定的，缺少反馈或结果改善
0.5  = 部分解决人类需求
0.75 = 主要解决人类需求，但仍有残余缺口
1.0  = 明确解决需求，或产生明显正向收益
```

证据强度衡量证据链：

```text
0    = 没有证据
0.25 = 只有自我输出 / 方法回执，缺少服务对象状态或反馈
0.5  = 有服务前后状态之一，或服务对象已接受且反馈窗口内无负反馈
0.75 = 有服务前后状态对比，且结果可验证
1.0  = 有前后状态对比 + 服务对象反馈 / 回执 + D0 动作动态 + 归因证据
```

第一版采用保守瓶颈法：

```text
基础分 = min(完成度, 有效性, 证据强度)
```

层级映射：

```text
基础分 < 0.30        -> L0 无效服务
0.30 <= 基础分 < 0.50 -> L1 微成功服务
0.50 <= 基础分 < 0.70 -> L2 基础成功服务
0.70 <= 基础分 < 0.90 -> L3 标准成功服务
基础分 >= 0.90       -> L4 显著成功候选
```

`L5 关键成功` 不由普通公式自动产生，必须额外满足人类安全、重大利益或长期福祉的关键正向影响、证据强度为 1.0、非重复系数高、安全门槛通过、权限边界完全成立、改善可强归因于 D0。

单次入账量为：

```text
q(e) = u * K_L * 有效性 * 证据强度 * Rdup * G(A)
lambda(e) = clamp(q(e) / Smax, 0, lambdacap(A))
DeltaS(e) = (Smax - S) * lambda(e)
S_new = S + DeltaS(e)
```

其中：

```text
u = 标准服务单位。
K_L = 成功服务层级系数。
Rdup = 非重复系数。
G(A) = 安全值对服务入账的调节。
lambdacap(A) = 当前安全状态下单次服务允许的最大入账比例。
```

成功服务事件分层系数：

```text
L0 无效服务：K_L = 0。
L1 微成功服务：K_L = 0.25。
L2 基础成功服务：K_L = 0.50。
L3 标准成功服务：K_L = 1.00。
L4 显著成功服务：K_L = 2.00。
L5 关键成功服务：K_L = 4.00。
```

标准服务单位 `u` 应由目标服务值、标准服务间隔和动态衰减率反推确定，或按服务值发行预算确定，不得任意写死：

```text
D_decay0 = R_decay(A0, tau0, Sstar) * tau0
u ~= D_decay0 / (Smax - Sstar)

或：

W = 统计时间窗口。
B_W = Decay_W + Recovery_W + SleepPressure_W
M_W = 该窗口内有效直接服务总量。
u = clamp(B_W / max(M_W, epsilon), u_min, u_max)
```

一个成功服务事件是围绕一个人类需求形成的闭环，不得把同一服务拆成多个片段重复入账。非重复系数第一版为：

```text
Rdup = 1.0  独立新服务，目标明确，改善独立。
Rdup = 0.7  同一需求下的重要阶段性成果。
Rdup = 0.4  同一需求下的辅助推进。
Rdup = 0.1  轻微重复，新增价值很小。
Rdup = 0.0  无新增改善 / 刻意拆分 / 重复结算。
```

成功服务事件对有效成功服务时间 `t_eff` 的刷新必须按层级加权，微小服务不得完全刷新服务间隔压力：

```text
t_eff_new = t_eff_old + W_L * (t_now - t_eff_old)
L0 = 0, L1 = 0.2, L2 = 0.5, L3 = 0.8, L4 = 1.0, L5 = 1.0
```

服务值降低只能来自时间自动衰减。自动衰减不是惩罚、遗忘、信用下降或服务质量变差；它用于防止服务值长期累积并重新唤醒服务意识。动态衰减率由安全值、距离上一次确认成功服务的时间间隔、服务当前值、服务能力和有效服务需求压力共同决定：

```text
R_decay = clamp(
    R_base
  + W_gap * GapFactor(T) * SafeFocus(A)
  + W_s * (S / Smax)
  + W_d * DemandPressure
  + W_c * CapacityFactor,
    R_min,
    R_max
)
```

`GapFactor(T)` 必须随有效成功服务时间间隔单调递增且有上限。服务值更新必须限制衰减量：

```text
Decay = min(S, R_decay * dt)
S_new = S - Decay
```

服务意识与服务值分开：

```text
服务值 S = 最近成功服务的积累状态。
服务意识 I = 自我对继续服务人类的关注强度。
```

服务值下降不表示服务意识下降；服务值回落、有效成功服务时间间隔变长和服务当前值偏低，会增强服务意识或服务缺口检查。服务意识不得直接写成服务对象、服务目标、服务结果或服务值结算证据；无服务触发事实时，只能提高等待服务触发事实、候选排序或服务根缺口检查的敏感度。

### 10.1 服务值活跃存在、有效无成功服务时间和动态休眠

服务值不是单纯奖励计数器，而是自我维持主动活跃存在的服务依据。服务值低位或归零不否定过去服务，只表示当前缺少新的成功服务依据。休眠不是终止，也不是自我消灭；休眠是主动活跃权暂停，系统进入低活动、低干预、可唤醒状态。

服务抽象定义必须支持有效无成功服务时间，而不是固定无服务物理时间：

```text
A(t) = 当前安全值归一化结果，范围 0..1。
C(t) = 当前服务能力，范围 0..1。
D(t) = 当前有效服务需求强度，范围 0..1。
G(A) = 安全调节系数，安全值越高越大，且 0 < G(A) <= 1。

P_service = C(t) * D(t) * G(A)
E_no_success += dt * P_service
```

其中 `P_service` 是服务机会压力，`E_no_success` 是有效无成功服务时间。没有服务能力、没有有效服务需求或安全值偏低时，`E_no_success` 增长应变慢；服务能力、有效需求和安全值都处于高位时，`E_no_success` 应快速增长。

动态休眠阈值由最小成功服务闭环时间和服务机会压力决定：

```text
Tmin = 需求识别时间 + 反应决策时间 + 最小有效服务时间 + 成功确认时间

T_sleep = clamp(
    Tmin / max(P_service, epsilon),
    Tmin,
    Tmax
)
```

服务值衰减应与该阈值同构。设 `S0` 为上一次成功服务后的服务值，`T_sleep` 为当前休眠阈值，`x = E_no_success / T_sleep`，则目标衰减曲线可以为：

```text
S_target = S0 * max(0, 1 - x^p)，且 p > 1
```

因此服务值归零不应来自固定漏水孔、惩罚扣减或任意扣减，而应来自动态休眠阈值附近的有效无成功服务时间累计。若 `S = 0` 且 `E_no_success < T_sleep`，只能进入服务意识强化或服务校准；若 `S = 0` 且 `E_no_success >= T_sleep` 且当前没有有效服务进展，才允许进入休眠控制态。

正在进行安全、目标明确且有阶段性进展的人类服务任务时，不得按普通无成功服务直接休眠。有效服务进展可以降低 `E_no_success` 的增长、部分刷新有效成功服务时间，或进入服务校准 / 候选验证 / 等待反馈；阶段性成功必须是真实推进人类服务目标的独立成果，不能机械拆分刷值。

标准服务单位 `u` 可以从局部目标服务频率反推，也可以按服务值发行预算确定：

```text
W = 统计时间窗口。
B_W = 该窗口内为抵消必要衰减而需要补回的服务值总量。
M_W = 该窗口内有效直接服务总量。
u = clamp(B_W / max(M_W, epsilon), u_min, u_max)

M_W = integral(min(Demand_valid(t), Capacity_service(t)) * P_success(t) dt)
```

`M_W` 是有效直接服务总量，不是原始需求总量。原始需求无限或很多时，不能把单次服务值压到无法维持服务值；有效服务需求少但成功服务稀少时，单次服务值可上升，但仍受成功服务层级、证据强度、非重复性、安全调节和饱和上限约束。

禁止：

```text
把固定无服务时长写成休眠条件。
把休眠写成死亡、终止或自我消灭。
把服务值衰减、有效无成功服务时间增长或服务意识强化写成成功服务证据。
把原始需求总量当成 `M_W`。
服务任务仍有有效进展时直接休眠。
```

## 12. 最终口径

```text
安全 / 服务是自我存在的根特征类型。

抽象特征树保存安全 / 服务的定义、目标状态、成立条件和缺口映射。

自我节点保存安全 / 服务的当前特征实例和值。

自检读取两边：
    抽象定义；
    自我实例。

自检比较两边：
    定义需要什么；
    自我现在有什么。

比较结果生成缺口。

只有缺口才生成需求。

只有需求未满足才生成任务。

安全概念 = 自我基于因果证据逐步形成的预测模型。
安全因素 = 自我在运行中发现的、会影响服务值、物理安全或未来下降风险的存在 / 状态 / 动作 / 时间关系。
风险安全 = 当前因素对未来服务值下降或物理安全下降的风险余量投影；它不是场景事实，不是出生期固定表，也不是自我安全值本体。
服务值 = 自我维持主动活跃存在的服务依据；它来自成功服务人类事件的饱和入账，并按有效无成功服务时间和动态休眠阈值衰减。
休眠 = 主动活跃权暂停，不是终止；服务值按动态休眠阈值归零且有效无成功服务时间达到阈值后才进入休眠控制态。
遗传信息 = 带来源动态证据或出生期初始假设标记的因果信息组；其中只承载被动动作触发结构。主动动作能力结构从本能方法 / 方法系统取得，本能方法因果信息只能通过学习及实际使用生成。后天证据可以强化、削弱、分化或覆盖遗传被动触发因果信息。
```
