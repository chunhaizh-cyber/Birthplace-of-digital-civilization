## 1. 定案

核心口径：

```text
作用外设不能直接“改变关系”；
作用外设只能改变某个存在的一阶特征，或改变自身的一阶特征；
关系是自我基于两个或多个存在的一阶特征计算出来的二次特征。
```

也就是说：

```text
机械手没有直接改变“杯子与机械手的距离关系”；
机械手改变了“机械手末端空间坐标”；
杯子的空间坐标可能也被改变；
自我再根据两者空间坐标计算出：
    机械手末端 与 杯子 的距离二次特征发生变化。
```

一句话：

```text
外设动的是世界里的数值；
自我生出的是数值之间的关系。
手不会直接改变“关系”，手只改变坐标、力、姿态，关系是自我算出来的。
```

## 2. 外设能力分类

外设能力分成两大类：

```text
感知发现型外设：
    发现 / 取得特征值。
    例如双目相机、触觉、力传感器、麦克风。

作用改变型外设：
    改变一阶特征值。
    例如机械手、底盘、云台、夹爪、灯光、电机。
```

作用改变型外设又分成：

```text
改变自身一阶特征：
    例如机械手末端坐标、夹爪开合度、相机云台角度、灯光亮度。

改变其他存在一阶特征：
    例如杯子位置、物体姿态、目标受力、目标表面照度。
```

不应说：

```text
改变存在之间的关系
```

应说：

```text
改变导致关系二次特征重新计算后发生变化的一阶特征。
```

## 3. 一阶特征与二次关系特征

### 3.1 一阶特征

一阶特征是某个存在自身可以被感知、改变、记录或比较的特征值。

示例：

```text
机械手末端.空间坐标
机械手末端.姿态
夹爪.开合度
夹爪.夹持力
相机.空间坐标
相机.朝向
自我宿主.空间坐标
杯子.空间坐标
杯子.姿态
目标表面.照度
目标观察簇.投影像素面积
```

作用外设方法的直接输出只能落到这类一阶特征，或落到外设自身状态特征，例如：

```text
机械手末端.空间坐标 == 目标坐标
夹爪.开合度 == 目标开度
底盘.里程计状态 == 已更新
灯光.亮度 == 目标亮度
```

### 3.2 二次关系特征

关系不是外设直接改变的物理字段，而是自我基于特征比较形成的概念。它应作为二次特征处理。

示例：

```text
距离关系 =
    A.空间坐标
    B.空间坐标
    -> A与B距离值

接触关系 =
    A.空间范围
    B.空间范围
    力反馈
    形变 / 位移
    -> A与B接触状态

遮挡关系 =
    A.空间范围
    B.空间范围
    相机位姿
    深度前后关系
    -> A遮挡B状态

包含关系 =
    A.空间范围
    B.空间范围
    -> B是否在A范围内
```

这些都不是外设直接输出的一阶事实，而是自我计算出来的二次特征。

### 3.3 与现有二次特征规范的关系

概念上，一个关系判断可以读取两个或多个存在的一阶特征；实现和持久化时仍必须服从 `011002 二次特征规范20260520`。

第一版约束：

```text
1. 二元关系可以沉淀为二次特征。
2. 多输入关系可以先由自我计算方法、条件场景、临时视图或组合判断承载。
3. 只有当上级二次特征规范允许时，多输入关系才可沉淀为更高阶或多特征二次特征。
4. 不得为了表达“关系变化”而给作用外设方法新增关系直接输出字段。
```

## 4. 需求表达修正

错误表达：

```text
机械手.改变杯子与桌子的关系
夹爪.改变夹持关系
底盘.改变相机与目标的观察关系
```

正确表达：

```text
杯子.空间坐标 == 目标坐标
杯子.姿态偏差 < 最大允许偏差
机械手末端.空间坐标 == 目标坐标
夹爪.开合度 == 目标开度
夹爪.夹持力 > 最小夹持力
```

然后由自我计算：

```text
杯子与桌面距离 < 阈值
机械手末端与杯子距离 < 阈值
夹爪与杯子接触状态 == 成立
```

所有需求比较符仍只允许：

```text
大于
小于
等于
```

“改变、靠近、接触、遮挡、包含、夹持稳定”等业务词不能直接作为方向词或外设输出字段。它们必须拆成一阶特征目标，或由自我计算出的二次特征比较表达。

## 5. 多外设协同链修正

旧表达：

```text
作用外设改变关系，感知外设验证关系
```

修正为：

```text
作用外设改变一阶特征；
感知外设观察一阶特征；
自我根据一阶特征计算二次关系特征；
自我比较预测关系与观察关系；
自我更新因果。
```

完整链：

```text
动作前感知：
    感知外设取得 A、B 的一阶特征。

自我预测：
    预测作用外设执行后，哪些一阶特征会变化；
    进一步预测哪些二次关系特征会变化。

作用执行：
    作用外设改变自身或目标存在的一阶特征。

动作后感知：
    感知外设再次取得一阶特征。

二次特征计算：
    自我根据动作后一阶特征计算关系。

验证：
    比较预测二次关系与实际二次关系。

归因：
    判断该变化是否由本次动作造成。

学习：
    世界树更新因果成立 / 失败次数。
```

### 5.1 外设协同的基本分工

外设协同的核心闭环是：

```text
作用外设负责改变特征值；
感知外设负责发现特征值；
自我负责预测、编排、比较、归因和学习。
```

感知发现型外设包括：

```text
双目相机
麦克风
力传感器
触觉传感器
编码器
温度传感器
```

它们负责：

```text
发现特征值
测量特征值
稳定复现特征值
提供观察报告
提供扫描 / 跟踪 / 稳定特征报告
```

它们不负责：

```text
确认世界真值
确认任务完成
确认安全值增加
确认服务值增加
```

感知使用方法只能记录观测动作产生的观察事实或世界模型刷新，不能把外界对象自身变化伪装成自我造成的物理变化。

作用改变型外设包括：

```text
机械手
底盘
云台
灯光
电机
夹爪
执行器
```

它们负责：

```text
改变自身一阶特征
改变其他存在一阶特征
改变环境一阶特征
改变会导致存在间关系二次特征重算后发生变化的一阶特征
```

例如：

```text
机械手.末端位置 == 目标位置
夹爪.开合度 == 目标开度
杯子.位置 == 目标位置
灯光.亮度 > 最低亮度
相机.空间坐标 == 目标坐标
相机.朝向 == 目标朝向
```

不得把上面的作用改写成：

```text
作用外设直接改变关系。
```

作用外设的动作动态必须记录：

```text
动作前特征
预测动作结果
动作后观察结果
实际变化是否归因于该动作
是否出现副作用
```

### 5.2 自我层七步协同闭环

外设协同不是局部设备配合，而是自我建立世界因果的基本方式。

```text
动作前感知
    -> 自我预测动作结果
    -> 作用外设执行动作
    -> 感知外设观察动作后结果
    -> 自我比较预测与观察
    -> 自我判断目标是否达成、是否有副作用
    -> 世界树更新因果
```

第一步：动作前感知。

```text
目标观察簇.跟踪状态 == 稳定
目标观察簇.空间坐标复现离散度 < 最大允许离散度
目标物体.当前位置观测状态 == 已取得
```

感知外设输出的是：

```text
观察像素簇
跟踪报告
目标特征值
稳定性
失败原因
```

不是直接输出：

```text
杯子一定是世界存在A
```

旧像素级目标中的“100%”也只是帧内可寻址、可回查、无遗漏、无重复，不表示稳定对象、语义识别或目标可见性闭合。

第二步：自我预测动作结果。

```text
如果执行动作M，
目标一阶特征可能如何变化？
副作用可能是什么？
需要哪些感知验证？
哪些二次关系特征会随之变化？
```

预测不是事实。它应落到预测记录或动作计划上：

```text
动作预测.目标位置 == 目标位置
动作预测.最大允许误差 == 阈值
动作预测.副作用风险值 < 最大允许风险值
```

第三步：作用外设执行动作。

```text
机械手.动作执行状态 == 已执行
```

这只表示作用方法完成执行，不代表目标已经达成。不能因为机械手方法运行成功，就直接写：

```text
杯子.位置 == 目标位置
```

第四步：动作后感知。

```text
目标观察簇.跟踪状态 == 稳定
目标观察簇.最近观测年龄 < 最大允许观测年龄
目标观察簇.空间中心坐标 == 观测值
目标观察簇.距离复现离散度 < 最大允许离散度
夹爪.夹持力 > 最小夹持力
夹爪.夹持力 < 最大安全夹持力
机械手.末端位置误差 < 最大允许误差
```

第五步：自我比较预测与观察。

```text
杯子.位置误差 < 最大允许位置误差
杯子.姿态偏差 < 最大允许姿态偏差
目标观察簇.丢失状态 == 未丢失
副作用风险值 < 最大允许副作用风险值
```

可输出：

```text
动作结果验证状态 == 通过 / 未通过 / 证据不足
```

第六步：自我归因。

```text
动作结果归因状态 == 已归因
动作结果归因状态 == 不确定
动作结果归因状态 == 证据不足
副作用归因状态 == 已确认
```

相机观察到杯子动了，不代表机械手导致杯子动了；必须结合动作时间、动作范围、作用对象、前后特征变化、传感器一致性来判断。

第七步：更新世界树因果。

```text
验证通过:
    因果.成立次数 + 1

预测失败:
    因果.失败次数 + 1

证据不足:
    生成证据补齐需求

出现副作用:
    生成安全树下的副作用约束 / 避免需求
```

### 5.3 多外设协同的典型形式

机械手 + 双目相机：

```text
相机扫描 / 跟踪目标簇
    -> 自我预测机械手动作后一阶特征和二次关系特征
    -> 机械手执行动作
    -> 相机跟踪动作后目标簇
    -> 自我比较位置误差
    -> 自我更新因果
```

机械手 + 力传感器 + 相机：

```text
夹爪.夹持力 > 最小夹持力
目标观察簇.丢失状态 == 未丢失
目标观察簇.位置误差 < 最大允许误差
```

如果力传感器说夹住了，但相机看见目标没动：

```text
特征冲突状态 == 存在
```

然后生成：

```text
夹持结果验证需求
目标观察质量补齐需求
动作归因补齐需求
```

底盘 / 云台 + 相机：

```text
底盘或云台改变：
    自我宿主.空间坐标
    相机.空间坐标
    相机.朝向

相机观察：
    目标观察簇.深度有效率 > 最低深度有效率
    目标观察簇.空间坐标有效率 > 最低空间坐标有效率

自我计算：
    相机_目标.距离值 < 最大有效观察距离
    目标区域.画面中心距离 < 最大允许中心偏差
    目标区域.投影像素面积 > 最小有效面积
```

底盘或云台不是直接改变“观察关系”，而是改变会让观察关系二次特征重算的一阶特征。

灯光 + 相机：

```text
灯光.亮度 > 目标亮度
目标区域.颜色特征稳定状态 == 稳定
观察像素簇.轮廓完整度 > 最低轮廓完整度
```

这属于：

```text
环境一阶特征改变
    -> 感知特征稳定性提升
    -> 自我计算观察质量或任务达成相关二次特征
```

### 5.4 对任务筹办的影响

任务筹办不只是找一个方法，而是要找一条：

```text
动作路径 + 感知验证路径
```

例如需求：

```text
杯子.位置 == 目标位置
```

任务筹办不能只找：

```text
机械手_移动杯子
```

还要派生：

```text
动作前:
    杯子.当前位置观测状态 == 已取得

动作后:
    杯子.位置误差 < 最大允许误差

验证:
    动作结果归因状态 == 已归因
```

一个作用任务的完整筹办应包括：

```text
1. 动作前感知需求
2. 动作预测需求
3. 作用外设执行需求
4. 动作后感知需求
5. 结果比较需求
6. 归因需求
7. 副作用检查需求
```

### 5.5 对外设消息的影响

外设线程仍然负责生产消息。

```text
相机线程:
    扫描报告
    跟踪报告
    观察像素簇
    稳定特征报告

机械手线程:
    动作执行回执
    当前位置反馈
    夹爪状态
    力反馈
    错误状态
```

任务管理工作线程负责承接这些消息：

```text
外设消息
    -> 匹配等待任务
    -> 生成任务回执
    -> 生成动作动态输入
    -> 需要时生成派生需求消息
    -> 上报自我线程
```

自我线程负责裁决：

```text
是否入需求树
是否入世界树
是否更新因果
是否形成副作用 / 禁忌 / 可信路径
```

### 5.6 动作动态的预测与验证字段

不用新增大结构，可以作为动态特征补充记录：

```text
动作动态.动作前观察状态 == 已取得
动作动态.预测结果状态 == 已生成
动作动态.动作执行状态 == 已执行
动作动态.动作后观察状态 == 已取得
动作动态.预测偏差值
动作动态.预测偏差值 < 最大允许偏差
动作动态.结果验证状态 == 通过 / 未通过 / 证据不足
动作动态.结果归因状态 == 已归因 / 不确定 / 证据不足
动作动态.副作用状态 == 可接受 / 不可接受
```

这样世界树因果可以知道：

```text
这个方法在什么条件下真的导致了目标特征变化；
什么时候只是执行了但没达成；
什么时候副作用不可接受；
什么时候感知证据不足。
```

### 5.7 自我预测和感知验证的三比较表达

例子：机械手移动杯子。

```text
父需求:
    杯子.位置 == 目标位置

动作前感知:
    杯子.当前位置观测状态 == 已取得

动作预测:
    动作预测.目标位置 == 目标位置
    动作预测.最大允许位置误差 == 阈值

作用执行:
    机械手.动作执行状态 == 已执行

动作后感知:
    目标观察簇.跟踪状态 == 稳定
    目标观察簇.最近观测年龄 < 最大允许观测年龄

验证:
    杯子.位置误差 < 最大允许位置误差

归因:
    动作结果归因状态 == 已归因
```

全部仍然是：

```text
大于
小于
等于
```

不得把“改善、确认、验证”作为方向词。

### 5.8 多外设互证

当多个感知外设给出同一目标特征，可以生成一致性判断：

```text
视觉测得位置
编码器推算位置
触觉 / 力反馈状态
```

对应特征：

```text
多源感知一致性状态 == 一致
多源感知偏差值 < 最大允许偏差
冲突感知源数量 == 0
```

如果冲突：

```text
多源感知一致性状态 == 冲突
```

然后派生：

```text
冲突特征.证据状态 == 补齐
目标观察质量状态 == 提升
传感器校准状态 == 检查
```

## 6. 方法契约修正

作用外设方法的输出结果模式不要写二次关系作为直接输出，除非这个方法本身就是自我计算二次特征的方法。

### 6.1 作用外设方法输出

```text
机械手_移动末端
输出：
    机械手末端.空间坐标 == 目标坐标

夹爪_闭合
输出：
    夹爪.开合度 == 目标开度
    夹爪.夹持力 > 最小夹持力

底盘_移动
输出：
    自我宿主.空间坐标 == 目标坐标

云台_转动
输出：
    相机.朝向 == 目标朝向

灯光_调亮
输出：
    灯光.亮度 == 目标亮度
```

### 6.2 自我计算二次特征的方法输出

```text
自我_计算存在间距离
输出：
    A_B.距离值 == 计算值

自我_判断接触状态
输出：
    A_B.接触状态 == 成立 / 不成立

自我_判断遮挡状态
输出：
    A_B.遮挡状态 == 成立 / 不成立

自我_判断包含状态
输出：
    A_B.包含状态 == 成立 / 不成立
```

边界句：

```text
外设改变一阶特征；
自我计算二次特征。
```

## 7. 动作预测与验证修正

旧表达：

```text
自我预测动作可能造成的关系变化，感知侧验证。
```

修正为：

```text
自我预测动作可能造成的一阶特征变化；
自我进一步推导可能造成的二次特征变化；
感知外设观察动作后的一阶特征；
自我再计算二次特征并验证预测。
```

完整表达：

```text
预测：
    动作后 A.空间坐标 == 预测坐标
    动作后 B.空间坐标 == 预测坐标
    推导 A_B.距离值 < 目标阈值

执行：
    作用外设改变 A 或 B 的一阶特征

观察：
    感知外设取得动作后 A、B 的一阶特征

验证：
    自我计算 A_B.距离值
    比较 A_B.距离值 < 目标阈值 是否成立
```

验证结果进入任务回执、动作动态输入、状态动态或因果学习时，必须保留：

```text
来源动作
动作前一阶特征
动作后一阶特征
预测二次特征
实际计算二次特征
比较结果
归因结论
```

不得只记录：

```text
关系被外设改变成功
```

## 8. 示例

### 8.1 机械手靠近杯子

不要写：

```text
机械手改变了机械手与杯子的距离关系。
```

应写：

```text
动作目标：
    机械手末端.空间坐标 == 目标坐标

感知输入：
    机械手末端.空间坐标
    杯子.空间坐标

自我计算二次特征：
    机械手末端_杯子.距离值 < 最大允许距离

验证目标：
    机械手末端_杯子.距离值 < 最大允许距离
```

其中：

```text
机械手末端.空间坐标
杯子.空间坐标
```

是一阶特征。

```text
机械手末端_杯子.距离值
```

是二次特征。

### 8.2 夹爪夹住杯子

不要写：

```text
夹爪改变了夹持关系。
```

应写：

```text
作用外设改变的一阶特征：
    夹爪.开合度 == 目标开度
    夹爪.夹持力 > 最小夹持力

感知外设观察的一阶特征：
    杯子.空间坐标
    杯子.运动状态
    夹爪.力反馈
    夹爪.开合度

自我计算的二次特征：
    夹爪_杯子.接触状态 == 成立
    夹爪_杯子.夹持稳定状态 == 稳定
```

### 8.3 相机靠近目标

底盘或云台改变的是：

```text
相机.空间坐标
相机.朝向
自我宿主.空间坐标
```

不是直接改变：

```text
相机与目标的观察关系
```

自我再根据：

```text
相机.空间坐标
相机.朝向
目标观察簇.空间坐标
目标观察簇.投影像素面积
```

计算：

```text
相机_目标.距离值
目标区域.画面中心距离
目标区域.投影像素面积
```

这些才是二次或派生特征。

## 9. 写入权威

### 9.1 作用外设可以写入或回执的内容

作用外设可以通过合法方法回执：

```text
外设自身状态
外设自身一阶特征
目标存在的一阶特征变化请求结果
执行失败原因
执行耗时
安全停止状态
```

例如：

```text
机械手末端.空间坐标 == 目标坐标
夹爪.开合度 == 目标开度
夹爪.夹持力 > 最小夹持力
底盘.运动状态 == 已停止
灯光.亮度 == 目标亮度
```

### 9.2 自我计算方法可以写入的内容

自我计算方法可以基于一阶特征写入：

```text
A_B.距离值
A_B.接触状态
A_B.遮挡状态
A_B.包含状态
A_B.夹持稳定状态
预测关系与实际关系匹配状态
```

这些写入必须绑定明确输入特征、计算方法、比较符、目标值和来源动态。

### 9.3 不得裸写

不得由作用外设裸写：

```text
A_B.关系已改变
A_B.距离关系已改变
A_B.接触关系已成立
A_B.遮挡关系已解除
A_B.包含关系已成立
```

若这些语义需要入账，必须由自我计算二次特征方法或验证方法生成。

## 10. 禁止项

禁止：

```text
1. 把作用外设方法输出写成“改变关系”。
2. 把关系变化当作作用外设直接结果。
3. 把机械手、底盘、云台、夹爪、灯光等作用外设登记为二次特征生产者。
4. 把感知外设观察到的一阶特征直接解释成关系成立。
5. 绕过自我计算方法，把 A_B.距离值、接触状态、遮挡状态或包含状态裸写入世界树。
6. 在需求方向中使用“改变关系、建立关系、消除关系”等词代替三比较表达。
7. 在动作预测中只预测关系变化，不预测一阶特征变化。
8. 在验证中只比较关系结论，不保留动作前后一阶特征证据。
9. 把控制面板显示的距离、接触或遮挡效果当作关系二次特征权威写入来源。
10. 为了简化方法契约，把作用执行、感知观察和自我二次特征计算合并成一个外设本能方法。
```

## 11. 最终定案

规范句：

```text
自我经常需要感知外设和作用外设协同工作。

作用外设不直接改变“关系”。
关系是自我基于一个或多个存在的一阶特征计算出来的二次特征。

作用外设只能直接改变：
    自身一阶特征；
    或其他存在的一阶特征。

感知外设负责发现这些一阶特征；
自我负责根据一阶特征计算二次特征，
并判断二次特征是否发生了目标变化。

因此，多外设协同时，
作用外设执行动作，
感知外设观察动作前后的一阶特征，
自我计算并比较二次特征，
最后再进行结果验证、归因和因果学习。

任何作用类任务，都不应只记录“方法执行成功”；
还应记录：
    动作前观察
    预测结果
    动作执行
    动作后观察
    目标特征比较
    结果归因
    副作用判断

只有当动作后感知结果与预测目标匹配，并且能归因于该动作时，
才允许认为该作用路径在世界树因果中成立。
```

一句话：

```text
外设动的是世界里的数值；
自我生出的是数值之间的关系；
手不会直接改变“关系”，手只改变坐标、力、姿态，关系是自我算出来的。
感知是自我的眼睛，作用是自我的手；
自我先猜手会把世界改成什么样，再让眼睛看世界是不是真变成了那样，猜对的沉淀成因果，猜错的沉淀成经验。
```
