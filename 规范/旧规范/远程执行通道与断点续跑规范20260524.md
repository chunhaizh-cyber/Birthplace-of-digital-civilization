# 远程执行通道与断点续跑规范 20260524

编号：070

层级：一级规范 / 工程执行稳定性约束

状态：有效

## 1. 总口径

远程 Codex / ChatGPT 执行过程中的上下文压缩、流断开、网络错误、工具通道错误，属于工程执行通道状态，不属于鱼巢业务链路状态。

出现下列现象时，必须先按远程执行通道失败处理：

```text
remote compact
stream disconnected
websocket
network error
error sending request
responses/compact
远程压缩失败
远程流连接中断
```

不得仅凭上述错误写成：

```text
编译失败
代码实现失败
计划逻辑失败
业务验证失败
方法筹办失败
真实硬件验证失败
```

这些结论必须由构建日志、运行日志、状态快照、动作动态、错误日志或真实硬件样本证明。

## 2. 远程执行状态

计划、实施记录或断点清单需要记录远程任务结果时，使用下列状态：

```text
已完成
中断于远程压缩
中断于网络连接
中断于工具调用
中断于构建
中断于真实硬件验证
```

若中断于远程压缩、网络连接或工具调用：

```text
1. 项目实现状态保持最近一次已知状态。
2. 验收状态保持不变。
3. 不扩大为业务失败或业务通过。
4. 下一步从仓库内最近检查点重新开小任务继续。
```

## 3. 小切片执行规则

生成计划或交给 Codex 执行的远程任务，必须优先切成可恢复的小切片。

一个 Codex 任务只允许执行一个闭合切片。每个切片必须写清：

```text
1. 本次目标。
2. 背景摘要。
3. 允许修改文件。
4. 禁止修改范围。
5. 验收命令或证据口径。
6. 回执文件路径。
7. 禁止宣称项。
```

禁止在一个远程任务中同时执行：

```text
规范修改
计划重切
方法登记
适配器实现
任务筹办改造
构建验证
真实硬件验证
```

如果确实需要跨多类工作，必须拆成多个切片，并在每个切片结束后写入仓库内检查点。

## 4. 检查点文件

长计划必须使用仓库内文件作为远程执行检查点，避免依赖远程会话记忆。

推荐路径格式：

```text
实施记录/YYYYMMDD_主题_Codex断点清单.md
```

当前外设本能方法计划可使用：

```text
实施记录/20260524_外设本能方法_Codex断点清单.md
```

每个切片完成后至少记录：

```text
当前切片
已完成事项
修改文件
验收命令
验收结果
未完成事项
下一切片建议
禁止宣称项
```

检查点只记录实际完成和真实证据，不得补写伪造结论。

## 5. 证据边界

缺真实硬件、真实目标样本、真实运行日志、状态快照、动作动态或错误日志时，只能记录：

```text
等待真实样本验证
等待真实硬件验证
等待真实日志证据
```

不得写成：

```text
业务链路已通过
真实 D455 链路已通过
方法完整闭合
内部循环全部完成
自我苏醒完成
初步成熟完成
```

静态登记通过、构建通过、日志入口存在，只能证明对应证据范围，不得扩大解释为真实业务闭环通过。

## 6. 恢复执行规则

远程执行中断后，不要求新任务记住上一轮远程上下文。

恢复时按下列顺序处理：

```text
1. 读取规范目录、计划索引、相关计划和最近断点清单。
2. 明确上次远程执行状态和项目最近已知状态。
3. 选择一个最小可闭合切片。
4. 只执行该切片允许范围内的读取、修改和验证。
5. 将结果写回断点清单。
```

如果上下文不足，只记录缺口，不猜测、不伪造、不把远程通道失败解释成项目失败。

## 7. 计划生成约束

生成计划时，大计划只保留路线和证据闸门；执行项必须能拆成小切片。

计划中涉及远程 Codex 执行时，必须包含：

```text
远程执行状态
最近检查点
下一切片
允许修改范围
禁止修改范围
验收证据
禁止宣称项
```

计划文字应优先使用：

```text
目标
依据
下一步
验证证据
```

避免把完整历史、完整日志、完整规范和多阶段实现细节塞入单次远程任务。
