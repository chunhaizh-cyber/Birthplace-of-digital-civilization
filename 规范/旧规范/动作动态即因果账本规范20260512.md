# 动作动态即因果账本规范 20260512

## 0. 权威修订

本规范受以下硬规则约束：

```text
规范/方法动作动态硬规则规范20260512.md
```

凡是生成“方法动作动态”的变化，都必须绑定具体方法。线程只能调度和调用方法，不能作为方法动作动态的动作来源。

动作动态只提供事实证据和因果证据。下一步动作不得直接由动作动态本身生成，必须由需求状态、任务状态、方法状态等正式状态重新驱动。

主动 / 被动因果信息对应主动 / 被动动态信息。主动动态抽象出的动作致变因果可以在满足方法结构、条件、结果和证据要求后参与方法选择；被动动态抽象出的因果只能承载自动触发、提交、结算、观察和证据承接关系，不能直接成为可调用动作来源。

被动状态动作动态的动作语义统一写为 `被动动作`。`被动动作` 是空占位动作，表示该动态只能证明状态提交事实，不能被学习为主动方法，也不能进入自我动作组合反推候选。

所有动作动态转入因果抽象的逻辑必须一致。主动动作动态和被动动作动态都先生成统一结构的动作动态，再由同一套动态到因果信息流程提取状态迁移、来源证据和二次特征；区别只在于动作语义是否可主动调用。读取到 `被动动作`、被动动态类型、提交动作或结算动作时，因果抽象可以保留它的承上启下关系，但不得把它变成可执行动作模板，也不得把它作为普通可任务化需求的直接来源。

遗传信息不得直接遗传裸动作动态。动作动态是一次实际发生的账本证据；可遗传的是由动作动态或动态组抽象出的因果信息 / 因果模板，并且该因果信息必须保留来源动态证据引用。标准链路为：

```text
动作动态组
    -> 统一动态到因果信息流程
    -> 因果信息 / 因果模板
    -> 保留证据动态样本或出生期初始假设标记
    -> 冷启动读取为可复用因果知识
```

方法能力和初始因果模板的分工如下：

```text
主动动作：
    能力结构从本能方法 / 方法系统获得；
    本能方法的因果信息不进入出生期初始因果模板组；
    本能方法因果信息只能通过学习及实际使用生成；
    主动动作动态只作为运行证据、因果证据动态样本和稳定度样本。

被动动作：
    出生期初始因果模板组只承载被动动作触发结构；
    必须把被动因模板、自动果模板、动态转因果规则和幂等规则抽象为可遗传触发结构；
    被动动作动态只作为该触发结构的来源证据和动态样本。
```

因此，“动作动态即因果账本”不是说遗传运行日志，也不是说因果信息有多种来源；因果信息统一来自自我的认知过程。出生期初始模板和后天证据的区别，只是证据状态和生命周期阶段不同。

被动动作的自动性定义为：

```text
被动因正式出现
-> 匹配对应被动规则
-> 被动果自动出现
-> 生成标准动作动态
-> 进入统一因果抽象流程
```

被动因已经正式出现但被动果未出现时，不得把问题转成普通任务筹办；应记录为被动提交链、后处理链或结算链缺口。自动出现不等于重复出现，必须以被动因主键、目标主体、目标特征和规则语义形成幂等键。

被动动作自动性的验收必须查代码，不查口头口径。有效证据是：

```text
被动因入账位置；
自动触发或后处理扫描入口；
从因到果的函数调用链；
幂等 / 防重复判断；
被动果写入位置；
动作动态生成位置；
因果抽象入口，若该被动果需要增强因果链。
```

若中间任一环需要普通任务重新筹办、把 `被动动作` 放入候选集、等待学习补入口、等待人工触发，或缺少必要参数 / 状态 / 权限，则该链不满足被动动作定义。

## 1. 定义

系统内部不再单独创建“因果记录”结构。自我内部生成的因果信息统一表达为：

```text
动作动态节点
```

其中“方法动作动态”表示：

```text
某个方法，在某个场景下，
对某个主体的某个特征，
造成了一次可记录事实。
```

方法动作动态不以“成功 / 失败”作为根概念。`成功 / 失败` 只能作为普通结果特征、兼容字段或派生判断。动作动态本体应优先记录：

```text
方法运行了什么。
作用主体是什么。
作用特征是什么。
输入场景是什么。
输出场景是什么。
事实类型是什么。
相位是什么。
如果中断，中断原因是什么。
```

如果变化没有对应方法，只能落为：

```text
观察动态
外部事件动态
环境动态
未知来源动态
```

不能伪装成自我方法动作动态。

## 2. 动作来源规则

旧口径废止：

```text
哪个线程 / 层真实提交特征变化，哪个线程 / 层生成动作动态。
```

新口径：

```text
哪个域拥有提交权限，哪个域的线程负责编排调用对应提交类方法；
动作动态的动作来源必须是该方法。
```

| 域 | 编排者 | 必须对应的方法来源 | 变化内容 |
| --- | --- | --- | --- |
| 世界域 | 执行方法 / 世界树提交层 | 具体业务方法或提交类方法 | 真实世界事实、特征值、状态节点、动态事实 |
| 任务域 | 任务管理界面线程 | 任务域被动状态提交动作入口，来源方法固定为 `提交任务状态变化` | 任务状态 |
| 需求域 | 自我线程 | `派生需求入树`；来源需求收束后处理不生成动作动态 | 需求树、需求有效截止、需求权重刷新 |
| 方法域 | 学习 / 方法管理流程 | `提交方法状态变化`、`建立条件结果对` | 方法状态、条件结果对、学习产物 |

禁止：

```text
1. 新增任务完成因果记录结构。
2. 新增需求满足因果记录结构。
3. 新增世界事实因果记录结构。
4. 用输出结果场景承载任务状态动作动态。
5. 由任务管理工作线程生成已提交的任务状态方法动作动态。
6. 由自我线程生成任务状态方法动作动态。
7. 由线程直接作为方法动作动态来源。
```

补充边界：

```text
不是所有治理过程、推理过程或筹办过程都需要方法化。

只读查询、因果反推、候选筛选、诊断、评分、排序、预测、回执整理、候选镜像同步等中间过程，
如果不直接持久写入方法、任务、需求或世界树的特征状态，
可以由普通逻辑代码实现，不生成方法动作动态。

只有当流程进入持久提交段，
例如写任务状态、写需求入树、写方法状态、写方法动作入口、写世界事实特征，
才需要明确动作来源，并按上级规范生成或串接方法动作动态。

2026-06-04 修订：

```text
写需求有效截止、最近结算任务、最近结算时间和父子权重刷新属于任务价值反馈后的来源需求收束后处理。
该后处理不再生成 需求满足动作动态，也不再要求 回写需求满足 方法来源。
```

任务回执同步、候选集镜像、当前方法镜像和执行回执整理属于被动整理动作。它们必须退回生命周期普通代码，不是主链状态变化，不应生成主链动作动态，也不得进入普通候选方法集、学习目标或自我动作组合反推候选。

条件结果对属于方法状态可用的证据。若学习流程需要持久提交条件结果对，应由 `建立条件结果对` 承接并记录证据；但主链仍以 `方法状态` 是否可用为驱动，不以“条件结果配对状态”作为独立主链状态。
```

2026-05-23 补充：

```text
被动筹办动态、被动执行过程动态、被动诊断动态只能用于：
    调试；
    复盘；
    解释为什么生成子需求或任务；
    构造因果候选；
    审计过程。

它们不能直接证明：
    需求已经满足；
    服务值应该增加；
    安全值应该增加；
    任务状态已经改变；
    方法状态已经改变。

正式证明必须来自：
    对象作用方法动态；
    提交动作动态；
    输出结果场景中的结果状态变化；
    来源需求收束状态；
    因果归因结果；
    价值结算入口。

被动动态只负责留痕，不负责结算。
```

## 3. 三通道边界

本能函数继续遵守三通道：

```text
运行存在 / 函数返回回执：
    给任务管理层使用，承载任务层含义。

输出结果场景：
    给世界树提交层使用，只承载世界事实。

方法虚拟存在：
    给方法自身使用，只承载方法记忆和运行账。
```

动作动态生成位置不改变三通道语义。

任务筹办 / 任务执行是任务管理生命周期普通函数，只产出过程结果和任务层回执。任务管理界面线程读取过程结果后，可以调用回执同步类入口整理任务账；只有当任务状态发生正式变化时，才调用任务域被动状态提交动作入口，并由来源方法 `提交任务状态变化` 把任务域变化落成任务状态方法动作动态。

## 4. 动作动态链

动作动态之间应通过特征形成链式解释能力，而不是创建新因果结构。

建议复用或补充以下特征入口：

```text
来源动作动态
上游动作动态
满足证据动态
触发任务
来源需求
来源运行存在
来源输出结果场景
```

标准链路：

```text
世界事实动作动态
    -> 任务状态动作动态
        -> 需求状态动作动态
```

示例：

```text
D0 = 服务业务 / 世界事实动作动态
D1 = 提交任务状态变化动作动态
G0 = 成功服务治理视图
D2 = 服务值结算动作动态

D1.来源动作动态 = D0
G0.来源动作动态 = D0
G0.任务状态动态 = D1
G0.现实证据 = 输出结果场景中的实际结果状态 / 服务对象反馈 / 验证反馈
D2.来源动作动态 = D1
D2.来源治理判断 = G0
D2.满足证据动态 = D0 / 输出结果场景中的实际结果状态 / 验证反馈事实
```

G0 是内部治理判断视图，不是方法动作动态。D2 只能证明服务值如何入账，不能反向证明 D0 构成成功服务。

## 4.1 与因果补完流程的关系

本规范中的“动作动态就是因果账本”表示：系统内部事实与证据首先落在动作动态及其来源链上，不再为任务完成、需求满足、世界事实变化另造并行因果记录。

当这些动态证据进入因果学习或因果抽象时，必须遵守：

```text
规范/因果补完流程规范20260516.md
```

即：

```text
条件状态 + 动作 -> 结果状态
```

才是完整因果模板。若动态证据只有：

```text
初始状态 -> 结果状态
```

则只能生成状态变化线索，不能直接生成完整因果模板。

因此：

```text
动作动态链 = 事实账本和证据来源。
状态变化线索 = 待补动作的变化线索。
完整因果模板 = 从动态证据中补完出的因果知识结构。
```

完整因果模板不是任务 / 需求 / 世界事实的第二套账本；它是学习和筹办可使用的知识抽象。

因果链的正当用途，是组织自我已经实现的最小本能方法，形成可解释、可验证的复杂能力执行依据。

```text
因果链不是新的动作来源；
因果链不替代本能方法；
因果链不证明自我已经具备某个动作；
因果链只说明：哪些已实现本能方法，在什么条件、顺序和验收关系下，可以组合成复杂能力。
```

因此，因果链参与复杂能力组织时，链上每个动作节点都必须能落回一个已实现的本能方法或方法动作入口，并且该方法已经具备明确输入参数、明确输出结果和动作动态落账规则。若链上某段只有状态变化线索、外部事件或未知动作，不能直接纳入自我复杂能力，只能生成观察、学习、补动作入口或补条件结果对等需求。

被动状态动作产生的动作动态只能作为证据进入因果抽象。它不能反向生成新的主动动作；主动动作仍必须通过需求目标、任务状态、方法状态和方法能力查找来选择。

被动动作的标准因果桥形式是：

```text
上游动态 / 状态事实
-> 被动因正式出现
-> 被动果自动出现
-> 被动动作动态（统一动作动态结构）
-> 下游状态变化 / 二次特征
-> 因果信息 / 目标投影 / 需求候选材料
```

其中 `被动动作动态` 必须能回解动态主体、动态特征、初始状态、结果状态、来源低层动态和输入 / 输出事实场景。若这些字段缺失，只能作为弱审计证据，不能抽象成可用于解释、预测或需求投影的完整因果。

被动动作动态若要与某条状态迁移动态视为同一次事实的两种记录，必须满足同一存在、同一特征类型，并且被动动作动态的动作时间段被状态迁移动态的变化时间段包含。若它只记录任务、方法执行实例或提交函数自身的运行状态，而没有落到被提交事实的存在和特征类型上，则只能作为提交过程证据，不能直接当作同源动作致变动态。

因果抽象或学习流程读取到动作语义 `被动动作` 时，必须停止把该动态转成可调用动作模板；只能把它作为来源证据、状态变化证据、需求投影材料或审计证据。反推时得到的结果应是“需要哪些上游事实 / 条件 / 证据”，而不是“下一步调用被动动作”。

工程门禁必须同时检查动态类型、动作语义和来源方法语义。仅仅存在提交来源方法、结算来源方法或任务域 / 方法域提交入口，不足以证明该动态是主动动作致变动态；若动作语义为 `被动动作`，或该动态表达的是提交、同步、结算、回执整理等被动过程，则只能生成被动因果 / 状态变化因果 / 来源证据，不得生成可被方法筹办直接选择的主动动作致变因果。

## 6. 函数级注释要求

后续实现本规范时，新增或修改的函数必须写函数级注释，至少说明：

```text
1. 本函数属于哪个域：世界 / 任务 / 需求 / 方法。
2. 本函数是否调用或实现明确方法。
3. 本函数生成的动作动态以哪个方法为动作来源。
4. 本函数生成的动作动态记录哪一个特征变化。
5. 本函数生成的动作动态记录哪一种事实类型。
6. 本函数不得写哪些域。
7. 本函数的输入动态 / 输出动态链路字段来源。
```

注释示例：

```cpp
// 任务域提交动作：
// 本函数由任务管理界面线程调用，动作来源方法是“提交任务状态变化”。
// 它只提交任务状态旧值到新值，并生成任务状态方法动作动态。
// 不写需求树，不写世界事实，不替代工作线程回执。
```

## 7. 最终口径

```text
动作动态就是因果账本。
系统不再另造“因果信息”结构。
任务完成、需求满足、世界事实变化、方法学习结果，都落成各自域的动作动态。
其中凡是方法动作动态，都必须绑定一个可调用方法作为动作来源。
动作动态记录事实，不以成功 / 失败作为根分类。
动作动态是状态变化证据，不是下一步动作来源；下一步动作由需求状态、任务状态和方法状态重新驱动。
因果链用于组织已实现本能方法形成复杂能力；链上未知动作只能进入学习或观察，不能伪装成已实现能力。
被动状态动作动态中的 `被动动作` 是空占位动作，学习链必须将其判为不可主动调用。
```
