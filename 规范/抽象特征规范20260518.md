## 0. 与上级规范的关系

本规范用于收口 `011 特征类规范` 中抽象特征部分的字段、语义和值域规则。

若旧规范或旧代码仍保留：

```cpp
组合规则
生命周期
重叠命中次数
最近重叠命中时间
升格时间
```

这些字段不得继续作为抽象特征本体设计依据。后续实现应按本规范修订 `011` 主规范和对应代码，避免父子规范长期冲突。

## 1. 目标

抽象特征用于描述一类实例特征的归纳结果。

它不是具体观测值，而是对实例特征的结构、类型和值域的抽象表达。

抽象特征分为两类：

```cpp
叶子抽象特征
复合抽象特征
```

其中：

```cpp
叶子抽象特征 = 名称 + 特征类型 + 特征值域 + 来源实例特征
复合抽象特征 = 名称 + 特征类型 + 子特征结构 + 来源实例特征
```

复合抽象特征本身不携带特征值域。只有叶子抽象特征才携带特征值域。

## 2. 核心语义

### 2.1 叶子抽象特征

叶子抽象特征表示一个可以直接取值、比较、匹配的特征。

例如：

```cpp
安全等级
颜色编号
尺寸X
相对位置X
物体类别ID
```

叶子抽象特征必须有：

```cpp
特征类型
特征值域
来源实例特征
```

例如：

```cpp
安全等级 ∈ {0, 1, 2, 3}
尺寸X ∈ [10, 100]
物体类别ID ∈ {杯子, 桌子, 人}
```

### 2.2 复合抽象特征

复合抽象特征表示由多个子特征共同构成的结构特征。

例如：

```cpp
安全值
空间姿态
物体外观
行为状态
```

复合抽象特征只表达组成结构。它声明：

```cpp
父复合特征类型
直接子特征槽位名称
直接子特征类型
直接子特征结构
```

复合抽象特征本体不表达：

```cpp
关系
比较
推导
状态判断
```

这些内容由二次特征表达。

例如：

```cpp
安全值
├─ 安全等级      -> I64值域
├─ 安全来源      -> 指针句柄值域
└─ 生效范围      -> 复合特征
    ├─ 开始时间  -> I64值域
    └─ 结束时间  -> I64值域
```

其中：

```cpp
安全值
生效范围
```

都是复合抽象特征，不携带值域。

而：

```cpp
安全等级
安全来源
开始时间
结束时间
```

是叶子抽象特征，携带值域。

### 2.3 二次特征的定位

二次特征独立成类，但它也具有特征属性。

划分如下：

```cpp
普通特征：
    描述单个对象、场景、存在自身的属性。

复合特征：
    由多个普通子特征组成一个结构属性。

二次特征：
    描述特征与特征、存在与存在、对象与状态之间的关系。
```

例如：

```cpp
普通叶子特征：
    温度 = 80

复合特征：
    位姿 = {位置, 方向, 速度}

二次特征：
    A 与 B 的距离
    A 是否遮挡 B
    温度 与 安全阈值 的关系
    某存在是否处于危险状态
```

因此：

```cpp
危险状态
```

更适合作为二次特征或关系特征表达，而不是作为复合特征表达。

抽象特征规范中的复合抽象特征只负责声明组成结构。二次特征不作为普通复合抽象特征的子特征组合规则。

二次特征可以拥有自己的：

```cpp
名称
类型
值域
来源
比较方式
```

但这些由二次特征类自身规范，不混入复合抽象特征本体。

### 2.4 根特征定义视图

安全 / 服务这类根特征定义不改变抽象特征本体规则。

抽象特征节点本体仍只表达：

```text
名称；
类型；
叶子 / 复合形态；
值域或子特征结构；
来源实例特征。
```

根特征定义视图允许从抽象特征树读取额外规则：

```text
目标状态 / 目标区间；
最低阈值；
维持条件集 / 增加条件集；
缺口到需求的映射规则。
```

这些规则是围绕抽象根特征的定义材料，不是 `抽象特征主信息类` 的新增字段。实现时应优先用已有结构表达：

```text
抽象特征父子节点；
状态节点；
二次特征比较模板；
规则 / 因果节点；
运行期只读读取结构。
```

第一版自我根特征定义按 011003 执行：

```text
世界树.抽象特征树.安全定义
    -> 自我_安全值 的目标状态和维持条件。

世界树.抽象特征树.服务定义
    -> 自我_服务值 的目标状态和增加条件。
```

代码不得用硬编码函数表替代世界树中的定义节点；允许初始化代码显式创建默认定义。

### 2.5 需求目标语义定义视图

需求节点的逻辑组织语义由目标特征类型及其定义视图解释，不由需求树子节点数量或 `需求主信息类` 字段解释。

抽象特征节点本体仍只保存叶子 / 复合形态和值域 / 子特征结构；围绕某个目标特征的需求推进规则，应作为定义视图、规则节点、状态节点、二次特征或运行期只读视图表达。

第一版至少需要明确下列目标特征：

```text
AND组满足状态
OR组满足状态
方法路径完成状态
因果子链支撑状态
OR组结算令牌状态
```

这些目标特征的定义视图至少应能回答：

```text
是否逻辑组织节点；
是否可作为普通叶子需求任务化；
满足判定规则；
子节点聚合规则；
推进权重规则；
结算闸门规则。
```

推荐定义口径：

```text
AND组满足状态：
    所有子需求满足，则 AND组满足；
    组节点不可直接任务化；
    子项推进权重由运行期权重视图计算。

OR组满足状态：
    任一子路径满足，则 OR组满足；
    组节点不可直接任务化；
    结算只能由一条路径领取令牌。

方法路径完成状态：
    路径内必要步骤满足后，路径完成；
    路径节点通常不可直接任务化。

因果子链支撑状态：
    表示中间目标对父需求的因果支撑；
    可用于解释和展开，不替代真实中间目标需求。

OR组结算令牌状态：
    表示 OR组结算预算是否已被某条路径领取；
    应作为状态 / 动态 / 二次特征或提交入口记录，不进入需求主信息字段。
```

因此，需求树物理结构仍是普通树：

```text
父需求 -> 子需求 -> 叶子需求
```

但每个节点的逻辑语义必须由目标特征类型背后的定义视图解释：

```text
叶子 / 非叶子看结构；
目标特征类型看语义；
抽象特征定义视图看规则。
```

## 3. 特征值定义

当前基础特征值定义为：

```cpp
using 特征值 = std::variant<
    std::monostate,
    I64,
    VecU句柄,
    指针句柄
>;
```

其中：

```cpp
std::monostate  // 显式空值
I64             // 整数值
VecU句柄        // 向量 / 集合类数据句柄
指针句柄        // 指向信息节点、对象、存在、语义实体等的句柄
```

注意：

```cpp
std::monostate
```

表示“显式空值”。

它不等于：

```cpp
值缺失
值域不存在
复合特征没有值域
```

这些概念必须分开。

## 4. 特征值域定义

### 4.1 值域不是单纯区间

原来的：

```cpp
std::optional<I64区间> 区间{};
```

表达能力不足。

抽象特征的值域应支持：

```cpp
空值值域
空集合值域
I64值域项集
VecU句柄允许集合
指针句柄抽象目标集
```

因此推荐使用：

```cpp
using 特征值域 = std::variant<
    空值值域,
    空集合值域,
    I64值域,
    VecU句柄值域,
    指针句柄值域
>;
```

## 5. 值域类型规范

### 5.1 值域类型由分支表达

v0.2 不再使用：

```cpp
无约束值域
枚举_特征值种类::任意
```

值域类型由 `特征值域` 的 variant 分支表达：

```cpp
空值值域      -> std::monostate
空集合值域    -> 不匹配任何值
I64值域       -> I64值域项
VecU句柄值域  -> VecU句柄
指针句柄值域   -> 指针句柄指向目标匹配允许目标抽象
```

特征值域只表达明确的允许集合。若只是“要求特征存在”，不应伪装成“任意值可匹配”的值域。

### 5.2 空值值域

```cpp
struct 空值值域 {
};
```

语义：

```cpp
只匹配 std::monostate。
```

它表示“这个叶子特征的值必须显式为空”。

它不表示：

```cpp
复合特征没有值域
当前值缺失
```

### 5.3 空集合值域

```cpp
struct 空集合值域 {
};
```

语义：

```cpp
不匹配任何值。
```

它通常用于约束推导失败、交集为空、规则矛盾等情况。

例如：

```cpp
[1, 10] ∩ [20, 30] = 空集合值域
```

它不应该作为普通抽象特征的默认值域。

### 5.4 I64区间

```cpp
struct I64区间 {
    std::optional<I64> 下界{};
    std::optional<I64> 上界{};

    bool 包含下界 = true;
    bool 包含上界 = true;
};
```

语义示例：

```cpp
下界 = 10, 上界 = 20, 包含下界 = true,  包含上界 = true   -> [10, 20]
下界 = 10, 上界 = 20, 包含下界 = false, 包含上界 = true   -> (10, 20]
下界 = nullopt, 上界 = 20                                  -> (-∞, 20]
下界 = 10, 上界 = nullopt                                  -> [10, +∞)
```

校验规则：

```cpp
如果 下界 和 上界 都存在，则 下界 <= 上界。
如果 下界 == 上界，则 必须同时包含下界和上界，否则该区间为空。
```

### 5.5 I64值域

```cpp
using I64值域项 = std::variant<
    I64,
    I64区间
>;

struct I64值域 {
    std::vector<I64值域项> 项集{};
};
```

语义：

```cpp
I64值域 = I64值域项集
```

其中：

```cpp
I64 是特征值。
I64区间 不是特征值，而是值域项。
```

例如：

```cpp
I64值域{
    .项集 = {
        I64{1},
        I64{3},
        I64{7},
        I64区间{.下界 = 10, .上界 = 20},
        I64区间{.下界 = 50, .上界 = 60}
    }
}
```

表示：

```cpp
值 ∈ {1, 3, 7} ∪ [10, 20] ∪ [50, 60]
```

因此：

```cpp
I64区间 可以作为 I64值域项集中的一项。
I64区间 不得称为“离散值集中的一个值”。
I64区间 不得被当作 特征值。
```

规范要求：

```cpp
I64值域 不表示“任意 I64”。
抽象特征值域不表达“任意 I64”。
```

如果：

```cpp
项集为空
```

则该 `I64值域` 是非法普通值域。

若确实要表达“不匹配任何 I64”，应使用：

```cpp
空集合值域{}
```

### 5.6 VecU句柄值域

```cpp
struct VecU句柄值域 {
    std::vector<VecU句柄> 允许句柄{};
};
```

语义：

```cpp
特征值必须是这些 VecU句柄 中的一个。
```

注意：

```cpp
VecU句柄值域
```

只约束句柄身份，不直接约束 VecU 内部内容。

以后若需要约束 VecU 内容，应另行扩展：

```cpp
VecU内容值域
```

而不是把 VecU 的内容规则塞进句柄值域里。

### 5.7 指针句柄值域

```cpp
struct 指针句柄值域 {
    std::vector<可解析引用<基础信息节点类>> 允许目标抽象{};
};
```

语义：

```cpp
当前指针句柄指向的对象，必须能够匹配其中某个抽象目标。
```

也就是说，`指针句柄值域` 不表示：

```cpp
允许这些具体裸指针
```

而表示：

```cpp
允许指向这些抽象目标
```

目标可以是：

```cpp
抽象存在
抽象特征
其他可作为抽象匹配目标的基础信息节点
```

例如：

```cpp
安全来源 -> 指向 抽象存在：传感器
关联特征 -> 指向 抽象特征：温度
责任对象 -> 指向 抽象存在：人
目标区域 -> 指向 抽象存在：区域
```

匹配时不是简单比较指针地址，而是：

```cpp
具体指针句柄 -> 解析出具体目标
允许目标抽象 -> 解析出抽象目标
判断具体目标是否符合该抽象目标
```

伪代码：

```cpp
bool 匹配指针句柄值域(
    指针句柄 当前值,
    const 指针句柄值域& 值域
)
{
    auto* 具体目标 = 解析指针句柄(当前值);
    if (!具体目标) {
        return false;
    }

    for (const auto& 抽象引用 : 值域.允许目标抽象) {
        auto* 抽象目标 = 解析引用(抽象引用);
        if (!抽象目标) {
            continue;
        }

        if (具体目标匹配抽象目标(具体目标, 抽象目标)) {
            return true;
        }
    }

    return false;
}
```

地址大小没有语义。指针句柄值域不得做地址区间，也不得把地址相等当作主要抽象匹配方式。

## 6. 同类型值集原则

值域中的多个值必须属于同一种特征值类型。

不推荐这样设计：

```cpp
struct 混合值域 {
    std::vector<特征值> 值集{};
};
```

因为它允许：

```cpp
{ I64{1}, I64{2}, VecU句柄{...}, 指针句柄{...} }
```

这会导致匹配、排序、归一化、哈希和去重全部变复杂。

推荐由类型结构保证同类型：

```cpp
I64值域       -> 只允许 I64值域项，即 I64 或 I64区间
VecU句柄值域  -> 只允许 VecU句柄
指针句柄值域   -> 只允许 可解析的抽象目标引用
空值值域      -> 只允许 std::monostate
```

其中：

```cpp
I64 是实例特征可直接持有的特征值。
I64区间 是值域项，不是实例特征值。
```

## 7. 抽象特征形态

抽象特征必须显式区分形态。

```cpp
enum class 枚举_抽象特征形态 : std::uint8_t {
    叶子,
    复合
};
```

语义：

```cpp
叶子：有值域
复合：没有值域，由子特征构成
```

不建议只通过“有没有子节点”判断叶子或复合。

原因：

```cpp
复合特征刚创建时可能还没有挂子特征
叶子特征可能临时挂辅助节点
非复合特征节点的子节点不一定全是子特征
节点可能延迟加载
```

因此：

```cpp
形态
```

是语义事实。

```cpp
子节点数量
```

是结构事实。

二者不能互相替代。

## 8. 抽象特征主信息类

推荐结构如下。字段名落地时可按现有代码命名适配，但语义不得改变。

```cpp
class 抽象特征主信息类 : public 基础信息基类 {
public:
    // 名称表示这个特征在父复合特征中的结构槽位。
    // 如果是根抽象特征，则表示自身名称。
    词性节点类* 名称 = nullptr;

    // 抽象特征的类型。
    // 类型由特征比较方式解释。
    词性节点类* 类型 = nullptr;

    // 叶子 / 复合。
    枚举_抽象特征形态 形态 = 枚举_抽象特征形态::叶子;

    // 只有叶子特征允许存在值域。
    // 复合特征必须为 std::nullopt。
    // 叶子特征创建后必须显式设置明确值域；默认空 optional 表示尚未完成结构初始化。
    std::optional<特征值域> 值域{};

    // 粗粒度溯源：这个抽象特征从哪些实例特征归纳得到。
    // 可以指向 特征节点主信息类、二次特征节点主信息类 等所在节点。
    // 只保留抽象特征整体来源，不表达值域项级来源。
    std::vector<可解析引用<基础信息节点类>> 来源实例特征{};

public:
    bool 是叶子特征() const noexcept
    {
        return 形态 == 枚举_抽象特征形态::叶子;
    }

    bool 是复合特征() const noexcept
    {
        return 形态 == 枚举_抽象特征形态::复合;
    }

    const 特征值域* 取值域() const noexcept
    {
        if (!是叶子特征()) {
            return nullptr;
        }

        if (!值域.has_value()) {
            return nullptr;
        }

        return &值域.value();
    }

    特征值域* 取可写值域() noexcept
    {
        if (!是叶子特征()) {
            return nullptr;
        }

        if (!值域.has_value()) {
            return nullptr;
        }

        return &值域.value();
    }

    void 设为叶子特征(特征值域 新值域)
    {
        形态 = 枚举_抽象特征形态::叶子;
        值域 = std::move(新值域);
    }

    void 设为复合特征()
    {
        形态 = 枚举_抽象特征形态::复合;
        值域.reset();
    }

    bool 校验结构() const noexcept
    {
        if (名称 == nullptr || 类型 == nullptr) {
            return false;
        }

        if (是叶子特征()) {
            return 值域.has_value();
        }

        if (是复合特征()) {
            return !值域.has_value();
        }

        return false;
    }
};
```

## 9. 值域为空的精确定义

必须区分以下三种状态：

```cpp
std::nullopt
空值值域{}
空集合值域{}
```

语义如下。

```cpp
std::nullopt
```

表示：

```cpp
该节点不适用值域。
```

只允许用于：

```cpp
复合抽象特征
```

```cpp
空值值域{}
```

表示：

```cpp
该叶子特征只匹配 std::monostate。
```

```cpp
空集合值域{}
```

表示：

```cpp
该叶子特征不匹配任何值。
```

通常表示推导矛盾，不作为默认状态。

### 9.1 存在性不进入值域

如果一个叶子特征只是“要求存在”，但不约束具体值，不应使用“无约束值域”表达。

v0.2 不提供“无约束值域”。存在性要求可暂时不纳入抽象特征值域规范，或后续另行定义：

```cpp
存在性特征
```

不要让这些语义混在同一个值域概念里：

```cpp
任意值都可匹配
任意类型都可匹配
只要求特征存在
值域暂未生成
```

## 10. 子特征结构规范

复合抽象特征的子特征不建议直接保存在主信息类中。

推荐通过世界链或基础信息节点树表达父子关系：

```cpp
抽象特征节点：安全值
├─ 抽象特征节点：安全等级
├─ 抽象特征节点：安全来源
└─ 抽象特征节点：生效范围
    ├─ 抽象特征节点：开始时间
    └─ 抽象特征节点：结束时间
```

也就是说：

```cpp
抽象特征主信息类
```

只描述自身语义。

子特征关系由节点层表达。

复合抽象特征节点的直接子节点，只能表示该复合抽象特征的组成子特征。

因此，在复合抽象特征节点下：

```cpp
父子关系 = 组成关系
```

不需要再增加：

```cpp
枚举_节点关系类型::子特征
```

来重复表达同一语义。

也就是说，若某个节点已经被声明为：

```cpp
形态 == 枚举_抽象特征形态::复合
```

则它的直接子节点不得用于表达：

```cpp
统计记录
生命周期记录
组合规则记录
来源实例记录
辅助说明节点
临时缓存节点
非子特征的管理节点
```

这些内容若确实需要，应放在外部管理器、索引层、来源引用字段、规则对象或明确的非子节点关系中，不得混入复合抽象特征的直接子链。

### 10.1 直接子特征名称

复合抽象特征的每个直接子特征必须具有名称。

该名称在父复合抽象特征内部表示结构槽位，不等同于全局特征类型名。

例如：

```cpp
安全值
├─ 槽位名：安全等级  -> 子特征类型：安全等级
├─ 槽位名：安全来源  -> 子特征类型：安全来源
└─ 槽位名：生效范围  -> 子特征类型：生效范围
```

同一父复合抽象特征下，直接子特征名称默认应唯一。

```cpp
父复合特征.直接子特征槽位名
```

是父内部结构键，用于：

```cpp
子特征定位
复合结构匹配
抽象模板与实例结构对齐
调试和错误报告
```

如果后续需要表达同名重复槽位、数组槽位、集合槽位或多实例槽位，应由额外匹配策略或节点关系类型显式声明；v0.2 不用同名子特征隐式表达重复结构。

### 10.2 创建与校验接口约束

复合抽象特征子链规则必须由创建接口或校验接口保证，不得依赖调用者“记得不要乱挂节点”。

创建接口在向复合抽象特征节点挂接直接子节点时，必须检查：

```cpp
1. 父节点是复合抽象特征。
2. 子节点主信息是抽象特征主信息。
3. 子节点具有父内槽位名称。
4. 同一父节点下槽位名称默认不重复。
```

校验接口至少应检查：

```cpp
bool 校验抽象特征子链(const 基础信息节点类* 节点)
{
    if (!节点) {
        return false;
    }

    auto* 主信息 = dynamic_cast<const 抽象特征主信息类*>(节点->主信息);
    if (!主信息) {
        return false;
    }

    if (!主信息->是复合特征()) {
        return true;
    }

    auto* child = 节点->子;
    if (!child) {
        return true;
    }

    auto* it = child;
    do {
        if (!dynamic_cast<const 抽象特征主信息类*>(it->主信息)) {
            return false;
        }

        if (!存在父内槽位名称(it)) {
            return false;
        }

        if (父内槽位名称重复(节点, it)) {
            return false;
        }

        it = it->下;
    } while (it && it != child);

    return true;
}
```

其中：

```cpp
存在父内槽位名称
父内槽位名称重复
```

是示意接口，具体实现可根据现有节点命名、语素入口或特征槽位字段落地。

这样可以避免主信息类中同时出现：

```cpp
子特征列表
世界树父子关系
链表父子关系
```

三套结构互相打架。

## 11. 结构合法性规则

### 11.1 叶子抽象特征合法条件

叶子抽象特征必须满足：

```cpp
形态 == 枚举_抽象特征形态::叶子
类型 != nullptr
值域.has_value() == true
```

叶子抽象特征可以没有子抽象特征。

若叶子抽象特征存在子节点，则这些子节点不应被解释为“子特征”，除非系统另有明确标记。

### 11.2 复合抽象特征合法条件

复合抽象特征必须满足：

```cpp
形态 == 枚举_抽象特征形态::复合
类型 != nullptr
值域.has_value() == false
```

复合抽象特征的值域必须为：

```cpp
std::nullopt
```

不得使用：

```cpp
空值值域{}
空集合值域{}
```

来表示“复合特征没有值域”。

若复合抽象特征已经挂接直接子特征，则还必须满足：

```cpp
每个直接子节点都是组成子特征
每个直接子节点的主信息都是抽象特征主信息
每个直接子特征都有父内槽位名称
同一父复合特征下直接子特征槽位名称默认唯一
```

复合抽象特征刚创建、尚未挂接子特征时，可以暂时没有子特征；但一旦挂接直接子特征，就必须满足上述组成关系、槽位名称和唯一性规则。

### 11.3 来源实例特征规则

```cpp
来源实例特征
```

只表示抽象特征整体的粗粒度归纳来源，不参与普通匹配。

它不应影响：

```cpp
值域判断
子特征匹配
特征类型判断
```

它可以用于：

```cpp
追溯抽象特征由哪些实例生成
重新归纳
调试
统计可信度
反向更新
```

但这些逻辑应放在归纳器、统计器或外部分析器中，不应污染抽象特征主信息类。

`来源实例特征` 不提供值域项级细溯源。也就是说：

```cpp
I64值域项
I64区间
VecU句柄值域中的某个句柄
指针句柄值域中的某个允许目标抽象引用
```

这些值域项内部不得携带来源字段。

如果需要追溯某个值域项来自哪次观察、哪个动态、哪个因果样本或哪个实例特征，应通过因果信息系统、动态链、归纳器记录或外部索引反查，不应把来源塞进 `特征值域` 结构。

## 12. 匹配规则

### 12.1 总体匹配入口

抽象特征匹配实例特征时，先按形态分流。

伪代码：

```cpp
bool 匹配抽象特征(
    const 抽象特征节点类& 抽象节点,
    const 特征节点类& 实例节点,
    const 特征比较策略& 比较策略
)
{
    auto* 抽象 = 取抽象特征主信息(抽象节点);
    if (!抽象) {
        return false;
    }

    if (抽象->是叶子特征()) {
        auto* 实例 = 取特征主信息(实例节点);
        if (!实例) {
            return false;
        }

        return 匹配叶子抽象特征(*抽象, *实例, 比较策略);
    }

    if (抽象->是复合特征()) {
        return 匹配复合抽象特征(抽象节点, 实例节点, 比较策略);
    }

    return false;
}
```

### 12.2 叶子特征匹配

叶子特征匹配条件：

```cpp
名称一致
特征类型一致
实例特征存在当前值
比较方式确认值域合法
比较方式确认实例值合法
实例值命中值域
```

伪代码：

```cpp
bool 匹配叶子抽象特征(
    const 抽象特征主信息类& 抽象,
    const 特征节点主信息类& 实例,
    const 特征比较策略& 比较策略
)
{
    if (抽象.名称 != 实例.名称) {
        return false;
    }

    if (抽象.类型 != 实例.类型) {
        return false;
    }

    if (!抽象.值域.has_value()) {
        return false;
    }

    if (!实例.当前值) {
        return false;
    }

    if (!比较策略.值域是否合法(*抽象.值域)) {
        return false;
    }

    if (!比较策略.特征值是否合法(实例.当前值)) {
        return false;
    }

    return 比较策略.特征值是否命中值域(
        实例.当前值,
        *抽象.值域
    );
}
```

默认规则：

```cpp
实例当前值缺失
```

不等于：

```cpp
std::monostate
```

因此：

```cpp
当前值缺失
```

默认不匹配：

```cpp
空值值域{}
```

只有实例值被明确解析成：

```cpp
std::monostate
```

时，才匹配：

```cpp
空值值域{}
```

### 12.3 复合特征匹配

复合特征不是一组松散条件，而是命名结构体。

例如：

```cpp
struct 位姿 {
    位置;
    方向;
    速度;
};
```

其中 `位置 / 方向 / 速度` 是父复合特征内部的结构槽位，不是可任选命中的条件项。

复合特征匹配条件：

```cpp
名称一致
特征类型一致
父节点没有值域
直接子特征按父内槽位名称逐一对齐
同名槽位的子特征类型一致
所有声明的组成子特征都匹配
```

因此，复合特征匹配规则固定为：

```cpp
1. 父特征名称一致。
2. 父特征类型一致。
3. 父节点没有值域。
4. 抽象复合特征声明的每个直接子槽位，候选复合特征中必须存在同名槽位。
5. 同名槽位对应的子特征类型必须一致。
6. 同名槽位对应的子特征必须按自身形态递归匹配。
7. 所有声明的组成子特征都必须匹配。
```

伪代码：

```cpp
bool 匹配复合抽象特征(
    const 抽象特征节点类& 抽象节点,
    const 特征节点类& 实例节点,
    const 特征比较策略& 比较策略
)
{
    auto* 抽象 = 取抽象特征主信息(抽象节点);
    auto* 实例 = 取特征主信息(实例节点);

    if (!抽象 || !实例) {
        return false;
    }

    if (!抽象->是复合特征()) {
        return false;
    }

    if (抽象->值域.has_value()) {
        return false;
    }

    if (抽象->名称 != 实例->名称) {
        return false;
    }

    if (抽象->类型 != 实例->类型) {
        return false;
    }

    for (auto* 抽象子 : 枚举直接子抽象特征(抽象节点)) {
        auto* 抽象子信息 = 取抽象特征主信息(*抽象子);
        if (!抽象子信息 || !抽象子信息->名称) {
            return false;
        }

        auto* 实例子 = 查找直接子特征_按名称(
            实例节点,
            抽象子信息->名称
        );

        if (!实例子) {
            return false;
        }

        if (!匹配抽象特征(*抽象子, *实例子, 比较策略)) {
            return false;
        }
    }

    return true;
}
```

也就是说：

```cpp
复合特征匹配 = 结构组成匹配
```

不得解释为：

```cpp
任意一个子特征命中
至少 N 个子特征命中
按子特征权重累计命中
```

候选复合特征若携带未被该抽象复合特征声明的额外观测信息，这些信息不得作为该复合结构的一部分参与匹配；若需要把额外信息纳入结构，应先在抽象复合特征中声明对应具名槽位。

槽位名称只在直接父复合特征内部判定唯一。不同父复合特征下可以使用相同槽位名称。

## 13. 不纳入抽象特征主信息类的字段

以下字段暂不应放入 `抽象特征主信息类`：

```cpp
组合规则
生命周期
重叠命中次数
最近重叠命中时间
升格时间
```

原因如下。

### 13.1 组合规则

复合关系已经由节点父子结构表达，并且其语义是“组成关系”。

以下规则不得作为复合抽象特征的基础匹配规则：

```cpp
至少命中 N 个
任意一个子特征命中
按权重匹配
排斥子特征
可选子特征
```

这些规则属于条件集合、评分器、任务选择器或外部策略，不属于复合抽象特征本体。

复合抽象特征的本体匹配只能按命名结构组成执行：

```cpp
父特征类型一致
子特征名称一致
子特征类型一致
所有声明子特征递归匹配
```

因此，不仅不建议把组合规则塞进 `抽象特征主信息类`，也不得把它们作为复合抽象特征的默认匹配语义。

### 13.2 生命周期

生命周期属于抽象特征管理系统，而不是抽象特征本体。

例如：

```cpp
候选
稳定
废弃
冻结
```

这些是管理状态，不是特征定义。

应放入外部管理器或索引层。

### 13.3 重叠命中次数、最近重叠命中时间

这些是统计字段。

它们属于：

```cpp
归纳器
匹配器
统计器
缓存层
```

不属于抽象特征定义本身。

### 13.4 升格时间

升格是生命周期管理行为。

不应污染抽象特征结构定义。

## 14. 示例：安全值

### 14.1 结构

```cpp
安全值

├─ 安全来源

    ├─ 开始时间
    └─ 结束时间
```

### 14.2 安全值，复合抽象特征

```cpp
抽象特征主信息类 安全值{};

```

语义：

```cpp
安全值本身没有值域。
安全值通过子特征表达内容。
```

### 14.3 安全等级，叶子抽象特征

```cpp
抽象特征主信息类 安全等级{};

安全等级.设为叶子特征(
```

语义：

```cpp
开始时间 >= 0
```

## 15. 推荐最小实现版本

如果当前只想先落地，不做复杂策略，可以先实现下面这些：

```cpp
enum class 枚举_抽象特征形态 : std::uint8_t {
    叶子,
    复合
};

struct 空值值域 {
};

struct 空集合值域 {
};

struct I64区间 {
    std::optional<I64> 下界{};
    std::optional<I64> 上界{};

    bool 包含下界 = true;
    bool 包含上界 = true;
};

using I64值域项 = std::variant<
    I64,
    I64区间
>;

struct I64值域 {
    std::vector<I64值域项> 项集{};
};

struct VecU句柄值域 {
    std::vector<VecU句柄> 允许句柄{};
};

struct 指针句柄值域 {
    std::vector<可解析引用<基础信息节点类>> 允许目标抽象{};
};

using 特征值域 = std::variant<
    空值值域,
    空集合值域,
    I64值域,
    VecU句柄值域,
    指针句柄值域
>;
```

然后：

```cpp
class 抽象特征主信息类 : public 基础信息基类 {
public:
    // 名称表示这个特征在父复合特征中的结构槽位。
    // 如果是根抽象特征，则表示自身名称。
    词性节点类* 名称 = nullptr;

    // 类型由特征比较方式解释。
    词性节点类* 类型 = nullptr;

    枚举_抽象特征形态 形态 = 枚举_抽象特征形态::叶子;

    std::optional<特征值域> 值域{};

    std::vector<可解析引用<基础信息节点类>> 来源实例特征{};

public:
    bool 是叶子特征() const noexcept
    {
        return 形态 == 枚举_抽象特征形态::叶子;
    }

    bool 是复合特征() const noexcept
    {
        return 形态 == 枚举_抽象特征形态::复合;
    }

    const 特征值域* 取值域() const noexcept
    {
        if (!是叶子特征()) {
            return nullptr;
        }

        if (!值域.has_value()) {
            return nullptr;
        }

        return &值域.value();
    }

    void 设为叶子特征(特征值域 新值域)
    {
        形态 = 枚举_抽象特征形态::叶子;
        值域 = std::move(新值域);
    }

    void 设为复合特征()
    {
        形态 = 枚举_抽象特征形态::复合;
        值域.reset();
    }

    bool 校验结构() const noexcept
    {
        if (名称 == nullptr || 类型 == nullptr) {
            return false;
        }

        if (是叶子特征()) {
            return 值域.has_value();
        }

        if (是复合特征()) {
            return !值域.has_value();
        }

        return false;
    }
};
```

## 16. 规范总结

抽象特征的最终规则压缩如下：

```cpp
1. 抽象特征分为叶子和复合。
2. 抽象特征必须有名称和类型。
3. 名称表示父复合特征内的结构槽位；根抽象特征的名称表示自身名称。
4. 类型由特征比较方式解释。
5. 叶子抽象特征必须有值域。
6. 复合抽象特征必须没有值域。
7. 复合关系由节点父子结构表达。
8. 复合抽象特征节点的直接子节点只能表示组成子特征。
9. 复合抽象特征的父子关系本身就是组成关系，不再新增“子特征关系类型”重复表达。
10. 复合抽象特征的每个直接子特征必须有父内槽位名称。
11. 同一父复合特征下，直接子特征槽位名称默认唯一。
12. 复合抽象特征直接子链规则必须由创建接口或校验接口保证。
13. 复合抽象特征只表达组成结构；关系、比较、推导、状态判断由二次特征表达。
14. 二次特征独立成类，不作为普通复合抽象特征的子特征组合规则。
15. 危险状态、遮挡关系、距离关系、阈值关系等关系性事实应优先由二次特征表达。
16. 值域必须保持同类型，不使用 std::vector<特征值> 混装。
17. std::nullopt 表示“不适用值域”，只给复合特征用。
18. 抽象特征值域只表达明确允许集合，不提供无约束值域。
19. 空值值域表示“只匹配 std::monostate”，只给叶子特征用。
20. 只要求特征存在时，不进入抽象值域规范，后续可另行定义存在性特征。
21. 来源实例特征只做溯源，不参与普通匹配。
22. 来源实例特征只保留抽象特征整体粗溯源；值域项来源不进入特征值域结构。
23. 值域项细溯源需要通过因果信息系统、动态链、归纳器记录或外部索引反查。
24. 生命周期、命中次数、升格时间等管理统计字段不放进抽象特征本体。
25. 安全 / 服务根特征的目标状态、必要条件和缺口映射属于根特征定义视图，不进入抽象特征主信息字段。
26. 需求逻辑组织语义属于目标特征定义视图；AND / OR / 因果子链 / 方法路径组和 OR结算令牌不得新增为需求主信息字段，也不得混入抽象特征主信息字段。
```

最终抽象特征模型是：

```cpp
抽象特征
├─ 叶子抽象特征
│  ├─ 类型
│  ├─ 值域
│  └─ 来源实例特征
│
└─ 复合抽象特征
   ├─ 类型
   ├─ 子抽象特征节点
   └─ 来源实例特征
```

这版结构足够轻，不会过早把统计、生命周期、组合策略揉进本体里；同时也给后续扩展留了位置。
