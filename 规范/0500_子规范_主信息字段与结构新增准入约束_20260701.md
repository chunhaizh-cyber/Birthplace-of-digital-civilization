## 2. 上级约束

1. 本规范服从 `规范/规范目录.md`、0050 总纲、0300 冲突清单和对应根规范。
2. 历史来源中与当前根规范冲突的表述不进入当前权威口径。
3. 旧名称、旧结构和旧阶段口径必须按 `规范/0300_规范冲突与前后矛盾清单_20260701.md` 的 C001-C008 收束，不得在本规范中恢复历史并列结构、旧字段身份或旧执行来源。
4. 任务筹办 / 任务执行只作为任务管理生命周期普通函数；动作来源、方法注册和方法选择必须服从 0050 总纲、3200 任务根规范、3300 方法根规范和 1170 动态根规范。
5. 文本、日志、注释、临时 JSON、自由字段和显示摘要不得承载正式机器逻辑或业务状态。

## 3. 当前有效规则

以下条款由历史来源按当前根规范修订抽取；若条款与第 2 章或上级规范冲突，以上级规范和第 2 章为准。

1. 被动整理动作必须退回普通代码。
2. 只保留为历史解释示例；当前实现不得把它们作为本能方法、主链动作动态来源或可学习动作语义。
3. 安全评估结果由安全性评估方法生成，优先作为输出结果场景、执行回执视图或短期评估状态缓存。
4. 不得把安全度、伤害可能性、风险值、服务值、伤害次数、最近伤害时间等写成抽象存在或具体存在主信息的常驻权威字段。
5. 动态路径签名、来源字段、缓存字段只能作为来源追踪、排序、去重或显示辅助；
6. 不得替代场景、存在、特征、变化四根抽象链，
7. 不得新增“变化”平行结构、变化枚举或变化签名作为动态抽象的权威字段。
8. 新增结构体或字段前，必须先判断它是否符合本项目的底层逻辑。
9. 凡是可以用上述底层逻辑表达的内容，不得新增平行字段或平行结构。
10. 不得因为上层业务好描述，就在主信息类里新增业务语义字段。
11. 新增结构体按默认禁止处理。凡是用于承载业务语义、治理判断、状态集合、特征组合、需求准入、任务回执、方法结果、因果缺口、安全 / 服务判断的持久结构体，都必须先证明已有项目通用结构无法承载；证明不足时不得新增。
12. 新建布尔型特征类型前，必须先判断它是否只是多个更细特征判定后的综合结论。若是综合状态，不得裸建“是否 / 已 / 可 / 成功 / 明确 / 开 / 关 / 连接”等叶子特征，必须展开其包含的子特征集合、各子特征值域、判定规则、写入方、来源动态和验证方式。

## 4. 使用边界

1. 本规范用于计划、详细设计、代码修改和验收前的规则回读。
2. 本规范不能作为代码实现完成、业务闭环完成、自我苏醒完成或初步成熟完成的证据。
3. 需要展开历史论证时，只能把 `规范/旧规范/` 中的原文件作为追溯材料，不得让旧文件反向覆盖本规范。
