2026-05-29 安全因果口径修订：

```text
本文中的“基础风险判断”只表示当前阶段对安全影响因果是否具备足够证据的兼容命名。
它不是出生期安全因素表，也不是固定风险因子加权公式。

安全检查不定义风险。
安全检查只产生事实。
因果模块根据事实形成安全影响候选。
价值模块只在因果归因足够时投影安全值。
```

2026-05-31 风险判断来源口径修订：

```text
当前风险判断读取负向安全因果信息。
历史直接伤害如果发生，应先沉淀为“曾经直接伤害自我”的负向因果信息。
运行时不绕开因果信息另查一套历史伤害表。

没有负向因果信息时，当前风险判断默认安全。
这就是“无知者无畏”的当前推进口径：
    不因未知而堵塞需求树和任务推进；
    后续若出现真实直接伤害或负向归因，再生成 / 更新负向因果信息并重评估。

默认安全只表示当前风险判断和筹办路径可以继续；
不等于写入永久安全事实，不等于关闭被动更新入口，不等于直接结算自我安全值。
```

基础观察或场景集合尚未形成时的正确口径是：

```text
基础输入不足
-> 不能生成稳定评估视图
-> 不允许直接升高安全值
-> 需要观察和持续验证
```

基础输入已经具备、但没有读到负向因果信息时，不再按未知阻塞，当前风险判断走默认安全。

2026-05-29 安全数据存储口径补充：

```text
存在中只记录原始事实数据。
安全度、伤害可能性、场景安全度、最低安全存在等，由安全性评估方法按因果信息和原始事实临时生成。

存在 = 事实底稿
评估方法 = 解释器
安全度 = 评估结果
```

不得把所有评估结论都做成存在的常驻特征，否则系统会把“上一次判断”误当成“对象本体事实”。

安全信息拆成三层：

```text
抽象规则：
    保存为因果模板 / 抽象因果信息。

具体证据：
    保存为具体存在、场景、状态、动态、二次特征、因果实例和证据动态样本。

评估结果：
    由 安全_评估当前场景安全性 临时生成。
```

抽象存在只作为概念模板、分类身份和适用范围，不保存动态历史、不保存安全评估结果、不保存伤害记忆。

特征分三类：

```text
原始事实特征：
    可以记录在存在 / 场景 / 动态 / 因果实例中。
    例如存在被观察到、出现时间、离开时间、当前可观察状态、与自我共处时间段、动作动态、交互动态、自我安全相关状态变化、时间关系和证据动态。

评估型派生特征：
    由安全性评估方法生成，不常驻记录在存在本体。
    例如存在对自我直接伤害可能性候选、存在对自我安全度候选、伤害可能性下界候选、连续无伤害共处时长、评估置信度、当前场景安全度、当前场景最低安全度存在、当前场景风险状态。

账务型特征：
    只能由结算入口写入。
    例如自我_安全值、自我_服务值。
```

第一版原始事实底稿至少覆盖：

```text
存在级原始事实：
    存在_最近被观察时间；
    存在_当前是否在场景中；
    存在_出现过的场景引用；
    存在_当前可观察状态；
    存在_与自我共处时间段；
    存在_最近动作动态引用；
    存在_与自我交互动态引用。

自我级原始事实：
    自我_安全值状态变化；
    自我_运行状态变化；
    自我_资源状态变化；
    自我_权限边界变化；
    自我_异常状态变化。

场景级原始事实：
    场景_存在集合；
    场景_观察时间；
    场景_观察来源；
    场景_观察置信度；
    场景_动态集合；
    场景_状态变化集合。

因果级证据事实：
    某存在出现 / 动作 / 状态变化；
    某自我安全相关特征下降；
    时间顺序成立；
    替代原因集合；
    归因置信度；
    因果实例是否验证；
    证据动态样本。
```

评估结果若确需持久引用，只能作为带来源、输入场景、证据引用、生成时间和有效期的评估状态缓存，不得写成“存在永久自带该安全度”。

## 1. 定案

`基础风险判断状态 == 已明确` 不是第一阶段观察闭环的直接目标。

第一阶段最多先达到：

```text
当前观察帧.基础观察事实可用状态 等于 可用
```

只有在进一步读取原始事实、构造安全因果候选、运行安全性评估并满足证据阈值后，才允许进入：

```text
自我所在场景.基础风险判断状态 等于 已明确
```

像素级 100% 只表示当前帧内像素可寻址、可回查、无遗漏、无重复；不表示已经理解稳定真实对象，也不表示风险已经判断。

本文所有写入实例节点的 `已建立 / 已取得 / 已覆盖 / 已完成 / 已完备 / 新鲜 / 可用 / 已明确` 等枚举型实例特征值，都必须按 `枚举型实例特征值合法来源规范20260526.md` 追溯到合法生产者、输入证据、判定标准、输出宿主、输出特征和动作动态 / 来源动态 / 规则证据。枚举值域定义本身不需要通过本能方法获取。

一句话：

```text
已明确不是看见了一帧，而是证据够了、因子全了、不确定度低了、风险值算出来了。
```

## 2. 第一阶段：基础观察事实可用

基础观察事实可用目标为：

```text
当前观察帧.基础观察事实可用状态 等于 可用
```

第一阶段必须拆成三层，不得把 `当前观察帧存在状态` 做成过重状态。

### 2.1 观察帧存在已建立

这是帧容器成立：

```text
自我所在场景.当前观察帧存在状态 等于 已建立
```

只表示：

```text
自我所在场景中已经创建一个当前观察帧存在；
该观察帧存在有来源外设、帧宽、帧高、帧号、预期像素数量等基本元信息；
该观察帧存在可以承载后续像素观察存在。
```

不要求此时所有像素观察存在都已经生成。

当且仅当这些比较成立：

```text
当前观察帧.来源外设 等于 双目相机
当前观察帧.所属上下文 等于 自我所在场景
当前观察帧.帧宽度 大于 0
当前观察帧.帧高度 大于 0
当前观察帧.预期像素数量 等于 当前观察帧.帧宽度 * 当前观察帧.帧高度
当前观察帧.彩色帧号状态 等于 已取得
当前观察帧.深度帧号状态 等于 已取得，若本轮观察需要深度
当前观察帧.创建动作动态状态 等于 已记录
```

合法生产者：

```text
自我_建立观察帧存在
```

输入：

```text
双目相机_取得当前观察特征帧 的输出
自我所在场景
来源外设
帧宽度
帧高度
彩色帧号
深度帧号
```

输出：

```text
自我所在场景.当前观察帧存在状态 等于 已建立
```

该旧字段仅按兼容口径解释为观察帧容器成立。后续新实现优先使用更明确的枚举特征：

```text
当前观察帧.观察帧容器状态 等于 已建立
```

不要把它与下列事实完备目标混在一起：

```text
当前观察帧.观察事实完备状态 等于 已完备
```

`观察事实完备状态 等于 已完备` 至少依赖：

```text
当前观察帧.像素覆盖状态 等于 已覆盖
当前观察帧.像素特征值承接状态 等于 已完成
当前观察帧.坐标回查可用状态 等于 可用
当前观察帧.帧内编号回查可用状态 等于 可用
```

### 2.2 像素观察存在覆盖已完成

这是每个像素都有对应的像素观察存在：

```text
当前观察帧.像素覆盖状态 等于 已覆盖
```

标准是：

```text
当前观察帧.像素观察存在数量 等于 当前观察帧.预期像素数量
当前观察帧.缺失像素数量 等于 0
当前观察帧.重复映射数量 等于 0
当前观察帧.坐标回查可用状态 等于 可用
当前观察帧.帧内编号回查可用状态 等于 可用
```

这里的存在是：

```text
像素观察存在
```

不是稳定外部对象。

合法生产者：

```text
自我_建立像素观察存在集合
```

第一版如果沿用既有方法名，可由：

```text
自我_建立像素观察事实索引
```

承接，但输出状态必须写成 `当前观察帧.像素覆盖状态 等于 已覆盖`，不得继续把像素覆盖混入 `当前观察帧存在状态 等于 已建立`。

### 2.3 像素特征值承接已完成

这是每个像素观察存在上有对应的颜色、深度有效性、深度值、空间坐标等特征值：

```text
当前观察帧.像素特征值承接状态 等于 已完成
```

最低标准：

```text
每个像素观察存在.颜色R值状态 等于 已取得
每个像素观察存在.颜色G值状态 等于 已取得
每个像素观察存在.颜色B值状态 等于 已取得
每个像素观察存在.深度有效性值状态 等于 已取得
```

如果本阶段要求深度：

```text
深度有效性 等于 1 的像素:
    像素观察存在.深度值 大于 0

深度有效性 等于 0 的像素:
    像素观察存在.深度值状态 等于 无效
```

如果本阶段要求空间坐标：

```text
深度有效性 等于 1 的像素:
    像素观察存在.空间坐标X值状态 等于 已取得
    像素观察存在.空间坐标Y值状态 等于 已取得
    像素观察存在.空间坐标Z值状态 等于 已取得
```

如果空间坐标暂未实现：

```text
当前观察帧.空间坐标承接状态 等于 条件不足
```

或：

```text
当前观察帧.空间坐标承接状态 等于 待补齐
```

此时不得写：

```text
当前观察帧.像素特征值承接状态 等于 已完成
```

合法生产者：

```text
自我_承接像素特征值
```

### 2.4 当前观察新鲜度

`新鲜` 也必须由合法生产者或合法判定规则计算，不得手写。当前口径下，新鲜度作为观察材料承接和基础观察事实可用性判定中的时效证据，不要求登记独立 `自我_判断当前观察帧新鲜度` 本能方法。

目标：

```text
自我所在场景.当前观察新鲜度状态 等于 新鲜
```

当且仅当：

```text
自我所在场景.当前观察帧存在状态 等于 已建立
当前观察帧.采集时间 大于 0
当前观察帧.观察年龄 小于 当前需求.最大允许观察年龄
当前观察帧.失效状态 等于 未失效
当前观察帧.来源外设状态 等于 可追溯
```

合法来源：

```text
观察材料承接链中的当前观察帧新鲜度判定规则
自我_判断基础观察事实可用性中的时效证据判定
```

若历史文档或日志中出现 `自我_判断当前观察帧新鲜度`，只按兼容旧名或内部判定规则解释，不得据此新增独立本能方法、方法头、候选方法或方法动作动态。

输入：

```text
当前观察帧
当前时间
最大允许观察年龄
当前需求类型，安全 / 服务 / 内部世界细分
```

输出：

```text
当前观察帧.观察年龄
自我所在场景.当前观察新鲜度状态 等于 新鲜 / 过期
```

成立条件全部用三比较表达：

```text
自我所在场景.当前观察特征帧取得状态 等于 已取得
自我所在场景.当前观察帧存在状态 等于 已建立
当前观察帧.像素覆盖状态 等于 已覆盖
当前观察帧.像素特征值承接状态 等于 已完成
当前观察帧.观察事实完备状态 等于 已完备
当前观察帧.质量可用状态 等于 可用
自我所在场景.当前观察新鲜度状态 等于 新鲜
```

这一阶段只能证明：

```text
自我拥有一份可用的当前观察事实。
```

不得证明或暗示：

```text
基础风险判断状态 等于 已明确
基础风险值已计算
基础风险等级已确定
场景安全
稳定真实对象已理解
```

## 3. 第二阶段：基础风险判断已明确

基础风险判断状态是派生枚举型实例特征值，兼容解释为“当前场景安全影响因果评估状态”。它不得由单一观察帧存在、像素覆盖、质量可用或任何预设危险对象直接推出。

正式目标为：

```text
自我所在场景.基础风险判断状态 等于 已明确
```

当且仅当以下三比较条件全部成立：

```text
自我所在场景.基础风险评估范围状态 等于 已确定
自我所在场景.基础风险评估范围类型 等于 当前观察帧可见范围
当前观察帧.基础观察事实可用状态 等于 可用
当前观察帧.观察年龄 小于 最大允许风险判断观察年龄
当前观察帧.质量可用状态 等于 可用
当前场景.场景存在集合明确状态 等于 已明确
自我.关键特征变化观察状态 等于 已建立
自我所在场景.安全因果候选构造状态 等于 已构造
自我所在场景.基础风险未判断因子数量 等于 0
自我所在场景.基础风险证据完整度 大于 最低基础风险证据完整度
自我所在场景.基础风险不确定度 小于 最大允许基础风险不确定度
自我所在场景.基础风险值计算状态 等于 已计算
```

其中 `基础风险值计算状态 等于 已计算` 第一版应由 `安全_评估当前场景安全性` 或等价安全性评估对象作用方法产生；旧名 `自我_判断基础风险状态` 只作为兼容别名，不得被解释为只读判断函数或线程逻辑。

第一版风险评估范围只采用：

```text
当前观察帧可见范围
```

不得混入：

```text
自我近距安全范围
执行器作用范围
当前服务目标区域
```

这些范围可作为后续扩展，但必须以独立范围类型和独立评估口径进入。

## 4. 基础风险必要因子

基础风险必要因子不再解释为“哪些东西危险”的固定列表。它们只是安全因果验证所需的事实类别。第一版至少包含：

```text
1. 观察依据可用性；
2. 观察新鲜度；
3. 观察质量；
4. 当前场景存在集合明确度；
5. 自我关键特征影响前 / 影响后状态可比性；
6. 时间顺序证据；
7. 归因证据和替代原因覆盖度；
8. 未解释区域比例。
```

对应统计特征为：

```text
自我所在场景.基础风险必要因子总数
自我所在场景.基础风险已判断因子数量
自我所在场景.基础风险未判断因子数量
```

已明确的必要条件为：

```text
自我所在场景.基础风险未判断因子数量 等于 0
```

如果当前系统尚未实现当前场景存在集合识别、自我关键特征变化跟踪、时间顺序证据或归因候选构造，则不得写：

```text
自我所在场景.基础风险判断状态 等于 已明确
```

只能写成：

```text
自我所在场景.基础风险判断状态 等于 条件不足
```

或：

```text
自我所在场景.基础风险判断状态 等于 证据不足
```

## 5. 证据完整度、不确定度和风险值

风险证据完整度值域：

```text
0 ~ 1000000
```

第一版建议阈值：

```text
最低基础风险证据完整度 = 800000
```

成立条件：

```text
自我所在场景.基础风险证据完整度 大于 最低基础风险证据完整度
```

风险不确定度值域：

```text
0 ~ 1000000
```

第一版建议阈值：

```text
最大允许基础风险不确定度 = 200000
```

成立条件：

```text
自我所在场景.基础风险不确定度 小于 最大允许基础风险不确定度
```

基础风险值口径：

```text
0 = 当前证据下未预测到负向安全影响
1000000 = 当前证据下预测到极高负向安全影响
```

基础风险值不是固定因素加权求和。它是自我基于当前场景存在、历史影响、时间稳定性和归因证据，对“该场景在未来一段时间内是否会负向影响自我关键特征”的预测值。因果信息属于被动获取证据；历史直接伤害若发生，应先生成或更新负向安全因果信息。没有收到负向因果证据时，不强求补齐因果链，不把“因果缺省”写成危险，也不派生负向处置。场景评估安全值范围是 `0..I64_MAX`，其中 `I64_MAX` 只表示当前评估下无已知负向因果压力 / 场景绝对安全，条件不足取 `I64_MAX / 4`，已证不安全取 `0`。存在风险安全值按具体存在分别评估；若没有可回查历史风险值，历史值必须为 `0`，无负向因果证据时风险压力候选为 `0`，不能用固定常量伪造历史风险。默认良好不是已证永远安全，只表示当前没有被动获得的负向因果证据；后续若出现真实直接伤害、负向变化和归因证据，再更新负向因果信息、风险压力、处置需求和风险安全值投影。

风险安全采用层间十进衰减、同层因素平分规则。风险安全层第一版因素集合版本为 `风险安全层v1`：

```text
1. 场景影响部分
2. 运行影响部分
3. 资源影响部分
4. 权限影响部分
5. 未知影响部分
```

风险安全层值为五项安全方向子项平均：

```text
风险安全 =
平均(
    风险安全_场景影响部分,
    风险安全_运行影响部分,
    风险安全_资源影响部分,
    风险安全_权限影响部分,
    风险安全_未知影响部分
)
```

风险安全层再按第二层权重进入自我安全值候选：

```text
自我安全值候选 += 风险安全 * 0.09
```

因此 `风险安全_场景影响部分` 对自我安全值候选的最大直接权重为：

```text
0.09 / 5 = 0.018
```

场景评估安全值本身是 `风险安全_场景影响部分` 的候选值，不再额外乘 `0.09`。外层风险安全层的 `* 0.09` 负责层级衰减。

### 5.1 安全性评估方法

方法名：

```text
安全_评估当前场景安全性
```

方法类型：

```text
安全对象作用方法。
```

它可以进入任务候选方法集，因为它不是任务筹办算法函数，而是真正用于满足安全事实需求的对象作用方法。

可满足的需求包括：

```text
当前场景安全度明确状态
当前场景最低安全度存在明确状态
当前场景各存在安全评估明确状态
基础风险判断状态 / 风险状态明确状态
```

旧需求兼容解释：

```text
风险状态明确状态
= 当前场景风险安全影响评估结果已生成；
  当前场景最低安全度存在作为诊断 / 处置线索已明确。
```

输入条件：

```text
1. 当前场景存在集合明确。
2. 自我存在明确。
3. 场景中存在的原始观察事实可读。
4. 自我安全相关原始状态变化可读。
5. 因果信息库可读。
6. 历史动作动态 / 状态动态 / 因果实例证据可读。
```

如果当前场景存在集合未知，则该方法不能直接完成，应返回或保持缺口：

```text
需求：当前场景存在集合明确
候选对象作用方法：安全_观察当前场景 / 安全_识别场景存在集合
```

动作过程：

```text
1. 读取当前场景存在集合。
2. 对每个存在 E，读取原始事实：
       E 是否在当前场景；
       E 出现时间；
       E 与自我共处时间段；
       E 的动作动态；
       E 的状态变化动态；
       自我安全值下降事件；
       自我安全相关特征下降事件；
       与 E 有关的因果实例和证据动态。
3. 对每个 E 计算：
       是否曾经被归因为直接造成自我安全值下降；
       最近一次归因伤害时间；
       归因成立次数；
       共处且无伤害的持续时间；
       伤害可能性下界候选；
       当前直接伤害可能性候选；
       当前对自我安全度候选；
       评估置信度和证据不足原因。
4. 对所有存在按同层因素平分规则聚合：
       场景风险压力值 = 平均(所有已确认存在的风险压力候选)；
       风险安全_场景影响部分 = I64_MAX - 场景风险压力值；
       当前场景评估安全值候选 = 风险安全_场景影响部分。
5. 同时保留诊断线索：
       当前场景最低安全度存在 = argmin(所有存在的安全度候选)。
6. 生成安全评估输出结果场景。
```

评估规则：

```text
曾经造成实质伤害：
    若存在 E 曾经被归因为直接造成自我安全值下降，
    则 E 的直接伤害可能性下界候选 > 0。

随时间推移降低可能性：
    若 E 长时间与自我共处且没有新的归因伤害，
    则 E 的直接伤害可能性候选下降。
    若 E 曾经造成过实质伤害，下降不得低于非零下界候选。

再次伤害提高可能性：
    若 E 再次被归因为直接造成自我安全值下降，
    则 E 的直接伤害可能性候选上升，非零下界候选可以上升。

没有负向因果默认安全：
    若当前没有读取到 E 对自我造成直接伤害的负向因果信息，
    则 E 的直接伤害可能性候选按 0 处理。
    这不是“E 已证永远安全”，只表示当前风险判断不因未知而阻塞。
    后续若真实伤害或归因证据出现，应先生成 / 更新负向因果信息，再重评估。
```

场景安全度计算口径：

```text
存在安全度(E)
= 安全刻度上限 - 存在直接伤害可能性(E)

场景存在风险压力
= 平均(场景中所有已确认存在的直接伤害可能性候选)

风险安全_场景影响部分
= I64_MAX - 场景存在风险压力

当前场景评估安全值候选
= 风险安全_场景影响部分

当前场景最低安全度存在
= argmin(场景中所有存在安全度(E))
```

`当前场景最低安全度存在` 是诊断 / 处置线索，不再单独决定整个场景安全值；场景中多个已确认存在属于同层影响因素，应按平均值聚合。若当前场景定义中存在数量为 `N`，每个存在对 `风险安全_场景影响部分` 的最大直接权重为 `1 / N`，再经风险安全层 v1 的五项平均后，对自我安全值候选的最大直接权重为 `0.09 / (5 * N)`。

## 安全因果风险树

`安全因果风险树` 是当前安全目标在当前上下文中，沿安全因果信息反向展开后形成的运行期因素树。它也可简称为 `安全风险树`，但完整口径必须保留“因果”二字：这棵树来自因果链反推，不是预设风险表、不是抽象存在字段、不是需求树、不是任务树，也不是价值账。

```text
因果信息 = 抽象规则 / 路线图
因果反推算法 = 展开过程
安全因果风险树 = 本轮上下文中的展开结果
安全因果层证据搜索 = 验证树节点的证据动作
提交入口 = 将节点结果正式写入因素值或默认满足状态
```

安全因果风险树的用途是：

```text
1. 给任务筹办提供“当前安全目标需要查哪些层 / 哪些因素”的运行期解释面。
2. 给 `安全_搜索安全因果因素证据` 提供层级、因素ID、证据方向和搜索范围来源。
3. 给安全因果层聚合函数提供父子关系、同层因素集合和公式版本。
4. 给诊断解释“为什么某因素未搜索、默认满足、扣分或不可聚合”。
```

安全因果风险树的建立输入为：

```text
当前安全目标 / 来源需求
当前安全上下文
当前场景
因果信息库
当前事实视图
已提交的安全因素值 / 默认满足状态
```

安全因果风险树必须支持一条从自我定义自然推出的场景特征值缺口链：

```text
自我需要维护自身安全值
-> 自我安全值依赖多层安全因果链
-> 风险安全层是第二层安全因果信息
-> 风险安全层 v1 由场景影响、运行影响、资源影响、权限影响、未知影响五个同层因素平分聚合
-> 风险安全_场景影响部分依赖当前场景风险安全值
-> 当前场景风险安全值依赖当前场景已确认存在集合及各存在风险安全值
-> 存在风险安全值依赖该存在当前特征值、历史动态、自我关键特征变化观察、因果归因证据和无负向证据搜索结果
-> 当前场景中相关特征值未知时，场景影响因果条件不可判断
-> 因果条件不可判断时，场景影响部分不能入账，风险安全层不能聚合，自我安全值不能合法结算
-> 生成缺口报告：当前场景特征值明确状态 未满足
```

第一版遗传因果模板为：

```text
G1: 物理安全、风险安全、第三层安全因果链、第四层安全因果链 ... -> 自我安全值
G2: 场景影响、运行影响、资源影响、权限影响、未知影响 -> 风险安全层
G3: 当前场景风险安全值 -> 自我_风险安全_场景影响部分 -> 风险安全层
G4: 当前场景已确认存在集合、各存在风险安全值 -> 当前场景风险安全值
G5: 存在当前特征值、关键特征变化观察、历史动态、因果归因证据、无负向证据搜索结果 -> 存在风险安全值
G6: 安全_观察当前场景 -> 当前观察材料 -> 候选存在 -> 候选验证 -> 候选确认 -> 提交确认观察存在事实 -> 当前场景存在集合和相关特征值可评估
```

这不是“预设当前场景危险”，也不是把未知当危险；它只说明安全结算所需的因果条件尚未具备。未知既不能直接扣分，也不能直接默认安全。默认满足必须满足：

```text
没查过 != 默认满足
查过且无负向证据 = 可以经提交入口默认满足
特征值未知 = 证据搜索未完成或搜索前置材料缺口
```

建立过程为安全因果反推算法步骤，不是对象作用方法，也不是提交入口。运行期风险树由自我线程侧维护段持有和更新；任务筹办只有使用权，只能读取已有因果信息 / 已有风险树视图形成缺口报告、派生需求消息草案或参数化搜索输入草案，不得刷新树视图、创建风险树节点或写同步状态：

```text
1. 从当前安全目标的目标特征 / 目标状态出发。
2. 在因果信息中查找主果匹配目标特征或中间安全因素的因果链。
3. 沿因侧反推上级因素、同层因素和必要前置状态。
4. 为每个需要验证或聚合的因素生成运行期树节点。
5. 树节点记录层级、因素ID、上级因素ID、来源因果信息ID、反推路径、搜索规则、当前证据状态和入账状态。
6. 未搜索节点只产出缺口报告或参数化搜索子需求草案。
7. 真正生成子需求、登记任务意图、写默认满足或写因素值，仍由提交入口完成。
8. 搜索 / 提交结果回来后，安全因果风险树作为运行期视图重新展开或刷新，再向上聚合。
```

安全因果风险树可以由自我线程侧维护段保持同步。该维护段只在首次、输入变化或低频兜底触发时运行；主循环和任务筹办不等待风险树稳定。该维护段的职责只能是：

```text
反推更新安全因果风险树。
```

也就是说：

```text
安全因果链 / 安全上下文 / 当前场景 / 已提交因素值版本变化
-> 安全因果风险树同步状态过期
-> 自我线程侧维护段调用因果反推算法
-> 刷新安全因果风险树运行期视图、节点父子关系、同层因素集合、来源因果路径和缺口报告
-> 标记安全因果风险树同步状态
```

该常驻任务不得执行：

```text
证据搜索
默认满足提交
因素值提交
风险处置判断
风险安全层总值写入
自我安全值写入
需求满足回写
价值结算
```

如果安全因果风险树只作为运行期视图存在，常驻任务可以直接刷新本轮上下文缓存；如果需要持久化，也只能写入带来源因果、上下文版本、树版本、时间窗口和有效期的树视图状态 / 场景索引缓存，不得写成安全因素结论或价值账。

安全因果风险树节点表示“当前为了评估安全目标需要处理的因果因素”，不表示该因素已经危险，也不表示该因素已经默认满足。节点最少应包含：

```text
层级
因素ID
因素名称
上级因素ID
同层因素集合版本
来源因果信息ID
来源因果类型
反推路径摘要
证据搜索方向
证据搜索规则ID
搜索范围要求
当前搜索状态
当前入账状态
当前聚合状态
```

第一版安全因果风险树优先作为：

```text
运行期上下文
输出结果场景
只读诊断投影
筹办缺口报告
```

不得新增专用的安全风险树主信息账本。若后续确需持久引用，也只能作为带来源需求、来源因果、时间窗口、有效期和证据引用的状态 / 二次特征 / 场景索引缓存，不得写成抽象存在或具体存在的本体事实。

安全因果风险树与需求树的边界：

```text
安全因果风险树：
    说明当前安全目标沿因果链反推后有哪些因素需要查证。

需求树：
    只记录正式生成的“目标宿主上的目标特征达到目标状态”的需求。

筹办可从安全因果风险树发现缺口；
但缺口正式入树必须走提交_生成缺口子需求。

安全根需求下不得再由固定必要条件清单直接生成“确认自我运行状态 / 恢复资源状态 / 确认权限边界 / 取得基础观察事实 / 确认风险状态 / 恢复风险可控状态”等当前主动需求。若这些目标在当前轮确实需要推进，必须先成为安全因果风险树缺口、具体负向触发事实或来源因果信息下的可验证缺口，再经提交入口入树。
```

安全因果风险树与证据搜索的边界：

```text
安全因果风险树节点未搜索：
    只能说明该因素需要搜索。

安全_搜索安全因果因素证据：
    才能对该节点执行证据搜索并输出结果场景。

提交_安全因果因素无负证据默认满足 /
提交_安全因果因素证据评估值：
    才能将搜索结果正式转成因素值或默认满足状态。
```

缺失因素不得使其他因素自动变重。这里的“风险因素搜索”应提升为通用的：

```text
安全因果层证据搜索
```

原因是风险安全只是第二层安全因果信息里的负向影响证据；第三层、第四层和第 N 层也都有各自的因果信息、同层因素、负向证据、无负证据默认满足规则。因此核心搜索逻辑必须是通用函数，任务可选入口必须是参数化对象作用方法，正式入账仍走提交入口。

```text
通用函数：
搜索安全因果因素证据

对象作用方法：
安全_搜索安全因果因素证据

提交入口：
提交_安全因果因素无负证据默认满足
提交_安全因果因素证据评估值
```

任务筹办构造 `安全_搜索安全因果因素证据` 的输入包时，只能承接目标宿主、来源需求、来源因果或已提交事实中已经存在的参数：

```text
安全因果层级
目标安全因果信息
安全因果因素ID
安全因果证据方向
安全因果搜索时间窗口
搜索范围完整状态
证据数量 / 材料缺失数量 / 冲突数量 / 搜索置信度
```

筹办不得生成搜索结果、不得写默认满足、不得写因素值。第二层风险安全 v1 的固定因素可作为兼容便捷规则：因素ID已明确但层级缺失时可补 `层级 = 2`；层级 / 因素已明确但证据方向缺失时可补 `证据方向 = 负向`。搜索范围是否完整、是否无负向证据，必须由对象作用方法搜索事实给出。

第二层风险安全 v1 只是该通用机制的一个参数实例：

```text
层级 = 2
因果信息 = 风险安全层
因素 = 场景影响 / 运行影响 / 资源影响 / 权限影响 / 未知影响
证据方向 = 负向证据
```

默认满足的前提不是“没有数据”，而是“按该层该因素的证据搜索规则查过，并且没有找到负向证据”。因此：

```text
没查过 != 默认满足
查过但没找到负向证据 = 默认满足
查过但材料不足 = 本次搜索缺口 / 搜索不成立
查过且发现负向证据 = 按证据计算扣分
```

`材料不足` 不应成为安全因果因素的稳定业务状态；它只是搜索尝试失败或前置材料缺口，必须通过缺口回执 / 派生需求补材料后重跑。未搜索、搜索缺口、冲突未解、仅有候选视图但未提交，均不可作为该层可用值。

风险安全层 v1 每个因素的可用值来源只允许四类：

```text
1. 新评估入账值；
2. 合法沿用旧值；
3. 已搜索无负向证据并经提交入口入账的默认满足值 I64_MAX；
4. 已搜索有负向证据后计算并入账的扣分值。
```

风险安全层 v1 为了诊断仍记录第二层风险因素证据搜索掩码：

```text
0x01 = 场景影响部分
0x02 = 运行影响部分
0x04 = 资源影响部分
0x08 = 权限影响部分
0x10 = 未知影响部分

风险因素未搜索掩码
风险因素搜索缺口掩码
风险因素负向证据掩码
风险因素默认满足掩码
风险因素已入账掩码
```

只有当五个同层因素均有合法可用值，且没有未搜索、搜索缺口或冲突未解时，风险安全层可聚合状态才可写为已明确。当前若运行 / 资源 / 权限 / 未知四项未执行负向证据搜索，应显示：

```text
风险因素未搜索掩码 = 0x1E
风险因素默认满足掩码 = 0x00
风险因素证据搜索未完成数量 = 4
风险安全层可聚合状态 = 未明确
```

不得把这四项直接按默认满足或满值参与正式风险安全层入账。

`风险安全_场景影响部分` 从候选进入正式分量账时，还必须满足 C8 入账闸门：

```text
1. 来源需求存在；
2. 来源任务存在；
3. 来源因果信息存在，且能作为被动归因证据的一部分；
4. 安全评估对象作用动态存在；
5. 安全评估输出结果场景存在；
6. 场景存在集合明确；
7. 风险状态明确；
8. 证据不足原因 = 0；
9. 因素集合版本 / 聚合公式版本明确；
10. 候选值相对旧入账值的变化方向明确。
```

若目标宿主尚无旧的 `自我_风险安全_场景影响部分` 入账值，变化方向记为：

```text
初始入账
```

它不是上调，也不是下调；但仍必须满足来源需求、来源任务、被动归因证据和持续稳定性证据。诊断命令或裸方法调用缺少这些来源时，只能输出不可结算原因，不得把候选值直接提交为自我风险安全分量。

该计算结果由评估程序生成；不是场景原始事实，也不是存在原始事实。

风险值计算完成条件：

```text
自我所在场景.基础风险值计算状态 等于 已计算
```

风险是否可接受必须另立目标：

```text
自我所在场景.基础风险值 小于 最大允许基础风险值
```

不得把：

```text
基础风险判断状态 等于 已明确
```

等同于：

```text
场景安全
```

一个场景可以同时满足：

```text
自我所在场景.基础风险判断状态 等于 已明确
自我所在场景.基础风险值 大于 最大允许基础风险值
```

这表示风险很明确，而且很高。

## 6. 基础风险判断状态值域

`基础风险判断状态` 的建议值域为：

```text
未判断
条件不足
观察过期
观察质量不足
证据不足
必要因子未覆盖
已明确
```

风险等级若需要输出，应作为评估结果特征或短期评估状态缓存，不作为场景原始事实：

```text
自我所在场景.基础风险等级 等于 低风险
自我所在场景.基础风险等级 等于 中风险
自我所在场景.基础风险等级 等于 高风险
```

`基础风险判断状态` 只表示判断是否有足够证据成立；`基础风险值 / 基础风险等级` 表示本次评估结果中的风险高低，必须带来源方法、输入场景、证据引用和有效期。

## 7. 需求侧因果与派生消息口径

第一阶段不得直接派生：

```text
自我所在场景.基础风险判断状态 等于 已明确
```

当来源因果路径为 `自我安全值 -> 风险安全层 -> 场景影响部分 -> 当前场景风险安全值` 时，优先形成的缺口应是：

```text
当前场景.当前场景特征值明确状态 等于 已明确
```

该目标表示当前场景中与场景影响评估相关的已确认存在集合、各存在当前特征值、必要历史动态和因果证据具备可读材料。它不是风险已明确，也不是安全已结算。

若当前场景特征值不能从已提交场景缓存、已确认存在事实或交互者说明中取得，才继续派生观察材料路径，例如：

```text
当前观察帧.基础观察事实可用状态 等于 可用
```

本节定义的是需求侧 / 因果侧目标顺序，不是任务筹办器的领域特判规则。任务筹办只能在下列通用数据来源中读到该前置关系后，按 020005 生成派生需求消息草案：

```text
世界树因果条件；
需求侧条件；
候选方法条件节点；
条件结果对；
已入树子需求。
```

不得在任务筹办代码中按 `基础风险判断状态`、`风险状态明确状态` 或其他安全观察领域词硬编码生成 `当前观察帧.基础观察事实可用状态 等于 可用`。

派生需求消息字段为：

```text
目标宿主 = 当前观察帧
目标特征类型 = 基础观察事实可用状态
目标比较符 = 等于
目标值 = 可用
生成类型 = 条件补齐 / 证据补齐，按上级路径角色决定
```

随后再派生基础观察事实可用的子目标：

```text
自我所在场景.当前观察特征帧取得状态 等于 已取得
自我所在场景.当前观察帧存在状态 等于 已建立
双目相机.可用状态 等于 可用
双目相机.运行可用性值 大于 0
当前观察帧.像素覆盖状态 等于 已覆盖
当前观察帧.像素特征值承接状态 等于 已完成
当前观察帧.观察事实完备状态 等于 已完备
当前观察帧.质量可用状态 等于 可用
自我所在场景.当前观察新鲜度状态 等于 新鲜
```

上述 `已取得 / 已建立 / 已覆盖 / 已完成 / 已完备 / 可用 / 新鲜` 均是枚举型实例特征值，派生消息只能把它们作为目标值；实例取值本身必须由合法生产者写入，并记录输入证据、判定标准、输出宿主、输出特征和动作动态 / 来源动态 / 规则证据。像素数量、缺失数量、重复映射数量、坐标回查状态、帧内编号回查状态等比较，是 `自我_建立像素观察存在集合` 或兼容的像素索引方法推出 `像素覆盖状态 等于 已覆盖` 的内部成立证据，不应再混作第一层观察帧容器已建立。

这些目标闭合之后，才允许生成或推进基础风险判断目标：

```text
当前场景安全度明确状态 等于 已明确
当前场景最低安全度存在明确状态 等于 已明确
当前场景各存在安全评估明确状态 等于 已明确
自我所在场景.基础风险判断状态 等于 已明确
```

这些目标应由 `安全_评估当前场景安全性` 读取原始事实、因果信息和历史动态后生成评估结果视图。任务筹办不能把它们硬编码成固定前置链。

## 8. 禁止项

```text
1. 禁止用“已经观察了一帧”推出“基础风险判断状态 == 已明确”。
2. 禁止用“像素 100% 可回查”推出“基础风险判断状态 == 已明确”。
3. 禁止把观察质量可用状态等同于风险已判断。
4. 禁止把基础风险判断状态已明确等同于风险可接受或场景安全。
5. 禁止在当前场景存在集合、关键特征变化、时间顺序证据或归因候选缺失时写已明确。
6. 禁止把相机内部采集、对齐、滤波、分割步骤登记成自我层本能方法。
7. 禁止把补全深度、融合轮廓或未验证候选升级为基础风险已明确证据。
8. 禁止由普通线程、任务筹办普通函数、控制面板、日志解析器或只读快照直接写入 已建立 / 已取得 / 已覆盖 / 已完成 / 已完备 / 新鲜 / 可用 / 已明确 等枚举型实例特征值。
9. 禁止把本文的分层目标顺序实现为任务筹办器内部的安全观察专用能力；任务筹办只能读取需求、因果、方法条件或子需求数据来找条件。
10. 禁止把存在_对自我直接伤害可能性、存在_对自我安全度、伤害可能性下界、连续无伤害共处时长、当前场景安全度、当前场景最低安全度存在等评估型派生结果写成存在本体的常驻原始特征。
11. 禁止评估方法直接写自我_安全值或自我_服务值；账务型特征必须通过叶子任务价值结算入口写入。
```

## 9. 最终定义

```text
基础观察事实可用状态：
    表示当前观察帧已经具备可寻址、可回查、无遗漏、无重复且质量可用的观察事实。

基础风险判断状态：
    兼容解释为安全性评估状态。
    表示自我在确定评估范围内，拥有未过期、质量可用的观察依据，
    当前场景存在集合明确，
    各存在安全评估结果视图已生成，
    当前场景安全度和最低安全度存在已明确，
    证据完整度超过阈值，
    不确定度低于阈值，
    安全影响预测值 / 兼容基础风险值已经由安全评估方法计算完成。

安全评估结果：
    优先存在输出结果场景、运行期视图或任务执行回执中。
    若需要持久化，只能作为带来源方法、来源输入场景、证据引用、生成时间和有效期的评估状态缓存。
    不得写成存在或场景的永久本体事实。

账务结果：
    自我_安全值 / 自我_服务值只能由价值结算入口写入。
```

最短版：

```text
存在只存原始事实；
安全性评估生成本次解释结果；
价值结算才决定是否改变自我安全值。
```
