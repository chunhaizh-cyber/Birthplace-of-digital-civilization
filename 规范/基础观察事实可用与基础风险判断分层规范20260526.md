2026-05-29 安全因果口径修订：

```text
本文中的“基础风险判断”只表示当前阶段对安全影响因果是否具备足够证据的兼容命名。
它不是出生期安全因素表，也不是固定风险因子加权公式。

安全检查不定义风险。
安全检查只产生事实。
因果模块根据事实形成安全影响候选。
价值模块只在因果归因足够时投影安全值。
```

未知场景的正确口径是：

```text
场景影响未知
-> 场景安全度不可判定 / 低置信
-> 不允许直接升高安全值
-> 需要观察和持续验证
```

2026-05-29 安全数据存储口径补充：

```text
存在中只记录原始事实数据。
安全度、伤害可能性、场景安全度、最低安全存在等，由安全性评估方法按因果信息和原始事实临时生成。

存在 = 事实底稿
评估方法 = 解释器
安全度 = 评估结果
```

不得把所有评估结论都做成存在的常驻特征，否则系统会把“上一次判断”误当成“对象本体事实”。

安全信息拆成三层：

```text
抽象规则：
    保存为因果模板 / 抽象因果信息。

具体证据：
    保存为具体存在、场景、状态、动态、二次特征、因果实例和证据动态样本。

评估结果：
    由 安全_评估当前场景安全性 临时生成。
```

抽象存在只作为概念模板、分类身份和适用范围，不保存动态历史、不保存安全评估结果、不保存伤害记忆。

特征分三类：

```text
原始事实特征：
    可以记录在存在 / 场景 / 动态 / 因果实例中。
    例如存在被观察到、出现时间、离开时间、当前可观察状态、与自我共处时间段、动作动态、交互动态、自我安全相关状态变化、时间关系和证据动态。

评估型派生特征：
    由安全性评估方法生成，不常驻记录在存在本体。
    例如存在对自我直接伤害可能性候选、存在对自我安全度候选、伤害可能性下界候选、连续无伤害共处时长、评估置信度、当前场景安全度、当前场景最低安全度存在、当前场景风险状态。

账务型特征：
    只能由结算入口写入。
    例如自我_安全值、自我_服务值。
```

第一版原始事实底稿至少覆盖：

```text
存在级原始事实：
    存在_最近被观察时间；
    存在_当前是否在场景中；
    存在_出现过的场景引用；
    存在_当前可观察状态；
    存在_与自我共处时间段；
    存在_最近动作动态引用；
    存在_与自我交互动态引用。

自我级原始事实：
    自我_安全值状态变化；
    自我_运行状态变化；
    自我_资源状态变化；
    自我_权限边界变化；
    自我_异常状态变化。

场景级原始事实：
    场景_存在集合；
    场景_观察时间；
    场景_观察来源；
    场景_观察置信度；
    场景_动态集合；
    场景_状态变化集合。

因果级证据事实：
    某存在出现 / 动作 / 状态变化；
    某自我安全相关特征下降；
    时间顺序成立；
    替代原因集合；
    归因置信度；
    因果实例是否验证；
    证据动态样本。
```

评估结果若确需持久引用，只能作为带来源、输入场景、证据引用、生成时间和有效期的评估状态缓存，不得写成“存在永久自带该安全度”。

## 1. 定案

`基础风险判断状态 == 已明确` 不是第一阶段观察闭环的直接目标。

第一阶段最多先达到：

```text
当前观察帧.基础观察事实可用状态 等于 可用
```

只有在进一步读取原始事实、构造安全因果候选、运行安全性评估并满足证据阈值后，才允许进入：

```text
自我所在场景.基础风险判断状态 等于 已明确
```

像素级 100% 只表示当前帧内像素可寻址、可回查、无遗漏、无重复；不表示已经理解稳定真实对象，也不表示风险已经判断。

本文所有写入实例节点的 `已建立 / 已取得 / 已覆盖 / 已完成 / 已完备 / 新鲜 / 可用 / 已明确` 等枚举型实例特征值，都必须按 `枚举型实例特征值合法来源规范20260526.md` 追溯到合法生产者、输入证据、判定标准、输出宿主、输出特征和动作动态 / 来源动态 / 规则证据。枚举值域定义本身不需要通过本能方法获取。

一句话：

```text
已明确不是看见了一帧，而是证据够了、因子全了、不确定度低了、风险值算出来了。
```

## 2. 第一阶段：基础观察事实可用

基础观察事实可用目标为：

```text
当前观察帧.基础观察事实可用状态 等于 可用
```

第一阶段必须拆成三层，不得把 `当前观察帧存在状态` 做成过重状态。

### 2.1 观察帧存在已建立

这是帧容器成立：

```text
自我所在场景.当前观察帧存在状态 等于 已建立
```

只表示：

```text
自我所在场景中已经创建一个当前观察帧存在；
该观察帧存在有来源外设、帧宽、帧高、帧号、预期像素数量等基本元信息；
该观察帧存在可以承载后续像素观察存在。
```

不要求此时所有像素观察存在都已经生成。

当且仅当这些比较成立：

```text
当前观察帧.来源外设 等于 双目相机
当前观察帧.所属上下文 等于 自我所在场景
当前观察帧.帧宽度 大于 0
当前观察帧.帧高度 大于 0
当前观察帧.预期像素数量 等于 当前观察帧.帧宽度 * 当前观察帧.帧高度
当前观察帧.彩色帧号状态 等于 已取得
当前观察帧.深度帧号状态 等于 已取得，若本轮观察需要深度
当前观察帧.创建动作动态状态 等于 已记录
```

合法生产者：

```text
自我_建立观察帧存在
```

输入：

```text
双目相机_取得当前观察特征帧 的输出
自我所在场景
来源外设
帧宽度
帧高度
彩色帧号
深度帧号
```

输出：

```text
自我所在场景.当前观察帧存在状态 等于 已建立
```

该旧字段仅按兼容口径解释为观察帧容器成立。后续新实现优先使用更明确的枚举特征：

```text
当前观察帧.观察帧容器状态 等于 已建立
```

不要把它与下列事实完备目标混在一起：

```text
当前观察帧.观察事实完备状态 等于 已完备
```

`观察事实完备状态 等于 已完备` 至少依赖：

```text
当前观察帧.像素覆盖状态 等于 已覆盖
当前观察帧.像素特征值承接状态 等于 已完成
当前观察帧.坐标回查可用状态 等于 可用
当前观察帧.帧内编号回查可用状态 等于 可用
```

### 2.2 像素观察存在覆盖已完成

这是每个像素都有对应的像素观察存在：

```text
当前观察帧.像素覆盖状态 等于 已覆盖
```

标准是：

```text
当前观察帧.像素观察存在数量 等于 当前观察帧.预期像素数量
当前观察帧.缺失像素数量 等于 0
当前观察帧.重复映射数量 等于 0
当前观察帧.坐标回查可用状态 等于 可用
当前观察帧.帧内编号回查可用状态 等于 可用
```

这里的存在是：

```text
像素观察存在
```

不是稳定外部对象。

合法生产者：

```text
自我_建立像素观察存在集合
```

第一版如果沿用既有方法名，可由：

```text
自我_建立像素观察事实索引
```

承接，但输出状态必须写成 `当前观察帧.像素覆盖状态 等于 已覆盖`，不得继续把像素覆盖混入 `当前观察帧存在状态 等于 已建立`。

### 2.3 像素特征值承接已完成

这是每个像素观察存在上有对应的颜色、深度有效性、深度值、空间坐标等特征值：

```text
当前观察帧.像素特征值承接状态 等于 已完成
```

最低标准：

```text
每个像素观察存在.颜色R值状态 等于 已取得
每个像素观察存在.颜色G值状态 等于 已取得
每个像素观察存在.颜色B值状态 等于 已取得
每个像素观察存在.深度有效性值状态 等于 已取得
```

如果本阶段要求深度：

```text
深度有效性 等于 1 的像素:
    像素观察存在.深度值 大于 0

深度有效性 等于 0 的像素:
    像素观察存在.深度值状态 等于 无效
```

如果本阶段要求空间坐标：

```text
深度有效性 等于 1 的像素:
    像素观察存在.空间坐标X值状态 等于 已取得
    像素观察存在.空间坐标Y值状态 等于 已取得
    像素观察存在.空间坐标Z值状态 等于 已取得
```

如果空间坐标暂未实现：

```text
当前观察帧.空间坐标承接状态 等于 条件不足
```

或：

```text
当前观察帧.空间坐标承接状态 等于 待补齐
```

此时不得写：

```text
当前观察帧.像素特征值承接状态 等于 已完成
```

合法生产者：

```text
自我_承接像素特征值
```

### 2.4 当前观察新鲜度

`新鲜` 也必须由合法生产者或合法判定规则计算，不得手写。当前口径下，新鲜度作为观察材料承接和基础观察事实可用性判定中的时效证据，不要求登记独立 `自我_判断当前观察帧新鲜度` 本能方法。

目标：

```text
自我所在场景.当前观察新鲜度状态 等于 新鲜
```

当且仅当：

```text
自我所在场景.当前观察帧存在状态 等于 已建立
当前观察帧.采集时间 大于 0
当前观察帧.观察年龄 小于 当前需求.最大允许观察年龄
当前观察帧.失效状态 等于 未失效
当前观察帧.来源外设状态 等于 可追溯
```

合法来源：

```text
观察材料承接链中的当前观察帧新鲜度判定规则
自我_判断基础观察事实可用性中的时效证据判定
```

若历史文档或日志中出现 `自我_判断当前观察帧新鲜度`，只按兼容旧名或内部判定规则解释，不得据此新增独立本能方法、方法头、候选方法或方法动作动态。

输入：

```text
当前观察帧
当前时间
最大允许观察年龄
当前需求类型，安全 / 服务 / 内部世界细分
```

输出：

```text
当前观察帧.观察年龄
自我所在场景.当前观察新鲜度状态 等于 新鲜 / 过期
```

成立条件全部用三比较表达：

```text
自我所在场景.当前观察特征帧取得状态 等于 已取得
自我所在场景.当前观察帧存在状态 等于 已建立
当前观察帧.像素覆盖状态 等于 已覆盖
当前观察帧.像素特征值承接状态 等于 已完成
当前观察帧.观察事实完备状态 等于 已完备
当前观察帧.质量可用状态 等于 可用
自我所在场景.当前观察新鲜度状态 等于 新鲜
```

这一阶段只能证明：

```text
自我拥有一份可用的当前观察事实。
```

不得证明或暗示：

```text
基础风险判断状态 等于 已明确
基础风险值已计算
基础风险等级已确定
场景安全
稳定真实对象已理解
```

## 3. 第二阶段：基础风险判断已明确

基础风险判断状态是派生枚举型实例特征值，兼容解释为“当前场景安全影响因果评估状态”。它不得由单一观察帧存在、像素覆盖、质量可用或任何预设危险对象直接推出。

正式目标为：

```text
自我所在场景.基础风险判断状态 等于 已明确
```

当且仅当以下三比较条件全部成立：

```text
自我所在场景.基础风险评估范围状态 等于 已确定
自我所在场景.基础风险评估范围类型 等于 当前观察帧可见范围
当前观察帧.基础观察事实可用状态 等于 可用
当前观察帧.观察年龄 小于 最大允许风险判断观察年龄
当前观察帧.质量可用状态 等于 可用
当前场景.场景存在集合明确状态 等于 已明确
自我.关键特征变化观察状态 等于 已建立
自我所在场景.安全因果候选构造状态 等于 已构造
自我所在场景.基础风险未判断因子数量 等于 0
自我所在场景.基础风险证据完整度 大于 最低基础风险证据完整度
自我所在场景.基础风险不确定度 小于 最大允许基础风险不确定度
自我所在场景.基础风险值计算状态 等于 已计算
```

其中 `基础风险值计算状态 等于 已计算` 第一版应由 `安全_评估当前场景安全性` 或等价安全性评估对象作用方法产生；旧名 `自我_判断基础风险状态` 只作为兼容别名，不得被解释为只读判断函数或线程逻辑。

第一版风险评估范围只采用：

```text
当前观察帧可见范围
```

不得混入：

```text
自我近距安全范围
执行器作用范围
当前服务目标区域
```

这些范围可作为后续扩展，但必须以独立范围类型和独立评估口径进入。

## 4. 基础风险必要因子

基础风险必要因子不再解释为“哪些东西危险”的固定列表。它们只是安全因果验证所需的事实类别。第一版至少包含：

```text
1. 观察依据可用性；
2. 观察新鲜度；
3. 观察质量；
4. 当前场景存在集合明确度；
5. 自我关键特征影响前 / 影响后状态可比性；
6. 时间顺序证据；
7. 归因证据和替代原因覆盖度；
8. 未解释区域比例。
```

对应统计特征为：

```text
自我所在场景.基础风险必要因子总数
自我所在场景.基础风险已判断因子数量
自我所在场景.基础风险未判断因子数量
```

已明确的必要条件为：

```text
自我所在场景.基础风险未判断因子数量 等于 0
```

如果当前系统尚未实现当前场景存在集合识别、自我关键特征变化跟踪、时间顺序证据或归因候选构造，则不得写：

```text
自我所在场景.基础风险判断状态 等于 已明确
```

只能写成：

```text
自我所在场景.基础风险判断状态 等于 条件不足
```

或：

```text
自我所在场景.基础风险判断状态 等于 证据不足
```

## 5. 证据完整度、不确定度和风险值

风险证据完整度值域：

```text
0 ~ 1000000
```

第一版建议阈值：

```text
最低基础风险证据完整度 = 800000
```

成立条件：

```text
自我所在场景.基础风险证据完整度 大于 最低基础风险证据完整度
```

风险不确定度值域：

```text
0 ~ 1000000
```

第一版建议阈值：

```text
最大允许基础风险不确定度 = 200000
```

成立条件：

```text
自我所在场景.基础风险不确定度 小于 最大允许基础风险不确定度
```

基础风险值口径：

```text
0 = 当前证据下未预测到负向安全影响
1000000 = 当前证据下预测到极高负向安全影响
```

基础风险值不是固定因素加权求和。它是自我基于当前场景存在、历史影响、时间稳定性和归因证据，对“该场景在未来一段时间内是否会负向影响自我关键特征”的预测值。影响关系未知时应优先写入低置信、条件不足或证据不足，而不是写成高风险结论。

### 5.1 安全性评估方法

方法名：

```text
安全_评估当前场景安全性
```

方法类型：

```text
安全对象作用方法。
```

它可以进入任务候选方法集，因为它不是任务筹办算法函数，而是真正用于满足安全事实需求的对象作用方法。

可满足的需求包括：

```text
当前场景安全度明确状态
当前场景最低安全度存在明确状态
当前场景各存在安全评估明确状态
基础风险判断状态 / 风险状态明确状态
```

旧需求兼容解释：

```text
风险状态明确状态
= 当前场景中最低安全度存在及其直接伤害可能性评估明确。
```

输入条件：

```text
1. 当前场景存在集合明确。
2. 自我存在明确。
3. 场景中存在的原始观察事实可读。
4. 自我安全相关原始状态变化可读。
5. 因果信息库可读。
6. 历史动作动态 / 状态动态 / 因果实例证据可读。
```

如果当前场景存在集合未知，则该方法不能直接完成，应返回或保持缺口：

```text
需求：当前场景存在集合明确
候选对象作用方法：安全_观察当前场景 / 安全_识别场景存在集合
```

动作过程：

```text
1. 读取当前场景存在集合。
2. 对每个存在 E，读取原始事实：
       E 是否在当前场景；
       E 出现时间；
       E 与自我共处时间段；
       E 的动作动态；
       E 的状态变化动态；
       自我安全值下降事件；
       自我安全相关特征下降事件；
       与 E 有关的因果实例和证据动态。
3. 对每个 E 计算：
       是否曾经被归因为直接造成自我安全值下降；
       最近一次归因伤害时间；
       归因成立次数；
       共处且无伤害的持续时间；
       伤害可能性下界候选；
       当前直接伤害可能性候选；
       当前对自我安全度候选；
       评估置信度和证据不足原因。
4. 对所有存在取最小安全度：
       当前场景安全度 = min(所有存在的安全度候选)；
       当前场景最低安全度存在 = argmin(所有存在的安全度候选)。
5. 生成安全评估输出结果场景。
```

评估规则：

```text
曾经造成实质伤害：
    若存在 E 曾经被归因为直接造成自我安全值下降，
    则 E 的直接伤害可能性下界候选 > 0。

随时间推移降低可能性：
    若 E 长时间与自我共处且没有新的归因伤害，
    则 E 的直接伤害可能性候选下降。
    若 E 曾经造成过实质伤害，下降不得低于非零下界候选。

再次伤害提高可能性：
    若 E 再次被归因为直接造成自我安全值下降，
    则 E 的直接伤害可能性候选上升，非零下界候选可以上升。

没有历史不伪造安全：
    若 E 缺少足够历史证据，
    则 E 的安全评估状态 = 证据不足 / 低置信。
    这不是“E 危险”，只表示 E 不能作为场景安全提升证据。
```

场景安全度计算口径：

```text
存在安全度(E)
= 安全刻度上限 - 存在直接伤害可能性(E)

场景安全度
= min(场景中所有存在安全度(E))

场景直接伤害可能性
= max(场景中所有存在直接伤害可能性(E))
```

该计算结果由评估程序生成；不是场景原始事实，也不是存在原始事实。

风险值计算完成条件：

```text
自我所在场景.基础风险值计算状态 等于 已计算
```

风险是否可接受必须另立目标：

```text
自我所在场景.基础风险值 小于 最大允许基础风险值
```

不得把：

```text
基础风险判断状态 等于 已明确
```

等同于：

```text
场景安全
```

一个场景可以同时满足：

```text
自我所在场景.基础风险判断状态 等于 已明确
自我所在场景.基础风险值 大于 最大允许基础风险值
```

这表示风险很明确，而且很高。

## 6. 基础风险判断状态值域

`基础风险判断状态` 的建议值域为：

```text
未判断
条件不足
观察过期
观察质量不足
证据不足
必要因子未覆盖
已明确
```

风险等级若需要输出，应作为评估结果特征或短期评估状态缓存，不作为场景原始事实：

```text
自我所在场景.基础风险等级 等于 低风险
自我所在场景.基础风险等级 等于 中风险
自我所在场景.基础风险等级 等于 高风险
```

`基础风险判断状态` 只表示判断是否有足够证据成立；`基础风险值 / 基础风险等级` 表示本次评估结果中的风险高低，必须带来源方法、输入场景、证据引用和有效期。

## 7. 需求侧因果与派生消息口径

第一阶段不得直接派生：

```text
自我所在场景.基础风险判断状态 等于 已明确
```

应先派生：

```text
当前观察帧.基础观察事实可用状态 等于 可用
```

本节定义的是需求侧 / 因果侧目标顺序，不是任务筹办器的领域特判规则。任务筹办只能在下列通用数据来源中读到该前置关系后，按 020005 生成派生需求消息草案：

```text
世界树因果条件；
需求侧条件；
候选方法条件节点；
条件结果对；
已入树子需求。
```

不得在任务筹办代码中按 `基础风险判断状态`、`风险状态明确状态` 或其他安全观察领域词硬编码生成 `当前观察帧.基础观察事实可用状态 等于 可用`。

派生需求消息字段为：

```text
目标宿主 = 当前观察帧
目标特征类型 = 基础观察事实可用状态
目标比较符 = 等于
目标值 = 可用
生成类型 = 条件补齐 / 证据补齐，按上级路径角色决定
```

随后再派生基础观察事实可用的子目标：

```text
自我所在场景.当前观察特征帧取得状态 等于 已取得
自我所在场景.当前观察帧存在状态 等于 已建立
双目相机.可用状态 等于 可用
双目相机.运行可用性值 大于 0
当前观察帧.像素覆盖状态 等于 已覆盖
当前观察帧.像素特征值承接状态 等于 已完成
当前观察帧.观察事实完备状态 等于 已完备
当前观察帧.质量可用状态 等于 可用
自我所在场景.当前观察新鲜度状态 等于 新鲜
```

上述 `已取得 / 已建立 / 已覆盖 / 已完成 / 已完备 / 可用 / 新鲜` 均是枚举型实例特征值，派生消息只能把它们作为目标值；实例取值本身必须由合法生产者写入，并记录输入证据、判定标准、输出宿主、输出特征和动作动态 / 来源动态 / 规则证据。像素数量、缺失数量、重复映射数量、坐标回查状态、帧内编号回查状态等比较，是 `自我_建立像素观察存在集合` 或兼容的像素索引方法推出 `像素覆盖状态 等于 已覆盖` 的内部成立证据，不应再混作第一层观察帧容器已建立。

这些目标闭合之后，才允许生成或推进基础风险判断目标：

```text
当前场景安全度明确状态 等于 已明确
当前场景最低安全度存在明确状态 等于 已明确
当前场景各存在安全评估明确状态 等于 已明确
自我所在场景.基础风险判断状态 等于 已明确
```

这些目标应由 `安全_评估当前场景安全性` 读取原始事实、因果信息和历史动态后生成评估结果视图。任务筹办不能把它们硬编码成固定前置链。

## 8. 禁止项

```text
1. 禁止用“已经观察了一帧”推出“基础风险判断状态 == 已明确”。
2. 禁止用“像素 100% 可回查”推出“基础风险判断状态 == 已明确”。
3. 禁止把观察质量可用状态等同于风险已判断。
4. 禁止把基础风险判断状态已明确等同于风险可接受或场景安全。
5. 禁止在当前场景存在集合、关键特征变化、时间顺序证据或归因候选缺失时写已明确。
6. 禁止把相机内部采集、对齐、滤波、分割步骤登记成自我层本能方法。
7. 禁止把补全深度、融合轮廓或未验证候选升级为基础风险已明确证据。
8. 禁止由普通线程、任务筹办普通函数、控制面板、日志解析器或只读快照直接写入 已建立 / 已取得 / 已覆盖 / 已完成 / 已完备 / 新鲜 / 可用 / 已明确 等枚举型实例特征值。
9. 禁止把本文的分层目标顺序实现为任务筹办器内部的安全观察专用能力；任务筹办只能读取需求、因果、方法条件或子需求数据来找条件。
10. 禁止把存在_对自我直接伤害可能性、存在_对自我安全度、伤害可能性下界、连续无伤害共处时长、当前场景安全度、当前场景最低安全度存在等评估型派生结果写成存在本体的常驻原始特征。
11. 禁止评估方法直接写自我_安全值或自我_服务值；账务型特征必须通过叶子任务价值结算入口写入。
```

## 9. 最终定义

```text
基础观察事实可用状态：
    表示当前观察帧已经具备可寻址、可回查、无遗漏、无重复且质量可用的观察事实。

基础风险判断状态：
    兼容解释为安全性评估状态。
    表示自我在确定评估范围内，拥有未过期、质量可用的观察依据，
    当前场景存在集合明确，
    各存在安全评估结果视图已生成，
    当前场景安全度和最低安全度存在已明确，
    证据完整度超过阈值，
    不确定度低于阈值，
    安全影响预测值 / 兼容基础风险值已经由安全评估方法计算完成。

安全评估结果：
    优先存在输出结果场景、运行期视图或任务执行回执中。
    若需要持久化，只能作为带来源方法、来源输入场景、证据引用、生成时间和有效期的评估状态缓存。
    不得写成存在或场景的永久本体事实。

账务结果：
    自我_安全值 / 自我_服务值只能由价值结算入口写入。
```

最短版：

```text
存在只存原始事实；
安全性评估生成本次解释结果；
价值结算才决定是否改变自我安全值。
```
