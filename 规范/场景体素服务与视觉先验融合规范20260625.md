## 1. 目标

本规范定义当前场景体素只读服务、SceneVoxelPrior、合法外设材料融合层和 6145 / 6146 / 6147 / 6150 入口之间的权责边界。

核心口径：

```text
先验可以帮助看，不能替代看。
外设只供材料，自我组织，提交入口裁决。
场景体素服务只读发布快照，不写世界树事实。
视觉融合层只生成观察域候选、评分、解释和缺口，不直接确认事实。
```

## 2. 主链

正式链路如下：

```text
当前场景已确认存在 / 世界树事实
-> 场景体素只读服务
-> SceneVoxelPrior / 视野投影解释包
-> 外设报告队列
-> 质量门 / 合法外设材料
-> 视觉融合层读取合法材料 + SceneVoxelPrior
-> 观察域结果包
-> 6146 / 6150 / 6145 / 6147 按各自语义只读消费
-> 提交入口裁决后才写入世界树、场景、存在、特征或状态
```

任何实现不得让原始外设报告、场景体素快照或视觉先验绕过质量门、合法材料层和提交入口。

## 5. 强制规则

### RULE-VISION-PRIOR-001：场景体素快照不是事实源

场景体素服务只能从当前场景已确认存在、坐标、稳定体素等既有事实只读生成运行期快照。快照可用于检索、过滤、解释和显示，不得直接写世界树事实、需求满足、安全 / 服务结算或方法动作动态。

### RULE-VISION-PRIOR-002：视觉融合只产观察域结果

视觉融合层读取合法外设材料和 SceneVoxelPrior 后，只能输出观察域候选、评分、解释和结构化缺口。它不得直接创建存在、确认消失、写一阶特征、写需求满足或生成价值结算。

### RULE-VISION-PRIOR-003：业务入口不得绕过合法材料层

6145 / 6146 / 6147 / 6150 消费视觉先验时，必须先经过外设材料质量门、合法材料承接和观察域结果包。不得直接把原始 D455 报告、场景体素快照或 SceneVoxelPrior 当作事实输入。

### RULE-VISION-PRIOR-004：机器判断必须落项目结构

观察域结果包第一版可以是运行期结构，但凡要被任务筹办、扫描、识别、跟踪、提交入口或后续审计消费的判断，必须以 I64、枚举、VecU 句柄、指针句柄、运行存在特征或输出结果场景特征表达。自由文本只能用于日志、显示和人工说明。

### RULE-VISION-PRIOR-005：版本或坐标不匹配只能生成缺口

当场景体素版本、坐标系版本、外设帧时间、报告 ID、TTL 或 D455 到当前场景位姿证据不满足可接受条件时，业务入口只能降权、请求复验或写结构化缺口，不得入账为确认事实。

## 6. 入口分工

```text
6146 扫描：
    优先使用观察域结果包解释未覆盖、遮挡、视野外、深度缺失和自由空间冲突。
    不得把未覆盖直接写成消失事实。

6150 提交入口：
    负责检查观察域结果包的先验版本、坐标系版本、来源报告和可接受状态。
    版本过旧或证据不足时写结构化缺口，不入账。

6145 识别：
    只能把先验作为唯一性收敛辅助评分。
    识别仍只返回已有存在指针或空指针，不创建存在。

6147 跟踪：
    只能把先验作为目标 ROI、AABB 和丢失解释辅助。
    跟踪丢失不等于存在消失。
```

## 7. 验收证据边界

允许作为工程守卫证据：

```text
规范目录已挂载本规范。
规则原子和工程图谱已索引本规范。
场景体素模块构建通过。
快照版本、坐标系版本和只读查询可读。
观察域结果包字段使用项目结构类型。
Debug x64 构建通过。
```

不得作为业务闭合证据：

```text
单帧 D455 feed 成功。
OpenGL 或控制面板快照显示正常。
场景体素快照可生成。
构建通过。
人工伪造样本、夹具样本、模拟入口或旧日志。
```

业务闭合必须等待真实外设材料、自然任务链、提交入口裁决、状态 / 动态 / 因果证据形成同一窗口证据。
