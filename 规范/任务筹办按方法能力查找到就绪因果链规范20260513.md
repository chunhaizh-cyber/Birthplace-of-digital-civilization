## 1. 标准因果句式

本规范只适用于叶子任务，或已经被判定必须直接执行的原子任务。

父任务 / 汇总任务不以“找到单步本能方法 M”为就绪前提。父任务仍必须有方法承接，但该方法通常是复合方法 / 任务抽象方法：

```text
复合需求
    -> 复合特征分解
        -> 子需求
            -> 子任务
                -> 子结果归并
```

父任务的就绪依据可以是：

```text
子需求已经满足
子任务已经完成
子结果已经归并
等待条件已经解除
任务回执已经同步
```

只有普通可任务化叶子任务必须最终绑定可执行本能方法 / 可执行动作入口。

任务筹办按方法能力查找到普通可任务化叶子任务就绪，使用以下因果链模板：

```text
要普通可任务化叶子任务 T 就绪，
需要用本能方法 / 可执行动作入口 M。

因为方法 M 的结果能力能够改变：
    目标宿主 X 的目标特征 F

但方法 M 要可用于任务 T，
还需要条件 C1 / C2 / C3 成立。

所以需要派生更细需求 D_child，
让这些条件成立。

D_child 被子任务满足后，
父任务 T 重新筹办，
再次查找 / 绑定方法 M，
最终形成可就绪回执，
再由提交任务状态变化方法把任务状态推进到就绪。
```

## 2. 任务目标与适用范围

任务 `T` 来源于需求 `D`：

```text
D 的目标：

    目标宿主 = X
    目标特征类型 = F
    目标状态 = V_target
    满足关系 = R
```

也就是：

```text
需要让 X.F 达到 V_target。
```

如果 `T` 是父任务 / 汇总任务，则不要求直接找到本能方法。它应先检查：

```text
来源需求是否是复合需求；
是否可由复合特征分解出子需求；
是否已有子需求承接该目标；
是否已有子任务正在推进；
是否已有子结果可以归并；
是否需要等待或重筹办；
是否应把缺口继续生长成更细需求。
```

如果 `T` 是普通可任务化叶子任务，则要就绪必须找到一个本能方法 / 可执行动作入口：

```text
M.结果能力 能够产生 X.F -> V_target 相关结果。
```

这里的“叶子”只是结构前提，不是语义前提。进入本规范的方法筹办前，必须已经确认来源需求目标特征定义视图允许普通任务化。

不得把下列节点仅因当前没有子节点就送入本规范的候选方法查找：

```text
AND组满足状态
OR组满足状态
方法路径完成状态
因果子链支撑状态
结构性缺口目标
```

这些目标应先按其目标特征定义视图处理展开、聚合、路径选择、结算令牌或治理缺口。只有落到普通可任务化目标特征后，才按方法结果能力填充候选方法集。

这一步叫：

```text
按方法结果能力查找候选方法。
```

叶子任务查找依据不是方法名字，而是：

```text
哪个方法声明自己能够改变目标特征类型 F。
```

方法头只用于候选召回。真正执行仍必须看：

```text
条件节点
结果节点
条件结果对
方法虚拟存在
方法状态
```

任务筹办对普通任务、学习任务和练习任务采用同一套就绪判断规则。筹办只面向“当前方法”检查结构、条件和参数，不在筹办阶段展开另一个目标方法的参数规格。

```text
普通任务：
    当前方法 = 被执行的业务方法。

学习 / 练习任务：
    当前方法 = 自我_尝试学习 / 自我_练习。
    被学习 / 被练习的方法头节点，只是当前学习方法输入条件包中的一个参数：
        目标方法头节点 = 被补方法。
```

因此，学习任务不得因为“是学习任务”而跳过通用输入闭合，也不得在筹办中混用学习方法自身条件节点和目标方法条件节点。目标方法头节点的展开、探索参数构造和练习参数构造，只能发生在学习方法动作内部：

```text
自我_尝试学习：
    按目标方法头节点可展开的信息构造探索参数。

自我_练习：
    按目标方法已有条件节点 / 条件结果对构造练习参数。
```

候选方法选择必须先区分“可直接达成”与“可补齐推进”：

```text
可直接达成：
    方法自身条件全部满足，参数可绑定，禁止项未命中，结果能力确定命中目标。

可补齐推进：
    方法自身不能直接完成父任务目标，但能够推进目标方法的结构、条件结果对、参数或方法状态。
```

直接达成方法优先于可补齐推进方法。多个直接达成方法同时存在时，按：

```text
禁止项少
风险少
前置冲突少
效率高
耗时少
能耗少
资源占用少
副作用少
稳定性高
```

依次排序。

`任务筹办` 不能作为过程推进方法声明，也不能进入候选方法集：

```text
任务筹办不是本能方法；
任务筹办不是候选方法；
任务筹办不声明“目标方法.方法状态 -> 可用”的方法结果能力。
```

同理，任务筹办不能声明或内置具体领域目标的前置能力：

```text
不能声明“安全目标 -> 观察目标”的专用筹办能力；
不能声明“服务目标 -> 服务对象状态”的专用筹办能力；
不能声明“外设目标 -> 某外设控制链”的专用筹办能力。
```

这些前置关系只能通过 020005 临时因果视图、需求侧条件、候选方法条件节点或已入树子需求被任务筹办读取。

当来源需求目标是：

```text
目标方法.方法状态 -> 可用
```

在方法筹办阶段，任务筹办只负责单步查找、填充候选集、选择当前方法并形成回执。
候选方法应来自能够推进方法可用性的真实方法，例如：

```text
尝试学习
定向学习
练习
建立条件结果对
提交方法状态变化
```

其中能够直接推进当前阶段、且条件满足的方法优先。
`任务筹办` 本身不参与这次选择；它只在下一轮读取这些方法产生并回流的事实。

## 3. 直达就绪路径

如果存在方法 `M`：

```text
M.结果能力.结果项集 包含：
    特征类型 = F

并且：

M.方法状态 = 可用
M.有执行入口
M.有条件结果对
M.条件节点可由任务输入场景满足
M.参数可绑定
```

则因果链是：

```text
要普通可任务化叶子任务 T 就绪，
需要用方法 M。

因为方法 M 的结果能力能够作用于：
    X.F

并且方法 M 的条件已经满足：
    方法状态 = 可用
    执行入口存在
    条件结果对存在
    参数可绑定
    可执行输入参数场景可构造

所以任务筹办生成可就绪回执：
    当前方法 = M
    可执行输入参数场景 = S_exec
    筹办缺口类型 = 无
    建议任务状态 = 就绪
```

提交链：

```text
任务筹办
    -> 运行存在中形成“可就绪回执”

同步筹办回执到任务
    -> 写入任务虚拟存在：
        当前方法 = M
        可执行输入参数场景 = S_exec
        筹办缺口类型 = 无

提交任务状态变化
    -> 写入：
        T.任务状态 = 就绪
    -> 生成任务状态动作动态
```

## 4. 无既有候选方法路径

如果任务筹办按能力查找后发现：

```text
不存在结果能力命中 F 的方法
```

则不是失败，也不直接派生“存在一个方法”的抽象需求。
当前口径为：

```text
无候选 = 遍历完整方法树并完成候选集填充后，候选集为空。

无候选时，任务筹办必须立即在方法树中创建一个面向目标特征 F 的方法头，
把该方法加入候选集，并返回该方法作为本轮候选。
```

当前实现不得用 `自我_改变特征值` 填充候选集：

```text
`改变特征值` 是先天特征写入逻辑；
它不作为任务可选择方法；
也不作为动作动态来源。
```

因此候选查找必须寻找能解释目标特征变化的语义方法。若完整遍历后仍无候选，任务筹办创建面向目标特征 F 的占位方法头，将后续生长交给该方法的具体缺口，而不是用通用写入逻辑兜底。

占位方法头只解决：

```text
有候选方法可以承接目标特征类型 F。
```

它仍然要求：

```text
目标特征类型已确定；
目标宿主已确定；
执行差值或目标执行后值已确定；
执行差值 / 目标执行后值有可追溯出处；
差值约束能够校验。
```

所以：

```text
缺少改变量或改变量出处，不是“无候选方法”；
它是参数 / 条件补齐缺口。
```

应派生：

```text
确定执行差值或目标值
确定目标变化来源 / 目标变化依据
补齐可执行输入参数场景
```

这些需求属于筹办条件 / 参数需求，不归入学习需求自然三类剧本。

这个新建方法不是可执行方法，只是被任务目标约束出来的候选方法壳：

```text
方法 M 已存在于方法树；
M 的目标结果能力指向目标特征类型 F；
M 的方法状态通常仍未达到可用；
M 的条件结果对、执行入口、参数规则等可能仍缺失。
```

因此，需求树继续生长的对象不再是：

```text
存在一个可改变目标特征类型 F 的方法
```

而是围绕已创建并返回的 `M` 生成更具体的缺口需求：

```text
要普通可任务化叶子任务 T 就绪，
需要用方法 M。

因为任务目标是：
    X.F -> V_target

所以需要存在一个方法 M，
其结果能力能够改变特征类型 F。

但当前方法库中没有既有候选方法。

所以任务筹办创建方法 M，并返回 M。

随后根据 M 的明确缺口派生子需求：
    M.方法状态 = 可用；
    或 M.条件结果对状态 = 已建立；
    或 M.执行入口状态 = 已形成。
```

动作链：

```text
任务筹办
    -> 遍历完整方法树并完成候选集填充
    -> 候选集为空
    -> 创建目标特征 F 对应的方法 M
    -> 将 M 加入候选集并返回 M
    -> 形成筹办回执：
        当前方法 = M
        筹办缺口类型 = 候选方法不可用 / 缺条件结果对 / 缺执行入口
        派生需求提示 = 补齐 M 的具体缺口

派生需求入树
    -> 新增子需求 D1：
        被需求存在 = M 的方法虚拟存在
        目标特征类型 = 方法状态 / 条件结果对状态 / 执行入口状态
        目标状态 = 可用 / 已建立 / 已形成

承接需求创建任务
    -> 创建子任务 T1

子任务 T1 通过学习链补齐方法 M

提交方法状态变化 / 建立条件结果对
    -> 方法 M 达到可用条件

回写需求满足
    -> 登记 D1 已满足

唤醒任务重筹办
    -> 父任务 T 进入待重筹办

任务筹办再次运行
    -> 再次查到 M
    -> 形成可就绪回执

同步筹办回执到任务
提交任务状态变化
    -> T.任务状态 = 就绪
```

## 5. 候选方法存在但不可用路径

如果查到方法 `M`，但：

```text
M.方法状态 != 可用
```

则因果链是：

```text
要普通可任务化叶子任务 T 就绪，
需要用方法 M。

因为方法 M 的结果能力命中了：
    X.F

但方法 M 要被用于任务 T，
需要：
    M.方法状态 = 可用

当前：
    M.方法状态 = 待学习 / 待补齐 / 未可用

所以需要派生子需求 D2：
    M.方法状态 = 可用
```

为了让 `M.方法状态 = 可用`，又需要：

```text
M 有执行入口
M 有条件节点
M 有结果节点
M 有至少一组有效条件结果对
```

如果缺条件结果对：

```text
要 M 可用，
需要建立条件结果对。

因为方法可用最低条件是：
    至少存在一组有效条件结果对。

所以需要调用：
    尝试学习
    建立条件结果对
    提交方法状态变化
```

动作链：

```text
任务筹办
    -> 筹办缺口类型 = 候选方法不可用
    -> 派生需求提示 = 方法状态 = 可用

派生需求入树
    -> D2：M.方法状态 = 可用

承接需求创建任务
    -> 子任务 T2

尝试学习
    -> 形成条件结果对候选

建立条件结果对
    -> 写入 M.条件结果对集合
    -> 生成条件结果对动作动态

提交方法状态变化
    -> M.方法状态 = 可用
    -> 生成方法状态动作动态

回写需求满足
    -> D2 满足

唤醒任务重筹办
    -> 父任务 T 待重筹办

任务筹办再次运行
    -> M 已可用
    -> 继续检查参数和条件
```

候选方法不可用时，派生需求应表达为：

```text
方法状态 = 可用
```

不得在缺口不明确时直接派生：

```text
方法动作状态
```

## 6. 候选方法缺执行入口路径

如果查到 `M`，且结果能力命中，但：

```text
M 缺执行入口
```

则因果链是：

```text
要普通可任务化叶子任务 T 就绪，
需要用方法 M。

因为 M 的结果能力能够改变 X.F。

但方法 M 要用于任务 T，
需要 M 有可执行入口。

当前 M 缺执行入口。

所以需要派生子需求 D3：
    M.执行入口状态 = 已形成
```

执行链：

```text
D3 被承接为子任务 T3

T3 调用：
    因果信息获取自我动作组合
    -> 若得到单个本能方法 ID，则提交方法可执行入口
    -> 若得到多步动作组合，则记录动作序列候选并等待动作序列入口规则

完成后：
    M.执行入口状态 = 已形成

若执行入口和条件结果对都满足可用条件：
    提交方法状态变化
    -> M.方法状态 = 可用

父任务 T 被唤醒重筹办
任务筹办再次运行
```

边界：

```text
当前内部方法补齐场景中，缺执行入口不能直接由定向学习闭合。
若该场景出现定向学习被选中，说明尚未找到能让目标状态 A -> B 的自我动作组合，
或该组合 / 方法尚未声明能命中这些结果特征。

定向学习可以补动作语义线索，但不能伪造真实动作句柄。
```

随后闭合到：

```text
M 可用 + 条件满足 + 参数可绑定
    -> 形成可就绪回执
    -> 提交任务状态变化
    -> T 就绪
```

## 7. 候选方法参数无法绑定路径

如果 `M` 可用，但任务上下文无法构造 `M` 的输入参数场景：

```text
缺目标宿主
缺目标特征类型绑定
缺目标值
缺工具存在
缺环境条件
缺中间对象
```

则因果链是：

```text
要普通可任务化叶子任务 T 就绪，
需要用方法 M。

因为方法 M 的结果能力能作用于 X.F。

但方法 M 要执行，
需要输入参数场景 S_exec。

S_exec 需要参数：
    P1, P2, P3 ...

当前缺参数 P2。

所以需要派生子需求 D4：
    参数 P2 已获得 / 已绑定 / 已识别。
```

动作链：

```text
任务筹办
    -> 筹办缺口类型 = 参数配对失败
    -> 派生需求提示 = 获取或绑定缺失参数

派生需求入树
    -> D4：缺失参数 P2 已绑定

承接需求创建任务
    -> 子任务 T4

子任务 T4
    -> 查找 / 识别 / 构造参数 P2

回写需求满足
    -> D4 满足

父任务 T 重筹办
    -> 任务筹办再次调用配对参数

配对参数
    -> 生成 S_exec

任务筹办
    -> 可就绪回执

同步筹办回执到任务
提交任务状态变化
    -> T 就绪
```

## 8. 候选方法条件节点不满足路径

如果 `M` 可用，参数也基本存在，但 `M` 的条件节点不满足：

```text
M.条件节点要求 C
当前任务上下文不满足 C
```

则因果链是：

```text
要普通可任务化叶子任务 T 就绪，
需要用方法 M。

因为 M 的结果能力命中 X.F。

但 M 要运行，
需要条件 C 成立。

当前条件 C 不成立。

所以需要派生子需求 D5：
    条件 C 成立。
```

例如：

```text
M = 加热方法
C = 有可用加热器
```

则派生子需求：

```text
D5：可用加热器存在
```

满足后：

```text
D5 满足
    -> 父任务重筹办
        -> 条件节点匹配成功
            -> 构造可执行输入参数场景
                -> 任务进入就绪
```

## 9. 统一因果模板

完整模板：

```text
要普通可任务化叶子任务 T 就绪，
需要方法 M。

因为任务 T 的来源需求要求：
    X.F 满足目标状态 V_target

所以方法 M 必须具有结果能力：
    能产生 / 改变 特征类型 F

如果 M 不存在：
    任务筹办创建 M 并返回 M；
    随后按 M 的具体缺口派生需求。

如果 M 存在但不可用：
    需要需求 D2：M.方法状态 = 可用。

如果 M 缺执行入口：
    需要需求 D3：M.执行入口状态 = 已形成。

如果 M 缺条件结果对：
    需要需求 D4：M.条件结果对 = 已建立。

如果 M 参数无法绑定：
    需要需求 D5：缺失参数已获得 / 已绑定。

如果 M 条件节点不满足：
    需要需求 D6：方法前置条件成立。

当这些子需求被满足：
    父任务 T 被唤醒重筹办。

父任务 T 再次任务筹办：
    能找到 M
    M 可用
    参数可绑定
    条件满足
    可执行输入参数场景可构造

所以任务筹办形成：
    可就绪回执。

同步筹办回执到任务：
    写入当前方法、可执行输入参数场景、筹办缺口类型。

提交任务状态变化：
    写入任务状态 = 就绪
    生成任务状态动作动态。
```

## 10. 闭合点

### 10.1 方法能力查找闭合

```text
需求目标 X.F
    -> 查找结果能力包含 F 的方法 M
```

若找到：

```text
进入方法可用性检查
```

若找不到：

```text
创建面向 F 的方法 M；
进入方法可用性 / 条件结果对 / 执行入口缺口闭合。
```

### 10.2 方法可用性闭合

```text
M 不可用
    -> 派生需求：M.方法状态 = 可用
    -> 学习 / 补齐
    -> 提交方法状态变化
    -> M 可用
```

### 10.3 参数和条件闭合

```text
参数缺失 / 条件不满足
    -> 派生参数需求 / 条件需求
    -> 子任务满足
    -> 父任务重筹办
```

### 10.4 父任务重筹办闭合

```text
子需求满足
    -> 自我线程发父任务重筹办请求
    -> 任务管理线程调用相关任务域方法
    -> 父任务状态进入待重筹办
    -> 再次调用任务筹办
```

自我线程不得直接写任务状态。

### 10.5 任务状态落账闭合

```text
任务筹办形成可就绪回执
    -> 同步筹办回执到任务
        -> 提交任务状态变化
            -> 任务状态 = 就绪
```

任务状态动作动态绑定：

```text
本能方法_提交任务状态变化
```

不能绑定线程，也不能由任务筹办裸生成。

## 11. 完整链条

```text
D0：需求 D
    目标 = X.F -> V_target

D1：承接需求创建任务
    生成任务 T
    T.状态 = 未启动

D2：任务筹办
    按 F 遍历方法树并填充候选集
    若候选集为空，则创建方法 M 并返回 M
    形成候选方法 M

若 M 不存在：
    不允许停留在“无方法”状态；
    任务筹办必须先创建 M，再继续检查 M 的具体缺口。

若 M 已创建但不可用：
    D3：派生需求入树
        子需求 = M.方法状态 = 可用

    D4：承接需求创建任务
        子任务 T_child

    D5：学习 / 建立条件结果对 / 提交方法状态变化
        方法 M 被补齐并可用

    D6：回写需求满足
        子需求满足

    D7：唤醒任务重筹办
        父任务 T 可重新筹办

    回到 D2

若 M 可用且参数条件满足：
    D8：任务筹办
        形成可就绪回执

    D9：同步筹办回执到任务
        写入当前方法 M
        写入可执行输入参数场景 S_exec

    D10：提交任务状态变化
        T.状态 = 就绪
        生成任务状态动作动态
```

## 12. 实现前提

按照方法能力查找方法，能够形成任务推进到就绪的闭环。前提是：

```text
1. 任务筹办必须从来源需求解析出：
   目标宿主 + 目标特征类型 + 目标状态 + 满足关系。

2. 任务筹办必须先根据目标特征定义视图确认该需求是普通可任务化叶子目标；
   AND组、OR组、方法路径组、因果子链组织节点和结构性缺口节点不得进入普通方法候选查找。

3. 方法能力查找必须按：
   方法结果项.特征类型
   或 特征类型由参数决定并绑定到目标特征类型。

4. 查不到既有方法时，不进入失败，也不直接派生抽象“存在方法”需求；
   任务筹办必须在方法树中创建面向目标特征的方法头，加入候选集并返回该方法。

5. 新建方法或既有方法不可用时，派生“方法状态 = 可用”的子需求；
   只有回执明确缺条件结果对或缺执行入口时，才派生对应更细需求。

6. 参数 / 条件缺失时，派生对应参数或条件需求。

7. 子需求满足后，必须触发父任务重筹办。

8. 任务筹办形成可就绪回执后，必须通过：
   同步筹办回执到任务
   -> 提交任务状态变化
   把任务状态真正落到就绪。

9. 所有状态、需求、方法变化的动作动态必须绑定对应本能方法，不能绑定线程。
```

## 13. 最终定稿

```text
要普通可任务化叶子任务就绪，需要找到能改变目标特征的方法；
若找不到既有方法，任务筹办先创建并返回目标特征对应的方法；
要方法可用，需要满足方法自己的状态、入口、条件、参数；
这些缺口会长成子需求；
子需求满足后回流父任务重筹办；
最终形成可就绪回执；
再由状态提交方法把任务推进到就绪。
```
