# 0050 项目通用结构与禁止性规则总纲

编号：0050
日期：20260701
状态：正式上级规范

## 1. 定位

本规范是当前项目通用结构闭环、禁止性规则、输出边界和验收表述的上级规范。它约束计划执行、代码修改、规范修订、回归验证和实现验收。

旧 `禁止性规范20260611.md` 已迁入 `规范/旧规范/`，只作历史参考。当前执行以本文件、`规范/规范目录.md` 和当前根目录正式规范为准。

## 2. 项目通用结构闭环

系统内部逻辑必须通过项目通用数据结构表达和流转。设计和实现不仅要证明有闭环，还要证明闭环由项目结构闭合。

允许作为业务承载的结构包括：

```text
存在 / 场景 / 特征 / 特征值 / 状态 / 动态 / 二次特征 / 因果 / 方法 / 需求 / 任务 / 基础信息节点
I64 / VecU句柄 / VecI64 / VecIU64 / 指针句柄
抽象特征树 / 特征值类值池 / 项目已有枚举和状态值域
语素入口节点类作为类型、名称和抽象入口的身份标识
```

禁止用以下形式承载系统逻辑、系统状态、存在关系、特征归属、方法关系、需求关系或因果判断：

```text
自由文本
字符串字段
文本标签
日志文案
注释说明
临时 JSON
自由字段
```

文本只允许用于日志输出、调试说明、测试名称、用户可读错误信息、语素入口注册时的名称种子和文档说明。语素注册后必须转为项目内部身份结构参与判断。

## 3. 新增结构约束

默认禁止为业务语义、治理判断、状态集合、特征组合、需求准入、任务回执、方法结果、因果缺口、安全 / 服务判断新建持久结构体。

新增结构前必须先证明无法用已有存在、场景、特征、特征值、状态、动态、二次特征、因果、需求、方法或基础信息节点表达。

短期局部运行期结构、非权威只读投影结构或诊断结果结构只能作为实现辅助，不得承载业务权威事实，不得跨域流转成机器判断依据。

## 4. 输出和日志边界

运行日志、预测日志、逻辑错误排查日志、调试日志、控制台输出、UI 直接提示输出和调试器输出不得承载正式机器逻辑、业务状态、因果判断或验收结论。

所有输出必须通过 `预处理开关变量.h` 的总开关和细分开关控制。关闭输出只能关闭输出面，不得改变项目结构事实写入、错误检测、异常终止、需求 / 任务 / 方法 / 因果闭环或正式返回结构。

关闭全部输出后的验证口径是：本次运行不新增日志文件，既有日志文件不新增行、不增长；旧日志内容不得作为本次运行证据。

## 5. 兼容和旧口径禁止

当前机器判断不得依赖旧字段、旧入口、旧流程、旧枚举、旧 ID、旧状态名、旧错误码或旧日志文本。

发现兼容路径时，当前切片若必须触碰该点，应优先删除兼容路径并收束为唯一正式路径；若删除会扩大范围，应暂停当前切片并生成明确清理计划。

旧规范、旧说明、旧计划和旧实施记录不得覆盖当前正式规范。

## 6. 错误和回执边界

非正常逻辑错误必须弹错 / 报错并记录必要诊断，不允许静默兜底。所有弹窗错误按逻辑错误处理，必须追究根因并解决。

错误码只允许作为调试显示值、错误日志辅助检索值或已被特征化事实完整覆盖后的非权威附属值。任何机器判断不得只读取错误码。

本能方法、任务筹办和任务执行不得只返回裸失败。不能继续推进的信息必须先处理成项目结构中的特征化事实、过程回执、缺口、等待、重筹办、派生需求、学习补齐或异常处理入口。

任务筹办 / 任务执行是任务管理生命周期普通函数，不作为本能方法注册、选择或动作动态来源，也不得被建成子任务来解决自身。

## 7. 实现前结构映射

设计进入实现前必须给出项目结构映射表：

```text
业务概念 -> 项目承载结构 -> 值类型 -> 写入方 -> 读取方 -> 验证方式
```

实现时必须证明：

```text
输入进入项目节点 / 特征 / 特征值结构
-> 处理过程读取项目结构
-> 输出写回项目节点 / 特征 / 特征值结构
-> 后续流程继续读取这些结构
```

## 8. 验收表述约束

验收“已实现 / 已支持 / 已完成 / 已接入 / 已闭环 / 可用 / 已修复 / 已验证”声明时，必须同时给出六类证据：

```text
输入入口
核心处理
项目结构承载证据
输出 / 状态变化
调用路径
测试 / 验证
```

没有项目结构闭环时，必须降级为：

```text
文本替代实现不合格
仅定义壳
孤立实现未接入项目结构闭环
部分实现
```
