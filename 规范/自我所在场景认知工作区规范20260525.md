# 自我所在场景认知工作区规范 20260525

## 0. 定位

自我所在场景不是所有信息的仓库，而是：

```text
自我当前认知的工作区
```

它只保存能被自我继续观察、确认、比较、调度、绘制、查询和验收使用的信息。

核心问题不是“能列举哪些场景特征”，而是：

```text
我正在观察什么？
我观察到了哪些特征？
哪些特征已经组合成存在？
哪些存在已经确认？
哪些区域还未解释？
和上一帧相比发生了什么变化？
这些结果能否被筹办、查询、绘制、验证继续使用？
```

## 1. 最高硬规则

```text
只有会被自我认知过程使用的信息，才进入自我所在场景。
```

不得进入自我所在场景根层：

```text
相机内部处理步骤
原始驱动缓存
临时算法中间量
未被自我接收的预览画面
控制面板显示层推导结果
外设私有校正 / 匹配 / 滤波 / 分割过程
```

可以进入自我所在场景：

```text
外设使用后进入自我认知链的观察事实
自我根据观察事实生成的候选、存在、关系、变化、验证结果
自我继续推理、筹办、绘制、回查所需的索引和摘要
```

### 1.1 状态 / 动态信息的场域归属

状态信息和动态信息必须按主体所属场域记录：

```text
谁的状态 / 动态，
就记录到谁所属的世界、场景或证据层中。
```

自我所在场景记录：

```text
当前场景中存在的状态；
当前场景中存在的动态；
当前场景中关系的状态；
当前场景中关系的动态；
自我身体 / 外设 / 边界在当前场景中的空间状态和空间动态。
```

自我内部世界记录：

```text
需求状态；
目标状态；
任务状态；
方法状态；
方法执行实例状态；
筹办状态；
执行状态；
判断状态；
信息缺口状态；
因果沉淀状态；
记忆整理状态；
自我安全 / 服务 / 价值判断状态。
```

归属规则固定为：

```text
主体是场景存在或场景关系：
    记录到自我当前所在场景。

主体是需求、目标、任务、方法、方法执行实例、判断对象、信息缺口：
    记录到自我内部世界。

主体是外设观察材料或观察候选：
    入账前记录为观察证据层；
    经质量验证、同一性比较、归属判断、稳定复现和事实提交后，
    才派生为当前场景事实或内部治理事实。

主体是自我身体 / 自我边界 / 自我外设：
    空间接触和运动状态记录在当前场景；
    安全、风险、需求和治理解释记录在自我内部世界。

主体是因果样本、因果分支或因果模板：
    记录到因果库 / 自我内部世界。
```

压缩口径：

```text
场景状态写场景，治理状态写内部；
场景动态写世界变化，治理动态写自我处理；
观察材料先做证据，裁决之后再入账。
```

外设适配器、驱动、采集、校正、匹配、滤波、分割属于外设私有领域。自我只通过本能方法接收外设的控制、检查和使用结果。

外设与自我本能方法的职责分层以 `外设观察特征与自我场景认知本能方法分层规范20260525.md` 为准：

```text
相机只取得观察特征；
自我把观察特征组织成观察帧、像素事实、空间候选、已确认观察存在、内部世界和可绘制快照。
```

## 2. 根层与观察帧隔离

像素观察存在虽然记录到自我所在场景范围内，但必须通过“当前观察帧存在”隔离本轮画面，避免污染自我所在场景根层。

自我所在场景根层只保存：

```text
当前认知索引
当前工作指针
当前摘要
当前接口
当前质量状态
```

观察帧存在内部保存：

```text
本轮观察事实
像素特征索引
空间候选集合
存在假设
已确认观察存在
像素归属图
未解释区域
冲突区域
覆盖 / 回查 / 质量统计
```

像素观察事实是当前观察帧内的最小观察事实单位，不等同于稳定外部对象。

观察帧、观察材料和观察候选在事实提交前属于观察证据层。它们可以作为质量验证、同一性比较、归属判断、稳定复现和事实提交的证据，但不得直接冒充当前场景稳定事实或自我内部治理事实。

第一阶段允许：

```text
像素特征 100% 可寻址
像素观察存在按需物化
观察帧负责隔离像素事实
```

不得因为节点数量压力而破坏：

```text
观察帧编号 + 像素坐标 / 帧内像素编号的唯一回查目标
```

## 3. 自我所在场景根层应保存的信息

自我所在场景根层应保存高价值认知索引和摘要：

```text
自我所在场景 {
    当前观察帧引用
    最近观察帧引用集合

    当前已确认观察存在集合引用
    当前空间候选集合引用
    当前待观察候选队列引用
    当前未解释区域引用
    当前冲突区域引用

    场景坐标口径
    场景边界
    有效观察范围

    场景接口集合
    当前帧接口
    历史帧接口
    OpenGL导出接口

    当前认知质量摘要
    当前存在数量统计
    当前变化事件集合
    当前可绘制状态
}
```

自我所在场景根层不得直接摊开所有像素事实。

## 4. 观察帧存在应保存的信息

当前观察帧存在应保存本轮观察事实和处理结果：

```text
当前观察帧存在 {
    来源外设
    深度帧号
    彩色帧号
    帧宽度
    帧高度
    观察生成时间
    观察状态

    像素特征索引
    像素观察事实集合 / 懒展开索引
    空间候选集合
    待观察候选队列
    已确认观察存在集合
    像素归属图
    未解释区域
    冲突区域
    覆盖率 / 回查率 / 深度有效率
}
```

观察帧存在是本轮画面的权威来源锚点。没有观察帧来源锚点的认知结果不得写成已确认事实。

## 5. 九类认知用途信息

### 5.1 观察入口信息

保存：

```text
当前观察帧
最近观察帧集合
观察来源外设
观察生成时间
观察状态
```

用途：

```text
确定当前认知依据哪一帧
确定观察来自哪个外设
判断当前帧是否完整
为后续空间候选、存在确认、变化判断提供来源
```

根层只保存当前观察帧引用、最近观察帧引用和观察状态摘要；帧号、宽高、来源外设、像素特征索引保存在观察帧存在内部。

### 5.2 像素级观察事实

保存：

```text
像素坐标X/Y
帧内像素编号
颜色R/G/B
深度值
深度有效性
空间坐标X/Y/Z
```

用途：

```text
作为空间候选生成原材料
作为存在确认的证据
支持像素坐标 / 帧内编号 100% 回查
支持鼠标命中查询颜色、深度、空间坐标
支持 OpenGL 复现颜色层、深度层、空间点层
```

像素观察事实必须挂在观察帧存在之下，不得直接堆到自我所在场景根层。

### 5.3 空间候选信息

保存：

```text
空间候选集合
来源观察帧
像素索引集合 / 掩码引用
中心空间坐标
范围坐标AABB
点数量
有效点比例
深度范围
空间连续性评分
范围稳定性评分
相对独立状态
```

用途：

```text
把密集像素事实压缩成可逐个观察的候选
决定自我接下来观察哪个候选
以空间坐标和范围坐标作为存在确认主依据
区分相对独立、待拆分、待合并、不确定和不独立
```

空间候选是注意力的承载结构，不是已确认观察存在。

### 5.4 观察队列与注意力状态

保存：

```text
待观察候选队列
当前观察候选
已观察候选集合
已跳过候选集合
观察排序策略
观察预算
观察进度
```

用途：

```text
让自我一次只观察一个候选
支持确认一个存在后继续观察下一个候选
支持远程执行或本地运行中断后的恢复
支持任务驱动注意力
```

根层保存当前观察队列引用、当前观察候选引用和观察进度摘要；队列明细保存到观察帧存在内部。

### 5.5 已确认观察存在

保存：

```text
已确认观察存在集合
来源观察帧
来源空间候选
中心空间坐标
范围坐标AABB
内部世界引用，可为空
距离
尺寸
方位
像素归属掩码 / 归属索引
验证状态
置信度
```

用途：

```text
回答当前场景里有哪些存在
支持距离、相对位置、尺寸、方位等特征查询
支持存在变化判断
支持任务筹办继续生成行动需求
支持 OpenGL 画出自我已经确认的场景
```

这里确认的是当前观察帧内的观察存在，不得直接宣称为：

```text
跨帧稳定世界对象
语义分类完成
目标可见性 / 在场状态闭合
长期身份已确认
```

### 5.5.1 存在内部世界边界

存在节点在父场景中表现为一个可观测成员，负责记录该成员在父场景中的位置、范围、外轮廓、归属像素和确认状态。存在节点的 `内部世界` 字段是该成员被展开后的子场景入口。

当自我需要继续认知某个已确认观察存在的内部结构时，子存在、子轮廓、子结构、叶子特征块、内部未解释区域和内部冲突区域，均应进入：

```text
目标存在.内部世界
```

不得直接堆叠为父存在的普通字段。

第一阶段采用懒创建口径：

```text
只有当出现 目标存在.内部世界 -> 已建立
或 目标存在.内部世界.成员存在集合 -> 已更新
或 目标存在.内部世界.细分状态 -> 已完成
等认知需求时，才解析或创建内部世界。
```

存储边界：

```text
观察帧存在：
    保存本轮相机观察到的像素、颜色、深度、空间坐标等原始观察事实。

存在.内部世界：
    保存自我把观察事实组合、验证后形成的内部认知结构。
```

也就是：

```text
像素观察事实在观察帧里；
认知出的子存在住进父存在的内部世界里。
```

### 5.6 未解释区域与冲突区域

保存：

```text
未解释区域集合
冲突区域集合
深度无效区域
归属冲突像素集合
候选待拆分区域
候选待合并区域
```

用途：

```text
决定是否继续观察下一个空间候选
判断当前场景理解是否足够完整
生成重新观察、调整相机、扩大范围或换角度需求
作为存在拆分 / 合并输入
在 OpenGL 中显示哪些地方尚未解释清楚
```

未解释区域和冲突区域不是普通错误日志，而是后续认知动作的输入。

### 5.7 场景边界与坐标口径

保存：

```text
坐标单位
坐标系类型
到父场景变换
边界类型
二维边界
空间范围AABB
有效观察范围
```

用途：

```text
判断观察存在是否属于当前场景
判断空间候选是否越界
将相机观察坐标换算到自我宿主场景
为 OpenGL 提供绘制尺度、裁剪范围和坐标轴
支持目标是否在当前观察范围内的判断
区分没看到是消失还是不在场景边界内
```

空间坐标必须有明确单位和参考坐标系。未声明单位或参考系的坐标不得进入真实验证结论。

2026-06-01 补充：场景绝对坐标与自我视图口径。

```text
场景中存在的正式位置特征使用场景绝对坐标表达；
自我相对坐标不作为存在本体的主要存储事实，
而是由自我当前场景绝对坐标 / 姿态和存在绝对坐标计算出的自我视图。
```

正式存储优先表达：

```text
存在_场景绝对坐标
存在_场景绝对空间范围
存在_场景绝对坐标明确状态
存在_场景绝对空间范围明确状态
存在_坐标来源
存在_坐标时间戳
存在_坐标置信度

自我_场景绝对坐标
自我_场景绝对姿态
自我_场景绝对坐标明确状态
自我_场景绝对姿态明确状态
外设_D455到场景绝对坐标变换明确状态
```

派生视图优先表达：

```text
自我视图_存在相对坐标
自我视图_存在相对距离
自我视图_存在相对方向
自我视图_存在边界关系
自我视图_存在靠近趋势
自我视图_存在进入近身边界候选
自我视图_存在接触候选
自我视图_存在遮挡感知边界候选
```

自我视图派生项可以短期缓存，但必须带来源绝对坐标版本、来源自我姿态版本、来源边界定义版本、时间戳和有效期。

自我移动时，只更新自我在场景绝对坐标中的位置和姿态；不得批量改写其他存在的场景绝对坐标。相对坐标、距离、方向和边界关系应由自我视图重新计算。

D455 的相机坐标、ROI、掩码、点集和深度切片只是观察材料；只有经过验证、确认、坐标变换和提交入口后，才能写成存在的场景绝对坐标特征。

自我边界宜定义在自我相对视图坐标系中。判断流程应为：

```text
存在_场景绝对坐标 / 空间范围
+ 自我_场景绝对坐标 / 姿态
-> 自我视图_存在相对坐标
-> 与自我边界比较
-> 得到边界关系候选
```

### 5.8 场景接口信息

保存：

```text
场景接口集合
观察帧场景 -> 自我所在场景接口
相机场景 -> 自我宿主场景接口
当前观察帧 -> 上一观察帧接口
自我所在场景 -> OpenGL复现快照接口
```

每个接口至少包含：

```text
来源场景
目标场景
接口类型
接口状态
接口变换
接口可信度
```

用途：

```text
场景之间坐标换算
当前帧和上一帧比较
观察帧结果挂到自我所在场景
将自我所在场景导出为 OpenGL 可绘制快照
区分观察场景、宿主场景、世界场景边界
```

接口应建成可查询、可验证、可过期、可更新的独立存在或等价结构，不得只写成不可追踪的说明字符串。

### 5.8.1 运行期心像缓存边界

场景体素、可见性缓存、遮挡缓存、通行缓存、风险缓存和 OpenGL 复现快照属于当前场景的运行期心像层。它们可以服务视觉中间层、规划、调试和复现，但不能直接裁决世界树事实。

三类动态必须分开：

```text
场景体素动态：
    属于当前场景运行期心像动态。

事实入账动态：
    属于自我内部治理动态，记录观察材料如何经裁决提交为事实。

稳定存在状态变化：
    属于当前场景 / 世界树存在动态，记录已确认存在或关系的状态变化。
```

运行期心像缓存不得绕过观察、扫描、跟踪、识别、质量验证、同一性比较、归属判断和事实提交，直接写成稳定存在状态或内部治理结论。

保存：

```text
像素覆盖率
空间点有效率
已确认存在数量
未解释区域比例
归属冲突率
最近动作动态
失败原因
场景可绘制状态
场景认知完整状态
```

用途：

```text
判断当前场景是否足够可信
判断是否需要重新观察
判断是否允许进入变化检测
判断是否允许生成 OpenGL 复现快照
给任务筹办提供条件缺口
给调试和验收提供证据
```

认知质量摘要只能作为派生统计或诊断，不得替代权威事实集合。

## 6. 权威事实与派生统计

权威事实包括：

```text
当前观察帧引用
像素特征索引
空间坐标 / 深度 / 颜色观察事实
空间候选集合
已确认观察存在集合
像素归属图
场景边界
场景接口集合
动作动态
```

派生统计包括：

```text
存在数量
像素覆盖率
未解释区域比例
归属冲突率
空间点有效率
已确认存在数量
可绘制状态
认知完整状态
```

派生统计必须能说明来源：

```text
存在数量 = 从已确认观察存在集合统计
像素覆盖率 = 从像素存在数量 / 预期像素数量计算
未解释区域比例 = 从场景边界 - 已归属区域 - 无效区域计算
```

不得把派生统计写成唯一真相；不得让派生统计和权威事实集合长期不一致。

## 7. 按认知流程的读写关系

| 自我认知动作 | 读取信息 | 产生 / 更新信息 | 用途 |
| --- | --- | --- | --- |
| 取得观察依据 | 当前观察帧引用、来源外设、帧号 | 观察帧存在 | 确定这次认知基于哪一帧 |
| 像素回查 | 像素坐标、帧内编号、像素特征索引 | 像素观察事实 | 保证每个像素可寻址、可回查 |
| 提取空间候选 | 空间坐标、深度、有效性 | 空间候选集合 | 把密集特征压缩成可观察候选 |
| 安排观察顺序 | 空间候选、任务目标、画面中心、范围大小 | 待观察候选队列 | 决定自我先观察哪个候选 |
| 组合存在假设 | 单个空间候选、范围坐标、像素掩码 | 存在假设 | 把一组空间特征解释成一个可能存在 |
| 验证存在 | 存在假设、原帧特征、空间范围、归属图 | 验证结果、冲突区域 | 判断候选能否成为已确认观察存在 |
| 确认存在 | 验证结果、像素归属结果 | 已确认观察存在集合 | 更新当前场景有哪些存在 |
| 发现变化 | 当前帧存在、历史帧存在、场景接口 | 变化事件集合 | 判断新增、消失、移动、范围变化 |
| 继续观察 | 未解释区域、冲突区域、质量摘要 | 新观察需求 / 下一个候选 | 决定是否继续处理当前帧 |
| 场景复现 | 已确认存在、像素事实、归属图、边界、坐标口径 | OpenGL复现快照 | 把自我认知结果画出来 |
| 任务筹办 | 当前场景存在、特征、状态、缺口 | 新需求 / 前置需求 | 判断下一步要观测、验证还是行动 |

新增字段、节点或摘要前，必须先说明它服务上述哪一个认知动作。

## 8. 优先级

第一优先级，没有它们自我无法认知：

```text
当前观察帧引用
像素特征索引
空间坐标 / 深度 / 有效性
空间候选集合
已确认观察存在集合
场景坐标口径
场景接口
动作动态
```

第二优先级，没有它们自我可以认知但难以验证：

```text
像素归属图
范围坐标AABB
未解释区域
冲突区域
覆盖率
回查率
空间点有效率
验证状态
```

第三优先级，没有它们自我可以认知但难以调度和展示：

```text
存在数量
候选数量
观察队列进度
可绘制状态
OpenGL复现快照
诊断摘要
```

第四优先级，后续扩展：

```text
跨帧跟踪编号
世界存在归并状态
语义类别
长期地图接口
行为可达区域
```

## 9. 控制面板与复现边界

控制面板复现必须读取自我所在场景中的识别结果。

控制面板不得：

```text
把相机原始画面当真值
绕过自我所在场景直接使用相机缓存宣称认知结果
把显示层推导结果回写世界树
把 OpenGL 复现成功等同于场景认知成功
```

控制面板可以显示：

```text
观察帧引用
像素覆盖率
空间候选
已确认观察存在
像素归属
未解释区域
冲突区域
边界与坐标轴
最近动作动态
失败原因
```

控制面板只是证据面，不是业务目标本身。

## 10. 任务筹办与需求生成边界

自我所在场景中的认知结果可以被任务筹办读取，用于：

```text
确认当前场景中有哪些观察存在
查询距离、方位、尺寸、颜色、深度、范围坐标等特征
发现缺口并生成观察 / 验证 / 调整外设需求
判断当前观察质量是否足够支持后续行动
```

任务筹办不得把控制面板显示状态当作权威输入。

任务筹办不得因为存在摘要字段就跳过：

```text
观察帧来源
已确认观察存在集合
像素归属证据
动作动态证据
失败原因
```

## 10.1 基础观察事实与基础风险判断边界

基础观察事实可用与基础风险判断已明确必须分层，详细口径以 `基础观察事实可用与基础风险判断分层规范20260526.md` 为准；枚举型实例特征值来源以 `枚举型实例特征值合法来源规范20260526.md` 为准。

第一阶段观察闭环只能以：

```text
当前观察帧.基础观察事实可用状态 等于 可用
```

作为目标。它依赖当前观察特征帧取得、当前观察帧存在、像素覆盖、像素特征值承接、质量可用和观察新鲜度。`已取得 / 已建立 / 已覆盖 / 已完成 / 可用 / 新鲜` 都必须由合法生产者写入并有动作动态 / 来源动态 / 规则证据，不能由场景工作区、控制面板或只读快照直接写入。

不得把第一阶段观察闭环直接写成：

```text
自我所在场景.基础风险判断状态 等于 已明确
```

基础风险判断状态是派生状态特征值，必须在确定风险评估范围、确认观察依据未过期、覆盖基础风险必要因子、满足证据完整度和不确定度阈值，并完成基础风险值计算后，才允许写为 `已明确`。

## 11. 禁止宣称项

仅有当前观察帧、像素特征或空间候选时，不得宣称：

```text
观察存在已确认
基础风险判断状态已明确
基础风险值已计算
场景安全
目标可见性 / 在场状态已闭合
跨帧身份稳定
语义识别完成
世界对象已稳定归并
当前画面全帧像素归属已闭合
自我苏醒完成
初步成熟完成
```

只有当观察存在集合、像素归属、验证结果、动作动态和日志证据共同闭合后，才允许宣称对应范围已通过。

## 12. 最终定义

```text
自我所在场景存储的不是外部世界的全部内容，
而是自我当前认知所需的观察事实、认知中间结果、确认结果、接口关系、质量摘要和可复现快照入口。

它的核心用途是：
    承接外设观察结果；
    隔离每一帧观察事实；
    支持像素和空间特征回查；
    支持自我从特征组合存在；
    支持存在验证和像素归属；
    支持发现新增、消失、移动、范围变化；
    支持任务筹办继续生成需求；
    支持 OpenGL 从自我认知结果复现场景；
    支持日志、动作动态、状态快照共同验收。
```

一句话：

```text
自我所在场景不是数据仓库，而是自我的当前认知工作区：
它只保存能被观察、确认、比较、调度、绘制和验收继续使用的信息。
```
