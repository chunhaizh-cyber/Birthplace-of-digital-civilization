## 1. 定案

原则：

```text
每个外设实例必须有独立控制域；
每种外设都应有独立的外设控制线程 / 外设代理线程；
高实时、高带宽、状态复杂的外设，最好每个物理实例独占线程。
```

工程解释：

```text
独立控制域是强规则；
是否独占 OS 线程是工程实现选择；
低频简单外设可以共享线程池，但仍必须有独立命令队列、状态机、报告队列和错误状态。
```

边界：

```text
外设控制线程只管理外设自身和外设消息；
不直接写自我需求树；
不直接写世界树真值；
不直接做安全 / 服务价值结算。
```

一句话：

```text
外设线程负责“看、动、报”；
任务管理线程负责“接、分拣、匹配任务”；
自我线程负责“裁决是否入树、是否成为正式认知”。
```

外设本能方法的边界仍然是：

```text
控制
检查
使用
```

该边界只约束自我 / 任务管理可见的外设契约，不要求外设控制线程内部用本能方法实现能力。外设控制线程内部可以直接用工程代码、驱动适配器、状态机、缓存、队列、算法模块和私有学习模块完成看、动、报。

不得暴露外设内部采集、校正、滤波、匹配、分割、轨迹规划、驱动重试、内部学习等私有过程，也不得把这些私有过程登记成自我层本能方法。

## 2. 总体线程结构

推荐结构：

```text
自我线程
    管理统一需求树 / 世界树裁决 / 安全服务根需求

任务管理工作线程
    任务筹办
    等待项管理
    外设消息承接
    派生需求消息上报

外设控制线程 A：双目相机
    逐簇识别 / 扫描变化 / 目标跟踪 / 稳定特征报告

外设控制线程 B：机械手
    动作执行 / 位姿状态 / 夹爪状态 / 力反馈

外设控制线程 C：云台
    朝向控制 / 当前朝向反馈

外设控制线程 D：灯光
    亮度控制 / 光照状态反馈
```

每个外设控制线程有自己的：

```text
命令队列
状态缓存
报告队列
错误状态
实时性统计
内部学习 / 配置缓存，可选
```

## 3. 为什么每类外设 / 每个实例需要独立控制域

### 3.1 避免阻塞自我线程

相机、机械手、传感器都可能阻塞：

```text
相机采集等待
机械手动作等待
驱动异常
硬件超时
通信延迟
```

这些不能阻塞自我线程。自我线程应该保持：

```text
需求树裁决
世界树裁决
根价值判断
派生需求入树
```

### 3.2 隔离实时流

双目相机会高频产生：

```text
逐簇识别报告
扫描变化报告
跟踪报告
观察像素簇
簇级特征
低质量区域
```

如果直接进入自我线程，会把自我线程淹没。

所以要：

```text
相机线程高频生产；
任务管理工作线程按需求消费；
自我线程只接收被需求命中的摘要 / 回执 / 派生需求消息。
```

旧像素级方案里的“100%”也只是帧内可寻址、可回查、无遗漏、无重复，不表示稳定对象识别或语义识别完成。

### 3.3 外设自身状态需要连续管理

机械手线程要维护：

```text
当前关节角
末端坐标
夹爪开合度
动作执行状态
错误状态
急停状态
```

相机线程要维护：

```text
当前配置
最近逐簇识别报告
最近扫描变化报告
最近跟踪报告
观察像素簇缓存
稳定特征缓存
队列积压
丢帧率
```

这些都不适合由任务管理线程临时处理。

## 4. 外设控制线程的通用职责

每个外设控制线程统一负责：

```text
1. 接收任务管理线程下发的外设命令。
2. 串行化外设命令，避免多个任务同时乱控硬件。
3. 管理外设驱动 / 适配器句柄。
4. 维护外设当前状态缓存。
5. 执行控制、检查、使用动作或内部状态机动作。
6. 生成外设报告。
7. 将报告写入外设消息队列。
8. 记录外设错误、超时、降级、丢弃。
9. 支持取消、超时、抢占和优先级。
```

其中“执行外设命令”可以是直接代码实现，不必映射成外设线程内部本能方法；本能方法只在自我 / 任务管理边界用于表达控制、检查、使用契约。

它不负责：

```text
1. 直接生成正式需求节点。
2. 直接修改需求树。
3. 直接确认父需求满足。
4. 直接写世界树真值。
5. 直接结算安全值或服务值。
```

外设线程可以高频运行，也可以内部复杂，但它对自我侧只通过任务管理承接链间接产生影响。

外设线程内部的私有工程代码不得成为需求树、世界树、动作动态或价值结算的权威来源；权威来源只能是任务管理承接后的回执、承接请求，以及自我线程裁决后的入账结果。

## 5. 通用消息模型

### 5.1 输入：外设命令消息

任务管理线程发给外设控制线程：

```text
外设命令消息 {
    命令ID
    来源任务ID
    来源需求ID
    目标外设
    命令类型:
        控制
        检查
        使用

    目标特征比较:
        目标宿主
        目标特征类型
        比较符: 大于 / 小于 / 等于
        目标值

    优先级
    截止时间
    允许缓存结果
    参数摘要
}
```

示例：

```text
双目相机.可用状态 == 可用
双目相机.运行可用性值 > 0
外设观察报告.生成状态 == 已生成
目标观察簇.跟踪状态 == 稳定
机械手末端.空间坐标 == 目标坐标
夹爪.开合度 == 目标开度
```

### 5.2 输出：外设报告消息

外设控制线程发给任务管理工作线程：

```text
外设报告消息 {
    报告ID
    对应命令ID，可空
    来源外设
    报告类型:
        控制回执
        检查回执
        使用回执
        逐簇识别报告
        扫描变化报告
        跟踪报告
        稳定特征摘要
        质量缺口摘要
        错误报告

    时间戳
    输出特征集合
    配置摘要
    错误摘要
    是否命中命令
}
```

具体外设若已有更收敛的报告规范，按该外设规范执行。例如双目相机对外观察运行模式收敛为：

```text
陌生环境逐簇识别模式 -> 逐簇识别报告
已识别场景扫描变化模式 -> 扫描变化报告
目标跟踪观察模式 -> 跟踪报告
```

稳定特征、质量缺口、失败原因和配置摘要可以作为三种报告字段，不得被误解为新的相机外显模式。ROI、补观察、质量诊断、重捕获、配置学习和局部细分只能作为内部策略、等待项参数或报告字段。

任务管理线程再根据等待项和活跃需求判断：

```text
生成任务回执
生成派生需求消息
生成动作动态输入
仅缓存
丢弃
```

## 6. 感知外设线程：以双目相机为例

双目相机线程的主要输出不再是“像素级 100% 识别”，而是：

```text
逐簇识别报告
扫描变化报告
跟踪报告
观察像素簇
簇级稳定特征
掩码
彩色轮廓局部图
深度轮廓局部图
```

### 6.1 陌生环境逐簇识别报告

回答：

```text
当前视野里有哪些观察像素簇？
每个簇能稳定给出哪些特征？
哪些区域低质量、未归簇、不可观测？
```

输出 / 承接后可核对：

```text
双目相机.主观察运行模式 == 陌生环境逐簇识别
当前观察帧.观察像素簇集合状态 == 已生成
当前观察帧.簇ID掩码状态 == 已生成
当前观察帧.存在候选集合状态 == 已生成
当前观察帧.已解释像素比例 > 最低解释比例
观察像素簇.像素集合掩码状态 == 已生成
观察像素簇.彩色轮廓局部图状态 == 已承接
观察像素簇.深度轮廓局部图状态 == 已承接
```

其中存在候选集合由自我承接观察像素簇后生成，不能由相机线程直接写成已确认观察存在。

### 6.2 已识别场景扫描变化报告

回答：

```text
当前视野和已知场景解释相比有没有明显变化？
有没有新增、消失、移动、尺寸变化、质量异常或高风险未知簇？
```

输出：

```text
双目相机.主观察运行模式 == 已识别场景扫描变化
当前观察帧.变化候选集合状态 == 已生成
当前观察帧.扫描变化报告年龄 < 最大允许扫描变化报告年龄
当前观察帧.新增观察簇候选数量 == 0
当前观察帧.高风险未知簇数量 == 0
```

### 6.3 目标跟踪观察报告

回答：

```text
指定簇 / 候选目标是否还在？
它的特征是否稳定复现？
```

输出：

```text
双目相机.主观察运行模式 == 目标跟踪观察
目标观察簇.跟踪状态 == 稳定
目标观察簇.丢失状态 == 未丢失
目标观察簇.最近观测年龄 < 最大允许观测年龄
目标观察簇.距离复现离散度 < 最大允许离散度
目标观察簇.空间坐标复现离散度 < 最大允许离散度
```

### 6.4 相机线程内部可以复杂，但对外收敛

相机内部可以做：

```text
ROI
多帧融合
分辨率调整
配置学习
分簇
重捕获
质量诊断
稳定特征统计
```

但对自我侧暴露的仍然是：

```text
逐簇识别报告
扫描变化报告
跟踪报告
稳定特征字段
失败原因
配置摘要
```

## 7. 作用外设线程：以机械手为例

机械手属于改变一阶特征值的外设。

它可以改变：

```text
机械手自身一阶特征:
    机械手末端.空间坐标 == 目标坐标
    夹爪.开合度 == 目标开度
    夹爪.夹持力 > 最小夹持力

其他存在一阶特征，可间接造成:
    目标物.空间坐标变化
    目标物.姿态变化
```

但不能说：

```text
机械手直接改变关系
```

关系是自我根据一阶特征计算出来的二次特征。

例如：

```text
机械手末端.空间坐标
杯子.空间坐标
    -> 自我计算:
        机械手末端_杯子.距离值
```

所以机械手线程输出：

```text
机械手.动作执行状态 == 已执行
机械手末端.空间坐标 == 当前坐标
夹爪.开合度 == 当前开合度
夹爪.夹持力 > 某值
机械手.错误状态 == 无错误 / 有错误
```

自我再用相机、力传感器、编码器等感知外设验证动作效果。

## 8. 多外设协同模式

自我经常需要：

```text
作用外设 + 感知外设
```

形成闭环。

标准链：

```text
动作前感知
    -> 自我预测动作结果
    -> 作用外设执行
    -> 动作后感知
    -> 自我比较预测与观察
    -> 自我归因
    -> 世界树更新因果
```

例如机械手配相机：

```text
1. 相机跟踪目标观察簇。
2. 自我预测机械手动作后目标一阶特征变化。
3. 机械手执行动作。
4. 相机重新跟踪目标簇。
5. 自我比较目标位置误差。
6. 自我判断动作结果归因状态。
7. 世界树更新该动作因果成立 / 失败次数。
```

注意：

```text
相机验证动作后的一阶特征；
自我计算二次特征；
自我判断关系是否变化。
```

## 9. 任务管理工作线程的承接职责

任务管理工作线程是外设消息第一接收者。

职责：

```text
1. 接收外设线程消息。
2. 校验消息完整性。
3. 匹配等待任务。
4. 匹配活跃需求。
5. 更新最新缓存。
6. 生成任务回执。
7. 生成派生需求消息。
8. 生成动作动态输入。
9. 上报自我线程裁决。
```

它不能：

```text
直接写需求树
直接写世界树真值
直接结算安全 / 服务值
```

## 10. 自我线程的裁决职责

自我线程接收任务管理侧上报后：

```text
1. 校验父需求。
2. 校验目标宿主。
3. 校验目标特征类型。
4. 校验比较符，只允许 大于 / 小于 / 等于。
5. 校验目标值。
6. 校验来源因果 / 来源动态。
7. 去重、合并、循环截断。
8. 通过统一需求树更新指令入树。
9. 决定哪些观察报告进入世界树。
```

完整链路：

```text
外设线程生产
    -> 任务管理线程承接
        -> 自我线程裁决
            -> 需求树 / 世界树更新
```

## 11. 实时性和舍弃策略

每个外设控制线程必须支持实时性策略：

```text
不是所有消息都处理；
不是所有报告都上报；
不是所有结果都入树。
```

可以舍弃：

```text
过期扫描变化报告
重复报告
无需求命中的观察材料
低优先级局部细分
中间跟踪帧
低优先级配置学习样本
```

不能舍弃：

```text
安全事件
活跃任务回执
状态跃迁
跟踪目标丢失
外设错误
影响父需求判断的缺口事实
```

外设报告处理策略应记录：

```text
外设观察报告.处理策略 == 正式承接 / 仅缓存 / 降级处理 / 摘要保留 / 已丢弃
外设观察报告.丢弃原因 == 过期 / 重复 / 无需求命中 / 队列积压
```

## 12. 外设线程与 OS 线程的关系

工程规则：

```text
逻辑上，每个外设必须有独立控制域；
高频、高实时、强状态外设，使用独占 OS 线程；
低频简单外设，可以共享线程池，但必须有独立命令队列和状态机。
```

示例：

```text
双目相机:
    独占线程，必要。

机械手:
    独占线程，必要。

底盘:
    独占线程，建议。

灯光:
    可共享线程池，但逻辑上独立控制域。

温度传感器:
    可共享采样线程，但逻辑上独立外设代理。
```

更严谨的规则：

```text
每个外设实例必须有独立控制域；
是否独占 OS 线程，取决于实时性、状态复杂度和驱动要求。
```

在当前系统中，双目相机、机械手这类核心外设建议都独占线程。

## 13. 禁止项

禁止：

```text
1. 让外设控制线程直接写自我需求树。
2. 让外设控制线程直接写世界树真值。
3. 让外设控制线程直接结算安全值或服务值。
4. 让自我线程直接消费高频外设原始流。
5. 让任务管理线程临时管理高实时外设驱动和长时状态。
6. 多个任务绕过外设控制域同时控制同一物理外设。
7. 把外设内部采集、滤波、分割、规划、重试等私有过程登记为自我可见本能方法。
8. 把作用外设的执行成功直接解释成目标需求满足。
9. 把感知外设的观察报告直接解释成世界树真值。
10. 把低频简单外设共享线程池理解成没有独立控制域。
```

## 14. 最终定案

```text
每个外设实例必须有独立控制域；
每种外设都应有独立的控制线程或外设代理线程；
高实时、高带宽、状态复杂的物理实例最好独占 OS 线程。
外设线程负责外设生命周期、命令串行化、状态缓存、报告生产和错误隔离；
任务管理工作线程负责接收外设消息、匹配任务和需求、生成回执或派生需求消息；
```
