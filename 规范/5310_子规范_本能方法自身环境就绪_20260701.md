## 2. 上级约束

1. 本规范服从 `规范/规范目录.md`、0050 总纲、0300 冲突清单和对应根规范。
2. 历史来源中与当前根规范冲突的表述不进入当前权威口径。
3. 旧名称、旧结构和旧阶段口径必须按 `规范/0300_规范冲突与前后矛盾清单_20260701.md` 的 C001-C008 收束，不得在本规范中恢复历史并列结构、旧字段身份或旧执行来源。
4. 任务筹办 / 任务执行只作为任务管理生命周期普通函数；动作来源、方法注册和方法选择必须服从 0050 总纲、3200 任务根规范、3300 方法根规范和 1170 动态根规范。
5. 文本、日志、注释、临时 JSON、自由字段和显示摘要不得承载正式机器逻辑或业务状态。

## 3. 当前有效规则

以下条款由历史来源按当前根规范修订抽取；若条款与第 2 章或上级规范冲突，以上级规范和第 2 章为准。

1. 每个本能方法在执行自己的核心逻辑之前，必须先确保“自己作为方法”已经完整存在。
2. 本能方法是自我的最小可执行动作，因此“自身环境就绪”还必须保证：
3. 若只存在函数入口、方法头或动作句柄，但没有明确输入参数与输出结果规格，该方法只能处于待补齐状态，不得进入叶子任务的可执行本能动作阶段。
4. 真正执行本能函数时，必须以方法条件节点作为参数设置、参数匹配和特征值范围判断的直接依据。
5. 条件节点匹配成功，才允许进入本能核心逻辑。
6. 其中第 1 段是硬前置，不允许跳过。
7. 第 2 段必须遵循：
8. 禁止在第 2 段直接绕过条件节点，只按输入包字段拼装执行参数。输入包只能作为“实参来源”，不能替代条件节点成为规格权威。
9. 关键结构的职责不得混用：
10. 筹办阶段可以用方法头和能力签名做候选召回与预筛选；执行阶段必须回到条件节点完成本轮输入绑定。
11. 因此，差异应集中在“确认专属规格”函数里，而不是分散在每个本能方法函数体开头。
12. 环境结构应允许记录本方法的首个可用条件节点和条件匹配结果。若代码暂未把条件节点指针放入环境结构，也必须在读取输入前通过统一 helper 从方法首节点解析条件节点。
13. 禁止把两者混为一谈：
14. 不得把目标方法虚拟存在当作当前学习本能方法自己的虚拟存在；
15. 不得把当前学习本能方法的条件 / 结果场景当作目标方法的条件 / 结果场景；
16. 不得在确保自身环境阶段修改目标方法结构，目标方法结构补齐属于核心逻辑阶段或输出阶段。
17. 练习方法不得把目标方法运行账缺口补写到目标方法虚拟存在。
18. 目标方法的运行次数、成功次数、最近连续成功次数、方法状态和稳定状态，只能由目标方法自身执行路径更新。
19. 自身方法环境确保失败属于非正常逻辑错误或关键结构缺失，不允许静默兜底。
20. 非正常逻辑错误，必须报错和记录日志。
21. 本方法规格未就绪。若该方法已被召回执行，应记录错误并返回条件不足。
22. 当前方法在本轮上下文不可用，返回参数绑定失败 / 条件不满足。
23. 这四类不得混成“目标方法缺口”，也不得静默兜底成执行成功。
24. 新增禁止项：
25. 1. 禁止把方法首节点当作执行参数依据。
26. 2. 禁止仅凭能力签名直接执行本能核心逻辑。
27. 3. 禁止在存在方法条件节点时绕过条件节点直接读取输入包执行。
28. 4. 禁止将条件范围读取长期藏在学习函数内部，执行函数必须能通过公共 helper 读取条件节点范围。
29. 1. 禁止只因方法首节点存在就跳过规格确认。
30. 2. 禁止在读取输入前未创建本轮运行虚拟存在。
31. 3. 禁止把目标方法环境当作自身方法环境。
32. 4. 禁止把任务筹办、任务执行、自我线程主循环、任务界面线程承接注册成本能方法。
33. 5. 禁止用方法名 / 动作名 / 显示文本判断语义，能力匹配仍以特征类型、状态和能力签名为准。
34. 6. 禁止用静默兜底替代规格失败报错。
35. 本规范约束普通本能方法的完整执行壳：方法首节点、动作句柄、方法虚拟存在、条件 / 结果场景、本轮运行虚拟存在和方法运行账都必须在执行前就绪。
36. 因此，任务状态被动提交入口必须保留：
37. 禁止把该例外扩展到普通主动方法、需求域提交、方法域提交或世界事实提交。
38. 本能方法执行前必须先确保自身方法环境。

## 4. 使用边界

1. 本规范用于计划、详细设计、代码修改和验收前的规则回读。
2. 本规范不能作为代码实现完成、业务闭环完成、自我苏醒完成或初步成熟完成的证据。
3. 需要展开历史论证时，只能把 `规范/旧规范/` 中的原文件作为追溯材料，不得让旧文件反向覆盖本规范。
