## 1. 总口径

```text
因果信息让学习从“随机试错”变成“定向补缺”。
```

因果信息在学习中的作用，不只是补完方法，而是告诉自我：

```text
该学什么；
为什么学；
怎么验证学会了；
学到的东西能不能复用。
```

学习的核心对象是两类因果的缺口和证据：

```text
状态变化因果：
    证明状态 A -> B 的变化存在。
    学习层只能把它作为补动作、补条件、补来源、补证据的线索。

动作致变因果：
    证明动作 / 方法可以造成 A -> B。
    学习层可以围绕它补稳定度、适用范围、好用度和执行验证证据。
```

可执行完整因果模板的核心形式是：

```text
条件状态 + 动作 -> 结果状态
```

所以学习不是笼统地“学一个方法”，而是补完这三个位置：

```text
补条件：
    这个动作在什么条件下有效？

补动作：
    当前条件下，做什么动作能得到目标结果？

补结果：
    这个条件下执行这个动作，会产生什么结果？
```

因此，因果信息在学习中的第一用途是定位缺口：

```text
条件
动作
结果
参数
副作用
适用范围
验证证据
```

学习层是方法域的候选生成层，只能生成学习候选、方法候选、条件结果对候选、动作候选、参数映射候选、失败缺口和练习收益证据。学习层不得直接宣布方法已好用、因果已验证、任务已完成、需求已满足或安全 / 服务值可结算。最终入账必须由方法运行账、动作动态、因果验收和自我治理入口裁决。

## 2. 因果缺口与学习需求

不同因果残缺，对应不同学习需求。

### 2.1 只有状态变化，没有动作

形式：

```text
状态 A -> 状态 B
动作未知
```

这是状态变化因果的典型学习入口。它在尚未稳定或尚未验证时也称状态变化线索。

学习目标：

```text
找出是什么动作 / 事件导致了 A -> B。
```

对应学习需求：

```text
补动作
寻找致变动作
追踪来源动态
分析场景变化
观察类似动态
来源归因
外部事件确认
```

禁止直接生成方法候选。只有补出动作致变因果后，才能进入普通方法候选链。

示例：

```text
温度正常 -> 温度过高
```

此时要学的是：

```text
是什么导致温度升高？
高负载？
环境温度？
风扇故障？
电源异常？
```

### 2.2 有动作和结果，但不知道条件

形式：

```text
动作 X -> 结果 Y
条件未知
```

学习目标：

```text
这个动作在什么情况下有效？
```

对应学习需求：

```text
补条件
补适用范围
补禁止条件
补参数边界
```

示例：

```text
降低负载 -> 温度下降
```

还要继续学习：

```text
什么温度下有效？
什么硬件状态下有效？
风扇坏了还有效吗？
环境高温时还有效吗？
```

### 2.3 有条件和动作，但不知道结果

形式：

```text
条件 C + 动作 X -> ?
```

学习目标：

```text
执行这个动作会产生什么结果？
```

对应学习需求：

```text
补结果
补副作用
补失败结果
补风险结果
```

示例：

```text
条件：系统高负载
动作：降低任务并发
结果：？
```

需要学习：

```text
温度是否下降？
服务是否下降？
任务是否延迟？
是否触发新的需求？
```

### 2.4 有目标结果，但不知道动作

形式：

```text
当前条件 C
目标结果 Y
动作未知
```

学习目标：

```text
找出能够导致 Y 的动作或方法。
```

对应学习需求：

```text
补动作
生成方法头
寻找候选方法
建立执行入口
```

示例：

```text
目标：降低关机风险
```

系统需要反推：

```text
哪些动作能降低关机风险？
提高硬件稳定性？
降低异常行为？
增加人类信任？
进入保护模式？
请求维护？
```

## 3. 因果信息决定怎么学

因果信息不只说明缺什么，还决定学习方式。

学习入口按两类因果绑定：

| 学习入口 | 来源因果 | 目标 |
| --- | --- | --- |
| 观察学习 | 状态变化因果 | 补动作、补条件、补来源、补外部事件归因 |
| 尝试学习 | 候选动作和可观测后果 | 补结果、补条件、补副作用、补适用范围 |
| 练习 | 已有动作致变因果或练习收益因果 | 补稳定度、补适用范围、补好用度 |

### 3.1 观察学习

```text
从已有动态中提取状态变化和动作。
```

适用：

```text
已有动态证据；
风险较高，不宜主动试错；
动作来源可从动态链追溯。
```

### 3.2 尝试学习

```text
在先天硬保护壳内执行受限可观测动作，观察结果。
```

适用：

```text
有真实动作入口；
不命中先天硬保护壳或已知致命禁区；
动作幅度可限制；
当前缺结果或缺适用范围；
尝试前后状态可记录；
输出结果场景可验证；
后果可由特征比较表达。
```

注意：

```text
尝试学习不要求尝试前已经知道动作安全。
安全边界不是尝试前的许可证，而是尝试后由后果样本、特征比较和因果沉淀逐步形成的知识产物。
```

### 3.3 验证学习

```text
重复测试已有因果，更新稳定度。
```

适用：

```text
已有状态变化因果、动作致变因果或候选因果模板；
证据次数不足；
需要判断是否稳定可复用。
```

### 3.4 对比学习

```text
比较同一动作在不同条件下的结果。
```

适用：

```text
动作有时有效、有时无效；
需要补条件、禁止条件或参数边界。
```

### 3.5 反例学习

```text
记录动作失败或产生副作用的情况。
```

适用：

```text
执行后目标未达成；
出现副作用；
需要更新失败次数、风险结果或不适用条件。
```

### 3.6 练习方法与目标方法账本边界

`自我_练习` 是练习方法 A，它的练习对象是目标方法 B。

练习的职责是：

```text
复用或构造练习输入场景；
调用目标方法 B 的真实动作入口；
让 B 自己运行起来；
读取 B 运行后由 B 自身留下的运行账和方法状态；
把观察结果、好用差距和失败原因写入 A 的运行存在 / 输出结果场景。
```

练习不得代替目标方法改写目标方法虚拟存在。禁止由 A 写入 B 的：

```text
方法运行次数；
方法成功次数；
方法最近连续成功次数；
方法状态；
方法稳定状态；
最近运行虚拟存在；
其他属于 B 自身运行账的特征。
```

B 的执行成功 / 失败，以 B 的运行结果和 B 自己写下的运行账为准。A 自身执行成功不等于 B 成功。

若 B 被调用后没有自行更新运行账，A 只能记录：

```text
目标方法未自行更新运行账；
目标方法运行账缺失；
当前连续成功数；
目标连续成功数；
当前方法状态；
目标方法状态。
```

并输出结构化差距或缺口回执，供后续派生需求 / 排错使用。A 不得补写 B 的运行账来制造好用结果。

方法达到 `好用` 的第一版练习判据是：

```text
目标方法 B 自身方法状态达到 好用；
目标方法 B 自身最近连续成功次数 > 3。
```

更完整的好用判据还包括：

```text
目标方法头节点声明的特征类型有明确值域；
所有条件节点值域覆盖该方法头节点的目标值域；
所有条件结果对都能稳定运行。
```

这些覆盖值域和稳定运行判据属于后续扩展。第一版不得由练习代写账本绕过。

### 3.7 尝试 / 练习启动的学习收益因果链

尝试学习或练习不是因为存在“学习需求”就必然启动。它必须具备一条最小学习收益因果链：

```text
尝试 / 练习动作
-> 产生因果证据
-> 补全或验证因果模板
-> 方法状态 / 稳定度 / 适用范围改善
-> 父任务可继续筹办或执行
-> 父需求有机会满足
```

形式化为：

```text
L -> E -> H -> M -> T -> D
```

其中：

```text
L = 学习任务或练习任务
E = 新因果证据
H = 被补全或验证的因果模板
M = 被改善的方法
T = 被解除阻塞的父任务
D = 被推动的父需求
```

没有这条链，尝试 / 练习不得进入主需求竞争，避免为了学习而学习、为了练习而练习。

启动尝试或练习至少需要满足：

```text
1. 有父任务或父需求来源。
2. 明确父任务或父方法卡在哪里。
3. 卡点能表达成因果缺口。
4. 存在真实动作入口，或至少存在可被进一步查找的候选动作。
5. 尝试不命中先天硬保护壳或已知致命禁区。
6. 动作幅度可限制，尝试失败不会破坏系统基本运行壳。
7. 尝试前状态、尝试动作和尝试后状态可以观察和记录。
8. 尝试后果能通过特征比较表达。
9. 尝试结果能更新方法或因果模板。
```

尝试学习用于因果模板还不完整或尚未验证：

```text
缺结果：
    已知 C + A -> ?
    条件 C 可满足，动作 A 有真实入口，尝试前后状态可观察。

缺条件：
    已知 ? + A -> R
    动作 A 有真实入口，结果 R 可观察，可在不同状态下比较。

缺动作：
    已知 C + ? -> R
    必须先有候选动作；若没有候选动作，只能生成寻找候选动作、观察类似动态或请求外部信息的需求候选。
```

练习需要已有可练习对象和可验证收益链。它通常需要已有动作致变因果；若目标是让 `自我_练习` 本能方法先运行起来，则至少需要内部治理层的练习收益因果：

```text
方法缺口存在
-> 练习产生因果证据
-> 方法状态 / 条件结果对 / 稳定度改善
-> 父任务可继续筹办
-> 父需求有机会满足
```

第一版允许内部治理练习链作为出生期被动触发假设或治理初始模板，先让练习方法在硬保护壳内运行；但不得伪造目标方法成功，不得代写目标方法运行账，不得把练习收益因果当作目标业务动作致变因果。

练习用于已有动作致变因果或练习收益因果但稳定度不足：

```text
C + A -> R 已存在；
稳定度不足 / 成功次数不足 / 失败边界不清；
当前条件 C 可满足；
动作 A 可执行；
结果 R 可观察；
练习不命中先天硬保护壳或已知致命禁区。
```

因此：

```text
练习需要已有动作致变因果或练习收益因果；
尝试需要真实动作入口、受限执行条件和可观测后果；
候选因果只影响尝试优先级，不是启动前置；
安全边界由尝试后果后天生成和完善；
缺动作且无候选动作时，不启动尝试或练习。
```

### 3.8 先天硬保护壳与后天安全边界

必须区分：

```text
先天硬保护壳：
    工程运行、权限、预算和提交链的硬限制。
    它不是后天学习出来的安全知识，而是系统不能越过的运行壳。

后天安全边界：
    由尝试前状态、动作、尝试后状态、特征比较、后果评价和因果沉淀逐步形成。
    它不是第一次尝试前必须已知的前置条件。
```

先天硬保护壳包括但不限于：

```text
不能越权写系统核心结构；
不能无来源提交世界事实；
不能伪造动作动态；
不能直接结算安全值；
不能把 改变特征值 当成业务方法；
不能在无动作句柄时伪造可执行入口；
不能绕过领域提交方法改写任务、需求、方法或世界树事实。
```

后天安全边界由以下链路形成：

```text
受限可观测尝试
-> 尝试前状态
-> 动作动态
-> 尝试后状态
-> 特征比较
-> 因果样本
-> 风险 / 副作用 / 适用范围归纳
-> 后天安全边界
```

因此：

```text
缺少已知安全边界，不等于禁止尝试；
缺少真实动作入口，禁止尝试；
缺少可观测后果，禁止有效学习尝试；
命中先天硬保护壳或已知致命禁区，禁止尝试。
```

## 4. 补完方法

方法不是孤立函数，而是一个因果模板：

```text
输入条件场景
+ 动作
-> 输出结果场景
```

因果信息可以补：

```text
方法条件
方法动作
方法结果
方法参数
方法执行入口
方法副作用
方法稳定度
```

对应关系：

| 因果缺口 | 学习产物 |
| --- | --- |
| 缺条件 | 条件节点、适用场景、禁止条件 |
| 缺动作 | 方法头、动作语义、执行入口 |
| 缺结果 | 结果节点、主结果、副结果 |
| 缺参数 | 参数绑定规则 |
| 缺验证 | 成立次数、失败次数、稳定度 |
| 缺证据 | 来源动态、来源任务、来源方法 |

核心是补条件、补动作、补结果；参数、入口、副作用、验证、证据是辅助。

## 5. 反推方法

当自我有一个需求目标：

```text
我要让状态 B 出现。
```

因果信息可以反查：

```text
什么动作曾经导致过 B？
什么条件下能导致 B？
是否有稳定模板？
是否有副作用？
```

示例：

```text
目标：温度下降
```

可反推候选动作：

```text
降低负载
开启散热
暂停非关键任务
请求维护
转移运行环境
```

随后按因果稳定度和当前条件排序：

```text
哪个动作最可靠？
哪个动作最快？
哪个动作副作用最小？
哪个动作在当前条件下适用？
```

任务筹办因此不只是找名字相似的方法，而是找能导致目标结果的方法。

但因果链不是用来凭空制造动作能力。因果链在方法主链中的作用，是组织自我已经实现的最小本能方法，形成复杂能力的候选执行路径。

```text
复杂能力 = 已实现本能方法节点 + 条件顺序 + 输入输出接续 + 结果验收。
```

因此，因果反推得到的每个动作节点都必须落回一个已实现本能方法或方法动作入口；该动作必须已经有明确输入参数、明确输出结果和可记录动作动态。不能落回已实现本能方法的链段，只能作为学习缺口、观察需求、外部支撑需求或替代动作搜索依据。

### 5.1 因果转化为自我方法

因果信息转化为自我方法的关键，不是“存在一条因果模板”本身，而是判断：

```text
自我能否制造因果模板的触发条件。
```

动作致变因果 / 可执行完整因果模板为：

```text
条件状态 C + 动作 A -> 结果状态 R
```

若要把它转成自我方法，必须同时满足：

```text
1. 自我能产生或维持条件状态 C。
2. 动作 A 能落回自我已实现的本能方法 / 方法动作入口，或明确进入补动作学习链。
3. 执行后能够观测并验收结果状态 R。
```

因此标准句式为：

```text
自我能产生因，
且能用已实现本能方法控制动作，
并能验得果，
才可能固化为方法。
```

如果只有状态变化因果 / 状态变化线索：

```text
因状态 C -> 果状态 R
动作未知
```

则不能直接固化为自我方法，只能生成学习需求：

```text
学习导致 C -> R 的动作或事件。
```

如果动作已知但自我不能执行或诱发，则也不能固化为方法，只能生成：

```text
补动作执行能力；
补动作请求能力；
寻找替代动作；
或确认外部动作可触发条件。
```

这里的“判断 / 反推 / 匹配”本身只是中间过程。

```text
因果反推自我动作组合；
判断条件状态是否可由自我产生；
判断动作是否可执行或可诱发；
候选方法排序和风险评分；
```

这些步骤如果只返回本轮候选和诊断结果，不持久改写方法、任务、需求或世界树特征状态，可以由普通逻辑代码实现，不需要本能方法，也不生成动作动态。

只有当系统把反推结果正式写入方法或治理账时，例如：

```text
提交方法动作入口；
提交动作序列入口；
提交复杂能力组织结果；
建立条件结果对；
提交方法状态变化；
派生学习需求入树；
```

才进入需要明确动作来源的方法化提交段。

### 5.2 自我可产生状态集

因果转方法前，必须维护“自我可产生状态集”。

其来源包括：

```text
已有方法的结果状态；
已完成任务的输出结果场景；
已验证因果模板的结果状态；
自我可执行动作的直接结果；
自我可请求或诱发的外部动作结果。
```

用途：

```text
拿自我可产生状态集，去匹配因果模板中的条件状态 C。
```

若：

```text
C 可由自我产生
A 可由自我执行或诱发
R 是目标结果或有益结果
```

则可生成候选方法。

若 C 不可产生，则派生：

```text
让 C 成立的子需求。
```

若 A 不可执行，则派生：

```text
补动作 / 补执行能力 / 请求外部动作 / 寻找替代动作 的学习需求。
```

### 5.3 正向达成与反向阻断

因果转方法必须区分好结果和坏结果。

若因果模板指向好结果：

```text
C + A -> 好结果 R
```

可以正向利用：

```text
产生 C；
执行或诱发 A；
获得 R。
```

若因果模板指向坏结果或物理不安全事件：

```text
C + A -> 坏结果 P
```

不能生成“制造 C 或触发 A”的方法。

应反向投影为：

```text
避免 C；
阻断 A；
降低 C 的发生概率；
降低 A 的影响强度；
建立预警；
建立备份。
```

也就是说：

```text
好结果因果用于正向达成；
坏结果因果用于反向阻断。
```

## 6. 预测动作后果

学习后的因果信息应在执行前被使用。

候选动作出来后，自我应先判断：

```text
如果做这个动作，会发生什么？
```

因果模板可预测：

```text
主结果
副结果
风险结果
失败概率
适用条件
派生置信分
```

示例：

```text
动作：降低负载
预测：
    温度下降
    服务能力下降
    当前任务变慢
```

这样系统不会只看“能不能完成安全目标”，还要看：

```text
会不会伤害服务？
会不会引入新的风险？
会不会破坏其它任务？
```

这属于执行前因果审查。

## 7. 验证是否学会

学习不是生成模板，而是不断验证模板。

任务执行后，不只看：

```text
任务状态 = 完成
```

还要检查：

```text
预测结果是否发生？
目标状态是否变化？
副作用是否出现？
动作和结果之间是否有证据链？
```

示例：

```text
预测：降低负载 -> 温度下降
实际：温度没有下降
```

则：

```text
该因果模板失败次数 +1
稳定度下降
可能需要补条件
```

如果：

```text
预测：降低负载 -> 温度下降
实际：温度下降
```

则：

```text
成立次数 +1
稳定度上升
方法更可信
```

## 8. 深层学习需求

生存深层需求投影规范中定义的深层原因，也会生成学习需求。

因果链示例：

```text
硬件过热
<- 散热不足
<- 风扇积尘
<- 长期无人维护
<- 维护请求不被信任
<- 自我解释能力不足
```

由此可能生成学习需求：

```text
学习识别散热不足
学习检测风扇积尘
学习建立维护机制
学习生成可信维护请求
学习解释自身状态
```

这些不是凭空的高级需求，而是从因果链中长出来的。

## 9. 直接学习与工具学习

因果信息应区分两类学习：

```text
直接学习：
    学习点直接改变目标结果。

工具学习：
    学习点只是让别的学习或任务可执行。
```

示例：

```text
直接学习：
    学习降低温度的方法。

工具学习：
    学习如何调用降温接口；
    学习如何绑定参数；
    学习如何生成维护请求；
    学习如何记录证据。
```

因果信息用于判断：

```text
这个学习点在因果链上处于什么位置？
它是直接导致目标结果？
还是只支持另一个动作？
```

这能避免所有学习任务都被当成同等价值。

## 10. 防止乱学

没有因果信息时，系统可能会：

```text
看到缺口就学习；
看到异常就生成方法；
看到目标就乱试动作。
```

有因果信息后，学习需求必须说明：

```text
它补的是哪条因果链？
它缺的是条件、动作还是结果？
它能降低哪个风险？
它能帮助哪个需求？
它的证据来自哪里？
```

学习约束：

```text
没有目标结果，不乱补动作。
没有状态变化，不乱建因果。
没有动作证据，不建动作致变因果。
没有足够派生置信分，不用于高风险执行。
```

这让学习从“长野草”变成“长根系”：允许生长，但必须有目标、路径和证据。

## 11. 学习闭环

完整学习闭环：

```text
1. 观察动态
   - 初始状态
   - 动作
   - 结果状态

2. 沉淀因果
   - 有动作：形成动作致变因果 / 可执行完整因果模板
   - 无动作：形成状态变化因果 / 状态变化线索

3. 诊断缺口
   - 缺条件
   - 缺动作
   - 缺结果
   - 缺参数
   - 缺验证

4. 生成学习需求
   - 学条件
   - 学动作
   - 学结果
   - 学适用范围
   - 学副作用

5. 任务化学习需求

6. 执行学习任务

7. 验收结果
   - 是否补上缺口
   - 是否形成模板
   - 是否增加证据
   - 是否提高稳定度

8. 回写方法 / 因果模板

9. 父任务重筹办

10. 下一轮使用学到的因果
```

## 12. 与当前学习本能方法的关系

当前学习类本能方法仍按方法结构缺口承接：

```text
定向学习：
    偏向补动作、补方法动作、补执行入口。

尝试学习：
    偏向补条件结果对、补结果证据、形成可用依据。

练习：
    偏向补验证、补稳定度、补适用范围和好用度。
```

但这些本能方法不是学习的全部。它们只是当前方法学习链中的执行工具。因果信息还会服务需求投影、方法反推、执行审查、执行后验收和稳定度更新。

## 13. 最终口径

因果信息在学习和执行组织中至少有八个用途：

```text
1. 定位学习缺口：缺条件、缺动作、缺结果。
2. 生成学习需求：把因果缺口变成需求。
3. 补完方法：形成条件 + 动作 -> 结果。
4. 组织已实现能力：从目标结果找到可组合的本能方法链。
5. 预测后果：执行前判断收益、风险、副作用。
6. 验证学习成果：执行后更新成立次数、失败次数、稳定度。
7. 发现深层需求：从安全因果链上游生成长期学习目标。
8. 防止乱学：要求学习必须绑定目标、证据和因果路径。
```

一句话：

```text
因果信息在学习中的作用，是把“我要学”变成“我缺哪段因果，所以要学什么，并用什么证据证明学会了”；在执行中的作用，是把“我要做”变成“哪些已实现本能方法可以按什么因果顺序组成复杂能力”。
```
