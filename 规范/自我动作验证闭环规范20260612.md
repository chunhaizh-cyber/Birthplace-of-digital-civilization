## 0. 文档定位

本文档规定“自我”在执行任何动作时如何形成闭环验证。该规范覆盖两类核心场景：

1. **物理外部动作**：例如移动、转向、抓取、观察。实际回读主要来自 D455、IMU、编码器、触觉、电流反馈等外设。
2. **内部治理与方法动作**：例如需求治理、方法执行、虚拟存在状态修改、数据仓库写入。实际回读来自方法执行后虚拟存在中的实际值、仓库提交后的实际记录、治理规则执行后的实际状态。

核心目标：

```text
防止预测污染事实；
防止执行报告冒充事实；
防止目标值覆盖实际值；
使每个动作都有预测、执行、实际回读、验证、修正的闭环。
```

## 1. 总公理

### 1.1 事实来源公理

事实状态必须来自对应实在域的实际确认通道，而不能直接来自预测。

```text
物理外部域事实：
    来自 D455、IMU、编码器、触觉、电流反馈等外设观测或传感器融合结果。

内部虚拟存在域事实：
    来自方法执行后，虚拟存在中的实际字段、实际关系、实际状态、实际版本号。

治理域事实：
    来自治理规则执行后，需求、任务、方法、资源、约束关系中的实际治理状态。

数据仓库域事实：
    来自仓库提交后，可按主键或引用关系重新读取到的实际记录。

推理域事实：
    来自推理方法执行后，可检查、可复核的一致性状态、结论状态或约束满足状态。
```

### 1.2 预测禁止提交公理

预测态禁止直接写为事实态。

预测态只能存在于：

```text
动作事务；
预测模板场景；
候选状态；
计划状态；
内部模拟状态。
```

只有经过对应实在域实际回读后，系统才允许产生新的事实状态。

### 1.3 动作不等于事实公理

```text
发送控制指令 != 动作完成
调用方法 != 治理成功
方法返回成功 != 内部状态正确
写入请求成功 != 仓库事实已经形成
```

动作产生的只是“意图”和“执行事件”。事实必须来自实际回读。

### 1.4 事实性与正确性分离公理

实际回读得到的值是事实候选，但不一定是正确结果。

例如：

```text
目标：
    需求 D1 的优先级应为 1。

预测：
    D1.priority = 1。

方法执行后实际回读：
    D1.priority = 2。
```

此时事实是：

```text
D1.priority 实际上是 2。
```

验证结果是：

```text
动作未达到目标。
```

系统禁止把目标值 `1` 强行写为事实。

### 1.5 异常事实保留公理

当实际回读与预测冲突时，系统应保留实际回读结果，并标注为：

```text
异常事实；
待复核事实；
低置信事实。
```

系统禁止因为实际结果“不符合期望”而丢弃真实回读。

## 2. 基本概念

### 2.1 自我

自我是动作发起者、状态持有者和验证闭环的主体。

自我包含：

```text
物理本体；
内部世界；
需求环境；
方法环境；
数据仓库状态；
推理状态；
外设感知通道；
动作执行通道。
```

### 2.2 动作

动作是自我试图改变某个实在域状态的过程。

动作包括：

```text
物理动作；
内部治理动作；
方法执行动作；
数据仓库动作；
推理检查动作。
```

### 2.3 实在域

实在域是事实存在的上下文。不同实在域有不同的实际回读方式。

| 实在域 | 典型动作 | 实际回读来源 |
| --- | --- | --- |
| 物理外部域 | 移动、转向、抓取、观察 | D455、IMU、编码器、触觉、电流反馈 |
| 内部虚拟存在域 | 修改虚拟存在字段、创建内部关系 | 方法执行后的虚拟存在实际值 |
| 治理域 | 分配需求、调整优先级、选择方法 | 需求、任务、方法、约束对象的实际治理状态 |
| 数据仓库域 | 写入、删除、挂接、索引更新 | 仓库提交后重新读取的实际记录 |
| 推理域 | 生成结论、检查约束、规划 | 推理执行结果与一致性检查结果 |

### 2.4 状态分类

系统必须区分以下状态：

```text
目标态：
    希望达到的状态。

预测态：
    动作模型估计执行后会出现的状态。

执行报告态：
    执行器或方法返回的报告状态。

实际回读态：
    从对应实在域实际读取到的状态。

验证态：
    实际回读与目标、预测、约束比较后的结论。

事实态：
    系统承认为对应实在域当前实际情况的状态。

异常事实态：
    系统承认实际发生，但与目标、预测或约束冲突的事实。
```

## 3. 闭环总流程

任何动作必须遵循以下通用闭环：

```text
当前事实 S0
    ↓
建立动作事务 Tx
    ↓
生成目标态 G1
    ↓
生成预测态 S_hat1
    ↓
动作前验证
    ↓
执行动作 A
    ↓
对应实在域实际回读 R1
    ↓
重建实际状态 Sobs1
    ↓
比较 S_hat1、G1、Sobs1
    ↓
生成验证结论 V1
    ↓
提交正常事实 / 异常事实 / 待复核事实
    ↓
修正动作模型、恢复、重试或生成新需求
```

最简表达：

```text
事实 -> 预测 -> 执行 -> 实际回读 -> 验证 -> 新事实
```

其中：

```text
D455 是物理域实际回读器；
虚拟存在实际值是内部治理域实际回读器；
数据仓库重新读取是数据域实际回读器；
推理一致性检查是推理域实际回读器。
```

## 4. 动作事务规范

### 4.1 动作事务定义

动作事务是一次动作的生命周期记录。系统中的动作禁止只用裸指令表达，必须由动作事务承载。

动作事务至少包含：

```text
事务ID
父事务ID
动作类型
实在域
发起者
目标对象
当前事实快照
目标态
预测态
执行指令或方法调用
执行报告
实际回读态
验证结论
残差
置信度
开始时间
预测时间
执行开始时间
执行完成时间
回读时间
验证时间
提交时间
超时时间
前置版本号
后置版本号
失败原因
恢复策略
偏差记录集
纠偏建议集
长期学习统计引用
```

## 5. 场景承载规范

### 5.1 事实场景

事实场景是系统承认的当前实际状态。

事实场景可以进入世界链，但必须携带：

```text
来源；
时间；
置信度；
事务ID；
验证状态。
```

### 5.2 目标场景模板

目标场景模板表示希望动作达成的状态。

目标场景模板禁止直接提交为事实。

### 5.3 预测场景模板

预测场景模板表示动作模型预计的未来状态。

预测场景模板必须使用值语义或私有模板结构，禁止作为事实挂入世界链。

```text
目标态、预测态、候选态：
    使用模板场景。

事实态、异常事实态、持久观测态：
    在验证与提交策略允许后进入世界链或对应数据仓库。
```

### 5.4 实际回读场景模板

实际回读场景模板保存执行后从对应实在域读取到的状态。

它可以先作为模板场景存在，经验证后再按提交策略写入事实场景。

### 5.5 D455 观测场景

D455 的原始帧不能直接写成最终事实。D455 必须先形成观测场景：

```text
D455观测场景
    ├── 帧号
    ├── 观测时间
    ├── D455坐标系
    ├── 坐标单位
    ├── 置信度
    ├── 自我参照特征
    ├── 障碍物存在
    ├── 地面或空间结构
    └── 目标物体或视觉特征
```

之后再通过坐标变换进入自我本体坐标系或世界参考坐标系。

## 6. 实际回读接口规范

系统应定义统一的实际回读接口：

```cpp
class 实际回读器接口 {
public:
    virtual bool 支持实在域(枚举_实在域 域) const = 0;

    virtual bool 回读(
        结构体_动作事务& 事务,
        场景节点类& out实际回读场景模板,
        结构体_实际回读信息& out回读信息
    ) = 0;
};
```

不同实在域实现不同回读器：

```text
D455回读器：
    从 D455 帧缓存读取物理观测。

IMU回读器：
    读取姿态、角速度、加速度积分状态。

编码器回读器：
    读取轮速、位移或关节位置。

虚拟存在回读器：
    方法执行后从虚拟存在对象读取实际字段、关系和版本号。

需求治理回读器：
    从需求环境读取实际优先级、状态、约束、分配关系。

方法环境回读器：
    从方法环境读取方法实际状态、负载、可用性、执行结果对象。

数据仓库回读器：
    按主键、父子关系或索引重新读取仓库提交后的实际节点。

推理回读器：
    读取推理输出、冲突集、一致性检查和约束满足结果。
```

## 7. 预测接口规范

动作预测器负责根据当前事实和动作意图生成预测态。

```cpp
class 动作预测器接口 {
public:
    virtual bool 生成预测(
        结构体_动作事务& 事务,
        const 场景节点类* 当前事实场景,
        场景节点类& out预测场景模板
    ) = 0;
};
```

预测器必须满足：

```text
1. 只能写入预测场景模板。
2. 禁止写入事实场景。
3. 必须记录预测依据、预测时间、容差范围。
4. 应给出可验证特征，而不是只给自然语言描述。
```

## 8. 执行接口规范

动作执行器负责向外设、方法环境、需求环境、数据仓库或推理模块发出执行请求。

```cpp
class 动作执行器接口 {
public:
    virtual bool 执行(
        结构体_动作事务& 事务
    ) = 0;
};
```

执行器必须满足：

```text
1. 必须记录事务ID。
2. 必须记录执行开始时间和执行完成时间。
3. 执行器返回值只能作为执行报告态，不得直接作为事实态。
4. 对异步动作，必须记录可追踪的指令ID、帧号、版本号或回调标识。
```

## 9. 验证接口规范

验证器负责比较目标态、预测态和实际回读态。

```cpp
class 动作验证器接口 {
public:
    virtual 结构体_动作验证报告 验证(
        const 结构体_动作事务& 事务,
        const 场景节点类& 目标场景模板,
        const 场景节点类& 预测场景模板,
        const 场景节点类& 实际回读场景模板
    ) = 0;
};
```

验证器应支持以下比较方式：

```text
精确比较：
    用于枚举状态、布尔状态、主键引用关系。

容差比较：
    用于位置、角度、速度、时间、置信度。

区间比较：
    用于预测范围、传感器误差范围、治理负载范围。

AABB 或空间相交比较：
    用于 D455 物理空间障碍、目标物体、可通行区域。

语义一致性比较：
    用于需求状态、任务状态、方法绑定、治理约束。

版本比较：
    用于内部虚拟存在、数据仓库提交、治理对象变化。
```

## 10. 事实提交规范

### 10.1 禁止项

系统禁止以下行为：

```text
1. 禁止把预测场景模板直接挂入事实世界。
2. 禁止把目标态直接写为事实态。
3. 禁止把方法返回的“成功”直接当作治理事实。
4. 禁止把控制指令发送成功当作物理状态已经改变。
5. 禁止在没有实际回读的情况下用预测值补写事实。
```

### 10.2 正常事实提交

当实际回读置信度足够，并且验证成功或相似成功时，可以提交正常事实。

正常事实必须记录：

```text
事务ID
实在域
来源对象
实际回读时间
验证状态
置信度
残差
提交时间
```

### 10.3 异常事实提交

当实际回读置信度足够，但与目标或预测冲突时，必须提交异常事实或待复核事实，而不是提交预测值。

异常事实必须记录：

```text
实际值
目标值
预测值
残差
冲突类型
失败原因
是否需要恢复动作
是否需要重新规划
```

### 10.4 低置信事实处理

当实际回读置信度不足时，系统应进入待复核状态。

低置信回读不得直接覆盖高置信事实，除非恢复策略明确允许。

## 11. 物理外部域规范：D455 移动闭环样板

### 11.1 物理移动动作流程

```text
1. 读取当前事实位姿 S0。
2. 读取 D455 当前帧，确认路径安全。
3. 根据移动指令生成预测位姿 S_hat1。
4. 建立动作事务 Tx。
5. 发送移动控制指令，指令携带事务ID。
6. 移动中持续读取 D455 或其他安全传感器。
7. 动作结束后读取 D455 新帧、IMU、编码器等实际回读。
8. 生成实际回读场景。
9. 将 D455 坐标系转换到自我本体坐标系或世界参考坐标系。
10. 比较预测位姿和实际位姿。
11. 成功则提交正常事实。
12. 失败则提交异常事实，并进入停止、重定位、修正或重新规划。
```

### 11.2 D455 三层验证

物理移动必须支持三层验证：

```text
动作前验证：
    确认路径、地面、障碍、目标区域可接受。

动作中验证：
    持续检查新障碍、偏航、定位丢失、碰撞风险。

动作后验证：
    确认最终状态是否符合预测和目标。
```

### 11.3 D455 坐标规范

D455 观测值必须标明坐标系。典型转换链为：

```text
D455相机坐标系
    ↓
自我本体坐标系
    ↓
世界参考坐标系
```

场景中应显式记录：

```text
类型_坐标单位
类型_到父场景变换
类型_D455帧号
类型_观测时间
类型_观测置信度
类型_相对位置
类型_绝对位置
```

### 11.4 D455 回读有效性

D455 回读必须满足：

```text
1. 回读时间晚于指令发送时间。
2. 帧号晚于动作前使用的帧号。
3. 观测置信度达到动作要求。
4. 坐标变换链完整。
5. 若存在运动模糊或遮挡，应标记低置信或待复核。
6. 对关键动作，应要求连续若干帧稳定后再提交最终事实。
```

## 12. 内部虚拟存在域规范

### 12.1 内部方法动作流程

```text
1. 读取当前虚拟存在事实 S0。
2. 建立动作事务 Tx。
3. 生成目标态 G1。
4. 根据方法语义生成预测态 S_hat1。
5. 调用方法执行。
6. 方法返回执行报告态。
7. 从虚拟存在中重新读取实际字段、实际关系、实际状态和版本号。
8. 生成实际回读态 R1。
9. 比较 G1、S_hat1、R1。
10. 提交正常事实、异常事实或待复核事实。
```

### 12.2 回读来源限制

内部治理类动作的事实必须来自方法执行后虚拟存在中的实际值。

系统禁止把以下内容直接当作事实：

```text
方法输入参数
方法目标值
方法预测值
方法返回的成功标志
动作事务中的预测副本
```

合法事实来源包括：

```text
虚拟存在对象中的实际字段
虚拟存在对象中的实际关系
需求对象中的实际状态
任务对象中的实际状态
方法对象中的实际状态
约束对象中的实际状态
数据仓库中重新读取到的实际节点
```

### 12.3 版本要求

内部虚拟存在回读应记录前置版本号和后置版本号。

```text
前置版本号：
    方法执行前读取到的对象版本。

后置版本号：
    方法执行后重新读取到的对象版本。
```

若动作声称改变了对象，但后置版本号未变化，系统应标记为验证失败或待复核。

### 12.4 内部治理失败处理

内部治理动作验证失败时，系统应区分失败原因：

```text
约束冲突
权限不足
前置条件不满足
方法实现错误
并发修改覆盖
数据仓库写入失败
状态机转移非法
异步执行尚未完成
```

恢复策略可以是：

```text
回滚到动作前快照
生成补偿动作
重新选择方法
降低目标强度
请求重新规划
标记需求冲突
暂停该治理链
```

## 13. 治理域规范

治理域包括：

```text
需求；
任务；
方法；
资源；
约束；
优先级；
分配关系。
```

治理动作必须遵循：

```text
1. 治理动作必须有事务ID。
2. 治理动作必须有目标态和预测态。
3. 治理动作执行后必须从实际治理对象回读。
4. 治理事实以实际治理对象中的值为准。
5. 当实际治理状态与目标不一致时，必须保留实际状态并记录冲突。
```

示例：

```text
动作：
    把需求 D1 分配给方法 M3。

目标：
    D1.绑定方法 = M3。

预测：
    D1.绑定方法 = M3；
    M3.负载 + 1。

执行：
    调用需求治理方法。

实际回读：
    D1.绑定方法 = M2；
    D1.状态 = 已分配但冲突。

事实：
    D1 实际绑定 M2，并存在冲突。

验证：
    失败。

恢复：
    生成重新分配或冲突解除需求。
```

## 14. 数据仓库域规范

数据仓库动作包括向以下结构创建、删除、挂接、修改或索引更新：

```text
世界链；
特征值链；
需求链；
任务链；
方法链；
其他链式仓库。
```

### 14.1 提交后回读

数据仓库写入动作完成后，必须按主键、父子关系或索引重新读取实际节点。

```text
写入请求成功 != 仓库事实形成。

重新读取成功 + 结构一致性检查通过 = 仓库事实候选。
```

### 14.2 链结构一致性检查

对链式仓库，回读时应检查：

```text
节点主键存在
父指针符合预期
子链包含关系符合预期
同层上/下环关系有效
全链链上/链下关系有效
主信息类型符合预期
引用对象可解析
```

### 14.3 仓库异常事实

如果写入后重新读取到的结构与预测不一致，系统必须记录仓库异常事实，禁止用预测结构补写检查结果。

## 15. 推理域规范

推理动作包括：

```text
结论生成；
约束检查；
计划生成；
一致性验证。
```

推理域实际回读来自推理过程的可复核输出，而不是来自“我认为结论应当成立”。

推理动作必须至少记录：

```text
输入事实集合
推理方法
预测结论或目标结论
实际输出结论
冲突集合
约束满足状态
一致性检查结果
验证结论
```

如果推理输出与目标不一致，实际输出仍应记录为推理事实或异常推理事实。

## 16. 时间与版本规范

所有动作事务必须记录单调时间序列：

```text
T0 当前事实读取时间
T1 预测生成时间
T2 执行开始时间
T3 执行完成时间
T4 实际回读时间
T5 验证时间
T6 提交时间
```

约束：

```text
T1 >= T0
T2 >= T1
T4 >= T2
T5 >= T4
T6 >= T5
```

对于内部虚拟存在和数据仓库动作，应记录版本号：

```text
V0 动作前版本
V1 动作后版本
```

若动作预期改变对象，则 `V1` 应大于 `V0`，或者对象状态应有明确变化记录。

## 17. 置信度规范

实际回读必须包含置信度。

置信度来源可以是：

```text
传感器质量
帧稳定性
坐标变换完整性
方法执行完整性
仓库回读一致性
版本变化可信度
多源一致性
约束检查通过率
```

建议分级：

```text
高置信：
    可提交正常事实。

中置信：
    可提交待复核事实，禁止覆盖关键高置信事实。

低置信：
    只记录观测，不改变关键事实。

无置信：
    回读不足，动作进入等待、重试或失败。
```

## 18. 并发与锁规范

### 18.1 总原则

系统必须遵循：

```text
锁内只复制或交换轻量数据。
重计算、视觉解析、推理、匹配、验证应在锁外完成。
写入世界链或仓库时再短时间加锁。
```

### 18.2 禁止项

```text
禁止拿着 D455 帧锁执行点云重建后再写世界链。
禁止拿着消息队列锁等待外设回调。
禁止拿着世界链写锁执行长时间推理。
禁止在持有后序锁域时反向申请前序锁域。
```

### 18.3 推荐线程模型

```text
D455采集线程：
    只采集帧，写入帧缓存，快速释放帧锁。

感知解析线程：
    从帧缓存复制快照，在锁外解析点云、目标、位姿。

动作验证线程：
    读取事务、预测态、实际回读态，执行比较，生成验证报告。

事实提交线程或阶段：
    按提交策略短时间写入世界链、需求链、任务链、方法链或其他仓库。
```

### 18.4 锁顺序

多锁同时持有时，应遵循系统既有锁顺序原则：

```text
线程内部锁：
    消息队列 -> 帧 -> 外设 -> 参数

数据仓库锁：
    语素 -> 自然语言 -> 高级信息 -> 世界 -> 特征值

OpenGL 资源锁：
    尽量避免与数据仓库锁同时持有
```

动作闭环实现不得破坏该顺序。

## 19. 动作失败与恢复规范

动作失败不等于没有事实。动作失败通常意味着实际事实与目标或预测不一致。

失败处理必须遵循：

```text
1. 保留实际回读。
2. 记录预测与实际残差。
3. 标注失败原因。
4. 决定是否需要停止、回滚、补偿、重试、重新规划或生成新需求。
5. 修正动作模型或治理模型。
```

物理动作失败恢复：

```text
停止运动
重新定位
降低速度
重新规划路径
更新地面摩擦或运动误差模型
标记传感器异常
```

内部治理动作失败恢复：

```text
回滚快照
执行补偿方法
解除约束冲突
重新选择方法
调整需求优先级
标记方法不可用或低可信
```

## 20. 残差与学习规范

每次验证都应产生残差记录。

```text
残差 = 实际回读值 - 预测值
```

残差应按动作类型保存：

```text
物理移动：
    位置残差、角度残差、时间残差。

抓取动作：
    目标物体位置残差、夹持状态差异。

治理动作：
    状态差异、绑定差异、优先级差异、负载差异。

方法动作：
    输出对象差异、副作用差异、版本差异。

数据动作：
    结构差异、引用差异、索引差异。
```

系统应周期性统计残差，用于修正预测模型和执行策略。

## 21. 偏差纠正规范

闭环获得偏差之后，不能直接把事实改成预测值或目标值。纠偏的核心规则是：

```text
让实际值成为事实；
让偏差成为证据；
让下一次动作、预测模型、方法可靠度和目标策略一起被修正。
```

偏差不是要被擦掉，而是要被分配责任。不同类型的偏差对应不同修正对象。

### 21.1 四值与三类偏差

一次动作闭环至少有四个值：

```text
G = 目标值
P = 预测值
R = 实际回读值
E = 执行报告值
```

系统至少应生成三类偏差：

```text
目标偏差：
    DeltaG = G - R
    表示离目标还差多少。

预测偏差：
    DeltaP = R - P
    表示预测模型错了多少。

报告偏差：
    DeltaE = R - E
    表示执行报告与实际回读是否一致。
```

这三种偏差不得混用。

示例：

```text
目标 G = 300
预测 P = 295
实际 R = 274
执行报告 E = 成功
```

应得到：

```text
目标偏差 DeltaG = +26
预测偏差 DeltaP = -21
报告偏差 DeltaE = 实际未到位但执行报告说成功
```

对应纠正不是一个动作，而是多账本处理：

```text
1. 当前事实改为实际移动 274mm。
2. 目标还差 26mm，若安全和约束允许，生成补偿动作。
3. 预测模型记录当前环境下存在欠执行。
4. 方法 / 执行器报告可信度下降或进入待复核。
```

### 21.2 第一原则：事实只按实际值修正

闭环后的第一修正是事实态纠偏：

```text
S_fact = R
```

不得写成：

```text
S_fact = P
S_fact = G
S_fact = E
```

物理外部域中，D455 / IMU / 编码器等实际回读是事实候选；内部治理域中，方法执行后的虚拟存在实际值、治理对象实际状态或仓库重新读取结果是事实候选。目标值、预测值和执行报告不得覆盖实际回读。

事实纠偏按置信度处理：

```text
实际值可信：
    提交为事实。

实际值可信但与目标冲突：
    提交为异常事实。

实际值低可信：
    提交为待复核事实，不覆盖高置信旧事实。

实际值缺失：
    不提交事实，生成补观察、重读或回读不足处理。
```

### 21.3 五层纠偏

偏差获得后，必须按五层处理：

```text
1. 事实纠偏
2. 动作补偿
3. 预测模型修正
4. 方法 / 执行器可靠度修正
5. 需求 / 目标治理修正
```

#### 21.3.1 事实纠偏

事实纠偏只提交实际回读、异常事实或待复核事实，不提交预测值。

D455 观察链路应保持：

```text
D455 原始帧
    ↓
外设观察报告 / 材料包
    ↓
动作验证
    ↓
事实提交
```

禁止：

```text
D455 原始帧
    ↓
直接改事实
```

#### 21.3.2 动作补偿

目标偏差 `DeltaG = G - R` 用于判断是否需要补偿。

```text
|DeltaG| <= 容差：
    目标达成，不补偿。

|DeltaG| > 容差：
    生成补偿动作或重新规划需求。
```

补偿动作不得裸发，必须重新形成闭环：

```text
补偿需求
    ↓
动作前安全检查
    ↓
补偿预测
    ↓
执行补偿
    ↓
实际回读
    ↓
再次验证
```

#### 21.3.3 预测模型修正

预测偏差 `DeltaP = R - P` 用于修正模型。

```text
预测偏差小：
    当前模型可靠。

预测偏差稳定偏正或偏负：
    模型存在系统性偏差。

预测偏差忽大忽小：
    模型不稳定，可能受环境、外设质量或控制噪声影响。
```

模型参数不得被单次异常回读大幅改写，应使用缓慢更新：

```text
新模型参数 = 旧模型参数 * 0.9 + 本次估计 * 0.1
偏差均值 = EMA(历史偏差)
偏差方差 = EMA(偏差波动)
```

#### 21.3.4 方法 / 执行器可靠度修正

执行报告只能作为执行报告态，不得作为事实态。

当出现：

```text
执行报告：成功
实际回读：未达到目标
```

修正对象是：

```text
方法可靠度
执行器可靠度
执行报告可信度
方法前置条件
方法结果预测
```

内部方法纠偏应写入方法虚拟存在或方法统计事实，例如：

```text
方法_运行次数 += 1
方法_验证成功次数 += 1 或 0
方法_验证失败次数 += 1 或 0
方法_平均残差_EMA 更新
方法_可靠度_Q10000 更新
方法_最近失败原因 更新
方法_适用条件 更新
```

方法不是因为“执行过”就更可靠，而是因为“执行后实际回读符合目标和约束”才更可靠。

#### 21.3.5 需求 / 目标治理修正

有些偏差不是动作或方法错误，而是目标不可达、目标强度不合理或治理约束阻挡。

例如：

```text
目标：
    把物体移动到某位置。

实际：
    D455 发现目标位置有障碍。

归因：
    目标不可达，不应继续机械补偿。
```

此时应进入治理：

```text
目标不可达
    ↓
生成重新规划需求
    ↓
降低目标强度 / 改路径 / 改约束
```

内部治理同理：

```text
目标：
    需求 D1 优先级设为 1。

实际：
    规则约束导致只能设为 2。

纠偏：
    记录实际值 2；
    标记目标冲突；
    生成解除约束、调整目标或重排优先级的治理需求。
```

### 21.4 偏差纠正矩阵

| 情况 | 含义 | 修正对象 |
| --- | --- | --- |
| 实际值可信，目标达成，预测也准 | 正常完成 | 提交事实，轻微强化方法 |
| 实际值可信，目标达成，但预测不准 | 结果成功，模型不准 | 提交事实，修正预测模型 |
| 实际值可信，目标未达成，但预测准 | 动作不足或目标过强 | 生成补偿动作或重规划 |
| 实际值可信，目标未达成，预测也不准 | 执行 / 模型双错 | 停止、补偿、降信任、重新规划 |
| 执行报告成功，实际失败 | 报告不可信 | 降低方法 / 执行器报告可信度 |
| 执行报告失败，实际成功 | 报告机制有误 | 标为异常成功，修正报告逻辑 |
| 实际值低可信 | 观测不足 | 重新观察，不改高置信事实 |
| 多次同类偏差稳定 | 系统性偏差 | 更新动作模型 / 方法模型 |
| 多次同类偏差发散 | 不稳定 | 降级保护、限制动作、要求更多观测 |

该矩阵可以作为动作验证模块的策略表，但实现时不得只依赖自由文本；每个策略分支必须有结构化偏差类型、置信度、来源证据和后续承接入口。

### 21.5 D455 观察偏差纠正

D455 相关偏差主要分为观察质量纠偏和事实提交纠偏。

常见偏差：

```text
深度有效率不足；
空间坐标有效率不足；
候选存在不稳定；
跨帧跟踪丢失；
像素簇归属冲突；
观察材料缺失；
帧号没有更新；
坐标系或标定版本不一致。
```

纠正策略：

```text
低质量：
    不提交正常事实；
    生成重采样或补观察需求。

候选不稳定：
    多帧确认；
    暂存为待复核候选；
    不升级为确认存在。

跟踪丢失：
    进入重捕获；
    降低目标跟踪置信度；
    必要时生成目标丢失事实。

像素归属冲突：
    重新分区；
    请求更高质量观察；
    标记冲突区域。

帧新鲜度不足：
    等待新帧；
    不使用旧帧验证新动作。
```

D455 纠偏不得另开旁路，应沿既有观察承接链：

```text
观察材料
    ↓
质量评估
    ↓
候选验证
    ↓
确认候选
    ↓
事实提交
    ↓
若失败，派生补观察 / 重采样 / 跟踪恢复需求
```

### 21.6 内部治理偏差纠正

内部治理偏差的本质是：

```text
方法执行后的虚拟存在实际值
    与
目标值 / 预测值 / 方法报告值
    不一致。
```

示例：

```text
目标：
    任务状态 = 已完成

预测：
    方法执行后任务状态会变成已完成

实际回读：
    任务状态 = 等待回接

执行报告：
    成功
```

纠偏方式：

```text
事实纠偏：
    任务状态事实写为等待回接。

目标纠偏：
    原目标未完成，不删除需求。

方法纠偏：
    方法报告成功但实际未完成，降低方法验证成功率。

治理纠偏：
    进入回接、补条件、收束或重筹办。
```

内部方法偏差不能靠重新写目标值纠正，只能靠读取实际值后生成补偿治理动作。

### 21.7 纠偏动作也必须闭环

纠偏动作本身也是动作，也必须经过预测、执行、实际回读和验证。

例如第一次动作前进 300mm，实际 274mm；若生成补偿事务，应表达为：

```text
补偿事务 Tx2
    当前事实：已前进 274mm
    目标：再前进 26mm
    预测：补偿后总位移 300mm
    执行：发送补偿指令
    回读：D455 / IMU / 编码器
    验证：是否达到 300mm
```

禁止开环纠偏。任何“纠偏建议执行”都不得直接改事实状态，而应生成新的动作事务、治理需求、补观察需求、重新规划需求或安全降级动作。

### 21.8 偏差纠正器

系统可定义偏差纠正器，但它只能分析偏差和生成承接动作，不得直接绕过闭环改事实。

```cpp
class 动作偏差纠正器 {
public:
    结构_动作偏差记录 分析偏差(const 结构体_动作事务& tx);

    bool 生成纠偏承接(
        const 结构_动作偏差记录& 偏差,
        结构体_动作事务* out新动作事务,
        需求节点** out治理需求
    );
};
```

`生成纠偏承接` 的输出必须进入正式任务、需求、动作或观察链路。它不得裸写世界事实、需求满足、任务完成、方法可靠度或预测模型参数。

### 21.9 偏差进入长期学习

每次闭环后的偏差都应沉淀为统计：

```text
按动作类型统计；
按方法统计；
按外设统计；
按场景 / 环境统计；
按目标对象统计；
按时间窗口统计。
```

示例：

```text
移动类：
    动作类型：前进
    地面条件：光滑
    速度档位：低速
    平均预测偏差：-22mm
    偏差方差：5mm
    建议补偿系数：1.08

观察类：
    外设：D455
    场景：弱光
    平均深度有效率：4200 / 10000
    候选稳定率：低
    建议：提高曝光 / 多帧重采样 / 降低提交置信度

内部方法类：
    方法：调整需求优先级
    目标：优先级降至 1
    实际：常停在 2
    原因：约束规则阻挡
    建议：方法适用条件加入无强约束阻挡
```

长期学习不是记住失败文本，而是将偏差沉淀为可复核参数、适用条件、可靠度和后续治理证据。

### 21.10 固定顺序

偏差纠正顺序固定为：

```text
1. 先承认实际值。
2. 再判断目标是否达成。
3. 再归因偏差来源。
4. 再决定补偿、重观察、重规划、回滚或降级。
5. 最后更新模型和方法可靠度。
```

最简公式：

```text
事实修正：
    S_fact = R

动作补偿：
    下一目标 = G - R

模型修正：
    模型参数 = 模型参数 + 学习率 * (R - P)

方法修正：
    方法可靠度按验证成功率、报告偏差和残差稳定性更新

治理修正：
    若偏差不可由动作补偿解决，则生成新需求或调整目标
```

闭环得到的偏差，不是用来把事实拉回预测，而是用来让预测、动作、方法、目标和治理系统一起变得更诚实。

## 22. 最小实现范围

第一阶段必须实现两个样板闭环：

```text
D455 移动闭环；
内部方法执行闭环。
```

### 22.1 D455 移动闭环

最小特征集合：

```text
类型_动作事务ID
类型_动作验证状态
类型_自我绝对位置
类型_自我朝向
类型_预测自我绝对位置
类型_预测自我朝向
类型_D455观测位置
类型_D455观测朝向
类型_D455帧号
类型_观测时间
类型_观测置信度
类型_动作残差
类型_坐标单位
类型_到父场景变换
```

最小流程：

```text
1. D455 当前帧生成当前事实或观测事实。
2. 建立移动动作事务。
3. 生成预测位姿。
4. 发送移动指令。
5. D455 新帧生成实际回读。
6. 比较预测位姿与实际位姿。
7. 成功则提交正常事实。
8. 失败则提交异常事实并停止或重新定位。
```

### 22.2 内部方法执行闭环

最小特征集合：

```text
类型_动作事务ID
类型_方法ID
类型_目标对象ID
类型_前置版本号
类型_后置版本号
类型_预测字段值
类型_实际字段值
类型_验证状态
类型_失败原因
类型_动作残差
```

最小流程：

```text
1. 读取虚拟存在当前实际值和版本号。
2. 建立方法动作事务。
3. 生成预测值。
4. 调用方法。
5. 方法执行后重新读取虚拟存在实际值和版本号。
6. 比较预测值与实际值。
7. 实际值成为事实候选。
8. 不一致时提交异常事实并生成恢复动作。
```

## 23. 验收标准

实现满足以下条件时，可视为符合本规范 v1.1：

```text
1. 任一动作都有事务ID。
2. 任一动作都有目标态或明确说明无目标态。
3. 任一可预测动作都有预测态。
4. 预测态不会直接进入事实世界。
5. 执行报告不会直接成为事实。
6. 物理动作有外设实际回读。
7. 内部治理动作有虚拟存在实际值回读。
8. 数据仓库动作有提交后重新读取。
9. 验证结果包含成功、相似、失败、超时或回读不足之一。
10. 验证失败时保留实际回读，而不是覆盖为预测值。
11. 每次验证记录残差、置信度、来源和时间。
12. D455 采集线程不直接长时间持锁写世界链。
13. 锁顺序不违反系统既有锁域顺序。
14. 至少有 D455 移动闭环和内部方法执行闭环两个样板实现。
15. 目标偏差、预测偏差和执行报告偏差分账记录，不混用。
16. 纠偏动作本身必须重新进入动作闭环。
17. 方法可靠度和预测模型只能依据实际回读、残差、置信度和结构化偏差更新。
```

## 24. 最终原则

```text
动作不是事实。
预测不是事实。
执行报告不是事实。

事实来自对应实在域的实际回读。

物理域靠外设回读。
内部治理域靠虚拟存在实际值回读。
数据域靠提交后仓库回读。
推理域靠可复核推理结果回读。

验证负责判断实际事实是否符合目标和预测。
失败事实仍然是事实，必须被记录、解释和治理。

偏差不是把事实拉回预测的理由。
偏差是修正下一次动作、预测模型、方法可靠度、目标策略和治理链的证据。
```
