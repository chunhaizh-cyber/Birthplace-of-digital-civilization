1. 本规范服从 `规范/规范目录.md`、0050 总纲、0300 冲突清单和对应根规范。
2. 历史来源中与当前根规范冲突的表述不进入当前权威口径。
3. 旧名称、旧结构和旧阶段口径必须按 `规范/0300_规范冲突与前后矛盾清单_20260701.md` 的 C001-C008 收束，不得在本规范中恢复历史并列结构、旧字段身份或旧执行来源。

5. 文本、日志、注释、临时 JSON、自由字段和显示摘要不得承载正式机器逻辑或业务状态。

## 3. 当前有效规则

以下条款由历史来源按当前根规范修订抽取；若条款与第 2 章或上级规范冲突，以上级规范和第 2 章为准。

1. 这些消息不得进入自我线程治理邮箱，不得落自我内部世界治理事实，不得生成主动动态、被动动态、方法动作动态或治理动作动态。
2. 这些内容必须由任务管理界面线程按任务管理上行消息承接和上报，不得用通用线程状态变化消息替代。
3. 如果系统线程 ID 只能在线程入口内取得，创建者先发送带逻辑 ID 的创建消息；线程入口取得系统线程 ID 后，必须补发一次状态更新消息完成绑定。
4. 线程自身在生命周期或运行状态发生变化时，必须向控制面板线程信息模块发送状态变化消息。
5. 线程状态消息发送不得长期阻塞业务线程。控制面板队列不可用时，发送方应记录独立错误日志或诊断日志，并继续按线程自身职责收口。
6. 为避免线程创建早于控制面板线程启动导致创建消息丢失，线程状态消息必须先写入消息中间件缓存，再由控制面板线程信息模块消费。
7. 线程自身退出前必须发送退出前消息。
