## 3. 当前有效规则

以下条款由历史来源按当前根规范修订抽取；若条款与第 2 章或上级规范冲突，以上级规范和第 2 章为准。

3. 它不能拥有安全、服务、观察、外设、学习等领域专用能力。
4. 领域前置关系必须先落在需求侧条件、世界树因果、临时因果视图、方法条件节点、条件结果对或已入树子需求中，再由任务筹办通用读取。
5. 都必须由对应本能方法完成，并由该方法生成动作动态。
6. 任务筹办不能在自己内部递归执行子任务、学习链或执行链。它发现缺口后只返回等待 / 派生 / 重筹办提示；后续由 `提交_生成缺口子需求` 或统一需求树更新提交入口正式生长需求，任务管理线程创建或推进子任务，再在下一轮筹办中读取已经回流的事实。

9. 每个任务都必须有方法头承接。
10. 不是每个任务都需要绑定单步本能方法。

13. 必须有复合方法 / 任务抽象方法承接。
14. 不再继续向下拆分，必须直接产生可验收结果。

17. 因此任务筹办必须先判断本轮任务形态：

26. 这些事实只是任务管理过程回执，不是方法动作动态。若要把候选方法集、当前方法、可执行输入参数场景等写入任务虚拟存在，必须由 `同步筹办回执到任务` 完成。

36. 候选方法排序或优先级
37. 如果当前方法最终写入任务虚拟存在，应由 `同步筹办回执到任务` 完成。
38. 选择当前方法必须采用分层排序。候选集必须先由“方法结果能力是否命中任务目标”完整填充，当前方法只能从候选集中选择。
39. 第一优先级是方法结果与任务目标的一致程度：
40. 目标宿主越一致越优先；
41. 目标特征类型越一致越优先；
42. 目标状态 / 目标值越一致越优先；
43. 满足关系越一致越优先；
44. 固定特征类型确定命中优先于参数化命中；
45. 直接目标结果命中优先于间接或待补齐命中。
46. 结果一致程度高的方法，即使当前还需要补条件、补参数或补状态，也优先于结果只粗略命中的方法。不能因为某方法当前更容易执行，就选择一个结果目标不一致的方法。
47. 在结果一致程度相同的候选之间，直接满足全部执行条件的方法优先：
48. 禁止项未命中。
49. 1. 禁止项少者优先；
50. 2. 风险约束少者优先；
51. 3. 前置冲突少者优先；
52. 4. 预计效率高者优先；
53. 5. 预计耗时少者优先；
54. 6. 能耗和资源占用少者优先；
55. 7. 副作用少者优先；
56. 8. 最近复现次数多、失败次数少、派生稳定分高者优先。
57. 方法不可用但已有学习链可推进；
58. 禁止项可通过子需求解除；
59. 需要任务筹办继续拆解缺口。
60. 需要外界反馈或观察。
61. 真正能改变 方法状态 / 条件结果对 / 参数 / 世界特征 的，必须是对应方法。
62. 对于 `方法状态 = 可用 / 好用` 这类目标，候选集不应写死为某一个学习方法，也不应按状态值特判学习方法。应先包含所有结果能力能够命中该任务目标的候选，再按“方法结果与任务目标的一致程度”选择；当前目标方法的缺口阶段只能通过候选方法自己的条件、结果能力和执行反馈体现。
63. 候选方法必须显式声明自身结果能力的目标特征类型和目标值。第一版固定口径：
64. 当任务目标是 `方法状态 = 好用` 时，`方法状态 = 好用` 的结果项优先于 `方法状态 = 可用` 的结果项；当任务目标是 `方法状态 = 可用` 时，`方法状态 = 可用` 的结果项优先。该选择来自结果能力与任务目标值的比较，不来自筹办函数对学习方法的硬编码。
65. `自我_练习` 与目标方法的账本边界必须保持清楚：
66. A 不得写入 B 的方法运行次数、方法成功次数、方法最近连续成功次数、方法状态、方法稳定状态和最近运行虚拟存在。
67. B 的成功 / 失败只能由 B 自己的运行结果和运行账确认。
68. 外界信息链、未知动作语义线索或因果补动作场景中，缺少“应执行什么动作”的语义判断。
69. 当前内部方法补齐场景中，候选方法缺方法动作 / 缺可执行入口不应直接由定向学习闭合。
70. 真正需要的是一组自我动作组合来获得目标状态。内部方法补齐场景必须先用因果信息
71. 需要把该本能函数绑定为目标方法的真实动作句柄。
72. 没有明确本能方法 ID 时，不得写入方法可执行入口数量，也不得把定向学习结果当作真实入口。
73. 多步动作组合不得被压扁成单个本能函数入口；此时应返回缺口回执：
74. 方法不可用：
75. 任务筹办要完成“初始状态 -> 就绪状态”这一整段，需要一组协作方法。
76. 每个中间特征变化都必须交给对应本能方法或方法动作入口落账。
