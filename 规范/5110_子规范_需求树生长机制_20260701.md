126. | 方法阻塞 -> 派生需求 | 必须，但可后置 | 建议 | 因果补完和学习需求前置 |
127. 不得恢复旧的：
128. 本能转换名称 -> 当前实现函数 -> 所属模块 -> 是否需要包装成本能方法
129. 代码枚举名应按项目现有 `枚举_本能方法ID` 风格再定，不在规范中直接占用枚举值。
130. 不是所有本能转换函数都必须立刻注册成本能方法。
131. 注册成本能方法应至少满足：
132. 1. 该转换需要被任务系统作为可执行方法调用。
133. 2. 该转换需要记录方法虚拟存在、运行账或条件结果对。
134. 注册成本能方法后，必须声明能力签名。
135. 不得按方法名称、动作名称、动作句柄、本能 ID 或固定编号命中。
136. 本能转换函数可以直接调用，但必须守住模块职责：
137. 禁止：
138. 执行需求任务化后无对应任务信息节点。
139. 参数不可配。
140. 3. 最后按需要注册成本能方法。
141. 不得反过来：
142. 1. 最小闭环必须由本能转换函数保证。
143. 2. 需要进入任务 / 方法 / 因果记录体系的转换，再包装为本能转换方法。
144. 3. 学习方法和外界探索方法只能增强需求树，不得成为需求树最小生长前提。

## 4. 使用边界

1. 本规范用于计划、详细设计、代码修改和验收前的规则回读。
2. 本规范不能作为代码实现完成、业务闭环完成、自我苏醒完成或初步成熟完成的证据。
3. 需要展开历史论证时，只能把 `规范/旧规范/` 中的原文件作为追溯材料，不得让旧文件反向覆盖本规范。
