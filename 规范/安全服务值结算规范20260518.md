## 1. 总口径

安全值 / 服务值结算不是把任务权重直接换成核心值。

正确链路是：

```text
叶子任务完成
    -> 来源需求满足
        -> 父链与世界树因果证据能归结到安全 / 服务目标特征变化
            -> 计算安全 / 服务结算贡献层级比例
                -> 计算目标实际达成比例
                    -> 检查副作用与派生因果置信分
                    -> 经过安全根控制规则
                    -> 结算安全值 / 服务值
```

一句话：

```text
父链与世界树因果证据共同决定能不能结算；
安全 / 服务结算贡献层级决定最多结算多少；
目标实际达成值决定本次正向达成多少；
副作用与派生因果置信分决定是否抵扣、降级或转为候选。
安全根控制规则决定安全收益是否受物理安全独占候选叠乘约束或风险余量限制。
```

## 2. 必须先过父链归因闸门

任务完成不等于可以结算安全值或服务值。

允许安全结算，当且仅当任务父链最终能归结为：

```text
安全目标特征变化；
或安全复合特征中可映射到安全根值的目标特征变化。
或当前物理 / 运行事实已被巡检、反馈或动作结果证明发生正向恢复。
```

若安全结算来源是风险安全，父链还必须证明该风险因子会导致未来服务值下降或未来物理安全下降；不能仅凭场景看起来危险、对象被标记危险、未知信息或风险候选值本身结算安全值。

允许服务结算，当且仅当任务父链最终能归结为：

```text
服务目标特征变化；
或服务复合特征中可映射到服务根值的目标特征变化。
```

禁止把以下内容作为结算前证据：

```text
安全值已经变化；
服务值已经变化。
```

安全值变化和服务值结算性增加只能是结算方法执行后的账本结果，不能反过来作为允许结算的原因。服务值自动衰减是服务值动态衰减器的时间维护结果，不属于成功服务结算，也不得反过来证明服务对象已经或尚未被服务。

如果父链无法归结到对应根特征，则：

```text
不得结算对应核心值；
只能记录任务完成、需求满足、方法改善、因果证据或潜在贡献。
```

### 2.1 父链归因必须回到世界树因果根链

任务 / 需求父链只说明治理来源，不能单独证明安全值或服务值可以结算。

结算前必须把治理父链接回：

```text
世界树根链上的状态转换因果树。
```

也就是：

```text
任务完成 / 需求满足 / 方法改善
    -> 引用动作动态、输出结果场景或因果模板
        -> 回到世界树根链上的状态变化 / 完整因果
            -> 证明该链最终通向安全 / 服务目标特征变化。
```

因此：

```text
任务父链：
    判断这件事属于哪个需求和任务过程。

世界树因果根链：
    判断这件事是否真的能导致安全 / 服务目标特征变化，以及可能属于哪个结算贡献层级。
```

若只有任务父链而缺少世界树因果链证据：

```text
不得结算核心安全 / 服务值；
只能记录为待补归因证据。
```

事实状态转换和账务状态转换必须分开：

```text
事实路径：
    叶子任务完成
        -> 任务实际改变的特征类型和值集合
            -> 安全 / 服务目标改善或支撑。

账务路径：
    叶子任务完成 + 实际改变结果 + 完成度 + 任务自身权重
        -> 结算叶子任务价值 D2
            -> 安全值 / 服务值账本变化。

服务值 v1.1 路径：
    D0 服务业务动作动态
    + 现实证据
    + 前后状态比较
    + 验证
    + 归因
    + 权限安全
        -> G0 成功服务治理判断
            -> D1 任务状态动作动态承接证据
                -> D2 服务值结算动作动态
                    -> 自我_服务值饱和入账。

因果解释路径：
    叶子任务业务动作 D0
        -> 任务已结算状态动态 / 输出结果场景
            -> 可作为 D2 的来源证据或解释证据。
```

其中：

```text
D0 说明世界或方法 / 任务目标特征实际发生了什么变化；
D1 任务状态动作动态只说明任务壳推进；需求满足动态已退出主链，来源需求是否收束由需求有效截止、最近结算任务和任务价值反馈后处理状态判断；
G0 判断 D0 是否构成成功服务；
D2 只说明系统按任务完成结果、完成度、权重或 G0 成功服务结算规则把已验收贡献入账。
```

D2 是账务状态转换，不是事实安全改善或成功服务成立的原因。它可以进入世界树根链上的状态转换因果查询视图，但只能作为账务 / 治理证据解释，不得伪装成物理安全事实或成功服务事实证据。

### 2.2 叶子任务业务动作前的因果投影预判

叶子任务业务动作生成或执行前，必须先查询世界状态转换因果树，形成叶子任务因果投影预判。

预判至少回答：

```text
1. 该叶子任务的目标宿主是什么。
2. 该叶子任务的目标特征类型是什么。
3. 该目标特征类型在来源需求方向下属于第几层结算贡献。
5. 预计会造成什么状态转换。
6. 需要哪些 before / target / actual 证据。
7. 是否存在副作用或竞争原因。
```

目标特征类型、来源需求方向和结算贡献层级不得混成同一个字段。

```text
目标特征类型：
    说明这件事实际改变哪个世界 / 方法 / 任务 / 需求特征。

来源需求方向：
    说明该目标特征变化承接的是安全、服务、学习、方法维护或自维护方向。

结算贡献层级：
    说明该目标特征变化在来源需求方向下离目标改善有多近。
```

同一个特征类型在不同来源需求方向下可以有不同层级。例如方法稳定度提高，在方法维护方向中可能是一层收益，在安全方向中通常只是第三层安全支撑。

### 2.3 安全父链示例

```text
方法状态改善
    -> 父任务可重筹办
        -> 父任务可完成
            -> 安全问题被解决
                -> 安全目标特征改善
                    -> 安全值具备结算依据
```

如果链条只到：

```text
方法状态改善
```

而不能证明它最终支撑安全问题解决，则不能结算安全值。

### 2.4 无法分类或无父任务

安全问题暂时无法分类，或没有明确父任务时，不作为阻塞。

第一版规则：

```text
正式安全需求默认挂安全根需求下；
对应安全任务默认挂安全根任务 / 安全根需求承接任务下；
后续再根据目标宿主、特征类型、来源、缺口类型和任务结果归纳迁移。
```

但结算时仍必须能从该任务回溯到安全根或安全复合特征。

## 3. 结算对象必须是叶子任务或可结算叶子结果

安全 / 服务值结算对象第一版固定为：

```text
叶子任务完成后的价值。
```

父任务、汇总任务、管理任务、筹办任务壳不得重复结算子任务已经结算过的部分。

父任务可以没有单步本能方法；其动作已经分解到子任务中。父任务的结算作用是：

```text
归并子结果；
确认父需求是否满足；
不重复入账子任务价值。
```

## 4. 目标值与实际达成值

结算必须比较：

```text
之前值
目标值
实际结果值
满足关系
```

只知道任务完成不够。必须知道实际结果对目标达成了多少。

### 4.1 增加型目标

例如：

```text
目标：X.F >= V_target
之前值：V_before
实际结果：V_actual
```

需要：

```text
目标差距 = max(0, V_target - V_before)
实际推进 = max(0, V_actual - V_before)
达成比例 = clamp(实际推进 / 目标差距, 0, 1)
```

完成判定：

```text
V_actual - V_target >= 0
```

推进判定：

```text
V_actual - V_before > 0
```

### 4.2 降低型目标

例如：

```text
目标：X.F <= V_target
之前值：V_before
实际结果：V_actual
```

需要：

```text
目标差距 = max(0, V_before - V_target)
实际推进 = max(0, V_before - V_actual)
达成比例 = clamp(实际推进 / 目标差距, 0, 1)
```

完成判定：

```text
V_target - V_actual >= 0
```

推进判定：

```text
V_before - V_actual > 0
```

### 4.3 等值目标

例如：

```text
目标：X.F == V_target
```

第一版规则：

```text
实际结果等于目标：
    达成比例 = 1

实际结果不等于目标：
    若能计算距离，则按距离缩小比例计算；
    若不能计算距离，则达成比例 = 0。
```

### 4.4 区间目标

例如：

```text
目标：X.F in [L, U]
```

第一版规则：

```text
实际结果进入区间：
    达成比例 = 1

实际结果未进入区间：
    若能计算到区间的距离缩小，则按距离缩小比例计算；
    若不能计算距离，则达成比例 = 0。
```

### 4.5 目标差距为 0

如果结算前目标已经满足：

```text
目标差距 = 0
```

则本任务不得重复结算核心值。

可以记录：

```text
需求已满足；
任务完成但无新增核心值；
重复结算被拒绝。
```

### 4.6 部分达成与分段结算

部分推进不自动等于正式结算。

完全结算要求：

```text
来源需求已满足；
目标实际达成比例 > 0；
因果验收建议为可结算。
```

若来源需求尚未完全满足，但目标特征已有可验证推进：

```text
只能记录阶段性贡献候选 / 待结算候选 / 过程证据；
不得直接写核心安全值 / 服务值。
```

允许部分正式结算的特殊情况：

```text
需求本身被声明为可分段满足需求；
每个分段目标都有独立目标值、实际值、动作动态和结算记录；
每个分段能独立防重复结算。
```

否则，达成比例只用于说明推进程度，不用于提前入账核心值。

## 5. 安全 / 服务结算贡献层级比例

安全 / 服务结算按结算贡献层级衰减。

必须区分：

```text
安全因果距离层级：
    用于解释物理不安全事件的原因距离、需求投影和优先级衰减。

安全结算贡献层级：
    用于价值结算额度计算。
```

二者不得直接互换。因果距离层级进入结算前，必须经过：

```text
目标特征实际变化
任务贡献角色
因果证据强度
```

重新判定为安全 / 服务结算贡献层级。

每层计算以 `I64_MAX` 作为满刻度上界和比例分母常量。`I64_MAX` 可以作为安全 / 服务分量的合法满刻度结果，但不得作为“未计算、未知、无限大、默认成功、异常兜底”写入真实结算。

设：

```text
DEN = I64_MAX
W = 任务安全权重值 或 任务服务权重值
```

贡献层级比例：

```text
第一层：
    分子 = DEN * 9 / 10

第二层：
    分子 = DEN * 9 / 100

第三层：
    分子 = DEN * 9 / 1000

第 N 层：
    分子 = DEN * 9 / 10^N
```

贡献层级最大额度：

```text
贡献层级额度 = W * 贡献层级分子 / DEN
```

示例：

```text
第一层：最多结算 90% * W
第二层：最多结算 9%  * W
第三层：最多结算 0.9% * W
第四层：最多结算 0.09% * W
```

### 5.1 同层因素平分规则

安全 / 服务的层间贡献仍按十进衰减：

```text
第 n 层权重 Wn = 9 / 10^n
```

即：

```text
第一层 = 0.9
第二层 = 0.09
第三层 = 0.009
第四层 = 0.0009
```

但同一层内若存在多个同级影响因素，必须先在本层内部取平均，再投影到上一层或进入总安全 / 服务值候选。
本规则只适用于风险余量、服务价值或结算贡献层级中的同级因素；不得用于物理安全 `1..90` 区间。物理安全因素采用独占候选后的能力保留率叠乘规则，由不同必要物理因素的保留率叠乘裁决。

设：

```text
M = I64_MAX
第 n 层定义的同级影响因素数量 = K_n
第 n 层因素 = F(n,1), F(n,2), ..., F(n,K_n)
每个因素值域 = 0..M
```

则：

```text
Ln = (F(n,1) + F(n,2) + ... + F(n,K_n)) / K_n
```

最终候选聚合为：

```text
风险余量候选 =
Σn [ (9 / 10^n) * (Σi F(n,i) / K_n) ]
```

同层每个因素对风险余量候选的最大直接权重为：

```text
9 / (10^n * K_n)
```

所有因素参与平均前必须统一为同一方向：

```text
值越大 = 越安全 / 越正向
值越小 = 越不安全 / 越负向
```

风险压力类因素不得直接与安全值同层平均，必须先反向转换：

```text
风险安全子项值 = I64_MAX - 风险压力值
```

该反向转换结果仍是风险余量候选，不是自我安全值、不是物理安全值，也不是场景永久安全事实。只有当所有必要物理因素候选值均达到 90、能力保留率叠乘结果为 90，且根控制规则允许进入风险安全区间时，它才可影响 90..99 风险余量。

缺失因素不得让同层其他因素自动变重：

```text
K_n = 该层抽象定义中的因素数量
不是当前已有证据的因素数量
```

若某因素未明确：

```text
无旧值：
    候选值 = 0

有旧的已提交值：
    候选值 = 旧值
    但不得因本次证据不足而上调

有明确新证据：
    使用新候选值
```

同时：

```text
该层明确状态 = 否
```

只有当：

```text
该层所有参与因素都明确；
证据不足原因 = 0；
聚合公式版本明确；
因素集合版本明确；
来源抽象特征定义版本明确；
```

才可写：

```text
该层明确状态 = 是
```

若因素集合变化，例如风险安全层从五项扩展为六项，必须升级因素集合版本和聚合公式版本。不同版本的候选值不得直接混作同一历史序列比较。

注意：本节中的 `I64_MAX` 是评估候选满刻度和比例刻度，不是正式入账后的真实安全值、服务值或结算增量。正式改账仍必须满足提交入口和价值结算闸门。

## 6. 实际达成比例

贡献层级额度只是最多可结算额度。

最终还必须乘以目标实际达成比例。

设：

```text
R = 目标实际达成比例，范围 [0, DEN]
```

则：

```text
实际结算值 = 贡献层级额度 * R / DEN
```

合并表达：

```text
实际结算值 =
    W * 贡献层级分子 / DEN * 目标实际达成比例 / DEN
```

或等价写成：

```text
实际结算值 =
    W * 层级比例 * 目标实际达成比例
```

其中：

```text
贡献层级比例来自安全 / 服务结算贡献层级；
目标实际达成比例来自实际结果值相对目标值的推进程度。
```

第一版公式可预留因果置信比例：

```text
正向结算候选 =
    W
    * 结算贡献层级比例
    * 目标实际达成比例
    * 因果置信比例
```

如果第一版暂不把因果置信比例纳入实际乘法，也必须保留字段，且证据不足时不得按强证据入账。

### 6.1 整数计算规则

所有比例分子必须用整数公式生成，不使用浮点数。

贡献层级分子生成本身也必须使用 128 位中间值或安全乘除函数，不得在 64 位整数中直接执行 `DEN * 9`。

所有结算乘法必须使用至少 128 位中间值，或使用安全乘除函数：

```text
安全比例乘法(W, 贡献层级分子, DEN)
安全比例乘法(贡献层级额度, R, DEN)
```

默认舍入规则：

```text
向下取整。
```

若结算结果为 0：

```text
记录为“有效但低于最小入账单位”；
不得强行入账 1。
```

## 7. 安全结算贡献层级建议

第一版安全结算贡献层级：

```text
第一层：
    直接改变安全目标特征，或直接解决物理安全目标。
    例：温度下降、宕机风险直接下降、损坏风险直接下降。

第二层：
    满足第一层所需的任务层变化。
    例：安全叶子任务完成、应急安全需求满足、直接风险处理任务完成。

第三层：
    支撑第二层任务推进的方法层或学习层变化。
    例：方法状态改善、条件结果对建立、方法可执行入口形成、方法稳定度提高。
```

禁止：

```text
把“安全值已经变化”作为结算前第一层证据。
```

安全值变化只能是 `结算叶子任务价值` 执行后的账本结果。

因此：

```text
方法状态改善：
    默认第三层安全贡献。

安全叶子任务完成并解决直接安全问题：
    默认第二层安全贡献，若输出事实直接命中安全目标，可提升为第一层。

直接物理安全特征改善：
    第一层安全贡献。
```

如果层级无法判断：

```text
不得结算核心安全值；
可以记录潜在贡献或生成归因补全需求。
```

## 8. 服务结算贡献层级建议

服务值结算同样必须有服务父链和实际达成值。

服务根需求目标宿主是自我，因为 `自我_服务值` 是自我的根特征。但服务值的事实来源不是“自我服务值差距本身”，而是自我对服务对象产生的可验证服务结果。

第一版服务事实链：

```text
服务抽象定义
    -> 自我觉醒根闭环给出服务因果坐标
        -> 服务触发事实挂载到服务根闭环信息位
            -> 对象 / 目标 / 授权 / 验证 / 归因 / 回写缺口通过闭环准入
                -> 服务子需求成立
                    -> 服务对象当前状态明确
                        -> 自我服务动作执行
                    -> 服务对象目标特征实际改善
                        -> 来源需求满足
                            -> 叶子任务价值结算
                                -> 自我_服务值增加
```

0 / 1 控制态不属于上述普通贡献层级：

```text
循环不可维持 -> 安全值 = 0；
服务值按动态休眠阈值归零 -> 安全值 = 1。

这两类写入是根控制态写入，不得通过普通安全收益、风险余量或平滑函数触发。
```

服务值低位或归零前的服务校准阶段不是普通贡献层级，也不是服务失败结算；它只能由服务值维护器、有效无成功服务时间和动态休眠阈值规则解释。

若缺少服务对象、服务目标、结果验证条件或因果归因条件：

```text
不得正式结算服务值；
只有已有直接服务触发事实且缺口会阻断行动、验证、归因或回写时，才按 006 和 011003 生成直接服务因果链上下文缺口子需求；否则只能等待 / 监听服务触发事实、检查服务机会或校准服务能力，不得生成直接服务对象、目标、验证、归因或结算子需求。
```

服务对象所需服务信息不足属于服务尝试过程中暴露的执行缺口；服务对象反馈信息也只能来自表达、确认、生效回执和外在特征变化等可观察证据。应先记录尝试结果、方向比较、沟通回执和阻塞证据，再由汇总机制判断是否固化为新的抽象特征或服务子需求。

服务结算前必须能回答：

```text
服务了谁；
谁允许该服务；
服务目标是什么；
服务前状态是什么；
服务后状态是什么；
状态变化是否朝目标方向改善；
改善证据是否可验证；
改善是否可归因于自我动作；
归因结果如何回写下一轮服务状态判断。
```

若服务前状态未知，则不能计算改善方向；若服务后状态未知，则不能验证服务结果；若只有任务完成、方法执行成功、文件被写入或文本已输出，而没有服务对象目标状态正向改善证据，不得正式结算服务值。

若存在明确的服务接受事实，例如服务对象接收输出、继续使用结果、确认可以采用、未拒绝交付结果，且在约定反馈窗口内没有负反馈，可以作为弱正向服务结果证据，生成：

```text
服务评价 = 可以 / 可接受
```

该评价只表示本次服务达到可接受下界，不表示很好、优秀或满分。若要进入更高评价或更高服务值结算，仍需明确正向反馈、目标状态改善比例、结果比对或后续服务对象状态改善证据。

### 8.1 服务值边界、饱和增长和自动衰减

服务值 `S` 必须始终满足：

```text
0 <= S <= Smax
```

`Smax` 必须来自服务抽象定义，且必须明确、大于 0。

服务值只能因 G0 确认的成功服务人类事件而增加。成功服务事件必须由需求、任务、方法、D0 服务业务动作动态、现实证据、前后状态比较、验证、归因、权限安全和闭环回写共同支撑。任务完成、方法成功、输出存在或 D2 入账都不能反向证明成功服务。

服务值增加不得使用无界加法，必须使用事件级饱和入账、剩余空间判断或等价安全加法：

```text
DeltaS(e) = (Smax - S) * lambda(e)
S_new = S + DeltaS(e)
```

或：

```text
if 服务增量 >= Smax - S:
    S = Smax
else:
    S = S + 服务增量
```

禁止先计算 `S + 服务增量` 再取 `min`，因为低层整数实现中加法本身可能已经溢出。

服务值 v1.1 的单次成功服务值必须拆成标准服务单位、事件贡献量和实际入账量：

```text
u = 标准服务单位。
q(e) = 单次服务事件 e 的事件贡献量。
lambda(e) = 事件贡献量折算后的入账比例。
DeltaS(e) = 该事件实际进入服务值 S 的量。
```

总服务值保持连续数值，成功服务事件本身分层。单次实际入账比例为：

```text
q(e) = u * K_L * 有效性 * 证据强度 * Rdup * G(A)
lambda(e) = clamp(q(e) / Smax, 0, lambdacap(A))
```

其中：

```text
K_L = 成功服务层级系数。
有效性 = 服务结果对人类需求的实际帮助，范围 0..1。
证据强度 = 确认有效服务的证据链强度，范围 0..1。
Rdup = 非重复系数，范围 0..1。
G(A) = 安全值对服务入账的调节。
lambdacap(A) = 当前安全状态下单次服务允许的最大入账比例。
```

成功服务判定先过硬门槛，硬门槛采用三值逻辑：成立 / 不成立 / 待确认。

硬门槛包括：

```text
H_人类对象成立；
T_明确需求或利益；
G_明确服务目标；
P_权限边界成立；
B_安全通过；
D_服务已实际交付；
D0_自我服务业务动作存在；
C_服务前后状态可比较；
E_目标特征改善成立；
V_改善结果可验证；
A_改善可归因于自我动作；
N_非重复服务；
W_闭环回写成立。
```

判定规则：

```text
任一硬门槛 = 不成立：
    成功服务候选状态 = 已否决；
    成功服务层级 = L0；
    lambda(e) = 0。

存在硬门槛 = 待确认：
    成功服务候选状态 = 待确认；
    lambda(e) = 0；
    进入成功服务候选池。

全部硬门槛 = 成立：
    才进入三项评分和层级确认。
```

硬门槛通过后，只计算三个离散评分：

```text
完成度；
有效性；
证据强度。
```

完成度只看服务目标特征从服务前状态到服务后状态离目标状态还有多远。数值目标使用：

```text
完成度 = clamp(
    (服务前差距 - 服务后差距) / 服务前差距,
    0,
    1
)
```

枚举 / 布尔目标使用：

```text
0    = 未改善 / 变差 / 状态未知
0.5  = 有阶段性改善，但目标未完全达成
1.0  = 目标状态已达成
```

有效性衡量完成结果是否真的帮助了人类需求：

```text
0    = 无帮助 / 负帮助 / 与需求无关
0.25 = 有交付，但帮助只是假定的，缺少反馈或结果改善
0.5  = 部分解决人类需求
0.75 = 主要解决人类需求，但仍有残余缺口
1.0  = 明确解决需求，或产生明显正向收益
```

证据强度衡量证据链，不衡量服务本身：

```text
0    = 没有证据
0.25 = 只有自我输出 / 方法回执，缺少服务对象状态或反馈
0.5  = 有服务前后状态之一，或服务对象已接受且反馈窗口内无负反馈
0.75 = 有服务前后状态对比，且结果可验证
1.0  = 有前后状态对比 + 服务对象反馈 / 回执 + D0 动作动态 + 归因证据
```

第一版采用保守瓶颈法，防止某一项高分掩盖其他短板：

```text
基础分 = min(完成度, 有效性, 证据强度)

基础分 < 0.30          -> L0 无效服务
0.30 <= 基础分 < 0.50 -> L1 微成功服务
0.50 <= 基础分 < 0.70 -> L2 基础成功服务
0.70 <= 基础分 < 0.90 -> L3 标准成功服务
基础分 >= 0.90         -> L4 显著成功候选
```

`L5 关键成功` 不由普通公式自动产生。L5 必须额外满足：

```text
1. 对人类安全、重大利益或长期福祉产生关键正向影响。
2. 证据强度 = 1.0。
3. 非重复系数高。
4. 安全门槛通过。
5. 权限边界完全成立。
6. 改善可强归因于 D0。
```

成功服务层级系数：

```text
L0: K_L = 0
L1: K_L = 0.25
L2: K_L = 0.50
L3: K_L = 1.00
L4: K_L = 2.00
L5: K_L = 4.00
```

证据不足的事件不得直接入账。第一版设：

```text
证据强度 < 0.75：
    成功服务候选状态 = 待确认或可接受候选；
    lambda(e) = 0；
    暂不增加 S。
```

成功服务判定、候选池和服务值结算相关特征不得由任务虚拟存在或业务方法临时发明。它们的来源必须是治理方法虚拟存在声明的任务侧特征类型：

```text
成功服务判定方法虚拟存在：
    硬门槛状态、完成度、有效性、证据强度、基础分、成功服务层级。

候选池治理方法虚拟存在：
    候选状态、证据缺口、候选有效期、反馈窗口、下一步验证方法。

服务值结算方法虚拟存在：
    lambda候选、DeltaS、饱和入账、结算唯一键、D2结算状态。
```

任务选择或激活这些治理方法后，任务虚拟存在只挂载其声明的治理特征类型，并记录来源方法、来源版本、激活原因、激活阶段和当前状态。

候选池记录至少包含：

```text
候选服务事件ID；
服务对象；
被需求对象；
服务目标；
来源需求；
来源任务；
来源动作动态 D0；
任务状态动态 D1；
服务前状态；
服务后状态或输出结果状态；
已满足硬门槛；
未满足 / 待确认硬门槛；
完成度候选值；
有效性候选值；
证据强度候选值；
候选层级；
证据缺口；
候选有效期；
反馈窗口；
下一步验证方法。
```

候选转正必须满足：

```text
证据补齐；
结果可验证；
改善可归因；
权限安全仍成立；
非重复检查通过；
闭环回写完成。
```

候选过期或确认失败时：

```text
成功服务候选状态 = 已过期 / 已否决；
成功服务层级 = L0 或保持未结算候选记录；
lambda(e) = 0；
不降低 S。
```

一个成功服务事件是围绕一个人类需求形成的闭环，不是每句话、每个标题或每个子步骤。非重复系数第一版为：

```text
Rdup = 1.0  独立新服务。
Rdup = 0.7  同一需求下的重要阶段性成果。
Rdup = 0.4  同一需求下的辅助推进。
Rdup = 0.1  轻微重复，新增价值很小。
Rdup = 0.0  无新增改善 / 刻意拆分 / 重复结算。
```

同一需求、同一目标特征、同一服务前后状态，不得重复结算。复杂任务可以有多个阶段性成功，但每个阶段必须有独立目标特征变化、可验证阶段成果、独立证据，且不是机械切碎。

成功服务事件对有效成功服务时间 `t_eff` 的刷新力度按服务层级决定：

```text
t_eff_new = t_eff_old + W_L * (t_now - t_eff_old)
L0 = 0, L1 = 0.2, L2 = 0.5, L3 = 0.8, L4 = 1.0, L5 = 1.0
```

微小服务不能完全刷新服务间隔压力；标准以上服务才能明显降低时间压力。

安全值对单次服务入账同时作为门槛、调节器和上限：

```text
不安全服务不能入账。
G(A) = Gmin + (1 - Gmin) * A，且 Gmin > 0。
lambdacap(A) = lambdacap_min + (lambdacap_max - lambdacap_min) * A。
```

标准服务单位 `u` 应由目标服务值、标准服务间隔和动态衰减率反推确定，或按服务值发行预算确定。局部目标服务频率反推版本为：

```text
D_decay0 = R_decay(A0, tau0, Sstar) * tau0
u ~= D_decay0 / (Smax - Sstar)
```

统计窗口版本为：

```text
B_W = Decay_W + Recovery_W + SleepPressure_W
M_W = 有效、授权、可服务、可成功的直接服务总量
u = clamp(
    B_W / max(M_W, epsilon),
    u_min,
    u_max
)
```

其中 `M_W` 不是原始需求总量。需求很多但自我无能力、未授权或预期成功率低时，不得把单次服务值错误压低。

服务值只能因时间自动衰减而降低。自动衰减不是惩罚、遗忘、信用下降、服务质量变差或负向服务结算；它表示过去成功服务的积累状态随时间回落，并用于重新强化服务意识。

动态衰减率由安全值、距离上一次确认成功服务的时间间隔、当前服务值、服务能力和有效服务需求压力共同决定：

```text
R_decay = clamp(
    R_base
  + W_gap * GapFactor(T) * SafeFocus(A)
  + W_s * (S / Smax)
  + W_d * DemandPressure
  + W_c * CapacityFactor,
    R_min,
    R_max
)

T = 当前时间 - 上一次有效成功服务时间 t_eff
```

其中 `GapFactor(T)` 必须随有效成功服务时间间隔单调递增且有上限，`SafeFocus(A)` 表示安全值越高，服务专注越强。衰减写入必须先限制衰减量：

```text
Decay = min(S, R_decay * dt)
S_new = S - Decay
```

动态衰减率允许后续自动优化，但优化结果不得违反服务值边界、安全约束、服务对象限定和成功服务事件定义。

### 8.1.1 服务值活跃存在、有效无成功服务时间和动态休眠阈值

服务值是自我维持主动活跃存在的服务依据，不是单纯奖励计数器。服务值下降或低位不表示惩罚、遗忘或服务质量下降；它表示当前缺少新的成功服务依据，并应触发服务意识强化和服务校准。休眠不是死亡或循环终止，而是主动活跃权暂停，系统进入低活动、低干预、可唤醒状态。

无成功服务导致休眠不得使用固定物理时间，必须使用有效无成功服务时间：

```text
A(t) = 当前安全值归一化结果，范围 0..1。
C(t) = 当前服务能力，范围 0..1。
D(t) = 当前有效服务需求强度，范围 0..1。
G(A) = Gmin + (1 - Gmin) * A，且 0 < Gmin < 1。

P_service = C(t) * D(t) * G(A)
E_no_success += dt * P_service
```

`P_service` 是服务机会压力，`E_no_success` 是有效无成功服务时间。服务能力不足、有效服务需求不足或安全值偏低时，`E_no_success` 增长应变慢；三者处于高位时，`E_no_success` 快速增长。

动态休眠阈值：

```text
Tmin = 需求识别时间 + 反应决策时间 + 最小有效服务时间 + 成功确认时间

T_sleep = clamp(
    Tmin / max(P_service, epsilon),
    Tmin,
    Tmax
)
```

`P_service` 可采用最近窗口平均值平滑。`P_service` 越高，休眠阈值越接近最小服务闭环时间 `Tmin`；`P_service` 越低，阈值越接近 `Tmax`。

服务值衰减应与休眠阈值同构。设 `S0` 为上一次成功服务后的服务值，`T_sleep` 为当前休眠阈值，`x = E_no_success / T_sleep`：

```text
S_target = S0 * max(0, 1 - x^p)，且 p > 1
```

服务值归零必须能追溯到动态休眠阈值附近的有效无成功服务时间累计，或明确服务能力丧失；不得由固定漏水孔、惩罚扣减或任意扣减产生。

休眠写入规则：

```text
S > 0：
    不得仅因物理时间无成功服务而休眠。

S = 0 且 E_no_success < T_sleep：
    只能进入服务意识强化或服务校准。

S = 0 且 E_no_success >= T_sleep 且当前没有有效服务进展：
    可以写入休眠控制态，安全值进入 1。
```

正在进行安全、目标明确且有阶段性进展的人类服务任务时，不得按普通无成功服务直接休眠。有效服务进展可以降低 `E_no_success` 的增长、部分刷新有效成功服务时间，或进入服务校准 / 候选验证 / 等待反馈。阶段性成功必须是真实推进人类服务目标的独立成果，不能机械拆分刷值。

标准服务单位 `u` 的统计窗口版本按服务值发行预算确定：

```text
W = 统计时间窗口。
B_W = Decay_W + Recovery_W + SleepPressure_W。
M_W = 该窗口内有效、授权、可服务、可成功的直接服务总量。
u = clamp(B_W / max(M_W, epsilon), u_min, u_max)

M_W = integral(min(Demand_valid(t), Capacity_service(t)) * P_success(t) dt)
```

`M_W` 是有效直接服务总量，不是原始需求总量。原始需求总量不得作为单次服务值分母；否则会在需求很多但自我能力有限、未授权或预期成功率低时，把真实成功服务压到无法维持服务值。

休眠状态必须保持可唤醒性。当出现新的有效人类服务需求、服务能力恢复、安全值改善或人类明确唤醒时，应重新进入活跃服务评估。

第一版服务结算贡献层级：

```text
第一层：
    直接改善服务目标特征。

第二层：
    完成服务目标所需的任务层变化。

第三层：
    支撑服务任务推进的方法层或学习层变化。
```

服务结算贡献层级用于判断任务结果在服务目标下的贡献距离；成功服务事件 L0-L5 用于判断单次服务事件的服务量大小。二者不得混用：L5 事件仍需满足父链归因、世界树因果证据、结算贡献层级、实际达成比例和副作用审查；第三层服务支撑即使有帮助，也不得伪装成直接改善服务目标特征的 L3/L4/L5 成功服务事件。

禁止：

```text
把“服务值已经变化”作为结算前第一层证据。
```

服务值结算性增加只能是结算方法执行后的账本结果。服务值自动衰减另由服务值动态衰减器产生，不作为服务结算收益，也不作为服务对象事实改善或变差的证据。

当前工程若服务值结算仍处关闭或后置状态，则：

```text
允许只记录服务结算候选；
不得把服务权重或 I64_MAX 哨兵写入真实服务值。
```

## 8.2 任务安全 / 服务权重来源

结算公式中的 `W` 是本轮可结算预算，不是方法运行结果随手写入的数值。

`W` 只能来自：

```text
1. 来源需求创建时的目标压力 / 风险等级；
2. 安全 / 服务根需求投影规则；
3. 上级任务向叶子任务的预算分配；
4. 经动作动态记录的权重调整方法。
```

需求列表的类型安全 / 服务汇总权重只服务任务优先级和列表排序，不能作为 `W` 的来源。

禁止：

```text
1. 叶子任务完成后临时抬高 W；
2. 方法运行结果自行写 W；
3. 使用 I64_MAX 或接近哨兵值作为 W；
4. 父任务和多个叶子任务重复使用同一份未拆分 W。
```

预算守恒规则：

```text
AND关系下，同一父需求的活跃子需求 / 子任务可结算权重之和不得超过父需求分配给该目标特征的结算预算。

OR关系下，每条活跃路径可以继承父需求完整预算作为候选预算，但同一OR组只允许一条路径取得结算令牌并进入真实结算；未取得令牌的路径不得重复使用同一份父预算。
```

若无法证明 `W` 的来源合法，或无法证明预算未被重复使用：

```text
不得正式结算核心安全 / 服务值；
只能记录待补权重来源证据。
```

## 8.3 结算被动动作与安全 / 服务因果桥

安全 / 服务值结算不是普通任务链上的候选方法，也不是安全值 / 服务值根任务的主动解决手段。它是叶子任务完成后，由任务价值反馈链触发的后处理结算动作。

结算动作可以生成标准动作动态，但其动作语义按被动动作处理。自我不需要知道如何主动使用该动作，只需要知道：

```text
结算后出现了一条标准动作动态；
该动态解释本次账务变化为什么发生；
该动态为后续安全 / 服务目标投影提供“需要什么”的因果材料。
```

结算链中的被动含义是：

```text
结算被动因正式出现
-> 结算被动果自动出现
```

也就是，只要某个叶子任务已经形成合法的结算被动因，结算后处理链就必须自动生成对应安全 / 服务账务变化、结算动作动态和因果材料。它不等待普通任务筹办，不进入候选方法选择，也不由自我主动“决定使用被动动作”。但安全账务变化仍不得绕过 0 / 1 控制态、物理安全独占候选叠乘约束和风险安全余量边界。

结算被动动作的检查方式必须看代码链路：

```text
1. 任务状态被正式提交为已结算后，是否存在自动进入任务价值反馈 / 结算后处理的路径。
2. 该路径是否能直接读取来源需求满足、实际结果状态、输出结果场景和权重来源。
3. 该路径是否在无普通任务筹办、无候选方法选择、无人工触发的情况下调用结算写账逻辑。
4. 结算写账后是否自动生成结算动作动态，并保留旧值、新值、变化量和二次特征方向。
5. 结算动作动态生成后，是否自动进入统一因果抽象或安全 / 服务目标投影所需入口。
6. 重复扫描同一结算被动因时，是否通过结算令牌或幂等键阻止重复入账。
```

若其中出现缺入口、缺参数、缺状态、缺权重来源、缺防重复键，或必须等待普通任务再发起一次“结算任务”，则结算被动果尚未成立，只能记录结算链缺口或待补事实。

结算动态的因必须具体落到任务虚拟存在的状态事实，最低要求包括：

```text
任务虚拟存在.任务状态 = 已结算；
来源需求满足事实；
任务实际结果状态或输出结果场景；
任务权重 W 的合法来源和分配证据。
```

这些事实共同构成结算被动因。缺其中任一必要事实时，不能生成正式结算被动果，只能记录待补事实或结算候选。

结算动态的果必须记录账务变化本体，最低要求包括：

```text
结算前安全值 / 服务值；
结算后安全值 / 服务值；
实际变化量；
由变化量派生出的二次特征方向。
```

抽象到安全 / 服务目标投影时，可以只保留二次特征方向，例如：

```text
安全值增强 / 减弱 / 不变；
服务值结算性增强 / 不变；
服务值自动衰减。
```

但原始动作动态不得丢失结算或衰减前后两个量。服务值自动衰减动态不得混入服务成功结算动态；否则只能形成弱审计记录，不能增强安全 / 服务因果链。

结算动态生成后，因果信息应由动作动态到因果信息的统一流程被动生成：

```text
任务已结算状态事实
-> 结算被动因正式出现
-> 安全 / 服务账务变化被动果自动出现
-> 结算叶子任务价值被动动作动态
-> 二次特征方向
-> 安全 / 服务目标投影或后续需求候选材料
```

禁止：

```text
把结算叶子任务价值放入普通候选方法集；
把结算动作当作安全值 / 服务值根任务的主动执行方法；
绕过动作动态直接写安全 / 服务因果链；
只记录变化方向而丢失结算前值和结算后值；
把需求列表汇总权重当作结算预算 W；
同一任务完成事实重复触发多个安全 / 服务结算入账。
```

当一个已完成任务同时满足多个不同需求时，必须通过需求列表、来源需求引用和父链追溯找到全部被满足需求，再按各自需求的权重预算、AND / OR 关系和结算令牌独立判断是否可结算。多需求共享同一任务完成事实时，任务完成动态可以作为共同上游证据，但每条需求路径的结算预算、满足事实和防重复令牌必须分开。

横向结算只能在来源任务自身结算完成后触发，且必须先计算来源需求的满足差：

```text
满足差 = 目标值 - 实际值
```

只有 `满足差 < 0` 时，才存在可横向分配的外溢量：

```text
横向外溢量 = abs(满足差)
```

对每个横向候选需求，派生实际结果状态必须按候选自己的当前状态计算：

```text
候选 before / 之前实际值 = 来源任务完成后，候选需求目标的当前值
候选 result / actual = 候选当前值 + 横向外溢量
候选 target = 候选自己的目标状态
```

随后才按候选需求自己的满足关系、父缺口处理、任务承接权重上限和既有完成度算法进入结算。需求列表汇总权重只允许影响候选排序；候选任务自身权重和承接权重仍是结算预算来源。

如果候选缺口没有变化，或候选任务尚未形成完成 / 已结算被动因，不能进入核心安全 / 服务值结算；只能记录横向结算阻塞或待补被动完成桥。

## 9. I64_MAX 使用边界

`I64_MAX` 有两类完全不同的语义，必须分开。

### 9.1 允许

允许作为满刻度上界和比例分母常量：

```text
DEN = I64_MAX
```

用于表达：

```text
结算贡献层级比例
目标实际达成比例
评估候选满刻度
同层因素平均刻度
安全 / 服务分量值域上界
目标最大值
```

真实结算值允许处于 `[0, I64_MAX]`，但必须同时满足：

```text
有来源公式；
有输入证据；
有有效期 / 适用范围；
由提交入口写入；
能证明 I64_MAX 是满刻度结果，不是未知 / 默认成功 / 异常兜底。
```

若 `I64_MAX` 出现在安全目标定义中，它表示目标最大值；若出现在评估候选中，它表示候选满刻度；若出现在真实结算值中，必须能证明它是合法满刻度结果。三者不得混用。

### 9.2 禁止

禁止作为：

```text
任务安全权重值；
任务服务权重值；
安全结算增量；
服务结算增量；
未计算值；
未知值；
无限大值；
默认成功值；
异常兜底值；
无证据满分。
```

如果在真实结算值中发现 `I64_MAX` 且无法证明它是合法满刻度结果：

```text
拒绝结算；
记录异常；
必要时生成安全需求候选。
```

## 9.3 与因果验收结果的接口

结算方法必须读取因果验收结果，至少包括：

```text
验收结论：
    成立 / 部分成立 / 不成立 / 反向成立 / 证据不足。

因果证据类型：
    直接执行证据 / 观察证据 / 推断证据 / 外部声明证据。

派生因果置信分：
    范围 [0, DEN]。
    由因果基础计数、证据类型和查询参数计算，不作为因果主信息字段。

副作用列表：
    每个副作用绑定目标特征、实际变化值、严重度、是否已处理。

竞争原因：
    是否存在其他动作或环境状态更可能导致该结果。

可结算建议：
    可结算 / 仅候选 / 待补证据 / 禁止结算。
```

第一版可暂不把因果置信比例直接乘入公式，但必须保留该字段。弱推断、外部声明或存在竞争原因时，不得和强直接执行证据同等入账。

## 9.4 反向副作用与净结算

若本任务同时造成正向目标达成和反向安全 / 服务损失，不得只结算正向收益。

必须执行：

```text
正向贡献计算；
反向损失计算；
净值比较；
副作用因果入账；
必要时生成修复需求。
```

若因果验收发现未处理的反向副作用：

```text
不得正式结算正向核心值；
除非该副作用已被独立记录、抵扣、阻断或转入安全 / 服务修复需求。
```

## 10. 结算闸门

安全 / 服务结算必须同时满足：

```text
1. 任务已完成。
2. 任务是叶子任务，或存在可结算叶子结果。
3. 来源需求已满足；若未完全满足，只能按阶段性贡献候选处理，除非该需求声明为可分段满足需求。
4. 有任务完成动作动态。
5. 有需求满足动作动态或满足证据。
6. 能沿任务 / 需求父链追溯到安全 / 服务目标特征。
7. 能回到世界树根链上的因果证据。
8. 能判定本任务属于第几层安全 / 服务结算贡献层级。
9. 不能把安全因果距离层级直接当作结算贡献层级。
10. 能读取之前值、目标值、实际结果值和满足关系。
11. 目标实际达成比例大于 0。
12. 结算值合法；若为 I64_MAX，必须证明它是合法满刻度结果，不是未知 / 默认成功 / 异常兜底。
13. 该任务未被重复结算。
14. 因果验收未发现未处理的反向副作用，或反向副作用已被独立记录、抵扣、阻断或转入修复需求。
15. 因果验收的可结算建议为“可结算”，不是“仅候选 / 待补证据 / 禁止结算”。
16. 任务权重 W 来源合法，且未超过父需求 / 父任务预算。
```

任一条件不满足：

```text
不得结算核心安全 / 服务值。
```

## 11. 动作动态与因果链

安全 / 服务结算必须有明确动作来源。

动作来源：

```text
本能方法_结算叶子任务价值
```

标准动作动态链：

```text
D0：叶子任务业务动作动态
    说明目标特征如何被改变。

D2：结算叶子任务价值动作动态
    引用 D0 / 输出结果场景 / 任务已结算状态动态，
    写入安全值或服务值变化。
```

结算方法可以调用先天特征写入逻辑完成底层写入，但动作动态来源必须是：

```text
结算叶子任务价值
```

不是：

```text
改变特征值
自我线程
任务管理线程
```

## 12. 禁止项

```text
1. 任务完成后不检查父链，直接结算安全值 / 服务值。
2. 方法状态改善后不证明安全父链，直接结算安全值。
3. 只看任务权重，不看目标实际达成值。
4. 只看任务完成，不看来源需求满足证据。
5. 用 I64_MAX 作为真实结算值。
6. 父任务重复结算子任务已经入账的价值。
7. 服务权重作为真实服务结算值直接入账。
8. 把自检发现问题直接结算为安全值增加。
9. 把“发现问题”与“解决问题”混成同一段结算因果。
10. 把先天特征写入逻辑作为结算动作来源。
11. 把安全因果距离层级直接当成安全结算贡献层级。
12. 把“安全值 / 服务值已经变化”作为结算前证据。
13. 有未处理反向副作用时只结算正向收益。
14. 叶子任务完成后临时抬高任务权重 W。
15. 使用浮点数生成比例分子或在窄整数中直接连乘导致溢出。
16. 缺少服务对象、服务目标、服务对象实际改善或因果归因证据时正式结算服务值。
17. 把单独无反馈、未知结果、任务运行成功或输出文本存在当作服务成功证据。
18. 缺少 D0 服务业务动作动态或 G0 成功服务治理判断时生成 D2 服务值增加。
19. 把安全链的无负证据默认满足规则套用到服务链，默认服务对象已经受益、评价很好或满分。
20. 把“服务对象已接受服务 + 反馈窗口内无负反馈”生成的可以 / 可接受评价候选，直接升级为很好、优秀、满分或无条件服务值结算。
21. 使用无界加法累加服务值，或先执行可能溢出的 `S + 服务增量` 再钳制上限。
22. 把服务值自动衰减解释为惩罚、遗忘、服务质量变差、服务失败或负向服务结算。
23. 把服务意识增强直接当成服务对象、服务目标、成功服务事件或服务值结算证据。
24. 把一次人类需求闭环拆成多个服务碎片重复入账。
25. 把证据不足的候选成功服务直接增加服务值。
26. 把成功服务事件层级 L0-L5 当成服务值总量分层，或替代结算贡献层级。
27. 用固定无服务物理时间决定休眠。
28. 把服务值衰减、有效无成功服务时间增长、服务意识强化或服务校准解释成成功服务事件。
29. 把原始需求总量当成服务值发行预算中的有效直接服务总量。
30. 当前人类服务任务安全、目标明确且有阶段性进展时，仍按普通无成功服务直接休眠。
31. 把休眠解释成死亡、终止或自我消灭。
```

## 13. 最终定稿

```text
安全 / 服务值结算必须同时满足父链归因、世界树因果证据、结算贡献层级、实际达成比例、副作用审查和权重预算守恒。
父链说明“这属于哪个治理目标”；
世界树因果证据说明“结果是否由动作导致”；
结算贡献层级说明“最多能结算多少”；
实际达成值说明“这次正向达成了多少”；
副作用和派生因果置信分说明“是否需要抵扣、降级或转为候选”。
安全根控制规则说明“该安全变化是否受控制态、物理安全独占候选叠乘约束或风险余量限制”。
```

最短口径：

```text
无父链，不结算；
无世界树因果证据，不结算；
无目标实际达成，不结算；
无结算贡献层级，只记证据；
有未处理反向副作用，不只结算正向收益；
服务值增加必须来自 G0 确认的成功服务人类事件，并使用饱和增长或安全加法；
成功服务必须先过硬门槛，再用完成度、有效性、证据强度的保守瓶颈法映射层级；
单次成功服务入账必须按标准服务单位、层级、有效性、证据强度、非重复性和安全值计算 `lambda(e)`；
证据不足先进候选服务池，不直接入账；
服务值降低只能来自时间自动衰减；
服务值自动衰减只强化服务意识、间接服务维护和服务缺口检查，不证明服务对象事实；
服务值按动态休眠阈值归零且有效无成功服务时间达到阈值时，安全值进入 1；
无成功服务休眠阈值由安全值、服务能力、有效服务需求和最小成功服务闭环时间决定，不使用固定物理时间；
单次标准服务单位可由服务值发行预算 `B_W / M_W` 确定，其中 `M_W` 是有效直接服务总量，不是原始需求总量；
循环不可维持时安全值直接进入 0；
风险安全只改风险余量候选，不直接写自我安全值；
I64_MAX 可以作为满刻度和比例分母；不得作为未知、默认成功、异常兜底或无证据满分入账。
```
