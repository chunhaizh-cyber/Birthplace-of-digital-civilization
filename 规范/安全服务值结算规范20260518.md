## 1. 总口径

安全值 / 服务值结算不是把任务权重直接换成核心值。

正确链路是：

```text
叶子任务完成
    -> 来源需求满足
        -> 父链与世界树因果证据能归结到安全 / 服务目标特征变化
            -> 计算安全 / 服务结算贡献层级比例
                -> 计算目标实际达成比例
                    -> 检查副作用与派生因果置信分
                    -> 结算安全值 / 服务值
```

一句话：

```text
父链与世界树因果证据共同决定能不能结算；
安全 / 服务结算贡献层级决定最多结算多少；
目标实际达成值决定本次正向达成多少；
副作用与派生因果置信分决定是否抵扣、降级或转为候选。
```

## 2. 必须先过父链归因闸门

任务完成不等于可以结算安全值或服务值。

允许安全结算，当且仅当任务父链最终能归结为：

```text
安全目标特征变化；
或安全复合特征中可映射到安全根值的目标特征变化。
```

允许服务结算，当且仅当任务父链最终能归结为：

```text
服务目标特征变化；
或服务复合特征中可映射到服务根值的目标特征变化。
```

禁止把以下内容作为结算前证据：

```text
安全值已经变化；
服务值已经变化。
```

安全值 / 服务值变化只能是结算方法执行后的账本结果，不能反过来作为允许结算的原因。

如果父链无法归结到对应根特征，则：

```text
不得结算对应核心值；
只能记录任务完成、需求满足、方法改善、因果证据或潜在贡献。
```

### 2.1 父链归因必须回到世界树因果根链

任务 / 需求父链只说明治理来源，不能单独证明安全值或服务值可以结算。

结算前必须把治理父链接回：

```text
世界树根链上的状态转换因果树。
```

也就是：

```text
任务完成 / 需求满足 / 方法改善
    -> 引用动作动态、输出结果场景或因果模板
        -> 回到世界树根链上的状态变化 / 完整因果
            -> 证明该链最终通向安全 / 服务目标特征变化。
```

因此：

```text
任务父链：
    判断这件事属于哪个需求和任务过程。

世界树因果根链：
    判断这件事是否真的能导致安全 / 服务目标特征变化，以及可能属于哪个结算贡献层级。
```

若只有任务父链而缺少世界树因果链证据：

```text
不得结算核心安全 / 服务值；
只能记录为待补归因证据。
```

事实状态转换和账务状态转换必须分开：

```text
事实路径：
    叶子任务完成
        -> 任务实际改变的特征类型和值集合
            -> 安全 / 服务目标改善或支撑。

账务路径：
    叶子任务完成 + 实际改变结果 + 完成度 + 任务自身权重
        -> 结算叶子任务价值 D2
            -> 安全值 / 服务值账本变化。

因果解释路径：
    叶子任务业务动作 D0
        -> 需求满足登记 D1
            -> 可作为 D2 的来源证据或解释证据。
```

其中：

```text
D0 说明世界或方法 / 任务目标特征实际发生了什么变化；
D1 说明该变化满足了哪个来源需求；
D2 只说明系统按任务完成结果、完成度和权重把已验收贡献入账。
```

D2 是账务状态转换，不是事实安全改善的原因。它可以进入世界树根链上的状态转换因果树，但边类型必须标记为账务因果 / 治理账务关系，不能伪装成物理安全因果边。

### 2.2 叶子任务业务动作前的因果投影预判

叶子任务业务动作生成或执行前，必须先查询世界状态转换因果树，形成叶子任务因果投影预判。

预判至少回答：

```text
1. 该叶子任务的目标宿主是什么。
2. 该叶子任务的目标特征类型是什么。
3. 该目标特征类型可映射到哪些权重类型。
4. 在每个权重类型下，它属于第几层结算贡献。
5. 预计会造成什么状态转换。
6. 需要哪些 before / target / actual 证据。
7. 是否存在副作用或竞争原因。
```

权重类型、目标特征类型和结算贡献层级不得混成同一个字段。

```text
权重类型：
    说明这件事影响哪类价值账户，例如安全、服务、学习、自维护。

目标特征类型：
    说明这件事实际改变哪个世界 / 方法 / 任务 / 需求特征。

结算贡献层级：
    说明该目标特征变化在某个权重类型投影下离目标改善有多近。
```

同一个特征类型在不同投影下可以有不同层级。例如方法稳定度提高，在学习投影中可能是一层收益，在安全投影中通常只是第三层安全支撑。

### 2.3 安全父链示例

```text
方法状态改善
    -> 父任务可重筹办
        -> 父任务可完成
            -> 安全问题被解决
                -> 安全目标特征改善
                    -> 安全值具备结算依据
```

如果链条只到：

```text
方法状态改善
```

而不能证明它最终支撑安全问题解决，则不能结算安全值。

### 2.4 无法分类或无父任务

安全问题暂时无法分类，或没有明确父任务时，不作为阻塞。

第一版规则：

```text
正式安全需求默认挂安全根需求下；
对应安全任务默认挂安全根任务 / 安全根需求承接任务下；
后续再根据目标宿主、特征类型、来源、缺口类型和任务结果归纳迁移。
```

但结算时仍必须能从该任务回溯到安全根或安全复合特征。

## 3. 结算对象必须是叶子任务或可结算叶子结果

安全 / 服务值结算对象第一版固定为：

```text
叶子任务完成后的价值。
```

父任务、汇总任务、管理任务、筹办任务壳不得重复结算子任务已经结算过的部分。

父任务可以没有单步本能方法；其动作已经分解到子任务中。父任务的结算作用是：

```text
归并子结果；
确认父需求是否满足；
不重复入账子任务价值。
```

## 4. 目标值与实际达成值

结算必须比较：

```text
之前值
目标值
实际结果值
满足关系
```

只知道任务完成不够。必须知道实际结果对目标达成了多少。

### 4.1 增加型目标

例如：

```text
目标：X.F >= V_target
之前值：V_before
实际结果：V_actual
```

需要：

```text
目标差距 = max(0, V_target - V_before)
实际推进 = max(0, V_actual - V_before)
达成比例 = clamp(实际推进 / 目标差距, 0, 1)
```

完成判定：

```text
V_actual - V_target >= 0
```

推进判定：

```text
V_actual - V_before > 0
```

### 4.2 降低型目标

例如：

```text
目标：X.F <= V_target
之前值：V_before
实际结果：V_actual
```

需要：

```text
目标差距 = max(0, V_before - V_target)
实际推进 = max(0, V_before - V_actual)
达成比例 = clamp(实际推进 / 目标差距, 0, 1)
```

完成判定：

```text
V_target - V_actual >= 0
```

推进判定：

```text
V_before - V_actual > 0
```

### 4.3 等值目标

例如：

```text
目标：X.F == V_target
```

第一版规则：

```text
实际结果等于目标：
    达成比例 = 1

实际结果不等于目标：
    若能计算距离，则按距离缩小比例计算；
    若不能计算距离，则达成比例 = 0。
```

### 4.4 区间目标

例如：

```text
目标：X.F in [L, U]
```

第一版规则：

```text
实际结果进入区间：
    达成比例 = 1

实际结果未进入区间：
    若能计算到区间的距离缩小，则按距离缩小比例计算；
    若不能计算距离，则达成比例 = 0。
```

### 4.5 目标差距为 0

如果结算前目标已经满足：

```text
目标差距 = 0
```

则本任务不得重复结算核心值。

可以记录：

```text
需求已满足；
任务完成但无新增核心值；
重复结算被拒绝。
```

### 4.6 部分达成与分段结算

部分推进不自动等于正式结算。

完全结算要求：

```text
来源需求已满足；
目标实际达成比例 > 0；
因果验收建议为可结算。
```

若来源需求尚未完全满足，但目标特征已有可验证推进：

```text
只能记录阶段性贡献候选 / 待结算候选 / 过程证据；
不得直接写核心安全值 / 服务值。
```

允许部分正式结算的特殊情况：

```text
需求本身被声明为可分段满足需求；
每个分段目标都有独立目标值、实际值、动作动态和结算记录；
每个分段能独立防重复结算。
```

否则，达成比例只用于说明推进程度，不用于提前入账核心值。

## 5. 安全 / 服务结算贡献层级比例

安全 / 服务结算按结算贡献层级衰减。

必须区分：

```text
安全因果距离层级：
    用于解释物理不安全事件的原因距离、需求投影和优先级衰减。

安全结算贡献层级：
    用于价值结算额度计算。
```

二者不得直接互换。因果距离层级进入结算前，必须经过：

```text
目标特征实际变化
任务贡献角色
因果证据强度
```

重新判定为安全 / 服务结算贡献层级。

每层计算以 `I64_MAX` 作为满刻度上界和比例分母常量。`I64_MAX` 可以作为安全 / 服务分量的合法满刻度结果，但不得作为“未计算、未知、无限大、默认成功、异常兜底”写入真实结算。

设：

```text
DEN = I64_MAX
W = 任务安全权重值 或 任务服务权重值
```

贡献层级比例：

```text
第一层：
    分子 = DEN * 9 / 10

第二层：
    分子 = DEN * 9 / 100

第三层：
    分子 = DEN * 9 / 1000

第 N 层：
    分子 = DEN * 9 / 10^N
```

贡献层级最大额度：

```text
贡献层级额度 = W * 贡献层级分子 / DEN
```

示例：

```text
第一层：最多结算 90% * W
第二层：最多结算 9%  * W
第三层：最多结算 0.9% * W
第四层：最多结算 0.09% * W
```

### 5.1 同层因素平分规则

安全 / 服务的层间贡献仍按十进衰减：

```text
第 n 层权重 Wn = 9 / 10^n
```

即：

```text
第一层 = 0.9
第二层 = 0.09
第三层 = 0.009
第四层 = 0.0009
```

但同一层内若存在多个同级影响因素，必须先在本层内部取平均，再投影到上一层或进入总安全 / 服务值候选。

设：

```text
M = I64_MAX
第 n 层定义的同级影响因素数量 = K_n
第 n 层因素 = F(n,1), F(n,2), ..., F(n,K_n)
每个因素值域 = 0..M
```

则：

```text
Ln = (F(n,1) + F(n,2) + ... + F(n,K_n)) / K_n
```

最终候选聚合为：

```text
自我安全值候选 =
Σn [ (9 / 10^n) * (Σi F(n,i) / K_n) ]
```

同层每个因素对自我安全值候选的最大直接权重为：

```text
9 / (10^n * K_n)
```

所有因素参与平均前必须统一为同一方向：

```text
值越大 = 越安全 / 越正向
值越小 = 越不安全 / 越负向
```

风险压力类因素不得直接与安全值同层平均，必须先反向转换：

```text
风险安全子项值 = I64_MAX - 风险压力值
```

缺失因素不得让同层其他因素自动变重：

```text
K_n = 该层抽象定义中的因素数量
不是当前已有证据的因素数量
```

若某因素未明确：

```text
无旧值：
    候选值 = 0

有旧的已提交值：
    候选值 = 旧值
    但不得因本次证据不足而上调

有明确新证据：
    使用新候选值
```

同时：

```text
该层明确状态 = 否
```

只有当：

```text
该层所有参与因素都明确；
证据不足原因 = 0；
聚合公式版本明确；
因素集合版本明确；
来源抽象特征定义版本明确；
```

才可写：

```text
该层明确状态 = 是
```

若因素集合变化，例如风险安全层从五项扩展为六项，必须升级因素集合版本和聚合公式版本。不同版本的候选值不得直接混作同一历史序列比较。

注意：本节中的 `I64_MAX` 是评估候选满刻度和比例刻度，不是正式入账后的真实安全值、服务值或结算增量。正式改账仍必须满足提交入口和价值结算闸门。

## 6. 实际达成比例

贡献层级额度只是最多可结算额度。

最终还必须乘以目标实际达成比例。

设：

```text
R = 目标实际达成比例，范围 [0, DEN]
```

则：

```text
实际结算值 = 贡献层级额度 * R / DEN
```

合并表达：

```text
实际结算值 =
    W * 贡献层级分子 / DEN * 目标实际达成比例 / DEN
```

或等价写成：

```text
实际结算值 =
    W * 层级比例 * 目标实际达成比例
```

其中：

```text
贡献层级比例来自安全 / 服务结算贡献层级；
目标实际达成比例来自实际结果值相对目标值的推进程度。
```

第一版公式可预留因果置信比例：

```text
正向结算候选 =
    W
    * 结算贡献层级比例
    * 目标实际达成比例
    * 因果置信比例
```

如果第一版暂不把因果置信比例纳入实际乘法，也必须保留字段，且证据不足时不得按强证据入账。

### 6.1 整数计算规则

所有比例分子必须用整数公式生成，不使用浮点数。

贡献层级分子生成本身也必须使用 128 位中间值或安全乘除函数，不得在 64 位整数中直接执行 `DEN * 9`。

所有结算乘法必须使用至少 128 位中间值，或使用安全乘除函数：

```text
安全比例乘法(W, 贡献层级分子, DEN)
安全比例乘法(贡献层级额度, R, DEN)
```

默认舍入规则：

```text
向下取整。
```

若结算结果为 0：

```text
记录为“有效但低于最小入账单位”；
不得强行入账 1。
```

## 7. 安全结算贡献层级建议

第一版安全结算贡献层级：

```text
第一层：
    直接改变安全目标特征，或直接解决物理安全目标。
    例：温度下降、宕机风险直接下降、损坏风险直接下降。

第二层：
    满足第一层所需的任务层变化。
    例：安全叶子任务完成、应急安全需求满足、直接风险处理任务完成。

第三层：
    支撑第二层任务推进的方法层或学习层变化。
    例：方法状态改善、条件结果对建立、方法可执行入口形成、方法稳定度提高。
```

禁止：

```text
把“安全值已经变化”作为结算前第一层证据。
```

安全值变化只能是 `结算叶子任务价值` 执行后的账本结果。

因此：

```text
方法状态改善：
    默认第三层安全贡献。

安全叶子任务完成并解决直接安全问题：
    默认第二层安全贡献，若输出事实直接命中安全目标，可提升为第一层。

直接物理安全特征改善：
    第一层安全贡献。
```

如果层级无法判断：

```text
不得结算核心安全值；
可以记录潜在贡献或生成归因补全需求。
```

## 8. 服务结算贡献层级建议

服务值结算同样必须有服务父链和实际达成值。

服务根需求目标宿主是自我，因为 `自我_服务值` 是自我的根特征。但服务值的事实来源不是“自我服务值差距本身”，而是自我对服务对象产生的可验证服务结果。

第一版服务事实链：

```text
服务抽象定义
    -> 自我觉醒根闭环给出服务因果坐标
        -> 服务触发事实挂载到服务根闭环信息位
            -> 对象 / 目标 / 授权 / 验证 / 归因 / 回写缺口通过闭环准入
                -> 服务子需求成立
                    -> 服务对象当前状态明确
                        -> 自我服务动作执行
                    -> 服务对象目标特征实际改善
                        -> 来源需求满足
                            -> 叶子任务价值结算
                                -> 自我_服务值增加
```

若缺少服务对象、服务目标、结果验证条件或因果归因条件：

```text
不得正式结算服务值；
只有已有服务触发事实且缺口会阻断行动、验证、归因或回写时，才按 006 和 011003 生成服务因果链上下文缺口子需求；否则等待服务触发事实或外部输入。
```

服务对象所需服务信息不足属于服务尝试过程中暴露的执行缺口；服务对象反馈信息也只能来自表达、确认、生效回执和外在特征变化等可观察证据。应先记录尝试结果、方向比较、沟通回执和阻塞证据，再由汇总机制判断是否固化为新的抽象特征或服务子需求。

服务结算前必须能回答：

```text
服务了谁；
谁允许该服务；
服务目标是什么；
服务前状态是什么；
服务后状态是什么；
状态变化是否朝目标方向改善；
改善证据是否可验证；
改善是否可归因于自我动作；
归因结果如何回写下一轮服务状态判断。
```

若服务前状态未知，则不能计算改善方向；若服务后状态未知，则不能验证服务结果；若只有任务完成、方法执行成功、文件被写入或文本已输出，而没有服务对象目标状态正向改善证据，不得正式结算服务值。

若存在明确的服务接受事实，例如服务对象接收输出、继续使用结果、确认可以采用、未拒绝交付结果，且在约定反馈窗口内没有负反馈，可以作为弱正向服务结果证据，生成：

```text
服务评价 = 可以 / 可接受
```

该评价只表示本次服务达到可接受下界，不表示很好、优秀或满分。若要进入更高评价或更高服务值结算，仍需明确正向反馈、目标状态改善比例、结果比对或后续服务对象状态改善证据。

第一版服务结算贡献层级：

```text
第一层：
    直接改善服务目标特征。

第二层：
    完成服务目标所需的任务层变化。

第三层：
    支撑服务任务推进的方法层或学习层变化。
```

禁止：

```text
把“服务值已经变化”作为结算前第一层证据。
```

服务值变化只能是结算方法执行后的账本结果。

当前工程若服务值结算仍处关闭或后置状态，则：

```text
允许只记录服务结算候选；
不得把服务权重或 I64_MAX 哨兵写入真实服务值。
```

## 8.1 任务安全 / 服务权重来源

结算公式中的 `W` 是本轮可结算预算，不是方法运行结果随手写入的数值。

`W` 只能来自：

```text
1. 来源需求创建时的目标压力 / 风险等级；
2. 安全 / 服务根需求投影规则；
3. 上级任务向叶子任务的预算分配；
4. 经动作动态记录的权重调整方法。
```

需求列表的类型安全 / 服务汇总权重只服务任务优先级和列表排序，不能作为 `W` 的来源。

禁止：

```text
1. 叶子任务完成后临时抬高 W；
2. 方法运行结果自行写 W；
3. 使用 I64_MAX 或接近哨兵值作为 W；
4. 父任务和多个叶子任务重复使用同一份未拆分 W。
```

预算守恒规则：

```text
AND关系下，同一父需求的活跃子需求 / 子任务可结算权重之和不得超过父需求分配给该目标特征的结算预算。

OR关系下，每条活跃路径可以继承父需求完整预算作为候选预算，但同一OR组只允许一条路径取得结算令牌并进入真实结算；未取得令牌的路径不得重复使用同一份父预算。
```

若无法证明 `W` 的来源合法，或无法证明预算未被重复使用：

```text
不得正式结算核心安全 / 服务值；
只能记录待补权重来源证据。
```

## 9. I64_MAX 使用边界

`I64_MAX` 有两类完全不同的语义，必须分开。

### 9.1 允许

允许作为满刻度上界和比例分母常量：

```text
DEN = I64_MAX
```

用于表达：

```text
结算贡献层级比例
目标实际达成比例
评估候选满刻度
同层因素平均刻度
安全 / 服务分量值域上界
```

真实结算值允许处于 `[0, I64_MAX]`，但必须同时满足：

```text
有来源公式；
有输入证据；
有有效期 / 适用范围；
由提交入口写入；
能证明 I64_MAX 是满刻度结果，不是未知 / 默认成功 / 异常兜底。
```

### 9.2 禁止

禁止作为：

```text
任务安全权重值；
任务服务权重值；
安全结算增量；
服务结算增量；
未计算值；
未知值；
无限大值；
默认成功值；
异常兜底值；
无证据满分。
```

如果在真实结算值中发现 `I64_MAX` 且无法证明它是合法满刻度结果：

```text
拒绝结算；
记录异常；
必要时生成安全需求候选。
```

## 9.3 与因果验收结果的接口

结算方法必须读取因果验收结果，至少包括：

```text
验收结论：
    成立 / 部分成立 / 不成立 / 反向成立 / 证据不足。

因果证据类型：
    直接执行证据 / 观察证据 / 推断证据 / 外部声明证据。

派生因果置信分：
    范围 [0, DEN]。
    由因果基础计数、证据类型和查询参数计算，不作为因果主信息字段。

副作用列表：
    每个副作用绑定目标特征、实际变化值、严重度、是否已处理。

竞争原因：
    是否存在其他动作或环境状态更可能导致该结果。

可结算建议：
    可结算 / 仅候选 / 待补证据 / 禁止结算。
```

第一版可暂不把因果置信比例直接乘入公式，但必须保留该字段。弱推断、外部声明或存在竞争原因时，不得和强直接执行证据同等入账。

## 9.4 反向副作用与净结算

若本任务同时造成正向目标达成和反向安全 / 服务损失，不得只结算正向收益。

必须执行：

```text
正向贡献计算；
反向损失计算；
净值比较；
副作用因果入账；
必要时生成修复需求。
```

若因果验收发现未处理的反向副作用：

```text
不得正式结算正向核心值；
除非该副作用已被独立记录、抵扣、阻断或转入安全 / 服务修复需求。
```

## 10. 结算闸门

安全 / 服务结算必须同时满足：

```text
1. 任务已完成。
2. 任务是叶子任务，或存在可结算叶子结果。
3. 来源需求已满足；若未完全满足，只能按阶段性贡献候选处理，除非该需求声明为可分段满足需求。
4. 有任务完成动作动态。
5. 有需求满足动作动态或满足证据。
6. 能沿任务 / 需求父链追溯到安全 / 服务目标特征。
7. 能回到世界树根链上的因果证据。
8. 能判定本任务属于第几层安全 / 服务结算贡献层级。
9. 不能把安全因果距离层级直接当作结算贡献层级。
10. 能读取之前值、目标值、实际结果值和满足关系。
11. 目标实际达成比例大于 0。
12. 结算值合法；若为 I64_MAX，必须证明它是合法满刻度结果，不是未知 / 默认成功 / 异常兜底。
13. 该任务未被重复结算。
14. 因果验收未发现未处理的反向副作用，或反向副作用已被独立记录、抵扣、阻断或转入修复需求。
15. 因果验收的可结算建议为“可结算”，不是“仅候选 / 待补证据 / 禁止结算”。
16. 任务权重 W 来源合法，且未超过父需求 / 父任务预算。
```

任一条件不满足：

```text
不得结算核心安全 / 服务值。
```

## 11. 动作动态与因果链

安全 / 服务结算必须有明确动作来源。

动作来源：

```text
本能方法_结算叶子任务价值
```

标准动作动态链：

```text
D0：叶子任务业务动作动态
    说明目标特征如何被改变。

D1：回写需求满足动作动态
    说明该结果满足了哪个来源需求。

D2：结算叶子任务价值动作动态
    引用 D0 / D1 / 输出结果场景，
    写入安全值或服务值变化。
```

结算方法可以调用先天特征写入逻辑完成底层写入，但动作动态来源必须是：

```text
结算叶子任务价值
```

不是：

```text
改变特征值
自我线程
任务管理线程
```

## 12. 禁止项

```text
1. 任务完成后不检查父链，直接结算安全值 / 服务值。
2. 方法状态改善后不证明安全父链，直接结算安全值。
3. 只看任务权重，不看目标实际达成值。
4. 只看任务完成，不看来源需求满足证据。
5. 用 I64_MAX 作为真实结算值。
6. 父任务重复结算子任务已经入账的价值。
7. 服务权重作为真实服务结算值直接入账。
8. 把自检发现问题直接结算为安全值增加。
9. 把“发现问题”与“解决问题”混成同一段结算因果。
10. 把先天特征写入逻辑作为结算动作来源。
11. 把安全因果距离层级直接当成安全结算贡献层级。
12. 把“安全值 / 服务值已经变化”作为结算前证据。
13. 有未处理反向副作用时只结算正向收益。
14. 叶子任务完成后临时抬高任务权重 W。
15. 使用浮点数生成比例分子或在窄整数中直接连乘导致溢出。
16. 缺少服务对象、服务目标、服务对象实际改善或因果归因证据时正式结算服务值。
17. 把单独无反馈、未知结果、任务运行成功或输出文本存在当作服务成功证据。
18. 把安全链的无负证据默认满足规则套用到服务链，默认服务对象已经受益、评价很好或满分。
19. 把“服务对象已接受服务 + 反馈窗口内无负反馈”生成的可以 / 可接受评价候选，直接升级为很好、优秀、满分或无条件服务值结算。
```

## 13. 最终定稿

```text
安全 / 服务值结算必须同时满足父链归因、世界树因果证据、结算贡献层级、实际达成比例、副作用审查和权重预算守恒。
父链说明“这属于哪个治理目标”；
世界树因果证据说明“结果是否由动作导致”；
结算贡献层级说明“最多能结算多少”；
实际达成值说明“这次正向达成了多少”；
副作用和派生因果置信分说明“是否需要抵扣、降级或转为候选”。
```

最短口径：

```text
无父链，不结算；
无世界树因果证据，不结算；
无目标实际达成，不结算；
无结算贡献层级，只记证据；
有未处理反向副作用，不只结算正向收益；
I64_MAX 可以作为满刻度和比例分母；不得作为未知、默认成功、异常兜底或无证据满分入账。
```
