# 因果补完流程规范 20260516

## 0. 上级约束

本规范受以下规范约束：

```text
规范/规范目录.md
规范/方法动作动态硬规则规范20260512.md
规范/动作动态即因果账本规范20260512.md
```

本规范不新增“任务完成因果记录”“需求满足因果记录”“世界事实因果记录”等并行账本结构。动作动态仍是系统内部事实与证据的权威来源。本文定义的是从动态证据中补完因果知识的流程。

## 1. 核心口径

```text
能建立完整因果，就一次性建完整因果；
动作未知时，只建状态变化线索，后续再补动作。
```

完整因果必须同时具备：

```text
条件状态
动作
结果状态
```

即：

```text
条件状态 + 动作 -> 结果状态
```

如果只有：

```text
初始状态 -> 结果状态
```

则只能称为：

```text
状态变化线索
待补动作线索
待补因果线索
```

不能称为完整因果模板。

## 2. 四类对象

| 对象 | 定义 | 是否因果主体 |
| --- | --- | --- |
| 动态节点 | 方法动作、状态变化、观察事件等事实来源。 | 否，作为证据来源。 |
| 状态变化线索 | 只描述状态从初始状态到结果状态的变化，动作未知或未确认。 | 否。 |
| 完整因果模板 | 描述“条件状态 + 动作 -> 结果状态”的可复用因果知识。 | 是。 |
| 因果实例 | 某次动态或动态链支持某个完整因果模板的证据实例。 | 否，作为模板证据。 |

状态变化线索不是因果主体。完整因果模板才是因果主体。因果实例只是完整因果模板的证据。

### 2.1 因果主信息收束原则

因果主信息只存可还原事实骨架和基础计数，不存解释结论。

硬规则：

```text
1. 因果作用类型不作为因果主信息独立字段。
   生成、消除、增强、减弱、抑制、转换等作用含义，
   只能由主果比较模板及其二次特征比较对象、比较量符号在解释层临时命名。
   这些命名不参与底层因果匹配、结算或任务判断。

2. 因果确定性不作为因果主信息独立枚举。
   稳定度、置信分、成功率、基线率、提升率等都属于解释层或查询层派生值。

3. 时间窗口不进入因果主信息。
   时间窗口属于动态匹配策略、场景推理策略或查询参数。

4. 失败样本引用不进入因果主信息。
   因果主信息只保留失败次数和最近失败时间；失败细节从动态链、日志链或统计索引追溯。

5. 基线统计只存基础计数，不存成功率、基线率、提升率等派生值。
```

推荐因果主信息骨架：

```cpp
class 因果主信息类 : public 基础信息基类 {
public:
    枚举_因果形态 形态 = 枚举_因果形态::未定义;

    枚举_因果锚点类型 适用锚点类型 = 枚举_因果锚点类型::未定义;
    std::uint32_t 适用层级 = 0;

    std::vector<可解析引用<二次特征节点类>> 条件比较模板{};

    std::vector<可解析引用<二次特征节点类>> 因比较模板{};
    可解析引用<方法节点类> 因方法模板{};
    std::string 因动作名称{};
    std::string 因动作语义键{};

    std::vector<可解析引用<二次特征节点类>> 果比较模板{};
    可解析引用<二次特征节点类> 主果比较模板{};

    枚举_因果来源类型 来源类型 = 枚举_因果来源类型::未定义;
    std::vector<可解析引用<动态节点类>> 证据动态样本{};

    std::uint64_t 观察次数 = 0;
    std::uint64_t 条件命中次数 = 0;
    std::uint64_t 因出现次数 = 0;
    std::uint64_t 果出现次数 = 0;
    std::uint64_t 成立次数 = 0;
    std::uint64_t 失败次数 = 0;

    时间戳 最近命中时间 = 0;
    时间戳 最近失败时间 = 0;

    bool 已验证 = false;

    std::int64_t 计算稳定度() const noexcept {
        return static_cast<std::int64_t>(成立次数)
             - static_cast<std::int64_t>(失败次数);
    }
};
```

不得新增或保留为主信息事实字段：

```text
枚举_因果作用类型
枚举_因果确定性
时间窗口字段
失败动态样本集合
置信度字段
成功率 / 基线率 / 提升率字段
```

如果接口需要输出“因果置信度 / 置信分 / 稳定度”，必须由基础计数临时计算，作为解释结果返回，不得写回因果主信息事实字段。

## 3. 三种处理情况

### 3.1 动态同时具备状态变化和动作

例如：

```text
条件状态：温度过高
动作：降低负载
结果状态：温度下降
```

应直接建立完整因果模板：

```text
温度过高 + 降低负载 -> 温度下降
```

可以同时建立或更新状态变化索引：

```text
温度过高 -> 温度下降
```

但该索引只用于检索、归并和补完，不是因果主体。

### 3.2 动态只有状态变化，没有动作

例如：

```text
初始状态：温度正常
结果状态：温度过高
动作：未知
```

只能建立状态变化线索：

```text
温度正常 -> 温度过高
状态 = 待补动作
```

不得直接建立完整因果模板。

### 3.3 后续发现动作

后续若发现可匹配动作：

```text
动作：高负载运行
```

则可补完为完整因果模板：

```text
温度正常 + 高负载运行 -> 温度过高
```

原状态变化线索应标记为：

```text
已被完整因果模板解释
或
部分补完
```

同一个状态变化线索可以被多个完整因果模板解释，因为相同状态变化可能有多个原因。

## 4. 标准补完流程

推荐入口命名为：

```cpp
按动态补完因果(...)
```

不得继续使用容易误导为两套因果结构的命名，例如：

```cpp
按动态补全两层因果(...)
```

标准流程：

```text
1. 从动态中提取初始状态和结果状态。
2. 如果没有状态变化，退出。
3. 查找或创建状态变化线索。
4. 把当前动态追加为状态变化证据。
5. 检查动态中是否有动作信息。
6. 如果没有动作：
       返回“仅有状态变化线索”。
7. 如果有动作：
       查找或创建完整因果模板。
8. 创建因果实例。
9. 把实例挂到完整因果模板。
10. 让完整因果模板引用状态变化线索。
11. 状态变化线索标记为已补完或部分补完。
```

## 5. 返回状态

建议返回状态：

```cpp
enum class 枚举_因果补完状态
{
    无状态变化 = 0,
    仅状态变化线索 = 1,
    已建立完整因果 = 2,
    已补完既有线索 = 3
};
```

建议返回结构：

```cpp
struct 结构_因果补完结果
{
    枚举_因果补完状态 状态 = 枚举_因果补完状态::无状态变化;

    状态变化线索节点类* 状态变化线索 = nullptr;

    因果模板节点类* 完整因果模板 = nullptr;
    因果实例节点类* 因果实例 = nullptr;

    bool 是完整因果() const noexcept
    {
        return 完整因果模板 != nullptr;
    }
};
```

## 6. 动作补完匹配规则

后续发现动作时，不得随意补到旧线索上。至少应匹配：

```text
状态变化签名一致
主体一致
特征类型一致
初始状态一致或兼容
结果状态一致或兼容
时间窗口接近
场景相同或相关
任务 / 方法来源相关
动态链存在引用关系
```

匹配不确定时，只能生成：

```text
候选完整因果
证据不足完整因果
待验证完整因果
```

不得直接升格为稳定因果。

## 7. 数据结构建议

### 7.1 状态变化线索

```cpp
struct 状态变化线索主信息
{
    状态节点类* 初始状态 = nullptr;
    状态节点类* 结果状态 = nullptr;

    std::string 状态变化签名;

    std::vector<动态节点类*> 动态证据;
    std::vector<因果模板节点类*> 已补完因果模板;

    bool 已有动作解释 = false;
    bool 待补动作 = true;
};
```

### 7.2 完整因果模板

```cpp
struct 因果模板主信息
{
    std::vector<可解析引用<二次特征节点类>> 条件比较模板{};

    std::vector<可解析引用<二次特征节点类>> 因比较模板{};
    可解析引用<方法节点类> 因方法模板{};
    std::string 因动作名称;
    std::string 因动作语义键;

    std::vector<可解析引用<二次特征节点类>> 果比较模板{};
    可解析引用<二次特征节点类> 主果比较模板;

    状态变化线索节点类* 来源状态变化线索 = nullptr;

    std::vector<因果实例节点类*> 证据实例;

    std::uint64_t 观察次数 = 0;
    std::uint64_t 条件命中次数 = 0;
    std::uint64_t 因出现次数 = 0;
    std::uint64_t 果出现次数 = 0;
    std::uint64_t 成立次数 = 0;
    std::uint64_t 失败次数 = 0;
};
```

`主果比较模板` 是果侧比较关系的主引用。生成、消除、增强、减弱、抑制、转换等词只能由显示层、查询层或二次特征解释器读取 `主果比较模板` 的比较对象和值符号后临时命名，不写入因果主信息，也不得作为底层推理条件。

### 7.3 因果实例

```cpp
struct 因果实例主信息
{
    状态节点类* 条件状态 = nullptr;
    存在节点类* 动作主体 = nullptr;
    词性节点类* 动作语义 = nullptr;
    std::string 动作语义键;
    状态节点类* 结果状态 = nullptr;

    动态节点类* 来源动态 = nullptr;
    任务节点类* 来源任务 = nullptr;
    方法节点类* 来源方法 = nullptr;

    bool 已验证 = false;
};
```

因果实例也不保存 `置信度`。实例只保存一次证据的引用和验证标记；置信分由模板基础计数、实例证据类型和查询参数临时计算。

## 8. 实现伪代码

```cpp
结构_因果补完结果 因果类::按动态补完因果(动态节点类* 动态)
{
    结构_因果补完结果 结果{};

    auto 变化 = 提取状态变化线索(动态);
    if (!变化.有效()) {
        结果.状态 = 枚举_因果补完状态::无状态变化;
        return 结果;
    }

    auto* 线索 = 查找或创建状态变化线索(变化);
    追加动态证据(线索, 动态);

    结果.状态变化线索 = 线索;
    结果.状态 = 枚举_因果补完状态::仅状态变化线索;

    if (!动态包含动作信息(动态)) {
        return 结果;
    }

    auto 动作 = 提取动作信息(动态);

    auto* 模板 = 查找或创建完整因果模板(
        变化.初始状态,
        动作,
        变化.结果状态,
        线索);

    auto* 实例 = 创建因果实例(
        变化.初始状态,
        动作,
        变化.结果状态,
        动态);

    追加实例证据(模板, 实例);
    标记线索已补完(线索, 模板);

    结果.完整因果模板 = 模板;
    结果.因果实例 = 实例;
    结果.状态 = 枚举_因果补完状态::已建立完整因果;

    return 结果;
}
```

## 9. 与动作动态账本的关系

动作动态仍是内部事实账本和证据来源。完整因果模板不是另一套任务 / 需求 / 世界事实账本，而是从动态证据中抽象出来的知识结构。

规则：

```text
1. 任务完成、需求满足、世界事实变化、方法学习结果仍落成各自域的动作动态。
2. 动作动态链提供因果补完的证据。
3. 只有具备条件状态、动作、结果状态三项时，才能生成完整因果模板。
4. 只有状态变化而缺动作时，只生成状态变化线索。
5. 状态变化线索不得伪装为完整因果模板。
```

## 10. 最终定稿

```text
因果补完不是两层因果关系。
它是从状态变化线索补到完整因果模板的流程。

动态提供证据；
状态变化线索保存待补动作的变化；
完整因果模板表达条件状态 + 动作 -> 结果状态；
因果实例为完整因果模板提供证据。
```

最短口径：

```text
能一次建完整因果就一次建；
不能，就先存变化线索，等动作出现再补因。
```
