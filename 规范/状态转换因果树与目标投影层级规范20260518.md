## 1. 总口径

```text
因果树本体存储所有状态转换信息。
安全、服务、学习、自维护等不是因果树本体，而是从状态转换因果树中按目标维度生成的只读投影树。
安全值变化不是因果树总根。它可能来自：
    自我存在不可维持或服务值按动态休眠阈值归零触发的根控制态；
    巡检 / 反馈证明的当前物理或运行事实变化；
    叶子任务完成后的账务状态转换投影。
```

一句话：

```text
世界状态转换是本体；安全 / 服务 / 学习 / 自维护是视角；
安全值变化必须区分控制态、物理事实变化和账务结果。
```

## 2. 状态转换因果树本体

状态转换因果树本体挂在世界树根链上，承载所有可追溯状态转换。

最小语义为：

```text
条件状态 C
    + 动作 A / 动态 D
        -> 结果状态 R
```

动作未知时，只能形成：

```text
状态变化线索：
    S_before -> S_after，待补动作。
```

本体节点与边至少表达：

```text
宿主存在
特征类型
before 状态
after 状态
条件状态 C
动作 A
结果状态 R
动作动态
输出结果场景
因果模板
证据动态样本
证据类型
基础计数
派生置信分
派生稳定度
副作用
竞争原因
来源引用
```

其中：

```text
基础计数：
    观察次数、条件命中次数、因出现次数、果出现次数、成立次数、失败次数。

派生置信分 / 派生稳定度：
    从基础计数、证据类型和查询参数临时计算；
    不作为因果主信息事实字段持久保存。
```

### 2.1 比较模板解释边界

状态转换因果树不存独立的 `枚举_因果作用类型`。

状态转换因果树本体只保存状态转换事实、动作来源、二次特征比较模板和基础计数。

生成、出现、消除、解除、增强、提升、减弱、抑制、转换等词，只能作为显示层、查询层或目标投影解释器对 `主果比较模板` 的临时命名。

底层因果匹配、任务判断和结算不得读取这些解释词，只能读取：

```text
二次特征比较对象
比较字段
比较量符号：
    r < 0
    r = 0
    r > 0
基础计数和证据引用
```

显示层可以按项目术语把比较结果命名为：

```text
初始状态：不存在 / 不满足
结果状态：存在 / 满足
    => 生成 / 出现

初始状态：存在 / 满足
结果状态：不存在 / 不满足
    => 消除 / 解除

初始状态：数值较低
结果状态：数值较高
    => 增强 / 提升

初始状态：数值较高
结果状态：数值较低
    => 减弱 / 抑制

初始状态 A
结果状态 B
    => 转换
```

这些命名只用于说明和展示，不属于因果树本体存储字段，也不得作为结算贡献层级、目标投影命中或因果成立判断的权威依据。

## 3. 目标维度投影

目标投影是只读视图，不新增权威因果节点。

第一版必须支持：

```text
安全目标投影
服务目标投影
学习收益投影
方法维护投影
自维护投影
账务状态投影
```

目标投影输出至少包含：

```text
目标维度
权重类型
目标宿主
目标特征类型
目标投影路径
安全 / 服务 / 学习等目标语义
结算贡献层级
因果距离层级
投影显示层级
证据路径
缺失证据
副作用路径
是否可结算
是否仅为候选
派生置信分
```

同一特征类型在不同目标投影下可以拥有不同层级。例如：

```text
方法稳定度提高：
    在学习投影中可能是一层或二层收益；
    在安全投影中通常是第三层安全支撑；
    在服务投影中也可能是第三层服务支撑。
```

2026-05-23 服务投影补充：

```text
自我_服务值 是自我存在的服务账务根特征。
服务对象外在特征状态改善 是服务事实目标特征变化。
服务目标投影必须区分二者：
    服务对象事实改善 -> 可作为服务值结算前证据；
    自我_服务值增加 / 结算性变化 -> 只能作为结算方法 D2 后的账务结果；
    自我_服务值自动衰减 -> 只能作为服务值动态衰减器的时间维护结果。
```

不得用 `自我_服务值已经变化` 反推证明服务对象已被服务。
不得用 `自我_服务值自动衰减` 反推证明服务对象未被服务、服务质量变差或服务对象受损。自动衰减只表示过去成功服务的积累状态随时间回落，并可作为服务意识重新唤醒和服务缺口检查的材料。

成功服务事件层级只用于单次服务事件的名义服务量和入账比例判定，不用于把总服务值改造成分层状态：

```text
成功服务事件：L0-L5 分层判定。
单次服务量：按标准服务单位、层级、有效性、证据强度、非重复性和安全值折算。
总服务值：连续数值，按剩余容量饱和入账并随时间动态衰减。
```

目标投影不得把服务事件拆成碎片重复结算。若多个 D0 都属于同一人类需求闭环，只有形成独立有效成果的阶段可作为子服务事件；否则必须通过非重复系数降权或归零。证据不足的候选成功服务只能进入候选服务池，不生成 D2 服务值增加。

服务值活跃存在和动态休眠阈值属于服务根特征维护投影，不属于服务对象事实投影：

```text
服务值低位 / 归零：
    只能表示当前缺少新的成功服务依据或进入休眠判断材料。

有效无成功服务时间增长：
    只能表示在安全值、服务能力和有效服务需求共同形成的服务机会压力下，
    无成功服务的压力正在累积。

服务意识强化 / 服务校准：
    只能触发服务根需求关注、服务能力检查、服务需求识别检查、
    目标识别检查、方法能力检查和安全约束检查。

休眠：
    是主动活跃权暂停的控制状态，不是服务失败事实，不是死亡，也不是终止。
```

目标投影不得用固定物理时间生成休眠结论。休眠投影必须读取：

```text
当前服务值 S；
有效无成功服务时间 E_no_success；
动态休眠阈值 Theta；
安全值 A；
服务能力 C；
有效服务需求强度 D；
当前是否存在有效服务进展。
```

若当前人类服务任务安全、目标明确且有阶段性进展，投影层只能生成“有效无服务压力降低 / 阶段性成功候选 / 服务校准继续”之类候选，不得直接投影为休眠成立。休眠状态必须保留可唤醒条件：新的有效人类服务需求、服务能力恢复、安全值改善或人类明确唤醒。

## 4. 三种层级必须分开

```text
因果距离层级：
    状态转换链中，原因距离目标结果有多远。

结算贡献层级：
    本次状态转换在某个权重类型下按第几层贡献结算。

投影显示层级：
    控制面板或解释树展示用的树状深度。
```

硬规则：

```text
安全因果距离层级不得直接作为安全结算贡献层级使用。
结算前必须通过目标特征实际变化、任务贡献角色、因果证据强度重新判定结算贡献层级。
```

## 5. 叶子任务业务动作前预判

叶子任务业务动作 D0 生成或执行前，必须先查询状态转换因果树，形成叶子任务因果投影预判。

预判必须回答：

```text
1. 这个叶子任务要改变哪个目标宿主。
2. 这个叶子任务要改变哪个目标特征类型。
3. 该目标特征类型可映射到哪些权重类型。
4. 在每个权重类型下属于第几层结算贡献。
5. 预计造成什么状态转换。
6. 需要哪些 before / target / actual 证据。
7. 是否存在副作用或竞争原因。
8. 是否允许形成业务动作 D0。
9. 是否允许进入结算候选。
```

建议接口：

```cpp
结构_叶子任务因果投影预判 查询叶子任务权重类型与层级(
    const 结构_叶子任务因果投影输入& 输入);
```

该接口只读，不写任务、需求、方法或世界树特征，不生成动作动态。

## 6. D0 / D1 / D2 硬边界

```text
D0：叶子任务业务动作动态
    记录事实状态转换。

D1：任务状态动作动态
    方法 = 提交任务状态变化；
    记录任务壳状态推进；
    可引用 D0 作为来源动作动态。

G0：成功服务治理判断
    只在服务值结算路径中使用；
    由 D0、现实证据、前后状态比较、验证、归因、权限安全和闭环回写共同生成；
    判断 D0 是否构成成功服务。

D2：结算叶子任务价值动作动态
    读取叶子任务完成事实、实际改变结果状态集合、完成度和任务自身权重，
    写入安全值、服务值或其他价值账务变化；
    普通安全 / 任务价值结算可引用 D0 / D1 / 输出结果场景作为因果解释证据；
    服务值增加必须引用 D0、D1 和 G0，缺任一项不得生成 D2 服务值增加。
```

D2 只处理叶子任务完成后的结算性账务变化。服务值自动衰减、有效无成功服务时间累计、服务校准和休眠阈值判断都不是 D2，不等待叶子任务完成，也不得伪装成服务对象事实改善或服务失败；它们应由服务值动态衰减器 / 活跃存在维护器生成独立时间维护动态，并保留衰减前后值、有效无成功服务时间、时间步长、动态衰减率、休眠阈值和来源参数。

禁止：

```text
D2 作为 D0 的事实因果证据。
安全值 / 服务值账务变化反推证明安全 / 服务目标已经真实改善。
任务完成、方法成功或输出存在反推证明成功服务。
账务状态转换伪装成物理事实证据、服务事实证据或方法学习事实证据。
风险安全候选反推证明物理安全事件已经发生。
无负向证据候选反推证明场景或存在永久安全。
```

## 7. 权重类型、预算与防重复

任务权重 W 只能来自：

```text
来源需求创建时的目标压力 / 风险等级；
安全 / 服务根需求投影规则；
上级任务向叶子任务的预算分配；
经动作动态记录的权重调整方法。
```

禁止：

```text
叶子任务完成后临时抬高 W；
方法运行结果自行写 W；
使用 I64_MAX 或接近哨兵值作为真实 W；
父任务和多个叶子任务重复使用同一份未拆分 W。
```

预算守恒：

```text
同一父需求下，所有子任务可结算权重之和不得超过父需求分配给该目标特征的结算预算。
同一 D0 在同一目标特征下不得重复计入贡献。
同一 D0 经多条路径命中同一目标时，只能选择一条主路径正式结算，其余路径作为解释候选。
```

## 8. 副作用与净贡献闸门

结算前必须检查反向副作用。

若存在未处理反向副作用：

```text
不得只结算正向收益。
必须执行：
    副作用记录；
    反向损失估算；
    净结算判断；
    必要时生成安全 / 服务修复需求候选。
```

净贡献规则：

```text
正向贡献
    - 反向安全损失
    - 反向服务损失
    = 净可结算贡献
```

## 9. 部分达成与阶段性候选

```text
完全结算：
    来源需求已满足；
    目标实际达成比例 > 0；
    可正式结算。

阶段性候选：
    来源需求未满足；
    但目标特征已有可验证推进；
    只记录候选贡献，不写核心安全值 / 服务值。

分段结算：
    只有需求被声明为可分段满足需求，
    且每段有独立目标值、实际值、D0、D1、防重复记录，
    才允许按段正式结算。
```

## 10. 整数计算安全规则

```text
禁止使用浮点数生成比例分子。
DEN = I64_MAX 可以作为比例分母常量，也可以作为安全 / 服务评估候选满刻度。
I64_MAX 不得作为真实安全值、服务值、权重值或结算增量。
```

评估候选满刻度与真实入账值必须分开。候选视图中 `I64_MAX` 可表示该评估公式版本、范围和有效期内的候选满刻度；提交后的真实根安全值、服务值和结算增量仍不得写入 `I64_MAX`，除非能证明它是合法满刻度结果且不是未知、默认成功或异常兜底。

比例分子：

```text
第一层分子 = DEN * 9 / 10
第二层分子 = DEN * 9 / 100
第三层分子 = DEN * 9 / 1000
第 N 层分子 = DEN * 9 / 10^N
```

工程规则：

```text
所有中间乘法必须使用至少 128 位，或使用安全乘除函数。
默认向下取整。
若结算值为 0，则记录“有效但低于最小入账单位”，不得强行入账 1。
```

## 11. DAG 化、环检测与去重

状态转换因果结构不强制是严格树，实际应按 DAG 处理。

必须支持：

```text
环检测
重复节点合并
重复路径去重
最大深度限制
同一 D0 不得重复结算同一目标特征
同一 D0 命中多目标时分别记录候选，并由结算闸门决定是否多目标净结算
```

## 12. V1.0 回归矩阵

V1.0 至少覆盖：

```text
1. 状态转换因果树能存 before / after / 动作 / 证据。
2. 安全目标投影能生成。
3. 服务目标投影能生成。
4. 安全值账务变化只进入账务投影，不作为事实根。
5. 叶子任务执行前能返回权重类型候选。
6. 叶子任务执行前能返回目标特征类型。
7. 叶子任务执行前能返回对应目标投影层级。
8. 只有 D2，没有 D0 / D1 / actual，不可结算；服务值增加还必须有 G0 成功服务治理判断。
9. 只有任务父链，没有世界树因果链，不可结算。
10. 方法改善没有被安全任务链引用，只能是候选。
11. 自检发现问题不直接结算安全值。
12. 解决自检发现的问题可以进入安全收益候选。
13. 有副作用时不得直接可结算。
14. 同一 D0 不得重复结算同一目标特征。
15. I64_MAX 不能进入真实权重或真实结算值。
16. 目标差距为 0 时拒绝重复结算。
17. 安全值 = 0 / 1 是根控制态，不由普通收益、风险余量或平滑函数触发。
18. 风险安全只表达未来服务值或物理安全下降的风险余量；无服务 / 物理下降路径时不能成立风险安全。
19. 物理安全采用独占候选后的能力保留率叠乘规则，不采用目标投影层级、同层平均、配额、加权模型或单纯最低值裁决；各必要物理因素给出完整 1..90 候选值后转换为能力保留率并叠乘裁决。
20. 场景评估结果只能作为风险因子、候选视图或结算前证据，不作为场景本体事实。
21. 服务值活跃存在投影使用有效无成功服务时间和动态休眠阈值，不使用固定无服务物理时间。
22. 有效无成功服务时间、服务意识强化和服务校准不得投影为成功服务事件、服务对象事实改善或 D2 服务值增加。
23. 当前人类服务任务安全、目标明确且有阶段性进展时，不得投影为普通无服务休眠成立。
```

## 13. V1.0 定稿判据

```text
给定一个叶子任务，
系统能在执行前判断：
    它要改变哪个目标特征；
    属于哪些权重类型；
    在每个权重类型下属于第几层；
    需要提交哪些证据。

执行后，系统能判断：
    实际状态转换是否成立；
    来源需求是否满足；
    是否存在副作用；
    是否重复结算；
    可结算多少；
    应写入哪个账务状态变化。

同时：
    因果树本体不写账；
    投影不写账；
    结算方法按 D0 / D1 / D2 明确入账。
```

一句话：

```text
叶子任务动手前能查清“改什么、算哪类权重、第几层、要什么证据”；
动手后能用 D0-D1-G0-D2 证明“真改了、任务壳已推进、成功服务已治理确认、可结算、没重复、没副作用”。
```
