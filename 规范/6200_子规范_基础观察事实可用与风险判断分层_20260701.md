91. 上述 `已取得 / 已建立 / 已覆盖 / 已完成 / 已完备 / 可用 / 新鲜` 均是枚举型实例特征值，派生消息只能把它们作为目标值；实例取值本身必须由合法生产者写入，并记录输入证据、判定标准、输出宿主、输出特征和动作动态 / 来源动态 / 规则证据。像素数量、缺失数量、重复映射数量、坐标回查状态、帧内编号回查状态等比较，是 `自我_建立像素观察存在集合` 或兼容的像素索引方法推出 `像素覆盖状态 等于 已覆盖` 的内部成立证据，不应再混作第一层观察帧容器已建立。
92. 这些目标闭合之后，才允许生成或推进基础风险判断目标：
93. 这些目标应由 `安全_评估当前场景安全性` 读取原始事实、因果信息和历史动态后生成评估结果视图。任务筹办不能把它们硬编码成固定前置链。
94. 1. 禁止用“已经观察了一帧”推出“基础风险判断状态 == 已明确”。
95. 2. 禁止用“像素 100% 可回查”推出“基础风险判断状态 == 已明确”。
96. 3. 禁止把观察质量可用状态等同于风险已判断。
97. 4. 禁止把基础风险判断状态已明确等同于风险可接受或场景安全。
98. 5. 禁止在当前场景存在集合、关键特征变化、时间顺序证据或归因候选缺失时写已明确。
99. 6. 禁止把相机内部采集、对齐、滤波、分割步骤登记成自我层本能方法。
100. 7. 禁止把补全深度、融合轮廓或未验证候选升级为基础风险已明确证据。
101. 8. 禁止由普通线程、任务筹办普通函数、控制面板、日志解析器或只读快照直接写入 已建立 / 已取得 / 已覆盖 / 已完成 / 已完备 / 新鲜 / 可用 / 已明确 等枚举型实例特征值。
102. 9. 禁止把本文的分层目标顺序实现为任务筹办器内部的安全观察专用能力；任务筹办只能读取需求、因果、方法条件或子需求数据来找条件。
103. 10. 禁止把存在_对自我直接伤害可能性、存在_对自我安全度、伤害可能性下界、连续无伤害共处时长、当前场景安全度、当前场景最低安全度存在等评估型派生结果写成存在本体的常驻原始特征。
104. 11. 禁止评估方法直接写自我_安全值或自我_服务值；账务型特征必须通过叶子任务价值结算入口写入。
105. 12. 禁止把无负向证据、默认满足候选值或 `I64_MAX` 候选满刻度解释为自我安全值已达最大值。
106. 13. 禁止在没有服务值下降路径或物理安全下降路径时成立风险安全。
107. 优先存在输出结果场景、运行期视图或任务执行回执中。
108. 若需要持久化，只能作为带来源方法、来源输入场景、证据引用、生成时间和有效期的评估状态缓存。
109. 不得写成存在或场景的永久本体事实。
110. 自我_安全值 / 自我_服务值只能由根控制规则和价值结算入口写入。
111. 场景评估、风险搜索和默认满足提交只能提供风险因子、候选分量、缺口或结算前证据。

2. 本规范不能作为代码实现完成、业务闭环完成、自我苏醒完成或初步成熟完成的证据。
3. 需要展开历史论证时，只能把 `规范/旧规范/` 中的原文件作为追溯材料，不得让旧文件反向覆盖本规范。
