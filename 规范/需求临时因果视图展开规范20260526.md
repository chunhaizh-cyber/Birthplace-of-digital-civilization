## 1. 定案口径

为了满足任意需求，标准流程定为：

```text
为了满足某个需求：
    先根据该需求的目标特征，
    从世界树已有因果信息中生成一个临时因果视图；
    再根据这个临时因果视图，
    形成缺口报告 / 派生需求消息 / 需求树更新指令输入草案；
    最后由提交入口裁决是否在统一需求树中补全子需求。
```

关键边界：

```text
临时因果视图不是新权威结构；
它只是一次需求展开时的解释结果。

需求树仍然是唯一承接结构；
安全 / 服务只是统一需求树里的两个根分区。

临时因果视图可以建议把正式需求树展开成逻辑组织节点，但这些节点仍然是普通需求节点：

```text
AND组：
    目标特征类型 = AND组满足状态

OR组：
    目标特征类型 = OR组满足状态

方法路径组：
    目标特征类型 = 方法路径完成状态

因果子链支撑节点：
    目标特征类型 = 因果子链支撑状态
```

临时因果视图不能直接把节点写成正式需求，也不能在需求已经入树后再补猜逻辑类型。它只能把展开建议翻译为带明确获取途径的更新指令输入草案：

```text
必要条件同时成立：
    获取途径 = 复合目标AND组生成
    目标语义 = AND组满足状态

替代路径择一满足：
    获取途径 = 多候选替代路径组生成
    目标语义 = OR组满足状态

方法能力路径需要分段完成：
    获取途径 = 方法能力路径组生成
    目标语义 = 方法路径完成状态

因果链证据或支撑条件需要补齐：
    获取途径 = 因果链支撑组生成
    目标语义 = 因果子链支撑状态
```

获取途径只用于提交入口选择生成规则和校验上下文；不得写入需求主信息。正式需求入树后，后续筹办、展示和聚合只读取目标特征类型及其抽象特征定义视图。

叶子 / 非叶子只表示结构是否展开，不表示 AND / OR / 因果子链 / 方法路径语义。正式入树和后续筹办必须读取目标特征类型及其抽象特征定义视图，判断是否可任务化、如何聚合子节点、是否需要 OR组结算令牌和提交闸门。

因果主信息仍然只存可还原事实；
临时视图中的角色、层级、优先级、禁忌、可信路径等，都属于解释结果。
```

一句话：

```text
需求先问世界树“哪些因果能让我达成、哪些会让我失败、我缺什么条件”；
世界树临时排出一张因果路网；
任务筹办把这张路网整理成缺口报告和派生需求草案；
提交入口裁决并落账后，需求树再承接正式子需求。
```

## 2. 标准流程

需求临时因果视图展开分为八步：

```text
1. 读取当前需求目标。
2. 构造目标比较。
3. 从世界树因果主信息生成临时因果视图。
4. 将临时因果视图翻译成缺口报告 / 派生需求消息 / 需求树更新指令输入草案。
5. 上报给需求治理 / 提交链，由提交入口校验、去重、合并、裁决。
6. `提交_生成缺口子需求` 或统一需求树更新提交入口新增或更新正式需求节点。
7. 子需求满足后回查父需求目标是否真的达成。
8. 根据实际达成情况更新世界树因果统计和证据链。
```

### 2.1 在任务筹办中的位置

任务筹办不再只是“为需求找一个方法”。新的任务筹办定义为：

```text
任务筹办 =
    路径筹办
  + 方法筹办
```

其中：

```text
路径筹办：
    根据当前需求目标查询世界树因果信息，包含来源为“遗传”的现有因果信息，
    生成临时因果视图，
    分析这个需求可以通过哪些因果路径被满足、会被哪些因果破坏、缺哪些条件和证据，
    再把这些路径翻译成缺口报告 / 派生需求消息 / 需求树更新指令输入草案。
    路径筹办只解释已有需求目标和因果 / 条件数据；不得在代码中按具体目标特征类型新增领域前置规则。

方法筹办：
    对已经足够叶子、没有未满足子需求，且目标特征定义视图允许普通任务化的需求，
    按方法输出结果能力寻找候选方法，
    检查输入、前置、动作入口、输出模式和动作动态落账规则，
    形成就绪回执或结构化缺口。
```

也就是说：

```text
任务筹办先解决路径问题：
    这个需求可以被哪些因果促成？
    哪些因果需要避免？
    哪些条件、证据、方法就绪项需要补齐？

再解决方法问题：
    某个叶子需求该由哪个方法执行？
```

方法只是满足需求路径的最后一段，不是全部路径。

若某个领域前置关系没有出现在世界树因果、需求侧条件、方法条件或已入树子需求中，任务筹办应生成学习缺口、条件来源缺口或规范缺口，而不是在筹办器里补写固定规则。

路径筹办输出只允许是三类：

```text
1. 缺口报告 / 子需求建议：
       说明要满足当前目标，路径上的某个必要前置状态 B 缺失。
       该报告不是正式需求节点，必须交给提交入口。

2. 候选对象作用方法：
       说明某个对象作用方法可能产生路径上的必要中间状态。
       该候选只进入方法候选集，不直接改变需求树。

3. 不可任务化原因：
       说明缺定义、缺权限、缺材料、缺来源需求或路径不足。
       该原因只进入回执 / 诊断 / 缺口报告。
```

禁止把上述任何一类输出直接当成正式子需求或任务。

### 2.2 任务管理侧与自我线程分工

路径筹办可以放入任务筹办逻辑中，但任务管理侧仍然不能直接写需求树。

职责定为：

```text
任务管理侧负责：
    发现缺口；
    查询世界树因果；
    生成临时因果视图；
    形成派生需求消息 / 需求树更新指令输入草案。

自我线程负责：
    校验派生需求是否具备入树条件；
    去重 / 合并 / 裁决；
    通过需求树统一更新指令新增或更新正式需求节点。
```

因此：

```text
任务筹办负责提出缺口报告和子需求草案；
提交入口负责裁决并正式入树。
```

现有链路保持不变：

```text
任务筹办 / 执行发现缺口
    -> 任务管理工作线程构造派生需求消息
    -> 上报给需求治理 / 提交链
    -> 提交入口校验是否具备入树条件
    -> 通过 `提交_生成缺口子需求` 或需求树统一更新指令新增 / 更新 / 合并需求
```

新增因果路径筹办后，链路扩展为：

```text
任务筹办发现当前需求不能直接执行
    -> 进入因果路径筹办阶段
    -> 根据世界树因果信息生成临时因果视图，包含来源为“遗传”的现有因果信息
    -> 从临时因果视图生成缺口报告 / 派生需求消息
    -> 上报给需求治理 / 提交链
    -> 提交入口裁决入树
    -> 入树后再由任务筹办处理这些子需求
```

流程关系：

```text
需求节点 D
    目标 = 目标宿主.目标特征类型 比较符 目标值
        ↓
世界树因果信息查询
        ↓
临时因果视图 V(D)
        ↓
促成 / 避免 / 条件补齐 / 证据补齐 / 方法就绪 / 副作用约束 / 学习缺口
        ↓
形成 D 的派生需求消息 / 更新指令输入草案
        ↓
提交入口裁决入树
        ↓
任务筹办按子需求目标找方法
        ↓
动作动态 / 状态变化 / 输出结果场景
        ↓
更新世界树因果信息
        ↓
回查 D 是否满足
```

## 3. 需求目标完整性

任何需求展开前，都必须先有明确目标：

```text
目标宿主
目标特征类型
当前值 / 当前状态
目标比较符
目标值 / 目标状态
```

示例：

```text
自我.安全值 大于 安全值基线
自我.服务值 大于 服务值基线
自我所在场景.当前观察帧存在状态 等于 已建立
目标存在.内部世界.细分状态 等于 已完成
双目相机.运行状态 等于 正常
双目相机.运行状态 等于 降级可用
```

同一目标需要“正常或降级可用”这类可接受集合时，应表达为多个 `等于` 比较的组合或由特征类提供可比状态集合，不得写成第四种比较符。

缺少目标宿主、目标特征类型、目标比较符或目标值时，不得生成临时因果视图。此时只能按上级需求规范生成目标补齐需求、维护报告或逻辑错误报告。

需求改变的不是目标宿主整体，而是：

```text
目标宿主.目标特征类型 比较符 目标值
```

## 4. 临时因果视图定义

临时因果视图是：

```text
针对某个需求目标，
从世界树因果信息中临时筛出的
达成路径 / 失败路径 / 条件缺口 / 方法缺口 / 证据缺口 / 副作用路径 / 学习缺口。
```

它不是：

```text
不是需求树。
不是因果树。
不是安全树。
不是服务树。
不是新的主信息结构。
不是方法候选集合的替代物。
```

工程实现中，临时因果视图应优先作为函数内局部结果、短生命周期 DTO 或调试摘要存在。必要时可将摘要作为普通特征写回需求节点，例如：

```text
需求节点.最近因果视图状态 = 已生成
需求节点.最近因果来源集合 = [...]
需求节点.因果展开时间 = ...
```

但权威来源仍然是：

```text
世界树中的因果主信息
需求树中的需求节点
动作动态中的证据链
```

## 5. 临时因果视图的逻辑格式

临时因果视图的概念格式为：

```text
临时因果视图 {
    根需求
    根分区
    根目标比较

    促成路径集合
    避免路径集合
    条件缺口集合
    方法就绪缺口集合
    证据缺口集合
    副作用约束集合
    学习缺口集合

    排序结果
    去重结果
    循环截断记录
}
```

路径项的概念格式为：

```text
因果路径项 {
    来源因果
    因果角色：
        促成 / 避免 / 条件支撑 / 方法支撑 / 证据支撑 / 副作用 / 学习缺口

    层级：
        1 / 2 / 3 / ...

    层级权重：
        900000 / 90000 / 9000 / ...

    条件状态：
        已满足 / 未满足 / 未知

    证据状态：
        充足 / 不足 / 待验证

    子需求目标比较：
        目标宿主.目标特征类型 比较符 目标值

    来源动态样本
    稳定度摘要
}
```

这些字段是解释层格式。除非另有上级规范批准，不得新增为因果主信息字段。

## 6. 世界树因果到临时视图的转换

### 6.1 主果命中当前目标

如果：

```text
因果.主果比较模板 ≈ 当前需求.目标比较
```

则生成促成路径。

示例：

```text
当前需求：
    自我.安全值 大于 安全值基线

世界树因果：
    因：自我.过热风险值 小于 过热风险安全阈值
    果：自我.安全值 大于 安全值基线

临时视图：
    促成路径 = 自我.过热风险值 小于 过热风险安全阈值
```

### 6.2 主果反向破坏当前目标

如果：

```text
因果.主果比较模板 与 当前需求.目标比较 方向相反
```

则生成避免路径。

示例：

```text
当前需求：
    自我.安全值 大于 安全值基线

世界树因果：
    因：自我所在场景.未知安全影响关系状态 等于 持续未知
    果：自我.安全值 小于 安全值基线

临时视图：
    避免路径 = 自我所在场景.安全影响关系状态 等于 已明确
```

避免路径生成子需求时必须收束成明确目标，不能只写抽象口号：

```text
自我所在场景.安全影响关系状态 等于 已明确
```

或：

```text
自我所在场景.安全影响未知持续时长 小于 最大允许持续时长
```

### 6.3 条件模板未满足

如果命中因果的条件模板未满足或未知，则生成条件补齐路径。

示例：

```text
因果条件：
    双目相机.运行状态 = 正常

当前状态：
    双目相机.运行状态 = 未知

条件补齐子需求：
    双目相机.运行状态 等于 正常
    或
    双目相机.运行状态 等于 降级可用
```

### 6.4 因方法模板存在

如果因果中含有因方法模板，不得直接生成“调用某方法”的命令。

必须先检查方法是否具备最小契约：

```text
输入参数明确
前置条件明确
动作入口存在
输出结果模式明确
动作动态落账规则存在
```

如果完整，则该方法只能作为后续任务筹办的候选依据之一；任务筹办仍必须按“方法结果能力是否命中任务目标”完整填充候选集。

如果不完整，则生成方法就绪缺口子需求，例如：

```text
方法.动作入口状态 等于 已建立
方法.输出结果模式状态 等于 已补齐
方法.输入参数模式状态 等于 已补齐
方法.条件结果对状态 等于 已补齐
```

### 6.5 证据不足

如果因果存在以下情况：

```text
成立次数少
失败次数多
未验证
证据动态样本不足
最近失败时间很近
```

则生成证据补齐路径。

示例：

```text
因果节点.证据状态 等于 足够
服务反馈.可信状态 等于 已验证
任务结果归因状态 等于 已确认
观察证据状态 等于 已补齐
```

证据补齐需求只补证据，不直接冒充业务目标已达成。

### 6.6 副作用因果

如果一条路径能促成某根分区目标，但会破坏另一根分区目标，则临时视图必须同时记录促成路径和副作用约束。

示例：

```text
因：某服务行为.执行状态 = 已执行
果1：服务对象.目标特征值 大于 服务对象.目标特征基线
果2：自我.安全值 小于 安全值基线
```

生成：

```text
服务根分区：
    服务对象.目标特征值 大于 服务对象.目标特征基线

安全根分区：
    某服务行为.副作用可接受状态 等于 可接受
```

服务有效但副作用不可接受的路径，不得沉淀成无条件可信路径。

### 6.7 无因果路径

如果无法从世界树因果信息找到促成、避免、条件、方法或证据路径，则生成学习缺口路径。

示例：

```text
目标特征.促成因果状态 等于 已补齐
目标特征.可执行方法状态 等于 已建立
需求.满足路径学习状态 等于 待学习
```

## 7. 临时视图到派生需求消息

临时视图只负责解释。任务管理侧根据临时视图生成的不是正式需求节点，而是：

```text
结构_任务管理派生需求消息
```

或等价的：

```text
需求树更新指令输入草案
```

真正写入统一需求树的动作只能由自我线程在校验、去重、合并和裁决之后完成。

转换表：

| 临时视图路径 | 生成派生需求消息类型 |
| --- | --- |
| 促成路径 | 促成类派生需求 |
| 避免路径 | 避免类派生需求 |
| 条件缺口 | 条件补齐派生需求 |
| 方法缺口 | 方法就绪派生需求 |
| 证据不足 | 证据补齐派生需求 |
| 副作用 | 副作用约束派生需求 |
| 无因果路径 | 学习缺口派生需求 |

每条派生需求消息至少应能表达：

```text
父需求引用
根分区
目标宿主
目标特征类型
当前状态
目标比较符
目标值
来源因果，可空
生成类型
贡献层级，可空
层级权重，可空
派生原因
证据状态，可空
```

可对应为特征：

```text
派生需求.根分区
派生需求.生成类型
派生需求.来源因果
派生需求.贡献层级
派生需求.层级权重
派生需求.派生原因
```

生成类型可以是：

```text
促成
避免
条件补齐
方法就绪
证据补齐
副作用约束
学习缺口
```

不得生成没有目标宿主、目标特征类型、当前状态、目标比较符或目标值的派生需求消息。

若兼容旧字段名 `目标方向`，其值域也必须收束为 `大于 / 小于 / 等于`。建立、刷新、确认、明确、新鲜等语义只能放入生成类型、派生原因、方法语义、目标特征类型或目标值，不得进入目标比较符。

层级权重不得由任务管理侧任意指定。任务管理侧可以报告贡献层级和来源因果，自我线程应按统一规则重算层级权重，例如：

```text
1 -> 900000
2 -> 90000
3 -> 9000
4 -> 900
```

## 8. 安全 / 服务根分区

安全 / 服务不是两套独立需求系统，而是统一需求树中的两个根分区。

安全根需求示例：

```text
自我.安全值 大于 安全值基线
```

可由临时因果视图生成的子需求包括：

```text
自我.物理安全值 大于 物理安全基线
自我所在场景.场景安全度预测置信状态 等于 达标
当前场景安全度明确状态 等于 已明确
当前场景最低安全度存在明确状态 等于 已明确
当前场景各存在安全评估明确状态 等于 已明确
自我所在场景.安全影响关系状态 等于 已明确
当前场景.场景存在集合明确状态 等于 已明确
自我.关键特征变化观察状态 等于 已建立
自我所在场景.安全因果候选构造状态 等于 已构造
当前观察帧.基础观察事实可用状态 等于 可用
自我所在场景.基础风险判断状态 等于 已明确
自我所在场景.安全影响预测值 小于 最大允许负向影响值
自我所在场景.负向影响处置需求明确状态 等于 已明确
自我所在场景.避险执行状态 等于 已执行
自我所在场景.安全影响未知持续状态 等于 不持续
自我所在场景.安全影响未知持续时长 小于 最大允许持续时长
```

其中 `当前观察帧.基础观察事实可用状态 等于 可用` 是第一阶段观察事实闭环目标；`当前场景安全度明确状态`、`当前场景最低安全度存在明确状态` 和 `当前场景各存在安全评估明确状态` 必须由 `安全_评估当前场景安全性` 读取原始事实和因果证据后生成；`自我所在场景.基础风险判断状态 等于 已明确` 是第二阶段兼容目标，解释为安全影响因果评估证据足够，不得由当前观察帧存在、像素 100% 回查、预设危险对象或存在常驻安全度特征直接推出。

服务根需求示例：

```text
自我.服务值 大于 服务值基线
```

可由临时因果视图生成的子需求包括：

```text
当前服务对象明确状态 等于 已明确
当前服务目标明确状态 等于 已明确
服务对象.目标外在特征值 大于 创建时目标外在特征值
服务反馈可信状态 等于 已验证
服务结果归因状态 等于 已确认
服务副作用状态 等于 可接受
```

服务根需求的根目标宿主仍是自我。服务对象是服务事实目标、证据目标或子需求目标的宿主，不得把服务对象改造成另一棵服务根树。

## 9. 观察需求的自然生成

观察需求不应被硬编码成固定低层链。只要世界树中存在下列因果，需求展开器即可自然生成观察需求：

```text
自我所在场景.当前观察特征帧取得状态 等于 已取得
自我所在场景.当前观察帧存在状态 等于 已建立
当前观察帧.像素覆盖状态 等于 已覆盖
当前观察帧.像素特征值承接状态 等于 已完成
当前观察帧.观察事实完备状态 等于 已完备
当前观察帧.质量可用状态 等于 可用
自我所在场景.当前观察新鲜度状态 等于 新鲜
    -> 当前观察帧.基础观察事实可用状态 等于 可用

当前观察帧.基础观察事实可用状态 等于 可用
当前场景.场景存在集合明确状态 等于 已明确
自我.关键特征变化观察状态 等于 已建立
自我所在场景.安全因果候选构造状态 等于 已构造
当前场景各存在安全评估明确状态 等于 已明确
当前场景最低安全度存在明确状态 等于 已明确
自我所在场景.基础风险评估范围状态 等于 已确定
当前观察帧.观察年龄 小于 最大允许风险判断观察年龄
自我所在场景.基础风险未判断因子数量 等于 0
自我所在场景.基础风险证据完整度 大于 最低基础风险证据完整度
自我所在场景.基础风险不确定度 小于 最大允许基础风险不确定度
自我所在场景.基础风险值计算状态 等于 已计算
    -> 自我所在场景.基础风险判断状态 等于 已明确

自我所在场景.基础风险判断状态 等于 已明确
自我所在场景.安全影响预测值 小于 最大允许负向影响值
自我所在场景.安全评估归因置信度 大于 最低安全评估归因置信度
自我所在场景.安全价值投影状态 等于 可投影
    -> 自我.安全值投影候选 大于 0

自我所在场景.当前观察帧存在状态 等于 已建立
    -> 服务对象当前状态明确状态 等于 可明确

服务对象当前状态明确状态 等于 已明确
    -> 服务对象目标特征值 大于 创建时目标特征值
```

安全根需求到观察 / 评估的推荐展开链：

```text
自我安全值不足
-> 需要判断当前场景安全度
-> 场景安全度由当前场景中最低存在安全度决定
-> 需要知道当前场景存在集合
-> 当前场景存在集合未知
-> 生成需求：当前场景存在集合明确
-> 任务化：安全_观察当前场景 / 安全_识别场景存在集合
-> 当前场景存在集合明确

-> 需要评估各存在安全度
-> 生成需求：当前场景各存在安全评估明确
-> 任务化：安全_评估当前场景安全性
-> 输出当前场景安全度、最低安全度存在和评估置信度
```

场景安全度、最低安全度存在、直接伤害可能性候选和评估置信度是评估结果视图，不是存在或场景的原始事实。若需要持久引用，只能作为带来源方法、输入场景、证据引用、生成时间和有效期的评估状态缓存。

`自我.安全值投影候选` 也不是自我安全值写账。它只表示评估结果可进入后续因果归因和价值投影；正式 `自我_安全值` 改写仍必须由叶子任务价值结算入口完成。

对应生成的子需求可能是：

```text
当前观察帧.基础观察事实可用状态 等于 可用
自我所在场景.当前观察特征帧取得状态 等于 已取得
自我所在场景.当前观察帧存在状态 等于 已建立
当前观察帧.像素覆盖状态 等于 已覆盖
当前观察帧.像素特征值承接状态 等于 已完成
当前观察帧.观察事实完备状态 等于 已完备
当前观察帧.质量可用状态 等于 可用
自我所在场景.当前观察新鲜度状态 等于 新鲜
双目相机.运行状态 等于 正常
双目相机.可用状态 等于 可用
```

其中 `已取得 / 已建立 / 已覆盖 / 已完成 / 已完备 / 可用 / 新鲜` 都是枚举型实例特征值。临时因果视图可以把它们展开成派生需求目标，但不得由任务管理线程、视图展开器、控制面板或只读快照直接写入这些状态；正式入树后必须由合法生产者及动作动态 / 来源动态 / 规则证据证明。

观察链进入任务筹办的方式只能是通用数据方式：

```text
世界树因果声明某目标需要观察事实；
需求侧条件声明某目标需要观察事实；
候选方法条件节点声明执行前需要观察事实；
已入树子需求要求补齐观察事实。
```

不得在任务筹办器内按 `基础风险判断状态`、`风险状态明确状态` 或其他领域目标特征名写死“先生成当前观察帧.基础观察事实可用状态 等于 可用”。如果该前置关系成立，必须先作为上述通用数据来源之一出现。

观察边界：

```text
相机只提供观察特征，自我把特征组织成场景和存在。
像素级 100% 只表示当前帧内可寻址、可回查、无遗漏、无重复。
像素观察事实不是稳定外部对象。
当前观察存在不是跨帧稳定身份。
基础观察事实可用不是基础风险已明确。
基础风险已明确不是风险可接受或场景安全。
控制面板复现必须读取自我所在场景中的识别结果，不能把相机预览当真值。
```

## 10. 去重、排序和循环截断

### 10.1 去重

需求唯一键：

```text
根分区
目标宿主
目标特征类型
目标比较符
目标值
父需求
来源因果，可选
```

同一父需求下，目标完全一致的子需求应合并或复用，不得重复入树。

如果安全和服务都需要同一个子需求，可以标记为：

```text
根分区 = 安全服务共享
```

共享分区只表示同一个子需求被两个根分区引用或贡献，不表示出现第三套需求树。

### 10.2 排序

排序优先级可参考：

```text
贡献层级越高越优先
层级权重越大越优先
因果稳定度越高越优先
已验证优先
条件缺口少优先
副作用低优先
最近失败少优先
方法已就绪优先
```

稳定度来自世界树因果主信息中的基础计数，例如：

```text
成立次数 - 失败次数
```

成功率、置信度、提升率等均为临时推导结果，不得写成因果主信息权威字段。

### 10.3 循环截断

如果需求路径中再次出现同一个目标：

```text
目标宿主 + 目标特征类型 + 目标比较符 + 目标值
```

则必须截断继续展开，并记录：

```text
需求节点.展开状态 = 因果循环已截断
```

循环截断不删除需求节点，只停止该路径继续生长，等待新的证据、条件或人工规范修订。

### 10.4 自我线程入树裁决

自我线程接收任务管理侧上报的派生需求消息或更新指令输入草案后，必须执行入树裁决。现有校验至少包括：

```text
缺上级需求拒绝。
上级是需求树结构根拒绝。
缺当前状态拒绝。
缺目标值 / 目标状态拒绝。
缺目标特征类型拒绝。
```

因果路径筹办新增消息还必须满足：

```text
1. 目标宿主不能为空。
2. 目标比较符不能为空，且必须是 大于 / 小于 / 等于。
3. 根分区必须与父需求兼容。
4. 来源因果若存在，必须能解析到世界树因果节点。
5. 生成类型必须合法：
       促成 / 避免 / 条件补齐 / 方法就绪 / 证据补齐 / 副作用约束 / 学习缺口。
6. 贡献层级必须 >= 1，或为空表示普通非价值需求。
7. 层级权重必须由自我线程按统一规则重算，不接受任务管理侧随意填权重。
8. 避免类需求不能只有“避免”字样，必须改写成明确目标特征状态。
9. 不能产生父子循环。
10. 不能绕过统一需求树更新指令。
11. 若目标值是枚举值，目标比较符必须是 等于。
12. 目标枚举值必须属于目标特征类型值域。
13. 枚举型实例特征值必须存在合法生产者；缺生产者时只能生成方法就绪缺口、判定规则待建立缺口或学习缺口，不能直接入普通执行路径。
```

如果任务管理侧仍以旧字段传来 `目标方向 = 建立 / 刷新 / 取得 / 确认 / 明确 / 新鲜 / 增加 / 降低 / 改善 / 避免 / 补齐 / 验证`，自我线程必须先尝试规范化为三比较格式。无法规范化时拒绝入树，并记录：

```text
拒绝原因 = 目标比较不合法
```

提交入口裁决结果可以是：

```text
新增正式子需求。
复用 / 合并既有子需求。
更新既有子需求来源、状态或归因。
拒绝入树并记录逻辑错误或普通报告。
暂存为候选信息，等待目标或证据补齐。
```

## 11. 需求满足后的回查

子需求完成后，不允许直接认为父需求完成。

必须执行：

```text
1. 子需求产生动作动态、观察动态、外部事件动态或状态变化。
2. 更新世界树因果统计。
3. 回查父需求目标特征是否真的变化。
4. 若变化达成，父需求满足。
5. 若未达成，相关因果失败次数增加或证据状态降级。
6. 下次临时视图生成时降低该路径排序，或生成诊断 / 替代路径需求。
```

示例：

```text
子需求：
    降温任务.完成状态 = 已完成

父需求：
    自我.过热风险值 小于 过热风险安全阈值

如果任务完成但温度没降：
    父需求不满足；
    因果失败次数 +1；
    生成诊断或替代路径需求。
```

执行了任务不等于达成了价值；子需求完成不等于父需求满足。

## 12. 与任务筹办和方法候选的边界

临时因果视图属于任务筹办的路径筹办阶段，不得绕过任务筹办，也不得替代方法候选筹办。

任务筹办的两段式边界为：

```text
第一段：路径筹办
    读取来源需求；
    检查需求目标完整性；
    构造目标比较；
    生成临时因果视图；
    生成促成、避免、条件补齐、方法就绪、证据补齐、副作用约束、学习缺口等缺口报告 / 派生需求消息；
    交给 `提交_生成缺口子需求` 或统一需求树更新提交入口裁决入树；
    若提交入口裁决后存在未满足子需求，则返回等待子需求 / 待重筹办回执。

第二段：方法筹办
    仅在当前需求足够叶子、没有未满足子需求，且目标特征定义视图允许普通任务化时进入；
    根据任务目标填充完整候选方法集；
    从候选集中选择当前方法；
    按方法状态、条件、参数、动作入口和结果能力形成就绪或缺口回执。
```

方法筹办仍必须遵守：

```text
根据任务目标填充完整候选方法集；
从候选集中选择当前方法；
按方法状态、条件、参数、动作入口和结果能力形成就绪或缺口回执；
缺口通过统一需求树继续生长。
```

禁止：

```text
用临时因果视图直接指定唯一方法并跳过候选集填充。
用路径筹办结果直接执行方法。
用安全 / 服务 / 外设控制 / 检查 / 使用分类替代结果能力命中。
用安全 / 服务 / 观察 / 外设 / 学习等领域分类在任务筹办器内硬编码固定前置需求。
把任务筹办 / 任务执行注册为本能方法。
把方法未命中直接复制成父需求目标。
把方法缺口子需求写到错误目标宿主上。
把子需求完成直接记成父需求满足。
任务管理侧直接调用统一需求树更新入口写正式需求节点。
```

临时因果视图只能告诉系统“哪些方向值得补、哪些路径要避免、哪些条件或证据缺失”。真正的执行承接仍由统一需求树、任务树、方法候选和动作动态链完成。

## 13. 动作动态与因果账本

临时因果视图本身不生成业务动作动态。

能生成动作动态的是明确方法，例如：

```text
需求域方法：派生需求入树 / 回写需求满足
任务域方法：任务状态提交 / 回执同步
世界域方法：写入观察结果 / 写入输出结果场景
方法域方法：补齐方法入口 / 补齐条件结果对
```

动作动态不是成功 / 失败日志，也不得把成功 / 失败作为根分类。需求满足只能作为输出结果、二次特征或派生判断写入，不能替代输入特征到输出特征的因果链。

## 14. 伪算法

任务筹办路径阶段伪流程：

```text
函数：路径筹办(需求节点 D)

1. 如果 D 已满足：
       返回

2. 如果 D 没有明确目标宿主 / 目标特征类型 / 目标比较符 / 目标值：
       标记 D = 目标不完整
       构造目标补齐派生需求消息或维护报告
       返回

3. 构造目标比较 T

4. 生成临时因果视图 V(D, T)

5. 从 V 中生成派生需求消息草案：
       促成类派生需求
       避免类派生需求
       条件补齐派生需求
       方法就绪派生需求
       证据补齐派生需求
       副作用约束派生需求
       学习缺口派生需求

6. 对草案做本轮去重、排序和循环预判。

7. 上报自我线程。

8. 返回等待裁决 / 等待子需求 / 待重筹办回执。
```

自我线程入树裁决伪流程：

```text
函数：裁决派生需求入树(派生需求消息 M)

1. 校验父需求存在且不是需求树结构根。
2. 校验目标宿主、目标特征类型、当前状态、目标比较符、目标值完整。
3. 校验根分区与父需求兼容。
4. 校验来源因果、生成类型、贡献层级和派生原因。
5. 将避免类、约束类需求改写成明确目标特征比较。
6. 查找同父直接子需求是否已有目标重叠项。
7. 若已有，合并 / 更新来源、状态、归因和统计。
8. 若没有，构造结构_需求树更新指令。
9. 通过需求类::执行更新指令新增正式需求节点。
10. 刷新子需求权重、结构角色和调度相关摘要。
```

临时因果视图生成伪流程：

```text
生成临时因果视图(D, 目标比较 T):

1. 初始化临时视图 V。
2. 遍历世界树因果信息。
3. 读取因果主信息和主果比较模板。
4. 如果主果命中 T：
       加入促成路径；
       分析条件缺口；
       分析方法缺口；
       分析证据缺口。
5. 如果主果反向破坏 T：
       加入避免路径；
       分析副作用约束。
6. 如果没有任何路径：
       加入学习缺口。
7. 排序临时视图路径。
8. 返回 V。
```

## 15. 实施切片

### P1 需求目标完整性检查

确保每个被展开的需求节点都有：

```text
目标宿主
目标特征类型
目标比较符
目标值
```

缺失则不能展开临时因果视图。

### P2 世界树因果查询

实现：

```text
按主果命中目标比较查因果
按主果反向目标比较查因果
按条件模板查未满足条件
按方法模板查候选方法 / 方法缺口
```

### P3 临时因果视图生成

实现：

```text
生成促成路径集合
生成避免路径集合
生成条件缺口集合
生成方法就绪缺口集合
生成证据缺口集合
生成副作用约束集合
```

第一阶段只在内存中生成，不入库，不新增权威主信息结构。

### P4 根据临时视图生成派生需求消息

实现：

```text
促成类派生需求消息
避免类派生需求消息
条件补齐派生需求消息
方法就绪派生需求消息
证据补齐派生需求消息
副作用约束派生需求消息
学习缺口派生需求消息
```

任务管理侧只形成消息或更新指令输入草案，不直接写需求树。

### P5 自我线程入树裁决

实现：

```text
校验目标宿主 / 目标特征 / 当前状态 / 目标比较符 / 目标值
校验父需求和根分区
校验来源因果和生成类型
重算层级权重
同父目标去重 / 合并
父子循环截断
通过统一需求树更新指令入树
```

### P6 去重、排序、循环截断

实现：

```text
需求唯一键
安全 / 服务共享合并
最大展开深度
循环路径截断
```

### P7 满足回写与因果更新

实现：

```text
子需求完成后验证父目标
更新因果成立 / 失败次数
重新生成临时视图
必要时更新需求树
```

## 16. 禁止项

```text
1. 禁止把临时因果视图持久化为新的权威树、权威账本或主信息结构。
2. 禁止把安全 / 服务做成脱离统一需求树的两套独立需求系统。
3. 禁止让临时视图绕过任务筹办候选集填充。
4. 禁止用分类标签替代方法结果能力命中。
5. 禁止生成没有目标宿主、目标特征类型、当前状态、目标比较符或目标值的派生需求消息。
6. 禁止把子需求完成直接等同于父需求满足。
7. 禁止把任务完成直接等同于安全值 / 服务值变化。
8. 禁止把临时推导的置信度、稳定度、优先级写成因果主信息事实字段。
9. 禁止把动作动态写成成功 / 失败根分类。
10. 禁止把服务对象作为服务根需求宿主。
11. 禁止把相机预览当作观察需求满足证据。
12. 禁止让 I64_MAX 进入真实服务或安全结算。
13. 禁止任务管理侧直接写需求树或直接调用统一需求树更新入口生成正式需求节点。
14. 禁止把派生需求消息等同于已入树正式需求。
15. 禁止接受任务管理侧随意填入的层级权重；层级权重必须由自我线程按统一规则重算。
16. 禁止把某个领域目标的前置条件写成任务筹办器内部独立能力；前置条件必须以需求、因果、方法条件或子需求数据表达。
```

## 17. 验收口径

第一阶段只能宣称：

```text
需求目标完整性可检查。
可以从世界树因果信息生成临时因果视图。
临时因果视图可以翻译为派生需求消息 / 需求树更新指令输入草案。
促成、避免、条件补齐、方法就绪、证据补齐、副作用约束和学习缺口都有明确目标口径。
任务管理侧不直接写需求树。
提交入口负责入树裁决、去重、合并和通过统一需求树更新入口正式入树。
任务筹办仍按方法结果能力完整填充候选集。
任务筹办仍只找路径、找方法、找条件，且路径 / 条件必须来自通用数据来源。
子需求完成后仍需回查父需求目标。
```

不得宣称：

```text
安全值 / 服务值已自动正确结算。
临时因果视图已成为新的权威因果结构。
需求树双根分区已等同于两套独立价值观系统。
没有父目标回查就完成父需求。
没有真实动作动态、状态快照或证据日志就证明因果成立。
任务管理侧已生成派生需求消息就等同于正式需求已入树。
```

## 18. 最终定义

```text
为了满足任意需求，系统首先将该需求的目标表达为二次特征比较；
然后以该目标比较为根，从世界树因果主信息中生成一个临时因果视图；
临时因果视图只作为本次需求展开的解释结果，不作为新的权威树结构；
任务管理侧再根据该视图生成促成、避免、条件补齐、方法就绪、证据补齐、副作用约束和学习缺口等缺口报告、派生需求消息或更新指令输入草案；
提交入口负责校验、去重、合并和裁决是否通过统一需求树更新指令写成正式子需求；
所有正式子需求仍挂回统一自我需求树；
安全 / 服务只是统一需求树中的两个根分区；
子需求完成后必须回查父需求目标特征是否真的达成，并据此更新世界树因果统计。
```
