# 特征值符号三态比较底层逻辑规范 2026-05-18

## 1. 总口径

所有基本逻辑都通过“特征值比较”得到方向。

本规范所说的三态比较，不是一个应进入数据层的数据结构，而是一条底层逻辑协议：

```text
任意两个已确认可比的特征值
    -> 比较
        -> 得到有符号比较量 r
            -> 系统只读取 r < 0 / r = 0 / r > 0
```

因此：

```text
三态比较协议：
    不是节点。
    不是特征。
    不是二次特征。
    不是因果信息。
    不进入概念树、场景树或信息仓库。

比较函数：
    只是实现该协议的工具。

方向掩码 / 允许方向：
    可以作为模板值域或匹配约束存储。

二次特征：
    是比较关系被特征化后的可存储特征。

因果信息：
    是因侧二次特征 / 因方法 与 果侧二次特征之间的统计关系。
```

比较函数不强制返回固定的：

```text
-1 / 0 / 1
```

而是返回一个有符号比较量：

```text
比较量 r = 比较(左值, 右值)

r < 0：左值 < 右值
r = 0：左值 = 右值
r > 0：左值 > 右值
```

也就是说，本系统的三态不是固定数值三态，而是符号三态：

```text
小于0
等于0
大于0
```

系统底层不使用这些解释概念参与推理：

```text
生成
消除
增强
减弱
转换
满足
不满足
促进
抑制
```

这些词最多作为人类阅读时的自然语言命名或展示标签，不得作为底层逻辑字段、推理枚举、结算依据或候选选择依据。

一句话：

```text
比较即方向，方向只取比较量的符号。
```

---

## 2. 比较量定义

底层比较函数应按三态比较协议返回一个有符号比较量：

```cpp
using 比较量 = std::int64_t;
```

所有比较函数可以返回：

```text
任意负数
0
任意正数
```

系统基础逻辑只读取其符号：

```cpp
if (r < 0) {
    // 左值小于右值
}
else if (r > 0) {
    // 左值大于右值
}
else {
    // 左值等于右值
}
```

比较量的绝对值不属于底层方向语义。

如果某些实现返回差值幅度，该幅度只能用于：

```text
排序距离
差异缓存
调试显示
启发式评分
生成更高阶关系特征 / 多次特征
```

不得直接作为基础逻辑分支。

## 3. 符号提取

系统可以提供符号提取工具，把任意比较量归一为：

```text
-1 / 0 / 1
```

但这只是符号提取，不是要求原始比较函数只能返回这三个值。

推荐工具：

```cpp
static inline std::int8_t 比较符号(std::int64_t r) noexcept
{
    return static_cast<std::int8_t>((r > 0) - (r < 0));
}
```

结果：

```text
r < 0  => -1
r == 0 => 0
r > 0  => 1
```

不得把“符号归一结果”误当作比较器原始返回值约束。

---

## 4. 比较前置条件

比较器只负责比较，不负责解释两个值是否可比。

进入比较前，调用方必须确保：

```text
1. 左值和右值属于同一可比域。
2. 特征类型一致，或已有明确映射规则。
3. 值域一致。
4. 度量签名一致。
5. 比较字段一致。
6. 指针值、枚举值、数值、时间值等已经转换到对应比较域。
```

如果前置条件不满足，不得让比较器返回“未知”或“不可比”。应在比较前阻断，并按错误性质处理：

```text
非正常逻辑错误：
    报错 / 弹错 / 记录日志。

业务缺口：
    形成回执、派生需求、等待条件或学习候选。
```

比较器职责边界：

```text
输入：两个已确认可比的特征值。
输出：有符号比较量。
使用：只读取比较量符号。
```

不可比较不是第四种比较结果。

---

## 5. 应用位置：关系生成点

三态比较协议应当应用在系统的关系生成点，而不是语义解释点。

关系生成点指系统需要判断两个特征值之间是否形成方向关系、命中关系、排序关系、动态关系或因果统计关系的地方。

总规则：

```text
凡是系统要判断“两个特征值之间的方向关系”时，就应用三态比较协议。
凡是只是保存对象、创建节点、记录原始值时，不应用三态比较协议。
```

底层链路为：

```text
特征值
  ↓
比较量 r
  ↓
r < 0 / r = 0 / r > 0
  ↓
条件命中 / 动态方向 / 二次特征模板 / 因果统计 / 方法判断 / 场景匹配
```

解释词不参与这条链路。

---

## 6. 左值和右值约定

为了避免方向反转，所有关系生成点必须固定左值和右值语义。

| 场景 | 左值 | 右值 | 比较意义 |
| --- | ---: | ---: | --- |
| 状态迁移 | 初始状态值 | 结果状态值 | 旧值相对新值的方向 |
| 条件匹配 | 当前值 | 模板值 / 阈值 | 当前是否命中模板 |
| 方法前置 | 当前输入值 | 方法要求值 | 是否允许执行 |
| 方法输出 | 执行前值 | 执行后值 | 方法造成的变化方向 |
| 因果果侧 | 果初始值 | 果结果值 | 果动态方向 |
| 排序查找 | 当前节点键 | 目标节点键 | 节点相对目标的顺序 |

状态迁移必须统一为：

```text
左值 = 初始状态值
右值 = 结果状态值
```

因此：

```text
比较(初始值, 结果值) < 0
    表示初始值小于结果值。

比较(初始值, 结果值) = 0
    表示初始值等于结果值。

比较(初始值, 结果值) > 0
    表示初始值大于结果值。
```

任何模块不得私自反转状态迁移的左右值含义。

## 7. 应用时机

### 7.1 特征状态写入后

当某个特征从旧值变为新值时，应比较旧值和新值：

```text
左值 = 初始状态值 / 写入前值
右值 = 结果状态值 / 写入后值
```

流程：

```text
写入特征值
    ↓
旧值与新值比较
    ↓
产生动态方向
    ↓
生成或匹配二次特征模板
    ↓
进入因果统计
```

这里不解释为：

```text
出现 / 消除 / 增强 / 减弱
```

只记录或匹配：

```text
比较量 < 0
比较量 = 0
比较量 > 0
```

### 7.2 条件模板匹配时

方法、因果、场景规则的条件模板，本质上都是比较：

```text
当前特征值 ? 模板值
当前特征值 ? 阈值
当前特征值 ? 目标状态值
```

流程：

```text
当前值与模板值比较 -> 比较量
比较量与比较条件匹配 -> 命中 / 不命中
```

因此，比较层和条件命中层必须分开：

```text
第一层：比较器
    左值 vs 右值 -> 比较量

第二层：条件命中器
    比较量 + 比较条件 -> 命中 / 不命中
```

已有返回 `1 / 0 / -1` 的条件函数如果语义是“满足 / 不满足 / 条件不支持”，它不是三态比较器本体，而是条件命中层。

### 7.3 方法执行前后

方法执行前使用三态比较器检查输入场景和前置条件：

```text
当前输入值 与 方法要求值 比较
```

方法执行后使用三态比较器检查输出场景和方法结果：

```text
执行前状态值 与 执行后状态值 比较
```

方法基本结构可理解为：

```text
前置比较集合满足
    ↓
执行方法
    ↓
输出比较集合产生
    ↓
生成动态
```

若方法执行后没有任何可比较事实变化，不得伪造解释性动态。是否记录 `比较量 = 0` 的稳定动态，由具体动态记录规范决定。

### 7.4 动态节点生成时

动态节点只提供比较材料：

```text
动态主体
动态特征
初始状态
结果状态
来源方法
```

动态方向由：

```text
比较(初始状态值, 结果状态值)
```

得到。

### 7.5 二次特征生成或匹配时

二次特征应表示比较关系模板：

```text
某特征：比较(初始值, 结果值) < 0
某特征：比较(初始值, 结果值) = 0
某特征：比较(初始值, 结果值) > 0
```

底层二次特征不得表示：

```text
风险增强
任务推进
需求满足出现
```

### 7.6 因果匹配与统计时

因果成立流程基于比较集合命中：

```text
1. 当前条件特征值与条件模板值比较。
2. 因侧动态的初始值与结果值比较。
3. 果侧动态的初始值与结果值比较。
4. 三者的比较量符号命中模板。
5. 成立次数 +1。
```

失败流程：

```text
因侧命中，但果侧比较未命中
    -> 失败次数 +1
```

因果主信息只保存比较模板、因方法、证据动态和基础次数，不保存语义解释。

### 7.7 场景匹配、空间匹配、距离判断时

场景、空间、距离、相似度等逻辑应先计算特征值，再比较特征值。

例如：

```text
距离值 = 计算距离(A, B)
比较量 = 比较(距离值, 阈值)
```

三态比较器不负责计算距离、相似度、重叠度或夹角。它只比较这些值。

### 7.8 查找、排序、去重时

排序比较：

```text
左节点键 ? 右节点键 -> 比较量
```

条件查找：

```text
节点字段与目标字段比较 -> 比较量
比较量与比较条件匹配 -> 命中 / 不命中
```

如果现有 `比较(...)` 在某些路径中返回 `1 / 0` 表示“命中 / 不命中”，它应被视为条件命中函数，不是三态比较器。

推荐拆分接口：

```cpp
std::int64_t 比较量(基础信息基类* 对象, 枚举_比较字段 字段) const;

bool 命中条件(
    基础信息基类* 对象,
    枚举_比较字段 字段,
    枚举_比较条件 条件
) const;
```

避免 `1` 同时表示“大于”和“满足条件”。

---

## 8. 不应用时机

### 8.1 不可比时不调用

不可比是比较前流程失败，不是比较结果。

```text
值域一致 -> 调用比较器
值域不一致 -> 本轮匹配失败，不调用比较器
```

不得用比较量表达：

```text
不可比
未知
未定义
```

### 8.2 只创建节点时不调用

以下操作若没有两个值需要形成关系，不调用三态比较器：

```text
创建存在节点
创建特征节点
创建状态节点
创建方法节点
创建任务节点
```

### 8.3 不用于语义解释

比较器不得输出：

```text
增强
减弱
出现
消除
推进
回退
改善
恶化
```

它只输出有符号比较量。

## 9. 整数比较实现规则

对于 `I64 / std::int64_t` 等整数值，不建议直接返回：

```cpp
return 左 - 右;
```

原因是差值可能溢出。

如果底层只需要符号，推荐：

```cpp
static inline 比较量 比较I64(std::int64_t 左, std::int64_t 右) noexcept
{
    if (左 < 右) return -1;
    if (左 > 右) return 1;
    return 0;
}
```

如果确实需要差值幅度，应使用：

```text
安全差值
饱和差值
更宽中间类型
```

但系统基础逻辑仍只能读取：

```text
差值 < 0
差值 = 0
差值 > 0
```

## 10. 复合关系由比较量符号组合得到

底层不需要单独保存“不等于、大于等于、小于等于”等关系。

### 6.1 等于

```cpp
比较(A, B) == 0
```

可用于：

```text
状态一致
条件命中
目标达成
模板匹配
实际值到达目标值
```

### 6.2 大于

```cpp
比较(A, B) > 0
```

可用于：

```text
超过阈值
优先级更高
阶段更靠后
数量更多
时间更晚
```

### 6.3 小于

```cpp
比较(A, B) < 0
```

可用于：

```text
低于阈值
优先级更低
阶段更靠前
数量更少
时间更早
```

### 6.4 不等于

```cpp
比较(A, B) != 0
```

### 6.5 大于等于

```cpp
比较(A, B) >= 0
```

### 6.6 小于等于

```cpp
比较(A, B) <= 0
```

## 11. 比较条件、允许方向与方向区间

本系统要区分：

```text
允许方向 / 方向掩码：
    表示允许哪些比较方向命中。

方向区间：
    表示已经取得比较方向之后，该方向内部的量域细分。
```

二者都不负责解释，不负责生成语义，不负责说明：

```text
增强
减弱
出现
消除
转换
满足
不满足
促进
抑制
```

底层流程必须固定为：

```text
左值、右值
    -> 比较器
        -> 比较量 r
            -> r < 0 / r == 0 / r > 0
                -> 允许方向 / 方向掩码判断是否命中
                -> 方向区间记录该方向内部的量域细分
```

因此允许方向不是第一步。它只能在已经得到比较量之后，作为模板、条件、方法前置、二次特征、因果和查询筛选的匹配约束。

方向区间也不是第一步。它只能在已经得到比较量或安全差值之后，表达某一方向内部的细分域。例如：

```text
负方向内部的近 / 中 / 远区间
零方向附近的容差区间
正方向内部的近 / 中 / 远区间
```

第一版实现可以只有粗粒度：

```text
负区间
零区间
正区间
```

后续若需要更细粒度，可以在不改变三态比较协议的前提下扩展方向区间。因为三态比较协议只规定：

```text
r < 0 / r == 0 / r > 0
```

而方向区间处理的是：

```text
在 r 的符号已确定之后，r 或差值落入哪个细分量域。
```

### 11.1 比较方向与变化方向

`允许方向` 和 `方向区间` 不应互相替代，因为二者回答的问题不同：

```text
允许方向：
    回答 比较(左值, 右值) 的符号是否被模板允许。
    例如 左值 < 右值 时，比较量 r < 0。

方向区间：
    回答右值相对左值的变化量落入哪个量域。
    例如 右值 - 左值 > 0 时，进入正向量域。
```

在状态迁移场景中：

```text
左值 = 初始值
右值 = 结果值
比较量 r = 比较(初始值, 结果值)
差值 d = 结果值 - 初始值
```

二者非零时符号相反：

```text
初始值 < 结果值：
    r < 0
    d > 0

初始值 > 结果值：
    r > 0
    d < 0
```

因此：

```text
允许方向 不能当作 方向区间。
方向区间 不能当作 允许方向。
```

`允许方向` 是模板命中约束；`方向区间` 是变化量域特征。

如果使用比较条件枚举，条件判断应基于比较量符号：

```cpp
static inline bool 比较量命中条件(std::int64_t r, 枚举_比较条件 条件) noexcept
{
    switch (条件) {
    case 枚举_比较条件::相等:
        return r == 0;
    case 枚举_比较条件::不相等:
        return r != 0;
    case 枚举_比较条件::小于:
        return r < 0;
    case 枚举_比较条件::小于等于:
        return r <= 0;
    case 枚举_比较条件::大于:
        return r > 0;
    case 枚举_比较条件::大于等于:
        return r >= 0;
    default:
        return false;
    }
}
```

如果使用方向掩码，掩码也必须由比较量符号生成：

```cpp
constexpr std::uint8_t 方向_小于0 = 1u << 0;
constexpr std::uint8_t 方向_等于0 = 1u << 1;
constexpr std::uint8_t 方向_大于0 = 1u << 2;

static inline std::uint8_t 比较量方向掩码(std::int64_t r) noexcept
{
    if (r < 0) return 方向_小于0;
    if (r > 0) return 方向_大于0;
    return 方向_等于0;
}

static inline bool 命中方向(std::int64_t r, std::uint8_t 允许方向) noexcept
{
    return (比较量方向掩码(r) & 允许方向) != 0;
}
```

于是：

```cpp
constexpr std::uint8_t 条件_小于     = 方向_小于0;
constexpr std::uint8_t 条件_等于     = 方向_等于0;
constexpr std::uint8_t 条件_大于     = 方向_大于0;
constexpr std::uint8_t 条件_不等于   = 方向_小于0 | 方向_大于0;
constexpr std::uint8_t 条件_小于等于 = 方向_小于0 | 方向_等于0;
constexpr std::uint8_t 条件_大于等于 = 方向_大于0 | 方向_等于0;
constexpr std::uint8_t 条件_任意     = 方向_小于0 | 方向_等于0 | 方向_大于0;
```

这里仍然只有三种底层状态：

```text
小于0
等于0
大于0
```

其他条件只是方向集合。

方向掩码的合法使用位置：

```text
1. 条件模板匹配：
       当前值 与 模板值 / 阈值 比较后，判断 r 是否命中允许方向。

2. 方法前置条件：
       当前输入值 与 方法要求值 比较后，判断是否允许执行。

3. 二次特征模板匹配：
       初始状态值 与 结果状态值 比较后，判断该动态方向是否命中模板方向集合。

4. 因果模板匹配：
       条件比较集合、因比较集合、果比较集合均通过方向掩码命中。

5. 查询筛选：
       节点字段 与 目标字段 比较后，通过方向掩码判断是否命中筛选条件。
```

方向掩码的禁止用途：

```text
1. 原始状态存储不得保存方向掩码。
2. 不得用方向掩码解释语义。
3. 不可比不是方向掩码，不可比应在比较前失败。
4. 不得把方向掩码当作因果作用类型或动态类型。
```

## 12. 二次特征口径

二次特征不是判断器，而是由比较生成的关系性特征。

判断只是二次特征的一种用途。二次特征本体应理解为：

```text
把两个对象、两个状态、两个特征值，
或一个动态的初始值与结果值之间的比较关系，
特征化之后形成的新特征。
```

一次特征描述某个存在本身：

```text
任务状态
资源数量
风险值
服务值
```

二次特征描述关系本身：

```text
旧任务状态 与 新任务状态 的比较关系
当前资源量 与 需求资源量 的比较关系
执行前风险值 与 执行后风险值 的比较关系
预计时间 与 计划时间 的比较关系
```

因此：

```text
三态比较器：
    产生比较量。

二次特征：
    把比较量、差值、余量、方向关系或其他关系值特征化。

方向掩码 / 标量区间：
    是二次特征模板的允许值域。

判断：
    是实例二次特征与模板二次特征匹配后的临时结果。
```

二次特征一旦沉淀为 `二次特征节点类`，就进入特征体系，具备特征的通用用途：

```text
可挂接
可索引
可进入场景关系索引
可作为方法条件
可作为方法结果
可作为因果条件
可作为因果结果
可进入概念树
可继续被比较并生成更高阶关系特征
```

二次特征的核心不应是：

```text
出现
消失
增强
减弱
转换
促进
抑制
```

而应是：

```text
左状态
右状态
比较字段
标量值 / 比较量 / 差值 / 余量
标量区间 / 允许方向 / 方向区间
度量签名
```

状态迁移二次特征的标准表达为：

```text
左状态 = 初始状态
右状态 = 结果状态
比较字段 = 特征值 / 标量值 / 时间值 / 枚举序号等
比较量 r = 比较(左状态, 右状态, 比较字段)
```

如果实现上为了索引或缓存保存比较量，必须约定：

```text
系统基础逻辑只使用 r < 0 / r = 0 / r > 0。
```

主信息收缩时，不应保存“比较器”或“比较量缓存”这类工具性字段。可以保存：

```text
左状态
右状态
比较字段
允许方向
差值
方向区间
度量签名
```

需要方向时运行：

```text
比较特征值(左状态, 右状态, 比较字段)
```

### 12.1 实例二次特征与模板二次特征

实例二次特征保存实际关系值：

```text
标量值
差值
允许方向
左对象
右对象
来源状态 / 来源动态
所属场景
```

模板二次特征保存允许值域：

```text
标量区间
允许方向
方向区间
度量签名
概念模板
```

匹配时不问“这是不是增强 / 消除 / 出现”，只问：

```text
实例标量值 是否落入 模板标量区间
实例左右值按需比较所得符号 是否命中 模板允许方向
实例方向区间 是否命中 模板方向区间
实例度量签名 是否匹配 模板度量签名
```

### 12.2 `是否满足` 的地位

`是否满足` 不应作为底层事实源头。它只能是：

```text
实例二次特征与模板二次特征匹配后的缓存结果
控制面板显示结果
过渡兼容字段
```

底层事实应来自：

```text
标量值
标量区间
允许方向
左对象 / 右对象
来源状态 / 来源动态
```

`置信度`、成功率、解释分等不属于二次特征主事实字段。若需要显示或排序，应由统计、证据或解释层临时计算，不进入 `二次特征主信息类`。

## 13. 概念树口径

概念树不存“增强 / 消除 / 出现 / 转换”等解释概念作为底层逻辑节点。

概念树可保存的基础结构是：

```text
特征值比较概念
├── 比较量 < 0
├── 比较量 = 0
└── 比较量 > 0
```

状态迁移可表达为：

```text
状态迁移比较
├── 比较(初始值, 结果值) < 0
├── 比较(初始值, 结果值) = 0
└── 比较(初始值, 结果值) > 0
```

业务语义只能绑定到这些比较结构之上作为说明，不得反过来成为底层推理依据。

例如：

```text
任务状态：比较(初始值, 结果值) < 0
风险数值：比较(初始值, 结果值) > 0
需求目标：比较(实际值, 目标值) = 0
阶段时间：比较(当前时间, 计划时间) > 0
```

系统不需要知道这叫“推进”“下降”“满足”或“超时”；系统只需要比较量符号。

---

## 14. 因果信息口径

因果信息不保存作用类型、解释类型、成功率、确定性枚举或时间窗口。

因果主信息应收束为：

```text
条件比较集合
因侧比较集合 / 因方法
果侧比较集合
动态证据
基础次数
```

标准形式：

```text
条件比较集合 + 因比较集合 / 因方法 -> 果比较集合
```

其中：

```text
条件比较：
    某些前置状态或上下文的比较量符号。

因比较：
    因侧状态变化的比较量符号。

因方法：
    明确动作来源方法。

果比较：
    果侧状态变化的比较量符号。
```

因果主信息不得保存：

```text
生成 / 消除 / 增强 / 减弱 / 转换
促进 / 抑制
满足 / 不满足
```

这些都必须从果侧比较模板临时解释。

因果关系的工程定义：

```text
因果 = 条件比较集合 + 因比较集合 / 因方法 + 果比较集合 + 次数统计 + 动态证据
```

---

## 15. 动态节点口径

动态节点可以记录：

```text
初始状态
结果状态
来源动作
输入场景
输出场景
```

但动态节点不得在底层说：

```text
出现
消除
增强
减弱
转换
成功
失败
```

动态节点只提供比较材料：

```text
左状态 = 初始状态
右状态 = 结果状态
比较字段 = 特征值
比较量 r = 比较(初始状态, 结果状态, 比较字段)
```

动作动态仍然记录方法运行造成事实变化；但事实变化方向由状态比较量符号得到，不由解释枚举得到。

---

## 16. 需求目标与任务完成判断

需求目标应仍然表达为：

```text
目标宿主.目标特征类型 -> 目标状态
```

但底层判断必须落到比较量：

```text
r = 比较(实际值, 目标值)
```

例如：

```text
目标要求：结果 >= 目标
完成判断：比较(结果值, 目标值) >= 0

目标要求：结果 = 目标
完成判断：比较(结果值, 目标值) == 0

目标要求：结果 <= 目标
完成判断：比较(结果值, 目标值) <= 0
```

“任务完成”“需求满足”不是底层比较结果，而是任务域 / 需求域根据比较量符号和满足关系作出的治理判断。

---

## 17. 结算判断口径

安全 / 服务结算不得直接使用“促进、抑制、增强、减弱”等解释词作为依据。

结算前必须能还原：

```text
目标特征类型
目标值
执行前实际值
执行后实际值
执行后实际值与目标值的比较量
执行后实际值与执行前实际值的比较量
```

其中：

```text
比较(执行后实际值, 目标值)
    决定目标是否达成或达成比例。

比较(执行后实际值, 执行前实际值)
    决定本轮是否有推进。
```

例如：

```text
结果 - 目标 >= 0
    才能判断该方向目标完成。

结果 - 之前结果 > 0
    只能说明本轮有推进，不能直接等于完成。
```

若实际实现没有直接使用差值，也必须通过比较量符号得到等价结论。

## 18. 人类解释层

系统允许在展示层、人类文档、控制面板或日志中使用解释词：

```text
出现
消除
增强
减弱
转换
满足
不满足
推进
阻塞
促进
抑制
```

但必须遵守：

```text
1. 解释词只用于阅读。
2. 解释词不得进入底层推理字段。
3. 解释词不得作为任务完成、需求满足、方法选择、因果结算的直接依据。
4. 解释词必须能追溯到具体比较对象和比较量符号。
```

也就是说：

```text
解释词 = 比较量符号的人类命名。
```

不是：

```text
比较量符号 = 解释词的实现细节。
```

---

## 19. 实现约束

后续实现应遵守：

```text
1. 新增底层逻辑时，先寻找是否能表达为有符号比较量。
2. 不新增“作用类型”“迁移类型”“促进/抑制”等底层枚举。
3. 若确需展示解释词，必须放到解释函数或展示函数中。
4. 因果主信息只存比较模板和基础次数，不存解释结论。
5. 二次特征只存可比较对象和必要比较字段，不存业务解释。
6. 任务完成、需求满足、价值结算必须先还原实际值、目标值、前值及比较量符号。
7. 比较前置条件失败不得伪装成第四种比较结果。
8. 系统基础逻辑不得依赖比较量绝对值。
```

推荐函数命名：

```cpp
std::int64_t 比较特征值(...);
std::int64_t 比较状态值(...);
std::int64_t 计算状态迁移比较量(...);
std::int8_t 比较符号(std::int64_t 比较量);
```

不推荐：

```cpp
判断是否增强(...);
判断是否消除(...);
判断是否促进(...);
判断是否满足(...);
```

若保留这些名称，也只能作为封装比较量符号组合的高层解释函数。

---

## 20. 与上级规范关系

本规范是系统最基础规范之一，编号为 `004`。

与因果、二次特征、动作动态、需求满足、任务完成、价值结算相关的下级规范如出现冲突，应按本规范修订：

```text
1. 删除底层解释枚举。
2. 将作用、方向、达成、推进等判断还原为比较量符号。
3. 将解释词移动到展示层或解释器。
4. 保留动作动态、因果模板、结算证据中的可还原事实。
```

本规范不改变动作动态必须绑定方法的硬规则，也不改变线程不是动作来源的边界。它只规定：动作造成的事实变化方向必须由特征值比较量符号得到。

---

## 21. 最终定稿

```text
所有基本逻辑都通过特征值比较得到方向。

比较函数返回有符号比较量：
    r < 0
    r = 0
    r > 0

系统基础逻辑只使用比较量的符号。

生成、消除、增强、减弱、转换、满足、不满足、促进、抑制等，
都不是底层逻辑，
只是人类阅读时对比较量符号的命名。
```

最短版：

```text
底层只比较符号，不解释概念。
```

应用时机最短版：

```text
当两个特征值需要形成关系、方向、命中、排序、动态或因果统计时应用；
当只是保存单个事实时不应用。
```
