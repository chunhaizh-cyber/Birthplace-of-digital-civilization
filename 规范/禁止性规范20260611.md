# 禁止性规范 20260611

规范编号：007

## 0. 定位

本规范是项目级禁止性上级规范，用于约束计划执行、代码修改、规范修订和回归验证。

执行任何计划前，必须先读取：

```text
规范/禁止性规范20260611.md
规范/规范目录.md
计划/计划索引.md
```

若计划、代码、详细设计、历史规范或实现注释与本规范冲突，以本规范为准；不能立即按本规范执行时，必须暂停当前步骤并说明冲突点，不得用临时兼容、错误码兜底或说明文本绕过。

## 1. 禁止保留兼容手段

代码中禁止新增、保留或扩大兼容手段，包括但不限于：

```text
1. 新旧字段双写。
2. 新旧入口并存。
3. 旧枚举 / 旧 ID / 旧状态名继续参与机器判断。
4. 兼容旧结构的兜底分支。
5. 旧返回码、旧文本、旧日志格式作为当前判断依据。
6. 为避免清理旧逻辑而新增适配层、桥接层、别名层或 fallback。
7. 在新流程旁边保留旧流程以便“过渡”。
```

允许存在的历史内容只有两类：

```text
1. 已归档文档中的历史说明。
2. 迁移前用于定位待删除对象的只读排查记录。
```

这些历史内容不得进入当前机器判断、当前计划验收、当前代码路径或当前规范依据。

发现兼容代码时，处理顺序必须是：

```text
1. 判断当前切片是否必须触碰该兼容点。
2. 若必须触碰，优先删除兼容路径并收束为唯一正式路径。
3. 若删除会影响更大范围，暂停当前切片，生成明确清理计划或请求确认。
4. 不得在兼容路径上继续加补丁。
```

## 2. 项目通用数据结构闭环

所有系统内部逻辑必须通过项目通用数据结构表达和流转。设计和实现阶段不仅要证明“有闭环”，还必须证明闭环由项目通用数据结构闭合。

允许作为业务承载的结构包括：

```text
基础信息节点类 / 基础信息节点类*
存在节点 / 场景节点 / 方法节点 / 需求节点等项目已有节点类型
特征节点类
抽象特征节点类
特征节点主信息类
抽象特征主信息类
特征值
I64
VecU句柄
VecI64 / VecIU64
指针句柄
特征值类值池
语素入口节点类作为类型 / 名称 / 抽象入口的身份标识
项目已有的枚举、状态值域、体素链、场景关系、存在关系
```

禁止用以下形式承载系统逻辑、系统状态、存在关系、特征归属、方法关系或需求关系：

```text
自由文本
字符串字段
文本标签
日志文案
注释说明
临时 JSON
自由字段
```

禁止新增以下业务承载形式：

```cpp
std::string 状态;
std::string 类型;
std::string 归属;
std::string 存在ID;
std::string 特征名;
std::vector<std::string> 状态列表;
std::map<std::string, std::string> 业务状态;
if (状态 == "已发现") { ... }
if (类型 == "存在") { ... }
```

文本只允许用于日志输出、调试说明、测试名称、用户可读错误信息、语素入口注册时的名称种子和文档说明。即使使用文本注册语素入口，也必须立即转换为项目内部身份结构；后续逻辑必须比较 `语素入口节点类*` 或通过项目已有同一性函数比较，不得继续用字符串比较。

日志输出面硬规则：

```text
运行日志、预测日志、逻辑错误排查日志、调试日志、控制台输出、UI 直接提示输出和调试器输出等所有输出，都不得进入正式机器逻辑，不得承载系统状态、存在关系、特征归属、方法关系、需求关系、因果判断或验收结论。
所有输出必须通过 `预处理开关变量.h` 的总开关和细分开关控制；总开关必须支持一键关闭，细分开关必须能分别关闭运行日志、预测日志、逻辑错误日志、逻辑错误排查日志、调试日志、控制台输出、UI 直接提示输出和调试器输出。
关闭输出只能关闭输出面，不得改变项目通用数据结构中的事实写入、错误检测、异常终止、需求 / 任务 / 方法 / 因果闭环和正式返回结构。
关闭全部输出后的验证口径是：本次运行不新增日志文件，既有日志文件不新增行、不增长；旧日志内容不得作为本次运行证据。
```

任何设计方案进入实现前，必须给出【项目结构映射表】：

```text
业务概念 -> 项目承载结构 -> 值类型 -> 写入方 -> 读取方 -> 验证方式
```

实现时必须证明：

```text
输入进入项目节点 / 特征 / 特征值结构
    -> 处理过程读取项目结构
    -> 输出写回项目节点 / 特征 / 特征值结构
    -> 后续流程继续读取这些结构
```

凡是用字符串保存状态、用日志表示状态变化、用注释描述逻辑、用临时 JSON 传递内部业务状态的实现，均判定为“文本替代实现，不合格”。只注册语素 / 状态名而没有写入读取闭环，判定为“仅定义壳”。有结构体但未挂接到存在、特征、场景、方法或需求节点，判定为“孤立实现，未接入项目结构闭环”。

没有项目结构闭环时，禁止写“已实现、已接入、已闭环、已支持、已完成”。必须改写为“仅有文本替代实现，未接入项目通用数据结构”“仅定义状态名，未形成特征写入读取闭环”或“已有孤立数据结构，未挂接到存在 / 特征 / 场景 / 方法体系”。

## 3. 本能方法必须内部逻辑闭环

所有本能方法必须在方法内部形成逻辑闭环。最低要求：

```text
1. 明确输入参数场景。
2. 明确输出结果场景。
3. 明确目标宿主。
4. 明确目标特征类型。
5. 明确当前状态 / 目标状态 / 实际结果状态。
6. 明确方法执行情况。
7. 明确失败原因、缺口类型或异常类型。
8. 明确动作动态或错误日志证据。
9. 明确后续承接入口：等待、重筹办、派生需求、学习补齐、状态提交或异常处理。
```

本能方法不得只返回错误码了事。

禁止：

```text
return 错误码;
return 本能动作错误_*;
仅写 本能动作运行结果码;
仅写 方法执行情况=执行失败;
仅写 文本说明 / 原因摘要;
由上层根据错误码猜测缺口、等待或失败原因;
```

必须：

```text
1. 把错误、缺口、等待、异常写成运行存在或输出结果场景中的特征事实。
2. 用离散语义键表达失败原因、缺口类型或异常类型。
3. 把输入 / 输出场景、目标宿主、目标特征、实际结果状态和动作动态证据串起来。
4. 只在事实闭环后返回运行存在。
```

## 4. 错误码口径

错误码不能作为闭环事实，也不能作为兼容手段保留。

错误码只允许作为：

```text
1. 调试显示值。
2. 错误日志中的辅助检索值。
3. 已被特征化事实完整覆盖后的非权威附属值。
```

任何机器判断不得只读取错误码。若某路径目前只能提供错误码，该路径视为未闭环，必须修复或暂停，不得继续执行计划。

## 5. 任务筹办 / 任务执行同步约束

任务筹办和任务执行虽然不是本能方法，但同样不得返回裸失败。

它们只能返回结构化过程回执。所有不能继续推进的信息必须先处理成特征化事实：

```text
缺口特征类型
缺口目标主体
缺口当前状态
缺口目标状态
当前方法
候选方法集
输入参数场景
输出结果场景
当前方法运行存在
需要等待 / 重筹办 / 派生需求 / 学习补齐 / 异常处理
```

裸 `失败`、`执行失败`、`筹办失败`、`上报失败`、`生成失败` 等只能作为日志显示文本，不得作为机器决策字段或返回根语义。

## 6. 计划执行前检查

每次执行计划前，必须先检查：

```text
1. 当前计划是否要求保留兼容路径。
2. 当前切片是否新增兼容层、fallback、旧字段双写或新旧入口并存。
3. 当前切片是否让本能方法只返回错误码。
4. 当前切片是否让任务筹办 / 任务执行返回裸失败。
5. 当前验证是否依赖旧兼容路径、旧返回码或旧日志文本作为通过证据。
6. 当前设计是否缺少项目结构映射表。
7. 当前切片是否用字符串、文本标签、日志、注释、临时 JSON 或自由字段承载业务状态。
8. 当前验收是否缺少项目结构承载证据。
```

任一命中时，当前计划不得直接执行，必须先修订计划或暂停确认。

## 7. 验收要求

相关切片闭合前，至少检查：

```powershell
rg -n "兼容|fallback|旧字段|旧入口|旧流程|错误码|本能动作错误_|return .*失败|执行失败|筹办失败|上报失败|生成失败" -g "*.cpp" -g "*.h" -g "*.ixx"
rg -n "std::string|const char\\*|string_view|map<.*string|string.*状态|string.*类型|string.*归属" -g "*.cpp" -g "*.h" -g "*.ixx"
rg -n "\"已发现\"|\"未发现\"|\"已归属\"|\"未归属\"|\"证据不足\"|\"冲突\"" -g "*.cpp" -g "*.h" -g "*.ixx"
```

命中结果不能直接判失败，必须逐项判断：

```text
1. 是否仍在当前机器判断路径中。
2. 是否只是归档文档或日志显示文本。
3. 是否已有特征化事实替代。
4. 是否已有项目结构承载证据。
5. 是否需要删除、改名或停用。
```

验收任何“已实现 / 已支持 / 已完成 / 已接入 / 已闭环”声明时，必须同时给出：

```text
1. 输入入口。
2. 核心处理。
3. 项目结构承载证据。
4. 输出 / 状态变化。
5. 调用路径。
6. 测试 / 验证。
```

只有当前机器路径不再依赖兼容手段、不再只靠错误码、不再返回裸失败，并且核心逻辑已通过项目通用数据结构闭合，才允许进入构建和真实运行验证。
