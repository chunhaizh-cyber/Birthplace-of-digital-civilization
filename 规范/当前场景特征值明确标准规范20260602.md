## 1. 核心定义

`当前场景特征值明确状态` 在本层只回答一个问题：

```text
当前帧中所有有效观察特征值，是否都已经能稳定对应到存在。
```

它不是：

```text
安全意义明确；
风险状态明确；
自我边界影响明确；
特征质量全部达标；
所有特征都能直接用于安全评估；
观察完成后自动满足需求。
```

本层只关注：

```text
观察特征值 -> 存在
```

不关注：

```text
存在是否危险；
存在是否靠近自我；
存在是否影响服务；
特征是否进入安全因果候选；
安全值、服务值或需求满足。
```

因此，本规范把原先过重的安全因果判定下移到后续层。当前层的正式输出应是事实：

```text
当前帧观察特征值存在对应事实。
```

## 2. 现实前提

现实世界中，每个有效观察特征值必然来自某个存在。

所以：

```text
未知区域不能作为最终归属。
```

系统内部可以临时记录：

```text
未识别；
待确认；
冲突；
证据不足；
需补观察；
需重识别。
```

但这些只是识别过程状态或缺口状态，不是最终闭合归属。

最终闭合归属只能表达为：

```text
有效观察特征值已经稳定对应到某个存在。
```

背景、地面、墙面、桌面、空气中可观测介质、无效材料承载体等，也应作为存在或材料排除事实处理；不得用“未知区域已记录”替代存在对应闭合。

## 3. 当前帧观察特征值存在对应事实

本层新增或明确的事实口径：

```text
当前帧观察特征值存在对应事实
```

最小字段：

```text
场景ID；
帧ID；
来源外设ID；
来源报告ID；
来源材料页ID；

当前帧有效特征值数量；
已稳定对应存在特征值数量；
未稳定对应存在特征值数量；
多重对应冲突特征值数量；
稳定对应存在数量；

特征值到存在映射表；
映射稳定性状态；
映射缺口原因掩码；
扫描可启动状态；
当前帧特征值存在对应闭合状态。
```

这个事实回答三件事：

```text
1. 当前帧有多少个有效特征值；
2. 这些特征值是否都能稳定对应到存在；
3. 当前帧稳定对应出了多少个存在。
```

## 4. 明确状态判定

`当前场景特征值明确状态` 可以由 `当前帧观察特征值存在对应事实` 派生，但不得直接由 D455 报告、材料页、像素簇、扫描包或跟踪包满足。

最低判定公式：

```text
当前场景特征值明确状态 = 已明确
当且仅当：

当前帧有效特征值数量 > 0
AND 已稳定对应存在特征值数量 == 当前帧有效特征值数量
AND 未稳定对应存在特征值数量 == 0
AND 多重对应冲突特征值数量 == 0
AND 稳定对应存在数量 > 0
```

如果当前帧有效特征值数量为 0，不能直接写全场景明确；只能写：

```text
当前帧无有效观察特征事实
```

后续是否构成空场景明确，必须由观察范围、观察能力和场景覆盖事实另行裁决。

## 5. 扫描可启动阈值

上级需求不需要等待全场景 100% 对应闭合后才启动扫描。

扫描可启动阈值：

```text
稳定对应存在数量 >= 1
```

也就是说：

```text
只要当前帧已有至少一个稳定对应存在，
就可以开始扫描该存在的状态、变化和动态。
```

这和 `当前场景特征值明确状态=已明确` 是两件事：

```text
扫描可启动：
    至少有一个稳定对应存在。

当前场景特征值明确：
    当前帧全部有效特征值都稳定对应存在。
```

因此不到 100% 闭合时，不能冒充全场景明确，但已经稳定对应的存在可以进入扫描和动态关注。

## 6. 识别、扫描、跟踪边界

### 识别

识别只做：

```text
把当前帧有效观察特征值稳定对应到存在；
生成当前帧观察特征值存在对应事实；
暴露未稳定对应、冲突、证据不足和需补观察缺口。
```

识别不产生被观察存在的状态和动态。

注意这里的“状态和动态”指被观察存在的业务状态、位置变化、趋势变化、遮挡、丢失等存在状态 / 存在动态；方法运行自身仍可按 001 规范留下方法动作动态作为因果账本记录，但该动作动态不得冒充被观察存在的状态或动态。

识别输出不是：

```text
存在当前状态；
存在变化动态；
安全因果候选；
风险状态明确；
需求满足。
```

识别输出是：

```text
当前帧观察特征值存在对应事实。
```

### 扫描

扫描从稳定对应存在开始。

扫描负责：

```text
读取已稳定对应存在；
检查是否已有上一帧或历史可比状态；
首次扫描生成发现动态；
后续扫描生成该存在的当前状态、特征变化和变化动态；
输出需重识别或未稳定对应缺口。
```

扫描产生：

```text
首次扫描：
    发现动态；
    当前状态快照；

后续扫描：
    存在当前特征状态；
    存在特征变化动态；
    位置 / 范围 / 深度 / 遮挡 / 丢失 / 稳定性变化事实。
```

第一次扫描不得因为缺少历史基准而伪造变化动态。它只能说明：

```text
在当前帧首次发现一个已经稳定对应的存在。
```

只有存在上一帧、上一轮或其他可比历史状态时，才允许生成变化动态。

扫描不负责：

```text
确认新存在；
把未稳定特征强行归属；
证明全场景明确。
```

### 跟踪

跟踪从指定稳定存在或目标种子开始。

跟踪负责：

```text
持续观察指定存在；
输出目标当前状态、目标变化动态、连续性、遮挡、丢失和趋势。
```

跟踪不负责：

```text
非目标存在；
全场景扫描；
全场景特征值明确。
```

## 7. 三类外设提交包

D455 外设线程只供材料和提交包，不写自我账本。

```text
识别提交包：
    提供当前帧有效特征值、候选映射、冲突和缺口材料；
    供自我生成当前帧观察特征值存在对应事实。

扫描提交包：
    针对已稳定对应存在，提供当前特征、首次发现、后续变化、遮挡、丢失和需重识别材料；
    供提交入口写发现动态或变化动态。

跟踪提交包：
    针对指定稳定存在，提供连续特征、趋势、遮挡和丢失材料；
    供提交入口写目标状态和目标变化动态。
```

外设提交包都不是账本提交入口。

## 8. 自我本能方法与提交入口

第一版链路：

```text
外设识别提交包
-> 自我_识别外设观察材料
-> 当前帧观察特征值存在对应事实
-> 当前场景特征值明确状态 / 扫描可启动状态

外设扫描提交包
-> 自我_扫描已识别区域
-> 扫描结果场景
-> 提交_观察存在发现事实 / 提交_观察存在特征值变化事实
-> 发现动态或变化动态可读

外设跟踪提交包
-> 自我_跟踪指定存在
-> 跟踪结果场景
-> 提交_指定存在跟踪事实
-> 目标状态和目标变化动态可读
```

应补或明确的提交入口：

```text
提交_当前帧观察特征值存在对应事实
提交_观察存在发现事实
```

该入口消费识别组织结果，写入：

```text
当前帧有效特征值数量；
已稳定对应存在特征值数量；
未稳定对应存在特征值数量；
多重对应冲突特征值数量；
稳定对应存在数量；
特征值到存在映射表；
当前帧特征值存在对应闭合状态；
扫描可启动状态。
```

`提交_观察存在发现事实` 消费第一次扫描结果，写入：

```text
目标存在；
当前帧ID；
当前状态快照；
发现动态；
发现来源扫描结果；
发现时间；
来源动作动态。
```

`提交_观察存在发现事实` 不得写成变化动态。只有存在上一帧、上一轮或其他可比历史状态时，才可转入 `提交_观察存在特征值变化事实`。

`提交_当前帧观察特征值存在对应事实` 不得写：

```text
存在状态；
存在动态；
```

上述两个入口均不得写：

```text
安全值；
服务值；
需求满足；
风险状态明确。
```

## 9. 与安全因果链的关系

安全因果链可以反推出 `当前场景特征值明确状态` 这个需求，但本层的满足标准不是安全意义明确，而是特征值到存在的稳定对应事实闭合。

后续安全评估如果需要自我边界、距离、靠近、遮挡、趋势等信息，应继续读取：

```text
扫描产生的存在状态和变化动态；
跟踪产生的目标状态和目标变化动态；
自我边界参照；
坐标转换；
安全因果模板。
```

这些是下游安全解释层，不得塞回本层作为 `当前场景特征值明确状态` 的最低标准。

## 10. 标准子需求生长链

第一版标准子链应调整为：

```text
当前场景特征值明确状态
└── OR组满足状态：特征值存在对应取得路径
    └── D455观察确认路径：方法路径完成状态
        ├── 材料型子需求
        │   ├── 当前观察特征帧取得状态
        │   └── 外设观察材料可回查状态
        ├── 对应事实型子需求
        │   ├── 当前帧有效特征值计数事实取得状态
        │   ├── 当前帧特征值存在稳定对应事实取得状态
        │   ├── 稳定对应存在数量明确状态
        │   ├── 当前帧特征值存在对应闭合状态
        │   └── 扫描可启动状态
        ├── 扫描型子需求
        │   ├── 当前帧稳定对应存在扫描状态
        │   ├── 首次发现动态生成状态
        │   ├── 观察存在发现事实提交状态
        │   ├── 已知存在当前状态取得状态
        │   ├── 已知存在变化动态生成状态
        │   └── 观察存在特征值变化事实提交状态
        ├── 跟踪型子需求
        │   ├── 指定存在跟踪状态
        │   ├── 指定存在状态变化明确状态
        │   └── 指定存在跟踪事实提交状态
        └── 缺口解释子需求
            └── 当前帧特征值存在对应缺口可解释状态
```

生成规则：

```text
1. 当前场景特征值明确状态只负责触发标准子链，不直接生成外设等待项。
2. OR组负责表达多种取得路径，不直接写明确状态。
3. D455观察确认路径不能停成空叶子；路径激活后必须继续生成材料型、对应事实型、扫描型、跟踪型或缺口解释子需求。
4. 对应事实型子需求先于扫描型子需求。
5. 稳定对应存在数量 >= 1 时，可以生成或激活扫描型子需求。
6. 当前帧全部有效特征值稳定对应存在时，才可写当前场景特征值明确状态。
7. 跟踪型子需求只有在有目标种子或指定稳定存在时激活。
8. 扫描型子需求必须区分首次扫描和后续扫描：首次扫描生成发现动态，后续有可比历史后才生成变化动态。
9. 任务管理线程只能按结构化目标特征和已入树子需求生成等待项，不得从目标特征文本猜测。
```

## 11. 生产者边界

```text
D455外设线程：
    只生产观察报告、材料页、句柄和识别 / 扫描 / 跟踪提交包。

自我识别方法：
    只生成当前帧观察特征值存在对应事实；
    不生成被观察存在状态或动态。

扫描 / 跟踪方法：
    在已有稳定对应存在基础上，生成状态、变化和动态。

提交入口：
    裁决并写入对应事实、扫描变化事实和跟踪事实。

安全 / 服务评估方法：
    只读取已提交事实和后续状态 / 动态；
    不把识别结果直接当安全意义。

自我线程：
    可以根据事实变化派生需求和重筹办；
    不裸写当前场景特征值明确状态。
```

## 12. 禁止规则

```text
1. 不得把 D455 报告、像素簇、材料页直接等同于当前场景特征值明确。
2. 不得把未知区域作为最终归属类型。
3. 不得让识别产生被观察存在状态或动态。
4. 不得把扫描可启动等同于全场景明确。
5. 不得把已稳定对应的一个存在扩大解释为全部特征值已稳定对应。
6. 不得把扫描或跟踪结果反推成识别已闭合。
7. 不得把安全因果、自我边界、风险评估塞回本层作为最低标准。
8. 不得由任务管理线程按目标文本或路径名称猜测外设等待项。
9. 不得把外设提交包当作自我内部账本提交入口。
10. 不得写需求满足、安全值、服务值或风险状态明确。
```

一句话版：

```text
当前场景特征值明确，不是“特征有安全意义”，而是“当前帧有效特征值都已经稳定对应到存在”；识别只产出对应事实，扫描和跟踪才产出状态与动态。
```
