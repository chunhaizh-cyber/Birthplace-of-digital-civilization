## 1. 核心定义

`当前场景特征值明确状态` 不得定义为“已经有任意特征值”，也不得由 D455 报告、像素簇候选或材料页直接满足。

它应定义为：

```text
某个指定范围内，当前安全评估所需的、由外设或场景事实可提供的关键特征值，
已经对该范围内的已确认存在形成可追溯、可比较、可解释缺口的读取结果。
```

它不是：

```text
有 D455 报告；
有像素簇；
有任意特征值；
有逐簇识别结果；
有跨帧簇 ID。
```

它要求：

```text
当前安全评估需要的那些特征值已经足够读出来；
这些值来自哪里、是否过期、是否可比较、是否能映射到自我边界，都可追溯。
判定必须携带或隐含明确范围，不能把局部明确写成全场景明确。
```

因此，标准必须从两个源头共同生成：

```text
1. 外设实际能提供哪些特征类型；
2. 这些特征类型中，哪些能进入自我安全因果链。
```

并按四层转换：

```text
外设可产出的原始观察特征
-> 自我可解释的场景事实特征
-> 自我相对特征
-> 安全因果候选
```

本规范的基础原则：

```text
特征本身没有语言意义；
特征只有被组织到存在、区域、场景、任务输入、因果链之后，才成为自我可利用的信息。
```

因此实现上必须避免：

```text
外设给了一个特征值
-> 自我直接认为它有安全意义 / 服务意义
```

正确链路应为：

```text
外设材料
-> 外设加工成识别 / 扫描 / 跟踪提交包
-> 自我外设本能方法组织这些包
-> 形成候选事实 / 特征值视图 / 缺口说明
-> 提交入口正式入账
-> 因果链解释这些特征值对自我的意义
```

## 2. D455 可产出的原始观察特征

D455 作为感知外设，只能直接提供观察材料和观察候选，不能直接确认真实对象，也不能直接写安全值、服务值或当前场景明确结论。

第一版可用原始特征类型包括：

```text
观察来源：
    来源外设、报告ID、等待项ID、报告类型、采集成功状态、失败原因、短期材料页、d455://句柄。

观察时间：
    外设时间戳、系统承接时间、帧号、观察年龄、最大允许报告年龄。

帧材料：
    彩色帧、深度帧、对齐帧、帧宽高、深度帧号、彩色帧号、原始帧句柄、深度帧句柄、彩色帧句柄、对齐帧句柄。

相机参照：
    相机内参、相机外参、坐标转换信息、坐标系版本。

像素与材料回查：
    像素数量、ROI、掩码、像素集合掩码、点集、深度切片、空间候选句柄、像素归属账本、像素归属验证材料句柄。

深度与空间：
    深度有效率、空间坐标有效率、中心空间坐标、空间范围AABB、范围内点比例、深度一致率。

轮廓与边界：
    彩色轮廓、深度轮廓、空间投影轮廓、融合轮廓、轮廓闭合率、轮廓置信度、低置信轮廓、未解释区域。

跨帧与变化：
    跨帧簇ID、跨帧匹配状态、连续命中次数、丢失次数、复现离散度、新增/消失/变化像素簇数量。

质量与稳定：
    帧质量评分、空间连续性评分、范围稳定性评分、深度稳定性、低质量区域、不可观测区域。
```

这些特征只说明“外设看到了什么、材料能不能回查、质量如何”，不等同于“当前场景特征值明确”。

## 3. 场景存在特征值

场景存在特征值是从外设材料中提取并挂到具体场景存在上的可读特征值。它回答：

```text
当前场景中这个已确认存在，有哪些可读的观察特征值？
```

第一版包含：

```text
当前场景关系：
    存在是否在当前场景中、当前帧观察时间、出现 / 消失状态。

来源追溯：
    来源报告ID、来源帧ID、来源簇ID、来源ROI、来源掩码、来源点集、来源深度切片。

材料与归属：
    像素归属验证状态、像素归属账本、ROI / 掩码 / 点集可回查状态。

空间特征：
    2D轮廓 / ROI、3D中心点、3D空间范围 / AABB、深度范围。

质量特征：
    深度有效率、空间坐标有效率、深度稳定性、空间连续性、范围稳定性。

跨帧特征：
    跨帧匹配状态、跨帧稳定性、跨帧丢失状态、可比历史状态。
```

这一层仍不直接说明安全。它只说明某个已确认存在有哪些场景事实可读。

## 4. 对自我真正有影响的特征

外设原始特征进入自我后，只有被转换为下列影响特征时，才参与 `当前场景特征值明确状态` 的判定。

```text
空间影响：
    存在或区域相对自我的距离、方向、接近/远离趋势、进入边界、接触边界、遮挡边界。

范围影响：
    存在或区域的空间范围、边界稳定性、是否覆盖自我活动范围或目标服务范围。

变化影响：
    新增、消失、移动、靠近、远离、持续稳定、连续丢失、突发高风险未知区域。

可作用影响：
    是否可能作用到自我关键特征，或是否处在自我可作用、可避让、可服务的空间关系中。

置信影响：
    观察质量、材料可回查状态、跨帧稳定性、轮廓/深度/空间一致性是否足够支持判断。

缺口影响：
    哪些原始特征缺失、过期、冲突或不可观测；这些缺口是否需要补观察、换姿态、持续跟踪或请求交互者说明。

观察影响：
    是否遮挡关键观察区域、是否造成未解释区域增加、是否造成观察质量下降。

归因影响：
    是否与自我关键特征负向变化存在时间关系。
```

不影响自我的特征可以记录，但不得单独推动安全因果链入账。影响未知时应进入“证据不足”或“部分明确”，不得默认安全、默认服务可用或默认需求满足。

注意：

```text
RGB局部图本身不是安全影响特征；
深度值本身也不是安全影响特征。

它们必须进一步转换为：
    轮廓 / 分类 / 匹配材料；
    空间距离 / 空间范围；
    相对自我边界距离；
    靠近 / 远离 / 进入缓冲区；
才可能进入安全因果候选。
```

## 5. 明确状态判定

`当前场景特征值明确状态(范围) == 已明确` 的最低标准：

```text
0. 判定范围必须明确：
       范围可以是全场景、已识别区域、指定区域、指定存在或跟踪目标；
       不得把已识别区域、指定 ROI 或跟踪目标的明确结果提升为全场景明确。

1. 评估对象必须是已确认存在：
       进入该范围评估的对象必须是已通过提交入口写入当前场景的已确认存在；
       不得使用外设簇候选、未验证像素簇、跨帧簇ID、冲突候选或证据不足候选替代。

2. 特征值必须有可追溯来源：
       每个用于安全评估的特征值，必须能追到来源外设报告、来源帧、来源ROI/掩码/点集/深度切片、
       来源像素归属账本、来源对象作用方法动态、来源提交入口动态或来源场景。

3. 特征值必须可比较：
       必须具备单位、坐标系、时间戳、比较方式、有效范围和置信度；
       D455空间值必须能从相机坐标转换到当前场景坐标或自我边界参照坐标。

4. 特征值必须满足质量门槛：
       深度有效率、空间坐标有效率、点云有效像素数量、深度稳定性、深度邻域一致性、
       像素归属账本闭合状态、ROI/掩码冲突状态、材料TTL、generation匹配等必须满足当前用途。

5. 特征值必须覆盖当前安全评估需要的最小特征集：
       当前场景特征值明确不是全场景全特征完备；
       而是当前激活安全因果模板在指定范围内所需最小特征集明确。

6. 未解决冲突、材料过期和关键缺失必须为零：
       若存在未确认候选、冲突区域、过期材料、不可解引用句柄、缺坐标转换、缺自我边界参照等关键缺口，
       当前场景特征值明确状态不得为已明确。
```

未满足全部最低标准时，不得写 `当前场景特征值明确状态(该范围)=已明确`。

范围化口径：

```text
当前场景特征值明确状态(已识别区域) = 已明确
不推出：
当前场景特征值明确状态(全场景) = 已明确

当前场景特征值明确状态(目标存在A) = 已明确
不推出：
当前场景扫描完成 或 当前场景存在集合全域明确
```

因此，后续所有 `当前场景特征值明确状态`、`当前场景存在集合明确状态`、`当前场景风险状态明确状态` 的使用，都必须能回查其作用范围。

## 6. 最小特征集

第一版最小特征集由当前激活的安全因果模板决定，不是固定全量清单。

默认空间安全评估至少需要：

```text
对指定范围内每个当前场景已确认存在：

1. 当前在场状态；
2. 来源观察材料；
3. ROI / 掩码 / 点集之一，且能对应像素归属；
4. 空间中心或空间范围；
5. 深度 / 空间质量依据；
6. 相对自我边界的位置或距离；
7. 当前观察时间；
8. 若需要趋势判断，则有上一帧或历史可比状态；
9. 若存在冲突、缺失或过期，原因明确记录。
```

如果安全评估需要靠近趋势，必须有跨帧可比状态。

如果安全评估只需要当前是否进入边界，可以不要求趋势，但仍必须满足当前空间值、坐标转换和自我边界参照。

## 7. 明确状态与缺口可解释状态

`当前场景特征值明确状态` 和 `当前场景特征值缺口可解释状态` 必须分开。

```text
当前场景特征值明确状态(范围)：
    回答该范围内安全评估所需的特征值是否已经达到可评估标准。

当前场景特征值缺口可解释状态(范围)：
    回答该范围未明确时，缺失、过期、冲突或证据不足原因是否能列出并转成后续补观察 / 补解释需求。
```

不明确并不可怕，不知道为什么不明确才可怕。

如果只满足“缺失原因可记录”，只能得到：

```text
当前场景特征值缺口可解释状态(范围) = 是
```

不能得到：

```text
当前场景特征值明确状态(该范围) = 已明确
```

## 8. 分级口径

当前建议分级：

```text
未明确：
    没有当前场景存在集合，或没有任何可用观察来源。

证据不足：
    有观察材料或候选，但缺已确认存在、缺时间、缺空间、缺质量或缺自我参照，无法判断影响。

部分明确：
    至少一部分已确认存在具备可读影响特征，但仍有影响候选缺材料、过期、冲突或不可观测。

已明确：
    所有进入当前评估候选的存在 / 区域 / 变化都满足最低标准；
    未进入候选的区域也有明确排除理由或补观察需求。
```

`当前场景各存在特征值可读状态` 可以作为材料门分级，但它不是全部标准。它必须继续接到自我边界、影响关系和缺口派生链。

建议扩展 `当前场景各存在特征值可读状态` 的状态口径：

```text
未可读；
部分可读；
可读；
证据不足；
冲突；
过期。
```

但即使 `当前场景各存在特征值可读状态=可读`，也不等于 `当前场景特征值明确状态(范围)=已明确`。

例如：

```text
ROI、掩码、点集都可读；
但无法转成自我边界坐标；
则各存在特征值可读可以是部分可读或可读，
但当前场景特征值仍未明确。
```

## 9. 外设特征类型与安全影响关系

| D455 / 外设可提供特征 | 原始用途 | 转换后的安全相关特征 | 是否直接进入安全因果候选 |
| --- | --- | --- | --- |
| 彩色帧 | 材料 | 辅助轮廓 / 分类 / 匹配 | 否 |
| 深度帧 | 材料 | 空间距离 / 深度范围 | 间接 |
| 对齐帧 | 材料 | RGB 与深度对应 | 间接 |
| ROI | 局部区域 | 存在 2D 范围 | 间接 |
| 掩码 | 像素归属 | 存在边界 / 遮挡判断 | 间接 |
| 点集 | 空间材料 | 空间范围 / AABB / 中心 | 间接 |
| 像素归属账本 | 归属验证 | 已确认存在边界可信度 | 间接 |
| 深度有效率 | 质量 | 空间判断置信度 | 间接 |
| 空间坐标有效率 | 质量 | 空间范围可信度 | 间接 |
| 跨帧匹配 | 连续性 | 靠近 / 远离 / 稳定性 | 间接 |
| 未解释区域比例 | 缺口 | 未知影响候选 | 间接 |
| 相机到自我坐标转换 | 参照 | 相对自我边界距离 | 必要中介 |
| 自我边界距离 | 派生特征 | 进入 / 接触 / 靠近候选 | 是 |
| 遮挡关键观察区域 | 派生特征 | 感知可用性影响候选 | 是 |
| 自我关键特征负向变化 | 自我侧特征 | 影响候选归因依据 | 是 |

这里的“直接进入安全因果候选”不表示可以直接结算自我安全值。

## 10. 第一版判定算法

```text
输入：
    当前安全评估目标；
    判定范围；
    当前场景；
    指定范围内当前场景已确认存在集合；
    D455 材料视图；
    自我边界参照；
    安全因果模板。

步骤：
    1. 根据当前安全评估目标，读取需要的特征类型集合。
    2. 读取判定范围和该范围内当前场景已确认存在集合。
    3. 对该范围内每个已确认存在读取外设材料：ROI、掩码、点集、深度切片、像素归属账本、来源报告、时间戳。
    4. 检查材料有效性：是否过期、generation是否匹配、是否可解引用、质量是否达标。
    5. 从材料生成场景存在特征值：2D范围、3D中心、AABB、深度范围、空间范围、跨帧状态。
    6. 转换成自我相关特征值：相对自我边界距离、是否进入缓冲区、是否接触候选、是否靠近、是否遮挡关键区域。
    7. 检查每个必需特征是否可比较：坐标系、单位、时间戳、比较规则、置信度。
    8. 汇总明确状态和缺口可解释状态。
```

判定公式：

```text
当前场景特征值明确(范围) =
判定范围明确
AND 指定范围内当前场景已确认存在集合可读
AND 当前安全评估所需特征类型集合已知
AND 对指定范围内每个已确认存在，每个必需特征都有可追溯值或明确不适用原因
AND 所有参与比较的特征值可比较
AND 所有空间特征可转换到自我边界参照
AND 质量指标达标
AND 未解决冲突数量 = 0
AND 材料过期数量 = 0
AND 关键缺失原因数量 = 0
```

## 11. 空场景明确口径

空集合可以在指定范围内明确，未知集合不能明确。

如果指定观察范围已处理、像素归属账本闭合、未知区域已记录，并且没有已确认存在：

```text
当前场景已确认存在集合 = 空
```

可以判定为明确。

条件是：

```text
观察区域闭合；
候选处理完毕；
冲突为 0；
未知区域已记录；
材料有效。
```

这可以避免系统永远因为“没有看到对象”而不明确。

## 12. 与默认风险满足的关系

`当前场景特征值明确状态` 不是风险因素默认满足。

```text
当前场景特征值明确
-> 可以进行风险证据搜索 / 安全评估
```

不推出：

```text
当前场景特征值明确
-> 风险安全
```

风险因素默认满足必须另行满足：

```text
按该风险因素的证据搜索规则查过；
材料完整；
未发现负向证据；
无冲突；
无证据不足。
```

## 13. 三种外设提交包与自我组织入口

外设提交包和提交入口必须区分：

```text
外设提交包 =
    外设向自我提交的一份材料包 / 特征包。

提交入口 =
    自我内部正式改写账本的入口。
```

禁止等同关系：

```text
外设识别提交包 != 已确认观察存在
外设扫描提交包 != 当前场景风险明确
外设跟踪提交包 != 指定目标需求已满足
```

### 13.1 通用外设提交包头

三类外设提交包必须有统一包头。包头至少说明：

```text
包ID；
报告ID；
帧ID；
场景ID；
包类型：识别 / 扫描 / 跟踪；
触发来源：默认维护 / 需求等待项 / 指定目标跟踪 / 诊断入口；
采集时间；
提交时间；
外设ID；
材料页ID；
坐标系ID；
标定版本；
generation；
有效截止时间；
材料句柄集；
缺失材料；
质量问题。
```

包头必须能回答：

```text
这个包来自哪里；
它基于哪一帧；
材料是否可回查；
使用哪个坐标系；
是否已经过期；
是否来自真实需求等待项。
```

### 13.2 通用外设特征值条目

因为特征本身没有语言意义，外设特征值条目不得只保存自然语言名。每个条目至少包含：

```text
特征类型ID；
特征值形态；
值；
宿主局部ID：区域ID / 候选ID / 簇ID / 目标ID / 存在ID；
坐标系ID；
单位；
时间戳；
置信度；
质量分；
来源材料；
来源动态；
可比较状态；
比较器ID；
不可比较原因。
```

注意：

```text
特征类型ID 不是意义本身；
它只有在被抽象特征定义、因果模板、需求目标读取之后，才有系统意义。
```

### 13.3 三类外设提交包

场景不需要全部识别后才能扫描。识别、扫描、跟踪不是按“整场景阶段”串行排队，而是按当前帧材料的区域归属状态并行分工。

当前帧材料应先被划分为：

```text
已识别区域：
    已归属到已确认存在或已确认背景结构。

未识别区域：
    有有效观察材料，但尚未归属到存在、背景、冲突或无效。

候选区域：
    已生成存在候选，但尚未确认 / 合并 / 冲突裁决。

冲突区域：
    多个存在或候选争用同一区域，归属不唯一。

无效区域：
    深度无效、材料缺失、不可解引用或质量不足。

背景区域：
    已判定为稳定背景、场景结构或不参与当前存在集合的区域。
```

分工规则：

```text
已识别区域 -> 扫描
未识别区域 -> 识别
候选区域 / 冲突区域 -> 识别或自我侧验证裁决
指定目标所在已识别区域 -> 跟踪
无效区域 -> 记录无效原因或派生补观察需求
背景区域 -> 可参与遮挡 / 可通行 / 观察质量等影响判断，但不得当作已确认存在
```

### 识别：处理未识别区域

适用目标：

```text
处理未识别区域、候选区域和冲突区域，
让有效观察材料建立归属结果。
```

识别回答：

```text
这些未归属像素 / 点集 / ROI / 掩码 / 簇应归到谁？
哪些是新存在候选？
哪些可能匹配已有存在？
哪些是背景候选？
哪些存在冲突？
哪些证据不足？
```

识别输出：

```text
新存在候选；
已有存在匹配候选；
背景候选；
冲突原因；
证据不足原因；
需要确认的候选；
未知区域记录；
无效材料排除原因。
```

识别完成后不得直接写 `已确认观察存在`，仍必须走：

```text
验证候选
-> 确认候选
-> 提交_确认观察存在事实
```

识别适合支撑：

```text
当前帧未识别区域识别状态；
当前帧区域归属状态；
当前观察材料归属闭合状态；
未知区域记录状态；
冲突区域处理状态；
已确认观察存在取得状态。
```

### 扫描：处理已识别区域

适用目标：

```text
处理已识别区域、已确认存在和已确认背景结构，
发现已知存在的特征值变化和未解释变化。
```

扫描回答：

```text
已知存在的位置变了吗？
范围变了吗？
深度变了吗？
距离变了吗？
遮挡状态变了吗？
像素归属变了吗？
是否出现未解释变化？
是否产生需重识别区域？
```

扫描的前提不是全场景已识别，而是：

```text
存在可扫描的已识别区域；
该区域内有已确认存在或已确认背景结构；
有上一帧 / 上一轮可比状态。
```

扫描输出：

```text
已知存在当前特征值；
已知存在特征值变化；
位置变化；
空间范围变化；
深度变化；
遮挡变化；
丢失状态；
稳定性变化；
未解释变化区域；
需要重识别区域。
```

扫描适合支撑：

```text
当前帧已识别区域扫描状态；
已识别区域特征值明确状态；
当前场景已知存在特征变化明确状态；
自我关键特征变化关联候选；
安全因果候选构造；
当前场景特征值变化可比状态。
```

扫描发现无法继续归属、新区域出现或未解释变化过大时，只能输出 `未识别区域 / 需重识别区域`，交给识别处理；不得由扫描直接确认新存在。

### 跟踪：处理指定目标存在

适用目标：

```text
对指定已确认存在进行持续观察，
只维护目标存在的特征值和变化，
主动忽略非目标存在。
```

跟踪回答：

```text
目标还在吗？
目标在哪里？
目标是否靠近 / 远离？
目标是否被遮挡？
目标是否丢失？
目标的目标特征是否变化？
```

第一版跟踪目标只允许来自已确认存在；候选目标跟踪可以作为后续扩展，但不得把未确认候选的跟踪成功当成已确认观察存在。

跟踪必须有：

```text
目标存在ID；
目标种子；
目标上一轮 ROI / 掩码 / 点集 / 空间位置；
当前帧材料；
目标特征定义；
跟踪时间窗口。
```

跟踪输出：

```text
目标当前特征值；
目标位置变化；
目标距离变化；
目标稳定性；
目标遮挡状态；
目标丢失状态；
目标靠近 / 远离趋势。
```

跟踪适合支撑：

```text
指定存在跟踪状态；
指定存在特征值变化明确状态；
目标存在靠近趋势明确状态；
目标存在遮挡状态明确状态。
```

跟踪不能被当成全场扫描。它只能证明指定目标存在的特征值变化明确，不能证明当前场景存在集合明确、全场景扫描完成或全场风险状态明确。

### 13.4 三个自我外设本能方法

三类外设提交包分别由三个自我外设本能方法组织：

```text
外设识别提交包
-> 自我_识别外设观察材料
-> 识别结果场景

外设扫描提交包
-> 自我_扫描已识别区域
-> 扫描结果场景

外设跟踪提交包
-> 自我_跟踪指定存在
-> 跟踪结果场景
```

这三个本能方法负责：

```text
读取外设提交包；
检查材料是否可追溯、可比较、未过期；
把外设特征组织成自我可用的候选事实；
生成输出结果场景；
产生对象作用方法动态。
```

这三个本能方法不得直接：

```text
写安全值；
写服务值；
写需求满足；
写当前场景存在集合明确；
结算价值。
```

### 13.5 三个正式提交入口

正式事实写入由提交入口完成：

```text
提交_确认观察存在事实：
    用于识别链后段；
    写入已确认观察存在、存在与当前场景关系、来源材料、观察动态、二次特征和场景索引。

提交_观察存在特征值变化事实：
    用于扫描链后段；
    写入存在当前特征状态、存在特征变化动态、已识别区域扫描状态和需重识别区域记录。

提交_指定存在跟踪事实：
    用于跟踪链后段；
    写入目标存在跟踪状态、目标存在特征变化动态、目标观察窗口状态、遮挡 / 丢失 / 稳定性状态。
```

三类链路关系：

```text
外设识别提交包
-> 自我_识别外设观察材料
-> 识别结果场景
-> 自我_确认外设观察存在候选
-> 提交_确认观察存在事实

外设扫描提交包
-> 自我_扫描已识别区域
-> 扫描结果场景
-> 提交_观察存在特征值变化事实
-> 安全 / 服务因果候选可读取

外设跟踪提交包
-> 自我_跟踪指定存在
-> 跟踪结果场景
-> 提交_指定存在跟踪事实
-> 目标存在特征变化可读取
```

一句话：

```text
外设提交包 = 供料；
自我本能方法 = 组织；
自我提交入口 = 入账；
因果链 = 解释。
```

三者关系：

```text
识别处理未识别区域，补区域归属空白；
扫描处理已识别区域，更新已知存在变化；
跟踪处理指定目标，忽略非目标存在。
```

同一帧可以同时发生：

```text
扫描：
    更新已识别区域中已知存在的特征值变化。

识别：
    处理未识别区域和扫描产生的未解释区域。

跟踪：
    对指定目标存在做高频持续观察。
```

对 `当前场景特征值明确状态(范围)` 的影响：

```text
识别提供：
    区域归属账本、未识别区域处理结果、候选 / 冲突 / 背景 / 无效区域记录。

扫描提供：
    已识别区域中已知存在的当前特征值、变化方向、变化时间、变化置信度、未解释变化。

跟踪提供：
    指定存在的连续特征值、趋势、遮挡 / 丢失 / 靠近状态。
```

第一版判定可写成：

```text
指定范围内，当前安全评估所需的场景存在已经完成识别归属；
该范围内已确认存在的必要特征值已经可读；
如果评估需要变化量，则扫描或跟踪提供了可比变化；
所有未知、冲突、证据不足和过期材料都有明确原因。
```

## 14. 生产者边界

```text
D455外设线程：
    只生产观察报告、材料页、句柄、区域归属摘要、像素簇摘要、扫描变化摘要、跟踪摘要，
    并可组织成识别 / 扫描 / 跟踪三类外设提交包。

任务管理线程：
    可按正式需求目标生成外设观察等待项，承接外设报告并生成上行消息；
    不直接写当前场景特征值明确状态，也不得把局部报告升级成全场景明确。

自我外设本能方法：
    消费三类外设提交包，检查材料和可比较性，组织候选事实 / 特征值视图 / 缺口说明，
    输出结果场景和对象作用方法动态；
    不直接写安全值、服务值、需求满足或当前场景存在集合明确。

自我观察承接 / 提交入口：
    验证候选、确认候选、提交已确认观察存在事实，
    并承接扫描变化事实、指定存在跟踪事实等正式入账。

安全 / 服务评估方法：
    只读取已提交入账的存在事实、扫描变化事实、跟踪事实、材料门、自我边界和影响特征；
    只在指定范围最低标准满足后，才可输出该范围的“明确”或相应候选视图。

自我线程：
    根据事实变化重新裁决需求、重筹办根需求或派生补观察 / 补解释需求；
    不用风险树维护直接裸写明确状态。
```

## 15. 对实现的直接约束

```text
1. 不得把 `当前场景特征值明确状态` 直接等同于 D455 报告产生。
2. 不得把观察像素簇候选直接等同于稳定真实对象。
3. 不得把当前场景存在数量大于 0 直接等同于特征值明确。
4. 不得把外设材料可回查直接等同于安全影响可评估。
5. 不得把未知、低质量、不可观测、过期或冲突材料当作默认安全证据。
6. 等待项生成可以由材料型子需求触发，但总目标必须优先展开为材料、确认、影响和缺口解释子目标。
7. 不得把相机坐标中的 XYZ 直接当作自我安全因果里的空间特征值明确。
8. 缺口可解释不得被当作特征值明确。
9. 不得把已识别区域扫描成功写成全场景特征值明确。
10. 不得把指定目标跟踪明确写成当前场景存在集合明确或全场风险状态明确。
11. 扫描发现未解释区域时，应输出需重识别区域，不得直接确认新存在。
12. 不得把外设提交包当作自我内部账本提交入口。
13. 不得让特征值脱离区域 / 存在 / 场景 / 任务输入 / 因果模板直接进入安全值或服务值。
14. 不得在自我线程过程代码里硬编码识别 / 扫描 / 跟踪 / 确认子需求定义；子需求必须来自结构化特征、提交包、方法能力和需求树更新规则。
```

后续实现应优先让 `当前场景特征值明确状态` 展开为可执行的标准子链，而不是把该总目标直接映射到某个外设运行模式。

一句话版：

```text
当前场景特征值明确，不是“有值”，而是“指定范围内安全评估需要的那些值已经能被自我拿来比较、解释和追溯”。
```
