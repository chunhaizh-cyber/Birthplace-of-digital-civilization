# 规范状态管理

## 0. 定位

权威等级：治理规则。它不改变 `规范/规范目录.md` 的正式优先级，只规定如何标注和追踪规范状态。

## 1. 状态枚举

| 状态 | 含义 | 是否可作为核心代码依据 |
| --- | --- | --- |
| 生效 | 已进入规范目录，当前无待修订标记 | 可以 |
| 草案 | 尚未定稿或仍需实装验证 | 不得单独作为核心代码依据 |
| 待修订 | 已知与上级规范或当前代码口径不一致 | 不得作为新增实现依据 |
| 已废止 | 已被新规范替代 | 不得作为当前依据 |
| 历史参考 | 仅保留索引或考古价值 | 不得作为当前依据 |
| 参考说明 | 总结、`规范/详细设计/`、说明材料 | 只能辅助理解 |

## 2. 文件头模板

```text

不适用范围：
相关工程图谱：
相关代码：
相关测试：
最后修订：
修订原因：
```

## 3. 状态迁移

```text
草案 -> 生效：
    必须进入规范目录；
    必须说明上级规范；
    必须检查下级规范；
    必须建立至少人工审查级验证。

生效 -> 待修订：
    上级规范变化、代码口径变化或规则冲突时标记；
    规范变更时必须同步检查 `规范/详细设计/` 中派生设计是否需要改判。

待修订 -> 生效：
    冲突修复、目录更新、图谱和规则原子同步后恢复。

任意状态 -> 已废止 / 历史参考：
    必须说明替代规范或保留原因。
```
