## 2. 结算相关映射

| 概念 | 当前口径 | 相关代码入口 | 证据入口 | 禁止事项 |
| --- | --- | --- | --- | --- |
| 安全 / 服务根特征 | 自我根特征，不由显示摘要定义 | `自我类.特征定义.*`、`特征类.*`、`状态类.*` | 根特征定义、状态值、特征值 | 不把面板摘要当根特征事实 |
| 因果证据 | 因果账本由动作动态及来源动态链表达 | `动态类.*`、`因果类.*` | 动作动态、来源动作动态、满足证据动态 | 不另造轻量因果链结构冒充当前因果账本 |
| 任务完成 | 任务完成只是结算输入之一 | `任务模块.执行.ixx`、`任务类.*` | 任务状态、执行结果、输出场景 | 不把完成状态直接当需求满足或价值满分 |
| 价值结算 | 叶子任务完成后由任务管理后处理方法进入反馈链 | `自我动作实现.服务模块.ixx`、`需求类.*`、`任务模块.*.ixx` | 实际改变结果状态、完成度、任务权重、账务变化 | 不作为安全值 / 服务值根任务的普通筹办候选 |
| 安全 / 服务入账 | 必须有父链归因、世界树因果证据、贡献层级和权重预算 | `因果类.*`、`需求类.*`、`动态类.*` | 结算日志、动作动态、状态变化、实施记录 | `I64_MAX` 不得作为未知、默认成功或无证据满分入账 |
| 结算贡献公式 | 父需求安全 / 服务权重平分到活跃子需求，任务继承来源需求权重，任务完成时按目标特征当前值 / 目标值比例生成贡献候选 | `自我线程模块.impl.cpp`、`需求类.*`、`任务类.*` | 来源需求权重、任务承接权重、当前值、目标值、完成 / 已结算被动因 | 不能绕过 D0/G0、父链归因、世界树因果证据、贡献层级、副作用审查和防重复令牌 |
| D0 / D1 | 因果解释证据，不再单独阻断入账 | `因果类.*`、相关实施记录 | 因果解释链 | 缺 D0 / D1 不单独作为阻断理由 |

## 3. 改代码前检查点

```text
1. 当前改动是在状态判断、任务执行、因果证据还是结算反馈链。
2. 是否把真实结果状态、完成度和任务权重同时带入。
3. 是否通过动作动态和因果类功能函数沉淀证据。
4. 是否避免 I64_MAX 进入真实服务结算。
5. 是否没有提前宣称自我苏醒完成或初步成熟完成。
```
