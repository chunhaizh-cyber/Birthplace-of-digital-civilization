# Codex 改代码前检查清单

## 0. 定位

本清单用于代码修改前的最小自检。它不替代 `AGENTS.md`、规范、计划或工程图谱正文。

## 1. 必读入口

```text
1. AGENTS.md
2. docs/00_文档总索引.md
3. 规范/禁止性规范20260611.md
4. 规范/规范目录.md
5. 计划/计划索引.md
6. docs/工程图谱/00_图谱总索引.md
7. docs/工程图谱/05_规则原子索引.md
8. 当前主题对应图谱
```

## 2. 权威关系自检

```text
1. 规范决定能不能做。
2. 详细设计解释怎么做。
3. 计划决定本轮做哪一段。
4. 实施记录只记录实际证据。
5. 流程图只做视觉解释。
6. 图谱只做导航索引。
7. 说明书和 README 只做对外说明与阅读入口。
8. 规则原子只做高风险规则导航，必须回读来源规范。
```

## 3. 结构闭环自检

```text
1. 业务概念是否已映射到项目承载结构。
2. 输入是否进入项目节点 / 特征 / 特征值结构。
3. 处理过程是否读取项目结构，而不是文本或日志。
4. 输出是否写回项目节点 / 特征 / 特征值结构。
5. 后续流程是否继续读取这些结构。
6. 是否没有新增自由文本、字符串字段、临时 JSON 或摘要字段承载机器逻辑。
```

## 4. 类边界自检

```text
1. 世界树操作是否调用世界树类功能函数。
2. 因果信息操作是否调用因果类功能函数。
3. 语素信息操作是否调用语素类功能函数。
4. 需求、任务、方法、特征、状态、动态、场景、存在等操作是否回到对应类。
5. 缺哪个类的功能函数，就生成或修订对应类逻辑纠偏计划，并把缺口放到第一优先。
```

## 5. 收尾自检

```text
1. 是否只改当前切片需要的文件。
2. 是否避开用户已有未提交改动。
3. 新增 / 删除 / 改名函数后是否刷新函数功能说明文档。
4. 是否记录已运行命令和关键结果。
5. 是否按需要更新计划状态、实施记录和图谱。
6. 文档小改未构建时，最终说明必须明确未运行构建。
```

## 6. 规范治理自检

```text
1. 命中 RULE 后是否回读来源规范。
2. 来源规范是否已进入 规范/规范目录.md。
3. 草案 / 待修订 / 历史参考是否没有被当成正式权威依据。
4. 是否需要更新 docs/规范治理/规范清册.md。
5. 是否需要运行 python .\tools\check_specs.py。
```

## 7. 映射和追踪自检

```text
1. 是否需要更新 docs/工程图谱/06_规范到代码映射.md。
2. 是否需要更新 docs/工程图谱/07_规范到测试映射.md。
3. 是否涉及事实写权，需不需要更新 docs/工程图谱/08_事实来源与写入权限图谱.md。
4. 是否是规范变更，需不需要更新 docs/规范治理/规范变更追踪表.md。
```
