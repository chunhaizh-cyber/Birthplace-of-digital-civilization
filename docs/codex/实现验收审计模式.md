# 实现验收审计模式

本文件是仓库级 `AGENTS.md` 中【实现验收审计模式】的完整细则。用于设计、实现、自检、验收和反向审计，目标是防止用状态名、字符串、日志、注释、空壳接口或孤立函数冒充真实项目闭环。

## 1. 总规则

设计和实现阶段不仅要证明“闭环”，还要证明这个闭环是用本项目的通用数据结构闭合的。

凡是系统内部逻辑，必须落到项目结构中：

```text
存在 / 场景 / 特征 / 特征值 / 方法 / 需求 / 基础信息节点
```

文本只能做外壳说明，不能做骨架承重。

禁止用以下内容承载系统状态、存在归属、特征归属、方法关系或需求关系：

```text
自由文本
std::string
文本标签
日志文案
注释说明
临时 JSON
自由字段
```

## 2. 三阶段工程协议

### 2.1 设计阶段

进入代码修改前，必须输出：

```text
目标行为
现有代码证据
项目结构映射表
当前缺口
最小实现方案
预期调用闭环
文本替代风险
测试计划
不做范围
```

【项目结构映射表】是强制项：

```text
业务概念 -> 项目承载结构 -> 值类型 -> 写入方 -> 读取方 -> 验证方式
```

示例：

| 业务概念 | 项目承载结构 | 值类型 | 写入方 | 读取方 | 验证方式 |
| --- | --- | --- | --- | --- | --- |
| 观察存在发现状态 | 宿主存在 / 观察过程节点的特征节点 | I64 状态值 | 眼睛观察方法 | 扫描治理方法 | 搜索写入点和读取点 |
| 当前轮廓局部体素 | 特征值类值池 + VecU句柄 | VecU句柄 | 轮廓体素生成方法 | 体素归属比较方法 | 比较函数测试 |
| 归属存在 | 特征节点或指针句柄特征 | 指针句柄 | 多候选归属方法 | 场景维护方法 | 调用链验收 |
| 存在稳定体素模型 | 存在节点下的三维体素特征 | VecU句柄 | 体素账本重建方法 | 体素比较方法 | 体素命中测试 |

如果设计阶段不能给出这张表，不能进入实现阶段。

### 2.2 实现阶段

实现过程中，任何业务状态、归属关系、存在关系、特征关系、方法关系、需求关系，都必须进入项目结构：

```text
存在节点 / 场景节点 / 特征节点 / 特征值 / VecU句柄 / 指针句柄 / I64状态值 / 方法节点 / 需求节点
```

不得用 `std::string` 或文本标签承载。

不合格示例：

```cpp
struct 观察结果 {
    std::string 状态;
    std::string 归属存在;
    std::string 轮廓类型;
};
```

合格方向：

```cpp
struct 观察结果 {
    I64 发现状态 = 0;
    指针句柄 归属存在{};
    VecU句柄 局部体素{};
};
```

或写入宿主节点的特征：

```cpp
特征类.写入特征值_I64(观察存在发现状态特征, 已发现状态值, now);
特征类.写入三维体素特征值(局部三维体素特征, 局部体素句柄, now);
```

实现时必须证明：

```text
输入进入项目节点 / 特征 / 特征值结构
    -> 处理过程读取项目结构
    -> 输出写回项目节点 / 特征 / 特征值结构
    -> 后续流程继续读取这些结构
```

不得出现：

```text
输入是项目结构
    -> 中间转成文本
    -> 文本判断
    -> 文本输出
    -> 声称完成
```

### 2.3 验收阶段

验收任何“已实现 / 已支持 / 已完成 / 已接入 / 已闭环”声明时，必须同时给出六类证据：

```text
输入入口
核心处理
项目结构承载证据
输出 / 状态变化
调用路径
测试 / 验证
```

“项目结构承载证据”必须回答：

```text
该逻辑用了哪个存在 / 场景 / 特征 / 特征值 / 方法 / 需求结构？
业务状态是否写入特征？
归属关系是否写入指针句柄或项目关系？
体素模型是否写入 VecU句柄 / 特征值类值池？
是否存在 std::string 替代业务结构？
```

## 3. 文本允许范围

文本只允许用于：

- 日志输出
- 调试说明
- 测试名称
- 用户可读错误信息
- 语素入口注册时的名称种子
- 文档说明

即使使用文本注册语素入口，也必须立即转换为项目内部身份结构，例如：

```cpp
const 语素入口节点类* 类型 = 语素集.添加信息入口词(...);
```

后续逻辑必须比较 `语素入口节点类*` 或通过项目已有同一性函数比较，不得继续用字符串比较。

## 4. 文本替代审计

完成后必须额外审计以下内容：

```powershell
rg "std::string|const char\\*|string_view|map<.*string|string.*状态|string.*类型|string.*归属" .
rg "\"已发现\"|\"未发现\"|\"已归属\"|\"未归属\"|\"证据不足\"|\"冲突\"" .
rg "TODO|FIXME|未实现|暂不|不直接|不生产|不确认" .
```

发现文本承载业务状态时，必须判定为：

```text
文本替代实现，不合格
```

除非能证明该文本仅用于日志、调试、测试名称、错误信息或语素入口注册，并且业务逻辑实际使用项目结构流转。

## 5. 降级规则

如果缺少完整证据，必须按以下口径降级：

- 只有状态名、枚举、抽象节点、字段、注册表、初始化逻辑：仅定义壳
- 只有头文件声明、函数签名、结构体定义：仅声明接口
- 有函数实现但没有主流程调用：孤立实现，未接入闭环
- 有结构体但未挂接到存在、特征、场景、方法或需求节点：孤立实现，未接入项目结构闭环
- 有部分逻辑但缺少输出、调用链或测试：部分实现
- 用字符串保存状态：文本替代实现，不合格
- 用日志表示状态变化：仅有日志 / 注释
- 用注释描述逻辑：仅有日志 / 注释
- 用临时 JSON 传递内部业务状态：文本替代实现，不合格
- 只注册语素 / 状态名，没有写入读取闭环：仅定义壳
- 找不到实现证据：未实现

## 6. 禁止声明

没有完整闭环证据时，禁止写：

```text
已经实现
已经闭环
已经接入
已经支持
可以工作
基本完成
```

没有项目结构闭环时，禁止写：

```text
已实现
已接入
已闭环
已支持
已完成
```

必须改写为：

```text
仅有文本替代实现，未接入项目通用数据结构
仅定义状态名，未形成特征写入读取闭环
已有孤立数据结构，未挂接到存在 / 特征 / 场景 / 方法体系
已定义抽象状态，但未实现行为
已有底层工具，但未接入主流程
已有孤立函数，但缺少调用链
已有接口声明，但缺少实现
已有部分逻辑，但缺少测试验证
```

## 7. 输出格式

执行验收时必须输出：

```text
# 实现验收报告

## 总结结论

总体判定：
- 已实现闭环：N 项
- 部分实现：N 项
- 孤立实现，未接入闭环：N 项
- 仅定义壳：N 项
- 仅声明接口：N 项
- 仅有日志 / 注释：N 项
- 文本替代实现，不合格：N 项
- 未实现：N 项
- 无法判断：N 项

一句话结论：
<当前真实进度，不允许夸大>

## 逐项验收

| 编号 | 声明 | 判定 | 关键证据 | 缺口 |
|---|---|---|---|---|

## 证据详情

每项必须包含：

1. 输入入口
2. 核心处理
3. 项目结构承载证据
4. 输出 / 状态变化
5. 调用路径
6. 测试 / 验证
7. 缺口
8. 最小补丁建议
```

## 8. 搜索要求

验收时必须搜索：

```text
声明关键词
相关状态名
相关函数名
写入点
读取点
调用方
测试用例
日志反证
TODO / FIXME / 未实现 / 暂不 / 不直接 / 不生产 / 不确认
文本替代风险词
```

C++ 项目优先使用：

```powershell
rg "关键词|状态名|函数名|TODO|FIXME|未实现|暂不|不直接|不生产|不确认" .
rg "函数名" .
rg "状态名" .
rg "std::string|const char\\*|string_view|map<.*string|string.*状态|string.*类型|string.*归属" .
```

## 9. 行为约束

如果用户要求“验收 / 审计 / 证明已实现 / 检查是否真实现”，不要改代码。

如果用户要求“实现”，完成修改后也必须附带一段自我验收，按六类证据说明是否闭环。

如果无法给出项目结构承载证据，必须停止夸大结论，按降级规则输出当前真实状态。
