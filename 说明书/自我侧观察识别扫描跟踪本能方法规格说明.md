状态：2026-06-15 规格说明稿。

```text
识别
```

## 1. 总体定位

D455 / RGB-D 外设只负责稳定供料。外设侧 L0-L3 产出原始帧、深度与掩码稳定材料、跨帧关联材料和稳定观察子集；自我侧 L4 才负责观察、识别、跟踪、扫描。

当前阶段对自我内部治理真正主动需要的是扫描：

```text
安全 / 服务增加根需求
    -> 内部治理判断需要当前状态或任务结果验证
    -> 生成扫描需求
    -> 任务创建 / 任务筹办 / 方法选择
    -> 外设供料
    -> 扫描读取自我内部场景指针和外设当前数据集
    -> 扫描比较内部场景基准和外设当前数据集
    -> 扫描语义输出状态信息或空信息
    -> 比较缺口写入输出结果场景作为结构化需求来源
    -> 状态信息接回需求、任务、方法、学习虚拟存在特征变化链
```

观察、识别、跟踪不是扫描的直接子函数。四者只能通过下列链路间接衔接：

```text
方法结果 / 结构化缺口
    -> 需求生成
    -> 任务创建
    -> 任务筹办
    -> 方法选择
```

## 2. 共同硬规则

四个方法都必须形成本能方法内部闭环，至少写清：

```text
输入参数场景
输出结果场景
目标宿主
目标特征类型
当前状态 / 目标状态 / 实际结果状态
方法执行情况
失败原因、缺口类型或异常类型
动作动态或错误日志证据
后续承接入口
```

四个方法都不得只返回错误码、失败文本或原因摘要。过程证据只能写入运行存在或输出结果场景；不得把过程证据长期挂到世界树存在主特征集合中。

按 `本能函数实现规范20260430.md`，四个本能函数的 C++ 返回值均为本轮运行虚拟存在指针。本文中的“语义输出”不是函数裸返回值，而是写入输出结果场景、运行存在或后续提交链可消费的功能结果事实。

世界树中已确认存在的长期观察特征类型只允许保存：

```text
空间位置
空间尺寸
轮廓
彩图
深度图
轮廓极值
```

下列内容不得作为已确认存在的长期特征保存：

```text
外设内部候选编号
帧内编号
报告编号
任务编号
同一性评分
匹配评分
候选数量
硬冲突数量
质量诊断摘要
补观察建议
调试文本
```

这些数据可以作为本轮运行存在、输出结果场景、外设材料页或日志证据使用，用完即丢，或仅保留为可回查证据引用。

## 3. 方法关系

### 3.1 扫描驱动关系

扫描执行中遇到缺口时，不直接调用其它方法，也不直接决定“观察 / 识别 / 跟踪”。扫描只记录结构化需求来源；需求生成后进入任务创建、任务筹办和方法选择。

```text
对应关系缺口
    -> 目标宿主：当前材料 / 候选存在
    -> 目标特征：当前材料对应已有存在状态
    -> 目标状态：已确定

空间坐标缺口
    -> 目标宿主：目标存在
    -> 目标特征：当前空间坐标
    -> 目标状态：已取得

当前特征值缺口
    -> 目标宿主：目标存在 / 目标特征
    -> 目标特征：当前特征值可比较状态
    -> 目标状态：已取得 / 可比较

材料质量缺口
    -> 目标宿主：外设当前数据集
    -> 目标特征：材料质量
    -> 目标状态：可比较

状态变化
    -> 目标宿主：发生变化的存在或场景范围
    -> 目标特征：状态变化记录状态
    -> 目标状态：已记录并进入内部治理判断
```

### 3.2 结果回流关系

```text
观察完成
    -> 已确认存在的允许特征值集合得到补充
    -> 扫描可使用更完整的当前特征

识别返回存在指针
    -> 任务链可选择扫描该存在

识别返回空指针
    -> 任务链可生成观察补完、存在创建或其它后续需求

跟踪返回新空间坐标
    -> 任务链可让扫描或观察继续锁定同一存在

跟踪返回空信息
    -> 任务链记录跟丢，并按需求重新识别或补观察

扫描语义输出状态信息
    -> 接入内部治理被动因果链

扫描语义输出空信息
    -> 表示本轮没有可提交状态变化或当前材料不足
```

## 4. 观察方法规格

### 4.1 方法名

规格语义名：

```text
自我_观察存在特征
```

当前已有实现名：

```text
自我_观察单个空间候选并组合存在假设
```

当前已有实现名带有历史语义。按本规格理解时，它只能收束为“锁定同一个存在并补充允许特征值集合”，不得继续把“组合存在假设”当作观察方法的当前语义。

### 4.2 目标

观察的目标是：

```text
在锁定同一个已知存在的前提下，
补充该存在当前可观察到的特征值集合，
直到本轮可观察特征类型不再出现新特征值。
```

观察不是识别，不回答“有没有见过”。观察不是跟踪，不负责在空间位置变化后找回目标。观察不是扫描，不输出状态变化。

### 4.3 输入

输入参数场景必须提供：

```text
目标存在指针 / 目标存在引用
当前观察材料集 / 外设观察报告引用
观察范围 / ROI / 掩码 / AABB / 点集
当前空间位置
当前空间尺寸
当前轮廓
彩图材料引用
深度图材料引用
轮廓极值材料
材料质量状态
允许补充的特征类型集合
观察窗口 / TTL / generation
```

允许补充的特征类型集合只能包含：

```text
空间位置
空间尺寸
轮廓
彩图
深度图
轮廓极值
```

子轮廓可以作为自我内部细化线程从彩图和深度图中提取的过程材料；当前不得作为已确认存在根层长期特征类型直接追加。若需要长期表达，应进入内部世界子存在、轮廓细化结果或轮廓极值等合法承载面。

### 4.4 判定逻辑

观察先用空间位置锁定目标：

```text
空间位置一致
    -> 使用空间尺寸和轮廓确认仍是同一个存在

空间位置不一致
    -> 不继续观察
    -> 输出需跟踪缺口
```

确认同一存在后，逐项比较允许特征类型：

```text
已存在相同特征值
    -> 不重复写入

出现新的合法特征值
    -> 添加到目标存在的特征值集合

特征材料质量不足
    -> 输出补观察缺口

特征类型不在允许集合
    -> 不写入存在
```

### 4.5 输出

观察的输出结果场景必须包含：

```text
目标存在指针 / 目标存在引用
观察状态 = 进行中 / 已完成 / 需跟踪 / 需补观察 / 需识别 / 材料不足
本轮新增特征值数量
本轮新增特征类型集合
本轮未新增特征类型集合
材料质量状态
动作动态引用
后续承接入口
```

观察完成条件：

```text
当前观察材料中所有允许特征类型均已检查；
同一存在仍被锁定；
没有新的合法特征值可追加；
没有未解释质量缺口。
```

语义输出：

```text
观察状态信息
```

持久写入：

```text
仅允许向目标存在追加：
空间位置 / 空间尺寸 / 轮廓 / 彩图 / 深度图 / 轮廓极值
```

## 5. 识别方法规格

### 5.1 方法名

```text
自我_识别外设观察材料
```

当前本能方法 ID：

```text
6145
```

### 5.2 目标

识别只回答：

```text
当前获取到的存在材料有没有见过。
```

输出只有两类：

```text
已有存在指针
空指针
```

已有存在可以是具体存在，也可以是抽象存在。

### 5.3 输入

输入参数场景必须提供：

```text
当前存在材料 / 外设观察材料引用
当前观察范围
识别范围
自我所在场景指针
世界树根指针
轮廓
空间尺寸
子轮廓材料，若已有
彩图 / 深度图材料，若需要辅助
空间位置上下文
材料质量状态
匹配阈值 / 硬冲突阈值
```

识别不得以外设内部候选编号、帧内编号、报告编号、任务编号或固定 ID 作为“见过”的依据。

### 5.4 查找顺序

识别必须先查自我所在场景，再查世界树：

```text
当前材料
    -> 自我所在场景已有存在
    -> 世界树根部
    -> 由粗到细向下查找
```

候选召回推荐顺序：

```text
1. 轮廓
2. 空间尺寸 / AABB 尺寸
3. 子轮廓
4. 掩码重合
5. 深度摘要 / 颜色特征
6. 可观测物理标记，若存在
7. 空间位置上下文 / 局部三维模型
```

空间位置不是识别主准则，只能作为范围上下文、反证检查或后续跟踪入口。

### 5.5 判定逻辑

```text
候选数量 = 0
    -> 输出空指针

候选数量 = 1 且无硬冲突
    -> 输出已有存在指针

候选数量 > 1
    -> 继续使用轮廓、尺寸、子轮廓等更细特征收敛

唯一候选存在硬冲突
    -> 输出空指针
```

最低反证检查：

```text
轮廓是否严重失配
空间尺寸是否严重失配
子轮廓是否严重失配
掩码重合率是否低于硬阈值
关键类别特征是否互斥
一个材料是否强匹配多个存在
一个存在是否被多个互斥材料强匹配
```

### 5.6 输出

语义输出：

```text
存在指针 | 空指针
```

输出结果场景可记录过程证据：

```text
候选数量
唯一性状态
硬冲突状态
证据不足原因
补观察建议
动作动态引用
```

这些过程证据不是识别语义输出，不得写入目标存在的一阶特征集合。

识别不得：

```text
创建新存在
补写空间位置
补写空间尺寸
补写轮廓
补写彩图
补写深度图
输出当前状态
输出状态变化
```

## 6. 跟踪方法规格

### 6.1 方法名

```text
自我_跟踪指定存在
```

当前本能方法 ID：

```text
6147
```

### 6.2 目标

跟踪只回答：

```text
同一个存在现在在哪里。
```

输出只有两类：

```text
新空间坐标
空信息
```

空信息表示跟丢或当前材料不足以唯一找回。

### 6.3 输入

输入参数场景必须提供：

```text
目标存在指针 / 目标存在引用
上一空间位置
当前观察材料集 / 外设跟踪报告引用
当前场景指针
空间尺寸
轮廓
轮廓极值
ROI / 掩码 / 点集
搜索范围 / TTL / generation
材料质量状态
唯一凭证阈值
```

外设内部跟踪 ID、候选编号、帧内编号只能用于回查材料，不得作为自我世界存在对应关键。

### 6.4 判定逻辑

```text
空间位置一致
    -> 使用空间尺寸和轮廓确认仍是同一个存在
    -> 输出当前空间坐标

空间位置不一致
    -> 在当前场景中用空间尺寸、轮廓、轮廓极值等唯一凭证查找
    -> 找到唯一匹配则输出新空间坐标
    -> 找不到或多重冲突则输出空信息
```

跟踪不得把找到的材料直接写成新存在，也不得补写长期特征集合。跟踪只产坐标或空信息；坐标入树或后续观察/扫描由提交入口和任务链承接。

### 6.5 输出

语义输出：

```text
新空间坐标 | 空信息
```

输出结果场景可记录：

```text
目标存在指针 / 目标存在引用
上一空间位置
新空间坐标或空信息
跟踪状态 = 已定位 / 跟丢 / 多重冲突 / 材料不足
唯一凭证特征类型集合
冲突 / 证据不足原因
动作动态引用
后续承接入口
```

## 7. 扫描方法规格

### 7.1 方法名

```text
自我_扫描当前场景
```

方法类型：

```text
自我内部本能方法
```

当前旧实现入口仍可能使用 `自我_扫描已识别区域` / 本能方法 ID `6146`，后续实现时应按本节语义收束，不得让旧名称扩大为“发现存在”或“全场景扫描”。

### 7.2 职责与边界

职责：

```text
维护当前场景中本轮应覆盖存在的当前状态；
消费已合法外设数据项；
比较已归属存在的已有特征；
更新当前状态、基准、状态动态、缺口信息。
```

不负责：

```text
不生产新的观察特征值；
不直接调用观察、识别、跟踪；
不确认新存在；
不删除世界存在；
不直接满足安全 / 服务根需求。
```

### 7.3 输入参数

```text
自我内部场景指针
自我内部场景基准 / 上一轮扫描基准，若存在
已合法外设当前数据集 / 外设扫描报告引用
内部场景中的已确认存在指针 / 已确认存在集合
已合法外设数据项集合
存在对应关系 / 对应状态
当前观察材料范围 / 数据集范围
当前扫描范围 / ROI / 外设视野
来源需求 / 来源任务的目标范围
当前状态基准，若存在
目标特征类型集合
比较规则：空间位置、空间尺寸、轮廓、当前特征值、材料质量
材料质量状态
处理频率规则 / 扫描优先级规则
状态变化阈值
TTL / generation
```

实现前必须建立特征类型绑定表，不允许在代码中散落字符串或临时枚举。

#### 7.4.1 方法运行虚拟存在特征

```text
扫描运行状态
扫描闭合状态

本轮应覆盖存在集合
本轮可忽略存在集合
本轮需补条件存在集合
本轮异常未覆盖存在集合

本轮应覆盖存在数量
本轮可忽略存在数量
本轮需补条件存在数量
本轮异常未覆盖存在数量

外设数据项总数

已成功解析数据项计数
已闭合处理数据项计数

```

#### 7.4.2 存在级特征

这些是被扫描存在本身已有或可读取的特征：

```text
空间位置
空间尺寸
平面轮廓
彩图
深度图
轮廓极值
扫描基准
特征值域
归属状态
运动状态
当前出现状态
扫描优先级值
低频维护周期
```

扫描不能创建这些一阶特征的新值。扫描只能消费已合法外设数据项中的值，并把它作为当前状态更新或比较材料。如果特征本身不存在，进入信息缺口，不能由扫描补。

#### 7.4.3 二次特征类型

扫描中的判断应落成二次特征：

```text
外设数据项_内部存在.空间位置误差值
外设数据项_内部存在.空间尺寸误差值
外设数据项_内部存在.轮廓一致性评分
外设数据项_内部存在.平面轮廓偏差值
外设数据项_内部存在.轮廓极值误差值
当前特征值_扫描基准值.变化差异值
当前特征值_特征值域.值域判断状态
预测坐标_当前视野.视野外判断状态
预测区域_覆盖存在.遮蔽覆盖评分
```

这些不能用自然语言判断，必须由函数计算。

#### 7.4.4 状态动态类型

扫描可以生成或推动这些状态动态：

```text
扫描当前状态更新动态
扫描无变化动态，可选，建议仅摘要
扫描值域内变化动态
扫描值域冲突动态
扫描条件不足动态
扫描信息缺口动态
扫描视野外动态
扫描遮蔽覆盖动态
扫描未观测到动态
扫描消失候选动态
```

单轮未覆盖不应直接写最终“消失”。建议先写“未观测到 / 消失候选”；是否升级为更强状态，应由连续证据、提交入口或后续治理链裁决。

### 7.5 已合法外设数据项结构

扫描消费的是“已合法外设数据项”，不是原始相机报告。如果数据项没有经过合法化，扫描不能用它写场景当前状态。

建议最小结构：

```cpp
struct 结构_已合法外设数据项 {
    std::uint64_t 数据项ID = 0;
    std::uint64_t 来源报告ID = 0;
    std::uint64_t 来源帧ID = 0;
    std::uint64_t 来源外设ID = 0;

    std::string 来源观察存在ID{};
    std::string 可能归属存在ID{};

    std::uint64_t 约束ID = 0;
    std::string 约束generation{};
    std::string 目标特征generation{};
    std::string 来源材料generation{};

    std::int64_t 时间戳毫秒 = 0;
    std::int64_t TTL毫秒 = 0;

    std::vector<结构_外设特征材料> 特征材料集合{};

    std::int64_t 材料质量等级 = 0;
    bool 可回查 = false;
    bool 可比较 = false;
    bool 可生成扫描变化候选 = false;

    std::string 坐标系ID{};
    std::string 失败原因{};
};
```

特征材料：

```cpp
struct 结构_外设特征材料 {
    std::string 特征类型ID{};
    特征值 当前值{};
    std::string 特征值generation{};
    std::string 来源材料句柄{};
    bool 可回查 = false;
    bool 可比较 = false;
};
```

### 7.6 本轮关注集合生成规则

扫描正式核对外设数据前，必须先生成本轮扫描关注集合：

```text
当前场景存在集合
    -> 按当前扫描范围 / ROI / 外设视野筛选
    -> 按空间位置或预测投影判断是否应被当前外设覆盖
    -> 按低频维护规则排除本轮不维护的静止 / 环境存在
    -> 按跟踪接管状态排除已被目标跟踪任务接管的存在
    -> 按扫描优先级筛出本轮需要维护的存在
```

筛选结果只写入扫描方法运行虚拟存在，不直接写入存在长期状态。

三类核心集合：

```text
本轮应覆盖存在集合：
    本轮理论上应被当前外设覆盖或维护。

本轮可忽略存在集合：
    范围外 / 视野外 / 低频跳过 / 跟踪排除 / 优先级不足。
    不参与消失、遮蔽或异常未覆盖判断。

本轮需补条件存在集合：
    缺空间位置 / 缺基准 / 缺值域 / 预测位置不可靠 / 材料不可回查。
    记录信息缺口，不进入普通扫描比较。
```

外设数据项处理完成后，未覆盖解释的输入必须是：

```text
本轮异常未覆盖存在集合
    = 本轮应覆盖存在集合 - 本轮外设覆盖存在集合
```

不得使用：

```text
当前场景所有存在 - 本轮外设覆盖存在集合
```

作为未覆盖解释输入。

### 7.7 量化判断函数

所有判断函数至少输出：

```cpp
struct 判断结果 {
    枚举_判断状态 状态;
    std::int64_t 分值;
    std::string 原因;
};
```

#### 7.7.1 筛选函数

```cpp
bool 属于当前扫描范围(存在, 扫描范围);
判断结果 判断外设视野重合(存在, 外设视野);
判断结果 判断维护策略是否需要扫描(存在, 来源需求, 当前时间);
bool 是否被高优先级跟踪接管(存在);
std::int64_t 计算扫描优先级(存在, 来源需求, 当前时间);
判断结果 判断扫描特征条件是否齐备(存在, 目标特征类型);
```

#### 7.7.2 对应关系判断函数

```cpp
判断结果 判断空间位置一致(外设数据项, 内部存在);
判断结果 判断空间尺寸一致(外设数据项, 内部存在);
判断结果 判断轮廓一致(外设数据项, 内部存在);
判断结果 判断轮廓极值一致(外设数据项, 内部存在);
判断结果 判断唯一找回(外设数据项, 本轮应覆盖集合);
```

唯一找回必须遵守识别原则：

```text
候选数量 == 1
硬冲突数量 == 0
用于唯一识别特征数量 > 0
```

不能只用最高分。

#### 7.7.3 特征变化判断函数

```cpp
判断结果 判断特征是否可比较(存在, 特征类型);
判断结果 判断可记录变化(当前值, 基准值, 特征值域, 特征类型);
判断结果 判断值域冲突(当前值, 特征值域);
```

关键规则：

```text
变化成立 != 当前值 != 基准值

变化成立 =
    差异值 >= 最小可记录变化量
    且 当前值落入存在特征值域
```

超值域不是正常变化，应记录值域冲突。

#### 7.7.4 未覆盖解释函数

```cpp
判断结果 预测当前应在空间坐标(存在, 当前时间);
判断结果 判断预测坐标是否视野外(预测坐标, 外设视野);
判断结果 判断遮蔽覆盖证据(存在, 覆盖索引, 外设数据项集合);
判断结果 判断子层证据是否足够(存在, 外设材料);
判断结果 判断消失候选是否成立(存在, 未覆盖解释输入);
```

遮蔽 / 覆盖证据建议拆成：

```text
图像覆盖证据
空间深度遮蔽证据
```

### 7.8 场景写入接口

扫描流程中允许执行中写场景，但必须通过统一接口，不得在流程各处直接改特征。

建议接口：

```cpp
写入结果 写入场景当前特征值(
    场景节点类* 场景,
    存在节点类* 存在,
    特征类型ID 特征类型,
    特征值 新值,
    来源信息 来源,
    扫描运行虚拟存在* 运行存在);
```

该接口必须做：

```text
1. 校验新值来源是否合法。
2. 校验特征类型是否允许由扫描更新当前状态。
3. 写入当前状态值。
4. 记录写入摘要。
5. 串接来源动作动态或外设数据项证据。
6. 返回写入结果。
```

写入摘要至少包括：

```text
目标存在
目标特征类型
旧值
新值
来源外设数据项ID
来源报告ID
来源动作动态
写入时间
写入结果状态
```

如果写入预测坐标，空间位置特征值本体仍只保存坐标。预测来源和可信状态应同步写入运行存在、写入摘要、状态信息或动态证据，例如：

```text
空间位置当前值来源状态 == 预测
空间位置当前值可信状态 == 估计
```

这些状态不得塞入空间位置特征值本体。

### 7.9 输出结果场景格式

语义输出：

```text
状态信息 | 信息缺口 | 空信息
```

输出结果场景可记录：

```text
状态信息集合
信息缺口集合
空信息
写入摘要集合
临时证据集合
处理闭合证据
```

状态信息示例：

```text
扫描运行存在.场景维护结果状态 == 已更新
扫描运行存在.内部信息一致性状态 == 一致 / 冲突 / 信息不全
扫描运行存在.扫描闭合状态 == 已闭合
```

信息缺口至少包括：

```text
缺口目标宿主
缺口特征类型
缺口原因
来源运行ID
建议后续路径
```

缺口类型示例：

```text
缺空间位置
缺预测依据
缺扫描基准
缺特征值域
缺子层证据
外设材料不可回查
值域冲突
```

建议后续路径可以是：

```text
观察补特征
识别复验
跟踪重捕获
等待下一轮扫描
```

扫描本身不直接调用这些方法，只把它们作为结构化缺口的后续承接建议。

如果状态信息为空，也要输出：

```text
语义输出 == 空信息
```

同时仍保留：

```text
写入摘要
缺口集合
处理闭合证据
```

否则无法追踪“为什么没有状态信息”。

### 7.10 伪代码骨架

当前阶段可先写骨架，不写所有判断细节：

```cpp
扫描方法结果 自我_扫描当前场景事实可用性(const 扫描输入& 输入)
{
    auto* 运行存在 = 创建扫描方法运行虚拟存在(输入);

    auto 关注集合 = 生成本轮扫描关注集合(输入, 运行存在);
    写入运行存在_筛选集合(运行存在, 关注集合);

    auto 数据项队列 = 展开已合法外设数据项队列(输入.外设当前数据集);
    写入运行存在_数据项总数(运行存在, 数据项队列.size());

    覆盖索引 索引{};

    for (auto& 数据项 : 数据项队列) {
        标记取出(运行存在);

        auto 解析 = 解析外设数据项(数据项);
        if (!解析.成功) {
            记录外设数据项诊断(运行存在, 数据项, 解析.原因);
            标记闭合(运行存在);
            continue;
        }

        auto 对应 = 判断外设数据项对应关系(解析, 关注集合);
        if (对应.锁定同一存在) {
            更新覆盖索引(索引, 对应);
            处理已覆盖存在特征(输入.场景, 对应, 运行存在);
        } else {
            记录对应关系缺口(运行存在, 解析, 对应);
        }

        标记闭合(运行存在);
    }

    auto 异常未覆盖 = 计算异常未覆盖集合(关注集合.应覆盖, 索引);
    处理异常未覆盖存在集合(输入.场景, 异常未覆盖, 索引, 运行存在);

    auto 输出场景 = 构造扫描输出结果场景(运行存在);
    写入运行存在_输出结果(运行存在, 输出场景);

    return {运行存在, 输出场景};
}
```

## 9. 实现落地注意

1. 当前代码中 `自我_识别外设观察材料`、`自我_扫描已识别区域`、`自我_跟踪指定存在` 已有本能 ID 和执行入口；规格修订后，旧实现中“首次发现提交入口”等命名需要后续按当前状态基准口径复核。
2. 当前代码中观察方法仍使用历史名 `自我_观察单个空间候选并组合存在假设`；后续若保留该 ID，必须收束语义，不得继续把“存在假设”作为观察的正式输出。
3. 任何旧日志、旧断点或旧计划中出现“扫描发现存在 / 首次发现事实”时，应解释为历史证据，不得作为当前新规格的验收标准。
4. 本说明书只定义方法规格，不宣称 D455 自然业务样本完整通过，也不宣称识别 / 扫描 / 跟踪边界已经全部动态闭合。
