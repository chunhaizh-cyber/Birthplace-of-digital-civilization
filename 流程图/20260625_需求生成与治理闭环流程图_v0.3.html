需求生成与治理闭环流程图 v0.3

总图 + 模块图。v0.3 补入拒绝回执治理闭环，并将代码缺陷型拒绝固定为开发诊断闭环，不进入普通需求树。

总图

flowchart TD
    Start(["开始：进入需求生成与治理闭环"]) --> M1[["模块 1：来源发现<br/>发现需求前材料"]]
    M1 --> A[/接口 A：需求前材料<br/>候选 / 报告 / 草案 / 回查信号<br/>不是正式需求/]
    A --> M2[["模块 2：目标归一与消息规范化<br/>差距确认、补槽、幂等"]]
    M2 --> B[/接口 B：入树请求<br/>新增指令或派生需求消息/]
    B --> M3[["模块 3：自我线程入树裁决<br/>校验、去重、合并、执行更新指令"]]

    M3 --> COK[(正式需求节点<br/>统一需求树)]
    M3 --> CREJ[/需求入树拒绝回执<br/>已进入治理闭环/]
    CREJ --> M35[["模块 3.5：拒绝回执治理处理<br/>分类、转派、隔离、关闭"]]

    COK --> M4[["模块 4：任务化与任务推进<br/>任务承接、筹办、执行"]]
    M4 --> D[/接口 D：结果事实 / 新缺口<br/>输出场景、动作动态、回执/]
    D --> M5[["模块 5：结果验证与满足回写<br/>事实可信、需求满足、结算闸门"]]
    M5 --> Root{"父链 / 根状态<br/>是否需要重判？"}
    Root -- "需要继续推进" --> M1
    Root -- "本轮重判完成" --> Next(["结束：等待下一轮状态触发"])

    M35 -- "补槽后重提 / 观察验证 / 学习 / 材料处理" --> M2
    M35 -- "合并 / 冷却 / 来源任务内部闭合" --> M4
    M35 -- "开发诊断闭环：等待代码修复" --> StopDiag(["暂停该来源路径<br/>不得普通需求化"])

    B1["边界：候选、报告、草案不是正式需求"] -.-> A
    B2["边界：正式需求只能经自我线程裁决和需求类::执行更新指令入树"] -.-> M3
    B3["边界：拒绝入树可以，拒绝治理不可以"] -.-> M35
    B4["边界：代码缺陷不是需求缺口，只能走开发诊断闭环"] -.-> StopDiag
    B5["边界：任务筹办 / 任务执行不是本能方法或动作来源"] -.-> M4

模块 1：来源发现

flowchart TD
    In(["开始：扫描来源"]) --> Root["读取根特征状态<br/>安全 / 服务 / 抽象根特征定义"]
    Root --> RootGap{"根特征存在缺口？"}
    RootGap -- "是" --> RootMat[/根特征缺口材料/]
    RootGap -- "否" --> RootIdle["根需求保持低压或等待"]

    In --> Self["自检 / 主动报送"]
    Self --> SelfKind{"材料类型？"}
    SelfKind -- "差距" --> SelfGap[/自检差距材料/]
    SelfKind -- "代码缺陷" --> CodeMat[/代码缺陷报告<br/>仍是需求前材料/]
    SelfKind -- "诊断" --> SelfDiag[/诊断报告/]

    In --> Body["身体反馈 / 观察反馈"]
    Body --> BodyMat[/反馈材料<br/>实时值、观察事实、证据状态/]

    In --> Prep["任务筹办不能一步就绪"]
    Prep --> Causal["路径筹办<br/>读取来源需求目标和世界树因果"]
    Causal --> LearnSplit{"缺口类型？"}
    LearnSplit -- "方法 / 动作 / 条件结果对 / 参数映射 / 验证方法" --> LearnMat[/学习或方法补全缺口材料/]
    LearnSplit -- "条件 / 证据 / 副作用 / 因果路径" --> PrepMat[/筹办缺口材料或派生草案/]

    In --> Exec["任务执行未满足来源需求"]
    Exec --> ExecMat[/执行缺口材料或派生草案/]

    In --> Parent["子需求满足 / 任务完成"]
    Parent --> ParentMat[/父目标回查材料/]

    RootMat --> Out[/接口 A：需求前材料/]
    SelfGap --> Out
    CodeMat --> Out
    SelfDiag --> Out
    BodyMat --> Out
    LearnMat --> Out
    PrepMat --> Out
    ExecMat --> Out
    ParentMat --> Out

模块 2：目标归一与消息规范化

flowchart TD
    In[/接口 A：需求前材料/] --> Kind{"来源形态？"}

    Kind -- "自检 / 反馈 / 根缺口" --> Translate["翻译获取途径<br/>裁决父域和目标宿主"]
    Translate --> CodeDefect{"代码缺陷型报告？"}
    CodeDefect -- "是" --> CodeReceipt[/拒绝回执<br/>闭环类型=开发诊断闭环/]
    CodeDefect -- "否" --> Atomic["检查原子目标完整性<br/>父需求、目标宿主、目标特征、当前状态、目标状态、满足关系"]
    Atomic --> Complete{"目标字段完整？"}
    Complete -- "否" --> MissingReceipt[/拒绝回执<br/>字段缺失或目标不可判定/]
    Complete -- "是" --> Compare{"三态比较 / 差距确认<br/>当前状态 vs 目标状态"}
    Compare -- "已满足" --> Natural[(自然闭合记录<br/>不入普通需求树)]
    Compare -- "不可判定" --> ObserveMat[/观察验证缺口材料/]
    Compare -- "未满足" --> NewInstr[/新增原子需求指令/]

    Kind -- "筹办 / 执行派生草案" --> Build["构造结构_任务管理派生需求消息"]
    Build --> Normalize["规范化消息<br/>补主键槽、语义槽、版本号、幂等键"]
    Normalize --> MsgComplete{"字段完整？"}
    MsgComplete -- "否" --> BuildReceipt[/拒绝回执<br/>退回来源补槽/]
    MsgComplete -- "是" --> Internal{"外设内部材料字段<br/>或仅参数诊断？"}
    Internal -- "外设材料" --> MaterialReceipt[/拒绝普通需求化<br/>闭环类型=外设材料闭环/]
    Internal -- "参数诊断" --> ParamReceipt[/拒绝普通需求化<br/>闭环类型=来源任务内部闭环或学习闭环/]
    Internal -- "否" --> Dedup{"同批 / 近期重复？"}
    Dedup -- "是" --> MergeReceipt[/拒绝回执<br/>闭环类型=合并冷却闭环/]
    Dedup -- "否" --> UpMsg[/上报派生需求消息<br/>直接写需求树=0/]

    NewInstr --> Out[/接口 B：入树请求/]
    UpMsg --> Out
    ObserveMat --> BackA((回到模块 1<br/>继续补证据))

    CodeReceipt --> Reject[/进入模块 3.5/]
    MissingReceipt --> Reject
    BuildReceipt --> Reject
    MaterialReceipt --> Reject
    ParamReceipt --> Reject
    MergeReceipt --> Reject

模块 3：自我线程入树裁决

flowchart TD
    In[/接口 B：入树请求/] --> Shape{"请求形态？"}
    Shape -- "新增原子需求指令" --> Entry["需求类::执行更新指令"]
    Shape -- "派生需求消息" --> Receive["自我线程接收派生需求消息"]
    Receive --> Ensure["私有_确保派生需求节点"]
    Ensure --> Gate{"入树闸门通过？"}

    Gate -- "父需求非法" --> RejectDev[/拒绝回执<br/>开发诊断闭环/]
    Gate -- "父为结构根且无合法映射" --> RejectDev
    Gate -- "父子目标自复制" --> RejectDev
    Gate -- "本应存在的动态为空 / 结构损坏" --> RejectDev
    Gate -- "逻辑上不允许的空指针 / 非法枚举" --> RejectDev

    Gate -- "字段可补 / 主体可观察 / 证据可补" --> RejectGov[/拒绝回执<br/>可治理闭环/]
    Gate -- "外设材料 / 参数诊断 / 重复" --> RejectOther[/拒绝回执<br/>材料、来源任务内部或合并冷却闭环/]

    Gate -- "通过" --> Same{"同父已有目标重叠子需求？"}
    Same -- "有" --> Merge["复用 / 合并既有需求<br/>补证据和版本"]
    Same -- "无" --> NewDemand["构造新增原子需求指令"]
    Merge --> Entry
    NewDemand --> Entry

    Entry --> Result{"更新指令结果？"}
    Result -- "新增 / 更新 / 合并成功" --> Node[(正式需求节点<br/>统一需求树)]
    Result -- "服务拒绝 / 结构异常" --> RejectService[/拒绝回执<br/>按原因分类/]

    Node --> Refresh["刷新子需求权重、结构角色、调度摘要"]
    Refresh --> Success[/派生需求入树成功回执/]
    Success --> Out[/接口 C：正式需求节点/]

    RejectDev --> ROut[/进入模块 3.5/]
    RejectGov --> ROut
    RejectOther --> ROut
    RejectService --> ROut

模块 3.5：拒绝回执治理处理

flowchart TD
    In[/需求入树拒绝回执/] --> Ledger[(拒绝回执账本<br/>原因、阶段、版本、幂等键)]
    Ledger --> HasPlan{"拒绝原因有处理方案？"}
    HasPlan -- "否" --> SpecBlock["不得进入正式规范 / 正式枚举<br/>升级为规范缺口或开发诊断"]
    HasPlan -- "是" --> Type{"拒绝闭环类型？"}

    Type -- "内部治理闭环" --> Fill["自动补槽 / 重判父域 / 重建语义槽"]
    Fill --> Retry{"可重提入树？"}
    Retry -- "是" --> RetryOut[/修复后重提到模块 2/]
    Retry -- "否" --> Escalate["升级为诊断或来源补槽"]

    Type -- "观察验证闭环" --> Observe["生成观察验证材料<br/>记录来源版本和证据缺口"]
    Observe --> ObserveOut[/回到模块 1 或模块 2/]

    Type -- "学习闭环" --> Learn["生成学习缺口材料<br/>区分缺方法、缺动作、缺条件结果对、缺参数映射、缺验证方法"]
    Learn --> LearnOut[/回到模块 1 或模块 2/]

    Type -- "来源任务内部闭环" --> SourceTask["绑定来源任务<br/>参数重绑、方法候选降权或重筹办"]
    SourceTask --> SourceDone[(来源任务处理状态更新)]

    Type -- "外设材料闭环" --> Peripheral["转外设材料仓库 / 观察结果包 / 方法内部材料依赖"]
    Peripheral --> MaterialDone[(材料闭合或来源任务降级)]

    Type -- "合并冷却闭环" --> Cool["绑定既有需求 / 任务 / 回执<br/>合并证据、更新冷却"]
    Cool --> CoolDone[(冷却或合并关闭)]

    Type -- "开发诊断闭环" --> Diag[["开发诊断闭环子流程"]]
    Diag --> DevItem[(结构_开发诊断项<br/>复现上下文、来源对象、版本信息)]
    DevItem --> Isolate["阻断 / 降级 / 隔离来源路径"]
    Isolate --> FailReceipt[/向来源任务返回实现缺陷阻断回执/]
    FailReceipt --> Alert[/日志 + 弹窗 / 报错 / 通知开发者/]
    Alert --> WaitFix(["等待开发者修正代码"])
    WaitFix --> Build["编译 / 预编译检查"]
    Build --> Regression{"回归测试通过？"}
    Regression -- "否" --> WaitFix
    Regression -- "是" --> CloseDiag[(关闭开发诊断项<br/>允许恢复或替换路径)]

    SpecBlock --> DevItem

模块 4：任务化与任务推进

flowchart TD
    In[/接口 C：正式需求节点/] --> List["从需求树构建服务优先 / 安全优先需求列表"]
    List --> Main["选择当前主需求候选"]
    Main --> Taskable{"普通可任务化叶子需求？"}
    Taskable -- "否" --> WaitNode["等待子需求、逻辑组织聚合<br/>或父任务重筹办"]
    Taskable -- "是" --> Intent["提交活动需求任务化意图"]
    Intent --> TaskHead["任务管理界面线程<br/>创建或复用任务头 / 任务虚拟存在"]
    TaskHead --> Prep["任务管理工作线程筹办"]

    Prep --> Path["路径筹办<br/>临时因果视图、条件、证据、副作用、学习缺口"]
    Path --> BlockGap{"发现阻塞派生需求？"}
    BlockGap -- "是" --> Suspend["冻结 / 挂起来源任务<br/>记录派生需求幂等键"]
    Suspend --> BackM2[/回到模块 2<br/>规范化派生需求消息/]
    Suspend --> WaitReceipt{"收到入树成功或拒绝回执？"}
    WaitReceipt -- "入树成功" --> WaitChild["等待派生需求完成"]
    WaitReceipt -- "可治理拒绝" --> Replan["按回执补槽、转学习、转观察或重筹办"]
    WaitReceipt -- "开发诊断拒绝" --> StopPath["来源任务进入实现缺陷阻断<br/>停止当前路径重复筹办"]

    BlockGap -- "否" --> MethodPlan["方法筹办<br/>按结果能力填充候选方法集"]
    MethodPlan --> Select["从候选集中确定当前方法"]
    Select --> Ready{"方法、条件、参数、入口就绪？"}
    Ready -- "否" --> Suspend
    Ready -- "是" --> Execute["执行当前方法<br/>任务执行仍是生命周期普通函数"]
    Execute --> Result["输出结果场景 / 运行存在 / 动作动态"]
    Result --> Hit{"来源需求目标实际达成？"}
    Hit -- "否" --> ExecGap[/执行缺失回执或派生需求草案/]
    ExecGap --> Suspend
    Hit -- "是" --> Out[/接口 D：结果事实/]

模块 5：结果验证与满足回写

flowchart TD
    In[/接口 D：结果事实/] --> Fact["读取任务完成回执<br/>输出事实、运行存在、动作动态、需求目标"]
    Fact --> Trust{"结果事实可信？"}
    Trust -- "证据不足" --> ObsNeed[/观察验证或诊断材料/]
    Trust -- "事实冲突" --> Conflict[/冲突缺口材料<br/>降低路径排序/]
    Trust -- "可信" --> Satisfied{"来源需求满足？"}

    ObsNeed --> BackM1((回到模块 1))
    Conflict --> BackM1

    Satisfied -- "否" --> NotDone["记录路径失败或证据不足<br/>来源任务重筹办或生成更细材料"]
    NotDone --> BackM1

    Satisfied -- "是" --> WriteBack["回写需求满足状态<br/>退出活动集"]
    WriteBack --> SettleGate{"价值结算硬闸门通过？"}
    SettleGate -- "否" --> NoSettle["不结算安全 / 服务值<br/>只记录任务完成事实"]
    SettleGate -- "是" --> Settle["叶子任务价值反馈链<br/>实际结果、完成度、权重、因果证据"]

    NoSettle --> ParentCheck["回查父需求目标特征"]
    Settle --> ParentCheck
    ParentCheck --> ParentDone{"父目标达成？"}
    ParentDone -- "否" --> Rebatch["唤醒父任务重筹办<br/>子需求完成不等于父需求满足"]
    Rebatch --> BackM1
    ParentDone -- "是" --> Root["继续向上回查父链<br/>刷新根状态、主需求和调度摘要"]
    Root --> BackM1

关键边界
  • 需求前材料、派生需求消息、拒绝回执都不是正式需求节点。
  • 正式需求只能经自我线程裁决并通过 需求类::执行更新指令 入统一需求树。
  • 拒绝入树不是终态；每类拒绝原因必须有处理方案。
  • 代码缺陷型拒绝不是需求缺口，固定进入开发诊断闭环。
  • 开发诊断项建立不等于代码缺陷关闭；关闭必须依赖代码修正、编译和回归测试。
  • 来源任务必须接收入树成功或拒绝回执，并停止同一路径重复派生。
  • 子需求完成不等于父需求满足；任务完成不等于可以价值结算。
