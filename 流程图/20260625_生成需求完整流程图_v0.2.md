## 说明

v0.2 将 v0.1 的单张大图拆成“总图 + 模块图”。总图只表达模块接口和主循环；模块图分别展开来源、归一、入树、任务化和回写重判。候选信息、缺口报告和派生需求消息仍然不是正式需求；正式需求必须经自我线程裁决并通过 `需求类::执行更新指令` 写入统一需求树。

flowchart TD

## 模块 1：来源发现

```mermaid
flowchart TD
    In["进入本轮需求来源扫描"] --> Root["读取根特征状态<br/>安全值 / 服务值 / 抽象根特征定义"]
    Root --> RootGap{"根特征有缺口？"}
    RootGap -- "有" --> RootOut["根需求活动权重刷新<br/>根闭环信息位 / 必要条件子需求候选"]
    RootGap -- "无" --> RootIdle["根需求保持低压或待机"]

    In --> SelfCheck["自检 / 主动报送"]
    SelfCheck --> SelfOut["差距候选 / 需求候选 / 自检报告"]

    In --> Feedback["身体反馈 / 观察反馈"]
    Feedback --> FeedbackOut["关注特征实时值<br/>自我线程后续计算差距"]

    In --> PrepGap["任务筹办不能一步就绪"]
    PrepGap --> CausalView["读取来源需求目标<br/>生成临时因果视图"]
    CausalView --> DraftOut["缺口报告 / 派生需求消息草案<br/>促成、避免、条件、方法、证据、副作用、学习"]

    In --> ExecGap["任务执行未满足来源需求<br/>或输出显式派生需求特征"]
    ExecGap --> ExecOut["执行缺失派生需求消息草案"]

    In --> ChildDone["子需求满足 / 任务完成回执"]
    ChildDone --> ParentSignal["父目标回查信号<br/>可能触发父任务重筹办"]

    RootOut --> Out["输出到模块 2"]
    SelfOut --> Out
    FeedbackOut --> Out
    DraftOut --> Out
    ExecOut --> Out
    ParentSignal --> Out
```

## 模块 2：目标归一与消息规范化

```mermaid
flowchart TD
    In["接口 A：候选或消息"] --> Kind{"来源类型"}

    Kind -- "自检 / 反馈候选" --> Route["自我线程翻译获取途径<br/>按缺口类型裁决父域"]
    Route --> CodeDefect{"代码缺陷型报告？"}
    CodeDefect -- "是" --> ReportOnly["记录报告 / 弹错 / 待处理<br/>不进入普通需求树"]
    CodeDefect -- "否" --> Atomic["检查原子目标完整性<br/>父需求、目标宿主、目标特征、当前状态、目标状态、满足关系"]
    Atomic -- "不完整" --> RejectA["逻辑错误<br/>拒绝入树"]
    Atomic -- "完整" --> NewInstr["构造新增原子需求指令"]

    Kind -- "筹办 / 执行派生草案" --> MsgBuild["构造结构_任务管理派生需求消息"]
    MsgBuild --> Normalize["规范化消息<br/>补主键槽、同步语义槽、生成幂等键"]
    Normalize --> Complete{"字段完整？"}
    Complete -- "否" --> RejectB["记录构造逻辑错误<br/>不上报派生需求消息"]
    Complete -- "是" --> InternalField{"目标是否外设内部材料字段<br/>或仅参数诊断？"}
    InternalField -- "是" --> RejectC["拒绝普通需求化<br/>保留诊断或方法内部数据"]
    InternalField -- "否" --> Dedup["按稳定键去重<br/>同批 / 响应内 / 最近缓存"]
    Dedup --> UpMsg["上报任务管理派生需求消息<br/>直接写需求树=0"]

    NewInstr --> Out["接口 B：入树请求"]
    UpMsg --> Out
```

## 模块 3：自我线程入树裁决

```mermaid
flowchart TD
    In["接口 B：入树请求"] --> Source{"请求形态"}
    Source -- "新增原子需求指令" --> UpdateEntry["需求类::执行更新指令"]
    Source -- "派生需求消息" --> Receive["自我线程收到派生需求消息<br/>私有_收到派生需求消息时完善需求树"]
    Receive --> Ensure["私有_确保派生需求节点"]

    Ensure --> Gate{"入树闸门通过？"}
    Gate -- "缺父需求 / 父为结构根" --> Reject1["弹错或记录逻辑错误<br/>提交拒绝回执"]
    Gate -- "来源因果或动态不可解析" --> Reject1
    Gate -- "当前状态、目标状态或目标特征缺失" --> Reject1
    Gate -- "目标主体不可判定" --> Reject1
    Gate -- "外设内部材料字段 / 父子目标自复制" --> Skip["拒绝普通需求化<br/>不兜底生成模糊需求"]

    Gate -- "通过" --> SameTarget{"同父已有目标重叠子需求？"}
    SameTarget -- "有" --> Merge["复用 / 合并既有子需求<br/>补齐目标关系"]
    SameTarget -- "无" --> NewDemand["构造新增原子需求指令"]
    Merge --> UpdateEntry
    NewDemand --> UpdateEntry

    UpdateEntry --> Result{"更新指令结果"}
    Result -- "新增 / 更新 / 合并成功" --> Node["正式需求节点进入统一需求树"]
    Result -- "服务拒绝" --> Reject2["拒绝入树并记录原因"]
    Node --> Refresh["刷新子需求权重<br/>刷新结构角色和调度摘要"]
    Refresh --> Receipt["提交派生需求入树回执"]
    Refresh --> Out["接口 C：正式需求节点"]
    Reject1 --> OutReject["接口 C：拒绝 / 暂存结果"]
    Skip --> OutReject
    Reject2 --> OutReject
```

## 模块 4：任务化与任务推进

```mermaid
flowchart TD
    In["接口 C：正式需求节点"] --> List["从需求树构建服务优先 / 安全优先需求列表"]
    List --> Main["选择当前主需求候选"]
    Main --> Taskable{"普通可任务化叶子需求？"}
    Taskable -- "否" --> Wait["等待子需求、逻辑组织聚合<br/>或父任务重筹办"]
    Taskable -- "是" --> Intent["提交活动需求任务化意图"]
    Intent --> TaskHead["任务管理界面线程<br/>创建或复用任务头 / 任务虚拟存在"]
    TaskHead --> Plan["任务管理工作线程筹办"]
    Plan --> PathPlan["路径筹办<br/>临时因果视图与缺口报告"]
    PathPlan --> HasChildGap{"发现阻塞派生需求？"}
    HasChildGap -- "是" --> BackToM2["回到模块 2<br/>规范化派生需求消息"]
    HasChildGap -- "否" --> MethodPlan["方法筹办<br/>按目标填充候选方法集"]
    MethodPlan --> Select["从候选集中确定当前方法"]
    Select --> Ready{"方法、条件、参数、入口就绪？"}
    Ready -- "否" --> BackToM2
    Ready -- "是" --> Execute["执行当前方法"]
    Execute --> Result["输出结果场景 / 运行存在 / 动作动态"]
    Result --> Hit{"来源需求目标实际达成？"}
    Hit -- "否" --> ExecGap["形成执行缺失回执或派生需求草案"]
    ExecGap --> BackToM2
    Hit -- "是" --> Out["接口 D：结果事实"]
```

## 模块 5：满足回写与父链重判

```mermaid
flowchart TD
    In["接口 D：结果事实"] --> Check["自我线程读取任务完成回执<br/>输出事实和需求目标"]
    Check --> Satisfied{"来源需求满足？"}
    Satisfied -- "否" --> Diagnose["记录路径失败或证据不足<br/>下次降低路径排序或生成诊断需求"]
    Diagnose --> BackToM1["回到模块 1<br/>继续形成更细来源"]

    Satisfied -- "是" --> WriteBack["回写需求满足<br/>需求有效截止、状态更新"]
    WriteBack --> Weight["子需求退出活动集<br/>权重归零或重新分配"]
    Weight --> Settlement["叶子任务价值反馈链<br/>按实际结果、完成度、权重和因果证据结算"]
    Settlement --> ParentCheck["回查父需求目标特征"]
    ParentCheck --> ParentDone{"父目标达成？"}
    ParentDone -- "否" --> Rebatch["唤醒父任务重筹办<br/>不直接把子需求完成当父需求满足"]
    Rebatch --> BackToM1
    ParentDone -- "是" --> Next["父需求满足<br/>下一轮根状态和主需求重判"]
    Next --> BackToM1
```

## 关键边界

```text
1. 模块 1 的输出只是候选、报告、草案或回查信号；不是正式需求节点。
2. 模块 2 的任务管理派生需求消息只是入树请求材料；任务管理侧不直接写需求树。
3. 模块 3 是正式入树边界；只有自我线程裁决并通过需求类::执行更新指令后，才形成正式需求节点。
4. 模块 4 中任务筹办 / 任务执行仍是任务管理生命周期普通函数，不作为本能方法或动作动态来源。
5. 模块 5 中子需求完成不等于父需求满足，必须回查父需求目标特征。
6. 本流程图是当前代码与规范口径的结构化梳理，不作为需求树整体闭合、自我苏醒完成或初步成熟完成证明。
```
