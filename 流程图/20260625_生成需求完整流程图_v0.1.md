## 说明

本图只梳理“生成需求”的当前权威流程：候选信息、缺口报告和派生需求消息都不是正式需求；正式需求必须由自我线程裁决，通过 `需求类::执行更新指令` 写入统一需求树。图中不宣称需求树机制整体闭合，也不宣称自我苏醒或初步成熟完成。

## 流程图

```mermaid
flowchart TD
    Start["开始：自我内部循环进入需求治理"] --> SourceGate["收集本轮需求来源"]

    subgraph S1["一、需求来源层：只产生候选、报告或消息"]
        RootState["根特征状态读取<br/>安全值、服务值、抽象根特征定义"] --> RootGap{"根特征有缺口？"}
        RootGap -- "有缺口" --> RootNeed["刷新安全根/服务根活动权重<br/>生成根闭环信息位和必要条件子需求"]
        RootGap -- "无缺口" --> RootIdle["根需求保持低压或待机"]

        SelfCheck["自检 / 主动报送"] --> SelfCandidate["差距候选 / 需求候选 / 自检报告"]
        BodyFeedback["身体反馈 / 观察反馈"] --> FeedbackCandidate["关注特征实时值<br/>由自我线程计算差距"]
        TaskPrep["任务筹办不能一步就绪"] --> CausalView["读取来源需求目标<br/>生成临时因果视图"]
        CausalView --> Drafts["促成 / 避免 / 条件补齐 / 方法就绪 / 证据补齐 / 副作用约束 / 学习缺口草案"]
        TaskExec["任务执行后未满足来源需求<br/>或输出显式派生需求特征"] --> ExecGap["执行缺失派生需求消息草案"]
        ChildDone["子需求满足 / 任务完成回执"] --> ParentRecheck["回查父需求目标<br/>必要时唤醒父任务重筹办"]
    end

    SourceGate --> RootState
    SourceGate --> SelfCheck
    SourceGate --> BodyFeedback
    SourceGate --> TaskPrep
    SourceGate --> TaskExec
    SourceGate --> ChildDone

    subgraph S2["二、候选归一层：确认目标和承接父需求"]
        SelfCandidate --> SelfRoute["自我线程翻译来源为获取途径<br/>按缺口类型裁决父域"]
        FeedbackCandidate --> SelfRoute
        SelfRoute --> CodeDefect{"代码缺陷型自检报告？"}
        CodeDefect -- "是" --> ReportOnly["记录报告 / 弹错 / 待处理<br/>不进入普通需求树"]
        CodeDefect -- "否" --> AtomicCheck["检查原子目标完整性<br/>目标宿主、目标特征、当前状态、目标状态、满足关系"]
        AtomicCheck -- "不完整" --> SelfReject["自检入树逻辑错误<br/>拒绝入树"]
        AtomicCheck -- "完整" --> SelfDemandPath["构造新增原子需求指令"]

        Drafts --> PrepMsg["任务筹办构造结构_任务管理派生需求消息"]
        ExecGap --> ExecMsg["任务执行桥构造结构_任务管理派生需求消息"]
        PrepMsg --> MsgNormalize["任务管理工作线程规范化消息<br/>补主键槽、同步语义槽、生成幂等键"]
        ExecMsg --> MsgNormalize
        MsgNormalize --> MsgComplete{"字段完整且不是内部材料字段？"}
        MsgComplete -- "否" --> MsgReject["记录构造逻辑错误或执行桥逻辑错误<br/>不上报派生需求消息"]
        MsgComplete -- "是" --> MsgDedup["按稳定键同批 / 响应内 / 最近缓存去重"]
        MsgDedup --> UpMsg["上报任务管理派生需求消息<br/>任务管理侧直接写需求树=0"]
    end

    subgraph S3["三、自我线程入树裁决层：正式需求唯一写入边界"]
        SelfDemandPath --> UpdateEntry["需求类::执行更新指令"]
        UpMsg --> ReceiveMsg["自我线程收到派生需求消息<br/>私有_收到派生需求消息时完善需求树"]
        ReceiveMsg --> EnsureDemand["私有_确保派生需求节点"]
        EnsureDemand --> Gate{"入树闸门通过？"}
        Gate -- "缺父需求 / 父为结构根 / 来源不可解析 / 状态或特征缺失 / 目标主体不可判定" --> RejectDemand["弹错或记录逻辑错误<br/>提交已拒绝回执"]
        Gate -- "外设内部材料字段 / 缺失参数诊断 / 父子目标自复制" --> SkipDemand["拒绝普通需求化<br/>不兜底生成模糊需求"]
        Gate -- "通过" --> SameTarget{"同父已有目标重叠子需求？"}
        SameTarget -- "有" --> MergeDemand["复用或合并既有子需求<br/>补齐目标关系"]
        SameTarget -- "无" --> NewDemand["构造新增原子需求指令"]
        MergeDemand --> UpdateEntry
        NewDemand --> UpdateEntry
        UpdateEntry --> TreeWrite{"更新指令结果"}
        TreeWrite -- "新增 / 更新 / 合并成功" --> DemandNode["正式需求节点进入统一需求树"]
        TreeWrite -- "服务拒绝" --> UpdateReject["拒绝入树并记录原因"]
        DemandNode --> Refresh["刷新子需求权重<br/>刷新结构角色和调度摘要"]
        Refresh --> Receipt["向任务管理提交派生需求入树回执"]
    end

    subgraph S4["四、任务化与继续生长层"]
        Refresh --> DemandList["从需求树构建服务优先 / 安全优先需求列表"]
        DemandList --> MainDemand["选择当前主需求候选"]
        MainDemand --> Taskable{"普通可任务化叶子需求？"}
        Taskable -- "否：逻辑组或仍有未满足子需求" --> WaitChildren["等待子需求、逻辑组织聚合或父任务重筹办"]
        Taskable -- "是" --> TaskIntent["提交活动需求任务化意图"]
        TaskIntent --> TaskCreate["任务管理界面线程创建或复用任务头 / 任务虚拟存在"]
        TaskCreate --> TaskPlan["任务管理工作线程筹办"]
        TaskPlan --> MethodCandidates["按目标填充候选方法集<br/>再确定当前方法"]
        MethodCandidates --> Ready{"方法、条件、参数、入口就绪？"}
        Ready -- "否" --> TaskPrep
        Ready -- "是" --> Execute["执行当前方法"]
        Execute --> ResultScene["输出结果场景 / 运行存在 / 动作动态"]
        ResultScene --> Satisfied{"来源需求目标实际达成？"}
        Satisfied -- "否" --> TaskExec
        Satisfied -- "是" --> Settle["自我线程回写需求满足<br/>子需求截止、权重归零、价值反馈链按证据结算"]
        Settle --> ParentRecheck
        ParentRecheck --> ParentDone{"父需求目标达成？"}
        ParentDone -- "否" --> TaskPrep
        ParentDone -- "是" --> NextRound["父需求满足 / 下一轮根状态和主需求重判"]
        NextRound --> SourceGate
    end

    subgraph S5["硬边界"]
        B1["任务管理线程不直接写需求树"]
        B2["自检、身体反馈、外设报告不是正式需求入树者"]
        B3["线程不是动作来源；动作动态必须绑定明确方法"]
        B4["任务筹办 / 任务执行不是本能方法，不注册为动作来源"]
        B5["I64_MAX 不得进入真实服务结算"]
        B6["派生需求消息不等于正式需求已入树"]
    end

    B1 -. "约束" .-> UpMsg
    B2 -. "约束" .-> SelfRoute
    B3 -. "约束" .-> ResultScene
    B4 -. "约束" .-> TaskPlan
    B5 -. "约束" .-> Settle
    B6 -. "约束" .-> ReceiveMsg
```

## 关键边界

```text
1. 正式需求树只通过统一更新指令生长；任务筹办、任务执行、外设线程、自检线程都不能直接写正式需求节点。
2. 生成需求前必须明确父需求、目标宿主、目标特征类型、当前状态、目标状态和满足关系；缺失时拒绝入树并记录逻辑错误。
3. 任务筹办先做路径筹办和候选方法填充；缺口只能形成回执、缺口报告或派生需求消息，不能跳过自我线程裁决。
4. 派生需求消息经字段完整性、幂等去重、同父目标重叠和父子目标自复制保护后，才可能变成正式需求。
5. 子需求完成不等于父需求满足，必须回查父需求目标特征；未达成则重筹办或继续生成更细需求。
6. 需求树生长正常只说明目标正在被拆解为可执行、可结算子目标，不等于自我苏醒完成或初步成熟完成。
```
