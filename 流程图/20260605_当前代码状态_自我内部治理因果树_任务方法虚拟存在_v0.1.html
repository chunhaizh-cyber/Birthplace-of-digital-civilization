口径

任务筹办和任务执行只形成过程回执；任务账由同步回执和提交任务状态变化写入。方法状态、运行账、结构成熟度写在方法虚拟存在。动作动态之间通过来源动态形成统一因果账本。

任务虚拟存在树

活动需求
└── 任务虚拟存在
    ├── 来源需求镜像：发起存在 / 作用对象 / 当前状态 / 目标状态 / 满足关系 / 权重
    ├── 筹办回执镜像：候选方法虚拟存在集 / 当前方法虚拟存在 / 输入场景 / 筹办缺口
    ├── 执行回执镜像：目标是否达成 / 推进量 / 剩余差距 / 方法运行存在 / 输出结果场景
    └── 任务状态动作动态：就绪 / 等待中 / 待重筹办 / 完成 / 已结算

方法虚拟存在树

方法头 / 当前方法
└── 方法虚拟存在
    ├── 方法身份：方法来源 / 动作句柄类型 / 动作名 / 成熟度阶段
    ├── 方法结构：父方法 / 前置方法 / 后续方法 / 条件场景 / 结果场景
    ├── 方法状态：待方法动作 -> 待可执行入口 -> 待条件节点 -> 待结果节点 -> 待条件结果对 -> 可用
    ├── 方法运行统计：运行次数 / 成功次数 / 失败次数 / 最近执行时间
    └── 方法状态动作动态：方法状态旧值 -> 新值

因果节点说明

节点因果动作动态归属
任务筹办任务状态允许筹办，需求目标明确候选方法、当前方法、输入场景、缺口或就绪建议自身不生成方法动作动态
方法状态治理方法头、动作句柄、条件节点、结果节点、条件结果对状态方法状态写入方法虚拟存在方法状态变化可生成方法状态动作动态
任务执行任务就绪，当前方法和输入场景具备世界事实、输出结果场景、执行回执D0 归当前业务方法或提交类方法
提交任务状态变化筹办或执行回执给出建议任务状态任务状态写入并生成任务状态动作动态D1 归提交任务状态变化
叶子任务价值结算任务完成且满足证据合法安全值 / 服务值 / 结算增量入账D2 归结算叶子任务价值
父任务重筹办子任务完成、子需求满足或方法可用性变化父任务从等待中回到待重筹办需要串上权威任务状态动作动态

边界

1. 不把任务筹办 / 任务执行画成本能方法。
2. 不把任务管理线程画成动作动态来源。
3. 不把方法运行账写入任务虚拟存在。
4. 不把任务完成直接等同于需求满足。
5. 不用说明文本、原因摘要或日志文案作为机器因果依据。
6. 下一步动作仍由正式需求状态、任务状态、方法状态和因果信息驱动。
