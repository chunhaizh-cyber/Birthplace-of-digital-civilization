# 创建子任务相关流程图 v0.1

更新时间：2026-06-12

## 用途

本图用于梳理当前代码中“创建子任务”的实际链路。

当前口径：

```text
缺口 / 派生事实
-> 自我线程裁决生成或复用子需求
-> 子需求任务化
-> 任务管理界面线程创建或复用任务
```

这里的“子任务”不是任务线程直接裸建的子任务节点。任务父子关系从需求树推导，任务节点只绑定自己的 `对应需求`。

## 对账点

1. 任务管理工作线程不直接写需求树，只上报 `结构_任务管理派生需求消息`。
2. 派生需求消息字段不完整不是普通跳过条件，而是消息构造逻辑错误，必须追查根因。
3. 稳定键重复是幂等去重条件；单次重复可不重复上报，持续重复或异常重复应追查重复生成来源。
4. 自我线程通过 `私有_确保派生需求节点` 裁决是否形成正式子需求；证据或路由非法时必须按原因分类，不用一个“拒绝入树”概括。
5. 子需求候选目标与父需求目标重叠是父子目标自复制保护，应停止入树并追查派生目标构造根因；同父直接子需求目标重叠才是正常复用路径。
6. 子需求任务化通过 `私有_提交任务发起请求到任务管理界面线程_线程侧` 提交任务发起意图。
7. 任务管理界面线程可复用 / 升级同目标任务；无法复用时才创建任务头结点。
8. 任务创建后必须绑定需求、确保任务虚拟存在，并用来源需求初始化任务语义。
9. 子任务创建后不等于父任务完成；父任务需要等待子需求结果，后续通过待重筹办 / 巡检派发重新进入筹办。

## 边界

```text
任务筹办 / 任务执行不是本能方法。
任务线程不得直接写需求树。
只有需求需要任务化，任务筹办 / 任务执行本身不应被建成子任务。
子任务完成只触发父任务重新判断，不直接证明父需求完成。
```
