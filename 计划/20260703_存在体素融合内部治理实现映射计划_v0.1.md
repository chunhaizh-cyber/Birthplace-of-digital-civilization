## 1. 设计条款清单

### 1.1 必须实现

```text
1. 存在体素融合只能承接已确认存在 E 的新增、未消费、可回查观察体素材料。
2. C_E 同一性候选和局部体素证据链只能作为融合前置输入，不得直接写 E 或 E_voxel。
3. 输入必须先形成待处理材料，再提取输入证据子轮廓，再生成子体素候选，再生成稳定体素主模型更新候选。
4. 正式稳定体素主模型更新必须经提交入口或对应领域类裁决。
5. 体素加工线程或耗时计算链只能输出候选结果包、计数、评分、版本、缺口和可回查句柄。
6. 基准稳定体素版本、坐标系版本、来源观察候选 generation 和材料页版本必须参与幂等与版本闸门。
7. 无融合点、外边界占据、generation 失配、质量不足、归属不可信或自由空间冲突时，只能挂起候选或输出结构化缺口。
8. 稳定体素版本更新后，只能向场景体素服务提交只读快照刷新请求。
```

### 1.2 禁止实现

```text
1. 禁止外设、视觉中间层、场景体素服务、控制面板或日志直接写稳定存在体素。
2. 禁止单帧局部体素候选直接覆盖稳定体素主模型。
3. 禁止子体素候选入链等同于主模型更新。
4. 禁止体素加工线程直接创建内部世界子存在、生成方法动作动态、写需求满足或安全 / 服务结算。
5. 禁止由外设原始帧、旧当前特征值、融合写回、控制面板刷新或场景体素快照触发体素融合。
6. 禁止用普通 bool、判断型枚举、日志文本、临时 JSON 或说明字段承载可融合、可提交、归属可信、材料可回查等判断。
7. 禁止新增持久业务结构体绕过存在、特征、特征值、二次特征、状态节点、VecU / VecIU64 句柄和提交入口。
```

### 1.3 后续待补

```text
1. 稳定体素主模型正式更新入口的最终函数名和调用点，必须由 S0 扫描后确定。
2. 子体素候选入稳定体素子链的现有承载位置，必须由 S0 扫描后确定。
3. 结构化融合缺口到 D5 缺口治理链的完整映射，可在 D5 实施计划进入代码后补齐。
4. 场景体素刷新事件的增强值域，可在场景体素服务增强计划进入代码后补齐。
```

### S1：体素融合输入组只读视图

目标：读取 E 稳定体素、C_E 候选、局部体素证据、来源材料 generation 和坐标系版本，形成只读输入摘要。

禁止：写稳定体素主模型、创建子存在、生成动作动态。

验证：缺任一关键输入时只输出缺口或挂起原因。

### S2：待处理材料和幂等闸

目标：把同一 E、同一 C、同一来源材料页、同一基准体素版本归并为同一待处理材料。

禁止：由外设原始帧或场景体素快照直接触发。

验证：重复触发不重复生成子体素候选。

### S3：输入证据子轮廓和子体素候选

目标：复用或补齐子轮廓提取、局部体素候选检查和正立方体包围盒检查。

禁止：彩色轮廓无深度支撑时生成子存在或稳定体素更新。

验证：外边界占据、无融合点、质量不足均进入候选阻断原因。

### S4：主模型融合候选

目标：只生成主模型更新候选，记录基准版本、融合点、冲突计数、越界计数和来源证据。

禁止：候选生成即写入主模型。

验证：基准版本失配时挂起重算，不覆盖稳定体素。

### S5：正式提交入口对接

目标：将合格主模型融合候选交给提交入口或对应领域类裁决。

禁止：治理链、工作线程或视觉融合层直接写正式事实。

验证：提交入口拒绝时只写结构化缺口或待复算状态。

### S6：场景体素刷新请求

目标：稳定体素版本更新后，仅提交场景体素只读快照刷新请求。

禁止：体素融合链直接修改场景体素缓存。

验证：刷新请求只影响 SceneVoxelPrior 快照，不写世界树事实。

### S7：验证和实施记录

目标：运行 `python .\tools\check_specs.py`；代码切片进入时按范围运行 `生成函数功能说明文档.py`、`git diff --check` 和 Debug x64 构建。

父计划回写：S7 完成后，更新 `计划/计划索引.md`、`docs/current-state.md` 和实施记录；不得宣称 C -> E 最终裁决、稳定存在更新治理链全闭环或场景体素先验图层已完整实现。
