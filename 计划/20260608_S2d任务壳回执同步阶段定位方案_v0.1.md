## 2. 目标

```text
第一目标：
    拆清 `状态提交回执同步` 的真实内部归属：
        状态提交前后快照读取；
        被动状态提交；
        提交后任务壳字段同步；
        无变化回执字段重复写入。

第二目标：
    拆清 `回执方法同步` 的真实内部归属：
        候选方法同步；
        当前方法同步；
        方法虚拟存在 / 方法状态读取；
        无变化方法字段重复写入。

第三目标：
    只在日志证明存在重复写入、重复查找或可安全移出锁的只读整理时实现瘦身；
    若主耗时实为必须保留的 `提交任务状态变化` 动作动态账，则记录证据并转向下一热点。
```

## 3. 硬边界

```text
任务状态变化仍必须通过 `提交任务状态变化` 动作入口。
不得裸写任务状态，不得跳过任务状态动作动态。
不得把任务筹办 / 任务执行恢复为本能方法、候选方法或动作动态来源。
不得让 worker 先执行后补任务状态账。
不得把外设执行失败、等待或 D455 条件不足改写成完成 / 满足。
不得新增 mock、fixture、伪入口、伪动作动态或 `--*-check` 回归入口。
诊断只走独立日志和真实运行日志，不新增机器决策字段。
旧代码若被新路径替代，必须删除旧分支，不保留双路径兜底。
```

