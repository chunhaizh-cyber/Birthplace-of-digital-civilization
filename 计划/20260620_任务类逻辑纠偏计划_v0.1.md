## 0. 目标

围绕 `任务主信息类.h`、`任务类.h/.cpp`、`任务模块.*` 的任务信息操作做一次边界收口：

```text
1. 所有关于任务信息节点、任务状态、任务虚拟存在、任务结果状态、任务执行方法、任务权重和任务调度特征的操作，默认必须调用 任务类 功能函数。
2. 外部代码不得直接解释 `任务主信息类` 字段作为机器逻辑依据。
3. 任务类自身不得直接操作非任务类主信息字段；需要需求、状态、特征、方法、存在、场景、世界树信息时，调用对应类功能函数。
4. 若对应类缺少功能函数，按“缺哪个类补哪个类第一优先”规则生成或修订对应类逻辑纠偏计划；当前缺口放在第一优先，闭合第一优先后返回本计划。
5. 审查任务主信息、任务类枚举和任务模块协议结构是否仍符合当前规范；能删除的删除，不能删除的说明边界和替代条件。
```

本计划只登记任务类纠偏路线，不执行源码修改。

任务类边界：

```text
1. 任务信息节点是任务树、调度、运行状态、执行反馈和子任务组织的运行壳。
2. 任务虚拟存在是任务作为存在对象的语义身份、记忆对象和任务特征承载位置。
3. 任务信息节点不能被任务虚拟存在替代；关系是：
   需求节点 -> 任务信息节点 -> 任务虚拟存在。
4. 自我线程不得直接写任务状态、当前方法、输入参数场景、筹办缺口、执行缺口、最近回执。
5. 任务管理线程负责任务状态推进、任务筹办、任务执行、回执同步和任务域提交。
6. 任务筹办 / 任务执行是任务管理生命周期普通函数，不进入方法树，不作为本能方法，不生成方法动作动态。
7. 任务状态变化若需要正式动作动态证据，必须通过任务域被动状态提交动作入口；线程不是动作来源。
8. 筹办 / 执行只返回任务层过程回执，不直接改需求树，不直接结算父需求，不把任务状态写入输出结果场景。
```

## 4. 任务主信息与枚举初判

### 4.1 暂保留

```text
枚举_任务状态
```

理由：

```text
它是任务生命周期状态值，当前已映射到任务虚拟存在状态特征和任务管理推进逻辑。
问题不在枚举本身，而在谁可以写状态、是否绕过任务管理提交链。
```

```text
任务主信息类::对应需求
任务主信息类::任务虚拟存在
任务主信息类::场景
任务主信息类::目标状态
任务主信息类::实际结果状态
```

理由：

```text
这些是任务信息节点运行壳的必要结构引用。
后续要做的是收口读写入口，不是直接删除字段。
```

### 4.2 需审查后降权或迁移

```text
任务主信息类::名称
任务主信息类::类型
```

审查点：

```text
1. 是否只用于显示 / SQL / 控制面板。
2. 是否被机器逻辑用于分类、调度或任务类型判断。
3. 若用于机器判断，必须改为任务虚拟存在概念 / 特征 / 任务角色 / 来源需求目标，而不是词面文本。
```

```text
任务主信息类::创建时间
任务主信息类::启动时间
任务主信息类::完成时间
```

审查点：

```text
1. 创建时间可作为审计字段保留。
2. 启动 / 完成时间若作为生命周期事实，应与任务状态提交链和任务虚拟存在运行账一致。
3. 不得用完成时间单独替代任务完成判定。
```

```text
枚举_任务阶段
枚举_任务节点种类
枚举_任务角色
```

审查点：

```text
1. 枚举_任务阶段 是否仍准确表达当前“路径筹办 + 方法筹办 + 执行 + 回执同步 + 结算后处理”链路。
2. 枚举_任务节点种类 当前只有头结点 / 步骤节点；若任务树不再负责旧步骤结构，需要判断步骤节点是否仍有真实用途。
3. 枚举_任务角色 不能由叶子 / 非叶子直接推断；必须结合来源需求目标语义和任务层级。
```

### 4.3 不纳入本轮删除

```text
任务模块.治理协议.ixx 中的 `结构_任务管理*` 和 `枚举_任务管理*`
任务模块.筹办.ixx 中的 `结构_任务推进回执 / 结构_任务筹办结果`
任务模块.工作线程消息协议.ixx 中的任务管理上行 / 结果状态消息
```

理由：

```text
这些是任务管理线程、工作线程、自我线程之间的协议结构。
它们是否合理需要单独做“任务模块协议结构审查”，不能混同为任务主信息字段清理。
本计划只登记该审查范围，后续如需清理，另开子切片或独立计划。
```

## 6. 已知跨类缺口

### 6.1 任务类直接读取需求主信息

初扫命中：

```text
任务类.cpp::私有_取需求目标状态
任务类.cpp::私有_取需求当前状态
任务类.cpp::私有_推导任务场景
任务类.cpp::私有_推导基准优先级
任务类.cpp::创建任务头结点
```

问题：

```text
任务类创建任务时直接读取：
    来源需求->主信息.需求状态
    来源需求->主信息.被需求当前状态
    来源需求->主信息.需求场景
    来源需求->主信息.安全权重
    来源需求->主信息.服务权重

这违反“任务类自身不得直接操作非任务类主信息字段”的边界。
```

处理规则：

```text
1. 若 需求类 已有对应只读函数，任务类直接调用。
2. 若 需求类 缺少函数，修订 `计划/20260620_需求类逻辑纠偏计划_v0.1.md`，把缺口放到第一优先。
3. 需求类第一优先闭合后，返回本计划 P0。
```

建议需求类缺口：

```cpp
需求节点类* 需求类::解析需求节点引用(...) noexcept; // 若已有同功能函数则复用
bool 需求类::读取需求当前状态引用(... ) noexcept;
bool 需求类::读取需求目标状态引用(... ) noexcept;
状态节点类* 需求类::解析需求当前状态(... ) noexcept;
状态节点类* 需求类::解析需求目标状态(... ) noexcept;
bool 需求类::读取需求场景引用(... ) noexcept;
场景节点类* 需求类::解析需求场景(... ) noexcept;
I64 需求类::读取需求安全权重(... ) noexcept;
I64 需求类::读取需求服务权重(... ) noexcept;
I64 需求类::读取需求综合权重(... ) noexcept;
```

### 6.2 任务类直接读取 / 写入世界事实和特征

初扫命中：

```text
任务类.cpp 内部多处调用：
    世界树.读取特征_I64
    世界树.写入特征_I64
    世界树.读取特征_指针
    世界树.写入特征_指针
    世界树.存在().取或创建子存在_按名称类型
    世界树.场景().读取场景宿主存在
```

初判：

```text
1. 任务虚拟存在上的任务特征读写可以由任务类封装，属于任务类职责。
2. 创建任务虚拟存在和读取场景宿主存在涉及存在 / 场景 / 世界树边界；若需要更细收口，应调用 存在类 / 场景类 / 世界树类 功能函数。
3. 任务类可以调用世界树功能函数，但不得直接遍历或改写非任务世界树结构。
```

处理规则：

```text
缺存在类函数 -> 修订 存在类逻辑纠偏计划；
缺场景类函数 -> 修订 场景类逻辑纠偏计划；
缺世界树类函数 -> 修订 世界树类逻辑纠偏计划；
缺特征类函数 -> 修订 特征类逻辑纠偏计划。
```

### 6.3 任务完成 / 推进判断缺口

规范口径：

```text
任务完成：结果 - 目标 >= 0。
任务推进：结果 - 之前结果 > 0。
两者不能混用。
```

当前风险：

```text
外部代码可能直接读取 `目标状态 / 实际结果状态` 后自行比较，或只看任务状态 / 完成时间。
```

处理规则：

```text
1. 任务类应提供任务目标达成 / 本轮推进的只读判定函数。
2. 判定函数内部比较状态值时调用 状态类 / 特征类；若缺函数，转入对应计划第一优先。
3. 外部调用方不再直接解释状态节点主信息。
```
