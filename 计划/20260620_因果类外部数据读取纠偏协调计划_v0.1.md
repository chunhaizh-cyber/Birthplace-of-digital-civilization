# 因果类外部数据读取纠偏协调计划 v0.1

日期：2026-06-20

状态：由“因果类自身是否直接操作非因果信息数据”检查触发；本计划只做路由和缺口协调，具体函数补齐进入对应类逻辑纠偏计划。

原计划返回点：`计划/20260619_因果类功能函数补完计划_v0.1.md` 的 P5 被动触发初始因果模板确保函数。

## 0. 目标

把 `因果类.cpp` 中直接解析、读取和解释非因果主信息字段的逻辑迁回对应功能类，保证后续因果类只组合因果信息、动态证据和对应功能类公开查询结果。

当前检查结论：

```text
因果类未发现直接写入非因果主信息字段。
因果类存在直接读取和解释 动态 / 状态 / 二次特征 / 特征 / 需求 / 方法 等非因果主信息字段的情况。
这些读取当前多为因果生成、因果查询和目标投影服务，但按当前类边界应通过对应类功能函数封装。
```

## 1. 项目结构映射表

| 业务概念 | 项目承载结构 | 值类型 | 写入方 | 读取方 | 验证方式 |
| --- | --- | --- | --- | --- | --- |
| 动态因果生成输入 | 动态节点 / 动态主信息 | 状态引用、方法引用、语义类型、层级 | 动态类 | 因果类 | 因果类不再直接读 `动态节点主信息类` 字段 |
| 状态主体和状态特征 | 状态节点 / 状态主信息 | 基础信息指针、特征指针 | 状态类 | 因果类、二次特征类 | 因果类不再直接读 `状态节点主信息类` 字段 |
| 状态迁移二次特征来源 | 二次特征节点 / 二次特征主信息 | 起始状态、结果状态、来源动态、标量区间 | 二次特征类 | 因果类 | 因果类不再直接读 `二次特征主信息类` 来源字段 |
| 特征语义类型 | 特征节点 / 特征主信息 | 语素入口指针 | 特征类 | 因果类、状态类 | 因果类不再直接读 `特征节点主信息类::类型` |
| 需求安全/服务方向 | 需求节点 / 需求主信息 | 权重方向 bool / I64 | 需求类 | 因果类 | 因果类不再直接读 `需求->主信息.安全权重/服务权重` |
| 方法引用解析 | 方法节点 / 方法主信息 | 方法指针 / 主键 | 方法类 | 因果类 | 因果类不再用 `基础信息->查找主键` 解析方法引用 |

## 3. 推荐执行顺序

```text
P1 动态类：读取动态因果生成输入。
P2 状态类：读取状态主体 / 状态特征 / 状态特征类型。
P3 二次特征类：读取状态迁移来源和可融合标量区间。
P4 特征类：读取特征语义类型。
P5 需求类：读取安全 / 服务方向。
P6 方法类：解析方法引用。
P7 因果类回迁：删除因果类中对应直接主信息读取和私有解析函数。
```

第一优先执行 P1。P1 闭合后停止动态类计划，返回本协调计划，再根据计划索引切到 P2。

P1-P7 全部闭合并完成因果类回迁验证后，返回 `计划/20260619_因果类功能函数补完计划_v0.1.md` 的 P5。

## 4. 跨类缺口转向规则

执行本计划或本计划派生的任一类计划时，如果发现当前切片必须依赖其它类新增或补齐功能函数，按以下规则处理：

```text
1. 后续任意类缺少当前切片所需功能函数时，不在当前调用方临时拼字段、解释其它类主信息或新增平行结构体。
2. 若对应类已有逻辑纠偏计划，则把当前缺口加入该计划，并放到第一优先位置。
3. 若对应类没有逻辑纠偏计划，则生成 `计划/YYYYMMDD_<类名>逻辑纠偏计划_v0.1.md`，并把当前缺口作为第一优先切片。
4. 新生成或被修改的逻辑纠偏计划必须包含本“跨类缺口转向规则”，保证后续继续发现缺口时仍按同一调度口径处理。
5. 更新 `计划/计划索引.md`：把新生成或新修改的计划临时提升为第一优先计划；原计划和原切片记录为返回点。
6. 只执行新计划的第一优先缺口切片，不顺带推进新计划后续候选项。
7. 第一优先缺口闭合后，立即停止该新计划，更新计划索引返回原计划和原切片。
8. 若第一优先缺口切片不能闭合，保留该计划为当前阻塞，不回到原计划继续补丁化绕过。
```
