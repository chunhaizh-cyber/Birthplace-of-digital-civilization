## 2. 定案目标

实现一个可进入候选方法集的安全对象作用方法：

```text
安全_评估当前场景安全性
```

它用于满足这些事实 / 评估明确类需求：

```text
当前场景安全度明确状态 等于 已明确
当前场景最低安全度存在明确状态 等于 已明确
当前场景各存在安全评估明确状态 等于 已明确
自我所在场景.基础风险判断状态 等于 已明确
风险状态明确状态 等于 已明确，兼容旧目标
```

当安全评估结果已满足且已被动获得负向因果证据时，本方法才输出低安全后续链线索：

```text
当前场景持续观察需求明确状态 = 未明确
负向影响处置需求明确状态 = 未明确
派生需求线索：当前场景持续观察需求明确状态 / 负向影响处置需求明确状态 -> 已明确
```

这只是已知负向影响后的后续链派生线索，不表示本方法已经满足持续观察或处置需求。若没有负向因果证据，本方法默认良好并把这些需求明确状态写为已明确，不主动生成处置压力。

但它不负责：

```text
定义什么东西危险；
写入存在本体安全度；
写入抽象存在伤害历史；
提高或降低 自我_安全值；
替代叶子任务价值结算入口。
```

一句话：

```text
该方法只把当前证据解释成安全评估结果视图，不把评估结果结算成安全值。
```

## 3. 边界

### 3.1 必须保留

```text
1. 存在只保存原始事实和证据引用。
2. 安全度、伤害可能性、伤害下界、场景安全度、最低安全度存在只作为评估结果。
3. 评估结果优先写入输出结果场景、方法运行虚拟存在和执行回执视图。
4. 若需要短期持久引用，只能写带来源方法、输入场景、证据引用、生成时间和有效期的评估状态缓存。
5. 基础风险判断状态、当前场景安全度明确状态等枚举型实例值必须由本方法或等价合法生产者写入。
6. 方法动作动态必须绑定本方法，不能用任务筹办、线程或控制面板显示当动作来源。
```

### 3.2 明确禁止

```text
1. 不新增安全因素定义表。
2. 不新增抽象存在主信息类。
3. 不新增存在安全画像结构体。
4. 不把评估结果写成存在或抽象存在的常驻本体字段。
5. 不把未知影响写成危险结论。
6. 不把缺少历史证据写成安全结论。
7. 不把基础风险判断状态 等于 已明确 等同于场景安全。
8. 不写安全值 / 服务值。
9. 不恢复任务筹办 / 任务执行为本能方法。
10. 不新增模拟样本、夹具入口、伪造动作动态或 `--*-check` 回归入口。
```

```text

    -> 派生需求：当前观察帧.基础观察事实可用状态 等于 可用

    -> 派生需求：当前场景.场景存在集合明确状态 等于 已明确
    -> 候选方法：安全_观察当前场景 / 安全_识别场景存在集合

    -> 派生需求：自我.关键特征变化观察状态 等于 已建立

    -> 评估结果：基础风险判断状态 = 证据不足
    -> 不生成安全值投影候选。
```

### S6 因果证据读取与第一版计算

目标：

```text
按因果模板和具体证据生成评估候选。
```

第一版计算规则：

```text
若 E 曾被归因为直接造成自我安全值下降：
    伤害可能性下界候选 > 0。

若 E 长时间与自我共处且没有新的归因伤害：
    直接伤害可能性候选下降。
    曾造成实质伤害者不得低于非零下界候选。

若 E 再次被归因为直接造成自我安全值下降：
    直接伤害可能性候选上升；
    非零下界候选可以上升。

若 E 缺少足够历史证据：
    评估状态 = 证据不足 / 低置信；
    E 不能作为场景安全提升证据。
```

场景汇总：

```text
存在安全度(E) = 安全刻度上限 - 存在直接伤害可能性(E)
场景风险压力值 = 平均(所有已确认存在的直接伤害可能性候选)
风险安全_场景影响部分 = I64_MAX - 场景风险压力值
当前场景评估安全值候选 = 风险安全_场景影响部分
当前场景最低安全度存在 = argmin(所有存在安全度候选)
```

`当前场景最低安全度存在` 只作为诊断 / 处置线索，不再单独决定整个场景安全值。风险安全层 v1 由场景影响、运行影响、资源影响、权限影响、未知影响五项平均后，再整体按第二层权重 `0.09` 投影到自我安全值候选。

未知证据处理：

```text
未知不是危险；
未知也不是安全；
未知只能导致低置信 / 证据不足 / 不能提升安全值。
```
