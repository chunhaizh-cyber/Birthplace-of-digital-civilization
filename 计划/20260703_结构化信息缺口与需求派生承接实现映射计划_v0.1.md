## 1. 计划目标

建立从各感知 / 体素 / 任务模块输出的缺口到需求派生链的统一映射：

```
外设缺口 / 视觉缺口 / 观察缺口 / 体素缺口 / 方法缺口
    -> 结构化信息缺口特征族
    -> 缺口收束
    -> 任务管理派生需求消息
    -> 入树 / 拒绝闭环
    -> 父子关系角色视图
```

本计划只把缺口接到现有任务管理派生需求消息和入树拒绝闭环，不新增自由结构体，不直接写需求树。

## 2. 不解决范围

```
1. 不新增自由 C++ 结构体作为业务事实。
2. 不改写需求树主信息持久字段。
3. 不让外设 / 视觉中间层直接写需求树。
4. 不把日志文本、界面 文本、普通函数返回 布尔值 当机器判断依据。
5. 不把缺口直接等同于需求。
6. 不把父子关系角色写成需求本体字段。
7. 不完成观察 / 识别 / 跟踪 / 扫描完整代码接入。
8. 不完成 D6 场景体素服务增强与 D7 外设观察先验发布器。
```

## 3. 设计条款清单

### 3.1 必须实现

```
M1. 缺口必须先结构化为可回查证据，再进入需求派生候选。
M2. 缺口来源必须包含来源层级、来源模块、来源任务 / 方法 / 报告 / 帧 / 候选等可追溯材料。
M3. 缺口进入派生需求消息前，必须具备父需求、目标宿主、目标特征类型、当前状态、目标状态和满足关系。
M4. 缺口到需求派生必须经过收束，不能由外设、视觉中间层或单个方法直接决定。
M5. 父子角色只能作为角色建议进入父需求视角角色视图，不能写成需求本体字段。
M6. 外设内部材料字段、参数诊断、规范缺口和代码缺陷型报告不得普通需求化。
M7. 入树拒绝必须进入拒绝闭环，不能静默丢弃。
M8. 稳定键 / 幂等键必须由结构化主键和值域材料组成，不得依赖自由文本语义解析。
```

### 3.2 禁止实现

```
F1. 禁止新增 `结构_结构化信息缺口` 等自由结构体作为业务事实承载。
F2. 禁止外设缺口码直接生成需求节点。
F3. 禁止视觉信息缺口直接写需求树或世界树。
F4. 禁止把普通布尔值 写成项目一阶事实，例如 是否阻塞 / 是否派生 / 是否必须。
F5. 禁止用日志、控制面板、说明文本或临时结构化文本作为机器判断依据。
F6. 禁止绕过任务管理上行消息直接写需求树。
F7. 禁止把代码缺陷型报告普通需求化。
F8. 禁止把“缺像素归属账本”直接派生成必须子需求。
```
