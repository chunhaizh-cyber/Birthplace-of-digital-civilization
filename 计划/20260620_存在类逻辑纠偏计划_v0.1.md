## 0. 目标

按当前项目结构闭环口径，检查并纠偏 `存在类`：

```text
1. 检查存在相关结构 / 字段是否仍符合当前逻辑，能删除则删除，能迁移则迁移到 owning class。
2. 补齐存在类功能函数，使外部系统逻辑不直接读取 / 解释 存在节点主信息类 字段。
3. 检查存在类实现中是否直接操作非存在主信息类数据；若需要其它类能力，按跨类缺口转向规则登记。
4. 区分只读读取和显式确保，禁止 const 读取路径隐式创建或补齐结构。
```

当前触发缺口：

```text
1. 存在类::取存在主信息(const 存在节点类*) 当前通过 const_cast 隐式补齐 需求 / 任务 / 方法 三类根节点。
2. 存在类中仍有 特征节点主信息类 创建、读取和特征值解释逻辑，与 特征类 功能函数重复。
3. 存在节点主信息类 中的观测缓存字段被二次特征生成读取，需要确认其仍只是缓存入口，不是权威事实字段。
4. 世界树类、二次特征应用模块、控制面板、语言层和部分动作实现仍存在直接读取 存在节点主信息类 的路径，需要分类回迁。
```

## 1. 第一优先切片：只读读取与显式确保拆分

问题锚点：

```text
存在类.cpp:
    存在类::取存在主信息(存在节点类*) 会调用 私有_确保存在具备三类信息根节点。
    存在类::取存在主信息(const 存在节点类*) 也会 const_cast 后调用 私有_确保存在具备三类信息根节点。

这会导致“读取主信息”隐式创建 需求根节点 / 任务根节点 / 方法根节点。
```

纠偏目标：

```text
1. 只读函数只读取，不创建、不补齐、不修改。
2. 显式确保函数负责创建或补齐三类根节点。
3. 获取需求根节点 / 获取任务根节点 / 获取方法根节点 的只读版本不得隐式创建。
4. 需要确保的调用方改为先调用 确保存在三类根节点，再获取对应根节点。
```

建议函数边界：

```cpp
存在节点主信息类* 取存在主信息(存在节点类* 节点) const noexcept;
const 存在节点主信息类* 取存在主信息(const 存在节点类* 节点) const noexcept;

bool 确保存在三类根节点(存在节点类* 节点) const noexcept;

需求类::节点类* 确保需求根节点(存在节点类* 节点) const noexcept;
任务类::节点类* 确保任务根节点(存在节点类* 节点) const noexcept;
方法类::节点类* 确保方法根节点(存在节点类* 节点) const noexcept;
```

执行步骤：

```text
P1.1 扫描所有 获取需求根节点 / 获取任务根节点 / 获取方法根节点 调用方，分类为只读显示、只读判断、确需确保。
P1.2 修改 取存在主信息 两个重载，去掉隐式补齐。
P1.3 将确需确保的调用方改为显式确保后读取。
P1.4 删除 const_cast 补齐路径，不保留旧入口或兼容 fallback。
```
