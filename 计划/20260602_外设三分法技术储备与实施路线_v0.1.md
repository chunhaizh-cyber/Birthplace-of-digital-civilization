# 外设三分法技术储备与实施路线 v0.1

日期：2026-06-02

状态：技术储备与实施路线；不作为代码已实现证明。

## 1. 目标

本路线承接 050004、050005、040007、040008 的最新口径，把外设技术储备按系统能力分层，而不是按算法名堆叠。

```text
识别：
    处理未识别 / 候选 / 冲突区域，让有效观察材料有归属结果。

扫描：
    处理已识别区域，发现已知存在的特征值变化和未解释变化。

跟踪：
    处理指定已确认存在，持续观察目标特征，主动忽略非目标存在。
```

本路线只回答：

```text
这些能力后续可以借哪些技术实现或增强。
```

不回答：

```text
当前代码已经实现完整识别 / 扫描 / 跟踪；
模型输出可以直接写已确认存在；
当前场景特征值明确可以直接由 D455 报告满足。
```

## 2. 硬边界

```text
1. D455 / RGB-D 基础材料层不是识别、扫描、跟踪本身，只是供料地基。
2. 模型输出、几何聚类输出、检测框、掩码、轨迹和地图更新都只是候选或材料。
3. 已确认观察存在仍必须经过：
       自我_验证外设观察像素簇候选
       -> 自我_确认外设观察存在候选
       -> 提交_确认观察存在事实。
4. 扫描发现新区域、匹配失败或未解释变化过大时，只能生成未识别区域 / 需重识别区域，不得直接确认新存在。
5. 跟踪只证明指定目标特征值变化明确，不证明全场景明确。
6. 技术储备不得替代真实 D455 数据验收；不得构造样本、伪造报告、伪造来源需求或手动调用筹办链。
```

## 3. A 类：D455 / RGB-D 基础材料与质量

优先级最高。第一版先固化 D455 材料包，而不是先接大模型。

直接支撑：

```text
深度有效率；
空间坐标有效率；
ROI / 掩码 / 点集；
深度切片；
像素归属账本；
D455 坐标到场景坐标 / 自我边界参照；
材料 TTL / generation；
遮挡 / 空洞 / 无效材料原因；
材料质量门槛。
```

技术资料：

| 资料 | 用途 |
| --- | --- |
| Intel RealSense D400 / D455 Datasheet | D455 深度相机规格、深度流、视场、工作距离、硬件能力依据。 |
| Depth Post-Processing for D400 | 深度滤波、空洞处理、时间滤波、host 侧后处理与延迟 / 质量权衡。 |
| Projection / Texture-Mapping / Occlusion | deprojection、projection、外参、对齐、纹理映射和遮挡处理。 |
| Self-Calibration for D400 | 材料质量异常时的外设治理入口，不进入安全因果链本身。 |
| D400 Visual Presets / Tuning | 识别、扫描、跟踪的外设配置候选库。 |

第一版实现优先级：

```text
P1. 原始帧 / 对齐帧 / 深度帧句柄可回查；
P2. ROI / 掩码 / 点集 / 深度切片句柄可回查；
P3. 深度有效率、空间坐标有效率、材料 TTL、generation 可读；
P4. 像素归属账本和区域状态可读；
P5. 空间中心、AABB、深度中值、空间范围可读；
P6. 相机坐标到场景坐标 / 自我边界参照转换缺口可解释。
```

## 4. B 类：识别技术储备

识别目标：

```text
有效观察材料
-> 已确认存在 / 新候选 / 候选区域 / 冲突区域 / 未知区域 / 背景 / 无效材料
```

第一版优先使用：

```text
D455 深度连通域；
3D 点集聚类；
ROI / 掩码生成；
像素归属账本；
候选与已有存在的几何匹配。
```

中长期增强储备：

| 技术 | 可用位置 | 边界 |
| --- | --- | --- |
| SAM / SAM2 | 未识别区域候选掩码、目标提示分割、视频候选持续分割。 | 输出候选掩码，不是已确认存在。 |
| Mask2Former | 语义 / 实例 / 全景区域候选。 | 背景和实例标签只是归属候选。 |
| Grounding DINO | 语言目标到开放集检测候选。 | 标签只是语义候选，不能直接入账。 |
| YOLOv10 | 低延迟检测框候选。 | 检测框只作为 ROI / 候选种子。 |

识别包技术字段建议：

```text
区域范围；
未识别区域；
候选区域；
冲突区域；
背景候选；
无效材料原因；
候选簇列表；
候选掩码 / ROI / 点集；
已有存在匹配候选；
新存在候选；
证据不足原因。
```

## 5. C 类：扫描技术储备

扫描目标：

```text
在已识别区域中，更新已知存在当前特征值和变化；
把未解释变化区域回流给识别。
```

第一版优先使用：

```text
已识别区域 ROI / AABB / 中心点变化；
深度中值 / 深度范围变化；
掩码面积和像素归属变化；
已知存在匹配失败记录；
未解释变化区域和需重识别区域。
```

中长期增强储备：

| 技术 | 可用位置 | 边界 |
| --- | --- | --- |
| OctoMap | occupied / free / unknown 区域表达，扫描覆盖率和未知区域管理。 | 地图视图不是已确认存在本身。 |
| Voxblox / TSDF / ESDF | 局部表面、障碍距离、距离场。 | 距离场只是安全候选输入，不直接写安全值。 |
| RTAB-Map / ORB-SLAM3 | 场景基准、重定位、相机位姿参考。 | 位姿 / 地图失效时不得声明空间特征明确。 |
| DynaSLAM | 动态区域与稳定背景区分。 | 动态区域应回流为变化 / 识别缺口。 |
| RAFT / SEA-RAFT / RGB-D Scene Flow | 光流、运动趋势、靠近 / 远离候选。 | 运动估计是趋势候选，仍需质量门槛和自我参照。 |

扫描包技术字段建议：

```text
区域基准ID / 场景基准ID；
扫描范围；
已知存在列表；
当前特征值；
特征值变化量；
变化方向；
变化时间；
扫描覆盖率；
未解释变化区域；
需重识别区域；
匹配失败原因；
材料质量。
```

## 6. D 类：跟踪技术储备

跟踪目标：

```text
对指定已确认存在持续观察；
主动忽略非目标存在；
只输出目标特征值和目标变化。
```

第一版优先使用：

```text
目标存在ID；
上一帧 ROI / 掩码 / 点集 / 中心点 / AABB；
IoU / 中心距离 / 深度残差；
连续命中次数；
丢失次数；
遮挡 / 重捕获候选；
靠近 / 远离趋势。
```

中长期增强储备：

| 技术 | 可用位置 | 边界 |
| --- | --- | --- |
| SAM2 | 目标种子到视频目标掩码持续维护。 | 跟踪成功不证明全场景明确。 |
| XMem / Cutie | 长视频目标记忆、遮挡后重现、目标一致性。 | 只服务指定目标，不替代全场扫描。 |
| ByteTrack | 检测候选与 tracklet 关联，低置信帧目标维持。 | 关联成功不是自我世界存在确认。 |
| RAFT / Scene Flow | 目标运动趋势、靠近 / 远离候选。 | 只作为目标变化材料。 |

跟踪包技术字段建议：

```text

目标种子；
目标上一轮 ROI / 掩码 / 点集 / 空间位置；
当前帧材料；
目标当前特征值；
目标变化量；
目标稳定性；
遮挡状态；
丢失状态；
重捕获候选；
靠近 / 远离趋势；
跟踪置信度；
证据不足原因。
```

## 7. 实施阶段建议

### 第一阶段：固化 D455 材料包和区域分区

```text
目标：
    让当前帧材料能稳定形成区域状态：
        已识别区域；
        未识别区域；
        候选区域；
        冲突区域；
        无效区域；
        背景区域。

只接 D455 / RealSense 官方处理链和简单几何。

验收：
    真实 D455 报告；
    材料页 / d455:// 句柄；
    ROI / 掩码 / 点集 / 深度切片可回查；
    区域状态和缺口原因可记录；
    不写已确认存在、不写安全值、不写需求满足。
```

### 第二阶段：经典几何 + 简单关联形成三类包

```text
识别：
    深度聚类 / ROI / 掩码 / 归属账本。

扫描：
    AABB / 中心 / 深度中值 / 掩码面积 / 未解释变化。

跟踪:
    目标 ID + 上一帧 ROI / 掩码 / 中心点 + IoU / 距离 / 深度残差。

验收：
    三类包能按范围 / 目标输出；
    扫描新区域回流识别；
    跟踪不证明全场景明确。
```

### 第三阶段：学习模型增强

```text
识别增强：
    SAM / SAM2 / Mask2Former / Grounding DINO / YOLOv10。

扫描增强：
    OctoMap / Voxblox / RTAB-Map / ORB-SLAM3 / DynaSLAM / RAFT / Scene Flow。

跟踪增强：
    SAM2 / XMem / Cutie / ByteTrack / RAFT。

验收：
    模型输出只作为候选；
    自我侧提交入口仍负责验证 / 确认 / 入账；
    不因模型置信度直接写世界树真值或安全评估结论。
```

## 8. S6-N2a 接入规则

S6-N2a 做代码对账或实现前，必须先按下列顺序核对：

```text
1. 目标是否带范围：
       全场景 / 已识别区域 / 指定区域 / 指定存在 / 跟踪目标。

2. 当前帧区域归属状态是否可表达：
       已识别 / 未识别 / 候选 / 冲突 / 无效 / 背景。

3. 子需求是否是材料型、确认型、扫描型或跟踪型：
       不得把 当前场景特征值明确状态 裸映射为 D455 等待项。

4. 外设输出是否只是材料或候选：
       模型输出、几何聚类、地图更新、轨迹关联都不得直接写已确认存在。

5. 缺口是否可解释：
       缺材料、缺坐标转换、缺可比历史、低质量、过期、冲突、无效、不可回查都必须有原因。
```
