# S1d-4d 任务状态提交本能方法通用环境快路径方案 v0.1

日期：2026-06-07

## 1. 目标

```text
在不跳过任务状态动作动态和运行账的前提下，
减少 自我_提交任务状态变化 每次执行前重复补齐通用方法环境的成本。
```

## 2. 依据

```text
S1d-4c 真实运行显示：
    本能方法自身环境 helper 平均约 135512us；
    确保本能方法平均约 54935us；
    首次同步方法虚拟存在平均约 38013us；
    二次同步方法虚拟存在平均约 34911us；
    确认规格平均约 0us。

因此当前可先治理通用环境重复补齐和重复同步，
而不是继续扩大任务管理层裸异步化。
```

## 3. 边界

```text
1. 不修改 自我_提交任务状态变化 具体方法体内的耗时日志。
2. 不跳过本轮运行虚拟存在创建。
3. 不跳过任务状态写入、任务状态动作动态、输出运行虚拟存在和更新方法运行账。
4. 不修改 方法虚拟存在服务类 的全局语义，先只在 自我动作实现模块.ixx 的统一 helper 中做调用方限定快路径。
5. 快路径只在 调用方=自我_提交任务状态变化 且同一方法首节点 / 方法虚拟存在 / 条件节点 / 条件场景 / 结果场景 已在本进程成功验证后生效。
```

## 4. 最小实现

```text
在 确保本能方法自身环境 中增加任务状态提交专用的进程内环境缓存：
    缓存方法首节点；
    缓存方法虚拟存在；
    缓存条件场景；
    缓存结果场景；
    缓存方法条件节点。

首次完整环境成功后写入缓存。
后续同一调用方、同一方法首节点、同一方法虚拟存在且缓存指针齐备时：
    仍创建本轮运行虚拟存在；
    仍读取 / 绑定缓存的条件场景、结果场景、条件节点；
    跳过重复 确保本能方法、首次同步方法虚拟存在、确认规格和二次同步。

若缓存不齐或方法首节点不匹配，退回完整环境路径。
```

## 5. 验证预测

```text
构建：
    Debug x64 应通过。

真实运行：
    .\x64\Debug\鱼巢.exe --self-check-log --self-check-log-wait-ms=10000 应退出码 0。

日志：
    本能方法自身环境/阶段耗时 仍可出现，但快路径样本应显示：
        确保本能方法、首次同步方法虚拟存在、确认规格、二次同步接近 0；
        本轮运行虚拟存在仍非 0。

效果：
    任务状态提交完整耗时和执行本能方法耗时应下降；
    若动作函数调用仍明显高于环境 helper，则下一刀只能在用户允许后细分具体方法体的任务状态写入、动作动态输出、输出运行虚拟存在和更新方法运行账。

负向核对：
    不应出现 状态提交确认失败、后台worker工作项进入死信、拒绝归并完成项；
    派发前 终止过期工作项 | 状态版本错配 若仍出现，登记为旧等待项残留治理，不作为本快路径破坏证据。
```
