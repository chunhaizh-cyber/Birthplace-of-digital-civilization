# 任务筹办通用参数绑定器纠偏计划 v0.1

日期：2026-05-31

## 1. 背景

现有任务筹办已经能创建 `任务可执行输入参数场景`，并写入 `输入条件包`、`目标方法头节点`、`目标宿主`、`目标特征类型`、`来源需求`、`任务信息节点`、`任务虚拟存在`、`任务状态`、`目标执行后值`、`执行差值` 等通用实参。

问题在于：

```text
参数绑定规则分散在输入闭合函数和少量专用补齐函数中；
后续新增本能方法形参时，容易继续写成方法名特判；
学习 / 练习和普通任务虽然已共用筹办流程，但参数来源规则还没有形成统一边界。
```

需要把这部分收束为：

```text
方法规范提供参数约束；
任务筹办根据约束生成可执行输入参数场景；
多候选只做确定性选择；
方法本身不关心参数怎么凑齐。
```

## 2. 纠偏目标

第一版目标不是构造“绝对最优参数”，而是构造：

```text
合法；
闭合；
可执行；
可追溯；
缺口明确。
```

具体目标：

```text
1. 建立通用参数绑定器普通函数。
2. 绑定器只读任务 / 需求 / 方法 / 当前状态 / 目标状态 / 当前上下文。
3. 绑定器写入 `任务可执行输入参数场景` 的 `输入条件包`。
4. 绑定器优先处理所有方法共享的参数来源。
5. 绑定器允许调用少量领域无关或已明确参数规则的专用补齐函数。
6. 绑定器最后统一检查必需形参。
7. 绑定失败只返回参数缺口，不执行方法、不生成需求、不写账。
```

## 3. 第一版覆盖范围

第一版绑定来源：

```text
目标方法头节点：
    普通任务绑定当前方法；
    方法结构补齐任务绑定被补方法。

目标宿主 / 目标存在：
    来源需求的目标宿主。

目标特征类型 / 目标抽象特征 / 目标特征：
    来源需求目标特征。

任务信息节点：
    当前任务头。

来源需求：
    当前任务来源需求。

任务虚拟存在：
    当前任务虚拟存在。

任务状态：
    当前任务状态。

选中自我能力值：
    普通任务来自任务选中能力或当前方法本能 ID；
    学习 / 练习补齐任务来自被补方法本能 ID，不冒充当前学习方法入口。

目标执行后值：
    来源需求目标状态的 I64 值。

执行差值：
    当前状态与目标执行后值可比较时计算。

安全因果搜索参数：
    继续使用已实现的安全因果因素搜索参数补齐规则。
```

暂不纳入第一版自动生成：

```text
不存在来源的现实对象指针；
未声明值域的枚举 / 状态值尝试序列；
需要学习方法内部构造的探索参数；
需要练习方法内部构造的练习参数；
路径候选代价 / 收益比较。
```

这些缺失时应返回参数缺口，而不是猜。

## 4. 实施切片

### P1 建立绑定器边界

新增普通函数：

```text
通用绑定候选方法输入参数_筹办
```

职责：

```text
读取绑定上下文；
写入通用实参；
调用明确的补齐规则；
检查必需形参；
输出绑定统计和首个缺口。
```

### P2 接入输入闭合流程

`尝试构造候选方法输入参数场景` 只负责：

```text
检查目标基础；
检查目标执行值是否可得；
创建输入参数场景和输入条件包；
调用通用绑定器；
根据绑定结果返回可执行或参数缺口。
```

### P3 保持学习 / 练习边界

```text
学习 / 练习任务与普通任务同样由绑定器闭合当前方法参数；
被学习 / 被练习的方法只作为 `目标方法头节点` 实参；
目标方法头展开、探索参数构造、练习参数构造仍发生在学习 / 练习方法动作内部。
```

### P4 后续增强

后续再分切片补：

```text
枚举 / 状态值有限序列候选；
指针参数从方法头子链 / 条件子链 / 当前场景子链取候选；
多候选确定性选择；
可选参数尽量补全；
学习 / 练习内部参数生成增强。
```
