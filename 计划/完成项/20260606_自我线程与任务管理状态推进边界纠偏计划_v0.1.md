# 自我线程与任务管理状态推进边界纠偏计划 v0.1

日期：2026-06-06

## 1. 目标

把自我线程与任务管理界面线程的任务生命周期边界重新收紧：

```text
自我线程只做需求侧治理、任务创建意图、真实执行动作前一次性许可、需求满足回写和价值结算。
任务管理界面线程独占任务生命周期状态裁决与提交。
任务管理工作线程执行任务筹办 / 任务执行普通函数。
工作项执行未结束前，不重复向自我线程申请同一工作项的执行许可。
```

## 2. 纠偏口径

自我线程可以表达：

```text
这个需求需要任务承接。
这个工作项在真实执行动作前是否允许执行。
这个观察事实已经承接，可能解除等待。
这个子需求 / 子任务结果已经返回，可能解除父任务等待。
这个任务完成后的价值结算已经完成。
```

自我线程不得表达：

```text
任务状态 = 筹办中。
任务状态 = 就绪。
任务状态 = 排队中。
任务状态 = 待重筹办。
任务状态 = 完成。
任务状态 = 已结算。
```

任务管理界面线程负责：

```text
创建任务节点和任务虚拟存在。
初始化任务状态。
根据任务当前状态、阶段、等待原因和回执事件裁决下一状态。
提交全部任务状态变化。
归并任务筹办 / 执行结果。
裁决等待、重筹办、完成、失败、挂起、取消、超时、已结算。
```

## 3. 当前需纠偏点

```text
1. 自我线程当前仍会构造结构_任务状态推进请求：
   - 完成 -> 已结算；
   - 父任务等待解除 -> 待重筹办；
   - 观察事实更新触发来源需求任务 -> 待重筹办；
   - 观察事实更新触发安全根任务 -> 待重筹办。

2. 自我主循环仍调用任务管理界面线程的巡检派发入口。

3. 任务管理界面线程仍存在调用者线程同步 fallback：
   worker 池未运行时，由调用者线程消费任务调度队列。

4. 执行前门控语义仍需要收束为一次性工作项许可，
   不应覆盖筹办、重筹办、等待、完成、失败等普通状态推进。
```

## 4. 实施切片

### P0 规范先行

修改：

```text
规范/自我线程与任务管理线程权责边界规范20260512.md
规范/任务筹办与执行边界规范20260512.md
```

写明：

```text
自我线程不得发送带目标任务状态值的推进请求。
自我线程只发送任务生命周期事件。
任务状态值只能由任务管理界面线程裁决。
执行前许可只在真实动作执行前发生一次。
同一工作项执行未结束前不得重复审批。
```

### P1 协议拆分

把跨线程公共请求从“状态推进请求”拆成事件型请求：

```text
观察事实更新任务唤醒通知
父任务等待条件变化通知
任务价值结算完成通知
执行前许可请求
执行前许可结果
```

`结构_任务状态推进请求` 降级为任务管理界面线程内部提交结构，或者至少禁止自我线程直接构造。

### P2 自我线程改造

替换自我侧所有 `提交任务状态推进请求` 调用。

要求：

```text
自我线程不再写建议任务状态。
自我线程不再写建议任务阶段。
自我线程不再写写入任务状态 / 写入任务阶段。
自我线程只投递事件和执行前许可结果。
```

### P3 任务管理界面线程接管状态裁决

任务管理界面线程收到事件后内部裁决：

```text
观察事实更新 -> 是否进入待重筹办或保持等待。
父任务等待解除 -> 是否进入待重筹办或保持等待。
价值结算完成 -> 是否允许完成 -> 已结算。
终态任务 -> 是否跳过。
等待中任务 -> 是否保持等待、挂起或重筹办。
```

### P4 执行前一次性审批

任务管理准备派发执行工作项时，向自我线程申请一次许可：

```text
任务ID
工作项ID
当前方法
输入参数场景
治理帧版本
```

自我线程返回：

```text
允许执行
禁止执行
挂起等待
```

许可绑定 `工作项ID`。工作线程未结束前，不重复审批同一工作项。

### P5 移除同步 fallback

拆分任务管理界面线程入口：

```text
允许自我线程调用：
    提交任务创建意图。
    提交执行前许可结果。
    提交任务生命周期事件。
    提取任务管理上行消息。

禁止自我线程调用：
    消费任务调度队列。
    调用任务筹办普通函数。
    调用任务执行普通函数。
```

如果任务管理 worker 未启动：

```text
记录错误或保持阻塞。
不得在自我线程同步 fallback 执行任务调度队列。
```
