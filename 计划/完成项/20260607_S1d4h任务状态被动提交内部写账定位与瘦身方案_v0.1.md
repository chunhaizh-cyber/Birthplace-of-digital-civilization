# S1d-4h 任务状态被动提交内部写账定位与瘦身方案 v0.1

日期：2026-06-08

## 1. 目标

```text
继续优化 S1d-4g 之后的 `执行被动提交` 内部成本。

保持：
    任务状态变化必须通过任务域被动状态提交动作入口；
    动作来源方法固定为 提交任务状态变化；
    动作语义固定为 被动动作；
    每次真实状态 / 阶段变化仍生成任务状态动作动态；
    状态值、动作动态、任务壳快照和 worker 派发顺序一致。

本切片只做最小瘦身：
    首次成功确认 `提交任务状态变化` 来源规格后，
    后续同一方法首节点走来源规格快路径，
    不再每次重复确保方法虚拟存在、确认规格和同步方法节点到虚拟存在。
```

```text
    真实日志已输出 任务状态动作动态=<动态主键>；

```

## 3. 代码判断

```text
`提交任务状态被动动作` 的重路径包括：
    1. 确认任务状态被动提交来源规格；
    2. 取或创建任务虚拟存在；
    3. 完成态推进特征同步和目标检查；
    4. 写任务状态 / 阶段；
    5. 创建旧状态节点、新状态节点和方法动作动态；
    6. 回写 任务状态动作动态 / 动作动态 两个指针特征。

其中 4/5/6 是每次真实状态动作动态的核心账，不能为提速删除。
完成态检查只在完成状态提交发生，不能跳过。
本切片优先处理 1：来源规格确认的重复方法虚拟存在确保和同步。
```

## 6. 实施步骤

```text
S1d-4h-1：
    在 `确认任务状态被动提交来源规格` 中增加进程内方法首节点确认缓存。
    缓存命中时仍校验方法首节点动作句柄合法，
    但不再调用 `方法虚拟存在()`、`确认提交任务状态变化规格()`、
    `方法虚拟存在服务类::同步方法节点到虚拟存在()`。

S1d-4h-2：
    构建 Debug x64。

S1d-4h-3：
    真实运行 `--self-check-log --self-check-log-wait-ms=10000`。

S1d-4h-4：
    用日志核对正向和负向证据。
```

