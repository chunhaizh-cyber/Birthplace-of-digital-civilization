# 安全因果链反推当前场景特征值需求纠偏计划 v0.1

## 1. 纠偏目标

本计划核对并纠偏“用因果链反推需求”的安全场景影响链。

目标链路为：

```text
自我安全值需要达标
<- 风险安全层明确
<- 场景影响部分可用
<- 当前场景风险安全值明确
<- 当前场景已确认存在集合明确
<- 各存在风险安全值明确
<- 各存在当前特征值明确 / 历史动态可读 / 因果证据可读 / 自我关键特征变化观察明确
```

关键结论为：

```text
当前场景中存在的特征值未知
-> 各存在风险安全值不能评估
-> 当前场景风险安全值不能明确
-> 风险安全_场景影响部分不能明确
-> 风险安全层不能合法聚合
-> 自我安全值不能合法判断
```

因此应生成缺口：

```text
缺口：当前场景特征值明确状态 未满足
来源因果：自我安全值 -> 风险安全层 -> 场景影响部分 -> 场景风险安全值 -> 场景存在特征值
```

然后由提交入口正式生成需求：

```text
需求：当前场景特征值明确
```

## 2. 最新规范核对

### 2.1 020005 已给出完整反推链

`需求临时因果视图展开规范20260526.md` 已明确：

```text
自我安全值需要达标
-> 风险安全层需要明确
-> 风险安全_场景影响部分需要明确
-> 当前场景风险安全值需要明确
-> 当前场景已确认存在集合需要明确
-> 当前场景各存在风险安全值需要明确
-> 当前场景各存在当前特征值需要明确
-> 当前场景特征值未知
-> 生成缺口：当前场景特征值明确状态 未满足
-> 经提交入口生成需求：当前场景特征值明确
```

并已给出后续逻辑组织：

```text
需求：当前场景特征值明确
└── OR组：特征值获取路径
    ├── D455外设观察确认路径
    │   ├── 当前观察特征帧取得
    │   ├── 外设观察材料可回查
    │   ├── 外设像素簇候选已验证
    │   ├── 外设观察存在候选确认方案已取得
    │   └── 已确认观察存在已提交入账
    ├── 读取已有场景缓存路径
    └── 交互者直接说明路径
```

因此用户提出的反推链路与最新规范一致。

### 2.2 050003 明确边界：风险树反推不是对象方法

`基础观察事实可用与基础风险判断分层规范20260526.md` 已明确：

```text
建立过程为安全因果反推算法步骤，不是对象作用方法，也不是提交入口。
运行期风险树由自我线程侧维护段持有和更新。
任务筹办只有使用权，只能读取已有因果信息 / 已有风险树视图形成缺口报告、派生需求消息草案或参数化搜索输入草案。
任务筹办不得刷新树视图、创建风险树节点或写同步状态。
```

因此“任务筹办按因果反推”在最新规范下应收束为：

```text
自我线程 / 临时因果视图维护段反推风险树和缺口；
任务筹办读取已有因果视图和已入树需求，继续筹办方法、参数和执行条件；
正式子需求仍由提交入口裁决入树。
```

### 2.3 020003 约束 OR 组不能写入需求主信息

`需求树生长机制规范20260512.md` 和 `需求临时因果视图展开规范20260526.md` 均明确：

```text
OR组、方法路径组和因果子链语义只能由普通需求节点目标抽象特征、逻辑组织只读视图和提交入口校验承载。
不得新增需求主信息字段。
```

所以 `当前场景特征值明确` 的后续分解不能写成一批固定布尔字段堆在需求主信息里，而应生成目标明确的普通需求节点和逻辑组织视图。

## 3. 代码核对结论

### 3.1 已经实现的部分

`自我线程模块.impl.cpp` 中 `私有_维护安全因果风险树_线程侧` 已从安全根需求读取：

```text
来源需求
目标宿主
目标特征
当前状态 / 目标状态
需求目标比较
来源因果
```

当缺少来源因果时，它会确保遗传来源：

```text
自我安全值目标 <- 风险安全层明确状态
```

随后生成风险安全层 v1 的五个因素节点：

```text
场景影响
运行影响
资源影响
权限影响
未知影响
```

其中场景影响节点已能检查：

```text
当前场景特征值明确状态 != 已明确
```

并生成缺口消息，日志来源路径为：

```text
自我安全值->风险安全层->场景影响部分->当前场景风险安全值->场景存在特征值
```

该缺口会经自我线程侧统一入口提交：

```text
自我线程/安全因果风险树缺口提交入树
使用提交_生成缺口子需求=1
不执行搜索=1
不写默认满足=1
不写因素值=1
不写风险安全层总值=1
不写自我安全值=1
不结算价值=1
```

这与当前规范的边界一致。

### 3.2 任务筹办侧边界已经收紧

`任务模块.筹办.ixx` 中旧风险树维护入口现在直接跳过：

```text
原因=任务筹办无安全因果风险树更新权
更新持有者=自我线程
任务筹办更新权=0
不执行搜索=1
不写默认满足=1
不写因素值=1
不写风险安全层总值=1
不写自我安全值=1
```

这说明最新代码已经避免让任务筹办裸刷风险树，符合规范。

### 3.3 已登记的需求目标材料

`特征类.cpp` 和 `需求类.cpp` 已登记：

```text
当前场景特征值明确状态
场景存在集合明确状态
当前观察特征帧取得状态
当前场景各存在安全评估明确状态
```

其中 `当前场景特征值明确状态` 已可作为正式需求目标特征。

### 3.4 尚未完成的部分

当前代码仍存在以下缺口：

1. 反推链只在缺口原因字符串中完整表达，风险树节点本身还没有逐级保存：

```text
风险安全层明确
场景影响部分可用
当前场景风险安全值明确
当前场景已确认存在集合明确
各存在风险安全值明确
各存在当前特征值明确
```

2. `当前场景特征值明确` 需求尚未自然展开为 OR 获取路径。

当前规范要求的路径：

```text
当前观察特征帧取得
外设观察材料可回查
外设像素簇候选已验证
外设观察存在候选确认方案已取得
已确认观察存在已提交入账
当前场景存在集合明确
当前场景各存在特征值可读
```

其中代码已实现若干执行材料：

```text
当前观察特征帧取得状态
D455短期观察材料页 / 解析D455观察材料句柄
自我_验证外设观察像素簇候选
自我_确认外设观察存在候选
提交_确认观察存在事实
场景存在集合明确状态
```

但以下需求目标或逻辑路径尚未形成统一入树链：

```text
外设观察材料可回查
已确认观察存在已提交入账
当前场景各存在特征值可读
```

3. `当前场景各存在特征值可读` 还没有明确值域、合法生产者和提交边界。

这一项不能简单等同于：

```text
存在集合明确
观察像素簇已验证
已确认观察存在已创建
```

它必须表示：

```text
已确认存在在当前场景中具有可用于风险评估的当前特征值材料。
```

4. 当前风险树只生成单个 `当前场景特征值明确` 缺口，尚未把 `当前场景已确认存在集合明确`、`各存在风险安全值明确`、`关键特征变化观察明确`、`历史动态 / 因果证据可读` 作为同一因果子链上的分层缺口视图。

5. `评估存在风险安全值` 仍需要配合前序计划修正：缺少当前特征值和证据时，不得返回零风险且明确。

## 4. 纠偏后的目标形态

### 4.1 反推链表达

风险树或临时因果视图中应能表示：

```text
根目标：
    自我安全值 达标

因果子链：
    自我安全值 达标
    <- 风险安全层 明确
    <- 场景影响部分 可用
    <- 当前场景风险安全值 明确
    <- 当前场景已确认存在集合 明确
    <- 各存在风险安全值 明确
    <- 各存在当前特征值 明确
```

每一层至少应保留：

```text
目标宿主
目标特征类型
当前状态 / 当前值
目标状态 / 目标值
来源因果
上级目标
缺口状态
允许生成需求状态
```

### 4.2 缺口生成

当各存在当前特征值未知时，缺口应为：

```text
目标宿主：当前场景
目标特征：当前场景特征值明确状态
当前状态：未明确
目标状态：已明确
来源因果：自我安全值 -> 风险安全层 -> 场景影响部分 -> 场景风险安全值 -> 场景存在特征值
生成类型：因果子链支撑 / 条件补齐
提交入口：提交_生成缺口子需求 或统一需求树更新提交入口
```

### 4.3 后续 OR 获取路径

`当前场景特征值明确` 入树后，应继续展开：

```text
当前场景特征值明确
└── OR组：特征值获取路径
    ├── D455观察确认路径
    ├── 读取已有场景缓存路径
    └── 交互者说明路径
```

D455 路径第一版为：

```text
当前观察特征帧取得
-> 外设观察材料可回查
-> 外设像素簇候选已验证
-> 外设观察存在候选确认方案已取得
-> 已确认观察存在已提交入账
-> 当前场景存在集合明确
-> 当前场景各存在特征值可读
```

该路径的每一步都必须是合法生产者写入的特征值，不得由控制面板、任务筹办或日志摘要反向猜测。

## 5. 纠偏实施切片

```text
将用户给出的六步反推链映射到现有特征、状态和风险树节点。
```

输出：

```text

风险安全层明确状态

验收：

```

### P1 补齐 `当前场景特征值明确` 的 OR 获取路径目标

目标：

```text
把 D455观察确认 / 已有场景缓存 / 交互者说明 建成逻辑组织视图，而不是新增需求主信息字段。
```

第一版先补 D455 路径：

```text
当前观察特征帧取得
外设观察材料可回查
外设像素簇候选已验证
外设观察存在候选确认方案已取得
已确认观察存在已提交入账

```

验收：

```text
OR组语义可在需求树摘要 / 控制面板只读视图中看到；
需求主信息不新增 OR 字段；
每条路径能追溯来源因果和获取途径。
```

### P2 补 `外设观察材料可回查` 目标

目标：

```text
D455短期观察材料页 / d455:// 句柄解引用结果成为正式可比较目标。
```

验收：

```text
材料句柄为空、过期、未找到、材料未就绪时，不能写可回查。
解析D455观察材料句柄成功且必要材料齐备时，才可写可回查。
可回查只表示材料可读，不表示存在已确认、风险明确或安全值增加。
```

### P3 补 `已确认观察存在已提交入账` 目标

目标：

```text
把 提交_确认观察存在事实 的提交状态转成可比较需求目标。
```

验收：

```text
只有提交入口成功或部分成功时，才能推进该目标。
自我_确认外设观察存在候选 仍只输出确认方案，不创建观察存在。
外设报告、簇候选、验证通过结果不得直接满足该目标。
```

### P4 定义并实现 `当前场景各存在特征值可读`

目标：

```text
明确哪些当前特征值可用于 G5 的存在风险安全值评估。
```

第一版可读材料：

```text
在当前场景中
ROI / 掩码 / 像素归属
深度 / 点集 / 空间候选
位置 / 距离 / 尺寸 / 相对方向
稳定性 / 遮挡 / 接触 / 进入边界
```

边界：

```text
不把“已确认存在”直接等于“所有特征值可读”。
不把“读取已有快照”冒充“外设新观察”。
不把 D455 材料直接写成风险明确。
```

### P5 让当前场景特征值明确需求自然展开

目标：

```text
当前场景特征值明确 入树后，
由临时因果视图 / 获取途径规则生成 OR 获取路径子需求草案，
再由提交入口正式入树。
```

验收：

```text
需求树不再只显示一个孤立的 当前场景特征值明确状态。
能看到 D455观察确认路径 或其他 OR 路径。
路径子需求完成后，父需求可重筹办。
```

### P6 接回场景风险安全值评估

目标：

```text
当前场景各存在特征值可读后，
安全_评估当前场景安全性 才能消费这些材料生成存在风险安全值和当前场景风险安全值候选。
```

验收：

```text
缺特征值 -> 评估不明确 / 材料缺口。
有特征值但无搜索 -> 不默认满足。
搜索完成且无负向证据 -> 可走默认满足提交。
候选值不越级写自我安全值。
```

## 6. 建议下一步

下一步先做 P0 + P1：

```text
先把反推链每一层补成可回查节点映射；
再让 当前场景特征值明确 需求展开 OR 获取路径。
```

这样才能把当前“一个缺口节点 + 原因字符串”的实现，推进为真正可筹办、可执行、可回写的因果子链。
