# 追根因：自我初始场景子链混入内部治理信息

当前现象：
SQL 投影中 `Ez 自我初始场景` 的直接子链包含内部治理对象和治理事实，例如 `任务可执行输入_*` 内部世界场景、`本能动作运行虚拟存在`、任务虚拟存在状态、方法调用动作动态和因果节点。

最高优先级原因：
不是单纯 SQL 关系表误挂。`世界树类.cpp` 的 SQL 投影按真实世界树子链递归收集，`父节点主键` 来自递归父节点；因此 `父节点主键=Ez` 说明快照时内存世界树中这些节点就是 `Ez` 的直接子节点。

当前层级：
L2 本地事实写入层。

同层疑点记录：
1. `任务模块.筹办.ixx::创建任务可执行输入参数场景` 使用 `任务类::解析任务场景` 作为父节点；任务场景为 `Ez` 时，内部输入参数场景直接挂到现实场景。
2. `任务模块.执行.ixx::私有_创建方法调用动作动态_执行桥_最小_v0` 固定使用 `世界树.自我所在场景` 创建方法调用动作动态，主体为 `自我存在`，导致治理过程动态进入 `Ez`。
3. `本能动作管理类.ixx::本能动作运行结果宿主` 在没有方法虚拟存在时退到 `输出结果场景`，导致 `本能动作运行虚拟存在` 可直接挂到 `Ez`。

选中下钻分支：
先修正上述三个写入父节点选择点；不做数据库搬迁，不把 SQL 投影作为业务权威。

主链判断：
内部治理状态、动态和运行存在应存自我内部世界或治理虚拟存在内部世界；外部场景事实和自我外设空间事实才允许进入自我所在场景。

已确认事实：
- `规范/动态信息分层获取与聚合规范20260430.md` 规定需求 / 目标 / 任务 / 方法 / 方法执行实例记录到自我内部世界。
- `规范/自我所在场景认知工作区规范20260525.md` 规定自我所在场景不是所有信息仓库，根层不得摊开内部治理过程。
- `世界树类.cpp` SQL 投影递归真实子链，当前证据更像写入父节点错误，不是 SQL 关系目标误投影。

已排除：
- 暂不认定所有 `Ez` 下动态非法；自我外设空间状态和场景事实仍可合法记录在当前场景。
- 暂不做历史数据库数据迁移；本切片只修正后续写入。

当前结论：
本次问题不是单纯数据库关系表投影错误，而是多个写入入口把内部治理对象、治理状态或治理动态直接挂到了自我所在场景。SQL 投影按内存世界树子链递归生成，因此数据库暴露的是上游入树父节点选择错误。
