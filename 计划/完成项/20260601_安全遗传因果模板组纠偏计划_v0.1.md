# 安全遗传因果模板组纠偏计划 v0.1

## 1. 纠偏目标

本计划核对并纠偏安全侧第一批遗传因果模板 G1-G6 的规范和代码落点。

目标不是新增一张“安全因素定义表”，也不是把一组固定布尔状态写进需求树，而是把自我定义自然推出的安全因果链初始化为现有因果信息：

```text
来源类型 = 遗传
形态 = 抽象因果模板 / 根闭环因果信息
用途 = 反推缺口、解释路径、初始化搜索规则
禁止 = 直接生成需求、直接创建任务、直接写安全值、直接结算价值
```

第一批模板为：

```text
G1 自我安全值由多层安全因果链聚合
G2 风险安全层由同层因素平分聚合
G3 场景影响部分由当前场景风险安全值影响
G4 当前场景风险安全值由当前场景已确认存在集合产生
G5 存在风险安全值由该存在当前特征值和历史因果证据评估
G6 观察当前场景可以获得当前场景特征值材料
```

这些模板只提供冷启动路线图。它们必须可被后天事实、动作动态、观察证据、因果归因和无负向证据搜索结果强化、削弱、分化或覆盖。

## 2. 规范核对结论

### 2.1 006 主规范已经支持 G1-G6 的上位口径

`自我存在服务与生存基本因果闭环规范20260601.md` 已明确：

```text
定义本身只能生成遗传因果模板和根闭环因果信息，
不能直接生成当前主动需求；
当前主动需求必须来自这些因果信息在当前事实下反推出的闭环缺口。
```

安全侧已给出核心链：

```text
自我关键特征负向变化
-> 自我安全值下降

当前场景中的存在、状态、动作、关系
-> 可能造成自我关键特征变化
-> 可能影响自我安全值

当前场景风险安全值
-> 自我_风险安全_场景影响部分
-> 风险安全层
-> 自我安全值

当前场景风险安全值
<- 当前场景已确认存在集合
<- 各存在风险安全值
<- 各存在当前特征值 / 历史动态 / 因果归因证据 / 无负向证据搜索结果
```

这与 G3、G4、G5 一致。

### 2.2 050003 已明确写出 G1-G6

`基础观察事实可用与基础风险判断分层规范20260526.md` 已明确安全因果风险树链：

```text
自我需要维护自身安全值
-> 自我安全值依赖多层安全因果链
-> 风险安全层是第二层安全因果信息
-> 风险安全层 v1 由场景影响、运行影响、资源影响、权限影响、未知影响五个同层因素平分聚合
-> 风险安全_场景影响部分依赖当前场景风险安全值
-> 当前场景风险安全值依赖当前场景已确认存在集合及各存在风险安全值
-> 存在风险安全值依赖该存在当前特征值、历史动态、自我关键特征变化观察、因果归因证据和无负向证据搜索结果
-> 当前场景中相关特征值未知时，场景影响因果条件不可判断
-> 生成缺口报告：当前场景特征值明确状态 未满足
```

并已列出第一版遗传因果模板：

```text
G1: 物理安全、风险安全、第三层安全因果链、第四层安全因果链 ... -> 自我安全值
G2: 场景影响、运行影响、资源影响、权限影响、未知影响 -> 风险安全层
G3: 当前场景风险安全值 -> 自我_风险安全_场景影响部分 -> 风险安全层
G4: 当前场景已确认存在集合、各存在风险安全值 -> 当前场景风险安全值
G5: 存在当前特征值、关键特征变化观察、历史动态、因果归因证据、无负向证据搜索结果 -> 存在风险安全值
G6: 安全_观察当前场景 -> 当前观察材料 -> 候选存在 -> 候选验证 -> 候选确认 -> 提交确认观察存在事实 -> 当前场景存在集合和相关特征值可评估
```

因此用户提出的 G1-G6 与最新规范一致。

### 2.3 旧口径需要降级为 v1 模板，不可作为根规则

`自我根特征抽象定义与自检缺口规范20260523.md` 已说明：

```text
遗传因果 = 来源 / 归类口径为“遗传”的现有因果信息。
不得新增独立的 结构_遗传因果模板 主信息结构。
```

但旧文中仍有“条件不足取 I64_MAX / 4”“默认良好结果提交”等表达。按 006 和近期纠偏口径，这些只能保留为历史 v1 评估实现说明，不能覆盖以下新规则：

```text
未知不能直接扣分。
未知不能直接默认安全。
默认满足必须搜索完成且无负向证据。
候选视图不能写成正式安全值。
```

## 3. 代码核对结论

### 3.1 已有基础能力

`自我线程模块.impl.cpp` 已有遗传因果模板创建函数：

```text
私有_确保遗传因果模板_线程侧
```

它使用现有因果信息体系：

```text
因果形态 = 抽象
来源类型 = 遗传
主果比较模板
因比较模板
因方法模板
适用层级
```

日志已明确：

```text
后天验证=0
直接生成需求=0
直接创建任务=0
直接结算价值=0
```

`任务模块.筹办.ixx` 已能把遗传因果当作冷启动路线图使用，并生成正式派生需求消息草案；筹办侧也明确遗传因果不是后天结论。

### 3.2 当前只落了一个核心锚点，G1-G6 尚未成组初始化

当前安全风险树遗传来源主要确保：

```text
遗传因果.安全风险树.自我安全值依赖风险安全层明确
```

也就是：

```text
自我安全值目标 <- 风险安全层明确状态
```

这只是 G1/G2 之间的一个锚点，不等于 G1-G6 模板组已经完整入账。

当前缺口：

```text
G1 没有完整表达物理安全、风险安全、第三层、第四层等多层安全因果链。
G2 五因素平均主要是代码常量和掩码，不是可追溯的遗传因果模板组。
G3 场景影响部分已有候选和提交入口，但来源链还没有独立模板表达。
G4 当前场景风险安全值尚未明确映射为“已确认存在集合 + 各存在风险安全值”的因果模板。
G5 存在风险安全值评估仍是骨架，尚未真实读取存在当前特征值、历史动态、归因证据和无负向证据搜索结果。
G6 D455 / 外设观察链路已有方法链，但没有作为当前场景特征值明确需求的 OR 获取路径因果模板成组初始化。
```

### 3.3 G2 在代码中是硬编码 v1 公式

`自我动作实现.外设模块.ixx` 和 `自我线程模块.impl.cpp` 已有：

```text
风险安全层v1因素数量 = 5
场景影响 / 运行影响 / 资源影响 / 权限影响 / 未知影响 掩码
平均风险安全层v1因素 / 私有_平均风险安全五因素_线程侧
风险安全层投影候选 = 风险安全层候选 * 0.09
```

这说明 G2 的 v1 计算已有实现材料。

但现状仍偏“代码知道公式”，而不是“因果信息知道来源”。后续应把五因素同层集合版本、因素 ID、来源因果模板、搜索规则和入账状态绑定起来，避免需求树只看到一组状态名，看不到为什么需要这些因素。

### 3.4 G3-G5 在评估方法中仍偏候选视图

`安全_评估当前场景安全性` 已输出：

```text
风险安全_场景影响部分候选
风险安全层候选
风险安全层投影候选
风险因素未搜索 / 默认满足 / 已入账掩码
```

但它仍存在两个问题：

```text
1. 场景风险安全值、场景影响部分、风险安全层之间的因果模板没有成组初始化。
2. 存在风险安全值评估对“当前特征值 / 历史动态 / 归因证据 / 无负向证据搜索结果”的读取不完整。
```

尤其 `评估存在风险安全值` 目前在缺少关键证据时仍可能把未知表达成零风险且明确，这已经在“未知不能作为已安全证据”计划中列为纠偏点。

### 3.5 G6 的外设材料链路已有执行骨架

当前代码已有 G6 的若干执行材料：

```text
外设线程_D455深度相机
-> 外设观察报告队列 / D455短期观察材料页
-> 自我_验证外设观察像素簇候选
-> 自我_确认外设观察存在候选
-> 提交_确认观察存在事实
-> 写入已确认观察存在原始事实 / 动作动态 / 二次特征 / 当前场景索引
-> 场景存在集合明确状态
```

这些代码边界大体正确：

```text
候选验证不等于已确认观察存在。
确认方案不创建观察存在。
提交入口才创建 / 合并已确认观察存在。
提交入口不写基础风险明确，不结算安全值。
```

但 G6 还缺一层因果表达：

```text
外设材料
-> 候选验证
-> 候选确认
-> 提交确认观察存在事实
-> 当前场景存在集合明确
-> 当前场景相关特征值可用于评估
```

尚未作为 `当前场景特征值明确` 的 OR 获取路径成组初始化。并且目标级 `获取特征值` 仍不是已闭合默认本能方法，不能把已存在的材料读取误说成“已经能获取任意存在任意特征值”。

## 4. 纠偏后的模板语义

### 4.1 G1 多层安全因果链

模板语义：

```text
物理安全
+ 风险安全
+ 第三层安全因果链
+ 第四层安全因果链
+ ...
-> 自我安全值
```

权重口径：

```text
第一层 = 0.9
第二层 = 0.09
第三层 = 0.009
第四层 = 0.0009
```

落点：

```text
使用现有因果信息表达层级和来源。
层级权重由自我线程统一计算，任务管理侧不得随意填权重。
风险安全层只是第二层安全因果信息，不是安全值本体。
```

### 4.2 G2 风险安全层同层因素

模板语义：

```text
风险安全层 =
平均(
    场景影响部分,
    运行影响部分,
    资源影响部分,
    权限影响部分,
    未知影响部分
)
```

落点：

```text
第一版可保留五因素 v1。
必须带因素集合版本。
同层因素缺失时不能自动把已知因素放大权重。
未搜索 / 搜索缺口 / 默认满足 / 负向证据 / 已入账必须分开记录。
```

### 4.3 G3 场景影响部分

模板语义：

```text
当前场景风险安全值
-> 自我_风险安全_场景影响部分
-> 风险安全层
-> 自我安全值
```

落点：

```text
当前可映射到现有的 当前场景评估安全值候选 / 风险安全_场景影响部分候选。
除非现有字段无法表达，不新增说明性摘要字段。
候选值必须经提交入口和入账状态判断后，才可影响风险安全层正式聚合。
```

### 4.4 G4 当前场景风险安全值

模板语义：

```text
当前场景风险安全值
<- 当前场景已确认存在集合
<- 各存在风险安全值
```

落点：

```text
当前场景已确认存在集合来自提交入口确认的观察存在事实。
外设报告、像素簇、验证通过候选、确认方案都不是已确认存在集合。
多个存在属于同层输入时按平均或模板指定规则聚合。
```

### 4.5 G5 存在风险安全值

模板语义：

```text
存在风险安全值
<- 存在当前特征值
<- 自我关键特征变化观察
<- 该存在与自我之间的历史动态
<- 因果归因证据
<- 无负向证据搜索结果
```

落点：

```text
存在名不是风险依据。
存在当前特征值、历史动态、时间窗口、归因证据和搜索状态才是风险依据。
特征值未知必须落到材料缺口或搜索缺口，不能落成零风险且明确。
```

### 4.6 G6 当前场景观察材料链

模板语义：

```text
安全_观察当前场景
-> 当前场景观察材料
-> 当前场景候选存在
-> 当前场景特征值材料

外设材料
-> 候选验证
-> 候选确认
-> 提交确认观察存在事实
-> 当前场景存在集合明确
-> 当前场景相关特征值可用于评估
```

落点：

```text
D455 是 OR 获取路径之一，不是唯一来源。
读取已有场景缓存、交互者直接说明也可以成为 OR 路径，但都必须有来源、证据和提交边界。
D455 材料不能直接证明需求满足、风险明确或安全值增加。
```

```text

外设材料、候选验证、候选确认、提交确认观察存在事实边界保持不变。
不把读取已有快照冒充新观察动作。
不把 D455 材料直接写成风险明确或安全值增加。
```

### P6 修正存在风险安全值评估

目标：

```text
让 G5 真正消费特征值和证据，而不是只消费存在集合是否明确。
```

第一批可读特征值材料：

```text
是否在当前场景中
ROI / 掩码 / 像素归属
深度 / 点集 / 空间候选
位置 / 距离 / 尺寸 / 相对方向
稳定性 / 遮挡 / 接触 / 进入边界
自我关键特征变化观察
历史动态
归因证据
无负向证据搜索状态
```

验收：

```text
缺材料 -> 材料缺口或评估不明确。
查过且无负向证据 -> 可走默认满足提交。
发现负向证据 -> 进入风险值评估或处置链。
```


