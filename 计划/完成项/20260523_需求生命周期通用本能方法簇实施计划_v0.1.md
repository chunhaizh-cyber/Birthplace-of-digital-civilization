当前有效口径：

```text
筹办 = 判断和选择。
执行 = 做对象作用并验证结果。
提交 = 正式改账。
动态 = 留证据。

读定义、定位、读状态、比对、查缺口、查方法是筹办 / 执行普通算法步骤。
生成子需求、登记任务意图、创建任务、提交状态、回写满足、价值结算是提交入口。
服务 / 安全观察检查等才是任务真正可选择的对象作用方法。
```

因此：

```text
任务筹办不得把需求生命周期算法函数放入候选方法集。
执行验证不得把结果提取 / 结果比对函数注册为对象作用方法。
缺口入树必须走 提交_生成缺口子需求 或统一需求树更新提交入口。
需求满足回写必须走 回写需求满足。
```
