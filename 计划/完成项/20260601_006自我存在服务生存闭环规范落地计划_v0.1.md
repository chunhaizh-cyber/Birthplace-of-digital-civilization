## 2. 总目标

目标：

```text
让服务根需求可以初始化，
但裸服务必要条件不得自动成为当前主动任务；
只有通过服务事件、人类表达、外部请求、当前会话、已确认服务目标、服务动作结果缺口或明确因果定义支撑的节点，才允许进入服务链、需求树和任务链。
```

非目标：

```text
不删除特征定义、语素入口或历史日志。
不恢复任务筹办 / 任务执行为本能方法。
不新增模拟样本、伪造入口或伪造动作动态。
不在本计划内正式结算安全值 / 服务值。
不宣称自我苏醒完成、初步成熟完成或完整服务闭环完成。
```

## 3. 待确认问题

以下问题确认前，不进入代码修改：

```text
Q1. 启动期固定服务必要条件第一版保留哪些节点？
    建议保留：
        当前人类服务对象明确状态
        当前服务目标明确状态
    建议移出启动期固定必要条件：
        当前交互者明确状态

        交互者 / 权限者仅在服务事件需要身份、授权、多人区分或责任归因时进入链条。

    建议：
        服务根需求保留；
        服务链上下文为空；
        不生成当前服务上下文子需求；
        不创建方法头；
        不派生学习信息补齐需求。

Q3. `当前人类服务对象明确状态` 和 `当前服务目标明确状态` 是否也必须先有服务事件才入树？
    建议：
        是。没有服务事件时不主动生成；
        有人类表达 / 外部请求 / 当前会话输入但缺对象或目标时，才生成对应事实补全需求。

Q4. 安全 / 生存链是否采用同样“节点因果准入”闸门？
    建议：
        是，但本轮只落服务链最小版本；
        生存链只补规范口径，不改安全因果风险树已验证路径。

Q5. 当前计划索引中的 `当前交互者明确状态` 纠偏计划如何处理？
    建议：
        降级为本计划下的具体子切片；
        不再作为顶层主动计划。
```

### P3 服务链因果准入最小实现

目标：

```text
在服务必要条件生成 / 入树前增加最小因果准入判断。
```

第一版准入来源：

```text
服务事件存在；
人类表达存在；
外部请求存在；
当前会话输入存在；
已确认服务目标存在；
服务动作执行后的结果缺口存在；
根特征自检中有明确因果定义支撑。
```

第一版输出：

```text
有准入来源：
    允许对应服务链节点进入需求树。

无准入来源：
    记录服务上下文为空 / 等待外部输入；
    不生成当前交互者 / 当前权限者主动需求；
    不创建占位方法头；
    不派生泛化学习信息补齐需求。
```

验收：

```text
Debug x64 构建通过；
真实运行日志或只读快照能证明无服务事件时不会生成裸服务链任务。
```

### P4 当前交互者 / 权限者具体迁移

目标：

```text
把当前交互者明确状态、当前权限者明确状态从启动期固定服务必要条件改为条件触发节点。
```

触发条件：

```text
当前存在服务事件或会话输入；
本次服务目标需要身份 / 授权 / 多人区分 / 责任归因；
已有事实读取或等待外部输入路径。
```

验收：

```text
无服务事件时，不出现当前交互者 / 权限者主动任务；
有服务事件且需要身份或授权时，节点可以按因果准入进入链条。
```
