# S3a 日志分级批量 flush 最小方案 v0.1

日期：2026-06-07

## 1. 目标

```text
降低运行日志逐条 flush 对常驻路径的放大效应。
```

## 2. 依据

```text
日志模块.ixx 当前默认 每条刷新=true；
初始化项目日志 也强制 每条刷新=true；
S1d-4f 已把任务状态提交调用侧准备查找成本压低；
剩余动作函数耗时仍可能被日志同步落盘放大。
```

## 3. 边界

```text
1. 错误日志和致命日志必须立即 flush。
2. 普通运行信息日志改为批量 / 间隔 flush。
3. 不改变日志文本语义、不删除错误日志、不吞异常日志。
4. 不引入后台日志线程。
5. 不混入任务状态、需求满足、价值结算、外设或索引改造。
```

## 4. 最小实现

```text
在 日志参数 中增加：
    错误立即刷新；
    普通刷新间隔毫秒。

在 单文件日志器 中记录上次 flush 时间；
写一行 时：
    若 每条刷新=true，保持原行为；
    若 级别>=错误 且 错误立即刷新=true，立即 flush；
    普通 / 警告日志按刷新间隔 flush；
    关闭日志时仍关闭文件，触发最终落盘。

初始化项目日志：
    每条刷新=false；
    错误立即刷新=true；
    普通刷新间隔毫秒=250。
```

## 5. 验证预测

```text
构建：
    Debug x64 应通过。

真实运行：
    .\x64\Debug\鱼巢.exe --self-check-log --self-check-log-wait-ms=10000 应退出码 0。

日志：
    运行日志仍应持续写入；
    错误 / 致命日志仍走立即 flush 分支；
    普通日志不再每条 flush。

负向核对：
    不应出现 日志模块低级错误；
    不应出现 状态提交确认失败、后台worker工作项进入死信、拒绝归并完成项。
```
