## 1. 目标

将创建子任务相关流程图中的异常分支落到代码逻辑：

1. 字段不完整时，进入消息构造逻辑错误诊断和根因追查，不再作为普通“上报跳过”。
2. 稳定键重复时，保留幂等去重语义，但与字段缺失分离；若持续重复，必须留下可追生成源头的证据。
3. 派生需求入树证据不合法时，先按具体原因分类，再拒绝入树、改路由或弹错；不使用笼统“裁决拒绝入树”覆盖根因。
4. 候选目标与父需求目标重叠时，作为父子目标自复制保护和构造根因追查，不再作为正常“同目标停等”分支。
5. 同一父需求下已有同目标子需求仍是正常复用 / 幂等承接，不与父子目标自复制混在一起。

## 4. 执行切片

### P0 执行前断点与基线

允许修改文件：

- `实施记录/20260612_创建子任务异常分支代码逻辑修订_Codex断点清单.md`

动作：

1. 写入执行前断点：依据文件、当前分支、当前已改文件、禁止宣称项。
2. 记录三个待改分支的现状：字段不完整、稳定键重复、父目标重叠。
3. 若工作区已有无关改动，只记录并避开，不回滚。

验收：

- 断点清单只写真实已读、已改、已运行命令和当前判断。

### P1 字段不完整改为构造逻辑错误诊断

允许修改文件：

- `任务模块.管理工作线程.ixx`

动作：

1. 在字段完整性判断旁增加“缺失槽位列表”辅助函数。
2. 缺失槽位至少覆盖：父需求、派生需求类型、因果路径生成类型、阻塞级别、目标特征类型、目标主体、当前状态、目标状态、满足关系。
3. 字段不完整时记录 `任务管理工作线程/派生需求消息构造逻辑错误`，包含缺失槽位、任务、当前方法、执行尝试键、稳定键、消息文本、`直接写需求树=0`。
4. 保持不发送派生需求消息，但日志语义从普通跳过改为逻辑错误诊断。
5. 检查本模块现有弹错 / 错误日志入口；若已有线程侧逻辑错误弹错路径，按规范接入；若没有，先落错误日志并在断点中记录待接入口。

验收：

- 字段缺失不再只出现 `上报跳过 | 原因=字段不完整`。
- 日志能直接看出缺哪个槽位，以及是哪次任务筹办 / 方法上下文构造出来的消息。

### P2 稳定键重复改为幂等去重并保留追因证据

允许修改文件：

- `任务模块.管理工作线程.ixx`

动作：

1. 将重复来源拆分为：同批候选重复、响应内已包含、最近已上报缓存命中。
2. 对首个重复样本记录 `任务管理工作线程/派生需求消息幂等去重`，写出重复来源、稳定键、任务、消息摘要。
3. 汇总日志中保留各重复来源数量，不再只有一个 `重复消息`。
4. 不把稳定键重复直接作为错误；只有当真实运行持续重复且影响推进时，再进入生成源头根因追查。

验收：

- 稳定键重复与字段缺失在日志上可区分。
- 单次幂等重复不会误报为逻辑错误。
- 持续重复有稳定键和消息样本可追到生成源。

### P3 入树拒绝原因分类

允许修改文件：

- `自我线程模块.impl.cpp`

动作：

1. 在 `私有_确保派生需求节点` 内部建立局部拒绝 / 保护原因分类，优先用局部枚举或局部结构，不扩展跨线程协议字段。
2. 至少分类：缺父需求、父需求是结构根、来源因果不可解析、来源动态不可解析、贡献层级越界、当前状态缺失、目标状态缺失、目标特征缺失、外设内部材料字段误入普通需求、目标主体不可判定、父子目标自复制。
3. 对每类原因记录 `自我线程/派生需求入树原因分类`，包含原因码、父需求、目标主体、目标特征、当前状态、目标状态、来源因果、来源动态、消息摘要。
4. 对规范明确的逻辑错误继续走 `私有_提示派生需求逻辑错误` 或同级错误处理。
5. 外设内部材料字段不再只写普通“入树拒绝”，改写为边界字段误入普通需求。

验收：

- `新需求=null` 的每条入树失败都有明确分类日志。
- 不再只能从 `裁决拒绝入树` 猜原因。

### P4 父目标重叠改为自复制保护

允许修改文件：

- `自我线程模块.impl.cpp`

动作：

1. 替换 `派生需求同目标停等` 分支。
2. 父需求目标与候选目标重叠时，不调用 `任务类::标记任务等待`，不把关联任务或父任务改为正常等待。
3. 记录 `自我线程/父子目标自复制保护`，包含父需求目标键、候选目标键、目标主体、目标特征、目标状态、满足关系、来源任务、当前方法、派生消息稳定键。
4. 返回 `nullptr` 阻止入树，同时把原因分类为父子目标自复制。
5. 保留 `查找同目标子需求` 的正常复用逻辑。

验收：

- 父子目标重叠不再产生正常停等状态变化。
- 同父需求下已有同目标子需求仍可复用，不重复入树。

### P5 回执与日志口径收束

允许修改文件：

- `自我线程模块.impl.cpp`

动作：

1. 调整 `私有_收到派生需求消息时完善需求树` 的回执原因摘要。
2. `原因摘要` 只能作为人读摘要，不作为机器决策依据。
3. 当 `新需求=null` 时，摘要应区分：逻辑错误、边界字段误入、父子目标自复制保护、其他入树证据不合法。
4. `提交_生成缺口子需求` 日志增加原因分类，不只写 `成功=否`。

验收：

- 上层任务管理收到的回执不会把所有失败都看成同一种“拒绝入树”。
- 机器决策仍依赖结构化结果和本地分类，不依赖自由文本摘要。
