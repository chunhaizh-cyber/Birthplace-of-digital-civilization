## 3. 发现的不一致

### 3.1 根名不一致

新增基础抽象命名规则要求：

```text
存在类信息最高抽象 = 存在
根名 = 类型最高抽象名
```

当前 `基础信息类::取或创建存在概念根()` 使用：

```text
名称 = 存在概念根
类型 = 概念根
```

这应视为历史存储容器口径，不能继续作为最高抽象名。纠偏后，存在概念链最高节点应是：

```text
名称 = 存在
类型 = 存在
```

如果需要兼容旧节点，只能作为一次性迁移或读取别名处理，不得把 `存在概念根` 当作新的权威根名。

### 3.2 概念侧和实例侧边界不够显式

当前概念和实例都由 `存在节点主信息类` 承载，这是正确方向；但生成规则需要更明确：

```text
概念侧：
    存在根抽象 -> 上位抽象存在 -> 下位抽象存在

实例侧：
    场景 / 内部世界 -> 实例存在
    实例存在.概念集 -> 指向概念侧抽象存在
```

不得把实例直接挂到概念树下，也不得把概念节点当作实例事实账本。

### 3.3 类型字段策略需要纠偏

当前 `世界树类::确保存在概念()` 在类型为空时写：

```text
类型 = 名称
```

当前 `存在类::创建存在实例()` 写：

```text
类型 = nullptr
```

按现行口径应纠偏为：

```text
概念节点：
    名称 = 显示概念名
    类型 = 上位抽象归属；根节点为 存在

实例节点：
    名称 = 可选显示名，允许为空
    类型 = 主概念 / 抽象归属
    概念集 = 一个或多个抽象存在归属
```

### 3.4 归类证据链尚未形成纠偏入口

当前 `概念集` 已能支持快速查找，但规范要求：

```text
概念集 = 快速匹配缓存
归类证据 = 二次特征 / 状态 / 动态 / 场景 / 因果证据
```

因此概念集新增、删除、替换、冲突处理不能只靠字符串、名称或临时判断完成，必须能回查项目结构证据。

### 3.5 概念扩充实例记忆缺少冲突处理规则

当前 `根据概念扩充实例记忆()` 会把概念侧特征结构扩充到实例。后续需要明确：

```text
缺失特征：
    可按概念默认槽位补入。

已有实例特征：
    以实例事实为准，不被概念默认值静默覆盖。

冲突特征：
    生成纠偏证据或纠偏任务，不直接吞掉。
```

### 3.6 读取路径存在隐式确保

当前 `读取自我初始化结果()` 最终会触发 `初始化存在概念系统()`。这和“只读读取”和“显式确保”必须区分的硬规则冲突，应拆分为：

```text
读取路径：
    只读取当前是否已存在、是否已绑定、是否已就绪。

确保路径：
    允许创建根概念、核心概念、默认槽位和语素绑定。
```

## 4. 目标状态

目标不是新增一套“抽象存在结构”，而是把现有存在树分成两个清晰用途：

```text
概念侧存在树：
    根抽象 = 存在
    承载抽象存在、概念模板、概念层级、默认特征槽

实例侧存在树：
    根容器 = 场景 / 自我内部世界 / 现实世界
    承载具体存在实例、实例特征、实例状态、实例动态

连接关系：
    实例存在.概念集 / 概念模板
        -> 指向概念侧抽象存在

纠偏证据：
    二次特征 / 状态 / 动态 / 场景 / 因果链
        -> 说明为什么归入、为什么移除、为什么冲突
```

生成标准形式：

```text
在某类场景中，
根据候选存在的特征、状态、动态和来源证据，
选择一个或多个抽象存在概念，
创建或修正实例存在，
写入实例类型和概念集，
再按概念默认槽位补齐缺失特征。
```

## 6. 分阶段计划

### P0 现状审计

目标：先确认当前运行时实际生成了哪些概念根、核心概念和实例节点。

检查项：

```text
1. 搜索所有创建“存在概念根”“概念根”“存在”的代码路径。
2. 检查 初始化存在概念系统() 是否会重复创建或复用旧节点。
3. 检查控制面板 / SQL 显示是否依赖“存在概念根”文本。
4. 检查实例创建入口是否都走 世界树类::创建存在实例 或 存在类::创建存在实例。
5. 检查是否有代码把概念节点当作实例事实账本写状态、动态或安全评估。
```

输出：

```text
现状审计记录
需要兼容的旧节点清单
允许修改文件清单
禁止修改范围
```

### P1 纠正根抽象命名

目标：把存在概念链最高节点统一为 `存在`。

实施要点：

```text
1. 调整 基础信息类::取或创建存在概念根() 的创建口径：
       名称=存在
       类型=存在

2. 如果已有旧节点“存在概念根”，仅作为迁移查找来源：
       优先查找 名称=存在, 类型=存在
       找不到时查找旧节点
       迁移或复用后不得继续新建“存在概念根”

3. 选择信息入口默认根仍可返回同一个概念侧根节点，
   但语义上它是“存在”根抽象，不是“存在概念根”根名。

4. 更新函数注释和文档说明，避免继续把“存在概念根”当最高抽象。
```

验收：

```text
运行初始化后，概念链最高节点只有一个权威根：名称=存在，类型=存在。
规范和代码中不再把“存在概念根”作为最高抽象名。
```

### P2 明确概念侧生成规则

目标：让抽象存在节点沿 `存在` 根抽象链生成，而不是散落为文本标签。

实施要点：

```text
1. 世界树类::确保根概念_存在() 直接命中根抽象节点。
2. 子概念由 世界树类::确保存在概念(名称, 父概念) 创建。
3. 概念节点唯一性按同一概念侧父链下 名称 + 类型 判断。
4. 概念节点 类型 写上位抽象归属；根节点 类型=存在。
5. 概念节点不得记录动态历史、安全评估、伤害记忆、任务账务值。
```

建议纠偏：

```text
当前 类型=名称 的写法改为：
    if 根概念:
        类型=存在
    else if 父概念有效:
        类型=父概念的名称或父概念对应类型入口
    else:
        类型=存在
```

验收：

```text
实物存在 / 虚拟存在 / 信息存在 的上位归属可回到 存在。
需求 / 任务 / 方法 的上位归属可回到 虚拟存在。
状态 / 事件 / 规则 的上位归属可回到 信息存在。
```

### P3 明确实例存在树生成规则

目标：从抽象存在生成具体实例时，实例进入场景树，抽象归属进入概念集。

实施要点：

```text
1. 创建实例时必须先确定所属场景：
       外部现实对象 -> 现实场景 / 当前观察场景
       自我内部对象 -> 自我内部世界
       任务 / 方法 / 需求虚拟存在 -> 对应内部世界或治理场景

2. 创建实例时写：
       名称 = 可选显示名，可为空
       类型 = 主抽象归属
       概念集 = 主概念 + 其他适用抽象概念

3. 实例默认不按名称全局复用。
   需要去重时必须通过场景、特征、状态、观察证据或因果证据判断。

4. 实例不得挂在概念侧父节点下。
   概念树只承载抽象存在，实例树只承载事实存在。
```

验收：

```text
给定抽象概念“任务”，创建出的任务实例位于自我内部世界或任务治理场景。
给定抽象概念“杯子”，创建出的杯子实例位于现实/观察场景。
实例概念归属可通过 概念集 查询，实例事实可通过场景树查询。
```

### P4 建立归类和纠偏规则

目标：让“抽象存在 -> 实例存在”的归类可解释、可撤销、可纠偏。

归类输入：

```text
场景类型
候选存在的已知特征
候选存在的状态值
候选存在的动态历史
观察来源或任务来源
因果模板适用证据
```

归类输出：

```text
实例存在
主概念
附加概念集
归类证据
冲突或缺口
```

纠偏类型：

```text
缺概念：
    证据足够但实例未加入对应概念集。

错概念：
    实例概念集包含与证据冲突的概念。

旧概念：
    概念曾经成立，但当前场景 / 状态 / 动态证据已失效。

重复概念：
    同一上位链下多个等价概念重复命中。

冲突概念：
    多个概念的必要特征或值域互斥。
```

纠偏原则：

```text
1. 概念集只作为缓存更新。
2. 纠偏理由必须落到二次特征、状态、动态、场景或因果证据。
3. 不能用自由文本、日志、临时 JSON 或说明字段冒充归类依据。
4. 不确定时生成缺口或纠偏任务，不静默覆盖。
```

### P5 纠正概念扩充实例记忆

目标：概念默认槽位只补缺，不覆盖实例事实。

实施要点：

```text
1. 从概念集收集上位概念时保持去重和稳定顺序。
2. 复制默认特征槽时只复制特征类型和必要值域。
3. 指针类当前值、运行状态、动态历史不从概念复制到实例。
4. 实例已有同类型特征时不静默覆盖。
5. 发生值域或默认值冲突时写纠偏证据，必要时生成纠偏任务。
```

验收：

```text
实例从“任务”概念获得任务状态槽位，但不继承某个抽象任务的运行历史。
实例从“杯子”概念获得可观察特征槽位，但不继承另一个杯子的当前位置值。
```

### P6 拆分只读和确保路径

目标：诊断读取不再隐式创建概念节点。

实施要点：

```text
1. 自我初始化结果读取路径改为纯只读：
       只检查已存在结构，不调用 初始化存在概念系统()

2. 显式初始化 / 修复路径保留确保行为：
       初始化存在概念系统()
       初始化核心存在概念树()
       绑定核心概念语素()

3. 命名上区分：
       读取...
       检查...
       确保...
       初始化...

4. 诊断、控制面板、验收读取不得通过只读路径创建结构。
```

验收：

```text
调用 读取自我初始化结果() 前后，节点数量不发生变化。
调用 初始化存在概念系统() 才允许创建缺失概念结构。
```

```powershell
python .\tools\生成函数功能说明文档.py
```

## 8. 禁止范围

```text
1. 不新增 抽象存在主信息类。
2. 不新增 枚举_存在形态 作为归类主机制。
3. 不用字符串签名、日志、说明字段、临时 JSON 承载机器判断。
4. 不把概念集当成归类证据本体。
5. 不把抽象存在节点当动态历史、任务账务、安全评估或伤害记忆账本。
6. 不把实例挂入概念侧父链。
7. 不让读取函数隐式创建结构。
8. 不把“存在概念根”继续解释成最高抽象名。
```

## 9. 最小执行顺序

推荐按以下闭合切片推进：

```text
S1 根名纠偏
    只处理 存在 / 存在概念根 命名和兼容读取。

S2 类型字段纠偏
    只处理概念节点和实例节点的 类型 写入规则。

S3 实例生成链纠偏
    只处理创建实例时的场景归属、概念集和主概念写入。

S4 只读 / 确保边界纠偏
    只处理读取初始化结果不再隐式确保。

S5 概念扩充和冲突处理
    只处理默认槽位补缺、冲突记录和纠偏入口。

S6 回归和图谱更新
    补实施记录、函数说明、必要工程图谱和规则原子索引。
```

每个切片完成后单独提交，不混入当前主动队列或其他未提交改动。
