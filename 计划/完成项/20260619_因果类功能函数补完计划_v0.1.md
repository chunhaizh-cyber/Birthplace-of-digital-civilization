# 因果类功能函数补完计划 v0.1

日期：2026-06-19

## 0. 定位

用户口径：

```text
因果类中结构体已经清完。
以后所有涉及因果信息的操作，都必须调用因果类中的功能函数。
```

本计划只补 `因果类` 功能函数和迁移调用方，不恢复已删除的因果结构体、目标投影枚举、状态转换因果边类型等旧抽象。

## 2. 硬约束

```text
1. 不新增因果 wrapper 结构体；函数使用直接参数和调用方提供的输出引用。
2. 不恢复 枚举_目标投影维度、枚举_目标权重类型、枚举_状态转换因果边类型。
3. 不新增因果作用类型、因果确定性、置信度、成功率、时间窗口等主信息字段。
4. 不以字符串、日志文案、规则名、幂等键作为机器判断依据；字符串只允许用于主键查找、动作语义键现有字段和临时验证输出。
5. 因果类不直接写任务状态、需求满足、安全值、服务值；只提供解释、预测、反推、审查、验收、结算证据和稳定度依据。
6. 主动动作能力从方法系统获取；被动动作因果不得被任务筹办反推为可调用方法。
7. 安全、服务、学习、自维护只作为从世界状态转换因果树生成的只读投影视图，不写成因果主信息类型。
8. 新建函数前必须扫描 说明书/函数功能说明文档.md；新增、删除或改名函数后运行 python .\tools\生成函数功能说明文档.py。
9. 涉及自定义项目类型的函数放入 因果类.h/.cpp，不放入 全局共享函数类.ixx。
10. 每个闭合切片只提交本切片相关文件。
11. 因果类功能函数不返回“摘要”作为机器结果。
12. 日志、控制面板、SQL 展开和显示层不作为本计划的正式补完目标；确需观察时只加临时诊断代码，验证后不得作为长期因果 API 保留。
```

## 3. 项目结构映射表

| 业务概念 | 项目承载结构 | 值类型 | 写入方 | 读取方 | 验证方式 |
| --- | --- | --- | --- | --- | --- |
| 因果节点身份 | 基础信息节点类 / 因果节点类 | 指针 / 主键 | 基础信息树、因果类 | 任务筹办、自我线程、需求类 | 外部不再自行 `reinterpret_cast` 后读主信息 |
| 因果主果方向命中 | 因果主信息类::主果比较模板 + 二次特征节点类 | 可解析引用 / 指针 | 因果类生成或确保模板 | 任务筹办、自我线程 | 同向/反向命中由因果类输出 |
| 因果证据状态 | 因果主信息类基础计数字段、证据动态样本 | 计数、bool、动态引用 | 因果类生成、后续稳定度更新入口 | 任务筹办、自我线程 | 外部不直接读 `证据动态样本/已验证/计算稳定度` |
| 因果条件缺口 | 条件比较模板 + 证据动态初始状态 | 特征 / 状态 / I64 | 因果类读取既有因果信息 | 任务筹办 | 条件目标状态由因果类查询输出 |
| 因果动作来源 | 因方法模板、因动作语义键、因动作名称 | 方法引用 / 现有动作键 | 因果类生成或确保模板 | 需求校验、任务筹办 | 外部不直接解释因果动作字段 |
| 被动触发初始因果 | 因果主信息类条件 / 动作 / 主果 / 证据动态 | 因果模板节点、二次特征、动态 | 因果类 | 自我线程后处理链 | 不靠规则名幂等，靠结构签名命中 |

## 4. 当前欠缺点

1. 节点解析分散：任务筹办、自我线程、需求类仍各自按主键或指针解析因果节点。
2. 主果命中扫描重复：任务筹办和自我线程各自枚举全部因果、读取主果比较模板、比较需求方向。
3. 证据状态 / 计数读取分散：多个调用方直接读 `已验证`、`证据动态样本`、`观察次数`、`成立次数`、`失败次数`、`计算稳定度()`。
4. 条件缺口反推分散：任务筹办直接读 `条件比较模板` 和证据动态样本反推条件目标状态。
5. 动作来源判断分散：需求类直接读 `因方法模板 / 因动作语义键 / 因动作名称` 判断目标生产者。
6. 因果验收 / 稳定度更新只有成功样本追加路径，缺少统一的失败或后验评价计数入口。

## 7. 跨类缺口转向规则

执行本计划时，如果发现当前切片必须依赖其它类新增或补齐功能函数，按以下规则处理：

```text
1. 后续任意类缺少当前切片所需功能函数时，不在当前调用方临时拼字段、解释其它类主信息或新增平行结构体。
2. 若对应类已有逻辑纠偏计划，则把当前缺口加入该计划，并放到第一优先位置。
3. 若对应类没有逻辑纠偏计划，则生成 `计划/YYYYMMDD_<类名>逻辑纠偏计划_v0.1.md`，并把当前缺口作为第一优先切片。
4. 新生成或被修改的逻辑纠偏计划必须包含本“跨类缺口转向规则”，保证后续继续发现缺口时仍按同一调度口径处理。
5. 更新 `计划/计划索引.md`：把新生成或新修改的计划临时提升为第一优先计划；原计划和原切片记录为返回点。
6. 只执行新计划的第一优先缺口切片，不顺带推进新计划后续候选项。
7. 第一优先缺口闭合后，立即停止该新计划，更新计划索引返回原计划和原切片。
8. 若第一优先缺口切片不能闭合，保留该计划为当前阻塞，不回到原计划继续补丁化绕过。
```
