# S1d-4f 任务状态提交调用侧方法首节点缓存方案 v0.1

日期：2026-06-07

## 1. 目标

```text
减少 私有_准备任务域本能调用 中反复查找 / 创建 自我_提交任务状态变化 方法首节点的成本。
```

## 2. 依据

```text
S1d-4e 真实运行显示：
    准备本能调用平均约 104655us；
    准备查找本能方法平均约 100035us；
    25 条完整状态提交中，准备最慢阶段全部为 查找本能方法。
```

## 3. 边界

```text
1. 只缓存 自我_提交任务状态变化 的方法首节点。
2. 缓存命中后仍创建输入参数场景、输入条件包、输出结果场景。
3. 缓存命中后仍执行 自我_提交任务状态变化 本能方法。
4. 不跳过任务状态动作动态、运行存在、运行账或 pending 确认。
5. 若自我存在或缓存方法首节点不匹配，退回 本能方法类::查找或创建本能方法首节点。
```

## 4. 最小实现

```text
在 任务模块.管理界面线程.impl.cpp 中增加进程内缓存：
    缓存自我存在指针；
    缓存 自我_提交任务状态变化 方法首节点指针。

私有_准备任务域本能调用 中：
    若 本能ID=自我_提交任务状态变化 且缓存自我存在匹配、方法首节点动作句柄匹配，则直接使用缓存；
    否则走现有 查找或创建 逻辑；
    查找成功后写入缓存。
```

## 5. 验证预测

```text
构建：
    Debug x64 应通过。

真实运行：
    .\x64\Debug\鱼巢.exe --self-check-log --self-check-log-wait-ms=10000 应退出码 0。

日志：
    任务状态提交/阶段耗时 中 准备查找本能方法 应显著下降；
    准备本能调用平均耗时应下降；
    状态提交确认完成仍应出现。

负向核对：
    不应出现 状态提交确认失败、后台worker工作项进入死信、拒绝归并完成项；
    派发前 终止过期工作项 | 状态版本错配 若仍出现，继续登记为旧等待项残留治理。
```
