# 任务执行回执与本能方法闭环整改计划 v0.1

生成日期：2026-06-11

## 0. 定位

本计划根据“任务执行把可等待的执行前置 / 输入缺口压成普通动作失败”的根因报告制定。

本计划不是外设专项计划。整改目标是收束通用任务筹办、任务执行、本能方法运行结果三条链路：

```text
本能方法内部特征化闭环
-> 执行桥读取运行存在 / 输出结果场景
-> 任务执行普通函数生成结构化过程回执
-> 任务管理线程按回执选择等待、重筹办、派生需求、学习补齐或异常处理
```

## 2. 根因摘要

已定位的根因链：

```text
本能方法已经写入 失败原因 = 执行缺口_当前方法条件不满足
-> 运行存在没有把该失败原因升格成统一执行缺口类型 / 承接方式
-> 本能动作运行结果值() 只把 方法执行情况=执行成功 解释为 0，其余统一折成 本能动作错误_执行失败
-> 任务执行普通函数按 本能动作运行成功() 写 成功 / 失败 记账结果
-> 工作线程执行回执构造函数只识别少数返回码或外设等待特判
-> 无法通用区分“前置条件未满足 / 等待供料 / 参数缺口 / 可学习缺口 / 异常”
-> 最终落成普通动作执行失败
```

当前代码中已有但未贯通的通用结构：

```text
任务推进回执
执行缺口类型
当前方法运行存在
输入参数场景
输出结果场景
目标是否达成 / 本轮是否有推进 / 剩余差距 / 执行结果类型
失败原因
派生需求提示
```

因此整改方向不是新增 6150、外设方法 ID、外设特征名等特判，而是把这些已有槽位贯通成通用闭环。

## 3. 禁止边界

本计划执行时禁止：

```text
1. 在任务筹办 / 任务执行函数中列举外设方法 ID、6150 或具体外设特征名。
2. 在通用执行推进里保留“外设观察供料等待”专项分支。
3. 继续用 本能动作运行结果值() / 本能动作运行成功() 作为机器判断主依据。
4. 让本能方法只返回 本能动作错误_*、执行失败、错误码或文本原因。
5. 保留旧返回码兼容路径、旧字段双写、新旧入口并存或 fallback。
6. 把任务筹办 / 任务执行恢复成本能方法或方法动作动态来源。
7. 把输出结果场景当作任务状态回执；输出结果场景只承载真实事实。
```

## 4. 目标模型

### 4.1 本能方法输出闭环

每个本能方法本轮调用必须返回运行存在，且运行存在或其可解析输出场景至少形成以下特征事实：

```text
方法执行情况
失败原因
执行缺口类型
输入参数场景
输出结果场景
目标宿主
目标特征类型
当前状态
目标状态
实际结果状态
动作动态或错误日志证据
后续承接方式
```

`后续承接方式` 是通用语义，不绑定领域：

```text
无缺口
等待既有事实
等待供料
重筹办
派生需求
学习补齐
异常处理
```

错误码只允许作为日志辅助检索值，不参与任务状态推导。

### 4.2 任务执行回执闭环

任务执行普通函数只产出结构化过程回执。所有不能推进的信息都必须转成：

```text
推进状况
执行缺口类型
缺口目标主体
当前方法
输入参数场景
输出结果场景
当前方法运行存在
建议任务状态
建议任务阶段
需要自我线程
需要创建或复用子需求
父任务需要重筹办
摘要仅作日志显示
```

不能出现“默认失败”作为闭环出口。若运行存在缺少上述必需特征，该路径应归为“方法运行回执未闭环”的异常缺口，而不是普通动作失败。

## 5. 整改切片

### P0 证据冻结与冲突清单

目标：冻结当前根因证据，列出必须删除或改写的判断点。

检查范围：

```text
任务模块.执行.ixx
任务模块.管理工作线程.ixx
任务模块.管理界面线程.impl.cpp
任务模块.筹办.ixx
本能动作管理类.ixx
自我动作实现模块.ixx
自我动作实现.*模块.ixx
本能方法类.*
```

输出：

```text
1. 依赖 本能动作运行结果值() / 本能动作运行成功() 做机器判断的清单。
2. 返回 本能动作错误_* / 创建本能动作运行结果实例_按码 的清单。
3. 任务筹办 / 执行中出现兼容、旧 ID、旧流程、外设等待特判的清单。
4. 每个命中点的去向：删除、改为读取闭环特征、改为异常缺口、或暂停确认。
```

验收：

```powershell
rg -n "本能动作运行结果值\\(|本能动作运行成功\\(|本能动作错误_|创建本能动作运行结果实例_按码|外设观察供料等待|兼容历史数据|历史本能方法ID_任务筹办|历史本能方法ID_任务执行" -g "*.ixx" -g "*.cpp" -g "*.h"
```

### P1 统一运行闭环读取视图

目标：建立一个通用只读视图，读取运行存在和输出结果场景中的特征事实，不返回错误码。

建议实现方向：

```text
结构_本能方法运行闭环视图
读取本能方法运行闭环视图(运行存在, 输出结果场景)
```

视图字段只来自既有特征，不新增说明性摘要字段：

```text
方法执行情况
失败原因
执行缺口类型
后续承接方式
输入参数场景
输出结果场景
目标宿主
目标特征类型
当前状态
目标状态
实际结果状态
动作动态证据
错误日志证据
闭环完整性
```

验收：

```text
任务执行、工作线程、界面线程的机器判断读取该闭环视图。
本能动作运行结果值() 不再作为状态推导主路径。
```

### P2 本能动作管理返回口径收束

目标：把 `本能动作运行结果值()` 从权威判断降为日志辅助，并删除旧返回码兼容语义。

修改原则：

```text
1. 创建运行存在时写入特征化事实，而不是只写 本能动作运行结果码。
2. 方法执行情况为失败时，必须同步写入失败原因、执行缺口类型、后续承接方式。
3. 若无法形成运行存在，调用侧只能进入异常处理，不能返回普通失败码。
4. 保留错误码仅可作为日志检索附属值，不参与任务状态、派生需求或等待判断。
```

验收：

```text
本能动作管理类不再把“非执行成功”统一折成 本能动作错误_执行失败 供机器判断。
```

### P3 执行桥结构性缺口特征化

目标：执行桥所有结构性前置缺口直接形成运行闭环事实。

覆盖缺口：

```text
缺方法动作
方法缺可执行入口
方法缺条件节点
方法缺结果节点
方法缺条件结果对
参数不可配
方法运行账不足
方法结果不稳定
可执行输入参数场景缺失
当前方法条件不满足
```

每类缺口必须写入：

```text
执行缺口类型
缺口目标主体
当前方法
输入参数场景
输出结果场景
当前状态
目标状态
后续承接方式
```

验收：

```text
执行桥不再通过返回 本能方法结果_任务缺条件需自我线程 或 本能动作错误_输入参数不满足 来让上层猜测。
```

### P4 任务执行普通函数回执化

目标：`任务模块.执行.ixx` 不再用成功 / 失败记账作为根语义。

修改点：

```text
1. 删除“只识别两个缺条件返回码”的判断。
2. 执行后读取 P1 闭环视图。
3. 根据闭环视图构造执行推进回执。
4. 无闭环视图时返回“方法运行回执未闭环”异常缺口。
5. 不直接返回裸失败、执行失败或普通动作失败。
```

验收：

```text
执行任务() 的主要出口都带结构化回执信息；
记账结果不再只有 成功 / 失败 / 未定义 三值支撑任务状态推导。
```

### P5 工作线程通用推进映射

目标：`任务模块.管理工作线程.ixx` 删除领域特判，统一按闭环视图和任务推进回执决定下一步。

通用映射：

```text
承接方式=等待既有事实 / 等待供料
    -> 建议任务状态=等待中；不派生子需求；保留等待项或等待证据。

承接方式=重筹办
    -> 建议任务状态=待重筹办；父任务需要重筹办。

承接方式=派生需求
    -> 需要自我线程；需要创建或复用子需求。

承接方式=学习补齐
    -> 需要自我线程；生成学习补齐类缺口消息。

承接方式=异常处理
    -> 报错 / 弹错 / 错误日志；不得伪装成业务失败。

承接方式=无缺口
    -> 继续读取实际结果状态并判断目标是否达成、是否有推进、是否可比较。
```

必须删除：

```text
执行失败回执外设观察供料等待专项分支
按外设等待特征修正任务状态的分支
按具体外设缺口过滤派生需求的通用执行分支
```

允许保留：

```text
外设模块内部的供料口径配置。
工作线程侧通用等待项事实读取。
日志显示里的外设名称。
```

验收：

```text
任务筹办 / 任务执行函数内不出现外设方法 ID、6150、外设特征名、外设等待专项状态推导。
```

### P6 任务筹办历史兼容清理

目标：清理任务筹办中仍作为机器路径存在的历史任务生命周期方法残留口径。

重点：

```text
历史本能方法ID_任务筹办
历史本能方法ID_任务执行
兼容历史数据
旧数据残留
非当前默认本能方法残留
```

处理规则：

```text
1. 若仍参与候选判断，删除该机器路径。
2. 若只用于一次性排查，移出当前执行路径。
3. 若删除会影响现有持久数据读取，暂停并生成独立清理方案，不得继续加兼容补丁。
```

验收：

```text
任务筹办候选选择不依赖历史任务生命周期方法 ID。
```

### P7 本能方法全量闭环扫尾

目标：全量整改本能方法，确保每个本能方法都内部闭环。

扫描命令：

```powershell
rg -n "return .*错误|return .*失败|本能动作错误_|创建本能动作运行结果实例_按码|写入方法执行情况\\(.*值_执行失败|失败原因 =|特征_失败原因\\(\\)" -g "*.ixx" -g "*.cpp" -g "*.h"
```

每个命中点必须判定：

```text
1. 是否已经写入运行存在。
2. 是否有执行缺口类型。
3. 是否有输入 / 输出场景。
4. 是否有目标宿主 / 目标特征 / 当前状态 / 目标状态 / 实际结果状态。
5. 是否有动作动态或错误日志证据。
6. 是否有后续承接方式。
```

验收：

```text
所有本能方法返回前都已写入闭环特征事实。
不能闭合的命中点不得标记完成，必须生成后续子计划或暂停确认。
```

### P8 构建与真实运行验证

执行顺序：

```text
1. 先写预测。
2. 静态扫描禁止项。
3. Debug x64 构建。
4. 真实运行路径验证。
5. 用日志、状态快照、动作动态和错误日志核对预测。
```

构建命令：

```powershell
msbuild .\鱼巢.vcxproj /p:Configuration=Debug /p:Platform=x64 /p:LinkIncremental=false /m
```

禁止：

```text
不得用模拟样本、夹具测试、伪造入口、伪造动作动态或旧 --*-check 回归命令替代真实验证。
```

真实验收关注点：

```text
1. 本能方法前置未满足时，日志显示执行缺口类型和后续承接方式。
2. 任务执行不再输出普通动作失败作为根语义。
3. 等待供料类场景通过通用等待承接方式进入等待，不出现外设专项判断。
4. 派生需求类场景通过缺口目标主体 + 缺口特征类型生成消息。
5. 异常类场景报错 / 记录错误日志，不进入业务失败闭环。
```

## 7. 完成定义

本计划完成必须同时满足：

```text
1. 任务筹办 / 任务执行无裸失败出口。
2. 本能方法不再只返回错误码、失败码或文本原因。
3. 任务执行状态推导不依赖 本能动作运行结果值() / 本能动作运行成功()。
4. 通用任务层不含外设方法 ID、6150 或外设特征名特判。
5. 旧兼容路径已删除或转为不参与机器判断的归档说明。
6. 真实运行日志证明缺口、等待、派生、异常都能进入对应特征化回执。
```
