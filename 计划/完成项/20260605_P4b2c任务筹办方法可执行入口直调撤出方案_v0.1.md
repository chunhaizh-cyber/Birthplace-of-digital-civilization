## 问题

P4b2-a 已确认任务筹办中仍存在直接执行方法域提交动作：

```text
任务模块.筹办.ixx:6200
    调用提交方法可执行入口

任务模块.筹办.ixx:6347
    因果反推出单步本能候选后，在筹办中直接调用提交方法可执行入口

任务模块.筹办.ixx:6831
    学习本能真实单步入口待提交时，在筹办中直接调用提交方法可执行入口

任务模块.筹办.ixx:6960
    既有真实单步本能入口待提交时，在筹办中直接调用提交方法可执行入口
```

这与当前口径冲突：

```text
任务筹办只负责找方法、绑定候选、形成可执行回执或结构缺口回执；
任务执行负责执行当前方法；
方法动作动态必须来自被执行的方法，不能由筹办阶段现场调用动作函数产生。
```

## 目标

```text
撤出任务筹办阶段对 自我_提交方法可执行入口 的直接执行；
保留“目标方法可执行入口缺口 / 方法动作缺口”的结构化回执；
让后续任务创建、候选方法查找、输入闭合和任务执行统一承接 自我_提交方法可执行入口。
```

## 现有可承接基础

当前代码已经具备统一承接条件：

```text
自我_提交方法可执行入口 的规格包含：
    目标方法头节点
    选中自我能力值

任务筹办通用输入闭合已经会写：
    特征_目标方法头节点()
    特征_选中自我能力值()

方法结构补齐任务会把被补方法作为输入目标方法：
    方法结构补齐被补方法
    任务方法结构补齐目标方法(...)
```

因此不需要在任务筹办中手工创建输入 / 输出场景并执行动作。

## 代码切片

### P4b2-c1 删除直调 helper

撤出或停用：

```text
调用提交方法可执行入口(...)
```

验收：

```text
rg -n "调用提交方法可执行入口" 任务模块.筹办.ixx
```

应无结果。

### P4b2-c2 因果反推单步本能候选改为结构缺口

原行为：

```text
反推出单步本能候选
-> 筹办现场执行 自我_提交方法可执行入口
-> 返回 已建立方法头待重入
```

新行为：

```text
反推出单步本能候选
-> 只记录候选本能ID
-> 返回方法结构缺口
-> 缺口继续由统一需求 / 任务 / 方法执行链承接
```

### P4b2-c3 学习本能自身入口待提交改为结构缺口

原行为：

```text
学习补齐本能方法自身有待提交入口本能ID
-> 筹办现场提交入口
```

新行为：

```text
学习补齐本能方法自身有待提交入口本能ID
-> 返回 方法缺可执行入口 / 方法可执行入口数量 缺口
-> 不在筹办阶段提交。
```

### P4b2-c4 既有真实单步入口待提交改为结构缺口

原行为：

```text
已有单步本能入口待提交动作状态
-> 筹办现场提交入口
```

新行为：

```text
已有单步本能入口待提交动作状态
-> 返回 方法缺可执行入口 / 方法可执行入口数量 缺口
-> 由后续任务执行 自我_提交方法可执行入口。
```
