## 目标

复核安全需求树是否仍只表达需求节点和逻辑组织需求节点，并确认以下内容只作为生产者 / 承接者存在：

```text
自我线程维护安全因果风险树
提交_生成缺口子需求
自我_识别外设观察材料
自我_扫描已识别区域
自我_跟踪指定存在
安全_评估当前场景安全性
提交_风险安全场景影响部分状态变化
```

本切片只做消费边界复核；除非发现直接把生产者写成安全需求树主干节点，否则不改 C++。

## 检查项

### 1. 需求节点口径

检查安全需求树主干是否只出现：

```text
直接需求节点：目标宿主 + 目标特征类型 + 目标状态 + 满足关系
逻辑组织需求节点：AND组满足状态 / OR组满足状态 / 方法路径完成状态
```

扫描、跟踪、安全评估、提交入口不得作为父需求下的主干子需求名称。

### 2. TSV 被动因果口径

检查 `data/initial_causal_templates.tsv` 是否只保存：

```text
条件集合 -> 必然结果
```

它不得登记本能方法，不携带目标任务或目标方法宿主，不表达动作语义。

### 3. 自我线程风险树维护

检查 `私有_维护安全因果风险树_线程侧` 是否只生成派生需求消息和风险树治理材料。

要求：

```text
直接写需求树=0
自我线程固定OR路径=0
自我线程生成D455固定子需求=0
安全需求正式入树必须走 提交_生成缺口子需求
```

### 4. 任务筹办边界

检查任务筹办侧安全风险树相关函数是否仍无更新权。

要求：

```text
任务筹办更新权=0
直接写需求树=0
不执行搜索=1
不写默认满足=1
不写风险安全层总值=1
不写自我安全值=1
```

### 5. 外设与安全评估生产者边界

检查外设识别、扫描、跟踪、安全评估、场景影响提交入口是否只写事实、候选、提交状态或动作动态。

要求：

```text
识别不产生被观察存在状态动态
第一次扫描只写发现存在或发现特征事实
扫描 / 跟踪不写需求满足
安全评估不直接消费外设提交包或观察报告
安全评估只生成候选 / 派生缺口
场景影响提交不写根安全值、不关闭安全根需求
```
