# 追根因：控制面板启动失败 v0.1

当前弹窗：
    控制面板页面显示 `SQL 投影读取失败。需求树 查询失败 | ADO执行查询失败 | HRESULT=0x80040E37 | 描述=对象名 '鱼巢.当前需求面板节点' 无效。`

最高优先级原因：
    A 主链根因候选：每次启动前会清空数据库，控制面板启动页却同步读取 SQL 投影视图；自我尚未运行并写入投影时，`[鱼巢].[当前需求面板节点]` 等对象可能尚未存在，控制面板首屏就显示 SQL 读取失败。

当前层级：
    L1 直接生成层：控制面板初始页面生成。修复方向改为启动页先显示加载中，SQL 数据区后加载；投影生成端保留完整视图校验。

同层疑点记录：
    1. 控制面板查询 SQL 写错对象名：暂排除；源码读取 `[鱼巢].[当前需求面板节点]`，该对象正是需求投影视图脚本声明的当前面板读模型。
    2. 视图 SQL 本身不可创建：暂排除；手工 `CREATE OR ALTER VIEW [鱼巢].[当前需求面板节点]` 成功，`OBJECT_ID` 返回对象 ID。
    3. 投影刷新后视图未落库：命中风险；当前数据库曾只存在 `[当前需求主信息]`、`[当前需求树节点]`，缺 `[当前需求面板节点]`。
    4. ADO 多语句建视图执行后没有后置对象校验：命中风险；`重写需求树SQL投影` 只在可选字段恢复比对中比较表字段，不检查面板视图存在。
    5. 启动清库后控制面板应等待数据：用户确认；控制面板数据需要后加载，启动时可显示数据加载中。

选中下钻分支：
    控制面板 WebView2 首屏改为不预读 SQL 的启动骨架；页面加载后通过已有 `refresh-page:<区段>` 通道刷新当前区段，数据库未就绪时显示“数据加载中”并重试。需求投影端在真正写入投影后校验三张当前需求视图均存在。

主链判断：
    控制面板首屏不应因清库后的暂时无数据而报启动失败；这是启动时机与数据加载方式不匹配。对象缺失在数据刷新阶段仍应作为投影未就绪反馈，不应阻断窗口出现。

已确认事实：
    日志 `日志/鱼巢_exception_20260624.低值g` 记录控制面板 HTML 生成失败，来源 ADO-SQL，原因是 `[鱼巢].[当前需求面板节点]` 无效。
    源码 `控制面板类.cpp` 的需求树主查询和子层查询都读取 `[鱼巢].[当前需求面板节点]`。
    源码 `需求类.cpp` 建表脚本会先删除三张当前需求视图。
    手工创建 `[鱼巢].[当前需求主信息]`、`[鱼巢].[当前需求树节点]`、`[鱼巢].[当前需求面板节点]` 可成功；面板视图定义本身不是当前阻塞。
    用户确认：每次启动前都需要先清数据库，控制面板数据需要等自我运行获取数据后再加载，启动时可以显示数据加载中提示。
