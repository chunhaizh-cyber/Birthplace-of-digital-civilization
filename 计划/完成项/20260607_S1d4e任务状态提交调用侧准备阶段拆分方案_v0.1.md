# S1d-4e 任务状态提交调用侧准备阶段拆分方案 v0.1

日期：2026-06-07

## 1. 目标

```text
继续定位 私有_提交界面任务状态变化 中 准备本能调用 的耗时来源。
```

## 2. 依据

```text
S1d-4d 后真实运行显示：
    完整任务状态提交平均约 285352us；
    执行本能方法平均约 170344us；
    准备本能调用平均约 105677us。

通用环境重复补齐已下降，
当前仍可在调用侧继续拆分，不需要进入 自我_提交任务状态变化 具体方法体加耗时日志。
```

## 3. 边界

```text
1. 只在任务管理调用侧拆分 准备本能调用。
2. 不在 自我_提交任务状态变化 具体方法体内新增耗时日志。
3. 不跳过任务状态写入、动作动态、输出运行虚拟存在、运行账。
4. 不改变 pending 确认前不可派发的顺序。
5. 不恢复任务筹办 / 任务执行为本能方法。
```

## 4. 最小实现

```text
在 私有_提交界面任务状态变化 的准备本能调用阶段细分：
    本能方法查找 / 确保；
    输入参数场景创建；
    输入条件包创建；
    写任务指针；
    写建议状态；
    写建议阶段；
    输出结果场景创建；
    调用前其他整理。

日志仍挂在现有 任务状态提交/阶段耗时 或新增同前缀子锚点，
只记录调用侧阶段，不记录具体方法体内部阶段。
```

## 5. 验证预测

```text
构建：
    Debug x64 应通过。

真实运行：
    .\x64\Debug\鱼巢.exe --self-check-log --self-check-log-wait-ms=10000 应退出码 0。

日志：
    应能看到准备本能调用内部哪个子阶段占主要耗时。

负向核对：
    不应出现 状态提交确认失败、后台worker工作项进入死信、拒绝归并完成项；
    派发前 终止过期工作项 | 状态版本错配 若仍出现，继续登记为旧等待项残留治理。
```
