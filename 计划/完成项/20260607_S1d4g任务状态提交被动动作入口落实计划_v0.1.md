# S1d-4g 任务状态提交被动动作入口落实计划 v0.1

日期：2026-06-07

## 1. 目标

```text
把 自我_提交任务状态变化 从“每次完整本能函数运行外壳”中拆出任务域被动提交入口，
并彻底删除任务管理热路径上的旧完整本能函数执行代码。

保持：
    动作来源方法 = 提交任务状态变化；
    动作语义 = 被动动作；
    任务状态动作动态仍是权威证据；
    状态值、动作动态、任务壳快照、worker 派发顺序一致。

减少：
    状态提交锁内的输入 / 输出场景构造；
    本轮运行虚拟存在创建；
    输出运行虚拟存在；
    方法运行账读写；
    完整本能方法自身环境重复进入。
```

## 3. 规范落实口径

### 3.1 上级硬规则不改

```text
规范/方法动作动态硬规则规范20260512.md 已允许被动状态动作：
    被动状态动作不是主动候选；
    只由生命周期代码显式调用；
    可以产生方法动作动态；
    动作语义必须是 被动动作；
    提交任务状态变化 只能作为提交来源、审计来源或实现来源记录。

本切片不得修改该硬规则。
```

### 3.2 下级规范需要修订的口径

```text
把下级规范中“必须调用 提交任务状态变化 本能方法 / 提交类本能方法”的实现表述，
收束为：

    任务状态变化必须通过任务域被动提交动作入口完成；
    该入口必须绑定 提交任务状态变化 方法首节点作为动作来源；
    生成的任务状态动作动态动作语义必须是 被动动作；
    该入口不得进入普通候选方法集、任务当前方法、学习目标或练习目标。

解释：
    完整本能函数运行四段式仍适用于普通本能函数执行；
    任务状态提交是被动状态动作入口，不再保留普通候选本能函数执行入口；
    因此可绕开本轮运行虚拟存在和方法运行账，但不能绕开来源方法和动作动态。
```

### 3.3 需修订文件

```text
规范/任务筹办与执行边界规范20260512.md
    修订“任务管理层必须调用 提交任务状态变化 本能方法”的措辞。
    保留“不得由任务管理层裸生成任务状态动作动态”。
    增加“任务域被动提交动作入口可作为快路径，但必须校验来源方法首节点”。

规范/自我线程与任务管理线程权责边界规范20260512.md

规范/动作动态即因果账本规范20260512.md
    修订任务域表述，明确 `提交任务状态变化` 是动作来源方法；
    具体实现入口统一为任务域被动提交动作入口；

规范/本能方法自身环境就绪规范20260510.md
    增加边界说明：
        该规范约束普通本能函数执行路径；

        但必须在进程内已有合法方法首节点和规格确认基础上运行。
```

### P0：导出任务状态被动提交契约

允许修改：


新增结构建议：

```cpp
struct 结构_任务状态被动提交请求 {
    方法类::节点类* 提交方法首节点 = nullptr;
    任务类::节点类* 任务 = nullptr;
    枚举_任务状态 新状态 = 枚举_任务状态::未定义;
    枚举_任务阶段 新阶段 = 枚举_任务阶段::未定义;
    场景节点类* 输入参数场景 = nullptr;
    场景节点类* 输出结果场景 = nullptr;
    时间戳 now = 0;
};

struct 结构_任务状态被动提交结果 {
    bool 已提交 = false;
    bool 已写任务状态 = false;
    bool 已写任务阶段 = false;
    枚举_任务状态 旧状态 = 枚举_任务状态::未定义;
    枚举_任务状态 新状态 = 枚举_任务状态::未定义;
    枚举_任务阶段 旧阶段 = 枚举_任务阶段::未定义;
    枚举_任务阶段 新阶段 = 枚举_任务阶段::未定义;
    动态节点类* 任务状态动作动态 = nullptr;
    const 语素入口节点类* 失败原因 = nullptr;
};
```

新增函数建议：

```cpp
using 任务状态被动提交函数 = 结构_任务状态被动提交结果 (*)(
    const 结构_任务状态被动提交请求& 请求) noexcept;
```

要求：

```text
1. 该函数不注册到 本能动作管理类。
2. 该函数不进入普通候选方法集。
3. 该函数只作为任务管理线程的任务域提交入口。
4. 该函数内部复用 输出任务状态提交动作动态 和 任务状态提交来源方法可生成动作动态。
5. 删除旧的 自我_提交任务状态变化 本能函数指针导出和注册代码，不保留兼容 fallback。
```

### P1：实现最小被动提交函数

允许修改：

```text
自我动作实现模块.ixx
```

实现流程：

```text
1. 校验请求：
       任务不为空；
       新状态不为 未定义；
       提交方法首节点可生成动作动态。

2. 读取旧状态 / 旧阶段。

3. 完成态仍保留提交前检查：
       新状态 = 完成 时，继续执行 任务结果达到目标_提交前检查；
       不达成则返回失败，不写完成状态，不生成任务状态动作动态。

4. 写任务状态：
       调用 任务类::写入任务状态。

5. 如有有效建议阶段，写任务当前阶段。

6. 若 状态变化 || 阶段变化：
       调用 输出任务状态提交动作动态；
       动态主体仍是任务虚拟存在；
       动态特征是任务状态或任务当前阶段；
       初始状态 / 结果状态必须写入；
       来源动作 = 提交方法首节点；
       来源动作名 / 动作语义 = 被动动作。

7. 动态成功后回写任务虚拟存在：
       任务状态动作动态；
       动作动态。

8. 无状态 / 阶段变化时：
       不生成动作动态；
       返回已提交=true，任务状态动作动态=nullptr；
       仅在诊断开关启用时记录短日志。

9. 失败时：
       继续调用 记录并提示任务状态动作动态逻辑错误；
       不静默兜底。
```

禁止：

```text
1. 不创建本轮运行虚拟存在。
2. 不调用 输出运行虚拟存在。
3. 不调用 更新方法运行账。
4. 不把任务状态写入输出结果场景。
5. 不新增伪动态、伪场景或模拟入口。
6. 不把动作来源记为任务管理线程。
```

### P2：任务管理线程调用侧切换

允许修改：

```text
任务模块.管理界面线程.impl.cpp
```

改造点：

```text
1. 保留 私有_读取状态提交方法首节点缓存 / 私有_写入状态提交方法首节点缓存。
2. 新增 私有_准备任务状态被动提交方法：
       只负责取得 自我_提交任务状态变化 方法首节点；
       不创建每次唯一输入 / 输出场景；
       不创建输入条件包。

3. 私有_提交界面任务状态变化：
       状态提交锁内调用任务状态被动提交函数；
       用返回结果更新已提交判断；
       若有动态，保留后续调度侧快照和日志。

4. 提交任务状态推进请求：
       状态提交锁内调用任务状态被动提交函数；
       输出结果->任务状态动作动态 直接取返回结果；
       不再从运行存在读取动作动态。

5. 完成归并提交任务状态：
       状态提交锁内调用任务状态被动提交函数；
       工作结果.治理结果.任务状态动作动态 直接取返回结果；
       工作结果.治理结果.最新动态 同步为该动态。

6. 删除任务状态提交路径对 私有_准备任务域本能调用 / 私有_执行任务域本能方法 的依赖。
   若这两个 helper 已无其他合法使用者，则同步删除 helper；
   若仍服务其他提交入口，本切片只删除 自我_提交任务状态变化 旧调用分支。
```

注意：

```text
如果某条路径必须保留输入 / 输出场景作为动态来源字段，
优先复用请求场景 / 任务场景；
不要在状态提交锁内创建每次唯一的新场景。
```

```text

    任务状态提交/动作动态创建逻辑错误；
```
