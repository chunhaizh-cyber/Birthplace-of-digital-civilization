## 1. 目标

把当前过渡路径：

```text
任务价值反馈数值
    -> 安全 / 服务满足量
    -> 计划结算增量
    -> 结算叶子任务价值
```

替换为正式路径：

```text
D0：叶子任务业务动作动态
    + actual：目标宿主.目标特征类型 的执行后实际状态
        -> D1：回写需求满足动作动态
            -> D2：结算叶子任务价值动作动态
```

最终规则：

```text
没有 D0，不知道哪个动作造成结果。
没有 actual，不知道目标特征实际达到多少。
没有 D1，不知道该结果是否已登记为满足来源需求。

2026-05-23 修正：`actual` 仍是正式结算硬前提；D0 / D1 是因果解释证据，缺 D0 / D1 不再单独阻断正式结算。
```

## 2. 非目标

本方案不做：

```text
1. 不恢复“增加安全值 / 增加服务值”类业务方法。
2. 不把 结算叶子任务价值 当作绕过条件的直接根写入原语；它可以按结果能力被安全值 / 服务值目标召回，但必须由叶子任务完成、实际改变结果状态、完成度和任务自身权重门控。
3. 不用任务价值反馈数值伪造 D0 / D1 / actual。
4. 不把安全值账务变化反推为事实安全改善。
5. 不要求父任务 / 汇总任务必须有单步业务动作动态。
```

父任务 / 汇总任务可以通过子任务结果归并、父任务重筹办和需求回流推进；正式结算只落在具备业务动作证据的叶子任务上。

## 3. 当前代码现状

### 3.1 过渡结算入口

当前自我线程中的任务价值反馈路径大致为：

```text
私有_处理任务价值反馈_线程侧(...)
    -> 读取任务承接安全 / 服务权重上限
    -> 读取任务价值反馈段中的安全满足量 / 服务满足量
    -> 计算计划安全 / 服务增量
    -> 私有_调用结算叶子任务价值本能方法_线程侧(...)
```

当前调用结算方法时，`来源动作动态` 和 `满足证据动态` 仍可为空：

```text
私有_调用结算叶子任务价值本能方法_线程侧(
    ...,
    来源动作动态,
    满足证据动态,
    now)
```

这说明结算方法的输入口已预留证据位，但过渡路径尚未接入正式证据链。

### 3.2 回写需求满足入口

当前已有：

```text
私有_调用回写需求满足本能方法_线程侧(...)
私有_写入回写需求满足输入(...)
```

并且输入也已经支持：

```text
来源动作动态
满足证据动态
```

但当前调用路径尚未稳定把 D0 / actual 传入并把回写需求满足生成的动作动态 D1 返回给结算链。

### 3.3 目标投影预判入口

当前已有：

```text
因果类::查询叶子任务权重类型与层级(...)
```

并已接入结算前路径：

```text
私有_查询叶子任务结算前因果投影_线程侧(...)
```

它能识别：

```text
目标宿主
目标特征类型
候选权重类型
候选投影路径
缺失证据
```

2026-05-23 后，结算候选不再由 D0 / D1 缺失决定；实际改变结果状态、完成度、任务权重和哨兵检查决定是否允许进入结算。

## 4. 数据定义

### 4.1 D0

```text
D0 = 叶子任务业务动作动态。
```

来源：

```text
叶子任务当前方法执行；
当前方法运行存在；
输出结果场景；
世界树动作动态。
```

D0 必须说明：

```text
哪个方法执行了；
作用于哪个目标宿主；
改变了哪个目标特征类型；
执行前状态是什么；
执行后实际状态是什么；
输出结果场景在哪里。
```

D0 不能来自：

```text
结算叶子任务价值；
回写需求满足；
任务状态提交；
纯数值反馈。
```

### 4.2 actual

```text
actual = 目标宿主.目标特征类型 的执行后实际状态。
```

来源优先级：

```text
1. D0 输出结果场景中与 来源需求.目标宿主 / 目标特征类型 匹配的状态节点。
2. D0 动作动态的结果状态。
3. 当前方法运行存在引用的输出结果场景。
4. 世界树中同一目标宿主 / 目标特征类型的执行后状态。
```

禁止来源：

```text
安全值结算增量；
服务值结算增量；
任务价值反馈满足量；
D2 账务结果。
```

### 4.3 before / target

```text
before = 需求生成或任务执行前的目标特征状态。
target = 来源需求的目标状态。
```

来源：

```text
before：
    来源需求.被需求当前状态；
    或 D0 初始状态；
    或任务执行前快照。

target：
    来源需求.需求状态 / 目标状态；
    来源需求.满足关系。
```

比较规则：

```text
固定值 / 增加方向：
    完成：actual - target >= 0
    推进：actual - before > 0

降低方向：
    完成：target - actual >= 0
    推进：before - actual > 0

区间目标：
    完成：actual 落入目标区间
    推进：actual 比 before 更接近目标区间
```

### 4.4 D1

```text
D1 = 回写需求满足动作动态。
```

来源：

```text
自我线程确认 actual 满足来源需求目标；
调用 自我_回写需求满足；
该本能方法生成需求满足动作动态。
```

D1 必须引用：

```text
来源需求
来源任务
D0
actual / 输出结果场景
满足证据动态
```

### 4.5 D2

```text
D2 = 结算叶子任务价值动作动态。
```

来源：

```text
自我_结算叶子任务价值。
```

D2 必须读取：

```text
D0
D1
actual
before
target
来源需求
来源任务
目标投影路径
结算贡献层级
因果置信度
防重复记录
```

副作用检查结果、竞争原因和净贡献抵扣属于真实运行期后置输入，
当前 v0.1 不要求 D2 读取这些字段。

D2 只负责账务入账，不得反过来证明 D0 有效。

## 5. 推荐新增结构

第一版可先放在自我线程价值结算模块附近，作为普通过程结构，不新增基础信息节点。

```cpp
struct 结构_叶子任务正式结算证据
{
    任务节点* 叶子任务 = nullptr;
    需求节点* 来源需求 = nullptr;

    动态节点类* D0_业务动作动态 = nullptr;
    动态节点类* D1_需求满足动态 = nullptr;

    场景节点类* 输出结果场景 = nullptr;
    状态节点类* before状态 = nullptr;
    状态节点类* target状态 = nullptr;
    状态节点类* actual状态 = nullptr;

    基础信息节点类* 目标宿主 = nullptr;
    特征节点类* 目标特征类型 = nullptr;

    结构_叶子任务因果投影预判 投影预判{};

    bool actual满足目标 = false;
    bool actual有推进 = false;
    bool 来源需求已回写满足 = false;
    // 后置字段：当前项目不具备真实运行条件，v0.1 不以副作用审查作为结算闸门。
    bool 无未处理副作用 = true;

    std::vector<std::string> 缺失证据{};
};
```

该结构只作为结算前证据包，不直接写任务、需求、方法或世界树。

## 6. 实施步骤

### P0. 现有链路审计

目标：

```text
列出当前所有能调用 结算叶子任务价值 的入口。
确认哪些入口仍只带数值反馈。
确认哪些入口已经能拿到输出结果场景或动作动态。
```

检查点：

```text
私有_处理任务价值反馈_线程侧
私有_调用结算叶子任务价值本能方法_线程侧
私有_调用回写需求满足本能方法_线程侧
私有_写入结算叶子任务价值输入
私有_写入回写需求满足输入
任务管理结果状态消息
当前方法运行存在
输出结果场景
```

难点：

```text
旧路径分散，部分回归直接制造数值反馈；
如果漏掉一个入口，仍可能绕过 D0-D1-actual。
```

停机点：

```text
如果发现多个入口可以直接改变安全 / 服务值且无法统一收口，暂停并先做入口收口计划。
```

### P1. 增加证据包采集函数

新增普通逻辑函数：

```cpp
结构_叶子任务正式结算证据 收集叶子任务正式结算证据(
    任务节点* 叶子任务,
    需求节点* 来源需求,
    const 任务管理结果状态消息* 结果消息,
    时间戳 now) noexcept;
```

职责：

```text
1. 读取目标宿主。
2. 读取目标特征类型。
3. 查询目标投影预判。
4. 从任务执行结果 / 方法运行存在 / 输出结果场景读取 D0。
5. 从输出结果场景读取 actual。
6. 读取 before / target。
7. 计算 actual 是否满足目标、是否有推进。
8. 汇总缺失证据。
```

难点：

```text
D0 的统一存放位置可能尚未固定；
actual 可能只写在输出结果场景，也可能只作为状态节点挂在动作动态上；
旧回归可能没有真实输出结果场景。
```

停机点：

```text
如果叶子任务执行成功但完全找不到 D0 或输出结果场景，不能继续硬结算；应先补任务执行结果携带 D0 / 输出结果场景。
```

### P2. D0 提取

提取规则：

```text
优先从当前方法运行存在读取动作动态；
其次从输出结果场景读取动作动态；
再从任务执行结果 / 工作结果读取来源动作动态；
最后从世界树动态中按 来源任务 / 来源方法 / 时间窗口 查询。
```

验收：

```text
叶子业务方法执行后，证据包能拿到 D0。
父任务 / 汇总任务没有 D0 时，不视为代码错误，但不得正式结算。
```

难点：

```text
不是所有现有本能方法都稳定写动作动态；
部分旧方法可能只写运行存在摘要；
父任务状态提交动态不能冒充叶子业务动作动态。
```

### P3. actual 提取与目标比较

提取规则：

```text
用 来源需求.目标宿主 + 来源需求.目标特征类型 定位 actual。
actual 必须与目标特征类型同源同类。
```

验收：

```text
固定值需求：
    actual - target >= 0 才可满足；
    actual - before > 0 只表示有推进。

降低型需求：
    target - actual >= 0 才可满足；
    before - actual > 0 只表示有推进。
```

难点：

```text
当前需求目标可能有明确值、区间、方向三种形态；
旧回归中可能只写“满足量”，没有 actual 状态；
actual 若落到安全值账务特征上，应拒绝作为事实安全改善证据。
```

### P4. D1 生成与返回

调整 `回写需求满足` 调用链：

```text
只有 actual 满足来源需求目标时，调用 自我_回写需求满足。
调用输入必须携带 D0 和 actual 输出结果场景。
调用后必须返回 D1。
```

需要补强：

```text
私有_调用回写需求满足本能方法_线程侧 返回结构化结果；
从回写运行存在或输出结果场景读取需求满足动作动态；
若读不到 D1，则视为回写失败或缺证据。
```

难点：

```text
当前函数多处返回 bool，需要升级返回结构；
回写需求满足本能方法生成的动作动态可能没有统一特征槽；
若回写需求满足只是更新需求账但没有动态返回，需要补输出。
```

### P5. D2 正式结算入口

新增或替换：

```cpp
结构_线程价值结算结果 私有_处理叶子任务正式结算_线程侧(
    自我类& 自我对象,
    const 结构_叶子任务正式结算证据& 证据,
    时间戳 now) noexcept;
```

硬闸门：

```text
1. 必须是叶子任务。
2. 任务状态已完成。
3. 来源需求存在。
4. D0 存在。
5. actual 存在。
6. actual 满足目标。
7. D1 存在。
8. 投影路径存在。
9. 结算贡献层级 > 0。
10. 未重复结算。
11. 权重和结算比例合法。
```

难点：

```text
当前投影路径仍可能只是规则候选，未有完整世界树因果路径；
如果立即把投影路径缺失设为硬闸门，现有回归会从入账变成拒绝结算；
需要同步改回归夹具制造 D0 / D1 / actual。
```

### P6. 删除旧数值反馈入账

替换后：

```text
任务价值反馈.本次安全满足量
任务价值反馈.安全累计比例
任务价值反馈.本次服务满足量
任务价值反馈.服务累计比例
```

只能作为：

```text
兼容日志
阶段性候选
回归诊断信息
```

不得作为：

```text
核心安全 / 服务值正式入账依据。
```

难点：

```text
旧回归和旧自然路径可能仍只产生数值反馈；
删除后这些路径会显示“缺 D0 / D1 / actual”，需要接受短期回归失败并同步修夹具。
```

### P7. 回归夹具改造

第一条必须改：

```text
--subtask-parent-flow-check
```

新回归链：

```text
1. 创建叶子任务。
2. 让叶子任务执行业务方法并产生 D0。
3. 输出结果场景写入 actual。
4. 判断 actual 达到来源需求 target。
5. 调用 回写需求满足，拿到 D1。
6. 调用 结算叶子任务价值，拿到 D2。
7. 断言安全 / 服务入账符合投影层级和达成比例。
```

旧断言需要删除或降级：

```text
权重夹具成功
满足量直接入账
服务满足量直接影响服务值
```

难点：

```text
当前没有合适业务方法时，夹具需要用已有合法本能方法制造实际状态，而不能恢复 改变特征值 作为候选方法；
如果只能通过任务状态 / 方法状态类特征制造 actual，则需明确其安全结算贡献层级。
```

### P8. 日志与错误

缺证据日志必须具体：

```text
缺D0：未找到叶子业务动作动态。
缺actual：输出结果场景无目标宿主.目标特征实际状态。
缺D1：需求满足未回写或回写未生成动作动态。
缺投影路径：目标特征未映射到权重类型 / 层级。
```

非正常逻辑错误：

```text
任务已完成但既无 D0 又无输出结果场景；
目标特征类型为空；
actual 特征类型与来源需求目标特征不一致；
安全值账务变化被当作 D0 事实变化；
```

必须弹错 / 报错并记录日志，不允许静默兜底。

## 7. 关键难点汇总

### 难点 1：D0 没有统一来源

目前动作动态可能存在于：

```text
方法运行存在
输出结果场景
世界树动态
任务工作结果
```

需要先统一抽取规则，否则结算入口无法稳定拿到 D0。

### 难点 2：actual 不等于反馈数值

旧路径的 `安全满足量 / 服务满足量` 不能当 actual。

actual 必须是：

```text
目标宿主.目标特征类型 的执行后状态。
```

这要求叶子业务方法必须把实际结果写进输出结果场景。

### 难点 3：D1 目前可能只被调用，不被返回

`回写需求满足` 已经是本能方法，但调用链需要从 bool 升级为结构化结果，稳定返回：

```text
回写运行存在
需求满足动作动态 D1
输出结果场景
```

### 难点 4：父任务无 D0 是正常情况

父任务 / 汇总任务不是叶子业务动作，不能因为没有 D0 就当异常。

规则应是：

```text
父任务不结算；
叶子任务结算；
父任务通过子任务回流和父链重判体现收益。
```

### 难点 5：回归夹具要同步升级

删除过渡路径后，旧回归中只靠“满足量 + 权重夹具”入账的路径会失败。

这不是退化，而是证据链收紧。

### 难点 6：正式投影路径尚未完全硬化

当前规则投影仍可能是候选路径，缺：

```text
D0事实状态转换证据
D1需求满足证据
actual实际达成证据
```

如果一次性全设硬闸门，必须同步改至少一条回归形成完整证据。

### 难点 7：多目标投影

一个 D0 可能同时影响安全、服务、学习或方法维护。

需要后续支持：

```text
同一 D0 多投影候选；
同一目标只结算一次；
跨目标投影去重。
```

第一版可以先拒绝复杂多目标正式结算，只记录候选。
副作用抵扣、竞争原因和净贡献计算属于真实运行期后置能力，
当前项目不具备运行条件时不作为本方案实施难点。

## 8. 建议的最小原子实现范围

第一轮不要一次覆盖所有自然任务，只做一条正式回归链。

最小原子范围：

```text
1. 新增正式结算证据包。
2. 从叶子任务结果读取 D0 / 输出结果场景。
3. 从输出结果场景读取 actual。
4. 回写需求满足返回 D1。
5. 2026-05-23 修订：结算入口要求叶子任务完成、实际改变结果状态、完成度和任务自身权重齐全；D0 / D1 为因果解释证据。
6. 修改 --subtask-parent-flow-check。
7. 旧数值反馈无证据时拒绝入账并打日志。
```

暂不做：

```text
多目标净结算；
所有自然任务覆盖；
控制面板展示完整路径；
分段结算。
副作用 / 竞争原因 / 运行风险审查。
```

## 9. 推荐执行顺序

```text
P0 审计结算入口和 D0 / D1 / actual 可读位置。
P1 新增正式结算证据包与只读采集函数。
P2 接入 D0 抽取。
P3 接入 actual 抽取与目标比较。
P4 升级回写需求满足调用，返回 D1。
P5 新增正式结算入口，并把旧数值反馈降级为候选。
P6 修改 --subtask-parent-flow-check。
P7 构建与回归。
P8 删除或封死旧直接入账路径。
```

## 10. 停机点

遇到以下情况应暂停：

```text
1. 叶子业务方法执行后没有任何动作动态可追踪。
2. 输出结果场景无法表达目标宿主.目标特征实际状态。
3. 回写需求满足无法生成或返回 D1。
4. 当前唯一可用回归必须依赖“满足量直接入账”，且无法改造成 actual。
5. 为了让回归通过需要恢复 改变特征值 作为任务候选方法。
6. 为了结算需要把安全值账务变化当作事实安全改善证据。
```

## 11. 最终验收标准

```text
1. 缺 D0 时，正式结算拒绝。
2. 缺 actual 时，正式结算拒绝。
3. 缺 D1 时，正式结算拒绝。
4. 任务价值反馈数值不能单独触发核心值入账。
5. --subtask-parent-flow-check 能通过正式 D0-D1-actual 链入账。
6. 结算日志能显示 D0 / D1 / actual / 投影路径 / 结算层级。
7. D2 只作为账务动作动态，不作为事实安全改善证据。
```

一句话：

```text
正式路径不是“任务说贡献了多少”，而是“业务动作实际改变了目标特征、该改变满足了需求、结算方法据此入账”。
```
