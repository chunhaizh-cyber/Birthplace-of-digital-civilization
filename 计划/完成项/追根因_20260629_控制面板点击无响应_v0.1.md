# 追根因：控制面板点击无响应 v0.1

## 当前状态

已闭合并归档。当前结论：控制面板点击菜单停在“正在刷新”的主根因候选已通过按区段读取 SQL 投影和 WebView2 后台生成页面 JSON 收束；本计划不再留在默认执行队列。

## 当前现象

控制面板点击菜单后停在“正在刷新：demandTree”等状态，页面不更新或看起来无响应。

## 当前层级

L1 直接生成层：WebView2 点击消息、页面刷新 JSON、SQL 区段数据读取。

## 同层疑点记录

| 疑点 | 证据 | 状态 |
| --- | --- | --- |
| 点击消息未发到 WebView2 | 前端 `请求刷新当前SQL区段` 会先设置“正在刷新”，说明点击事件至少已触发；后端尚缺每次刷新日志 | 暂未定主因 |
| 需求树投影为空 | SQL 直查 `[鱼巢].[当前需求面板节点]` 当前有 11 行，根层 2 行；日志有 `需求树SQL投影完成 | 节点数=12` | 已排除当前主因 |
| 区段刷新全量读取导致卡顿 | `refresh-page:demandTree` 进入 `私有_SQL控制面板区段刷新JSON` 后先调用 `私有_读取SQL控制面板数据`，该函数读取所有区段；当前 `causal roots` 查询约 7880 ms，完整统计查询超时 | 主链根因候选 |
| 前端空结果显示加载中 | 只会在后端返回并执行 `__panelApplyPageRefresh` 后出现；当前截图停在“正在刷新”更像返回未及时到达 | 旁支候选 |

## 选中下钻分支

把 SQL 控制面板区段刷新从全量读取改为按目标区段读取，只保留目标区段需要的依赖：`causalInfo` 读取因果节点和关系，`causalChain` 只读取关系，`worldTree` 读取世界树根和关系，其它区段只读自身。

## 已确认事实

- 当前 SQL Server 连接可用。
- `[鱼巢].[当前需求面板节点]` 当前总数 12、根层 2。
- 当前视图列名为 `行号`、`父节点行号`、`显示深度`、`节点名称` 等加工视图字段；旧列名 `节点序号`、`父序号`、`深度`、`名称` 不再适用。
- 单独需求树根查询约 209 ms。
- 单独因果根查询约 7880 ms。

## 已改文件

- `控制面板类.cpp`：`私有_读取SQL控制面板数据` 增加目标区段过滤；实时刷新只读目标区段及必要依赖。
- `控制面板WebView2.cpp`：页面刷新回灌增加 JSON 生成耗时、JSON 字节数和 `ExecuteScript` 失败诊断。
- `计划/计划索引.md`：登记本追根因切片为当前主动项。
- `计划/追根因_20260629_控制面板点击无响应_v0.1.md`：记录本轮证据和修复边界。

## 已运行命令

- `sqlcmd` 直查需求树投影视图。
- `sqlcmd -S .\SQLEXPRESS -d 鱼巢投影库 -E -W -s "," -Q "SET NOCOUNT ON; SELECT COUNT(*) AS 总数, SUM(CASE WHEN [显示深度]=0 THEN 1 ELSE 0 END) AS 根层数 FROM [鱼巢].[当前需求面板节点]; SELECT TOP (10) [行号],[父节点行号],[显示深度],[节点名称],[目标语义],[目标特征显示] FROM [鱼巢].[当前需求面板节点] WHERE [显示深度]=0 ORDER BY [行号];"`：通过，当前总数 12，根层数 2，根节点为“安全”“服务”。
- `sqlcmd` 计时需求树根、世界树根、因果根查询。
- `msbuild .\鱼巢.vcxproj /p:Configuration=Debug /p:Platform=x64 /p:LinkIncremental=false /m`：通过，0 警告，0 错误。
- `.\x64\Debug\鱼巢.exe --panel-html`：通过，生成 `D:\鱼巢\控制面板.html`。
- `Select-String -Path 控制面板.html -Pattern '<section id="demandTree"|<td>安全</td>|<td>服务</td>|SQL 节点'`：静态 HTML 中需求树区段包含根节点“安全”“服务”。
