# 需求树结构错挂追根因 v0.1

## 当前弹窗 / 现象

控制面板需求树截图显示：

```text
SQL 节点：10
2 安全 叶子 目标特征=安全值 | 任务=安全根任务
3 方法维护管理状态 有子=1 目标特征=方法维护管理状态 | 任务=...
4 方法状态 有子=2 ...
8 服务 有子=3 目标特征=服务值 | 任务=未记录
```

异常点：

```text
1. 安全根显示为叶子，但截图中其下方又出现方法维护管理状态子链。
2. 方法维护管理状态看起来被挂在安全根附近，需确认它属于安全根子链、服务根子链、还是控制面板还原缩进错位。
3. 服务根应作为根层节点，需确认 SQL 结构表中的父节点是否为空 / 根节点，还是被错挂到安全链。
```

## 当前层级

L1 直接生成层：控制面板树视图、SQL 读模型、需求树投影。

## 主链判断

已确认主链：

```text
自检方法维护缺口
-> 私有_裁决自检候选父需求_线程侧
-> 退维护(方法维护)
-> 私有_确保自检维护管理父需求_线程侧
-> 以需求结构根作为父需求新增“方法维护管理状态”
-> SQL 需求树投影把“方法维护管理状态”显示为结构根的第三个直接子节点
```

分歧点：

```text
裁决阶段已经写出固定来源需求=安全根需求，但旧实现只把该来源用于日志 / 因果摘要；
维护管理父需求创建时没有使用该来源需求作为父链锚点，而是直接挂到需求树根。
```

## 已确认事实

```text
1. 规范要求安全 / 服务是自我存在上的根特征类型。
2. 根需求、安全根需求、服务根需求初始化只表示需求系统骨架。
3. 叶子 / 非叶子只能说明是否已有展开结构，不能单独决定需求逻辑语义。
4. SQL 视图 fishnest.v_current_demand_tree_nodes 中，结构根 A 的 direct_child_count=3，直接子节点为：安全、方法维护管理状态、服务。
5. 控制面板前端 buildGenericHierarchy 原先仅按 depth 栈还原树，没有优先使用 display_parent_id；这是次要风险，不是本次第三根层节点的主因。
```

## 已采取补丁

```text
1. 私有_确保自检维护管理父需求_线程侧 增加明确承接父需求参数。
2. 维护管理分支必须挂到裁决出的来源需求；缺来源父需求或父需求已截止时记录错误并拒绝入树，不再回退结构根。
3. 方法维护 / 学习维护 / 世界模型维护 / 自我结构维护分支暂按当前因果投影中的固定来源安全根需求承接。
4. 控制面板树状 SQL 区块优先使用 display_parent_id 建树，只有缺父链接时才回退 depth 栈。
```
