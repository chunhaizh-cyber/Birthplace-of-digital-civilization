# S1d-4a 状态提交本能调用外层阶段与规格快路径方案 v0.1

日期：2026-06-07

## 1. 目标

```text
继续治理 自我_提交任务状态变化 本能方法长期耗时。
本切片先处理重复专属规格确认，不改变任务状态提交的动作动态来源。
```

## 2. 边界

```text
1. 不在 自我_提交任务状态变化 本能方法内部新增耗时日志。
2. 不跳过 提交任务状态变化 本能方法。
3. 不由任务管理层裸写任务状态、任务阶段或动作动态。
4. 不改变 pending 状态提交确认队列、工作项派发顺序和状态版本同步规则。
5. 不混入日志 flush、D455、短摘要、候选 / 因果 / 基础信息索引线。
```

## 3. 代码定位结论

```text
任务模块.管理界面线程.impl.cpp:
    私有_提交界面任务状态变化 已在调用侧记录 准备本能调用 / 执行本能方法 / 同步镜像 / 快照等阶段。
    私有_执行任务域本能方法 当前外层只包住 取本能动作集().执行功能函数。

本能动作管理类.ixx:
    执行功能函数 外层包含 检查是否可调用、查询动作、动作函数调用、运行码写回。

自我动作实现模块.ixx:
    提交任务状态变化 的统一环境入口会调用 确认提交任务状态变化规格。
    确认提交任务状态变化规格 每次都会重复声明形参、条件特征和执行回执表子特征。
```

## 4. 最小实现

```text
第一刀：
    在 确认提交任务状态变化规格 中增加进程内快路径。
    当同一 方法首节点 和同一 方法虚拟存在 已经完整确认过规格时，后续调用直接返回 true。

安全条件：
    只有完整规格声明成功后才写入快路径缓存。
    方法首节点或方法虚拟存在指针变化时自动回到完整确认路径。
    快路径只跳过重复规格声明，不跳过统一环境、运行存在、任务状态写入、动作动态和运行账。
```

## 5. 验证预测

```text
构建：
    Debug x64 应通过。

真实运行：
    .\x64\Debug\鱼巢.exe --self-check-log --self-check-log-wait-ms=10000 应退出码 0。

日志核对：
    状态提交待确认入队 / 确认完成 仍应自然出现。
    不应出现 状态提交确认失败、状态版本错配、后台worker工作项进入死信、拒绝归并完成项。
    任务状态提交/阶段耗时 中 执行本能方法 可能下降；若仍高，下一刀继续拆 本能动作管理器外层检查 / 动作函数 / 运行码写回 或方法环境同步。
```

## 6. 执行结果 2026-06-07

```text
已实现：
    确认提交任务状态变化规格 增加同一进程内 方法首节点 + 方法虚拟存在 已确认快路径。

构建：
    msbuild .\鱼巢.vcxproj /p:Configuration=Debug /p:Platform=x64 /p:LinkIncremental=false /m
    退出码=0，警告=既有 LNK4075。

真实运行：
    .\x64\Debug\鱼巢.exe --self-check-log --self-check-log-wait-ms=10000
    退出码=0。

日志证据：
    20:03 窗口 状态提交确认完成 30 条；
    完整状态提交阶段耗时 27 条，平均总耗时约 463832us；
    执行本能方法平均约 337040us，最大 681557us；
    准备本能调用平均约 117366us，最大 301357us；
    同状态 / 同阶段确认可在 1082us、2241us、2666us 级别完成。

负向核对：
    20:03-20:05 窗口未检索到 状态提交确认失败；
    未检索到 状态版本错配、后台worker工作项进入死信、拒绝归并完成项。

结论：
    S1d-4a 未破坏 pending 状态确认链，但完整状态提交主耗时仍在 执行本能方法；
    单独规格声明快路径不是主收益点；
    下一刀应拆 本能动作管理器外层检查 / 动作函数 / 运行码写回，或继续定位方法环境同步和运行账写入。
```
