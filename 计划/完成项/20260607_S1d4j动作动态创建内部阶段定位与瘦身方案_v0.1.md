## 4. 实施步骤

```text
S1d-4j-1：
    `输出任务状态提交动作动态` 接收调用侧已取得的任务虚拟存在。
    调用侧已保证该任务虚拟存在不为空；
    函数内部保留兜底：缺少已知存在时仍按旧路径取或创建。

S1d-4j-2：
    在 `输出任务状态提交动作动态` 内增加低频阶段采样。
    采样锚点：`任务状态动作动态创建/内部阶段耗时`。
    采样规则：
        总耗时低于 100000us 不输出；
        慢调用前 3 次输出；
        之后每 10 次输出；
        总耗时不低于 500000us 输出。

S1d-4j-3：
    构建 Debug x64，真实运行 `--self-check-log --self-check-log-wait-ms=10000`。

S1d-4j-4：
    用日志确认：
        动作动态创建内部阶段采样存在；
        任务状态动作动态仍生成；
        旧完整本能函数路径和逻辑错误锚点不出现。
```

## 5. 验证预测

```text
构建：
    Debug x64 构建通过。

真实运行：
    退出码=0。
    日志出现少量 `任务状态动作动态创建/内部阶段耗时`。
    日志保留 `任务状态动作动态=<动态主键>`。
    不出现 `任务状态被动提交/逻辑错误`。
    不出现 `任务状态动作动态逻辑错误`。
    不出现 `准备本能调用`、`执行本能方法`、`任务域本能输入包`。

性能判断：
    如果旧 / 新状态节点创建是主耗时，下一轮只讨论状态创建后处理是否存在任务状态动作动态专用安全入口。
    如果方法动作动态创建是主耗时，下一轮继续拆动态类创建动态内部的查重、索引、二次特征生成。
    如果已知任务存在复用收益很小，以日志结论为准，不扩大改动。
```

## 6. 阻塞条件

```text
如果传递已知任务虚拟存在导致动作动态创建失败，停止并修正。
如果真实日志出现任务状态动作动态缺失，停止并修正动作动态账。
如果主耗时落在世界层状态 / 动态后处理，且没有规范允许的专用安全入口，停止在证据和方案，不直接删除后处理。
```
