## 1. 目标

从世界树根链上的已有因果信息、动作动态、状态变化线索、因果实例，以及任务 / 需求父链引用线索中构造一棵只读安全值因果树投影。

该树回答：

```text
哪些特征类型变化最终可以导致安全目标特征改善？
它们在安全结算贡献链中属于第几层？
每条路径的证据是什么？
某个叶子任务完成后应按第几层安全贡献结算？
```

一句话：

```text
先定安全结算贡献层级，再结算。
```

## 1.1 结构挂载口径

本计划中的“安全值因果树”不是新建一棵脱离世界树的权威树。

权威结构口径：

```text
因果树挂在世界树的根链上。
```

因此第一版实现应理解为：

```text
世界树根链上的因果信息：
    状态节点
    动态节点
    状态变化线索
    完整因果模板
    因果实例

安全值因果树：
    以安全值为目标特征，从世界树根链因果信息中生成的只读投影。
```

任务 / 需求 / 方法父链只提供治理归属和引用线索，不是因果树的挂载位置。

```text
任务树引用安全因果路径；
需求树引用安全因果解释；
方法树引用因果模板和实例；
世界树根链承载因果树本体。
```

## 2. 边界

安全值因果树生成是只读解释 / 归因逻辑。

它不得直接：

```text
1. 写安全值。
2. 写服务值。
3. 写需求树。
4. 写任务状态。
5. 写方法状态。
6. 生成动作动态。
7. 结算叶子任务价值。
```

它只输出：

```text
安全因果树节点；
安全因果边；
安全因果距离层级 / 可选；
安全结算贡献层级判定；
因果证据强度 / 置信度；
反向副作用候选；
竞争原因说明；
结算归因候选；
缺失证据说明。
```

如果后续要把归因结果持久写入任务、需求或结算账，必须交给对应提交方法。

## 3. 最小数据模型

第一版使用普通结构体，不新增基础信息节点。

注意：

```text
普通结构体只是第一版只读投影结果；
不表示因果树本体挂在该结构体里。
因果树本体语义上挂在世界树根链；
结构体节点必须能追溯到世界树状态 / 动态 / 因果模板 / 因果实例。
```

```text
结构_安全因果树节点：
    特征类型
    目标宿主 / 可选
    安全因果距离层级 / 可选
    安全结算贡献层级 / 可选
    节点类型
    来源因果模板
    来源动作动态
    来源需求
    来源任务

结构_安全因果树边：
    原因节点
    结果节点
    因果模板

    置信度 / 稳定度
    副作用标记
    竞争原因标记

    节点集
    边集

```

节点类型第一版：

```text
安全根值：
    安全值。

直接安全特征：

任务层特征：
    任务状态、目标是否达成、需求满足登记、叶子任务价值结算等。

方法层特征：
    方法状态、方法动作、方法可执行入口、条件结果对状态、方法稳定度。

观测层特征：
    自检结果、安全不确定性、方法维护状态等。

未知层特征：
    可疑但证据不足，不能结算。
```

## 4. 层级规则

本计划同时输出两类层级，不得混用：

```text
安全因果距离层级：
    表示某个原因距离物理不安全事件的反向因果距离。
    只用于解释、需求投影和优先级衰减。

安全结算贡献层级：
    表示某个任务结果最多可按第几层安全贡献结算。
    只用于安全 / 服务结算额度计算。
```

安全因果距离层级不得直接作为安全结算贡献层级。

第一版安全结算贡献层级固定：

```text
第一层：
    直接改变安全目标特征或直接命中物理安全目标。

第二层：
    使第一层安全目标特征变化可发生的任务层变化。
    例如：安全叶子任务完成、来源安全需求满足、结算叶子任务价值。

第三层：
    支撑第二层任务推进的方法层变化。
    例如：方法状态改善、方法动作入口形成、条件结果对建立、方法稳定度提高。
```

如果当前路径无法证明某特征最终通向安全目标特征变化：

```text
不判层；
不结算；
只记录缺失证据。
```

## 5. 输入来源

### 5.1 因果模板

读取：

```text
因果类::枚举因果模板()
```

使用：

```text
结果状态命中安全目标特征 / 安全复合特征；
条件状态作为上游节点；
动作模板 / 动作语义键作为边证据。
```

### 5.2 动作动态

读取动态中的：

```text
初始状态
结果状态
动态主体
动态特征
来源动作
来源低层动态
来源输入场景
来源输出场景
```

用途：

```text
串起：
    业务动作动态
    -> 需求满足动作动态
    -> 结算叶子任务价值动作动态
```

### 5.3 任务 / 需求父链

读取：

```text
任务 -> 来源需求
需求 -> 父需求链
需求目标宿主
需求目标特征类型
任务完成动态
需求满足动态
```

用途：

```text
确认任务是否能归结到安全根或安全复合特征；
确认该任务属于第几层安全结算贡献；
确认是否存在反向副作用或竞争原因。
```

## 6. 生成算法

### P1. 建立安全根节点

```text
根节点 = 自我.安全复合特征 / 安全根值
安全结算贡献层级 = 0
节点类型 = 安全根值
```

### P2. 从直接安全结果反向找因果模板

遍历因果模板：

```text
若模板结果状态命中安全目标特征 / 物理安全 / 风险安全 / 安全复合特征：
    创建第一层候选节点；
    建边到安全根节点。
```

### P3. 从任务 / 需求链补第二层

对每个安全需求满足链：

```text
任务完成
    -> 需求满足
        -> 安全目标已满足
```

生成第二层节点：

```text
任务状态 = 完成
目标是否达成 = true
来源需求满足登记
叶子任务价值结算
```

并建边：

```text
第二层任务节点 -> 第一层安全特征节点 / 安全根节点
```

### P4. 从方法 / 学习链补第三层

对能支撑安全任务推进的方法变化：

```text
方法状态 = 可用 / 好用
方法动作入口形成
条件结果对建立
方法稳定度提高
```

如果其父链能通向安全任务，则生成第三层节点。

建边：

```text
第三层方法节点 -> 第二层任务节点
```

### P5. 输出可结算路径

每条路径输出：

```text
任务 / 需求来源
命中安全根或安全复合特征
安全因果距离层级 / 可选
安全结算贡献层级
贡献层级比例
因果证据类型
因果置信度
副作用列表
竞争原因
目标实际达成值来源
缺失证据
```

## 8. 回归命令建议

新增：

```text
--safety-causal-tree-check
```

第一版断言：

```text
1. 能生成安全值根节点。
2. 能识别结算叶子任务价值 -> 安全目标特征改善 -> 安全值结算结果 为安全结算动作链。
3. 能把安全叶子任务完成 / 需求满足识别为第二层。
4. 能把方法状态改善 / 条件结果对建立 / 方法入口形成识别为第三层。
5. 没有父链归因的任务不产生可结算路径。
6. 未知层级不返回安全结算额度。
7. 安全因果距离层级不会被直接当作安全结算贡献层级。
8. 未处理反向副作用会让路径降级为候选或禁止结算。
```

## 10. 停止条件

```text
1. 若生成树需要直接写需求树，暂停。
2. 若生成树需要直接写安全值，暂停。
3. 若无法从现有因果模板 / 动作动态 / 父链获得任一证据，暂停并补日志。
4. 若发现安全因果距离层级 / 安全结算贡献层级规则与 060004 冲突，暂停。
5. 若需要新增基础信息结构，先确认，不直接实现。
```

## 11. 最终口径

```text
安全值因果树投影是安全结算贡献层级的判定来源之一。
它不是新账本，不替代动作动态，也不直接结算。
它只是把已有因果信息、动作动态和任务 / 需求父链组织成“哪些变化能通向安全目标特征改善”的可解释结构，并输出结算贡献层级、因果置信度、副作用和缺失证据。
```

一句话：

```text
先把安全目标特征为什么会改善画成树，再按结算贡献层级和因果证据算账。
```
