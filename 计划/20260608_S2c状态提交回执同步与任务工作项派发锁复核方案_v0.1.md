# S2c 状态提交回执同步与任务工作项派发锁复核方案 v0.1

日期：2026-06-08

状态：当前主动性能切片；先复核证据和边界，不直接进入实现。

## 1. 触发依据

```text
S2b 已闭合：
    任务壳整理侧已复用已有方法虚拟存在指针。
    `普通整理回执到任务壳` 平均约 37309us。
    `候选同步` 平均约 3557us，`当前方法同步` 平均约 4803us。
    `任务壳应用锁持有` 平均约 101960us，最大约 370629us。

S2b 后剩余候选热点：
    `任务壳应用锁/内部阶段耗时` 91 条，内部总耗时平均约 101855us。
    `状态提交回执同步` 平均约 45621us，最大约 125299us。
    最慢阶段分布：状态提交回执同步 72 条，回执方法同步 19 条。
    `任务工作项派发锁持有` 90 条，平均约 54096us，最大约 452740us。
    `任务工作项派发锁等待` 90 条，平均约 30033us，最大约 998771us。
    `任务状态提交阶段` 94 条，平均约 63437us，最慢阶段全部为执行被动提交。
    `任务状态巡检阶段` 124 条，平均约 31243us，等待工作项登记平均约 107us。

安全锚点：
    本轮窗口保留 `任务状态动作动态=<动态主键>` 96 条。
    `任务状态被动提交/逻辑错误`、`任务状态动作动态逻辑错误`、`准备本能调用`、`执行本能方法`、`任务域本能输入包`、`[FTL]` 均为 0。
    `[ERR]=1` 为 D455 观察材料条件不足，不作为 S2c 失败条件。
```

## 2. 目标

```text
第一目标：
    复核 `状态提交回执同步` 是否仍是任务壳应用锁内主耗时。
    将耗时拆清为：提交前准备、执行被动提交、提交后回执字段同步、任务壳镜像同步。

第二目标：
    复核 `任务工作项派发锁` 是否仍存在高等待或长持有。
    将耗时拆清为：同步请求路径、后台派发路径、锁等待、锁内提交、锁后归并。

第三目标：
    根据真实日志决定下一刀：
        若状态提交链仍主导，进入状态提交被动动作内部最小瘦身。
        若派发锁仍主导，进入任务工作项派发锁持有范围复核和缩短。
        若两者均不再主导，S2c 以无实现动作闭合，重新选择下一热点。
```

## 3. 硬边界

```text
任务状态变化仍必须通过 `提交任务状态变化` 动作入口。
不得裸写任务状态，不得跳过任务状态动作动态。
不得把任务筹办 / 任务执行恢复为本能方法、候选方法或动作动态来源。
不得让 worker 先执行后补任务状态账。
不得为了降低派发锁耗时改变任务状态、动作动态、任务壳快照和 worker 派发之间的顺序一致性。
不得把等待、未满足或 D455 条件不足写成完成 / 满足。
诊断必须走独立日志和真实运行日志，不新增 mock、fixture、伪入口或 `--*-check` 回归入口。
若后续实现替换旧锁内路径，旧分支必须删除，不保留双路径兜底。
```

## 4. 代码锚点

```text
任务模块.管理界面线程.impl.cpp:
    `私有_提交任务状态被动动作`
        状态变化提交入口；S2c 不允许绕开。

    `私有_应用工作结果到任务壳`
        当前 `状态提交回执同步` 发生在任务壳应用锁持有期间。
        已有 `任务壳应用锁/内部阶段耗时` 阶段日志。

    `私有_归并完成队列项`
        完成队列项归并到任务壳的入口。

    `私有_消费任务调度队列_按请求`
        同步请求路径中调用 `任务管理工作线程::提交任务工作项`。

    后台派发路径
        现有 `任务工作项派发锁` 日志已能区分锁等待和持有。
```

## 6. 执行步骤

```text
1. 实现前先写断点清单和预测：
       预计 `状态提交回执同步` 与 `任务工作项派发锁` 仍是 S2b 后剩余热点。
       预计任务状态动作动态仍输出，旧本能执行锚点仍为 0。

2. 先复核现有日志是否足以区分：
       `任务壳应用锁/内部阶段耗时`
       `任务状态提交/阶段耗时`
       `任务状态被动提交/内部阶段耗时`
       `任务互斥/持有耗时 | 锁=任务工作项派发锁`
       `任务互斥/等待耗时 | 锁=任务工作项派发锁`

3. 如果现有日志不足：
       只补最小阶段日志。
       不新增业务字段，不写入机器决策结构。
       不改变状态提交和 worker 派发顺序。

4. 如果 `状态提交回执同步` 仍为主耗时：
       回到 `私有_提交任务状态被动动作` 内部阶段。
       优先处理重复同步、重复查找、无变化回执字段同步。
       不绕开 `提交任务状态变化`，不裸写状态。

5. 如果 `任务工作项派发锁` 仍为主耗时：
       先确认锁持有期间是否只做提交队列账，还是包含实际工作执行或重归并。
       只缩短锁内登记和提交范围。
       不把 worker 执行提前到状态动作动态确认之前。

6. 如果主耗时转向日志、快照或 D455：
       S2c 只记录结论，不混入日志策略、快照策略或外设链路改动。
```
