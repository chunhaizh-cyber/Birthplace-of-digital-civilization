# 未知不能作为已安全证据纠偏计划 v0.1

## 1. 纠偏目标

本计划纠偏“因果 5：未知不能作为已安全证据”的规范和代码落点。

正确规则为：

```text
没查过
!= 默认满足

查过且无负向证据
= 可以经提交入口默认满足

当前场景特征值未知
= 证据搜索未完成或搜索前置材料缺口
```

因此目标链路为：

```text
当前场景特征值未知
-> 没有完成证据搜索，或证据搜索前置材料缺失
-> 不能默认满足风险安全因素
-> 需要获得当前场景特征值
```

这不是把未知当危险。未知只表示安全结算所需的因果材料尚未具备，不能直接扣分，也不能直接默认安全。

## 2. 规范核对结论

### 2.1 最新规范已经明确该规则

`基础观察事实可用与基础风险判断分层规范20260526.md` 已明确：

```text
当前场景中相关特征值未知时，场景影响因果条件不可判断。
未知既不能直接扣分，也不能直接默认安全。
没查过 != 默认满足。
查过且无负向证据 = 可以经提交入口默认满足。
特征值未知 = 证据搜索未完成或搜索前置材料缺口。
```

该规范还明确：

```text
筹办不得生成搜索结果、不得写默认满足、不得写因素值。
搜索范围是否完整、是否无负向证据，必须由对象作用方法搜索事实给出。
默认满足的前提不是“没有数据”，而是“按该层该因素的证据搜索规则查过，并且没有找到负向证据”。
```

### 2.2 自我生存闭环规范给出当前链路

`自我存在服务与生存基本因果闭环规范20260601.md` 已明确：

```text
若当前场景特征值未知，则因果条件不可判断。
因果条件不可判断时，不能结算安全，也不能把风险因素默认满足。
只有按该因素的证据搜索规则查过且没有找到负向证据，才允许经提交入口写入无负向证据默认满足。
```

因此 `当前场景特征值明确状态` 的需求不是安全因果链末端的布尔补丁，而是场景影响因素能否进入证据搜索和默认满足提交的前置材料要求。

### 2.3 临时因果视图规范已经支持缺口入树

`需求临时因果视图展开规范20260526.md` 已有：

```text
当前场景特征值未知
-> 当前场景特征值明确状态 未满足
-> 生成当前场景特征值明确需求
```

同时规范禁止把安全链的“无负证据默认满足”规则借给服务链使用。该规则只适用于安全链中完成搜索后的风险因素默认满足，不适用于服务值默认成功、默认优秀或默认满分。

## 3. 代码核对结论

### 3.1 已符合口径的部分

`自我动作实现.外设模块.ixx` 中 `搜索安全因果因素证据` 已具备正确闸门：

```text
缺层级 / 缺因素 / 缺方向 -> 搜索状态=缺参数，材料缺失数量至少为 1
冲突数量 > 0 -> 搜索状态=冲突
搜索范围不完整 或 材料缺失数量 > 0 -> 搜索状态=搜索缺口
负向证据数量 > 0 -> 搜索状态=发现负向证据
搜索完成 + 负向证据为 0 + 置信度 > 0 -> 允许默认满足
```

`提交安全因果因素无负证据默认满足` 也有提交闸门：

```text
搜索状态 == 已完成
默认满足允许状态 == 允许
负向证据数量 == 0
材料缺失数量 == 0
冲突数量 == 0
```

`自我线程模块.impl.cpp` 中线程侧默认满足提交同样读取搜索状态、默认满足允许状态、负向证据数量、材料缺失数量、冲突数量和已入账状态；条件不足时只记录跳过，不写因素值、不写风险安全层总值、不写自我安全值。

`任务模块.筹办.ixx` 中安全因果因素搜索参数筹办只补齐兼容参数，日志明确 `不生成需求=1`、`不写默认满足=1`，符合“筹办不生成搜索结果、不写默认满足”的规范边界。

### 3.2 仍需纠偏的部分

1. `评估存在风险安全值` 在缺少自我关键特征观察或安全因果候选时，会给出：

```text
风险安全值候选 = 0
存在安全度候选 = 场景绝对安全值
评估明确 = true
证据不足原因 = 0
```

这会把“证据不足 / 特征值未知”表达成“零风险且明确”，与“未知不能作为已安全证据”冲突。

2. `安全_评估当前场景安全性` 会基于 `场景风险压力平均值 == 0`、`最高存在风险值 == 0` 生成 `无负向因果默认安全` 来源。若上游存在评估把未知落成零风险，该来源会被误读成“当前场景已安全”。

3. 当前场景影响因素的证据搜索还需要更明确地把：

```text
当前场景特征值明确状态 != 已明确
```

转成：

```text
安全因果因素材料缺失数量 > 0
安全因果因素搜索范围完整状态 != 完整
安全因果因素默认满足允许状态 = 不允许
```

否则“未取得当前场景特征值”与“已搜索无负向证据”在后续聚合视图中仍可能混淆。

4. 风险树缺口消息已经生成 `当前场景特征值明确状态` 需求，但缺口、证据搜索、默认满足提交三者还需要形成硬前置关系：

```text
当前场景特征值未明确
-> 场景影响因素搜索不可完成
-> 场景影响因素不可默认满足
-> 风险安全层不可正式聚合入账
```

## 4. 纠偏后的状态模型

风险安全因素证据状态应至少分为：

```text
未搜索
    搜索状态 = 未执行
    默认满足允许状态 = 不允许

搜索前置材料缺口
    搜索状态 = 缺参数 或 搜索缺口
    材料缺失数量 > 0 或 搜索范围完整状态 != 完整
    默认满足允许状态 = 不允许

已搜索无负向证据
    搜索状态 = 已完成
    负向证据数量 = 0
    材料缺失数量 = 0
    冲突数量 = 0
    搜索置信度 > 0
    可以进入默认满足提交入口

已搜索发现负向证据
    搜索状态 = 发现负向证据
    负向证据数量 > 0
    不允许默认满足
    进入风险值评估或负向影响处置链

搜索冲突
    搜索状态 = 冲突
    冲突数量 > 0
    不允许默认满足
```

`当前场景特征值未知` 必须映射到 `搜索前置材料缺口`，不能映射到 `已搜索无负向证据`。

## 5. 纠偏原则

1. 未知不等于危险，也不等于安全。
2. 默认满足只能由搜索完成后的提交入口写入。
3. 只要当前场景特征值未知，场景影响因素的材料缺失数量必须非零，或搜索范围完整状态必须非完整。
4. 存在风险评估不能用 `风险值=0 + 评估明确=true` 表示材料不足。
5. 候选安全值、投影安全值、正式入账安全值必须区分。
6. 风险树节点表示待评估因素或缺口，不表示该因素已经危险，也不表示该因素已经默认满足。
7. 服务链不得借用安全链的无负证据默认满足规则。

## 6. 纠偏实施切片

### P0 盘点证据搜索和默认满足写入口

目标：

```text
确认所有写入 安全因果因素值 / 默认满足提交状态 / 风险安全层聚合 的入口。
```

验收：

```text
除提交入口外，没有其他路径能把“无数据 / 未搜索 / 特征值未知”写成默认满足。
```

### P1 强化当前场景特征值未知到材料缺口的映射

目标：

```text
当 当前场景特征值明确状态 != 已明确 时，
场景影响因素搜索输入必须携带材料缺失或范围不完整。
```

建议落点：

```text
自我线程模块.impl.cpp 的风险树视图维护和安全因果因素搜索任务输入构造路径。
任务模块.筹办.ixx 的搜索参数复制路径只允许复制已有材料缺失，不自行伪造成搜索完成。
```

验收：

```text
当前场景特征值未知时，安全因果因素证据搜索状态为缺口或未执行。
安全因果因素默认满足允许状态为不允许。
默认满足提交入口日志显示不写因素值。
```

### P2 修正存在风险评估的未知表达

目标：

```text
评估存在风险安全值 在缺少关键材料时返回 评估明确=false，
并写入明确的 证据不足原因。
```

禁止：

```text
缺自我关键特征观察 / 缺安全因果候选 / 缺当前场景特征值
-> 风险安全值候选=0
-> 评估明确=true
```

验收：

```text
存在风险评估全部明确=false。
场景安全判定不能进入“无负向因果默认安全”。
后续风险树生成当前场景特征值明确或证据搜索缺口。
```

### P3 收紧当前场景安全性评估来源

目标：

```text
无负向因果默认安全 只能表示“搜索完成且无负向证据后的候选来源”，
不能由“当前风险压力为 0”单独推出。
```

建议：

```text
将 无负向因果默认安全 的前置条件扩展为：
场景影响因素搜索状态 == 已完成
默认满足允许状态 == 允许
材料缺失数量 == 0
冲突数量 == 0
负向证据数量 == 0
```

验收：

```text
若当前场景特征值未知，即使当前风险压力平均值为 0，也不能出现已安全来源。
```

### P4 建立当前场景特征值明确需求与场景因素搜索的硬前置关系

目标：

```text
当前场景特征值明确状态 未满足
-> 当前场景特征值明确需求入树
-> 场景影响因素证据搜索保持缺口
-> 默认满足提交不发生
```

验收：

```text
需求树中能看到当前场景特征值明确需求。
对应场景影响因素证据搜索任务不写默认满足。
风险安全层聚合标记场景影响因素未入账或材料缺失。
```

### P5 区分候选值、缺口值和正式入账值

目标：

```text
日志、动作动态、控制面板和风险树视图中，
候选安全值不得被展示为正式安全值。
```

验收：

```text
存在以下可区分字段或日志语义：
候选评估值
证据搜索状态
材料缺失数量
默认满足提交状态
安全因果因素已入账状态
风险安全层正式聚合状态
```

### P6 回归验证

验证顺序仍遵守项目规则：

```text
1. 先写预测结果。
2. 构建 Debug x64。
3. 走真实运行路径，不新增模拟入口、夹具入口或伪造动作动态。
4. 用日志模块、状态快照、动作动态和错误日志核对。
```

验收重点：

```text
没查过时，不出现默认满足。
当前场景特征值未知时，不出现默认满足。
查过且无负向证据、材料缺失为 0、冲突为 0、置信度大于 0 时，才允许默认满足提交。
默认满足提交后，才能参与对应风险安全因素的正式入账。
```

## 7. 建议下一步

下一步先执行 P1 + P2：

```text
先把当前场景特征值未知硬映射为搜索材料缺口；
再修正存在风险评估中“证据不足却零风险且明确”的表达。
```

这两个切片是当前链路最容易把未知误当已安全的源头。P3 之后再收紧 `无负向因果默认安全` 的来源条件。
