```text
5. 观察、识别、跟踪只能经需求任务链间接承接，扫描不能直接调用。
```

## 2. 当前代码事实

当前没有 `自我动作实现.扫描.ixx` 文件。旧扫描入口主要分布在：

```text
本能方法类.h
    枚举_本能方法ID::自我_扫描已识别区域 = 6146

本能方法类.cpp
    本能方法显示名：扫描已识别区域

自我动作实现.外设模块.ixx
    确认自我扫描已识别区域规格
    自我扫描已识别区域
    旧函数包含首次发现提交入口和已识别区域扫描入账口径

自我动作实现.外部模块.ixx
    外部模块对旧扫描规格和执行函数的桥接

自我动作实现模块.ixx
    旧扫描函数前置声明
    注册本能函数执行闭环中绑定旧函数
    规格确认 switch 中调用旧规格

自我动作实现.内部模块.ixx
    内部本能函数集字段：扫描已识别区域
    内部变化本能方法判断
    注册内部本能函数执行闭环

任务模块.筹办.ixx
任务模块.管理界面线程.impl.cpp
自检线程模块.impl.cpp
    仍引用 枚举_本能方法ID::自我_扫描已识别区域
```

工程文件当前只登记：

```text
自我动作实现.外设模块.ixx
自我动作实现.外部模块.ixx
自我动作实现.内部模块.ixx
自我动作实现.服务模块.ixx
```

因此新增 `自我动作实现.扫描.ixx` 时必须同步 `鱼巢.vcxproj` 和 `鱼巢.vcxproj.filters`。

## 3. 实施前必须先清理

### 3.1 清理原则

```text
不在旧扫描函数上继续打补丁；
不保留旧扫描函数作为新函数 fallback；
不同时注册旧扫描和新扫描；
不保留“扫描发现存在 / 首次发现提交入口”作为当前扫描语义；
旧名称只允许出现在迁移排查记录或归档说明中，不进入机器判断路径。
```

### 3.2 清理清单

实施前先生成引用清单：

```powershell
rg -n "自我_扫描已识别区域|自我扫描已识别区域|扫描已识别区域|6146" -g "*.h" -g "*.cpp" -g "*.ixx"
```

清理顺序：

```text
1. 决定 6146 是否继续作为扫描方法数字 ID。
2. 将方法正式语义收束为 自我_扫描当前场景。
3. 删除旧函数体 自我扫描已识别区域。
4. 删除外部模块旧桥接函数。
5. 删除或改名内部函数集中的 扫描已识别区域 字段。
6. 将注册闭环改为只注册 自我_扫描当前场景。
7. 将方法显示名改为 扫描当前场景。
8. 清理任务筹办、界面线程、自检线程中的旧枚举引用。
9. 静态扫描确认机器路径中不再出现旧扫描入口。
```

如果第 1 步不能确认，停止实施。

推荐决策：

```text
保留数字 ID 6146；
将枚举名从 自我_扫描已识别区域 改为 自我_扫描当前场景；
不新增第二个扫描 ID；
不保留旧枚举别名。
```

理由：

```text
这样可以避免新旧扫描入口并存；
同时减少任务筹办、方法表和历史数值引用的大范围迁移风险；
但所有机器可见名称必须切换为 自我_扫描当前场景。
```

## 4. 模糊点与确认闸门

以下问题必须在对应切片开始前确认，不能边写边猜。

### 4.1 方法 ID 闸门

```text
问题：
    删除原来扫描本能函数时，是删除旧函数体并复用 6146，
    还是删除旧 ID 并新增一个全新 ID？

推荐：
    复用 6146，重命名为 自我_扫描当前场景。
```

### 4.2 特征类型 ID 闸门

规格说明书要求的部分特征名当前未在代码中直接命中：

```text
本轮应覆盖存在集合
本轮可忽略存在集合
本轮需补条件存在集合
本轮异常未覆盖存在集合
场景维护结果状态
信息完备性状态
内部信息一致性状态
扫描治理输出状态
空间位置当前值来源状态
空间位置当前值可信状态
```

实施前必须形成绑定表：

```text
已有特征可复用 -> 使用既有 特征_*()；
确实缺失 -> 在既有特征定义位置新增 特征_*()；
不得在扫描实现中散落字符串或临时枚举。
```

如果不能确定某个特征是否应新增，停止并提问。

### 4.3 已合法外设数据项闸门

当前代码主要消费 `外设观察报告队列` 的扫描变化报告；规格要求消费“已合法外设数据项”。

实施前必须明确：

```text
外设观察报告中的哪个结构等价于 已合法外设数据项；
哪些字段作为 数据项ID / 来源报告ID / 来源帧ID / 来源外设ID；
哪些材料可以作为 空间位置 / 空间尺寸 / 平面轮廓 / 彩图 / 深度图 / 轮廓极值；
合法化由上游保证，还是扫描入口需要只做预编译诊断。
```

不允许扫描直接把原始相机报告当作合法数据项写入场景。

### 4.4 新模块依赖闸门

旧扫描依赖大量 `自我动作实现.外设模块.ixx` 内部 helper，其中很多位于匿名 namespace。新文件 `自我动作实现.扫描.ixx` 无法直接使用这些内部 helper。

实施前必须选择：

```text
方案 A：
    将扫描必需 helper 收束到新扫描模块内，旧外设模块不再拥有扫描 helper。

方案 B：
    抽出共享 helper 到明确命名的可导出模块，但只抽扫描确实需要的最小集合。

禁止：
    新扫描模块调用旧扫描函数；
    外部模块保留旧扫描桥接作为过渡；
    复制一整套旧外设扫描逻辑造成两份权威。
```

### 4.5 输出场景格式闸门

实施前必须确认现有写入 helper 能否表达：

```text
状态信息集合
信息缺口集合
空信息
写入摘要集合
临时证据集合
处理闭合证据
```

如果不能，需要先补统一写入 helper，而不是在扫描主函数里裸写零散 I64。

### P3 特征类型绑定与输出场景写入

### P4 已合法外设数据项展开

目标：

```text
从外设扫描报告中展开已合法外设数据项队列；
只处理已合法、可比较、可回查或可生成扫描变化候选的数据项；
上游契约错误只走预编译诊断日志 / 弹窗，不进入普通业务需求分支。
```

验收：

```text
外设数据项总数、已取出计数、已成功解析计数、已闭合处理计数可写入运行存在；
所有数据项均闭合处理；
无原始相机报告直接写入场景当前状态。
```

### P5 本轮扫描关注集合

目标：

```text
从当前场景存在集合生成：
    本轮应覆盖存在集合
    本轮可忽略存在集合
    本轮需补条件存在集合
```

必须实现的判断：

```text
属于当前扫描范围
外设视野重合
维护策略是否需要扫描
是否被高优先级跟踪接管
扫描优先级
扫描特征条件是否齐备
```

验收：

```text
未覆盖解释输入只能是：
    本轮应覆盖存在集合 - 本轮外设覆盖存在集合
```

### P6 对应关系与当前状态写入

目标：

```text
处理所有已合法外设数据项；
建立本轮外设覆盖索引；
对锁定同一存在的数据项更新当前状态值 / 基准 / 写入摘要。
```

必须实现的判断：

```text
判断空间位置一致
判断空间尺寸一致
判断轮廓一致
判断轮廓极值一致
判断唯一找回
判断特征是否可比较
判断可记录变化
判断值域冲突
```

边界：

```text
扫描不能创建新的观察特征值；
超值域记录值域冲突，不写正常变化；
唯一找回不能只取最高分。
```

### P7 异常未覆盖解释

目标：

```text
处理本轮异常未覆盖存在集合。
```

流程：

```text
读取当前场景既有状态 / 动态；
预测当前应在空间坐标；
判断预测坐标是否视野外；
判断遮蔽 / 覆盖证据；
判断子层证据是否足够；
无解释时写未观测到 / 消失候选，不删除世界存在。
```

边界：

```text
单轮未覆盖不直接写最终消失；
预测坐标可以作为空间位置当前值，但来源 / 可信 / 视野外状态写到状态信息、动态证据或写入摘要。
```
