# 20260703 桥接型详细设计补齐计划 v0.1

## 0. 文件定位

本文件是详细设计补齐计划，不是代码实现计划，也不是代码落地契约。

目标是把当前外设感知、观察、识别、跟踪、扫描、存在体素、场景体素和需求派生之间缺失的“中间承接设计”补齐，使后续实现映射计划不再在空档中临时造字段、造结构体、让外设越权，或把判断型状态当成一阶事实写入。

本计划完成后，仍不得直接进入代码实施。每一份桥接型详细设计完成后，若要写代码，还必须另行生成对应的实现映射计划 / 代码落地契约。

## 6. 统一文件头要求

```text
上级规范：

相关计划：
权威等级：
当前状态：
不解决范围：
禁止事项：
```

权威等级统一写为：

```text
待完成详细设计；依据规范生成；不覆盖规范；不声明实现完成或验证通过。
```

## 7. 反走样清单

生成这些详细设计时禁止：

```text
1. 把外设报告、日志、说明文本或调试输出当作机器事实。
2. 新增 C++ 结构体作为默认承载方案。
3. 把判断型 bool 或判断型枚举写成外设直接产出的一阶事实。
4. 让外设线程、视觉中间层或先验发布器直接写世界树事实。
5. 让观察、扫描、识别、跟踪直接互相调用。
6. 让像素直接归属世界树稳定存在 E。
7. 让局部体素证据直接写稳定存在体素主模型。
8. 把场景体素快照、ROI 或先验投影当成当前帧观察事实。
9. 因新建存在缺少任意可能特征就批量派生补完需求。
10. 把计划文件当成规范或详细设计使用。
```

## 8. 验证剧本

每份详细设计完成后必须自检：

```text
1. 是否列出上级规范。
2. 是否说明不解决范围。
3. 是否给出项目结构映射口径。
4. 是否区分一阶材料、判断型状态、复合特征 / 治理收束。
5. 是否明确写入方、读取方和禁止写入方。
6. 是否说明失败分流。
7. 是否给出后续实现映射计划需要确认的入口清单。
8. 是否避免新增字段、新结构体、日志判断、说明文本判断和硬编码领域词。
```
