# 需求类逻辑纠偏计划 v0.1

日期：2026-06-20

状态：执行中；不宣称需求类逻辑纠偏完成。

## 0. 目标

围绕 `需求主信息类.h`、`需求类.h`、`需求类.cpp` 和外部调用点，完成需求类边界收口：

```text
1. 所有关于需求信息的读取、判断、更新和入树操作，默认必须调用 需求类 功能函数。
2. 外部代码不得直接解释 需求主信息类 字段作为机器逻辑依据。
3. 需求类自身不得直接操作非需求类主信息字段；需要状态、特征、二次特征、任务、因果、世界树信息时，调用对应类功能函数。
4. 若对应类缺少功能函数，按“缺哪个类补哪个类第一优先”规则生成或修订对应类逻辑纠偏计划；当前缺口放在第一优先，闭合第一优先后返回本计划。
5. 审查需求类中现存结构体、枚举和语义视图是否仍符合当前规范；能删除的删除，不能删除的说明边界和替代条件。
```

本计划不重开 `计划/完成项/20260619_需求类头文件结构体清理与目标逻辑纠偏计划_v0.1.md`，而是在该计划已闭合缺口基础上生成新的需求类总纠偏路线。

## 1. 权威口径

依据：

```text
规范/主信息字段与结构新增准入约束规范20260519.md
规范/需求主信息类规范20260507.md
规范/需求树生长机制规范20260512.md
规范/需求临时因果视图展开规范20260526.md
计划/计划索引.md 第 0 章维护规则
```

需求主信息口径：

```text
1. 需求主信息只是一张目标关系索引卡，不是值类型仓库。
2. 单个执行需求只表达一个原子目标：
   目标宿主 / 被需求存在
   目标特征类型
   当前状态 / 当前特征值
   目标状态 / 目标特征值
   满足关系
3. 多目标、AND / OR、方法路径、因果子链支撑，必须由父子链和目标特征类型解释，不在需求主信息里新增业务字段。
4. 获取途径不进入需求主信息；获取途径只用于生成规则选择和来源追溯。
5. 叶子 / 非叶子只表示树形展开状态，不表示逻辑语义，也不能直接决定是否可任务化。
6. 是否可任务化、如何聚合、是否普通候选方法筹办，必须读取目标特征类型及其抽象特征定义视图。
7. 需求树归自我线程管理；任务管理线程、任务筹办、任务执行不得直接写需求树，只能通过回执、缺口、派生需求消息或统一更新指令提交。
```

## 4. 结构体和枚举初判

第一轮不直接大删协议结构；先区分“协议边界”“只读视图”“临时算法包”“显示 / 日志包”。

### 4.1 暂保留

```text
枚举_需求树更新指令类型
结构_需求树更新指令
```

理由：

```text
当前是自我线程、消息协议和需求类统一入树 / 更新 / 满足 / 删除的结构化协议。
不能在同一切片删除；后续若要简化，应先拆成新增 / 更新 / 满足 / 删除专用函数，再迁移调用方。
```

```text
枚举_需求获取途径
枚举_需求目标语义
枚举_逻辑组织需求类型
```

理由：

```text
三者当前用于生成规则选择和目标语义判定；只要不写入 需求主信息类，符合规范边界。
后续重点不是删除枚举本身，而是防止调用方绕过目标特征类型和抽象特征定义视图直接猜语义。
```

```text
结构_任务初始化上下文
```

理由：

```text
当前用于把需求目标关系转换为任务初始化输入，属于需求 -> 任务边界的结构化输出。
后续需要审查字段是否完整由需求类生成，调用方不得继续从需求主信息裸读同类字段。
```

### 4.2 需审查后简化

```text
结构_需求目标语义视图
结构_需求获取途径语义视图
```

审查点：

```text
1. 是否只是多个只读函数的打包返回。
2. 是否被任务筹办 / 控制面板作为机器逻辑判断依据。
3. 若只为显示层组合文本，应移到临时显示代码。
4. 若机器逻辑确实需要多个结构化标志，可以暂保留，但必须由需求类唯一生成。
```

```text
结构_逻辑组织需求更新输入
```

审查点：

```text
当前是构造逻辑组织需求更新指令的参数包。
若调用方只在少数位置使用，可改为需求类专用构造函数参数或拆成更明确的提交函数。
删除前必须避免新增另一套平行输入包。
```

```text
结构_需求目标视图项
结构_子需求平分权重
结构_需求方向签名
结构_枚举目标校验结果
枚举_枚举目标生产者分级
```

审查点：

```text
1. 若是跨函数公开返回包，先确认调用方数量和消费字段。
2. 若只在单函数内部临时计算，优先改为局部变量或输出参数。
3. `结构_枚举目标校验结果::说明` 是文本字段，只能用于日志 / 诊断；不得进入机器判断。
4. `结构_需求方向签名` 当前从二次特征主信息提取方向，应审查是否应由 二次特征类 提供只读签名函数。
```

### 4.3 私有结构优先内聚

```text
结构_需求目标键
```

处理原则：

```text
该结构当前在 需求类 内部用于目标重叠和去重。
可暂保留为私有实现细节；但其状态、特征、特征值读取必须逐步改为调用 状态类 / 特征类 功能函数。
若后续只有单处使用，可内联为函数局部结构。
```

## 6. 需求类自身跨类操作审查

当前需要优先检查的需求类内部路径：

```text
状态主信息_已加锁
状态特征类型主键_已加锁
生成需求目标键_已加锁
生成需求方向签名
校验枚举目标合法性
校验更新指令枚举目标
生成任务初始化上下文
获取需求方向
重写需求树SQL投影
```

审查口径：

```text
1. 需求类可以组织需求目标关系，但不应直接解释 状态节点主信息类 / 特征节点主信息类 / 二次特征主信息类 字段。
2. 状态值、状态主体、状态特征类型应调用 状态类 功能函数。
3. 特征比较、枚举值域、抽象特征查询和比较方法应调用 特征类 功能函数。
4. 二次特征方向签名、方向区间、差值、标量值读取应调用 二次特征类 功能函数。
5. 节点父 / 子 / 下 链如果属于世界树基础信息结构，应调用 世界树类 功能函数；需求类自身独立树内部遍历可保留。
6. SQL 投影、控制面板和日志显示可以后置，但不得反向成为机器判断依据。
```

跨类缺口生成规则：

```text
1. 缺状态类函数：
   修订或生成 状态类逻辑纠偏计划，把缺口放第一优先。

2. 缺特征类函数：
   修订 特征类逻辑纠偏计划，把缺口放第一优先。

3. 缺二次特征类函数：
   修订 二次特征类逻辑纠偏计划，把缺口放第一优先。

4. 缺任务类函数：
   生成或修订 任务类逻辑纠偏计划，把缺口放第一优先。

5. 缺世界树类函数：
   修订 世界树类逻辑纠偏计划；如果当前世界树计划正在执行且不阻塞本切片，只登记短缺口，不打断当前主动队列。

6. 缺语素 / 语言函数：
   修订对应类逻辑纠偏计划；不得用词面字符串作为机器判断替代。
```
