# 自我所在场景复杂动作提取计划 v0.1

日期：2026-06-26

## 0. 定位

本计划是 `计划/20260626_状态动态因果生成校准与因果信息生成逻辑完善计划_v0.1.md` 的外部场景动作提取配套计划，专门处理：

```text
自我当前所在场景中的现实世界动态信息
-> 原子动态归并
-> 动作候选提取
-> 复杂动作信息样本
-> 动作模式分支
-> 因果样本中的动作项
```

本计划不改变 `计划/计划索引.md` 第 1 章当前主动队列。执行前需用户明确切入，或 P1c/P0.5b 证明“外部场景复杂动作提取”已经阻塞动态归纳动作信息和因果生成链。

核心口径：

```text
外部场景动态只描述场景存在 / 场景关系的变化。
复杂动作不是直接写出来的动作名，而是从一组同主体、同窗口、可复现的动态模式中提取出的动作信息。
外部动作信息可以进入因果样本，但不得直接伪装成自我可调用方法。
```

## 2. 本计划解决什么

只解决自我所在场景中外部现实动态到复杂动作信息的提取方案：

```text
已入账场景状态序列
-> 场景存在 / 场景关系原子动态
-> 动态窗口
-> 主体一致性与关系连续性校验
-> 运动基元候选
-> 多基元组合
-> 复杂动作候选
-> 动作信息样本
-> 动作模式分支 / 反例统计
-> 因果样本动作字段
```

其中“动作信息样本”只表示一次或一组动态可被解释为某类动作候选，不表示该动作规则已经稳定成立。

## 3. 本计划不解决什么

```text
1. 不把原始相机帧、观察像素簇或未裁决观察候选直接当作世界事实动态。
2. 不替代观察、扫描、跟踪、识别四类自我场景认知方法边界。
3. 不把外部存在的动作候选登记成自我方法动作动态。
4. 不把“人走 / 杯子被拿起 / 门打开”等外部动作直接学习成自我可调用方法。
5. 不用单次动态直接沉淀稳定动作规则或稳定动作致变因果。
6. 不用自由文本动作名作为机器判断字段；动作类型、主体、客体、方向、参数和证据动态必须结构化。
7. 不直接实现 D455 视觉算法或新增 CV 模型；本计划只规定世界树侧动作提取链路。
8. 不提前宣称扫描需求自然生长闭合、自我苏醒完成或初步成熟完成。
```

## 5. 总体方案

推荐把外部场景复杂动作提取做成四层：

```text
第一层：原子动态层
    只记录存在 / 关系的状态变化。

第二层：动态片段层
    按主体、客体、关系和时间窗口把原子动态归组。

第三层：动作候选层
    把片段组解释为运动基元和复杂动作候选。

第四层：动作信息样本层
    输出可进入因果样本的结构化动作信息。
```

存储形态建议：

```text
当前场景动作提取树
    当前场景
        动态窗口
            主体片段组
                原子动态
                关系动态
                运动基元候选
                复杂动作候选
                动作信息样本
```

这棵树是提取和检索视图，不替代状态树、动态树和因果树；权威事实仍在状态 / 动态 / 因果对应结构中。

## 6. 分步实施

### P0：冻结输入入口和证据边界

目标：

```text
确认动作提取只能读取：
1. 已入账当前场景状态；
2. 已入账当前场景动态；
3. 已裁决可交付观察材料派生出的场景事实；
4. 可只读参考的运行期心像缓存。
```

禁止：

```text
1. 原始相机帧直接进入动作提取；
2. 未归属观察候选直接进入动作提取；
3. 场景体素 / 运行期心像缓存直接裁决事实；
4. 观察材料绕过质量验证、同一性比较、归属判断和事实提交。
```

输出：

```text
实施记录/YYYYMMDD_自我所在场景复杂动作提取_Codex断点清单.md
动作提取输入入口清单
可读取场景动态类型清单
禁止读取证据清单
```

### P1：原子动态标准化

目标：

```text
把场景存在和场景关系的状态变化统一压成可比较的原子动态。
```

首批原子动态类型：

```text
位置变化：P1 -> P2
速度变化：静止 -> 移动 / 低速 -> 高速
方向变化：D1 -> D2
高度变化：低 -> 高 / 高 -> 低
姿态变化：站立 -> 弯曲 / 压缩 -> 伸展
可见性变化：可见 -> 不可见 / 不可见 -> 可见
接触关系变化：未接触 -> 接触 / 接触 -> 分离
支撑关系变化：有支撑 -> 失去支撑 / 无支撑 -> 建立支撑
遮挡关系变化：未遮挡 -> 遮挡 / 遮挡 -> 显露
相对距离变化：接近 / 远离 / 保持
包含关系变化：进入 / 离开
开合状态变化：关闭 -> 打开 / 打开 -> 关闭
```

验收：

```text
每个原子动态必须能回查动态主体、初始状态、结果状态、记录场域和证据来源。
```

### P2：动态窗口和片段组

目标：

```text
按时间连续性、主体一致性和关系连续性生成动态片段组。
```

窗口规则：

```text
1. 同一主体连续变化优先归为主体片段组。
2. 两个存在之间的接触、支撑、遮挡、相对距离变化优先归为关系片段组。
3. 身份不稳定、跟踪断裂或主体切换时必须拆窗。
4. 时间缺口超过阈值时拆窗，不能硬拼成一个动作。
5. 自我相机位姿变化导致的相对位置变化必须单独标记，避免误判为外部存在移动。
```

输出：

```text
动态窗口ID
主体片段组ID
关系片段组ID
窗口起止时间
主体连续性状态
关系连续性状态
缺口 / 冲突项
```

### P3：运动基元候选提取

目标：

```text
从片段组中提取低层运动基元，作为复杂动作组合的积木。
```

首批运动基元：

```text
移动：位置连续变化且主体身份连续。
停止：位置变化低于阈值并保持。
接近：主体与客体距离持续减小。
远离：主体与客体距离持续增大。
上升：高度持续增大。
下降：高度持续减小。
旋转：方向或姿态角连续变化。
压缩：主体结构高度降低或关键部位靠近。
伸展：主体结构高度增加或关键部位远离。
接触：接触关系从无到有。
分离：接触关系从有到无。
支撑建立：支撑关系从无到有。
支撑丢失：支撑关系从有到无。
遮挡：遮挡关系从无到有。
显露：遮挡关系从有到无。
同步移动：两个主体相对位姿近似保持且共同移动。
```

每个基元候选必须携带：

```text
基元类型
主体
客体或关系对象
方向 / 参数
起止时间
证据动态集合
冲突证据集合
```

### P4：复杂动作候选组合

目标：

```text
用运动基元组合生成复杂动作候选。
```

首批复杂动作模式：

```text
走：
    主体位置连续前移
    支撑 / 姿态呈周期变化
    无明显腾空阶段

跑：
    主体位置连续快速前移
    支撑 / 姿态呈周期变化
    可有短暂腾空或速度阈值明显高于走

跳：
    压缩
    上升
    支撑丢失
    下降
    支撑建立

拿起：
    操作者与客体接触
    客体支撑丢失
    客体上升
    操作者与客体同步移动

放下：
    操作者与客体同步下降
    客体支撑建立
    操作者与客体分离或接触弱化

推动：
    操作者与客体接触
    客体沿接触方向移动
    客体未被拿起或支撑关系未完全丢失

掉落：
    客体支撑丢失
    客体下降
    末端接触或支撑重新建立
    缺少可归因操作者接触时先标记为外部事件候选

打开门：
    门体围绕门轴旋转
    开合状态 关闭 -> 打开
    通行 / 可见关系变化

关闭门：
    门体围绕门轴旋转
    开合状态 打开 -> 关闭
    通行 / 可见关系变化

遮挡：
    遮挡主体进入被遮挡主体与观察源之间
    被遮挡主体可见性下降

显露：
    遮挡关系解除
    被遮挡主体可见性恢复
```

复杂动作候选输出不是最终动作事实，而是：

```text
动作信息样本候选
候选动作类型
匹配到的硬条件
匹配到的软证据
冲突证据
竞争候选
待补证据
```

### P5：竞争候选和反例处理

目标：

```text
同一动态窗口允许多个动作候选并存，不强行压成唯一解释。
```

典型竞争：

```text
杯子位置上升：
    拿起
    掉落后反弹
    被推入斜面
    自我视角变化造成相对位置变化

人位置变化：
    走
    跑
    被载具带动
    跟踪身份错配

门状态变化：
    人打开
    自动门打开
    风导致打开
    观察角度变化误判
```

比较规则：

```text
1. 先保留竞争候选，再用证据强弱排序。
2. 缺关键证据时输出待补证据，不补写结论。
3. 反例样本不得删除，只更新候选分支计数。
4. 常见背景条件不能因为高频出现而成为动作核心条件。
```

### P6：动作信息样本结构

目标：

```text
把复杂动作候选压成可进入因果样本的动作信息样本。
```

最小字段：

```text
动作类型
动作来源场域 = 自我当前所在场景
动作主体
动作客体
动作方向 / 参数
动作起止时间
动作阶段集合
证据动态集合
冲突证据集合
竞争候选集合
提取方法或识别方法
动作样本状态 = 新生 / 待验证 / 弱可信 / 被削弱 / 淘汰 / 可入因果样本
```

硬边界：

```text
1. 动作主体必须是场景存在或场景关系中的存在。
2. 动作证据必须来自当前场景动态或已裁决观察事实派生动态。
3. 提取方法只是识别来源，不等于动作本身。
4. 外部动作信息不得自动变成自我可执行方法候选。
```

### P7：动作族和动作模式分支

目标：

```text
把同类动作信息样本放入动作族，支持后续检索、比较和因果生成。
```

动作族结构建议：

```text
动作族
    动作类型
    主体类型模板
    客体类型模板
    结果状态模板集合
    样本集合
    分支集合
        硬条件
        软高频证据
        分化条件
        反例计数
        最近命中时间
        最近失败时间
```

分支原则：

```text
1. 同类动作可以有多个分支，例如“门打开”可由人推、自动门机制、风力触发分别形成分支。
2. 分支内做硬交集和软交集；不同分支不得做总交集。
3. 动作族只服务动作识别、解释和因果样本生成，不直接替代因果族。
```

### P8：因果样本交接

目标：

```text
把动作信息样本交给因果类，生成外部场景动作致变因果候选样本。
```

标准交接：

```text
前置场景状态 S_pre
    + 动作信息 A_scene
        -> 后置场景状态 S_post
```

交接要求：

```text
1. S_pre 来自动作窗口前的场景状态。
2. A_scene 来自动作信息样本，不是方法 ID 或文本动作名。
3. S_post 来自动作窗口后的场景状态变化。
4. 证据动态集合必须包含动作主体动态、关键关系动态和主果变化动态。
5. 单次交接只生成因果样本或待验证动作致变因果候选，不生成稳定因果规则。
```

任务筹办消费边界：

```text
外部场景动作致变因果：
    可用于解释、预测、需求投影和观察补齐。

自我主动动作致变因果：
    条件满足且已映射到自我方法时，才可作为方法候选。

外部动作信息：
    未完成“自我可执行方法映射”前，不得直接进入自我任务筹办方法候选。
```

### P9：真实验证路线

验证必须使用真实运行路径和真实日志，不用模拟样本、夹具样本、伪造入口或伪造动作动态。

首批验证剧本：

```text
1. 已确认存在位置连续变化 -> 移动动作候选。
2. 已确认存在与客体接触 + 客体支撑丢失 + 上升 -> 拿起候选。
3. 客体支撑丢失 + 下降 + 重新支撑 -> 掉落候选。
4. 门体旋转 + 开合状态变化 -> 打开 / 关闭候选。
5. 自我相机位姿变化 + 外部相对位置变化 -> 排除外部存在主动移动。
```

每个剧本先写预测：

```text
输入动态窗口应包含哪些原子动态；
应提取哪些运动基元；
应生成哪些复杂动作候选；
应有哪些竞争候选或待补证据；
是否允许交给因果类；
是否禁止进入自我方法候选。
```

验收证据：

```text
状态节点回读
动态节点回读
动态窗口日志
运动基元候选日志
复杂动作候选日志
动作信息样本回读
因果样本入族日志
反例 / 竞争候选统计
```

## 7. 停止条件

遇到以下情况必须停止动作提取或降级为待补证据：

```text
1. 缺动态主体。
2. 缺记录场域。
3. 只有原始观察材料，没有事实提交后的场景状态 / 动态。
4. 主体身份不稳定或跟踪断裂。
5. 自我位姿变化未被排除，无法判断外部存在是否真实移动。
6. 关键关系动态缺失，例如拿起缺接触或支撑关系变化。
7. 多个竞争候选无法排序，且缺少可补证据入口。
8. 试图把外部动作候选直接当作自我方法动作动态。
9. 试图用单次样本宣称稳定动作规则或稳定因果规则。
```

## 8. 冲突和待确认点

### 8.1 外部动作信息与方法动作动态的命名冲突

处理口径：

```text
外部动作信息：
    由场景存在 / 关系动态提取，用于解释外部现实动作。

方法动作动态：
    由自我方法执行造成事实变化，必须绑定来源方法。
```

二者都可以向因果样本提供动作字段，但不能互相冒充。

### 8.2 场景体素和观察材料的事实权冲突

处理口径：

```text
场景体素和观察材料可以提供候选证据；
只有事实提交后的当前场景状态 / 动态可以作为动作提取的正式输入。
```

### 8.3 外部动作能否进入任务筹办候选

处理口径：

```text
外部动作本身不能直接成为自我方法候选。
只有当外部动作模式完成“自我可执行方法映射”，并形成自我主动动作致变因果后，才允许进入任务筹办候选。
```

待确认：

```text
后续是否需要单独建立“外部动作模式 -> 自我可执行方法映射计划”。
```
