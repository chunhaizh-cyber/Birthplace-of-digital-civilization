# 自我所在场景复杂动作提取计划 v0.1

日期：2026-06-26

## 0. 定位

本计划是 `计划/20260626_状态动态因果生成校准与因果信息生成逻辑完善计划_v0.1.md` 的外部场景动作提取配套计划，专门处理：

```text
自我当前所在场景中的现实世界动态信息
-> 原子动态归并
-> 动作候选提取
-> 动作包含判定
-> 重复样本统计
-> 因果样本中的动作项
```

本计划不改变 `计划/计划索引.md` 第 1 章当前主动队列。执行前需用户明确切入，或 P1c/P0.5b 证明“外部场景复杂动作提取”已经阻塞动态归纳动作信息和因果生成链。

2026-06-27 路由修订：

```text
本计划属于后续外部数据 / 外设观察阶段。
只有当内部需求树自然生长出外设观察 / D455 工作需求，且外设 D455 能正常工作并提供真实外部数据后，才允许恢复执行。
没有真实外部数据时，不测试、不枚举、不验证“走 / 跑 / 跳 / 拿起 / 放下 / 推动 / 掉落 / 开关门”等动作候选。
外部动作能提取出什么，应由算法基于真实动态窗口和状态证据判定，不由当前代码计划预设为固定业务链。
```

核心口径：

```text
外部场景动态只描述场景存在 / 场景关系的变化。
复杂动作不是直接写出来的动作名，而是从一组同主体、同窗口、可复现的动态模式中提取出的动作信息。
外部动作信息可以进入因果样本，但不得直接伪装成自我可调用方法。
本计划不要求新增结构体、主信息字段或并行权威账本；动作提取先作为复用既有状态、动态、因果证据链的判定逻辑和查询视图。
```

## 2. 本计划解决什么

只解决自我所在场景中外部现实动态到复杂动作信息的提取方案：

```text
已入账场景状态序列
-> 场景存在 / 场景关系原子动态
-> 动态窗口
-> 主体一致性与关系连续性校验
-> 运动基元候选
-> 多基元组合
-> 复杂动作候选
-> 动作包含判定
-> 重复样本 / 反例统计
-> 因果样本动作字段
```

其中“动作包含判定”只表示一次因果样本中的目标特征变化与某个已成型动作实例完成了足够绑定，不表示该动作规则已经稳定成立。

## 3. 本计划不解决什么

```text
1. 不把原始相机帧、观察像素簇或未裁决观察候选直接当作世界事实动态。
2. 不替代观察、扫描、跟踪、识别四类自我场景认知方法边界。
3. 不把外部存在的动作候选登记成自我方法动作动态。
4. 不把“人走 / 杯子被拿起 / 门打开”等外部动作直接学习成自我可调用方法。
5. 不用单次动态直接沉淀稳定动作规则或稳定动作致变因果。
6. 不用自由文本动作名作为机器判断字段；动作类型、主体、客体、方向、参数和证据动态必须结构化。
7. 不直接实现 D455 视觉算法或新增 CV 模型；本计划只规定世界树侧动作提取链路。
8. 不新增动作提取专用结构体、主信息字段、动作族持久结构或动作绑定结构；优先复用存在、场景、特征、状态、动态、因果样本、动态证据集合和基础计数。
9. 不提前宣称扫描需求自然生长闭合、自我苏醒完成或初步成熟完成。
```

## 4. 既有结构复用表

本计划的工程入口不是“新增动作结构体”，而是给既有状态 / 动态 / 因果样本增加判定流程。实现前如确需新增字段或结构，必须另走 `规范/主信息字段与结构新增准入约束规范20260519.md` 和结构审计计划，不在本计划内直接默认新增。

| 判定概念 | 复用既有结构 | 读取 / 派生内容 | 写入边界 | 验证方式 |
| --- | --- | --- | --- | --- |
| 目标特征变化 | 当前场景存在、特征、状态节点、状态迁移动态 | 目标存在、目标特征类型、初始值、结果值、特征变化动态 | 已有状态 / 动态写入链 | 可回查宿主、特征、前态、后态和动态端点 |
| 动态证据集合 | 动态节点集合、同源变化证据组、观察事实派生动态 | 时间窗内同主体 / 强关系主体的原子动态 | 已有动态链和因果样本证据引用 | 每条动态有存在主体和记录场域 |
| 动作实例候选 | 运行期判定结果，不新增持久结构 | 动作类型、动作主体、客体、起止时间、动作证据动态、来源识别方法 | 可作为因果样本动作字段候选；不得直接写成稳定规则 | 可回答谁在动、动作是什么、何时发生、证据来自哪里 |
| 绑定判定 | 运行期评分 / 日志 / 因果样本基础计数 | 时间绑定、主体 / 客体绑定、特征结果绑定、证据链绑定、排他性 | 不新增动作绑定结构体；必要时写入实施记录或因果基础计数 | ContainsAction 判定可复算 |
| 反例和竞争候选 | 因果样本、动态证据、基础计数 | 候选动作不成立、存在更强替代动作、动作出现但目标特征未变 | 不删除证据，只更新计数或候选状态 | 反例可回查，候选排序可解释 |
| 因果动作项 | 因果样本 / 因果主信息既有动作字段 | 已确认包含动作或高可信动作候选 | 只经因果类入口写入，不绕过因果类 | 动作字段不是方法 ID 或文本动作名 |

## 5. 总体方案

推荐把外部场景复杂动作提取做成四层运行期判定：

```text
第一层：原子动态层
    只读取存在 / 关系的状态变化。

第二层：动态片段层
    按主体、客体、关系和时间窗口把原子动态归组；这是查询视图，不是新增存储树。

第三层：动作候选层
    把片段组解释为运动基元和复杂动作候选。

第四层：动作包含判定层
    判断已成型动作实例是否可以进入该因果样本的动作字段。
```

核心判定式：

```text
某个特征类型的因果样本“包含了一个动作”
=
在该特征变化的因果时间窗内，
存在一个已经成型的动作实例 A，
并且 A 与该特征变化之间完成了：
    时间绑定
    主体 / 客体绑定
    特征结果绑定
    证据链绑定
```

其中若动作 A 通过动作致变动态解释目标特征变化，则同源匹配必须先成立：

```text
目标状态迁移动态 D_state:
    E.FT-X = V0@T0 -> V1@T1

动作致变动态 D_action:
    E.FT-X 在动作 A 作用下变化，动作时间段 [Ta0, Ta1]

同源成立：
    E 一致；
    FT-X 一致；
    T0 <= Ta0；
    Ta1 <= T1。
```

动作主体可以是 E 自身，也可以是作用于 E 的外部存在；但进入目标特征变化的动作致变动态主体必须落到被改变的 E.FT-X 上。若动作动态只描述观察者、相机、方法执行实例或任务步骤自身状态，只能作为过程证据，不能替代目标存在的动作致变动态。

形式化表达：

```text
ContainsAction(CS, A) =
    HasFeatureTransition(CS)
 ∧  HasActionInstance(A)
 ∧  TemporalBind(CS, A)
 ∧  RoleBind(CS, A)
 ∧  EffectBind(CS, A)
 ∧  EvidenceBind(CS, A)
 ∧  QualityOK(CS, A)
 ∧  NoStrongerAlternative(CS, A)
```

最小追问：

```text
谁在动？
动作是什么？
动作什么时候发生？
动作和哪个存在绑定？
动作之后哪个特征从什么值变成什么值？
这个变化是否由同一组动态证据支持？
```

## 6. 分步实施

### P0：冻结输入入口和证据边界

目标：

```text
确认动作提取只能读取：
1. 已入账当前场景状态；
2. 已入账当前场景动态；
3. 已裁决可交付观察材料派生出的场景事实；
4. 可只读参考的运行期心像缓存。
```

禁止：

```text
1. 原始相机帧直接进入动作提取；
2. 未归属观察候选直接进入动作提取；
3. 场景体素 / 运行期心像缓存直接裁决事实；
4. 观察材料绕过质量验证、同一性比较、归属判断和事实提交。
```

输出：

```text
实施记录/YYYYMMDD_自我所在场景复杂动作提取_Codex断点清单.md
动作提取输入入口清单
可读取场景动态类型清单
禁止读取证据清单
```

P0 阻塞判定：

```text
若找不到已入账当前场景动态入口：
    不进入 P1；
    转为场景 / 动态类入口缺口。

若只有观察材料，没有事实提交后的状态 / 动态：
    不进入动作提取；
    转为外设观察事实提交缺口。

若动作候选需要场景体素辅助：
    场景体素只能作为候选证据；
    不改变事实来源权。
```

### P1：原子动态标准化

目标：

```text
把场景存在和场景关系的状态变化统一压成可比较的原子动态。
```

首批原子动态类型：

```text
位置变化：P1 -> P2
速度变化：静止 -> 移动 / 低速 -> 高速
方向变化：D1 -> D2
高度变化：低 -> 高 / 高 -> 低
姿态变化：站立 -> 弯曲 / 压缩 -> 伸展
可见性变化：可见 -> 不可见 / 不可见 -> 可见
接触关系变化：未接触 -> 接触 / 接触 -> 分离
支撑关系变化：有支撑 -> 失去支撑 / 无支撑 -> 建立支撑
遮挡关系变化：未遮挡 -> 遮挡 / 遮挡 -> 显露
相对距离变化：接近 / 远离 / 保持
包含关系变化：进入 / 离开
开合状态变化：关闭 -> 打开 / 打开 -> 关闭
```

验收：

```text
每个原子动态必须能回查动态主体、初始状态、结果状态、记录场域和证据来源。
```

### P2：动态窗口和片段组

目标：

```text
按时间连续性、主体一致性和关系连续性生成动态片段组。
```

窗口规则：

```text
1. 同一主体连续变化优先归为主体片段组。
2. 两个存在之间的接触、支撑、遮挡、相对距离变化优先归为关系片段组。
3. 身份不稳定、跟踪断裂或主体切换时必须拆窗。
4. 时间缺口超过阈值时拆窗，不能硬拼成一个动作。
5. 自我相机位姿变化导致的相对位置变化必须单独标记，避免误判为外部存在移动。
```

输出：

```text
动态窗口ID
主体片段组ID
关系片段组ID
窗口起止时间
主体连续性状态
关系连续性状态
缺口 / 冲突项
```

### P3：运动基元候选提取

目标：

```text
从片段组中提取低层运动基元，作为复杂动作组合的积木。
```

首批运动基元：

```text
移动：位置连续变化且主体身份连续。
停止：位置变化低于阈值并保持。
接近：主体与客体距离持续减小。
远离：主体与客体距离持续增大。
上升：高度持续增大。
下降：高度持续减小。
旋转：方向或姿态角连续变化。
压缩：主体结构高度降低或关键部位靠近。
伸展：主体结构高度增加或关键部位远离。
接触：接触关系从无到有。
分离：接触关系从有到无。
支撑建立：支撑关系从无到有。
支撑丢失：支撑关系从有到无。
遮挡：遮挡关系从无到有。
显露：遮挡关系从有到无。
同步移动：两个主体相对位姿近似保持且共同移动。
```

每个基元候选必须携带：

```text
基元类型
主体
客体或关系对象
方向 / 参数
起止时间
证据动态集合
冲突证据集合
```

### P4：复杂动作候选组合

目标：

```text
用运动基元组合生成复杂动作候选。
```

首批复杂动作模式：

```text
走：
    主体位置连续前移
    支撑 / 姿态呈周期变化
    无明显腾空阶段

跑：
    主体位置连续快速前移
    支撑 / 姿态呈周期变化
    可有短暂腾空或速度阈值明显高于走

跳：
    压缩
    上升
    支撑丢失
    下降
    支撑建立

拿起：
    操作者与客体接触
    客体支撑丢失
    客体上升
    操作者与客体同步移动

放下：
    操作者与客体同步下降
    客体支撑建立
    操作者与客体分离或接触弱化

推动：
    操作者与客体接触
    客体沿接触方向移动
    客体未被拿起或支撑关系未完全丢失

掉落：
    客体支撑丢失
    客体下降
    末端接触或支撑重新建立
    缺少可归因操作者接触时先标记为外部事件候选

打开门：
    门体围绕门轴旋转
    开合状态 关闭 -> 打开
    通行 / 可见关系变化

关闭门：
    门体围绕门轴旋转
    开合状态 打开 -> 关闭
    通行 / 可见关系变化

遮挡：
    遮挡主体进入被遮挡主体与观察源之间
    被遮挡主体可见性下降

显露：
    遮挡关系解除
    被遮挡主体可见性恢复
```

动作模式状态：

```text
草案模式
待样本模式
已有候选样本
已有反例
可参与候选排序
可进入因果样本候选
```

第一版动作模式状态：

```text
全部默认为：
    草案模式 + 待真实样本验证。

不得把本节列出的动作模式当作已经成熟的动作识别规则。
```

复杂动作候选输出不是最终动作事实，而是：

```text
动作包含候选
候选动作类型
匹配到的硬条件
匹配到的软证据
冲突证据
竞争候选
待补证据
```

### P5：竞争候选和反例处理

目标：

```text
同一动态窗口允许多个动作候选并存，不强行压成唯一解释。
```

典型竞争：

```text
杯子位置上升：
    拿起
    掉落后反弹
    被推入斜面
    自我视角变化造成相对位置变化

人位置变化：
    走
    跑
    被载具带动
    跟踪身份错配

门状态变化：
    人打开
    自动门打开
    风导致打开
    观察角度变化误判
```

比较规则：

```text
1. 先保留竞争候选，再用证据强弱排序。
2. 缺关键证据时输出待补证据，不补写结论。
3. 反例样本不得删除，只更新候选分支计数。
4. 常见背景条件不能因为高频出现而成为动作核心条件。
```

### P6：动作包含判定

目标：

```text
判断复杂动作候选是否能作为当前因果样本中的动作项。
```

判定结果只作为运行期结论或因果样本动作字段的输入，不要求新增 `因果样本动作绑定` 之类结构体。

动作成型条件：

```text
A.动作主体存在
A.动作类型明确
A.动作证据动态集合非空
A.起止时间明确或可估计
A.动作置信度达到阈值
```

包含动作的七项判定：

```text
1. 动作成型：
    动作不是一个词，必须由动态证据形成。

2. 时间嵌入：
    动作时间窗被因果样本目标特征变化时间窗包含，或在采样误差 ε 内满足包含关系；
    结果特征变化不得早于动作发生。

3. 主体 / 客体绑定：
    动作主体、动作客体、方法执行实例或场景关系必须与目标存在发生结构绑定。

4. 特征结果绑定：
    动作结果特征集合包含目标特征类型，或动作参数方向与目标特征变化方向一致。

5. 证据链绑定：
    优先满足同一存在、同一特征类型、动作动态时间段被状态迁移动态时间段包含；
    任务、方法执行实例、观察帧组、轨迹、坐标系版本、事件、同源变化证据组或动态证据集合只作辅助证据。

6. 非空壳重命名：
    动作证据动态集合不得只是目标特征变化动态的换名；
    若只能做到这一点，只能降级为原子动作候选或结果型动作。

7. 无更强替代动作：
    存在更强替代动作时，不确认包含，只保留候选包含和待补证据。
```

判定状态：

```text
不包含
弱动作候选
强动作候选
已确认包含
原子动作候选
多动作序列成员
冲突待复验
```

Q10000 评分建议：

```text
动作包含评分 =
    动作成型评分           * 0.20
  + 时间绑定评分           * 0.15
  + 主体/客体绑定评分      * 0.20
  + 特征结果绑定评分       * 0.25
  + 证据链闭合评分         * 0.15
  + 排他性评分             * 0.05

>= 8500      已确认包含动作
7000 - 8499  高可信动作候选
5000 - 6999  弱动作候选，需复验
< 5000       不认为包含动作
```

#### 6.1 评分参数状态

Q10000 评分权重当前为第一版经验参数，只作为候选排序依据，不作为稳定动作规则的权威定义。

参数修改条件：

```text
1. 真实样本中连续出现误判。
2. 反例样本显示某项权重过高或过低。
3. 动作类型不同导致绑定项重要性不同。
4. 有实施记录说明修改原因、样本证据和影响范围。
```

禁止：

```text
1. 不得为了让单次样本通过而临时调高评分。
2. 不得用评分替代硬边界。
3. 不得让评分结果绕过因果类入口直接写稳定因果。
```

硬边界：

```text
1. 动作主体必须是场景存在或场景关系中的存在。
2. 动作证据必须来自当前场景动态或已裁决观察事实派生动态。
3. 提取方法只是识别来源，不等于动作本身。
4. 外部动作信息不得自动变成自我可执行方法候选。
```

### P7：重复样本升级规则

目标：

```text
同一特征类型、同一变化方向、相似前置状态下，重复出现的动作包含判定可以提高动作候选强度。
但升级过程复用因果样本、动态证据集合和基础计数，不新增动作族结构体。
```

升级指标：

```text
N：
    动作 A 至少在 N_min 个同类因果样本中被判定为已确认包含。

Support(A)：
    包含 A 的 FT-X 变化样本数 / FT-X 同类变化样本总数。

EffectRate(A)：
    A 出现后产生 FT-X 同类变化的次数 / A 在相似前置状态下出现的总次数。

Lift(A)：
    P(FT-X变化 | S_pre, A) / P(FT-X变化 | S_pre, 非A)。

RoleStability(A)：
    A 的主体、客体、目标特征绑定关系稳定度。
```

建议升级阈值：

```text
N >= N_min
Support(A) >= 0.7
EffectRate(A) >= 0.7
Lift(A) > 1.2
RoleStability(A) >= 0.8
平均动作包含评分 >= 8500
```

升级结果：

```text
满足阈值：
    A 可以作为该因果信息的动作项候选，交由因果类按既有规则写入。

不满足阈值：
    A 仍保留为动作候选或待复验证据，不写成稳定因果动作。
```

多动作情况：

```text
若多个动作总是以固定顺序共同出现，不强行选一个动作。
先按前置动作、核心因果动作、后续结果动作区分。
只有直接改变目标特征的动作，才优先作为核心因果动作。
```

### P8：因果样本交接

目标：

```text
把通过 ContainsAction 判定的动作候选交给因果类，生成外部场景动作致变因果候选样本。
```

标准交接：

```text
前置场景状态 S_pre
    + 动作信息 A_scene
        -> 后置场景状态 S_post
```

交接要求：

```text
1. S_pre 来自动作窗口前的场景状态。
2. A_scene 来自已成型动作实例和 ContainsAction 判定结果，不是方法 ID 或文本动作名。
3. S_post 来自动作窗口后的场景状态变化。
4. 证据动态集合必须包含动作主体动态、关键关系动态和主果变化动态。
5. 单次交接只生成因果样本或待验证动作致变因果候选，不生成稳定因果规则。
```

任务筹办消费边界：

```text
外部场景动作致变因果：
    可用于解释、预测、需求投影和观察补齐。

自我主动动作致变因果：
    条件满足且已映射到自我方法时，才可作为方法候选。

外部动作信息：
    未完成“自我可执行方法映射”前，不得直接进入自我任务筹办方法候选。
```

#### 8.1 外部动作到自我方法映射边界

外部动作进入任务筹办候选前，必须另开计划：

```text
计划名：
    外部动作模式到自我可执行方法映射计划
```

最低准入条件：

```text
1. 外部动作模式有多个真实样本。
2. 动作结果特征稳定。
3. 自我存在拥有可执行动作入口。
4. 自我动作能产生同类前置状态或动作过程。
5. 执行后结果能被外设或内部治理事实验证。
6. 能形成自我主动动作动态，而不是复用外部动作动态。
```

禁止：

```text
不得把“看见外部存在能做某动作”直接翻译为“自我已经具备该动作方法”。
不得复用外部动作动态作为自我主动动作动态。
不得跳过自我动作验证闭环和动作致变因果验证。
```

### P9：真实验证路线

验证必须使用真实运行路径和真实日志，不用模拟样本、夹具样本、伪造入口或伪造动作动态。

验证前置门槛：

```text
1. 内部治理链已经自然生长出外设观察 / D455 工作需求。
2. 外设 D455 能正常运行，并能提供本轮需求对应的真实外部数据。
3. 动态窗口来自已裁决事实或正式提交后的当前场景状态 / 动态，不来自原始相机帧、未归属观察候选或控制面板显示缓存。
4. 若缺少真实数据，本计划停在待条件状态，不得用代码审计替代真实动作候选验证。
```

首批验证剧本：

```text
1. 已确认存在位置连续变化 -> 移动动作候选。
2. 已确认存在与客体接触 + 客体支撑丢失 + 上升 -> 拿起候选。
3. 客体支撑丢失 + 下降 + 重新支撑 -> 掉落候选。
4. 门体旋转 + 开合状态变化 -> 打开 / 关闭候选。
5. 自我相机位姿变化 + 外部相对位置变化 -> 排除外部存在主动移动。
```

每个剧本先写预测：

```text
输入动态窗口应包含哪些原子动态；
应提取哪些运动基元；
应生成哪些复杂动作候选；
应有哪些竞争候选或待补证据；
是否允许交给因果类；
是否禁止进入自我方法候选。
```

验收证据：

```text
状态节点回读
动态节点回读
动态窗口日志
运动基元候选日志
复杂动作候选日志
动作包含判定复算证据
因果样本入族日志
反例 / 竞争候选统计
```

## 7. 停止条件

遇到以下情况必须停止动作提取或降级为待补证据：

```text
1. 缺动态主体。
2. 缺记录场域。
3. 只有原始观察材料，没有事实提交后的场景状态 / 动态。
4. 主体身份不稳定或跟踪断裂。
5. 自我位姿变化未被排除，无法判断外部存在是否真实移动。
6. 关键关系动态缺失，例如拿起缺接触或支撑关系变化。
7. 多个竞争候选无法排序，且缺少可补证据入口。
8. 试图把外部动作候选直接当作自我方法动作动态。
9. 试图用单次样本宣称稳定动作规则或稳定因果规则。
```

## 8. 冲突和待确认点

### 8.1 外部动作信息与方法动作动态的命名冲突

处理口径：

```text
外部动作信息：
    由场景存在 / 关系动态提取，用于解释外部现实动作。

方法动作动态：
    由自我方法执行造成事实变化，必须绑定来源方法。
```

二者都可以向因果样本提供动作字段，但不能互相冒充。

### 8.2 场景体素和观察材料的事实权冲突

处理口径：

```text
场景体素和观察材料可以提供候选证据；
只有事实提交后的当前场景状态 / 动态可以作为动作提取的正式输入。
```

### 8.3 外部动作能否进入任务筹办候选

处理口径：

```text
外部动作本身不能直接成为自我方法候选。
只有当外部动作模式完成“自我可执行方法映射”，并形成自我主动动作致变因果后，才允许进入任务筹办候选。
```

待确认：

```text
后续是否需要单独建立“外部动作模式 -> 自我可执行方法映射计划”。
```
