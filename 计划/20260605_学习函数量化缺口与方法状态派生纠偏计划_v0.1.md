# 20260605_学习函数量化缺口与方法状态派生纠偏计划_v0.1

## 1. 目标

按当前口径纠正学习相关闭环：

```text
方法状态结构保留；
方法状态只作为派生汇总；
需求和缺口优先表达为可计数、可比较、可验证的具体特征；
主动学习 / 练习方法只直接改变量化底账；
量化底账达成后，由被动因果链派生方法状态；
方法状态改变必须通过方法域提交链生成被动动作动态证据；
方法状态提交动态不得被主动反推为可学习业务方法；
任务筹办只通过统一找方法逻辑生成可被学习本能承接的学习任务；
任务筹办不得直接调用 自我_尝试学习 / 自我_定向学习 / 自我_练习。
```

本计划只整理偏差和纠偏路径，不直接改代码。

规范口径：

```text
有条件结果对 = 条件结果对数量 > 0；
可用 = 真实动作入口存在 且 条件结果对数量 > 0；
好用 = 目标方法最近连续成功次数 > 3；
更严格练习口径 = 同一条件命中过 3 次以上，且未生成新的结果对；
结果符合 / 不符合次数应作为条件结果稳定性的底账；
方法状态可以表达为 可用 / 好用，但不应替代底层量化证据；
方法状态变化来源应是 提交方法状态变化；
方法状态提交只形成被动动作动态证据，不生成主动因果信息；
主动因果属于学习 / 练习动作对量化底账的改变；
被动因果属于量化底账达成后对方法状态的必然派生。
```

## 3. 三个学习相关函数现状

### 3.1 自我_尝试学习

当前实现要点：

```text
确认尝试学习规格：
    形参包含 输入条件包 / 目标方法头节点 / 来源因果信息 / 条件结果对等；
    结果表包含 方法条件结果配对状态 / 方法状态；
    声明结果能力为：
        方法条件结果配对状态 = 1
        方法状态 = 可用

实际执行：
    先绑定输入；
    读取目标方法；
    目标方法已有动作时，通过 自我_建立条件结果对 提交条件结果对；
    成功后通过 自我_提交方法状态变化 写 方法状态 = 可用；
    方法状态提交会生成被动动作动态证据；
    失败时输出 方法动作状态 或 方法条件结果配对状态 的派生需求。
```

偏差：

```text
1. 缺条件结果对的需求目标仍偏向 方法条件结果配对状态 = 1；
2. 按新口径，直接目标应是 方法条件结果对数量 > 0；
3. 方法状态 = 可用 可以作为提交后的派生汇总，但不应成为底账目标；
4. 方法状态提交动态只能作为被动证据，不能作为“尝试学习能直接让方法可用”的主动因果；
5. 输入绑定失败时生成的派生需求也应尽量落到 条件结果对数量 这类可计数特征。
```

### 3.2 自我_定向学习

当前实现要点：

```text
确认定向学习规格：
    形参包含 输入条件包 / 目标方法头节点 / 目标特征类型 / 来源因果信息等；
    结果表包含 候选动作节点 / 方法动作状态 / 方法状态；
    声明结果能力为：
        方法动作状态 = 1

实际执行：
    读取目标方法和目标特征；
    补目标方法候选结构；
    记录候选动作语义；
    若目标方法本来已有动作或动作句柄，才认为动作补齐闭合；
    不能伪造目标方法动作状态，失败时继续输出 方法动作状态 0 -> 1。
```

偏差：

```text
1. 缺动作的学习需求仍以 方法动作状态 为主；
2. 按新口径，直接目标应拆为：
        方法动作数量 > 0
        方法可执行入口数量 > 0
   其中 方法动作状态 只由这两个量化特征派生；
3. 当前 定向学习 能记录候选动作语义，但不一定能关闭真实动作缺口；
4. 需要区分 候选动作数量 / 真实动作数量 / 可执行入口数量，避免把候选语义当成真实动作。
```

### 3.3 自我_练习

当前实现要点：

```text
确认练习规格：
    形参包含 输入条件包 / 目标方法头节点 / 来源缺口 / 目标特征类型等；
    结果表包含 方法状态 / 运行账 / 候选实参表等；
    声明结果能力为：
        方法状态 = 好用

实际执行：
    读取目标方法运行账；
    生成候选实参和可执行输入场景；
    确认目标方法有真实入口、真实条件节点和真实条件结果对；
    调用目标方法执行；
    读取目标方法运行账变化；
    以 最近连续成功次数 >= 4 推导 好用；
    未达成时输出 方法最近连续成功次数 N -> 4 和 方法状态 -> 好用 的派生需求。
```

偏差：

```text
1. 练习成功判据目前主要依赖 方法最近连续成功次数；
2. 按新口径，还需要同一条件下的结果复现证据：
        同一条件命中次数 > 3
        结果符合次数 > 3
        结果不符合次数 = 0
        本轮没有生成新的结果对 / 新结果分支
3. 当前 归并方法条件结果对 已记录 结果符合次数 / 结果不符合次数，
   但这些计数的宿主和作用域需要确认是否绑定到具体条件或条件结果对；
4. 练习方法的结果能力只声明 方法状态=好用，
   任务筹办不一定能通过底层量化缺口直接召回 自我_练习；
5. 若把 方法状态=好用 当成练习的直接主动结果，
   会弱化“练习先增加复现底账，再由被动链派生好用状态”的因果边界。
```

## 4. 任务筹办侧现状

当前实现要点：

```text
任务目标是方法结构补齐需求：
    已识别 方法状态 / 方法稳定状态 / 方法运行账完整性 / 方法动作状态 /
    方法动作数量 / 方法可执行入口数量 / 方法条件节点数量 /
    方法结果节点数量 / 方法条件结果配对状态。

筹办缺口特征类型：
    缺方法动作 -> 方法动作状态
    方法缺可执行入口 -> 方法可执行入口数量
    方法缺条件节点 -> 方法条件节点数量
    方法缺结果节点 -> 方法结果节点数量
    方法缺条件结果对 -> 方法条件结果配对状态
    方法运行账不足 -> 方法运行账完整性
    方法结果不稳定 -> 方法稳定状态

候选方法不可就绪状况：
    已检查动作 / 可执行入口 / 条件结果对数量；
    学习补齐本能本身不被自身条件结果对反向阻塞。
```

偏差：

```text
1. 筹办缺口特征仍有粗状态目标：
        方法动作状态
        方法条件结果配对状态
        方法运行账完整性
        方法稳定状态
2. 任务目标识别缺少更细量化目标：
        方法条件结果对数量
        方法最近连续成功次数
        结果符合次数
        结果不符合次数
        新结果分支数量 / 新条件结果对候选数量
3. 当缺口是量化特征时，找方法必须能命中对应学习本能；
   不能在任务筹办中直接调用学习函数。
```

## 4.1 派生需求消息与任务化现状

当前实现要点：

```text
任务管理工作线程：
    将任务筹办 / 执行回执转换为 结构_任务管理派生需求消息；
    主要搬运：
        需求特征类型
        需求目标主体
        需求当前状态
        需求目标状态
        满足关系
        当前方法主键
        方法虚拟存在
        来源因果 / 来源动态
    字段完整后才发送上行派生需求消息。

自我线程：
    收到派生需求消息后，通过提交入口裁决入树；
    根据派生消息创建或更新需求节点；
    立即提交任务发起请求；
    任务创建本身不判断该学习任务应由 尝试学习 / 定向学习 / 练习 承接；
    后续仍由任务筹办统一找方法。

当前同方法学习任务过滤：
    以派生来源方法为主去重；
    不足以区分同一目标方法上的不同量化缺口。
```

偏差：

```text
1. 如果任务筹办仍生成粗状态缺口，
   工作线程会无损打包旧目标，
   自我线程会按旧目标入树和任务化。

2. 如果工作线程只搬运回执缺口特征，
   但执行输出场景中的当前状态 / 目标状态仍是粗状态，
   自我线程最终得到的学习需求仍不符合量化口径。

3. 如果自我线程同方法学习任务过滤只按来源方法去重，
   同一目标方法的不同学习阶段可能互相吞并：
       条件结果对数量 > 0
       方法最近连续成功次数 >= 4
       结果符合次数 >= 4
       结果不符合次数 = 0

4. 自我线程的任务创建逻辑应继续保持通用，
   但必须无损保存量化目标和精确去重键。
```

## 5. 纠偏原则

```text
1. 底账优先：
   学习缺口先写具体特征目标，不先写 方法状态 / 稳定状态 这类聚合状态。

2. 状态派生：
   方法状态仍保留，但由量化特征推导和提交，不反向替代量化事实。

3. 统一找方法：
   所有任务都走同一套候选填充和方法选择逻辑。
   学习任务也只是需求任务化后的普通任务，不允许任务筹办直接调用学习函数。

4. 主动 / 被动因果分开：
   遗传被动链可以发现缺口并发起学习需求；
   学习需求生成任务后，仍由任务执行调用学习本能动作；
   本能方法运行一轮以后才产生新的本能因果信息；
   主动因果只表达学习 / 练习动作对底账的改变；
   被动因果表达底账达标后必然派生方法状态。

5. 候选不等于真实：
   候选动作、候选条件结果对、新结果分支只能作为候选证据；
   真实动作数量、真实入口数量、真实条件结果对数量必须由方法域提交链闭合。

6. 状态提交不是业务能力：
   方法状态改变必须通过 自我_提交方法状态变化 生成动作动态证据；
   该动作动态语义应保持 被动动作；
   因果反推、学习和动作组合映射不得把 提交方法状态变化 学成主动方法。

7. 派生消息无损：
   任务管理工作线程只负责把筹办 / 执行输出转换为结构化派生需求消息；
   不得把量化缺口规约回 方法状态 / 稳定状态 / 运行账完整性 等粗状态。

8. 任务化通用但去重精确：
   自我线程仍按通用逻辑把需求任务化；
   不在自我线程直接选择学习函数；
   去重键必须覆盖目标方法、目标主体、目标特征、满足关系和目标值。
```

## 6. 纠偏步骤

### P0：确定量化特征清单和宿主

目标：

```text
确认以下特征是否已有、是否有执行桥、是否能作为需求目标：
    方法动作数量
    方法可执行入口数量
    方法条件节点数量
    方法结果节点数量
    方法条件结果对数量
    方法运行次数
    方法成功次数
    方法最近连续成功次数
    结果符合次数
    结果不符合次数
    新结果分支数量 / 新条件结果对候选数量
```

重点：

```text
结果符合次数 / 结果不符合次数 必须能表达“同一条件”的作用域。
如果当前只挂在方法虚拟存在上，需要调整为：
    条件节点作用域；
    或 条件结果对作用域；
    或 带条件身份的作用域化统计特征。
```

验收：

```text
列出每个特征的：
    特征词；
    读写入口；
    需求匹配能力；
    结果能力声明入口；
    当前宿主。
```

### P1：修正任务筹办缺口映射并同步派生任务链

#### P1.1 任务筹办缺口映射

```text
缺方法动作:
    方法动作数量 > 0

方法缺可执行入口:
    方法可执行入口数量 > 0

方法缺条件结果对:
    方法条件结果对数量 > 0

方法运行账不足:
    方法运行次数 > 0
    或按具体学习目标写 方法最近连续成功次数 >= 目标值

方法结果不稳定:
    结果符合次数 >= 4
    结果不符合次数 = 0
    新结果分支数量 = 0
    临时兼容目标可保留 方法最近连续成功次数 >= 4
```

同步调整：

```text
任务目标是方法结构补齐需求 需要接纳上述量化目标；
粗状态仍可接纳，但只作为兼容和派生状态入口；
返回方法结构缺口 时优先返回量化目标特征。
```

细化要求：

```text
返回方法结构缺口：
    必须同时写入量化缺口特征、当前状态、目标状态和满足关系；
    不能只改 回执.缺口特征类型 而让输出结果场景仍保留粗状态目标。

返回方法状态可用性缺口：
    不能再把不明确缺口兜底为 方法状态；
    应先按方法动作数量、可执行入口数量、条件结果对数量判定具体底账缺口。

候选方法不可就绪状况：
    状况可以仍用枚举表达过程判断；
    但派生需求目标必须转换成量化特征目标。
```

#### P1.2 任务管理工作线程派生消息打包

```text
工作线程构造派生需求消息时必须无损搬运：
    需求特征类型 = 量化特征；
    需求目标主体 = 目标方法虚拟存在或作用域化条件 / 条件结果对宿主；
    需求当前状态 = 当前量化值；
    需求目标状态 = 目标量化值；
    满足关系 = 大于 / 大于等于 / 等于；
    当前方法主键 = 产生缺口的目标方法或来源方法；
    方法虚拟存在 = 目标方法虚拟存在；
    来源因果 / 来源动态 = 遗传被动链或执行回执证据。

如果执行输出场景缺少量化当前 / 目标状态：
    不允许用 方法状态 / 稳定状态 兜底；
    应记录执行桥逻辑错误或生成“量化状态缺失”堵点。
```

#### P1.3 自我线程入树、任务化和去重

```text
自我线程保持通用任务创建逻辑：
    派生需求入树；
    提交任务发起请求；
    后续由任务筹办统一找方法。

自我线程不得直接选择：
    自我_尝试学习
    自我_定向学习
    自我_练习

自我线程必须无损保留：
    量化目标特征；
    目标主体；
    当前状态；
    目标状态；
    满足关系；
    来源方法；
    来源因果。

同方法学习任务去重键至少包含：
    目标方法 / 方法虚拟存在；
    目标主体；
    目标特征类型；
    目标状态值；
    满足关系；
    派生需求类型。

同一目标方法上的不同学习阶段不得互相吞并：
    方法条件结果对数量 > 0
    方法最近连续成功次数 >= 4
    结果符合次数 >= 4
    结果不符合次数 = 0
```

验收：

```text
由候选方法不可就绪状况生成的缺口，
必须能通过同一套候选填充逻辑查到 自我_定向学习 / 自我_尝试学习 / 自我_练习。

任务管理工作线程日志中：
    需求特征 / 当前状态 / 目标状态 / 满足关系 均为量化目标；
    不出现量化缺口被规约为 方法状态 / 方法稳定状态。

自我线程日志中：
    提交_生成缺口子需求 保留量化目标；
    任务发起请求成功；
    不同量化学习目标不会被同方法任务过滤误吞。
```

### P2：修正学习本能结果能力声明

自我_定向学习：

```text
直接结果能力：
    方法动作数量 > 0
    或 候选动作数量 > 0

闭合前提：
    候选动作数量 不能冒充 方法动作数量；
    真实动作数量必须由真实动作挂接或方法域提交链关闭。

派生结果：
    方法动作状态 = 已有动作

因果边界：
    主动因果只到 动作候选 / 真实动作数量 / 可执行入口数量；
    方法动作状态 只作为这些量化结果的派生状态。
```

自我_尝试学习：

```text
直接结果能力：
    方法条件结果对数量 > 0
    或 方法条件结果对数量 增加

派生结果：
    方法条件结果配对状态 = 已配对
    方法状态 = 可用

因果边界：
    主动因果只到 条件结果对数量增加；
    方法状态 = 可用 由底账满足后的被动因果派生；
    自我_提交方法状态变化 只生成被动动作动态证据。
```

自我_练习：

```text
直接结果能力：
    方法最近连续成功次数 >= 4
    结果符合次数 >= 4
    结果不符合次数 = 0
    新结果分支数量 = 0

派生结果：
    方法稳定状态 = 稳定
    方法状态 = 好用

因果边界：
    主动因果只到 试运行、复现次数、连续成功次数和新分支统计；
    方法状态 = 好用 由稳定性底账满足后的被动因果派生；
    练习不得把 方法状态=好用 当作绕过复现底账的直接结果。
```

验收：

```text
任务筹办通过量化需求找方法时，
不需要知道三个学习函数的函数名；
只依赖方法头、条件节点和结果能力。
```

### P3：修正三个学习函数输出缺口

自我_定向学习：

```text
失败时输出 方法动作数量 0 -> 1 或 方法可执行入口数量 0 -> 1；
如果只能形成候选动作，则输出候选动作证据，不写真实动作状态已满足。
```

自我_尝试学习：

```text
失败时输出 方法条件结果对数量 0 -> 1；
成功后读取或计算真实条件结果对数量；
确认底账达标后，再通过 自我_提交方法状态变化 提交 方法状态 = 可用；
状态提交动态只作为被动动作动态证据，不进入主动因果反推。
```

自我_练习：

```text
先比较同一条件下的结果复现底账；
如果命中次数不足，输出 结果符合次数 / 方法最近连续成功次数 的量化缺口；
如果出现新结果分支，输出 新结果分支数量 或 结果不符合次数 的纠偏缺口；
底账未达标时只输出量化缺口和派生状态缺口，不提交好用状态；
底账达标后，才通过 自我_提交方法状态变化 提交 方法状态 = 好用；
状态提交动态只作为被动动作动态证据，不进入主动因果反推。
```

### P4：集中方法状态派生逻辑

目标：

```text
形成统一的 方法量化特征 -> 方法状态 推导口径。
形成统一的 量化底账 -> 方法状态 被动因果模板。
明确 自我_提交方法状态变化 只是提交 / 审计入口，不是主动业务能力。
```

建议判据：

```text
无真实动作入口:
    待可执行入口

无条件节点:
    待条件节点

方法条件结果对数量 <= 0:
    待条件结果对

条件结果对数量 > 0 但稳定性不足:
    可用

同一条件复现次数 > 3
且 结果不符合次数 = 0
且 无新结果分支
且 最近连续成功次数 > 3:
    好用
```

边界：

```text
状态刷新必须通过方法域提交链；
任务筹办只生成缺口或可执行任务，不直接裸写状态。
方法状态提交动态必须存在，并标记为被动动作；
因果类主动反推必须继续排除 被动动作；
可学习的主动因果不得以 提交方法状态变化 为因动作。
```

建议补充的被动因果模板：

```text
因：
    方法动作数量 > 0
    方法可执行入口数量 > 0
    方法条件结果对数量 > 0
果：
    方法状态 = 可用
来源：
    遗传 / 方法状态派生规则
动作语义：
    无主动动作；状态提交动态只作证据

因：
    同一条件复现次数 > 3
    结果不符合次数 = 0
    新结果分支数量 = 0
    方法最近连续成功次数 > 3
果：
    方法状态 = 好用
来源：
    遗传 / 方法状态派生规则
动作语义：
    无主动动作；状态提交动态只作证据
```

### P5：验证剧本

验证顺序：

```text
先写预测；
再构建；
再用真实运行和 --self-check-log；
最后查日志、状态快照、动作动态和错误日志。
```

预测锚点：

```text
1. 方法无条件结果对时：
   筹办生成 方法条件结果对数量 > 0 的缺口；
   再筹办能通过结果能力命中 自我_尝试学习；
   任务执行才调用 自我_尝试学习。

2. 方法有条件结果对但未稳定时：
   筹办生成 结果符合次数 / 方法最近连续成功次数 等量化缺口；
   再筹办能命中 自我_练习；
   任务执行才调用 自我_练习。

3. 方法无动作时：
   筹办生成 方法动作数量 > 0 或 方法可执行入口数量 > 0；
   再筹办能命中 自我_定向学习；
   不把候选动作当真实动作。

4. 方法状态更新：
   只在量化底账变化后由方法域提交链刷新；
   日志中不出现任务筹办直接调用学习本能；
   状态提交动态存在；
   状态提交动态语义为 被动动作；
   主动因果反推不以 提交方法状态变化 为因动作。

5. 主动 / 被动因果分层：
   自我_尝试学习 的主动结果是 条件结果对数量增加；
   自我_练习 的主动结果是 复现 / 连续成功 / 新分支统计变化；
   方法状态 = 可用 / 好用 只由被动派生链闭合。

6. 派生需求消息链：
   任务筹办回执中的量化缺口，
   在任务管理工作线程构造派生需求消息后仍保持同一目标特征、主体、当前状态、目标状态和满足关系；
   若执行输出场景缺量化状态，必须暴露缺口，不得用粗状态兜底。

7. 自我线程任务化链：
   提交_生成缺口子需求 日志中的需求类型为量化特征；
   新需求的满足关系保持 大于 / 大于等于 / 等于；
   任务发起请求成功；
   不同量化学习目标不会被同方法活跃学习任务过滤合并。
```

## 7. 当前堵点

```text
1. 同一条件稳定性统计的宿主需要先定：
   现有 结果符合次数 / 结果不符合次数 已存在，
   但需要确认是否足以表达“同一条件”而非方法整体统计。

2. 结果能力匹配需要支持量化比较：
   当前结果能力常见写法是 I64 等值目标；
   若需求是 > / >=，需要确认查找方法逻辑是否能匹配比较关系。

3. 新结果分支数量特征可能尚未成型：
   如果没有独立特征，需要先补特征词和读写桥，
   或临时用 结果不符合次数 表达。

4. 方法状态与量化底账的双写顺序要收敛：
   不能先写 方法状态=可用/好用 再倒推底账；
   必须先有底账，再刷新状态。

5. 方法状态被动因果模板尚未纳入本计划实现面：
   需要确认是复用现有遗传因果模板加载，
   还是新增专门的 方法状态派生规则模板；
   无论哪种，都不能把 提交方法状态变化 写成主动因动作。

6. 状态提交动态与主动因果反推的排除关系需要验收：
   当前代码已有 被动动作 排除主动反推 的方向；
   后续实现应增加日志锚点，确认方法状态提交动态没有被学成主动方法。

7. 任务管理工作线程派生消息打包需要同步更新：
   当前工作线程会搬运回执缺口特征和输出场景状态；
   如果输出场景仍是粗状态，入树后的学习需求也会是粗状态；
   因此必须把量化当前 / 目标状态写入执行输出场景，并在消息构造处拒绝粗状态兜底。

8. 自我线程同方法学习任务过滤过粗：
   当前过滤主要按派生来源方法判断；
   同一目标方法上的不同量化学习目标可能被误判为已有活跃学习任务；
   需要把去重键扩展到 目标方法 / 目标主体 / 目标特征 / 目标值 / 满足关系。

9. 自我线程不应新增学习分流器：
   学习任务仍应作为普通需求任务化；
   承接方法由后续任务筹办按方法结果能力查找；
   如果在自我线程直接分派 尝试学习 / 练习，会重新破坏统一找方法逻辑。
```
