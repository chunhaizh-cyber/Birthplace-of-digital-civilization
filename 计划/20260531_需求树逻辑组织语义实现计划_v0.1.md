## 1. 目标

把“树形”和“语义”彻底分开：

```text
叶子 / 非叶子：
    只判断需求树结构是否已经展开。

目标特征类型：
    判断普通目标、AND组、OR组、方法路径组、因果子链支撑或结构性缺口。

抽象特征定义视图：
    判断是否可任务化、如何聚合子节点、如何领取 OR 结算令牌、如何回写满足。
```

本计划第一版只实现最小可运行骨架：

```text
普通需求树物理结构不变；
需求主信息不新增 AND / OR / 因果子链 / 方法路径字段；
任务筹办不再把“当前无子节点”直接等同于“可进入方法候选”；
逻辑组织节点通过目标特征定义视图被识别、阻断普通任务化，并返回明确筹办回执；
OR组结算令牌通过状态 / 动态 / 提交入口记录，不进入需求主信息。
```

### P3 任务筹办目标语义闸门

目标：

```text
任务筹办在方法候选填充前读取 结构_需求目标语义视图。
```

规则：

```text
普通可任务化目标：
    保持现有候选方法填充、选择、参数绑定流程。

AND组：
    不填充候选方法；
    检查子节点满足情况；
    返回等待未满足子节点 / 聚合待回写 / 结构缺口回执。

OR组：
    不填充候选方法；
    选择或保持一条激活路径；
    返回等待激活路径 / 令牌待提交 / 结构缺口回执。

方法路径组：
    不直接任务化；
    检查路径内部普通叶子需求。

因果子链支撑：
    不直接任务化；
    等待或推进真实中间目标需求。

结构性缺口：
    不任务化；
    返回治理缺口或规范缺口。
```

验收：

```text
逻辑组目标进入筹办时，候选方法集为空是预期结果，不被记为失败；
日志出现 目标语义 / 可普通任务化 / 处理分支；
普通可任务化需求原有候选集填充不回退；
任务筹办 / 任务执行仍不生成方法动作动态。
```

### P4 AND组聚合满足回写

目标：

```text
当 AND组所有必要子需求满足时，形成组节点满足回写输入；
当仍有未满足子需求时，返回等待子需求。
```

实现边界：

```text
只读路径可以计算聚合视图；
正式满足必须经需求域提交入口回写；
不得由任务筹办直接改需求状态。
```

验收：

```text
AND组存在未满足子项时不回写满足；
全部子项满足后才调用需求满足回写链；
父任务按子需求完成后重筹办路径继续推进。
```

### P5 OR组路径选择与结算令牌提交

目标：

```text
OR组只允许一条路径领取结算令牌；
重复路径完成只记录冗余证据，不重复结算。
```

建议新增提交类能力：

```text
提交_领取OR组结算令牌
```

职责：

```text
读取 OR组节点 / 领取路径 / 来源任务 / 来源动作动态；
若令牌未领取，写入 OR组结算令牌状态 = 已领取；
记录领取路径、领取任务和来源动作动态；
若令牌已领取，返回已领取 / 不重复入账回执；
生成提交类动作动态或串接正式动作动态证据。
```

实现边界：

```text
该提交入口不得进入普通候选方法集；
不得成为任务当前方法；
不得被学习链当作主动动作语义；
令牌状态不得写入需求主信息。
```

验收：

```text
首次路径完成能领取令牌并回写 OR组满足；
第二条路径完成时不重复结算；
重跑 / 重入不会双花；
日志能按 OR组节点、路径、任务、动作动态追溯。
```

### P6 方法路径组和因果子链最小执行语义

目标：

```text
方法路径组只组织实现路径；
因果子链只解释为什么需要中间目标；
真正任务化仍落到路径内普通可任务化叶子需求。
```

第一版策略：

```text
方法路径组：
    路径内必要步骤满足后，路径完成；
    路径节点不直接找业务方法。

因果子链支撑：
    若只需要解释，可生成组织节点；
    若不需要展示，直接生成真实中间目标需求。
```

验收：

```text
方法路径组和因果子链节点不会进入普通候选方法填充；
路径内普通叶子需求仍可正常任务化；
子需求完成后父路径 / 父组能重筹办。
```
