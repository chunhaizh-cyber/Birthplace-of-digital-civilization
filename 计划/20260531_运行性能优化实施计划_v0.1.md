# 运行性能优化实施计划 v0.1

日期：2026-05-31

## 1. 背景

本计划针对当前项目运行偏慢问题制定，只做性能治理，不改变内部循环、任务筹办、需求树生长、方法候选选择和动作动态边界的业务语义。

已观察到的慢点证据：

```text
1. `.\x64\Debug\鱼巢.exe --demand-tree-growth-summary` 真实运行退出码 0，但耗时约 176.5 秒。
2. 同次日志中 `默认本能方法规格确认 | 已确认=64` 出现 7 次。
3. 摘要命令在 `控制面板摘要/等待稳定` 阶段等待 30046ms 后仍为 `稳定=否`。
4. 等待结束时任务管理界面线程仍有 `请求队列=52 / 等待工作项=12 / 待筹办=11 / 待执行=1`。
5. 同次会话出现 21 次 `因果路径筹办查询壳统计` 和 21 次 `候选集填充全树遍历完成`。
6. 单次因果路径筹办最多扫描 `因果节点=1174`，方法候选填充访问约 201 个方法节点。
7. D455 不可用时出现长 `双目相机本能方法结果` 日志，并触发方法结果不稳定、练习未达目标和待重筹办链路。
```

本计划遵守：

```text
规范/规范目录.md
规范/方法动作动态硬规则规范20260512.md
规范/自我内部循环实现规范20260512.md

规范/任务筹办父方法与协作子方法链规范20260513.md
规范/任务筹办按方法能力查找到就绪因果链规范20260513.md
规范/需求临时因果视图展开规范20260526.md
规范/因果信息用途与用法规范20260516.md
规范/方法规范20260425.md
计划/计划索引.md
```

硬边界：

```text
1. 优化不得把任务筹办 / 任务执行恢复为本能方法。
2. 优化不得让线程成为动作动态来源。
3. 摘要、快照、诊断、等待稳定和性能埋点都是只读或诊断路径，不得写需求树、任务状态、方法状态、世界事实或价值账。
4. 任务筹办仍必须先填充候选集，再从候选集中选择当前方法。
5. 因果路径筹办只能读取世界树因果、需求条件、方法条件、条件结果对和已入树子需求，不得写领域硬编码捷径。
6. 无真实证据不得宣称内部循环闭合、自我苏醒完成或初步成熟完成。
7. `I64_MAX` 仍只按现有规范作为满刻度或异常哨兵处理，不得进入真实服务 / 安全结算兜底。
8. 验证不得新增 `--*-check` 回归入口，不得新增模拟样本、夹具入口或伪造动作动态。
```

## 3. 优化目标

第一阶段目标是让常用只读摘要命令不再被运行链拖慢。

目标指标：

```text
G1. `--demand-tree-growth-summary` 默认路径不再固定等待 30 秒稳定窗口。
G2. 单次摘要命令内 `默认本能方法规格确认` 期望降到 1 次，最多不超过 2 次。
G3. 无 D455 或 D455 不可用时，不反复进入练习 / 重筹办震荡；只形成外设条件等待或明确外设不可用回执。
G4. 任务筹办因果扫描和方法树遍历先保留语义，补可观测耗时指标，再按索引化切片降低重复全量扫描。
G5. 运行日志保留关键证据，长失败日志改为关键字段默认输出，完整字段只在详细诊断模式输出。
```

不作为第一阶段目标：

```text
1. 不改需求树生长口径。
2. 不改任务完成 / 需求满足 / 价值结算规则。
3. 不重构方法树、因果树或控制面板整体结构。
4. 不把外设真实运行失败伪装为通过。
5. 不用性能优化绕开候选集填充、参数绑定、条件检查或提交入口裁决。
```

## 4. 实施切片

### P0 基线与耗时埋点

目标：

```text
建立可复验的性能基线，让后续每个优化能用日志证明收益。
```

实施：

```text
1. 在以下阶段补充耗时日志：
   - 自我环境初始化
   - 默认本能方法规格确认
   - 自我线程启动 / 首轮完成
   - 自检线程启动
   - 控制面板摘要等待稳定
   - 控制面板快照读取
   - 任务筹办因果路径查询
   - 方法候选填充全树遍历
   - D455 不可用失败回执生成

2. 日志只记录阶段名、耗时、关键计数和是否命中快路径。
3. 不新增业务字段，不新增权威主信息结构。
```

验收预测：

```text
Debug x64 构建通过。
运行 `--demand-tree-growth-summary` 后日志出现各阶段耗时。
日志能区分初始化耗时、等待稳定耗时、快照读取耗时、筹办扫描耗时。
```

禁止出现：

```text
新增动作动态。
新增模拟入口。
诊断路径写需求 / 任务 / 方法状态。
```

### P1 初始化与默认规格确认幂等快路径

目标：

```text
消除摘要命令中的重复初始化和重复规格确认。
```

实施：

```text
1. 为 `初始化自我环境()` / `自我线程类::自我初始化()` 增加已初始化快路径。
2. 为 `确认默认本能方法专属规格集` 增加结构版本或本轮已确认标记。
3. 已初始化且默认本能方法表未变化时，直接返回已确认数量或跳过重复同步。
4. 快路径只减少重复整理，不跳过缺失结构的显式确保。
5. 初始化失败仍必须报错和记录日志，不允许静默兜底。
```

验收预测：

```text
Debug x64 构建通过。
单次 `--demand-tree-growth-summary` 中 `默认本能方法规格确认` 降到 1 次，最多不超过 2 次。
摘要输出的需求规模、目标绑定异常、死信等关键字段不因快路径丢失。
```

禁止出现：

```text
因为快路径跳过自我存在、需求根、任务根、方法根缺失检查。
默认本能方法缺规格却被视为已确认。
```

### P2 摘要命令只读快照模式

目标：

```text
让只读摘要命令默认快速返回当前一致快照，不再等待任务管理队列完全空闲。
```

实施：

```text
1. 保留现有稳定等待函数，但不作为摘要命令默认路径。
2. `--demand-tree-growth-summary`、`--task-mgmt-summary`、`--gap-summary` 等只读摘要默认等待：
   - 自我线程首轮运行已完成；
   - 当前没有正在执行的工作线程写入；
   - 控制面板快照能读取到最小线程快照。
3. 若队列仍有待筹办 / 待执行项，摘要明确标记为中间态快照。
4. 需要完整稳定等待时，后续可新增显式命令参数或内部选项，例如 `等待稳定摘要模式`，但不得替代默认快照路径。
```

验收预测：

```text
Debug x64 构建通过。
`--demand-tree-growth-summary` 默认路径不再出现 30000ms 等待稳定耗时。
输出中若队列未空，应保留 `当前等待工作项`、`待筹办`、`待执行` 等字段。
日志显示 `控制面板摘要/只读快照` 或等价标记。
```

禁止出现：

```text
把中间态摘要解释为业务验收通过。
为了让摘要稳定而停止自检、清空任务队列或改写任务状态。
```

### P3 摘要路径自检线程静默化

目标：

```text
只读摘要不主动制造新的自检需求，避免队列持续不空。
```

实施：

```text
1. 摘要命令启动自检线程时，默认进入只读 / 静默观察模式。
2. 只读模式允许读取自检摘要，不允许提交新的自检需求或自检报告入树。
3. `--self-check-log` 保持现有显式自检语义，不受摘要静默模式影响。
4. 自检线程停止时必须能快速响应停止请求。
```

验收预测：

```text
摘要命令运行期间不新增 `自检正式需求入树`。
退出时自检线程 join 不再长时间等待正在提交的新自检项。
`--self-check-log` 仍能产生自检日志。
```

禁止出现：

```text
删除自检能力。
把自检发现的问题静默丢弃到业务链路。
只读摘要生成修复需求。
```

### P4 D455 不可用路径去震荡

目标：

```text
外设不可用时形成明确外部条件等待，不再反复练习目标方法和写超长失败日志。
```

实施：

```text
1. 将 D455 未打开、不可用、无设备等情况归为外设条件缺口或硬件条件不足。
2. 任务执行回执中保留外设不可用证据，但不把它升级为方法好用度练习失败。
3. 对同一运行周期内重复 D455 不可用结果做去重或冷却。
4. 默认日志只写关键字段：方法、外设状态、失败原因、目标宿主、目标特征、是否生成动作动态、是否等待外设条件。
5. 完整观察帧诊断字段仅在详细诊断模式输出。
```

验收预测：

```text
缺 D455 时日志明确 `硬件条件不足` 或 `外设不可用等待`。
不出现同一外设不可用原因导致的连续练习 / 重筹办震荡。
不宣称真实 D455 链路通过。
```

禁止出现：

```text
把外部硬件失败记成业务逻辑失败。
用缺硬件条件生成伪观察事实或伪动作动态。
删除必要错误日志。
```

### P5 方法候选能力索引

目标：

```text
降低每次叶子任务筹办都全树遍历方法节点的成本。
```

实施：

```text
1. 建立短生命周期或可重建的 `结果特征类型 -> 方法首节点集合` 索引。
2. 索引来源仍是方法结果能力，不来自方法名、领域标签或临时推断。
3. 方法新增、结果能力变化或默认本能方法规格确认后刷新索引。
4. 筹办仍先通过索引填充候选集，再从候选集中确定性选择当前方法。
5. 索引缺失或校验失败时允许回退全树遍历，并记录回退原因。
```

验收预测：

```text
Debug x64 构建通过。
任务筹办日志显示索引命中数量、回退次数和候选集数量。
候选选择结果与全树遍历基线一致。
多候选确定性选择口径不变。
```

禁止出现：

```text
用索引结果直接跳过候选集填充。
索引按方法名称、领域词或状态值硬编码。
漏掉新建目标方法头。
```

### P6 因果主果目标索引

目标：

```text
降低路径筹办每轮扫描全部因果节点的成本。
```

实施：

```text
1. 建立短生命周期或可重建的主果比较索引。
2. 第一版索引键可按主果目标宿主、目标特征、比较符、目标状态的可解析部分建立。
3. 路径筹办先查索引得到候选因果，再执行现有严格命中 / 反向命中判断。
4. 因果新增、主果比较模板变化或因果树重建后刷新索引。
5. 索引不新增因果主信息字段，不保存置信度、稳定度等解释值。
6. 索引缺失或不确定时回退全量扫描，并记录回退原因。
```

验收预测：

```text
Debug x64 构建通过。
因果路径筹办日志显示索引候选数量、最终命中数量、回退次数。
派生需求来源因果追溯样本不减少。
临时因果视图统计与全量扫描基线一致或差异有日志说明。
```

禁止出现：

```text
把索引持久化成新的权威因果结构。
用索引绕过临时因果视图生成规则。
接受任务管理侧随意写入层级权重。
```

## 5. 推荐执行顺序

```text
第一轮：P0 -> P1 -> P2 -> P3
    目标是让只读摘要命令先快起来，并保留业务语义不变。

第二轮：P4
    目标是解决缺 D455 时的重筹办 / 练习震荡和长日志。

第三轮：P5 -> P6
```

第一轮完成后再决定是否继续 P5 / P6。若 P1-P3 已把摘要命令降到可接受范围，P5 / P6 可等待后续任务筹办规模继续增长时再实施。

## 10. 2026-05-31 追加执行记录：轻量摘要与停止收尾

追加原因：
