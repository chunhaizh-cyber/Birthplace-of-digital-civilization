## 用户口径

```text
方法虚拟存在服务类是从方法类派生出来，专门用于方法虚拟存在功能实现的函数集合和写入边界。

学习方法如果需要改写方法虚拟存在特征值，应调用方法虚拟存在服务类中的函数。
```

本方案按此口径执行：

```text
方法类：
    负责方法树本体结构，包括方法动作、条件节点、结果节点、条件结果对、条件场景和结果场景。

方法虚拟存在服务类：
    负责方法虚拟存在的确保、结构投影、统计槽初始化、方法状态派生、方法状态动作动态输出。

学习本能方法：
    只能生成学习事实、结构补齐事实或运行统计材料；
    若这些事实会改变方法虚拟存在特征，必须通过方法虚拟存在服务类同步；
    不直接把 方法状态=可用 / 好用 写成最终状态。
```

## 当前冲突

P4b2-a 已确认现有代码同时存在两条方法状态写值路径：

```text
内部治理路径：
    方法虚拟存在服务类.cpp:407
        私有_同步方法状态特征

    方法虚拟存在服务类.cpp:328
        私有_输出方法状态动作动态

方法域提交动作路径：
    自我动作实现模块.ixx:8210
        提交目标方法I64特征_方法域动作

    自我动作实现模块.ixx:8630
        自我_尝试学习 成功后提交 方法状态=可用

    自我动作实现模块.ixx:9585
        自我_练习 成功后提交 方法状态=好用
```

冲突判断：

```text
方法状态变化应是内部治理被动果；
学习 / 练习是产生结构事实和统计材料的主动方法；
方法状态最终值必须由方法虚拟存在服务类根据事实派生并输出内部机制动作动态。
```

## P4b2-b 目标

```text
将学习相关本能方法内的方法状态改值收口到方法虚拟存在服务类；
撤出 自我_尝试学习 / 自我_练习 对 自我_提交方法状态变化 的直接依赖；
保留方法状态派生动作动态的内部机制归属；
不在本切片处理任务筹办直接调用 自我_提交方法可执行入口 的问题。
```

## 权责边界

### 方法结构事实

允许学习本能调用方法类或既有方法结构函数完成：

```text
新增或确认条件节点；
新增或确认结果节点；
新增或确认条件结果对；
更新条件场景 / 结果场景；
记录同条件样本次数、结果符合次数、结果不符合次数、新结果分支数量等结构或统计材料。
```

这些事实本身是学习方法的运行结果材料，不直接等于方法状态。

### 方法虚拟存在特征

必须由方法虚拟存在服务类负责：

```text
确保方法虚拟存在；
同步方法首节点结构特征；
初始化或刷新方法统计槽；
读取方法动作、条件节点、结果节点、条件结果对和统计底账；
派生 方法状态；
派生 方法稳定状态；
输出方法状态内部机制动作动态。
```

若现有 `同步方法节点到虚拟存在` 足够，应优先复用：

```text
方法虚拟存在服务类::同步方法节点到虚拟存在(方法首节点, 宿主存在, now)
```

若学习路径需要更明确的承接口，再新增服务类小函数，名称和语义限定为：

```text
学习事实入账后同步方法虚拟存在
```

该函数内部仍只调用服务类已有同步 / 状态派生逻辑，不在学习本能中裸写方法状态。

### 方法状态动作动态

方法状态变化需要动作动态，但动作动态归属必须固定为：

```text
主体：
    方法虚拟存在。

特征：
    方法状态 或 方法稳定状态。

来源：
    内部机制动作 / 治理过程动态。

生产者：
    方法虚拟存在服务类。
```

学习本能方法的动作动态只能证明：

```text
学习尝试发生；
练习发生；
条件结果对事实或运行统计材料产生。
```

不能直接证明：

```text
方法状态最终变为可用；
方法状态最终变为好用；
需求已经满足。
```

## 代码切片

### P4b2-b1 检查服务类能力

检查：

```text
方法虚拟存在服务类.h
方法虚拟存在服务类.cpp
自我动作实现模块.ixx
```

判断 `同步方法节点到虚拟存在` 是否已经覆盖：

```text
确保方法虚拟存在；
同步条件 / 结果 / 条件结果对数量；
同步方法状态；
初始化方法统计槽；
输出方法状态动作动态。
```

若已覆盖，不新增接口。

若未覆盖，只在 `方法虚拟存在服务类` 增加最小公开包装函数，不新增新的状态提交本能方法。

### P4b2-b2 收口自我_尝试学习

目标：

```text
自我_尝试学习 在生成条件结果对或学习输出材料后，
调用方法虚拟存在服务类同步目标方法虚拟存在，
不再确保 / 调用 自我_提交方法状态变化 写 方法状态=可用。
```

验收：

```text
自我_尝试学习 代码块内不再出现：
    自我_提交方法状态变化
    提交目标方法I64特征_方法域动作(... 特征_方法状态(), 方法状态_可用 ...)

自我_尝试学习 代码块内出现方法虚拟存在服务类同步调用或等价服务类包装函数。
```

### P4b2-b3 收口自我_练习

目标：

```text
自我_练习 在刷新运行统计、同条件样本和稳定材料后，
调用方法虚拟存在服务类同步目标方法虚拟存在，
不再确保 / 调用 自我_提交方法状态变化 写 方法状态=好用。
```

`好用 / 稳定` 口径：

```text
好用 / 稳定只作为方法自检维护材料；
不作为任务筹办最低可用阈值；
不由练习方法直接裸写成方法状态最终值。
```

验收：

```text
自我_练习 代码块内不再出现：
    自我_提交方法状态变化
    提交目标方法I64特征_方法域动作(... 特征_方法状态(), 方法状态_好用 ...)

方法稳定状态如需写入，必须通过方法虚拟存在服务类或服务类内部派生函数。
```

### P4b2-b4 保留 / 降级自我_提交方法状态变化

本切片不直接删除枚举、规格确认或兼容入口。

本切片先做到：

```text
学习 / 练习路径不再依赖它；
它不再作为方法状态被动派生的默认路径；
后续由 P4b2-e 决定是否撤出普通本能方法体系、改名为内部治理提交函数，或仅作为历史兼容入口保留。
```

若实现中发现 `自我_提交方法状态变化` 仍被任务执行阶段正式任务调用，必须暂停并记录具体调用链，不在本切片扩大修改。

## 停止条件

执行 P4b2-b 代码时若发现以下情况，必须停下记录堵点：

```text
1. 方法虚拟存在服务类无法从方法首节点读取条件结果对数量或统计底账。
2. 方法状态动作动态只能由 自我_提交方法状态变化 输出，服务类路径不可用。
3. 自我_尝试学习 / 自我_练习 的结果回执强依赖直接提交 方法状态=可用 / 好用。
4. 某个任务执行路径正在正式调用 自我_提交方法状态变化，且无法判断是否兼容入口。
```
