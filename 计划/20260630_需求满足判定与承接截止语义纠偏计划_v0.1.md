# 需求满足判定与承接截止语义纠偏计划 v0.1

日期：2026-06-30

状态：可执行；已完成静态检查，尚未修改代码，尚未构建验证。

## 0. 目标

本计划纠正当前代码中把 `需求有效截止 / 需求已截止` 当作 `当前已满足` 的旧口径。

目标口径：

```text
1. 需求节点是目标契约，不是过程记录。
2. 当前是否满足必须每次读取当前状态 / 当前值，与目标状态 / 目标值和满足关系实时比较。
3. 需求有效截止只表示本轮活动承接截止 / 不再参与当前活动集，不表示当前世界状态下仍然满足。
4. 任务完成只是需求满足和结算的输入之一，不得直接等同于需求满足。
5. 满足过、何时满足、由谁导致满足，进入动态信息、任务运行账、因果链和结算证据。
```

本计划不修改规范口径，只把代码和显示路径收束到已修订规范。

硬边界：

```text
1. `需求有效截止 != 0` 不得显示或判断为当前已满足。
2. 控制面板、任务筹办和父需求聚合需要显示或判断满足时，必须按当前状态 / 目标状态实时比较。
3. 任务状态完成后不得直接把来源需求写成满足。
4. 任务筹办 / 任务执行仍是任务管理生命周期普通函数，不作为本能方法或主动方法动作来源。
```

## 2. 已定位问题锚点

### 2.1 机器逻辑违规

```text
任务模块.筹办.ixx
    统计直接子需求聚合_筹办
        当前把 `需求已截止 || 需求已满足` 统计为子已满足。

    返回直接子需求聚合筹办结果
        当前把未满足子需求数为 0 推进为 `目标结果符合 / 当前任务目标达成`。

自我线程模块.impl.cpp
    私有_回查父需求目标_任务管理新链
        当前用 `已满足或截止子数 == 直接子总数` 设置父目标已满足。

    私有_收束已完成叶需求_线程侧
        当前存在按任务完成 / 已结算直接收束叶需求的入口，需要补实时满足或可信 actual 满足目标闸门。
```

### 2.2 显示和 SQL 镜像违规

```text

    同步SQL控制面板需求显示项

    私有_评估需求满足情况_控制面板

    当前需求表列名仍为 `已满足`，容易把本轮承接截止误读为当前满足。
```

## 4. 实施切片

### P0 只读复核入口

目标：确认本计划锚点仍是当前代码真实路径。

步骤：

```text
1. 回读代码文件头部规则注释模块。
2. rg 检查 `需求已截止 || 需求已满足`、`已满足或截止`、`显示项.已满足 = 需求已截止`、`需求有效截止 != 0` 计入已满足的全部路径。
3. 检查 `说明书/函数功能说明文档.md` 是否已有可复用的需求满足判定函数；优先复用现有函数，不先新增函数。
```

完成判定：

```text
形成本轮最小修改清单，不扩大到需求类总重构。
```

### P1 修正机器逻辑

目标：保证任务筹办、父需求聚合和叶需求收束不再把截止当满足。

修改范围：

```text
任务模块.筹办.ixx
自我线程模块.impl.cpp
必要时少量触碰 需求类.h / 需求类.cpp 注释或既有入口语义说明
```

要求：

```text
1. `统计直接子需求聚合_筹办` 拆分已满足子数、已截止子数、活动未满足子数。
2. `返回直接子需求聚合筹办结果` 只有在正式必要子需求实时满足时才能返回目标结果符合。
3. 父需求聚合不得用已截止子数设置父目标已满足。
4. 已完成叶需求直接收束入口必须先通过实时满足或可信 actual 满足目标闸门；否则只允许进入重筹办、派生需求或开发诊断路径。
5. 不新增任务筹办 / 任务执行本能方法，不生成伪动作动态。
```

完成判定：

```text
代码中不再存在将 `已截止 || 已满足` 作为满足判定的机器逻辑。
Debug x64 构建通过。
```

### P2 收束需求提交入口语义

目标：保留收束入口，但限定入口只能记录“满足事件后的本轮承接截止”。

修改范围：

```text
需求类.h
需求类.cpp
自我线程模块.impl.cpp 调用点
```

要求：

```text
1. `构造满足需求指令` 保留历史命名时，注释必须写清其规范语义是满足事件后的收束指令。
2. `提交需求结算收束` 只作为提交入口，不作为实时满足判定函数。
3. 调用点必须在提交前已有实时满足或可信 actual 满足目标证据。
```

完成判定：

```text
需求类入口不再被外部调用点当作“直接把任务完成转成满足”的工具。
```

### P3 修正控制面板和 SQL 显示

目标：显示层区分当前满足、状态已达未截止、本轮已截止。

修改范围：

```text
需求类.cpp
控制面板类.cpp
控制面板类.ixx
数据库ADO模块.cpp / 数据库ADO模块.ixx 如确需调整 SQL 镜像字段
```

要求：

```text
1. 控制面板摘要不得把 `需求有效截止 != 0` 命名为已满足。
2. SQL 当前需求显示项不得再用 `已满足` 承载 `需求已截止`。
3. 若数据库字段暂不迁移，页面列名至少改为 `本轮已截止`；若迁移字段，拆成 `当前满足` 与 `本轮已截止`。
4. 显示层不得反向影响机器逻辑。
```

完成判定：

```text
控制面板中截止数量和当前满足数量可分辨；重新打开控制面板不再出现“只有截止但显示已有满足”的误导。
```

## 5. 停止条件

必须暂停或拆分新计划的情况：

```text
1. 发现需要新增通用需求满足判定函数，但函数说明文档已有同功能函数可复用却边界不清。
2. SQL 表结构迁移需要用户授权或真实 SQL 环境不可用。
3. 修正机器逻辑暴露任务状态提交、动态信息或结算证据缺失，超出本计划“满足判定语义”范围。
4. 继续修改会把任务筹办 / 任务执行恢复为本能方法或主动动作来源。
```
