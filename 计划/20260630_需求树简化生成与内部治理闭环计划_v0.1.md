## 1. 本计划解决什么

本计划目标是把需求树生成和内部治理闭环收束为一条可实现、可验收的主链：

```text
根特征缺口
-> 根需求活动
-> 根任务承接
-> 任务筹办读取目标变化因果
-> 被动因果向上游追溯
-> 命中主动动作致变因果
-> 生成真正可任务化目标
-> 任务执行产生动作动态 / 状态变化动态
-> 因果信息生成或增强
-> 任务完成后结算
-> 安全 / 服务账务变化
-> 下一轮根特征状态判断
```

核心收口：

```text
需求不是看到一个字段就生成。
需求是在明确缺口以后才生成。
缺口必须有目标宿主、目标特征、当前状态、目标状态、来源因果或来源定义、权限 / 验证要求。
被动因果只能提供证据、来源和上游追溯线索。
主动动作致变因果才能承接真正可任务化目标。
内部治理结构缺陷不得包装成普通需求。
```

## 2. 简化需求树生成规则

### 2.1 需求树生成入口只保留四类

```text
入口 A：根特征缺口
    自我_安全值 / 自我_服务值 当前状态低于最大值目标。
    只激活安全根需求 / 服务根需求和根任务承接。
    不直接生成固定安全清单或直接服务任务。

入口 B：任务筹办缺口
    任务筹办为了让当前任务可执行而发现缺口。
    原则上只允许四类：缺方法、缺条件、方法缺动作、方法缺条件结果对。
    参数不可配、证据不足、服务触发事实缺失等必须归并到条件 / 证据条件缺口，不另造泛化需求类型。

入口 C：执行期真实变化缺口
    只允许条件突然变化、输入材料过期、输出结果不满足目标、副作用约束触发等运行期事实。
    如果执行期才发现目标语义缺失、协议缺入口、方法结构字段缺失、任务状态账无法写回，应按逻辑错误或开发诊断处理。

入口 D：可验证外部 / 人类服务触发事实
    当前会话输入、人类表达、外部请求、服务目标事实、反馈事实等点亮直接服务因果链。
    只在触发事实存在且闭环信息位确认缺口阻断行动、验证、归因或回写时，生成直接服务子需求。
```

自检不单独作为第五类普通入口。自检只负责发现根特征缺口、事实缺口、因果缺口或代码缺陷型拒绝；入树前必须翻译到上述入口之一或进入开发诊断闭环。

### 2.2 被动因果不能直接生普通需求

被动因果包括：

```text
观察动态导致的状态变化因果；
提交入口导致的状态变化因果；
任务状态动作动态；
任务完成后结算动态；
服务值自动衰减动态；
外部事实变化动态。
```

它们只能说明：

```text
发生了什么变化；
变化由哪个提交 / 观察 / 结算 / 外部事件留下证据；
上游来源动态或来源因果是什么；
还缺哪些条件、证据、动作入口或方法结构。
```

它们不得直接成为：

```text
普通可执行方法候选；
主动动作来源；
普通可任务化需求来源；
安全 / 服务值结算前证据的充分条件。
```

### 2.3 主动因果是可任务化承接点

主动动作致变因果至少需要：

```text
动作主体；
被作用目标；
目标特征；
动作前状态；
动作后状态；
方法 / 动作入口；
D0 方法动作动态或可验证的动作运行证据；
同源变化证据组；
副作用约束和验证方式。
```

只有命中主动动作致变因果后，任务筹办才允许生成真正可任务化的原子需求：

```text
让某个被需求存在的目标特征从当前状态达到目标状态。
```

若主动因果命中但方法结构不完整，生成的不是普通业务需求，而是方法补齐类缺口：

```text
缺方法；
缺方法动作入口；
缺条件节点；
缺结果节点；
缺条件结果对；
缺参数绑定条件；
缺验证证据条件。
```

## 3. 内部治理真正闭环

### 3.1 目标闭环

```text
自我根特征当前状态读取
-> 与最大值目标比较
-> 根需求活动性刷新
-> 根任务承接
-> 根任务筹办
-> 读取目标变化因果视图
-> 被动链追溯到主动链
-> 主动链生成原子任务 / 方法补齐任务
-> 任务管理执行
-> 方法动作动态 D0 / 任务状态动态 D1 / 服务治理判断 G0 / 结算动态 D2
-> 因果信息生成或增强
-> 安全 / 服务账务变化或候选
-> 下一轮自我状态判断
```

### 3.2 不闭环的情况如何处理

```text
追溯停在被动因果：
    记录被动因果闭环状态和缺上游主动因果；
    不生成普通任务；
    可进入等待事实、补证据、观察、学习或诊断。

追溯停在内部治理函数：
    不生成需求；
    进入开发诊断或逻辑错误处理。

追溯停在方法结构缺口：
    生成方法补齐类缺口；
    不包装成安全 / 服务业务目标。

追溯停在服务直接触发事实缺失：
    只能生成间接服务维护需求；
    不生成当前服务对象、服务目标、G0、D2 或服务值入账任务。
```

### 3.3 安全 / 服务治理主轴

安全值只调节治理优先级，不改服务根目标值：

```text
安全值高：
    服务优先级提升；
    服务衰减压力、服务候选排序和休眠压力可以更充分展开。

安全值低：
    安全优先级提升；
    服务优先级降低；
    服务仍可在安全边界内保留等待 / 监听 / 校准需求。
```

实现上只能影响：

```text
需求列表排序主轴；
任务调度优先级；
服务衰减压力；
休眠阈值；
单次服务入账上限；
间接服务维护敏感度。
```

禁止影响：

```text
自我_服务值 最大值目标；
服务对象是否存在；
服务目标是否明确；
服务成功是否成立；
服务值结算证据是否充分。
```

## 4. 项目结构映射

| 业务概念 | 项目承载结构 | 写入方 | 读取方 | 验证方式 |
| --- | --- | --- | --- | --- |
| 根特征目标 | 抽象特征树 / 状态节点 / I64 最大值 | 特征类初始化、根特征读取函数 | 自我类、自我线程 | 日志证明读取“最大值”，不是高位低值 |
| 根需求活动性 | 需求节点、需求主信息、需求权重 | 自我线程根需求刷新入口 | 需求列表、任务发起意图 | 需求树日志、SQL 投影、需求权重变化 |
| 根任务承接 | 任务节点、任务虚拟存在、对应需求引用 | 自我类初始化或任务管理线程 | 任务筹办、任务调度 | 根任务存在、绑定根需求、状态可推进 |
| 被动因果 | 动态链、因果信息、来源动态引用 | 动态 / 因果类、提交入口、结算后处理 | 任务筹办因果视图、结算证据读取 | 被动因果可回溯来源动态，不可作为方法候选 |
| 主动因果 | 方法动作动态 D0、因果信息、同源变化证据组 | 方法执行、因果生成链 | 任务筹办、学习链、结算审查 | D0 / 前后状态 / 方法入口 / 目标特征齐备 |
| 因果缺口 | 缺口回执、候选因果、诊断项 | 任务筹办、因果类 | 需求入树入口、学习入口、诊断闭环 | 缺口分类明确，不直接裸接需求 |
| 方法补齐缺口 | 方法头、方法虚拟存在、条件节点、结果节点、条件结果对 | 方法类、学习相关本能方法 | 任务筹办、执行模块 | 方法候选集、可执行入口、条件结果对日志 |
| 直接服务触发事实 | 服务根闭环信息位、来源动态、服务上下文状态 | 会话 / 外部请求 / 服务事实提交入口 | 服务需求生成、G0 判断 | 无触发事实时只生成间接维护需求 |
| 结算闭环 | D1 / G0 / D2、任务价值反馈链、账务状态 | 任务管理后处理、服务模块 | 自我状态判断、因果增强 | 任务完成不等于服务成功，D2 不反推 G0 |

### P1 根目标读取与根任务承接闭合

目标：

```text
根需求活动性来自最大值目标和当前值差距。
根需求有根任务承接壳。
根任务不是任务筹办 / 任务执行本能方法。
```

必要修正：

```text
1. 根目标读取优先读取“最大值”状态，不再用“高位 / 目标区间低值”当根目标。
2. 自我类::确保自我根需求与根任务已初始化_ 必须明确根任务承接策略。
3. 若初始化期创建根任务，则调用现有 确保根任务_ 并绑定安全根需求 / 服务根需求。
4. 若选择只由活动需求任务化生成根任务，必须在计划和代码注释中明确，并保证任务化入口能稳定生成根任务。
```

验收预测：

```text
启动日志能证明安全 / 服务目标读取为最大值。
安全根需求、服务根需求可读取当前状态、目标状态和满足关系。
根任务承接策略唯一，不出现“函数名说已初始化但实际未初始化”的歧义。
```

### P2 被动因果信息闭环

目标：

```text
被动因果能够闭合为证据链，但不会被误用为主动方法或普通需求来源。
```

工作项：

```text
1. 盘点被动动态来源：
   任务状态动态、提交动态、结算动态、观察动态、服务衰减动态、外部事实动态。

2. 为每类被动动态确认：
   来源动态；
   旧状态 / 新状态；
   目标宿主；
   目标特征；
   同源变化证据组；
   可追溯上游因果或缺上游因果状态。

3. 增加或复用 因果类 普通函数：
   读取被动因果闭环状态；
   验证被动因果来源动态完整；
   读取被动因果上游来源；
   标记缺上游主动因果。
```

禁止：

```text
不得把被动动作学习成主动方法。
不得把任务状态提交动态当作可执行动作模板。
不得用单次状态变化线索直接标记因果已验证。
```

验收预测：

```text
同一被动变化能回查来源动态。
被动因果缺上游主动因果时，任务筹办只生成缺口回执或诊断，不生成普通需求。
```

### P3 主动因果信息生成链路

目标：

```text
主动方法执行后能稳定生成或增强动作致变因果。
主动因果可被任务筹办消费，承接初始任务生成。
```

工作项：

```text
1. 盘点 D0 方法动作动态生成入口。
2. 确认 D0 能携带动作主体、被作用对象、目标特征、初始状态、结果状态、输出场景和方法入口。
3. 建立或复用主动因果生成函数：
   从 D0 + 状态迁移账 + 同源变化证据组生成主动动作致变因果。
4. 建立主动因果可任务化判定：
   有正式方法入口 -> 可生成原子需求 / 任务；
   有方法头但不可执行 -> 方法补齐缺口；
   无方法入口 -> 学习或方法头承接；
   只有被动状态变化 -> 不可任务化。
```

验收预测：

```text
真实方法执行后能查到主动动作致变因果。
任务筹办能从主动因果读出目标宿主、目标特征、目标状态和方法承接。
被动因果不会进入方法候选集。
```

### P4 简化需求树生成入口

目标：

```text
需求树生成统一走缺口分类和更新指令，不再由分散路径凭字段名造需求。
```

建议普通函数：

```text
需求_构造缺口候选视图(...)
需求_按缺口类型选择获取途径(...)
需求_因果承接原子目标准入(...)
需求_方法补齐缺口准入(...)
需求_直接服务缺口准入(...)
需求_开发诊断拒绝回执(...)
```

这些是需求域普通函数或提交入口，不是本能方法。

验收预测：

```text
每个入树需求都有获取途径、目标语义、目标宿主、当前状态、目标状态和来源证据。
普通目标直接生成只保留为兼容枚举值，不再显示或语义化为“凭空普通目标”。
```

### P5 任务筹办消费因果视图

目标：

```text
任务筹办只负责找路径、找方法、找条件。
任务筹办消费因果视图，而不在内部硬编码安全 / 服务规则。
```

工作项：

```text
1. 任务筹办读取来源需求目标语义。
2. 生成临时因果视图。
3. 被动因果继续追溯上游。
4. 主动因果输出候选方法或原子目标。
5. 缺方法 / 缺条件 / 缺动作 / 缺条件结果对输出结构化回执。
6. 内部治理缺陷输出开发诊断，不入普通需求树。
```

验收预测：

```text
候选集先填充再选择。
被动因果不会被当作方法候选。
任务筹办不生成任务筹办子任务或任务执行子任务。
```

### P6 安全 / 服务治理主轴裁决

目标：

```text
安全值高提升服务优先级。
安全值低提升安全优先级并降低服务优先级。
服务根目标值不随安全值变化。
```

建议普通函数：

```text
自我_裁决安全服务治理主轴(...)
自我_计算服务治理压力参考点(...)
自我_计算服务衰减与休眠压力(...)
自我_按治理主轴排序需求列表(...)
```

这些函数只影响排序、调度、衰减和休眠，不写服务目标值。

验收预测：

```text
低安全样本下安全列表优先。
高安全且有效服务需求存在时服务列表优先。
服务目标状态仍为自我_服务值最大值。
```

### P7 直接服务触发事实准入

目标：

```text
无直接服务触发事实时，只生成间接服务维护需求。
有直接服务触发事实时，才允许直接服务上下文缺口入树。
```

工作项：

```text
1. 追踪服务直接子需求生成入口。
2. 服务对象 / 服务目标 / 服务结果验证 / 归因 / G0 / D2 类需求必须检查触发事实。
3. 无触发事实时，只允许：
   服务触发事实监听；
   服务机会检查；
   服务能力校准；
   服务根缺口检查；
   休眠 / 唤醒候选判断。
```

验收预测：

```text
无服务触发事实运行时，直接服务上下文需求数为 0。
有服务触发事实时，直接服务需求带来源动态、服务对象、服务目标和验证方式。
```

### P8 结算到下一轮根状态闭环

目标：

```text
任务完成后通过价值反馈链结算。
结算动态增强因果证据。
安全 / 服务账务变化进入下一轮根特征状态判断。
```

工作项：

```text
1. 确认叶子任务完成后才进入价值反馈链。
2. D1 只证明任务壳推进。
3. G0 只由服务证据判断。
4. D2 只证明服务值如何入账，不能反推成功服务。
5. 结算被动因果增强必须回到下一轮自我状态判断。
```

验收预测：

```text
任务完成不直接写需求满足。
服务值增加只来自 G0 确认成功服务。
服务值衰减只唤醒服务意识和间接服务维护。
```

```text
根任务承接；
被动因果闭环可回查；
被动因果缺上游主动因果时不生成普通需求；
主动因果可生成可任务化目标；
任务筹办四类缺口分类；
无直接服务触发事实只生成间接服务维护；
任务完成后结算回写下一轮状态判断。
```

禁止验收说法：

```text
不得宣称自我苏醒完成。
不得宣称初步成熟完成。
不得用构建通过证明业务闭环。
不得用控制面板显示替代机器结构证据。
不得用模拟入口或伪造动作动态补样本。
```

## 7. 执行顺序建议

