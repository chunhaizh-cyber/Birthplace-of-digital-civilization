# 20260618 项目功能函数去重与无效代码清理计划 v0.1

## 0. 目标

按既有函数清单和项目规范，审计项目中的重复定义函数、无调用函数、无效壳函数和旧兼容代码，逐步删除或改为调用唯一正式函数。

本计划不以函数名相同作为删除依据；只有在调用证据、语义等价证据、项目结构闭环证据和构建验证均闭合后，才允许进入删除切片。

补充迁移规则：

```text
1. 无领域自定义类 / 结构体 / 节点类型参与的通用函数，才允许迁移到 全局共享函数类.ixx。
2. I64、比较量、三向关系掩码、VecI64、VecIU64 等基础别名 / 基础容器可以进入全局共享模块，但必须确认不会造成模块 import 环。
3. 有领域自定义类型参与的通用函数，必须迁移回对应专用类、功能类或对应头文件。
4. 领域自定义类型包括但不限于：语素、基础信息、主信息类、存在、场景、特征、特征值、需求、任务、方法、因果、动作动态、外设观察材料和控制面板 DTO。
5. 涉及结构体的函数，先回查结构体审计和本计划断点；若结构体已判定为未接入、只剩内部计数 / 去重视图或可删除壳，服务该结构体的函数可以纳入同一删除切片。
6. 若结构体仍承担协议、状态、动态、外部读取、控制面板显示或运行证据，不得因函数重复而迁移或删除。
```

单文件迁移流程：

```text
1. 打开一个源代码定义文件。
2. 逐个分析该文件内函数用途，补齐功能备注。
3. 根据原始 C++ 签名、输入输出承载、副作用、项目结构依赖和所属领域生成功能签名。
4. 判断函数归属：
   A. 无领域自定义类 / 结构体 / 节点类型参与的通用公用函数：
      先在 全局共享函数类.ixx 查找同功能函数；
      已存在则删除本地重复定义并改为调用全局函数；
      不存在则迁移或新增到 全局共享函数类.ixx。
      I64、比较量、VecI64、VecIU64 等基础别名 / 基础容器允许参与签名，
      但迁移前必须确认 import 方向不形成环。
   B. 有领域自定义类型参与的通用函数：
      迁移回对应专用类、功能类或对应头文件；
      不进入 全局共享函数类.ixx。
   C. 模块私有、入口、回调、virtual / override、线程、协议、项目结构读写证据函数：
      原地保留或进入专项审计。
5. 迁移后必须改变原引用方式，并删除原重复定义。
6. 每个文件完成后重生成 说明书/函数功能说明文档.md 并构建验证。
```

## 3. 判定规则

### 3.1 可删除

满足下列任一类，且未命中保留规则时，可进入删除候选：

```text
1. 只有声明 / 定义，没有真实调用，且不是入口、回调、虚函数、导出函数、注册函数或协议函数。
2. 函数只服务已经删除的结构体、视图、旧壳或兼容路径。
3. 函数体与已有正式函数语义完全等价，调用方约束一致，可改为调用唯一正式函数。
4. 函数只返回错误码、文本说明或日志，不写入 / 读取项目通用数据结构，属于无效闭环壳。
5. 函数属于旧入口、旧流程、旧字段兼容层，且当前正式路径已有唯一实现。
```

### 3.2 暂不删除

命中下列任一类，先标为保留或专项审计：

```text
1. 声明 / 定义对。
2. 重载、模板、构造函数、析构函数、操作符。
3. virtual / override / 接口实现。
4. main、线程入口、窗口入口、控制面板入口、导出入口。
5. 通过函数指针、注册表、宏拼接、消息分发、反射式名称或本能方法表间接调用。
6. 承担状态、动态、场景、特征、方法、需求、动作动态或错误日志证据写入 / 读取。
7. 外部观察材料、协议 DTO、控制面板显示读取和运行诊断仍需外部读取。
```
