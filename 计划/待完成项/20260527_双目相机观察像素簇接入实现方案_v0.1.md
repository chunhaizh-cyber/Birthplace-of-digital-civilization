# 20260527_双目相机观察像素簇接入实现方案 v0.1（簇级观察口径修订版）

## 0. 定位

状态：

```text
方案已生成；
未进入当前主动队列；
未实施代码；
真实 D455 连续观察样本待条件具备后验证。
```

本方案的“接入”不是让双目相机直接理解世界，而是建立：

```text
双目相机外设独占观察线程
    -> 持续生产外设观察报告 / 观察像素簇 / 稳定特征
    -> 写入外设观察消息队列 / 最新观察缓存 / 稳定特征缓存
    -> 任务管理外设消息承接线程按正式需求匹配和领取
    -> 生成任务回执 / 派生需求消息 / 动作动态输入 / 观察事实承接请求
    -> 自我线程裁决是否入树、入世界和生成存在候选
```

禁止把该接入目标写成：

```text
双目相机发现存在；
双目相机识别世界对象；
双目相机直接确认目标可见性；
双目相机直接完成安全值 / 服务值结算。
```

阶段命名口径：

```text
推荐名称：
    双目相机观察像素簇接入阶段
    双目相机簇级观察特征接入阶段

不再作为当前主线名称：
    像素级观察存在化
    像素级 100% 识别
```

## 1. 规范核对结果

| 核对项 | 规范要求 | 本方案处理 |
| --- | --- | --- |
| 线程来源边界 | 线程不是动作来源；动作动态必须绑定明确方法。 | 外设观察线程只作为外设内部观察服务；自我可见动作仍通过控制、检查、使用类本能方法或自我承接方法记录。 |
| 外设本能方法边界 | 外设本能方法只暴露控制、检查、使用契约。 | 相机内部采集、校正、匹配、滤波、分割、跟踪和学习保持私有，不登记为自我层本能方法。 |
| 外设独占观察线程 | 可持续观察并提交稳定特征报告，但不能写自我需求树、世界树真值或存在树。 | 外设输出外设观察报告、观察像素簇和稳定性证据；自我负责承接、生成存在候选和后续确认。 |
| 观察像素簇分层 | 观察像素簇是像素集合、掩码、局部图、特征摘要和稳定性状态的观察材料，不是稳定世界存在。 | 方案以观察像素簇为外设主要输出单位；存在候选由自我侧生成。 |
| 掩码和局部图 | 掩码是正式特征；彩色轮廓局部图、深度轮廓局部图是簇上的观察证据特征，不能替代候选确认。 | 掩码、局部图均作为特征句柄与状态入账，参与子轮廓、建模、回查和候选验证。 |
| 像素级可回查底座 | 旧文档中的 `100%` 只表示帧内可寻址、可回查、无遗漏、无重复，不是像素级物体识别。 | 该能力降级为观察簇、掩码、控制面板命中查询和调试归因的底座；当前主线是观察像素簇输出，不要求物化 `W * H` 个像素观察存在节点。 |
| 外设队列消费 | 外设线程主动生产观察材料；安全 / 服务根需求不得直接消费原始队列；任务管理外设消息承接线程按正式需求消费 / 匹配 / 领取。 | 方案采用“外设生产、队列缓存、需求驱动消费、任务管理承接、自我裁决入账”模型。 |
| 任务筹办接入 | 任务筹办生成临时因果视图和派生需求消息；正式入树由自我线程裁决。 | 本方案只要求任务管理侧输出派生需求消息，不允许任务筹办直接写正式需求。 |
| 枚举状态生产者 | `已生成`、`已承接`、`达标` 等枚举目标必须有合法方法生产者。 | 每个新增状态特征都在实施切片中要求登记生产方法或承接方法，不能只加字段。 |
| 验证证据 | 不使用模拟样本、伪造入口或伪造动作动态；硬件未具备时放入待完成。 | 真实 D455 连续观察、稳定性和控制面板复现验证均列为待条件恢复后的验收，不强行验证。 |

核对结论：

```text
本方案与当前规范口径一致；
未发现需要暂停的上级规范冲突；
但本方案不得直接并入当前主动队列，需等待计划索引选择该外设观察簇接入线后再实施。
```

### 1.1 新旧口径关系

最新口径不是：

```text
像素级 100% 识别；
每个像素都物化为自我关心的像素观察存在；
外设逐像素输出本能方法清单。
```

旧计划里的 `100%` 表达只保留为：

```text
像素级可回查底座 =
    帧内可寻址
    帧内可回查
    无遗漏
    无重复
```

该底座用途：

```text
支持掩码定位；
支持观察像素簇回查原始像素；
支持控制面板鼠标命中查询；
支持后续调试、验证、归因；
支持从簇回到颜色、深度、空间坐标。
```

当前主线改为：

```text
双目相机观察线程
    -> 当前观察帧
    -> 观察像素簇集合
    -> 每个簇的特征值
    -> 每个簇的掩码
    -> 每个簇的彩色轮廓局部图
    -> 每个簇的深度轮廓局部图
    -> 自我承接为存在候选
```

分层关系：

```text
像素是底层材料；
簇是外设输出单位；
存在候选是自我认知单位；
已确认观察存在是自我验证后的结果。
```

## 2. 接入目标

本阶段目标：

```text
双目相机稳定输出观察像素簇；
每个观察像素簇携带可复现特征值；
每个观察像素簇携带掩码、彩色轮廓局部图和深度轮廓局部图；
自我把观察像素簇承接为存在候选；
后续根据安全 / 服务需求决定是否继续验证、确认和入账。
```

本阶段不再验收：

```text
必须生成 W * H 个像素观察存在节点；
像素级 100% 识别通过。
```

若保留像素层验收，只写作：

```text
当前观察帧.像素级可回查底座状态 == 已建立
当前观察帧.像素级可回查状态 == 可用
```

最小闭环：

```text
安全 / 服务需求
    -> 任务筹办生成临时因果视图
    -> 任务管理生成派生观察需求消息
    -> 自我线程裁决入树
    -> 任务管理建立外设等待项 / 订阅项
    -> 双目相机观察线程持续把观察材料写入队列 / 缓存
    -> 任务管理外设消息承接线程匹配等待任务 / 活跃需求
    -> 生成任务回执 / 观察事实承接请求 / 派生需求消息
    -> 自我线程裁决并承接观察帧和观察像素簇
    -> 自我生成存在候选
    -> 自我统计当前帧存在识别情况
```

```text
    双目相机.运行状态

外设内部学习：
    观察条件 + 外设配置 + 目标特征类型 -> 特征稳定复现结果
```

### 3.2 双目相机不负责

```text
不直接写自我需求树；
不直接写世界树真值；

```

```text
承接外设观察报告；
```


## 5. 双目相机外设线程方案

### 5.1 线程职责

```text
双目相机观察线程 {
    1. 持续检查外设运行状态。
    2. 按当前观察配置采集 RGB-D 帧。
    3. 生成像素有效性图。
    4. 生成观察像素簇集合。
    5. 为每个簇计算颜色、深度、空间、轮廓和稳定性特征。
    6. 生成彩色轮廓局部图、深度轮廓局部图和相关掩码。
    7. 维护外设内部候选观察对象。
    8. 学习当前条件下哪些配置能稳定输出哪些特征。
    9. 向外设观察消息队列 / 最新观察缓存 / 稳定特征缓存发布观察材料。
}
```

### 5.2 线程状态特征

```text
双目相机观察线程.线程状态 == 未启动 / 运行中 / 暂停 / 异常 / 已停止
双目相机观察线程.最近报告状态 == 已生成 / 未生成 / 生成失败
双目相机观察线程.最近错误状态 == 无错误 / 有错误
双目相机观察线程.观察配置状态 == 已应用 / 待应用 / 应用失败
双目相机.运行可用性值 > 0
```

这些状态只能由合法方法或外设检查/使用回执生成，不能由线程裸写成自我动作动态。

### 6.5 队列和缓存分层

本方案不把所有原始帧直接塞入自我可见的全局队列。队列和缓存分三层。

第一层：外设内部原始帧缓存。

```text
原始 RGB 帧
原始深度帧
内部滤波结果
内部临时分割结果
内部多帧缓存
```

该层归双目相机外设线程内部管理，自我和任务管理不直接消费。

第二层：外设观察报告队列。

```text
外设观察报告队列项 {
    外设ID
    报告ID
    时间戳
    帧宽
    帧高
    彩色帧号
    深度帧号
    配置摘要

    观察像素簇集合
    簇ID掩码
    低质量区域集合
    未归簇区域集合
    错误摘要
}
```

这是任务管理外设消息承接线程消费的主队列。

第三层：最新稳定特征缓存。

```text
按 外设ID + 特征类型 + 目标区域 / 簇ID 建索引：
    最近稳定颜色特征
    最近稳定深度特征
    最近稳定空间坐标特征
    最近稳定轮廓特征
    最近推荐观察配置
```

如果正式需求需要：

```text
目标区域.深度有效率 > 阈值
```

任务管理外设消息承接线程可以先查稳定特征缓存；满足时生成任务回执或观察事实承接请求，不必等待下一帧。

### 6.6 任务管理外设消息承接线程

正式消费者是：

```text
任务管理外设消息承接线程
```

不是：

```text
自我线程；
安全 / 服务根需求；
普通任务执行线程直接读取外设流。
```

承接线程职责：

```text
1. 从外设观察消息队列读取报告。
2. 校验报告完整性。
3. 去重和时效检查。
4. 更新最新观察缓存和稳定特征缓存。
5. 匹配等待中的任务。
6. 匹配活跃需求。
7. 判断是否需要上报自我线程。
8. 生成任务回执 / 派生需求消息 / 动作动态输入 / 观察事实承接请求。
```

它是外设消息分拣层，不是世界树写入者。

### 6.7 三种消费方式

等待任务消费：

```text
有明确任务正在等待 双目相机_取得当前观察报告。
承接线程收到匹配报告后生成任务回执。
```

活跃需求消费：

```text
没有显式任务等待，但有活跃需求需要 目标区域.稳定特征状态 == 稳定。
承接线程收到可满足材料后生成满足线索、派生回执或观察事实承接请求，上报自我线程裁决。
```

缓存不消费：

```text
没有等待任务，也没有活跃需求，只是普通观察流。
承接线程只更新最新观察报告缓存 / 稳定特征缓存，不打扰自我线程，不入树。
```

### 6.8 上报自我线程的条件

不是每条外设消息都上报。只有以下情况才上报自我线程：

```text
1. 命中等待任务。
2. 满足某个活跃需求。
3. 产生安全相关高优先级缺口。
4. 外设状态发生关键变化。
5. 稳定特征首次达标。
6. 活跃父需求的关键质量条件不满足。
7. 外设错误影响当前任务。
8. 需要正式派生需求入树。
```

其它情况只留在：

```text
外设观察缓存
稳定特征缓存
外设内部历史样本
```

队列中的消息只是外设观察材料，不是自我所在场景的正式观察事实。只有经过任务管理承接、自我线程裁决、自我承接方法或统一更新指令后，才可能形成当前观察帧存在、观察像素簇集合、存在候选集合、动作动态或世界树因果样本。

## 7. 双目相机本能方法接口方案

本节是接口方案，不宣称方法已经全部创建或已具备真实硬件执行能力。

### 7.1 控制类

```text
双目相机_使达到可用状态
    输出：双目相机.可用状态 == 可用

双目相机_设置观察配置
    输出：双目相机.工作模式 == 指定模式
    输出：双目相机.观察配置状态 == 已应用

双目相机_释放
    输出：双目相机.占用状态 == 已释放
```

建议观察模式：

```text
高深度质量
```

### 7.4 不再作为外设本能方法主线的旧方法

旧计划中出现过的逐像素方法：

```text

双目相机_获取像素深度
双目相机_获取像素空间坐标
```

按最新口径不再作为双目相机外设本能方法主线。它们对应的能力应收敛为外设内部的像素索引、掩码、局部图和特征缓冲，或自我侧的回查能力。

对自我暴露的替代主接口是：

```text
双目相机_取得当前观察报告
```

输出：

```text
外设观察报告.生成状态 == 已生成
当前观察帧.观察像素簇集合状态 == 已生成
```

也就是说：

```text
外设内部可以维护像素级索引；
自我面向外设只读取观察报告和观察像素簇集合；
逐像素回查是底座能力，不是外设观察的主要输出单位。
```

## 10. 需求树与任务筹办接入

### 10.1 根需求到观察需求

安全或服务根需求可以通过世界树因果派生观察材料需求，例如：

```text
自我.安全值 > 安全值基线
自我.服务值 > 服务值基线
```

派生到：

```text
当前观察帧.基础观察事实可用状态 == 可用
当前观察帧.观察像素簇集合状态 == 已生成
当前观察帧.存在识别达标状态 == 达标
```

是否派生、是否阻塞父需求，必须由父需求所需特征和临时因果视图决定，不能由外设线程或 S1 诊断方法决定。

安全 / 服务根需求不得直接消费外设观察报告队列。根需求只通过需求树派生正式观察需求，任务管理据此建立外设等待项或订阅项。

### 10.2 临时因果视图

当需求目标需要观察材料时，任务筹办查询世界树因果，生成路径：

```text
双目相机.可用状态 == 可用
双目相机.运行可用性值 > 0
外设观察报告.生成状态 == 已生成
当前观察帧.观察像素簇集合状态 == 已生成
当前观察帧.存在候选集合状态 == 已生成
```

临时因果视图只用于筹办，不是权威世界事实。

### 10.3 外设等待项 / 订阅项

任务管理拿到正式观察需求后，建立等待项或订阅项，例如：

```text
外设等待项 {
    来源需求 = 当前观察帧.观察像素簇集合状态 == 已生成
    目标外设 = 双目相机
    期望消息类型 = 外设观察报告
    期望内容 = 观察像素簇集合
    最低稳定性要求
    最大等待时间
    是否允许缓存 = 是
}
```

任务管理外设消息承接线程按等待项 / 活跃需求消费队列或缓存：

```text
如果队列或缓存中有匹配报告：
    生成任务回执 / 观察事实承接请求。

如果没有匹配报告：
    等待外设线程下一次报告。

如果报告质量不足：
    生成派生需求消息，例如推荐配置 / 重新观察 / 调整工作模式 / 观察质量改善路径学习需求。
```

### 10.4 派生需求消息

任务管理侧只生成派生需求消息：

```text
派生需求消息 {
    父需求
    根分区
    目标宿主
    目标特征类型
    比较符：大于 / 小于 / 等于
    目标值
    来源因果
    生成类型
    阻塞级别
    优先级
}
```

正式需求仍由自我线程裁决后统一入树。

## 14. 验收标准

### 14.1 外设侧

```text
双目相机观察线程运行中；
外设观察报告.生成状态 == 已生成；
观察像素簇集合状态 == 已生成；
每个簇有像素集合掩码；
每个簇有彩色轮廓局部图；
每个簇有深度轮廓局部图；
每个簇有至少一类稳定特征摘要；
不可得特征有失败原因。
```

### 14.2 自我侧

```text
观察帧存在已挂到自我所在场景；
像素级可回查底座状态 == 已建立；
像素观察事实索引状态 == 已建立，可作为兼容旧链路的底座实现形态；
观察像素簇集合承接状态 == 已承接；
存在候选集合状态 == 已生成；
当前观察帧.存在识别摘要状态 == 已生成。
```

### 14.3 任务管理承接侧

```text
外设观察报告进入外设观察报告队列；
最新观察缓存可按外设ID和报告ID回查；
稳定特征缓存可按 外设ID + 特征类型 + 目标区域 / 簇ID 命中；
任务管理外设消息承接线程能匹配等待任务 / 活跃需求；
无匹配需求时只更新缓存，不入树；
命中需求时生成任务回执 / 派生需求消息 / 动作动态输入 / 观察事实承接请求；
安全 / 服务根需求没有直接读取原始队列。
```

### 14.4 回查侧

给定像素坐标，可回查：

```text
像素级底座事实；
所属观察像素簇；
所属存在候选，可选；
颜色；
深度；
空间坐标；
低置信 / 冲突 / 不可观测原因。
```

### 14.5 禁止宣称

```text
不宣称观察像素簇就是稳定世界存在；
不宣称存在候选已经确认；
不宣称跨帧身份稳定；
不宣称语义识别完成；
不宣称基础风险判断已明确；
不把控制面板显示成功当作业务验收通过。
```

```text
最新观察缓存和稳定特征缓存的索引、淘汰和时效规则确定；
任务管理外设消息承接线程的等待项 / 订阅项结构确定；
掩码 / 局部图 / 点集句柄的所有权和释放规则确定；
计划索引选择该双目相机观察像素簇接入线为主动队列。
```

风险：

```text
若直接把外设线程输出写成世界真值，会破坏自我承接和验证边界；
若让安全 / 服务根需求直接消费外设队列，会让价值根被高频外设流淹没；
若普通任务执行线程直接吃外设流，会绕过任务管理承接、等待项、时效和来源需求匹配；
若继续把旧像素级 100% 表述当成当前识别目标，会把底座能力误写成主线验收；
若把掩码只当显示附件，会破坏子轮廓、三维建模和像素归属链；
若只做整帧质量可用状态，会误杀颜色/像素可用但深度/空间不足的帧；
若没有真实连续样本，稳定性验收只能保持待完成，不能用模拟样本替代。
```

## 16. 最终定案

```text
最新主线不是像素级 100% 识别；
旧像素层目标只保留为像素级可回查底座。

双目相机接入采用“外设独占观察线程 + 观察像素簇输出 + 生产队列 / 缓存 + 需求驱动消费 + 任务管理承接 + 自我裁决入账”的模式。

外设线程负责持续观察和稳定输出观察像素簇；
每个观察像素簇必须包含像素集合、掩码、彩色轮廓局部图、深度轮廓局部图、颜色/深度/空间特征和稳定性摘要。

安全 / 服务根需求不直接消费外设原始队列；
任务管理外设消息承接线程根据正式观察需求匹配等待项、活跃需求和稳定特征缓存。

自我不直接接收“相机识别出的世界存在”；
自我只裁决被任务管理领走并转译后的观察材料，并将其生成存在候选。
存在候选再经过验证，才可能成为已确认观察存在。
```

一句话：

```text
相机线程一直把可稳定复现的观察簇放入队列和缓存；只有被正式需求通过任务管理领走的信息，才会进入自我的正式认知链。
```
