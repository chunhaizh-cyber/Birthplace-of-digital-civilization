## 2. 当前代码事实

### 2.1 可执行入口判定

当前执行桥最小判定为：

```text
方法可执行入口数量 = 1
当且仅当：
    动作句柄.类型 == 本能函数ID
    且 本能ID != 0
```

也就是说，真实可执行入口当前不是普通特征值，而是方法首节点上的有效动作句柄。

### 2.2 定向学习当前能力

`自我_定向学习` 当前可以补出：

```text
方法动作状态 = 1
方法状态 = 待条件结果对
候选动作节点 / 候选方法能力包 / 形参包 / 结果包 / 条件结果对候选结构
```

但它不会生成：

```text
动作句柄.类型 = 本能函数ID
动作句柄.本能ID = ...
```

因此它只能补“方法动作语义痕迹”，不能补真实可执行入口。

### 2.3 执行桥支持范围

`结构体_动作句柄` 虽然定义了：

```text
本能函数ID
外部实现主键
动作序列主键
```

但当前执行桥真实执行路径只支持：

```text
本能函数ID
```

外部实现主键和动作序列主键没有可执行调度实现，不能作为当前闭合依据。

## 3. 上级规范边界

必须遵守：

```text
1. 不能伪造 方法可执行入口数量 = 1。
2. 不能把 改变特征值 绑定为占位方法可执行入口。
3. 不能把任务筹办 / 任务执行恢复为本能方法。
4. 线程不是动作来源。
5. 方法状态、任务状态、需求状态等变化必须有明确方法来源。
```

因此，当前不能通过底层写入特征值绕过入口缺口。

### 3.1 是否需要本能方法的判定标准

不是所有过程都需要做成本能方法。

判定标准是：

```text
如果某段逻辑会持久改变方法、任务、需求或世界树中的特征状态，
    则它必须有明确动作来源；
    若要生成方法动作动态，应由对应语义方法 / 本能方法承接。

如果某段逻辑只是中间计算、候选筛选、诊断、评分、反推或回执整理，
    不直接持久改变方法、任务、需求或世界树特征状态，
    则可以由普通逻辑代码实现；
    不需要动作动态，也不需要本能方法。
```

因此：

```text
因果反推自我动作组合：
    只读因果、状态、方法能力，输出候选组合；
    不写方法动作句柄、不写任务状态、不写正式需求、不写世界事实；
    第一版可以是普通逻辑接口，不需要本能方法。

提交方法可执行入口：
    会把明确单步本能方法 ID 写入目标方法动作句柄，
    属于方法域特征状态提交；
    需要明确动作来源，第一版仍按方法域提交动作处理。

建立条件结果对：
    会改变方法虚拟存在 / 方法结构中的条件结果对集合；
    需要明确动作来源。

提交方法状态变化：
    会改变方法状态；
    需要明确动作来源。
```

## 4. 需要决策的问题

### 问题 1：真实入口来源从哪里来

可选方向：

```text
A. 只允许绑定已存在本能方法入口。
   前提：学习过程必须能确定目标方法应绑定哪个具体本能方法 ID。

B. 实现动作序列主键执行器。
   前提：定义动作序列节点、执行规则、参数绑定和失败回执。

C. 实现外部实现主键执行器。
   前提：定义外部实现注册、权限、调用边界和安全门控。

D. 当前阶段不闭合执行入口。
   入口缺失转入因果信息获取自我动作组合；若仍无法获得动作组合，则等待实现或外部补充。
```

当前代码最接近 D。2026-05-16 已进一步确认：

```text
在当前内部方法补齐场景中，若方法动作 / 可执行入口缺口仍被导向
自我_定向学习，唯一合理说明是尚未找到能让目标状态 A -> B 的自我动作组合，
或该组合 / 方法尚未声明能够命中这些结果特征。
```

因此下一步不是强行禁止 `自我_定向学习`，而是用因果信息获取自我动作组合。`自我_定向学习`
仍可服务外界信息链、未知动作语义线索和因果补动作场景；但它不能替代内部方法域提交本能方法。

### 问题 2：哪些逻辑需要方法域提交动作

已确认动作不是普通学习产物：

```text
所有当前可执行动作都是本能函数。
```

因此不应生成“缺动作”需求。当前需要区分：

```text
1. 因果信息获取自我动作组合：
   根据条件状态 A、目标结果 B 反推能导致 A -> B 的一组自我动作。
   这是只读中间计算，可以先用普通逻辑代码实现。

2. 提交方法可执行入口：
   当动作组合退化为单个本能方法时，把该本能函数绑定为目标方法的真实动作句柄。
   这是方法域状态提交，需要明确动作来源。

3. 动作序列入口：
   当动作组合包含多个本能动作时，必须记录为动作序列候选，等待动作序列执行器 /
   入口规则，不能伪装成单一本能函数入口。
   若只是候选计算，不需要本能方法；若写入动作序列主键、方法入口或正式需求，则需要提交动作。
```

职责：

```text
读取目标方法。
读取因果反推得到的动作组合。
校验动作组合合法。
若因果反推得到单个本能方法 ID：写入真实动作句柄。
若因果反推得到多个动作：
    若只返回候选，保持中间结果；
    若要写入方法或动作序列入口，必须走对应提交动作。
若不能反推动作组合：返回缺少动作组合 / 等待外部补充。
发生持久写入时生成方法域动作动态。
```

`提交方法可执行入口` 只能在单个本能方法 ID 已明确时提交，不能自己猜本能 ID，
也不能把多步动作组合压扁成单一入口。

## 5. 推荐第一步

先把缺口表达得更准确，并把缺方法动作转入因果获取自我动作组合流程：

```text
方法可执行入口缺失
    -> 若无明确动作组合：
        进入因果信息获取自我动作组合流程。
    -> 若因果信息反推出单个明确本能方法 ID：
        调用“提交方法可执行入口”提交真实动作句柄。
    -> 若因果信息反推出多步动作组合：
        记录动作序列候选，等待动作序列入口规则。
```

这样能够避免：

```text
定向学习补出方法动作状态后，
系统误以为已经具备可执行入口。
```

## 5.1 因果转方法口径下的入口规则

按因果学习最新口径，因果信息转化为自我方法的关键是：

```text
自我能否制造因果模板的触发条件。
```

因此占位方法不能因为“有方法动作语义”就直接进入可执行入口闭合。

必须先确认：

```text
1. 目标方法代表的动作 A 已确定。
2. 该动作 A 能由当前自我通过本能方法执行、诱发或请求。
3. 执行后的结果 R 可被输出结果场景或动作动态验收。
```

如果上述条件不成立，当前任务应停在：

```text
等待自我动作组合补全 / 动作序列入口规则 / 外部实现补充
```

而不是继续派生条件结果对。

最短口径：

```text
能造因，能控动，验得果，才成法。
```

套到本阻塞点：

```text
占位方法 = 尚未证明能控动；
定向学习 = 只能补动作语义痕迹；
提交方法可执行入口 = 只能在单个本能方法 ID 已确定后执行；
动作序列入口 = 多个本能动作组合的未来执行入口；
条件结果对学习 = 必须等待真实动作句柄存在后再进入。
```

### P4. 实现“提交方法可执行入口”

第一版可以先实现严格门控壳，不伪造入口。
该壳只在发生真实方法入口写入时需要作为方法域提交动作；
若没有明确单步本能 ID，只返回缺口回执，不做持久写入。

`提交方法可执行入口` 应：

```text
读取目标方法。
读取明确本能方法 ID。
校验本能方法存在且不是先天写入逻辑、不是任务筹办 / 任务执行生命周期函数。
写入动作句柄。
同步方法虚拟存在。
生成方法域动作动态。
```

若输入中没有明确本能方法 ID，或输入是多步动作组合，只能返回缺口回执：

```text
缺口 = 缺少可直接绑定的单步入口；若存在多步动作组合，则等待动作序列入口规则
建议 = 进入因果信息获取自我动作组合流程，或等待动作序列入口规则 / 外部实现补充
```

```text
新增枚举：
    自我_提交方法可执行入口 = 6081

新增默认本能方法注册：
    提交方法可执行入口

新增动作执行注册：
    自我_提交方法可执行入口 -> 提交方法可执行入口(...)

新增规格：
    输入：
        目标方法头节点
        选中自我能力值
        当前方法运行存在（可选）

    输出 / 回执：
        方法动作状态
        选中自我能力值
        目标方法头节点
        动作动态
        失败原因
```

实现边界：

```text
1. 只有输入中存在明确单步本能方法 ID 时才会写目标方法动作句柄。
2. 明确拒绝：
       自我_改变特征值
       历史任务筹办 / 任务执行生命周期入口编号 6062 / 6063
       非默认自我本能方法 ID
       与目标方法既有动作句柄冲突的入口
3. 成功时写入：
       目标方法.动作句柄 = 本能函数ID
       目标方法.方法动作状态 = 1
       输出结果场景中的 方法动作状态 实际结果状态
4. 成功时生成方法域动作动态，动作来源为：
       自我_提交方法可执行入口
5. 该方法不把目标方法状态直接设为可用；
   方法可用仍需条件结果对和提交方法状态变化链路。
6. 输入缺明确本能方法 ID 时只返回失败 / 缺口回执，不做持久写入。
```

```powershell
.\x64\Debug\鱼巢.exe --learning-demand-execution-entry-check

```

结果：

```text
两条明确缺执行入口回归均通过。
当前通过含义仍是反向验收：
```
