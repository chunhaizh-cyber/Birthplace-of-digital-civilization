# 20260605 任务筹办 OR 路径闭合与学习拦截实现计划 v0.1

## 0. 背景

本计划来自对以下材料的对账：

```text
流程图/20260605_任务筹办普通函数流程图_v0.1.md
任务模块.筹办.ixx
任务模块.工作线程消息协议.ixx
任务模块.管理工作线程.ixx
自我线程模块.impl.cpp
需求类.h
需求类.cpp
规范/任务筹办与执行边界规范20260512.md
规范/任务筹办按方法能力查找到就绪因果链规范20260513.md
规范/需求临时因果视图展开规范20260526.md
```

结论：

```text
流程图中的“下一步可选步骤 -> OR 子需求 -> 多轮分解 -> 无法闭合学习拦截 -> 路径选择”是正确的目标方向。
当前代码已经具备因果路径项、派生需求消息、逻辑组织目标语义和普通派生需求入树底座。
但缺少候选路径组生命周期，不能把所有可选步骤稳定落成 OR 路径组，也不能判断单条路径是否闭合或无法闭合。
```

## 1. 硬边界

```text
1. 不把任务筹办 / 任务执行恢复为本能方法。
2. 任务筹办仍只产出回执、派生需求消息或更新指令输入草案，不直接写需求树。
3. 非正常逻辑错误必须弹窗 / 报错并记录日志，不进入业务缺口分支。
4. 真实业务缺口才允许生成派生需求、子需求或学习需求。
5. 不新增需求主信息中的 OR / 路径选择 / 令牌专用字段；优先使用目标特征类型、获取途径、子需求结构、提交入口和动作动态证据。
6. 只在已有自然运行链路中验证，不新增模拟测试、伪造样本、伪造入口或 `--*-check` 回归入口。
7. OR 组选择和 OR 结算令牌不得进入普通候选方法集。
```

## 2. 缺口清单

### G1 派生需求消息缺少获取途径

当前：

```text
结构_任务管理派生需求消息：
    有 派生需求类型
    有 因果路径生成类型
    无 需求获取途径 / 逻辑组织获取途径
```

影响：

```text
任务筹办可以说明“这是促成 / 避免 / 条件补齐”等路径项，
但不能说明“这些候选步骤应该先由 多候选替代路径组生成 承接为 OR 组”。
```

### G2 自我线程派生需求入树直接挂父需求

当前：

```text
自我线程收到派生需求消息后，`私有_确保派生需求节点` 直接在父需求下新增 / 复用普通直接子需求。
```

影响：

```text
多条可选路径会变成父需求下的一组普通阻塞子需求，语义更接近 AND。
流程图要求的“全部可选步骤生成 OR 类子需求草案”没有形成稳定承接层。
```

### G3 OR 组聚合仍缺路径选择闸门

当前：

```text
任务筹办的逻辑组织聚合视图主要统计直接子需求数量、已满足数量、未满足数量。
```

影响：

```text
OR 组不能表达“某一路径闭合即可进入选择 / 领取结算令牌”；
也不能表达“其他路径完成只能记录冗余证据，不重复结算”。
```

### G4 单条路径没有闭合状态

当前：

```text
路径项只作为临时因果视图项或派生需求消息存在。
正式入树后没有路径状态视图：未展开 / 展开中 / 已闭合 / 无法闭合 / 已学习拦截。
```

影响：

```text
任务筹办无法判断“所有可继续路径是否都已闭合”；
也无法判断“哪些路径无法闭合，需要被学习任务拦截”。
```

### G5 无法闭合路径未被学习任务统一拦截

当前：

```text
学习缺口主要在临时视图无路径且对象明确时生成。
```

影响：

```text
已经展开过、但因为缺方法入口、缺条件结果对、缺证据、长期无进展等原因无法闭合的路径，
还没有统一进入学习任务拦截口。
```

### G6 路径选择收益和可执行性未落代码

当前：

```text
收益 / 可执行性只在流程图和计划口径中出现；
代码中尚无路径候选评分视图或路径选择回执。
```

影响：

```text
父任务无法在多条闭合路径之间做稳定选择。
```

### G7 目标不可解析缺少统一来源分类

当前：

```text
缺来源需求、缺目标宿主、缺目标特征、缺当前状态、缺目标状态等场景已有日志和返回，
但没有统一先分成“逻辑错误”和“真实需求缺口”。
```

影响：

```text
逻辑错误和真实业务缺口可能在日志语义上混在一起；
后续不利于压力来源、弹窗提醒和学习需求边界判定。
```


### P4 路径闭合状态视图

状态：待执行。

允许修改：

```text
任务模块.筹办.ixx
自我线程模块.impl.cpp
```

动作：

```text
1. 在任务筹办只读侧构造路径闭合视图。
2. 单条路径闭合标准：
   - 当前节点是可执行叶子且已就绪，或
   - 该路径下所有子需求都已满足 / 已闭合。
3. 路径展开中则返回等待子需求继续分解。
4. 不通过只读视图创建任何结构。
```

验收：

```text
日志能列出路径总数、已闭合、展开中、无法闭合。
存在展开中路径时不进入路径选择。
```

### P5 无法闭合路径学习拦截

状态：待执行。

允许修改：

```text
任务模块.筹办.ixx
自我线程模块.impl.cpp
```

动作：

```text
1. 明确无法闭合判据：缺方法入口、缺条件结果对、缺证据来源、长期重复等待、明确无候选方法等。
2. 逻辑错误不进入学习任务。
3. 真实无法闭合路径生成学习任务草案，学习对象必须明确到方法结构、条件结果对、证据来源或路径解释缺口。
4. 学习完成后唤醒父任务重筹办。
```

验收：

```text
无法闭合路径不会直接进入路径选择。
日志出现 学习任务拦截=1，且能追溯被拦截路径。
```

### P6 路径选择与 OR 结算令牌

状态：待执行。

允许修改：

```text
任务模块.筹办.ixx
自我线程模块.impl.cpp
自我动作实现模块.ixx
```

动作：

```text
1. 只在所有可继续路径闭合或被学习任务拦截后进入路径选择。
2. 收益评价优先读取安全 / 服务权重、贡献层级、稳定度和路径副作用。
3. 可执行性评价读取路径闭合状态、当前方法状态、入口、条件结果对和参数闭合结果。
4. 选中路径通过专用提交链领取 OR组结算令牌。
5. `提交_领取OR组结算令牌` 仍不得成为普通候选方法。
```

验收：

```text

重复路径完成不重复结算。
路径选择日志包含 收益 / 可执行性 / 选中路径。
```
