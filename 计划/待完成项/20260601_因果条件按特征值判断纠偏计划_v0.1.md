# 因果条件按特征值判断纠偏计划 v0.1

## 1. 纠偏目标

本计划纠偏“因果 4：因果条件是否成立，取决于特征值”在规范、需求树和代码中的表达方式。

因果关系不能只看特征类型是否出现，也不能只看状态名是否为“已明确”。因果条件必须落实到可比较的当前特征值、历史特征值、时间窗口和证据值。

示例模板：

```text
某存在曾造成自我安全值下降
+ 当前仍在场景中
+ 无伤害时间不足
-> 该存在仍有非零风险安全值
```

真正需要判断的是：

```text
该存在是否在场景中 = ?
最近伤害时间 = ?
无伤害共处时长 = ?
当前是否有负向变化 = ?
归因置信度 = ?
当前时间窗口是否仍有效 = ?
```

因此目标链路为：

```text
特征值未知
-> 因果条件无法判断
-> 风险安全值无法评估
-> 自我安全值中的相关部分无法明确
```

## 2. 规范核对结论

### 2.1 底层比较规范

`004 特征值三态比较底层逻辑规范` 已明确：

```text
系统基础逻辑来自两个已确认可比特征值的比较。
比较前必须确保值域、度量签名、比较字段和转换域一致。
不可比较不是第四种比较结果。
前置条件不满足时，应在比较前阻断，并形成错误、回执、派生需求、等待条件或学习候选。
```

这意味着：

```text
只有特征类型，没有特征值，不能判断因果条件成立。
只有特征名相同，没有当前值 / 目标值 / 比较符，不能完成因果条件命中。
```

### 2.2 需求和临时因果视图规范

需求目标必须具备：

```text
目标宿主
目标特征类型
当前值 / 当前状态
目标比较符
目标值 / 目标状态
```

因果条件未知时，应生成条件补齐路径，例如：

```text
因果条件：双目相机.运行状态 = 正常
当前状态：双目相机.运行状态 = 未知
条件补齐子需求：双目相机.运行状态 等于 正常
```

因此条件补齐不是“缺一个特征类型”，而是：

```text
缺某个宿主上的某个特征当前值；
或当前值与目标值不可比较；
或比较后未命中因果条件。
```

### 2.3 安全场景影响规范

`050003 基础观察事实可用与基础风险判断分层规范` 已明确：

```text
存在风险安全值依赖该存在当前特征值、历史动态、自我关键特征变化观察、因果归因证据和无负向证据搜索结果。
当前场景中相关特征值未知时，场景影响因果条件不可判断。
因果条件不可判断时，场景影响部分不能入账，风险安全层不能聚合，自我安全值不能合法结算。
```

并且：

```text
没查过 != 默认满足
查过且无负向证据 = 可以经提交入口默认满足
特征值未知 = 证据搜索未完成或搜索前置材料缺口
```

### 3.2 主要缺口

当前实现仍存在明显偏差：

```text
1. 评估存在风险安全值 没有读取真实条件值。
   历史值固定为 0；
   历史直接伤害次数没有从存在 / 因果证据读取；
   最近直接伤害时间没有读取；
   无伤害共处时长没有计算；
   归因置信度没有参与条件命中。

2. 自我_读取自我关键特征变化 只写观察状态和样本数量，
   关键特征负向变化数量固定为 0。
   它没有比较关键特征前值、后值、变化方向和证据时间窗。

3. 安全_构造场景影响因果候选 只依赖：
   - 目标宿主存在
   - 当前场景存在集合非空
   - 关键特征变化观察状态已明确
   然后按存在数量生成低置信候选，归因置信度固定为 0。
   这还不是因果条件按特征值命中。

4. 安全_评估当前场景安全性 中，关键特征变化未知或因果候选未知时，
   没有稳定地形成“因果条件不可判断”的材料缺口；
   部分路径会把风险候选置为 0、评估明确置为 true。

5. 任务筹办侧 吸收因果条件缺口_筹办查询 只遍历条件比较模板并生成通用条件补齐项，
   没有把每个条件目标化为：
   目标宿主 + 条件特征类型 + 当前值 + 目标比较符 + 目标值。

6. 自我线程风险树当前生成的场景影响前置缺口仍偏状态枚举：
   - 关键特征变化观察状态
   - 安全因果候选构造状态
   - 持续观察需求明确状态
   - 持续观察状态
   但还没有展开到具体条件值：
   在场状态、最近伤害时间、无伤害共处时长、当前负向变化、归因置信度等。
```

## 4. 目标模型

### 4.1 因果条件值视图

为安全场景影响链建立只读“因果条件值视图”。

最小字段：

```text
候选存在
条件模板ID
条件宿主
条件特征类型
当前值读取状态
当前值
目标比较符
目标值 / 阈值
比较前置状态
比较结果符号
条件命中状态
材料缺失原因
冲突原因
证据来源动态
时间窗口
```

该视图只读事实和条件，不直接写安全值。

### 4.2 存在风险条件组

针对示例模板，第一版条件组可以表达为：

```text
条件 C1：该存在当前在场景中 等于 是
条件 C2：历史直接伤害归因次数 大于 0
条件 C3：最近直接伤害归因时间 大于 0
条件 C4：当前时间 - 最近直接伤害归因时间 小于 最大无伤害证明窗口
条件 C5：无伤害共处时长 小于 安全衰减阈值
条件 C6：当前关键特征负向变化数量 大于 0，或负向变化证据存在
条件 C7：归因置信度 大于 最低归因置信度
```

注意：

```text
这些条件不要求一次性全部实现成固定安全规则。
第一阶段只要求能把条件值读出来、比较出来、缺口说清楚。
```

### 4.3 未知处理

统一处理口径：

```text
当前值未知：
    条件不可判断；
    生成材料缺口或证据搜索前置缺口；
    不写风险值为 0；
    不写默认满足；
    不结算安全值。

当前值可读但不命中：
    条件不成立；
    若搜索完整且无负向证据，可进入默认满足提交路径。

当前值可读且命中：
    生成风险安全值候选；
    仍需归因证据和提交入口，不能直接写自我安全值。
```

## 5. 纠偏原则

```text
1. 不把特征类型存在当作条件成立。
2. 不把状态名已明确当作具体值已命中。
3. 不把未知值解释为安全或危险。
4. 不把候选数量解释为归因置信度。
5. 不把归因置信度、稳定度、时间窗口写入因果主信息常驻字段；它们只能作为查询 / 评估解释值或结果视图。
6. 不把评估型派生结果写成存在本体常驻原始事实。
7. 不直接结算自我安全值。
```

### P3 改造 `评估存在风险安全值`

目标：

```text
让存在风险安全值候选由条件值命中结果决定。
```

第一阶段规则：

```text
1. 在场状态未知 -> 评估不明确。
2. 历史直接伤害次数未知 -> 评估不明确。
3. 历史直接伤害次数 = 0 且已完成负向证据搜索 -> 可生成无负向候选。
4. 历史直接伤害次数 > 0 且最近伤害时间可读 -> 进入无伤害时间条件判断。
5. 无伤害共处时长不足 -> 存在风险安全值候选至少非零。

7. 关键特征当前负向变化未知 -> 评估不明确。
```

禁止：

```text
把历史值固定为 0 后直接当作无风险。
把关键特征变化未知当作评估明确。
```


## 7. 与前三条因果纠偏计划的关系

```text
因果 1：
    自我关键特征负向变化 -> 自我安全值下降候选。

因果 2：
    当前场景变化 -> 可能影响自我关键特征。

因果 3：
    当前场景影响由存在的特征值、历史动态、因果证据和时间窗口决定，
    不是由存在名决定。

因果 4：
    每个因果条件是否成立，必须读取并比较具体特征值。
    特征值未知时，因果条件不可判断。
```

合并后的链路：

```text
当前场景已确认存在
-> 读取该存在当前特征值 / 历史动态 / 证据值
-> 比较条件值
-> 判断因果条件成立 / 不成立 / 不可判断
-> 构造存在风险安全值候选或材料缺口
-> 聚合当前场景风险安全值候选
-> 影响风险安全_场景影响部分明确状态
-> 影响风险安全层明确状态
-> 影响自我安全值相关部分是否可明确
```
