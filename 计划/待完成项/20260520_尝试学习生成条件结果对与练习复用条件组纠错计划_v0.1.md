## 一、问题定位

当前日志中的主要现象是：

```text
动作执行失败
缺条件结果对
缺失参数数量
```

尾部倒查后，问题不是“练习函数没跑”，而是学习链路职责错位：

```text
自我_尝试学习：
    当前主要输出“目标方法缺条件结果对”的派生需求提示；
    没有优先根据目标方法头节点中的条件 / 形参值域生成可复用条件组；
    因此没有稳定产出条件结果对样本。

自我_练习：
    当前主要根据目标方法形参表临时生成候选实参；
    没有优先复用自我_尝试学习已经生成的条件组 / 条件结果对；
    因此会继续出现缺失参数数量。
```

## 二、权威口径

```text
1. 自检目标统一是：方法状态 = 好用。
2. 方法状态收束为：
       结构完整
       有真实动作入口
       有条件结果对
       可用
       好用
3. 可用条件第一版：
       条件结果对数量 > 0
4. 好用条件第一版：
       最近连续成功次数 > 3
5. 好用的长期完整标准：
       方法头节点特征类型有值域；
       条件节点值域覆盖方法头值域；
       条件结果对能稳定运行。
   当前先不实现完整覆盖判定。
```

## 三、纠错目标

```text
自我_尝试学习：
    根据目标方法头节点 / 形参表 / 条件值域生成若干条件组；
    将条件组与结果场景归并成目标方法的条件结果对；
    更新目标方法虚拟存在：
        方法条件结果配对状态 = 1
        方法状态 = 可用

自我_练习：
    优先读取目标方法已有条件结果对；
    从条件节点 / 条件场景生成具体参数；
    执行目标方法；
    更新目标方法虚拟存在运行账：
        运行次数
        成功次数
        最近连续成功次数
    若最近连续成功次数 > 3：
        方法状态 = 好用
    否则输出结构化差距：
        当前方法状态 = 可用
        目标方法状态 = 好用
        当前连续成功数 = N
        目标连续成功数 > 3
```

## 四、边界约束

```text
1. 不新增动态业务语义枚举。
2. 不新增“方法可执行入口数量”等平行事实字段。
3. 不把 自我_定向学习 当作真实方法入口闭合路径。
4. 不绑定 自我_改变特征值。
5. 不伪造条件结果对；条件结果对必须来自条件场景 + 结果场景。
6. 不在自检线程抑制重复提交；重复需求由自我线程入树去重和任务创建去重处理。
7. 同一父需求下，同一目标宿主 + 目标特征 + 目标状态，只能形成一个需求节点。
8. 同一方法同一学习目标，同时只能有一个活动学习任务。
```

## 五、实施分步

### P1：计划与索引同步

```text
新增本计划；
将计划索引当前执行项指向本计划；
保留 C4 学习需求计划为上级背景，不继续硬推自然条件结果对闭合。
```

### P2：梳理目标方法条件 / 结果来源

```text
确认方法头节点的形参表 / 条件值域如何表达；
确认条件节点如何存储条件场景；
确认结果节点如何存储结果场景；
确认方法真实条件结果对数量如何统计；
确认方法虚拟存在中特征值如何更新。
```

### P3：修正自我_尝试学习

```text
1. 优先从目标方法头节点条件 / 形参值域生成条件场景。
2. 从目标方法结果能力 / 任务目标生成结果场景。
3. 调用现有条件结果对归并逻辑，生成：
       方法条件节点
       方法结果节点
4. 成功生成条件结果对后：
       写入 方法条件结果配对状态 = 1
       写入 方法状态 = 可用
5. 若无法生成条件场景或结果场景：
       输出结构化缺口；
       不只输出“缺条件结果对”笼统提示。
```

### P4：修正自我_练习

```text
1. 优先读取目标方法已有条件结果对。
2. 从条件节点 / 条件场景生成具体实参。
3. 只有没有可用条件组时，才回退到形参表候选生成。
4. 每次执行后更新目标方法运行账。
5. 根据方法虚拟存在中的连续成功次数判断是否好用。
6. 未好用时输出结构化差距，而不是普通动作失败。
```

### P5：修正任务工作回执映射

```text
练习输出“方法状态=可用 -> 好用”或“最近连续成功次数 N -> 4”时，
任务工作线程应识别为方法练习差距，
不应退化成泛化的“动作执行失败”。
```

```text

该回归验证：
    派生需求特征 = 方法状态
        -> 推进状况 = 方法结果不稳定

    派生需求特征 = 方法最近连续成功次数
        -> 推进状况 = 方法结果不稳定

断言：
    练习输出 方法状态=可用->好用 或 最近连续成功次数N->4 时，
    工作线程应识别为方法结果不稳定；
    不得退化成泛化动作执行失败。
```

## 六、验收标准

```text
1. 自我_尝试学习不再只生成“缺条件结果对”提示；
   在目标方法有条件 / 值域来源时，能够生成条件结果对。

2. 自我_练习不再优先裸生成临时参数；
   在目标方法已有条件结果对时，优先复用条件节点。

3. 方法虚拟存在运行账被目标方法执行路径更新：
       运行次数
       成功次数
       最近连续成功次数

4. 最近连续成功次数 > 3 时，方法状态推进为好用。

5. 未达到好用时，输出结构化差距：
       当前方法状态
       目标方法状态
       当前连续成功数
       目标连续成功数

6. 不新增主信息字段，不新增业务语义枚举。
```
