## 2. 背景口径

本轮口径：

1. 任务处于执行中时，允许方法持续产出阶段性结果。
2. 阶段性结果可以入账为输出结果场景、方法动作动态、观察事实或任务回执材料。
3. 阶段性结果不等于任务完成，不触发 `已结算`。
4. `已结算` 仍只表示任务完成后的价值结算后处理。
5. 不新增任务状态，不复用 `待重筹办` 作为正常批次推进中转状态。
6. 不给方法声明增加“执行形态”。界面线程和工作线程按消息 / 回执 / 输出结果分类处理。

```text
6145 自我_识别外设观察材料
6146 自我_扫描已识别区域
6147 自我_跟踪指定存在
```

### 4.3 6127 当前情况

`自我_验证外设观察像素簇候选` 当前会：

1. 读取 D455 逐簇识别报告。
2. 校验原始帧、深度帧、空间候选队列、像素归属账本和逐簇材料句柄。
3. 写入报告 ID、候选簇数量、通过簇数量、失败簇数量、证据不足簇数量、缺失材料原因。
4. 写入 `外设像素簇候选验证状态`、`外设观察像素簇候选已验证状态`、`外设观察材料可回查状态` 等实际结果状态。

主要缺口：

1. 聚合验证状态只有全量通过才算成功，部分簇通过时容易只表现为 `证据不足`，任务管理未必能识别为本轮有推进。
2. 通过簇数量、材料明确状态、稳定复现 / 观察完成 / 可复验状态虽然写入摘要，但需要确认是否都能作为来源需求目标特征的可比较实际状态。
3. 条件不足时派生需求可以保留，但不能让阶段性可用材料被归为任务失败或完成。

### 4.4 6145 当前情况

主要缺口：

## 5. 根本问题

当前逻辑不是完全缺少阶段性结果能力，而是有两层断裂：

1. 相机方法层：部分方法没有把领域结果统一落成任务管理可读取的实际结果状态。
2. 任务管理层：持续执行判断仍依赖相机 / 观察方法 ID 白名单，而不是通用执行回执。

因此修订方向不是增加新任务状态，也不是新增方法声明执行形态，而是：

```text
相机方法持续产出可比较实际结果状态
-> 任务执行普通函数形成通用执行回执
-> 有推进未达成保持执行中
-> 界面线程按消息分类提交部分结果
-> 完成后再进入结算
```

## 6. 修订目标

### 6.1 四方法统一输出协议

四个相机方法运行后，至少应满足：

1. `方法运行存在` 写入方法执行情况、动作动态、失败原因或缺口原因。
2. `输出结果场景` 写入本轮真实产出的领域事实。
3. 对能命中任务目标特征的结果，必须写入可比较的实际结果状态指针。
4. 对阶段性推进，写入本轮实际状态，但不写任务状态、不写需求满足最终事实、不触发已结算。
5. 对无材料 / 条件不足，输出明确缺口或等待原因，不伪装为完成。

### 6.2 任务管理统一判断

任务管理状态推导改为只看通用回执：

```text
阶段 = 执行
状况 = 目标结果不符合
本轮是否有推进 = true
执行结果类型 = 有推进未达成
```

满足以上条件时，任务保持 `执行中`。

不再要求当前方法属于相机 / 观察白名单。

### 6.3 界面线程消息分类

界面线程收到执行结果后按结果类型分类：

```text
目标已达成 -> 允许进入完成提交
有推进未达成 -> 提交部分结果 / 保持执行中 / 可继续派发执行
无推进未达成 -> 等待、待重筹办或缺口处理
退步 -> 缺口 / 风险 / 重筹办处理
动作失败 -> 失败或等待缺口处理
```

不新增“方法声明执行形态”。

```text
真实日志中可区分目标上下文缺口、材料质量缺口和目标未达成。
```

### P5 任务管理持续执行通用化

目标：移除持续执行对相机 / 观察方法 ID 的依赖。

工作：

1. 将 `私有_任务推进回执是持续观察批次推进` 改为通用判断。
2. 删除或停用 `私有_方法是持续观察批次方法` 在状态推导中的作用。
3. 状态推导规则：

```text
执行阶段 + 目标结果不符合 + 本轮有推进 + 有推进未达成 -> 执行中
执行阶段 + 目标结果不符合 + 无推进未达成 -> 待重筹办 / 等待中
目标结果符合 -> 完成
完成后才允许价值结算后处理
```

4. 保持任务状态提交仍走 `提交任务状态变化`。
5. 保持 `目标是否达成 / 本轮是否有推进 / 本轮推进量 / 剩余差距 / 执行结果类型` 写入任务虚拟存在。

验收：

```text
任务管理工作线程不再按 6127 / 6145 / 6146 / 6147 判断是否保持执行中；
任意方法只要回执满足有推进未达成，都能保持执行中；
无推进未达成不会假装持续执行。
```

4. 不把任务筹办 / 任务执行恢复成本能方法。

## 10. 当前结论

复用 `待重筹办` 不适合作为持续观察每批结果后的常规状态。

更合理的通用逻辑是：

```text
方法持续产出部分结果
-> 任务管理评价为有推进未达成
-> 任务保持执行中
-> 界面线程继续派发执行 / 承接外设材料
-> 满足目标后进入完成
-> 完成后再进入已结算
```

四个相机本能方法必须纳入这套通用协议，但任务管理不能再为这四个方法设计专用执行回路。
