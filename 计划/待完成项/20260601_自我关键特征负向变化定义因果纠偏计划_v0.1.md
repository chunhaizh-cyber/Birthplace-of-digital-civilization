```text
自我安全值目标
<- 风险安全层明确状态
```

```text
自我关键特征负向变化
-> 自我安全值下降候选

自我运行状态负向变化
-> 自我安全值下降候选

自我资源状态负向变化
-> 自我安全值下降候选

自我物理安全下降
-> 自我安全值下降候选

自我风险安全下降
-> 自我安全值下降候选
```

该组模板只表达定义因果方向，不直接生成当前主动需求、任务、方法头或安全值结算。

## 3. 当前代码现状

已有能力：

```text
1. 自我安全值、物理安全、风险安全已经是自我实例特征。
2. `安全值_下降_` 具备直接写入安全值的底层函数。
3. `私有_确保遗传因果模板_线程侧` 已能创建来源类型为“遗传”的因果模板。
4. 安全因果风险树已能确保 `自我安全值目标 <- 风险安全层明确状态` 的遗传因果来源。
5. 旧固定安全字段已被识别并清理 / 忽略，不再作为固定安全根必要条件裸生成子需求。
```

主要缺口：

```text
1. 没有明确生成 `自我关键特征负向变化 -> 自我安全值下降候选` 的遗传因果模板。
2. `自我关键特征集合` 不是一等定义，运行 / 资源 / 边界 / 物理安全 / 风险安全之间缺统一投影口径。
3. `自我边界` 还没有明确承载；目前只有权限边界、像素簇边界、轮廓边界等相邻概念。
4. 运行状态、资源状态、权限边界等旧字段只被当作旧固定安全条件清理，没有迁移为“关键特征负向变化的事实来源”。
5. `自我_读取自我关键特征变化` 当前固定写 `关键特征负向变化数量=0`，无法支撑定义因果模板。
6. 安全值底层下降函数存在，但不应被本纠偏切片直接调用；否则会绕过 060004 结算闸门。
```

## 4. 纠偏原则

```text
1. 定义因果只生成遗传因果模板，不直接写安全值。
2. 关键特征负向变化先产出候选、证据需求或评估输入，不直接结算。
3. 不恢复固定安全因素表。
4. 不把运行状态 / 资源状态 / 权限边界重新塞回安全根固定必要条件。
5. 不新增需求主信息字段表达 AND / OR / 因果子链。
6. 不把外设观察材料、控制面板摘要或只读诊断快照当成安全值结算证据。
7. 若需要新增结构，优先使用抽象特征、二次特征、状态比较、因果模板和动作动态，不新增主信息权威字段。
```

## 5. 目标模型

### 5.1 定义层

定义层只回答：

```text
哪些自我关键特征的负向变化，在原则上会削弱自我持续存在能力。
```

第一版关键特征集合：

```text
自我运行状态
自我资源状态
自我边界完整性
自我物理安全
自我风险安全
```

其中：

```text
自我运行状态 / 资源状态 / 边界完整性
```

若当前没有稳定实例特征承载，先作为抽象特征定义和因果模板适用范围，不直接硬造运行期固定需求。

### 5.2 事实层

事实层只回答：

```text
本轮有没有某个关键特征发生可回查的负向变化。
```

事实来源可以是：

```text
自我实例特征当前值 / 上一值
线程运行状态或健康状态变化
资源事实变化
外设观察到的边界接触 / 进入 / 破坏候选
物理安全值变化
风险安全候选或风险安全层候选变化
动作动态、状态节点、二次特征比较
```

事实层不得直接写：

```text
自我安全值下降
风险明确
安全根需求已满足
```

### 5.3 候选层

候选层把事实投影为：

```text
自我安全值下降候选
```

候选必须携带：

```text
来源关键特征
负向变化比较
来源状态 / 动态
来源因果模板
证据完整度
是否可进入结算评估
```

### 5.4 结算层

结算层仍按 060004 执行：

```text
候选
-> 父链归因
-> 世界树因果证据
-> 实际改变结果状态
-> 完成度 / 权重 / 副作用
-> 安全值账务变化
```

本计划不直接实现账务结算。

### P1 关键特征集合一等化口径

目标：

```text
确定第一版自我关键特征集合的表达方式。
```

优先级：

```text
1. 已有自我实例特征：物理安全、风险安全。
2. 已有线程 / 运行事实：实际运行状态、健康状态、阻塞状态。
3. 已有抽象状态词：自我运行状态明确 / 正常、资源状态明确 / 足够、权限边界明确。
4. 尚缺但定义必需：自我边界完整性。
```

边界：

```text
关键特征集合不是固定安全因素表。
关键特征集合只用于定义因果模板和事实投影。
运行期是否生成需求，仍由当前事实挂载和闭环缺口判断决定。
```

验收：

```text
形成 `关键特征类型 -> 负向变化比较 -> 安全值下降候选` 映射表。
```

### P2 自我边界承载方案

目标：

```text
补齐“自我边界完整性负向变化”的最小可表达参照。
```

第一版不得做复杂空间模型，只需能表达：

```text
自我边界参照存在
自我_场景绝对坐标 / 自我_场景绝对姿态
自我相对视图坐标系
边界完整性状态
外部观察对象是否进入 / 接触 / 破坏边界候选
```

可选实现方向：

```text
抽象特征：自我边界完整性
实例特征：自我_边界完整性状态
一阶特征：存在_场景绝对坐标 / 存在_场景绝对空间范围
派生视图：自我视图_存在相对坐标 / 相对距离 / 边界关系
二次特征：自我视图中外部对象空间范围 与 自我边界范围 的关系变化
因果模板：自我边界完整性下降 -> 自我安全值下降候选
```

坐标口径：

```text
场景用绝对坐标记世界，自我用相对视图看世界。
存在本体不以自我相对坐标作为主要存储事实；
自我相对坐标由存在场景绝对坐标、自我场景绝对坐标 / 姿态和自我边界定义计算得到。
```

禁止：

```text
把像素簇边界直接当自我边界。
把权限边界直接当物理边界。
把 D455 相机坐标、ROI、掩码、点集或深度切片直接当场景绝对坐标。
用一个“边界安全摘要”字段替代原始关系。
```

验收：

```text
能回答：自我边界由哪个特征 / 存在 / 状态节点承载。
不能回答时，必须先停在方案，不进入代码实现。
```

### P4 改造关键特征变化读取方法

目标：

```text
纠偏 `自我_读取自我关键特征变化`。
```

现状问题：

```text
目标宿主存在即成功；
观察状态固定已明确；
负向变化数量固定 0。
```

纠偏后：

```text
必须读取关键特征集合；
必须比较当前值与上一值 / 目标值 / 安全区间；
必须输出真实样本数量和负向变化数量；
缺少可比较事实时输出条件不足或派生缺口；
不得默认写已明确。
```

验收：

```text
缺少自我边界承载时，边界相关项不能判定已明确；
缺少可比较历史状态时，输出缺口而不是负向变化数量 0；
有真实负向变化样本时，负向变化数量大于 0；
不写基础风险明确，不结算安全值。
```
