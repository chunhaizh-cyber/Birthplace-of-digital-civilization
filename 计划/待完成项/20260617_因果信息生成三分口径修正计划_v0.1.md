# 因果信息生成三分口径修正计划 v0.1

更新时间：2026-06-17

## 0. 恢复摘要

```text
目标：
    修正当前代码中“按动态生成因果信息”的分类和字段落账口径。

核心口径：
    动态信息分三类：
        主动动态；
        被动动态；
        无动作动态。

    因果信息同步分三类：
        主动动作因果；
        被动动作因果；
        无动作状态变化因果。

    三类因果的共同点：
        都必须来源于动态信息；
        都必须使用二次特征给出的变化方向；
        都必须能追溯证据动态样本。

    三类因果的区别：
        有没有动作；
        动作是主动动作还是被动动作。

因果主信息字段口径：
    条件比较模板：
        存储条件特征信息。
    因方法模板：
        存储动作信息。主动动作和被动动作都必须通过该字段或可解析方法引用表达。
        无动作状态变化因果不得伪造因方法模板。
    果比较模板：
        存储结果特征信息。
    主果比较模板：
        存储结果特征的初始状态与结果状态比较信息，即二次特征方向。
    证据动态样本：
        存储生成该因果信息的动态证据引用。

数据库要求：
    因果信息生成时必须落入数据库投影 / 关系表。
    SQL 关系至少能看到：
        条件比较模板；
        因方法模板；
        果比较模板；
        主果比较模板；
        证据动态样本。

当前风险：
    工作区中 `基础信息主信息类.h` 已有未提交改动：
        `果比较模板` 被改名为 `结果比较模板`，且类型由二次特征引用改为特征引用。
    若采纳本计划，应先统一字段名和语义：
        不保留 `果比较模板` / `结果比较模板` 双字段兼容；
        按本计划保留一个正式字段，并同步所有引用、SQL 投影和控制面板读取。

禁止宣称：
    不宣称当前因果生成已经符合三分口径。
    不把二次特征当成因果信息本体。
    不把外部传入的动作主体 / 动作语义当作动态自身动作来源。
```

## 1. 当前代码问题

```text
1. 因果生成入口已经是动态：
       因果类::按动态补全两层因果
       因果类::按动态创建因果信息

2. 二次特征已经参与结果方向：
       因果生成会查找动态对应的状态迁移二次特征，
       并写入主果比较模板 / 果侧模板。

3. 但当前因果分类只有：
       状态变化关系；
       动作致变关系。

4. 当前 `有动作` 判定过宽：
       动作主体 || 动作语义 || 因动作语义键 ||
       dm->来源动作 || dm->来源动作名

   这会带来风险：
       普通无动作状态变化动态，只要调用方传入动作主体 / 动作语义，
       就可能被升格为动作致变因果。

5. 当前主动 / 被动动作没有在因果生成路径中形成稳定分流：
       动态层有 来源类型 / 业务语义类型；
       因果生成层没有据此区分主动动作因果和被动动作因果。
```

## 2. 修正原则

```text
1. 动态分类只能从动态主信息和可回解来源推导。
   外部调用参数只能补充显示语义，不得改变动态类别。

2. 因果生成必须先识别动态类别：
       主动动态；
       被动动态；
       无动作动态。

3. 无动作动态只能生成：
       无动作状态变化因果。
   不得生成动作致变因果。

4. 主动动态生成：
       主动动作因果。
   因方法模板必须指向主动方法。

5. 被动动态生成：
       被动动作因果。
   因方法模板必须指向被动提交 / 被动记账 / 被动治理动作对应的方法模板。
   如果当前被动动态只有动作名而没有方法模板，应先记录为被动动作方法模板缺口，
   不得伪造成主动方法。

6. 二次特征只提供方向：
       主果比较模板 = 结果特征的初始状态与结果状态比较信息。
   因果信息本体仍由因果主信息组织。

7. 果比较模板只保存结果特征信息。
   若当前代码把果比较模板当成二次特征集合使用，必须迁移到：
       果比较模板 = 结果特征；
       主果比较模板 = 主方向二次特征。

8. 不新增说明性摘要字段。
   如果需要三分类状态，优先用局部派生函数或查询投影从证据动态样本推导，
   不写入因果主信息主字段。
```

### P1 动态三分类推导

目标：

```text
在因果生成层新增局部推导函数，不写入因果主信息字段。
```

建议局部结构：

```text
enum class 枚举_动态因果生成类别 {
    无动作状态变化,
    主动动作致变,
    被动动作致变
};
```

推导规则：

```text
无动作状态变化：
    dm->来源动作无效；
    dm->来源动作名为空；
    dm->来源类型不是内部机制动作；
    业务语义类型为状态变化动态或未定义但存在初始/结果状态。

主动动作致变：
    dm->来源类型 == 方法调用；
    dm->来源动作有效；
    来源方法是普通主动可执行方法。

被动动作致变：
    dm->来源类型 == 内部机制动作；
    或业务语义类型 == 被动记账动态 / 治理过程动态；
    或来源方法属于被动提交、被动记账、任务状态提交、方法状态提交等被动动作入口。
```

验收：

```text
因果生成日志必须输出：
    动态因果生成类别=无动作状态变化 / 主动动作致变 / 被动动作致变

日志只作为验证证据，不作为机器判断字段。
```

### P2 重写 `按动态补全两层因果` 的动作判定

目标：

```text
删除“外部参数导致有动作”的判定。
```

修正点：

```text
当前风险代码：
    有动作 = 动作主体 || 动作语义 || !因动作语义键.empty()
        || dm->来源动作.有效() || dm->来源动作名 != nullptr;

修正后：
    类别 = 从动态主信息推导动态因果生成类别(dm);
    有动作 = 类别 == 主动动作致变 || 类别 == 被动动作致变;

外部参数：
    动作主体 / 动作语义 / 因动作语义键
    只能在有动作已经由动态自身成立后补充动作语义键；
    不能单独让无动作动态变成动作因果。
```

因果写入规则：

```text
无动作状态变化因果：
    条件比较模板：按动态初始状态 / 条件特征补齐；
    因方法模板：空；
    果比较模板：结果特征；
    主果比较模板：状态迁移二次特征；
    证据动态样本：当前动态。

主动动作因果：
    条件比较模板：按输入场景 / 初始状态 / 条件特征补齐；
    因方法模板：来源主动方法；
    果比较模板：结果特征；
    主果比较模板：状态迁移二次特征；
    证据动态样本：当前动态。

被动动作因果：
    条件比较模板：被动因特征；
    因方法模板：被动提交 / 被动记账 / 被动治理方法；
    果比较模板：被动果特征；
    主果比较模板：被动果状态迁移二次特征；
    证据动态样本：当前动态。
```

### P3 结果特征与主果方向拆分

目标：

```text
把“结果特征”和“结果变化方向”拆开。
```

实现要求：

```text
1. 从动态结果状态读取结果特征：
       dm->结果状态 -> 状态节点主信息.状态特征
   写入果比较模板。

2. 从动态对应状态迁移二次特征读取方向：
       二次特征.来源起始状态 / 来源结果状态
       二次特征.差值 / 离散语义 / 方向区间
   写入主果比较模板。

3. 如果结果状态存在但找不到状态迁移二次特征：
       只能创建证据实例或状态变化线索；
       不创建完整可复用因果模板。

4. 如果状态迁移二次特征存在但结果特征不可读：
       记录逻辑错误或阻断；
       不写空果比较模板。
```

### P4 更新调用方

范围：

```text
二次特征应用模块.ixx
自我类.cpp
自我动作实现.扫描.ixx
自我动作实现模块.ixx
其他直接调用 按动态创建因果信息 / 按动态补全两层因果 的位置
```

要求：

```text
1. `二次特征应用模块.ixx` 不再把动态主体 / 动态特征作为动作主体 / 动作语义传入。
   它只负责：
       动态生成二次特征；
       命中模板回写证据动态；
       请求因果类按动态自身生成因果。

2. 如果调用方确实拥有主动方法动作动态：
       必须先让动态主信息持有来源动作 / 来源动作名 / 来源输入输出场景；
       再调用因果生成。

3. 如果调用方只是普通状态变化动态：
       不传动作语义键强行升格。

4. 如果调用方是被动动态：
       必须保证动态主信息能回解被动动作方法模板；
       不能只靠显示文本。
```

### P5 数据库落库与控制面板投影

目标：

```text
因果信息生成后，数据库和控制面板能回查完整字段。
```

实现点：

```text
1. `世界树类.cpp` 的 SQL 引用投影保持并校正：
       条件比较模板；
       因方法模板；
       果比较模板；
       主果比较模板；
       证据动态样本。

2. 如果果比较模板字段类型调整为特征引用：
       SQL 投影仍使用字段名 `果比较模板`；
       引用类型可继续归入基础信息引用，但显示层应能区分特征 / 二次特征。

3. 控制面板因果页同步读取：
       因方法模板显示动作；
       果比较模板显示结果特征；
       主果比较模板显示结果方向；
       证据动态样本显示来源动态。

4. 不新增数据库旁路写入。
   因果信息必须从世界树 / 基础信息主信息投影统一落库。
```

```text

    因果节点存在；
    引用关系中存在 条件比较模板；
    引用关系中存在 因方法模板；
    引用关系中存在 果比较模板；
    引用关系中存在 主果比较模板；

```
