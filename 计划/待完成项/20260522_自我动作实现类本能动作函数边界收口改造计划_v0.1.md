## 1. 背景

本计划针对 `自我动作实现模块.ixx` 中当前已注册的自我本能动作函数做边界收口。

用户最新口径：

```text
本能动作对应的本能函数，
应当是：

1. 通过自身动作改变特定特征类型的值；
2. 或根据输入特征类型的值，改变 / 形成输出特征类型的值。
```

结合当前上级规范，本计划采用如下判定：

```text
普通逻辑：
    只读查询、局部判断、筛选、评分、排序、匹配、诊断、临时回执整理；
    不直接持久写入任务 / 需求 / 方法 / 世界树特征状态；
    不生成方法动作动态。

本能动作：
    以方法为动作来源；
    读取输入参数场景；
    直接改变某个目标宿主的特征值，或形成可落账的输出特征结果；
    运行后能写入本轮运行存在 / 输出结果场景；
    需要时生成方法动作动态。

提交类本能动作：
    把任务、需求、方法或自我状态的持久特征变化提交入账；
    线程只允许调用它，不允许裸写替代它。
```

`任务筹办`、`任务执行`仍然是任务管理生命周期普通函数，不得恢复为本能方法。

## 3. 改造原则

### 3.1 双层结构

每个可保留本能动作统一拆成两层：

```text
普通 helper：
    做只读匹配、绑定、评分、筛选、推导。

本能动作函数：
    建立自身方法环境；
    调用 helper；
    把结果写入本轮运行存在 / 输出结果场景；
    如属于提交类变化，再写持久特征和动作动态。
```

不得用本能动作函数承载普通循环控制；也不得让普通 helper 静默完成持久写入。

### 3.2 筹办 / 执行过程逻辑边界

筹办和执行过程逻辑不注册为本能动作。

```text
查找候选方法：
    任务筹办内部普通逻辑。

选择当前方法：
    任务筹办内部普通逻辑。

检查方法条件是否满足：
    普通 helper / 筹办内部判断。

查找特征类型 / 配对参数：
    任务执行前后用于参数解释、绑定、构造可执行输入场景的普通逻辑。

检查需求是否满足：
    任务执行后的验收判断普通逻辑。
```

这些过程判断可以写日志、形成任务层回执或输出场景事实，但不以自身名义生成方法动作动态。
持久提交必须交给提交类本能动作。

### 3.3 学习动作边界

学习动作可以是本能方法，但只能表达自身学习动作结果，不能混入目标方法域提交。

```text
定向学习：
    输出学习方向、候选动作线索、观察 / 确认材料。
    不直接把目标方法写成已有动作。

尝试学习：
    输出条件结果对候选、内化候选、目标方法补齐建议。
    不直接把目标方法状态写成可用。

练习：
    调用目标方法真实入口，观察目标方法自己留下的运行账。
    不代写目标方法运行次数、成功次数、连续成功次数、方法状态。
```

目标方法的持久状态提交应走方法域提交动作。
