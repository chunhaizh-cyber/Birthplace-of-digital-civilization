## 1. 本计划只解决什么

本计划只解决一条链：

```text
当前需求目标
-> 因果类读取世界树因果信息
-> 生成可解释因果路径 / 条件缺口 / 证据缺口
-> 任务筹办形成派生需求草案
-> 自我线程和需求类裁决入树
-> 需求树先自然生长到内部治理练习需求
-> 练习补齐方法动作状态 / 条件结果对 / 参数映射 / 方法可用证据
-> 需求树再自然生长到扫描事实 / 动态取得需求
```

目标扫描链收束为：

```text
方法缺口存在
-> 练习需求生成
-> 自我_练习 可筹办 / 可执行
-> 练习动态沉淀内部治理因果
-> 扫描方法具备可执行前提
-> 当前观察范围可观测单位存在对应事实
-> 扫描可启动状态
-> 当前观察范围稳定对应存在扫描事实 / 动态取得状态
-> 自我_扫描当前场景 / 6146 承接
-> 首次扫描建立当前状态基准
-> 后续扫描在可比历史存在时生成状态变化或结构化缺口
```

扫描链不得跳过内部治理练习闭合。若 `自我_扫描当前场景` 或其前置方法仍缺动作入口、方法状态、输入参数、条件结果对或可验证输出，应先派生练习需求，由 `自我_练习` 补齐方法可用证据，再继续扫描需求链。


上述扫描链只在扫描方法系统已经具备以下前提时成立：

```text
方法可用
动作状态明确
输入参数可构造
条件结果对可用
执行后结果可验证
```

任一前提不闭合时，本计划优先进入 `P0.5 内部治理练习链闭合`，不得直接补“扫描可启动状态 -> 扫描事实 / 动态取得需求”。

## 1.2 前置条件重排（2026-06-27）

当前执行不直接进入扫描业务闭合、P4 真实扫描验证、D455 手工运行或外部动作提取。扫描需求自然生长是内部治理练习链之后的结果，不是第一层目标。

```text
正确前置顺序：

1. 内部治理动作能产生真实状态端点。
2. 状态迁移动态证明“什么存在的什么状态真的变了”。
3. 动作致变动态证明“哪个本能方法 / 治理函数造成了变化”。
4. 两类动态按同主体、同特征、双状态时间段包含关系完成同源可复算。

6. 方法缺口自然生成练习需求。

8. 任务筹办只消费因果类 / 世界树查询结果，生成派生需求草案。
9. 需求树自然生长到外设观察 / D455 工作需求。
10. D455 正常工作并提供真实外部数据后，才恢复扫描真实验证或外部动作提取。
```

```text
    任务筹办必须通过因果类 / 世界树入口读取因果；
```

### P0.5：内部治理练习链闭合

目标：

```text
当任务筹办发现方法缺动作、缺条件结果对、缺参数映射、方法不可用或执行结果不可验证时，
不直接阻塞为死路，也不硬编码扫描领域链，
而是通过内部治理因果生成练习需求，并让 自我_练习 本能方法能够被任务系统筹办和执行。
```

关键链路：

```text
方法动作状态缺失 / 方法条件结果对缺失 / 参数映射缺失 / 方法不可用
-> 方法不可执行状态 / 方法结果不可预测状态
-> 练习需求生成状态
-> 练习任务可筹办状态
-> 自我_练习 可执行状态
-> 自我_练习 执行完成
-> 方法动作状态明确 / 条件结果对明确 / 参数映射可用 / 方法可用状态提升
-> 练习动态沉淀内部治理因果
```

约束：

```text
1. 自我_练习 是先天已有本能方法入口；练习需求必须由方法缺口和内部治理因果生成。
2. 练习不能伪造目标方法运行账，必须调用目标方法真实动作入口。
3. 练习结果写入方法虚拟存在、运行存在、输出结果场景和动作动态，不用日志或文本冒充机器事实。
4. 练习目标达成与练习动作执行完成要分开判断；目标方法未达到稳定阈值时不得宣称方法已好用。
5. 若缺口属于缺动作入口、缺条件结果对、缺参数映射或缺可验证输出，应生成结构化练习派生需求；若属于代码缺陷，转开发诊断闭环。
6. 不得随意新增函数；需要实现时，必须先检查 `说明书/函数功能说明文档.md`、现有公用函数和对应类特有功能函数，确认不能复用后才允许新增。
```

验收：

```text
1. 真实运行中出现方法缺口。
2. 因果解释材料能指出缺口属于练习可处理类型。
3. 生成结构化练习派生需求。
4. 练习任务入树。
5. 候选方法命中 自我_练习。
6. 自我_练习 执行后写入方法虚拟存在结果。
7. 生成方法动作动态或可追踪动作动态证据。
8. 动态可沉淀为内部治理因果。
```

#### P0.5b：两类动态生成入口与因果消费核查拆片

P0.5b 不再作为一个大切片一次性处理。后续按三个最小切片推进：

```text
P0.5b-1：状态生成入口核查
    查状态创建后是否生成状态迁移动态。
    查状态迁移动态是否带前态、后态、主体和场域。
    查状态迁移动态是否触发动态二次特征和因果生成。
    当前重点不是确认是否存在刷新入口，而是确认关键结果写入点是否真的创建状态节点。
    输出：状态 -> 动态 -> 因果入口清单、关键写入点 A/B/C 分类，以及缺失端点清单。

P0.5b-2：动作动态入口核查
    查本能方法 / 治理函数是否创建动作动态。
    查动作动态是否带来源方法、动态主体、输入 / 输出场景。
    查动作动态是否存在真实初始状态和结果状态端点。
    当前重点是调用方是否传入动作实际造成的状态端点，而不是动态类是否具备字段承载能力。
    输出：本能方法 / 治理函数 -> 动作动态入口清单，以及实际状态端点缺口。

P0.5b-3：互补绑定与筹办消费核查
    查状态迁移动态和动作动态是否能通过既有同源可复算能力闭合。
    查生成出的因果信息是否能被任务筹办按需求目标查询。
    查需求分解是否只消费因果信息，不反向把需求当因果来源。
    输出：同源可复算清单、任务筹办消费链路和不得继续推进的阻塞点。
```

拆片边界：

```text
1. P0.5b-1 只确认结果侧：什么存在的什么状态真的变了。
2. P0.5b-2 只确认来源侧：哪个本能方法或治理函数执行了什么动作。
3. P0.5b-3 才判断动作动态和状态迁移动态能否绑定成动作致变因果候选。
4. 当前不新增同源变化证据组结构；先用既有状态端点、动态端点、时间段和来源动态引用链复算。
5. 任一切片发现函数或类入口缺失，先进入计划索引 `0.1 Codex 困难处理协议`，不得直接扩大为扫描模板实现。
```

目标：
