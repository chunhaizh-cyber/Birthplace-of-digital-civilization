```text
1. 任务筹办、任务执行每轮治理完成前，生成一条实例级被动动态。
2. 多个同类型、同名称的动态实例沉淀后，再生成抽象动态、抽象因果和必要二次特征。
```

本计划只生成实施方案，不在当前切片直接修改代码。

## 2. 当前口径

```text
1. 任务筹办 / 任务执行仍是任务管理生命周期普通函数。
2. 它们不进入方法树、不进入候选方法集、不作为主动方法动作来源。
3. 每轮治理过程需要生成实例级被动动态，用于记录本轮从哪个出口出来。
4. 动作类型固定为“被动动作”。
5. 动作名称 / 治理过程名固定为“任务筹办”或“任务执行”。
6. 条件不是单值状态，而是任务虚拟存在的入口复合状态快照。
7. 结果不是单值状态，而是任务虚拟存在的出口复合状态快照。
8. 同一个被动动作名称可以有很多结果；结果差异由入口 / 出口复合状态表达，不拆成多个动作类型。
9. 抽象动态、分类和因果规则只能由多个实例动态沉淀生成，不能在单条实例动态中预塞抽象结论。
10. 抽象过程的核心不是保留全部入口特征，而是判断哪些入口特征变化真正影响出口结果。
11. 多轮样本对照后，将复合状态特征分为有效特征、待验证特征、无效特征候选；清理无用特征只能清理抽象签名和候选视图，不删除实例事实。
```

## 4. 复合状态快照定义

复合状态快照不是一个 I64 状态值，而是一组任务虚拟存在特征的同轮视图。实现上建议用一个“任务治理复合状态快照”存在节点承载，再由状态节点把该快照存在作为指针值引用。

### 4.1 入口快照

```text
主体：任务虚拟存在
特征：任务治理复合状态
值：入口快照存在指针
```

入口快照至少保留：

```text
任务状态
任务阶段
当前方法
候选方法集 / 候选数量
可执行输入参数场景
筹办缺口类型
执行缺口类型
最近筹办回执
最近执行回执
当前方法运行存在
任务目标状态
任务当前结果状态 / 当前差距
重筹办次数
执行次数
```

### 4.2 出口快照

```text
主体：任务虚拟存在
特征：任务治理复合状态
值：出口快照存在指针
```

出口快照在入口快照基础上补充：

```text
本轮治理过程名
本轮出口类型
建议下一步去向
是否目标已达成
是否有推进
本轮推进量
剩余差距
是否需要派生需求
是否需要等待外部事实
最终态候选：非最终 / 完成 / 放弃
```

## 5. 实例被动动态实现方案

### P0 规范与命名对齐

目标：

```text
确认“任务筹办 / 任务执行被动动态”不违反“任务筹办 / 任务执行不生成方法动作动态”的现有硬规则。
```

实施：

```text
1. 明确新增动态属于内部治理被动过程动态，不是主动方法动作动态。
2. 来源动作语义固定为“被动动作”。
3. 治理过程名固定为“任务筹办”或“任务执行”。
4. 动态主体必须是任务虚拟存在，不允许把线程、普通函数或流程文本作为动态主体。
5. 若规范文字与该口径冲突，先修订规范，再改代码。
```

验收：

```text
规范目录中能找到对应权威口径；
禁止项仍保留：任务筹办 / 任务执行不得进候选方法集，不得作为主动动作来源。
```

### P1 复合状态快照基础能力

目标：

```text
提供统一函数读取任务虚拟存在当前复合状态，并创建入口/出口快照存在。
```

建议函数归属：

```text
任务类：读取任务虚拟存在及任务域特征。
世界树类：创建复合状态快照存在、创建内部状态、创建被动动态。
任务管理工作线程/界面线程：只调用，不直接绕过世界树写动态。
```

候选函数：

```text
任务类::读取任务治理复合状态视图(...)
世界树类::创建任务治理复合状态快照(...)
世界树类::创建任务治理被动动态(...)
```

验收：

```text
给定任务虚拟存在，能创建入口快照和出口快照；
快照节点内不保存自由文本机器逻辑；
快照能回读到任务状态、当前方法、缺口、回执、运行存在等结构引用。
```

### P2 任务筹办每轮添加被动动态

目标：

```text
任务筹办每轮返回前，形成一条“被动动作 / 任务筹办”实例动态。
```

建议插入点：

```text
不要放在 任务模块.筹办.ixx::筹办任务 内部直接创建动态。
优先放在任务管理工作线程或界面线程的“筹办回执同步到任务虚拟存在”完成之后。
```

原因：

```text
任务筹办普通函数只形成过程回执；
被动动态的结果状态应是回执同步后的任务虚拟存在复合状态；
如果在筹办函数内部创建，出口状态还没有落到任务虚拟存在。
```

流程：

```text
1. 读取任务虚拟存在入口复合状态，创建 S_before。
2. 调用任务筹办普通函数。
3. 同步筹办回执到任务虚拟存在。
4. 读取任务虚拟存在出口复合状态，创建 S_after。
5. 调用 世界树类::创建任务治理被动动态：
   动作类型 = 被动动作
   名称 = 任务筹办
   条件 = S_before
   结果 = S_after
6. 动态引用本轮筹办运行存在、筹办回执和可执行输入参数场景。
```

验收：

```text
每轮筹办最多生成一条对应动态；
动态主体是任务虚拟存在；
初始状态引用 S_before；
结果状态引用 S_after；
同一任务多轮筹办可形成连续来源链；
不新增任务筹办本能方法，不进入候选方法。
```

### P3 任务执行每轮添加被动动态

目标：

```text
任务执行每轮返回前，形成一条“被动动作 / 任务执行”实例动态。
```

建议插入点：

```text
不要放在 任务执行桥::执行方法_同步等待 内部。
优先放在执行回执同步到任务虚拟存在之后。
```

原因：

```text
执行桥只负责调度当前方法并读取运行回执；
任务执行治理动态要表达任务虚拟存在从入口复合状态到出口复合状态的变化；
只有回执同步后，出口状态才完整。
```

流程：

```text
1. 读取任务虚拟存在入口复合状态，创建 S_before。
2. 调用任务执行普通函数。
3. 构造执行推进回执。
4. 同步执行回执到任务虚拟存在。
5. 读取任务虚拟存在出口复合状态，创建 S_after。
6. 调用 世界树类::创建任务治理被动动态：
   动作类型 = 被动动作
   名称 = 任务执行
   条件 = S_before
   结果 = S_after
7. 动态引用本轮方法运行存在、输入场景、输出场景和执行回执。
8. 如任务状态变化，再走既有“提交任务状态变化”被动状态动作入口。
```

验收：

```text
每轮执行最多生成一条对应动态；
动态不由执行桥创建；
动态不把执行成功、执行失败、缺参数等拆成动作类型；
结果差异只体现在 S_after 和相关任务虚拟存在特征中。
```

### P4 因果串联与来源链

目标：

```text
让任务筹办动态、任务执行动态、任务状态提交动态可以串成闭环链。
```

规则：

```text
1. 任务执行动态引用最近任务筹办动态或筹办回执同步动态。
2. 任务状态提交动态引用触发它的筹办 / 执行被动动态。
3. 回到重筹办时，新筹办动态引用上一轮执行动态。
4. 完成 / 放弃时，最终状态提交动态引用最后一轮执行或筹办动态。
```

验收：

```text
能从最终完成 / 放弃状态动态反查：
最终状态提交动态 -> 执行动态 -> 筹办动态 -> 上一轮过程链。
```

## 6. 动态信息抽象实现方案

### A0 抽象前提

```text
抽象动态不能由单条实例动态直接宣称稳定成立。
抽象来源必须是多个同类型、同名称、同复合状态结构的实例动态。
抽象不是把入口复合状态全部固化为条件，而是通过样本对照找出真正影响出口的特征。
```

分组键：

```text
动作类型 = 被动动作
治理过程名 = 任务筹办 / 任务执行
动态主体类型 = 任务虚拟存在
复合状态快照结构签名
入口有效特征签名
出口结果签名
```

分组键不直接使用完整入口快照。完整入口快照只作为溯源事实保存；抽象签名只使用经过影响评估后仍有效的特征。

### A1 实例动态采集

目标：

```text
从世界树动态链中读取任务治理被动动态样本。
```

读取条件：

```text
动态类型 = 被动动作动态
动作类型 = 被动动作
治理过程名 in {任务筹办, 任务执行}
动态主体可解析为任务虚拟存在
初始状态和结果状态均指向复合状态快照
```

输出：

```text
结构_任务治理动态样本视图
    动态节点
    任务虚拟存在
    治理过程名
    入口快照
    出口快照
    来源低层动态
    时间段
```

### A2 特征影响评估

目标：

```text
从同类任务治理动态样本中识别哪些入口特征真正影响出口结果。
```

基本方法：

```text
1. 固定动作类型、治理过程名和任务虚拟存在类型。
2. 对齐多条样本的入口复合状态字段和出口复合状态字段。
3. 对每个入口特征 F 分别统计：
   F 变化而出口结果也变化的样本数；
   F 变化但出口结果不变的样本数；
   F 不变但出口结果变化的样本数；
   F 不变且出口结果不变的样本数。
4. 若 F 的变化稳定伴随出口差异，且反例数低于阈值，则归入有效特征集合。
5. 若 F 的变化与出口差异无稳定关系，归入无效特征候选。
6. 若样本不足、反例冲突或存在共线特征，归入待验证特征，不进入稳定抽象签名。
```

结构化输出：

```text
结构_任务治理特征影响视图
    治理过程名
    特征类型
    样本数量
    支持样本数量
    反例样本数量
    出口差异数量
    影响状态：有效 / 待验证 / 无效候选
    来源动态样本集合
```

边界：

```text
1. 这里的影响判断是动态抽象证据，不是单条任务实例事实。
2. 不得用“相关”“无用”等自由文本作为机器判断；必须由样本计数、特征类型和出口差异结构表达。
3. 无效特征候选只能用于缩小抽象签名、提示开发清理和减少后续匹配条件；不得删除历史入口/出口快照。
4. 多特征共同作用暂不沉淀为单个二次特征；先保留为待验证特征组或因果解释链候选。
```

验收：

```text
给定多轮同名治理动态样本，能列出有效特征、待验证特征和无效特征候选；
有效特征可回溯到样本动态和入口/出口快照；
无效特征候选不改变实例事实，只影响抽象签名候选。
```

### A3 抽象动态生成

目标：

```text
多个同类样本和特征影响评估结果形成抽象动态节点，挂到世界树根链“抽象动态树”。
```

实现：

```text
1. 使用 世界树类::取或创建抽象动态根。
2. 按动作类型、治理过程名、主体类型和出口结果签名查找或创建抽象动态节点。
3. 抽象动态条件侧只保留有效特征集合；待验证特征保留为候选证据；无效特征候选不进入稳定条件签名。
4. 抽象动态保留来源动态样本集合。
5. 抽象动态保留样本数量、支持样本数量、反例数量、最近样本时间和稳定阶段。
6. 抽象动态不替代实例动态，不进入任务执行链。
```

验收：

```text
抽象动态能回溯来源实例动态；
抽象动态位于世界树根链抽象动态树；
实例动态仍保留完整初始 / 结果复合状态引用。
抽象动态的条件签名不含已判定无效的入口特征。
```

### A4 抽象因果生成

目标：

```text
从内部治理动态样本和抽象动态生成内部治理因果样本，再在多次复现后沉淀为稳定因果规则。
```

规则：

```text
1. 单次任务治理动态可生成内部治理因果样本。
2. 多次复现 + 条件抽象 + 失败样本统计 + 反例过滤后，才提升为稳定内部治理因果规则。
3. 被动动作因果用于解释、预测、投影需求和检查自动提交链缺口，不得给自我新增主动可调用方法。
4. 抽象因果必须挂在世界树根链因果树。
```

因果形式：

```text
入口有效特征集合
+ 被动动作: 任务筹办 / 任务执行
-> 出口结果签名
```

验收：

```text
因果模板可回溯抽象动态和实例动态样本；
因果模板不把“任务筹办 / 任务执行”注册为候选方法；
控制面板能显示样本数和反例数。
控制面板能显示有效特征和无效特征候选。
```

### A5 抽象二次特征与清理候选生成

目标：

```text
对同类任务治理动态样本生成可分析的二次特征和无效特征清理候选，用于开发人员观察闭环趋势并逐步收缩抽象条件。
```

候选二次特征：

```text
同一任务连续重筹办次数
同一缺口反复出现次数
筹办出口到执行出口的匹配关系
执行后回到重筹办比例
最终完成 / 放弃收束路径长度
同类入口状态下出口分布
入口特征影响度
入口特征反例率
无效特征候选连续稳定次数
```

边界：

```text
这些是沉淀后的抽象特征，不写入单条实例动态；
不得用日志文本承载机器判断；
抽象二次特征挂到世界树根链抽象二次特征树。
清理候选只减少抽象签名和匹配条件，不删除历史动态、状态快照或真实特征。
```

## 8. 风险与禁止项

```text
1. 不得把任务筹办 / 任务执行恢复为本能方法。
2. 不得把任务筹办 / 任务执行加入候选方法集。
3. 不得让工作线程或执行桥成为动作来源。
4. 不得把执行成功、执行失败、缺参数等结果拆成不同动作类型。
5. 不得只写日志而不写结构化动态。
6. 不得在单条实例动态中直接生成稳定抽象结论。
7. 不得用自由文本字段承载条件、结果、出口类型或机器判断。
8. 不得跳过世界树类直接创建基础信息或动态节点。
9. 不得因为某特征暂时无影响就删除历史事实、实例快照或正式特征节点。
10. 不得把多特征共同作用压扁成一个无来源的“综合影响”字符串。
```
