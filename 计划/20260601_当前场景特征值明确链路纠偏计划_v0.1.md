# 当前场景特征值明确链路纠偏计划 v0.1

日期：2026-06-01

状态：草案，待执行

## 1. 纠偏目标

将当前安全场景影响链从：

```text
自我安全值
-> 风险安全层
-> 场景影响部分
-> 当前场景风险安全值
-> 当前场景特征值明确状态
-> 若干状态型子需求
```

纠偏为：

```text
自我存在定义
-> 自我边界 / 自我关键特征 / 自我安全值
-> 当前场景中外设可提供的原始观察特征类型
-> 这些特征值及其跨时刻变化
-> 相对于自我边界和关键特征的影响候选
-> 当前场景特征值是否足够明确
-> 安全因果候选 / 场景影响评估
-> 风险安全层候选
```

`当前场景特征值明确状态` 只能作为这一段链路的阶段性目标或诊断结果，不再作为链路自身的原因起点。


上级口径：

```text
自我具有边界、关键特征、价值特征、当前状态、目标状态、方法 / 动作能力、观察入口、因果信息、需求系统和任务系统。

相机给特征，自我建场景。
观察像素簇不是稳定世界存在。
基础观察事实可用不是基础风险明确。
安全评估只能生成评估视图或候选，不直接写自我安全值。
```

## 3. 当前代码现状

已具备底座：

```text
1. 自我存在、现实场景、内部世界已经有入口。
2. 自我安全值、服务值、物理安全、风险安全是自我实例特征。
3. 安全根需求 / 服务根需求会绑定自我安全值 / 服务值，并创建当前状态与目标状态。
4. D455 已能产出观察帧、颜色、原始深度、滤波深度、补全深度、点云、轮廓、像素簇、空间范围、深度有效率、空间坐标有效率、未解释区域比例和跨帧稳定性等材料。
5. 自我线程承接外设观察报告时已有明确边界：只承接观察材料，不确认世界真值。
6. 安全因果风险树已能生成 `当前场景特征值明确状态 == 已明确` 的缺口并提交入树。
```

主要偏差：

```text
1. `自我边界` 不是当前代码中的一等参照。
2. `自我关键特征` 没有明确的一等集合，只被安全值 / 物理安全 / 风险安全间接覆盖。
3. `当前场景特征值明确状态` 仍偏布尔枚举状态，缺少“哪些原始特征值已经足够，哪些还不够”的依据。
4. `自我_读取自我关键特征变化` 当前只建立观察窗口，实际把负向变化数量固定为 0，尚未读取相机特征值变化和自我关键特征之间的关系。
5. `安全_构造场景影响因果候选` 当前主要按已确认场景存在数量构造低置信候选，还没有基于位置、距离、接近趋势、遮挡 / 接触 / 进入边界等事实。
6. 根需求目标值读取仍有 `高位` 与 `最大值` 口径不一致风险，需要单独核对并纠偏。
```

## 4. 纠偏原则

```text
1. 不新增“说明性摘要字段”替代真实特征值。
2. 不把相机输出直接写成需求满足、风险明确、安全值增加或世界存在真值。
3. 不把未知场景写成危险，也不把无负向证据写成永久安全。
4. 不恢复固定安全因素表。
5. 不把任务筹办 / 任务执行登记为本能方法。
6. 优先复用已有观察帧、像素簇、存在候选、已确认观察存在、原始事实、动作动态和因果信息。
7. 只有 `自我边界`、`自我关键特征集合` 这种自我定义必需参照缺失时，才允许补最小抽象定义或实例特征。
```

## 5. 新链路标准

### 5.1 相机可提供的原始特征类型

当前第一版只使用已有或已接近已有的外设材料：

```text
观察帧级：
    帧号
    采集时间
    帧宽 / 帧高
    深度单位
    相机内参
    深度是否对齐到彩色

像素 / 深度级：
    彩色值
    原始深度
    滤波深度
    补全深度
    深度有效状态
    点云坐标

观察像素簇级：
    像素数量
    投影范围
    空间范围最小 / 最大 X Y Z
    中心 X Y Z
    深度有效率
    空间坐标有效率
    空间连续性评分
    范围稳定性评分
    轮廓置信度
    掩码 / 彩色局部图 / 深度局部图句柄

跨帧级：
    跟踪状态
    连续成功次数
    失败次数
    距离复现离散度
    空间坐标复现离散度
    新增 / 消失 / 变化观察像素簇数量
```

### 5.2 自我使用这些特征值的目标

自我不是为了“知道有东西”而观察；自我需要这些值，是因为安全根需求反推到场景影响时，需要回答：

```text
1. 当前场景中是否有可确认的观察材料？
2. 观察材料能否形成候选存在或已确认观察存在？
3. 这些存在相对于自我边界在哪里？
4. 它们离自我多远？
5. 它们是否在靠近、远离或保持稳定？
6. 它们是否遮挡、接触、进入或逼近自我边界？
7. 这种变化是否可能影响自我关键特征？
8. 影响候选是否有足够因果证据进入安全评估？
```

### 5.3 `当前场景特征值明确` 的新标准

第一版不再定义为单个布尔灯，而定义为一组最低证据条件都可回查：

```text
当前场景特征值明确 =
    有观察来源
    有观察时间
    有可回查观察材料
    有观察像素簇或已确认观察存在集合
    对每个进入安全评估候选的存在，至少能读到空间位置 / 距离相关值
    对跨帧评估对象，至少能读到时间顺序和位置变化
    能把上述值放入自我边界参照系
    能说明哪些值缺失，因此不能继续评估
```

这不是说所有细节都必须完全识别，而是说安全场景影响评估所需的原始事实输入已经足够，且缺失项可解释、可派生补观察需求。

### P1 自我边界参照核定

目标：

```text
确认当前代码是否已有可表达自我边界的特征或存在结构。
若没有，制定最小补充方案。
```

补充边界只允许是根定义参照，不允许成为安全评估摘要字段。

第一版候选表达：

```text
自我边界参照 =
    自我存在在当前场景中的坐标参照
    自我物理占据范围或近身安全缓冲范围
    可作用边界 / 可接触边界的最小阈值
```

方向：

```text
相机特征值必须能相对该边界解释：
    距离
    靠近 / 远离
    进入边界 / 未进入边界
    接触候选 / 未接触
```

验收：

```text
明确回答“自我的边界在代码中由哪里承载”。
若当前没有，给出最小新增点和不得新增的派生字段清单。
```

### P2 自我关键特征集合核定

目标：

```text
把“自我必须维护的关键特征”从安全值里拆出解释参照。
```

第一版只允许使用已有自我特征：

```text
自我_安全值
自我_物理安全
自我_风险安全
自我_运行状态
自我_资源状态
自我_权限边界
自我_异常状态
```

若代码中没有后三类实例承载，先作为规范 / 抽象特征映射，不直接硬造固定安全因素表。

验收：

```text
形成“关键特征集合 -> 安全值影响候选”的映射表。
该映射表只用于因果反推和评估输入，不直接结算安全值。
```

### P3 改写当前场景特征值明确的判定来源

目标：

```text
保留 `当前场景特征值明确状态` 作为目标特征，但重写其生成依据：
从“状态未明确 -> 目标已明确”改为“缺哪些原始特征值 / 哪些边界参照不可读 / 哪些跨帧值不可回查”。
```

允许：

```text
沿用已有目标特征和提交入口。
补充缺口原因、来源因果、缺失特征清单、合法生产者说明。
```

禁止：

```text
新增一个大而全的 `当前场景摘要` 字段。
用外设报告可回查直接写 `当前场景特征值明确状态=已明确`。
用已确认观察存在数量直接代替特征值明确。
```

验收：

```text
需求树里仍可出现 `当前场景特征值明确状态`，
但日志必须能说明它缺的是观察来源、空间位置、边界参照、跨帧变化还是关键特征影响证据。
```

### P4 纠偏 `自我_读取自我关键特征变化`

目标：

```text
把当前“只要有目标宿主就已明确、负向变化固定 0”的实现改为证据驱动。
```

第一版输入：

```text
自我关键特征集合
当前场景已确认存在集合
外设观察材料 / 像素簇 / 空间范围
自我边界参照
上一轮可比较状态或动作动态
```

输出仍使用已有字段：

```text
关键特征变化观察状态
关键特征观察样本数量
关键特征负向变化数量
```

但这些值必须来自真实比较或明确缺口，不允许固定成功。

验收：

```text
缺少自我边界、缺少当前场景存在集合、缺少可比较历史状态时，方法应输出条件不足或缺口；
只有有真实可比较样本时，才写已明确；
负向变化数量必须由比较结果得出。
```

### P5 纠偏 `安全_构造场景影响因果候选`

目标：

```text
候选不再只是“场景存在数量”的低置信集合，
而是从外设特征值相对自我边界和关键特征变化中构造。
```

第一版候选条件：

```text
存在或候选有空间位置 / 范围
该空间位置能相对自我边界解释
存在跨帧接近、边界进入、遮挡、接触或关键特征负向变化样本之一
或存在明确缺失项，需要补观察 / 补因果证据
```

输出仍使用已有字段：

```text
安全因果候选构造状态
安全因果候选数量
安全因果候选低置信数量
安全因果候选归因置信度
```

验收：

```text
候选数量必须能追溯到具体观察存在 / 像素簇 / 边界关系 / 关键特征变化样本；
低置信数量必须来自证据不足，不是默认等于候选数量；
不得写基础风险明确、不得结算安全值。
```

### P6 根目标值口径核对

目标：

```text
核对安全 / 服务根需求目标值是否仍从 `高位` 读取。
```

上级口径：

```text
安全目标状态 = 自我_安全值 最大值
服务目标状态 = 自我_服务值 最大值
高位、基础稳定带、低位只用于状态分段和阈值判断，不作为根需求目标值。
```

验收：

```text
代码、抽象特征定义和根需求当前 / 目标状态一致；
不再把 `高位` 的低值当作根需求目标。
```

```text
    观察材料路径
```

## 7. 预期需求树方向

纠偏后，`当前场景特征值明确` 下方不应继续堆叠“已明确 / 已完成”状态灯，而应优先出现可追溯的目标链：

```text
当前场景特征值明确
├── 当前观察特征帧取得
├── 外设观察材料可回查
├── 观察像素簇集合可承接
├── 存在候选可由观察像素簇生成
├── 已确认观察存在已提交入账
├── 当前场景存在集合可读
├── 自我边界参照可读
├── 场景存在空间位置 / 距离 / 范围可读
├── 跨帧变化可比较
├── 关键特征变化观察可判断
└── 安全因果候选可构造
```

其中每一项的目标仍应落在正式特征类型和值上，不在需求主信息中新增 AND / OR / 因果子链字段。

## 8. 停止条件

遇到以下情况必须暂停并回报：

```text
1. 需要新增主信息字段才能表达目标。
2. 需要让任务筹办直接写需求树或世界树真值。
3. 需要把外设报告直接解释为已确认存在、风险明确或安全值变化。
4. 需要恢复固定安全因素表。
5. 需要使用模拟入口、伪造样本或已删除业务诊断入口。
6. 上级规范与现有计划发生冲突。
```

## 9. 当前建议下一步

先执行 P0 / P1：

```text
P0：做代码现状对账，列出已有外设原始特征和安全评估输入。
```
