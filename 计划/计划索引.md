# 计划索引

更新时间：2026-06-26

## 0. 索引用途

本文件只作为当前执行路由，不承载完整历史流水账。历史细节从对应计划、实施记录、真实日志、`计划/完成项/` 和 `计划/待完成项/` 查询。

维护规则：

```text
1. 规范优先于计划；计划优先于临时推断。
2. 当前主动队列只保留一个可闭合切片。
3. 已运行内容只保留检查点、证据范围和恢复条件。
4. 待条件项不得混入当前主动队列。
5. 已完成计划必须移入 计划/完成项/，不得继续留在根目录顶层保留计划；索引只保留短查询入口和证据指针。已实现但待自然样本、待真实外设业务样本或待用户切入的计划移入 计划/待完成项/，不得误归为完成项。
6. 旧版本被新版本替代时，只保留仍有恢复价值的版本；与当前规范冲突或已被替代且无引用价值的版本删除。
7. 每次行为验证必须先写预测，再走真实运行路径，最后用日志、状态快照、动作动态和错误日志核对。
8. 严禁新增或依赖模拟测试、夹具测试、伪造样本、伪造入口、伪造动作动态或 `--*-check` 回归命令。
9. 任务筹办 / 任务执行是任务管理生命周期普通函数，不恢复为本能方法。
10. 不提前宣称自我苏醒完成或初步成熟完成。
11. Codex 恢复执行默认只读第 0 章和第 1 章当前主动队列；读到 `### 1.1` 或 `## 2` 前停止。后续章节、历史摘录和待条件项按当前切片引用再读取。
12. 主动缩减上下文：第 1 章只保留当前切片、当前堵点、下一步和证据指针；长输出、长日志和完整历史落盘到实施记录或日志文件，汇报只给关键行。
13. 执行中发现缺口时先分类：是否阻塞当前切片、是否属于当前类、是否已有对应类逻辑纠偏计划。
14. 不阻塞当前切片的缺口，只登记到对应计划的待执行缺口，不打断当前主动计划；索引第 1 章只保留短入口。
15. 阻塞当前切片且属于当前类的缺口，优先补入当前计划当前切片或下一子切片，并同步更新当前目标 / 下一步。
16. 阻塞当前切片且属于其它类的缺口，按“缺哪个类补哪个类第一优先”规则更新或新建对应类逻辑纠偏计划；确需转向时才修改当前主动计划和返回点。
17. 新增或扩容计划后必须写清返回点；被临时提升的计划只执行第一优先闭合切片，闭合后自动返回原计划。
18. 若用户只要求登记计划内容，默认不改变当前主动计划；只有用户明确要求执行，或缺口已阻塞当前切片，才调整当前下一步执行计划。
19. 执行当前计划遇到真实堵点且无法在当前计划内立即闭合时，先记录堵点、证据、已排除路径、恢复条件和返回点，再按第 2 章未完成计划优先队列自动切换到下一个可执行计划；不得因为单个计划堵住就停止整体执行。
20. 用户要求“执行 / 继续执行计划 / 按计划索引执行”时，从第 1 章当前主动计划开始，按第 2 章优先顺序逐项尝试；已完成、已归档、待条件未满足或用户未授权切入的计划只登记为跳过原因。直到所有可执行计划都闭合、或所有可执行计划都遇到堵点后，才停止并汇总堵点清单。
21. 执行中确认无用、过时、已被替代且无恢复价值的代码，应在当前闭合切片或独立清理切片中及时删除；不得长期保留兼容壳、死代码、临时兜底或无人调用的旧入口。
22. 无调用函数清理优先：live 扫描确认没有直接调用，也没有构造 / 析构隐式调用、virtual / override、入口 / 回调 / 导出、注册表、消息分发、模板实例、宏拼接或外部公开合同引用，且不承担项目结构写入 / 读取证据的函数，直接删除；同文件 / 同族可批量处理，删除后刷新函数说明文档、构建、复扫，若仍有符合条件的无调用函数则继续删除。
```

默认恢复读取范围：

```text
1. 第 0 章：索引用途和维护规则。
2. 第 1 章：当前主动队列、当前阻塞、下一步、预测验收、禁止宣称。
3. 最近断点清单：只读当前主动队列指向的断点文件的 `## 0. 恢复摘要`；只有该摘要明确要求时再读取后续章节。
4. 归档历史、顶层保留计划、待条件项：默认不读；只有当前问题明确指向时才按标题小段读取。
```

## 2. 当前未完成计划优先队列

本章只登记 `计划/` 根目录当前可恢复的未完成计划顺序；不等同于开始执行。用户要求“执行 / 继续执行计划 / 按计划索引执行”时，先按第 1 章当前主动队列取一个最小闭合切片；若当前计划遇到真实堵点且无法在当前计划内立即闭合，记录堵点和返回点后，按本章优先顺序自动尝试下一个可执行计划。直到所有可执行计划都闭合、或所有可执行计划都遇到堵点后，才停止并汇总。
