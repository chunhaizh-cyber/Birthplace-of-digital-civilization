# 计划索引

更新时间：2026-06-27

## 0. 索引用途

本文件只作为当前执行路由，不承载完整历史流水账。历史细节从对应计划、实施记录、真实日志、`计划/完成项/` 和 `计划/待完成项/` 查询。

维护规则：

```text
1. 规范优先于计划；计划优先于临时推断。
2. 当前主动队列只保留一个可闭合切片。
3. 已运行内容只保留检查点、证据范围和恢复条件。
4. 待条件项不得混入当前主动队列。
5. 已完成计划必须移入 计划/完成项/，不得继续留在根目录顶层保留计划；索引只保留短查询入口和证据指针。已实现但待自然样本、待真实外设业务样本或待用户切入的计划移入 计划/待完成项/，不得误归为完成项。
6. 旧版本被新版本替代时，只保留仍有恢复价值的版本；与当前规范冲突或已被替代且无引用价值的版本删除。
7. 每次行为验证必须先写预测，再走真实运行路径，最后用日志、状态快照、动作动态和错误日志核对。
8. 严禁用模拟测试、夹具测试、伪造样本、伪造入口、伪造动作动态或 `--*-check` 回归命令证明业务闭合、需求满足、安全 / 服务值改善、扫描闭合、学习闭合或自我成熟。
   允许使用静态扫描、构建命令、函数说明文档生成、规范检查脚本和工程图谱检查脚本作为工程守卫证据。
   工程守卫证据只能证明代码结构、编译状态、引用清理、规范映射或文档一致性，不能证明真实业务行为。
9. 任务筹办 / 任务执行是任务管理生命周期普通函数，不恢复为本能方法。
10. 不提前宣称自我苏醒完成或初步成熟完成。
11. Codex 恢复执行默认采用两段式读取：先读第 0 章维护规则摘要并在 `## 0.1` 前停止；再从 `## 1. 当前主动队列` 读取到 `### 1.1` 前停止。`0.1/0.2/0.3` 只在遇到困难、阻塞回执或类边界缺口时读取；后续章节、历史摘录和待条件项按当前切片引用再读取。
12. 主动缩减上下文：第 1 章只保留当前切片、当前堵点、下一步和证据指针；长输出、长日志和完整历史落盘到实施记录或日志文件，汇报只给关键行。
13. 执行中发现缺口时先分类：是否阻塞当前切片、是否属于当前类、是否已有对应类逻辑纠偏计划。
14. 不阻塞当前切片的缺口，只登记到对应计划的待执行缺口，不打断当前主动计划；索引第 1 章只保留短入口。
15. 阻塞当前切片且属于当前类的缺口，优先补入当前计划当前切片或下一子切片，并同步更新当前目标 / 下一步。
16. 阻塞当前切片且属于其它类的缺口，按“缺哪个类补哪个类第一优先”规则更新或新建对应类逻辑纠偏计划；确需转向时才修改当前主动计划和返回点。
17. 新增或扩容计划后必须写清返回点；被临时提升的计划只执行第一优先闭合切片，闭合后自动返回原计划。
18. 若用户只要求登记计划内容，默认不改变当前主动计划；只有用户明确要求执行，或缺口已阻塞当前切片，才调整当前下一步执行计划。
19. 执行当前计划遇到真实堵点时，必须先进入 `0.1 Codex 困难处理协议`。
    只有满足以下任一条件，才允许切换到第 2 章未完成计划优先队列：
        A. 已完成最多 3 次有证据的最小自救尝试仍无法闭合；
        B. 堵点已确认属于其它类第一优先缺口；
        C. 当前堵点需要真实外设、自然样本、用户授权或环境条件，当前无法取得；
        D. 继续尝试会违反规范、扩大修改范围或伪造业务证据。
    切换前必须记录：堵点类型、证据、已尝试方案、已排除路径、恢复条件、返回点、下一个计划选择理由。
20. 用户要求“执行 / 继续执行计划 / 按计划索引执行”时，从第 1 章当前主动计划开始，按第 2 章优先顺序逐项尝试；已完成、已归档、待条件未满足或用户未授权切入的计划只登记为跳过原因。直到所有可执行计划都闭合、或所有可执行计划都遇到堵点后，才停止并汇总堵点清单。
21. 执行中确认无用、过时、已被替代且无恢复价值的代码，应在当前闭合切片或独立清理切片中及时删除；不得长期保留兼容壳、死代码、临时兜底或无人调用的旧入口。
22. 无调用函数清理优先：live 扫描确认没有直接调用，也没有构造 / 析构隐式调用、virtual / override、入口 / 回调 / 导出、注册表、消息分发、模板实例、宏拼接或外部公开合同引用，且不承担项目结构写入 / 读取证据的函数，直接删除；同文件 / 同族可批量处理，删除后刷新函数说明文档、构建、复扫，若仍有符合条件的无调用函数则继续删除。
23. 自然样本未命中不等于代码失败，也不等于业务闭合。
    处理规则：
        A. 若本切片目标是代码接入，构建通过但自然样本未命中，可标记为“代码接入闭合 / 自然验证待条件”。
        B. 若本切片目标是业务闭合，自然样本未命中必须降级为待条件项，不得通过伪造样本、旧日志、模拟入口或 `--*-check` 替代。
        C. 若自然样本未命中暴露出入口缺失、状态端点缺失或动作动态缺失，则转为真实堵点，进入困难处理协议。
```

## 0.1 Codex 困难处理协议

当执行当前切片遇到困难时，Codex 不得立即停止、不得直接切换计划、不得直接询问用户，必须先进入困难处理协议。

困难类型：

```text
1. 编译失败。
2. 真实运行失败。
3. 入口不明。
4. 当前规范、计划、代码现状冲突。
5. 当前切片所需函数或类入口缺失。
6. 自然样本未命中。
7. 真实证据不足。
8. 执行结果与预测不一致。
9. 发现旧逻辑、兼容壳、死代码或伪闭合路径。
10. 当前计划内部无法闭合，但可能由其它类逻辑纠偏计划承接。
```

处理顺序：

```text
1. 固定当前目标：
   说明本轮原目标、当前切片、禁止越界项。

2. 固定失败证据：
   记录命令、退出码、关键日志、状态快照、动作动态、错误日志或静态扫描结果。

3. 判断困难类型：
   将困难归入上述类型之一或多个。

4. 查依据：
   先查当前计划的上级依据、命中规则、项目结构映射表；
   再查 `docs/工程图谱/05_规则原子索引.md`；
   必要时回读对应规范；
   不得直接凭日志文本或字段名推断规则。

5. 生成最多 3 个候选处理方案：
   每个方案必须写明：修改范围、是否新增函数、是否复用已有函数、风险、验证方式、回滚方式。

6. 优先选择最小闭合方案：
   优先只读核查；
   其次复用已有函数；
   再次补当前类最小缺口；
   最后才按“缺哪个类补哪个类第一优先”切换计划。

7. 每次尝试后必须验证：
   代码修改必须构建；
   行为判断必须走真实运行路径；
   业务闭合必须有真实日志、状态快照、动作动态或控制面板真实输出。

8. 同一堵点最多允许 3 次有证据的尝试；
   仍不闭合时，输出阻塞回执。
```

```text
    命令：
    退出码：
    关键日志：
    状态 / 动态 / 因果证据：

已尝试方案：
    方案 1：
        假设：
        操作：
        结果：
        排除：
    方案 2：

    最可能原因是什么。

    A. 继续当前计划的某个最小切片。

```

## 0.3 类边界困难处理规则

当某一类在实现当前切片时需要读取或解释其它类主信息字段：

```text
1. 先查本类是否已有封装函数。
2. 再查目标类是否已有只读 / 写入 / 判断函数。
3. 若目标类已有函数，必须复用。
4. 若目标类没有函数：
    A. 若缺口阻塞当前切片，临时提升目标类逻辑纠偏计划第一优先；
    B. 若不阻塞当前切片，只登记短缺口，不打断当前计划；
    C. 若涉及结构新增，必须走结构新增准入规范。
5. 当前类不得直接解释其它类主信息字段作为机器判断。
6. 显示 / 日志 / SQL 读取可以后置，但不得反向作为机器判断依据。
```

默认恢复读取范围：

```text
1. 第 0 章：只读索引用途和维护规则；读到 `## 0.1` 停止。
2. 第 1 章：从 `## 1. 当前主动队列` 开始读；读到 `### 1.1` 停止。
3. `0.1 Codex 困难处理协议`、`0.2 阻塞回执模板`、`0.3 类边界困难处理规则`：默认不读；只有遇到困难、需要输出阻塞回执或出现类边界缺口时按标题读取。
4. 最近断点清单：只读当前主动队列指向的断点文件的 `## 0. 恢复摘要`；只有该摘要明确要求时再读取后续章节。
5. 归档历史、顶层保留计划、待条件项：默认不读；只有当前问题明确指向时才按标题小段读取。
```

## 5. 证据闸门

所有计划恢复、完成或移动必须满足以下证据边界：

```text
1. 构建证据只能来自真实构建命令和退出码。
2. 行为证据只能来自真实运行日志、状态快照、动作动态、错误日志或控制面板真实输出。
3. 业务通过不得由旧日志、伪造样本、模拟入口、夹具测试或 `--*-check` 回归命令证明。
4. remote compact / stream disconnected / websocket / network error 只表示远程执行通道中断，不得记成项目实现、业务验证或计划逻辑失败。
5. 纯线程生命周期消息只能进入控制面板信息域；不能生成方法动作动态，不能进入自我治理邮箱。
6. 任务筹办、任务执行、任务管理后处理不作为本能方法注册、选择或动作动态来源。
7. 价值结算只能在叶子任务完成后由任务价值反馈链携带实际改变结果状态、完成度和任务自身权重调用；不得作为安全值 / 服务值根任务的普通筹办候选或当前执行方法。
8. `I64_MAX` 是异常哨兵或未设置值，不得进入真实服务结算。
```

## 5.1 证据等级

```text
E0：文本依据
    规范、计划、工程图谱、实施记录。
    只能作为执行依据，不能证明代码或行为成立。

E1：静态结构证据
    rg 扫描、函数说明文档、工程图谱检查、规范检查。
    只能证明引用、命名、文档或结构关系。

E2：构建证据
    msbuild / 编译命令 / 退出码。
    只能证明当前配置可编译，不能证明业务正确。

E3：真实运行证据
    真实主循环日志、状态快照、动作动态、错误日志、控制面板真实输出。
    可以证明某条运行路径被真实触发。

E4：业务闭合证据
    预测 -> 真实运行 -> 状态 / 动态 / 因果 / 任务 / 需求 / 结算链一致。
    只有 E4 才能证明计划业务闭合。

E5：自然样本复验证据
    非伪造、非夹具、非旧日志，真实外设或真实主循环自然出现的可复核样本。
    只有 E5 可以证明待自然样本项恢复条件成立。
```

切片证据目标：

```text
只读总账梳理：E1。
代码接入：E2。
真实运行触发：E3。
扫描需求自然生长闭合：E4。
D455 自然复核：E5。
```
