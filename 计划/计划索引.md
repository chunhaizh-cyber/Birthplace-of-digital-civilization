# 计划索引

更新时间：2026-07-03

## 0. 维护口径

本索引只登记当前可作为计划层入口的事项。计划层不得绕过详细设计直接进入代码实现。

当前硬规则：

```text
规范 -> 详细设计 -> 实现映射计划 / 代码落地契约 -> 代码实施 -> 实施记录 -> 验证
```

计划文件只有在能追溯到对应详细设计时，才允许作为后续实现入口。若没有对应详细设计，应先拒绝制定 / 执行计划，并回到规范和详细设计层补齐口径。

窄例外：若计划目标本身就是“补齐详细设计”，允许建立详细设计治理计划，但该计划只能安排规范回读、详细设计生成、索引和状态回写，不得作为代码实现入口。

目录口径：

```text
计划/              只保留当前有效计划、计划索引和后续新建的合规计划
计划/完成项/       历史归档和证据入口；不进入默认执行队列
计划/待完成项/     待条件或待恢复入口；恢复前仍需重新检查规范和详细设计
```

归档到 `计划/完成项/` 只表示旧计划退出当前根目录默认队列，不自动证明该计划对应的业务目标已经完成。

### 1.1 连续执行规则

用户说“执行 / 继续 / 按计划索引执行 / 继续执行计划”且未明确限制只执行某一项时，默认执行语义为：

```text
从当前执行序中第一项未完成计划开始；
按 E1 -> E9 顺序连续执行全部未完成计划；
跳过状态为“已闭合”的 P2 / P11 / P12；
每个计划必须从自身 S0 只读代码事实扫描开始，除非该计划已有真实实施记录证明 S0 已完成；
完成一个切片、一个计划、一次构建、一次静态检查、一次提交或一次索引更新都不是停止条件；
每个计划完成后必须更新实施记录 / 计划证据，按 Git 规则提交本计划相关文件，重新读取本索引后自动进入下一未完成计划；
直到 E1-E9 全部完成，或遇到当前轮无法解决的问题，才允许停止。
```

若用户指定某一计划执行：

```text
从指定计划对应的执行序开始；
除非用户明确说“只执行这一项”或计划写有硬停止，否则完成该计划后继续执行后续未完成计划。
```

允许停止的情况仅限：

```text
已按第 1.2 章完成问题升级与分流，仍无法在当前轮解决；
规范或详细设计冲突，需要用户裁决；
继续会伪造业务证据、真实 D455 样本证据或项目结构闭环证据；
缺 SQL、外设、自然样本、权限、凭证或必须由用户决定的业务口径；
计划依赖的上游实施证据缺失且无法在当前轮补齐；
构建、运行、check_specs 或契约验证出现当前轮无法自行解决的阻塞；
计划明确写有硬停止 / 必须等待用户确认 / 不得自动继续；
上下文硬闸触发且已写最小断点。
```

### 1.2 问题升级与分流规则

连续执行中遇到问题时，默认不直接停止。必须先缩小问题、判定类型、升级为可执行切片或待条件切片；只有升级后仍无法在当前轮解决，才按第 1.1 章停止条件暂停。

处理顺序固定为：

```text
发现问题
    -> 只读确认问题边界
    -> 判定问题类型
    -> 选择升级切片
    -> 写入实施记录 / 计划证据
    -> 能解决则继续当前执行序
    -> 不能解决则写清停止原因、恢复条件和复跑入口
```

问题分流表：

| 问题类型 | 进阶解决方式 | 不允许做法 |
| --- | --- | --- |
| 代码入口找不到 | 扩大 S0 只读扫描，查函数说明、调用点、相邻模块；仍没有则插入“缺入口前置切片” | 直接造临时入口、跳过 S0、用日志或说明文本替代入口 |
| 详细设计与代码不一致 | 先修订详细设计或实现映射计划，再回到当前执行序 | 按代码现状反向覆盖详细设计或规范 |
| 上游依赖缺失 | 插入更小的前置切片，先补依赖，再回到消费端计划 | 硬写消费端、伪造上游输出、把待条件当完成 |
| 实现范围过大 | 拆成只读视图、适配层、v2 函数、最小接入口等渐进切片 | 全量重写、混入无关重构、一次替换多条主链 |
| bool / 枚举语义混乱 | 收束为 I64 状态、评分、掩码、来源句柄、复合特征或治理状态 | 新增普通一阶 bool 冒充事实判断 |
| 项目结构无法承载 | 标记缺结构 / 缺函数 / 缺入口，回到详细设计或规范层补齐 | 用自由文本、临时 JSON、注释、日志或 UI 字段承载机器逻辑 |
| 缺真实 D455 / 自然样本 | 代码可推进到入口和项目结构闭合，验证标记为待真实样本；写清恢复条件 | 伪造自然样本、把静态检查说成真实观察验证 |
| 构建 / 运行失败 | 进入根因切片，定位首个真实错误，修复后重跑验证 | 屏蔽弹窗、吞错、降级日志、绕过失败路径 |
| check_specs 或契约检查失败 | 先修规范 / 详细设计 / 计划索引 / 映射关系，再继续代码实施 | 忽略检查结果或只改文案规避检查 |
| 锁或并发占用 | 判断是否新鲜锁；新鲜锁等待或暂停，陈旧锁按规则清理并记录 | 并发构建 / 运行、强删未知持有者锁 |
| 上下文接近硬闸 | 先写最小断点清单，记录当前切片、证据、问题、下一步和禁止宣称项，再继续或暂停 | 凭记忆补写未落盘成果 |

升级切片类型：

```text
前置切片：补上游入口、只读视图、适配层或最小承载。
修订切片：修详细设计、实现映射计划、计划索引或工程图谱。
根因切片：定位并修复构建、运行、弹窗、契约或逻辑错误。
证据切片：补验证入口、回归剧本、实施记录或计划证据。
待条件切片：记录外设、自然样本、SQL、权限、凭证或用户裁决缺失。
用户裁决切片：问题属于业务口径选择，必须暂停等待确认。
```

升级登记规则：

```text
1. 不改变规范口径的小前置切片，可登记在当前计划实施记录和当前计划证据中，并继续执行。
2. 会改变执行顺序、修改计划范围、修改详细设计或新增计划任务的升级，必须回写本索引或对应计划文件。
3. 会改变上级规范、正式详细设计口径或项目结构承载方式的升级，必须先停止代码实施，回到规范 / 详细设计层。
4. 任一升级完成后，必须重新读取本索引当前执行序，继续第一项未完成计划。
```

```text
2. 规范/详细设计/ 或 规范/详细设计/待完成/ 是否存在对应详细设计；
3. 旧计划内容是否仍符合当前规范和详细设计；
4. 若不符合，先修订详细设计，再重新生成实现映射计划。
```

## 3. 新计划进入规则

新增计划必须满足：

```text
1. 有对应详细设计；
2. 计划文件明确承接哪个详细设计；
3. 包含设计条款清单、项目结构映射表、代码入口映射、流程状态表、反走样清单、验证剧本和最小切片计划；
4. 遇到冲突、不确定、读写方不清、项目结构无法映射、验证证据无法定义时，停止制定计划并进入讨论；
5. 不使用 README、说明书、实施记录、流程图、日志或旧对话记忆替代详细设计。
```

补齐详细设计的治理计划是唯一窄例外，但必须写明：

```text
1. 本计划不作为代码实现入口；
2. 输出产物只能是 规范/详细设计/待完成/ 下的详细设计文件；
3. 每份详细设计完成后，若要写代码，仍需另行生成实现映射计划 / 代码落地契约。
```

没有详细设计时固定返回：

```text
还没有对应详细设计，无法制定计划。
需要先根据规范生成详细设计，再制定代码落地契约 / 实现映射计划。
```

## 4. 下一次执行入口

若用户说“制定计划 / 生成计划 / 生成实现映射计划”：

```text
先定位主题；
再在 规范/详细设计/ 和 规范/详细设计/待完成/ 中查找对应详细设计；
存在则按 yu-chao-plan 规则生成或修订计划；
不存在则拒绝制定计划，并提示先生成详细设计。
```

若用户说“执行 / 继续”但未指定主题：

```text
按第 1 章执行序从第一项未完成计划开始连续执行；
当前默认连续执行队列为 E1 -> E9；
不得自动从 计划/完成项/ 恢复旧计划；
不得跳过任一计划自身的 S0 只读代码事实扫描；
不得因完成一个切片、一个计划、一次构建、一次静态检查、一次提交或一次索引更新而停止；
遇到问题先按第 1.2 章升级与分流；
只有第 1.1 章列出的停止条件出现且第 1.2 章无法继续收束时才允许暂停；
P2、P11、P12 已闭合，不进入默认连续代码实施队列；P12 后续若继续，只能围绕真实样本验证或新批准的后续计划进入。
```
