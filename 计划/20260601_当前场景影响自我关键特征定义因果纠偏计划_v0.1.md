# 当前场景影响自我关键特征定义因果纠偏计划 v0.1

## 1. 纠偏目标

本计划纠偏“因果 2：当前场景可能影响自我关键特征”在规范、需求树和代码中的表达方式。

目标链路不是：

```text
某个具体东西危险
-> 当前场景危险
-> 自我安全值下降
```

而是：

```text
当前场景中的存在 / 状态 / 动作 / 关系发生变化
-> 可能造成自我关键特征变化
-> 可能影响自我安全值
```

因此，当前场景只能先作为“自我安全值变化的可能因果来源之一”，不得被预设为危险来源，也不得直接写成安全值下降事实。

## 2. 规范依据

本计划以以下规范为直接依据：

```text
规范/规范目录.md
规范/自我存在服务与生存基本因果闭环规范20260601.md
规范/自我根特征抽象定义与自检缺口规范20260523.md
规范/需求临时因果视图展开规范20260526.md
规范/基础观察事实可用与基础风险判断分层规范20260526.md
规范/需求树生长机制规范20260512.md
规范/任务筹办与执行边界规范20260512.md
```

核对结论：

```text
1. 最新规范已经明确支持该因果：
   当前场景中的存在、状态、动作、关系
   -> 可能造成自我关键特征变化
   -> 可能影响自我安全值

2. 该因果属于自我定义和遗传因果层，不是后天学出的具体危险知识。

3. 当前场景未知不得写成危险。

4. 低场景安全值或场景影响候选不得直接结算自我安全值。

5. 需要进一步证据时，应展开为：
   场景存在事实、场景特征值、场景变化、时间先后、自我关键特征变化、归因证据。
```

## 3. 当前代码核对结论

### 3.1 已具备部分

当前代码已经具备以下基础：

```text
1. 特征词已经存在：
   - 场景存在集合明确状态
   - 当前场景特征值明确状态
   - 关键特征变化观察状态

2. 自我线程侧已经有风险安全树因素：
   - 场景影响
   - 运行状态
   - 资源状态
   - 权限 / 边界
   - 未知因素

3. 当前场景特征值明确状态未达时，会形成场景特征值缺口。

4. 场景影响前置缺口已经包含：
   - 关键特征变化观察状态
   - 安全因果候选构造状态
   - 当前场景持续观察需求明确状态
   - 当前场景持续观察状态

5. 已有方法：
   - 自我_读取自我关键特征变化
   - 安全_构造场景影响因果候选
   - 安全_评估当前场景安全性

6. 场景影响候选和风险安全层聚合当前仍记录为候选或部分值，
   日志中保留“不写风险安全层入账值 / 不写自我安全值”的边界。
```

### 3.2 主要缺口

当前代码还没有把“当前场景可能影响自我关键特征”落实成完整因果证据链：

```text
1. 缺少显式遗传因果模板：
   当前场景特征值变化
   -> 自我关键特征变化候选
   -> 自我安全值变化候选

2. 当前场景特征值明确状态仍偏状态门，
   还没有展开为“需要哪些原始场景特征值、这些值如何变化、变化方向是什么”。

3. 自我_读取自我关键特征变化 当前更像确认观察窗口，
   不能真实给出关键特征是否发生负向变化、变化幅度和方向。

4. 安全_构造场景影响因果候选 当前主要按场景存在数量构造低置信候选，
   还没有依据场景特征值变化、自我边界关系、时间先后和关键特征变化做归因。

5. 自我边界、关键特征和场景存在之间的相对关系尚未稳定表达。
   因此“接近 / 遮挡 / 接触 / 进入边界”等不能直接作为安全结论。

6. 当前实现仍有较多 bool / 状态枚举型门控，
   需要改为围绕原始事实、特征值、变化方向、证据引用来组织。
```

## 4. 目标模型

### 4.1 定义层

建立遗传因果模板：

```text
遗传因果.当前场景.场景特征值变化可能影响自我关键特征
    原因：当前场景中的存在 / 状态 / 动作 / 关系变化
    结果：自我关键特征变化候选
    性质：可能因果，不是危险事实

遗传因果.当前场景.自我关键特征变化可能影响自我安全值
    原因：自我关键特征变化候选
    结果：自我安全值变化候选
    性质：候选因果，不直接结算安全值
```

### 4.2 事实层

因果候选必须从事实材料中构造：

```text
当前场景已确认存在集合
当前场景中存在的原始特征值
当前场景中存在的特征值变化
场景存在与自我边界的相对关系
自我关键特征跨时刻变化
时间先后关系
候选归因证据引用
```

### 4.3 需求层

“当前场景特征值明确”应解释为：

```text
为了判断当前场景是否可能影响自我关键特征，
自我需要取得当前场景中相关存在的原始特征值及其变化证据。
```

它不是：

```text
当前场景危险
```

也不是：

```text
只要有场景存在集合，就已满足场景安全判断
```

## 5. 纠偏原则

```text
1. 不增加固定危险对象表。
2. 不把未知场景写成危险。
3. 不把当前场景特征值明确状态当作因果起点。
4. 不用 bool / 单枚举替代可解释的特征值、变化量、方向和证据引用。
5. 不让外部变化伪装成自我方法动作动态。
6. 不让场景影响候选直接写安全值结算。
7. 优先复用已有世界树、观察报告、动作动态和任务回执结构。
8. 缺证据时生成缺口或候选，不生成结论。
```

## 6. 分步纠偏计划

### P0 重新核对代码落点

目标：

```text
确认当前场景影响链路的所有现有落点，避免重复造结构。
```

核对范围：

```text
特征类.cpp
需求类.cpp
自我线程模块.impl.cpp
自我动作实现.外设模块.ixx
外设线程_D455深度相机.ixx
外设观察报告队列.ixx
```

输出：

```text
1. 当前可复用特征词清单。
2. 当前可复用观察事实清单。
3. 当前可复用动作动态 / 回执入口清单。
4. 需要新增或改名的最小项。
```

### P1 建立场景影响遗传因果模板

目标：

```text
把“当前场景可能影响自我关键特征”建成可被需求树反推和任务筹办读取的遗传因果模板。
```

要求：

```text
1. 模板来源标记为遗传 / 自我定义层。
2. 模板结果只能是候选或缺口。
3. 模板不得写具体危险对象。
4. 模板不得直接写自我安全值下降。
```

建议模板：

```text
当前场景特征值变化 -> 自我关键特征变化候选
自我关键特征变化候选 -> 自我安全值变化候选
```

### P2 重写“当前场景特征值明确”的需求口径

目标：

```text
把当前场景特征值明确从单一状态门，改成原始场景特征材料是否足以构造场景影响候选。
```

最小所需材料：

```text
1. 当前场景已确认存在集合。
2. 每个相关存在的可观察特征类型。
3. 每个相关存在的当前特征值。
4. 跨观察帧的特征值变化。
5. 与自我边界或关键特征相关的方向信息。
6. 证据来源引用。
```

不要求：

```text
1. 直接识别危险。
2. 直接形成安全值。
3. 外设直接完成高阶因果判断。
```

### P3 明确自我边界与场景关系

目标：

```text
将场景存在和自我之间的关系落到自我边界，而不是落到抽象“危险 / 安全”标签。
```

最小关系类型：

```text
相对位置
相对距离
相对运动方向
接近 / 远离趋势
遮挡关系
接触候选
进入自我边界候选
```

要求：

```text
1. 这些关系仍是场景特征或关系特征。
2. 不能直接作为安全结论。
3. 只有当它们与自我关键特征变化出现时间和归因证据时，才进入因果候选。
```

### P4 修正自我关键特征变化观察

目标：

```text
让“自我_读取自我关键特征变化”读取真实关键特征跨时刻变化，
而不是只写关键特征变化观察状态和固定的负向变化数量。
```

需要输出：

```text
关键特征类型
前值
后值
变化量
方向
是否负向候选
证据时间窗
证据来源
```

边界：

```text
该方法只能观察 / 构造变化事实或候选，
不得直接结算安全值。
```

### P5 修正场景影响因果候选构造

目标：

```text
让“安全_构造场景影响因果候选”从真实场景特征变化和自我关键特征变化之间构造候选，
不再只按场景存在数量生成低置信候选。
```

候选最小字段：

```text
候选场景存在
场景特征类型
场景特征前值
场景特征后值
场景特征变化方向
相关自我关键特征
自我关键特征前值
自我关键特征后值
自我关键特征变化方向
时间先后关系
归因置信度
证据引用
```

结论边界：

```text
候选存在不等于危险存在。
候选影响不等于已造成损害。
低置信候选不结算安全值。
```

### P6 调整需求树展开和缺口描述

目标：

```text
需求树中的“当前场景特征值明确”节点应表达材料缺口，
而不是表达布尔枚举结论。
```

调整方向：

```text
当前场景特征值明确状态 未满足
-> 当前场景影响候选构造材料不足
-> 需要取得相关场景存在的原始特征值、变化值和证据引用
```

禁止方向：

```text
当前场景特征值明确状态 未满足
-> 当前场景危险
-> 安全值下降
```

### P7 真实验证

验证要求：

```text
1. 先写预测，再走真实运行路径。
2. 使用日志模块、真实运行日志、状态快照、动作动态和错误日志核对。
3. 不新增模拟测试、夹具测试、伪造样本、伪造动作动态。
4. 构建 Debug x64。
5. 验证场景影响候选生成时，自我安全值不被直接入账。
```

预期日志证据：

```text
1. 遗传因果模板被读取。
2. 当前场景特征材料缺口被生成。
3. 外设观察事实进入世界树或观察报告队列。
4. 自我关键特征变化被独立观察。
5. 场景影响候选引用场景事实和关键特征变化证据。
6. 风险安全层和自我安全值保持未直接结算。
```

## 7. 与前置纠偏计划的关系

本计划处在两个已确认方向之间：

```text
上游：
    当前场景特征值明确链路纠偏计划
    负责回答相机 / 外设能提供哪些原始特征类型和特征值。

本计划：
    负责回答这些场景特征值变化为什么会被自我需要，
    即它们可能影响自我关键特征。

下游：
    自我关键特征负向变化定义因果纠偏计划
    负责回答自我关键特征负向变化为什么会影响自我安全值。
```

最终目标链路：

```text
外设观察到当前场景原始特征值
-> 当前场景特征值及其变化明确
-> 当前场景变化可能影响自我关键特征
-> 自我关键特征负向变化可能影响自我安全值
-> 进入安全根需求的因果候选 / 缺口 / 任务链
```

## 8. 当前建议下一步

先执行 P0 和 P1：

```text
1. 盘点当前代码中可复用的场景特征、观察事实、动作动态和回执入口。
2. 建立最小遗传因果模板，不触碰安全值结算。
3. 再回到“当前场景特征值明确”节点，重写其需求说明和缺口来源。
```

在 P1 完成前，不建议继续扩展更多 bool 型状态字段。
