# 世界树类逻辑纠偏计划 v0.1

日期：2026-06-20

状态：当前主动计划。当前口径为：`世界树类` 负责维护世界树，所有世界树操作都必须通过 `世界树类` 功能函数承接。

## 0. 目标

按当前项目结构闭环口径，纠偏世界树操作入口：

```text
1. 世界树结构操作统一收口到 世界树类。
2. 外部调用方不得直接调用 基础信息类 的 世界根 / 查找主键 / 添加子节点 / 删除节点 / 枚举节点_按类型 / 获取读写锁 来完成世界树操作。
3. 外部调用方不得直接遍历 基础信息节点类 的 父 / 子 / 下 链来完成世界树查询、归属判断、枚举或删除。
4. 世界树类 作为跨领域编排入口，调用 存在类 / 场景类 / 特征类 / 状态类 / 动态类 / 二次特征类 / 因果类 的功能函数完成本类主信息读写。
5. 世界树类 不吞并领域业务语义；领域类仍负责本类主信息字段、索引和业务读取函数。
6. 只读读取和显式确保必须分离；任何查询函数不得隐式创建节点。
```

本计划不恢复旧入口、不新增兼容层、不保留 `世界树类` 与调用方双轨维护同一世界树结构的路径。

## 0.1 世界树操作范围

纳入本计划的世界树操作：

```text
1. 基础信息世界根访问。
2. 世界树节点按主键解析、按类型解析、按引用解析。
3. 世界树节点创建、删除、挂接、迁移、父子归属判断。
4. 世界树节点子链枚举、按主信息类型枚举、祖先 / 后代关系判断。
5. 存在 / 场景 / 特征 / 状态 / 动态 / 二次特征 / 因果节点在基础信息世界树中的结构维护。
6. 世界树 SQL 投影、控制面板世界树只读投影和其它世界树结构快照生成。
7. 跨领域组合操作，例如 场景内存在查找、存在场景坐标读写、场景轮廓候选召回、因果信息挂接。
```

暂不纳入本计划的非世界树操作：

```text
1. 需求类、任务类、方法类内部独立树的生命周期维护，除非其节点引用解析或事实挂接进入基础信息世界树。
2. 语素树、语言树等非基础信息世界树的内部链表维护。
3. 双向链表模板核心、基础信息类本身的底层容器实现。
```

边界说明：

```text
1. 需求 / 任务 / 方法等模块若需要解析世界树引用，必须调用 世界树类 函数，不得调用 世界树.基础信息().查找主键。
2. 需求 / 任务 / 方法等模块若只是维护本类独立树，不属于世界树操作；仍按对应类逻辑纠偏计划处理。
3. 领域类内部现有 基础信息_ 结构操作要单独审计：最终目标是外部调用方只走 世界树类，领域类只作为 世界树类 内部服务或本类主信息功能函数提供者。
```

## 0.2 项目结构映射表

| 业务概念 | 项目承载结构 | 值类型 | 写入方 | 读取方 | 验证方式 |
| --- | --- | --- | --- | --- | --- |
| 世界根 | 基础信息链世界根 | `基础信息节点类*` | `基础信息类` 底层容器，`世界树类` 对外提供 | 外部调用方经 `世界树类` | 扫描外部 `基础信息().世界根()` 是否清零或被豁免 |
