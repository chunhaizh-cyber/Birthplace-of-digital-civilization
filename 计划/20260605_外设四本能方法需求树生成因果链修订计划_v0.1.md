# 20260605_外设四本能方法需求树生成因果链修订计划_v0.1

## 目标

依据 `流程图/20260605_外设四本能方法关系与状态机_v0.1.md` 重新梳理外设观察、识别、扫描、跟踪四类本能方法的因果链，目标不是把四个方法直接写进需求树，而是让需求树能够自然生长出可被任务筹办按结果能力查找到的目标特征需求，最终生成需要执行四个方法的任务。

## 当前口径

1. 需求树只表达目标宿主、目标特征、目标状态，不表达“调用某方法”。
2. 任务筹办只按目标特征和结果能力查找方法，不直接调用观察、识别、扫描、跟踪。
3. 外设线程、报告包、等待项、控制命令不是需求节点、不是因果节点、不是世界事实。
4. `data/initial_causal_templates.tsv` 只存储被动因果；外设识别、扫描、跟踪属于需要主动方法承接的链条，不从该文件直接生成。
5. 第一次扫描只能写“发现存在”或“发现特征”，不能写“发现动态”；只有已有可比较基线后，才能生成特征值变化动态。

## 四方法目标特征映射

| 状态机阶段 | 需求树应生成的目标 | 可被查找的方法 | 方法输出后的提交/派生 |
| --- | --- | --- | --- |
| 观察 | 当前观察特征帧取得状态达到可用，或外设观察材料集取得状态达到可用 | `双目相机_取得当前观察特征帧` | 生成外设观察存在、观察特征、质量/误差二次特征 |
| 识别 | 外设观察材料被组织为识别结果场景，或观察存在到自我存在的对应事实达到可提交 | `自我_识别外设观察材料` | `提交_当前观察范围可观测单位存在对应事实`，生成归属映射、身份二次特征、归属状态动态 |
| 扫描 | 已归属区域进入扫描，稳定对应存在的扫描事实/动态取得状态达到可用 | `自我_扫描已识别区域` | 首次生成发现存在/发现特征；已有基线时提交特征值变化事实 |
| 跟踪 | 指定已归属存在的跟踪结果场景达到可用，或指定存在跟踪状态达到稳定 | `自我_跟踪指定存在` | `提交_指定存在跟踪事实`，生成当前特征、预测误差二次特征、跟踪稳定/丢失/冲突动态 |

## 因果链分层

### 1. 被动派生层

被动派生层只负责说明“具备哪些内部条件后，必然得到哪个治理判断或缺口”。它不负责执行方法。

```text
安全/服务/当前场景类根需求
-> 需要当前场景存在或特征明确
-> 发现缺少可用观察材料
-> 派生目标：当前观察特征帧取得状态 = 可用
```

```text
已有观察材料
-> 发现缺少观察存在到自我存在的归属关系
-> 派生目标：外设识别结果场景状态 = 已组织
```

```text
已有归属关系
-> 需要确认已识别区域的当前特征或新存在
-> 派生目标：外设扫描结果场景状态 = 已组织
```

```text
已有归属关系 + 指定目标/窗口/持续关注意图
-> 需要连续读取指定存在动态特征
-> 派生目标：外设跟踪结果场景状态 = 已组织
```

### 2. 主动承接层

主动承接层由任务管理生命周期完成：

```text
需求目标特征
-> 创建任务
-> 任务筹办填充候选方法集
-> 按方法结果能力选择方法
-> 任务执行调用方法
-> 方法输出结果场景/事实
-> 提交入口写入世界事实或状态动态
-> 需求结算读取事实状态
```

该层必须复用全局“找动作”逻辑：任务筹办不得直接分支调用 `自我_识别外设观察材料`、`自我_扫描已识别区域`、`自我_跟踪指定存在`。

## 当前代码风险判断

1. 现有代码已经注册观察、识别、扫描、跟踪相关本能方法和一组提交方法，但最新运行日志中尚未看到自然生成指向 `当前观察特征帧取得状态`、`外设识别结果场景状态`、`外设扫描结果场景状态`、`外设跟踪结果场景状态` 的需求。
2. 当前风险不是“没有方法名”，而是需求树缺少能命中这些方法结果能力的目标特征链。
3. 识别、扫描、跟踪不能由 `initial_causal_templates.tsv` 直接派生为被动结果；它们应由需求缺口生成任务，再由任务筹办按结果能力找到主动方法。
4. 扫描和跟踪必须带作用域：已识别区域、指定 ROI、指定存在或指定跟踪窗口。缺少作用域时只能生成结构化缺口，不能静默兜底成全场景扫描。

## 修订计划

### P0：代码对账与特征清单

目标：确认四方法当前的结果能力、输入条件、输出场景、提交入口和日志证据。

检查点：

1. `本能方法类.h/.cpp` 中四方法和提交方法的注册项。
2. `自我动作实现.外设模块.ixx` 中四方法的规格确认、输入条件、结果能力、执行实现。
3. 当前特征类中是否已有以下目标特征：观察帧取得状态、外设识别结果场景状态、外设扫描结果场景状态、外设跟踪结果场景状态、归属状态、扫描取得状态、跟踪稳定状态。
4. 任务筹办日志中是否出现这些目标特征需求。

验收输出：

```text
实施记录/20260605_外设四本能方法P0代码对账记录.md
```

### P1：补齐需求树目标特征链

目标：让根需求能够经由当前场景明确、观察材料、归属关系、扫描/跟踪意图，生长出可被四方法承接的目标特征需求。

修订点：

1. 缺观察材料时，生成 `当前观察特征帧取得状态 = 可用` 或等价既有特征目标。
2. 有观察材料但缺归属关系时，生成 `外设识别结果场景状态 = 已组织` 或等价既有特征目标。
3. 有归属关系但缺当前区域变化材料时，生成 `外设扫描结果场景状态 = 已组织` 或等价既有特征目标。
4. 有指定已归属存在且需要持续动态时，生成 `外设跟踪结果场景状态 = 已组织` 或等价既有特征目标。

验收标准：

1. 生成的是需求目标，不是方法调用指令。
2. 任务筹办能够通过结果能力查找到对应方法。
3. 安全/服务权重不能作为是否活动任务化的限制条件。

### P2：任务筹办与等待项衔接

目标：任务筹办在方法缺输入材料时生成结构化缺口，任务管理线程据此形成外设等待项或上游子需求。

修订点：

1. 候选方法必须先填充候选集，再按确定规则选择。
2. 方法缺外设材料、识别区域、ROI、跟踪窗口时，生成对应目标特征缺口。
3. 等待项只表达边界合同：观察模式、目标区域/候选、期望报告类型、期望特征、稳定性、时效和质量要求。
4. 等待项不能替代需求、任务、方法动作动态或世界事实。

验收标准：

1. 缺输入不会被静默兜底。
2. 缺口再次任务化后仍能走同一套全局找方法逻辑。
3. 识别、扫描、跟踪方法由任务执行调用，不由任务筹办直接调用。

### P3：四方法输出去容器化

目标：四方法输出必须从报告包转成世界层可入账的存在、特征、二次特征和状态动态。

修订点：

1. 观察输出：外设观察存在集合、观察特征、误差/质量二次特征、观察状态动态。
2. 识别输出：身份二次特征、归属映射特征、归属状态动态。
3. 扫描输出：已归属存在当前特征、特征变化二次特征、发现存在/发现特征或变化状态动态。
4. 跟踪输出：指定存在当前特征、预测误差二次特征、跟踪稳定/丢失/冲突状态动态。

验收标准：

1. 报告包只作为材料来源，不作为最终世界事实。
2. 输出结果场景只承载真实事实，不承载任务状态回执。
3. 第一次扫描不得生成“发现动态”。

### P4：提交入口与因果账本

目标：四方法执行后的事实写入必须通过提交入口建立动作动态和因果账本引用。

修订点：

1. `提交_当前观察范围可观测单位存在对应事实` 承接识别归属。
2. `提交_观察存在发现事实` 承接首次扫描发现。
3. `提交_观察存在特征值变化事实` 承接已有基线后的扫描变化。
4. `提交_指定存在跟踪事实` 承接跟踪结果。

验收标准：

1. 提交入口写世界事实或状态动态，不直接写安全/服务结论。
2. 外部变化不能伪装成自我方法动作动态。
3. 动作动态来源必须绑定明确方法。

### P5：真实日志验证剧本

目标：用真实运行日志验证需求树已成长到能够生成四方法相关任务。

验证顺序：

1. 写预测：根需求应先派生当前场景明确类目标，缺观察材料时派生观察帧目标。
2. 构建 Debug x64。
3. 运行真实自检/外设路径，不新增模拟测试、夹具测试或伪造入口。
4. 核对日志、状态快照、动作动态和错误日志。

关键证据：

1. 出现指向观察目标特征的需求，并由 `双目相机_取得当前观察特征帧` 承接。
2. 观察材料具备后，出现指向识别结果场景或归属对应事实的需求，并由 `自我_识别外设观察材料` 承接。
3. 归属具备后，在扫描条件满足时出现扫描结果目标，并由 `自我_扫描已识别区域` 承接。
4. 指定存在/窗口具备后，出现跟踪结果目标，并由 `自我_跟踪指定存在` 承接。
5. 首次扫描日志使用“发现存在/发现特征”口径，不写“发现动态”。

## 待确认点

1. 扫描需求的触发条件是否只由“当前场景特征值明确”链触发，还是也允许由其他根需求在缺少区域当前特征时触发。
2. 跟踪需求的触发条件是否必须有显式指定存在/窗口，还是允许由扫描发现的高风险候选自动派生跟踪意图。
3. 如果现有特征类已经有等价特征名，后续实现应优先复用既有特征，不新造近义特征。

## 暂停条件

如果 P0 发现以下情况，应暂停并更新计划，不直接进入实现：

1. 四方法结果能力与需求目标特征无法一一对应。
2. 当前特征类没有可表达观察、识别、扫描、跟踪目标的稳定特征，且新增特征会影响上级规范口径。
3. 任务筹办的全局方法查找逻辑无法承接这些目标，只能靠方法名硬编码调用。
4. 扫描或跟踪的作用域无法从需求、任务输入或方法条件中取得。
