流程定案：

```text
观察：
    根据外设现实特征发现外设观察存在，或完善既有外设观察存在的特征。
    第一帧只建立基准观察存在，多帧关键特征稳定复现后才算观察完成。

识别：
    用自我所在场景中的存在特征与外设观察存在特征比较，判断是否同一存在。
    识别可能需要多帧证据，输出同一性二次特征和归属状态，不输出变化动态。

扫描：
    面向已归属、已有比较对象的存在，发现特征值变化。
    未归属外设观察存在不能生成动态，必须回到识别。

跟踪：
    面向指定已归属存在，在指定窗口内持续读取动态特征。
    跟踪判断重点不是有无变化，而是动态是否连续、合法、稳定。
```

## 3. 四方法契约

### 3.1 观察

职责：

```text
发现外设观察存在；
建立基准观察存在；
多帧比较关键特征误差；
完善外设观察存在的稳定特征。
```

可启动条件：

```text
外设现实材料可回查状态 == 可回查
观察范围明确状态 == 明确
特征类型清单状态 == 明确
各特征类型稳定值域状态 == 可读
最小观测帧数条件 == 满足或可继续累计
```

正式输入：

```text
观察范围存在
外设现实材料特征
上一帧或基准外设观察存在特征
特征类型稳定值域
```

正式输出：

```text
外设观察存在
外设观察存在.基准状态
外设观察存在.观察完成状态
外设观察存在.颜色特征 / 深度特征 / 空间坐标特征 / 空间范围AABB / 轮廓特征 / 掩码特征
外设观察存在.当前特征_基准特征误差二次特征
外设观察存在.连续稳定帧数 / 连续异常帧数 / 丢失帧数
外设观察存在生成动态
外设观察存在稳定复现动态
观察质量缺口动态
```

判断口径：

```text
第一帧 != 观察完成
第一帧 == 外设观察存在.基准状态已建立

观察完成 =
    多帧内关键特征持续有效
    + 误差持续落入对应特征值域
    + 未发生超阈值丢失、漂移、冲突、拆分、合并
```

实现策略：

```text
优先复用现有观察方法族：
    双目相机_取得当前观察特征帧
    自我_建立观察帧存在
    自我_建立观察帧到自我场景接口
    自我_建立像素观察事实索引
    自我_承接像素特征值
    自我_校验观察事实完备性
    自我_评估观察帧质量

如果 P0 对账确认需求筹办需要一个单一结果能力来承接“观察立存在”，
再新增或收口一个方法门面：
    自我_观察外设材料

该门面只能组织观察存在、特征、二次特征和状态动态，
不得把外设线程或材料容器作为动作来源。
```

### 3.2 识别

职责：

```text
比较外设观察存在特征与自我所在场景存在特征；
判断二者是否为同一存在；
建立或拒绝归属映射。
```

可启动条件：

```text
外设观察存在.观察完成状态 == 已完成或部分完成可识别
外设观察存在关键特征集合可读
自我所在场景存在集合可读
同一性比较值域状态 == 可读
最小同一性证据帧数条件 == 满足或可累计
```

正式输入：

```text
外设观察存在
外设观察存在特征集合
自我所在场景存在集合
自我存在特征集合
同一性比较值域
```

正式输出：

```text
外设观察存在_自我存在.同一性状态
外设观察存在_自我存在.同一性评分
外设观察存在_自我存在.特征一致比例
外设观察存在_自我存在.特征冲突数量
外设观察存在.自我归属状态
外设观察存在.归属目标
外设观察存在归属建立动态
外设观察存在归属冲突动态
外设观察存在识别证据不足动态
```

判断口径：

```text
识别不生成被观察存在的变化动态。
识别只回答：
    是否同一存在；
    是否能建立归属；
    是否需要继续观察、冲突消解或生成新存在候选。
```

实现策略：

```text
修订 自我_识别外设观察材料：
    保留工程材料解析适配；
    正式结果改为同一性二次特征、归属映射特征和归属状态动态；
    条件节点从“有可组织容器”改为“外设观察存在特征可读 + 自我场景存在特征可读 + 同一性值域可读”。
```

### 3.3 扫描

职责：

```text
对已归属、已有比较对象的存在进行范围性动态发现；
比较当前特征值与上一轮或基准特征值；
记录值域内变化，发现未归属存在时回到识别。
```

可启动条件：

```text
扫描范围明确状态 == 明确
已归属可扫描存在数量 > 0
扫描范围内未归属外设观察存在数量 == 0
当前特征值与目标宿主绑定状态 == 已绑定
上一轮扫描基准特征状态 == 可读
目标存在特征值域状态 == 可读
```

正式输入：

```text
已归属存在
已归属存在当前特征值
已归属存在上一轮或基准特征值
目标存在特征值域
扫描范围存在
```

正式输出：

```text
已归属存在当前特征
已归属存在当前特征_基准特征差异二次特征
已归属存在特征变化动态
观察存在发现动态
观察存在特征发现动态
已归属存在特征值域冲突动态
下一轮扫描基准特征
最近扫描时间特征
```

判断口径：

```text
首次扫描：
    只生成发现存在或发现特征事实，不生成变化动态。

无变化：
    更新最近扫描时间、稳定计数和下一轮基准，不生成完整变化动态。

值域内变化：
    生成特征变化二次特征和状态动态。

未归属或超值域：
    不强行写成原存在变化；
    输出归属缺口、值域冲突或复验线索，回到识别或补观察。
```

实现策略：

```text
修订 自我_扫描已识别区域：
    把“无归属特征值”改为“未归属外设观察存在”；
    首次扫描分支只写发现存在 / 发现特征；
    已有基线分支才写特征值变化动态；
    超值域分支写冲突动态并派生识别 / 复验缺口。
```

### 3.4 跟踪

职责：

```text
对指定已归属存在持续取值；
判断动态特征是否连续、合法、稳定；
在丢失、遮挡、冲突、预测偏差超限时回流观察、识别或扫描。
```

可启动条件：

```text
指定存在归属状态 == 已归属
跟踪窗口明确状态 == 明确
跟踪基准特征状态 == 可读
目标存在跟踪特征值域状态 == 可读
预测区间状态 == 可生成或已生成
```

正式输入：

```text
指定已归属存在
指定存在当前特征值
指定存在上一轮或跟踪基准特征值
跟踪窗口存在
跟踪特征值域区间
预测区间
```

正式输出：

```text
指定存在当前特征
指定存在跟踪状态
指定存在丢失状态
指定存在当前值域区间ID
指定存在预测误差二次特征
指定存在区间迁移二次特征
指定存在动态区间迁移动态
指定存在跟踪稳定动态
指定存在跟踪丢失动态
指定存在重捕获动态
指定存在预测偏差超限动态
下一轮跟踪基准特征
```

判断口径：

```text
跟踪不是全场扫描。
跟踪不能替代当前观察范围全部可观测单位明确。
动态目标允许变化，但必须判断：
    当前值是否落入合法值域；
    当前值是否落入预测区间；
    区间迁移是否合法；
    预测误差是否超限；
    目标是否丢失、遮挡、冲突或被错误替换。
```

实现策略：

```text
修订 自我_跟踪指定存在：
    增加跟踪值域区间和预测区间特征；
    增加非法区间跳变、预测误差、丢失和重捕获动态；
    缺目标、缺窗口、缺基准时只输出结构化缺口，不兜底成全场扫描。
```

### P1：正式特征清单与去容器化适配层

目标：

```text
保留工程通信容器的传输价值，
但新增或复用正式特征，使方法输出可以落到存在、特征、二次特征和状态动态。
```

实施点：

```text
1. 清点可复用特征：
       外设观察存在状态
       观察完成状态
       自我归属状态
       同一性状态
       扫描基准特征状态
       特征值域冲突状态
       跟踪状态
       预测误差

2. 缺失时新增最小特征，不新增说明性摘要字段。

3. 将工程通信容器解析结果转成正式对象视图：
       外设材料 -> 外设观察存在 / 特征
       识别材料 -> 同一性二次特征 / 归属特征
       扫描材料 -> 当前特征 / 差异二次特征 / 发现或变化动态
       跟踪材料 -> 当前特征 / 预测误差 / 跟踪状态动态
```

验收：

```text
新结果能力不以工程通信容器命名。
日志可继续记录容器 ID，但世界树事实和需求目标不使用容器 ID。
```

### P2：观察方法收口

目标：

```text
把观察正式定义为“外设观察存在多帧稳定复现过程”。
```

实施点：

```text
1. 第一帧只建立外设观察存在基准；
2. 后续帧计算颜色、深度、空间、轮廓、掩码误差；
3. 误差作为二次特征写入观察存在；
4. 各特征按自己的稳定值域判断；
5. 观察完成只说明本次任务、当前视野、当前外设配置和当前时间窗口内稳定复现；
6. 对部分稳定、部分不稳定的特征输出部分完成状态。
```

验收：

```text
第一帧不会写观察完成。
观察不会直接写世界存在永久成立、语义类别确定或安全结论。
```

### P3：识别方法修订

目标：

```text
把识别从“组织识别材料”修订为“外设观察存在与自我场景存在的同一性比较方法”。
```

实施点：

```text
1. 读取外设观察存在特征集合；
2. 读取自我所在场景存在候选集合；
3. 按同一性值域计算二次特征；
4. 多帧累计同一性证据；
5. 写归属映射特征和归属状态动态；
6. 冲突、候选切换、证据不足时输出结构化缺口。
```

验收：

```text
识别输出同一性和归属，不输出变化动态。
识别结果可以触发扫描或跟踪条件具备，但不直接写扫描 / 跟踪完成。
```

### P4：扫描方法修订

目标：

```text
把扫描从“取得扫描材料”修订为“已归属存在的范围性变化发现方法”。
```

实施点：

```text
1. 扫描只处理已归属存在；
2. 未归属外设观察存在回到识别；
3. 首次扫描只写发现存在 / 发现特征；
4. 已有基线后，值域内变化才写变化动态；
5. 超值域变化写冲突动态或复验缺口；
6. 无变化只更新基准、时间和稳定计数。
```

验收：

```text
首次扫描日志不出现“发现动态”。
无归属对象不会生成状态动态。
扫描结果不能反推全场景明确或安全值。
```

### P5：跟踪方法修订

目标：

```text
把跟踪从“指定目标材料组织”修订为“指定已归属存在的连续动态取值方法”。
```

实施点：

```text
1. 强制指定存在、跟踪窗口和跟踪基准；
2. 建立或读取跟踪特征值域区间；
3. 建立或读取预测区间；
4. 计算预测误差和区间迁移二次特征；
5. 写跟踪稳定、区间迁移、丢失、重捕获、预测偏差超限动态；
6. 目标不匹配或身份冲突时回到识别；
7. 质量不足或不可观测时回到补观察。
```

验收：

```text
跟踪只作用于指定存在。
跟踪不会替代全场扫描。
跟踪动态必须带来源方法和目标存在。
```

### P6：任务筹办和等待项衔接修订

目标：

```text
需求树生成正式目标特征需求；
任务筹办按方法结果能力选择方法；
方法缺供料时，任务管理生成外设等待项或上游缺口。
```

实施点：

```text
1. 需求目标不写“调用观察 / 调用识别 / 调用扫描 / 调用跟踪”；
2. 需求目标写目标宿主、目标特征、目标状态；
3. 任务筹办先填候选集，再按确定规则选择；
4. 当前方法缺外设材料时，按方法供料要求生成等待项；
5. 等待项只负责外设线程通信，不进入世界树事实。
```

验收：

```text
自然运行日志中能看到目标特征需求 -> 任务 -> 候选方法 -> 当前方法 -> 等待项或执行结果。
未登记目标特征暴露结构化缺口，不文本兜底。
```

### P7：提交入口和因果账本修订

目标：

```text
四方法执行结果通过提交入口入账，
动作动态来源绑定明确方法，
因果账本由动作动态和来源动态引用链表达。
```

实施点：

```text
1. 提交_当前观察范围可观测单位存在对应事实：
       承接识别归属。

2. 提交_观察存在发现事实：
       承接首次扫描发现存在 / 发现特征。

3. 提交_观察存在特征值变化事实：
       承接已有基线后的扫描变化。

4. 提交_指定存在跟踪事实：
       承接跟踪当前特征、预测误差、跟踪状态和跟踪动态。
```

验收：

```text
提交入口写世界事实、二次特征或状态动态。
提交入口不直接写安全 / 服务结论。
外部变化不伪装成自我方法动作动态。
```

### P8：真实日志验证

目标：

```text
用真实日志、状态快照、动作动态和错误日志验证四方法链路。
```

验证顺序：

```text
1. 写预测：
       预测需求树将生成哪些目标特征需求；
       预测任务筹办将选择哪个方法；
       预测方法缺哪些输入或输出哪些正式事实。

2. 构建 Debug x64。

3. 走真实运行路径：
       不新增模拟测试；
       不新增伪造样本；
       不新增 --*-check 回归入口；
       可使用保留的 --self-check-log 和真实外设运行日志。

4. 核对：
       日志模块；
       状态快照；
       动作动态；
       错误日志。
```

关键证据：

```text
观察：
    第一帧建立基准；
    多帧误差统计；
    稳定复现后生成外设观察存在完成状态。

识别：
    外设观察存在与自我存在生成同一性二次特征；
    多帧证据稳定后建立归属映射。

扫描：
    已归属存在有基线后生成值域内变化动态；
    首次扫描只生成发现存在 / 发现特征；
    未归属或超值域回识别 / 复验。

跟踪：
    指定存在持续输出当前特征、预测误差和区间迁移；
    丢失、冲突、质量不足时回流。
```

## 6. 验收闸门

### 6.1 方法契约闸门

```text
每个方法都有：
    方法头；
    条件节点；
    结果能力；
    输出结果场景；
    本轮运行虚拟存在；
    方法动作动态来源；
    可记录的正式输入和正式输出。
```

### 6.2 去容器化闸门

```text
正式结果节点不以工程通信容器命名。
世界树事实不依赖容器 ID 成立。
容器 ID 只作为日志、回查句柄或材料溯源。
```

### 6.3 需求树闸门

```text
需求树生成目标特征需求，而不是方法调用需求。
任务筹办通过结果能力找到方法。
方法缺条件时生成结构化缺口。
缺口再次任务化仍走统一任务生命周期。
```

### 6.4 因果账本闸门

```text
线程不作为动作来源。
外部变化只记录为观察动态或外部事件动态。
自我方法造成的事实变化才生成方法动作动态。
提交入口动态必须引用来源方法运行动态。
```

### 6.5 外设边界闸门

```text
D455 只提供现实材料和特征来源。
外设线程不确认世界存在。
外设线程不确认语义类别。
外设线程不确认安全 / 服务价值。
```

## 8. 暂停条件

如果出现以下情况，暂停实现并回到计划修订：

```text
1. 四方法无法表达为存在、特征、二次特征和状态动态；
2. 观察方法族无法收口，且新增单一观察方法会冲突上级规范；
3. 需求目标只能通过方法名硬编码命中；
4. 扫描或跟踪缺作用域，且无法从需求、任务输入或方法条件补齐；
5. 真实日志无法产生可比历史，而计划试图伪造扫描变化样本；
6. 提交入口必须直接消费工程通信容器本体才能工作。
```

## 9. 一句话验收

```text
外设线程可以传材料，
任务管理可以等材料，
方法可以使用材料，
但自我正式入账的只能是存在、特征、二次特征和状态动态。

观察立起可复验的外设观察存在；
识别建立这个存在与自我存在的归属；
扫描在已归属存在上记录值域内变化；
跟踪在指定已归属存在上持续守住合法动态。
```
