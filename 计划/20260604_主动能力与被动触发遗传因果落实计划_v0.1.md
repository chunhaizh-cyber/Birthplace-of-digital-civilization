# 方法能力与被动触发遗传因果落实计划 v0.1

日期：2026-06-04

## 1. 目标

按最新规范口径，把方法能力和初始因果模板拆开：

```text
主动动作：
    从本能方法 / 方法系统取得能力结构。
    本能方法因果信息不进入出生期初始因果模板组，只能通过学习及实际使用生成。
    动作动态只作为运行证据、因果实例和稳定度样本。

被动动作：
    必须把 被动因正式出现 -> 被动果自动出现 的触发结构遗传下来。
    被动动作动态只作为来源证据和实例样本。
```

最终形成：

```text
只承载被动触发结构、且带来源动态证据或出生期初始假设标记的初始因果模板组
```

而不是：

```text
裸动作动态遗传；
手写固定因果表；
把被动动作反推成可调用方法。
```

## 3. 当前判断

当前阻塞不应表述为“遗传模板有问题”。

准确表述是：

```text
被动触发遗传模板作为因果承接层是正确方向；
因果信息来源只有一个：自我的认知过程；
本能方法因果不属于出生期初始因果模板组；
剩余问题是部分被动 / 条件类遗传模板内容仍由 C++ 固定生成；
这些固定生成内容应迁移为因果信息组读取或出生期初始模板初始化入口。
```

其中风险安全层组成因的正确来源应为：

```text
初始因果模板或后天证据增强后的因果信息组；
因比较模板集合；
来源动态证据或出生期初始假设标记。
```

而不是：

```text
C++ 固定五因素表；
目标特征名表；
路径名数组；
固定方法 ID 表。
```

### P2 明确方法能力入口与本能方法因果边界

目标：

```text
确认主动动作能力只从方法系统读取。
确认本能方法因果信息不登记为出生期初始因果模板。
```

检查点：

```text
本能方法注册；
方法头；
方法虚拟存在；
条件节点；
结果能力；
条件结果对；
候选方法召回。
```

禁止：

```text
用主动动作动态直接补方法能力；
用一次运行动态替代方法头或结果能力；
用动作动态反向生成普通候选方法。
用出生期初始因果模板生成本能方法产出因果。
```

执行状态：

```text
已按用户要求跳过 P1-01 自然结算样本验收，直接执行 P2 对账。

结论：
    主动能力入口当前已收在方法系统内：
        本能方法注册 / 方法头 / 方法虚拟存在 / 结果能力 / 条件结果对；
        普通候选召回从方法树和结果能力进入；
        动作动态只进入因果证据、实例样本和稳定度材料；
        被动动作、同步回执、候选整理、候选选择、条件检查和治理镜像不会进入主动反推候选。
    纠偏后新增边界：
        出生期初始因果模板只承载被动动作触发结构；
        本能方法因果信息必须通过学习及实际使用生成，不得登记为出生期初始因果模板。

边界：
    因果反推自我动作组合只是只读中间逻辑；
    若反推出唯一单步本能，写入动作入口仍由“提交方法可执行入口”这个方法域提交动作完成；
    不由动作动态直接写方法能力。

记录：

```

### P5 接入任务完成后的被动结算因果

目标：

```text
任务状态=已结算 或 任务完成后结算资格成立
    -> 被动触发安全 / 服务值结算
    -> 生成标准被动动作动态
    -> 生成 / 增强结算因果信息
    -> 调整当前需求链对应权值
```

必须表达：

```text
因：
    任务虚拟存在特征：任务状态=已结算。

果：
    安全值变化量；
    服务值变化量；
    完成度 / 变化方向 / 抽象后二次特征方向。
```

边界：

```text
结算不走普通任务链；
不把结算方法放入安全值 / 服务值根任务候选；
自身先结算，然后按缺口满足程度处理父链，再做横向任务候选；
横向结算只在实际值超过目标值时，用溢出差值尝试满足同规则任务。
```
