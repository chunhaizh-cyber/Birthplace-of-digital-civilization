# 主动能力与被动触发遗传因果落实计划 v0.1

日期：2026-06-04

## 1. 目标

按最新规范口径，把遗传信息拆成两条来源：

```text
主动动作：
    从本能方法 / 方法系统取得能力结构。
    动作动态只作为运行证据、因果实例和稳定度样本。

被动动作：
    必须把 被动因正式出现 -> 被动果自动出现 的触发结构遗传下来。
    被动动作动态只作为来源证据和实例样本。
```

最终形成：

```text
带来源动态证据的遗传因果信息组
```

而不是：

```text
裸动作动态遗传；
手写固定因果表；
把被动动作反推成可调用方法。
```

## 3. 当前判断

当前阻塞不应表述为“遗传模板有问题”。

准确表述是：

```text
遗传模板作为因果承接层是正确方向；
剩余问题是部分遗传模板内容仍由 C++ 固定生成；
这些固定生成内容应迁移为遗传因果信息组读取。
```

其中风险安全层组成因的正确来源应为：

```text
来源类型=遗传 或 后天验证因果 的因果信息组；
因比较模板集合；
来源动态证据或出生期初始假设标记。
```

而不是：

```text
C++ 固定五因素表；
目标特征名表；
路径名数组；
固定方法 ID 表。
```

## 4. 落实顺序

### P1 盘点现有动态到因果路径

范围：

```text
因果类.cpp
自我线程模块.impl.cpp
任务模块.筹办.ixx
任务模块.管理界面线程.impl.cpp
```

要确认：

```text
1. 动态节点如何被转换为因果信息。
2. 来源类型=遗传 当前如何写入。
3. 证据动态样本如何保留。
4. 主动方法因果与被动动作因果当前是否混在同一入口。
5. 被动动作是否可能被反推成可调用方法。
```

产物：

```text
实施记录/20260604_动态到遗传因果路径盘点记录.md
```

执行状态：

```text
已执行并遇到首个问题 P1-01：
    被动任务状态动作动态会自动生成并带旧/新任务状态，
    但尚未看到它稳定命中并增强既有遗传被动因果信息；
    动态创建后的二次特征路径只有命中已有因果模板时才回写因果，
    命不中时尚未报告遗传被动因果信息缺口。

停止点：
    先确认或建立“任务状态=已结算 -> 结算被动果”的遗传被动因果信息，
    再补任务状态被动动作动态命中并增强该遗传信息的入口，
    再继续 P2 / P3。
```

### P2 明确主动能力遗传入口

目标：

```text
确认主动动作能力只从方法系统读取。
```

检查点：

```text
本能方法注册；
方法头；
方法虚拟存在；
条件节点；
结果能力；
条件结果对；
方法产出因果模板；
候选方法召回。
```

禁止：

```text
用主动动作动态直接补方法能力；
用一次运行动态替代方法头或结果能力；
用动作动态反向生成普通候选方法。
```

### P3 建立被动触发结构读取口径

目标：

```text
先从遗传因果信息组读取：
    被动动作类型；
    被动因模板；
    自动果模板；
    动态转因果规则；
    幂等 / 防重复规则；
    来源动态证据。

运行期被动动作动态只负责：
    命中上述遗传因果信息；
    追加证据动态样本；
    追加实例样本；
    增强稳定度或暴露遗传信息缺口。
```

第一批被动动作：

```text
提交任务状态变化；
回写需求满足；
叶子任务价值结算后处理；
安全 / 服务值账务变化；
需求链权值重算；
父任务重筹办触发；
横向任务结算候选触发。
```

产物：

```text
被动动作遗传因果信息组读取接口；
被动因具备但被动果缺失的缺口报告；
被动动作不得进入候选方法集的检查日志。
```

### P4 改风险安全层组成因来源

目标：

```text
风险安全层组成因不再由 C++ 固定五因素生成。
```

改为：

```text
读取主果 = 风险安全层明确状态 / 风险安全层候选 的遗传因果信息组；
从因比较模板集合生成组成因；
只对已入账因素做聚合；
缺失组成因按因果模板生成缺口。
```

验收日志：

```text
自我线程/遗传因果信息入账
自我线程/安全因果风险树因果模板展开
风险安全层组成因来源=遗传因果信息组
固定五因素生成=0
```

### P5 接入任务完成后的被动结算因果

目标：

```text
任务状态=已结算 或 任务完成后结算资格成立
    -> 被动触发安全 / 服务值结算
    -> 生成标准被动动作动态
    -> 生成 / 增强结算因果信息
    -> 调整当前需求链对应权值
```

必须表达：

```text
因：
    任务虚拟存在特征：任务状态=已结算。

果：
    安全值变化量；
    服务值变化量；
    完成度 / 变化方向 / 抽象后二次特征方向。
```

边界：

```text
结算不走普通任务链；
不把结算方法放入安全值 / 服务值根任务候选；
自身先结算，然后按缺口满足程度处理父链，再做横向任务候选；
横向结算只在实际值超过目标值时，用溢出差值尝试满足同规则任务。
```

### P6 验证

每个实现切片必须先写预测，再真实运行验证。

验证证据：

```text
Debug x64 构建；
--self-check-log；
真实日志；
状态快照；
动作动态；
因果信息入账日志；
错误日志。
```

禁止：

```text
新增 --*-check 回归入口；
模拟任务完成；
伪造动作动态；
人工写安全 / 服务值；
把日志文案当作因果信息已生成证明。
```
