## 2. 总目标

第一阶段只落地“任务执行方法闭环”的最小能力：

```text
执行报告态 E
实际回读态 R
来源需求目标态 G
预测态 P（第一版可为空或简化）
    ↓
生成动作验证报告 V
    ↓
写入任务执行结果 / 任务虚拟存在 / 方法虚拟存在可读取位置
```

第一版动作验证报告字段：

```text
动作事务ID
来源任务
来源方法
目标值
预测值
实际值
执行报告值
目标偏差
预测偏差
报告偏差
回读置信度
验证状态
事实提交等级
纠偏建议
```

## 3. 总边界

执行本计划时必须保持：

```text
1. 任务筹办 / 任务执行仍是任务管理生命周期普通函数，不注册为本能方法，不生成方法动作动态。
2. 方法返回成功只作为执行报告态，不作为事实态。
3. 预测态、目标态、执行报告态不得冒充实际回读态。
4. 任务状态变化仍走提交任务状态变化；动作验证报告只能作为治理依据。
5. 需求树写入仍由自我线程 / 提交入口裁决；任务管理线程不得直接写需求树。
6. 结算叶子任务价值仍只允许普通价值任务在硬闸门通过后触发；内部治理任务、证据任务和仅闭账任务不得进入核心值折算。
7. 不使用模拟样本、伪造入口、伪造外设帧、伪造动作动态或 `--*-check` 回归替代真实证据。
8. 新增结构前先确认是否能由特征、二次特征、动作动态、因果追踪或既有提交入口表达。
```

## 6. 后续接入顺序

### P2 接入任务执行段 WT11-WT15

接入位置：

```text
WT11 执行方法
WT12 读取本能方法运行闭环视图
VX0 任务执行闭环验证
WT13 验证实际结果状态与来源需求目标
WT14 计算完成度
WT15 判断目标达成
```

目标：

```text
闭环验证报告驱动任务推进。
方法返回成功 != 目标达成。
执行缺口 != 任务失败。
实际结果满足目标，才允许进入完成判断。
回读不足，进入等待 / 补观察 / 补证据。
实际与目标冲突，进入重筹办 / 纠偏 / 补条件。
```

验收：

```text
执行报告成功但实际回读未达成目标时，任务不得仅凭报告成功进入完成。
目标达成但报告失败时能记录异常成功，并生成报告机制修正建议。
```

### P3 接入结算域分类 CL0/VC0/CL1

接入位置：

```text
UP5 -> CL0 -> VC0 -> CL1
```

目标：

```text
结算域分类读取闭环验证报告，不再只靠任务名、任务类型或执行报告。
普通价值任务要求 actual 实际结果状态存在、完成度 > 0、非内部治理域、合法价值增量或 G0 服务确认路径。
内部治理任务要求结果主要是治理变化项。
证据 / 特殊无价值任务要求结果是证据、风险影响或缺口回执。
仅闭账任务表示完成但缺普通核心价值条件。
```

验收：

```text
内部治理任务不会先进入普通来源需求满足链。
证据任务不会直接写核心安全值 / 服务值。
缺 actual 或完成度为 0 的任务不会被判为普通价值任务。
```

### P4 接入核心价值结算硬闸门 VAL1

接入位置：

```text
VAL0 -> VAL1 -> VAL2 -> VAL3 -> VAL5 -> ACTION
```

目标：

```text
VAL1 必须读取 VC0 结算闭环验证报告。
只有任务已完成、任务已闭账、结算域正确、实际结果状态存在、闭环验证通过、完成度合法、价值增量合法、因果证据成立，才允许进入核心安全 / 服务值结算。
```

验收：

```text
硬闸门不通过时，阻断核心值结算，只记录待补证据或候选。
I64_MAX 不得作为未知、默认成功、异常兜底或无证据满分入账。
服务值仍必须走 G0 已确认成功服务路径。
```

### P5 接入治理闭账 / 证据闭账 / 仅闭账

接入位置：

```text
GOV0/GOV1/GOV2
EVD0/EVD1
CLOSE0/CLOSE1
```

目标：

```text
内部治理任务只做治理变化落账、回执、闭账和依赖唤醒。
证据任务只做证据、风险影响或缺口回执收束。
仅闭账任务只提交任务已结算状态和非核心价值回执。
三者都不得调用结算叶子任务价值。
```

验收：

```text
内部治理任务可以已结算，但不写核心安全值 / 服务值。
任务状态提交、回执同步、执行尝试对账等治理动作不会被画成或写成普通价值生产动作。
```
