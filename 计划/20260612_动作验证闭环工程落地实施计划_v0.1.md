## 1. 核心目标

把动作验证闭环落成工程骨架：

```text
动作事务存在
    ↓
目标 / 预测 / 执行报告 / 实际回读 特征
    ↓
偏差 / 达成度 / 可信度 / 提交等级 二次特征
    ↓
补观察 / 补偿动作 / 重规划 / 补条件 / 学习 需求
    ↓
方法可靠度 / 预测模型 / 观察策略 学习更新
```

职责分工：

```text
特征：
    记录是什么值。

二次特征：
    记录这些值之间有什么差异、冲突、相似、达成关系。

需求：
    记录因为这些差异，下一步应该做什么。

学习：
    记录这些差异长期反复出现后，系统应该如何改变自己。
```

## 2. 总边界

执行本计划时必须保持：

- D455 驱动层和外设线程仍只供观察材料，不直接写世界事实、需求满足或安全 / 服务值。
- 动作线程只作为执行器层，不把动作步骤返回值直接当事实。
- 方法返回成功只作为执行报告态，不作为事实态。
- 任务筹办 / 任务执行仍是任务管理生命周期普通函数，不注册为本能方法，不产生方法动作动态。
- 任务状态变化仍走 `提交任务状态变化`，动作验证报告只能作为治理依据。
- 需求树写入仍由自我线程 / 提交入口裁决，任务管理线程不得直接写需求树。
- 新增字段前先判断能否用特征、二次特征、动作动态、因果追踪和提交入口记录表达。
- 不使用模拟样本、伪造入口、伪造外设帧、伪造动作动态或 `--*-check` 回归替代真实证据。

## 4. 切片计划

### P0 动作事务可记录

目标：

```text
每次关键动作都有动作事务存在；
事务能关联动作线程请求ID、外设报告ID、来源任务和来源方法；
先只记录，不改变事实提交和任务状态。
```

允许新增：

```text
动作闭环特征定义.h
动作闭环特征定义.ixx
动作事务类.h
动作事务类.ixx
```

允许接入：

```text
动作线程类.ixx
任务模块.执行.ixx
自我动作实现.外设模块.ixx
自我动作实现模块.ixx
```

动作：

1. 定义动作事务存在的特征入口：事务 ID、父事务 ID、实在域、动作类型、阶段、来源任务、来源方法、目标存在、动作线程请求 ID、外设报告 ID、前后帧号、前后版本号。
2. 建立动作事务创建 / 查找 / 写基础特征 helper。
3. 在不改变执行结果语义的前提下，把动作线程请求 ID 或任务工作项请求 ID 写入事务特征。
4. 写运行日志：`动作闭环/动作事务建立`，包含事务 ID、请求 ID、来源任务、来源方法、实在域。

验收：

- `git diff --check` 通过。
- Debug x64 构建通过。
- 真实窗口中关键动作出现动作事务建立日志。
- 无事实提交路径改变；无任务完成语义改变。

### P1 D455 观察闭环

目标：

```text
D455 观察材料只作为实际回读来源；
观察质量写入动作事务普通特征；
二次特征判断帧新鲜度、观察质量、材料完备和可提交性；
低质量观察不得提交为正常事实。
```

允许新增：

```text
动作闭环二次特征生成器.h
动作闭环二次特征生成器.ixx
```

允许接入：

```text
外设观察报告队列.ixx
自我动作实现.外设模块.ixx
本能方法类.h
本能方法类.cpp
```

避免修改：

```text
D455相机类.ixx
D455相机类.cpp
外设线程_D455深度相机.ixx
双目相机本能适配器.h
双目相机本能适配器.cpp
```

动作：

1. 从外设报告或观察材料中读取深度有效率、空间坐标有效率、帧质量评分、空间候选数量、缺口数量、质量问题数量、前后帧号。
2. 写事务普通特征：`深度有效率_Q10000`、`空间坐标有效率_Q10000`、`帧质量评分_Q10000`、`观察材料缺口数量`、`观察质量问题数量`。
3. 生成二次特征：`帧新鲜度_Q10000`、`观察质量_Q10000`、`材料完备_Q10000`、`观察事实可提交`。
4. 在 `提交_确认观察存在事实` 等提交类动作前读取二次特征门禁。
5. 不可提交时走补观察 / 重采样 / 等待新帧派生链，不写正常事实。

验收：

- 低质量、旧帧或材料缺口样本不会提交为正常事实。
- 可提交样本仍能进入既有确认观察存在事实链。
- D455 驱动层和外设线程未承担世界事实写入。

### P2 内部方法执行闭环

目标：

```text
方法执行后重新读取实际值；
执行报告成功不等于目标达成；
目标未达成时任务不得只凭报告成功进入完成。
```

允许接入：

```text
任务模块.执行.ixx
任务模块.治理协议.ixx
方法虚拟存在服务类.h
方法虚拟存在服务类.cpp
自我动作实现模块.ixx
```

动作：

1. 在任务执行结果中关联最近动作事务 ID 或写入任务虚拟存在特征。
2. 方法执行后读取目标存在、任务虚拟存在、方法虚拟存在或需求状态的实际值。
3. 写事务普通特征：目标值、预测值、执行报告值、实际值、目标特征类型、来源方法。
4. 生成二次特征：目标状态已满足、方法报告可信、方法实际可靠、需补条件、需回接、需重筹办、需收束。
5. 任务治理读取动作验证结果；执行报告成功但实际目标未达成时，不允许任务仅凭报告成功完成。

验收：

- 执行报告成功但实际回读未达成目标时，任务进入等待、补条件、回接、重筹办或异常治理，不直接完成。
- 目标达成但报告失败时能记录异常成功并进入报告机制修正。

### P3 学习统计

目标：

```text
方法可靠度来自验证成功率、预测残差和报告可信度；
方法选择不再只按执行成功次数强化。
```

允许接入：

```text
方法虚拟存在服务类.h
方法虚拟存在服务类.cpp
任务模块.筹办.ixx
任务模块.管理工作线程.ixx
自我动作实现模块.ixx
自我动作实现.外设模块.ixx
```

动作：

1. 在方法虚拟存在中写入验证样本数、验证成功次数、验证失败次数、验证成功率、平均目标偏差 EMA、平均预测偏差 EMA、报告可信度。
2. 将动作事务和二次特征整理为学习样本，不直接读取 D455 原始帧或动作线程原始报告。
3. 候选方法排序第一阶段使用：`方法评分 = 需求匹配度 * 方法_验证成功率_Q10000 / 10000`。
4. 报告成功但实际失败的样本降低报告可信度和验证成功率。

验收：

- 经常报告成功但实际失败的方法被降权。
- 方法虚拟存在统计来自验证后样本，而不是裸执行报告。

### P4 补偿 / 重规划需求

目标：

```text
偏差不只被记录，还能驱动下一轮动作。
```

允许新增：

```text
动作闭环需求派生器.h
动作闭环需求派生器.ixx
动作闭环学习器.h
动作闭环学习器.ixx
```

允许接入：

```text
任务模块.管理工作线程.ixx
自我线程模块.impl.cpp
需求类.h
需求类.cpp
```

动作：

1. 目标偏差超阈值时派生补偿动作需求。
2. 预测偏差稳定时派生预测模型学习需求。
3. 目标不可达时派生重规划需求。
4. 观察质量低时派生补观察、重采样或持续观察需求。
5. 所有派生需求通过既有派生需求消息和自我线程入树裁决，不由任务管理直接写需求树。

验收：

- 纠偏需求有来源动作事务 ID、来源二次特征、目标特征、实际值、偏差值和纠偏类型。
- 纠偏需求能触发下一轮筹办或等待，不绕过需求树。
- 不把补偿动作裸发成执行指令。
