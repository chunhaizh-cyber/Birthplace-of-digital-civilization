# 特征类逻辑纠偏计划 v0.1

日期：2026-06-20

状态：由因果类外部数据读取纠偏触发；当前等待动态类、状态类、二次特征类第一优先闭合后执行。2026-06-20 已追加特征类结构体必要性审查与非特征主信息直接操作审查范围；不打断计划索引当前正在执行的因果类 P6。

## 0. 目标

补齐特征类只读功能函数，让因果类不再直接解释 `特征节点主信息类::类型`；同时审查 `特征类.h/.cpp` 中结构体是否必须、是否可由既有项目结构替代，以及实现代码是否直接操作非特征主信息类数据。

当前触发缺口：

```text
因果类.cpp 直接读取：
    特征节点主信息类::类型
```

## 1. 第一优先缺口

建议函数：

```cpp
特征节点类* 按主键解析特征节点(const std::string& 主键) const noexcept;

const 语素入口节点类* 读取特征语义类型(
    const 特征节点类* 特征) const noexcept;
```

实现边界：

```text
1. 函数归属 特征类.h/.cpp。
2. 不新增特征主信息字段。
3. 不创建特征，不写特征值，只读解析。
4. 特征类型比较仍使用语素入口同一性，不用字符串词面作为机器判断。
```

## 1.1 新增待执行范围：特征类结构体必要性审查与删除候选

触发点：

```text
特征类.h 当前集中定义多类结构体：
    存在比较结果
    稳态策略
    写入参数
    特征写入结果
    集合比较参数
    特征比较方法结果
    结构_特征状态比较结果
    结构_VecU特征解释规则
    结构_轮廓比较结果
    三维体素相关写入 / 查询 / 融合 / 相似度结构
    常用抽象特征初始化结果

其中部分是特征类内部算法返回包，部分可能只是参数包或显示 / 诊断字段。
需要逐项判断是否为必须结构，能否由 特征节点 / 抽象特征节点 / 特征值 / VecI64 / VecIU64 / 二次特征 / 动态 / 因果链 等既有结构替代。
```

审查口径：

```text
1. 必须保留：
    直接承载特征类算法多值结果，且调用方需要同时读取多个结构化数值；
    或作为公开接口输入输出，无法用现有节点 / 特征值 / 枚举 / 输出参数清晰替代。

2. 可删除：
    无调用；
    只在单函数内部临时打包；
    字段可直接改为局部变量或输出参数；
    字段只服务日志 / 显示 / 文本说明；
    字段可由特征值、二次特征、动态或因果链推导。

3. 需纠偏后再判断：
    包含 std::string 说明 / 失败原因 / 不可比较原因 等文本字段，且该字段进入机器判断、去重、候选生成或自检报告；
    先改为结构化枚举 / 数值 / 节点引用，再决定结构体是否仍需保留。
```

已知初始关注项：

```text
1. 存在比较结果：
    当前用于 特征类::比较特征集合 -> 世界树类::比较存在 -> 二次特征生成模块::由存在比较结果生成二次特征。
    结构体本身可暂保留；但 归一化差异度 当前计算后未被二次特征写入链消费，需要决定接入或删除。

2. 结构_特征状态比较结果：
    包含 std::string 说明，且 特征类::比较状态 直接读取 状态节点主信息类。
    需要优先审查：说明是否只作调试显示；若进入机器链路必须改为结构化状态 / 错误枚举或移出特征类。

3. 结构_三维体素轮廓融合结果 / 结构_三维体素局部轮廓相似度结果：
    包含 失败原因 / 不可比较原因 字符串。
    若只用于日志可暂留；若参与判断，必须结构化。
```

执行步骤：

```text
P2.1 列出 特征类.h 全部 struct / enum class，建立判定表：
    名称 -> 字段 -> 写入函数 -> 读取函数 -> 是否公开接口 -> 是否持久化 -> 是否含文本字段 -> 初判。

P2.2 对每个结构体做引用闭环：
    rg 结构体名；
    记录创建点、写入点、消费点；
    判断是否可由现有项目结构替代。

P2.3 对明确可删结构体执行删除：
    删除结构体；
    删除无用函数或改为局部变量 / 输出参数；
    不保留兼容别名、旧入口或 fallback。

P2.4 对暂不能删但含文本字段的结构体登记纠偏：
    文本字段只允许日志 / 显示；
    机器链路改为枚举、I64、节点引用或既有特征值结构。
```

验收命令：

```powershell
rg -n "^struct |enum class |std::string 说明|失败原因|不可比较原因" 特征类.h
rg -n "存在比较结果|结构_特征状态比较结果|结构_三维体素轮廓融合结果|结构_三维体素局部轮廓相似度结果|归一化差异度" -g "*.h" -g "*.cpp" -g "*.ixx"
python .\tools\生成函数功能说明文档.py
msbuild .\鱼巢.vcxproj /p:Configuration=Debug /p:Platform=x64 /p:LinkIncremental=false /m
```

## 1.2 新增待执行范围：非特征主信息直接操作审查

触发点：

```text
特征类.cpp 当前除 特征节点主信息类 / 抽象特征主信息类 外，还存在对其它数据的直接读取：
    基础信息子节点遍历时 dynamic_cast<T主信息*>(当前->主信息)
    三维体素链函数直接读取 特征值类 内部节点的 主信息.值
    特征类::比较状态 直接取 状态节点主信息类 并读取 状态特征 / 状态值
    特征类::比较特征集合 直接 dynamic_cast<const 特征节点主信息类*>(节点->主信息)

需要判断这些读取是否属于特征类职责，还是应回迁到对应 owning class 或通过功能函数读取。
```

审查口径：

```text
1. 特征类允许直接操作：
    特征节点主信息类；
    抽象特征主信息类；
    特征值解释 / 校验 / 比较所需的 特征值 / VecI64 / VecIU64 / VecU句柄；
    特征值类作为值池时，经特征值类公开函数或明确值池访问函数读取。

2. 特征类不应直接解释：
    状态节点主信息类 的主体、特征、状态值；
    场景 / 动态 / 二次特征 / 因果 / 需求 / 方法主信息；
    其它类主信息字段的业务语义。

3. 如必须比较状态，应优先调用 状态类 功能函数读取状态特征和值，或将状态比较入口迁出 / 改为接收已解析的特征类型和值。
```

已知初始关注点：

```text
1. 特征类::比较状态：
    当前读取 状态节点主信息类。
    候选处理：改为调用 状态类 读取状态主体 / 特征 / 状态值，或拆成 特征类::比较特征值_按特征类型，由状态类负责解析状态。

2. 私有_直接基础信息子节点_按类型：
    当前模板用 dynamic_cast<T主信息*>(当前->主信息) 扫子节点。
    候选处理：若只用于特征 / 抽象特征子节点，可改为明确函数，不保留任意 T主信息 模板穿透。

3. 比较特征集合：
    当前对 特征节点类 使用 dynamic_cast<const 特征节点主信息类*>(节点->主信息)。
    候选处理：改为调用 取特征主信息，保持特征类内部统一入口。

4. 三维体素链读取：
    当前直接读 特征值类 节点的 主信息.值。
    候选处理：确认 特征值类 是否已有只读值读取函数；若缺少，按跨类缺口规则登记到特征值类或对应值池类计划。
```

执行步骤：

```text
P3.1 扫描 特征类.cpp / 特征类.h 中所有：
    取主信息<...>
    dynamic_cast<...主信息...>
    ->主信息
    .主信息.值

P3.2 将命中点分类：
    特征主信息 / 抽象特征主信息内部职责；
    特征值结构读取；
    状态类读取；
    基础信息树遍历；
    其它类越界读取。

P3.3 对非特征类职责读取生成对应 owning class 缺口：
    缺状态读取函数 -> 状态类逻辑纠偏计划；
    缺特征值池读取函数 -> 特征值类逻辑纠偏计划；
    缺场景 / 动态 / 二次特征 / 因果读取函数 -> 对应类逻辑纠偏计划。

P3.4 若缺口阻塞当前特征类切片，按计划索引自动闭环规则临时转向；不阻塞则登记为待执行缺口，不打断当前主动计划。
```

验收命令：

```powershell

```

## 2. 跨类缺口转向规则

执行本计划时，如果发现当前切片必须依赖其它类新增或补齐功能函数，按以下规则处理：

```text
1. 后续任意类缺少当前切片所需功能函数时，不在特征类或调用方临时拼字段、解释其它类主信息或新增平行结构体。
2. 若对应类已有逻辑纠偏计划，则把当前缺口加入该计划，并放到第一优先位置。
3. 若对应类没有逻辑纠偏计划，则生成 `计划/YYYYMMDD_<类名>逻辑纠偏计划_v0.1.md`，并把当前缺口作为第一优先切片。
4. 新生成或被修改的逻辑纠偏计划必须包含本“跨类缺口转向规则”，保证后续继续发现缺口时仍按同一调度口径处理。
5. 更新 `计划/计划索引.md`：把新生成或新修改的计划临时提升为第一优先计划；原计划和原切片记录为返回点。
6. 只执行新计划的第一优先缺口切片，不顺带推进新计划后续候选项。
7. 第一优先缺口闭合后，立即停止该新计划，更新计划索引返回原计划和原切片。
8. 若第一优先缺口切片不能闭合，保留该计划为当前阻塞，不回到原计划继续补丁化绕过。
```
