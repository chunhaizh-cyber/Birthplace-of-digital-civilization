# 项目结构体审计与清理计划 v0.1

## 0. 目标

按当前项目结构约束，对仓库内自定义结构体建立清单、判断用途和不可替代性，清理只剩内部计数 / 去重视图或违反规范约束的孤立结构体，并保证系统逻辑仍由项目通用数据结构闭合。

本计划只建立审计和执行路线，不直接宣称任何结构体已可删除或已闭环。

## 1. 依据

- `规范/禁止性规范20260611.md`
- `规范/规范目录.md`
- `计划/计划索引.md`
- `docs/codex/实现验收审计模式.md`
- `说明书/函数功能说明文档.md`

必须执行的上级口径：

```text
1. 系统内部逻辑必须通过存在 / 场景 / 特征 / 特征值 / I64 / VecU句柄 / VecI64 / VecIU64 / 指针句柄 / 方法 / 需求 / 基础信息节点闭合。
2. 自定义结构体不得用自由文本、字符串、日志、注释、临时 JSON 或自由字段冒充系统逻辑。
3. 有结构体但未挂接到存在、特征、场景、方法或需求节点，按“孤立实现，未接入项目结构闭环”处理。
4. 删除或改造结构体前必须先确认写入方、读取方、调用路径、外部读取和验证方式。
5. 只剩内部计数 / 去重视图、且没有外部读取和项目结构承载价值的结构体，列入删除项。
```

## 2. 不做范围

```text
1. 不把本计划变成全仓库重构。
2. 不在审计阶段直接批量删除结构体。
3. 不为保留旧结构新增兼容层、桥接层、别名层或 fallback。
4. 不用字符串、日志或临时 JSON 替代被删除结构体的业务承载职责。
5. 不提前宣称内部循环完成、自我苏醒完成或初步成熟完成。
```

## 3. 输出物

```text
实施记录/20260618_项目结构体审计_文件清单.tsv
实施记录/20260618_项目结构体审计_结构体清单.tsv
实施记录/20260618_项目结构体审计_引用函数清单.tsv

实施记录/20260618_项目结构体审计_Codex断点清单.md
```

字段要求：

```text
文件清单：
    路径 / 类型 / 是否源码编译单元 / 是否头文件或模块接口 / 是否生成物 / 是否纳入结构体审计

结构体清单：
    结构体名 / 所在文件 / 行号 / 字段摘要 / 是否含文本业务字段 / 是否含项目结构字段 / 写入方 / 读取方 / 外部读取 / 初步分类

引用函数清单：
    结构体名 / 引用函数 / 所在文件 / 行号 / 读写类型 / 是否进入项目结构 / 是否符合规范 / 处理建议

判定表：
    结构体名 / 是否有用 / 是否不可替代 / 项目结构映射 / 不合规点 / 外部读取证据 / 结论 / 最小修改切片 / 验证方式
```

## 4. 项目结构映射表模板

每个进入修改阶段的结构体必须补齐本表：

| 业务概念 | 当前承载结构体 | 项目承载结构 | 值类型 | 写入方 | 读取方 | 验证方式 |
| --- | --- | --- | --- | --- | --- | --- |
| 待审计 | 待审计 | 存在 / 场景 / 特征 / 特征值 / 方法 / 需求 / 基础信息节点之一 | I64 / VecU句柄 / VecI64 / VecIU64 / 指针句柄等 | 待审计 | 待审计 | 搜索写入点、读取点、调用路径和真实运行证据 |

```text

```

## 5. 执行切片

### P0 基线和断点

目标：建立可恢复边界，避免一次性全仓库上下文膨胀。

步骤：

```text
1. 记录 git status --short --untracked-files=no。
2. 新建或更新结构体审计断点清单，只记录已复核证据。
3. 明确排除目录：.git、x64、Debug、Release、日志、logs、生成物和已归档完成项中不参与当前编译的材料。
```

验收：

```text
断点清单存在，且只记录真实读取和真实命令结果。
```

### P1 生成当前项目文件清单

目标：生成当前项目文件清单，作为后续结构体审计边界。

建议命令：

```powershell
rg --files `
  -g "*.h" -g "*.hpp" -g "*.hh" `
  -g "*.cpp" -g "*.cxx" -g "*.cc" `
  -g "*.ixx" -g "*.inl" `
  -g "!x64/**" -g "!Debug/**" -g "!Release/**" `
  -g "!日志/**" -g "!logs/**" -g "!.git/**"
```

输出：

```text
实施记录/20260618_项目结构体审计_文件清单.tsv
```

验收：

```text
每个纳入审计的文件都有路径、类型和纳入理由；不把日志、编译产物和归档历史误纳入当前实现审计。
```

### P2 生成每个文件中自定义结构体清单

目标：按文件列出自定义 `struct`，只形成候选清单，不直接下结论。

方法：

```text
1. 先用只读脚本或 rg 生成 struct 候选。
2. 对宏、模板、嵌套结构体和注释命中做二次复核。
3. 字段摘要必须标出是否含 std::string / const char* / string_view / 文本状态字段。
4. 字段摘要必须标出是否含 I64、VecU句柄、VecI64、VecIU64、指针句柄、节点指针、特征值等项目结构字段。
```

输出：

```text
实施记录/20260618_项目结构体审计_结构体清单.tsv
```

验收：

```text
每个结构体至少有：名称、文件、行号、字段摘要、候选分类。
```

### P3 引用函数和外部读取审计

目标：判断结构体是否被外部读取，以及引用它的函数逻辑是否符合规范和约束性条款。

步骤：

```text
1. 对每个结构体按名称搜索构造、写入、读取、传参、返回、容器持有和跨文件引用。
2. 对引用函数回查 说明书/函数功能说明文档.md，避免重复新建函数或误删已有权威函数。
3. 判断引用函数是否用结构体承载系统状态、存在关系、特征归属、方法关系或需求关系。
4. 判断引用函数是否只依赖文本、日志、注释、临时 JSON 或错误码作机器判断。
5. 判断结构体是否还有外部读取；若只剩内部计数 / 去重视图，标为删除项。
```

输出：

```text
实施记录/20260618_项目结构体审计_引用函数清单.tsv
实施记录/20260618_项目结构体审计_判定表.md
```

验收：

```text
每个结构体都有“有用 / 无用”“不可替代 / 可替代”“外部读取 / 仅内部视图”“保留 / 修改 / 删除 / 暂停确认”四类判定。
```

### P4 分类处理

分类口径：

```text
A 保留：
    结构体承载项目结构闭环中的必要中间态或明确外设 / 算法材料，
    且字段不是文本替代业务状态，引用函数符合规范。

B 修改：
    结构体有必要用途，但字段或引用函数存在规范缺口；
    只做最小改造，使业务状态进入项目结构。

C 删除：
    结构体无外部读取；
    或只剩内部计数 / 去重视图；
    或可由现有存在 / 场景 / 特征 / 特征值 / 方法 / 需求结构直接表达；
    删除后不得新增文本替代字段。

D 暂停确认：
    删除会影响更大范围，或结构体可能是外设算法材料、性能缓存、平台接口边界；
    先写清证据和风险，不在同一切片硬删。
```

处理规则：

```text
1. 每次只处理一个结构体族或一个模块内强相关结构体。
2. 删除函数前先确认没有外部读取、没有项目结构承载职责、没有真实运行路径依赖。
3. 修改引用函数时，若新增、删除或改名函数，必须重新运行 tools/生成函数功能说明文档.py。
4. 触碰任务、需求、方法、动作动态、外设提交链时，必须回读对应规范后再修改。
```

验收：

```text
每个处理切片都有修改前判定、修改文件、保留或删除理由、构建结果和必要真实运行证据。
```

### P5 构建和真实路径验证

基础构建：

```powershell
msbuild .\鱼巢.vcxproj /p:Configuration=Debug /p:Platform=x64 /p:LinkIncremental=false /m
```

验证口径：

```text
1. 文档 / 清单阶段不要求构建。
2. 任何代码删除或函数逻辑修改后必须至少通过 Debug x64 构建。
3. 触碰真实运行链路时，必须先写预测，再运行对应真实路径，最后核对日志、状态快照、动作动态或错误日志。
4. 不使用模拟测试、夹具测试、伪造样本、伪造入口或伪造动作动态作为验收。
```
