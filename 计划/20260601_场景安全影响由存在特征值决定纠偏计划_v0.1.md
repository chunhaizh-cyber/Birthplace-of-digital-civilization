# 场景安全影响由存在特征值决定纠偏计划 v0.1

## 1. 纠偏目标

本计划纠偏“因果 3：场景影响不是由存在名决定，而是由存在的特征值决定”在规范、需求树和代码中的表达方式。

正确链路为：

```text
当前场景安全影响判断
<- 当前场景存在集合
<- 当前场景中各存在的当前特征值
```

更准确的安全链路为：

```text
场景风险安全值
<- 当前场景中已确认存在的风险安全值
<- 这些存在的当前特征值 / 历史动态 / 因果证据 / 时间窗口
```

因此，“场景里有什么存在”只回答了对象入口，不足以回答安全影响。安全影响必须进一步追问：

```text
这个存在当前有什么特征值？
这些特征值是否可追溯？
这些特征值是否在变化？
变化是否与自我边界、关键特征和历史因果证据相关？
当前是否存在负向证据？
```

## 2. 规范核对结论

### 2.1 最新规范已经支持该因果

`006 自我存在服务与生存基本因果闭环` 已给出明确模板：

```text
当前场景风险安全值
<- 当前场景已确认存在集合
<- 各存在风险安全值
<- 各存在当前特征值 / 历史动态 / 因果归因证据 / 无负向证据搜索结果
```

并明确说明：

```text
场景影响不是由存在名决定，
而是由当前场景中已确认存在的当前特征值、历史动态、时间窗口和因果证据决定。
```

### 2.2 观察规范给出的材料层级

外设和场景规范已经把材料分层：

```text
D455 / 双目相机：
    提供当前观察特征帧、观察像素簇、ROI、掩码、点集、深度切片、局部图、稳定特征、质量缺口。

自我侧：
    承接观察报告；
    将观察像素簇转为存在候选；
    经确认后提交为已确认观察存在；
    再读取这些存在的原始特征和历史动态做安全评估。
```

关键边界：

```text
1. 相机不是世界存在识别器，而是稳定观察特征供应器。
2. 观察像素簇不是稳定世界存在。
3. 存在候选不是已确认观察存在。
4. 当前场景存在集合明确不是基础风险明确。
5. 基础观察事实可用不是场景安全。
6. ROI / 掩码 / 局部图不是显示附件，而是正式特征材料。
```


### 3.2 主要缺口

当前代码仍未真正按“存在特征值”决定场景安全影响：

```text
1. 评估存在风险安全值 当前没有读取存在名以外的当前特征值。

2. 存在风险安全值候选目前主要来自历史值占位和无负向因果默认安全，
   没有把位置、距离、深度、运动、ROI、掩码、像素归属、遮挡、稳定性等材料纳入证据视图。

3. 安全_构造场景影响因果候选 仍按当前场景存在数量生成低置信候选，
   没有生成“存在 + 特征类型 + 特征值 + 历史动态 + 时间窗口 + 因果证据”的候选条目。

4. 当前场景特征值明确状态仍偏单一枚举状态，
   没有拆出“哪些存在缺哪些特征值、哪些特征值过期、哪些特征值有冲突、哪些证据不足”。

5. 已确认观察存在虽然写入了多种原始事实，
   但安全评估没有形成统一的存在特征值读取清单和最小材料门。

6. 当前“高风险未知区域数量”等外设字段容易被误读为安全结论。
   它只能是观察质量 / 未解释区域线索，不能直接作为危险事实。
```

## 4. 目标模型

### 4.1 存在集合只做入口

```text
当前场景存在集合明确
    只表示：自我知道当前场景中有哪些已确认观察存在。

当前场景存在集合明确
    不表示：这些存在的安全影响已经明确。
```

### 4.2 存在特征值才进入判断

每个已确认观察存在至少应形成可读取的特征材料视图：

```text
存在ID / 观察存在引用
是否在当前场景中
来源观察报告ID
来源外设
观察时间 / 报告年龄
位置 / 中心坐标
距离 / 深度
投影范围 / 空间范围
运动状态 / 跨帧变化
ROI / 掩码 / 点集 / 像素归属材料引用
轮廓置信度 / 轮廓残差
深度一致率 / 深度残差
空间坐标有效率
稳定性评分
遮挡候选
接触 / 进入自我边界候选
与自我交互候选
历史动态引用
曾造成自我关键特征负向变化证据
当前负向证据搜索结果
无负向证据搜索结果
```

这些材料允许缺失，但缺失时必须表现为材料缺口或低置信候选，不能用默认值伪装已明确。

### 4.3 风险安全值是解释结果

```text
存在风险安全值候选
    <- 存在当前特征值
    <- 存在特征值变化
    <- 历史动态
    <- 与自我关键特征变化的时间关系
    <- 因果归因证据
    <- 负向证据 / 无负向证据搜索结果
```

它不是：

```text
存在名称 -> 风险安全值
存在数量 -> 风险安全值
未知对象 -> 风险安全值下降
```

## 5. 纠偏原则

```text
1. 不按存在名、对象类别或固定危险表直接判断风险。
2. 不因存在未知而写危险。
3. 不把存在集合明确当作场景安全影响明确。
4. 不把外设报告、像素簇、ROI、掩码、局部图直接写成安全结论。
5. 不把高风险未知区域数量直接解释成危险对象。
6. 不伪造缺失的颜色、深度、空间坐标、轮廓或稳定性特征。
7. 不用单一 bool / 枚举替代特征值、变化方向、时间窗口和证据引用。
8. 不直接结算自我安全值。
```

## 6. 分步纠偏计划

### P0 盘点已确认观察存在的原始特征落账情况

目标：

```text
确认当前哪些存在特征已经真实写入，哪些只停留在外设报告或输出场景中。
```

核对范围：

```text
外设观察报告队列.ixx
自我动作实现.外设模块.ixx
外设线程_D455深度相机.ixx
特征类.cpp
需求类.cpp
```

输出：

```text
已确认观察存在可读特征清单
外设报告可回查材料清单
输出结果场景临时评估字段清单
缺失但规范要求的最小材料清单
```

### P1 定义“当前场景各存在当前特征值明确”的最小材料门

目标：

```text
将当前场景特征值明确从单一状态门，改为按存在逐项核对特征材料。
```

建议最小门：

```text
每个已确认观察存在：
    在场关系可追溯
    来源观察报告可追溯
    当前时间窗可追溯
    位置 / 距离 / 空间范围至少一类可读
    ROI / 掩码 / 像素归属材料至少一类可回查
    深度或空间坐标质量状态可读
    稳定性或跨帧变化状态可读
```

输出状态不得只写：

```text
当前场景特征值明确状态 = 已明确
```

还必须能说明：

```text
明确了哪些存在
明确了哪些特征类型
哪些特征缺失
哪些特征过期
哪些特征冲突
证据来自哪里
```

### P2 补“存在特征值证据视图”

目标：

```text
为安全评估构造只读证据视图，统一读取已确认观察存在的当前特征值。
```

建议视图字段：

```text
被评估存在
在场状态
观察时间 / 报告年龄
中心坐标
距离 / 深度
空间范围
投影范围
像素数量
像素归属状态
掩码状态 / 掩码句柄
ROI 引用
点集引用
深度有效率
空间坐标有效率
轮廓置信度
范围稳定性评分
遮挡候选
冲突像素数
未解释像素数
来源报告ID
来源动作动态
材料缺口掩码
```

边界：

```text
该视图只读取事实，不写风险结论。
```

### P3 改造 `评估存在风险安全值`

目标：

```text
让存在风险安全值候选由存在特征值、历史动态和因果证据共同决定，
不再只依赖历史值占位和候选壳。
```

第一阶段不需要复杂危险公式，只需做到：

```text
1. 没有当前特征材料 -> 评估不明确，输出材料缺口。
2. 有当前特征材料但无负向证据 -> 可生成无负向证据候选。
3. 有特征变化但缺关键特征归因 -> 低置信候选，不结算。
4. 有负向归因证据 -> 生成存在风险安全值候选和证据引用。
```

禁止：

```text
按存在数量平均后直接宣称场景安全。
按存在名或类别直接生成风险值。
```

### P4 改造 `安全_构造场景影响因果候选`

目标：

```text
从“按存在数量生成低置信候选”改为“按存在特征值变化生成候选条目”。
```

候选条目最小内容：

```text
候选存在
特征类型
当前特征值
前一特征值
变化方向
时间窗口
来源观察报告
来源动作动态
相关自我关键特征
关键特征变化方向
归因证据状态
负向证据状态
候选置信度
```

输出边界：

```text
候选不是危险事实。
候选不是安全值结算证据。
候选只为后续评估和归因提供可追溯材料。
```

### P5 调整场景风险安全值聚合

目标：

```text
场景风险安全值聚合读取存在风险安全值候选时，必须知道每个候选的证据状态。
```

第一阶段聚合规则：

```text
1. 存在评估不明确 -> 场景风险安全值不明确或低置信。
2. 存在只有无负向证据候选 -> 可作为默认良好候选，但不直接入账。
3. 存在有负向归因证据 -> 进入场景风险压力。
4. 存在缺关键特征归因 -> 只进入低置信候选，不进入结算。
```

保留：

```text
风险安全_场景影响部分候选
风险安全_场景影响部分可结算状态
风险安全_场景影响部分不可结算原因
不写自我安全值
```

### P6 修正需求树展开

目标：

```text
让“当前场景特征值明确”继续展开为按存在 / 按特征类型的材料需求。
```

示例：

```text
当前场景特征值明确
└── OR组：特征值获取路径
    ├── D455观察确认路径
    │   ├── 当前观察特征帧取得
    │   ├── 外设观察材料可回查
    │   ├── 外设像素簇候选已验证
    │   ├── 外设观察存在候选确认方案已取得
    │   ├── 已确认观察存在已提交入账
    │   ├── 当前场景存在集合明确
    │   └── 当前场景各存在当前特征值可读
    ├── 读取已有场景缓存路径
    └── 交互者直接说明路径
```

其中 `当前场景各存在当前特征值可读` 不应只表示一个 bool，而应能解释缺口材料。

## 7. 与前两条因果纠偏计划的关系

```text
因果 1：
    自我关键特征负向变化
    -> 自我安全值下降候选

因果 2：
    当前场景变化
    -> 可能影响自我关键特征
    -> 可能影响自我安全值

因果 3：
    当前场景影响判断
    不能由存在名决定，
    必须由当前场景中已确认存在的特征值、历史动态、因果证据和时间窗口决定。
```

合并后的链路：

```text
外设观察材料
-> 观察像素簇 / ROI / 掩码 / 深度 / 轮廓 / 稳定性
-> 已确认观察存在
-> 当前场景各存在当前特征值明确
-> 存在风险安全值候选
-> 当前场景风险安全值候选
-> 场景影响候选
-> 自我关键特征变化候选
-> 自我安全值变化候选
```
