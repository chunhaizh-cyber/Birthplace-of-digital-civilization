# 自检问题因果投影入树逻辑修复计划 v0.1

日期：2026-05-31

## 1. 目标

修复自检发现问题进入需求树时的裁决逻辑：

```text
自检发现缺口
-> 确认自我线程已经运行并完成安全根任务来源锚点
-> 补齐原子目标
-> 查询遗传因果信息和状态转换因果投影
-> 判定安全 / 服务 / 学习 / 方法维护 / 自维护影响
-> 选择父需求和权重
-> 正式入需求树或保留为报告
```

核心口径：

```text
自检问题本身不是安全 / 服务硬分类。
它对安全或服务的影响必须通过自我固定安全 / 服务因果链、目标投影、固定来源任务和局部来源解释说明。
其中自我、自我安全根、自我服务根、自检来源和自检固定来源任务属于固定上下文；
自检固定来源任务就是安全根任务。
局部来源需求、局部来源子任务或目标方法只用于补充更近一层的解释，
不能因为局部来源缺失就改变整体分类方向。
自检线程必须在自我线程进入运行后才能启动；
启动前必须先检查所需基础信息是否具备；
未取得自我线程运行态、安全根需求、安全根任务来源锚点或必要因果投影入口时，
自检线程不开启自检，不产出正式候选。
```

本计划只修复自检候选入树裁决，不推进安全值 / 服务值结算，不恢复任何诊断业务入口。

```text

7. “遗传”因果信息是自我安全 / 服务根投影的初始路线图，必须进入因果查询接口，不得只作为任务筹办内部日志。
8. 本能方法自检只检查事实：是否有对应动作、是否有条件结果对、条件结果对命中次数；不再用笼统“方法好用”作为入树目标语义。
```

## 3. 当前问题

### 3.1 旧问题

当前自检入树裁决主要按目标特征文本分流：

```text
自我安全值 -> 安全根
自我服务值 -> 服务根
服务类特征文本 -> 服务根
安全类特征文本 -> 安全根
方法状态 -> 方法维护 / 旧逻辑曾暂由安全根承接
部分结构缺口 -> 报告或弹错
```

该逻辑的问题：

```text
1. 目标特征文本只能说明缺口对象，不足以说明安全 / 服务影响。
2. 方法状态、方法运行账、条件结果对等问题可能是安全或服务链上的间接缺口。
3. 旧逻辑把方法状态平铺到安全根，会污染安全根直接子需求。
4. 只把方法状态挡在需求树外，又会丢失真实的间接安全 / 服务修复需求。
```

### 3.2 当前停止点

为避免继续污染安全根，当前代码中 `目标特征=方法状态` 已临时改为不挂安全 / 服务根。

这只是止血，不是最终方案。执行本计划时必须用因果投影裁决替换该硬挡分支。

## 4. 设计口径

### 4.1 自检候选的本体意义

自检候选只表达：

```text
目标宿主.目标特征类型
    当前状态
    目标状态
    满足关系
    自检证据摘要
```

它不直接表达：

```text
是否安全
是否服务
是否直接影响
是否间接影响
是否应该结算
```

这些必须由后续裁决得到。

### 4.2 固定上下文与缺口补齐顺序

自我线程收到自检候选后，不重新裁决“自检是否属于自我”这类固定事实。
先承认固定上下文，再判断候选缺少哪段信息，并只补齐缺少的部分：

```text
1. 固定上下文先成立：
   自检来源=自我；
   自检固定来源任务=安全根任务；
   固定来源需求=安全根任务对应的安全根需求；
   默认目标主体=自我或自我内部循环中的目标宿主；
   安全根 / 服务根是自我的固定根目标；
   安全 / 服务因果链是自我的固定目标投影空间。

2. 补原子目标缺口：
   若候选缺目标宿主 / 目标特征 / 当前状态 / 目标状态，
   先按自检报告、目标状态主体、方法状态宿主或根特征宿主补齐；
   补不出来时保留报告并记录缺哪一项。

3. 补因果投影缺口：
   先用自我安全根 / 服务根固定因果链查询该原子目标是否为必要条件、
   促成条件、避免条件、方法就绪条件或证据补齐条件。

4. 补局部来源解释缺口：
   固定来源任务已经是安全根任务，不再把它作为待猜来源；
   若候选明确携带更具体的局部来源需求 / 来源子任务，则记录并细化父链；
   若没有局部来源需求 / 来源子任务，不因此把候选移出安全 / 服务链，
   只记录“局部来源解释缺失”。

5. 若目标状态能查询到状态转换因果投影：
   按目标投影路径补齐安全 / 服务 / 学习 / 方法维护 / 自维护维度。

6. 若无具体因果路径，但目标特征语义可生成规则候选投影：
   只作为候选投影，不允许据此结算。

7. 若在固定上下文和可补信息都尝试后仍无法建立任何投影：
   保留为自检报告或待休眠评估，不入普通执行需求；可进入自维护待分类分支。
```

启动前置：

```text
1. 自检线程不得早于自我线程运行态启动。
2. 自检线程执行前先检查所需基础信息是否具备。
3. 自我线程未初始化完成、安全根需求不存在、安全根任务来源锚点不可读、
   或因果投影入口不可用时，自检线程不开启自检，不生成正式候选。
4. `--self-check-log` 只能验证日志和入口状态；
   不得绕过自我线程运行态直接启动业务自检来补状态。
```

### 4.2a 本能方法自检事实口径

检查本能方法时，只读取以下事实：

```text
1. 方法是否有对应动作：
   方法首节点动作句柄是否有效；
   动作句柄是否能解析到已注册本能动作 / 外部动作入口。

2. 方法是否有条件结果对：
   条件结果对数量 > 0。

3. 条件结果对命中次数：
   按条件结果对自身统计或可追溯命中账读取；
   若当前结构只保存方法公共命中次数，必须标记为“缺条件结果对命中次数来源”，
   不能用方法公共命中次数冒充条件结果对命中次数。
```

输出缺口必须分别表达为：

```text
缺对应动作
缺条件结果对
条件结果对命中次数不足 / 缺命中次数来源
```

禁止：

```text
不再把 `方法状态=好用` 作为自检入树目标。
不再用最近连续成功次数替代条件结果对命中次数。
不再把“有动作但无条件结果对”的方法直接判为可用。
```

### 4.3 父需求选择

父需求选择规则：

```text
1. 自我根安全 / 服务因果链显示该缺口是安全 / 服务必要条件：
   挂到对应安全根 / 服务根，或挂到该根下已存在的同类管理子需求。

2. 有更具体的局部来源需求：
   在不改变固定安全 / 服务方向的前提下，优先挂到局部来源需求下，
   表达这是该需求达成链上的子缺口。

3. 有更具体的局部来源子任务：
   反查子任务来源需求，挂到该需求下。

4. 无局部来源链但固定因果投影为安全 / 服务：
   挂安全根 / 服务根或其管理子需求；
   不因缺局部来源任务而降级为“仅维护”或挡在需求树外。

5. 投影为方法维护 / 学习 / 自维护，且同时能通过自我安全 / 服务投影路径关联安全或服务：
   优先挂到对应安全 / 服务链上的管理子需求下；
   若管理子需求不存在，由自我线程通过正式需求更新入口创建或复用。

6. 仅投影为方法维护 / 学习 / 自维护，无法关联安全 / 服务：
   挂自维护 / 方法维护管理需求；
   若当前需求树尚无该管理需求，则按正式更新入口创建在需求树根下的管理分支。

7. 无法投影：
   不入普通需求树，只保留自检报告并写明缺失证据。
```

说明：

```text
直接 / 间接不作为需求主信息字段。
直接性由父需求位置和投影路径解释。
```

### 4.4 权重和阻塞规则

```text
1. 直接安全投影：
   安全权重=1，服务权重=0，阻塞父任务执行=按需求目标决定。

2. 直接服务投影：
   安全权重=0，服务权重=1，阻塞父任务执行=按需求目标决定。

3. 间接安全 / 服务投影：
   权重继承来源需求或由投影维度给出；
   控制面板只读展示其投影层级，不写新主信息字段。

4. 方法维护 / 学习 / 自维护且无安全 / 服务关联：
   安全权重=0，服务权重=0；
   是否阻塞只取决于它挂载的父管理需求，不默认阻塞安全根。

5. 无投影或证据不足：
   不入普通需求树，不给安全 / 服务权重。
```

## 5. 实施步骤

### P0 执行顺序闸门与现状冻结

目标：

```text
先确认自检线程启动顺序、基础信息预检和当前临时分流代码现状。
记录当前自检入树裁决代码现状。
确认 `目标特征=方法状态` 临时不入树分支只是止血。
```

允许修改：

```text
自检线程启动闸门和基础信息预检。
实施记录或计划说明。
```

禁止：

```text
自检线程不得早于自我线程运行态启动。
基础信息预检失败时不得开启自检线程主循环。
不得通过 `--self-check-log` 或控制面板摘要入口绕过自我线程运行态生成业务候选。
不继续扩大临时硬编码文本分流。
```

验收：

```text
自检启动日志能显示：基础信息预检通过 / 预检失败缺项 / 已启动自检。
若自我线程未运行或基础信息缺失，自检线程不开启自检且不产出正式候选。
rg 能定位当前自检裁决函数和临时方法状态分支。
```

基础信息预检项：

```text
自我线程运行态已成立；
自我初始化完成；
自我存在可读；
安全根需求可读且未截止；
安全根任务来源锚点可读；
自我内部世界可读；
状态 / 特征 / 因果投影查询入口可用；
本能方法表和动作注册表可读。
```

预检失败处理：

```text
返回启动失败或保持未启动；
写明缺项；
不创建任务；
不写需求树；
不投递自检候选。
```

### P1 补遗传因果信息与自检投影接口

目标：

补齐“遗传”因果信息在自检裁决中的只读查询路径。
因果接口要能以自我安全根 / 服务根和安全根任务为默认上下文，
返回自检缺口的目标投影，而不是只服务叶子任务结算预判。

新增或完善普通结构体和普通函数，例如：

```text
结构_自检候选目标投影裁决
私有_查询自检候选目标投影_线程侧(...)
因果类::查询自检原子目标投影(...)
```

输出至少包含：

```text
目标维度集合
候选权重类型集合
结算贡献层级
因果距离层级
投影显示层级
缺失证据
是否有安全投影
是否有服务投影
是否仅维护投影
是否只有候选规则投影
来源因果主键
来源因果类型
遗传因果命中数量
固定来源任务主键
固定来源需求主键
```

实现要求：

```text
1. 复用 因果类::查询叶子任务权重类型与层级 的投影输出语义，
   但不能要求自检缺口必须具备叶子任务。
2. 固定读取自我、自我安全根、自我服务根、自检来源和安全根任务上下文。
3. 查询时以自我根安全 / 服务因果链为默认上下文。
4. `枚举_因果来源类型::遗传` 必须被纳入查询结果；
   遗传因果命中只说明初始路线图和必要条件，不直接结算。
5. 安全根任务是自检固定来源任务，不作为可选增强项。
6. 若候选能反查更具体的局部来源需求 / 来源子任务，则把局部来源链作为增强上下文。
7. 若缺局部来源需求 / 来源子任务，只输出“局部来源解释缺失”，不得改变整体安全 / 服务投影方向。
8. 不写需求树、不写任务树、不写世界树。
9. 不新增主信息字段。
```

### P2 收缩本能方法自检事实口径

目标：

把本能方法自检从“方法好用 / 最近连续成功”等粗判断收缩为三类事实：

```text
有无对应动作
有无条件结果对
条件结果对命中次数
```

实现要求：

```text
1. 有无对应动作：
   读取方法首节点动作句柄；
   动作句柄必须能解析为已注册本能动作 / 外部动作入口。

2. 有无条件结果对：
   读取条件结果对数量；
   数量为 0 时输出 `缺条件结果对`，不要包装成 `方法状态未达到好用`。

3. 条件结果对命中次数：
   优先读取条件结果对自身命中次数。
   若当前结构没有条件结果对命中次数字段或索引，
   输出 `缺条件结果对命中次数来源`，
   不用方法公共统计命中次数、最近连续成功次数或候选命中次数替代。
```

验收：

```text
Debug x64 构建通过。
自检日志中的本能方法检查只出现：
缺对应动作 / 缺条件结果对 / 条件结果对命中次数不足 / 缺条件结果对命中次数来源。
rg 确认自检需求目标不再使用 `方法状态=好用` 作为正式入树目标。
```

### P3 替换自检父需求硬分流

目标：

把 `私有_裁决自检候选父需求_线程侧` 从目标特征文本硬分流改为：

```text
原子目标完整性检查
-> 自检候选目标投影裁决
-> 父需求选择
-> 权重选择
```

具体要求：

```text
1. `方法状态` 不再作为本能方法自检的正式目标口径。
2. 缺动作、缺条件结果对、条件结果对命中次数不足分别生成原子目标。
3. 先用固定自我安全 / 服务因果链补投影，再决定父需求。
4. 若本能方法结构缺口属于安全 / 服务链上的方法就绪条件，挂到局部来源父需求或对应根下维护管理子需求。
5. 只有在固定上下文、原子目标和因果投影补齐后仍无法关联安全 / 服务时，
   才进入方法维护 / 自维护管理分支。
6. 无投影、无原子目标且不能补齐的候选继续保留为报告或弹错。
```

验收：

```text
Debug x64 构建通过。
rg 确认不存在“方法状态暂由安全根承接调度”口径。
rg 确认不存在“目标特征=方法状态；不挂安全/服务根需求”作为最终挡板。
```

### P4 建立或复用管理分支需求

目标：

为无直接安全 / 服务父链但可维护的自检缺口提供正式需求树位置：

```text
方法维护管理需求
学习维护管理需求
自我结构维护管理需求
世界模型维护管理需求
```

实现口径：

```text
1. 管理分支本身是需求树组织节点，仍使用已有需求主信息表达。
2. 不新增 AND / OR / 因果子链类型字段。
3. 通过结构角色、目标宿主、目标特征、父子关系和派生归因表达。
4. 同一父需求 + 同一目标宿主 + 同一目标特征 + 方向重叠时复用 / 合并。
```

验收：

```text
自检产生的维护类需求不再集中成为安全根直接子需求。
控制面板需求树能看出维护分支父子关系。
```

2026-06-04 实施状态：

```text
已落地最小代码切片。
维护 / 学习 / 自维护投影不再直接退为“不入树”，而是先确保需求树根下的维护管理分支；
具体自检缺口继续通过统一需求树更新指令挂到管理分支下。
管理分支使用现有需求主信息、目标特征、父子关系和派生归因表达，不新增字段。
维护分支及其子需求默认安全 / 服务权重为 0 / 0，不借方法维护域偷带安全权重。
Debug x64 构建通过；未跑自然样本与控制面板展示验收。
```

### P5 补安全根任务来源绑定与局部来源解释

目标：

让自检候选固定承认安全根任务作为来源任务，再在可得时补充更具体的局部来源链。
局部来源链用于增强父链解释，不作为自检缺口能否归入安全 / 服务因果链的唯一前提：

```text
固定来源任务=安全根任务
固定来源需求=安全根任务对应的安全根需求
局部来源需求
局部来源子任务
目标方法
来源因果
```

实现要求：

```text
1. 自检线程仍只报候选，不直接裁决。
2. 自我线程收到候选后固定读取安全根任务 / 安全根需求作为来源锚点。
3. 若当前运行态尚未有安全根任务，不由自检线程创建任务；
   只记录“安全根任务来源绑定缺失”，由自我线程按正式任务发起流程补齐。
4. 能反查更具体的局部来源子任务及其来源需求时，优先挂到该局部来源需求下。
5. 不能反查局部来源时，仍以安全根任务和固定安全因果链作为父链锚点，
   再按目标投影选择安全根管理子需求或维护管理分支。
6. 局部来源链缺失时不能把维护类候选直接平铺到安全根直接子项。
```

验收：

```text
日志显示自检候选入树时的父需求来源：
固定来源任务=安全根任务 / 固定来源需求=安全根需求 /
安全根任务来源绑定缺失 / 局部来源需求 / 局部来源子任务 /
目标投影 / 管理分支 / 报告保留。
```
