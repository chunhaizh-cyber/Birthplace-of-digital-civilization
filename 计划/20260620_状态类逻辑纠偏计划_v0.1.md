# 状态类逻辑纠偏计划 v0.1

日期：2026-06-20

状态：由因果类外部数据读取纠偏触发；第一优先只读函数已闭合；2026-06-20 已闭合 1.1 状态创建事件枚举与内部参数结构清理、1.2 状态清理问题快照结构化纠偏。2026-06-20 由特征类 1.2 审查新增“读取状态特征和值”只读函数缺口，按跨类缺口转向规则临时提升为第一优先。

## 0. 目标

补齐状态类只读功能函数，让因果类不再直接解释 `状态节点主信息类` 字段；同时登记状态类剩余结构体清理 / 纠偏缺口，后续按计划索引自动闭环调度执行。

当前触发缺口：

```text
因果类.cpp 直接读取：
    状态节点主信息类::状态主体
    状态节点主信息类::状态特征
```

## 1. 第一优先缺口

建议函数：

```cpp
状态节点类* 按主键解析状态节点(const std::string& 主键) const noexcept;

bool 读取状态主体与特征(
    const 状态节点类* 状态,
    基础信息节点类*& 状态主体,
    特征节点类*& 状态特征) const noexcept;

特征节点类* 读取状态特征(const 状态节点类* 状态) const noexcept;
基础信息节点类* 读取状态主体(const 状态节点类* 状态) const noexcept;
```

实现边界：

```text
1. 函数归属 状态类.h/.cpp。
2. 不新增状态主信息字段。
3. 不创建状态，不改状态值，只读解析。
4. 主键解析不允许隐式创建节点。
```

## 1.1 已登记待执行缺口：状态创建事件枚举与内部参数结构清理

触发点：

```text
状态类剩余结构体必要性审查发现：
    枚举_存在状态事件 只作为创建 / 变化入口提示，未写入 状态节点主信息类。
    状态创建参数 只在 状态类.cpp 内部临时打包参数，没有外部构造调用。
    状态节点事实已经由 场景 + 状态主体 + 状态特征 + 状态值 + 发生 / 收到时间 表达。
```

处理目标：

```text
1. 删除 枚举_存在状态事件。
2. 删除 状态创建参数。
3. 删除 创建状态(场景, const 状态创建参数&, 后处理) 和 记录状态到场景(场景, const 状态创建参数&, 后处理) 这类内部 DTO 入口。
4. 清理 创建内部状态 / 记录内部状态到场景 / 创建世界状态 / 记录世界状态到场景 / 记录内部特征状态 的 事件 参数。
5. 保留状态节点权威事实字段：状态主体、状态特征、状态值、发生时间、收到时间、对应信息节点。
```

执行边界：

```text
1. 本缺口当前只登记，不提升为计划索引当前主动计划。
2. 删除时不得新增兼容枚举、兼容参数包或旧入口适配层。
3. `是否变化` 仍按既有口径视为创建提示 / 显示缓存，不得提升为状态变化权威事实。
4. 状态变化权威判断仍由动态初始 / 结果状态或二次特征比较得到。
5. 若删除公开函数参数导致调用方缺少更明确入口，优先拆成状态类命名函数，不新增平行结构体。
```

## 1.2 已登记待执行缺口：状态清理问题快照结构化纠偏

触发点：

```text
结构_状态清理问题快照 当前由 状态类 在活动状态索引超限且无法清理时写入。
自检线程会读取该快照并提交“状态清理阻塞”报告，因此它不是单纯显示结构。
但当前结构包含 场景主键 和 摘要 字符串，摘要还会进入自检候选说明，存在文本承载机器链路风险。
```

处理目标：

```text
1. 暂不裸删 结构_状态清理问题快照，因为自检线程仍在读取它。
2. 先把快照收束为结构化事实：场景节点引用或可解析引用、活动状态数量、活动状态上限、目标清理数量、已清理数量、被引用状态数量、记录时间。
3. 删除或下沉 摘要 / 场景主键 这类显示文本；显示层需要时临时从结构化字段生成。
4. 自检线程提交状态清理阻塞时，应读取结构化字段构造去重键和候选事实，不把日志摘要作为机器依据。
```

执行边界：

```text
1. 本缺口当前只登记，不提升为计划索引当前主动计划。
2. 若需要调整自检线程承接入口，先按跨类缺口转向规则登记到自检线程对应计划，不在状态类里临时拼文本。
3. 不新增 JSON、自由文本字段或显示摘要字段作为系统逻辑承载。
4. 闭合前不得宣称状态清理阻塞自检链已结构化闭环。
```

## 2. 跨类缺口转向规则

执行本计划时，如果发现当前切片必须依赖其它类新增或补齐功能函数，按以下规则处理：

```text
1. 后续任意类缺少当前切片所需功能函数时，不在状态类或调用方临时拼字段、解释其它类主信息或新增平行结构体。
2. 若对应类已有逻辑纠偏计划，则把当前缺口加入该计划，并放到第一优先位置。
3. 若对应类没有逻辑纠偏计划，则生成 `计划/YYYYMMDD_<类名>逻辑纠偏计划_v0.1.md`，并把当前缺口作为第一优先切片。
4. 新生成或被修改的逻辑纠偏计划必须包含本“跨类缺口转向规则”，保证后续继续发现缺口时仍按同一调度口径处理。
5. 更新 `计划/计划索引.md`：把新生成或新修改的计划临时提升为第一优先计划；原计划和原切片记录为返回点。
6. 只执行新计划的第一优先缺口切片，不顺带推进新计划后续候选项。
7. 第一优先缺口闭合后，立即停止该新计划，更新计划索引返回原计划和原切片。
8. 若第一优先缺口切片不能闭合，保留该计划为当前阻塞，不回到原计划继续补丁化绕过。
```
