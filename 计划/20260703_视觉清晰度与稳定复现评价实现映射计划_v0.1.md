把 D9 详细设计中的评价对象和收束规则映射到后续最小代码实施切片：

```

后续代码只允许输出候选、评分、计数、状态值域、缺口和可回查证据句柄；不得写世界树事实、稳定存在体素、`C -> E` 最终归属、需求满足或动作动态。

## 2. 设计条款清单

### 2.1 必须实现

```
1. 先执行 S0 只读代码事实扫描，确认真实字段、函数、枚举、句柄和调用入口。
2. 复用已有外设材料、观察候选、局部体素候选、视觉融合结果和 场景体素先验快照 输入。
3. 以 Q10000 评分、计数、版本、句柄、来源编号、来源帧编号、时间戳、坐标版本、消费状态和状态值域表达评价材料；不得用 `generation` / 代际身份作为稳定复现身份。
4. 判断型状态必须保留评分、计数、版本、句柄和缺口证据，不能脱离收束依据。
5. 清晰度 / 稳定复现 / 先验一致性 / 体素融合前置缺口必须映射到 D5 结构化缺口链。
6. 体素融合前置状态只能作为治理链输入，不能直接更新稳定存在体素。
7. 所有验证必须包含反走样负例。
```

### 2.2 禁止实现

```
1. 不新增长期业务结构体作为清晰度评价包。
2. 不新增普通一阶 布尔值：是否清晰、是否稳定、是否可融合、是否可提交、是否先验一致。
3. 不让外设线程直接写判断型状态作为一阶事实。
4. 不把单帧高清当稳定复现。
5. 不把先验匹配高当 E 当前存在。
6. 不把自由空间冲突当 E 消失。
7. 不把遮挡解释当跟踪成功。
8. 不从 D9 直接调用观察、扫描、识别、跟踪方法入口。
9. 不用日志、说明文本、控制面板、临时结构化文本或错误文案参与机器判断。
```

可实施最小切片建议。
```

### S1：冻结评价输入特征族

把 S0 确认存在的 F / C / 局部体素候选 / 稳定复现 / 先验一致性输入登记到实现注释或计划断点。缺失项只标 `缺入口 / 待补`。

### S2：观察帧清晰度评分

基于深度、空间、帧质量、融合深度、轮廓、未解释区域和低置信计数生成 F 层 Q10000 评分、状态值和阻断原因。

### S3：观察候选清晰度评分

基于像素数量、深度有效率、空间坐标有效率、空间连续性、范围稳定性、轮廓置信度、稳定锚点和像素归属材料生成 C 层评分和缺口。

### S4：跨帧稳定复现评分

基于跨帧簇编号、连续命中、丢失、离散度、稳定命中、来源链、坐标版本和稳定特征样本生成稳定复现评分。

### S5：先验一致性评分

复用视觉融合中的 场景体素先验快照 版本、坐标版本、轴对齐包围盒 命中、最近先验距离、空间重叠、深度一致、材料质量、自由空间冲突和遮挡候选材料生成先验一致性评分。

### S6：局部体素融合前置状态

读取局部体素清晰度、候选清晰度、稳定复现、归属可信性、来源链、坐标版本、一致性和冲突缺口，收束体素融合前置状态。

### S7：缺口标准化

将以下缺口标准化接入 D5：

```
清晰度缺口
稳定复现缺口
坐标稳定缺口
像素归属争议缺口
局部体素清晰度缺口
体素融合前置缺口
先验一致性缺口
自由空间冲突复验缺口
遮挡解释复验缺口
```

### S8：反走样检查和验证

运行验证剧本、`python .\tools\check_specs.py`、`git diff --check`。若有代码修改，按 AGENTS.md 更新函数说明文档和必要实施记录。

## 7. 验证剧本

```
V1 单帧高清：
    清晰度高，但稳定复现未成立，不得确认稳定存在。

V2 多帧稳定：
    连续命中、离散度低，输出稳定复现评分，不直接写 C -> E。

V3 局部体素清晰但归属不明：
    只挂 C 的局部体素证据链，不更新 E 稳定体素。

V4 先验匹配高：
    输出先验一致性评分，不写 E 当前存在。

V5 自由空间冲突：
    输出冲突候选和复验缺口，不写 E 消失。

V6 遮挡解释：
    输出遮挡解释和保留材料，不写跟踪成功。

V7 低清晰材料：
    输出清晰度缺口，不进入体素融合。

V8 来源链 / 坐标版本失配：
    稳定复现阻断，不合并多帧证据。

V9 普通布尔值 负例：
    不得新增普通一阶 布尔值 特征。

V10 check_specs：
    硬问题 = 0，警告 = 0。
```
