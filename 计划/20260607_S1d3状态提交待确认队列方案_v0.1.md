# S1d-3 状态提交待确认队列方案 v0.1

日期：2026-06-07

状态：S1d-3a 结构与快照预备已完成；S1d-3b pending 队列接入已完成；S1d-3c 真实运行顺序验证已完成。

## 1. 目标

```text
把任务工作项入队前的任务状态提交从调用线程同步等待中拆出来；
但工作项在任务状态、动作动态、任务壳快照和状态版本确认前，绝不能进入可派发队列。
```

## 2. 边界

```text
必须保持：
    任务状态变化仍通过 自我_提交任务状态变化 生成动作动态；
    任务管理层不得裸写任务状态；
    worker 不得先执行后补动作动态账；
    工作项状态版本必须来自状态提交后的任务状态快照；
    失败状态提交必须阻断工作项派发并反馈承接结果。

不得修改：
    任务完成、需求满足、价值结算规则；
    外设 / D455 功能线；
    日志模块 flush 策略；
    候选 / 因果 / 基础信息索引。
```

## 3. 当前代码证据

```text
任务模块.管理界面线程.impl.cpp：
    私有_登记等待工作项 先调用 私有_提交界面任务状态变化，成功后才进入等待队列。
    状态提交失败时记录承接失败并拒绝工作项入队。
    状态提交成功后，再从任务状态快照同步 工作项.状态版本。
    后台 worker 派发前通过 私有_工作项状态版本兼容 校验状态版本。

任务模块.管理线程协议.ixx：
    结构_任务工作项 目前有 工作项ID、幂等键、状态版本、租约、重试次数和入队原因；
    没有状态提交确认令牌、确认状态、状态提交失败原因或确认超时字段。
```

结论：

```text
现有路径的顺序是正确的，但调用线程必须同步等待状态提交；
直接把工作项提前放入等待队列会破坏派发顺序；
因此待确认队列必须是等待队列之前的独立 pending 区。
```

## 4. 新增协议草案

新增内部结构，不直接扩散到自我线程请求协议：

```text
结构_任务状态提交确认令牌：
    确认ID
    工作项ID
    任务主键
    目标状态
    目标阶段
    请求场景
    请求时间
    截止时间
    状态提交重试次数

结构_状态提交待确认项：
    原任务治理请求
    原界面承接结果
    原任务工作项
    任务虚拟存在
    请求场景
    调度事件类型
    入队原因
    确认令牌
```

待确认项不得进入 `待筹办队列`、`待执行队列` 或 `在途工作项索引`。

## 5. 时序规则

```text
1. 私有_登记等待工作项 发现需要入队前状态提交时：
       生成状态提交待确认项；
       记录承接状态为“等待任务状态提交确认”；
       放入状态提交待确认队列；
       唤醒状态提交确认线程 / 循环；
       不进入可派发等待队列。

2. 状态提交确认循环取出待确认项：
       调用 私有_提交界面任务状态变化；
       仍通过 自我_提交任务状态变化 生成动作动态；
       失败则记录承接失败，不入队；
       成功则刷新任务状态快照，读取确认后的状态版本。

3. 状态提交成功后：
       把确认后的状态版本写入工作项；
       再调用“不再重复入队前状态提交”的内部入队函数；
       入队后 worker 才能按现有状态版本 / 租约 / 执行前许可门控派发。

4. worker 派发前：
       继续调用 私有_工作项状态版本兼容；
       状态版本错配仍终止 / 死信；
       不新增绕过状态版本的快路径。
```

## 6. 失败与停止收口

```text
状态提交失败：
    更新承接为故障 / 拒绝请求；
    写错误日志；
    不入等待工作项队列。

确认超时：
    未开始执行的待确认项可重排，最多沿用工作项租约重派次数口径；
    超过上限进入死信；
    死信原因必须包含 确认ID、工作项ID、任务主键、目标状态、目标阶段。

停止请求：
    停止时不再取新的待确认项；
    未确认项不派发；
    可记录为停止收口残留，不作为业务失败。
```

## 7. 验收证据

```text
必须看到：
    工作项派发日志晚于同工作项 / 同任务的状态提交确认日志；
    状态提交失败样本不出现 worker 派发；
    状态提交成功样本的工作项状态版本等于确认后的任务状态快照版本；
    任务状态动作动态仍由 自我_提交任务状态变化 生成；
    调用线程的 等待工作项登记/入队前状态提交 耗时明显下降。

仍需观察：
    总体状态提交耗时是否只是转移到确认循环；
    状态提交锁等待是否因确认循环串行化而下降；
    若最慢阶段继续是 私有_执行任务域本能方法，则进入调用侧外层阶段细分与规格确认快路径小切片。
```
