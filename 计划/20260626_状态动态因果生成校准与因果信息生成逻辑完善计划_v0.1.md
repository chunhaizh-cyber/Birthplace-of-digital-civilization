# 状态动态因果生成校准与因果信息生成逻辑完善计划 v0.1

日期：2026-06-26

## 0. 定位

本计划是 `计划/20260626_因果链驱动扫描需求自然生长计划_v0.1.md` 的配套校准计划，用于把“状态生成 -> 动态生成 -> 动作信息归纳 -> 因果样本入族 -> 因果分支归纳 -> 任务筹办消费”的底层链路按最新规范收齐。

2026-06-26 修订：本计划已提升为 `计划/计划索引.md` 第 1 章当前主动队列，当前执行切片为 P0a。提升原因是当前需要重新梳理状态、动态、因果等信息的生成，再返回扫描需求自然生长链。

核心改造点：

```text
动态负责把变化说成动作；
因果负责把动作说成规律。

动态不描述流程本身；
动态只描述存在在流程中的变化。

动态信息通过记录不同时间状态之间的变化，归纳出动作信息；
动作信息再作为因果信息中的“动作”字段，连接前置状态和结果状态。

因此，因果信息不是直接保存零散特征变化，
而是保存“在某种状态下，某个动作发生，会使存在进入另一种状态”的规则。

动态信息只有两条生成途径：
    1. 状态 -> 动态；
    2. 本能方法或治理函数 -> 动作动态。

两套动态互补：
    状态迁移动态补结果侧，证明某存在的某特征实际从 V0 变成 V1；
    动作动态补来源侧，证明某本能方法、治理函数或自我动作实际发生；
    只有动作动态落到同一存在、同一特征类型，
    且动作动态时间段被状态迁移动态时间段包含时，
    二者才构成同一次事实的双账记录，并可进入动作致变因果候选。

场域归属固定为：
    内部治理状态、动态和因果存储在自我内部世界；
    外部场景状态和动态存储在自我当前所在场景；
    观察材料在入账前只属于观察证据层，不能直接当作当前场景事实。
```

## 2. 本计划只解决什么

只解决一条底层生成总账：

```text
状态信息生成
-> 相邻前状态确认
-> 状态迁移动态生成
-> 同源变化匹配 / 同源组复算或绑定
-> 动态序列 / 动作动态归纳为动作信息
-> 动作信息进入因果样本
-> 主果变化锚点入因果族
-> 样本与分支做交集 / 差异 / 反例比较
-> 状态变化因果候选 / 动作致变因果候选更新
-> 因果类 / 世界树包装函数可查询
-> 任务筹办按两类因果消费并生成缺口或方法候选
```

同时校准两条动态生成路径和它们的互补关系：

```text
路径 A：状态 -> 动态
    状态生成入口
    -> 同宿主同特征相邻前态
    -> 状态迁移动态
    -> 状态变化因果候选 / 状态变化线索

路径 B：本能方法 / 治理函数 -> 动作动态
    本能方法或治理函数执行
    -> 明确动作来源、来源方法、动态主体和记录场域
    -> 动作动态
    -> 与实际状态迁移动态完成同一存在、同一特征类型、时间段包含匹配
    -> 动作信息
    -> 动作致变因果候选

互补规则：
    状态迁移动态不能伪造来源方法；
    动作动态不能用需求目标冒充实际结果端点；
    只有完成同源匹配后，才允许进入动作致变因果候选。
```

## 3. 本计划不解决什么

```text
1. 不直接实现扫描业务链，不补扫描专用因果模板。
2. 不把需求节点当作因果信息来源。
3. 不用派生需求当前 / 目标状态冒充动作实际结果状态端点。
4. 不恢复旧因果边类型、旧目标投影维度、旧轻量因果链或旧兼容入口。
5. 不新增因果摘要字段、解释字段、自由文本字段或临时 JSON 作为机器判断依据。
6. 不把方法 ID 直接等同为因果信息中的动作；方法只是动作信息的生成、识别或确认来源。
7. 不把因果族样本树写成动作动态之外的并行权威账本。
8. 不用模拟测试、夹具测试、伪造入口、伪造动作动态或旧 `--*-check` 回归命令验收。
9. 不提前宣称扫描需求自然生长闭合、自我苏醒完成或初步成熟完成。
```

### P1：状态生成校准

目标：

```text
状态生成必须先确认宿主、特征类型、状态值和相邻前状态。
宿主必须是明确存在、场景、虚拟存在或因果对象。
只读查询不得隐式创建状态或结构。
状态生成后处理必须明确是否应生成状态迁移动态。
```

关键规则：

```text
1. 同宿主同特征已有前态时，生成 初始状态 -> 结果状态 的状态迁移动态。
2. 首次状态只能建立当前状态或当前状态基准；不得伪造成“发现”或状态变化。
3. 缺宿主、缺特征类型、缺状态值或无法判定相邻前态时，返回结构化缺口，不静默跳过。
4. 状态类只负责状态事实和必要索引，不直接生成任务、需求或结算判断。
```

完成证据：

```text
状态生成入口均可说明：是否创建状态、是否命中前态、是否生成状态迁移动态、缺口在哪里。
```

### P2：动态生成校准

目标：

```text
按最新规范收束两类动态生成入口：
1. 状态信息生成时自动生成状态迁移动态。
2. 治理函数和本能方法执行时直接生成方法动作动态。
所有动态都必须有动态主体和记录场域，不允许流程名、线程名或函数名作为动态主体。
```

互补关系：

```text
状态迁移动态：
    负责结果侧。
    回答：哪个存在 / 关系的哪个特征实际从什么值变成什么值。

动作动态：
    负责来源侧。
    回答：哪个本能方法、治理函数、任务步骤或自我动作实际发生。

同源绑定：
    状态迁移动态 + 动作动态
    -> 同源变化匹配 / 可复算同源组
    -> 动作信息
    -> 动作致变因果候选。
```

同源绑定硬规则：

```text
状态迁移动态：
    E.FT-X = V0@T0 -> V1@T1

动作致变动态：
    E.FT-X 在动作 A 作用下变化，动作时间段 [Ta0, Ta1]

同源成立：
    E 一致；
    FT-X 一致；
    T0 <= Ta0；
    Ta1 <= T1。

允许采样误差 ε：
    T0 - ε <= Ta0；
    Ta1 <= T1 + ε。
```

来源动作、来源方法、输入 / 输出场景、来源低层动态、因果证据动态样本只做辅助解释、证据链闭合和排他性校验，不替代同一存在、同一特征类型和时间段包含三项核心条件。

场域规则：

```text
内部治理动态：
    动态主体是任务虚拟存在、方法虚拟存在、方法执行实例、目标、需求、信息缺口或因果对象；
    状态、动态和因果证据归属自我内部世界。

外部场景动态：
    动态主体是当前场景中的场景存在或场景关系；
    状态和动态归属自我当前所在场景。

自我动作影响外部场景：
    内部世界记录自我动作发生和治理过程；
    当前场景记录外部存在 / 关系实际变化；
    二者只能通过证据链 / 同源变化证据组互证，不能混存或互相冒充。
```

状态迁移动态要求：

```text
宿主一致；
特征类型一致；
初始状态和结果状态完整；
动态类型明确为状态迁移 / 无动作状态变化；
可绑定同源变化证据组；
不携带伪造来源方法。
```

方法动作动态要求：

```text
必须绑定来源方法；
必须有动作语义；
必须有输入场景和输出结果场景或等价事实场景；
必须有动态主体；
必须有记录场域；
必须有实际初始状态和实际结果状态端点；
必须能匹配同源状态迁移动态，或回解可复算同源组；
动作时间段必须被状态迁移时间段包含；
不得用需求当前 / 目标状态冒充实际结果。
```

完成证据：

```text
动态生成日志能区分状态迁移动态、主动动作动态、被动动作动态和动作尝试 / 缺证据回执。
每条动态均可回查动态主体、记录场域、初始状态、结果状态和证据来源。
动作动态若缺同源状态迁移动态，只能作为动作事件或缺证据回执。
```

### P3：动作信息归纳校准

目标：

```text
动态信息不直接等同因果动作；动态序列和动作动态必须先归纳为动作信息，再进入因果信息。
内部治理动态可以因来源动作明确而直接抽取动作信息，但仍必须先确认动态主体是任务虚拟存在、方法虚拟存在、方法执行实例存在、需求虚拟存在、目标虚拟存在、信息缺口虚拟存在或因果对象。
```

动作信息最小字段：

```text
动作类型；
动作主体；
动作客体；
动作方向 / 参数；
动作持续时间；
动作来源类型：自我动作 / 外界动作 / 治理动作；
动作来源方法：生成 / 识别 / 确认该动作信息的方法；
动作证据动态集合。
```

三类动作边界：

```text
自我动作：自我主动执行动作，结果作用于自我或环境状态。
外界动作：外部存在发生动作，结果作用于场景状态。
治理动作：系统内部处理信息对象，结果作用于信息状态。
```

两套动作信息生成链：

```text
内部治理 / 自我方法动作信息：
    来源动作、来源方法、来源任务步骤通常明确；
    从方法动作动态和同源状态迁移动态中抽取动作信息；
    结果端点优先来自自我内部世界中的虚拟存在状态迁移动态。

外部场景动作信息：
    来源动作通常不明确；
    从当前场景存在 / 场景关系动态中提取运动基元和复杂动作候选；
    经 `计划/20260626_自我所在场景复杂动作提取计划_v0.1.md` 的 ContainsAction 判定后，
    才能作为外部场景因果样本的动作候选。
```

方法与动作边界：

```text
方法是动作信息的生成器、识别器或确认器；
动作信息才是因果链里的“动作”。
因果信息不得只把方法 ID 写成动作字段。
流程名、线程名和裸函数名不得作为因果动作字段。
```

P3b 动作信息最小字段映射方案：

```text
本方案不新增动作结构体、主信息字段或并行权威账本。
动作信息先作为“既有动态 / 状态 / 因果证据字段的可复算映射视图”使用；
字段缺失时登记缺口，不用自由文本补假字段。
```

| 动作信息字段 | 内部治理 / 自我方法动作映射 | 外部场景动作映射 | 缺失处理 |
| --- | --- | --- | --- |
| 动作类型 | 优先取因果主信息的因动作语义键；其次取因动作名称 / 来源动作名；再其次取动态类型。 | 来自外部动作提取计划的运行期动作候选类型，必须经 ContainsAction 判定。 | 不能确认动作类型时，只保留状态变化线索，不写因果动作项。 |
| 动作主体 | 优先取动态主体；治理动作通常是任务虚拟存在、方法虚拟存在、方法执行实例存在或自我存在。 | 取当前场景中发生动作的已确认存在 / 关系主体。 | 动作主体不明时，不生成已确认动作，只登记动作候选缺主体。 |
| 动作客体 | 优先从结果状态主体、输出结果场景中的被作用对象、输入参数场景中的目标对象读取。 | 取被接触、支撑变化、位置变化或关系变化影响的场景存在 / 关系客体。 | 客体非必需；但他物作用因果缺客体时只能降级为弱候选。 |
| 动作方向 / 参数 | 从动态特征、状态值差、输入参数场景、来源输出场景读取。 | 从位置差、速度方向、支撑 / 接触 / 遮挡关系变化和状态值差读取。 | 参数不足时不得用自然语言补齐，只记录缺参数。 |
| 动作持续时间 | 取动态主信息时间窗。 | 取动作候选覆盖的动态片段组时间窗。 | 时间窗缺失时不能通过时间绑定，只能登记待复验。 |
| 动作来源类型 | 来源动作有效且来自方法动作动态时为自我动作或治理动作；主体是治理虚拟存在时为治理动作。 | 主体属于当前场景外部存在 / 关系时为外界动作。 | 来源类型不明时不进入任务筹办方法候选。 |
| 动作来源方法 | 取动态来源动作 / 因果因方法模板；来源动作名作为动作名称，不等同完整动作信息。 | 取识别 / 生成动作候选的方法；未实现前只能记录为缺来源识别方法。 | 缺来源方法不一定否定外部动作候选，但不得伪装为自我方法动作动态。 |
| 动作证据动态集合 | 当前动态、来源低层动态、同来源流聚合片段、因果证据动态样本。 | 同时间窗内主体动态、关系动态、目标特征变化动态和排他性反例动态。 | 证据动态不足时只生成缺证据项，不升级为已确认包含动作。 |

P3b 使用规则：

```text
1. 内部治理动作可以从来源动作 / 来源方法 / 来源任务步骤直接抽取动作类型，
   但仍要绑定动态主体和结果状态端点。

2. 外部场景动作不得从方法 ID 推出；
   必须从当前场景存在 / 关系的状态迁移动态中提取候选，
   再经过时间绑定、主体 / 客体绑定、特征结果绑定和证据链绑定。

3. 因果类现有字段：
       因方法模板
       因动作语义键
       因动作名称
   只作为动作槽位的简化承载。
   当需要完整动作信息时，必须回到证据动态集合复算。

4. 如果某个动作字段无法从既有结构复算，
   先登记字段缺口；
   不新增说明性摘要字段，不用日志、文本或 JSON 冒充机器判断字段。
```

完成证据：

```text
至少一类真实动态能回查到动作信息：动态主体、记录场域、动作类型、动作主体、来源类型、来源方法和证据动态集合均完整。
```

### P4：同源变化证据组校准

目标：

```text
同一次特征变化相关的状态迁移动态、动作致变动态、状态变化因果和动作致变因果必须能绑定或回解到同一个同源变化证据组 / 可复算同源组。
```

实施边界：

```text
1. 优先复用现有基础信息节点、动态引用或因果证据结构。
2. 新增结构前必须确认不能由现有因果主信息、证据动态样本、动态链和基础信息节点表达。
3. 结算和需求满足按同源变化证据组或可复算同源组去重。
4. 后补动作来源时，不改写原状态变化因果，只补建动作致变动态和动作致变因果并绑定或回解到同源组。
5. P4b 当前采用无新增结构表达：同一存在 + 同一特征类型 + 动作动态时间段包含于状态迁移动态时间段。
6. 来源动作、来源方法、输入 / 输出场景、来源低层动态和因果证据动态样本只作为辅助校验，不构成同源核心。
```

P4b 无新增结构表达方案：

```text
不新增同源变化证据组结构体。
不新增动作提取结构体。

优先使用现有状态 / 动态 / 因果证据链复算：
    状态迁移动态 D_state = E.FT-X V0@T0 -> V1@T1；
    动作致变动态 D_action = E.FT-X 在动作 A 作用下变化，[Ta0, Ta1]；
    同源成立 = E 一致 + FT-X 一致 + T0 <= Ta0 + Ta1 <= T1。

若采样误差存在，可按 ε 放宽：
    T0 - ε <= Ta0；
    Ta1 <= T1 + ε。
```

P4c 下一切片：

```text
只读核查现有动态 / 状态结构是否能回解：
    动态主体；
    特征类型；
    初始状态发生时间；
    结果状态发生时间；
    动作执行开始 / 结束时间或动作动态自身 [T0, T1]。

若不能回解，登记时间端点读取缺口；
不得通过来源动作、输入 / 输出场景或证据样本冒充同源核心。
```

完成证据：

```text
一次真实动作引发状态变化时，日志能回查同一组内的状态迁移动态、动作动态和因果候选。
```

### P5：因果样本入族与分支归纳

目标：

```text
动态后处理不直接落定“已验证因果”，而是生成因果样本并进入主果变化锚点下的因果族。
```

关键链路：

```text
状态迁移动态 / 方法动作动态
-> 动作信息
-> 主果变化锚点
-> 候选条件项集合
-> 因果样本
-> 因果族
-> 因果分支
-> 硬交集 / 软交集 / 分化条件 / 动作候选 / 反例
```

候选条件项分层：

```text
前置状态：可作为条件候选。
区间内动态：伴随原因、共同结果或分支候选。
动作 / 方法动态：满足状态端点后可形成动作致变因果候选。
后置状态：只能作为可能后果或副作用候选。
未知时序：弱候选，不进入硬交集核心。
```

完成证据：

```text
新增样本能与既有分支比较，并更新基础计数；单样本不得标记已验证。
```

### P7：任务筹办和学习层消费校准

目标：

```text
任务筹办只把匹配当前条件的主动动作致变因果作为直接方法候选；其中动作致变因果的动作字段必须是动作信息，不得只用方法 ID 代替。
状态变化因果、条件伴随分支、未知来源分支只能生成学习、练习、观察、扫描、证据补齐或来源归因需求。
```

场域消费边界：

```text
内部治理动作致变因果：
    结果端点在自我内部世界闭合时，可服务任务治理、练习、筹办缺口补齐和内部方法状态推进。

自我主动动作致变因果：
    动作来源可映射到自我可执行方法，且当前条件匹配时，才允许进入任务筹办方法候选。

外部场景动作致变因果：
    证据回指当前场景状态 / 动态；
    可用于解释、预测、需求投影、观察补齐和学习；
    未完成自我可执行方法映射前，不得直接进入任务筹办方法候选。

状态变化因果：
    证明变化存在；
    只能作为变化线索、学习线索、观察线索或证据补齐线索。
```

消费顺序：

```text
1. 查询目标状态动作致变因果分支。
2. 找到主动动作且条件匹配时，进入候选方法。
3. 找不到动作致变因果时，查询状态变化因果 / 状态变化线索分支。
4. 有状态变化但无动作：生成补动作学习需求。
5. 有动作但结果不稳定：生成补条件、练习、参数边界或反例验证需求。
6. 连状态变化因果都没有：生成观察、尝试或因果补完需求。
```

完成证据：

```text
任务筹办日志明确区分：动作致变候选、状态变化线索、补动作学习、补条件学习、反例验证、代码缺陷转开发诊断。
```
