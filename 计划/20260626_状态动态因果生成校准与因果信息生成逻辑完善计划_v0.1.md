# 状态动态因果生成校准与因果信息生成逻辑完善计划 v0.1

日期：2026-06-26

## 0. 定位

本计划是 `计划/20260626_因果链驱动扫描需求自然生长计划_v0.1.md` 的配套校准计划，用于把“状态生成 -> 动态生成 -> 动作信息归纳 -> 因果样本入族 -> 因果分支归纳 -> 任务筹办消费”的底层链路按最新规范收齐。

本计划不改变 `计划/计划索引.md` 第 1 章当前主动队列；执行前需用户明确切入，或当前 P1c/P0.5b 真实阻塞点证明必须先校准本链路。

核心改造点：

```text
动态负责把变化说成动作；
因果负责把动作说成规律。

动态不描述流程本身；
动态只描述存在在流程中的变化。

动态信息通过记录不同时间状态之间的变化，归纳出动作信息；
动作信息再作为因果信息中的“动作”字段，连接前置状态和结果状态。

因此，因果信息不是直接保存零散特征变化，
而是保存“在某种状态下，某个动作发生，会使存在进入另一种状态”的规则。
```

## 2. 本计划只解决什么

只解决一条底层生成链：

```text
状态信息生成
-> 相邻前状态确认
-> 状态迁移动态生成
-> 同源变化证据组绑定
-> 动态序列 / 动作动态归纳为动作信息
-> 动作信息进入因果样本
-> 主果变化锚点入因果族
-> 样本与分支做交集 / 差异 / 反例比较
-> 状态变化因果候选 / 动作致变因果候选更新
-> 因果类 / 世界树包装函数可查询
-> 任务筹办按两类因果消费并生成缺口或方法候选
```

同时校准治理函数和本能方法直接生成动作动态的链路：

```text
治理函数 / 本能方法执行
-> 方法动作动态生成
-> 从动态主信息和证据动态集合归纳动作信息
-> 来源方法 / 动作语义 / 输入场景 / 输出结果场景 / 状态端点齐备
-> 绑定同源状态迁移动态或同源变化证据组
-> 动作致变因果候选入因果族分支
```

## 3. 本计划不解决什么

```text
1. 不直接实现扫描业务链，不补扫描专用因果模板。
2. 不把需求节点当作因果信息来源。
3. 不用派生需求当前 / 目标状态冒充动作实际结果状态端点。
4. 不恢复旧因果边类型、旧目标投影维度、旧轻量因果链或旧兼容入口。
5. 不新增因果摘要字段、解释字段、自由文本字段或临时 JSON 作为机器判断依据。
6. 不把方法 ID 直接等同为因果信息中的动作；方法只是动作信息的生成、识别或确认来源。
7. 不把因果族样本树写成动作动态之外的并行权威账本。
8. 不用模拟测试、夹具测试、伪造入口、伪造动作动态或旧 `--*-check` 回归命令验收。
9. 不提前宣称扫描需求自然生长闭合、自我苏醒完成或初步成熟完成。
```

### P1：状态生成校准

目标：

```text
状态生成必须先确认宿主、特征类型、状态值和相邻前状态。
宿主必须是明确存在、场景、虚拟存在或因果对象。
只读查询不得隐式创建状态或结构。
状态生成后处理必须明确是否应生成状态迁移动态。
```

关键规则：

```text
1. 同宿主同特征已有前态时，生成 初始状态 -> 结果状态 的状态迁移动态。
2. 首次状态只能建立当前状态或当前状态基准；不得伪造成“发现”或状态变化。
3. 缺宿主、缺特征类型、缺状态值或无法判定相邻前态时，返回结构化缺口，不静默跳过。
4. 状态类只负责状态事实和必要索引，不直接生成任务、需求或结算判断。
```

完成证据：

```text
状态生成入口均可说明：是否创建状态、是否命中前态、是否生成状态迁移动态、缺口在哪里。
```

### P2：动态生成校准

目标：

```text
按最新规范收束两类动态生成入口：
1. 状态信息生成时自动生成状态迁移动态。
2. 治理函数和本能方法执行时直接生成方法动作动态。
所有动态都必须有动态主体和记录场域，不允许流程名、线程名或函数名作为动态主体。
```

状态迁移动态要求：

```text
宿主一致；
特征类型一致；
初始状态和结果状态完整；
动态类型明确为状态迁移 / 无动作状态变化；
可绑定同源变化证据组；
不携带伪造来源方法。
```

方法动作动态要求：

```text
必须绑定来源方法；
必须有动作语义；
必须有输入场景和输出结果场景或等价事实场景；
必须有动态主体；
必须有记录场域；
必须有实际初始状态和实际结果状态端点；
必须能绑定同源状态迁移动态或同源变化证据组；
不得用需求当前 / 目标状态冒充实际结果。
```

完成证据：

```text
动态生成日志能区分状态迁移动态、主动动作动态、被动动作动态和动作尝试 / 缺证据回执。
```

### P3：动作信息归纳校准

目标：

```text
动态信息不直接等同因果动作；动态序列和动作动态必须先归纳为动作信息，再进入因果信息。
内部治理动态可以因来源动作明确而直接抽取动作信息，但仍必须先确认动态主体是任务虚拟存在、方法虚拟存在、方法执行实例存在、需求虚拟存在、目标虚拟存在、信息缺口虚拟存在或因果对象。
```

动作信息最小字段：

```text
动作类型；
动作主体；
动作客体；
动作方向 / 参数；
动作持续时间；
动作来源类型：自我动作 / 外界动作 / 治理动作；
动作来源方法：生成 / 识别 / 确认该动作信息的方法；
动作证据动态集合。
```

三类动作边界：

```text
自我动作：自我主动执行动作，结果作用于自我或环境状态。
外界动作：外部存在发生动作，结果作用于场景状态。
治理动作：系统内部处理信息对象，结果作用于信息状态。
```

方法与动作边界：

```text
方法是动作信息的生成器、识别器或确认器；
动作信息才是因果链里的“动作”。
因果信息不得只把方法 ID 写成动作字段。
流程名、线程名和裸函数名不得作为因果动作字段。
```

完成证据：

```text
至少一类真实动态能回查到动作信息：动态主体、记录场域、动作类型、动作主体、来源类型、来源方法和证据动态集合均完整。
```

### P4：同源变化证据组校准

目标：

```text
同一次特征变化相关的状态迁移动态、动作致变动态、状态变化因果和动作致变因果必须绑定同一个同源变化证据组。
```

实施边界：

```text
1. 优先复用现有基础信息节点、动态引用或因果证据结构。
2. 新增结构前必须确认不能由现有因果主信息、证据动态样本、动态链和基础信息节点表达。
3. 结算和需求满足按同源变化证据组去重。
4. 后补动作来源时，不改写原状态变化因果，只补建动作致变动态和动作致变因果并绑定同源组。
```

完成证据：

```text
一次真实动作引发状态变化时，日志能回查同一组内的状态迁移动态、动作动态和因果候选。
```

### P5：因果样本入族与分支归纳

目标：

```text
动态后处理不直接落定“已验证因果”，而是生成因果样本并进入主果变化锚点下的因果族。
```

关键链路：

```text
状态迁移动态 / 方法动作动态
-> 动作信息
-> 主果变化锚点
-> 候选条件项集合
-> 因果样本
-> 因果族
-> 因果分支
-> 硬交集 / 软交集 / 分化条件 / 动作候选 / 反例
```

候选条件项分层：

```text
前置状态：可作为条件候选。
区间内动态：伴随原因、共同结果或分支候选。
动作 / 方法动态：满足状态端点后可形成动作致变因果候选。
后置状态：只能作为可能后果或副作用候选。
未知时序：弱候选，不进入硬交集核心。
```

完成证据：

```text
新增样本能与既有分支比较，并更新基础计数；单样本不得标记已验证。
```

### P6：因果类功能函数和世界树包装入口

目标：

```text
因果族、样本、分支、交集和反例查询全部走因果类功能函数；世界树只提供薄包装入口。
```

建议函数方向：

```cpp
查询主果变化因果族(...);
查询目标状态动作致变因果(...);
查询目标状态变化因果(...);
查询动态归纳动作信息(...);
查询动作信息证据动态集合(...);
查询因果分支样本集(...);
查询候选条件项交集(...);
查询因果反例样本(...);
验证动作结果是否出现状态迁移(...);
查询同源变化证据组(...);
```

约束：

```text
1. 新建函数前扫描 说明书/函数功能说明文档.md。
2. 涉及项目自定义类型的共享函数放对应类，不放 全局共享函数类.ixx。
3. 因果类不直接写任务状态、需求满足、安全值或服务值。
4. 外部类不得直接拆读因果主信息字段自行判断因果链。
```

完成证据：

```text
任务筹办、自我线程、需求类等调用方通过因果类或世界树因果包装函数查询，不再本地解释因果主信息。
```

### P7：任务筹办和学习层消费校准

目标：

```text
任务筹办只把匹配当前条件的主动动作致变因果作为直接方法候选；其中动作致变因果的动作字段必须是动作信息，不得只用方法 ID 代替。
状态变化因果、条件伴随分支、未知来源分支只能生成学习、练习、观察、扫描、证据补齐或来源归因需求。
```

消费顺序：

```text
1. 查询目标状态动作致变因果分支。
2. 找到主动动作且条件匹配时，进入候选方法。
3. 找不到动作致变因果时，查询状态变化因果 / 状态变化线索分支。
4. 有状态变化但无动作：生成补动作学习需求。
5. 有动作但结果不稳定：生成补条件、练习、参数边界或反例验证需求。
6. 连状态变化因果都没有：生成观察、尝试或因果补完需求。
```

完成证据：

```text
任务筹办日志明确区分：动作致变候选、状态变化线索、补动作学习、补条件学习、反例验证、代码缺陷转开发诊断。
```

### P8：真实运行验证和回归收束

目标：

```text
用真实运行路径验证状态、动态和因果生成链，不用模拟入口。
```

预测先写：

```text
1. 某个状态生成入口应生成状态节点。
2. 若存在相邻前状态，应生成状态迁移动态。
3. 若本轮存在明确方法动作，应生成方法动作动态并绑定来源方法和实际状态端点。
4. 动态后处理应归纳动作信息，并把动作信息作为因果样本中的动作字段。
5. 因果样本应进入主果变化锚点因果族。
6. 任务筹办只消费动作致变因果为候选方法。
```

## 6. 停止条件

出现以下任一情况，当前切片停止并记录堵点：

```text
1. 发现规范冲突：计划、代码或下级规范与 001 / 007 / 060 上级规范冲突。
2. 需要新增项目承载结构，但无法证明现有项目结构不能表达。
3. 状态生成路径只能用日志或文本表示状态变化，未接入状态节点。
4. 动作动态缺实际状态端点，且调用方试图用需求目标冒充结果。
5. 因果生成必须修改其它类核心入口，且该类已有逻辑纠偏计划未同步。
6. 真实运行出现弹窗或 Debug Error，先转追根因，不得屏蔽。
```
