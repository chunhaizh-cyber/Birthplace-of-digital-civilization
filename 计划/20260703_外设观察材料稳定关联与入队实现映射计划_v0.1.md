## 1. 完整性和可行性检查结论

用户提供的草稿总体可行，已经覆盖 D1 详细设计要求的核心链路：

```text

```

落入计划前必须修订的点：

```text
1. generation 不得写成“文本 generation”并作为机器判断依据；
2. 代码入口均标为 S0 待核，不把草稿中的代码事实直接当作已确认实现；
3. 实施切片统一为 S0-S5，避免和计划索引 P 编号混淆；
4. 每个切片补允许文件、禁止文件、验证方式和父计划回写；
5. 幂等去重切片必须后置，不得在未确认等待项语义前直接改提交逻辑；
6. 普通 bool / 判断型枚举只登记治理债务，本计划不扩大为全量 1175 重构。
```

可行性判断：

```text
S0 只读扫描：可执行；
S1 generation 与来源链映射：条件可行，取决于是否存在合法身份承载；
S2 层级与来源链补强：条件可行，取决于 L1/L2/L3 派生入口是否集中；
S3 报告入队幂等：风险较高，必须在 S0-S2 后执行；
S4 材料页幂等：风险中等，必须避免破坏 TTL 和等待项回查；
S5 速度测量摘要：低风险，只做只读测量输出，不写世界树事实。
```

若 S0 发现必须新增结构体、普通 bool 字段或文本机器键才能继续，则停止执行并回到详细设计 / 本计划修订。

## 3. 设计条款清单

### 3.1 必须实现

```text
M1. L0 报告层级显式写入 0。
M2. L1/L2/L3 报告层级分别写入 1/2/3。
M3. L1 必须可回查 L0 来源原始报告、来源外设帧、来源材料 generation 和坐标版本。
M4. L2/L3 若由 L1 派生，必须继承 L1 的来源链。
M5. 来源材料 generation 必须由结构化一阶材料 / 身份材料收束，不得靠自由文本解析。
M6. 短期材料页必须受 TTL 和过期清理约束。
M7. 等待项绑定和消费标记不得等同事实入账完成。
M8. 采集 / 入队 / 消费速度只能作为一阶测量材料。
M9. S0 必须先确认真实函数名、字段类型、调用路径和验证入口。
```

### 3.2 禁止实现

```text
F1. 不新增结构体解决材料关联、幂等键或稳定材料页。
F2. 不新增普通 bool 特征值。
F3. 不把外设材料写入世界树事实、需求满足或价值结算。
F4. 不把 L1 稳定子集等同于稳定存在。
F5. 不把 D455 候选编号写成世界树稳定存在 ID。
F6. 不把资源句柄字符串解析结果作为机器判断依据。
F7. 不只用报告 ID 做幂等。
F8. 不把报告生成方法版本当作完整材料组 generation。
F9. 不把 FPS、耗时、队列数量直接收束成健康状态或材料可用状态。
F10. 不在本计划中顺手重构观察、扫描、识别、跟踪边界。
```
