# 追根因：练习规格写入特征稳态崩溃 v0.1

当前弹窗：
VS 调试栈显示 `std::vector<特征稳态>::push_back` 崩溃；路径为 `特征类::写入特征值_按参数` -> `世界树类::写入特征_指针` -> `声明形参规格` -> `确认练习规格` -> `确认本能方法专属规格` -> `自我动作实现模块::练习`。

最高优先级原因：
特征写入层对 `特征节点主信息类::当前值 / 近帧候选 / 稳态列表` 没有串行化保护；练习等本能方法环境可被多个任务/线程重复确认规格，同一特征节点的稳态列表扩容存在并发写破坏风险。

当前层级：
L2 本地事实层。

同层疑点记录：
- 候选 A：同一形参规格特征被并发写入，`稳态列表.push_back` 扩容时被另一个写入破坏。证据：崩溃点在 `特征类.cpp` 稳态创建；写入函数直接改 `std::vector`，没有锁。状态：主链。
- 候选 B：`取或创建子特征_按类型` 先读锁查找、再单独创建，查找与创建不是原子操作；并发规格确认可能制造重复形参/字段特征。证据：`特征类.cpp` 先 `查找子特征_按类型`，未命中后 `创建特征_按类型`。状态：同源修复。
- 候选 C：`声明形参规格` 把规格节点作为特征宿主继续挂子特征。证据：既有代码大量使用该结构；当前栈未显示类型校验失败。状态：暂不判为根因。

选中下钻分支：
先修复特征类写入和值结构确保的串行化，防止特征主信息缓存和同宿主子特征结构被并发修改。

主链判断：
本次不是业务缺口，也不是应隐藏的 Debug Error；是世界树/特征层对运行期重复规格确认缺少写入串行化导致的内存破坏风险。

已确认事实：
- `写入特征值_按参数` 在写 `当前值`、`近帧候选`、`近帧时间`、`稳态列表` 时未加锁。
- `写入基础节点指针` 直接调用 `世界树.写入特征_指针`，默认会进入稳态判定。
- `确认练习规格` 会连续声明多个形参规格，并由 `确保本能方法自身环境` 在练习入口执行。
