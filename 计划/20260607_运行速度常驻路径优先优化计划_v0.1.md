## 6. S2 任务巡检脏集 / 事件驱动

前置条件：

```text
S1 已定位稳定最慢阶段；
确认最慢阶段来自重复扫描或重复检查，而不是必须立即修正的语义错误。
```

目标：

```text
把后台循环从每 250ms 全量扫描，改为优先消费需要推进的任务集合。
```

架构形态：

```text
待推进任务索引：
    task_id -> dirty_version
    task_id -> last_checked_version
    task_id -> last_dispatch_result

完成队列：
    completed_work_item -> affected_task_id

等待解除索引：
    wait_condition_key -> task_id 集合

外设材料触发：
    外设 / 模式 / 目标约束 -> 等待项集合

低频兜底巡检：
    每 N 秒执行一次
    每轮限制任务数量或耗时预算
    超预算时记录续扫位置
```

触发源：

```text
任务状态变化 -> 标记脏任务
等待条件解除 -> 标记相关任务
工作项完成 -> 推入完成队列
外设材料到达 -> 标记相关等待项
显式新任务创建 -> 标记新任务
```

硬规则：

```text
脏集只改变“检查谁”，不改变“怎么裁决”。
最终是否可推进仍走现有严格裁决逻辑。
全量巡检保留为低频兜底。
脏集丢失或版本异常时必须回退全量巡检并记录日志。
```

验收预测：

```text
同一真实输入下，任务可推进 / 入队 / 等待 / 不可推进的裁决结果不因脏集改变。
后台常规循环不再每轮扫描全部任务。
兜底巡检能发现遗漏脏任务并记录来源。
巡检超过后台循环间隔的频率明显下降。
```

## 8. S4 短摘要命令离线 / live 拆分

目标：

```text
让摘要类命令默认能读取最近持久快照或最近日志，不再为“看一眼状态”支付完整冷启动成本。
```

命令语义建议：

```text
--demand-tree-growth-summary
    默认离线读取最近快照 / 最近日志。

--demand-tree-growth-summary-live
    明确进入真实环境初始化路径。
```

若为兼容旧用法保留原命令 live 语义，则新增：

```text
--demand-tree-growth-summary-offline
```

推荐选择：

```text
摘要类命令默认离线。
live 命令名称显式标注 live。
输出中标注快照来源、快照时间、是否冷启动、是否中间态。
```

离线诊断必须满足：

```text
不初始化自我环境。
不创建世界树结构。
不确认默认本能方法规格。
不写需求树、任务状态、方法状态、世界事实或价值账。
```

live 诊断必须满足：

```text
保留完整初始化语义。
日志和输出明确标注冷启动成本。
不得把 live 初始化副作用伪装成只读读取。
```

验收预测：

```text
离线摘要命令耗时应接近快照读取和日志解析成本。
live 摘要命令仍可完整初始化并输出冷启动阶段耗时。
离线输出若缺少持久快照，应明确报“无可用快照”，不得隐式创建结构。
```

```text
修复诊断读取带创建副作用的问题，为离线摘要和轻量诊断建立可靠边界。
```

拆分层次：

```text
只读检查：
    检查存在概念系统是否已就绪。
    不创建、不补齐、不拿写路径。

显式确保：
    初始化路径调用。
    可以创建必要结构。

诊断读取：
    只调用只读检查。
    日志标明“只读检查”。
```

改造对象：

```text
私有_计算自我初始化结果
读取自我初始化结果
线程侧读取初始化结果
鱼巢.cpp 初始化失败报告路径
```

验收预测：

```text
只读读取初始化结果不会调用 世界树.初始化存在概念系统()。
显式初始化路径仍会确保存在概念系统。
初始化失败时仍能给出错误报告和日志。
离线诊断路径不会因读取状态而创建结构。
```

## 10. S6 基础信息运行期索引

目标：

```text
降低主键查找、按类型枚举、子节点按类型筛选的基础成本。
```

索引形态：

```text
主键 -> 节点
主信息类型 -> 节点集合
父节点 + 主信息类型 -> 子节点集合
父节点 + 特征类型 -> 子特征集合
父节点 + 存在类型 -> 子存在集合
```

硬规则：

```text
链表 / 基础信息树仍是权威存储。
索引只是可重建运行期加速器。
索引命中后必须校验节点仍属于权威结构。
索引异常时回退链表扫描。
回退必须写日志并计数。
```

分阶段启用：

```text
阶段 1：
    只构建索引，不使用，只做一致性检查。

阶段 2：
    读路径灰度使用，失败回退。

阶段 3：
    统计命中率、回退率、重建次数和校验失败次数。

阶段 4：
    稳定后扩大到控制面板、任务筹办、因果查询和外设材料读取路径。
```

验收预测：

```text
索引启用前后同一主键 / 同一类型枚举结果一致。
索引失败能回退全链扫描。
不会改变基础信息树权威存储结构。
不会因索引命中跳过业务裁决。
```

## 11. S7 方法候选索引和因果路径索引

```text
S6 基础信息索引稳定；

```

方法候选索引：

```text
结果特征类型 -> 方法首节点集合
```

因果路径索引：

```text
主果比较模板 -> 因果候选集合
```

硬规则：

```text
索引只能缩小候选集合。
索引不能跳过候选集填充。
索引不能直接宣称方法可执行。
索引不能直接宣称需求满足。
索引失败必须回退全量扫描。
```

一致性验收：

```text
同一输入下：
    索引路径候选结果 == 全量扫描候选结果

不一致时：
    禁用索引路径
    记录差异样本
    回退全量扫描
```

与旧计划关系：

