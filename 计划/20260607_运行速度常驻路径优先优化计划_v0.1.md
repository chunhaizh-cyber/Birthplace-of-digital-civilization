# 运行速度常驻路径优先优化计划 v0.1

日期：2026-06-07

状态：候选优化计划，尚未纳入当前主动队列。

## 1. 依据

本计划依据以下文件和真实日志证据制定：

```text
AGENTS.md
规范/规范目录.md
计划/计划索引.md
计划/20260531_运行性能优化实施计划_v0.1.md
实施记录/20260607_运行速度架构缺陷检测报告.md
日志/鱼巢_run_20260607.低值g
```

当前关键证据：

```text
短摘要命令：
    .\x64\Debug\鱼巢.exe --demand-tree-growth-summary
    退出码=0
    总耗时约 9673ms
    自我环境初始化约 9565ms
    默认本能方法规格确认约 6533ms
    控制面板摘要轻量快照读取约 58ms

常驻后台巡检：
    任务管理界面线程/任务状态巡检 count=75
    最高耗时=13066643us
    单轮扫描任务=21
    可推进=7
    等待=12
    已有工作项=6
```

结论：

```text
当前慢点必须拆成两类治理：

1. 常驻运行路径慢：
   任务管理后台巡检已经出现 13 秒级单轮耗时，优先级最高。

2. 短命令诊断慢：
   摘要读取本身很快，慢在新进程完整冷启动和默认本能方法规格确认。

候选方法、因果路径和基础信息索引属于规模增长风险，但不应抢在 13 秒巡检定位之前改。
```

## 2. 上级约束

本计划只做性能治理，不改变任务、需求、方法、动作动态和外设事实边界。

硬约束：

```text
1. 不新增模拟样本、伪任务、夹具入口或 --*-check 回归入口。
2. 不为了加速跳过候选集填充。
3. 索引只能缩小候选范围，不能直接宣称方法可执行、需求满足或价值已结算。
4. 任务筹办 / 任务执行仍是任务管理生命周期函数，不注册回本能方法。
5. 诊断路径不得写需求树、任务状态、方法状态、世界事实或价值账。
6. 只读读取和显式确保必须分离。
7. 错误 / 致命日志不得关闭；只能做分级、限流和批量 flush。
8. D455 外设材料不得直接写成世界真值或需求满足事实。
9. 不提前宣称自我苏醒完成或初步成熟完成。
```

## 3. 总路线

执行顺序：

```text
S1 任务巡检细分耗时日志，只定位，不改语义。
S2 任务巡检改为脏集 / 事件驱动，全量巡检降为低频兜底。
S3 日志分级、批量 flush、热路径日志限流。
S4 短摘要命令拆出离线诊断模式，live 模式保留完整初始化。
S5 拆分只读检查和显式确保，清理诊断读取的创建副作用。
S6 基础信息主键 / 类型 / 子节点运行期索引。
S7 恢复方法候选索引和因果主果模板索引。
S8 D455 外设链路单独治理：背压、采样率、等待项索引、材料页句柄化。
```

优先级解释：

```text
S1/S2 是 P0：
    13 秒巡检发生在常驻运行路径，会造成锁竞争、后台追赶和调度延迟。

S3 是 P1：
    日志逐条 flush 和热路径长日志可能放大所有路径耗时，但必须等 S1 定位后再改，避免遮蔽真实热点。

S4/S5 是 P1-P2：
    解决短命令 9-10 秒固定冷启动成本，并为真正离线诊断建立只读地基。

S6/S7 是 P2-P3：
    属于增长性结构优化，影响面大，必须后置、灰度、带回退。

S8 是独立专线：
    D455 是高带宽外设链路，不和摘要命令或普通任务巡检混治。
```

## 4. S1 任务巡检细分耗时日志

目标：

```text
解释 13 秒任务巡检到底慢在何处。
```

允许修改：

```text
任务模块.管理界面线程.impl.cpp
```

不得修改：

```text
任务入队语义
任务裁决规则
等待工作项登记规则
任务状态推进规则
动作动态生成规则
外设事实写入规则
```

新增统计点：

```text
任务头收集耗时
单任务裁决耗时
已有工作项检查耗时
状态快照记录耗时
请求构造耗时
工作项构造耗时
等待工作项登记耗时
锁等待或锁内阶段耗时
本轮最慢任务主键
本轮最慢阶段
本轮超过阈值的任务数量
```

建议日志锚点：

```text
任务状态巡检/阶段耗时
任务状态巡检/单任务最慢阶段
任务状态巡检/已有工作项检查耗时
任务状态巡检/状态快照记录耗时
任务状态巡检/工作项构造登记耗时
任务状态巡检/慢任务摘要
```

验收预测：

```text
Debug x64 构建通过。
真实运行后能从日志定位单轮巡检最慢阶段和最慢任务。
新增日志不改变可推进、入队、等待、已有工作项和不可推进计数。
常驻运行中能判断巡检是否仍频繁超过后台循环间隔。
```

若短摘要命令没有自然触发 13 秒巡检：

```text
不新增伪任务、不造样本、不加回归入口。
保留埋点，等待真实运行样本或用户明确要求启动常驻真实路径。
```

## 5. S2 任务巡检脏集 / 事件驱动

前置条件：

```text
S1 已定位稳定最慢阶段；
确认最慢阶段来自重复扫描或重复检查，而不是必须立即修正的语义错误。
```

目标：

```text
把后台循环从每 250ms 全量扫描，改为优先消费需要推进的任务集合。
```

架构形态：

```text
待推进任务索引：
    task_id -> dirty_version
    task_id -> last_checked_version
    task_id -> last_dispatch_result

完成队列：
    completed_work_item -> affected_task_id

等待解除索引：
    wait_condition_key -> task_id 集合

外设材料触发：
    外设 / 模式 / 目标约束 -> 等待项集合

低频兜底巡检：
    每 N 秒执行一次
    每轮限制任务数量或耗时预算
    超预算时记录续扫位置
```

触发源：

```text
任务状态变化 -> 标记脏任务
等待条件解除 -> 标记相关任务
工作项完成 -> 推入完成队列
外设材料到达 -> 标记相关等待项
显式新任务创建 -> 标记新任务
```

硬规则：

```text
脏集只改变“检查谁”，不改变“怎么裁决”。
最终是否可推进仍走现有严格裁决逻辑。
全量巡检保留为低频兜底。
脏集丢失或版本异常时必须回退全量巡检并记录日志。
```

验收预测：

```text
同一真实输入下，任务可推进 / 入队 / 等待 / 不可推进的裁决结果不因脏集改变。
后台常规循环不再每轮扫描全部任务。
兜底巡检能发现遗漏脏任务并记录来源。
巡检超过后台循环间隔的频率明显下降。
```

## 6. S3 日志分级、批量 flush 和热路径限流

前置条件：

```text
S1 已给出阶段耗时分布，能判断日志是否是巡检热点之一。
```

目标：

```text
保留错误证据，降低信息日志、高频诊断日志和重复不可推进日志的同步 I/O 成本。
```

建议策略：

```text
错误 / 致命日志：
    保持逐条 flush。

警告日志：
    可配置逐条 flush，默认短周期批量 flush。

信息日志：
    批量 flush 或定时 flush。

高频诊断日志：
    默认摘要化，详细模式才输出完整字段。

重复不可推进日志：
    按 task_id + 状态版本限流。
```

新增统计：

```text
日志限流计数
日志合并计数
批量 flush 次数
强制 flush 次数
因异常触发立即 flush 次数
```

验收预测：

```text
错误日志和弹错日志仍可立即落盘。
信息日志不再默认每条 flush。
D455、任务巡检、自我线程热路径默认只写关键字段。
重复不可推进原因不再按固定周期刷屏。
日志限流不静默吞证据，必须有计数。
```

## 7. S4 短摘要命令离线 / live 拆分

目标：

```text
让摘要类命令默认能读取最近持久快照或最近日志，不再为“看一眼状态”支付完整冷启动成本。
```

命令语义建议：

```text
--demand-tree-growth-summary
    默认离线读取最近快照 / 最近日志。

--demand-tree-growth-summary-live
    明确进入真实环境初始化路径。
```

若为兼容旧用法保留原命令 live 语义，则新增：

```text
--demand-tree-growth-summary-offline
```

推荐选择：

```text
摘要类命令默认离线。
live 命令名称显式标注 live。
输出中标注快照来源、快照时间、是否冷启动、是否中间态。
```

离线诊断必须满足：

```text
不初始化自我环境。
不创建世界树结构。
不确认默认本能方法规格。
不写需求树、任务状态、方法状态、世界事实或价值账。
```

live 诊断必须满足：

```text
保留完整初始化语义。
日志和输出明确标注冷启动成本。
不得把 live 初始化副作用伪装成只读读取。
```

验收预测：

```text
离线摘要命令耗时应接近快照读取和日志解析成本。
live 摘要命令仍可完整初始化并输出冷启动阶段耗时。
离线输出若缺少持久快照，应明确报“无可用快照”，不得隐式创建结构。
```

## 8. S5 只读检查与显式确保分离

目标：

```text
修复诊断读取带创建副作用的问题，为离线摘要和轻量诊断建立可靠边界。
```

拆分层次：

```text
只读检查：
    检查存在概念系统是否已就绪。
    不创建、不补齐、不拿写路径。

显式确保：
    初始化路径调用。
    可以创建必要结构。

诊断读取：
    只调用只读检查。
    日志标明“只读检查”。
```

改造对象：

```text
私有_计算自我初始化结果
读取自我初始化结果
线程侧读取初始化结果
鱼巢.cpp 初始化失败报告路径
```

验收预测：

```text
只读读取初始化结果不会调用 世界树.初始化存在概念系统()。
显式初始化路径仍会确保存在概念系统。
初始化失败时仍能给出错误报告和日志。
离线诊断路径不会因读取状态而创建结构。
```

## 9. S6 基础信息运行期索引

目标：

```text
降低主键查找、按类型枚举、子节点按类型筛选的基础成本。
```

索引形态：

```text
主键 -> 节点
主信息类型 -> 节点集合
父节点 + 主信息类型 -> 子节点集合
父节点 + 特征类型 -> 子特征集合
父节点 + 存在类型 -> 子存在集合
```

硬规则：

```text
链表 / 基础信息树仍是权威存储。
索引只是可重建运行期加速器。
索引命中后必须校验节点仍属于权威结构。
索引异常时回退链表扫描。
回退必须写日志并计数。
```

分阶段启用：

```text
阶段 1：
    只构建索引，不使用，只做一致性检查。

阶段 2：
    读路径灰度使用，失败回退。

阶段 3：
    统计命中率、回退率、重建次数和校验失败次数。

阶段 4：
    稳定后扩大到控制面板、任务筹办、因果查询和外设材料读取路径。
```

验收预测：

```text
索引启用前后同一主键 / 同一类型枚举结果一致。
索引失败能回退全链扫描。
不会改变基础信息树权威存储结构。
不会因索引命中跳过业务裁决。
```
