## 5. S1d 任务状态提交同步热点治理方案

目标：

```text
解释并治理任务入队前状态提交中的同步本能方法执行和锁竞争放大问题。
不把状态提交裸异步化，不跳过 提交任务状态变化 本能方法，不让工作项先执行后补动作动态账。
```

原始堵点：

```text
主堵点：
    私有_提交界面任务状态变化 在持有 私有_任务生命周期调用互斥 后，继续准备本能调用、执行 自我_提交任务状态变化、同步镜像、记录快照和日志。
    因此状态提交耗时会被长生命周期锁放大。

同锁放大：
    worker 派发 任务管理工作线程::提交任务工作项 时也持有 私有_任务生命周期调用互斥。
    完成归并应用任务壳时也持有 私有_任务生命周期调用互斥。
    所以状态提交等待锁，不一定表示状态提交本身慢，也可能是在等待 worker 执行派发或完成归并。

规范边界：
    任务状态推进成新状态必须通过任务域被动状态动作 提交任务状态变化 完成。
    任务管理层不得为了加速裸写任务状态或跳过动作动态。
```

```text
实施记录/20260607_运行速度S1任务巡检耗时日志_Codex断点清单.md
```

不得修改：

```text
任务状态裁决来源；
任务完成 / 需求满足 / 价值结算规则；
动作动态必须绑定方法的硬规则；
执行前许可 mailbox 协议；
外设事实写入边界；
D455 报告队列、相机线程、外设观察材料页；
需求树、因果索引、候选方法索引、基础信息索引；
日志模块 flush 策略。
```

候选实现方向：

```text
第一层：
    扩大“无需状态提交”的去重范围。
    同状态、同阶段、同任务已有执行前许可占用、同任务已有在途执行项时，只记录调度诊断，不进入状态提交。
    该层只跳过无真实状态变化的重复提交，不改变任务状态裁决，也不跳过真实状态变化。

第二层：
    先加生命周期锁“持有原因 / 持有耗时 / 等待耗时”埋点，再拆用途。
    状态提交锁只保护状态变化与动作动态提交。
    任务壳应用锁只保护完成归并写任务壳。
    worker 派发不应长时间持有状态提交锁，除非真实证明任务筹办 / 执行会裸改同一任务状态。

第三层：
    如果 自我_提交任务状态变化 本能方法仍长期耗时，则建立状态提交待确认队列；
    工作项派发必须等待该任务当前状态提交确认，不能先执行后补账。
```

验收预测：

```text
Debug x64 构建通过。
真实自检或常驻路径自然触发任务入队。
任务状态提交/阶段耗时能区分状态提交锁等待、本能方法执行和回写确认。
新增锁埋点能区分状态提交、worker 派发、任务壳应用的锁持有原因和持有耗时。
同状态重排不再出现 0.5s-1.1s 生命周期互斥等待样本。
初次入队和真实状态变化仍生成合法动作动态。
工作项派发日志不得早于当前任务状态提交确认。
若方案无法保证动作动态时序和任务状态一致性，则只记录阻塞点，不实施待确认队列。
```

## 6. S2 任务巡检脏集 / 事件驱动

前置条件：

```text
S1 已定位稳定最慢阶段；
确认最慢阶段来自重复扫描或重复检查，而不是必须立即修正的语义错误。
```

目标：

```text
把后台循环从每 250ms 全量扫描，改为优先消费需要推进的任务集合。
```

架构形态：

```text
待推进任务索引：
    task_id -> dirty_version
    task_id -> last_checked_version
    task_id -> last_dispatch_result

完成队列：
    completed_work_item -> affected_task_id

等待解除索引：
    wait_condition_key -> task_id 集合

外设材料触发：
    外设 / 模式 / 目标约束 -> 等待项集合

低频兜底巡检：
    每 N 秒执行一次
    每轮限制任务数量或耗时预算
    超预算时记录续扫位置
```

触发源：

```text
任务状态变化 -> 标记脏任务
等待条件解除 -> 标记相关任务
工作项完成 -> 推入完成队列
外设材料到达 -> 标记相关等待项
显式新任务创建 -> 标记新任务
```

硬规则：

```text
脏集只改变“检查谁”，不改变“怎么裁决”。
最终是否可推进仍走现有严格裁决逻辑。
全量巡检保留为低频兜底。
脏集丢失或版本异常时必须回退全量巡检并记录日志。
```

验收预测：

```text
同一真实输入下，任务可推进 / 入队 / 等待 / 不可推进的裁决结果不因脏集改变。
后台常规循环不再每轮扫描全部任务。
兜底巡检能发现遗漏脏任务并记录来源。
巡检超过后台循环间隔的频率明显下降。
```

## 7. S3 日志分级、批量 flush 和热路径限流

前置条件：

```text
S1 已给出阶段耗时分布，能判断日志是否是巡检热点之一。
```

目标：

```text
保留错误证据，降低信息日志、高频诊断日志和重复不可推进日志的同步 I/O 成本。
```

建议策略：

```text
错误 / 致命日志：
    保持逐条 flush。

警告日志：
    可配置逐条 flush，默认短周期批量 flush。

信息日志：
    批量 flush 或定时 flush。

高频诊断日志：
    默认摘要化，详细模式才输出完整字段。

重复不可推进日志：
    按 task_id + 状态版本限流。
```

新增统计：

```text
日志限流计数
日志合并计数
批量 flush 次数
强制 flush 次数
因异常触发立即 flush 次数
```

验收预测：

```text
错误日志和弹错日志仍可立即落盘。
信息日志不再默认每条 flush。
D455、任务巡检、自我线程热路径默认只写关键字段。
重复不可推进原因不再按固定周期刷屏。
日志限流不静默吞证据，必须有计数。
```

## 8. S4 短摘要命令离线 / live 拆分

目标：

```text
让摘要类命令默认能读取最近持久快照或最近日志，不再为“看一眼状态”支付完整冷启动成本。
```

命令语义建议：

```text
--demand-tree-growth-summary
    默认离线读取最近快照 / 最近日志。

--demand-tree-growth-summary-live
    明确进入真实环境初始化路径。
```

若为兼容旧用法保留原命令 live 语义，则新增：

```text
--demand-tree-growth-summary-offline
```

推荐选择：

```text
摘要类命令默认离线。
live 命令名称显式标注 live。
输出中标注快照来源、快照时间、是否冷启动、是否中间态。
```

离线诊断必须满足：

```text
不初始化自我环境。
不创建世界树结构。
不确认默认本能方法规格。
不写需求树、任务状态、方法状态、世界事实或价值账。
```

live 诊断必须满足：

```text
保留完整初始化语义。
日志和输出明确标注冷启动成本。
不得把 live 初始化副作用伪装成只读读取。
```

验收预测：

```text
离线摘要命令耗时应接近快照读取和日志解析成本。
live 摘要命令仍可完整初始化并输出冷启动阶段耗时。
离线输出若缺少持久快照，应明确报“无可用快照”，不得隐式创建结构。
```

## 9. S5 只读检查与显式确保分离

目标：

```text
修复诊断读取带创建副作用的问题，为离线摘要和轻量诊断建立可靠边界。
```

拆分层次：

```text
只读检查：

    只调用只读检查。
    日志标明“只读检查”。
```

改造对象：

```text
私有_计算自我初始化结果
读取自我初始化结果
线程侧读取初始化结果
鱼巢.cpp 初始化失败报告路径
```

验收预测：

```text
只读读取初始化结果不会调用 世界树.初始化存在概念系统()。
显式初始化路径仍会确保存在概念系统。
初始化失败时仍能给出错误报告和日志。
离线诊断路径不会因读取状态而创建结构。
```

## 10. S6 基础信息运行期索引

目标：

```text
降低主键查找、按类型枚举、子节点按类型筛选的基础成本。
```

索引形态：

```text
主键 -> 节点
主信息类型 -> 节点集合
父节点 + 主信息类型 -> 子节点集合
父节点 + 特征类型 -> 子特征集合
父节点 + 存在类型 -> 子存在集合
```

硬规则：

```text
链表 / 基础信息树仍是权威存储。
索引只是可重建运行期加速器。
索引命中后必须校验节点仍属于权威结构。
索引异常时回退链表扫描。
回退必须写日志并计数。
```

分阶段启用：

```text
阶段 1：
    只构建索引，不使用，只做一致性检查。

阶段 2：
    读路径灰度使用，失败回退。

阶段 3：
    统计命中率、回退率、重建次数和校验失败次数。

阶段 4：
    稳定后扩大到控制面板、任务筹办、因果查询和外设材料读取路径。
```

验收预测：

```text
索引启用前后同一主键 / 同一类型枚举结果一致。
索引失败能回退全链扫描。
不会改变基础信息树权威存储结构。
不会因索引命中跳过业务裁决。
```
