## 1.1 新增待执行范围：场景结构 / 字段必要性审查与删除候选

触发点：

```text
场景类.h 当前没有自定义 struct / enum class。

场景节点主信息类 定义在 基础信息主信息类.h，当前字段包括：
    宿主存在
    世界类型
    来源文章
    状态索引
    动态索引
    关系索引
    二次特征索引

世界树类.h 当前还定义多组场景相关结构体：
    场景相对坐标项
    场景绝对坐标换算结果
    结构_世界树场景轮廓查找参数
    结构_世界树场景轮廓存在比较结果

这些结构 / 字段需要逐项判断：
    是否为场景事实目录必须字段；
    是否只是世界树临时算法 DTO；
    是否可由 场景节点 / 存在节点 / 特征值 / 二次特征 / 动态 / 因果链 替代；
    是否存在 关系索引 与 二次特征索引 双轨重复。
```

审查口径：

```text
1. 必须保留：
    场景作为事实集合容器所需的项目结构引用；
    调用方确实需要同时读取多个结构化数值的公开接口结果；
    与项目节点 / 特征 / 特征值闭环直接相关，且不能用已有节点引用或输出参数清晰替代。

2. 可删除：
    无调用；
    只在单函数内部临时打包；
    只为日志 / 显示 / 统计耗时服务；
    字段可由状态、动态、二次特征或因果链实时推导；
    同一事实被两个索引重复维护且无明确不同语义。

3. 可移动：
    场景坐标属于存在位置特征读写的，优先判断归属 存在类 / 特征类；
    轮廓查找属于特征比较的，优先判断归属 特征类；
    场景事实目录增删查改属于 场景类；
    世界树类只保留编排入口，不直接承载领域结构体。
```

已知初始关注项：

```text
1. 场景节点主信息类::关系索引 与 场景节点主信息类::二次特征索引：
    二者当前同为 二次特征节点类 引用集合。
    场景类::追加二次特征 同时写两者；
    二次特征类 和 语素类 也存在直接维护两者的路径。
    需要确认是否仍有差异语义；若没有，删除其中一个，不保留兼容双写。

2. 场景相对坐标项 / 场景绝对坐标换算结果：
    当前用于 世界树类::计算场景绝对坐标_由相对坐标表 与外设模块。
    需要判断是否只是坐标换算 DTO；若只服务单条流程，可改为输出参数或移入更合适的存在 / 特征位置函数。

3. 结构_世界树场景轮廓查找参数 / 结构_世界树场景轮廓存在比较结果：
    当前用于 世界树类::查找场景存在_按深度或彩图轮廓图 与外设模块。
    需要判断是否属于场景候选召回接口，还是属于特征轮廓比较接口；若保留，字段必须保持结构化，不允许补文本原因字段进入机器判断。
```

执行步骤：

```text
P2.1 列出场景相关 struct / enum / 主信息字段判定表：
    名称 -> 字段 -> 写入方 -> 读取方 -> 是否公开接口 -> 是否持久化 -> 是否含文本字段 -> 初判。

P2.2 对每个结构 / 字段做引用闭环：
    rg 结构 / 字段名；
    记录创建点、写入点、消费点和显示 / 日志点；
    判断是否能由现有项目结构替代。

P2.3 对明确可删项执行删除：
    删除结构体或字段；
    删除双写、同步、兼容分支和旧入口；
    不保留别名层、fallback 或新旧索引并存。

P2.4 对需要迁移归属的项生成 owning class 缺口：
    缺 场景类 功能函数则补入本计划第一优先；
    缺 存在类 / 特征类 / 动态类 / 二次特征类 功能函数则按跨类缺口转向规则登记。
```

## 1.2 新增待执行范围：场景类功能函数补缺

触发点：

```text
场景节点主信息类 保存场景事实目录，但 场景类 当前主要提供创建、查找、追加函数。

其它模块仍存在直接读取或维护场景主信息字段的路径，例如：
    状态类 直接读写 场景主信息->状态索引；
    动态类 直接读写 场景主信息->动态索引；
    二次特征类 直接读写 场景主信息->关系索引 / 二次特征索引；
    方法类 直接读取 场景主信息->二次特征索引；
    任务类 读取 场景主信息->宿主存在；
    世界树类 / 控制面板 / 语言层 读取 世界类型、索引数量或显示字段。

后续应判断哪些路径属于显示 / 语言层临时读取，哪些属于系统逻辑读取；系统逻辑读取必须补 场景类 功能函数后再调用。
```

建议优先补齐的候选函数：

```cpp
bool 是场景节点(const 基础信息节点类* 节点) const noexcept;

枚举_世界类型 读取场景世界类型(
    const 场景节点类* 场景,
    枚举_世界类型 默认值 = 枚举_世界类型::其它) const noexcept;

存在节点类* 读取场景宿主存在(const 场景节点类* 场景) const noexcept;

std::vector<可解析引用<状态节点类>> 读取场景状态索引快照(
    const 场景节点类* 场景) const;

std::vector<可解析引用<动态节点类>> 读取场景动态索引快照(
    const 场景节点类* 场景) const;

std::vector<可解析引用<二次特征节点类>> 读取场景二次特征索引快照(
    const 场景节点类* 场景) const;

bool 移除场景状态索引(场景节点类* 场景, 状态节点类* 状态节点);
bool 移除场景动态索引(场景节点类* 场景, 动态节点类* 动态节点);
bool 移除场景二次特征索引(场景节点类* 场景, 二次特征节点类* 二次特征节点);
```

函数边界：

```text
1. 场景类只管理场景身份、场景归属、场景事实目录和场景内直接子项枚举。
2. 场景类不解释状态值、动态语义、二次特征业务含义、任务回执或需求结算。
3. 读取快照必须受 场景索引同步 互斥保护；调用方不得拿引用直接改主信息字段。
4. 删除双轨索引前，不新增兼容函数同时维护旧新字段。
5. 显示 / 语言层若只是展示，可暂登记为显示层临时读取；系统逻辑不得继续直读主信息。
```

执行步骤：

```text
P3.1 扫描所有 场景节点主信息类 字段直读 / 直写路径，按调用方分类：
    场景类内部；
    状态 / 动态 / 二次特征写索引；
    方法 / 任务 / 自我线程系统逻辑读取；
    控制面板 / 语言 / SQL 投影显示读取。

P3.2 先补系统逻辑必需的 场景类 只读快照和索引移除函数。

P3.3 将状态、动态、二次特征、方法、任务等系统逻辑调用方改为调用 场景类 功能函数。

P3.4 显示 / 语言 / SQL 投影路径若暂不改，必须在计划中标注为显示层临时读取，不作为机器判断依据。
```

```text

2. 若对应类已有逻辑纠偏计划，则把当前缺口加入该计划，并放到第一优先位置。
3. 若对应类没有逻辑纠偏计划，则生成 `计划/YYYYMMDD_<类名>逻辑纠偏计划_v0.1.md`，并把当前缺口作为第一优先切片。
4. 新生成或被修改的逻辑纠偏计划必须包含本“跨类缺口转向规则”，保证后续继续发现缺口时仍按同一调度口径处理。
5. 更新 `计划/计划索引.md`：把新生成或新修改的计划临时提升为第一优先计划；原计划和原切片记录为返回点。
6. 只执行新计划的第一优先缺口切片，不顺带推进新计划后续候选项。
7. 第一优先缺口闭合后，立即停止该新计划，更新计划索引返回原计划和原切片。
8. 若第一优先缺口切片不能闭合，保留该计划为当前阻塞，不回到原计划继续补丁化绕过。
```
