# P4 多需求共享任务结果扇出小方案 v0.1

日期：2026-06-09

## 目标

同一任务被多个需求复用后，任务结果状态消息不能只沿任务来源需求单路径处理。共享任务完成或收束完成时，所有挂接到该任务的非根需求都必须分别检查满足、父链唤醒和价值结算去重。

## 只读结论

```text
需求类::绑定对应任务 已同时写入 需求.对应任务 和去重后的 需求.任务列表。
自我线程现有 私有_按任务查找非根需求_线程侧 只返回第一个命中需求。
结果状态消息入口 私有_按成功结果满足来源需求并唤醒父任务_任务管理新链 先取单个来源需求，再处理自身结算和不同任务横向结算。
现有横向结算显式跳过 候选任务 == 来源任务，不覆盖同一任务多需求挂接。
价值结算已有任务+需求+结果目标去重键，增量反馈已有事件键去重；任务已折算安全/服务值仍是任务级上限，不能因共享需求重复放大核心价值。
```

## 实现方案

```text
1. 在自我线程新增只读收集函数：
       私有_按任务收集非根需求集_线程侧(任务头)
   扫描当前需求树，收集 对应任务 或 任务列表 命中同一任务头的非根需求，并按需求树遍历顺序去重。

2. 用该收集函数替换旧 私有_按任务查找非根需求_线程侧 的单命中扫描循环。
   旧函数保留兼容签名，只返回收集集的第一个元素。

3. 新增共享任务挂接需求扇出处理函数。
   结果状态消息成功、收束完成或任务域已完成后：
       先处理来源需求；
       再对同一任务的其他挂接需求逐条调用既有 私有_处理任务满足反馈_线程侧；
       每条需求使用独立正式结算证据和 `原反馈事件|共享|需求|任务` 派生事件键；
       每条需求独立唤醒父任务。

4. 不新增任务状态裸写。
   任务状态仍由 提交任务状态变化 / 任务价值结算完成通知路径落账。

5. 不改 结构_任务工作结果，不动相机外设四方法。
```

## 验证

```text
构建：
    msbuild .\鱼巢.vcxproj /p:Configuration=Debug /p:Platform=x64 /p:LinkIncremental=false /m

真实运行：
    .\x64\Debug\鱼巢.exe --self-check-log --self-check-log-wait-ms=10000

日志核对：
    自我线程/共享任务挂接需求扇出扫描
    自我线程/共享任务挂接需求扇出处理
    同目标任务复用命中
    任务状态动作动态
    任务状态逻辑错误=0
    旧本能调用锚点=0
```

## 验收边界

```text
共享任务未自然完成时，可只记录扇出扫描未命中或待自然复核；不得造模拟样本。
共享任务扇出只做逐需求检查，不保证每个需求都满足。
核心价值不因同一任务挂接多个需求而重复放大。
```
