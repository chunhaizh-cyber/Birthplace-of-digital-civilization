# 安全因果链反推当前场景特征值需求纠偏计划 v0.2

日期：2026-06-01

状态：本轮执行入口草案，承接 v0.1 三份相关草案并收束为当前下一切片。

## 1. 定案链条

最终因果链按一条线表达为：

```text
自我定义为需要维护自身安全值的存在
-> 自我安全值下降意味着自我关键特征可能受损
-> 自我关键特征可能受当前场景影响
-> 当前场景影响来自场景中的存在及其当前特征值
-> 因果条件是否成立必须读取当前特征值
-> 当前场景特征值未知时，无法判断场景风险安全值
-> 场景风险安全值未知时，无法判断风险安全_场景影响部分
-> 风险安全_场景影响部分未知时，风险安全层不能明确
-> 风险安全层不能明确时，自我安全值不能合法判断 / 结算
-> 因此需要获得当前场景中的特征值
-> 生成需求：当前场景特征值明确
```

这不是人为指定“要看场景”，而是从自我定义自然推出：

```text
要维护自我安全，
必须判断当前场景是否会影响自我；
要判断当前场景影响，
必须知道当前场景中的存在及其特征值。
```

## 4. 需求树组织方式

运行期目标形态：

```text
需求：自我安全值达标
└── 因果子链：风险安全场景影响链
    └── 需求：风险安全_场景影响部分明确
        └── 需求：当前场景风险安全值明确
            └── 需求：当前场景特征值明确
                └── OR组：特征值获取路径
                    ├── D455外设观察确认路径
                    │   ├── 当前观察特征帧取得
                    │   ├── 外设观察材料可回查
                    │   ├── 外设像素簇候选已验证
                    │   ├── 外设观察存在候选确认方案已取得
                    │   └── 已确认观察存在已提交入账
                    ├── 读取已有场景缓存路径
                    └── 交互者直接说明路径
```

表达规则：

```text
OR组节点：
    目标特征 = OR组满足状态

D455路径节点：
    目标特征 = 方法路径完成状态

当前观察特征帧取得：
    目标特征 = 当前观察特征帧取得状态

外设观察材料可回查：
    目标特征 = 外设观察材料可回查状态

已确认观察存在已提交入账：
    目标特征 = 已确认观察存在提交入账状态

当前场景各存在特征值可读：
    目标特征 = 当前场景各存在特征值可读状态
```

上述逻辑组不得新增需求主信息字段。若缺目标特征、值域或合法生产者，先补特征和值域 / 生产者登记，再由提交入口生成普通需求节点或逻辑组织节点。

```text
像素归属验证材料
```

```text
风险状态明确
自我安全值增加
风险安全层入账
```

D455 材料只能满足早期前置：

```text
当前观察特征帧取得
外设观察材料可回查
外设像素簇候选可验证
```

后续必须继续经过：

```text
自我_验证外设观察像素簇候选
自我_确认外设观察存在候选
提交_确认观察存在事实
安全_评估当前场景安全性
提交_风险安全场景影响部分状态变化
```


验收：

```text
这些目标进入枚举目标生产者分级；
每个目标都有合法生产者，不由控制面板、任务筹办或只读快照写入。
```

### P3 绑定 D455 路径的合法生产者

目标：

```text
把已有正式方法接到路径目标。
```

映射：

```text
当前观察特征帧取得状态
    -> 双目相机_取得当前观察特征帧

外设观察材料可回查状态
    -> D455短期材料页提交 / d455:// 句柄解析成功

外设像素簇候选验证状态
    -> 自我_验证外设观察像素簇候选

外设观察存在候选确认方案取得状态
    -> 自我_确认外设观察存在候选

已确认观察存在提交入账状态
    -> 提交_确认观察存在事实

当前场景存在集合明确状态
    -> 提交_确认观察存在事实 成功更新当前场景索引后写入

当前场景各存在特征值可读状态
    -> 安全评估前的存在特征材料门读取 / 提交链结果
```

边界：

```text
提交_确认观察存在事实 是提交入口，不进入普通任务候选方法。
自我_确认外设观察存在候选 只输出确认方案，不创建观察存在。
外设报告、簇候选、验证通过结果不得直接满足已确认观察存在提交入账。
```

### P4 定义当前场景各存在特征值可读的最小材料门

目标：

```text
让 当前场景各存在特征值可读 表示“安全评估所需原始事实输入足够”，而不是单个布尔灯。
```

第一版最小材料：

```text
已确认观察存在引用
当前场景在场关系
来源报告ID / 来源外设 / 观察时间
ROI / 掩码 / 像素归属材料至少一类可回查
位置 / 距离 / 空间范围至少一类可读
深度或空间坐标质量状态可读
跨帧变化或稳定性状态可读；若不存在跨帧窗口，必须记录缺口
```

验收：

```text
能说明哪些存在可读；
能说明哪些特征类型可读；
能说明哪些特征缺失、过期、冲突或证据不足；
不能把已确认观察存在数量直接等同于特征值可读。
```

### P5 纠偏安全候选构造

目标：

```text
安全_构造场景影响因果候选 不再只按存在数量生成低置信候选，
而是按存在特征值、变化、时间窗口和归因证据生成候选条目。
```

第一版候选条目：

```text
候选存在
特征类型
当前特征值
前一特征值或缺口
变化方向
时间窗口
来源观察报告
来源动作动态
相关自我关键特征
归因证据状态
负向证据状态
候选置信度
```

验收：

```text
缺当前特征值 -> 候选构造不明确 / 派生材料缺口；
有当前特征值但无搜索 -> 不默认满足；
搜索完成且无负向证据 -> 才可走默认满足提交；
候选值不越级写风险安全层或自我安全值。
```

### P6 回接场景风险安全值评估

目标：

```text
当前场景各存在特征值可读后，
安全_评估当前场景安全性 读取这些材料，
生成存在风险安全值候选、当前场景风险安全值候选和风险安全_场景影响部分候选。
```

验收：

```text
当前场景风险安全值仍是评估视图 / 候选，不直接写根安全值；
风险安全_场景影响部分仍需提交入口判断可结算 / 已入账；
风险安全层只有所有必要因素状态满足后才允许聚合候选；
自我安全值最终仍只由价值结算入口合法改写。
```
