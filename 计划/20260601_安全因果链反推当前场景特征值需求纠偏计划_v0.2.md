## 1. 定案链条

最终因果链按一条线表达为：

```text
自我定义为需要维护自身安全值的存在
-> 自我安全值下降意味着自我关键特征可能受损
-> 自我关键特征可能受当前场景影响
-> 当前场景影响来自场景中的存在及其当前特征值
-> 因果条件是否成立必须读取当前特征值
-> 当前场景特征值未知时，无法判断场景风险安全值
-> 场景风险安全值未知时，无法判断风险安全_场景影响部分
-> 风险安全_场景影响部分未知时，风险安全层不能明确
-> 风险安全层不能明确时，自我安全值不能合法判断 / 结算
-> 因此需要获得当前场景中的特征值
-> 生成需求：当前场景特征值明确
```

这不是人为指定“要看场景”，而是从自我定义自然推出：

```text
要维护自我安全，
必须判断当前场景是否会影响自我；
要判断当前场景影响，
必须知道当前场景中的存在及其特征值。
```

## 4. 需求树组织方式

运行期目标形态：

```text
需求：自我安全值达标
└── 因果子链：风险安全场景影响链
    └── 需求：风险安全_场景影响部分明确
        └── 需求：当前场景风险安全值明确
            └── 需求：当前场景特征值明确
                └── OR组：特征值获取路径
                    ├── D455外设观察确认路径
                    │   ├── 当前观察特征帧取得
                    │   ├── 外设观察材料可回查
                    │   ├── 外设像素簇候选已验证
                    │   ├── 外设观察存在候选确认方案已取得
                    │   └── 已确认观察存在已提交入账
                    ├── 读取已有场景缓存路径
                    └── 交互者直接说明路径
```

表达规则：

```text
OR组节点：
    目标特征 = OR组满足状态

D455路径节点：
    目标特征 = 方法路径完成状态

当前观察特征帧取得：
    目标特征 = 当前观察特征帧取得状态

外设观察材料可回查：
    目标特征 = 外设观察材料可回查状态

已确认观察存在已提交入账：
    目标特征 = 已确认观察存在提交入账状态

当前场景各存在特征值可读：
    目标特征 = 当前场景各存在特征值可读状态
```

上述逻辑组不得新增需求主信息字段。若缺目标特征、值域或合法生产者，先补特征和值域 / 生产者登记，再由提交入口生成普通需求节点或逻辑组织节点。
