## 3. 入树范围

```text
第一版只承认以下三类自然学习需求触发。
“无既有候选方法”保留为候选填充安全兜底，不作为当前自然学习需求剧本。
```

### 3.1 无既有候选方法安全兜底

```text
触发：
    任务筹办按目标特征类型查找方法能力；
    遍历完整方法树并完成候选集填充后，候选集为空。

当前正常路径：
    任务筹办必须排除 `改变特征值` 这类先天写入逻辑；
    `改变特征值` 不再作为候选方法、当前方法或动作动态来源；
    因此候选集为空只表示没有语义方法能够承接目标特征。

筹办处理：
    立即在方法树中创建面向目标特征 F 的方法头；
    将该方法加入任务方法候选集；
    返回该方法作为当前候选。

后续派生需求：
    不再派生“存在可改变 F 的方法”这种抽象需求；
    围绕新建方法的具体缺口派生：
        目标宿主 = 新建方法的虚拟存在
        目标特征类型 = 方法状态 / 条件结果对状态 / 执行入口状态
        目标状态 = 可用 / 已建立 / 已形成

因果句式：
    要父任务就绪，需要一个能改变目标特征 F 的方法。
    因为当前没有既有候选方法，
    所以任务筹办先创建方法 M 并返回 M。
    因为 M 还不是可用方法，
    所以派生学习需求：M.方法状态 = 可用，或派生更具体的条件结果对 / 执行入口补齐需求。

先天写入逻辑边界：
    `改变特征值` 是外层语义方法共享的底层特征提交原语；
    它不得进入候选集，不得被任务筹办选为当前方法；
    若需要改变目标特征，必须由占位方法或具体语义方法解释“为什么能改、如何改、是否可用”。
```

### 3.2 候选方法不可用

```text
触发：
    候选方法结果能力命中；
    但方法状态未达到可用。

派生需求：
    目标宿主 = 候选方法虚拟存在
    目标特征类型 = 方法状态
    目标状态 = 可用

限制：
    不得在缺口不明确时直接派生“方法动作状态”。
    只有回执明确证明缺执行入口，才派生执行入口相关需求。
```

### 3.3 明确缺执行入口

```text
触发：
    筹办回执明确候选方法缺执行入口或缺方法动作。

当前处理：
    不再把该缺口直接交给 `自我_定向学习` 作为闭合路径。
    在当前内部方法补齐场景中，出现该缺口说明尚未找到能够让目标状态 A -> B 的自我动作组合，或该组合 / 方法的结果能力尚未声明。

后续应进入：
    因果信息获取自我动作组合；
    若组合为单步本能方法，则提交方法可执行入口；
    若组合为多步动作，则只返回动作序列候选，等待动作序列入口规则。

派生需求第一版：
    若因果反推出单步本能方法，且后续确实要写入目标方法动作句柄：
        目标宿主 = 候选方法虚拟存在
        目标特征类型 = 可执行入口状态
        目标状态 = 已形成

    若因果反推出多步动作组合：
        第一版只返回候选，不直接入树，不写动作序列入口；
        只有当动作序列入口规则明确且需要持久写入时，才生成对应提交需求或提交动作。

    若无法反推出动作组合：
        输出缺少动作组合 / 等待实现或外部补充回执。

限制：
    `自我_定向学习` 仍可用于外界信息链或未知动作语义线索；
    但它不能替代内部方法域提交动作。
    因果反推本身不是提交动作，不生成动作动态。
```

### 3.4 明确缺条件结果对

```text
触发：
    候选方法已有方法头或动作；
    但缺有效条件结果对。

派生需求：
    目标宿主 = 候选方法虚拟存在
    目标特征类型 = 条件结果对状态
    目标状态 = 至少一组有效条件结果对已建立

后续闭合：
    尝试学习
    建立条件结果对
    提交方法状态变化
```

## 4. 筹办条件需求边界

```text
参数 / 条件补齐需求第一版不归入学习需求。

例如：
    缺参数 P
        -> 需求：参数 P 已获得 / 已绑定

    方法条件 C 不满足
        -> 需求：条件 C 成立

它们可以支撑筹办，但不作为“学习需求正式入树”的验收项。
```

## 5. 权重来源

```text
学习需求权重不再来自触发它的父需求 / 父任务剩余压力。

正式活动学习需求使用单位活动权重：
    活动学习需求对应方向活动权重 = 1；
    非活动学习需求对应方向活动权重 = 0。

父需求 / 父任务的安全或服务压力只用于运行时调度方向和排序，
不写入学习子需求权重，
也不作为安全 / 服务结算上限。

禁止：
    I64_MAX 作为真实服务结算值。

轻量结算口径：
    学习子任务完成后，先按需求满足链路截止对应学习需求；
    叶子任务若具备真实价值结算证据，再由叶子任务价值结算方法处理；
    父任务和父需求通过真实状态 / 差距刷新回流；
    父任务不重复结算子任务已结算部分。
```

## 6. 父需求挂接策略

```text
学习需求挂在触发它的父需求下面。

挂接规则：
1. 必须有触发父需求。
2. 父需求不能是单纯结构根。
3. 子需求必须有明确目标宿主、目标特征类型、当前状态 / 目标状态、满足关系。
4. 子需求必须带派生归因。
5. 不直接挂到根需求，也不单独挂成全局学习树。
```

## 7. 禁止项

```text
1. 不允许从测试夹具直接执行入树。
2. 不允许复制父需求目标作为学习需求目标。
3. 不允许缺目标宿主 / 目标特征类型 / 当前状态 / 目标状态 / 满足关系时入树。
4. 不允许同时生成外界探索需求。
5. 不允许恢复旧学习主需求链。
6. 不允许把“候选方法不可用”默认派生成“方法动作状态”。
7. 不允许把参数 / 条件补齐需求误归为学习需求。
```

```text
        不允许直接写 `方法可执行入口数量 = 1` 伪造闭合；
        不允许把 `改变特征值` 绑定为占位方法的可执行入口；
        下一步必须先实现或确认因果信息获取自我动作组合与动作序列入口规则，
        再继续推进“明确缺条件结果对”自然剧本。
```

### 剧本 3：缺执行入口 -> 补齐入口 -> 父任务就绪

```text
候选方法 M 结果能力命中。
筹办回执明确 M 缺执行入口。
派生需求：M.执行入口状态 = 已形成。
因果信息获取自我动作组合；若得到单步本能方法，则提交方法可执行入口；若得到多步动作组合，则等待动作序列入口规则。
入口形成后，若满足可用条件，提交 M.方法状态 = 可用。
父任务重筹办。
父任务就绪。
```

### 剧本 4：参数缺失 -> 参数子需求 -> 父任务就绪

```text
候选方法 M 可用。
方法条件满足。
但参数 P 无法绑定。
派生子需求：参数 P 已获得 / 已绑定。
子任务完成参数获取。
父任务重筹办。
配对参数成功。
可执行输入参数场景形成。
父任务就绪。
```
