## 2. 目标

在任务筹办中新增“因果路径筹办阶段”，实现两个函数级流程：

```text
A. 根据世界树因果主信息生成临时因果视图
B. 从临时因果视图生成派生需求消息
```

完整链路：

```text
需求 D
    -> 构造目标比较
    -> 查询世界树因果主信息
    -> 生成临时因果视图
    -> 从视图生成派生需求消息
    -> 上报自我线程
    -> 自我线程接收并解析消息
    -> 自我线程校验入树条件
    -> 自我线程规范化目标表达
    -> 自我线程去重 / 合并 / 循环截断
    -> 通过需求树统一更新指令入树
    -> 自我线程回执任务管理侧
```

第一轮只追求“路径草案能被生成、上报、裁决”，不追求一次性完成所有因果解释能力。

## 3. 硬边界

必须保持：

```text
1. 临时因果视图不入树，不成为权威结构。
2. 不新增因果视图主信息类。
3. 任务管理线程不直接修改需求树。
4. 派生需求消息不是正式需求。
5. 正式需求是否入树，由自我线程裁决。
6. 方法候选仍按方法结果能力命中需求目标完整填充。
7. 不能因为因果里出现因方法模板就直接执行方法。
8. 不能在筹办阶段结算安全值或服务值。
9. 不能把任务筹办 / 任务执行注册成本能方法。
```

允许产物：

```text
派生需求消息
筹办缺口
执行缺口
需求树更新指令输入草案
筹办日志
```

禁止产物：

```text
直接新增需求节点
直接修改需求树
直接执行因果路径
直接结算安全值 / 服务值
伪造动作动态
伪造样本
```

## 5. 阶段划分

任务筹办拆成三段：

```text
阶段 1：需求目标规范化
阶段 2：因果路径筹办
阶段 3：方法候选筹办
```

完整工程链路分成六段：

```text
阶段 A：任务管理侧生成临时因果视图
阶段 B：任务管理侧生成派生需求消息
阶段 C：自我线程接收并解析派生需求消息
阶段 D：自我线程入树前校验
阶段 E：自我线程去重 / 合并 / 循环截断
阶段 F：自我线程通过统一更新指令入树并回执
```

建议执行顺序：

```text
检查任务状态
-> 构造需求生命周期上下文
-> 检查父需求是否已满足
-> 检查是否存在活动子需求
-> 需求目标规范化
-> 因果路径筹办
-> 若产生派生需求消息，提交自我线程并等待重筹办
-> 若需求已经足够叶子化，进入方法候选筹办
```

因果路径筹办应插入在 `任务模块.筹办.ixx` 中目标上下文完整性检查之后、方法候选筹办之前。第一轮可使用保守触发条件，避免需求树爆炸。

## 6. 临时 DTO 设计

第一轮在任务筹办实现文件内部定义局部 DTO，后续若体量变大再拆为独立实现文件。

```cpp
struct 局部_临时因果路径项 {
    因果节点类* 来源因果 = nullptr;
    I64 根分区 = 0;
    I64 生成类型 = 0;
    二次特征节点类* 子需求目标比较 = nullptr;
    std::uint32_t 贡献层级 = 0;
    I64 层级权重 = 0;
    I64 稳定度 = 0;
    bool 条件已满足 = false;
    bool 证据足够 = false;
};

struct 局部_临时因果视图 {
    需求节点类* 来源需求 = nullptr;
    二次特征节点类* 目标比较 = nullptr;
    I64 根分区 = 0;
    std::vector<局部_临时因果路径项> 促成路径;
    std::vector<局部_临时因果路径项> 避免路径;
    std::vector<局部_临时因果路径项> 条件缺口;
    std::vector<局部_临时因果路径项> 方法就绪缺口;
    std::vector<局部_临时因果路径项> 证据缺口;
    std::vector<局部_临时因果路径项> 副作用约束;
    std::vector<局部_临时因果路径项> 学习缺口;
};
```

DTO 只在筹办过程内使用：

```text
不写入世界树。
不写入需求树。
不作为主信息。
不作为长期缓存。
```

目标字段：

```text

目标宿主
目标特征类型
当前状态
目标比较符
目标值
目标枚举值合法生产者，可选

```

若 `目标值` 是枚举型实例特征值，派生需求消息必须能携带或反查合法生产者；尚无生产者时只能生成方法就绪缺口、判定规则待建立缺口或学习缺口，不得由任务筹办直接写该状态。枚举值域定义本身不需要派生消息获取。

生成类型：

```text
促成
避免
条件补齐
方法就绪
证据补齐
副作用约束
学习缺口
目标补齐
```

与现有 `枚举_任务管理派生需求类型` 的第一轮映射建议：

```text
促成          -> 缺信息 / 缺确认，按目标性质决定
避免          -> 风险处置
条件补齐      -> 缺条件
方法就绪      -> 方法结构 / 执行缺失
证据补齐      -> 缺确认
副作用约束    -> 风险处置
学习缺口      -> 缺信息 / 方法结构
目标补齐      -> 缺信息
```

若映射会丢失必要语义，再最小扩展枚举或补充语义特征。

## 8. 实现切片

### P1 目标比较构造

目标：

```text
从当前需求读取目标宿主、目标特征类型、当前状态、目标比较符、目标值；
构造用于匹配因果主果的目标比较。
```

允许修改：

```text
任务模块.筹办.ixx
必要时最小补充消息协议字段
```

验收：

```text
目标完整时能生成目标比较；
目标不完整时不进入因果路径筹办；
缺目标字段只形成目标补齐派生需求消息或现有拒绝日志。
```

### P2 世界树因果查询

目标：

```text
枚举世界树因果节点；
读取因果主信息类；
检查主果比较模板是否命中当前目标；
检查主果比较模板是否反向破坏当前目标。
```

第一轮匹配策略：

```text
优先使用现有二次特征比较工具；
若工具不足，先使用严格主键 / 指针等价匹配；
不得用名称字符串猜测业务命中。
```

验收：

```text
日志能显示枚举因果数量、主果可解析数量、促成命中数量、反向命中数量。
```

### P3 临时因果视图生成

目标：

```text
生成促成路径、避免路径、条件缺口、方法就绪缺口、证据缺口、学习缺口。
```

第一轮可延后：

```text
副作用约束完整分析
跨根分区安全服务共享合并
复杂路径多层展开
```

验收：

```text
临时视图只存在于函数局部；
视图为空时能生成学习缺口；
证据不足时能生成证据补齐项；
不会写需求树。
```

### P4 视图转派生需求消息

目标：

```text
把临时路径项转换成结构_任务管理派生需求消息；
做基础完整性校验；
做去重和排序；
通过现有任务管理消息链上报自我线程。
```

基础校验：

```text
父需求存在；
目标宿主存在；
目标特征类型存在；
目标比较符存在且值域为 大于 / 小于 / 等于；
目标值存在；
若目标值是枚举值，目标比较符必须是 等于；
若目标值是枚举型实例特征值，必须能携带或反查合法生产者；
生成类型合法；
非学习缺口 / 非目标补齐时来源因果可解析。
```

验收：

```text
任务管理侧只发送派生需求消息；
不直接调用需求树更新；
重复消息不会连续发送。
```

### P5 自我线程入树裁决增强

目标：

```text
补齐自我线程接收派生需求消息后的完整处理流程；
在 私有_确保派生需求节点 增强入树校验；
保证正式需求只能通过需求树统一更新指令新增、更新或合并。
```

处理流程：

```text
1. 接收结构_任务管理派生需求消息。
2. 解析父需求、目标宿主、目标特征类型、当前状态、目标比较符、目标值。
3. 解析根分区、来源因果、来源动态、来源方法、生成类型。
4. 校验消息是否具备入树条件。
5. 规范化目标表达。
6. 去重、合并、循环截断。
7. 构造需求树统一更新指令。
8. 调用 需求类::执行更新指令(...)。
9. 生成入树处理回执。
10. 回执任务管理侧。
```

新增校验：

```text
父需求必须存在；
父需求不能是需求树结构根；
目标宿主不能为空；
目标特征类型不能为空；
当前状态不能为空，除非生成类型明确允许“状态未知补齐”；
目标值不能为空；
目标比较符不能为空，且只能是 大于 / 小于 / 等于；
若目标值是枚举值，目标比较符必须是 等于；
目标枚举值必须属于目标特征类型值域；
枚举型实例特征值必须有合法生产者；缺生产者时只能转为方法就绪缺口、判定规则待建立缺口或学习缺口；
根分区与父需求兼容；
来源因果若存在必须可解析；
来源动态若声明存在必须可解析；
生成类型必须合法；
贡献层级必须合法；
层级权重由自我线程重算；
避免类需求不能只有抽象“避免”，必须是明确目标特征状态；
不能重复生成已有等价需求；
不能形成父子循环。
```

去重键：

```text
父需求
根分区
目标宿主
目标特征类型
目标比较符
目标值
生成类型
来源因果，可选
```

处理结果：

```text
新增：
    当前树中没有等价需求。

更新：
    已有等价需求，但需要补充状态、来源因果、层级或派生原因。

合并：
    安全和服务都需要同一个子需求时，可合并为安全服务共享。

拒绝：
    父需求非法、目标不完整、来源不可解析、避免需求未目标化、形成循环。

延后：
    父需求状态尚未稳定，暂不入树。
```

循环检测键：

```text
目标宿主 + 目标特征类型 + 目标比较符 + 目标值
```

若父链中已经存在同目标需求：

```text
拒绝或截断；
记录循环截断原因；
不得把循环路径继续入树。
```

自我线程必须重算：

```text
根分区是否与父需求兼容；
目标比较符是否明确且合法；
避免类需求是否已改写成明确目标；
来源因果是否存在；
贡献层级是否合法；
层级权重；
是否重复；
是否形成循环；
是否允许入树。
```

验收：

```text
通过校验后仍只走 需求类::执行更新指令；
拒绝时记录明确拒绝原因；
不绕过统一需求树更新指令；
任务管理侧能收到已新增 / 已更新 / 已合并 / 已拒绝 / 已延后回执。
```

### P5.1 自我线程入树回执

目标：

```text
自我线程处理派生需求消息后，向任务管理侧返回明确处理结果。
```

建议回执字段：

```text
原派生消息ID
处理结果：
    已新增
    已更新
    已合并
    已拒绝
    已延后
正式需求节点引用，可空
拒绝原因，可空
```

拒绝原因枚举建议：

```text
父需求不存在
父需求非法
缺目标宿主
缺目标特征类型
缺目标比较符
缺目标值
枚举目标比较符非法
枚举值不属于特征值域
枚举实例特征值缺合法生产者
来源因果不可解析
来源动态不可解析
根分区不兼容
避免需求未改写
形成循环
已存在等价需求
```

任务管理侧收到回执后的处理：

```text
已新增 / 已更新 / 已合并：
    当前父需求进入等待子需求或等待重筹办状态。

已拒绝：
    记录筹办失败或生成更上层缺口，不得假装子需求已存在。

已延后：
    保持当前需求待筹办或稍后重试。
```

边界：

```text
回执不是动作动态；
回执不是需求满足证据；
回执只说明派生需求消息的入树处理结果。
```

### P6 子任务生成确认与父需求回查预留

目标：

```text
第一轮先确认派生需求入树后已经生成对应子任务；
子任务可以继续分解，不要求在本片内完成；
子需求满足后回查父需求目标特征和因果失败计数更新作为后续深层证据预留。
```

第一轮边界：

```text
以派生需求入树成功、子任务创建 / 提交、父任务转等待为当前验收闸门；
不把子任务创建或子任务阶段性上报直接解释成父需求满足；
不强行要求子任务在本片内完成，也不强行改造全部因果统计更新链。
```

验收：

```text
派生需求成功入树；
对应子任务已生成并进入任务管理生命周期；
父任务因派生需求未满足进入等待 / 阻塞推进；
子任务生成不直接等于父需求完成，父需求满足仍必须来自目标特征回查。
```

## 9. 运行触发策略

为避免需求树爆炸，第一轮因果路径筹办只在以下条件同时满足时运行：

```text
当前需求目标完整；
父需求未满足；
没有未完成活动子需求；
当前筹办轮尚未做过因果路径筹办；
当前需求没有可直接就绪的方法，或方法候选筹办返回明确缺口；
```

每轮只展开一层：

```text
不递归展开新派生需求；
不在同一筹办轮连续长多层树；
下一轮由正式入树后的子需求再进入筹办。
```
