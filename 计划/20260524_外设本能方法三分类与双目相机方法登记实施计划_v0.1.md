## 2. 规范复核结论

本计划按规范复核后，必须遵守以下收口：

```text
1. 控制 / 检查 / 使用不是新增方法主信息权威字段。
   第一阶段只能作为方法专属规格、能力标签、抽象特征约束或结果能力分组使用。

2. 三分类不是任务筹办硬编码分派规则。
   任务筹办仍必须先按方法结果能力完整填充候选集，再从候选集中选择当前方法。
   三分类只用于校验目标宿主、目标特征和结果能力是否声明正确。

3. 外设本能方法必须满足本能方法最小动作标准。
   只有方法头或适配器函数不够；必须有明确输入、前置条件、动作入口、输出结果和动作动态落账规则。

4. 感知使用方法只能记录观测动作造成的观察事实或世界模型刷新。
   外界对象自身独立发生的变化不能伪装成自我造成的世界事实动作动态。

5. 动作动态不以成功 / 失败作为根分类。
   是否满足需求只能作为输出结果或派生判断特征，不能作为动作动态本体分类轴。
```

## 3. 定案

外设本能方法只描述自我面向外设的可复用动作能力契约，不描述外设内部实现。

```text
外设本能方法 =
    自我对外设的控制方法
  + 自我对外设的检查方法
  + 自我通过外设进行使用的方法
```

外设适配器、驱动、采集、校正、匹配、滤波、分割等内部过程属于外设私有领域。自我只通过本能方法看到外设的可控面、可查面、可用面。

三类方法按目标宿主区分：

```text
控制类：
    外设.可控特征 -> 目标状态

检查类：
    外设.状态特征 -> 已知 / 正常 / 异常 / 可用 / 不可用

使用类：
    目标宿主.目标特征 -> 目标状态
    外设只是工具参数
```

关键边界：

```text
控制和检查的目标宿主通常是外设。
使用的目标宿主通常不是外设，而是自我、对象、场景或环境。
```

## 4. 非目标

```text
1. 不把双目相机内部步骤登记成本能方法。
   例如采集、校正、匹配、视差、深度、滤波、分割不是自我层方法清单。

2. 不恢复任务筹办 / 任务执行为本能方法。
   它们仍是任务管理生命周期普通函数。

3. 不新增模拟测试、夹具测试、伪造样本、伪造入口或伪造动作动态。

4. 不为了分类方便直接新增主信息权威字段。
   先判断能否用方法能力、专属规格、特征、条件结果对或动作动态表达。

5. 不把控制方法或检查方法直接当成外部对象特征需求的命中方法。
   例如 `杯子.距离 -> 已知` 不应直接命中 `启动双目相机` 或 `检查双目相机状态`。
```

## 5. 第一阶段双目相机方法范围

第一阶段采用收敛版清单，先保证筹办能按目标宿主与目标特征正确命中。

### 5.1 控制类

```text
1. 使双目相机达到可用状态
2. 设置双目相机工作模式
3. 释放双目相机
```

暂不优先拆出以下方法，除非实现中发现明确复用需求：

```text
启动双目相机
停止双目相机
设置双目相机观察参数
占用双目相机
```

控制类输出只写外设自身状态：

```text
双目相机.可用状态 -> 可用 / 不可用
双目相机.启停状态 -> 已启动 / 已停止
双目相机.工作模式 -> 指定模式
双目相机.占用状态 -> 已占用 / 已释放
```

### 5.2 检查类

```text
4. 检查双目相机运行状态
5. 检查双目相机是否满足当前观察需求
```

检查类输出只确认外设自身状态：

```text
双目相机.运行状态 -> 正常 / 异常 / 降级可用
双目相机.对当前观察需求的能力匹配状态 -> 满足 / 不满足
双目相机.工作质量状态 -> 可用 / 不可用 / 降级可用
```

这里的“满足 / 不满足”只表示双目相机对当前观察需求的能力匹配结果，不写需求域的需求满足状态，不替代 `回写需求满足`。

后续可按真实需求再拆出：

```text
检查双目相机可用状态
检查双目相机能力
检查双目相机工作质量
检查双目相机占用状态
```

### 5.3 使用类

```text
6. 用双目相机刷新当前观察场景
7. 用双目相机发现候选存在
8. 获取特征值（通过双目相机观测目标空间特征）
9. 用双目相机判断目标可见性或在场状态
```

使用类输出写外设之外的目标宿主：

```text
宿主.当前观察场景 -> 已刷新
观察场景.候选存在集合 -> 已生成
目标存在.距离 -> 已知
目标存在.相对位置 -> 已知
目标存在.尺寸 -> 已知
目标存在.方位 -> 已知
目标存在.高度 -> 已知
目标存在.可见性 -> 已知
目标存在.在场状态 -> 已知
```

`获取特征值` 是自我通过双目相机取得外部可观察特征值的使用类本能方法，不是读取世界树已有特征快照。
它可以与“用双目相机观测目标空间特征”共用一个动作入口，但必须登记多条输出能力，使筹办可按具体目标特征命中。
当前该方法尚未实现；在双目相机动作入口、目标绑定和输出落账规则闭合前，不得加入默认可执行本能方法表或普通候选方法集。

## 6. 统一方法契约

所有外设本能方法都必须具备：

```text
方法类别：
    控制 / 检查 / 使用
    只作为方法专属规格、能力标签、抽象特征约束或结果能力分组。
    不作为新增方法主信息字段，不作为候选选择权威。

调用者：
    谁要求执行

目标外设：
    使用哪个外设或哪类外设
    作为输入参数、条件约束或方法能力约束表达。
    不直接新增方法主信息字段。

目标宿主：
    最终要改变或确认哪个存在
    作为结果节点目标宿主或输出结果场景目标表达。
    不直接新增方法主信息字段。

目标特征类型：
    要改变或确认哪个特征

目标状态：
    希望变成什么状态

输入参数模式：
    必须提供哪些对象、场景、参数、限制

前置条件：
    执行前必须满足什么

动作入口：
    对外设适配器暴露的不透明入口

输出结果模式：
    明确写入哪个存在的哪个特征

动作动态落账规则：
    记录用了哪个外设、输入是什么、输出是什么、方法运行造成了什么事实。
    需求满足判断只能作为普通结果特征或派生判断，不作为动作动态根分类。
```

第一阶段先把类别表达为方法专属规格或能力面，不急于新增主信息字段。若现有结构无法稳定表达，再按 005 规范提出字段新增理由。

感知使用方法的落账边界：

```text
方法动作动态记录：
    自我通过双目相机执行了观测 / 刷新 / 发现动作；
    自我内部世界或观察场景得到了哪些新事实。

不得记录为：
    自我改变了被观测对象自身的外部物理状态。

若观测到外部对象状态变化：
    只能作为观察动态、外部事件动态或观察结果事实进入世界模型，
    不能伪装成自我方法造成的对象作用动态。
```

### P4 筹办匹配规则接入

目标：让任务筹办按结果能力完整填充候选集，同时用目标宿主和目标特征校验外设方法分类，避免控制 / 检查 / 使用互相误命中。

规范约束：

```text
1. 不能先硬编码选择某一类方法再绕过候选集填充。
2. 候选集仍必须由“方法结果能力是否命中任务目标”完整填充。
3. 当前方法只能从候选集中选择。
4. 分类判断只作为结果能力声明正确性、候选过滤和候选排序的约束。
```

匹配规则：

```text
需求目标是 外设.可控特征 -> 目标状态：
    候选应来自结果能力命中该外设可控特征的控制类方法。

需求目标是 外设.状态特征 -> 已知 / 正常 / 可用：
    候选应来自结果能力命中该外设状态特征的检查类方法。

需求目标是 外设之外的对象 / 场景 / 环境特征 -> 目标状态：
    候选应来自结果能力命中该目标宿主目标特征的使用类方法。
```

前置条件派生：

```text
使用类方法命中后，若缺：
    双目相机.可用状态 = 可用
    双目相机.运行状态 = 正常 / 降级可用

则派生控制或检查类子需求，而不是把控制 / 检查类方法作为原需求的直接解法。
前置条件必须落在使用类方法的条件节点 / 条件场景中；
派生子需求由需求树生长承接，不由使用类方法绕过任务筹办直接调用控制或检查方法。
```

典型验收样例：

```text
需求：杯子.距离 -> 已知

应命中：
    获取特征值（通过双目相机观测目标空间特征）

不应直接命中：
    启动双目相机
    检查双目相机运行状态

若相机不可用或状态未知，应派生：
    双目相机.可用状态 -> 可用
    双目相机.运行状态 -> 正常 / 降级可用
```

### P5 真实 D455 入口对接

目标：将第一阶段使用类方法连接到现有 D455 适配器，不暴露内部步骤给自我层。

实现方向：

```text

2. 检查类入口读取运行时、依赖、打开状态、帧质量、能力摘要。
3. 使用类入口调用采集与轮廓 / 空间观测结果，写入目标宿主特征。
```

检查类边界：

```text
检查方法原则上不启动、重启、修复、切换模式或长期占用外设。
若检查发现必须启动、重启、切换模式或配置参数，返回控制类缺口。
需要采样才能判断工作质量时，只允许使用已运行外设的轻量探测结果；
若探测会改变外设主要工作状态，必须先派生控制类需求。
```

边界：

```text
缺真实 D455 或缺真实目标样本时，只能记录等待真实样本。
不得用伪造帧、伪造目标、伪造动作动态补验收。
```

## 8. 风险与处理

```text
风险 1：把方法类别做成新的主信息权威字段，扩大结构面。
处理：先用方法能力、专属规格、特征或条件结果对表达；确需字段时单独论证。

风险 2：使用类方法命中后前置条件缺失，筹办错误地判定无方法。
处理：使用方法先命中，再派生控制 / 检查子需求。

风险 3：双目相机内部算法步骤被学习或登记成自我层方法。
处理：适配器内部步骤不进入方法树候选；只允许暴露控制、检查、使用入口。

风险 4：无硬件时误判实现失败或通过。
处理：无真实硬件只记录等待真实样本；不得用伪造样本替代。

风险 5：运行时依赖缺失导致延迟加载崩溃。
处理：相机入口先做 RealSense 运行时依赖检查，失败时返回错误结果并记录日志。
```
