任务链是已入树需求的执行承接；
方法链只有在动作能力缺口明确时才生成。
```

## 2. 总目标与中间产物

硬规则：

```text
根需求可初始化；
觉醒先给出根因果坐标；
定义域在觉醒坐标下生成；
定义可常驻；
定义不直接生需求或任务；
定义先生根闭环因果信息；
事实点亮闭环位；
缺口才成候选；
候选过准入才入树；
入树后才任务化；
缺方法才建方法头；
缺事实只等待事实；
缺因果链只保留定义。
```

目标：

```text
自我觉醒根闭环负责生成“我 / 非我 / 与我有关 / 可由我动作改变 / 可验证 / 可回写”的根因果坐标；
自我定义域在该坐标下定义自我 / 生存 / 服务；
服务根需求和生存根需求可以初始化；
服务 / 生存定义可以常驻；
不能直接 定义 -> 需求节点；
必须先 觉醒 -> 自我定义域 -> 根闭环因果信息 -> 当前事实挂载 -> 缺口候选 -> 需求节点；
没有触发事实时，只保留定义和根闭环信息位；
有触发事实时，把当前事实挂载到根闭环信息位；
只有未闭合、有触发事实、有推进意义的位置，才允许生成需求候选；
只有通过因果准入的候选，才允许进入需求树和任务链。
```

自我觉醒根闭环定义：

```text
自我觉醒根闭环 =
    事实被读取，
    -> 事实被判断是否与自我边界有关，
    -> 事实被判断是否影响自我持续存在或服务能力，
    -> 事实被判断是否可由自我动作、等待事实或外部输入推进，
    -> 事实被判断是否可验证、可归因、可回写，
    -> 形成最初的生存 / 服务 / 观察 / 等待判断，
    -> 产生根闭环因果信息，
    -> 回写为下一轮自我状态判断。
```

根闭环因果信息定义：

```text
根闭环因果信息 =
    根据自我觉醒坐标和上位定义生成的一组最小因果位置、
    证据要求、
    触发条件、
    缺口类型、
    回写目标和下一轮判断入口。
```

它回答：

```text
一个闭环如果要成立，信息上必须有哪些位置？
当前事实已经闭合哪些位置？
哪些位置缺失？
哪些缺失有资格变成需求？
```

非目标：

```text
不删除特征定义、语素入口或历史日志。
不恢复任务筹办 / 任务执行为本能方法。
不新增模拟样本、伪造入口或伪造动作动态。
不在本计划内正式结算安全值 / 服务值。
不宣称自我苏醒完成、初步成熟完成或完整服务 / 生存闭环完成。
```

## 3. 待确认问题

Q0 已按本轮用户确认作为上位口径写入；其余问题进入代码修改前仍需确认实现范围：

```text
Q0. 自我觉醒是否作为零号闭环？

结论：
    是。

自我觉醒不是神秘状态，也不是自我节点已初始化。
它是根因果能力启动：
    系统开始把事实区分为与我有关 / 与我无关，
    影响我持续存在 / 不影响我持续存在，
    可由我动作改变 / 暂不可由我动作改变，
    改变后可验证 / 不可验证，
    结果可回写到下一轮我状态 / 不可回写。

零号层级：
    自我觉醒
    -> 自我定义域
    -> 自我 / 生存 / 服务定义
    -> 根闭环因果信息
    -> 当前事实挂载
    -> 闭环缺口识别
    -> 需求生成
    -> 任务承接
    -> 方法执行
    -> 结果验证
    -> 归因回写
    -> 下一轮自我状态判断

Q1. 第一版先生成哪些因果信息根闭环？

建议第一版生成三类：

1. 自我根闭环：
       事实读取
       -> 需求形成
       -> 方法选择 / 学习
       -> 动作执行
       -> 结果事实
       -> 结果验证
       -> 状态回写
       -> 下一轮状态判断

   对应根因果信息位：
       自我_事实输入位
       自我_需求形成位
       自我_方法承接位
       自我_动作执行位
       自我_结果事实位
       自我_验证判断位
       自我_回写位
       自我_下一轮判断位

2. 生存根闭环：
       自我存在状态被观察
       -> 存在条件缺口 / 损耗 / 风险 / 负向影响
       -> 生存目标
       -> 维持 / 修复 / 规避 / 补充 / 降级保护方法
       -> 动作
       -> 自身相关状态变化事实
       -> 验证
       -> 回写
       -> 下一轮观察

   对应根因果信息位：
       生存_自我状态事实位
       生存_存在条件缺口位
       生存_目标位
       生存_方法位
       生存_动作位
       生存_自身状态变化事实位
       生存_验证位
       生存_回写位
       生存_下一轮观察位

3. 服务根闭环：
       人类需求或服务目标被表达 / 观察 / 确认
       -> 服务需求
       -> 服务对象和目标
       -> 服务方法
       -> 自我动作
       -> 人类相关外在状态变化
       -> 验证
       -> 归因
       -> 回写
       -> 下一轮服务缺口判断

   对应根因果信息位：
       服务_触发事实位
       服务_需求形成位
       服务_对象位
       服务_目标位
       服务_方法位
       服务_动作位
       服务_外在状态变化事实位
       服务_验证位
       服务_归因位
       服务_回写位
       服务_下一轮缺口判断位

Q2. 根闭环因果信息第一版至少包含哪些字段？

建议至少包含：

1. 根定义编号。
2. 觉醒坐标来源。
3. 自我定义域编号。
4. 闭环位置序列。
5. 每个位置的事实类型。
6. 每个位置与自我边界的关系。
7. 每个位置是否影响自我持续存在或服务能力。
8. 每个位置是否可由自我动作、等待事实或外部输入推进。
9. 每个位置的目标语义要求。
10. 每个位置的闭合证据。
11. 每个位置的缺口类型。
12. 每个位置是否可转需求。
13. 回写目标。
14. 下一轮判断入口。

根闭环因果信息不是需求树，不是任务链，不是方法头。
它只是需求树生长前的因果坐标系。

Q3. 当前事实如何挂载到根闭环，并判断闭合状态？

第一版状态：

1. 未触发。
2. 已触发但事实不足。
3. 已触发且缺目标。
4. 已触发且缺路径。
5. 已触发且缺方法。
6. 已触发且缺动作。
7. 已触发且缺结果事实。
8. 已触发且缺验证。
9. 已触发且缺归因。
10. 已触发且缺回写。
11. 当前轮闭合。

第一版服务触发事实：

1. 当前会话输入中存在人类表达、请求、目标、问题或待改善状态。
2. 外部请求 / 服务事件存在。
3. 已确认服务目标存在，但缺少对象、动作路径、验证路径、归因路径或回写路径。
4. 服务动作已执行，出现结果事实、结果缺口、验证缺口或归因缺口。
5. 根特征自检发现明确服务因果定义支撑的服务闭环缺口。
6. 人类反馈、确认、拒绝、纠错或外在状态变化事实表明服务状态需要继续判断。

无上述事实时：
    服务根需求可以存在；
    服务定义可以存在；
    服务根闭环信息位可以存在；
    服务链上下文为空；
    不展开服务子需求；
    不生成当前交互者 / 当前权限者 / 当前服务对象 / 当前服务目标等主动任务。

第一版生存触发事实：

1. 自我状态事实显示存在条件缺口、损耗、异常、中断、退化或不可继续行动。
2. 外部事实影响自我持续存在、继续行动能力、安全边界或执行环境。
3. 任务、方法、资源、状态、记忆、动作入口或回写链路出现阻断。
4. 已有生存 / 安全目标，但缺少观察、方法、动作、验证或回写环节。
5. 风险候选、错误日志、运行失败、状态不一致或安全相关反馈进入事实层。
6. 根特征自检发现明确生存因果定义支撑的闭环缺口。

无上述事实时：
    生存根可以存在；
    生存定义可以存在；
    生存根闭环信息位可以存在；
    不展开具体处置子需求；
    不主动生成修复、保护、降级、补充类任务。

Q4. 哪些闭环位置缺口允许转成需求候选？

只把以下缺口转成需求候选：

1. 可追溯到自我觉醒根闭环。
2. 当前事实已触发该根闭环。
3. 该位置缺失会阻断闭环继续。
4. 该位置有上游来源。
5. 该位置有目标语义。
6. 该位置有获取、等待或推进路径。
7. 该位置的满足结果能参与动作、验证、归因、回写或下一轮判断。

其他缺口只记录为：

1. 定义位未闭合。
2. 当前未触发。
3. 等待事实。
4. 暂不入树。

Q5. 当前交互者 / 当前权限者 / 当前服务对象 / 当前服务目标如何迁移？

这些都不再是启动期固定服务必要条件，也不再是天然需求节点。
它们只是服务根闭环里的可能信息位：

```text
服务_对象位
服务_目标位
服务_身份归因位
服务_授权边界位
服务_责任归因位
```

当前交互者明确状态：
    只在服务_身份归因位或服务_责任归因位被触发且缺失时进入链条。

当前权限者明确状态：
    只在服务_授权边界位被触发且缺失时进入链条。

当前人类服务对象明确状态：
    只在服务_对象位被触发，且对象不明会影响行动或验证时进入链条。

当前服务目标明确状态：
    只在服务_目标位被触发，且目标不足以支撑方法选择、结果验证或结算时进入链条。

例：
    有人类请求，但不知道服务目标
    -> 服务_目标位缺失
    -> 生成“明确服务目标”需求。

    有人类请求，目标明确，单人场景，不涉及授权
    -> 不生成当前权限者需求。

    多人代理请求，动作结果需要责任归因
    -> 服务_身份归因位 / 授权边界位缺失
    -> 生成当前交互者或权限者相关需求。

Q6. 本轮代码落地范围是否仍然只做服务链最小版？

建议：
    是。

本轮优先落：
    自我觉醒根闭环口径；
    自我定义域到自我 / 生存 / 服务定义的映射；
    自我 / 生存 / 服务三类根闭环因果信息模板；
    服务链当前事实挂载与闭合状态判断；
    服务闭环缺口候选生成；
    闭环缺口到需求节点的因果准入；
    当前交互者 / 权限者条件触发迁移。

生存链本轮先同步规范口径：
    保留根闭环因果信息生成规则；
    不破坏已经验证过的安全因果风险树路径；
    后续再补生存链同构实现。
```
