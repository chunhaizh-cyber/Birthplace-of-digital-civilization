### C4.5 外设观察模式触发纠偏

执行状态：2026-05-30 检查发现当前实现与最新口径有出入，先制定纠偏计划，后续代码修改必须先执行本段。

当前实现事实：

```text
1. `--auto-observe-stable` 诊断入口会一次性提交：
       陌生环境逐簇识别等待项
       已识别场景扫描变化等待项
       目标跟踪观察等待项

2. D455 线程每个成功采样帧都会生成逐簇识别报告。

3. D455 线程只有在队列中存在扫描变化等待项时才生成扫描变化报告，
   但当前诊断入口无条件创建该等待项。

4. D455 线程只有在队列中存在目标跟踪等待项时才生成跟踪报告，
   但当前诊断入口无条件创建目标簇=0 的等待项。

5. D455 的逐簇识别跨帧缓存会为本帧所有簇分配或匹配跨帧簇ID，
   当前实现会统计多个跨帧稳定簇，而不是一次只围绕一个待确认候选进行目标跟踪。
```

最新口径：

```text
逐簇识别：
    是陌生场景下的基础本能观察模式；
    可持续输出簇候选材料；
    跨帧连续性只作为候选验证证据；
    不等于目标跟踪；
    不等于已确认观察存在。

目标跟踪：
    只有自我或任务管理基于明确来源需求发出目标跟踪等待项 / 指令后才执行；
    等待项必须携带目标簇、存在候选、ROI、掩码或目标特征摘要之一作为跟踪种子；
    同一时刻第一版只允许一个主动目标跟踪对象；
    该目标确认、否定、丢失或交回后，才选择下一个候选。

扫描变化：
    只在场景已确认 / 基准场景已建立 / 已识别场景需要守望时执行；
    未识别场景不生成扫描变化等待项；
    未建立基准时不得用相邻逐簇报告伪装成已识别场景扫描变化。
```

纠偏计划：

```text
C4.5-1 诊断入口拆分：
    `--auto-observe-stable` 默认只提交逐簇识别等待项；
    扫描变化等待项只能由“已识别场景守望”诊断或正式需求创建；
    目标跟踪等待项只能由“指定目标跟踪”诊断或正式需求创建；
    当前三等待项同跑入口保留时必须标记为全模式诊断，不作为业务验收入口。

C4.5-2 等待项前置条件补齐：
    扫描变化等待项必须记录基准场景 / 基准报告 / 已确认场景解释来源；
    目标跟踪等待项必须记录目标种子来源；
    缺前置时任务管理只生成缺口或等待，不让外设线程生产对应正式报告。

C4.5-3 D455 线程调度收口：
    逐簇识别报告可作为陌生场景基础报告持续生产或按等待项生产；
    扫描变化报告生成前检查已识别场景基准；
    跟踪报告生成前检查目标种子；
    若存在多个跟踪等待项，第一版按确定规则只选择一个，其余保持等待并记录跳过原因。

C4.5-4 跨帧簇ID降权：
    外设跨帧簇ID只表示外设内部候选连续性证据；
    不作为世界存在ID；
    不作为目标跟踪报告的充分条件；
    不作为当前场景存在集合明确证据。

C4.5-5 顺序确认候选：
    逐簇识别报告可以包含多个簇候选；
    自我侧每轮只选择一个待确认候选进入目标跟踪 / 像素归属深验证；
    候选确认、否定、拆分、合并或交回后，再选择下一个候选。

C4.5-6 验证：
    无扫描变化等待项时，不应出现扫描变化报告入队；
    无目标跟踪等待项或无目标种子时，不应出现正式跟踪报告入队；
    有一个目标种子时，只出现一个主动跟踪报告；
    逐簇识别报告中的多个跨帧簇只能作为候选连续性摘要；
    安全评估仍不得把这些外设报告直接解释成基础风险已明确或安全值结算。
```

### C4.7 已确认轮廓驱动的下一帧分区识别 / 扫描

执行状态：2026-05-30 根据最新口径新增；章节上接在 C4.6 后说明，但实际执行必须排在 C5-3c 之后，因为它依赖已确认存在、已写入轮廓 / 掩码 / ROI 和来源动作动态。

定案：

```text
当一个存在已经被确认 / 识别，
并且已经有可追溯的外轮廓 / 掩码 / ROI 后，
下一帧不再默认把整帧都作为陌生区域逐簇识别。

应先用已确认存在的上一帧轮廓或预测轮廓拆分当前原始帧：
    轮廓覆盖且匹配可信的部分 -> 已知存在扫描区；
    未被任何已知轮廓覆盖的部分 -> 新识别区；
    轮廓重叠、漂移、残差异常或遮挡的部分 -> 冲突 / 待重识别区。
```

这里的“轮廓图”仍是观察材料和分区依据，不是永久世界真值。它必须能追溯到：

```text
来源观察帧；
来源已确认存在；
来源轮廓 / 掩码 / ROI；
来源像素归属账本；
来源确认动作动态；
轮廓有效期和置信度。
```

下一帧分区流程：

```text
1. 取得当前原始帧、深度帧和对齐帧。

2. 读取上一轮已确认观察存在集合。

3. 对每个已确认存在 E，读取：
       E 的上一帧外轮廓 / 掩码 / ROI；
       E 的空间范围、深度范围和轮廓置信度；
       E 的最近确认时间、来源帧和来源动作动态；
       E 是否需要继续扫描 / 守望 / 内部细分。

4. 将 E 的上一帧轮廓投影或预测到当前帧。
       第一版可以使用同坐标近邻投影 + ROI 扩张；
       后续可由目标跟踪、姿态变化或空间变换提供更准预测。

5. 生成分区材料：
       已知存在扫描区 = 已确认存在轮廓投影区域及必要扩张边界；
       新识别区 = 当前帧 - 所有已知存在扫描区；
       冲突区 = 多个轮廓重叠 / 像素归属不一致区域；
       待重识别区 = 轮廓匹配失败、残差过大、深度突变或遮挡区域。

6. 对已知存在扫描区执行扫描变化：
       比对当前局部彩图、深度、轮廓、空间范围；
       更新候选轮廓、位置、可见状态、遮挡状态和变化摘要；
       若变化小且证据充分，输出该存在当前帧扫描结果；
       若变化大或匹配失败，输出重识别缺口。

7. 对新识别区和待重识别区执行逐簇识别：
       只在这些区域生成新簇候选；
       不把已知存在扫描区重复当成陌生区域全量识别；
       若扫描区内部出现未解释残差，也可派生局部识别任务。

8. 若某个已确认存在需要内部结构识别：
       用它的当前轮廓 / ROI 截取局部材料；
       进入该存在.内部世界；
       继续执行内部世界递归细分任务。
```

C4.7 判据补齐：

```text
轮廓有效期：
    有效帧数窗口；
    有效时间窗口；
    相机位姿连续性；
    深度连续性；
    遮挡状态；
    最近匹配状态。

轮廓失效条件：
    超过有效期；
    连续匹配失败达到阈值；
    相机位姿跳变；
    深度残差过大；
    轮廓残差过大；
    可见比例过低且非遮挡；
    材料缺失。

投影 / 预测优先级：
    1. 有 3D 空间候选时，使用深度 + 相机内参 / 外参 / 位姿变化投影到当前帧；
    2. 无稳定 3D 时，使用上一帧 2D ROI / 掩码 + 运动估计 / 光流 / 安全扩张边界；
    3. 无运动估计时，使用上一帧 ROI 膨胀为预测区域。

预测输出：
    预测ROI；
    预测掩码；
    预测中心；
    预测深度区间；
    预测置信度。

匹配分数组成：
    ROI IoU；
    掩码重叠率；
    中心点距离；
    深度中位数残差；
    轮廓边界残差；
    像素归属一致性；
    外观 / 特征相似度，若已有。

匹配判定：
    分数 >= 匹配阈值 -> 匹配成功；
    低于阈值但有遮挡证据 -> 暂存为遮挡 / 待观察；
    低于阈值且无遮挡证据 -> 匹配失败。

残差记录：
    像素残差 = 预测掩码与当前归属像素差异；
    深度残差 = 当前深度与预测深度区间差异；
    轮廓残差 = 当前轮廓边界与预测轮廓边界距离。

遮挡成立条件：
    预测区域内出现更近深度像素；
    被遮挡区域与其他已知存在或未知簇重叠；
    原轮廓可见比例下降；
    残余可见部分仍与原存在匹配。

多个已知轮廓重叠优先级：
    更高匹配分数优先；
    更近深度优先获得重叠像素；
    最近确认时间更近者优先；
    历史连续性更强者优先；
    仍无法决定时进入冲突区域，不强行归属。

匹配失败转重识别：
    单帧失败 -> 标记为待重扫 / 暂失，不立即删除存在；
    连续失败达到阈值 -> 生成未知区域识别需求；
    残差严重超阈值 -> 立即转未知区域识别；
    材料缺失 -> 生成材料缺口，不做重识别结论；
    遮挡成立 -> 等待恢复或局部扫描，不直接重识别。
```

区域语义：

```text
需要扫描的部分：
    已确认存在在下一帧中的预测轮廓区域；
    已确认存在轮廓附近的边界带；
    已建立基准的场景区域；
    已识别存在的内部世界当前观察切片。

    新出现轮廓 / 新深度团块；
    已知轮廓投影失败或漂移过大的区域；
    多存在轮廓重叠导致归属不明的区域；

```
