## 1. 承接目标

把详细设计中的三类父子关系角色落到可实施的工程路线：

```
必须子需求
可选路径子需求
非必须子需求
```

核心目标不是给 `需求主信息类` 增加类型字段，而是在运行期按父需求、子需求、当前方法路径和活动上下文推导只读角色视图。

本计划要保证后续代码只实现以下能力：

```
1. 读取父子关系角色视图。
2. 父需求结算前用角色视图区分必须阻塞、可选路径结算和非必须活动承接。
3. 父任务收束时按角色视图处理重筹办、截止、取消活动承接、转挂或暂缓结束。
4. 控制面板和 数据库查询 投影只显示只读结果，不参与机器判断。
```

## 2. 设计条款锁定清单

后续实现不得偏离以下条款：

```
1. 不新增“子需求类型”“父子关系类型”“是否必须”等持久字段。
2. 三类角色不是需求本体属性，而是父需求视角下的运行期关系角色。
3. 至少区分来源父子关系、满足依赖关系、活动承接关系。
4. 角色由目标特征定义、方法条件 / 结果链、来源动态 / 回执、二次特征缺口和活动承接状态推导。
5. 非必须子需求不阻塞父需求满足，但可在资源允许时执行，也可被更高来源接管。
6. 当前绑定方法的必要条件可以让非必须子需求在当前方法路径下临时成为必须前置。
7. 正式入树需求不靠物理删除表达放弃；应通过截止、取消活动承接、失去活动依据或转挂表达。
```

## 6. 验证剧本

后续实现至少覆盖：

```
1. 必须子需求未满足 -> 父需求不能满足。
2. 必须子需求满足 / 截止 / 明确收束 -> 父任务重筹办或父需求重新结算。
3. 可选路径子需求任一路径满足 -> 父需求重新结算，同组其他路径截止或取消活动承接。
4. 非必须子需求未完成 -> 不阻塞父需求满足。
5. 非必须子需求存在且无更高优先级任务 -> 父任务暂缓结束并先执行子需求。
6. 非必须子需求存在且有更高优先级任务 -> 取消当前活动承接，父任务结束。
7. 非必须子需求被更高来源接管 -> 转挂后继续保留合法活动来源。
8. 控制面板 / 数据库查询 投影关闭或缺失时，机器判断结果不变。
```

每个剧本的证据必须按 0050 总纲给出：

项目结构承载证据
输出 / 状态变化
