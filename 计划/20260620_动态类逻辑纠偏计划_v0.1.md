# 动态类逻辑纠偏计划 v0.1

日期：2026-06-20

状态：第一优先因果生成输入读取缺口已闭合；2026-06-20 因果类 P7 发现的动态来源场景读取缺口已闭合，已停止本计划并返回协调计划 P7；2026-06-20 用户确认动态名称 / 类型新口径后，动态来源类型与业务语义类型删除切片已闭合。

## 0. 目标

补齐动态类只读功能函数，让因果类不再直接解释 `动态节点主信息类` 字段。

当前触发缺口：

```text
旧口径问题：
    动态节点主信息类::来源类型 只剩语义标签价值，没有生成动态时的真实判断作用。
    动态节点主信息类::业务语义类型 属于可由来源动作、动作名、动作相位、初始/结果状态推导的缓存。
    动态节点主信息类::名称 与 类型 曾同时写动作词，导致动作语义和动态类别混在同一入口。
```

## 1. 第一优先缺口

建议函数：

```cpp
动态节点类* 按主键解析动态节点(const std::string& 主键) const noexcept;

bool 读取动态因果生成输入(
    const 动态节点类* 动态,
    状态节点类*& 初始状态,
    状态节点类*& 结果状态,
    方法节点类*& 来源动作,
    const 语素入口节点类*& 来源动作名,
    枚举_动态因果生成类别& 因果生成类别,
    std::uint32_t& 动态层级) const noexcept;
```

实现边界：

```text
1. 函数归属 动态类.h/.cpp。
2. 不新增结构体，不新增动态主信息字段。
3. `名称` 存动作 / 动态语义；`类型` 存主动动作动态、被动动作动态、无动作状态变化动态等类别入口。
4. 删除 `动态来源类型` 与 `动态业务语义类型`，不保留双写、缓存或兼容判断。
5. 动态因果生成类别由动态类根据来源动作、来源动作名、动作相位、初始/结果状态等项目结构字段推导。
6. 输出状态、方法和语素入口均使用现有节点 / 指针 / 引用结构。
7. 不把动作语义文本作为新业务状态承载；只返回现有动作名称入口或既有动作来源。
```

完成后返回：

```text
计划/20260620_因果类外部数据读取纠偏协调计划_v0.1.md
P2 状态类逻辑纠偏计划。
```

## 1.2 新增第一优先缺口：动态来源场景读取

触发点：

```text
因果类 P7 回迁发现 因果类::生成因果信息(动态节点类*) 会直接读取 动态节点主信息类::来源输出场景 / 来源输入场景。
该读取属于动态类数据解释，不应留在因果类中。
```

建议函数：

```cpp
bool 读取动态来源场景(
    const 动态节点类* 动态,
    场景节点类*& 输入场景,
    场景节点类*& 输出场景) const noexcept;
```

实现边界：

```text
1. 函数归属 动态类.h/.cpp。
2. 只读取动态来源输入场景和输出场景，不创建、不删除、不修改动态或场景节点。
3. 场景引用解析调用 场景类::按主键解析场景节点。
4. 第一优先闭合后停止本计划，返回 因果类外部数据读取纠偏协调计划 P7。
```

## 2. 跨类缺口转向规则

执行本计划时，如果发现当前切片必须依赖其它类新增或补齐功能函数，按以下规则处理：

```text
1. 后续任意类缺少当前切片所需功能函数时，不在动态类或调用方临时拼字段、解释其它类主信息或新增平行结构体。
2. 若对应类已有逻辑纠偏计划，则把当前缺口加入该计划，并放到第一优先位置。
3. 若对应类没有逻辑纠偏计划，则生成 `计划/YYYYMMDD_<类名>逻辑纠偏计划_v0.1.md`，并把当前缺口作为第一优先切片。
4. 新生成或被修改的逻辑纠偏计划必须包含本“跨类缺口转向规则”，保证后续继续发现缺口时仍按同一调度口径处理。
5. 更新 `计划/计划索引.md`：把新生成或新修改的计划临时提升为第一优先计划；原计划和原切片记录为返回点。
6. 只执行新计划的第一优先缺口切片，不顺带推进新计划后续候选项。
7. 第一优先缺口闭合后，立即停止该新计划，更新计划索引返回原计划和原切片。
8. 若第一优先缺口切片不能闭合，保留该计划为当前阻塞，不回到原计划继续补丁化绕过。
```
