## 0. 目标

补齐动态类只读功能函数，让因果类不再直接解释 `动态节点主信息类` 字段。

当前触发缺口：

```text
旧口径问题：
    动态节点主信息类::来源类型 只剩语义标签价值，没有生成动态时的真实判断作用。
    动态节点主信息类::业务语义类型 属于可由来源动作、动作名、动作相位、初始/结果状态推导的缓存。
    动态节点主信息类::名称 与 类型 曾同时写动作词，导致动作语义和动态类别混在同一入口。
```

## 1. 第一优先缺口

建议函数：

```cpp
动态节点类* 按主键解析动态节点(const std::string& 主键) const noexcept;

bool 读取动态因果生成输入(
    const 动态节点类* 动态,
    状态节点类*& 初始状态,
    状态节点类*& 结果状态,
    方法节点类*& 来源动作,
    const 语素入口节点类*& 来源动作名,
    枚举_动态因果生成类别& 因果生成类别,
    std::uint32_t& 动态层级) const noexcept;
```

实现边界：

```text
1. 函数归属 动态类.h/.cpp。
2. 不新增结构体，不新增动态主信息字段。
3. `名称` 存动作 / 动态语义；`类型` 存主动动作动态、被动动作动态、无动作状态变化动态等类别入口。
4. 删除 `动态来源类型` 与 `动态业务语义类型`，不保留双写、缓存或兼容判断。
5. 动态因果生成类别由动态类根据来源动作、来源动作名、动作相位、初始/结果状态等项目结构字段推导。
6. 输出状态、方法和语素入口均使用现有节点 / 指针 / 引用结构。
7. 不把动作语义文本作为新业务状态承载；只返回现有动作名称入口或既有动作来源。
```

4. 第一优先闭合后停止本计划，返回 因果类外部数据读取纠偏协调计划 P7。

## 2. 跨类缺口转向规则

执行本计划时，如果发现当前切片必须依赖其它类新增或补齐功能函数，按以下规则处理：

```text
1. 后续任意类缺少当前切片所需功能函数时，不在动态类或调用方临时拼字段、解释其它类主信息或新增平行结构体。
2. 若对应类已有逻辑纠偏计划，则把当前缺口加入该计划，并放到第一优先位置。
3. 若对应类没有逻辑纠偏计划，则生成 `计划/YYYYMMDD_<类名>逻辑纠偏计划_v0.1.md`，并把当前缺口作为第一优先切片。
4. 新生成或被修改的逻辑纠偏计划必须包含本“跨类缺口转向规则”，保证后续继续发现缺口时仍按同一调度口径处理。
5. 更新 `计划/计划索引.md`：把新生成或新修改的计划临时提升为第一优先计划；原计划和原切片记录为返回点。
6. 只执行新计划的第一优先缺口切片，不顺带推进新计划后续候选项。
7. 第一优先缺口闭合后，立即停止该新计划，更新计划索引返回原计划和原切片。
8. 若第一优先缺口切片不能闭合，保留该计划为当前阻塞，不回到原计划继续补丁化绕过。
```

## 7. 新增第一优先缺口：动态主信息可删除结构清理

触发口径：

```text
1. 枚举_动态因果生成类别 只是在动态类内部把“主动动作动态 / 被动动作动态 / 无动作状态变化动态”再包一层枚举，当前动态类型字段已经应承载该类别入口。
2. 枚举_动作事件相位 主要把执行成功 / 失败快照写进动态主信息，与“动作动态不是以成功 / 失败为根概念”的硬规则冲突。
3. 枚举_动态聚合方式 中 原子相邻 / 连续同向段 / 同类事件段 当前仍被二次特征聚合链真实使用；窗口聚合 / 路径压缩 没有落地生成路径，只剩预留枚举值。
```

第一优先删除对象：

```text
1. 删除 枚举_动态因果生成类别。
2. 删除 动态类::推导因果生成类别、动态类::动态因果生成类别文本，以及 读取动态因果生成输入 的枚举输出参数。
3. 删除 枚举_动作事件相位 和 动态节点主信息类::来源动作相位。
4. 删除 创建方法动作动态、绑定来源方法 等接口中的 相位 参数，并同步更新所有调用方。
5. 删除 枚举_动态聚合方式 中未落地值：窗口聚合、路径压缩。
```

保留对象：

```text
1. 暂不删除 枚举_动态聚合方式 整体。
2. 暂保留 聚合方式 字段及 原子相邻 / 连续同向段 / 同类事件段，因为二次特征应用模块当前用它区分原子动态、连续同向段和同类事件段。
3. 暂不处理 来源执行成功 / 来源错误码；它们属于相邻字段，后续单独审查，不混入本切片。
```

替代规则：

```text
1. 因果生成类别判断改为读取动态 类型 语素入口，必要时由动态类提供“是否动作动态 / 读取动态类别入口”功能函数。
2. 有动作判断不再依赖 来源动作相位，改用 来源动作、来源动作名、动态类型和初始 / 结果状态。
3. 同来源事件流比较不再比较 来源动作相位；若确实需要完成 / 失败区分，必须从输出结果场景、结果状态、运行存在特征或失败原因特征读取结构化结果。
4. 控制面板和日志只显示仍存在的结构字段，不保留旧枚举兼容文本。
```

执行约束：

```text
1. 删除时不保留兼容别名、旧枚举回填或双写路径。
2. 新增功能函数前必须先扫描 说明书/函数功能说明文档.md；已有同功能函数直接复用。
3. 新增、删除或改名函数后，重新运行 python .\tools\生成函数功能说明文档.py。

5. 本切片只做已确认可删除结构清理，不顺带扩展动态聚合新能力。
```
