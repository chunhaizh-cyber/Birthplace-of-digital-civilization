## 2. 目标

```text
1. 每个线程创建时，由创建者向控制面板线程发送创建消息。
2. 创建消息至少明确线程用途、名称、逻辑 ID、系统线程 ID、创建者、所属模块和初始状态。
3. 线程运行、阻塞、暂停、恢复、请求停止、退出前、已退出和故障等状态变化，统一发送给控制面板线程信息模块。
4. 控制面板收到消息后及时更新线程信息模块数据，并让控制面板线程状态页读取到最新事实镜像。
5. 纯线程状态不再进入自我线程治理邮箱，不生成主动动态、被动动态、方法动作动态、世界树事实或需求树输入。
6. 任务管理界面线程只收发任务管理工作线程相关消息；任务治理材料仍按任务管理上行协议进入自我线程。
```

## 3. 非目标

```text
1. 不改任务状态提交入口；任务状态变化仍必须通过 提交任务状态变化。
2. 不把控制面板线程信息表作为任务状态、需求满足、世界事实或安全 / 服务结算权威。
3. 不把线程创建、暂停、堵塞、退出解释为方法动作动态。
4. 不新增模拟测试、夹具入口或伪造线程状态样本。
5. 不恢复任务筹办 / 任务执行为本能方法。
```

## 4. 影响范围

```text
控制面板类.ixx / 控制面板类.cpp：
    增加线程状态消息接收、线程信息表更新和页面读取。

控制面板摘要线程模块.*：
    接入自身创建、运行状态变化和退出上报；避免摘要线程后台状态只存在于局部日志。

自我线程模块.*：
    接入自身创建、堵塞 / 等待 / 恢复、退出前上报；移除纯线程状态进入治理邮箱的入口或消费。

任务模块.管理界面线程.*：
    接入界面线程自身上报；拆分纯线程状态和任务治理上行消息。

任务模块.管理工作线程.* / 任务模块.管理工作线程池.*：
    由创建者上报工作线程创建；工作线程自身上报运行、阻塞、暂停、退出和故障。

外设独占线程 / 外设代理线程相关实现：
    按 002002 后续接入，不允许外设线程状态直接写自我治理邮箱或世界树真值。
```

## 5. 执行切片

```text
P0 只读盘点：
    搜索现有线程创建点、线程状态快照、控制面板线程状态树、自我治理邮箱中线程状态变化入口。
    输出允许修改文件清单和禁止触碰边界。

P1 协议与数据结构：
    新增或复用线程状态消息结构，包含消息 ID、事件类型、时间、线程用途、名称、逻辑 ID、系统线程 ID、创建者、模块、旧状态、新状态、堵塞 / 暂停 / 健康标志和原因键。
    新增控制面板线程信息表或扩展现有快照表，按逻辑线程 ID 幂等更新。

P2 控制面板消费：
    控制面板线程及时消费线程状态消息，更新线程信息模块数据。
    同状态重复消息可合并；退出 / 故障消息不得被旧运行消息覆盖。

P3 创建与退出上报：
    自我线程、任务管理界面线程、任务管理工作线程池、控制面板摘要线程先接入创建消息和退出前消息。
    创建者负责创建消息；线程自身负责退出前消息；异常退出由创建者或管理者补报故障。

P4 状态变化上报：
    在线程运行、阻塞 / 等待、暂停、恢复、请求停止、故障等状态变化点发送控制面板消息。
    发送失败只记录独立错误日志，不阻塞业务线程。

P5 自我治理邮箱收口：
    移除或停用纯线程状态变化进入自我线程治理邮箱的路径。
    保留任务管理派生需求、任务管理结果状态、执行前许可、观察事实承接和自检报告等治理消息。

P6 显示与真实验证：
    控制面板线程状态页展示线程用途、名称、逻辑 ID、系统线程 ID、创建者、当前状态、最近事件和更新时间。
    用真实运行日志、状态快照和控制面板数据核对，不使用伪造入口。
```

## 6. 验证证据

```text
1. 修改代码前写预测：哪些线程应出现创建消息，哪些状态变化应刷新控制面板，哪些消息不得进入自我治理邮箱。
2. Debug x64 构建退出码 0。
3. 真实运行 self-check-log 退出码 0。
4. 最新日志窗口能看到自我线程、任务管理界面线程、任务管理工作线程和控制面板摘要线程的创建 / 退出或状态变化上报。
5. 控制面板线程信息模块能读到线程用途、名称、逻辑 ID、系统线程 ID、当前状态和最近更新时间。
6. 自我线程治理邮箱不再出现纯线程创建、暂停、堵塞、恢复、退出或故障消息。
7. 任务管理结果状态、派生需求、执行前许可和观察事实承接仍按原治理协议运行。
8. 未新增线程状态动作动态、世界树事实或需求树输入。
```

## 7. 风险与回退

```text
风险 1：线程状态消息发送点持锁过深，可能放大阻塞。
处理：状态上报只写轻量队列；不可在业务锁内等待控制面板消费。

风险 2：任务工作线程状态和任务治理结果混淆。
处理：纯状态只发控制面板；绑定任务执行尝试和任务治理语义的材料仍发任务管理界面线程，再由其按上行协议处理。

风险 3：控制面板不可用导致业务线程被拖住。
处理：发送失败记录独立日志并继续；控制面板线程信息表不是业务权威。

风险 4：退出消息丢失。
处理：线程自身退出前发送；创建者 / 管理者在 join 或异常路径补报最终状态。
```

## 8. 暂停条件

```text
1. 发现现有代码把线程状态作为任务状态、需求输入、世界事实或动作动态来源使用。
2. 发现控制面板线程信息表需要新增主信息结构并可能违反 005 新增准入约束。
3. 发现线程状态发送需要在关键业务锁内同步等待控制面板消费。
4. 真实验证必须伪造线程样本才能通过。
```
