# P1 持续执行状态推导通用化小方案 v0.1

日期：2026-06-09

状态：已闭合；代码已改为通用部分推进判定，构建和真实运行通过。

## 1. 触发依据

```text
计划/20260608_任务持续执行与同目标任务去重纠偏计划_v0.1.md 的 P1 要求：
    删除或旁路 私有_方法是持续观察批次方法 对任务状态推导的决定作用。
    有推进未达成的执行回执可保持 执行中。

用户 2026-06-09 口径：
    相机外设四个方法先不用继续优化。
    结构_任务工作结果 后续需要删除，可以跳过优化。
```

## 2. 目标

```text
把“执行阶段 + 目标结果不符合 + 本轮有推进 + 有推进未达成”推导为 执行中 的依据从方法 ID 白名单改为通用回执条件。

不改：
    相机外设四方法实现。
    结构_任务工作结果。
    任务状态提交入口。
```

## 3. 边界

```text
不得把无推进未达成推导为 执行中。
不得把动作失败、等待子需求、需要创建或复用子需求、治理结果不可接受推导为 执行中。
不得把部分推进当作完成或已结算。
任务状态变化仍必须通过 提交任务状态变化。
任务筹办 / 任务执行仍是普通生命周期函数。
```

## 4. 实施

```text
修改点：
    任务模块.管理工作线程.ixx

动作：
    删除或旁路 私有_方法是持续观察批次方法 的状态推导依赖。
    将 私有_任务推进回执是持续观察批次推进 改为通用部分推进判定。
    通用条件：
        阶段 = 执行；
        状况 = 目标结果不符合；
        本轮是否有推进 = true；
        执行结果类型 = 有推进未达成；
        治理结果可接受 = true；
        需要创建或复用子需求 = false；
        当前任务目标达成 = false。
    命中后推导任务状态为 执行中，后续治理去向仍按既有逻辑进入运行。
```

## 5. 验收

```text

Debug x64 构建通过。

日志保留任务状态动作动态。
不出现任务状态逻辑错误、旧完整本能调用锚点或 [FTL]。
若真实运行没有自然命中有推进未达成样本，只记录未自然命中，不新增模拟样本。
```
