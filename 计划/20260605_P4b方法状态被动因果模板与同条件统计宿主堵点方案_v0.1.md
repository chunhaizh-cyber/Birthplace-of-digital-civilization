# P4b 方法状态被动因果模板与同条件统计宿主堵点方案 v0.1

## 目标

确认 `方法状态` 被动因果模板是否可以在当前代码边界内落账，并确认 `结果符合次数 / 结果不符合次数 / 新结果分支数量` 的宿主。

## 代码对账结论

### 1. 初始因果模板 TSV 口径修正

当前 `data/initial_causal_templates.tsv` 结构为：

```text
名称
层级
主果宿主
主果特征
因宿主
因特征集
```

该文件存储的是被动因果，只需要表达：

```text
具备哪些条件后，必然能够得到哪个结果。
```

因此 TSV 不需要动作语义列，也不应该把本能方法写成因动作。

当前代码读取器固定要求 6 列，并在安全风险树应用路径中调用：

```text
私有_确保安全风险树I64比较_线程侧(
    当前值 = 安全因果风险树明确状态_未明确,
    目标值 = 安全因果风险树明确状态_已明确)
```

所以现有 TSV 可以表达“条件特征集合 -> 结果特征”这一类被动因果，但当前应用入口只服务安全风险树明确状态，不是通用方法状态派生入口。

方法状态如果进入该 TSV，应该表达为被动条件链，例如：

```text
条件：
    方法动作数量已满足
    方法可执行入口数量已满足
    方法条件结果对数量已满足
结果：
    方法状态可用条件已满足

条件：
    方法最近连续成功次数已满足
    同一条件结果不符合次数为 0
    新结果分支数量为 0
结果：
    方法状态好用条件已满足
```

剩余问题不在于 TSV 要不要存动作，而在于这些“条件已满足 / 结果已满足”的特征是否已有宿主、读写桥和生成路径。

### 2. 当前方法状态被动模板缺应用入口

```text
data/initial_causal_templates.tsv
    当前由 私有_应用安全因果风险树初始模板种子_线程侧 读取；
    该函数只接收 安全目标宿主 / 当前场景宿主；
    没有把 target 解析为“目标方法虚拟存在”的方法状态派生入口。
```

因此不能直接新增方法状态行并认为它会作用到目标方法。

### 3. 被动触发初始因果公共口存在，但不适合直接在本切片调用

自我线程中存在：

```text
私有_读取或确保被动触发初始因果_线程侧
私有_追加被动触发初始因果证据_线程侧
私有_增强被动触发初始因果_线程侧
```

这些函数能把 `因动作语义键 / 因动作名称` 标为 `被动动作`。

但对 `data/initial_causal_templates.tsv` 来说，动作语义不是必要字段；这些公共口更适合用于“被动触发模板读取 / 证据增强”，不是把 TSV 改成动作模板。

同时它们位于 `自我线程模块.impl.cpp` 私有区，并且当前文件已有未提交改动；本切片若直接改，会跨入自我线程私有因果接口、模板比较构造和既有脏改冲突区。

### 4. 同一条件统计宿主未定义

当前 `结果符合次数 / 结果不符合次数` 写入位置在 `自我动作实现模块.ixx` 的条件结果对归并路径：

```text
条件原已存在 && 结果原已存在：
    方法虚拟存在.结果符合次数 += 1

条件原已存在 && 条件下原有结果：
    方法虚拟存在.结果不符合次数 += 1
```

这说明当前计数宿主是“方法虚拟存在整体”，不能严格表达：

```text
同一个条件被命中过 3 次以上，
且没有生成新的结果对。
```

若要严格表达，需要先选择宿主：

```text
条件节点宿主
条件结果对宿主
结果节点宿主
方法虚拟存在 + 条件签名键
```

当前没有规范指定。

### 5. 新结果分支数量未成型

当前只有 `结果不符合次数`，没有独立：

```text
新结果分支数量
```

也没有明确它的宿主、读写桥和任务筹办映射。

## 当前无法继续直接实现的原因

```text
1. TSV 口径已确认：只表达被动条件 -> 必然结果，不需要动作语义；
2. 当前 TSV 应用入口只服务安全风险树，不会把 target 解释为目标方法虚拟存在；
3. 方法状态条件需要先有“数量底账已满足”的条件特征或等价二次特征；
4. 不能把方法虚拟存在整体的结果符合次数冒充为同一条件统计；
5. 不能在未定义宿主时新增新结果分支数量；
6. 不能在自我线程私有实现已有未提交改动时，混入跨线程因果模板接口改造。
```

## 需要确认的问题

1. 方法状态被动模板如何接入 TSV：

```text
A. 复用现有 6 列 TSV，新增“方法状态被动因果种子应用入口”，让 target 绑定目标方法虚拟存在；
B. 不走 TSV，新增专门的“方法状态派生规则模板”创建入口；
C. 先不落模板，只在 P5 用真实日志验证被动动态排除主动反推。
```

2. 同一条件统计宿主采用哪一种：

```text
条件节点
条件结果对
结果节点
方法虚拟存在 + 条件签名键
```

3. `新结果分支数量` 是否新增独立特征，还是暂用 `结果不符合次数 > 0` 作为纠偏缺口。

## 建议停点

P4a 已清理学习本能主动 `方法状态` 缺口并补被动动态日志锚点。

P4b 在上述三个口径未确认前不继续改代码。
