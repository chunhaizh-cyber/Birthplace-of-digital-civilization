# P4b 方法状态被动因果模板与同条件统计宿主堵点方案 v0.1

## 目标

确认 `方法状态` 被动因果模板是否可以在当前代码边界内落账，并确认 `结果符合次数 / 结果不符合次数 / 新结果分支数量` 的宿主。

## 代码对账结论

### 1. 初始因果模板 TSV 不足以表达方法状态量化模板

当前 `data/initial_causal_templates.tsv` 结构为：

```text
名称
层级
主果宿主
主果特征
因宿主
因特征集
```

读取器固定要求 6 列，并在应用时调用：

```text
私有_确保安全风险树I64比较_线程侧(
    当前值 = 安全因果风险树明确状态_未明确,
    目标值 = 安全因果风险树明确状态_已明确)
```

因此它目前只能表达类似：

```text
某特征 未明确 -> 已明确
依赖另一组特征 未明确 -> 已明确
```

不能表达：

```text
方法动作数量 > 0
方法可执行入口数量 > 0
方法条件结果对数量 > 0
方法最近连续成功次数 > 3
结果不符合次数 = 0
新结果分支数量 = 0
    -> 方法状态 = 可用 / 好用
```

也不能在 TSV 中声明：

```text
因动作语义=被动动作
目标值=方法状态_可用 / 方法状态_好用
比较关系=> / >= / =
宿主=目标方法 / 条件节点 / 条件结果对
```

### 2. 被动触发初始因果公共口存在，但不适合直接在本切片调用

自我线程中存在：

```text
私有_读取或确保被动触发初始因果_线程侧
私有_追加被动触发初始因果证据_线程侧
私有_增强被动触发初始因果_线程侧
```

这些函数能把 `因动作语义键 / 因动作名称` 标为 `被动动作`。

但它们位于 `自我线程模块.impl.cpp` 私有区，并且当前文件已有未提交改动；本切片若直接改，会跨入自我线程私有因果接口、模板比较构造和既有脏改冲突区。

### 3. 同一条件统计宿主未定义

当前 `结果符合次数 / 结果不符合次数` 写入位置在 `自我动作实现模块.ixx` 的条件结果对归并路径：

```text
条件原已存在 && 结果原已存在：
    方法虚拟存在.结果符合次数 += 1

条件原已存在 && 条件下原有结果：
    方法虚拟存在.结果不符合次数 += 1
```

这说明当前计数宿主是“方法虚拟存在整体”，不能严格表达：

```text
同一个条件被命中过 3 次以上，
且没有生成新的结果对。
```

若要严格表达，需要先选择宿主：

```text
条件节点宿主
条件结果对宿主
结果节点宿主
方法虚拟存在 + 条件签名键
```

当前没有规范指定。

### 4. 新结果分支数量未成型

当前只有 `结果不符合次数`，没有独立：

```text
新结果分支数量
```

也没有明确它的宿主、读写桥和任务筹办映射。

## 当前无法继续直接实现的原因

```text
1. 不能把方法状态量化阈值模板硬塞进当前 6 列 TSV；
2. 不能把方法虚拟存在整体的结果符合次数冒充为同一条件统计；
3. 不能在未定义宿主时新增新结果分支数量；
4. 不能在自我线程私有实现已有未提交改动时，混入跨线程因果模板接口改造；
5. 若继续强改，会违反“先有底账，再刷新状态”和“不得虚构模板或宿主”的边界。
```

## 需要确认的问题

1. 方法状态被动模板应走哪条路线：

```text
A. 扩展 data/initial_causal_templates.tsv 架构，支持宿主、比较关系、当前值、目标值、动作语义；
B. 不扩展 TSV，新增专门的“方法状态派生规则模板”创建入口；
C. 先不落初始模板，只在 P5 用真实日志验证被动动态排除主动反推。
```

2. 同一条件统计宿主采用哪一种：

```text
条件节点
条件结果对
结果节点
方法虚拟存在 + 条件签名键
```

3. `新结果分支数量` 是否新增独立特征，还是暂用 `结果不符合次数 > 0` 作为纠偏缺口。

## 建议停点

P4a 已清理学习本能主动 `方法状态` 缺口并补被动动态日志锚点。

P4b 在上述三个口径未确认前不继续改代码。
