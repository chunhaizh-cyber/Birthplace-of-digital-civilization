# P4b 方法状态被动因果模板与同条件统计宿主堵点方案 v0.1

## 目标

确认 `方法状态` 被动因果模板是否可以在当前代码边界内落账，并确认 `结果符合次数 / 结果不符合次数 / 新结果分支数量` 的宿主。

## 代码对账结论

### 1. 初始因果模板 TSV 口径修正

当前 `data/initial_causal_templates.tsv` 结构为：

```text
名称
层级
主果宿主
主果特征
因宿主
因特征集
```

该文件存储的是被动因果，只需要表达：

```text
具备哪些条件后，必然能够得到哪个结果。
```

因此 TSV 不需要动作语义列，也不应该把本能方法写成因动作。

当前代码读取器固定要求 6 列，并在安全风险树应用路径中调用：

```text
私有_确保安全风险树I64比较_线程侧(
    当前值 = 安全因果风险树明确状态_未明确,
    目标值 = 安全因果风险树明确状态_已明确)
```

所以现有 TSV 可以表达“条件特征集合 -> 结果特征”这一类被动因果，但当前应用入口只服务安全风险树明确状态。

最新口径修正：这不是要补一个“可被任务筹办查找的方法状态派生方法入口”。被动因果只是内部治理依据；任务虚拟存在 / 方法虚拟存在特征的被动变化应由内部自动函数或普通代码写入。

方法状态如果进入该 TSV，应该表达为被动条件链，例如：

```text
条件：
    方法动作数量已满足
    方法可执行入口数量已满足
    方法条件结果对数量已满足
结果：
    方法状态可用条件已满足

条件：
    方法最近连续成功次数已满足
    同一条件结果不符合次数为 0
    新结果分支数量为 0
结果：
    方法状态好用条件已满足
```

剩余问题不在于 TSV 要不要存动作，而在于这些“条件已满足 / 结果已满足”的特征是否已有宿主、读写桥、生成路径，以及哪些内部治理写点会读取这些依据并自动写值。

### 2. 当前缺少内部治理写点与被动因果依据的绑定

```text
data/initial_causal_templates.tsv
    当前由 私有_应用安全因果风险树初始模板种子_线程侧 读取；
    该函数只接收 安全目标宿主 / 当前场景宿主；
    没有接入任务虚拟存在 / 方法虚拟存在自动改值治理写点。
```

因此不能直接新增方法状态行并认为它会自动改变目标方法状态。

正确方向是：

```text
内部治理写点已知道本轮要改哪个任务虚拟存在 / 方法虚拟存在；
该写点读取或命中被动因果依据；
条件成立后由内部代码自动写入目标特征值；
被动因果作为治理依据和证据，不作为本能方法。
```

### 3. 被动触发初始因果公共口存在，但不适合直接在本切片调用

自我线程中存在：

```text
私有_读取或确保被动触发初始因果_线程侧
私有_追加被动触发初始因果证据_线程侧
私有_增强被动触发初始因果_线程侧
```

这些函数能把 `因动作语义键 / 因动作名称` 标为 `被动动作`。

但对 `data/initial_causal_templates.tsv` 来说，动作语义不是必要字段；这些公共口更适合用于“被动触发模板读取 / 证据增强”，不是把 TSV 改成动作模板。

同时它们位于 `自我线程模块.impl.cpp` 私有区，并且当前文件已有未提交改动；本切片若直接改，会跨入自我线程私有因果接口、模板比较构造和既有脏改冲突区。

### 4. 同一条件统计宿主已在 P4b1 收束

当前 `结果符合次数 / 结果不符合次数` 写入位置在 `自我动作实现模块.ixx` 的条件结果对归并路径：

```text
条件原已存在 && 结果原已存在：
    方法虚拟存在.结果符合次数 += 1

条件原已存在 && 条件下原有结果：
    方法虚拟存在.结果不符合次数 += 1
```

P4b1 已将计数宿主从“方法虚拟存在整体”迁移为：

```text
条件节点 -> 条件场景
```

原因：

```text
方法节点不是世界树基础信息节点，不能直接写特征；
条件场景是基础信息节点，并且创建 / 绑定在目标方法虚拟存在之下；
因此它能同时表达“目标方法隔离”和“同一条件”。
```

条件场景现在写入 `样本次数 / 最近样本时间 / 结果符合次数 / 结果不符合次数 / 新结果分支数量`。

### 5. 新结果分支数量已在 P4b1 成型

P4b1 已新增：

```text
新结果分支数量
```

触发口径：

```text
同一条件已存在结果节点；
本次实际结果场景与既有结果场景不等价；
归并新增结果节点；
则 条件场景.新结果分支数量 += 1。
```

该特征只作为条件不稳定证据，不生成“把新结果分支数量降到 0”的普通派生需求。

### 6. 当前代码状态流程图重梳理后的 P4b2 口径

`流程图/20260605_当前代码状态_自我内部治理被动因果树_任务方法虚拟存在_v0.2.md` 已把 P4b2 口径收束为：

```text
正式入账事实 / 回执 / 状态动作动态
-> 生命周期提交链、后处理链或结算链自动出现治理结果
-> 自动改值对象是任务虚拟存在或方法虚拟存在上的特征
```

因此 P4b2 的第一步不再是扩展 TSV 应用入口，而是：

```text
按流程图对账真实代码写点：
    任务虚拟存在写点；
    方法虚拟存在写点；
    任务状态动作动态 D1 写点；
    方法状态动作动态写点；
    父任务重筹办写点；
    需求收束 / 结算 / 因果吸收写点。
```

安全需求树两张流程图只用于确认消费边界：

```text
安全需求树主干只允许需求节点和 AND / OR 逻辑组织需求节点；
自我线程维护、安全评估、扫描、跟踪、提交入口只作为生产者或承接方式；
第一次扫描只提交发现存在或发现特征事实，有可比历史后才提交变化事实。
```

## 当前无法继续直接实现的原因

```text
1. TSV 口径已确认：只表达被动条件 -> 必然结果，不需要动作语义；
2. 当前还没有按流程图对账哪些任务 / 方法虚拟存在特征自动改值写点已经存在；
3. 方法状态条件需要先有“数量底账已满足”的条件特征或等价读取逻辑；
4. 是否需要读取 TSV 必须由内部治理写点决定，不能从 TSV 反推一个可执行方法；
5. 现有 自我_提交方法状态变化 路径是否误把被动自动改值做成本能方法动作，尚未复查；
6. 父任务重筹办、需求收束、结算、因果吸收这些被动果的权威动作动态归属尚未按流程图逐一确认。
```

```text

```

