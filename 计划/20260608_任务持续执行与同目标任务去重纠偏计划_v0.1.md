# 任务持续执行与同目标任务去重纠偏计划 v0.1

日期：2026-06-08

## 1. 背景

本计划只制定任务管理语义纠偏方案，不修改代码。当前主动性能切片仍以 `计划/计划索引.md` 为准；本计划后续进入实现前，需要单独切片并避免混入当前 S2c 性能锁复核范围。

本轮口径：

```text
1. 任务管理执行回路必须是通用能力，不按观察、服务、安全等业务方法单独设计。
2. 方法声明不增加执行形态；界面线程按结构化消息分类处理。
3. 任务处于执行中时，允许方法返回部分结果并做阶段性结果入账；任务自身继续保持执行中。
4. 已结算仍只表示任务完成后的价值结算后处理，不用于部分结果。
5. 为新需求承接任务时，必须先查当前任务树中是否已有同目标任务；可复用时不新建并行任务。
6. 同目标任务严格检查目标宿主、目标特征类型和目标方向；目标值不作为同任务身份硬等值条件，只进入覆盖 / 升级判断。
```

## 2. 当前代码逻辑梳理

### 2.1 任务状态与回执基础已经具备

`任务主信息类.h` 已定义 `执行中`、`待重筹办`、`完成`、`已结算` 等状态，其中 `已结算` 注释为“任务目标已完成，且任务完成后的价值结算后处理已执行”。

`任务模块.筹办.ixx` 的 `结构_任务推进回执` 已包含：

```text
当前任务目标达成
本轮是否有推进
本轮推进量
剩余差距
完成度百万分比
执行结果类型
```

并且 `执行结果类型` 已区分：

```text
目标已达成
有推进未达成
无推进未达成
退步
不可比较
```

结论：持续执行所需的基础回执字段已存在，不需要新增“方法声明执行形态”。

### 2.2 执行结果评价已经能识别部分推进

`任务模块.管理工作线程.ixx` 中，执行结果会比较实际状态、目标状态和之前状态：

```text
目标达成 -> 目标结果符合 / 目标已达成
未达成但有推进 -> 目标结果不符合 / 有推进未达成
未达成且无推进 -> 目标结果不符合 / 无推进未达成
退步 -> 退步
```

同时上行 `结构_任务管理结果状态消息` 已有 `部分完成` 结果状态。

结论：代码已经有“部分结果 / 部分完成”的表达基础，但状态推导仍未完全按通用部分结果协议收束。

### 2.3 当前持续执行纠偏仍带业务特判

`任务模块.管理工作线程.ixx` 当前有 `私有_方法是持续观察批次方法`，按本能方法 ID 判断：

```text
自我_明确当前场景持续观察需求
安全_持续观察当前场景
自我_验证外设观察像素簇候选
自我_识别外设观察材料
自我_扫描已识别区域
自我_跟踪指定存在
```

随后 `私有_任务推进回执是持续观察批次推进` 只有在命中这些方法时，才把 `执行阶段 + 目标结果不符合 + 本轮有推进 + 有推进未达成` 推导为 `执行中`。

结论：这与“任务管理执行回路必须通用”冲突。正确做法应按回执 / 消息分类判断，而不是按具体方法 ID 判断。

### 2.4 `执行中` 已经能进入运行派发

`任务模块.管理界面线程.impl.cpp` 的调度裁决中，`就绪`、`排队中`、`执行中` 都会被判定为执行工作项。

`任务模块.管理工作线程.ixx` 的治理结果也已把 `执行中` 归入可运行，并将下一步去向设置为 `进入运行`。

结论：一旦通用状态推导能把部分推进结果保持为 `执行中`，现有派发路径可以继续运行，不需要新增任务状态。

### 2.5 任务创建入口目前只做需求主键幂等，不做同目标任务复用

自我线程发起任务时，`自我线程模块.impl.cpp` 构造：

```text
请求类型 = 发起任务
来源需求 = 当前需求
允许创建任务信息节点 = true
允许复用等待任务 = true
幂等键 = 发起任务|需求=<需求主键>
```

任务管理界面线程接收请求后，先调用 `私有_尝试复用幂等承接结果`。该函数只按幂等键查历史承接结果，并且只复用等待态承接结果。若未命中，则在 `发起任务` 分支中直接调用 `私有_按需求创建任务并初始化` 创建新任务。

结论：当前复用范围是“同一需求主键的等待承接幂等”，不是“同目标任务复用”。新需求即使目标宿主、目标特征类型、目标方向相同，也会走新任务创建。

### 2.6 自我线程有局部去重，但不是通用任务去重

自我线程活动需求任务化前会检查当前需求自己的 `对应任务 / 任务列表`，避免同一需求重复发起任务。

另外学习缺口有 `私有_查找同方法活跃学习任务_线程侧`，但它是学习任务专用，签名包含来源方法和目标状态键，不能作为通用同目标任务复用规则。

结论：现有去重是局部防重复，不是任务管理入口的通用同目标复用能力。

### 2.7 需求层已有目标语义和方向基础

`需求主信息类.h` 已明确：

```text
需求去重以同父子链上的目标特征类型和方向重叠为准。
```

`需求类` 已提供：

```text
读取需求目标特征类型
需求目标语义视图
生成需求方向签名
比较需求方向签名
需求方向同向 / 需求方向反向
```

结论：任务去重不应重新发明业务字段，应复用需求目标语义视图和方向签名能力，并补齐目标值覆盖 / 升级判断。

## 3. 目标口径

### 3.1 持续执行目标口径

通用规则：

```text
执行阶段结果消息 = 部分完成
且目标未达成
且本轮有推进
且执行结果类型 = 有推进未达成
且没有阻塞性派生需求 / 等待条件 / 显式重筹办请求 / 失败
=> 任务状态保持 执行中
=> 结果按批次提交和阶段性入账
=> 下一步继续进入运行
```

以下情况才进入 `待重筹办`：

```text
目标 / 作用对象 / 参数 / 方法有效性 / 前置条件 / 安全约束发生变化
需要重新选择方法或重新组织条件
方法明确返回重筹办请求
本轮无推进且需要换路径
```

以下情况进入 `等待中`：

```text
缺条件
等待子需求
等待外部支撑
阻塞性派生需求已提交
```

以下情况进入 `完成 -> 已结算`：

```text
目标达成
任务状态通过 提交任务状态变化 进入完成
完成后价值反馈链执行
任务状态通过 提交任务状态变化 进入已结算
```

### 3.2 同目标任务复用目标口径

同任务身份严格匹配：

```text
目标宿主一致
目标特征类型一致
目标方向一致
作用范围 / 场景范围兼容
事实时点 / 有效期兼容
```

目标值不是同任务身份硬条件。目标值只用于判断：

```text
已有任务目标是否覆盖新需求
新需求目标是否强于已有任务，需要升级任务目标
两者是否不可合并
```

判断规则：

```text
目标特征类型不同 -> 不复用
目标方向不同 -> 不复用
目标值不同但方向一致 -> 进入覆盖 / 升级判断
```

复用策略：

```text
已有任务目标覆盖新需求 -> 新需求挂接已有任务，不新建
新需求目标更强 -> 提交任务目标升级 / 待重筹办，不新建并行任务
目标区间仅重叠或精确等于目标值冲突 -> 不合并，或等待上层规则裁决
已有任务已完成 / 已结算 -> 只能复用结果事实或结算证据，不能复用执行中任务壳
已有任务失败 / 取消 / 结果失效 -> 不复用
```

## 4. 纠偏切片计划

### P0 计划与边界冻结

目标：将本计划作为独立语义纠偏线登记，进入实现前不得混入当前 S2c 性能切片。

动作：

```text
1. 保持任务筹办 / 任务执行是普通生命周期函数。
2. 保持任务状态变化必须通过 提交任务状态变化。
3. 保持 已结算 只表示完成后的价值结算后处理。
4. 不新增方法声明执行形态。
5. 不按业务方法 ID 设计任务管理状态机。
```

验收：

```text
计划文件存在；
未改代码；
未改当前主动性能切片允许范围。
```

### P1 持续执行状态推导通用化

目标：移除“持续观察方法 ID 白名单”对任务状态推导的决定作用。

建议修改点：

```text
任务模块.管理工作线程.ixx
```

动作：

```text
1. 删除或旁路 私有_方法是持续观察批次方法 的状态机依赖。
2. 将 私有_任务推进回执是持续观察批次推进 改为通用部分推进判定。
3. 判定条件改为：
   阶段 = 执行；
   状况 = 目标结果不符合；
   本轮是否有推进 = true；
   执行结果类型 = 有推进未达成；
   治理结果可接受 = true；
   不存在需要创建或复用子需求的阻塞；
   不存在显式重筹办 / 等待 / 失败请求。
4. 命中后推导状态为 执行中，下一步去向为 进入运行。
5. 未命中时仍按现有等待、重筹办、失败、完成规则处理。
```

验收：

```text
任务管理状态推导中不再出现观察方法 ID 白名单；
有推进未达成的执行回执可保持 执行中；
无推进未达成仍不得假装持续运行；
任务状态仍由 提交任务状态变化 写入。
```

### P2 部分结果消息分类与阶段性入账

目标：让界面线程 / 自我线程按通用消息分类处理部分结果，不把部分结果误当完成或已结算。

建议修改点：

```text
任务模块.工作线程消息协议.ixx
任务模块.管理工作线程.ixx
自我线程模块.impl.cpp
```

动作：

```text
1. 复用 结果状态消息 的 部分完成 分类。
2. 对 部分完成 消息补齐或约束以下通用字段来源：
   任务主键；
   执行尝试主键；
   完成度；
   是否仍有未满足项；
   未满足项类型；
   是否需要父任务处理；
   是否需要自我线程重判。
3. 如阶段性入账需要防重复，补一个批次幂等键：
   任务主键 + 方法运行 / 执行尝试 + 结果批次序号或输出场景主键。
4. 自我线程处理 部分完成 时：
   可以落输出结果场景、关键中间状态、过程证据或阶段性账；
   不调用正式来源需求满足收束；
   不触发任务已结算；
   不把需求满足裸写成最终事实。
5. 成功 / 收束完成 消息仍进入现有完成、需求回写和价值反馈链。
```

验收：

```text
部分完成消息不会推进任务到 已结算；
部分完成消息可被记录为阶段性证据；
正式结算仍要求任务完成 / 已结算状态动态和结算证据；
重复批次不会重复入账。
```

### P3 任务发起入口改为“查找或创建任务”

目标：任务管理界面线程在创建新任务前，先按同目标任务规则查当前任务树。

建议修改点：

```text
任务模块.管理界面线程.impl.cpp
需求类.cpp / 需求类.h
```

动作：

```text
1. 在 提交任务治理请求 的 发起任务 分支中，创建任务前插入：
   私有_查找可复用同目标任务(来源需求)。
2. 查找范围为当前任务树中的任务头，优先活动任务：
   未启动 / 筹办中 / 待重筹办 / 就绪 / 排队中 / 执行中 / 等待中 / 挂起。
3. 对每个候选任务解析来源需求，构造目标签名：
   目标宿主；
   目标特征类型；
   目标方向；
   作用场景 / 范围；
   有效期。
4. 严格判断同目标身份：
   目标宿主一致；
   目标特征类型一致；
   目标方向一致；
   场景范围兼容；
   有效期兼容。
5. 对目标值只做覆盖 / 升级判断：
   已有任务目标覆盖新需求 -> 复用；
   新需求目标强于已有任务 -> 提交目标升级并重筹办；
   不可比较 -> 不复用。
6. 复用时：
   不调用 私有_按需求创建任务并初始化；
   调用 需求类::绑定对应任务 将新需求挂接到已有任务；
   返回承接结果，任务信息节点指向已有任务；
   如需继续执行或重筹办，只提交治理请求 / 状态变化，不裸写状态。
```

验收：

```text
同目标新需求不会创建并行任务；
目标特征类型或方向不同绝不复用；
目标值不同但方向一致时进入覆盖 / 升级逻辑；
失败 / 取消 / 失效任务不作为执行壳复用；
完成 / 已结算任务只复用结果证据，不复用运行壳。
```

### P4 多需求共享任务结果扇出

目标：同一任务被多个需求复用后，部分结果、完成结果和结算反馈能按需求路径分别处理。

建议修改点：

```text
自我线程模块.impl.cpp
需求类.cpp
```

动作：

```text
1. 新增或收束通用查询：
   收集任务挂接需求集(任务头)。
2. 查询来源：
   每个需求的 对应任务；
   每个需求的 任务列表。
3. 部分完成：
   扇出为各挂接需求的阶段性过程证据；
   不写需求最终满足；
   不正式结算。
4. 完成 / 收束完成：
   按每条需求路径独立判断满足关系、父链、预算和防重复令牌；
   一个任务完成动态可以作为共同上游证据；
   每条需求自己的满足事实和结算令牌必须分开。
5. 已结算：
   仍只代表任务完成后处理完成；
   多需求共享时不能重复结算同一需求路径。
```

验收：

```text
共享任务完成后，所有挂接需求都能被检查；
部分结果不会关闭需求；
每条需求路径有独立防重复令牌；
不会因共享任务导致重复核心价值入账。
```

## 5. 实现顺序建议

```text
第一步：P1
    先移除持续执行方法 ID 特判，改为通用回执分类。

第二步：P2
    让部分完成消息明确只做阶段性入账 / 过程证据，不触发完成结算。

第三步：P3
    把任务发起入口从“创建任务”改为“查找或创建任务”。

第四步：P4
    补多需求共享任务的结果扇出和独立防重复结算。

第五步：P5
    用真实构建和真实日志验证；无自然样本时只登记等待条件。
```

## 7. 当前判断

当前代码不完全满足本轮口径：

```text
持续执行：
    基础字段和派发路径基本具备，但状态推导仍带持续观察方法 ID 特判，需要通用化。

任务去重：
    当前只防止同一需求主键重复任务化，且界面线程只复用幂等等待承接结果；
    尚未在创建任务前按目标宿主、目标特征类型、目标方向检查同目标任务。

结算：
    已结算语义当前仍符合“完成后价值结算后处理”，不应改成部分结果状态。
```
