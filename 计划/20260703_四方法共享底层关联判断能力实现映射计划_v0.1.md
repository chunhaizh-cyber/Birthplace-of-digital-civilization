## 1. 设计条款清单

### 1.1 必须实现

```
1. 四方法可共享底层纯判定能力和材料处理能力，但不得以本能方法身份互调。
2. 第一版共享能力优先复用视觉观察融合模块、外设观察报告队列、场景体素模块和 D5 缺口链。
3. 共享能力只输出候选、评分、计数、状态码、缺口材料、建议后续方法类型和可回查证据句柄。
4. 观察、识别、跟踪、扫描只能读取共享结果，再按各自方法职责继续处理。
5. 若需要其它方法承接，必须输出结构化缺口 + 建议后续方法类型，经需求树、任务筹办和方法选择承接。
6. 判断型状态必须按 1175 由材料、评分、数量、版本、来源、阈值和任务上下文收束。
```

### 1.2 禁止实现

```
1. 禁止新增第五个感知本能方法。
2. 禁止新增 C++ 长期业务结构体作为默认解法。
3. 禁止观察、扫描、识别、跟踪直接互相调用。
4. 禁止共享能力写世界树事实、稳定存在体素、场景体素缓存、需求满足或动作动态。
5. 禁止共享能力直接派生需求入树。
6. 禁止把候选评分最高写成唯一归属事实。
7. 禁止把遮挡候选写成存在仍存在。
8. 禁止把自由空间冲突写成存在已消失。
9. 禁止新增普通布尔值 一阶特征表达候选可用、唯一归属成立、需复验、可提交等判断型状态。
```

### 1.3 后续待补

```
1. 共享能力真实函数入口和已有函数签名。
2. 关联判断结果类型、来源类型、建议后续方法类型的真实值域落点。
3. 四方法真实入口和现有调用点互调风险清单。
4. 共享能力缺口到 D5 结构化信息缺口链的适配函数。
5. 四方法实现映射计划中对共享能力读取方式的逐方法接入。
```

### S4 四方法读取共享结果

目标：

```
每个方法只读取共享结果，不直接调用其它方法。

分工：

```
