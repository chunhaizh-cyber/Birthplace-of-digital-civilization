```text
RULE-DEMAND-003：每类入树拒绝原因必须有处理方案。
RULE-DEMAND-004：代码缺陷型拒绝必须走开发诊断闭环。
RULE-DEMAND-005：来源任务必须接收入树成功或拒绝回执。
```

## 1. 目标

把 v0.4 流程图中的治理闭环落到代码结构：

```text
需求前材料
    -> 目标归一 / 三态比较
    -> 自我线程入树裁决
    -> 成功：正式需求节点
    -> 拒绝：结构化拒绝回执
    -> 拒绝回执治理处理器
    -> 来源任务挂起、重筹办、转学习、转观察、转材料处理、合并冷却或开发诊断
```

其中代码缺陷固定走开发诊断闭环：

```text
代码缺陷型拒绝
    -> 开发诊断项
    -> 来源路径隔离
    -> 来源任务实现缺陷阻断回执
    -> 日志 / 弹窗 / 报错
    -> 代码修正 + 编译 + 回归测试后关闭
```

## 2. 不解决什么

```text
1. 不把代码缺陷普通需求化。
2. 不把任务筹办 / 任务执行恢复成本能方法。
3. 不用自由文本、日志或摘要字段承载机器判断。
4. 不在第一切片改价值结算和父链重判；先完成拒绝回执主干。
5. 不宣称需求生成与治理闭环、拒绝回执治理闭环或开发诊断闭环已经由代码实现。
```

```text
    任务价值反馈、父任务等待条件变化、父链重判已有基础入口
```

### 3.2 主要缺口

```text
1. 目前没有 结构_需求入树拒绝回执。
2. 目前没有 枚举_拒绝闭环类型、拒绝处理状态、拒绝终态检查。
3. 目前没有 结构_开发诊断项 或开发诊断账本。
4. 私有_确保派生需求节点 失败时主要写日志、弹错或返回 nullptr，没有产出结构化拒绝回执。
5. 私有_收到派生需求消息时完善需求树 只提交基础派生需求入树回执；回执缺少拒绝原因、闭环类型、处理状态、关联诊断项和版本信息。
6. 提交派生需求入树回执 当前只记录调度侧快照和日志，不根据拒绝类型推动来源任务挂起、重筹办、阻断或转派。
7. 参数诊断和外设内部材料字段已有阻断日志，但没有进入来源任务内部闭环或外设材料闭环。
8. 价值结算、父链重判已有入口，但还需按 v0.4 核对“事实可信”和“结算硬闸门”最低条件。
```

## 5. 修订切片

### C1：协议结构与策略枚举

目标：

```text
1. 在任务管理协议或需求治理协议中补齐拒绝原因、闭环类型、处理状态、终态枚举。
2. 扩展 结构_派生需求入树回执，或新增 结构_需求入树拒绝回执 并让派生回执能携带它。
3. 建立“拒绝原因 -> 闭环类型 -> 后续处理策略 -> 终态”的静态映射。
4. 没有处理方案的拒绝原因不得进入正式枚举或机器判断。
```

优先触碰：

```text
任务模块.管理线程协议.ixx
任务模块.工作线程消息协议.ixx
自我线程模块.impl.cpp
```

验收：

```text
1. 每个拒绝原因都有处理策略。
2. 编译通过。
3. 不新增自由文本机器判断字段。
```

### C2：自我线程生成结构化拒绝回执

目标：

```text
1. 将 私有_确保派生需求节点 的返回从“节点或 nullptr + 原因输出”升级为裁决结果结构。
2. 所有拒绝分支都生成结构化回执，包含来源任务、父需求、目标主体、目标特征、状态、幂等键和版本信息。
3. 区分可治理拒绝、来源任务内部闭环、外设材料闭环、合并冷却闭环、观察验证闭环和开发诊断闭环。
4. 父需求非法进一步区分：引用损坏、父域可重判、结构根可映射、结构根无映射。
```

优先触碰：

```text
自我线程模块.impl.cpp
任务模块.管理线程协议.ixx
```

验收：

```text
1. 入树失败不再只有 nullptr / 日志路径。
2. 代码缺陷型拒绝固定标记为开发诊断闭环。
3. 外设材料和参数诊断不普通需求化，但有闭环类型。
```

### C3：拒绝回执治理处理器和账本

目标：

```text
1. 新增拒绝回执治理处理器，负责分类、转派、隔离、终态检查。
2. 账本只记录状态、证据、版本、关联对象，不主动转派。
3. 处理器把回执推进到合法终态：补槽重提、合并关闭、转观察验证、转学习、转来源任务内部处理、转外设材料闭环、冷却关闭、进入开发诊断项或升级规范缺口。
4. 处理失败时升级开发诊断或规范缺口。
```

优先触碰：

```text
自我线程模块.impl.cpp
任务模块.管理线程协议.ixx
必要时新增需求治理协议头或内部辅助结构
```

验收：

```text
1. 拒绝回执有处理状态变化。
2. 账本和处理器职责分离。
3. 终态检查失败可被日志和诊断定位。
```

### C4：来源任务挂起、回执承接和恢复重筹办

目标：

```text
1. 来源任务上报派生需求后进入等待入树结果状态。
2. 入树成功时等待派生需求满足，满足后恢复来源任务重筹办。
3. 可治理拒绝时按回执补槽、转学习、转观察或重筹办。
4. 开发诊断拒绝时进入实现缺陷阻断，停止当前路径重复筹办。
5. 合并冷却时绑定既有对象并停止重复派生。
```

优先触碰：

```text
任务模块.管理线程协议.ixx
任务模块.治理协议.ixx
任务模块.管理界面线程.impl.cpp
任务模块.管理工作线程.ixx
```

验收：

```text
1. 同一任务同一路径不重复生成同一派生需求消息。
2. 来源任务状态变化有结构化证据。
3. 入树成功、拒绝、开发诊断三类回执均能影响来源任务。
```

### C5：开发诊断闭环

目标：

```text
1. 定义 结构_开发诊断项 或等价诊断账本节点。
2. 代码缺陷型拒绝生成开发诊断项，记录来源回执、任务、需求、方法、失败阶段、失败原因、版本和复现上下文。
3. 运行期只做诊断、隔离、报告和阻断；开发期通过代码修正、编译和回归关闭。
4. 来源任务收到实现缺陷阻断回执。
```

优先触碰：

```text
任务模块.管理线程协议.ixx
任务模块.管理界面线程.impl.cpp
自我线程模块.impl.cpp
必要时新增开发诊断协议结构
```

验收：

```text
1. 空指针、非法枚举、结构损坏、状态机非法跳转不普通需求化。
2. 同一路径不继续污染需求树。
3. 诊断项关闭条件明确要求编译和回归。
```

### C6：观察验证、学习、材料和参数闭环

目标：

```text
1. 三态比较不可判定进入观察验证闭环，而不是直接回来源扫描。
2. 学习缺口按缺方法、缺动作、缺条件结果对、缺参数映射、缺验证方法分类。
3. 外设内部材料字段转外设材料闭环或方法内部材料依赖。
4. 参数诊断转参数重绑、参数映射学习或方法候选降权。
```

验收：

```text
1. 不可判定材料有验证转派回执。
2. 参数和材料缺口不进入普通需求树。
3. 来源任务能拿到转派或降级结果。
```

### C7：结果事实可信、价值结算硬闸门和父链重判补强

目标：

```text
1. 审计并补强任务完成回执到需求满足判断之间的结果事实可信检查。
2. 审计并补强价值结算硬闸门：叶子需求、目标真实满足、结果可验证、动作可归因、未重复入账、属于安全 / 服务可结算域。
3. 子需求满足后继续回查父目标特征；父目标未达成则父任务重筹办。
```

验收：

```text
1. 证据不足不写成需求满足。
2. 任务完成不直接等于价值结算。
3. 父目标未达成能触发父任务重筹办。
```

## 6. 执行顺序

```text
第一执行切片：C1 协议结构与策略枚举。
第二执行切片：C2 自我线程生成结构化拒绝回执。
第三执行切片：C3 拒绝回执治理处理器和账本。
第四执行切片：C4 来源任务挂起、回执承接和恢复重筹办。
第五执行切片：C5 开发诊断闭环。
第六执行切片：C6 观察验证、学习、材料和参数闭环。
第七执行切片：C7 结果事实可信、价值结算硬闸门和父链重判补强。
```

每个切片必须独立构建验证并更新计划索引当前停止点；不得一次性大改全部闭环。
