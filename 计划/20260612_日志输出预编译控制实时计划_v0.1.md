# 20260612 日志输出预编译控制实时计划 v0.1

## 1. 目标

```text
把项目内所有对外输出纳入统一预处理开关范围。

输出类型至少分为：
1. 登记管理日志输出：运行链路、任务推进、状态登记、外设报告、控制面板和摘要类运行记录。
2. 逻辑错误日志输出：非正常逻辑错误、错误 / 致命日志、弹窗错误提示、空指逻辑错误、异常捕获记录。
3. 调试日志输出：性能耗时、阶段耗时、采样诊断、调试器输出、临时诊断输出。
4. 控制台 / UI 直接输出：std::cout、std::cerr、直接 MessageBox / OutputDebugString 等绕过项目日志入口的输出。

当所有输出开关均编译为 0 时，本次运行不得新增运行日志内容；若使用全新日志目录，运行日志应为空。
若同日已有旧日志文件，验收口径为“本次窗口无新增行 / 文件大小不增长”，不能把旧内容误判为本次输出。
```

## 4. 分类口径

```text
登记管理日志输出：
    用于登记运行事实、任务推进、线程状态、外设报告、控制面板命令、摘要窗口和普通业务观察。
    关闭后不影响机器事实写入，不得让关闭日志改变任务、需求、方法、世界树或因果账本行为。

逻辑错误日志输出：
    用于记录非正常逻辑错误、错误 / 致命日志、异常捕获、弹窗错误提示和空指逻辑错误。
    关闭开关只能关闭输出水位，不能删除逻辑错误检测、不能吞异常、不能把错误改成成功或静默兜底。
    全关静默构建不能作为“无逻辑错误”的业务验收证据；逻辑错误追根因仍必须使用逻辑错误日志打开的构建。

调试日志输出：
    用于耗时、采样、候选评分、中间统计、调试器输出、临时诊断输出。
    关闭后应尽量连字符串拼装成本一起编译掉；优先迁移高频 ostringstream 日志点。

控制台 / UI 直接输出：
    命令行显式结果输出和 UI 弹窗必须单独开关；
    直接 std::cout / std::cerr / MessageBoxW / OutputDebugStringW 不得绕过预处理控制。
```

## 5. 预处理开关设计

```text
统一写入文件：
    预处理开关变量.h

新增总开关：
    鱼巢_开关_启用所有输出

新增分类开关：
    鱼巢_开关_启用登记管理日志输出
    鱼巢_开关_启用逻辑错误日志输出
    鱼巢_开关_启用调试日志输出
    鱼巢_开关_启用控制台输出
    鱼巢_开关_启用调试器输出
    鱼巢_开关_启用UI直接提示输出

默认关系：
    各分类开关默认继承 鱼巢_开关_启用所有输出；
    鱼巢_开关_启用项目弹窗错误 默认受 鱼巢_开关_启用UI直接提示输出 约束；
    鱼巢_开关_启用不允许空指诊断 继续控制检测本身；
    鱼巢_开关_启用不允许空指弹窗 只控制弹窗输出。

取值校验：
    所有新增开关必须和既有开关一样限制为 0 / 1；
    发生非法值直接 #error，不做运行时兜底。
```

### P1 中央输出闸门

```text
目标：
    在 日志模块.ixx / 日志接入.h / 预处理开关变量.h 建立分类开关和中央 no-op 分支。

允许修改：
    预处理开关变量.h
    日志模块.ixx
    日志接入.h

实现要点：
    项目运行日志 -> 登记管理日志输出；
    项目运行警告日志 -> 登记管理日志输出，除明确逻辑错误外不归入错误类；
    项目运行错误日志 / 项目记录异常日志 / 项目致命日志 -> 逻辑错误日志输出；
    项目自检无上级需求日志 -> 登记管理日志输出或调试日志输出，按登记表定类；
    项目弹窗错误提示 -> 逻辑错误日志输出 + UI直接提示输出 双条件；
    日志模块内部 OutputDebugStringW -> 调试器输出；
    日志模块紧急 fatal 文件输出和 MessageBoxW 单独登记，先保留为低级错误保护，不参与普通静默运行验收。

验收：
    默认构建行为不变；
    全关构建可编译；
    全关构建运行时不新增 run / exception / selfcheck_orphan_requirement 日志内容。
```

### P3 高频调试日志编译期瘦身

```text
目标：
    对高频调试 / 耗时 / 采样类日志先做编译期包裹，避免关闭调试日志后仍构造长字符串。

优先文件：
    自我线程模块.impl.cpp
    任务模块.管理界面线程.impl.cpp
    自我动作实现.外设模块.ixx
    自我动作实现模块.ixx
    任务模块.管理工作线程.ixx
    外设线程_D455深度相机.ixx

实现要点：
    使用统一宏或 inline helper 包裹整段日志构造；
    不能只在 项目运行日志 函数体里 return，导致 ostringstream 仍运行；
    先迁移明确属于调试 / 耗时 / 采样的日志点，不改业务事实写入。
```

### P4 分类文件与命名复核

```text
目标：
    让日志文件和函数命名表达分类边界，避免错误日志和调试日志混在同一判断口径里。

候选实现：
    保留 run 文件承载登记管理日志；
    exception 或 logic_error 文件承载逻辑错误日志；
    debug 文件承载调试日志；
    selfcheck_orphan_requirement 维持独立文件，但必须明确归属开关。

边界：
    文件名调整不能成为兼容双写；
    若改名，旧文件只作历史日志，不进入当前机器判断。
```

## 7. 禁止范围

```text
1. 不删除逻辑错误检测。
2. 不把逻辑错误降级成普通调试日志。
3. 不用关闭日志来掩盖弹窗、Debug Error、abort、访问冲突或业务缺口。
4. 不改任务状态、需求满足、方法选择、动作动态、世界树、因果账本或价值结算。
5. 不恢复任务筹办 / 任务执行本能方法。
6. 不新增模拟样本、夹具入口、伪造动作动态或旧 --*-check 回归命令。
7. 不用全关静默构建证明业务链通过；它只证明输出开关覆盖完整。
```
